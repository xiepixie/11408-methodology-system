# Teaching AGENTS

> **Scope**：`teaching/` 及其后代。上层根 `AGENTS.md` 的全局渐进式铁律、三域边界与 Single Source of Truth 原则继续生效。
>
> **系统目标**：把题目、学生作答与长期画像组织成一套**教师真正能在备课、上课、课后追踪三个时刻高效使用**的教学交付系统。
>
> **核心原则**：教学公共资产（`teaching/pool/`、`teaching/topics/`、`teaching/templates/`）负责“可复用的数学与教学知识”，`teaching/students/` 负责“这个学生此刻为什么要学、课堂上发生了什么、下一次要验证什么”。两者严格物理隔离。所有会话与题包必须直连 Canonical 路径，禁止任何非规范历史路径回退。

---

## 一、系统边界与三个使用时刻

本系统服务于 120 分钟一对一数学辅导。其目标不是机械罗列所有题目，而是：
1. 锚定学生当前最值得解决的 1–3 个核心薄弱点；
2. 用最少但充分的题目完成验证、纠偏与能力迁移；
3. 为教师在课堂中提供快速决策依据（继续 / 降阶 / 跳过 / 追加变式）；
4. 课后仅将有充分证据支持的稳定问题沉淀至长期画像。

### 三个使用时刻

#### 1. 课前备课：5–15 分钟快速扫描
教师需要快速明确：
- 学生身份、本次课专题与已知历史证据；
- 本节课聚焦解决的 1–3 个可观察目标；
- 每道题目的处理方式、时间预算与取舍策略；
- 学生达标判据（达到何种程度即“停止基础讲解”）；
- 达标后的跳进路线，以及未达标时的梯级脚手架。

#### 2. 课堂进行：以“课堂教学导引表”为主视图
教师不应在长篇解析中寻找课堂动作。教案第一页与题目页必须优先呈现：
- 当前题目处理方式与时间预算；
- 核心检查点 (Checkpoint)；
- 关键追问梯度与递进式提示；
- 学生卡点时的分支处置策略；
- 便于板书的标准得分链与核心推理句。

#### 3. 课后追踪：3–8 分钟完成证据闭环
课后即时记录与更新：
- 学生的当堂实际表现与目标达成度；
- 区分偶发性失误（仅留存当次记录）与共性问题；
- 将获得多重证据支持的稳定问题晋升至长期画像（`profile.md`）；
- 布置针对性的课后重做与间隔复测任务。

## 二、数据分层：公共知识与学生证据严格分离

```text
教学公共知识 (teaching/)   <--- 严格物理隔离 --->   学生个性化数据 (teaching/students/)
├── pool/ 可复用题库                                  ├── 历史诊断与已知证据
├── topics/ 可复用专题                                ├── 课堂实际表现与轨迹
└── templates/ 教学模板                               └── 长期画像与演进档案
```

### 1. 教学公共资产：只存放可复用内容

```text
teaching/
  templates/            # 4页精排学案、教案、questions.tex 起始模板
  pool/                 # 公共题库，按 [学科专题]/[分层难度]/q_[description].tex 组织
  topics/               # 公共专题课，存放可复用讲义与配套题
```

全局 LaTeX Design System 与编译机制由 `infra/latex/`、`infra/scripts/` 唯一拥有；Teaching 只拥有教学业务语义与交付规则。

#### `teaching/pool/` 题库规范
公共题目只保存与具体学生无关的客观内容：
- 包含字段：`Stem`、`Options`、`Figure`、`Answer`、`Solution`、`AltSolution`、`CommonErrors`、`TeachingNotes`；
- **严禁**在公共题目中写入具体学生姓名、个体诊断或某次课的实际课堂表现；
- 文件头部必须标注难度（★ 基础 / ★★ 中档 / ★★★ 难题）与知识点标签。

### 2. 学生目录：只存放个性化证据与交付产物

```text
teaching/students/学生姓名/
  profile.md                    # 长期画像（只记录稳定事实与确认薄弱点）
  bank/                         # 可选：该学生专属错题/试卷原题
  sessions/
    01_专题名称/
      plan.md                   # 课前计划与决策表
      diagnosis.md              # 课前已有诊断与证据
      outcome.md                # 课后实际结果记录
      questions.tex             # 本课引用题目清单
      学案.tex                  # 面向学生的 4 页精排学案源码
      教案.tex                  # 面向教师的 4 页精排教案源码
      学案.pdf                  # 编译交付物
      教案.pdf                  # 编译交付物
```

### 3. 三类课次文档的职责划分

- `diagnosis.md`：**课前已知**。源自历史作业、试卷、上次课表现或用户反馈；
- `plan.md`：**课前计划**。规划本节课讲授重点、达标判定准则与分支处置逻辑；
- `outcome.md`：**课后事实**。客观记录课堂真实表现与达标证据，**绝不允许提前预填为既定事实**。

## 三、学生画像 `profile.md`：证据链原则

`profile.md` 是学生的长期档案，绝不能作为一次性错题标签的堆砌池。

### 推荐结构

```markdown
# 学生画像

## 当前阶段
- 年级/目标：

## 稳定优势
- ...

## 已确认薄弱点
| 能力/知识点 | 状态 | 证据 | 最近验证 | 下次检查 |
|---|---|---|---|---|
| 线面角射影构造 | confirmed | S01-Q4, S03-Q2 | 2026-08-03 | 新图形能否独立作出射影 |

## 候选问题 (Candidate)
- 仅有单次证据、尚未确认为稳定缺陷的问题。

## 已解决/降级观察
- 曾经薄弱，但最近连续通过独立验证的问题。

## 教学偏好与有效讲法
- 只记录长期稳定且切实影响讲课方式的信息。
```

### 画像晋升与降级规则

- **单次失误**：仅记录于当次 `outcome.md` 或 `profile.md` 的【候选问题】，不计入稳定薄弱点；
- **两次独立场景重复出现**：方可晋升为 `confirmed`（已确认薄弱点）；
- **连续 2 次独立复测/新课验证通过**：从薄弱点降级至【已解决/降级观察】；
- **严禁主观归因**：禁止使用“粗心”“可能没看清”等猜测性描述直接建立长期标签。

## 四、题目输入、PDF 处理与 `uv` 环境规范

### 1. 输入材料处理原则
- **干净题面/去手写版**：题面文字与 TikZ 图形转写的唯一基准；
- **学生作答扫描件**：仅用于分析学生的解题过程与卡点，不得覆盖干净题面；
- **转写为 LaTeX**：所有题目最终沉淀为 LaTeX 题目宏定义文件与 TikZ 图形。

### 2. 成套 PDF 输入流程
当输入为“去手写试卷 + 带学生书写扫描件”时：
1. 按页码和题号建立配对清单：
   ```text
   | QID | 干净题面页码 | 学生作答页码 | 题型 | 知识点 | 作答状态 | 题库文件 | 诊断状态 |
   ```
2. 拆分任务：干净题面交由 `question_ingester` 转写，作答件交由 `diagnosis_solver` 诊断；
3. 确保同一道题仅生成一个最终文件名与一组驼峰宏名。

### 3. PDF 与 Python 环境管理规范（使用 `uv`）
本工作区统一使用 **`uv`** 进行 Python 环境与依赖管理：
1. **虚拟环境隔离**：
   - 严禁全局 `pip3 install` 写入系统环境；
   - 需要分析 PDF 时，在工作目录下执行 `uv venv` / `uv pip install ...`，或使用 `uv run --with ...` 一次性隔离运行；
   - `.venv/` 属于本机 Generated State，严禁进入学生资产或提交仓库。
2. **扫描型 PDF 识别**：若文本提取显示 `[No text extracted]`，表明该文件为纯扫描图层，必须依赖视觉转写；
3. **双重数学逻辑与数值验证**：转写完成后必须使用 Python 或特值代入法核对坐标系、几何尺寸、向量代数关系、正负号与角范围，确保零 OCR/转写错误。

### 4. 自动化编译与辅助文件清理规范 (`compile_tex.py`)
- **统一编译入口**：`python3 infra/scripts/compile_tex.py <目标.tex>`；Teaching 不维护第二套编译入口，也不允许历史路径回退；
- **多遍编译与 Log 解析**：脚本自动执行 Double/Triple Pass，解析 Warning/Error/Undefined References；
- **自动清理机制**：编译成功后清理 `.aux`、`.log`、`.synctex`、`.xdv` 等 Generated State。

## 五、120 分钟课次的决策模型

### 1. 每节课仅设定 1–3 个可观察目标
目标必须具体且可在课堂上直接观察，例如：
- “能独立完成线面垂直 4 条件证明链（不漏写相交与在面内条件）”；
- “面对新图形，能准确找出线面角的高与射影，并口述‘高度看正弦，影子看余弦’”；
- “解三角形边角互化能在‘化边’与‘化角’中做出合理决策”。

### 2. 六级题目处理方式与时间预算
- `必讲`：暴露核心认知漏洞，本次课必须彻底解决；
- `精讲`：方法迁移价值极高，适合展开标准板书与解题模型归纳；
- `快讲`：单点知识/技巧纠偏，通常耗时 3–8 分钟；
- `自练`：学生当堂独立书写解答，教师实时观察卡点；
- `跳过`：学生已完全掌握、题型重复或教学价值偏低；
- `课后复练`：适合间隔复测，不占用课堂黄金时段。

### 3. 每题显式设立“停止条件”
避免教师机械讲完所有预设步骤，例如：
- “学生能独立找出垂足与射影 → 停止基础定义讲解，直接检查计算”；
- “学生 60 秒内选对方法并说明理由 → 跳过完整板书，仅核对易错收尾”。

## 七、学案与教案排版规范

> **全局 LaTeX 架构边界**：Family/Profile/Variant、KOMA/CTeX/IPARA 分工、Semantic API、依赖与兼容迁移由 `infra/latex/README.md` 唯一拥有。本节仅拥有一对一 Lesson/Teaching 的业务排版要求，不得重新定义全局 Design System。

教案与学案采用 **4 页精排（一界一页）** 标准结构：

### 1. 教案（面向教师）4 页标准布局
- **第 1 页：【第一部分：课堂教学导引】**：页首元信息框 + 3 项可观察成功标准 + 课前证据；120 分钟课堂路线表 + 动态 Checkpoint 与分支处置；时间不足删减顺序与出口检测项。
- **第 2 页：【第二部分：备课知识库与几何直观模型】**：2–3 个经典 TikZ 几何模型图示 + 定理得分推导链。
- **第 3 页：【第三部分：核心题目精讲与诊断】**：单栏题干与 TikZ 原图；题下双栏 (`paracol` 比例 0.68 / 0.32)，左侧标准解答与得分链，右侧证据、Checkpoint、追问梯度与学案思考对应。
- **第 4 页：【第四部分：课后总结与复练落实】**：包含 5.5cm 高对比度独立边框手写框；课后复练与画像跟进固定在底部。

### 2. 学案（面向学生）规范
- 保持干净题面与大面积演算空间；
- 选择/填空题留足演算区，解答题独占半页或一页；
- 包含“课前公式复习”与“课后公式默写（隐藏答案）”；
- 题目区不出现教师提示与教学策略；自查反思问题置于题目下方。

### 3. 黑白打印与文本排版原则
- 采用纯净高对比度黑白排版，不使用极浅背景色；
- 统一使用适度淡灰色作为边框与分割线；
- 避免大段密集文本，每 1–2 句主动换行；
- 复杂数学公式使用展示环境，长公式在等号、加号、减号处主动换行。

## 八、题目文件与 LaTeX 宏命名规范

### 1. 文件命名与存放
公共题目统一保存在：
```text
teaching/pool/[学科专题]/[分层难度]/q_[description].tex
```
严禁在文件名中使用学生名字缩写或授课日期。

### 2. 驼峰宏命名与向下兼容
题目文件内部宏一律使用纯英文驼峰命名（严禁包含数字字符），如：
```latex
\qSolidCubeAngleStem
\qSolidCubeAngleFigure
\qSolidCubeAngleAnswer
\qSolidCubeAngleSolution
```
为向下兼容已有课次，可保留旧宏名 alias，但 Canonical 名称必须与学生身份解耦。

## 九、TikZ 图像与流程图绘制规范

### 1. 立体几何与数学图形规范
1. **前实后虚**：背面顶点与被遮挡线段使用虚线，杜绝透视矛盾；
2. **标签避让**：顶点字母不得被线段穿过；
3. **印刷安全**：少画微小直角符号与密集角弧线，关键条件写入题干或解析；
4. **教/学分层**：学生端只画题目已知结构；教师端可增加辅助线与投影点；
5. **图内文字克制**：图内仅标顶点与极简角标，解释写正文。

### 2. 计算机系统、架构与拓扑流程图规范（五大黄金原则）
本规范适用于教学中出现的计算机科学、软件架构、逻辑拓扑与状态机流程图；若属于考研 Canonical Handbook，则同时服从 `kaoyan/` 对应图示规范。

#### (1) 连线路由优先级
`Direct → One-bend → Orthogonal multi-bend → Outer routing`。能直连绝不绕折，外围绕线只作为最后兜底。

#### (2) 网格先于节点
先定义矩阵网格与行列，再填业务节点，禁止随意摆放后补线。

#### (3) 包络盒预算
以当前 `\linewidth` 为唯一排版基准；核心机制图包络宽度满足 `W_figure ≤ min(13.6cm, 0.90 × linewidth)`，全景图不超过 `0.95 × linewidth`。

#### (4) 节点固定尺寸与文案分层
普通流程节点约 `2.6cm × 0.95cm`；内部最多两行：第一行对象/动作，第二行状态/意义，长解释移出节点。

#### (5) 线型与形状统一语义系统
| 视觉图形 / 线型 | 统一固定系统含义 |
|---|---|
| 实线箭头 | 动态控制流 / 数据流 / 状态转换 |
| 粗实线箭头 | Main Path / 正常运行流 |
| 虚线箭头 | 静态引用 / 指针 / 逻辑映射 |
| 点线 | Cache / 可选 Fast Path / 推测路径 |
| 双线框 | 持久化对象 / 存储介质 / 数据库 |
| 灰框 | 教材 / 理论高层抽象层 |
| `[E]` | 现代工程扩展 / 平台特定扩展 |

## 十、可观察行为诊断语言规范

诊断必须精确描述“可观察解题行为”，严禁主观标签化。

- **推荐**：“证明线面垂直时漏写相交条件”；“能求出 cos 值但特殊角映射错误”；“求线面角时未先寻找垂足与射影”。
- **严禁**：“学生粗心”“空间想象力差”“基础太差”“态度不认真”。

每个诊断须力求包含：1. 发生在哪一步骤；2. 属于概念理解、公式记忆、逻辑推理还是计算收尾；3. 下一次课如何验证。

## 十一、子 Agent 职责分工

1. **`question_ingester`**：干净题面转写、TikZ 几何/拓扑绘图、公共题库元数据标注与数学逻辑/数值检查；
2. **`diagnosis_solver`**：标准解答、得分点、通用易错点与课前诊断证据分析；
3. **`session_planner`**：120 分钟课次目标、题目取舍、时间预算、Checkpoint 与分支路由，生成 `plan.md`；
4. **`lesson_builder`**：根据 `plan.md`、Canonical 题目与学生私有证据生成 4 页学案/教案，并调用 `infra/scripts/compile_tex.py`；
5. **`session_reviewer`**：课后根据真实记录生成 `outcome.md`，执行 `profile.md` 画像证据链晋升与降级判定。

## 十二、质量检查清单

- [ ] **内容正确性**：题干与图形和原材料严格校对，数学逻辑与数值已验证；
- [ ] **课堂可用性**：第一页有课堂教学导引，120 分钟预算、Checkpoint 与停止条件清晰；
