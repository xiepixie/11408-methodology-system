## 3. Bridge Gate 与结果

| Bridge | Gate 结论 | 独立接口 |
|---|---|---|
| NET-B01 | 重构 | `(packet, egress, next hop) -> LinkAdapter`；按 multi-access/PPP/tunnel 分叉，不固定为 MAC |
| NET-B02 | 保持并去重 | selected route/FIB install/version -> packet-visible lookup state |
| NET-B03 | 重构 | reliable invariant -> TCP byte interval -> segment evidence -> action |
| NET-B04 | 重构 | `Usable=max(0,min(rwnd,cwnd)-FlightSize)` 与双反馈辨识 |
| NET-B05 | Candidate 通过 Gate并建册 | path rate/time -> required in-flight data -> window/utilization |
| NET-B06 | Candidate 通过 Gate并建册 | application/TCP/IP/link 四层尺寸预算与重组 Owner |

RIP、OSPF、BGP、PPP 没有升级为 Bridge：它们是各自 Topic 内协议，不存在需要独立 Owner 的跨专题接口。Graph Algorithm × Routing 继续保持 Use/Candidate Connection。

## 4. No Update / Remaining Risk

- **No Update：**X-B04 Process/Socket × Transport Endpoint 仍是 Candidate Core；本轮网络考纲补缺没有提供足够的跨科重复调用证据。
- **待验证：**海明码 syndrome、TDM/CDM、802.11 地址角色、PPP LCP/NCP、IPv6 压缩、组播成员/分发、Mobile IP 内外层、TCP 首部、BDP/Window 和 MTU/MSS 需要至少一组真题或陌生题逐项攻击。
- **深度边界：**408 考纲列名不要求纳入全部现代工程扩展；RFC 只用于校正稳定语义，正文刻意停在可复原的 408 Core。
- **外部基线：**待取得官方同版大纲原件后，对“2026 新增 OSI/TCP-IP”及转载排字做二次核验。
