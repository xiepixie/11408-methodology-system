## 1. 母问题

同一串比特怎样在给定位宽、解释和运算规则后得到确定结果？

```text
bit pattern + width + interpretation + operation + rounding
-> representable result + status
```

关键不是把“原码、补码、浮点”看成三套编码表，而是理解：硬件只能保存有限位串，表示系统决定这些位串映射到哪些数学对象，以及超出集合时怎么办。

## 2. 朴素模型为什么失败

“先按数学算，再写成二进制”会在三处失败：

- 数学整数无限，而寄存器只有固定 $n$ 位；
- 同一位串可同时解释为 unsigned、two's complement、地址或逻辑掩码；
- 浮点运算每一步都可能舍入，结合律等实数规律不再自动成立。

正确入口是先写四元组：

```text
$(width, interpretation, operation, destination)$
```

## 3. 定长整数：环上的位串

### 3.1 无符号数与补码共享同一加法器

$n$ 位加法器计算的是模 $2^n$ 加法：

$$
r=(a+b)\bmod 2^n
$$

位串层结果相同，区别在解释：

- unsigned 范围：$0\le x\le 2^n-1$；
- two's complement 范围：$-2^{n-1}\le x\le 2^{n-1}-1$。

补码的价值不是“负数前面有 1”，而是让加减法统一到同一个模环：

$$
a-b \equiv a+(2^n-b) \pmod {2^n}
$$

### 3.2 Carry 与 Overflow 不是同一件事

- **Carry** 服务于无符号解释：最高位是否产生进位/借位关系；
- **Overflow** 服务于有符号解释：数学结果是否越过补码可表示范围。

补码加法溢出的可操作判据：同号相加得到异号。减法先改写为加负数再判断。

| 位串运算 | unsigned 解释 | signed 解释 |
|---|---|---|
| $1111+0001\to0000$（4 位） | $15+1$ 溢出，$carry=1$ | $-1+1=0$，不溢出 |
| $0111+0001\to1000$ | $7+1=8$，无 unsigned 溢出 | $7+1$ 越界，$overflow=1$ |

## 4. 扩展、截断与移位

这些不是排版操作，而是在保留某种解释：

- zero extension 保留无符号数值；
- sign extension 保留补码数值；
- truncation 只保留低位，相当于模 $2^k$，通常不保数值；
- logical shift 填 0，处理位串或无符号量；
- arithmetic right shift 复制符号位，通常对应补码除以 $2^k$ 的向负无穷取整行为，不能无条件等同于高级语言整数除法。

不变量：每次转换都要问“要保留的是位模式、无符号值还是有符号值”。

## 5. 乘除：结果位宽决定是否丢信息

两个 $n$ 位整数的完整乘积可能需要 $2n$ 位。只保留低 $n$ 位时，signed 与 unsigned 的低位乘法结果相同，但高半部和溢出解释不同。

除法电路可抽象为重复的移位、比较与加减。做题不必从电路图背结论，应追踪：

```text
partial remainder -> compare/subtract -> quotient bit -> shift
```

边界要单独检查：除数为 $0$、最小补码除以 $-1$、商和余数的符号规则均由 ISA 决定。

## 6. 浮点：可变尺度的有限采样

### 6.1 表示模型

对普通二进制规格化数：

$$
x=(-1)^s\times(1.f)_2\times 2^{E-\mathrm{Bias}}
$$

三个字段承担不同职责：sign 选择方向，exponent 选择尺度，fraction 选择该尺度上的采样点。指数全 0 和全 1 必须进入特殊分支：零、subnormal、infinity、NaN；不能套普通规格化公式。

### 6.2 精度不是均匀的小数位数

相邻可表示数间距随指数增大而增大。因此：

- 大数附近的绝对间距更大；
- 小量加到大量上可能被对阶移走；
- 两个接近数相减可能发生有效数字消去；
- overflow 是尺度超界，underflow 与 tiny/inexact 的具体判定需服从标准和题设。

### 6.3 运算生成链

```text
classify operands
-> align exponents
-> significand operation
-> normalize
-> round
-> encode / signal exception
```

舍入不是最后随手“看下一位”，而是把无限精确结果映射回目标格式。题目若未声明，通常采用 round to nearest, ties to even，但必须以题设为准。

## 7. 机制、边界与代价

| 机制 | 解决的问题 | 适用前提 | 失效/边界 | 代价 |
|---|---|---|---|---|
| 补码 | 统一有符号加减 | 固定位宽 | 最小负数无对应正数 | 范围不对称 |
| 符号扩展 | 扩宽且保补码值 | 源按补码解释 | 对 unsigned 不保值 | 需知道解释 |
| 饱和运算 | 避免环绕 | ISA/题目明确支持 | 普通整数指令通常不饱和 | 额外比较选择 |
| 浮点指数 | 扩大数量级 | 接受非均匀精度 | 不能精确表示多数实数 | 舍入与特殊值 |
| guard/round/sticky | 支持正确舍入 | 保留足够中间信息 | 过早截断不可恢复 | 额外位和逻辑 |

## 8. 母例：为什么 $0.1+0.2$ 不是表示错误这么简单

十进制 0.1 和 0.2 在二进制中通常是无限循环展开。存入有限格式时各自先舍入；加法时再对阶、相加、规格化、舍入。因此误差来自一串有限映射，而不是某一个“转换失误”。

验证方法：不要求背最终小数，检查两点即可：输入是否可精确表示，以及运算的中间精确结果是否仍落在格式格点上。

## 9. 做题调用协议

1. 标位宽、编址/数据单位与解释；
2. 写可表示范围，不先套十进制直觉；
3. 在位串层执行扩展、截断和运算；
4. 分别判断 carry、overflow、zero、sign 等状态；
5. 浮点先分类，再走对阶—运算—规格化—舍入；
6. 用反向解码或数量级检查结果。

## 10. 最小反例

- `1000` 在 4 位 unsigned 中是 8，在补码中是 -8；“最高位是符号”不能说明运算语义。
- 4 位补码的 $-8$ 取负仍得到 `1000`；机械“按位取反加一就变正数”遗漏范围边界。
- 浮点加法不满足结合律：当尺度差使小量被舍去时，括号位置会改变结果。

## 11. 压缩信号

> 比特没有自带意义。先定宽度与解释，再谈数值；先定舍入点，再谈浮点结果。
