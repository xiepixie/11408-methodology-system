# CPU 数据通路与控制：把指令语义编排成状态转移

状态：工作稿，待人工确认。

## 1. 母问题

一条 ISA 指令怎样被拆成可由寄存器、组合逻辑与存储接口完成的真实数据移动？

```text
instruction semantic delta
-> required values
-> routes and functional units
-> micro-operations
-> control signals
-> state update
```

数据通路提供“能走的路”，控制器决定“此刻让谁走、走向哪里”。

## 2. 从状态差生成通路

不要先背整机图。给定一条指令，先写：

- 初态：PC、源寄存器、内存；
- 目标态：目标寄存器/内存/PC 的变化；
- 中间值：指令、扩展立即数、ALU 结果、访存数据；
- 必需部件：读取、运算、选择、暂存和写入位置。

例如 `LOAD rd, imm(rs1)` 至少需要：取指路径、寄存器读取、立即数扩展、地址加法、数据存储器读、写回选择。具体是否共享 ALU、是否需要 MAR/MDR，是实现选择。

## 3. 部件按职责理解

| 部件 | 角色 | 核心约束 |
|---|---|---|
| PC / IR | 指令流状态与当前编码 | 更新时机、异常时保存位置 |
| register file | 架构操作数与结果 | 读写端口数、同拍读写规则 |
| ALU | 组合变换 | 输入选择、关键路径延迟 |
| MUX | 在候选来源间选择 | 控制位与数据来源一一对应 |
| temporary register | 跨周期保存中间值 | 不属于软件可见状态 |
| memory interface | 发出地址/命令并收发数据 | 请求与返回可能跨多个周期 |
| control unit | 生成使能、选择与读写信号 | 必须避免冲突与错误提交 |

## 4. 微操作与总线约束

微操作是一个时钟边界内允许发生的寄存器传送或组合运算。例如：

```text
R1out, Yin          // R1 -> Y
R2out, ALUadd, Zin  // Y + R2 -> Z
Zout, R3in          // Z -> R3
```

在单总线模型中，同一拍只能有一个源驱动总线，但可以有多个目标锁存同一个值。两个需要不同总线源的动作不能机械合并。

判断可并行微操作的条件：

1. 数据依赖允许；
2. 共享资源不冲突；
3. 组合路径能在本拍稳定；
4. 目标寄存器写使能互不矛盾。

## 5. 四条母指令的路径

### 5.1 ADD

```text
register read -> ALU add -> result select -> register write
```

### 5.2 LOAD

```text
base + immediate -> address
-> memory read
-> width/extension
-> register write
```

### 5.3 STORE

```text
base + immediate -> address
data register -> write-data path
-> memory write
```

STORE 通常不写通用寄存器，但会改变内存可见状态。

### 5.4 BRANCH

```text
operand compare + target calculation
-> select sequential PC or target PC
```

比较与目标计算是否使用一个或两个加法器，是成本/关键路径权衡。

## 6. 单周期与多周期：复制资源还是复用时间

### 单周期

每条指令在一个长时钟周期完成。周期必须覆盖最慢指令的最长组合路径。

- 优点：控制直观，CPI 近似 1；
- 代价：时钟周期被最慢路径决定，短指令也等待；同拍冲突可能迫使复制资源。

### 多周期

把指令拆成多个短状态，共享 ALU、存储端口等部件，并用临时寄存器保存中间值。

- 优点：周期更短、资源复用；不同指令可用不同周期数；
- 代价：控制状态机和中间状态更复杂，CPI 大于 1。

性能不能只比 CPI：

$$
T_{CPU}=IC\times CPI\times T_{clk}
$$

## 7. 控制器：从条件到控制字

### 硬布线控制

组合/时序逻辑直接由 opcode、状态和条件产生控制信号。速度快，但修改和复杂化成本高。

### 微程序控制

把每拍控制信号编码成微指令，由微程序顺序器选择下一微地址。结构规整、便于复杂控制，代价是控制存储访问和微序列开销。

二者解决的是同一问题：

```text
$(instruction, phase, condition)$
-> control word + next phase
```

不要把“微程序”误认为软件程序；它是实现 ISA 的控制层。

## 8. 关键路径与结构代价

关键路径是一个周期内最长的寄存器到寄存器组合路径。加入 MUX、扩展器或更复杂 ALU 会增加延迟；复制加法器、增加端口可能缩短路径或避免冲突，却增加面积和功耗。

| 选择 | 性能收益 | 硬件代价 |
|---|---|---|
| 指令/数据分离存储口 | 同拍取指与访存 | 两套端口/存储结构 |
| 多端口寄存器堆 | 同拍多读一写 | 面积、布线、时延 |
| 独立 PC 加法器 | 并行计算下一 PC | 额外加法器 |
| 共享 ALU | 节省面积 | 需要多周期和暂存 |

## 9. 母例：由 `LOAD` 反推控制信号

1. PC 驱动取指地址，IR 锁存指令，PC 得到顺序下一值；
2. opcode 选择 load 路径，寄存器堆读 base；
3. immediate 符号扩展，MUX 选择它作为 ALU 第二输入；
4. ALU 结果作为访存地址，读命令有效；
5. 返回数据按指令宽度扩展；
6. 写回 MUX 选择内存数据，目标寄存器写使能有效。

验证：若错误打开 memory write 或选择 ALU result 写回，就违背 ISA 状态差。

## 10. 做题调用协议

1. 写 $\text{before} \rightarrow \text{after}$ 状态差；
2. 列出每个中间值的生产者和消费者；
3. 在图上沿最短路径连线，遇选择点再决定 MUX；
4. 按总线/端口/ALU 冲突拆拍；
5. 为每拍写“唯一驱动者 + 锁存目标 + 控制条件”；
6. 用 ISA 结果反查所有写使能，确认无多余副作用；
7. 性能题同时计算 CPI 与时钟周期。

## 11. 最小反例

- ALU 结果已经产生，但目标寄存器写使能未开，架构状态没有改变。
- 两个寄存器都想通过单总线输出，不能因为箭头画得下就同拍完成。
- 单周期 $CPI=1$ 不推出更快；其长周期可能超过多周期实现的平均总时间。

## 12. 压缩信号

> 从 ISA 状态差反推数据，再从数据依赖与资源冲突生成微操作和控制。
