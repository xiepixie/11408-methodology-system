## 待验证

### 数据结构首次定位链

```text
Goal
-> Relation
-> Operations / Workload
-> Representation
-> Invariant
-> State / Progress
-> Cost / Boundary
```

先确定目标操作和关系，再比较表示；模拟过程中写出当前已确定区域、frontier 或剩余规模，最后统一计算比较、移动、空间与 I/O 成本。若题目已经明确给出结构与操作，直接从 `Representation / Invariant` 开始，不机械补写前置步骤。

### 先写表示，再模拟操作

题目要求执行插入、删除、遍历或查找时，先明确数组、链式节点、矩阵、邻接表或树节点中究竟保存了什么，再画状态变化。

### 修改结构时说出不变量

每次指针修改、旋转、交换、relax 或合并前，先说出操作后必须继续成立的结构条件。

### 边界进入算法骨架

写伪代码前主动检查空结构、单元素、首尾、重复 key 和越界，而不是把它们留到最后补丁式处理。

### 复杂度绑定基本操作

给出复杂度时同时说明计数对象和输入规模，避免只写一个没有成本模型的 `O(...)`。

### 线性表题先拆 Locate 与 Update

看到插入、删除或按值操作时，先分开“是否还要定位元素/前驱”和“定位后怎样修改表示”。只有题目已经给出节点或前驱时，链式局部修改才可记为 `O(1)`；按关键字查找的成本必须另计。

### 长度与容量分开检查

看到顺序表或动态数组时，草稿同时写 `length` 与 `capacity`，先判有效元素区和扩容条件，再计算移动成本；不能把空槽当成有效元素，也不能把一次扩容复制改写成单次 `O(1)`。

### 指针题先写不变量再改边

修改链表前先写 `head / tail / length / next`（双链表再加 `prev`）必须满足的关系，按“接入新边、断开旧边、修复边界、验证可达性”执行；遇到空表、单元素、首尾和重复值时停下来分支。
