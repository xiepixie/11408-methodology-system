# B 树

## 大纲定位

本篇对应 2026 大纲 **六、查找 （六）B 树及其基本操作、B+ 树的基本概念**。

**分工边界**：本篇负责 **B 树及其基本操作**——m 阶 B 树的定义、 高度的上下界推导、查找、插入（分裂）、删除（借关键字与合并）。 **B+ 树的基本概念在[《B+ 树》](./b-plus-tree.html)**，本篇只在对比时提到它。

- 内存中的平衡查找树（二叉搜索树、平衡二叉树、红黑树）对应大纲六（五）， 编排在树那一章：[《二叉排序树》](./../tree/bst.html)、[《平衡二叉树》](./../tree/avl.html)、 [《红黑树》](./../tree/rbt.html)。B 树可以看作它们在外存场景下的多路推广， **但旋转、平衡因子那一套不在本篇重复**；
- ASL、失败结点等通用概念见[《查找基本概念》](./concepts.html)；
- 外存排序中的多路归并与 B 树共享"减少外存访问次数"这一目标，见 [《外部排序》](./../sorting/external-sort.html)。

考纲动词是"及其基本操作"，属**掌握**级：要能对给定关键字序列**手工建树**、 手工完成插入分裂与删除合并，并能推导高度界。

## 知识框架

本节回答 4 个问题：

- **内存里的平衡二叉树已经是 O(log⁡n) 了，为什么到了磁盘上还要换成 B 树？**
- **"每个非根结点至少 ⌈m/2⌉ 棵子树"这条下界是干什么用的？去掉会怎样？**
- **B 树的高度被什么夹住？给定 n 与 m，最少几层、最多几层？**
- **插入的分裂与删除的合并，为什么都能保证"所有叶结点仍在同一层"？**

## 为什么需要 B 树：把树高换成 I/O 次数

内存里比较一次关键字大约几个纳秒，磁盘随机读一次大约几毫秒——**相差六个数量级**。 所以外存上的查找结构，衡量指标不再是"比较了多少次"，而是"**读了多少个磁盘块**"。

一次磁盘 I/O 读进来的是一整个磁盘块（几 KB），而一棵平衡二叉树的结点只有一个关键字。 用二叉树做外存索引，等于**每读一个磁盘块只利用了其中几个字节**，其余全浪费。

改造思路只有一条：**把一个磁盘块塞满关键字，让一次 I/O 尽可能多地缩小候选范围。** 结点里放 m−1 个关键字、m 个子指针，一次 I/O 就能把候选范围缩小到 1m， 树高从 log2⁡n 降到 logm⁡n。

**量化一下**：取 m=1001，存 n=109 个关键字。

- 树高下界 h≥logm⁡(n+1)=3.0；
- 树高上界 h≤log⌈m/2⌉⁡n+12+1=4.2，即 h≤4。

也就是说，**十亿条记录，最多 4 次磁盘访问就能定位**。同样规模的平衡二叉树要 log2⁡109≈30 层， 即 30 次磁盘访问——**差了 7 倍多**。这就是数据库索引和文件系统目录普遍采用 B 树族的原因。

结点内部的比较（在 m−1 个关键字里找区间）是**在内存中做的**， 不产生磁盘 I/O。所以即使 m 取到上千，结点内多比几十次也无所谓—— **B 树是拿内存里的比较次数去换磁盘 I/O 次数**，这是它全部设计的出发点。

## m 阶 B 树的定义

一棵 m 阶 B 树，或者是空树，或者是满足下列全部性质的 m 叉树：

| 编号 | 性质 | **为什么要有这一条** |
| --- | --- | --- |
| （1） | 树中每个结点**至多有 m 棵子树**，即至多 m−1 个关键字 | 上界。保证一个结点装得进一个磁盘块 |
| （2） | 若**根结点**不是叶结点，则**至少有 2 棵子树**（至少 1 个关键字） | 根不受下界约束，否则树无法从 1 个关键字开始生长 |
| （3） | 除根之外的所有**非叶结点至少有 ⌈m/2⌉ 棵子树**，即至少 ⌈m/2⌉−1 个关键字 | 下界。**这是 B 树效率的命根子**，见下文 |
| （4） | 所有**叶结点都出现在同一层次**，且不带信息（**失败结点**） | 绝对平衡。保证任何一次查找的 I/O 次数完全相同 |
| （5） | 结点内关键字**递增有序**，K1<K2<⋯<Kn；指针 Pi−1 所指子树中所有关键字都小于 Ki，Pi 所指子树中所有关键字都大于 Ki | 有序性。使结点内可用顺序或折半查找定位子树 |

结点的结构：

```
┌──┬────┬──┬────┬──┬─ ... ─┬──────┬──┐
│P₀│ K₁ │P₁│ K₂ │P₂│       │Kₙ    │Pₙ│
└──┴────┴──┴────┴──┴─ ... ─┴──────┴──┘
```

n 个关键字对应 n+1 个子树指针。**关键字个数的取值范围**（非根结点）：⌈m2⌉−1≤n≤m−1

⚠️ **性质（3）里的"非叶结点"= 全部含关键字的结点，最底层那一排也算在内。** 这里有两套必须拆开的术语：严蔚敏教材的原话是"除根之外的所有**非终端结点**至少有 ⌈m/2⌉ 棵子树"，而该书把"终端结点"定义为**度为 0 的结点即叶子**（p112）， B 树里的叶子又是**失败结点**，所以该书的"非终端结点"指的正是**所有真实存在的结点** （同书性质（5）"所有的非终端结点最多有 m−1 个关键字"也只有这样读才讲得通）。 本篇按另一种通行口径把**最底层含关键字的结点叫"终端结点"**（见「易混淆知识点」）， 两套叫法对不上，所以这一条改写成"非叶结点"以免歧义。 **千万不要读成"终端结点不受下界约束"**——下面推最大高度时，正是靠"每个终端结点 也至少有 ⌈m/2⌉ 个失败结点孩子"才数得出第 h+1 层的结点数； 删除时终端结点关键字数低于 ⌈m/2⌉−1 就要借或合并，用的也是同一条下界。

图源：殷人昆《数据结构——用面向对象方法与 C++ 描述》（第 2 版），p478

图上要看清两件事：**一是所有空方框（失败结点）在同一层**，这正是性质（4）； **二是含关键字的结点最少也有 1 个关键字**——图中 m 较小，若把 m 提到 5， `[25]` 这种只含 1 个关键字的非根结点就违规了。

### 下界 ⌈m/2⌉−1 为什么必须存在

去掉这一条会怎样？答案是**B 树会退化**。

设想没有下界约束：每个结点只放 1 个关键字、2 棵子树，那么这棵"m 阶 B 树"实际上就是一棵 **二叉树**，树高回到 log2⁡n，一次磁盘 I/O 只读进 1 个关键字—— B 树相对二叉树的全部优势荡然无存。

下界的作用就是**强制每个结点至少半满**，从而保证分支因子至少是 ⌈m/2⌉， 树高被 log⌈m/2⌉⁡n 压住。**"至少半满"这四个字，就是 B 树高度上界的全部来源。**

反过来说，插入时的分裂与删除时的合并，唯一目的就是**在结点关键字数越界时把它拉回 [⌈m/2⌉−1, m−1] 这个区间**。理解了这一点，插入删除的所有分情形处理都是自然的。

### 结点的 C 语言定义
c

```
#define M 5  // 5 阶 B 树：每个结点最多 4 个关键字、5 棵子树

typedef struct BTNode {
    int keyNum;                      // 当前关键字个数 n
    int keys[M];                     // 关键字数组，keys[0] 不用，实际用 keys[1..M-1]
    struct BTNode *children[M + 1];  // 子树指针 P0..Pn，用 children[0..M-1]
    struct BTNode *parent;           // 指向双亲，删除时向上回溯要用
} BTNode;
```

`keys[0]` 空出不用，是为了让关键字下标与"第几个关键字"一致（K1 存在 `keys[1]`）， 这样 Ki 的左子树就是 `children[i-1]`、右子树就是 `children[i]`， 下标关系最简单。`parent` 指针不是定义要求的，是**实现删除时向上传播下溢**的便利。

## 高度：上界与下界

设 B 树含 n 个关键字，阶为 m，**高度 h 指从根到终端结点（含关键字的最底层）的层数， 不含最底层的失败结点层**。

### 最小高度：每个结点尽可能满

每个结点装满 m−1 个关键字、m 棵子树。第 1 层 1 个结点、第 2 层 m 个、 第 j 层 mj−1 个，h 层共 mh−1m−1 个结点，每个结点 m−1 个关键字， 故最多容纳n≤(m−1)⋅mh−1m−1=mh−1⟹h≥logm⁡(n+1)

### 最大高度：每个结点尽可能空

这里要用到**失败结点**这个工具。n 个关键字的 B 树恰有 n+1 个失败结点 （理由同[《查找基本概念》](./concepts.html)：n 个关键字把取值范围切成 n+1 段）， 它们全在第 h+1 层。

按下界逐层数最少结点数：

- 第 1 层（根）：至少 1 个结点；
- 第 2 层：根至少 2 棵子树 → 至少 2 个结点；
- 第 3 层：每个非根结点至少 ⌈m/2⌉ 棵子树 → 至少 2⌈m/2⌉ 个；
- ……
- 第 h+1 层（失败结点层）：至少 2⌈m/2⌉h−1 个。

于是n+1≥2⌈m2⌉h−1⟹h≤log⌈m/2⌉⁡n+12+1

### 两界合起来
logm⁡(n+1)≤h≤log⌈m/2⌉⁡n+12+1

**验算**（m=5）：

| h | 最少关键字数 2⌈m/2⌉h−1−1 | 最多关键字数 mh−1 |
| --- | --- | --- |
| 1 | 1 | 4 |
| 2 | 5 | 24 |
| 3 | 17 | 124 |

h=2 那一行可以手工验证：根 1 个关键字 + 2 个孩子各 2 个关键字 = 5 个关键字， 正是 5 阶 B 树两层时的最少配置 ✓

⚠️ **"高度"的两种口径**：上面的 h **不含失败结点层**。有的教材把失败结点层也计入， 此时高度 = h+1。同一棵树，按本篇口径算是 3 层，算上失败层就是 4 层。 **做题前先看题目怎么定义**——若题目说"叶结点在第 4 层"，多半是把失败层算进去了。

## 查找

B 树的查找是**结点间纵向移动**（磁盘 I/O）与**结点内横向比较**（内存操作）交替进行：

- 从根开始，在当前结点的关键字序列中查找 key（结点内关键字少时顺序查找，多时折半查找）；
- 若 key=Ki，查找成功；
- 若 Ki<key<Ki+1，沿指针 Pi 进入对应子树，**读取下一层结点（一次磁盘 I/O）**；
- 若走到失败结点（空指针），查找失败。c

```
// B 树查找：返回关键字所在结点与位置；失败时返回应插入的位置信息
typedef struct {
    BTNode *node;  // 成功时为关键字所在结点；失败时为最后访问的终端结点
    int index;     // 在结点中的位置
    int found;     // 1 = 成功，0 = 失败
} SearchResult;

SearchResult BTreeSearch(BTNode *root, int key) {
    BTNode *p = root, *parent = NULL;
    int i = 1;                       // 必须初始化：空树时循环一次都不进，i 会被直接返回
    while (p != NULL) {
        // 结点内顺序查找：停在第一个不小于 key 的关键字上
        for (i = 1; i <= p->keyNum && key > p->keys[i]; i++)
            ;
        if (i <= p->keyNum && key == p->keys[i])
            return (SearchResult){p, i, 1};   // 查找成功
        parent = p;
        p = p->children[i - 1];      // key < keys[i]，进入 K_i 的左子树 P_{i-1}
    }
    return (SearchResult){parent, i, 0};      // 走到失败结点，返回插入位置
}
```

**`children[i - 1]` 为什么是对的**：循环退出时有两种情况——

- i≤keyNum 且 key<Ki：应进入 Ki 的左子树，即 Pi−1 = `children[i-1]` ✓
- i=keyNum+1（key 比全部关键字都大）：应进入最右子树 PkeyNum = `children[i-1]` ✓

两种情况的表达式统一，所以不需要分支。

**磁盘 I/O 次数 = 查找路径上的结点数 = 树高 h**。结点内的比较全在内存完成，不计 I/O。 这就是前面那句"内存比较换磁盘 I/O"的代码级体现。

## 插入：分裂

B 树的插入**总是发生在最底层的终端结点**——因为查找失败必然停在终端结点， 新关键字就插在那里。**绝不会插到中间层**。

### 步骤

- 先查找，确定新关键字应插入的终端结点；
- 插入后若该结点关键字数 ≤m−1，**直接完成**；
- 若插入后关键字数 =m（**上溢**），执行**分裂**。

### 分裂的三步

- 取该结点的**第 ⌈m/2⌉ 个关键字**（记作 K⌈m/2⌉）作为分裂点；
- 分裂点**左边的关键字**留在原结点，**右边的关键字**移入一个新建结点；
- **分裂点本身上移到双亲结点**，并把新结点的指针也插进双亲。

**分裂后两个结点都合法吗**？设分裂前有 m 个关键字。左结点得到 ⌈m/2⌉−1 个， 右结点得到 m−⌈m/2⌉ 个。下界要求是 ⌈m/2⌉−1：

- 左结点恰好等于下界 ✓
- 右结点 m−⌈m/2⌉=⌊m/2⌋≥⌈m/2⌉−1 ✓（m≥3 时恒成立）

**所以分裂点必须取第 ⌈m/2⌉ 个**，取别的位置会让某一半低于下界。

- 若双亲结点也上溢，**继续向上分裂**；最坏情况一路分裂到根， 根分裂时会**新建一个只含 1 个关键字的根**，**树高增加 1**。

```
5 阶 B 树，结点最多 4 个关键字，插入后达到 5 个时分裂
分裂点 = 第 ⌈5/2⌉ = 3 个关键字

分裂前（上溢）:  [K₁ K₂ K₃ K₄ K₅]
                       ↑ K₃ 上移

分裂后:    双亲 ← [..., K₃, ...]
              /              \
         [K₁ K₂]          [K₄ K₅]
```

### 插入连环手算例（5 阶 B 树）

m=5：每个结点最多 4 个关键字，非根结点最少 2 个。依次插入 **20, 30, 50, 52, 60, 25, 68, 70, 90**。

**第 1~4 个**：结点未满，直接放。

```
[20, 30, 50, 52]
```

**插入 60 → 上溢，根分裂，树高 1 → 2**

结点变成 [20,30,50,52,60] 共 5 个关键字，上溢。分裂点是第 ⌈5/2⌉=3 个，即 **50**。 左边 [20,30] 留下，右边 [52,60] 新建，50 上移——但这是根结点，没有双亲， 于是**新建一个根**：

```
        [50]
       /    \
  [20,30]  [52,60]
```

这一步就是"**树长高的唯一方式是根分裂**"的现场：树高从 1 变成 2， 新根只有 1 个关键字（性质（2）允许根只有 1 个关键字，这正是为什么根要单列一条）。 而且分裂是**向上**长的，所以两个孩子仍在同一层——**绝对平衡自动被保持**。

**插入 25**：查找落在 [20,30]，插入后 [20,25,30] 只有 3 个，未满，完成。

**插入 68、70**：落在 [52,60]，依次变成 [52,60,68]、[52,60,68,70]，仍未满。

```
        [50]
       /    \
[20,25,30]  [52,60,68,70]
```

**插入 90 → 第二次分裂，这次上移到已有的根**

[52,60,68,70,90] 上溢，分裂点是第 3 个即 **68**。左 [52,60]、右 [70,90]， 68 上移进根：

```
      [50, 68]
     /    |    \
[20,25,30] [52,60] [70,90]
```

根从 1 个关键字变成 2 个，未超过 4，分裂到此为止，**树高不变**。

对照两次分裂：**只有根自己上溢时树才长高**；子结点上溢只是把一个关键字塞进双亲， 除非双亲也被塞爆，否则树高不动。

## 删除：借关键字与合并

删除要保证删完之后每个非根结点的关键字数**不低于 ⌈m/2⌉−1**。

### 第一步：把删除位置归约到终端结点

| 情况 | 处理 |
| --- | --- |
| 待删关键字在**终端结点** | 直接删，然后检查是否下溢 |
| 待删关键字在**非终端结点** | 用它的**直接前驱**（左子树中最右下的关键字）或**直接后继**（右子树中最左下的关键字）**替换**它，问题转化为"删除那个终端结点里的前驱/后继" |

**为什么用前驱或后继替换**：Ki 的作用是"分隔左右子树"。要保持这个分隔关系， 新的分隔者必须**大于左子树全部关键字、小于右子树全部关键字**—— 只有左子树的最大值（前驱）和右子树的最小值（后继）满足。前驱与后继**都在终端结点上**， 所以替换之后一定归约成"删终端结点里的关键字"。

⚠️ 前驱与后继**都可以用**，两种选择得到的树形不同但都合法。题目未指定时任选一种， 但同一道题里要**从一而终**。

### 第二步：处理下溢（关键字数 <⌈m/2⌉−1）

**判断顺序是固定的：先看能不能借，借不到才合并。**

| 策略 | 触发条件 | 具体操作 |
| --- | --- | --- |
| **向左兄弟借** | 左兄弟关键字数 >⌈m/2⌉−1（有富余） | 双亲中的分隔关键字**下移**到当前结点，左兄弟的**最大**关键字**上移**到双亲 |
| **向右兄弟借** | 右兄弟关键字数 >⌈m/2⌉−1 | 双亲中的分隔关键字**下移**到当前结点，右兄弟的**最小**关键字**上移**到双亲 |
| **合并** | 左右兄弟都恰好等于下界（谁也借不出） | 当前结点 + 双亲中的分隔关键字 + 一个兄弟，**三者拼成一个结点**；双亲少一个关键字 |

**借为什么必须"经双亲中转"**：不能把兄弟的关键字直接搬到当前结点。 以向右借为例，右兄弟的最小关键字比双亲的分隔关键字**大**，直接搬过来会破坏 "当前结点的关键字全部小于分隔关键字"这条有序性。正确做法是让双亲的分隔关键字下移 （它比当前结点全部关键字大、比右兄弟全部关键字小，放在当前结点末尾正合适）， 再把右兄弟最小的那个提上去当新分隔者。

**合并后是否越界**：当前结点 ⌈m/2⌉−2 个 + 分隔关键字 1 个 + 兄弟 ⌈m/2⌉−1 个 =2⌈m/2⌉−2≤m−1（m≥2 时成立），不会上溢 ✓

**合并可能连锁**：双亲少了一个关键字，可能自己也下溢，需要**逐层向上重复**。 最坏情况一路合并到根；若根的最后一个关键字也被下移参与合并，**根被掏空，删掉空根， 树高减 1**。

```
借右兄弟示例（5 阶 B 树，非根结点最少 2 个关键字）:

        [..., 35, ...]          双亲
        /          \
    [20]          [40, 50, 60]   当前结点下溢，右兄弟有 3 个（富余）
                ↓
        [..., 40, ...]          35 下移，40 上提
        /          \
    [20, 35]      [50, 60]      两边都合法
```

```
合并示例（5 阶 B 树）:

        [..., 35, ...]          双亲
        /          \
    [20]          [40, 50]       当前结点下溢，右兄弟恰好 2 个，借不出
                ↓
        [...]                    35 下移参与合并
          |
    [20, 35, 40, 50]            三部分拼成一个结点
```

### 删除连环手算例（一棵树串完全部情况）

5 阶 B 树（非根结点 2~4 个关键字，根至少 1 个），初始：

```
            [30, 60]
           /    |    \
   [10, 20] [40, 50] [70, 80, 90]
```

删终端结点里且删完不下溢的（比如删 90），直接删，没什么可讲。有意思的是下面这条连环：

**第 1 删：删 50 → 借右兄弟**

[40,50] 删 50 后剩 [40]，1 个 < 2 个，下溢。 左兄弟 [10,20] 恰好 2 个不富余；右兄弟 [70,80,90] 有 3 个，富余 → **借右**： 双亲的分隔关键字 **60 下移**到当前结点，右兄弟最小的 **70 上移**到双亲：

```
            [30, 70]
           /    |    \
   [10, 20] [40, 60] [80, 90]
```

注意不是把 70 直接搬给 [40]——借兄弟必须**经双亲中转**（60 下来、70 上去）， 否则会破坏"双亲关键字分隔左右子树"的有序性。

**第 2 删：删 60 → 合并**

[40,60] 删 60 剩 [40]，下溢。这回左右兄弟都只有 2 个，谁也不富余 → **与右兄弟合并**： 双亲的分隔关键字 **70 下移**参与合并，[40]+70+[80,90] 拼成一个结点：

```
         [30]
        /    \
  [10, 20] [40, 70, 80, 90]
```

双亲只剩 [30]——它是根，根允许只有 1 个关键字，到此为止，**树高不变**。

**第 3 删：删 30 → 非终端关键字，前驱替换**

30 在根（非终端结点），不能直接删：用**直接前驱**（左子树中最右下的关键字）20 替换 30， 问题转化为"删终端结点 [10,20] 里的 20"。删完剩 [10] 下溢， 右兄弟 [40,70,80,90] 有 4 个富余 → 借右（20 下移、40 上移）：

```
         [40]
        /    \
  [10, 20] [70, 80, 90]
```

**第 4 删：删 20 → 又一次借**

[10] 下溢，右兄弟 [70,80,90] 富余 → 借右（40 下移、70 上移）：

```
         [70]
        /    \
  [10, 40] [80, 90]
```

**第 5 删：删 10 → 合并掏空根，树高减 1**

[40] 下溢，右兄弟 [80,90] 只有 2 个，不富余 → 合并：70 下移，拼成 [40,70,80,90]， 根被掏空——**删掉空根，树高从 2 层降为 1 层**：

```
  [40, 70, 80, 90]
```

**对照插入的连环例**：树长高的唯一方式是**根分裂**，变矮的唯一方式是**根被合并掏空**。 除了这两种情形，B 树的高度在任何插入删除中都不变——这正是"所有叶结点始终在同一层" 得以维持的机制。

## 复杂度

| 操作 | 磁盘 I/O 次数 | 结点内比较 | 说明 |
| --- | --- | --- | --- |
| 查找 | h=O(log⌈m/2⌉⁡n) | 每层 O(log2⁡m)（折半）或 O(m)（顺序） | 每层读一个结点，正好一次 I/O |
| 插入 | 最坏 2h | 同上 | h 次查找 + 最坏逐层分裂到根，每次分裂写回 |
| 删除 | 最坏 2h | 同上 | h 次查找 + 最坏逐层合并到根 |

**为什么写成 O(log⌈m/2⌉⁡n) 而不是 O(logm⁡n)**： logm⁡n 是**最好情形**（结点全满）的树高，log⌈m/2⌉⁡n 是**最坏情形** （结点半满）的树高。复杂度取最坏，所以用后者。两者只差一个常数因子 （log⌈m/2⌉⁡n=logm⁡nlogm⁡⌈m/2⌉）， 量级上都可以粗略写作 O(logm⁡n)。

**实际应用中 m 取多大**：让一个结点恰好占满一个磁盘块。磁盘块 4 KB、 每个关键字加指针 16 字节时，m≈256；再大就要跨块读，反而增加 I/O。 m 取到几百到上千时，h 通常只有 3~4 层。

## 易混淆知识点

| 易混对象 | 区别 | **判别依据** |
| --- | --- | --- |
| B 树的**叶结点** vs **终端结点** | **叶结点 = 失败结点 = 空指针所在的那一层，不含任何关键字、实际不存在**；**终端结点 = 最底层含关键字的结点**，在叶结点的**上面一层** | 问一句"这个结点里有关键字吗"：有 → 终端结点；没有（只是个空指针的化身）→ 叶结点。"所有叶结点在同一层"说的是那些**空指针**在同一层 |
| 根结点的下界 vs 非根结点的下界 | 根：至少 2 棵子树、1 个关键字（非叶时）；非根：至少 ⌈m/2⌉ 棵子树、⌈m/2⌉−1 个关键字 | 5 阶 B 树：根最少 2 棵子树，非根最少 3 棵子树。**别把 3 套到根上** |
| 子树个数 vs 关键字个数 | 子树数 = 关键字数 + 1 | 看结点结构图：K 之间与两端都要挂指针，所以指针比关键字多一个。**B+ 树不是这样**，见[《B+ 树》](./b-plus-tree.html) |
| 高度含不含失败结点层 | 本篇口径**不含**；部分教材**含**（此时高度 = h+1） | 做题前看题干怎么定义。若题目说"叶结点在第 k 层"，多半把失败层算进去了 |
| 分裂点取第 ⌈m/2⌉ 个 vs 取"正中间" | m 为奇数时两者相同；m 为偶数时不同 | m=4：上溢时有 4 个关键字，分裂点是第 ⌈4/2⌉=2 个，左边留 1 个（正好等于下界 ⌈4/2⌉−1=1），右边 2 个。取第 3 个会让左边有 2 个、右边 1 个——也合法但与教材口径不符，**统一按 ⌈m/2⌉** |
| 下溢时先借还是先合并 | **先借，借不到才合并** | 反过来做会产生无谓的合并，并可能把本可停止的下溢传播到上层 |
| 插入会插到中间层吗 | **不会**，插入永远发生在终端结点 | 查找失败必然停在终端结点；中间层的关键字只能由**下层分裂上移**产生 |
| 树长高 / 变矮的条件 | 长高**只有**根分裂；变矮**只有**根被合并掏空 | 其余所有分裂与合并都只在层内重组，不改变层数 |
| B 树 vs 二叉排序树 | B 树绝对平衡（所有叶结点同层）且多路；BST 形态取决于插入顺序，可能退化成链 | 问"最坏树高是多少"：B 树被 log⌈m/2⌉⁡n 压住，BST 最坏是 n |

## 本节小结

学完本篇，应当能够：

- 说清 B 树的设计动机——**用内存中的比较次数去换磁盘 I/O 次数**，并能量化 （m=1001、n=109 时树高不超过 4）；
- 完整写出 m 阶 B 树的**五条性质**，并解释下界 ⌈m/2⌉−1 的作用是 **强制结点至少半满**，去掉它 B 树就退化成二叉树；
- 分清 **B 树的"叶结点"是不含信息的失败结点**，含关键字的最底层叫**终端结点**；
- 推导高度的上下界 logm⁡(n+1)≤h≤log⌈m/2⌉⁡n+12+1， 其中上界的推导要用到"n 个关键字对应 n+1 个失败结点"；
- 写出 B 树的查找过程，并说清**磁盘 I/O 次数 = 树高**、结点内比较不计 I/O；
- 对给定关键字序列**手工建树**：插入落在终端结点，上溢时取第 ⌈m/2⌉ 个关键字 作为分裂点上移，并能证明分裂后左右两半都不低于下界；
- 手工完成删除：非终端结点先用**前驱或后继替换**归约到终端结点， 下溢时**先借（经双亲中转）、借不到才合并**；
- 说清**树长高的唯一方式是根分裂、变矮的唯一方式是根被合并掏空**。

两条最关键的结论：**"至少半满"这条下界是 B 树高度上界的全部来源**； **分裂与合并都是把关键字数拉回 [⌈m/2⌉−1, m−1] 这个区间， 其余性质（尤其是绝对平衡）都是这一动作的副产品。**
