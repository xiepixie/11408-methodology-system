# B+ 树

## 知识框架

本节回答 4 个问题：

- **B 树已经能在 3~4 次 I/O 内定位了，B+ 树还改进了什么？**
- **"n 个关键字对应 n 棵子树"这条与 B 树的差别，根子在哪里？**
- **为什么 B+ 树的查找"不管成功与否都必须走到叶结点"？这是缺点还是优点？**
- **叶结点链表买到了什么，是用什么换的？**

## B+ 树解决的是什么问题

B 树把数据分散存放在**所有层**的结点里。这带来两个后果：

**痛点一：范围查询要在树里反复上下走。** 查"所有 100 到 200 之间的关键字"， 在 B 树上必须做中序遍历——从某个叶子回到双亲、再下到另一个子树， 每一次上下移动都是一次磁盘 I/O。

**痛点二：内部结点存数据，挤占了扇出。** 一个磁盘块的容量是固定的。 B 树的内部结点里既要放关键字与指针，又要放（或指向）实际记录， 一个块能装下的关键字就少，分支因子 m 就小，树就更高。

B+ 树的改造只有一句话：**把全部关键字与数据都放到叶结点，非叶结点只留索引副本， 再把叶结点按关键字顺序串成一条链表。**

两个痛点同时消失：范围查询变成沿叶链表顺序扫描；非叶结点不再存数据， 同样大小的磁盘块能装下更多关键字，扇出变大、树变矮。

**扇出到底大多少（估算）**：设磁盘块 4 KB，关键字 4 字节、指针 8 字节、 一条数据记录 100 字节。

- B 树内部结点每一项要占 4+8+100=112 字节 → m≈4096/112≈36
- B+ 树内部结点每一项只占 4+8=12 字节 → m≈4096/12≈341

存 107 条记录时，B 树需要 log36⁡107≈4.5 → 5 层， B+ 树只需要 log341⁡107≈2.8 → 3 层。**每次查找少两次磁盘 I/O。**

这组数字依赖假设的记录长度，换一组参数结论会变；但**方向是稳的**： 记录越大，B+ 树的扇出优势越明显。

## m 阶 B+ 树的定义

一棵 m 阶 B+ 树满足：

- 每个**内部结点最多有 m 棵子树**；
- **根结点**至少有 2 棵子树（除非整棵树只有一个叶结点）；
- 除根之外的**内部结点至少有 ⌈m/2⌉ 棵子树**；
- **内部结点的关键字个数 = 子树个数**（⚠️ B 树是"关键字个数 = 子树个数 − 1"）；
- **所有叶结点在同一层**，且包含**全部关键字**以及指向对应数据记录的指针；
- 叶结点之间通过**顺序指针**链接成一条有序链表。

由第 4 条与第 3 条合起来：非根内部结点的关键字个数范围是 ⌈m/2⌉≤n≤m。

图源：殷人昆《数据结构——用面向对象方法与 C++ 描述》（第 2 版），p487 图 10.39

对着图逐条核验定义：

- 根 `[67 84]`：2 个关键字、2 棵子树 ✓ 第 4 条；
- 内部结点 `[15 34 47 67]`：4 个关键字、4 棵子树，m=4 时正好达到上限 ✓；
- 叶结点 `[10 15]`、`[18 22 27 34]`、…… 依次被箭头串起来 ✓ 第 6 条；
- **每个索引关键字都是它所领子树的最大关键字**：15 是 `[10 15]` 的最大值、 34 是 `[18 22 27 34]` 的最大值、67 是左半棵子树的最大值。
- 全部关键字 10、15、18、22、27、34、40、44、47、54、67、72、74、78、81、84 **都出现在叶结点上**，而 15、34、47、67、84 在上层**又出现了一次**—— 这就是"关键字在内部结点会重复出现"。

### 为什么"关键字个数 = 子树个数"

根子在**关键字的角色变了**。

在 B 树里，Ki 是一个**真实存在的记录**，它把左右两棵子树**分隔**开来： 左边全部 <Ki，右边全部 >Ki。n 个分隔者切出 n+1 段，所以有 n+1 棵子树。

在 B+ 树里，Ki 只是一个**索引副本**——它是第 i 棵子树中**最大关键字的复写**。 每棵子树配一个"我这棵子树里最大的是多少"的标签，**一棵子树一个标签**， 所以关键字个数与子树个数相等。

**口径说明**：上面用的是「**最大关键字复写**」原则，这是 408 与严蔚敏教材的口径 ——"所有的非终端结点可以看成是索引部分，结点中仅含有其子树（根结点）中的最大关键字"。 另有一种「**最小关键字复写**」的定义（索引项记录子树中的最小值，此时 n 个关键字对应 n+1 个指针），部分数据库教材与工程实现采用它，画出来的树不一样。 **考研做题一律按本文口径**（n 个关键字 ↔ n 棵子树），读工程资料时注意区分。

### 两个头指针，两种查找方式

B+ 树通常设**两个头指针**：一个指向**根结点**，一个指向**关键字最小的叶结点**。 对应两种查找：

| 入口 | 过程 | 用途 |
| --- | --- | --- |
| 从**根**开始 | 逐层向下比较，一路走到叶结点 | 随机查找（按关键字精确定位） |
| 从**最小叶结点**开始 | 沿叶链表顺序扫描 | 顺序查找、全表扫描 |

**B 树没有第二个入口**——它的关键字散布在所有层，不存在一条能一次扫完全部关键字的链。

### 查找必须走到叶结点

**即使在内部结点上遇到了等于 key 的关键字，也不能停**，必须继续向下走到叶结点。 原因是内部结点里那个关键字**只是索引副本，不携带数据记录的指针**， 真正的记录挂在叶结点上。

这条性质的两面：

- **代价**：任何一次查找的比较路径都是"根到叶"，长度恒等于树高， **不会像 B 树那样有时在中间层就命中**；
- **收益**：**每次查找的 I/O 次数完全相同**，响应时间可预测。 对需要稳定延迟的系统（数据库），这个"稳定"比"偶尔更快"更值钱。

## 走一遍：查找、范围查询与插入分裂

用「m 阶 B+ 树的定义」里那棵 4 阶 B+ 树（m=4，非根内部结点关键字数 2∼4）：

```
                      [67  84]
                 /                \
        [15 34 47 67]           [78 84]
        /   |    |   \           /     \
 [10 15]→[18 22 27 34]→[40 44 47]→[54 67]→[72 74 78]→[81 84]
```

### 随机查找 44（成功）

- 根 `[67 84]`：44≤67 → 进第 1 棵子树；
- `[15 34 47 67]`：44>15、44>34、44≤47 → 进第 3 棵子树；
- 叶结点 `[40 44 47]`：找到 44，取出对应的记录指针 → **成功**。

走了 3 层，正好是树高。

### 随机查找 67（命中了中间层也不能停）

- 根 `[67 84]`：67≤67 → 进第 1 棵子树；
- `[15 34 47 67]`：这里**遇到了等于 67 的关键字**——但它只是个索引副本， **不带记录指针，不能停**，67≤67 → 进第 4 棵子树；
- 叶结点 `[54 67]`：找到 67 → **成功**。

同样走了 3 层。**这就是"B+ 树查找路径长度恒定"的现场**： 换成 B 树，第 2 步就命中返回了，路径长度是 2 而不是 3。

### 随机查找 50（失败）

根 → 第 1 棵子树；`[15 34 47 67]` 里 50>47、50≤67 → 第 4 棵子树； 叶结点 `[54 67]` 中没有 50 → **失败**。**仍然走了 3 层**—— 成功与失败的路径长度完全一样。

### 范围查询：找出 [22,54] 内的全部关键字

- 按 22 做一次随机查找，定位到叶结点 `[18 22 27 34]`（O(logm⁡n)）；
- 从 22 开始沿**叶链表**顺序扫：22、27、34 → 下一叶 `[40 44 47]`：40、44、47 → 下一叶 `[54 67]`：54 命中，67 已超出上界 → 停止。

结果 {22,27,34,40,44,47,54}，扫描阶段**一次都没有回到上层**。 换成 B 树，这 7 个关键字散落在不同层的不同结点里，取全它们要在树中反复上下移动。

### 插入 25：一次连锁分裂

m=4，叶结点最多 4 个关键字。25 应插入 `[18 22 27 34]`：

**第 1 步：叶结点上溢。** 插入后成为 `[18 22 25 27 34]`，5 个 >m，分裂。 分裂后两半的关键字数是 ⌈m+12⌉=3 与 ⌊m+12⌋=2：[18 22 25]与[27 34]

双亲中要同时包含这两个新结点各自的**最大关键字**，即 **25** 与 **34**。 34 原本就在，所以只需把 25 插进去。

**第 2 步：双亲上溢。** 双亲变成 `[15 25 34 47 67]`，5 个 >m，继续分裂：[15 25 34]与[47 67]

它们的最大关键字 **34** 与 **67** 要送进根。根原是 `[67 84]`，67 已在，插入 34。

**第 3 步：根未上溢，结束。** 根变成 `[34 67 84]`，3 个 ≤m，停止。

```
                      [34   67   84]
              /             |            \
      [15 25 34]         [47 67]         [78 84]
      /    |    \         /    \          /    \
[10 15]→[18 22 25]→[27 34]→[40 44 47]→[54 67]→[72 74 78]→[81 84]
```

逐条核验：根 3 个关键字 ↔ 3 棵子树 ✓；每个非根内部结点关键字数在 2∼4 之间 ✓； 每个索引关键字仍等于所领子树的最大值（34、67、84；15、25、34；47、67；78、84）✓； **叶链表顺序不变，且仍包含全部关键字** ✓。

对照 [B 树](./b-tree.html) 的分裂：B 树是把中间关键字**搬**到双亲（原结点不再有它）， B+ 树是把最大关键字**复写**一份到双亲（叶结点里那一份原样保留）。 上面第 1 步里 25 同时出现在叶结点和双亲中，就是这个差别的体现。

## B 树 vs B+ 树：核心对比表

| 对比项 | B 树 | B+ 树 |
| --- | --- | --- |
| **关键字与子树个数的关系** | n 个关键字 ↔ **n+1** 棵子树 | n 个关键字 ↔ **n** 棵子树 |
| **非根结点的关键字数范围** | ⌈m/2⌉−1∼m−1 | ⌈m/2⌉∼m |
| **数据存储位置** | 所有结点都可以存数据 | **只有叶结点**存数据 |
| **非叶结点的作用** | 既是索引又存数据 | **纯索引**，只存关键字副本与子指针 |
| **关键字是否重复出现** | 每个关键字只出现一次 | 内部结点的关键字在叶结点中**会再次出现** |
| **叶结点包含的关键字** | 只是全部关键字的一部分 | **全部**关键字 |
| **"叶结点"的含义** | 不含信息的**失败结点**（空指针层） | **真实存在**、含全部关键字与记录指针的结点 |
| **查找在哪里结束** | 可能在**任意层**命中 | **必须走到叶结点** |
| **查找路径长度** | 不定（最好 1 层，最坏 h 层） | **恒为 h 层**，性能稳定 |
| **叶结点链表** | 无 | **有**，按关键字顺序链接 |
| **范围查询** | 需中序遍历，反复上下移动 | **定位起点后沿叶链表扫描**，效率高 |
| **顺序遍历入口** | 无专用入口 | 有，指向最小叶结点的头指针 |
| **同样块大小下的扇出** | 较小（结点里还要放数据） | **较大**（纯索引，一个块装更多关键字） |
| **插入删除发生在哪** | 终端结点（可能是任意含关键字的最底层结点） | **只在叶结点** |

⚠️ **表里最容易记反的是第一行和倒数第七行**，它们是同一件事的两个侧面： B+ 树的关键字是"子树的标签"（一子树一标签，所以相等）， B 树的关键字是"子树的分隔者"（n 个分隔者切 n+1 段，所以差一）。 **记住这个理由，就不会记反。**

⚠️ **"叶结点"这个词在两棵树里指的不是一回事**： B 树的叶结点是**不存在的失败结点**（见[《B 树》](./b-tree.html)）， B+ 树的叶结点是**真实存在、装着全部关键字**的结点。 "所有叶结点在同一层"这句话两棵树都成立，但说的是不同的东西。

## 插入与删除的规则：与 B 树的差别

B+ 树的插入删除**只在叶结点进行**，整体流程与 B 树类似（上溢分裂、下溢合并）， 差别在三处：

|  | B 树 | B+ 树 |
| --- | --- | --- |
| 上溢的判定 | 关键字数 >m−1 | 关键字数 >m |
| 分裂后两半的关键字数 | ⌈m/2⌉−1 与 m−⌈m/2⌉ | ⌈m+12⌉ 与 ⌊m+12⌋ |
| 分裂点关键字的去向 | **上移到双亲**，原结点不再保留它 | **复制**一份到双亲：双亲中同时包含分裂出的两个结点各自的**最大关键字**；原关键字仍留在叶结点 |
| 下溢的判定 | 关键字数 <⌈m/2⌉−1 | 关键字数 <⌈m/2⌉ |

**"上移"与"复制"的差别是本节的关键**。B 树分裂时中间关键字**离开**原结点搬到双亲， 所以它在树中仍然只出现一次；B+ 树的叶结点必须保有**全部**关键字， 所以分裂时只能把最大关键字**复写**一份到双亲当索引，叶结点里的那一份原样保留。 这正是"B+ 树的关键字会重复出现"的成因。

**删除的一个细节**：当叶结点里的**最大关键字**被删掉时， 它在非叶结点里的那个副本**不必立即修改**——那个值可以继续作为一个"分界关键字"存在， 因为它仍然正确地划分了左右子树的范围（只是不再对应任何真实记录）。 这是 B+ 树删除比 B 树省事的地方。

## 为什么外存索引普遍选 B+ 树

把前面的分析收成四条：

- **磁盘 I/O 更少**：内部结点不存数据 → 同样大小的磁盘页装下更多关键字 → 扇出更大 → 树更矮 → I/O 次数更少（前面的估算是 5 层 vs 3 层）。
- **范围查询高效**：定位到区间起点的叶结点后，**沿叶链表顺序扫描**即可， 代价是 O(logm⁡n+k)（k 为结果条数）；B 树要做中序遍历，反复上下移动。
- **查询性能稳定**：每次查询都走到叶，路径长度恒定，响应时间可预测。
- **全表扫描友好**：从最小叶结点出发沿链表走一遍就能顺序访问全部关键字， 完全不必碰内部结点。

数据库中还会区分**聚簇索引**（叶结点直接存放整行数据）与**非聚簇索引** （叶结点存放主键值，取完整记录还要再查一次聚簇索引）。这属于工程实现层面， 考纲不要求，了解即可。

## 复杂度

| 操作 | 时间复杂度 | **怎么来的** |
| --- | --- | --- |
| 查找 | O(logm⁡n) | 每次都从根走到叶，路径长度 = 树高；每层一次磁盘 I/O |
| 插入 | O(logm⁡n) | 查找到叶 + 最坏逐层分裂到根 |
| 删除 | O(logm⁡n) | 查找到叶 + 最坏逐层合并到根 |
| **范围查询** | O(logm⁡n+k) | logm⁡n 定位起点叶结点，再沿链表扫描 k 个结果 |

**空间复杂度** O(n)：全部 n 个关键字存在叶结点，内部结点额外存储索引副本。 索引部分的规模约为 nm−1 量级，m 较大时占比很小。

**与 B 树的量级对比**：两者的查找都是 O(logm⁡n)，**量级相同**。 B+ 树赢在**常数**（扇出更大 → m 更大 → 底数更大 → 层数更少） 和**范围查询**（O(k) 而不是 O(klogm⁡n)）上，不是赢在渐近阶上。

## 易混淆知识点

| 易混对象 | 区别 | **判别依据** |
| --- | --- | --- |
| B 树 n 关键字 ↔ n+1 子树 vs B+ 树 n ↔ n | 差别源于关键字的**角色** | 问"这个关键字是分隔者还是标签"：B 树的关键字**分隔**左右子树（n 个分隔切 n+1 段）；B+ 树的关键字**标记**一棵子树的最大值（一子树一标签） |
| B 树的叶结点 vs B+ 树的叶结点 | 前者是**不存在的失败结点**，后者是**真实存在、含全部关键字**的结点 | 问"这个结点里有关键字吗"：B 树的叶结点没有，B+ 树的叶结点有全部 |
| 非根结点关键字数范围 | B 树 ⌈m/2⌉−1∼m−1；B+ 树 ⌈m/2⌉∼m | 两者的子树数范围都是 ⌈m/2⌉∼m，把子树数换算成关键字数即可：B 树减 1，B+ 树不减 |
| 查找能否在中间层结束 | B 树可以，B+ 树不可以 | B+ 树内部结点的关键字是**副本**，不带记录指针，命中了也拿不到数据 |
| 查找性能"稳定"是优点还是缺点 | 是**优点**（路径长度可预测），代价是失去了"运气好时提前命中"的可能 | 问需求：要求**最坏/平均延迟可控**时稳定更值钱 |
| 最大关键字复写 vs 最小关键字复写 | 两种 B+ 树定义，画出来的树不同 | 看索引项等于子树的最大值还是最小值。**408 按最大值复写**（n ↔ n） |
| 分裂时关键字"上移"vs"复制" | B 树上移（原结点不再保留），B+ 树复制（叶结点保留） | 因为 B+ 树的叶结点必须含**全部**关键字，一个都不能少 |
| B+ 树是不是树 | 严格说**已不符合树的定义** | 叶结点之间有横向的顺序指针，存在非树边 |
| 范围查询谁快 | B+ 树 | 数一数移动次数：B+ 树是 k 次链表前进；B 树是 k 次中序遍历的上下移动 |

## 本节小结

学完本篇，应当能够：

- 说清 B+ 树相对 B 树改造了什么：**全部关键字下沉到叶结点、非叶结点只当索引、 叶结点串成有序链表**，以及这三点分别解决了 B 树的哪个痛点；
- 完整写出 m 阶 B+ 树的定义，特别是 **"内部结点关键字个数 = 子树个数"** 以及非根内部结点关键字数范围 ⌈m/2⌉∼m；
- 用"关键字是**分隔者**还是**标签**"解释 B 树与 B+ 树在关键字/子树个数关系上的差别， 做到**不靠死记**；
- 说明 B+ 树**查找必须走到叶结点**的原因（内部结点只有副本、没有记录指针）， 以及由此带来的**性能稳定**；
- 说清 B+ 树的**两个头指针**与两种查找方式（从根随机查找、从最小叶结点顺序扫描）；
- 复述 B 树与 B+ 树的完整对比表，尤其是**"叶结点"一词在两棵树里指的不是一回事**；
- 说明插入分裂时 B 树是**上移**、B+ 树是**复制**，并解释这是"关键字在 B+ 树中会重复出现"的成因；
- 从**扇出、范围查询、性能稳定、全表扫描**四个角度回答"为什么外存索引选 B+ 树"， 并能做一次数量级估算。

两条最关键的结论：**B+ 树把关键字从"分隔者"改成了"子树的最大值标签"， 这一条变化推出了它与 B 树的全部结构差异**； **叶结点链表把范围查询从 O(klogm⁡n) 降到了 O(k)，这是它统治外存索引的根本原因。**

## 教材出处

- 严蔚敏《数据结构（C 语言版）》（第 2 版）7.3.4 节「B+ 树」，p218： B+ 树是 B- 树的变形树，"严格来讲，它已不符合第 5 章中定义的树了"； 一棵 m 阶 B+ 树与 m 阶 B- 树的三条差异—— "有 n 棵子树的结点中含有 n 个关键字"； "所有的叶子结点中包含了全部关键字的信息，以及指向含这些关键字记录的指针， 且叶子结点本身依关键字的大小自小而大顺序链接"； "所有的非终端结点可以看成是索引部分，结点中仅含有其子树（根结点）中的最大（或最小）关键字"。
- 同书 p219：B+ 树"通常有两个头指针，一个指向根结点，另一个指向关键字最小的叶子结点"， 因此"可以对 B+ 树进行两种查找运算：一种是从最小关键字起顺序查找， 另一种是从根结点开始，进行随机查找"；查找时"若非终端结点上的关键字等于给定值，并不终止， 而是继续向下直到叶子结点……不管查找成功与否，每次查找都是走了一条从根到叶子结点的路径"； 插入"仅在叶子结点上进行"，分裂后"它们的双亲结点中应同时包含这两个结点中的最大关键字"； 删除"也仅在叶子结点进行，当叶子结点中最大关键字被删除时， 其在非终端结点中的值可以作为一个'分界关键字'存在"。同页还给出了 B+ 树的范围查询过程。
- 插图：殷人昆《数据结构——用面向对象方法与 C++ 描述》（第 2 版）p487 图 10.39 （按"最大关键码复写"原则组织的 4 阶 B+ 树，与 408 口径一致）。

## 相关知识

- [B 树](./b-tree.html)是 B+ 树的前身，**定义、高度推导、插入分裂与删除合并的完整流程在那一篇**， 本篇只标差异
- [折半查找](./binary-search.html)是"二路、静态"的极端，B+ 树是"多路、动态、外存"的另一端
- [分块查找](./block-search.html)的一级索引与 B+ 树的多级索引是同一思想的不同层数， B+ 树的叶链表相当于把"块间有序"贯彻到底
- [拉链法](./hash-chaining.html)与[开放定址法](./hash-open-addressing.html)在精确匹配上更快， 但**不支持范围查询与有序遍历**——这是选择树索引还是散列索引的核心依据
- B+ 树叶链表上的扫描本质就是[顺序查找](./sequential-search.html)，只是作用在已排好序的链上
- [外部排序](./../sorting/external-sort.html)与 B+ 树同属"以减少外存访问为目标"的设计
