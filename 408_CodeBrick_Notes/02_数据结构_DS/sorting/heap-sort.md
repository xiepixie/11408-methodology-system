## 知识框架

本节回答四个问题：

- 堆排序凭什么比简单选择排序快？"每趟 O(n) 选最值"是怎么变成"每趟 O(log2⁡n)"的？
- 排序阶段为什么要"堆顶与**末**元素交换"，而不是直接把堆顶取走？
- 为什么它的最好、最坏、平均三种复杂度**完全一样**？
- 它为什么不稳定？为什么它做不到用在链表上？

## 核心思想

### 先复述一下堆

**堆**是满足以下条件之一的 n 个元素的序列 {k1,k2,…,kn}：ki≥k2i 且 ki≥k2i+1（大根堆）ki≤k2i 且 ki≤k2i+1（小根堆）(1≤i≤⌊n2⌋)

把这个一维数组看成完全二叉树的顺序存储，堆就是：**所有非终端结点的值均不小于（或不大于）其左、右孩子结点的值**。于是**堆顶（根）必为序列中的最大值（或最小值）**——这正是排序要利用的性质。

**下标关系**（本篇用 1 起下标）：

| 关系 | 下标从 1 开始 | 下标从 0 开始 |
| --- | --- | --- |
| 结点 i 的双亲 | ⌊i/2⌋ | ⌊(i−1)/2⌋ |
| 结点 i 的左孩子 | 2i | 2i+1 |
| 结点 i 的右孩子 | 2i+1 | 2i+2 |
| 最后一个非终端结点 | ⌊n/2⌋ | ⌊n/2⌋−1 |

**两套编号只差一个平移**，把 1 起下标的 i 换成 0 起下标的 i+1 即可互相转换。**答题时按题面给的编号走，全程不要混用**——这是堆这一块最常见的计算错误来源。堆的完整性质与证明见 [堆](./../tree/heap.html)。

### 堆排序凭什么快

[简单选择排序](./selection-sort.html) 每趟都把未排序区从头扫到尾，上一趟比出来的大小关系一点都没留下，所以每趟要 O(n) 次比较、总共 O(n2)。

堆把这些比较结果**保存在树的结构里**：一旦堆建好，"谁大于谁"的关系就沿着每条根到叶的路径固化下来了。取走堆顶后，**只有从根到某个叶子的一条路径上的关系需要重新确认**，路径长度是树高 ⌊log2⁡n⌋+1，所以每趟只要 O(log2⁡n) 次比较。

n 趟 × O(log2⁡n) = O(nlog2⁡n)——这就是全部的提速来源。

### 排序流程

用**大根堆**得到**升序**序列（要降序就用小根堆）：

- **建初堆**：把无序序列 `A[1..n]` 调整成大根堆；
- 交换 `A[1]` 与 `A[n]`，则 `A[n]` 是最大值，**就此就位**；
- 把 `A[1..n-1]` 重新调整为大根堆；
- 交换 `A[1]` 与 `A[n-1]`，则 `A[n-1]` 是次大值；
- …… 循环 n−1 次，直到交换了 `A[1]` 与 `A[2]`，得到非递减有序序列。

**为什么是"与末元素交换"而不是"直接取走堆顶"？** 因为要**原地**排序。取走堆顶会在数组头部留下空洞，还得另找地方存放取出的元素；而末元素的位置正好是这个最大值的最终位置，交换一步就同时完成了"腾出堆顶"和"最大值归位"两件事，**一个额外单元都不用**。这就是堆排序空间复杂度 O(1) 的直接原因。

### 算法不变量

**第 k 趟结束后，数组尾部的 k 个元素是全局最大的 k 个、已按升序排好且永不再动；前 n−k 个元素构成一个合法的大根堆。**

后半句是堆排序独有的指纹。**冒泡排序第 k 趟后的尾部与它一模一样**（都是"最大的 k 个已就位"），区分只能靠前部：

- 堆排序的前部必须满足堆序（按完全二叉树逐个检查 A[i]≥A[2i] 且 A[i]≥A[2i+1]）；
- 冒泡排序的前部只经历过相邻交换，一般不满足堆序（尤其是**堆排序的前部第一个元素必是前部最大值**，而冒泡的前部首元素通常不是）。

## 操作详解

### 筛选法调整堆（sift-down）

**前提**：`A[s+1..m]` 已经都满足堆的性质，只有 `A[s]` 这一个结点可能违反。任务是把 `A[s..m]` 调整成以 `A[s]` 为根的大根堆。

**做法**（"筛选"）：把 `A[s]` 与它两个孩子中**较大**的那个比较；若 `A[s]` 不小于它，说明已经是堆，停止；否则把较大的孩子上移，`s` 下降到那个孩子的位置，继续，直到叶子。像过筛子一样，把小的关键字逐层筛下去、大的逐层选上来。c

```
// A[1..n] 存数据；假设 A[s+1..m] 已是堆，把 A[s..m] 调整为以 A[s] 为根的大根堆
void HeapAdjust(int A[], int s, int m) {
    int rc = A[s];                       // 暂存待筛选的记录，全程只搬它一次
    for (int j = 2 * s; j <= m; j *= 2) {// j 指向 s 的左孩子，沿路径向下
        if (j < m && A[j] < A[j + 1])
            j++;                         // j 指向左右孩子中较大的那个
                                         // j < m 保证右孩子存在，不越界
        if (rc >= A[j])
            break;                       // 已满足堆序，rc 就该待在位置 s 上
        A[s] = A[j];                     // 较大的孩子上移
        s = j;                           // 下降到该孩子的位置，继续
    }
    A[s] = rc;                           // 待筛记录落位
}
```

三处要点：

- **用"上移 + 最后落位"而不是"每步交换"**：交换要 3 条赋值，这里每步只写 1 条 `A[s] = A[j]`，最后再写一次 `A[s] = rc`。一条从根到叶的路径长 O(log2⁡n)，省下的是 2/3 的赋值量。
- **`j < m` 这个判断不能省**：当 `j == m` 时结点 `j` 没有右兄弟，写 `A[j+1]` 就越界了。
- **`for` 的步进是 `j *= 2`**：下降一层后，新的左孩子下标是新 `s` 的两倍，而循环变量 `j` 在循环体末尾已被赋成 `s`，所以 `j *= 2` 恰好指向新的左孩子。

**边界**：若 `2*s > m`（`s` 本身是叶子），循环一次都不进，直接 `A[s] = rc` 还原，正确。

### 建初堆

要把整个无序序列调成堆，就要把**每个结点为根的子树**都调成堆。而在完全二叉树中，**所有序号大于 ⌊n/2⌋ 的结点都是叶子**，单个结点必然已是堆。所以只需从最后一个非终端结点 ⌊n/2⌋ 开始，**倒着**（从右到左、从下到上）对每个结点调用一次筛选：c

```
void BuildMaxHeap(int A[], int n) {
    for (int i = n / 2; i >= 1; i--)   // 从最后一个非终端结点倒推到根
        HeapAdjust(A, i, n);           // 此时 A[i+1..n] 已全部满足堆序
}
```

**为什么必须倒着来？** `HeapAdjust` 的前提是"`A[s+1..m]` 已经是堆"。倒序遍历恰好保证了这个前提：处理结点 i 时，它的两棵子树（根为 2i 和 2i+1，下标都大于 i）已经被处理过了。正着来则前提不成立，一趟调不出堆。

### 堆排序主过程
c

```
void HeapSort(int A[], int n) {
    BuildMaxHeap(A, n);                  // 第一步：建初堆
    for (int i = n; i > 1; i--) {        // 共 n-1 趟
        int x = A[1];                    // 堆顶（当前最大值）
        A[1] = A[i];
        A[i] = x;                        // 与当前未排序区的末元素交换，A[i] 就此就位
        HeapAdjust(A, 1, i - 1);         // 把 A[1..i-1] 重新调整为大根堆
    }
}
```

**边界**：`n <= 1` 时 `BuildMaxHeap` 的循环不执行、排序循环也不执行，直接返回，正确。

### 建初堆的推演

以 `{49, 38, 65, 97, 76, 13, 27, 49*}` 为例（n=8，`49*` 是第二个 49）：

⌊n/2⌋=4，所以从结点 4 开始倒着筛选。

| i | 结点值 | 孩子 | 动作 | 结果 |
| --- | --- | --- | --- | --- |
| 4 | 97 | `A[8] = 49*` | 97≥49∗，不动 | 49 38 65 97 76 13 27 49* |
| 3 | 65 | `A[6] = 13`, `A[7] = 27` | 较大孩子 27，65≥27，不动 | 49 38 65 97 76 13 27 49* |
| 2 | 38 | `A[4] = 97`, `A[5] = 76` | 较大孩子 97 > 38，97 上移；38 下降到位置 4，其孩子 `A[8] = 49*` > 38，49* 上移；38 落到位置 8 | 49 **97** 65 **49*** 76 13 27 **38** |
| 1 | 49 | `A[2] = 97`, `A[3] = 65` | 较大孩子 97 > 49，97 上移；49 下降到位置 2，其孩子 `A[4]=49*`、`A[5]=76`，较大是 76 > 49，76 上移；49 落到位置 5 | **97** **76** 65 49* **49** 13 27 38 |

对应的完全二叉树：

```

           /        \

   49*(4)  49(5) 13(6)  27(7)

 38(8)
```

逐个验证堆序：97≥76,65；76≥49∗,49；65≥13,27；49∗≥38 ✓

## 复杂度分析

### 建初堆：O(n)，不是 O(nlog2⁡n)

直觉上"n/2 个非终端结点，每个筛选 O(log2⁡n)"会给出 O(nlog2⁡n)，但这个估计太松：**绝大多数结点位于树的底层，它们能下降的距离很短**。

设 n 个结点的完全二叉树深度为 h。第 i 层最多有 2i−1 个结点，而第 i 层的结点最多下移 h−i 层，每下移一层做 2 次比较（先在两个孩子间选大者、再与父比较）。于是建初堆的总比较次数∑i=h−112i−1⋅2(h−i)≤4n

即建初堆的时间是 O(n)——**与 n 成正比，不含对数因子**。（完整的求和过程见 [堆](./../tree/heap.html)。）

实测也印证这一点：n=1023 的随机数组，建初堆平均只做不到 2 千次比较，远小于上界 4n=4092，更远小于 nlog2⁡n≈104。

**对照**：若改用"从空堆开始，逐个元素插入并上浮（sift-up）"的方式建堆，代价是 O(nlog2⁡n)——因为上浮的距离由结点到**根**的距离决定，而**大多数结点离根很远**；下沉的距离由结点到**叶**的距离决定，而大多数结点离叶很近。两种建堆方式的复杂度差别，根子就在这一句上。

### 排序阶段：O(nlog2⁡n)

共 n−1 趟，每趟做一次从根到叶的筛选。第 i 趟时堆的规模是 i，路径长 ⌊log2⁡i⌋+1，每层 2 次比较：2(⌊log2⁡(n−1)⌋+⌊log2⁡(n−2)⌋+⋯+log2⁡2)<2n⌊log2⁡n⌋

即 O(nlog2⁡n)。

### 总计与"三种情况完全一样"
T(n)=O(n)⏟建初堆+O(nlog2⁡n)⏟排序阶段=O(nlog2⁡n)

**为什么最好、最坏、平均完全相同？** 因为算法的控制流几乎不受输入取值影响：

- 建初堆的循环边界只由 n 决定；
- 排序阶段固定跑 n−1 趟，每趟的筛选**最多**走到叶子，而实测表明平均性能接近最坏性能——路径长度的波动被 log 压得很小，不足以改变量级。

因此堆排序**没有"最好情况"这一说**，O(nlog2⁡n) 是一个对任意输入都成立的**保证**。这与快速排序（最坏退化成 O(n2)）形成本章最重要的一处对比。

### 空间：真正的 O(1)

只需要一个交换用的辅助单元 `x` 和筛选用的 `rc`，与 n 无关；`HeapAdjust` 写成上面的**循环**形式而非递归形式，连递归栈也没有。

这是堆排序最独特的价值：**在保证最坏 O(nlog2⁡n) 的前提下做到 O(1) 空间**。[二路归并排序](./merge-sort.html) 有同样的时间保证但要 O(n) 辅助数组；[快速排序](./quick-sort.html) 空间较小但要 O(log2⁡n)∼O(n) 的递归栈且最坏时间会退化。三者各缺一角，堆排序缺的是稳定性和常数因子。

### 稳定性：不稳定

**反例：`{21, 25, 49, 25*, 16, 08}`**（`25*` 是第二个 25，初始时排在 `25` 后面）

按 1 起下标：`A[1..6] = 21, 25, 49, 25*, 16, 08`。

| 阶段 | 数组状态 |
| --- | --- |
| 初始 | 21 25 49 25* 16 08 |
| 建初堆（i=3,2,1） | **49** 25 21 25* 16 08 |
| 第 1 趟：`A[1]`↔`A[6]`，筛选 | 25 25* 21 08 16 **49** |
| 第 2 趟：`A[1]`↔`A[5]`，筛选 | 25* 16 21 08 **25 49** |
| 第 3 趟：`A[1]`↔`A[4]`，筛选 | 21 16 08 **25* 25 49** |
| 第 4 趟：`A[1]`↔`A[3]`，筛选 | 16 08 **21 25* 25 49** |
| 第 5 趟：`A[1]`↔`A[2]` | **08 16 21 25* 25 49** |

最终结果 `08 16 21 25* 25 49` 里，`25*` 排在了 `25` **前面**——初始时 `25` 在前，排序后次序被颠倒，**故堆排序不稳定**。

**根源**：第 1 趟把堆顶 49 与末元素 08 交换后，08 从位置 6 一步跳到位置 1，随后的筛选又把 25 从位置 2 挪到位置 1、把 25* 从位置 4 挪到位置 2——两个相等元素在这一连串远距离搬动中**从未被直接比较过**（它们不是父子关系，堆序也不要求兄弟或跨子树之间有序）。与 [快速排序](./quick-sort.html)、[简单选择排序](./selection-sort.html)、[希尔排序](./shell-sort.html) 的不稳定根源完全一致。

上面那张教材原图用的正是这组数据（图中编号从 0 起），可以对照着看这两个 25 是怎么被换过去的。

### 为什么只能用于顺序结构

堆排序全程依赖"由下标 i 直接算出 2i、2i+1、⌊i/2⌋"这一能力，这是完全二叉树顺序存储的特权。链表上要找到"第 2i 个结点"必须从头遍历，每次筛选的每一步都退化成 O(n)，全部收益归零。

因此堆排序**只能用于顺序结构**。同样受此限制的还有 [折半插入排序](./binary-insertion-sort.html)、[希尔排序](./shell-sort.html)、[快速排序](./quick-sort.html)。

### 汇总

| 指标 | 结果 | 说明 |
| --- | --- | --- |
| 建初堆 | O(n)，比较次数 ≤4n | 大多数结点在底层，下沉距离短 |
| 排序阶段 | O(nlog2⁡n)，比较次数 <2n⌊log2⁡n⌋ | n−1 趟 × 每趟一条根到叶的路径 |
| 最好 / 最坏 / 平均时间 | **均为 O(nlog2⁡n)** | 控制流不受输入取值左右，是对任意输入的**保证** |
| 空间复杂度 | O(1) | 循环式筛选，无辅助数组、无递归栈 |
| 趟数 | 固定 n−1 趟（建初堆不计入） | 与初始序列无关 |
| 稳定性 | **不稳定** | 反例 `{21, 25, 49, 25*, 16, 08}` |
| 存储结构 | **只能用顺序表** | 依赖下标算术定位父子 |
| 适用场景 | n 较大；要求最坏也是 O(nlog2⁡n)；内存紧张 | 记录数较少时不宜采用——建初堆的比较次数较多，摊不开 |

## 易混淆知识点

| 对比项 | A | B | 判别依据 |
| --- | --- | --- | --- |
| **堆 vs 堆排序** | [堆](./../tree/heap.html)：数据结构（定义、调整、插入删除、优先队列、Top-K） | 本篇：用堆做排序的流程与排序视角的性质 | 问"这个问题问的是结构还是排序"。"给定数组是不是堆""插入一个元素后画出形态"属前者；"第 k 趟后的序列"属后者 |
| **建初堆的复杂度** | 自底向上**下沉**建堆：O(n) | 逐个插入**上浮**建堆：O(nlog2⁡n) | 下沉距离由结点到**叶**的距离决定（大多数结点离叶很近），上浮距离由到**根**的距离决定（大多数结点离根很远） |
| **堆排序 vs 冒泡排序的中间状态** | 两者尾部都是"最大的 k 个已就位" | 前部：堆排必满足堆序且首元素是前部最大值；冒泡一般不满足 | 按完全二叉树逐个验 A[i]≥A[2i]、A[i]≥A[2i+1] |
| **堆有序 vs 完全有序** | 堆只保证"双亲优于孩子" | 有序要求相邻处处有序 | 堆的左右孩子之间、同层之间、跨子树之间**都不要求有序**。所以"堆一定不是有序数组"是错的（升序数组是合法小根堆），但"堆一定是有序数组"更错 |
| **空间 O(1) vs O(log⁡n)** | 堆排序：O(1)（循环式筛选） | 快排：O(log2⁡n)∼O(n)（递归栈） | 有没有递归、有没有辅助数组。若把 `HeapAdjust` 写成递归形式，堆排序的空间也会变成 O(log2⁡n) |
| **1 起下标 vs 0 起下标** | 1 起：左孩子 2i，双亲 ⌊i/2⌋，最后一个非终端结点 ⌊n/2⌋ | 0 起：左孩子 2i+1，双亲 ⌊(i−1)/2⌋，最后一个非终端结点 ⌊n/2⌋−1 | 看题面数组从哪个下标开始存数据。**全程只用一套，绝不混用** |
| **最坏保证** | 堆排序、归并排序：最坏 O(nlog2⁡n) | 快速排序：最坏 O(n2) | "对任意输入都保证 O(nlog⁡n)"这类要求，快排出局 |

## 本节小结

学完本节，应该能够：

- **说清本篇与《堆》的分工**：堆的定义、调整原语、O(n) 建堆证明、插入删除、优先队列在《堆》；本篇只讲排序流程与排序视角的性质
- **默写筛选法（sift-down）与建初堆的代码**，并解释建初堆为什么必须从 ⌊n/2⌋ **倒着**做（`HeapAdjust` 的前提是右侧已成堆）
- **说清排序阶段为什么"堆顶与末元素交换"**——一步同时完成"腾堆顶"和"最大值归位"，这是 O(1) 空间的直接来源
- **给定序列画出建初堆的完整过程**与之后每一趟交换 + 调整的结果
- **写出算法不变量**："尾部 k 个是全局最大的 k 个且就位，前部是合法大根堆"，并据此把它与冒泡排序的中间状态区分开
- **推出复杂度**：建初堆比较次数 ≤4n 即 O(n)；排序阶段 <2n⌊log2⁡n⌋ 即 O(nlog2⁡n)；总计 O(nlog2⁡n)，且**三种情况完全一样**
- **说清空间复杂度是真正的 O(1)**（前提是筛选写成循环而非递归）
- **用 `{21, 25, 49, 25*, 16, 08}` 举出不稳定的反例并推到底**
- **说清它只能用于顺序结构**：依赖下标算术定位父子
- **在两套下标约定之间换算**，并做到全程不混用

三条最关键的结论：

- **建初堆是 O(n) 而不是 O(nlog2⁡n)**，根源是"下沉距离由到叶的距离决定"。
- **堆排序的 O(nlog2⁡n) 是对任意输入的保证**，不像快排会退化——代价是常数因子较大、跳跃访问对缓存不友好。
- **它是唯一同时做到"最坏 O(nlog2⁡n)"与"空间 O(1)"的比较排序**，缺的那一角是稳定性。
