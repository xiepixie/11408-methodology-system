# 归并排序（二路归并）

## 大纲定位

本篇对应 2026 大纲 **七、排序 （九）二路归并排序（merge sort）**。

分工边界：

- 本篇负责二路归并排序本身——**Merge 操作的完整实现与边界、⌈log2⁡n⌉ 趟的来历、比较次数与移动次数各自是否依赖初始序列、O(n) 辅助空间的由来、稳定性靠哪一个符号保证、以及"唯一既稳定又保证最坏 O(nlog2⁡n)"这一定位的代价**。
- **多路归并、败者树、置换-选择排序、最佳归并树**属于 [外部排序](./external-sort.html)（七（十一）），本篇只做内部排序的二路归并，不涉及磁盘 I/O。
- 与 [快速排序](./quick-sort.html) 的递归结构对称性两篇都写，本篇从归并一侧讲。
- 稳定性、"一趟"的定义等公共概念在 [排序的基本概念](./concepts.html)。

## 知识框架

本节回答五个问题：

- Merge 操作为什么必须借助辅助数组？能不能原地合并？
- 趟数为什么恰好是 ⌈log2⁡n⌉？递归写法和自底向上写法的趟数一样吗？
- 比较次数和移动次数，哪个依赖初始序列、哪个不依赖？（这一对很容易记反）
- 稳定性靠哪一行保证？改一个符号会怎样？
- 为什么说它是"唯一既稳定又保证 O(nlog2⁡n) 的比较排序"？代价是什么？

## 核心思想

归并排序基于**分治法**：

- **分解**：把待排序数组从中间一分为二；
- **递归求解**：对左右两个子数组分别递归地归并排序；
- **合并**：把两个已排好序的子数组合并成一个有序数组。

也可以从**自底向上**的角度看，这个视角在手工推演时更方便：

含 n 个记录的初始序列，可看成 n 个长度为 1 的有序子序列；两两归并得到 ⌈n/2⌉ 个长度为 2（最后一个可能是 1）的有序子序列；再两两归并……如此重复，直到得到一个长度为 n 的有序序列。

两种视角产生的**趟数与每趟的段长完全一致**，只是执行次序不同（递归是深度优先，自底向上是广度优先）。

### 算法不变量

**第 k 趟结束后，整个序列被切成若干**连续**的段，每段内部有序，段长为 2k（最后一段可能不足）。**

三个必须分清的点：

- **段是连续的**——这是它与 [希尔排序](./shell-sort.html) 中间状态的分界：希尔的有序是"隔 d 跳着看"，归并的有序是"连续切一刀"。
- **段长是 2 的幂**——第 1 趟后段长 2，第 2 趟后段长 4，第 k 趟后段长 2k。看到"段长 4 的各段各自有序"就能立刻定位到第 2 趟。
- **中途没有任何元素能保证就位**——归并排序**不满足**"每趟至少一个元素到最终位置"。一个元素在最后一趟归并中仍可能被搬到很远的地方，要到最后一趟结束才全部就位。这一点与冒泡、快排、选择、堆排全都相反。

```
原始数组: [8, 4, 5, 7, 1, 3, 6, 2]

分解:     [8,4,5,7]        [1,3,6,2]
          [8,4] [5,7]      [1,3] [6,2]
          [8][4] [5][7]    [1][3] [6][2]

合并:     [4,8] [5,7]      [1,3] [2,6]     ← 第 1 趟，段长 2
          [4,5,7,8]        [1,2,3,6]       ← 第 2 趟，段长 4
          [1,2,3,4,5,6,7,8]                ← 第 3 趟，段长 8
```

## 操作详解

### Merge：把两个相邻有序段合并

给定 `A[low..mid]` 与 `A[mid+1..high]` 两个**相邻且各自有序**的段，把它们合并成一个有序段：

- 把 `A[low..high]` 整段复制到辅助数组 `B`；
- 两个指针 `i`、`j` 分别指向 `B` 中左、右段的起点，`k` 指向 `A` 中的写入位置；
- 比较 `B[i]` 与 `B[j]`，把**不大的那个**写回 `A[k]`，对应指针后移；
- 一侧耗尽后，把另一侧剩余的元素**依次**搬回 `A`。c

```
// 把 A[low..mid] 与 A[mid+1..high] 归并；B 是与 A 等长的辅助数组
void Merge(int A[], int B[], int low, int mid, int high) {
    int i, j, k;
    for (k = low; k <= high; k++)
        B[k] = A[k];                   // 先整段复制到 B，A 中的位置随后要被覆盖
    for (i = low, j = mid + 1, k = low; i <= mid && j <= high; k++) {
        if (B[i] <= B[j])              // "<=" 而不是 "<" —— 稳定性靠这里
            A[k] = B[i++];             // 相等时优先取左段的元素
        else
            A[k] = B[j++];
    }
    while (i <= mid)  A[k++] = B[i++]; // 左段还有剩余，整体搬回
    while (j <= high) A[k++] = B[j++]; // 右段还有剩余，整体搬回
}
```

**为什么必须要辅助数组？** 因为归并是"边读边写同一片区域"：把右段的小元素写到 `A[low]` 会覆盖掉左段还没读的数据。若不复制到 `B`，就只能靠**整段后移**来腾位置，那样每次插入都是 O(n)，总复杂度退回 O(n2)——原地归并做得到，但代价是失去 O(nlog⁡n) 的保证。**"要 O(nlog⁡n) 就得掏 O(n) 空间"是归并排序的定价，不是实现上的偷懒。**

**两个 `while` 只会执行其中一个**：主循环退出时必然是 `i > mid` 或 `j > high` 二者之一成立。两个都写上是为了不用判断到底是哪一侧耗尽了。

### 递归框架
c

```
void MergeSort(int A[], int B[], int low, int high) {
    if (low < high) {                     // 长度 >= 2 才需要分
        int mid = (low + high) / 2;       // 分裂点，左段 A[low..mid]，右段 A[mid+1..high]
        MergeSort(A, B, low, mid);        // 递归排左半
        MergeSort(A, B, mid + 1, high);   // 递归排右半
        Merge(A, B, low, mid, high);      // 归并
    }
}

void MergeSortMain(int A[], int n) {
    if (n <= 1) return;
    int *B = (int *)malloc(n * sizeof(int));   // 辅助数组只申请一次，各层复用
    if (B == NULL) return;
    MergeSort(A, B, 0, n - 1);
    free(B);
}
```

两处细节：

- **辅助数组在最外层申请一次**，各层递归复用同一块 `B`。若在 `Merge` 内部申请，O(n) 次 `malloc`／`free` 的开销会成为新的瓶颈（复杂度不变，常数变得很难看）。
- **`mid = (low + high) / 2` 保证左段长度 ≥ 右段**（或相等），且 `low < high` 时必有 `low <= mid < high`，因此两个子问题都严格变小，递归一定终止。

### 逐趟推演

以 `{49, 38, 65, 97, 76, 13, 27}`（n=7）为例，按自底向上的视角逐趟列出（`[]` 表示一个有序段）：

| 趟 | 段长 | 结果 |
| --- | --- | --- |
| 初始 | 1 | [49] [38] [65] [97] [76] [13] [27] |
| 1 | 2 | [38 49] [65 97] [13 76] [27] |
| 2 | 4 | [38 49 65 97] [13 27 76] |
| 3 | 8（不足则取全部） | [13 27 38 49 65 76 97] |

n=7 时 ⌈log2⁡7⌉=3，与实际趟数吻合。注意每趟末尾可能剩下**不足一个完整段**的部分（第 1 趟的 `[27]`），它这一趟不参与归并，原样保留到下一趟。

再看一个 n=8 的例子 `{3, 8, 7, 4, 1, 5, 2, 6}`：

| 趟 | 段长 | 结果 |
| --- | --- | --- |
| 1 | 2 | [3 8] [4 7] [1 5] [2 6] |
| 2 | 4 | [3 4 7 8] [1 2 5 6] |
| 3 | 8 | [1 2 3 4 5 6 7 8] |

第 2 趟结束时，序列 `3 4 7 8 1 2 5 6` 的**两个连续 4 元段各自有序**——这就是归并排序中间状态的指纹。

## 复杂度分析

### 趟数：⌈log2⁡n⌉ 的来历

从递归树看：第 1 层是 1 个长度 n 的序列，第 2 层是 2 个长度 n/2 的序列，第 k 层是 2k−1 个长度 n/2k−1 的序列。递归到子序列长度为 1 时停止，即n2k−1=1 ⟹ k−1=log2⁡n

树高（也就是归并的趟数）为 ⌈log2⁡n⌉。**向上取整**是因为 n 不是 2 的幂时，最深的那一层只有部分子树存在，但整棵树的高度仍要覆盖它。

从自底向上看更直接：段长从 1 出发每趟翻倍，1→2→4→…，要让段长达到或超过 n，需要 ⌈log2⁡n⌉ 趟。

| n | 5 | 7 | 8 | 9 | 16 | 17 |
| --- | --- | --- | --- | --- | --- | --- |
| ⌈log2⁡n⌉ | 3 | 3 | 3 | 4 | 4 | 5 |

### 每趟的开销：移动固定，比较有波动

**这一对最容易记反，务必分清。**

设某一趟中要归并的两段总长为 L：

- **移动次数恒为 L**（把 L 个元素从 `B` 写回 `A`；若把"复制到 `B`"也算上则是 2L）。**每个元素不多不少各搬一次，与元素取值毫无关系。** 因此每趟的移动次数至多为 n（或 2n），总移动次数**至多** n⌈log2⁡n⌉—— 关键在于它**与初始序列完全无关**，只由 n 决定。

⚠️ **"n⌈log2⁡n⌉"是上界，只有 n 为 2 的幂时才取等。**n 不是 2 的幂时，某些趟会剩下一个**没有归并对象的尾段**，那一段这趟不搬动。 实测：n=7 实际搬 20 次（式子给 21）、n=9 搬 29 次（给 36）、n=100 搬 672 次（给 700）。 而且非 2 幂时**递归版与自底向上迭代版的划分方式不同，次数也不同**（n=9 分别是 29 与 33）。 这不影响本节的结论——**与初始序列无关**这一条严格成立：n=7 的全部 5040 种排列 实测移动次数**恒为 20**。做题时按 O(nlog2⁡n) 与"每趟至多 n 次"作答即可， 不必去背非 2 幂时的精确值。

- **比较次数在 min(L1,L2) 与 L−1 之间波动**。主循环每转一圈做 1 次比较，转到某一侧耗尽为止；若左段所有元素都小于右段首元素，主循环只转 L1 圈就结束（剩下的整体搬运不做比较）。所以**比较次数依赖初始序列**，教材的表述是"每一趟归并，其关键字比较次数不超过 n"。

穷举验证（n=8 的全部 8!=40320 种排列）：**总移动次数恒为 24（=3 趟 × 8），总比较次数在 12 到 17 之间浮动。**

**常见的记反**：有些说法是"归并排序的比较次数与初始序列无关、移动次数有关"，这是把两者对调了。正确的是：**移动次数无关（每个元素每趟必搬一次），比较次数有关（一侧提前耗尽就省下若干次比较）**。

顺带说明，这个"有关"只是常数级的波动（n/2 到 n 之间），**不改变量级**，所以最好、最坏、平均三种情况的时间复杂度仍然都是 Θ(nlog2⁡n)。

### 时间复杂度
T(n)=⌈log2⁡n⌉⏟趟数×O(n)⏟每趟=O(nlog2⁡n)

用递推式表述也一样：T(n)=2T(n/2)+O(n)。

**最好、最坏、平均全部是 Θ(nlog2⁡n)**，因为分治的结构由 n 唯一决定，与元素取值无关：既不会因为输入有序而变快（每个元素照样要搬 ⌈log2⁡n⌉ 次），也不会因为输入恶劣而变慢（不存在快排那样的"划分极端不均"）。

### 空间复杂度：O(n)

- **辅助数组 `B`**：与原数组等长，O(n)；
- **递归工作栈**：深度等于递归树高，O(log2⁡n)。

二者相加，O(n)+O(log2⁡n)=O(n)，由辅助数组主导。

**这是归并排序为"稳定 + 最坏 O(nlog2⁡n)"支付的全部代价。** [堆排序](./heap-sort.html) 有同样的时间保证且空间 O(1)，但不稳定；[快速排序](./quick-sort.html) 空间只要 O(log2⁡n) 且平均更快，但最坏 O(n2) 且不稳定。三者各缺一角，选谁完全取决于约束条件。

### 稳定性：稳定

保证稳定的是这一行：c

```
if (B[i] <= B[j]) A[k] = B[i++];   // 相等时取左段
else              A[k] = B[j++];
```

因为左段的元素在原序列中本来就在右段之前，**相等时优先取左段**就保证了相等元素的相对次序不变。而归并排序中不存在其他会改变相对次序的动作（每个元素只是按顺序被搬回原数组），所以整个算法稳定。

**改成 `<` 就不稳定**：反例 `[2a, 2b]`，n=2，`mid = 0`，左段 `[2a]`、右段 `[2b]`。正确版本判断 `2a <= 2b` 为真，先取 `2a`，输出 `2a, 2b`；错误版本判断 `2a < 2b` 为假，走 `else` 先取 `2b`，输出 `2b, 2a`。

### 可用于链表，而且更省

归并排序**只需要顺序访问**：Merge 从两个段的头部往后扫、结果依次追加。这一点使它成为**链表上唯一现实可用的 O(nlog⁡n) 排序**：

- 链表上归并两个有序链表**只需改指针，不需要辅助数组**——空间从 O(n) 降到 O(1)（递归写法仍需 O(log2⁡n) 的栈）；
- [快速排序](./quick-sort.html) 要双向扫描、[堆排序](./heap-sort.html) 要下标算术、[折半插入排序](./binary-insertion-sort.html) 与 [希尔排序](./shell-sort.html) 要随机存取，链表上全都不行。

这也是归并思想能被搬到 [外部排序](./external-sort.html) 的原因：磁盘上的数据只适合顺序读写，正好是归并唯一需要的访问模式。

### 汇总

| 指标 | 结果 | 说明 |
| --- | --- | --- |
| 最好 / 最坏 / 平均时间 | 均为 Θ(nlog2⁡n) | 分治结构由 n 决定，与元素取值无关 |
| 趟数 | 固定 ⌈log2⁡n⌉ | 段长每趟翻倍 |
| 移动次数 | 至多 n⌈log2⁡n⌉（复制回写口径；n 为 2 的幂时取等） | **与初始序列无关**，只由 n 决定 |
| 比较次数 | 每趟在 n/2 与 n−1 之间 | **与初始序列有关**，但不改变量级 |
| 空间复杂度 | O(n) | 辅助数组 O(n) + 递归栈 O(log2⁡n) |
| 稳定性 | **稳定** | 相等时优先取左段 |
| 存储结构 | 顺序表、链表均可 | 链表上不需要附加存储空间 |

### 与快速排序的对照

| 对比项 | 归并排序 | 快速排序 |
| --- | --- | --- |
| 最坏时间 | Θ(nlog2⁡n) | O(n2) |
| 平均时间 | Θ(nlog2⁡n) | O(nlog2⁡n)，常数因子更小 |
| 空间复杂度 | O(n)（辅助数组） | O(log2⁡n)∼O(n)（递归栈） |
| 稳定性 | **稳定** | 不稳定 |
| 递归结构 | **先递归后合并**：下去时什么都不做，回来才干活 | **先划分后递归**：下去前先干活，回来什么都不做 |
| 对初始序列 | 完全不敏感 | 敏感（已有序时最坏） |
| 链表 | 适用，且省掉辅助数组 | 难以适用 |
| 何时选它 | 要求稳定，或要求最坏也有保证，或数据在链表上 | 内存紧张、数据随机、追求平均速度 |

"先递归后合并 vs 先划分后递归"这一对称值得单独记：**两个算法的总工作量都是 O(nlog⁡n)，差别只在于这些工作是放在递归的"下行阶段"还是"上行阶段"完成的。** 快排把整理工作放在下行（划分），所以回来时无事可做；归并把整理工作放在上行（合并），所以下去时无事可做。

## 易混淆知识点

| 对比项 | A | B | 判别依据 |
| --- | --- | --- | --- |
| **比较次数 vs 移动次数谁依赖初始序列** | 移动次数：**不依赖**（每元素每趟必搬一次） | 比较次数：**依赖**（一侧提前耗尽会少比较） | 想一想"某个元素会不会因为数据不同而少搬一次"——不会。"会不会少比一次"——会 |
| **归并 vs 希尔的中间状态** | 归并：**连续段**内部有序，段长 2k | 希尔：间隔 d 的**跳跃子序列**各自有序 | 先按段长 2、4 切开看段内是否有序；不行再按 d=n/2,n/4 抽子序列验 |
| **每趟是否有元素就位** | 冒泡 / 快排 / 选择 / 堆排：**有** | 归并 / 插入 / 基数：**没有** | 归并要到最后一趟才全部就位，中途任何元素都可能被再次搬走 |
| **空间 O(n) 的来源** | 辅助数组：O(n) | 递归栈：O(log2⁡n) | 二者都要计入，但由前者主导。链表实现可以去掉前者 |
| **稳定性的分界符号** | `B[i] <= B[j]`：稳定 | `B[i] < B[j]`：不稳定 | 反例 `[2a, 2b]`，两版本输出正好相反 |
| **归并趟数 vs 快排趟数** | 归并：固定 ⌈log2⁡n⌉ 趟 | 快排：趟数 = 递归深度，随输入变 | 归并的分裂点由下标决定，快排的分裂点由数据决定 |
| **内部归并 vs 外部归并** | 本篇：二路归并，优化目标是比较与移动次数 | [外部排序](./external-sort.html)：多路归并，优化目标是磁盘 I/O 趟数 | 判据是"排序过程中要不要访问外存" |

## 本节小结

学完本节，应该能够：

- **默写 Merge 的完整实现**，说清为什么必须借助辅助数组、为什么两个收尾 `while` 只会执行其中一个、为什么辅助数组要在最外层申请
- **写出算法不变量**："第 k 趟后是若干**连续**段各自有序，段长 2k"，并据此在中间状态里认出归并排序、判断是第几趟
- **推出趟数 ⌈log2⁡n⌉**：段长每趟翻倍，或递归树高 log2⁡n；并说明为什么是向上取整
- **说准"移动次数与初始序列无关、比较次数与初始序列有关"**，别记反
- **推出时间复杂度**：⌈log2⁡n⌉ 趟 × 每趟 O(n)，三种情况全部是 Θ(nlog2⁡n)
- **说清 O(n) 空间的两个来源**（辅助数组 + 递归栈）以及链表实现能省掉哪一个
- **证明其稳定性**，并给出把 `<=` 改成 `<` 的反例
- **说清"唯一既稳定又保证最坏 O(nlog2⁡n) 的比较排序"这句话，代价是 O(n) 空间**
- **与快排做七维对照**，并用"工作放在下行还是上行"概括两者递归结构的对称

三条最关键的结论：

- **趟数 ⌈log2⁡n⌉、每趟 O(n)**——归并排序的全部复杂度结论都从这两句推出来。
- **移动次数固定、比较次数波动**，这是它与简单选择排序（比较固定、移动波动）恰好相反的一对。
- **稳定 + 最坏有保证 + 可用于链表**，三者的共同代价是 O(n) 辅助空间。

## 教材出处

- 二路归并排序的基本思想（"可看成 n 个有序的子序列，每个长度为 1，然后两两归并，得到 ⌈n/2⌉ 个长度为 2 或 1 的有序子序列，如此重复"）、以 {49,38,65,97,76,13,27} 为例的逐趟过程（图 8.13）：严蔚敏《数据结构（C 语言版）》（第 2 版），p254
- 相邻两个有序子序列归并的算法步骤与算法描述（算法 8.10 `Merge`，其中判断用 `R[i].key <= R[j].key`）、"假设每个子序列的长度为 h，则一趟归并排序需调用 ⌈n/2h⌉ 次 merge，整个归并排序需进行 ⌈log2⁡n⌉ 趟"、递归实现（算法 8.11）：同书 p255
- "当有 n 个记录时，需进行 ⌈log2⁡n⌉ 趟归并排序，每一趟归并，其关键字比较次数不超过 n，元素移动次数都是 n，因此归并排序的时间复杂度为 O(nlog2⁡n)"；"用顺序表实现归并排序时，需要和待排序记录个数相等的辅助存储空间，所以空间复杂度为 O(n)"：同书 p256
- 算法特点："是稳定排序"；"可用于链式结构，且不需要附加存储空间，但递归实现时仍需要开辟相应的递归工作栈"：同书 p256
- "直接插入排序、归并排序都易于在链表上实现"：同书 p269
- 各种内部排序方法比较表中归并排序"最好、最坏、平均均为 O(nlog2⁡n)，空间 O(n)，稳定"：同书 p267
