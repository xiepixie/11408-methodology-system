# 简单选择排序

## 大纲定位

本篇对应 2026 大纲 **七、排序 （五）简单选择排序**（也称直接选择排序）。

分工边界：

- 本篇负责简单选择排序本身——**算法不变量、比较次数为什么恒为 n(n−1)/2、移动次数为什么最多只有 3(n−1) 次、不稳定的具体反例与它的根源、以及"记录很大时反而它更划算"这条选型结论**。
- 选择类排序的改进版——用堆结构复用上一趟的比较结果——在 [堆排序](./heap-sort.html)；两篇的分界就是"选最值时是否利用了前一趟的信息"。
- 与冒泡排序的四维对照（比较次数是否随输入变、交换次数、稳定性、适用记录大小）本篇给出，横向总表在 [排序算法对比](./comparison.html)。
- 稳定性、"一趟"的定义等公共概念在 [排序的基本概念](./concepts.html)。

## 知识框架

本节回答四个问题：

- 每一趟结束后数组处于什么状态？为什么它的前缀比插入排序的前缀"强"？
- 为什么它的比较次数与初始序列**完全无关**，连"已经有序"都省不掉一次比较？
- 为什么它的移动次数少到 3(n−1)？什么场景下这一条能盖过它 O(n2) 的劣势？
- 它为什么不稳定？不稳定到底是"选择"这个思想带来的，还是"交换"这个实现手法带来的？

## 核心思想

每一趟从**未排序区**中扫描出关键字最小的记录，与未排序区的**第一个位置**交换，该位置就此确定，未排序区缩小一个。

- **选最小**：在未排序区 `[i, n-1]` 中找到最小元素的下标 `k`
- **交换归位**：把 `a[k]` 与 `a[i]` 交换，`a[i]` 到达最终位置
- **缩小范围**：`i++`，重复，共 n−1 趟

```
第0趟: [——————— 未排序区 ———————]
第1趟: [已排序] [———— 未排序区 ————]
第2趟: [已排序——] [——— 未排序区 ———]
 ...
第n-1趟: [———— 已排序 ————————] [待排]
```

### 算法不变量

**第 k 趟结束后，前 k 个位置上放的是整个序列中最小的 k 个元素，且已按升序排好、位置永不再变；后 n−k 个元素的内部次序则是任意的。**

前半句的"**全局最小的 k 个**"是这条不变量的分量所在，比插入排序的"前 k 个局部有序"强：

|  | 插入排序第 k 趟后 | 简单选择排序第 k 趟后 |
| --- | --- | --- |
| 前缀 | 前 k+1 个**局部有序**，可能被后来的元素插队 | 前 k 个是**全局最小的 k 个**，永不再动 |
| 后缀 | 与初始序列**逐位相同** | 因为交换，通常已经乱了 |

这两行就是 [由中间状态反推排序算法](./identify-state.html) 区分插入类与选择类的全部依据。判别方法很机械：**把前缀里的最大值与后缀里的最小值比一下**——前者不大于后者，就是"已就位"；否则只是"局部有序"。

为什么每趟只用交换一次就能保证"选出的是全局最小"？因为内层循环把未排序区**整个扫了一遍**，`k` 记录的是这一趟见过的最小者的下标，扫完后 `a[k]` 就是未排序区的最小值。

## 操作详解
c

```
void SelectionSort(int a[], int n) {
    for (int i = 0; i < n - 1; i++) {      // 共 n-1 趟，最后一个元素自动就位
        int k = i;                          // k 指向本趟见过的最小元素
        for (int j = i + 1; j < n; j++) {   // 扫遍未排序区 [i+1, n-1]
            if (a[j] < a[k])                // 严格小于才更新，相等时保留靠前的那个
                k = j;
        }
        if (k != i) {                       // 已在位就不做无谓的交换
            int tmp = a[i];
            a[i] = a[k];
            a[k] = tmp;                     // 一次交换 = 3 条赋值
        }
    }
}
```

三处细节：

- **外层只到 `n - 2`**：前 n−1 个位置都确定后，剩下的那一个必然是最大值，无须再选。
- **`if (k != i)` 只省移动，不省比较**：内层循环的执行次数完全由下标决定，与元素取值无关——这正是"比较次数恒定"的根源。
- **内层用 `<` 而不是 `<=`**：相等时不更新 `k`，本趟选中的是**最靠前**的那个最小值。这一条**减少了**不稳定发生的机会，但并不能消除它（见下文反例）。
- **边界**：`n <= 1` 时外层循环不执行，安全。

### 逐趟推演

以 `{49, 38, 65, 97, 49*, 13, 27, 76}` 为例（`49*` 是第二个 49，用于观察稳定性），括号内为已就位部分：

| 趟 | 未排序区 | 选出的最小值 | 交换 | 本趟结果 |
| --- | --- | --- | --- | --- |
| 初始 | — | — | — | 49 38 65 97 49* 13 27 76 |
| 1 | [0,7] | a[5] = 13 | a[0] ↔ a[5] | (**13**) 38 65 97 49* **49** 27 76 |
| 2 | [1,7] | a[6] = 27 | a[1] ↔ a[6] | (13 **27**) 65 97 49* 49 **38** 76 |
| 3 | [2,7] | a[6] = 38 | a[2] ↔ a[6] | (13 27 **38**) 97 49* 49 **65** 76 |
| 4 | [3,7] | a[4] = 49* | a[3] ↔ a[4] | (13 27 38 **49***) **97** 49 65 76 |
| 5 | [4,7] | a[5] = 49 | a[4] ↔ a[5] | (13 27 38 49* **49**) **97** 65 76 |
| 6 | [5,7] | a[6] = 65 | a[5] ↔ a[6] | (13 27 38 49* 49 **65**) **97** 76 |
| 7 | [6,7] | a[7] = 76 | a[6] ↔ a[7] | (13 27 38 49* 49 65 **76**) **97** |

**第 1 趟就把不稳定演出来了**：13 与 `a[0] = 49` 交换，`49` 被一脚踢到下标 5，而 `49*` 原本在下标 4——两个相等元素的先后关系当场翻转。最终结果 `13 27 38 49* 49 65 76 97` 里，`49*` 排在 `49` 前面。

共 7 趟（n−1），每趟扫一遍未排序区、最多做 1 次交换。**趟数固定，与初始序列无关。**

### 不稳定性：一个最小反例

**最小反例：`{2a, 2b, 1}`**（用下标区分两个 2）

| 趟 | 操作 | 结果 |
| --- | --- | --- |
| 初始 | — | 2a 2b 1 |
| 1 | 未排序区 [0,2] 的最小值是 a[2] = 1，交换 a[0] ↔ a[2] | **1** 2b **2a** |
| 2 | 未排序区 [1,2] 的最小值是 a[1] = 2b，`k == i`，不交换 | 1 2b 2a |

排序后 `2b` 排在 `2a` 前面，相对次序被改变，**故不稳定**。

**根源**：`a[i]` 与 `a[k]` 的交换是**远距离**的——`a[i]` 被直接甩到下标 `k` 处，中间凡是与它关键字相等的元素，都被它一次性跨了过去。这与冒泡排序形成鲜明对照：冒泡只交换**相邻**元素，一个元素想越过另一个元素，必须先与它直接比较一次，而相等时那次比较不会触发交换，所以永远越不过去。

**一条值得知道的分界**：教材在讨论算法特点时指出，"就选择排序方法本身来讲，它是一种稳定的排序方法，但……不稳定现象是因为上述实现选择排序的算法采用'交换记录'的策略所造成的，改变这个策略，可以写出不产生'不稳定现象'的选择排序算法"。也就是说，**不稳定来自"交换"这个实现手法，而不是"选择"这个思想**——若把"交换"改成"把区间整体后移一位、再把最小者插到前面"，就能做到稳定，但移动次数会退回 O(n2)，把它唯一的优势丢掉。

408 语境下的"简单选择排序"默认就是上面那个**交换实现**，所以结论按 **不稳定** 记；上面这段是为了让你明白不稳定的来源，而不是让你改答案。

### 把它改成稳定的：代价是什么

既然不稳定来自"交换"，那就把交换换掉：找到最小者 `a[k]` 后，**把 `a[i..k-1]` 整体后移一位，再把最小者放到 `a[i]`**——这样最小者是"插"进去的，不会有任何元素被跨越。c

```
void StableSelectionSort(int a[], int n) {
    for (int i = 0; i < n - 1; i++) {
        int k = i;
        for (int j = i + 1; j < n; j++)
            if (a[j] < a[k]) k = j;          // 仍取最靠前的最小值
        int t = a[k];
        for (int j = k; j > i; j--)
            a[j] = a[j - 1];                 // a[i..k-1] 整体后移一位
        a[i] = t;                            // 最小者插到最前
    }
}
```

验证：`{2a, 2b, 1}` → `{1, 2a, 2b}`，`{49, 38, 65, 97, 49*, 13, 27, 76}` → `13 27 38 49 49* 65 76 97`——两组相等元素的相对次序都保住了（3000 组随机数据实测排序正确且稳定）。

**但代价很重**：后移操作的次数与"最小者离目标位置多远"成正比，最坏情况下每趟要搬 O(n) 次，总移动次数退回 Θ(n2)：

| n（逆序输入） | 10 | 50 | 100 |
| --- | --- | --- | --- |
| 移动式（稳定）的移动次数 | 63 | 1 323 | 5 148 |
| 交换式（不稳定）的移动次数 3(n−1) | 27 | 147 | 297 |

**换来了稳定性，丢掉的正是简单选择排序唯一的优势——O(n) 的移动次数。** 而且此时它相对 [直接插入排序](./insertion-sort.html) 已经全面落后（同样 Θ(n2) 的移动，比较次数却固定为 n(n−1)/2，不会因为输入有序而下降）。

所以这个变体只有理论意义：它证明了"不稳定来自交换策略而非选择思想"，但没有实用价值。**408 语境下的简单选择排序就是上面的交换式版本，结论按不稳定记。**

## 复杂度分析

### 比较次数：恒定，与初始序列无关

第 i 趟（i 从 0 计）内层循环从 j=i+1 走到 j=n−1，执行 n−1−i 次比较。这个次数**只由下标决定**——循环边界里没有任何元素的取值参与，所以不管输入是正序、逆序还是随机，执行次数一模一样：KCN=∑i=0n−2(n−1−i)=(n−1)+(n−2)+⋯+1=n(n−1)2≈n22

于是得到一条独特结论：**简单选择排序的最好、最坏、平均时间复杂度全部是 Θ(n2)，不存在"已有序就变快"的情形**。这与冒泡排序（有序时 1 趟终止）、直接插入排序（有序时 n−1 次比较）完全不同。

### 移动次数：最多 3(n−1)

每趟最多做 1 次交换（3 条赋值），共 n−1 趟：

| 输入 | 交换次数 | 移动次数 |
| --- | --- | --- |
| 已有序 | 0（每趟 `k == i`） | **0** |
| 最坏 | n−1 | 3(n−1) |

**这是简单选择排序唯一的优势，而且是一个量级上的优势**：移动次数是 O(n) 而不是 O(n2)。当每条记录很大（关键字之外还挂着大量数据项）时，搬运一条记录的代价远高于比较两个关键字，此时：

- 直接插入排序要移动约 n2/4 次；
- 冒泡排序要移动约 3n2/4 次；
- 简单选择排序最多移动 3(n−1) 次。

差了整整一个数量级。教材据此给出的结论是："移动记录次数较少，当每一记录占用的空间较多时，此方法比直接插入排序快。"

### 汇总

| 指标 | 结果 | 说明 |
| --- | --- | --- |
| 比较次数 | 恒为 n(n−1)2 | **与初始序列无关** |
| 最好移动次数 | 0 | 已有序，每趟 `k == i` 不交换 |
| 最坏移动次数 | 3(n−1) | 每趟都交换 |
| 时间复杂度（三种情况） | 均为 Θ(n2) | 比较次数恒定，**不存在最好 O(n)** |
| 空间复杂度 | O(1) | 只需 `k` 与交换用的 `tmp` |
| 趟数 | 固定 n−1 趟 | 与初始序列无关 |
| 稳定性 | **不稳定** | 反例 `{2a, 2b, 1}` |
| 存储结构 | 顺序表、链表均可 | 只需顺序扫描找最小值 |

### 与冒泡排序的对照

| 对比项 | 简单选择排序 | 冒泡排序 |
| --- | --- | --- |
| 比较次数 | 恒 n(n−1)/2 | 最好 n−1，最坏 n(n−1)/2 |
| 交换次数 | 最多 n−1 | 等于逆序对数，最坏 n(n−1)/2 |
| 移动次数 | 最多 3(n−1) | 最坏 3n(n−1)/2 |
| 对输入是否敏感 | 否 | 是（有序时 1 趟终止） |
| 稳定性 | 不稳定 | 稳定 |
| 空间复杂度 | O(1) | O(1) |
| 何时该选它 | **记录很大**、移动代价高 | 输入**基本有序**、要求稳定 |

### 例题：数清比较次数与移动次数

对序列 (3,8,7,4,1,5,2,6) 做升序简单选择排序，比较多少次？移动多少次？

**解**：

**比较次数**与初始序列无关，直接套公式：KCN=n(n−1)2=8×72=28

**移动次数**要逐趟看有没有发生交换：

| 趟 i（0 起） | 未排序区 | 最小值位置 | `k != i`？ | 本趟结果 |
| --- | --- | --- | --- | --- |
| 0 | [0,7] | a[4]=1 | 是，交换 | **1** 8 7 4 3 5 2 6 |
| 1 | [1,7] | a[6]=2 | 是，交换 | 1 **2** 7 4 3 5 8 6 |
| 2 | [2,7] | a[4]=3 | 是，交换 | 1 2 **3** 4 7 5 8 6 |
| 3 | [3,7] | a[3]=4 | **否**，不交换 | 1 2 3 **4** 7 5 8 6 |
| 4 | [4,7] | a[5]=5 | 是，交换 | 1 2 3 4 **5** 7 8 6 |
| 5 | [5,7] | a[7]=6 | 是，交换 | 1 2 3 4 5 **6** 8 7 |
| 6 | [6,7] | a[7]=7 | 是，交换 | 1 2 3 4 5 6 **7** 8 |

共 6 次交换（第 3 趟因为 4 已在位而省掉），移动 6×3=18 次。

**对照**：同一序列用 [冒泡排序](./bubble-sort.html) 要交换 16 次（= 逆序对数）、移动 48 次；用 [直接插入排序](./insertion-sort.html) 要后移 16 次、移动约 16 条赋值。**简单选择排序的移动量只有它们的三分之一到八分之一**——这就是"记录很大时选它"的量化依据。

### 为什么它能被改进成 O(nlog⁡n)

简单选择排序每一趟都把未排序区**从头扫到尾**，上一趟辛辛苦苦比出来的大小关系，下一趟一点都没用上——这才是 n(n−1)/2 次比较的来源。

在 n 个关键字中选出最小值，至少要 n−1 次比较（每个非最小元素至少要输一次）；但**选次小值并不需要再做 n−2 次比较**，因为次小值只可能出现在"直接输给最小值的那些元素"里。把这个信息用一棵树保存下来，每次只需沿一条路径调整，每趟比较次数就从 O(n) 降到 O(log2⁡n)，总复杂度变成 O(nlog2⁡n)——这就是 [堆排序](./heap-sort.html) 的由来。

## 易混淆知识点

| 对比项 | A | B | 判别依据 |
| --- | --- | --- | --- |
| **前缀有序 vs 前缀就位** | 插入排序：前缀局部有序 | 选择排序：前缀是全局最小的 k 个 | 把前缀最大值与后缀最小值比一下：前者 ≤ 后者则已就位 |
| **哪些算法比较次数与初始序列无关** | 简单选择（恒 n(n−1)/2）、堆排序、归并排序、基数排序 | 直接插入、冒泡、快排 | 看内层循环的**边界**是由下标决定还是由元素取值决定 |
| **是否存在"最好情况更快"** | 简单选择：**不存在**，三种情况都是 Θ(n2) | 冒泡、直接插入：存在，最好 O(n) | 已有序输入下比较次数会不会下降。选择排序的双重循环照跑不误 |
| **不稳定的根源** | 选择排序：**远距离交换**跨过了相等元素 | 冒泡排序：只有**相邻交换**，跨不过去 | 问"元素能不能一步跳过与它相等的元素"。能跳就可能不稳定 |
| **移动次数量级** | 简单选择：O(n)，最多 3(n−1) | 插入 O(n2)、冒泡 O(n2) | 每趟最多交换 1 次 vs 每消一个逆序对就要动一次 |
| **简单选择 vs 堆排序** | 简单选择：每趟重新扫全部未排序区，O(n) 次比较 | 堆排序：复用上一趟的比较结果，每趟 O(log2⁡n) 次 | 判据是"有没有把上一趟的胜负关系保存下来" |

## 本节小结

学完本节，应该能够：

- **写出算法不变量**："第 k 趟后前 k 个是全局最小的 k 个且已就位"，并说清它比插入排序的前缀强在哪
- **给定序列逐趟写出结果**，包括每趟选中谁、与谁交换
- **证明比较次数恒为 n(n−1)/2**：内层循环边界只含下标、不含元素取值，因此与输入完全无关；并据此指出它**不存在最好 O(n)**
- **说清移动次数最多 3(n−1)**，以及这一条在"记录很大"场景下能盖过 O(n2) 的原因
- **用 `{2a, 2b, 1}` 举出不稳定的反例并推到底**，并解释根源是"远距离交换跨越了相等元素"，而不是"选择"这个思想
- **与冒泡排序做四维对照**（比较次数是否随输入变、交换次数、稳定性、适用记录大小）
- **说清它被改进成堆排序的动机**：每趟从头扫一遍，白白丢掉了上一趟的比较结果

两条最关键的结论：

- **比较次数恒为 n(n−1)/2、与输入完全无关**——它是全章唯一"三种情况完全一样"的比较类算法。
- **移动次数只有 O(n)**——这是它在所有 O(n2) 算法里唯一不可替代的地方。

- 算法特点，含"就选择排序方法本身来讲，它是一种稳定的排序方法，但图 8.6 所表现出来的现象是不稳定的，这是因为上述实现选择排序的算法采用'交换记录'的策略所造成的"、"可用于链式存储结构"、"移动记录次数较少，当每一记录占用的空间较多时，此方法比直接插入排序快"：同书 p247
- "在 n 个关键字中选出最小值至少要进行 n−1 次比较，然而继续在剩余的 n−1 个关键字中选择次小值并非一定要进行 n−2 次比较，若能利用前 n−1 次比较所得信息，则可减少以后各趟选择排序中所用的比较次数"（这是通向堆排序的动机）：同书 p247–p248
