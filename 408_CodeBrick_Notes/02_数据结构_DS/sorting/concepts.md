本节回答四个问题：

## 排序的定义

**排序**（Sorting）是按关键字的**非递减**或**非递增**顺序，对一组记录重新排列的操作。

设含 n 个记录的序列为{R1, R2, …, Rn}

其相应的关键字序列为 {K1, K2, …, Kn}。排序就是**确定 1,2,…,n 的一个排列 p1,p2,…,pn**，使得Kp1≤Kp2≤⋯≤Kpn

从而序列 {Rp1, Rp2, …, Rpn} 按关键字有序。

这个定义里有两处值得停一停：

**① 排序的对象是"记录"，比较的依据是"关键字"。** 一条记录通常还带着关键字之外的数据项（学号是关键字，姓名、成绩是其他数据项）。正因为记录里有"关键字之外的东西"，**交换两条记录的代价才可能远大于比较两个关键字**——这是后面"移动次数"要单独统计的根本原因，也是"记录很大时宁可多比较少移动"这类选型判断的来源。

**② 排序结果不一定唯一。** 当所有关键字互不相同时，满足上式的排列 p 只有一个，任何正确的排序算法给出的结果都相同。**只有当存在两个或两个以上关键字相等的记录时，合法的排列才不止一个**——稳定性这个概念才有意义。换句话说，**关键字全不相同的输入，永远看不出算法稳不稳定**。

## 排序的稳定性

### 定义

设 Ki=Kj（1≤i≤n，1≤j≤n，i≠j），且在排序**前**的序列中 Ri 领先于 Rj（即 i<j）。

- 若在排序**后**的序列中 Ri **仍**领先于 Rj，则称所用的排序方法是**稳定的**；
- 若**可能**使排序后的序列中 Rj 领先于 Ri，则称该方法是**不稳定的**。

```
排序前:  3a  1  3b  2     （3a 与 3b 关键字相同，3a 在 3b 前面）
稳定:    1  2  3a  3b     （3a 仍在 3b 前面 ✓）
不稳定:  1  2  3b  3a     （3a 跑到 3b 后面 ✗）
```

### 判定：一个反例就够了，一次"没出事"什么都证明不了

稳定性是**针对所有可能输入而言的算法性质**，不是某一次运行的观感。由此得到两条不对称的判定规则：

| 要证明 | 需要做什么 | 为什么 |
| --- | --- | --- |
| 该算法**不稳定** | 举出**一个**具体的输入序列，逐趟推到底，指出某两个相等元素的次序被颠倒 | 定义里写的是"**可能**使 Rj 领先于 Ri"，存在一个反例即成立 |
| 该算法**稳定** | 证明算法中**所有**会改变相对次序的动作都不会发生在相等元素之间 | 要覆盖所有输入，举再多"这次没乱"的例子也不算证明 |

所以本章每一篇讲到"不稳定"时都必须给出**具体反例序列**：快排 `[3a, 3b, 2]`、简单选择排序 `[2a, 2b, 1]`、希尔排序 `[2a, 2b, 1, 3]`、堆排序 `[21, 25, 49, 25*, 16, 08]`——只写"不稳定"三个字是不够的，因为你无法据此判断一个没见过的变体算法稳不稳定。

反过来，稳定的四种算法各自的"稳定性来源"都能一句话说清，而且都落在**同一个位置：相等时选谁**：

| 算法 | 保证稳定的那一行 | 破坏它会怎样 |
| --- | --- | --- |
| 直接插入 | 从后向前扫描，遇到 `A[j] == temp` 就**停止**，把 temp 放在它后面 | 把 `A[j] > temp` 写成 `A[j] >= temp`，相等元素会被越过，变不稳定 |
| 折半插入 | 折半查找中 `A[mid] == temp` 时令 `low = mid + 1`，往**右**半区找 | 改成往左半区找，插入位置会落到相等元素之前，变不稳定 |
| 起泡 | 相邻元素**相等时不交换**（判据是 `>` 而不是 `>=`） | 写成 `>=` 会让相等元素互换，变不稳定 |
| 二路归并 | 两段首元素相等时**优先取左段**（判据是 `<=` 而不是 `<`） | 写成 `<` 会让右段的相等元素抢到前面，变不稳定 |

**记住这张表比记口诀有用**：它告诉你稳定性不是算法的玄学属性，而是代码里某一个比较符号的直接后果。

### 稳定性速查

| 不稳定 | 稳定 |
| --- | --- |
| **快**速排序 | 直接**插**入排序 |
| 简单**选**择排序 | 折半插入排序 |
| **希**尔排序 | **冒**泡（起泡）排序 |
| **堆**排序 | **归**并排序 |
|  | **基**数排序 |

口诀：**快选希堆**不稳定，其余全稳定。

**一条常被误用的推论**：稳定性与效率**无关**。快速排序平均最快但不稳定，归并排序稳定但要 O(n) 辅助空间。不稳定不等于"不好"，它只是意味着**在多关键字场景下不能拿它做后一轮排序**（见下）。

### 稳定性在什么时候真的有用

只有一种场景需要稳定性，但它非常常见——**多关键字排序**。

要把学生记录先按"班级"、班级相同再按"成绩"排列，做法是：

- 先按**次关键字**（成绩）排一遍，用什么算法都行；
- 再按**主关键字**（班级）排一遍，**这一遍必须用稳定排序**。

第 2 遍稳定，才能保证同一个班级内部仍保持第 1 遍留下的成绩次序。若第 2 遍用了快排，同班的记录会被打乱，第 1 遍白做。

这条正是 [基数排序](./radix-sort.html) 正确性的基础：基数排序就是"从低位到高位做 d 遍单关键字排序"，每一遍都必须稳定，否则低位排好的结果会被高位那一遍毁掉。

## 内部排序与外部排序

| 分类 | 定义 | 关键约束 |
| --- | --- | --- |
| **内部排序** | 待排序记录**全部存放在内存**中完成排序 | 瓶颈是 CPU 的比较与移动次数 |
| **外部排序** | 记录数量太大，内存一次容纳不下，排序过程中**尚需对外存进行访问** | 瓶颈是**磁盘读写次数**，不是比较次数 |

两者的分界不在"数据多不多"，而在**排序过程中要不要访问外存**。这条分界导致优化目标完全不同：内部排序省的是比较与移动，外部排序省的是 I/O 趟数——同一个"归并"操作，在内部排序里追求"每层 O(n) 次比较"，在外部排序里追求"归并趟数 ⌈logk⁡m⌉ 尽量小"。详见 [外部排序](./external-sort.html)。

## 内部排序的分类

内部排序的过程，本质上是**逐步扩大"有序序列区"、缩小"无序序列区"**的过程。使有序区中记录数目增加一个或几个的操作，称为**一趟排序**。

按"用什么办法扩大有序区"，可以分成五类：

| 分类 | 扩大有序区的办法 | 代表算法 | 这一类的共同特征 |
| --- | --- | --- | --- |
| **插入类** | 把无序区的一个记录**插入**到有序区的适当位置 | 直接插入、折半插入、希尔 | 有序区是**前缀**，但前缀里的元素**不一定已在最终位置** |
| **交换类** | 通过**交换**把无序区中最大/最小的记录换到位 | 起泡、快速 | 每趟**至少有一个记录到达最终位置** |
| **选择类** | 从无序区**选出**最小/最大的记录接到有序区末尾 | 简单选择、堆 | 每趟**恰有一个记录到达最终位置**，且是全局最值 |
| **归并类** | 把两个有序区**合并**成一个更大的有序区 | 二路归并 | 有序区是**若干等长段**，段长每趟翻倍 |
| **分配类** | 不比较关键字，按关键字各位的值做**分配与收集** | 基数 | 唯一能突破 Ω(nlog⁡n) 下界的一类 |

这张表右列不是背景知识，它是 [由中间状态反推排序算法](./identify-state.html) 的全部依据：**一趟结束后数组长什么样，完全由"这一类算法怎么扩大有序区"决定**。

## 评价指标

### 时间：比较次数与移动次数要分开数

对内部排序（以顺序表存储为前提），时间主要花在两件事上：

- **关键字之间的比较**（KCN，Key Comparison Number）
- **记录的移动**（RMN，Record Movement Number）

为什么不合成一个数？因为二者的**单位代价差得很远，而且互相独立**：

- 一次**交换**要写三条赋值语句（`t = a; a = b; b = t;`），而插入类的一次**后移**只写一条。所以同为 O(n2)，直接插入排序的实际移动开销约为起泡排序的三分之一。
- 记录本身越大（关键字之外的数据项越多），移动一条记录越贵，比较却不变贵。**记录很大时应当选"移动次数少"的算法**——简单选择排序最坏也只移动 3(n−1) 次，这是它唯一的优势。
- 两个指标对初始序列的敏感性也不同：**简单选择排序的比较次数恒为 n(n−1)/2、与初始序列无关，移动次数却随初始序列变化**；**折半插入排序的比较次数几乎只由 n 决定，移动次数却完全随初始序列变化**。合并成一个数，这些结论就全看不见了。

因此本章每一篇都会分别给出**最好、最坏、平均**三种情况下的比较次数与移动次数，并说明各自在什么输入上取到。

### 空间：只数辅助空间

空间复杂度只统计**辅助空间**——除了存放待排序记录本身所占空间之外，算法执行还需要的其他存储。理想值是 O(1)，即与数据量无关（这样的算法称为**原地排序**）。

三个必须分清的来源：

| 辅助空间来源 | 出现在 | 量级 |
| --- | --- | --- |
| 暂存一条记录的单元（哨兵 / temp） | 插入类、交换类、选择类 | O(1) |
| **递归工作栈** | 快速排序（O(log2⁡n)∼O(n)）、递归写法的归并排序（O(log2⁡n)） | 与递归深度同阶 |
| **辅助数组 / 队列** | 归并排序的 B[]（O(n)）、基数排序的 r 个队列（O(r)） | 与数据规模或基数同阶 |

快速排序常被称作"原地排序"，指的是它**不需要与 n 同阶的辅助数组**；但它的递归栈是真实开销，最坏可达 O(n)。说快排空间 O(1) 是错的。

### 稳定性

见上文。它不是效率指标，是**功能指标**——决定这个算法能不能用在多关键字场景的后一轮。

## 比较类排序的下界：为什么快不过 O(nlog⁡n)

**结论**：任何**基于关键字比较**的排序算法，在最坏情况下至少需要 Ω(nlog⁡n) 次比较。

**推导**（决策树模型）：

- 把算法的执行过程画成一棵**判定树**：每个内部结点是一次"Ki 与 Kj 谁大"的比较，比较只有两种结果，所以是**二叉树**；每条根到叶的路径对应一次完整执行，叶结点是算法输出的那个排列。
- 算法必须对 n 个元素的**每一种**初始排列都给出正确结果，而 n 个元素共有 n! 种排列，不同排列需要不同的输出动作，因此**叶结点数 ≥n!**。
- 高度为 h 的二叉树最多有 2h 个叶结点，于是 2h≥n!，即 h≥log2⁡(n!)。
- 由 Stirling 公式 n!≈2πn(n/e)n，取对数得 log2⁡(n!)=Θ(nlog2⁡n)。

树高 h 就是**最坏情况下的比较次数**，故最坏比较次数 ≥Θ(nlog2⁡n)。

**这条下界的适用边界**（比结论本身更重要）：

- 它只约束**以"比较关键字"为唯一信息来源**的算法。[基数排序](./radix-sort.html) 与 [计数排序](./counting-sort.html) 不比较关键字，而是直接用关键字的**取值**去索引桶，信息来源不同，所以不受此界约束，可以做到 O(d(n+r))、O(n+k)。
- 它是**最坏情况**下界，不排除某个算法在特定输入上跑出 O(n)（直接插入排序对已有序输入只比较 n−1 次）。
- 归并排序与堆排序的最坏 O(nlog2⁡n) **正好达到这个下界**，因此在比较类排序里，它们的最坏情况已经无法再改进。

## "一趟"在不同算法里指什么

这是整章最容易搞混的一处，也是"给定第 k 趟结果反推算法"这类问题的前提。统一的定义是"**使有序区记录数目增加的一次操作**"，但落到每个算法上具体指什么，差别很大：

| 算法 | 一趟 = | 一趟后有序区变成 | 趟数 |
| --- | --- | --- | --- |
| 直接插入 / 折半插入 | 把第 i 个记录插入前 i−1 个已排好的记录中 | 前 i 个元素**局部有序**（未必是全局最小的 i 个） | 固定 n−1 趟 |
| 希尔 | 用**一个增量 d** 对全部 d 个子序列各做一次插入排序 | 间隔 d 的各子序列分别有序 | 等于增量序列长度 t |
| 起泡 | 从头到尾扫一遍，逐对相邻元素比较并在逆序时交换 | 一端多出**一个全局最值**且已就位 | 最多 n−1 趟，可提前终止 |
| 快速 | 一次 `Partition`，把一个枢轴放到最终位置 | 该枢轴归位，左右各成一个待排子表 | 等于递归树的**深度**，随初始序列变 |
| 简单选择 | 在无序区扫一遍选出最小者，与无序区首元素交换 | 前 k 个是**全局最小的 k 个**且有序 | 固定 n−1 趟 |
| 堆 | 堆顶与当前末元素交换 + 一次筛选调整 | 尾部 k 个是**全局最大的 k 个**且有序 | 固定 n−1 趟（建初堆不计入） |
| 二路归并 | 把当前所有相邻子表**两两归并**一遍 | 若干**等长段**各自有序，段长 2k | 固定 ⌈log2⁡n⌉ 趟 |
| 基数（LSD） | 对**一位**做一次分配 + 一次收集 | 按已处理的低 k 位整体有序 | 固定 d 趟 |

三处最容易出错的地方：

- **希尔排序的一趟是"一个增量"，不是"一个子序列"**。d=4 时把 4 个子序列全排完才算一趟。
- **快速排序的"趟"与递归深度绑定**，第 k 趟结束时归位的元素个数不是 k 而是"最多 2k−1、至少 k"（详见 [快速排序](./quick-sort.html)）。它是唯一趟数不固定的算法。
- **插入类的前缀有序 ≠ 前缀就位**。插入排序前 i 个有序，但后面可能还藏着更小的元素；选择排序的前 k 个才是真正的"全局最小 k 个"。这一条是区分两者的唯一判据。

## 易混淆知识点

| 对比项 | A | B | 判别依据 |
| --- | --- | --- | --- |
| **稳定 vs 不稳定** | 稳定：插入、折半插入、起泡、归并、基数 | 不稳定：快排、简单选择、希尔、堆 | 看算法里有没有"**跨越相等元素的远距离移动**"。快排的枢轴换位、选择排序的整体交换、希尔的跨组跳跃、堆的堆顶与末元素交换，都会让元素越过与它相等的元素 |
| **一趟结束 vs 一个元素就位** | 交换类、选择类：每趟必有元素**就位** | 插入类、归并类、基数：每趟**没有**元素能保证就位 | 问"这个位置以后还会不会再变"。插入排序的前缀会被后来的元素插队；归并要到最后一趟才全部就位 |
| **有序 vs 就位** | 局部有序：插入排序的前缀 | 已就位：选择排序的前缀 | 拿前缀里的元素与**后面所有元素**比一遍：若前缀最大值仍 ≤ 后面最小值，则已就位；否则只是局部有序 |
| **内部排序 vs 外部排序** | 内排：全部在内存 | 外排：排序过程中要访问外存 | 判据不是数据量，而是**排序过程中是否发生内外存交换**。优化目标随之从"比较+移动"变成"I/O 趟数" |
| **比较次数与初始序列的关系** | 无关：简单选择（恒 n(n−1)/2）、归并、堆、基数、折半插入（几乎） | 有关：直接插入、起泡、快排 | 看算法的**控制流是否被关键字取值左右**。简单选择的双重循环边界只由下标决定，与元素值无关；直接插入的内层循环次数由"要越过几个元素"决定 |
| **空间 O(1) vs 原地** | O(1)：插入、折半插入、起泡、选择、希尔、堆 | 非 O(1)：归并 O(n)、快排 O(log2⁡n)∼O(n)、基数 O(r) 或 O(n+r) | 数清三类来源：暂存单元、递归栈、辅助数组/队列。**递归栈必须计入** |
| **比较排序下界的适用范围** | 受 Ω(nlog⁡n) 约束：全部比较类 | 不受约束：基数、计数 | 判据是"算法获取顺序信息的唯一手段是不是两两比较"。用关键字的值去**索引**桶不算比较 |

## 本节小结

学完本节，应该能够：

- **写出排序的形式化定义**，并说清"排序结果不唯一"只在存在相等关键字时才成立
- **用定义判定稳定性**：证不稳定只需给出一个具体反例序列并推到底；证稳定必须说明算法中没有任何跨越相等元素的移动
- **指出四种稳定算法各自靠哪一行代码保证稳定**（插入的"遇等即停"、折半插入的"相等往右找"、起泡的"相等不交换"、归并的"相等取左段"），并说明把比较符号写反会怎样
- **说清稳定性唯一的实际用途**是多关键字排序的后一轮，以及它为什么是基数排序正确性的前提
- **按"排序过程中是否访问外存"区分内、外排序**，并说明两者优化目标的差异
- **把九种内部排序归入五类**，并说出每一类"一趟结束后数组长什么样"
- **分开统计比较次数与移动次数**，并解释为什么不能合成一个指标（交换 = 3 次赋值；记录大小影响移动不影响比较；两者对初始序列的敏感性不同）
- **用决策树 + Stirling 公式推出 Ω(nlog⁡n) 下界**，并说清这条下界只约束比较类算法
- **说出"一趟"在八种算法里各指什么**，特别是希尔的"一趟 = 一个增量"、快排的"趟数 = 递归深度"、以及插入类"前缀有序 ≠ 前缀就位"

两条最关键的结论：

- **稳定性是算法对所有输入的性质**，一个反例即可推翻，一次"没乱"什么都证明不了；它的根源永远是代码里"相等时选谁"那一个比较符号。
- **时间开销必须拆成比较与移动两项**——本章几乎所有横向对比结论（谁适合大记录、谁的比较次数与输入无关、谁的移动次数是别人的三倍）都来自这个拆分。
