## 知识框架

本节回答 4 个问题：

- 串既然是线性表，为什么还要单独讨论它？——差别在**操作粒度**，不在逻辑结构。
- 串的十来个基本操作里，哪一个才真正有算法含量？
- 三种存储结构都讲了，为什么最后实际只剩顺序存储在用？
- 长度为 n 的串到底有多少个子串？这个数是怎么数出来的，什么时候会数错？

## 串是数据元素受限的线性表

**串**（String）是由零个或多个字符组成的有限序列，记为S=′a1a2⋯an′(n≥0)

其中 S 是**串名**，引号里的字符序列是**串值**；n 称为**串的长度**；n=0 时称为**空串**。

从逻辑结构看，串和线性表**完全一样**：都是一对一的线性关系。既然如此，为什么教材要把它单列一章？差别不在逻辑结构，在**操作粒度**：

|  | 线性表 | 串 |
| --- | --- | --- |
| 数据元素 | 任意类型 | **只能是字符**（受限） |
| 典型操作对象 | **单个元素**：插入一个、删除一个、查找一个 | **整个串或一个子串**：赋值、联接、求子串、定位 |
| 典型问法 | "第 5 个元素是什么" | "串 T 在串 S 里出现在哪" |

一句话：**串是"内容受限、操作放大"的线性表**。正因为操作对象从"一个元素"放大到"一段连续元素"，才出现了线性表里根本不存在的问题——**模式匹配**，也才有了本章唯一有分量的算法。

## 基本术语

以 S=’abcabc’ 为例：

| 术语 | 定义 | 在 S 上的例子 |
| --- | --- | --- |
| **子串** | 串中**任意个连续字符**组成的子序列 | `'abc'`、`'bca'`、`'a'`、`''`、`'abcabc'` |
| **主串** | 包含该子串的串 | S 是 `'abc'` 的主串 |
| **位置** | 字符在串中的序号，**从 1 开始计** | `'c'` 第一次出现在位置 3 |
| **子串位置** | 子串**第一个字符**在主串中的位序 | `'bca'` 在 S 中的位置是 2 |
| **空串** | 长度为 0 的串 | `''` |
| **空格串** | 由空格字符组成的串 | `'␣␣␣'`（长度为 3） |
| **串相等** | **长度相同**且**对应位置字符全相同** | `'abc'` = `'abc'`，`'abc'` ≠ `'abcabc'` |

三个要特别抠清楚的地方：

**① "任意个"包含 0 个和全部 n 个。** 所以按定义，**空串是任何串的子串，串本身也是自己的子串**。这直接决定了下面子串计数的答案。

**② 空串 ≠ 空格串。** 空串长度为 0，串值里一个字符都没有；空格串的每个空格都是一个货真价实的字符，`'␣␣␣'` 长度为 3，它和空串既不相等，也不是空串。判别法只有一条：**数一数串值里有几个字符**。

**③ 位置从 1 开始，不是从 0 开始。** 这是数据结构教材讨论串时的统一约定，和 C 语言数组下标从 0 开始是两回事。后面 BF 与 KMP 返回的"匹配起始位置"、next 数组的下标，全部建立在这个约定上。

### 子串个数怎么数

**问法一：长度为 n 的串有多少个子串（按位置计）？**

一个子串由"起点 + 长度"唯一确定。起点 i 可取 1∼n；起点定在 i 之后，长度 l 最多能取到 n−i+1。于是非空子串的个数为∑i=1n(n−i+1)=n+(n−1)+⋯+1=n(n+1)2

再加上空串，共 n(n+1)2+1 个。

换个角度数也能得到同一个式子：一个非空子串等价于在 n 个字符里选一个起点和一个终点（允许相同），即 (n2)+n=n(n+1)2。

**问法二：有多少个"互不相同"的子串？**

这是**另一个问题**，答案不再只由 n 决定，而要看串值本身：

- S=’abc’：按位置有 3×4/2=6 个非空子串，内容也恰好互不相同，仍是 6 个。
- S=’aaa’：按位置仍是 6 个（`a`×3、`aa`×2、`aaa`×1），但**互不相同的只有 3 个**（`a`、`aa`、`aaa`）。

**判别依据：题面问的是"子串的个数"还是"不同子串的个数"。** 前者按位置数，公式恒成立；后者必须逐个去重，没有通用公式。若题面明确"含空串"，两种数法都各自 +1。

## 串的基本操作

| 操作 | 说明 |
| --- | --- |
| `StrAssign(&T, chars)` | 赋值：把字符串常量 chars 赋给 T |
| `StrCopy(&T, S)` | 复制 |
| `StrEmpty(S)` | 判空（判的是**空串**，不是空格串） |
| `StrLength(S)` | 求串长 |
| `StrCompare(S, T)` | 比较大小（按字典序，逐字符比编码值） |
| `SubString(&Sub, S, pos, len)` | 求子串：从 pos 起取长度 len |
| `Concat(&T, S1, S2)` | 联接 |
| `Index(S, T, pos)` | **定位**：从 pos 起，求 T 在 S 中首次出现的位置 |
| `Replace(&S, T, V)` | 用 V 替换 S 中所有与 T 相等且不重叠的子串 |
| `StrInsert(&S, pos, T)` / `StrDelete(&S, pos, len)` | 插入 / 删除一个**子串** |

注意这张表里**没有"插入一个字符""删除一个字符"**——插入删除的对象是子串。这正是上一节说的"操作粒度放大"。

这些操作里，绝大多数只是数组的搬运，唯独 **`Index` 有真正的算法含量**：它要在长度 n 的主串里找长度 m 的模式，朴素做法是 O(nm)，能不能做到线性？整个（八）字符串模式匹配就是在回答这一个问题。

另外，`Index` 可以由 `SubString` 与 `StrCompare` 组合出来（逐个位置取子串再比较），所以它**不是最小操作集里必需的**；但组合出来的版本要反复复制子串，效率极差。**为它单独设计不依赖其他操作的算法，正是 BF 与 KMP 的由来。**

## 串的存储结构

| 存储方式 | 实现 | 特点 |
| --- | --- | --- |
| **定长顺序存储** | 静态数组 `char ch[MAXLEN+1]` 外加 `int length` | 空间在编译期定死，超长则截断 |
| **堆式顺序存储** | `char *ch` 指向 `malloc` 出来的空间，外加 `int length` | 长度按需分配，运行期可变 |
| **块链存储** | 链表，每个结点存 CHUNKSIZE 个字符 | 结点大小是个两难，实际很少用 |

### 为什么最后只剩顺序存储

这三种不是并列的三个选项，它们之间有一条推导链：

- **先看链式**。串的数据元素只有一个字符（1 字节），如果每个结点只存 1 个字符，那么每个结点还要挂一个指针（4 或 8 字节）——**指针比数据本身大好几倍**，存储密度低到不可接受。
- **于是把结点做大**：一个结点存 CHUNKSIZE 个字符，密度上去了。但新问题来了：串长不一定是 CHUNKSIZE 的整数倍，**最后一个结点会有空位**，通常补 `#` 之类的非串值字符；而且插入、删除要在块内搬字符、块间调整，实现比顺序存储复杂得多。
- **回过头看顺序存储**：串操作大多以整串或子串为单位、按下标随机访问（`S[i]` 与 `T[j]` 的比较是模式匹配的基本动作），顺序存储正好 O(1) 随机访问；而"插入删除要搬移大量元素"这个顺序存储的老毛病，在串上反而不突出——串的典型操作是赋值、联接、匹配，不是频繁的单点插删。

结论：**串多采用顺序存储结构**。定长与堆式的区别只在"空间什么时候确定"：定长在编译期定死，简单但会截断；堆式在运行期按实际串长分配，灵活但要自己管理释放。

### 下标 0 闲置：一个必须记住的约定

定长顺序存储的定义通常写成：c

```
#define MAXLEN 255
typedef struct {
    char ch[MAXLEN + 1];  // 多开一个位置：下标 0 闲置不用
    int  length;          // 串的当前长度
} SString;
```

数组开 `MAXLEN + 1` 个位置，而**下标为 0 的分量闲置不用，串值从 `ch[1]` 开始存放**。

这不是随手写的。原因是上一节那条约定：**串中字符的位置从 1 开始计**。让数组下标与字符位置对齐之后：

- `S.ch[i]` 就是"主串第 i 个字符"，不用到处写 `i-1`
- 匹配成功返回"起始位置"时可以直接写 `i - m`，不必再 ±1 修正
- next 数组可以直接用 `next[j]` 表示"第 j 个字符失配时该退到第几个字符"，**而 0 这个值恰好空出来表示"退无可退"**

最后一条是关键：正因为位置 1 是第一个字符，`next[j] = 0` 才能被赋予"模式串已经无处可退，该整体右移一位"的特殊含义。**如果改成下标从 0 开始，这个哨兵值就要改写成 −1**——两套口径的全部差异都源于这一处。详见 [KMP 算法](./kmp.html) 里的两种口径对照表。

另有一种老写法是把串长记在 `ch[0]` 里（`T[0]` 即串长），这样连 `length` 字段都省了。它同样占用下标 0，同样让串值从 1 开始，与上面的约定是一致的。

## 模式匹配问题

把 `Index` 操作形式化，就是本章唯一的算法问题：

**输入**：主串 S=′s1s2⋯sn'（也称正文串）、模式串 T=′t1t2⋯tm'（也称模式），且 T 非空。 **输出**：T 在 S 中**首次**出现时，其第一个字符在 S 中的位置；若不存在，返回 0。

三个容易被略过、但会直接影响做题的约定：

- **返回的是"首次出现"**，不是全部出现位置。
- **失败返回 0**。因为位置从 1 开始计，0 不是任何合法位置，正好用来表示"没找到"。
- **匹配的是连续子串**，不是子序列。`'ac'` 在 `'abc'` 中**不算**出现——中间隔了 `b`。

两者的分水岭只有一条：**失配时，主串指针 i 要不要回退。**

- BF 要回退——它默认"前面比过的都白比了"，于是每趟都从模式串第一个字符重来；
- KMP 不回退——它意识到已经匹配上的那 j−1 个字符**本身就是模式串的前缀**，这段内容是**已知的**，可以事先算好该退到哪，运行时直接查表。

这就是为什么 KMP 要预处理模式串（求 next 数组），而 BF 不需要：**KMP 把运行时的重复比较，换成了预处理阶段的一次性计算。**

## 易混淆知识点

| 对比项 | 一方 | 另一方 | 判别依据 |
| --- | --- | --- | --- |
| **空串 vs 空格串** | 空串，长度 0，无字符 | 空格串，`'␣␣␣'` 长度 3 | 数串值里的字符个数；空格是字符 |
| **子串 vs 子序列** | 子串必须**连续** | 子序列可以跳着取 | 取出的字符在原串中是否相邻 |
| **子串个数 vs 不同子串个数** | 按位置数，n(n+1)2+1 | 按内容去重，无通用公式 | 题面问的是"子串"还是"**不同**子串" |
| **串的位置 vs 数组下标** | 位置从 **1** 开始 | C 数组下标从 **0** 开始 | 看是在讨论串的抽象概念，还是具体 C 代码 |
| **`StrEmpty` 判空 vs 长度为 0** | 判的是空串 | — | 空格串不空，`StrEmpty('␣')` 为假 |
| **定长顺序 vs 堆式顺序** | 空间编译期定死，超长截断 | 运行期 `malloc`，按实际串长分配 | 串长能否在运行时变化 |
| **块链 vs 单字符链表** | 每结点存多个字符，密度高但有空位 | 每结点存 1 字符，密度极低 | 结点大小 CHUNKSIZE 是否为 1 |

## 本节小结

学完本篇，应该能做到：

- **写出串的定义**，并说清它与线性表的差别**在操作粒度而不在逻辑结构**。
- **区分空串与空格串**，并解释为什么 `StrEmpty` 对空格串返回假。
- **推导长度为 n 的串的子串个数** n(n+1)2+1，而不是死记；遇到"**不同**子串个数"时知道要改用去重的数法。
- **说出三种存储结构各自的取舍**，并解释"串为什么多用顺序存储"——链式存储密度低、块链有块内空位与实现复杂度，而串的典型操作恰好是顺序存储的强项。
- **解释 `ch[0]` 闲置不用的原因**：让数组下标与"位置从 1 开始"对齐，从而空出 0 作为 next 数组的哨兵值。
- **把模式匹配问题形式化地写出来**，包括"返回首次出现位置""失败返回 0""匹配连续子串"三条约定。

两个最关键的结论：

- **串这一章的全部算法含量都集中在 `Index` 一个操作上**，其余操作只是数组搬运。
- **BF 与 KMP 的唯一分水岭是"失配时主串指针要不要回退"**；不回退之所以可能，是因为已匹配的那段内容本身就是模式串的前缀，可以离线预处理。
