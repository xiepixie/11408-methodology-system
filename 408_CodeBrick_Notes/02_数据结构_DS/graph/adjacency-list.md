# 邻接表

## 大纲定位

本篇对应 2026 大纲 **五、图 （二）图的存储及基本操作 2. 邻接表**。

**分工边界**：

- **本篇**负责邻接表：两级结构、C 语言定义、有向图与无向图的边结点数差别、逆邻接表、 与邻接矩阵的互相转换、各操作代价的来历，以及"表示不唯一"这一性质的全部后果。
- **邻接矩阵**是同一条大纲下的第 1 小项，见[邻接矩阵](./adjacency-matrix.html)。 **两种结构的完整对比表放在那一篇的《易混淆知识点》**，本篇只讲邻接表这一侧的细节， 不再重复一张会漂移的对比表。
- **邻接多重表与十字链表**是第 3 小项，见[十字链表与邻接多重表](./cross-list.html)； 它们各自要解决的问题（无向图删边、有向图求入度）在本篇末尾点明，具体结构在那一篇。

## 知识框架

本节回答四个问题：

- 为什么邻接表要分成"顶点表 + 边链表"两级？只用一级链表行不行？
- 无向图的边结点为什么是 2e 个而不是 e 个？这会怎样影响空间与遍历计数？
- 有向图求出度只要走一条链，求入度为什么必须遍历整张表？有哪两种补救办法？
- "邻接表表示不唯一"这句话，会一路影响到哪些后续结论？

## 核心思想：只存"确实存在的边"

邻接矩阵为每一对顶点都留了一个格子，稀疏图上绝大多数格子是空的。 邻接表的出发点就是**只为真实存在的边花空间**：给每个顶点挂一条链，链上只放它的邻居。

结构分两级：

- **顶点表（表头结点表）**：长度为 n 的**顺序**数组，第 i 个元素存顶点 i 的数据域 `data` 和一个链域 `firstarc`（指向该顶点的第一条边结点）。 ⚠️ 这一级必须是数组而不是链表，否则"按编号随机访问某个顶点"就退化成 O(n)， DFS/BFS 的外层循环、Dijkstra 的选点都会被拖慢。
- **边表（边链表）**：每个顶点对应一条单链表，结点包含邻接点域 `adjvex`（邻居的下标）、 链域 `nextarc`、以及可选的 `info`（权值等）。

```
顶点数组          边链表
[0] V₀ → (1) → (3) → NULL
[1] V₁ → (0) → (2) → NULL
[2] V₂ → (1) → NULL
[3] V₃ → (0) → NULL
```

图注：左边是一个 4 顶点无向图，右边是它的邻接表。注意右边一共有 6 个边结点而图上只有 3 条边——**每条无向边在两个端点的链上各存了一份**。同时留意顶点表这一列是紧挨着的方格 （顺序存储、可随机访问），只有边链表才是指针串起来的。 图源：殷人昆《数据结构——用面向对象方法与 C++ 描述》（第 2 版）图8.7 无向图的邻接表表示，p356

### 有向图与无向图的边结点数

|  | 边结点总数 | 空间 | 原因 |
| --- | --- | --- | --- |
| **有向图** | e | O(n+e) | 弧 ⟨vi,vj⟩ 只挂在 vi 的链上 |
| **无向图** | 2e | O(n+e) | 边 (vi,vj) 必须在 vi 和 vj 的链上**各存一份** |

无向图为什么非存两份不可？因为邻接表是"**从顶点出发找邻居**"的结构。 如果 (vi,vj) 只挂在 vi 的链上，那么从 vj 出发遍历时就永远看不到 vi， DFS/BFS 会漏掉整片区域。**代价是删一条无向边要删两个结点**——这正是 [邻接多重表](./cross-list.html)要解决的问题。

空间量级都写成 O(n+e)，但常数不同：无向图是 n 个顶点结点 + 2e 个边结点。 做"某图用邻接表存需要多少个结点"这类计数时，2e 这个 2 不能丢。

## 存储结构（C 语言）
c

```
#define MaxVertexNum 100

// 边结点
typedef struct ArcNode {
    int adjvex;              // 该边指向的顶点编号
    struct ArcNode *next;    // 指向下一条边的指针
    // int weight;           // 带权图可加权值字段（教材称 info）
} ArcNode;

// 顶点结点
typedef struct VNode {
    char data;               // 顶点数据
    ArcNode *first;          // 指向第一条边的指针
} VNode, AdjList[MaxVertexNum];

// 邻接表存储的图
typedef struct {
    AdjList vertices;        // 顶点数组（顺序存储，支持按编号随机访问）
    int vexnum, arcnum;      // 顶点数、边数
} ALGraph;
```

建表（无向图，头插法）：c

```
// 插入无向边 (u, v)：两端各插一个边结点
void addEdge(ALGraph *G, int u, int v) {
    ArcNode *p = (ArcNode *)malloc(sizeof(ArcNode));
    p->adjvex = v;
    p->next = G->vertices[u].first;   // 头插：新结点指向原链头
    G->vertices[u].first = p;         // 再让表头指向新结点，顺序不能反

    ArcNode *q = (ArcNode *)malloc(sizeof(ArcNode));
    q->adjvex = u;
    q->next = G->vertices[v].first;
    G->vertices[v].first = q;

    G->arcnum++;                      // 一条无向边只计一次
}
```

**为什么用头插而不是尾插**：头插是 O(1)，尾插要么走到链尾（O(deg)）要么额外维护尾指针。 代价是**链上的次序与输入次序相反**——这正是"邻接表表示不唯一"的直接来源， 也是同一个图不同人建出的表会产生不同遍历序列的原因。

## 度的计算：出度容易，入度困难

- **无向图**：顶点 vi 的度 = 第 i 条边链表的结点个数，代价 O(deg⁡(vi))。
- **有向图**：第 i 条链的结点个数只是 vi 的**出度**。 求入度必须**遍历所有 n 条链**，数出其中 `adjvex == i` 的结点有多少个，代价 O(n+e)。c

```
// 有向图求顶点 i 的入度：无法只看第 i 条链，必须扫全表
int inDegree(ALGraph *G, int i) {
    int d = 0;
    for (int u = 0; u < G->vexnum; u++)              // 遍历每个顶点的链……
        for (ArcNode *p = G->vertices[u].first; p; p = p->next)
            if (p->adjvex == i) d++;                 // ……数出指向 i 的弧
    return d;   // 总代价 O(n + e)：n 个链头 + e 个边结点各访问一次
}
```

**两种补救办法**：

- **逆邻接表**：对每个顶点 vi 另建一条链，串起所有**进入** vi 的弧。 此时求入度只要数第 i 条链的长度，O(deg−⁡(vi))。 代价是求出度反过来变难，且两张表要同步维护。
- **[十字链表](./cross-list.html)**：把邻接表与逆邻接表**合并成一张表**—— 每条弧只有一个结点，但同时挂在"弧尾链"和"弧头链"上，出度入度都能快速求。

这两条不是并列的可选项，而是一条递进：逆邻接表是"再存一份"，十字链表是"一份挂两条链"。 后者省掉了同步维护两张表的麻烦，这就是它存在的价值。

## 带权图的邻接表

带权图只需在边结点里加一个权值字段（教材称 `info`）：c

```
typedef struct ArcNode {
    int adjvex;              // 该边指向的顶点编号
    int weight;              // 边（弧）的权值
    struct ArcNode *next;
} ArcNode;
```

**权值必须存在边结点里，不能存在顶点结点里**——权属于"边"这个实体， 一个顶点身上挂着多条权值不同的边，顶点结点放不下。 无向带权图中，同一条边的两个副本各存一份**相同**的权值； 修改边权时两份都要改，否则两个方向读出的权就不一致了 （这又是[邻接多重表](./cross-list.html)想解决的问题）。

## 逆邻接表的构造

逆邻接表与邻接表的结构完全相同，只是链上串的是**入弧**： 顶点 vi 的链上放的是"所有指向 vi 的顶点"。c

```
// 由邻接表 G 构造逆邻接表 R（两者顶点数相同）
void buildReverse(ALGraph *G, ALGraph *R) {
    R->vexnum = G->vexnum;
    R->arcnum = G->arcnum;
    for (int i = 0; i < R->vexnum; i++)
        R->vertices[i].first = NULL;

    for (int u = 0; u < G->vexnum; u++)
        for (ArcNode *p = G->vertices[u].first; p; p = p->next) {
            // 原图有弧 u → p->adjvex，逆图就在 p->adjvex 的链上挂一个 u
            ArcNode *q = (ArcNode *)malloc(sizeof(ArcNode));
            q->adjvex = u;
            q->next = R->vertices[p->adjvex].first;
            R->vertices[p->adjvex].first = q;
        }
}
```

代价 O(n+e)：外层扫 n 个链头，内层每个边结点处理一次，每次 O(1) 头插。 **建好之后，求任意顶点的入度就降到 O(deg−)**，代价是这张表要与原表同步维护。

## 完整走查：画出邻接表与逆邻接表

取有向图（4 个顶点）：⟨0,1⟩, ⟨0,2⟩, ⟨1,2⟩, ⟨2,0⟩, ⟨3,2⟩。

**邻接表**（按弧的输入次序头插，故链上次序与输入相反）：

| 顶点 | 边链表（出弧） | 链长 = 出度 |
| --- | --- | --- |
| 0 | 2 → 1 → ∧ | 2 |
| 1 | 2 → ∧ | 1 |
| 2 | 0 → ∧ | 1 |
| 3 | 2 → ∧ | 1 |

**逆邻接表**（链上串入弧的来源）：

| 顶点 | 边链表（入弧来源） | 链长 = 入度 |
| --- | --- | --- |
| 0 | 2 → ∧ | 1 |
| 1 | 0 → ∧ | 1 |
| 2 | 3 → 1 → 0 → ∧ | 3 |
| 3 | ∧ | 0 |

**自检**：出度之和 =2+1+1+1=5；入度之和 =1+1+3+0=5； 两者都等于弧数 e=5 ✓（见[图的基本概念](./concepts.html)的握手定理）。 顶点 3 的入度为 0，[拓扑排序](./topological-sort.html)会第一个输出它。 ⚠️ 但**这张图排不出完整的拓扑序列**——0→2 与 2→0 构成一个环， 输出 3 之后剩下的三个顶点入度都降不到 0，算法就停在那里。 这正是拓扑排序用 `count < n` 判环的场景：**输出个数不足 n，说明图中有环。**

**边结点总数**：邻接表 5 个、逆邻接表 5 个，两张表合计 10 个。 换成[十字链表](./cross-list.html)只要 **5 个**弧结点就能同时支持两个方向—— 这个 2 倍差距就是十字链表的价值所在。

## 邻接矩阵与邻接表互转

**邻接矩阵 → 邻接表**：遍历矩阵第 i 行，若 A[i][j]=1 就在顶点 i 的链上插入结点 j。c

```
// 邻接矩阵转邻接表（头插法）
// 内层 j 从大到小扫：头插会让链上次序反转，倒着扫正好让链上编号升序
void MatToList(int A[][MaxVertexNum], ALGraph *G) {
    for (int i = 0; i < G->vexnum; i++) {
        G->vertices[i].first = NULL;
        for (int j = G->vexnum - 1; j >= 0; j--) {
            if (A[i][j] == 1) {
                ArcNode *p = (ArcNode *)malloc(sizeof(ArcNode));
                p->adjvex = j;
                p->next = G->vertices[i].first;
                G->vertices[i].first = p;
            }
        }
    }
}
```

**邻接表 → 邻接矩阵**：先把矩阵清零，再遍历每条链把对应位置置 1。c

```
void ListToMat(ALGraph *G, int A[][MaxVertexNum]) {
    for (int i = 0; i < G->vexnum; i++)          // 必须先清零：矩阵要为"无边"负责
        for (int j = 0; j < G->vexnum; j++)
            A[i][j] = 0;
    for (int i = 0; i < G->vexnum; i++) {
        ArcNode *p = G->vertices[i].first;
        while (p) {
            A[i][p->adjvex] = 1;
            p = p->next;
        }
    }
}
```

**两个方向的代价不对称**，这一点值得留意：

| 方向 | 时间复杂度 | 为什么 |
| --- | --- | --- |
| 矩阵 → 表 | O(n2) | 必须看遍每一格才知道哪里有边，即使图很稀疏 |
| 表 → 矩阵 | O(n2+e) | 清零本身就要 O(n2)，之后填边只要 O(e) |

也就是说，**只要一端是邻接矩阵，就逃不掉 O(n2)**——这与"邻接矩阵的空间与边数无关"是同一件事。

## 复杂度：每一条的来历

| 操作 | 时间复杂度 | 代价的来历 |
| --- | --- | --- |
| 建立邻接表 | O(n+e) | n 个表头初始化 + 每条边一次 O(1) 头插 |
| 判断 (vi,vj) 是否为边 | O(deg⁡(vi))，最坏 O(n) | 沿 vi 的链顺序查找，链最长可达 n−1 |
| 求顶点出度（有向）/ 度（无向） | O(deg⁡(vi)) | 数一条链的长度 |
| 求顶点入度（有向） | O(n+e) | 必须遍历全部 n 条链共 e 个边结点 |
| 统计边数 | O(n+e) | 按顶点顺序扫遍所有边链表，无向图结果要除以 2 |
| 插入一条边 | O(1) | 头插 |
| 删除一条边 | O(deg⁡(vi)) | 单链表删除要先找到前驱；无向图要在两条链上各删一次 |
| DFS / BFS 全图遍历 | O(n+e) | 每个顶点入栈/入队一次贡献 O(n)；每个边结点被检查恰好一次贡献 O(e) |

**空间复杂度 O(n+e)**：n 个顶点结点；有向图 e 个边结点，无向图 2e 个。

**O(n+e) 里的 n 不能省**。即使 e=0，顶点表仍占 n 个单元； DFS/BFS 的外层循环也仍要跑 n 次去找未访问顶点。 把复杂度写成 O(e) 是错的，非连通图和边极稀疏时会出问题。

## 遍历模板与 `FirstNeighbor` / `NextNeighbor`

图算法的代码里经常出现这样一对抽象操作：

- `FirstNeighbor(G, v)`：返回 v 的**第一个**邻接点；没有则返回 −1。
- `NextNeighbor(G, v, w)`：返回 v 相对于 w 的**下一个**邻接点；w 是最后一个则返回 −1。

有了它们，遍历"v 的所有邻接点"就能写成与存储结构无关的一行：c

```
for (int w = FirstNeighbor(G, v); w >= 0; w = NextNeighbor(G, v, w)) {
    // 处理邻接点 w
}
```

**这层抽象的价值是让同一份 DFS / BFS / 拓扑排序代码在两种存储结构上都能跑**—— [DFS](./dfs.html)、[BFS](./bfs.html)、[BFS 最短路径](./bfs-shortest.html)里的算法描述用的都是这套接口。 两种实现如下：c

```
// 邻接表实现：沿链走，代价 O(1)
int FirstNeighbor(ALGraph *G, int v) {
    ArcNode *p = G->vertices[v].first;
    return p ? p->adjvex : -1;
}
int NextNeighbor(ALGraph *G, int v, int w) {
    for (ArcNode *p = G->vertices[v].first; p; p = p->next)
        if (p->adjvex == w)                       // 先找到 w 这个结点……
            return p->next ? p->next->adjvex : -1; // ……再取它的后继
    return -1;
}

// 邻接矩阵实现：扫行，代价 O(n)
int FirstNeighbor_M(MGraph *G, int v) {
    for (int j = 0; j < G->vexNum; j++)
        if (G->edge[v][j] != 0) return j;
    return -1;
}
int NextNeighbor_M(MGraph *G, int v, int w) {
    for (int j = w + 1; j < G->vexNum; j++)        // 从 w 之后接着扫
        if (G->edge[v][j] != 0) return j;
    return -1;
}
```

**两处值得注意**：

- **返回 −1 而不是 0 表示"没有了"**。因为 0 是一个合法的顶点编号， 用它当哨兵会把"邻接点是 0 号顶点"误判成"没有邻接点"。 循环条件写成 `w >= 0` 正是与这个约定配套的。
- **邻接表版的 `NextNeighbor` 写成上面这样是 O(deg⁡(v))**（每次都要重新找到 w）， 整个遍历因此退化成 O(deg2)。**实际代码里应当直接持有指针 `p` 往下走**， 把整趟遍历压回 O(deg)；这套接口只是为了描述算法时不依赖具体存储结构。 这也解释了为什么本站在写具体实现时，邻接表版都直接用 `ArcNode *p` 而不是这对函数。

## 表示不唯一及其全部后果

**一个图的邻接矩阵表示是唯一的，但其邻接表表示不唯一**——因为边链表结点的链接次序 取决于建表算法和边的输入次序。

这句话不是一条孤立的性质，它至少往下传导出三个后果：

- **DFS / BFS 的遍历序列不唯一**。遍历时"依次检查 v 的所有邻接点"， 检查的顺序就是链上的顺序。同一个图、同一个起点，两份不同的邻接表会给出不同的遍历序列。 （用邻接矩阵则唯一，因为总是按下标 0,1,…,n−1 扫行。见 [DFS](./dfs.html)、[BFS](./bfs.html)。）
- **DFS / BFS 生成树不唯一**。生成树由"引起顶点首次被访问的边"构成，序列变了树就变了。
- **拓扑序列不唯一**（除了本身就唯一的情形）。Kahn 算法里入度为 0 的顶点入队的次序， 同样受链上次序影响。见[拓扑排序](./topological-sort.html)。

反过来，遇到"给定图和一个序列，问它能否是某种 DFS/BFS 的结果"这类判断时， **允许你自由选择每个顶点邻居的检查顺序**——因为邻接表本来就不唯一。

## 易混淆知识点

| 一组概念 | 差别 | 判别依据 |
| --- | --- | --- |
| 顶点表 vs 边表 | 顶点表是**顺序**数组，边表是**链式**的 | 问"要不要按编号随机访问"：顶点要，邻居不要 |
| 有向图边结点 e 个 vs 无向图 2e 个 | 无向边要在两端各存一份 | 数结点时先问图是否有向；算空间、算"表中共有多少结点"都靠它 |
| 邻接表 vs 逆邻接表 | 前者串**出**弧，后者串**入**弧 | 看链上结点记的是"我指向谁"还是"谁指向我" |
| 出度 O(deg) vs 入度 O(n+e) | 结构只对"从我出发"这个方向友好 | 问"这条信息在我自己的链上吗"：不在就得扫全表 |
| 邻接表不唯一 vs 邻接矩阵唯一 | 链上次序有自由度，矩阵下标没有 | 由此决定遍历序列、生成树是否唯一 |
| O(n+e) vs O(e) | 顶点表和外层循环都要 O(n) | 边数为 0 时复杂度仍是 O(n)，不能省 |

学完本篇，你应该能够：

- 给出一个图，**画出它的邻接表**（并说清自己用的是头插还是尾插、链上按什么次序）， 再由邻接表还原出原图。
- 正确计数：n 个顶点 e 条边的图，邻接表共有多少个结点（有向 n+e，无向 n+2e）。
- 写出邻接表的 C 语言类型定义、建边、求度、与邻接矩阵互转的代码。
- 说清每一项复杂度的来历，尤其是"求入度为什么是 O(n+e)"，并给出逆邻接表和十字链表两条补救路线。
- 由"邻接表表示不唯一"推出遍历序列、生成树、拓扑序列的不唯一性，并在判断题里正确使用这一自由度。

三条最关键的结论：

- **两级结构：顶点表顺序、边表链式**；空间 O(n+e)，无向图边结点 2e 个。
- **出度沿自己的链 O(deg)，入度必须扫全表 O(n+e)**——这是逆邻接表和十字链表的动机。
- **邻接表不唯一**，由此 DFS/BFS 序列、生成树、拓扑序列都不唯一；邻接矩阵唯一，遍历序列也随之唯一。

## 教材出处

- 严蔚敏《数据结构（C 语言版）》（第 2 版）**印刷 p156**，§6.4.2： 邻接表由"表头结点表"和"边表"两部分组成，表头结点含 `data` 与 `firstarc`， 边结点含 `adjvex`、`info`、`nextarc`；同页指出 "在有向图中，第 i 个链表中的结点个数只是顶点 vi 的出度，为求入度，必须遍历整个邻接表"， 并给出逆邻接表的做法。
- 同书**印刷 p158**：邻接表优缺点小节——空间复杂度 O(n+e)、适合稀疏图； "不便于判断顶点之间是否有边……最坏情况下要耗费 O(n) 时间"； 以及"一个图的邻接矩阵表示是唯一的，但其邻接表表示不唯一"。
- 同书**印刷 p164**（§6.5.2 算法分析）：用邻接矩阵存储时遍历为 O(n2)， 用邻接表存储时为 O(n+e)——本篇遍历一行的复杂度以此为准。
