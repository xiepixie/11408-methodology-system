# 有向无环图（DAG）描述表达式

## 大纲定位

本篇对应 2026 大纲 **五、图 （四）图的基本应用 3. 拓扑排序**（有向无环图的应用）。

**分工边界**：

- **本篇**只讲 DAG 的一类应用：**用共享子结构表示含公共子表达式的代数表达式**， 以及"最少需要多少个顶点"的算法与计数。
- **DAG 的定义、拓扑排序、AOV 网、环的检测**在[拓扑排序](./topological-sort.html)，本篇当作已知。
- **AOE 网与关键路径**是另一类 DAG 应用，属五（四）4，见[关键路径](./critical-path.html)。
- **用二叉树表示表达式并求值**属大纲三（六）栈的应用， 见[表达式求值](./../stack-queue/expression-eval.html)；两者关心的东西不同，见本篇《易混淆知识点》。

## 知识框架

本节回答四个问题：

- 表达式本来用二叉树就能表示，为什么还要用 DAG？省下的是什么？
- 哪些结点可以合并、哪些不能？合并的判据是什么？
- 给定一个表达式，怎样系统地数出 DAG 最少需要多少个顶点，而不是靠画图凑？
- 得到的图为什么一定无环？为什么它不能是一般的图？

## 为什么要用 DAG

**有向无环图**（DAG, Directed Acyclic Graph）是不含有向回路的有向图。

用**二叉树**表示表达式时，树上每个结点只能有一个双亲，所以**同一个子表达式出现几次就得存几份**。 改用 **DAG** 之后，一个结点允许有**多个双亲**，重复出现的子表达式只需存一份， 由多条边共享——存储量随之下降。

**这就是"树 → DAG"这一步的全部收益**：把"重复的子结构"从多份压成一份。 代价是结构不再是树（不能再用"每个结点一个双亲"的性质）， 但由于表达式的求值有明确的依赖方向（先算子表达式再算父表达式），**这个方向天然无环**， 所以得到的仍是一个良性的结构。

### 二叉树 vs DAG：一个完整对照

以表达式 ((a+b)×(b×(a+b))) 为例。

**二叉树表示**——子表达式 (a+b) 被存了两份：

```
         *
        / \
       +   *
      / \ / \
     a  b b   +
             / \
            a   b
```

逐个数：根 `*`、左子树的 `+`、`a`、`b`，右子树的 `*`、`b`、`+`、`a`、`b`， 共 **9 个结点**。

**DAG 表示**——(a+b) 只存一份，被两个父结点共享，a、b 也各只存一份：

共 **5 个顶点**：a、b、+、×（内层）、×（根）。 从 9 降到 5，省下的正是重复的那一份 (a+b) 及其两个叶子。

**注意 DAG 上的边数**：每个二元运算符结点有且只有 2 条出边（指向左右两个操作数）， 操作数结点出度为 0。所以本例边数 =3×2=6 条。

## 构造方法

从表达式的二叉树（语法树）出发，**自底向上**合并重复结点：

- **合并叶子**：所有表示同一个操作数的叶子结点，只保留一个。
- **合并内部结点**：若两个结点的**运算符相同**，且**左孩子指向同一结点、右孩子也指向同一结点**， 则合并为一个。
- 重复第 2 步，直到没有可合并的结点为止。

**必须自底向上**：判断两个内部结点能否合并，前提是它们的孩子已经处理完毕 （"指向同一结点"这个条件只有在孩子已合并之后才判得准）。自顶向下会漏掉可合并的机会。

### 合并的判据与它的边界

**判据（三条同时满足才能合并）**：运算符相同、左孩子是同一顶点、右孩子是同一顶点。

由此可以推出三条边界，都是容易想当然出错的地方：

- **a×b 与 b×a 不能合并**。虽然乘法可交换，但两个结点的左右孩子不同， 按判据它们是两个不同的结点。**DAG 合并的是"结构相同"，不做代数化简。**
- **a−b 与 b−a 更不能合并**，它们连值都不同。 减法、除法不可交换，这一点比乘法更直观，但判据是同一条。
- **(a+b) 与 (a+b) 一定能合并**，无论它们在表达式的哪个位置出现。

**关键性质**：合并完成后，**DAG 中不会出现重复的操作数顶点**， 也不会出现两个代表同一子表达式的顶点。

### 顶点数怎么数才不出错

与其画图凑，不如**把所有互不相同的子表达式列出来数一遍**：

**DAG 的最少顶点数 = 该表达式中互不相同的子表达式（含单个操作数）的个数。**

因为每个不同的子表达式恰好对应一个顶点，相同的合并成一个，不同的不能合并。

用这条规则重数上面的例子 ((a+b)×(b×(a+b)))：

| 序 | 子表达式 | 类型 |
| --- | --- | --- |
| 1 | a | 操作数 |
| 2 | b | 操作数 |
| 3 | (a+b) | 运算符 + |
| 4 | (b×(a+b)) | 运算符 × |
| 5 | ((a+b)×(b×(a+b))) | 运算符 ×（根） |

共 **5 个**，与画图结果一致 ✓。

## 例题一

**题**：用有向无环图描述表达式 (x+y)×((x+y)/x)，至少需要多少个顶点？

**解**：按"列出互不相同的子表达式"的方法：

| 序 | 子表达式 | 说明 |
| --- | --- | --- |
| 1 | x | 出现 3 次，只需 1 个顶点 |
| 2 | y | 出现 1 次 |
| 3 | (x+y) | 出现 2 次，合并成 1 个 + 顶点 |
| 4 | ((x+y)/x) | 1 个 / 顶点，左孩子是 3 号，右孩子是 1 号 |
| 5 | (x+y)×((x+y)/x) | 根，1 个 × 顶点，左孩子是 3 号，右孩子是 4 号 |

**共需 5 个顶点**：x, y, +, /, ×。

**对照二叉树**：×、+、x、y、/、+、x、y、x，共 9 个结点。 DAG 省掉了 4 个（重复的 +、两个重复的 x、一个重复的 y）。

**验算边数**：3 个二元运算符 ×2=6 条边，与图上数出来的一致 ✓。

## 例题二

**题**：表达式 a×(b+c)+(b+c)×d，画出它的 DAG，给出顶点数与边数。

**解**：

**第一步：列出互不相同的子表达式。**

| 序 | 子表达式 | 类型 |
| --- | --- | --- |
| 1 | a | 操作数 |
| 2 | b | 操作数 |
| 3 | c | 操作数 |
| 4 | d | 操作数 |
| 5 | (b+c) | +，出现 2 次 → 合并为 1 个 |
| 6 | a×(b+c) | × |
| 7 | (b+c)×d | × |
| 8 | a×(b+c)+(b+c)×d | +（根） |

**顶点数 = 8。**

**第二步：数边。** 二元运算符顶点有 4 个（5、6、7、8 号），每个出度为 2， 故**边数 =4×2=8**。

**第三步：对照二叉树。** 二叉树上要 11 个结点 （根 +；左子树 ×,a,+,b,c 共 5 个；右子树 ×,+,b,c,d 共 5 个）。 DAG 用 8 个，省下 3 个（重复的 + 及其两个叶子 b、c）。

**注意 6 号与 7 号不能合并**：虽然都是 ×，但 6 号的孩子是 {a, (b+c)}， 7 号的孩子是 {(b+c), d}，左右孩子都不相同，判据不满足。

## 例题三：含不可交换运算符

**题**：表达式 (a−b)/((a−b)×c)+(c−a)，求 DAG 的最少顶点数与边数。

**第一步：列出互不相同的子表达式。**

| 序 | 子表达式 | 说明 |
| --- | --- | --- |
| 1 | a | 出现 3 次 → 1 个顶点 |
| 2 | b | 出现 2 次 → 1 个顶点 |
| 3 | c | 出现 2 次 → 1 个顶点 |
| 4 | (a−b) | 出现 2 次 → 合并为 1 个 − 顶点 |
| 5 | ((a−b)×c) | 1 个 × 顶点 |
| 6 | (a−b)/((a−b)×c) | 1 个 / 顶点 |
| 7 | (c−a) | **不能与 4 号合并**：同是 −，但左孩子是 c、右孩子是 a，与 (a−b) 不同 |
| 8 | 整个表达式 | 1 个 + 顶点（根） |

**顶点数 = 8**；二元运算符顶点 5 个（4、5、6、7、8 号），**边数 =5×2=10**。

**第二步：确认哪些没合并、为什么。**

- (a−b) 与 (c−a) **不合并**：运算符相同，但左右孩子都不同。 减法不可交换，(a−b)≠(b−a) 更是显然。
- 三个 a 合并成一个：叶子只看操作数名，出现在哪里都一样。
- **/ 的两个孩子不能交换**：X/Y 与 Y/X 是不同的表达式， 所以画图时左右孩子的位置有意义，不能随手画。

**第三步：对照二叉树。** 二叉树上的结点数为 1(+)+1(/)+3(a−b 的三个结点)+1(×)+3(a−b 再来一份)+1(c)+3(c−a)=13。 DAG 用 8 个，省下 5 个。

**含不可交换运算符时最容易犯的错，是"看到两个 − 就想合并"。** 判据只有一条，三个条件缺一不可：运算符相同、左孩子同一顶点、右孩子同一顶点。

## 表达式 DAG 的结构性质

这些性质既能用来自检画出来的图，也常被直接问到：

| 性质 | 理由 |
| --- | --- |
| **一定无环** | 边的方向永远是"父表达式 → 子表达式"，子表达式严格更短，不可能绕回来 |
| **有且仅有一个入度为 0 的顶点** | 就是整个表达式对应的根；其余每个顶点都至少被某个父表达式引用一次 |
| **操作数顶点出度为 0** | 它们是叶子，不再依赖别的子表达式 |
| **二元运算符顶点出度恰为 2** | 左右各一条边；一元运算符（如取负）则出度为 1 |
| **边数 = 2 × 二元运算符顶点数** | 由上一条直接求和 |
| **入度可以大于 1** | 这正是"共享"的表现，也是它区别于二叉树的唯一地方 |
| **没有重复的操作数顶点** | 合并规则第 1 条的直接结果 |

**画完图的自检清单**：入度为 0 的顶点只有一个吗？每个运算符顶点的出度是 2 吗？ 同名操作数是不是只画了一个？三条都对，图基本不会错。

## 存储与逆向还原

### 怎么存

表达式 DAG 的每个顶点最多有两个后继（左、右操作数）， 所以可以直接沿用**二叉链表**式的结点结构，只是允许多个结点指向同一个孩子：c

```
typedef struct DagNode {
    char  data;                    // 操作数名，或运算符 '+' '-' '*' '/'
    int   isOperator;              // 1 表示运算符结点，0 表示操作数结点
    struct DagNode *lchild, *rchild;   // 操作数结点这两个域为 NULL
} DagNode;
```

**与二叉树的唯一差别**：二叉树里"两个结点的 `lchild` 指向同一个地址"是错误 （会造成重复释放、修改互相污染），在 DAG 里这恰恰是**共享的实现方式**。 也正因为存在共享，**释放整张 DAG 不能用二叉树那套后序递归 `free`**—— 同一个结点会被 `free` 多次。要么给每个结点加引用计数，要么另开一张"已释放"表。

若用[邻接表](./adjacency-list.html)存，就是一张普通的有向图邻接表， 每个运算符顶点的边链表上恰有两个结点（次序不能乱，第一个是左操作数）。

### 逆向：由 DAG 还原表达式

考场上也会反过来给图让你写表达式。做法是**从入度为 0 的根出发做后序遍历**， 每到一个运算符结点就写成 `(左子表达式 运算符 右子表达式)`：

**例**：某 DAG 有 5 个顶点——操作数 x、y，运算符 +（孩子是 x,y）、 ×（孩子是 + 和 y）、−（孩子是 × 和 +，且 − 的入度为 0）。 还原表达式。

从入度为 0 的 − 出发：

- 左孩子是 ×：它的左孩子是 + → (x+y)；右孩子是 y。 故 × 对应 ((x+y)×y)。
- 右孩子是 + → (x+y)。
- 合起来：((x+y)×y)−(x+y)。

**验算**：这个表达式里互不相同的子表达式是 $x,\ y,\ (x+y),\ ((x+y)\times y),\ $ 以及整式，共 5 个，与题给顶点数一致 ✓。

**共享结点会被"读到"多次，但只存一次**：上例中 (x+y) 在还原出的表达式里写了两遍， 而图上只有一个 + 顶点。**这正是 DAG 省空间的地方，也是逆向题最容易漏抄的地方**—— 一个入度为 2 的顶点，在表达式里就要出现两次。

## 与其他 DAG 应用的关系

DAG 在本章一共承担三类应用，共同点是"有向 + 无环"，但关心的东西完全不同：

| 应用 | 顶点表示 | 边表示 | 关心什么 | 在哪一篇 |
| --- | --- | --- | --- | --- |
| **表达式 DAG** | 子表达式 | 依赖（父指向子） | **顶点数最少**（共享子结构省空间） | 本篇 |
| **AOV 网** | 活动 | 先后关系 | **排出一个合法顺序**（拓扑排序） | [拓扑排序](./topological-sort.html) |
| **AOE 网** | 事件 | 活动（带权 = 时长） | **工期与关键活动**（关键路径） | [关键路径](./critical-path.html) |

**表达式 DAG 也可以做拓扑排序**——得到的正是一个合法的求值顺序： 按逆拓扑序（先算被依赖的子表达式）逐个求值，每个子表达式只算一次。 这就是编译器里"公共子表达式消除"这一优化的雏形：**DAG 省的不只是空间，还有重复计算的时间**。

## 易混淆知识点

| 一组概念 | 差别 | 判别依据 |
| --- | --- | --- |
| DAG 表示表达式 vs 二叉树表示表达式 | 前者共享公共子表达式（省空间/省重复计算），后者每次出现都存一份 | 问"同一个子表达式出现两次时存几份" |
| DAG 表达式 vs [表达式求值](./../stack-queue/expression-eval.html) | 前者是**图论应用**，重点是共享子结构、数顶点；后者是**栈的应用**，重点是用栈算出值 | 问"要的是结构还是数值" |
| 能合并 vs 不能合并 | 运算符相同 **且** 左右孩子分别指向同一顶点 | 三条缺一不可；a×b 与 b×a 不满足 |
| 自底向上合并 vs 自顶向下 | 只能自底向上 | 判断父结点能否合并，前提是孩子已经合并到位 |
| DAG vs 一般有向图 | DAG 无环 | 表达式的依赖方向严格从长到短，天然无环 |
| 顶点数 vs 边数 | 顶点数 = 不同子表达式个数；边数 = 2 × 二元运算符个数 | 两者分开数，别用顶点数去凑边数 |
| "至少多少个顶点" | 就是完全合并后的顶点数 | 只要按判据能合并的都合并，结果唯一 |

**"至少"这个词会不会有歧义？** 不会。合并规则是确定性的： 凡满足判据的必须合并，不满足的不能合并，所以完全合并后的 DAG 是**唯一**的， 顶点数也就唯一。"至少"只是提醒你别漏掉可合并的地方。

**代数上等价但结构不同的表达式呢？** 比如 a×b+a×c 与 a×(b+c)， 两者的值相等，但作为**不同的表达式**，DAG 也不同：

- a×b+a×c 的不同子表达式是 a, b, c, (a×b), (a×c) 和根， 共 **6 个**顶点；
- a×(b+c) 的是 a, b, c, (b+c) 和根，共 **5 个**顶点。

**DAG 不做代数变换（不会自动提公因式），只消除结构上完全相同的重复。**

## 本节小结

学完本篇，你应该能够：

- 说清用 DAG 而不是二叉树表示表达式的收益（共享公共子表达式，省空间也省重复计算）。
- 给定表达式，**先列出所有互不相同的子表达式，直接数出 DAG 的最少顶点数**， 再由二元运算符个数算出边数。
- 画出对应的 DAG，并用"唯一入度为 0 的顶点 / 运算符出度为 2 / 操作数不重复"三条自检。
- 判断两个结点能否合并，并说明 a×b 与 b×a 为什么不能。
- 说清表达式 DAG 与 AOV 网、AOE 网的共同点（都是 DAG）与不同点（关心的量不同）。

三条最关键的结论：

- **DAG 的最少顶点数 = 互不相同的子表达式（含单个操作数）的个数**——按这条数，不用画图凑。
- **合并判据：运算符相同 + 左孩子同一顶点 + 右孩子同一顶点**，三条缺一不可，且只能自底向上做。
- **结构性质**：唯一入度为 0 的顶点（根）、二元运算符出度为 2、 边数 =2× 二元运算符个数、无重复操作数顶点。
