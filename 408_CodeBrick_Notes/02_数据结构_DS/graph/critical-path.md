## AOE 网是什么

**AOE 网（Activity On Edge Network）**：一个**带权的有向无环图**，其中

- **顶点表示事件（Event）**：一个"状态"，表示"在它之前的活动全部完成、在它之后的活动可以开始"；
- **有向边表示活动（Activity）**，边上的权表示该活动的**持续时间**；
- **源点**：唯一的入度为 0 的顶点，表示整个工程开始；
- **汇点**：唯一的出度为 0 的顶点，表示整个工程结束。

**"有且仅有一个源点和一个汇点"** 是 AOE 网区别于一般 DAG 的硬约束。 因为一项工程只有一个起始时刻和一个完工时刻——多个源点意味着说不清工程什么时候开始。 与之相对，[AOV 网](./topological-sort.html)可以有多个入度为 0 的顶点。

AOE 网要回答两个工程问题：

- **完成整项工程至少需要多少时间？**
- **哪些活动是影响工期的关键？**

### 关键路径 = 源点到汇点的最长路径

**为什么是最长而不是最短**：工程完工的条件是"所有活动都结束"。 并行的若干条路径中，最慢的那条决定了什么时候能全部结束。 所以**工程的最短完成时间 = 源点到汇点的最长带权路径长度**。

这条最长路径称为**关键路径（Critical Path）**，其上的活动称为**关键活动**。 关键活动一旦拖延，整个工程就拖延；关键活动提前，整个工程才可能提前。

**"最短工期 = 最长路径"不是绕口令**，它是一句需要想明白的话： 短的那条路径上的活动可以慢慢做（有富余时间），长的那条一刻也不能耽误。 这也是它与[最短路径](./dijkstra.html)问题思路相反的地方。

## 四个时间参数

| 符号 | 名称 | 属于 | 计算方式 |
| --- | --- | --- | --- |
| ve(j) | 事件 j 的**最早发生时间** | 顶点 | ve(j)=max{ve(i)+w(i,j)}，对所有前驱 i 取 **max** |
| vl(j) | 事件 j 的**最迟发生时间** | 顶点 | vl(j)=min{vl(k)−w(j,k)}，对所有后继 k 取 **min** |
| e(a) | 活动 a 的**最早开始时间** | 边 | e(a)=ve(起点) |
| l(a) | 活动 a 的**最迟开始时间** | 边 | l(a)=vl(终点)−w(a) |

### 四条式子分别是怎么来的

**ve(j) 取 max**：事件 j 表示"射入 j 的所有活动都已结束"。 所有前驱活动里最晚结束的那个决定了 j 什么时候能发生，所以取**最大值**。 初始条件 ve(源点)=0。

**vl(j) 取 min**：事件 j 的发生不能耽误它的**任何一个**后继事件的最迟发生时间。 只要有一个后继要求得紧，j 就得跟着紧，所以取**最小值**。 初始条件 vl(汇点)=ve(汇点)——即"不允许拖延总工期"。

**e(a)=ve(i)**：活动 a=⟨i,j⟩ 只有在事件 i 发生后才能开始， 所以它最早能开始的时刻就是 ve(i)。

**l(a)=vl(j)−w(a)**：活动 a 必须在事件 j 的最迟发生时间之前干完， 倒推 w(a) 就是它最迟必须开工的时刻。

**两个方向的极值为什么相反**：ve 是"最早"，受制于**最慢的前驱**，所以取 max； vl 是"最迟"，受制于**最紧的后继**，所以取 min。 一个是"等所有人到齐"，一个是"迁就最赶时间的那个"——记住这两句话就不会取反。

### 关键活动的判据

**时间余量** d(a)=l(a)−e(a)：在不影响总工期的前提下，活动 a 可以推迟开工的最大时长。

- d(a)=0（即 e(a)=l(a)）→ **关键活动**：一刻也不能拖，拖一天工期就延一天。
- d(a)>0 → 非关键活动：在 d(a) 范围内推迟或拖长，都不影响总工期。

**关键路径**：由关键活动从源点串到汇点的路径。**关键路径可能不止一条。**

## 求解步骤

- 对 AOE 网做**拓扑排序**，同时按拓扑序正推出所有 ve[ ]。 （若拓扑排序失败，说明有环，工程本身自相矛盾，无关键路径。）
- 令 vl[汇点]=ve[汇点]，按**逆拓扑序**倒推出所有 vl[ ]。
- 遍历每条活动边，算出 e 与 l。
- 挑出 e=l 的活动，即关键活动；把它们串起来就是关键路径。

**次序不能乱**：ve 必须按拓扑序算（算 ve(j) 时它的所有前驱必须都已算完）， vl 必须按逆拓扑序算（算 vl(j) 时它的所有后继必须都已算完）。 **这就是"拓扑排序是关键路径的基础"这句话的确切含义。**c

```
#include <stdio.h>
#include <string.h>

#define MAXV 1005
#define MAXE 100005

typedef struct { int to, w, next; } Edge;

Edge edges[MAXE];
int head[MAXV], cnt;
int inDeg[MAXV];
int ve[MAXV], vl[MAXV];        // 事件最早/最迟发生时间
int topoOrder[MAXV], topoCnt;  // 拓扑序列
int n, m;                      // n 个事件, m 个活动

void initGraph(int nv) {
    n = nv; cnt = 0;
    memset(head, -1, sizeof(head));   // head 用 -1 表示空链，与遍历条件 i != -1 配套
    memset(inDeg, 0, sizeof(inDeg));
}

void addEdge(int u, int v, int w) {
    edges[cnt].to = v;
    edges[cnt].w = w;
    edges[cnt].next = head[u];
    head[u] = cnt++;
    inDeg[v]++;
}

// 拓扑排序 + 正推 ve[]；返回 0 表示有环
int topoSort(void) {
    int queue[MAXV], front = 0, rear = 0;
    topoCnt = 0;
    memset(ve, 0, sizeof(ve));        // ve 全置 0：源点的初值就是 0，其余会被 max 抬上去

    for (int i = 0; i < n; i++)
        if (inDeg[i] == 0) queue[rear++] = i;

    while (front < rear) {
        int u = queue[front++];
        topoOrder[topoCnt++] = u;      // 记下拓扑序，第二步要倒着用
        for (int i = head[u]; i != -1; i = edges[i].next) {
            int v = edges[i].to, w = edges[i].w;
            if (ve[u] + w > ve[v])
                ve[v] = ve[u] + w;     // 正推取 max
            if (--inDeg[v] == 0)
                queue[rear++] = v;
        }
    }
    return topoCnt == n;
}

// 求关键路径
void criticalPath(void) {
    if (!topoSort()) { printf("图中有环，无关键路径\n"); return; }

    int sink = topoOrder[topoCnt - 1];   // 拓扑序最后一个顶点就是汇点
    for (int i = 0; i < n; i++)
        vl[i] = ve[sink];                // 先全部置成总工期，再由 min 压下来

    // 逆拓扑序倒推 vl[]
    for (int idx = topoCnt - 1; idx >= 0; idx--) {
        int u = topoOrder[idx];
        for (int i = head[u]; i != -1; i = edges[i].next) {
            int v = edges[i].to, w = edges[i].w;
            if (vl[v] - w < vl[u])
                vl[u] = vl[v] - w;       // 倒推取 min
        }
    }

    printf("工程最短工期 = %d\n", ve[sink]);
    // 遍历每条活动，判断是否为关键活动
    for (int u = 0; u < n; u++) {
        for (int i = head[u]; i != -1; i = edges[i].next) {
            int v = edges[i].to, w = edges[i].w;
            int e = ve[u];               // 活动最早开始时间
            int l = vl[v] - w;           // 活动最迟开始时间
            if (e == l)
                printf("关键活动 <%d, %d>\n", u, v);
        }
    }
}
```

**三处实现细节**：

- **`ve[]` 初始化为全 0 是对的**，因为所有权值非负，源点的 ve 本就是 0， 其余顶点会被 `max` 逐步抬到正确值。但**若允许负权（AOE 网中不会出现），就必须初始化为负无穷**。
- **`vl[]` 先全部置成总工期再由 min 压下来**。取汇点的 ve 作为初值， 等价于"任何事件都不允许晚于总工期发生"。若初值取得比总工期小，某些 vl 会被压过头。
- **`head` 数组用 −1 表示空链**，所以必须 `memset(head, -1, ...)` （`memset` 按字节填充，−1 的每个字节都是 `0xFF`，恰好能得到全 −1 的 int 数组； 换成任何别的值就不能这样填）。

## 完整手算走查

下面用一个 7 事件、10 活动的 AOE 网走完全程。这是本条大纲的标准动作，每一步都不能跳。

活动清单（起点 → 终点，持续时间）：

| 活动 | 边 | w | 活动 | 边 | w |
| --- | --- | --- | --- | --- | --- |
| a1 | v1→v2 | 4 | a6 | v3→v6 | 3 |
| a2 | v1→v3 | 2 | a7 | v4→v5 | 2 |
| a3 | v2→v4 | 2 | a8 | v4→v6 | 3 |
| a4 | v2→v5 | 3 | a9 | v5→v7 | 1 |
| a5 | v3→v4 | 4 | a10 | v6→v7 | 4 |

源点是 v1（入度 0），汇点是 v7（出度 0），符合 AOE 网的要求。

### 第一步：按拓扑序正推 ve（取 max）

一个合法拓扑序：v1,v2,v3,v4,v5,v6,v7。每个事件对**所有前驱**取最大：

| 事件 | 计算过程 | ve |
| --- | --- | --- |
| v1 | 源点 | **0** |
| v2 | ve(1)+4=4 | **4** |
| v3 | ve(1)+2=2 | **2** |
| v4 | max{ve(2)+2, ve(3)+4}=max{6, 6} | **6** |
| v5 | max{ve(2)+3, ve(4)+2}=max{7, 8} | **8** |
| v6 | max{ve(3)+3, ve(4)+3}=max{5, 9} | **9** |
| v7 | max{ve(5)+1, ve(6)+4}=max{9, 13} | **13** |

**工程最短工期 =ve(v7)=13。**

v4 的两个前驱算出来**同为 6**，这不是巧合，是特意设计的。 **ve 取 max 时出现并列，就预示着可能有多条关键路径**——看到并列要打起精神。

### 第二步：按逆拓扑序倒推 vl（取 min）

初始化 vl(v7)=ve(v7)=13。每个事件对**所有后继**取最小：

| 事件 | 计算过程 | vl |
| --- | --- | --- |
| v7 | 汇点，=ve(7) | **13** |
| v6 | vl(7)−4=9 | **9** |
| v5 | vl(7)−1=12 | **12** |
| v4 | min{vl(5)−2, vl(6)−3}=min{10, 6} | **6** |
| v3 | min{vl(4)−4, vl(6)−3}=min{2, 6} | **2** |
| v2 | min{vl(4)−2, vl(5)−3}=min{4, 9} | **4** |
| v1 | min{vl(2)−4, vl(3)−2}=min{0, 0} | **0** |

**自检习惯**：算完必看 **vl(源点) 是否等于 0**。 不等于 0 就说明 ve 或 vl 某一步算错了，当场重查，别带着错往下填活动表。 原理：源点到汇点的最长路径长度既是 ve(汇点) 也决定了 vl(源点)=0， 两者必然自洽。

### 第三步：逐活动算 e、l、d

e(a)=ve(起点)，l(a)=vl(终点)−w，d=l−e：

| 活动 | 边 | w | e=ve(起) | l=vl(终)−w | 余量 d | 关键活动？ |
| --- | --- | --- | --- | --- | --- | --- |
| a1 | v1→v2 | 4 | 0 | 4−4=0 | 0 | ★ |
| a2 | v1→v3 | 2 | 0 | 2−2=0 | 0 | ★ |
| a3 | v2→v4 | 2 | 4 | 6−2=4 | 0 | ★ |
| a4 | v2→v5 | 3 | 4 | 12−3=9 | 5 |  |
| a5 | v3→v4 | 4 | 2 | 6−4=2 | 0 | ★ |
| a6 | v3→v6 | 3 | 2 | 9−3=6 | 4 |  |
| a7 | v4→v5 | 2 | 6 | 12−2=10 | 4 |  |
| a8 | v4→v6 | 3 | 6 | 9−3=6 | 0 | ★ |
| a9 | v5→v7 | 1 | 8 | 13−1=12 | 4 |  |
| a10 | v6→v7 | 4 | 9 | 13−4=9 | 0 | ★ |

（★ 表示关键活动，下同。）

### 第四步：连出关键路径

关键活动 a1,a2,a3,a5,a8,a10 连成了**两条**关键路径：

- v1→v2→v4→v6→v7，长度 4+2+3+4=13
- v1→v3→v4→v6→v7，长度 2+4+3+4=13

**自检**：两条关键路径长度必须相等（都等于总工期 13）✓； 所有关键活动的 d 都是 0 ✓；每条关键路径都从源点通到汇点 ✓。

## 缩短工期：一个定量分析

这是本条最需要动脑、也最容易答错的一问。**先把这张网里全部 6 条路径的长度列出来**：

| 路径 | 活动序列 | 长度 |
| --- | --- | --- |
| v1v2v4v6v7 | a1,a3,a8,a10 | **13**（关键） |
| v1v3v4v6v7 | a2,a5,a8,a10 | **13**（关键） |
| v1v2v4v5v7 | a1,a3,a7,a9 | 9 |
| v1v3v4v5v7 | a2,a5,a7,a9 | 9 |
| v1v3v6v7 | a2,a6,a10 | 9 |
| v1v2v5v7 | a1,a4,a9 | 8 |

有了这张表，三个结论就都是算出来的而不是背出来的：

**结论一：缩短非关键活动，工期一点也不会变。** 比如把 a4（余量 5）从 3 缩到 1，只影响最后那条长度 8 的路径，它变成 6， 最长路径仍是 13。

**结论二：只缩短一条关键路径上的活动，工期同样不变。**a1 只出现在第一条关键路径上。把 a1 从 4 缩到 1，第一条路径变成 10， 但**第二条关键路径 v1v3v4v6v7 仍然是 13**，工期纹丝不动。 **这就是"必须缩短所有关键路径的公共关键活动"的由来。**

**结论三：缩短公共关键活动有效，但存在下限。**a8 与 a10 同时出现在两条关键路径上。取持续时间较长的 a10（原为 4）来缩， 缩短量记作 δ。**注意 δ 有一个硬上界：活动时长不能缩成负数，所以 0≤δ≤4**—— 这一条在答"最多能缩多少"时最容易被忽略。

| 缩短量 δ | 0 | 1 | 2 | 3 | 4 |
| --- | --- | --- | --- | --- | --- |
| 经过 a10 的两条原关键路径 | 13 | 12 | 11 | 10 | 9 |
| **不经过** a10 的路径最长者 | 9 | 9 | 9 | 9 | 9 |
| **实际工期** | **13** | **12** | **11** | **10** | **9** |

δ≤3 时每缩 1 天工期就少 1 天；δ=4（即 a10 缩到 0）时工期降到 9， 此时 v1v2v4v5v7 与 v1v3v4v5v7 这两条**不经过 a10**、原本长度为 9 的路径 **升级成了新的关键路径**，工期就此卡死—— **这时哪怕把另一个公共关键活动 a8 也一并缩到 0，工期仍然是 9**： 那两条不含 a8 也不含 a10 的路径根本不受影响（可代入上面的路径长度表自行验算）。

**所以"缩短关键活动一定能缩短工期"是错的**，正确表述是： **缩短所有关键路径的公共关键活动能缩短工期，但每缩一步都可能让别的路径变成关键路径， 必须重新计算。** 一旦某条非关键路径追平，继续缩就是无效投入。

图注：左边是一个 9 事件、11 活动的 AOE 网，顶点 0 是源点（标"开始"）、顶点 8 是汇点（标"结束"）， 边上的 a1=6, a2=4,… 就是各活动的持续时间。 右边是它的邻接表：顶点表的 `count` 列存**入度**（拓扑排序用）， 边结点除了终点 `dest` 还多了一个 **`dur`** 字段存活动时长—— **正推 ve 时读的就是这个 `dur`**。 对照左图数一下顶点 4 的 `count`：射入它的是 a4 与 a5 两条弧，`count = 2` ✓。 与[拓扑排序](./topological-sort.html)那篇的 AOV 邻接表对比：**结构完全一样，只多了一个 `dur` 列**。 图源：殷人昆《数据结构——用面向对象方法与 C++ 描述》（第 2 版）图8.30 一个 AOE 网络及其邻接表表示，p388

## 复杂度分析

| 操作 | 时间 | 来历 |
| --- | --- | --- |
| 拓扑排序 + 正推 ve | O(n+e) | 每个顶点入队出队各一次，每条边处理一次 |
| 逆拓扑序倒推 vl | O(n+e) | 沿记录下的拓扑序反向扫一遍，每条边再处理一次 |
| 逐活动求 e、l | O(e) | 每条边一次 O(1) 计算 |
| **总体** | O(n+e) | 与拓扑排序同阶 |

**空间复杂度 O(n+e)**：邻接表 O(n+e)，`ve[]`、`vl[]`、`topoOrder[]`、队列各 O(n)。

**注意这里没有"求最长路径"的额外开销**。一般图上求最长路径是 NP-难的， 但 **DAG 上可以按拓扑序做一次线性 DP**——这正是 ve 的正推所做的事。 "有向无环"这个前提把一个困难问题降成了 O(n+e)。

## 易混淆知识点

| 一组概念 | 差别 | 判别依据 |
| --- | --- | --- |
| ve / vl vs e / l | 前两个属于**事件（顶点）**，后两个属于**活动（边）** | 看下标：ve(j) 的 j 是顶点，e(a) 的 a 是活动 |
| ve 取 max vs vl 取 min | 最早要"等所有前驱到齐"，最迟要"迁就最紧的后继" | 记住这两句话，比记公式可靠 |
| 正推 vs 倒推 | ve 按拓扑序，vl 按逆拓扑序 | 问"算它的时候需要谁已经算完"：前驱→正推，后继→倒推 |
| 关键路径 = 最长路径 vs 最短路径 | 关键路径求**最长** | 工期由最慢的并行分支决定 |
| 关键活动 vs 关键路径 | 前者是边，后者是边的序列 | d=0 的是关键活动；从源点串到汇点才叫关键路径 |
| 关键路径唯一 vs 不唯一 | 可能不唯一 | ve 正推出现并列 max 时，往往就有多条 |
| 缩短关键活动 vs 缩短工期 | 前者不一定导致后者 | 该活动是否在**所有**关键路径上；缩到别的路径追平就失效 |
| AOE 网 vs AOV 网 | 活动在**边**上 vs 在**顶点**上 | 见[拓扑排序](./topological-sort.html)的对照表 |
| 延长关键活动 | **一定**延长工期 | 与"缩短"不对称：延长必然使那条路径更长，工期至少同步增加 |

**为什么"延长关键活动一定延长工期"，而"缩短关键活动不一定缩短工期"？** 因为工期 = 所有路径长度的**最大值**。延长关键活动会把某条已经取到最大值的路径拉得更长， 最大值必然跟着涨；而缩短它只是把其中一条最大值降下来，**其他并列的最大值还在那儿**。 最大值对"变大"敏感，对"变小"迟钝——这就是不对称的根源。

**同一条路径上多个活动的余量可以各用各的吗？** 不可以，**余量是共享的，不能相加**。

d(a)=l(a)−e(a) 是在"其他活动都按最早时间开始"这个前提下算出来的。 上例中 a7 与 a9 同在路径 v1v2v4v5v7 上，各自余量都是 4， 但**整条路径的总富余只有 13−9=4**：

- 若 a7 推迟 4 天（在 l(a7)=10 开工，12 完工），v5 就被推到 12， a9 的最早开始时间随之变成 12——**它的余量已经被 a7 用光，归零了**。
- 此时 a9 若再推迟 4 天（16 开工、17 完工），整个工程就拖到 17，工期被延误 4 天。

所以"这条路径上有两个余量 4 的活动"不等于"这条路径可以富余 8 天"。 **看余量要看路径，不能逐个活动累加。**

## 本节小结

学完本篇，你应该能够：

- 判断一个带权 DAG 是不是合法的 AOE 网（唯一源点、唯一汇点、活动在边上）。
- 给定 AOE 网，**按顺序填全 ve、vl、e、l、d 五组数据**， 并用"vl(源点)=0"与"关键路径长度 = ve(汇点)"两条自检。
- 找出全部关键活动并连出全部关键路径，判断关键路径是否唯一。
- 面对"缩短哪个活动能缩短工期""最多能缩多少"这类追问， **通过列出所有路径长度定量作答**，而不是背一句结论。
- 说清 AOE 与 AOV 的区别，以及为什么关键路径必须以拓扑排序为基础。

三条最关键的结论：

- **工期 = 源点到汇点的最长路径**；ve 按拓扑序正推取 max，vl 按逆拓扑序倒推取 min， 初值分别是 ve(源点)=0 与 vl(汇点)=ve(汇点)。
- **关键活动的判据是 e(a)=l(a)（余量 d=0）**；关键路径可能不唯一。
- **缩短工期只能动"所有关键路径的公共关键活动"，且有下限**—— 一旦某条非关键路径追平，继续缩短无效；而**延长关键活动一定延长工期**。

- 严蔚敏《数据结构（C 语言版）》（第 2 版）**印刷 p178–p179**，§6.6.4： "与 AOV-网相对应的是 AOE-网 (Activity On Edge)，即以边表示活动的网。 AOE-网是一个带权的有向无环图，其中，顶点表示事件，弧表示活动，权表示活动持续的时间。"
- 同书**印刷 p179**： "由于整个工程只有一个开始点和一个完成点，故在正常的情况（无环）下， 网中只有一个入度为零的点，称作源点，也只有一个出度为零的点，称作汇点"； "要估算整项工程完成的最短时间，就是要找一条从源点到汇点的带权路径长度最长的路径， 称为关键路径 (Critical Path)"； 同页给出 ve(i)=max{ve(k)+wk,i} 与 vl(i)=min{vl(k)−wi,k} 两条递推式， 并明确"求 ve(i) 的值，可根据拓扑顺序从源点开始向汇点递推"、 "求出 ve(i) 后，可根据逆拓扑顺序从汇点开始向源点递推，求出 vl(i)"。
- 同书**印刷 p180**： e(i)=ve(j)、l(i)=vl(k)−wj,k； "显然，对于关键活动而言，e(i)=l(i)。对于非关键活动，l(i)−e(i) 的值是该工程的期限余量， 在此范围内的适度延误不会影响整个工程的工期"； 同页给出关键路径求解的五步过程，并指出"关键路径有可能不止一条"。
