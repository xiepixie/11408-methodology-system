# Kruskal 算法

## 大纲定位

本篇对应 2026 大纲 **五、图 （四）图的基本应用 1. 最小（代价）生成树**。

**分工边界**：这一条由两篇分担。

- **本篇（Kruskal）**："加边法"——按权值从小到大依次考察每条边，不成环就收下。 本篇负责：按边贪心的正确性（由环性质给出）、并查集判环、复杂度的瓶颈分析、 以及"图不连通时算法如何自然地报错"。
- **[Prim](./prim.html)** 是"加点法"，并且承载**最小生成树的公共基础**—— MST 的定义、MST 性质（割性质）及其证明、MST 唯一性的判据。 这三块内容在那一篇，本篇直接引用，不重复展开。
- 两者的选型对照表在 [Prim](./prim.html) 的《易混淆知识点》。
- 并查集本身（Find / Union、路径压缩、按秩合并）属大纲四（四）2， 完整讲解见[并查集](./../tree/union-find.html)；本篇只讲它在这里承担什么职责。

## 知识框架

本节回答四个问题：

- 按权值从小到大收边，为什么不会因为"贪早了"而错过全局最优？
- "加入这条边会不会成环"这个判断，为什么恰好等价于"两端是否已在同一集合"？
- O(elog⁡e) 的瓶颈在哪一步？为什么并查集那部分几乎可以忽略？
- 图不连通时会发生什么？算法怎么知道？

## 核心思想：加边法

Kruskal 的策略只有一句话：**把所有边按权值从小到大排好队，依次考察， 只要加入后不形成回路就收下；收够 n−1 条就结束。**

它与 [Prim](./prim.html) 的根本差别在"中间状态长什么样"：

- **Prim 的中间状态始终是一棵连通的树**，每轮长出一个新顶点。
- **Kruskal 的中间状态是一片森林**——已选的边可能分散在好几个互不相连的连通块里， 直到最后一条边才把它们全部并成一棵树。

正因为中间是森林，Kruskal 才需要一个专门的数据结构来回答"这两个顶点现在属不属于同一块"， 这就是并查集的用武之地。

```
原始边集（按权值排序）:
(A,B,1) → (C,D,2) → (A,C,3) → (B,D,4) → (B,C,5)

逐步选边（设共 4 个顶点）：
第 1 步: 选 (A,B,1)  ✓ A、B 原本不连通
第 2 步: 选 (C,D,2)  ✓ C、D 原本不连通
第 3 步: 选 (A,C,3)  ✓ {A,B} 与 {C,D} 两块合并 → 已选 n−1 = 3 条边，结束
```

## 正确性：环性质

[Prim](./prim.html) 用的是**割性质**（跨越任意割的最小边必属于某棵 MST）。 Kruskal 用的是它的对偶——**环性质**：

**环性质**：设 C 是图中的任意一个回路，f 是 C 上权值**最大**的边（且严格大于其他边）， 则**任何最小生成树都不含 f**。

**证明**：设某棵 MST T 含 f。从 T 中删去 f，T 被分成两个连通块， 顶点集被分成 U 与 V−U，且 f 是跨越这个划分的。 回路 C 上除 f 之外必然还有另一条跨越边 g（回路要从 U 出去再回来，至少跨两次）。 把 g 加回来即得另一棵生成树 T′，且 w(T′)=w(T)−w(f)+w(g)<w(T)， 与 T 是最小生成树矛盾。∎

**Kruskal 正是环性质的直接执行**：当它遇到一条两端已连通的边时， 这条边与已选的路径恰好构成一个回路；而由于边是按权值升序考察的， **这条边一定是该回路上权值最大的（或并列最大的）**，所以丢弃它是安全的。

反过来，被选中的每条边都是"连接两个当时互不相连的块"的最小可用边， 由割性质它属于某棵 MST。**两条性质一个管"收"、一个管"弃"，合起来保证 Kruskal 的每一步都不出错。**

## 并查集：为什么它恰好能判环

在无向图里，"加入边 (u,v) 会形成回路"与"u 和 v 在当前已选边构成的森林中已经连通" 是**等价的**：

- 若 u,v 已连通，说明它们之间已存在一条路径，再加 (u,v) 就闭合成环；
- 若 u,v 不连通，加上 (u,v) 后它们之间只有这一条路径，不可能成环。

而"是否连通"正是并查集的原生查询。所以：

| 需求 | 并查集操作 |
| --- | --- |
| 判断 u,v 是否已连通 | `Find(u) == Find(v)` |
| 收下一条边后合并两块 | `Union(u, v)` |
| 初始状态：每个顶点各成一块 | `parent[i] = i` |

经**路径压缩**与**按秩合并**优化后，单次 `Find`/`Union` 的均摊时间接近 O(α(n))， 其中 α 是反阿克曼函数，在任何现实规模下都不超过 4，可视为常数。 详见[并查集](./../tree/union-find.html)。

**教材里还有一种更朴素的写法**：用一个 `Vexset[]` 数组直接给每个顶点标"所属连通分量编号"， 合并时把编号为 `vs2` 的全部改成 `vs1`。这种写法**每次合并要扫一遍 n 个顶点**， 概念上更直白，但合并总代价升到 O(ne)。用并查集把它降到近似常数， 才使得排序成为唯一的瓶颈。

## 算法实现
c

```
#include <stdio.h>
#include <stdlib.h>

#define MAXE 1000  // 最大边数
#define MAXV 100   // 最大顶点数

typedef struct {
    int u, v;   // 边的两个端点
    int w;      // 边的权值
} Edge;

Edge edges[MAXE];  // 边集数组
int parent[MAXV];  // 并查集父结点数组
int rank_[MAXV];   // 并查集秩（用于按秩合并）

// 比较函数，供 qsort 按权值升序排序
int cmp(const void *a, const void *b) {
    return ((Edge *)a)->w - ((Edge *)b)->w;
}

// 并查集：查找根结点（路径压缩——查完顺手把沿途结点直接挂到根上）
int Find(int x) {
    if (parent[x] != x)
        parent[x] = Find(parent[x]);
    return parent[x];
}

// 并查集：合并两个集合（按秩合并——把矮树挂到高树上，控制树高）
void Union(int x, int y) {
    int rx = Find(x), ry = Find(y);
    if (rx == ry) return;
    if (rank_[rx] < rank_[ry])
        parent[rx] = ry;
    else if (rank_[rx] > rank_[ry])
        parent[ry] = rx;
    else {
        parent[ry] = rx;
        rank_[rx]++;      // 只有两棵等高树合并时，树高才会 +1
    }
}

// Kruskal 算法：n 个顶点、m 条边，返回 MST 总权值；图不连通返回 -1
int Kruskal(int n, int m) {
    int i, cnt = 0, totalW = 0;

    // ① 按权值排序所有边 —— 整个算法的瓶颈
    qsort(edges, m, sizeof(Edge), cmp);

    // ② 初始化并查集：每个顶点各成一个连通块
    for (i = 0; i < n; i++) {
        parent[i] = i;
        rank_[i] = 0;
    }

    // ③ 贪心选边。两个终止条件缺一不可：
    //    cnt < n-1 让选够就提前停；i < m 保证边用完也能退出
    for (i = 0; i < m && cnt < n - 1; i++) {
        int u = edges[i].u, v = edges[i].v;
        if (Find(u) != Find(v)) {      // 两端不在同一块 → 不会成环
            Union(u, v);
            totalW += edges[i].w;
            cnt++;
        }
        // else：丢弃。由环性质，它是所构成回路上权值最大的边，弃之无害
    }

    if (cnt < n - 1) return -1;        // 边考察完了仍凑不够 n-1 条 → 图不连通
    return totalW;
}
```

**三处细节**：

- **两个终止条件都要**。`cnt < n-1` 让算法在选够之后立刻停下（不必看完剩余的边）； `i < m` 保证即使图不连通、永远凑不够 n−1 条，循环也能结束。
- **`Find` 的路径压缩写在赋值里**：`parent[x] = Find(parent[x])` 既求出了根， 又顺手把 x 直接挂到根上，下次查就是 O(1)。
- **`rank_` 只在两棵等高树合并时才 +1**。矮挂高时高度不变，所以不能无脑自增。

**图不连通的判断是"免费"的**：不需要额外跑一次连通性检查， 算法自然会在边用完时留下 `cnt < n-1`。这一点比 Prim 更省事（Prim 要靠 `k == -1` 显式判）。

## 完整走查

用与 [Prim](./prim.html) **完全相同**的那张无向网（6 个顶点、10 条边）， 以便直接对比两种算法的选边次序：

| 边 | 权 | 边 | 权 |
| --- | --- | --- | --- |
| A−C | 1 | A−D | 5 |
| D−F | 2 | B−C | 5 |
| B−E | 3 | C−D | 5 |
| C−F | 4 | A−B | 6 |
|  |  | C−E | 6 |
|  |  | E−F | 6 |

排序后依次考察（权值相同的边按字典序排，实际实现中任选次序都可以）：

| 序 | 边 | 权 | `Find(u)` 与 `Find(v)` | 决策 | 考察后的连通块 | 已选 |
| --- | --- | --- | --- | --- | --- | --- |
| 1 | A−C | 1 | 不同 | **选中** | {A,C} {B} {D} {E} | 1 |
| 2 | D−F | 2 | 不同 | **选中** | {A,C} {B} {E} | 2 |
| 3 | B−E | 3 | 不同 | **选中** | {A,C} {B,E} | 3 |
| 4 | C−F | 4 | 不同 | **选中** | {A,C,D,F} | 4 |
| 5 | A−D | 5 | **相同** | 丢弃（成环 A−C−F−D−A） | 不变 | 4 |
| 6 | B−C | 5 | 不同 | **选中** → 已选够 5 条，结束 |  | 5 |

**结果**：MST 的 5 条边是 (A,C),(D,F),(B,E),(C,F),(B,C)， 总权值 1+2+3+4+5=15。

**与 Prim 的对照**：Prim 在同一张图上选出的是 (A,C),(C,F),(F,D),(C,B),(B,E)——**边集完全相同**（只是选出的次序不同）， 总权值也同为 15。这不是巧合，因为这张图的 MST 恰好唯一（判据见 [Prim](./prim.html) 的唯一性一节）。 若图的 MST 不唯一，两个算法完全可能给出**不同的边集，但总权值必然相同**。

**中间状态的差别值得留意**：Kruskal 在第 3 步时手上有 {A,C}、{B,E}、{D,F} 三棵**互不相连** 的小树，而 Prim 在任何时刻手上都只有一棵连通的树。**这就是"加边法"与"加点法"的实质区别。**

### 并查集内部：`parent[]` 的逐步变化

把上面的走查再做细一层，看看 `parent[]` 数组到底发生了什么。 把顶点 A∼F 编号为 0∼5，初始 `parent[i] = i`、`rank_[i] = 0`：

| 处理的边 | `Find` 结果 | `Union` 动作 | `parent[]`（下标 ABCDEF） | `rank_` 变化 |
| --- | --- | --- | --- | --- |
| 初始 | — | — | ABCDEF | 全 0 |
| A−C | A≠C | 秩相等 → C 挂到 A，`rank_[A]=1` | ABADEF | A:1 |
| D−F | D≠F | 秩相等 → F 挂到 D，`rank_[D]=1` | ABADED | D:1 |
| B−E | B≠E | 秩相等 → E 挂到 B，`rank_[B]=1` | ABADBD | B:1 |
| C−F | Find(C)=A，Find(F)=D，不同 | 秩相等（都是 1）→ D 挂到 A，`rank_[A]=2` | ABAABD | A:2 |
| A−D | Find(A)=A，Find(D)=A，**相同** | 丢弃，`parent` 不变 | ABAABD | — |
| B−C | Find(B)=B，Find(C)=A，不同 | rank[B]=1<rank[A]=2 → B 挂到 A | AAAABD | 不变 |

两点值得注意：

- **第 4 行的 `Find(F)`**：F 的 `parent` 是 D，D 的 `parent` 是自己，所以根是 D。 这一步走了两级；若树再深一点，**路径压缩**就会把 F 直接改挂到根上，下次查只要一步。
- **第 5 行的丢弃是"免费"的**：只做了两次 `Find`，没有任何写操作。 这正是并查集比"每次做一趟 DFS 判连通"高效得多的地方。

**最终 `parent[] = [A, A, A, A, B, D]`**，从任何顶点出发向上追都能到 A， 说明 6 个顶点已经并成了一块——这也是"cnt=n−1 时图必连通"的另一种验证方式。

**自检**：边数 =5=n−1 ✓；覆盖全部 6 个顶点 ✓；无回路 ✓； 被丢弃的 A−D 确实在已选边构成的回路上 ✓。

## 复杂度分析

逐步累加：

| 步骤 | 时间复杂度 | 说明 |
| --- | --- | --- |
| ① 边排序 | O(elog⁡e) | 用快排 / 归并 / 堆排序，见[排序算法比较](./../sorting/comparison.html) |
| ② 初始化并查集 | O(n) | 每个顶点各成一块 |
| ③ 遍历边 + 并查集操作 | O(e⋅α(n))≈O(e) | 每条边最多一次 `Find` 对 + 一次 `Union` |
| **总计** | O(elog⁡e) | **瓶颈在排序** |

**关键结论：O(elog⁡e) 只与边数有关，与顶点数几乎无关**（O(n) 那一项被吸收）。 这就是 Kruskal 适合**稀疏图**的定量依据。

**O(elog⁡e) 与 O(elog⁡n) 等价**：因为简单图中 e≤n(n−1)2<n2， 所以 log⁡e<2log⁡n，常数因子被 O 吸收。两种写法都对。

**与 Prim 的定量比较**（不是背结论，是代进去算）：

| 图的形态 | e 的量级 | Prim O(n2) | Kruskal O(elog⁡e) | 谁更快 |
| --- | --- | --- | --- | --- |
| 稀疏（如 e≈n） | n | n2 | nlog⁡n | **Kruskal** |
| 中等（如 e≈nlog⁡n） | nlog⁡n | n2 | nlog2⁡n | Kruskal（n 较大时） |
| 稠密（e≈n2/2） | n2 | n2 | n2log⁡n | **Prim** |

**空间复杂度 O(n+e)**：边集数组 O(e) + 并查集 O(n)。 注意 Kruskal 需要**边集数组**这种存储形式，而不是邻接矩阵—— 若题目给的是邻接矩阵，还要先花 O(n2) 把边抽出来。

## 易混淆知识点

| 一组概念 | 差别 | 判别依据 |
| --- | --- | --- |
| Kruskal vs Prim | 加边 vs 加点；中间状态是森林 vs 一棵树 | 看某一时刻已选的边连不连通 |
| 稀疏图用 Kruskal vs 稠密图用 Prim | O(elog⁡e) 只与 e 有关，O(n2) 只与 n 有关 | 把具体的 n,e 代进两个式子比大小 |
| 并查集判环 vs 遍历判环 | 前者均摊近似 O(1)，后者每次要 O(n+e) 做一趟 DFS/BFS | 问"这个判断要做多少次"：e 次，所以必须廉价 |
| `Find(u)==Find(v)` 成立 vs 边"没用" | 成立就必成环，必须丢弃 | 等价性来自"树上两点间路径唯一" |
| 排序是瓶颈 vs 并查集是瓶颈 | 排序 O(elog⁡e) 远大于 O(eα(n)) | 优化 Kruskal 要从排序下手（如边权范围小时用基数排序） |
| 边集数组 vs 邻接表 / 邻接矩阵 | Kruskal 需要"把边当成一等公民"排序 | 题目给邻接矩阵时要先 O(n2) 提取边 |
| 图不连通的检测 | Kruskal 靠 `cnt < n-1`，Prim 靠 `k == -1` | Kruskal 的检测是算法的自然副产品，不需额外代码 |

**Kruskal 会不会因为"先选了小边"而堵死后面的路？** 不会，这正是环性质保证的： 被丢弃的边一定是某个回路上的最大边，而回路上的最大边**必不属于任何 MST**，丢了不损失最优解。

**权值相同的边，先考察哪一条会影响结果吗？** 会影响**选出哪一棵 MST**（当 MST 不唯一时）， 但**不影响总权值**。所以答"总权值"的题不必纠结排序的稳定性， 答"写出 MST"的题则要说明自己采用的次序。

## 本节小结

学完本篇，你应该能够：

- 给定连通网，**按权值升序逐条考察并填出选中 / 丢弃的完整表格**， 写出每一步的连通块划分与最终总权值。
- 说清"加入某边是否成环"为什么等价于"两端是否已在同一集合"， 并用并查集的 `Find`/`Union` 落成代码。
- 完整叙述环性质及其证明，解释 Kruskal 丢弃一条边为什么是安全的。
- 拆出 O(elog⁡e) 的三段来源，指出瓶颈在排序，并据此在给定 n,e 下选 Prim 还是 Kruskal。
- 说明算法如何在图不连通时自然地给出"无 MST"的结论。

三条最关键的结论：

- **按边贪心 + 并查集判环**；正确性由环性质（回路上的最大边必不在 MST 中）保证。
- **O(elog⁡e)，瓶颈是排序**，只与边数有关，所以适合稀疏图； 稠密图上 e≈n2，会退化到 O(n2log⁡n)，不如 Prim。
- **中间状态是森林**（Prim 是一棵树），因此才需要并查集； 凑不够 n−1 条边就说明图不连通。
