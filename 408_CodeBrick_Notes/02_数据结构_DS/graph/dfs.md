## 知识框架

本节回答四个问题：

- 为什么图的遍历必须有 `visited[]`，而树的遍历不需要？
- 邻接矩阵 O(n2)、邻接表 O(n+e)，这两个数各自是怎么数出来的？
- 同一个图为什么会有多个不同的 DFS 序列？什么情况下它反而是唯一的？
- DFS 生成树上的边和原图上的边是什么关系？"非树边"意味着什么？

## 核心思想：走到底再回头

DFS 的策略是：**尽可能沿一条路径深入下去，走到无路可走时才退回上一个岔口换方向。**

它是[二叉树先序遍历](./../tree/preorder.html)在图上的推广。先序遍历"访问根 → 递归左 → 递归右"， DFS 则是"访问 v → 依次对 v 的每个未访问邻接点递归"。差别只有一处， 而这一处决定了图遍历的全部特殊性：

**树里从根到任一结点的路径唯一，所以一个结点不可能被访问两次； 图里存在环，沿着环走一圈会回到已经访问过的顶点。**

所以图的遍历必须额外维护一个访问标志数组 `visited[]`，初值全为 `false`， 一旦访问了顶点 vi 就置 `visited[i] = true`。没有它，DFS 在有环图上会无限递归。

三个要素：

- **递归 / 栈**：DFS 天然是递归的，系统调用栈自动完成"退回上一个岔口"；也可以用显式栈模拟。
- **`visited[]`**：防止顶点被重复访问。
- **回溯**：当前顶点所有邻接点都已访问时，退回到调用它的那一层，继续检查那一层剩下的邻接点。

## 算法步骤

- 初始化 `visited[]` 全为 `false`。
- 从起始顶点 v 出发，访问 v，置 `visited[v] = true`。
- 依次检查 v 的每个邻接点 w：若 `visited[w] == false`，则递归地对 w 执行 DFS； 否则跳过。
- v 的邻接点全部检查完毕后，回溯到调用 `DFS(v)` 的那一层。
- 若图非连通，第 2~4 步只能访问到一个连通分量。 需要在**外层循环**遍历所有顶点，对每个仍未访问的顶点再启动一次 DFS。

⚠️ 第 5 步的外层循环是最容易被省掉的一步。少了它，非连通图会漏掉除起点所在分量之外的全部顶点； 而**外层循环启动 DFS 的次数，恰好等于无向图连通分量的个数**——这是 DFS 最常用的一个副产品。

## 邻接矩阵实现
c

```
#define MAX_VERTEX 100
int visited[MAX_VERTEX];
int G[MAX_VERTEX][MAX_VERTEX];   // 邻接矩阵
int n;                            // 顶点数

void DFS(int v) {
    visited[v] = 1;               // 先置位再递归：置位晚了会在环上重复进入
    printf("%d ", v);             // 访问顶点 v
    for (int w = 0; w < n; w++) { // 必须扫完整行才知道哪些顶点与 v 相邻
        if (G[v][w] == 1 && !visited[w]) {
            DFS(w);
        }
    }
}

// 遍历整个图（处理非连通图）
void DFSTraverse(void) {
    for (int i = 0; i < n; i++)
        visited[i] = 0;
    for (int i = 0; i < n; i++) {
        if (!visited[i])
            DFS(i);               // 每次调用产生一棵 DFS 生成树
    }
}
```

**`visited[v] = 1` 必须写在递归之前**。若挪到 for 循环之后（"等孩子都处理完再置位"）， 那么在有环图上，从 v 出发绕环回到 v 时 `visited[v]` 仍是 0，会再次进入 `DFS(v)`， 无限递归直到栈溢出。**"先置位后展开"是所有图遍历的通用纪律。**

**复杂度 O(n2) 的来历**：`DFS` 被调用的次数等于顶点数 n（每个顶点恰好进入一次， 因为进入前必查 `visited`）；每次调用内部的 for 循环固定执行 n 次—— **即使该顶点只有 1 个邻居，也必须扫完一整行 n 格才能确认**。 所以总时间为 n×n=O(n2)，与边数无关。

## 邻接表实现
c

```
typedef struct ArcNode {
    int adjvex;                   // 邻接点编号
    struct ArcNode *next;         // 指向下一条边
} ArcNode;

typedef struct {
    int data;                     // 顶点数据
    ArcNode *first;               // 指向第一条边
} VNode;

VNode adjList[MAX_VERTEX];
int visited[MAX_VERTEX];
int n;

void DFS(int v) {
    visited[v] = 1;
    printf("%d ", v);
    ArcNode *p = adjList[v].first;
    while (p != NULL) {
        if (!visited[p->adjvex]) {
            DFS(p->adjvex);
        }
        p = p->next;              // 无论有没有递归下去，都要推进指针
    }
}

void DFSTraverse(void) {
    for (int i = 0; i < n; i++)
        visited[i] = 0;
    for (int i = 0; i < n; i++) {
        if (!visited[i])
            DFS(i);
    }
}
```

**`p = p->next` 必须在 if 之外**。若写进 `if (!visited[...])` 分支里， 遇到一个已访问的邻居时指针不推进，`while` 就会原地死循环。

**复杂度 O(n+e) 的来历**：把总代价拆成两部分——

- **顶点部分**：`DFS` 被调用 n 次，每次的固定开销（置位、访问、取链头）是 O(1)，共 O(n)； 外层 `DFSTraverse` 的循环也是 O(n)。
- **边部分**：每个边结点在整个遍历中**恰好被检查一次**（它只挂在一个顶点的链上， 而那个顶点只被展开一次）。有向图边结点数为 e，无向图为 2e，都是 O(e)。

两部分相加得 O(n+e)。**这个和号里的 n 不能省**：e=0 时仍要 O(n)。

## 非递归实现（显式栈）

408 会问"DFS 的非递归写法"，也会用它来考察对递归本质的理解。c

```
void DFS_NonRecursive(int v) {
    int stack[MAX_VERTEX], top = -1;
    stack[++top] = v;
    while (top >= 0) {
        int u = stack[top--];             // 出栈
        if (visited[u]) continue;         // 同一个顶点可能被多次入栈，出栈时再判一次
        visited[u] = 1;
        printf("%d ", u);
        // 逆序入栈，使出栈次序与递归版一致（先入的后出）
        for (int w = n - 1; w >= 0; w--)
            if (G[u][w] == 1 && !visited[w])
                stack[++top] = w;
    }
}
```

两处与递归版不同、且必须理解的地方：

- **出栈时还要再判一次 `visited`**。一个顶点可能在被弹出之前，从多条不同的边被重复压栈。 若只在入栈时判、出栈时不判，同一个顶点会被访问多次。
- **入栈顺序要逆序**，才能让出栈顺序与递归版的"按邻接次序依次深入"一致。 若按正序入栈，得到的是"按邻接次序倒着深入"的另一个合法 DFS 序列—— **它同样是合法的 DFS 序列，只是与递归版不同**。这本身就说明了 DFS 序列不唯一。

## 完整走查：DFS 序列与它的不唯一性

取如下无向图（顶点 0∼6）：E={(0,1),(0,2),(1,3),(1,4),(2,5),(2,6),(4,5)}

邻接表按**编号升序**建立：

| 顶点 | 边链表 |
| --- | --- |
| 0 | 1 → 2 |
| 1 | 0 → 3 → 4 |
| 2 | 0 → 5 → 6 |
| 3 | 1 |
| 4 | 1 → 5 |
| 5 | 2 → 4 |
| 6 | 2 |

从顶点 0 出发的执行过程：

| 步 | 当前顶点 | 检查到的邻居 | 动作 | 已输出序列 |
| --- | --- | --- | --- | --- |
| 1 | 0 | 1（未访问） | 访问 0，递归进 1 | 0 |
| 2 | 1 | 0（已访问）→ 3 | 访问 1，跳过 0，递归进 3 | 0 1 |
| 3 | 3 | 1（已访问） | 访问 3，链走完，**回溯到 1** | 0 1 3 |
| 4 | 1 | 4（未访问） | 递归进 4 | 0 1 3 |
| 5 | 4 | 1（已访问）→ 5 | 访问 4，递归进 5 | 0 1 3 4 |
| 6 | 5 | 2（未访问） | 访问 5，递归进 2 | 0 1 3 4 5 |
| 7 | 2 | 0（已访问）→ 5（已访问）→ 6 | 访问 2，递归进 6 | 0 1 3 4 5 2 |
| 8 | 6 | 2（已访问） | 访问 6，链走完，**逐层回溯至 0** | 0 1 3 4 5 2 6 |

**DFS 序列：0 1 3 4 5 2 6。**

**换一份邻接表，序列就变了**。若把顶点 0 的链改成 `2 → 1`（其余不变）， 第一步就会先进 2，得到序列 **0 2 5 4 1 3 6**： 0 → 2 → 5 →（5 的邻居 2 已访问，转 4）→ 4 →（4 的邻居 1 未访问）→ 1 → 3 → 回溯到 2 → 6。

**结论：DFS 序列不唯一，取决于起始顶点，以及每个顶点的邻接点被检查的次序。** 用邻接表存储时，链上次序由建表算法与边的输入次序决定（见[邻接表](./adjacency-list.html)）， 所以序列不唯一；用**邻接矩阵**存储时，内层循环固定按下标 0,1,…,n−1 扫行， 起点一旦确定，**序列就唯一**。

## DFS 生成树与生成森林

对连通图做一次 DFS，把**所有"引起某个顶点首次被访问"的边**挑出来， 这些边加上全部顶点构成一棵树，称为 **DFS 生成树**。

- **连通图**：一次 DFS 调用产生一棵 DFS 生成树。
- **非连通图**：外层循环会多次启动 DFS，每个连通分量产生一棵树，合起来是 **DFS 生成森林**。
- **有向图**：产生的是有向生成森林。

以上面的例子（起点 0、升序邻接表）为例，7 条原图边中被用来"首次到达"某顶点的有 6 条： (0,1),(1,3),(1,4),(4,5),(5,2),(2,6)——恰好 n−1=6 条，符合生成树的定义。 剩下的那条 (0,2) 是**非树边**：轮到顶点 0 检查邻居 2 时（它在链上排第二）， 2 已经被 5 提前访问过了，所以这条边没有承担"首次到达"的职责。

**非树边的意义**：在无向图上，每一条非树边都对应树上的一条祖先—后代路径， 因而必然与树边共同构成一个环。所以

**无向图有环 ⟺ DFS 过程中出现非树边**， 也即 ⟺ 边数 > 树边数 n−k（k 为连通分量数）。

图注：左图中每个顶点旁的数字是它被访问的次序（A 第 1 个、B 第 2 个……）， **实线箭头是"深入"，虚线箭头是"回溯"**——注意每条虚线都严格沿着来时的实线原路返回， 这正是递归调用栈弹栈的样子。右图把左图中所有实线箭头对应的边单独抽出来，就是 DFS 树； 树的形状明显"细长"，与 BFS 树的"扁宽"形成对照。 图源：殷人昆《数据结构——用面向对象方法与 C++ 描述》（第 2 版）图8.12 深度优先搜索示例，p364

## DFS 的两个直接应用

### 1. 求连通分量个数
c

```
int countComponents(void) {
    for (int i = 0; i < n; i++) visited[i] = 0;
    int cnt = 0;
    for (int i = 0; i < n; i++)
        if (!visited[i]) { DFS(i); cnt++; }   // 每启动一次 DFS 就多一个分量
    return cnt;
}
```

正确性：一次 `DFS(i)` 恰好访问 i 所在连通分量的全部顶点且不会越出该分量 （越出就意味着有跨分量的边，与"分量"的定义矛盾）。所以启动次数 = 分量数。

⚠️ 这条**只对无向图成立**。有向图上外层循环启动 DFS 的次数与强连通分量个数**没有**对应关系 （例如 0→1→2 这条链，从 0 启动一次就访问完，但它有 3 个强连通分量）。

**走查（非连通图）**：设图有 7 个顶点，边为 (0,1),(1,2),(3,4),(5,6)，邻接表升序。

| 外层 i | `visited[i]` | 动作 | 本次访问到的顶点 | `cnt` |
| --- | --- | --- | --- | --- |
| 0 | 否 | `DFS(0)` | 0, 1, 2 | 1 |
| 1, 2 | 是 | 跳过 | — | 1 |
| 3 | 否 | `DFS(3)` | 3, 4 | 2 |
| 4 | 是 | 跳过 | — | 2 |
| 5 | 否 | `DFS(5)` | 5, 6 | 3 |
| 6 | 是 | 跳过 | — | 3 |

**连通分量数 = 3**，DFS 生成森林由三棵树组成，树边分别是 {(0,1),(1,2)}、{(3,4)}、{(5,6)}，共 4 条 =n−k=7−3 ✓ （见[图的基本概念](./concepts.html)"生成森林有 n−k 条边"）。

**有向图上要格外小心**：一次 DFS 访问到的只是**当前顶点能到达的顶点集合**， 它既不是"连通分量"也不是"强连通分量"。两个反例足以说明这条计数法在有向图上完全失效：

- 有向图 0→1, 1→2：外层从 i=0 启动**一次**就访问完了全部 3 个顶点， 而它的**强连通分量有 3 个**（每个顶点各成一个）。1≠3。
- 有向图 0→1, 2→1：外层启动**两次**（i=0 访问 {0,1}，i=2 访问 {2}）， 强连通分量仍是 **3 个**。2≠3。

而且这两次的启动次数还依赖顶点编号的顺序——把第一个例子的顶点重新编号成 2→1, 1→0，外层就要从 i=0 起启动 3 次。 **结论：DFS 启动次数 = 连通分量数，这条只能用在无向图上； 有向图求强连通分量要用专门的算法（不在本篇范围内）。**

### 2. 判断有向图是否有环

DFS 判有向环要用**三色标记**，只用一个 `visited[]` 是不够的：c

```
// 0: 未访问；1: 访问中（正在递归栈上）；2: 已完成
int color[MAX_VERTEX];

int hasCycle(int v) {
    color[v] = 1;                             // 进入递归栈
    for (int w = 0; w < n; w++) {
        if (G[v][w] != 1) continue;
        if (color[w] == 1) return 1;          // 指回了栈上的顶点 → 有环
        if (color[w] == 0 && hasCycle(w)) return 1;
    }
    color[v] = 2;                             // 退出递归栈
    return 0;
}
```

**为什么两色不够**：设有向图 0→1, 0→2, 1→2。 从 0 出发 DFS：进 1，再从 1 进 2，回溯；回到 0 后检查邻居 2，发现它已被访问。 若只有"访问过 / 没访问过"两种状态，这里会误判成有环——但这个图显然无环。 关键区别是：**顶点 2 此刻已经"完成"（不在递归栈上），不是"正在访问中"**。 只有指向**仍在当前递归路径上**的顶点，才构成环。

## 复杂度分析

| 存储方式 | 时间复杂度 | 来历 |
| --- | --- | --- |
| 邻接矩阵 | O(n2) | n 次调用 × 每次扫一整行 n 格 |
| 邻接表 | O(n+e) | n 次调用的固定开销 + 每个边结点恰好被检查一次 |

**空间复杂度 O(n)**，由两部分构成：

- `visited[]` 数组：O(n)，与图的形态无关。
- **递归调用栈**：深度等于 DFS 树的最大深度。 最坏情形是图退化成一条链（如 0−1−2−⋯−(n−1)），此时递归深度为 n，栈空间 O(n)； 最好情形是星形图（一个中心连所有点），深度只有 2，栈空间 O(1)。 **所以 DFS 的空间复杂度写作 O(n) 指的是最坏情形。**

递归深度就是空间开销，这一条与[递归](./../stack-queue/recursion.html)里"每层递归占一个栈帧" 以及[复杂度分析](./../intro/complexity.html)里"空间复杂度要区分辅助数组与递归栈"是同一件事。 DFS 和 BFS 的空间同为 O(n)，但来源不同：DFS 是递归栈，BFS 是队列。

## 易混淆知识点

**1. DFS 与 BFS 的完整对照**

| 对比维度 | DFS | BFS | 判别依据 |
| --- | --- | --- | --- |
| 辅助结构 | 栈（递归调用栈或显式栈） | 队列 | 后进先出 → 深入；先进先出 → 逐层 |
| 策略 | 一条路走到底再回溯 | 一圈一圈向外扩散 | 看下一个访问的是"刚访问顶点的邻居"还是"最早入队顶点的邻居" |
| 与树遍历的类比 | 先序遍历 | 层序遍历 | 见[先序遍历](./../tree/preorder.html)、[层序遍历](./../tree/level-order-traversal.html) |
| 时间（邻接表） | O(n+e) | O(n+e) | 两者对边的访问次数完全相同 |
| 时间（邻接矩阵） | O(n2) | O(n2) | 同上 |
| 空间 | O(n)（递归栈，最坏为链形图） | O(n)（队列，最坏为星形图） | 量级同为 O(n)，但最坏情形的图形态相反 |
| 无权图最短路径 | **不能**求 | **能**求 | BFS 的层数就是距离，DFS 先到达不代表路径最短 |
| 生成树形状 | 细长 | 扁宽 | 由策略直接决定 |
| 典型应用 | 连通性、判环、拓扑排序（逆后序）、求路径 | 无权最短路径、层次划分、二部图判定 | 问题关心的是"能不能到"还是"最少几步到" |

**2. 遍历序列什么时候唯一？**

判据是"每一步的候选集合有没有歧义"：

- **邻接矩阵 + 固定起点 → 唯一**：内层永远按下标升序扫行，没有自由度。
- **邻接表 + 固定起点 → 不唯一**：链上次序由建表方式决定，同一个图可以有多份不同的邻接表。
- **换起点 → 一般都不唯一**。

**3. "DFS 序列相同"能推出"图相同"吗？**

不能。序列只记录了顶点被访问的次序，丢掉了非树边的信息。 上例中删掉边 (0,2) 后，从 0 出发的 DFS 序列仍是 0 1 3 4 5 2 6，但已经是另一个图了。

**4. DFS 能不能用来求无权图最短路径？**

不能。DFS 第一次到达某顶点时走的是"当前这条深入路径"，与最短无关。 反例：图 0−1, 1−2, 0−2，邻接表中 0 的链为 `1 → 2`。 DFS 从 0 出发：0→1→2，到达 2 用了 2 条边；而 0−2 直接相连，真实距离是 1。 求无权最短路径必须用 [BFS](./bfs-shortest.html)。

**5. `visited[v] = true` 放在递归前还是递归后？**

必须在**递归前**（也即"访问顶点的同时置位"）。放在后面，环上的顶点会被重复进入， 导致无限递归。这条纪律对 BFS 同样成立——BFS 是"入队时置位"，不是"出队时置位"。

## 本节小结

学完本篇，你应该能够：

- 给定图与邻接表（或邻接矩阵），**逐步写出 DFS 序列**，并说清每一步是"深入"还是"回溯"。
- 画出 DFS 生成树 / 生成森林，指出哪些是树边、哪些是非树边，并由非树边判断图中是否有环。
- 写出递归与非递归两版 DFS 代码，并解释非递归版为什么要"出栈时再判一次 `visited`"、 "为什么要逆序入栈"。
- 独立推出 O(n2) 与 O(n+e) 两个复杂度，而不是背结论；说清空间 O(n) 里递归栈那一部分 在什么图形上取到最坏。
- 用 DFS 求无向图连通分量个数，用三色标记判有向图是否有环，并解释两色为什么不够。

三条最关键的结论：

- **图遍历必须有 `visited[]`，且必须在访问顶点的同时置位**——因为图里有环。
- **邻接矩阵 O(n2)、邻接表 O(n+e)**，差别的根是"找邻接点要不要扫一整行"。
- **DFS 序列与生成树都不唯一**（邻接矩阵 + 固定起点时唯一）； 外层循环启动 DFS 的次数 = 无向图连通分量个数。
