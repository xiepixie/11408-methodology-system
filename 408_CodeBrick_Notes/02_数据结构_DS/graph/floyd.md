# Floyd 算法

## 大纲定位

本篇对应 2026 大纲 **五、图 （四）图的基本应用 2. 最短路径**。

**分工边界**：这一条由三篇分担，本篇管**所有顶点对**这一类。

- **本篇（Floyd）**负责：动态规划的状态定义与转移方程、 **为什么三重循环的 k 必须在最外层**（给出会出错的具体图并逐步执行）、 逐轮矩阵手算、`path[][]` 的更新式与路径还原、负权边与负权回路的边界。
- [BFS 最短路径](./bfs-shortest.html) 管无权图，[Dijkstra](./dijkstra.html) 管单源非负权图。 **三种算法的选型对照表在 [BFS 最短路径](./bfs-shortest.html) 的《易混淆知识点》**，本篇不重复。
- 邻接矩阵的定义与"无边填 ∞、对角线填 0"的约定见[邻接矩阵](./adjacency-matrix.html)。

## 知识框架

本节回答四个问题：

- Floyd 的状态是什么？"D(k)"里的 k 到底表示什么，不是"第 k 轮"这么含糊的说法？
- 三重循环的 k 为什么必须在最外层？把它挪到最内层，具体会在哪张图上算错？
- `path[i][j] = path[k][j]` 这个更新式为什么不是 `path[i][j] = k`？
- Floyd 能处理负权边、不能处理负权回路——这两句话各自的理由是什么？

## 核心思想：逐步放宽"允许走哪些中转点"

Floyd 是**动态规划**，它的状态定义必须说准，否则后面所有推理都是空的：

D(k)[i][j] = 从 vi 到 vj，且**中间顶点的序号都不超过 k** 的最短路径长度。

注意"中间顶点"三个字：起点 i 与终点 j 本身不受这个限制，受限的只是路上经过的中转点。

- D(−1)[i][j]：不许经过任何中转点，只能走直连边——**就是邻接矩阵本身**。
- D(n−1)[i][j]：所有顶点都可以当中转——**就是最终答案**。

**状态转移方程**：D(k)[i][j]=min(D(k−1)[i][j],  D(k−1)[i][k]+D(k−1)[k][j])

**推导**：考虑"中间顶点序号不超过 k"的最短路径，按**它到底经不经过 vk** 分成两类， 不重不漏：

- **不经过 vk**：那它的中间顶点序号其实都不超过 k−1，长度就是 D(k−1)[i][j]。
- **经过 vk**：把这条路径在 vk 处切成两段 i⇝k 与 k⇝j。 由于最短路径上的顶点不重复（无负权回路时），这两段的中间顶点序号都不超过 k−1， 且各自必须是最短的（否则整条路径可以更短）。所以长度是 D(k−1)[i][k]+D(k−1)[k][j]。

两类取小者，即得转移方程。∎

**这一步就是全篇的钥匙**：k 不是"第几轮"，而是"**允许使用的中转点集合的上界**"。 每让 k 增大 1，就等于把 vk 加进"可用中转点"这个池子，重新审视所有点对。

## 算法实现
c

```
#define V 4
#define INF 0x3f3f3f3f      // 取这个值是为了 INF+INF 不溢出 int

int dist[V][V];  // 最短距离矩阵
int path[V][V];  // 前驱矩阵：path[i][j] 是 i→j 最短路径上 j 的前一个顶点

// 初始化：直接由邻接矩阵得到 D^(-1)
void init(int graph[V][V]) {
    for (int i = 0; i < V; i++)
        for (int j = 0; j < V; j++) {
            dist[i][j] = graph[i][j];     // 无边处为 INF，对角线为 0
            if (i != j && graph[i][j] < INF)
                path[i][j] = i;           // 有直连边：j 的前驱就是 i
            else
                path[i][j] = -1;          // 无路径（或 i==j）
        }
}

// Floyd 核心：k 必须在最外层
void floyd(void) {
    for (int k = 0; k < V; k++)             // ① 枚举"允许的中转顶点上界"
        for (int i = 0; i < V; i++)         // ② 枚举起点
            for (int j = 0; j < V; j++)     // ③ 枚举终点
                if (dist[i][k] + dist[k][j] < dist[i][j]) {
                    dist[i][j] = dist[i][k] + dist[k][j];
                    path[i][j] = path[k][j];  // 注意不是 = k，理由见下
                }
}
```

### `path[i][j] = path[k][j]` 为什么不是 `= k`

`path[i][j]` 的定义是"i→j 最短路径上 **j 的前一个顶点**"， 而不是"这条路径经过的某个中转点"。

新路径是 i⇝k⇝j，那么 j 的前驱应该是 **k⇝j 这一段上 j 的前驱**，也就是 `path[k][j]`。 只有当 k→j 是一条直连边时，`path[k][j]` 才恰好等于 k； 若 k 到 j 还要绕别的点，写 `= k` 就把中间那些顶点丢了，回溯出来的路径是断的。

**用本篇下面的例子验证**：最终 0→2 的最短路径是 0→3→2， path[0][2]=3——这是在 k=3 那一轮由 `path[3][2]` 赋来的，而 3→2 恰是直连边， 所以 `path[3][2]` 就是 3。若换成一条要绕路的情形，`= k` 立刻出错。

### 就地更新为什么不会出错

代码里只有一个 `dist[][]` 数组，第 k 轮读到的 `dist[i][k]` 与 `dist[k][j]` 可能已经在**本轮**被改过了。这会不会破坏"用 D(k−1) 推 D(k)"的前提？

不会。因为第 k 轮中 `dist[i][k]` 与 `dist[k][j]` 这两类元素**本轮不可能被改变**： 要改 `dist[i][k]` 就得满足 `dist[i][k] + dist[k][k] < dist[i][k]`， 即 `dist[k][k] < 0`——只有存在负权回路时才可能。 所以在无负权回路的前提下，**第 k 行与第 k 列在第 k 轮是"冻结"的**， 就地更新与用两个数组滚动完全等价。这也顺带说明了负权回路为什么会让算法失去意义。

以 4 顶点**有向图**为例，初始邻接矩阵（∞ 表示无弧）：

|  | v0 | v1 | v2 | v3 |
| --- | --- | --- | --- | --- |
| **v0** | 0 | 5 | ∞ | 7 |
| **v1** | ∞ | 0 | 4 | ∞ |
| **v2** | 3 | ∞ | 0 | 2 |
| **v3** | ∞ | ∞ | 1 | 0 |

也就是这 6 条弧：0→1 权 5、0→3 权 7、1→2 权 4、 2→0 权 3、2→3 权 2、3→2 权 1。

**k=0（允许经过 v0 中转）**——逐格检查 dist[i][0]+dist[0][j]：

- dist[1][2]：∞+∞=∞≥4，不更新
- dist[1][3]：∞+7=∞≥∞，不更新
- dist[2][1]：3+5=8<∞，**更新为 8**
- dist[2][3]：3+7=10>2，不更新
- dist[3][1]：∞+5=∞，不更新
- dist[3][2]：∞+∞=∞≥1，不更新

D(0)：

|  | v0 | v1 | v2 | v3 |

| **v0** | 0 | 5 | ∞ | 7 |
| **v1** | ∞ | 0 | 4 | ∞ |
| **v2** | 3 | **8** | 0 | 2 |
| **v3** | ∞ | ∞ | 1 | 0 |

**k=1（允许经过 v0,v1）**：

- dist[0][2]：5+4=9<∞，**更新为 9**
- dist[0][3]：5+∞=∞≥7，不更新
- dist[2][0]：8+∞=∞≥3，不更新
- dist[2][3]：8+∞=∞≥2，不更新
- dist[3][0]、dist[3][2]：dist[3][1]=∞，均不更新

D(1)：

|  | v0 | v1 | v2 | v3 |
| --- | --- | --- | --- | --- |
| **v0** | 0 | 5 | **9** | 7 |
| **v1** | ∞ | 0 | 4 | ∞ |
| **v2** | 3 | 8 | 0 | 2 |
| **v3** | ∞ | ∞ | 1 | 0 |

**k=2（允许经过 v0,v1,v2）**——这一轮改动最多：

- dist[0][1]：9+8=17≥5，不更新
- dist[0][3]：9+2=11≥7，不更新
- dist[1][0]：4+3=7<∞，**更新为 7**
- dist[1][3]：4+2=6<∞，**更新为 6**

- dist[0][2]：7+1=8<9，**更新为 8**

### `path[][]` 与路径还原

最终的前驱矩阵：

| path[i][j] | j=0 | j=1 | j=2 | j=3 |
| --- | --- | --- | --- | --- |
| i=0 | −1 | 0 | **3** | 0 |
| i=1 | **2** | −1 | 1 | **2** |
| i=2 | 2 | **0** | −1 | 2 |
| i=3 | **2** | **0** | 3 | −1 |

**读法（从终点往回倒推）**，以 3→1 为例：

- path[3][1]=0 → 顶点 1 的前驱是 0；
- path[3][0]=2 → 顶点 0 的前驱是 2；
- path[3][2]=3 → 顶点 2 的前驱是 3，已到起点，停。

倒过来即 **3→2→0→1**，验算 1+3+5=9=dist[3][1] ✓。

再验一个：0→2。path[0][2]=3 → 2 的前驱是 3；path[0][3]=0 → 3 的前驱是 0，到起点。 路径为 **0→3→2**，长度 7+1=8=dist[0][2] ✓。

**每还原一条路径都要验算长度**——这是手算里唯一可靠的自检。

## k 为什么必须在最外层

这是本篇最需要讲透的一条。

**原理上的理由**：由状态定义，D(k) 的每一格都必须由**完整的 D(k−1)** 推出。 k 在最外层，意味着"先把中转集合固定为 {v0,…,vk}，再把所有点对全部刷新一遍"， 这才保证进入 k+1 轮时手上是一份完整、一致的 D(k)。

若把 k 挪到内层（写成 `for i → for j → for k`），语义就变成了 "对每一对 (i,j)，用**当前手头这份半成品**矩阵试一遍所有中转点"。 此时 dist[i][k] 与 dist[k][j] 可能还没被更新到位，**该改的没改成，而且再也没有机会补**。

**具体反例**（4 个顶点的有向图，只有 3 条弧，构成一条编号递减的链）：0→ 1 3,3→ 1 2,2→ 1 1

初始矩阵：

|  | 0 | 1 | 2 | 3 |
| --- | --- | --- | --- | --- |
| **0** | 0 | ∞ | ∞ | 1 |
| **1** | ∞ | 0 | ∞ | ∞ |
| **2** | ∞ | 1 | 0 | ∞ |
| **3** | ∞ | ∞ | 1 | 0 |

正确答案：dist[0][1]=3（路径 0→3→2→1）。

**错误写法 `for i → for j → for k` 的逐步执行**：

- **i=0**：

- j=1：试所有 k——k=2 时 dist[0][2]=∞；k=3 时 dist[0][3]+dist[3][1]=1+∞=∞。 **无更新，dist[0][1] 仍为 ∞。**（dist[3][1] 此刻还没算出来，因为 i=3 排在后面。）
- j=2：k=3 时 dist[0][3]+dist[3][2]=1+1=2<∞，更新 dist[0][2]=2。 ——**可惜晚了，j=1 已经过去了，本轮不会回头。**
- **i=1,2**：无有效更新。
- **i=3**：j=1 时 k=2：dist[3][2]+dist[2][1]=1+1=2，更新 dist[3][1]=2。 ——**同样晚了，i=0 已经过去了。**

**最终 dist[0][1]=∞，而正确答案是 3。算法给出了错误结果。**

**正确写法 `for k → for i → for j`**：

- k=0：无更新（没有弧指向 0）。
- k=1：无更新（顶点 1 没有出弧）。
- k=2：dist[3][1]=dist[3][2]+dist[2][1]=1+1=2。
- k=3：dist[0][1]=dist[0][3]+dist[3][1]=1+2=3 ✓； dist[0][2]=dist[0][3]+dist[3][2]=1+1=2 ✓。

**为什么这个反例要把链造成"编号递减"？** 因为若链是 0→1→2→3 这种编号递增的形状， `i-j-k` 的扫描次序恰好顺着链的方向，误打误撞也能算对。 **"某些图上碰巧对"正是错误循环序最危险的地方**——不构造这种逆序的图， 你在纸上试几个例子可能永远发现不了它是错的。

**内两层 i 与 j 的先后可以互换**，因为它们只是遍历"所有点对"，彼此无依赖。 真正有依赖关系的只有 k。

## 负权边与负权回路

**Floyd 能处理负权边。** 它的正确性来自动态规划的分类讨论（经不经过 vk）， 全程没有用到"边权非负"这个前提——这与 [Dijkstra](./dijkstra.html) 的贪心正确性形成鲜明对照： 后者的证明恰恰卡在"非负"那一步。

**Floyd 不能处理负权回路。** 存在负权回路时，沿回路绕一圈总权变小、绕两圈更小， **最短路径根本不存在**（可以无限减小），此时任何算法给出的"答案"都没有意义。

**检测方法**：算法结束后检查对角线——**若存在 dist[i][i]<0，则图中存在负权回路**。 因为 dist[i][i]<0 意味着"从 i 出发绕一圈回到 i 的总权是负的"，这正是负权回路的定义。

前面"就地更新为什么不会出错"那一节用到的正是同一个条件： 只有 dist[k][k]<0 时第 k 行/列才可能在本轮被改动。 **无负权回路 ⇒ 对角线恒为 0 ⇒ 就地更新安全**，三件事是同一件事的三种说法。

## 复杂度分析

| 指标 | 复杂度 | 来历 |
| --- | --- | --- |
| 时间 | O(n3) | 三重循环，每层各 n 次；循环体是 O(1) 的一次比较与赋值 |
| 空间 | O(n2) | `dist[][]` 与 `path[][]` 各占 n2；**不需要** O(n3) 的滚动数组 |

**与"对每个顶点跑一次 Dijkstra"的比较**：后者是 n×O(n2)=O(n3)，**同阶**。 差别在三处：

- **代码量**：Floyd 核心只有三重循环加一个 `if`，Dijkstra 要维护 `visited` 与选点循环。
- **负权边**：Floyd 支持，Dijkstra 不支持。
- **稀疏图**：n 次堆优化 Dijkstra 是 O(nelog⁡n)，稀疏时优于 Floyd 的 O(n3)。

所以"全源最短路径一律用 Floyd"是不对的，**稀疏图上跑 n 次堆优化 Dijkstra 更快**； 但只要图中有负权边，就只能用 Floyd（或 Bellman-Ford 系）。

**Floyd 也适用于无向图**：把无向边看成方向相反的两条弧即可（矩阵对称）， 算法一字不改。

## 易混淆知识点

| 一组概念 | 差别 | 判别依据 |
| --- | --- | --- |
| k 在最外层 vs 在最内层 | 前者对，后者错 | 记状态定义："k 是允许的中转集合上界"，必须先固定集合再刷全表 |
| i 与 j 的先后 | 可以互换 | 它们之间没有依赖，只有 k 有 |
| `path[i][j] = path[k][j]` vs `= k` | 前者对 | `path` 存的是"j 的前驱"，不是"某个中转点" |
| Floyd 支持负权边 vs 不支持负权回路 | 前者是能力，后者是问题本身无解 | 问"最短路径存不存在"：负回路下不存在 |
| D(k) 的 k | 是"中转点序号上界"，不是"第 k 短" | 复述状态定义即可排除误解 |
| Floyd vs n 次 Dijkstra | 同为 O(n3)（朴素）；稀疏图上 n 次堆优化 Dijkstra 更快 | 先问有没有负权边，再比 n3 与 nelog⁡n |
| Floyd vs Dijkstra 的算法思想 | 动态规划 vs 贪心 | 前者枚举中转点做分类讨论，后者每轮"钉死"一个顶点 |
| 就地更新 vs 滚动数组 | 无负权回路时两者等价 | 第 k 行与第 k 列在第 k 轮不会变 |

**为什么初始矩阵记作 D(−1) 而不是 D(0)？** 因为顶点编号从 0 开始，D(0) 已经表示"允许经过 v0 中转"了。 若顶点从 1 编号，初始矩阵就记作 D(0)。**编号习惯不同，上标随之平移，含义不变。**

## 本节小结

学完本篇，你应该能够：

- 准确复述状态定义"D(k)[i][j] = 中间顶点序号不超过 k 的最短路径长度"， 并由"经不经过 vk"的分类讨论推出转移方程。
- 给定邻接矩阵，**逐轮写出 D(0),D(1),…,D(n−1) 与 `path[][]`**， 并从 `path[][]` 还原任意一条最短路径、验算其长度。
- **构造出一个把 k 放在内层就会算错的图**，并逐步执行说明它错在哪一格。
- 说清 Floyd 为什么支持负权边、为什么不支持负权回路，以及如何用对角线检测负权回路。
- 在给定 n,e 与"有无负权边"的条件下，判断该用 Floyd 还是 n 次 Dijkstra。

三条最关键的结论：

- **k 是"允许的中转点上界"，所以必须在最外层**；内层写法在编号逆序的链上会给出 ∞。
- **`path[i][j] = path[k][j]`**，因为 `path` 记的是终点的前驱，不是中转点。
- **O(n3) 时间、O(n2) 空间；支持负权边，不支持负权回路**（判据：dist[i][i]<0）。

- 严蔚敏《数据结构（C 语言版）》（第 2 版）**印刷 p174**，§6.6.2 之 2： "求解每一对顶点之间的最短路径有两种方法：其一是分别以图中的每个顶点为源点共调用 n 次 迪杰斯特拉算法；其二是采用下面介绍的弗洛伊德 (Floyd) 算法。 两种算法的时间复杂度均为 O(n3)，但后者形式上较简单。" 同页给出两个辅助数组：`Path[i][j]` 为"最短路径上顶点 vj 的前一顶点的序号"， `D[i][j]` 记录 vi 与 vj 之间的最短路径长度。
- 同书**印刷 p174**：算法步骤逐层描述"在 vi 和 vj 间加入顶点 vk…… 取其中较短者作为 vi 到 vj 的中间顶点序号不大于 k 的最短路径"， 并给出方阵序列 D(−1),D(0),D(1),…,D(n−1) 与递推式 D(k)[i][j]=min{D(k−1)[i][j], D(k−1)[i][k]+D(k−1)[k][j]}—— 本篇的状态定义与转移方程即以此为准。
- 同书**印刷 p175**：`ShortestPath_Floyd` 的完整实现， 其中更新时写的正是 `Path[i][j] = Path[k][j]`（"更改 j 的前驱为 k"一侧的写法）， 与本篇一致；同页并给出从 `Path` 逐级回溯读出路径的示范。
