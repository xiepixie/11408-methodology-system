# Prim 算法

## 大纲定位

本篇对应 2026 大纲 **五、图 （四）图的基本应用 1. 最小（代价）生成树**。

**分工边界**：这一条由两篇分担，两者求的是同一个东西，贪心的**粒度**不同：

- **本篇（Prim）**："加点法"——每次把一个顶点并入生成树。 本篇同时负责**最小生成树的公共基础**：MST 的定义、MST 性质（割性质）及其证明、 MST 唯一性的判据。这些内容[Kruskal](./kruskal.html) 那一篇直接引用，不重复展开。
- **[Kruskal](./kruskal.html)**："加边法"——每次把一条边并入生成森林，用并查集判环。 两者的选型对照放在**本篇的《易混淆知识点》**。
- 生成树本身的定义（含全部顶点、n−1 条边、极小连通子图）见[图的基本概念](./concepts.html)。

## 知识框架

本节回答四个问题：

- 为什么"每次选连接树内与树外的最小边"这种目光短浅的贪心，能得到全局最优？
- `lowcost[]` 和 `closest[]` 各存什么？为什么两个数组必须同步更新？
- O(n2) 这个复杂度里的两个 n 分别来自哪里？为什么它与边数无关？
- 最小生成树什么时候唯一、什么时候不唯一？"有等权边"是不是就一定不唯一？

## 最小生成树是什么

在一个连通网的**所有生成树**中，各边**代价之和最小**的那一棵，称为 **最小代价生成树（Minimum Cost Spanning Tree）**，简称最小生成树（MST）。

三条由定义直接得到的性质：

- **MST 含全部 n 个顶点，恰有 n−1 条边**（因为它首先是一棵生成树）。
- **MST 不含回路**（树的定义）。
- **图必须连通**才存在 MST；非连通图只有"最小生成森林"。

**典型的应用形态**：n 个城市之间要架通信线路，任意两城之间架线各有造价， 要让 n 个城市连通且总造价最小。连通 n 个城市至少要 n−1 条线路， 而"用 n−1 条边把所有顶点连起来"正是生成树；"总造价最小"就是最小。

## MST 性质：贪心为什么正确

这条性质是 Prim 与 Kruskal **共同的正确性基础**，两个算法都是它的直接推论。

**MST 性质（割性质）**：设 N=(V,E) 是连通网，U 是顶点集 V 的一个非空真子集。 若 (u,v) 是**跨越 U 与 V−U 的所有边中权值最小的一条**（u∈U, v∈V−U）， 则**必存在一棵包含边 (u,v) 的最小生成树**。

**证明（反证 + 交换）**：

假设网 N 的任何一棵最小生成树都不含 (u,v)。取任意一棵最小生成树 T。 把边 (u,v) 加进 T，由生成树的性质（树上任意两点间已有唯一路径，再加一条边必成环）， T 中必出现一个包含 (u,v) 的回路。

这个回路从 u 出发经 (u,v) 到 v，再沿 T 中的树边回到 u。 既然它起于 U 内、终于 U 内，而中途去过 V−U，那么这条回路上**必然还有另一条跨越边**(u′,v′)，其中 u′∈U, v′∈V−U。

删去 (u′,v′)，回路被打断，得到的仍是一棵包含全部顶点的生成树，记作 T′。而w(T′)=w(T)+w(u,v)−w(u′,v′)

由于 (u,v) 是所有跨越边中权值最小的，w(u,v)≤w(u′,v′)，故 w(T′)≤w(T)。 又 T 已是最小生成树，所以 w(T′)=w(T)，即 T′ **也是**一棵最小生成树，而它含有 (u,v)。 这与假设矛盾。∎

**Prim 正是在反复使用这条性质**：把已并入生成树的顶点集看作 U， 每一轮选的"连接 U 与 V−U 的最小边"就是割性质里的 (u,v)， 所以每一步选出的边都必定属于某棵最小生成树，n−1 步之后得到的就是一棵完整的最小生成树。

**注意结论的措辞是"存在一棵包含它的 MST"，不是"所有 MST 都包含它"。** 当存在多条并列的最小跨越边时，任选其一都能走到某棵 MST，但走到的可能是不同的 MST。 这正是 MST 可能不唯一的根源。

## 核心思想：加点法

Prim 从任意一个顶点出发，**每次把"离当前生成树最近的顶点"并入树中**：

- 维护两个集合：已并入 MST 的顶点集 U，未并入的 V−U。
- 每轮从 V−U 中选出到 U 距离最小的顶点 k，把它并入 U，同时选中那条边。
- 并入后，U 变大了，V−U 中各顶点"到 U 的最近距离"可能变小，需要用新并入的 k 去更新。
- 共执行 n−1 轮，得到 n−1 条边。

两个辅助数组承担全部状态：

| 数组 | 含义 |
| --- | --- |
| `lowcost[j]` | 顶点 j（在 V−U 中）到集合 U 的**最小边权**，即 min{cost(u,j)∣u∈U} |
| `closest[j]` | 取到这个最小值的那个 U 中的顶点，即"j 挂在树上的哪个点最省" |

**两者必须同步更新**：`lowcost` 回答"多少"，`closest` 回答"接在哪"。 只更新前者，最后就说不出选中的是哪条边；只更新后者，就无法比较大小。

**与 Dijkstra 的关系**：两者的骨架完全相同——都是"选最小、并入、松弛"。 **唯一的差别在松弛式**：Dijkstra 更新的是 `dist[j] = min(dist[j], dist[k] + cost[k][j])` （到**源点**的距离），Prim 更新的是 `lowcost[j] = min(lowcost[j], cost[k][j])` （到**树**的距离，不累加）。少了那个 `dist[k] +`，就从"最短路径"变成了"最小生成树"。 见 [Dijkstra](./dijkstra.html)。

## 算法实现
c

```
#define MAXV 100
#define INF  0x3f3f3f3f      // 无边填 INF，且 INF+INF 不会溢出 int

// cost[][] 为无向网的邻接矩阵（无边处为 INF，对角线为 0）
// 从 v0 出发构造最小生成树，输出各条边，返回总权值；图不连通时返回 -1
int Prim(int cost[][MAXV], int n, int v0) {
    int lowcost[MAXV], closest[MAXV], visited[MAXV] = {0};
    int total = 0;

    // 初始化：U = {v0}，其余顶点到 U 的距离就是它到 v0 的边权
    for (int i = 0; i < n; i++) {
        lowcost[i] = cost[v0][i];
        closest[i] = v0;
    }
    visited[v0] = 1;

    for (int i = 1; i < n; i++) {        // 还要并入 n-1 个顶点
        // ① 选最小：在 V-U 中找 lowcost 最小的顶点 k
        int min = INF, k = -1;
        for (int j = 0; j < n; j++)
            if (!visited[j] && lowcost[j] < min) {
                min = lowcost[j];
                k = j;
            }
        if (k == -1) return -1;          // V-U 中所有顶点都不可达 → 图不连通
        // 少了这一句，下一行的 visited[-1] 就是越界写，这是本算法最常见的漏判

        visited[k] = 1;                  // ② 并入：k 加入 U
        printf("(%d, %d) w=%d\n", closest[k], k, lowcost[k]);
        total += lowcost[k];

        // ③ 更新：新并入的 k 可能让某些顶点离树更近
        for (int j = 0; j < n; j++)
            if (!visited[j] && cost[k][j] < lowcost[j]) {
                lowcost[j] = cost[k][j];   // 注意：不累加，只取这一条边的权
                closest[j] = k;            // 两个数组必须一起改
            }
    }
    return total;
}
```

**三处细节**：

- **更新式里没有加号**。`lowcost[j] = cost[k][j]` 而不是 `lowcost[k] + cost[k][j]`—— Prim 求的是"到树的距离"，树上任意一点都算"已到达"，不需要累加路径。 写成累加就变成了一个（错误的）最短路径算法。
- **`k == -1` 必须判**。图不连通时，V−U 里剩下的顶点 `lowcost` 全是 `INF`， `lowcost[j] < min` 永远不成立，`k` 保持 −1，接着 `visited[k]` 就越界了。
- **另一种等价写法是省掉 `visited[]`，改用 `lowcost[k] = 0` 标记已并入**。 两种写法效果相同，但**不能混用**：若既用 `lowcost[k]=0` 标记又不判 `visited`， 下一轮选最小时会把 0 当成最小值反复选中同一个顶点。本篇统一用 `visited[]`。

## 完整走查

取如下无向网（6 个顶点，10 条边，权值全部列出）：

| 边 | 权 | 边 | 权 |
| --- | --- | --- | --- |
| A−B | 6 | C−D | 5 |
| A−C | 1 | C−E | 6 |
| A−D | 5 | C−F | 4 |
| B−C | 5 | D−F | 2 |
| B−E | 3 | E−F | 6 |

从 A 出发。表中每格写"`lowcost`(`closest`)"，`—` 表示该顶点已并入 U：

| 轮次 | U | B | C | D | E | F | 选中顶点 | 选中的边 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 初始 | {A} | 6(A) | **1(A)** | 5(A) | ∞(A) | ∞(A) | C | (A,C) 权 1 |
| 1 | {A,C} | 5(C) | — | 5(A) | 6(C) | **4(C)** | F | (C,F) 权 4 |
| 2 | {A,C,F} | 5(C) | — | **2(F)** | 6(C) | — | D | (F,D) 权 2 |
| 3 | {A,C,F,D} | **5(C)** | — | — | 6(C) | — | B | (C,B) 权 5 |
| 4 | {A,C,F,D,B} | — | — | — | **3(B)** | — | E | (B,E) 权 3 |

逐轮的更新解释（这是手算最容易漏的一步）：

- **第 1 轮并入 C 之后**：B 原本挂在 A 上要 6，现在挂 C 只要 5，更新为 5(C)； D 挂 A 要 5、挂 C 也要 5，**不是严格小于，不更新**，仍是 5(A)； E 从 ∞ 变 6(C)；F 从 ∞ 变 4(C)。
- **第 2 轮并入 F 之后**：D 挂 F 只要 2，比原来的 5 小，更新为 2(F)。 E 挂 F 要 6，与原来的 6(C) 相等，**不更新**。
- **第 3 轮并入 D 之后**：D 与 B、E 都没有边，无更新。
- **第 4 轮并入 B 之后**：E 挂 B 只要 3，比 6 小，更新为 3(B)。

**结果**：MST 的 5 条边是 (A,C),(C,F),(F,D),(C,B),(B,E)， 总权值 1+4+2+5+3=15。

**自检**：边数 =5=n−1 ✓；含全部 6 个顶点 ✓；无回路 ✓。 这三条不满足任何一条，就说明前面某一轮算错了。

图注：六个快照 (a)→(f) 是 Prim 从顶点 0 出发逐轮生长的样子。 注意**每一步都只多出一个顶点和一条边**，而且已选中的部分**始终是连通的一棵树**—— 这是 Prim 与 Kruskal 最直观的区别（Kruskal 的中间状态是若干棵互不相连的树，见那一篇）。 图源：殷人昆《数据结构——用面向对象方法与 C++ 描述》（第 2 版）图8.18 用 Prim 算法构造最小生成树的过程，p374

## 最小生成树的唯一性

**结论一：MST 的总权值一定唯一。** 因为"最小"这个量是图的固有属性—— 不同的最小生成树只是达到同一个最小值的不同方案。

**结论二：若所有边权互不相同，则 MST 唯一。** 理由：由割性质，任何一步的"最小跨越边"都是唯一的（没有并列）， 整个贪心过程没有任何选择余地，结果自然唯一。

**结论三：存在等权边时，MST 可能唯一，也可能不唯一。** "有等权边"只是不唯一的**必要条件**，不是充分条件——这是本节最容易记反的一处。

- **反例（有等权边但 MST 唯一）**：上面走查用的那张图。 它有三条权为 5 的边（A−D、B−C、C−D）， 但穷举全部生成树可以验证 MST 只有一棵（权值 15，边集就是上面那 5 条）。 原因是那些等权边中只有 B−C 在关键时刻是唯一可选的跨越边， 另外两条在被考虑时其两端已经连通了。
- **正例（MST 不唯一）**：三角形 A−B=1, B−C=1, A−C=1。 任取两条边都构成一棵权值为 2 的最小生成树，共 3 棵。

**实操判据**：想判断 MST 是否唯一，不要只看"有没有等权边"，而要看 **"某一轮里有没有出现两条权值相同、且都能被选中（即两端此时分属不同连通块）的边"**。 只有这种真正的并列才制造出不同的 MST。

## 由割性质与环性质直接判边

有了割性质（Prim 的依据）与环性质（[Kruskal](./kruskal.html) 的依据）， 不必真的跑一遍算法，就能判断某条边**是否必定属于 / 必定不属于** MST。 这类判断题只要抓住两条规则：

| 规则 | 结论 | 依据 |
| --- | --- | --- |
| 某条边是**跨越某个割的唯一最小边**（严格小于其他跨越边） | **必定属于每一棵** MST | 割性质；若不含它，交换后总权严格变小，矛盾 |
| 某条边是**某个回路上的唯一最大边**（严格大于回路上其他边） | **必定不属于任何** MST | 环性质 |
| 全图**权值最小的边**（若唯一） | **必定属于** MST | 它是"以它一端为 U"这个割的唯一最小跨越边 |
| 全图**权值最大的边**（若唯一）且它在某个回路上 | **必定不属于** MST | 它是那个回路上的唯一最大边 |

**用走查那张图检验**：

- A−C 权 1 是全图唯一的最小边 → 必在 MST 中 ✓（Prim 与 Kruskal 都选了它）。
- A−D 权 5 在回路 A−C−F−D−A 上（权分别为 5,1,4,2）， 它是这个回路上的**唯一最大边** → 必不在任何 MST 中 ✓（Kruskal 第 5 步正是丢弃了它）。
- A−B 权 6 在回路 A−B−C−A 上（权 6,5,1），也是唯一最大边 → 必不在 MST 中 ✓。

**注意"唯一"两个字**：若最大边并列，就只能说"这些并列的边不可能全部入选"， 不能断定某一条一定落选。这与 MST 唯一性判据里"必须是真正的并列才制造出多解"是同一回事。

## 复杂度分析

**朴素实现 O(n2)，其中两个 n 分别来自：**

- 外层循环执行 n−1 次（每轮并入一个顶点）；
- 每轮内部有两次线性扫描：一次"选最小"扫 V−U（O(n)）， 一次"更新"扫 k 的所有可能邻接点（邻接矩阵下必须扫一整行，O(n)）。

故总时间为 (n−1)×O(n)=O(n2)。

**关键结论：O(n2) 与边数 e 完全无关。** 无论图上有 n−1 条边还是 n(n−1)/2 条边， Prim 朴素实现的耗时一样。这就是它适合**稠密图**的定量依据： 稠密图上 e≈n2，Kruskal 的 O(elog⁡e) 会变成 O(n2log⁡n)，反而更慢。

**堆优化 O(elog⁡n)**：把"选最小"从线性扫描换成从最小堆中取， 把"更新"改成对每条边做一次堆内调整。此时每条边最多引起一次 O(log⁡n) 的堆调整， 每个顶点最多一次 O(log⁡n) 的取出，总计 O((n+e)log⁡n)=O(elog⁡n)（连通图有 e≥n−1）。 适合稀疏图，但 408 一般考朴素版本。

| 指标 | 朴素（邻接矩阵） | 堆优化（邻接表 + 最小堆） |
| --- | --- | --- |
| 时间 | O(n2) | O(elog⁡n) |
| 空间 | O(n) 辅助（`lowcost`、`closest`、`visited`），图本身 O(n2) | O(n) 辅助，图本身 O(n+e) |
| 适合 | 稠密图 | 稀疏图 |

## 易混淆知识点

| 一组概念 | 差别 | 判别依据 |
| --- | --- | --- |
| Prim vs Kruskal | 前者加点（中间状态是**一棵**树），后者加边（中间状态是**森林**） | 看中间过程连不连通：Prim 的已选边始终连成一片 |
| 稠密图用 Prim vs 稀疏图用 Kruskal | O(n2) 与 e 无关；O(elog⁡e) 只与 e 有关 | 把具体的 n,e 代进两个式子比大小，别背结论 |
| Prim 的更新式 vs Dijkstra 的松弛式 | Prim 不累加（到**树**的距离），Dijkstra 累加（到**源点**的距离） | 看更新式里有没有 `dist[k] +` |
| MST 总权值唯一 vs MST 本身唯一 | 权值必唯一；树可能不唯一 | 前者是"最小值"的性质，后者是"取到最小值的方案数" |
| 有等权边 vs MST 不唯一 | 前者是后者的**必要不充分**条件 | 要看等权边是否在同一轮里**都可被选中**，不是只看权值相不相等 |
| MST vs 最短路径树 | 前者最小化**总权和**，后者最小化**各点到源点的距离** | 两者一般不是同一棵树，见下 |
| O(elog⁡e) vs O(elog⁡n) | 两者等价 | 因为 e≤n2，log⁡e≤2log⁡n，常数被 O 吸收 |

**MST 与最短路径树为什么不同？** 举个最小的例子：三角形 A−B=1，B−C=1，A−C=1.5。 MST 是 {AB,BC}，总权 2。但以 A 为源点的最短路径树中，A→C 的最短距离是 1.5（直连）， 而 MST 上 A 到 C 要走 1+1=2。 **MST 保证的是"总造价最小"，不保证"任意两点之间走得最近"。**

## 本节小结

学完本篇，你应该能够：

- 给定一个连通网，**逐轮填出 `lowcost[]` 与 `closest[]` 表**，写出 Prim 选边的次序与总权值， 并用"n−1 条边 / 含全部顶点 / 无回路"三条自检。
- 完整叙述 MST 性质（割性质）及其反证法证明，并说清 Prim 的每一步为什么都是安全的。
- 写出 Prim 的 C 代码，指出"更新式为什么不累加"和"为什么必须判 `k == -1`"。
- 独立推出 O(n2) 的两个来源，并据此在给定的 n,e 下判断该用 Prim 还是 Kruskal。
- 判断一张图的 MST 是否唯一，并给出"有等权边但 MST 唯一"的反例。

三条最关键的结论：

- **MST 性质（割性质）是 Prim 与 Kruskal 共同的正确性来源**： 跨越任意割的最小边，必属于某棵 MST。
- **Prim 朴素实现 O(n2)，与边数无关**，所以适合稠密图； `lowcost` 存的是"到树的距离"，更新时不累加。
- **MST 的总权值唯一，MST 本身未必唯一**；边权互不相同 ⇒ MST 唯一， 但"有等权边"推不出"不唯一"。

- 严蔚敏《数据结构（C 语言版）》（第 2 版）**印刷 p165**，§6.6.1： 最小生成树的引入（n 个城市建通信网，"连通 n 个城市只需要 n−1 条线路"）， 以及 MST 性质的表述——"假设 N=(V,E) 是一个连通网，U 是顶点集 V 的一个非空子集。 若 (u,v) 是一条具有最小权值（代价）的边，其中 u∈U，v∈V−U， 则必存在一棵包含边 (u,v) 的最小生成树"，并在同页起用反证法给出证明。
- 同书**印刷 p166**：证明的后半段（删去回路上的另一条跨越边 (u′,v′) 得到 T′， 由 (u,v) 权值不高于 (u′,v′) 推出矛盾）；同页给出普里姆算法的三步构造过程， 并指出"普里姆算法逐步增加 U 中的顶点，可称为**加点法**"， 以及"每次选择最小边时，可能存在多条同样权值的边可选，此时任选其一即可"。
- 同书**印刷 p166**：辅助数组 `closedge` 的定义——每个 vi∈V−U 对应一个分量， 含 `lowcost`（最小边上的权值）与 `adjvex`（最小边在 U 中的那个顶点）两个域， 即本篇的 `lowcost[]` 与 `closest[]`。
