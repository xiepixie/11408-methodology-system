## AOV 网与拓扑序列

**AOV 网（Activity On Vertex Network）**：用**顶点表示活动**、 **有向边表示活动之间的先后（先决）关系**的有向图。 若从 vi 到 vj 有边，表示活动 i 必须在活动 j 之前完成。

典型例子是课程的先修关系：学《数据结构》之前必须先学《程序设计基础》和《离散数学》， 学《操作系统》之前必须先学《数据结构》和《计算机原理》。 把每门课当成一个顶点、每条先修关系当成一条弧，就得到一个 AOV 网。

**拓扑排序**：把 AOV 网中所有顶点排成一个线性序列，使得 **若网中存在从 vi 到 vj 的路径，则序列中 vi 必定排在 vj 之前**。 这样的序列称为**拓扑序列**。

课程表就是最直白的解读：拓扑序列给出的是一个"任何时候要学的课， 它的先修课都已经学完"的合法学习顺序。

### 存在性：拓扑序列存在 ⟺ 图无环

**"有环 ⇒ 无拓扑序列"**：设环上有顶点 v1→v2→⋯→vm→v1。 按拓扑序列的定义，v1 要排在 v2 前、v2 排在 v3 前……vm 又要排在 v1 前。 把这一串不等式连起来得到"v1 排在 v1 之前"，矛盾。

**"无环 ⇒ 有拓扑序列"**：无环的有向图中**必存在入度为 0 的顶点**。 （反证：若每个顶点入度都 ≥1，从任一顶点沿入边一直往回走， 由于顶点有限，必然重复访问某个顶点，那就构成了环。） 把这个入度为 0 的顶点输出并删去，剩下的子图仍然无环，仍有入度为 0 的顶点， 如此重复 n 次即得一个完整的拓扑序列。

**所以：拓扑排序不仅能排序，还能顺带判环**——这是它最常被使用的副作用。 有向无环图记作 **DAG（Directed Acyclic Graph）**。

### 入度为 0 的顶点为什么可以随便挑

因为入度为 0 意味着**没有任何活动必须排在它之前**。把它放到当前位置，不会违反任何一条约束。 若同时有多个入度为 0 的顶点，它们之间彼此没有约束（否则被指向的那个入度就不是 0 了）， 所以谁先谁后都合法——**这正是拓扑序列一般不唯一的根源**。

```
示例 DAG：
  0 → 1 → 3
  ↓       ↑
  2 ------┘

合法拓扑序列：0, 1, 2, 3 或 0, 2, 1, 3
```

## 方法一：BFS 入度法（Kahn 算法）

核心思路：**不断取出入度为 0 的顶点输出，并"删去"它的所有出边**。

"删去出边"不需要真的改动存储结构，只要把每个后继的入度减 1 就等价了—— 这是本算法最省事的一处设计。

**算法步骤**：

- 求出所有顶点的入度，存入 `indegree[]`。
- 把所有入度为 0 的顶点入队（或入栈）。
- 队列非空时：取出队头 v 并输出；对 v 的每个后继 w 执行 `indegree[w]--`， 若减为 0 则把 w 入队。
- 若输出的顶点数 <n，说明图中有环；否则输出序列即为一个拓扑序列。c

```
#define MAX 100

typedef struct ArcNode {            // 邻接表边结点
    int adjvex;
    struct ArcNode *next;
} ArcNode;

typedef struct { ArcNode *first; } VNode;

// 返回 1 表示排序成功（图无环），结果放在 result[]
int TopologicalSort_BFS(VNode adjList[], int n, int result[]) {
    int indegree[MAX] = {0};
    int queue[MAX], front = 0, rear = 0, count = 0;

    // ① 统计入度：遍历所有边，O(n + e)
    for (int u = 0; u < n; u++)
        for (ArcNode *p = adjList[u].first; p; p = p->next)
            indegree[p->adjvex]++;

    // ② 入度为 0 的顶点全部入队
    for (int i = 0; i < n; i++)
        if (indegree[i] == 0)
            queue[rear++] = i;

    // ③ 反复取出、输出、减邻接点入度
    while (front < rear) {
        int v = queue[front++];
        result[count++] = v;
        for (ArcNode *p = adjList[v].first; p; p = p->next) {
            if (--indegree[p->adjvex] == 0)   // 减到 0 才入队，说明前驱都排完了
                queue[rear++] = p->adjvex;
        }
    }
    return count == n;   // count < n ⇒ 有环
}
```

**两处要点**：

- **必须在减到 0 的那一刻入队，不能提前也不能重复**。 若写成 `if (indegree[w] <= 0)`，同一个顶点会被多次入队； 若不减入度直接入队，会破坏"前驱全部排完才能排它"的约束。
- **队列不会溢出**：每个顶点入度减到 0 的时刻唯一，所以最多入队一次，`rear` 上界是 n。

**为什么 `count < n` 就一定有环**：算法结束时队列空，说明剩下的顶点入度都 >0。 这些顶点构成的子图中每个顶点入度都 ≥1，由前面的引理，该子图必含环。

### 换成栈会怎样

把队列换成栈，算法**照样正确**——因为"取哪个入度为 0 的顶点"本来就是自由的。 差别只在于得到的是**另一个**合法拓扑序列。教材给出的实现用的正是栈。

## 方法二：DFS 逆后序

**做法**：对每个未访问顶点执行 DFS，在一个顶点的**所有后继都递归完毕、即将退栈时** 把它压入栈中。全部 DFS 结束后，从栈顶到栈底依次弹出，就是一个拓扑序列。c

```
int stk[MAX], top = -1;
int visited[MAX];

void DFS_Topo(VNode adjList[], int v) {
    visited[v] = 1;
    for (ArcNode *p = adjList[v].first; p; p = p->next)
        if (!visited[p->adjvex])
            DFS_Topo(adjList, p->adjvex);
    stk[++top] = v;        // 后序位置压栈：此刻 v 的所有后继都已入栈
}

void TopologicalSort_DFS(VNode adjList[], int n) {
    for (int i = 0; i < n; i++) visited[i] = 0;
    top = -1;
    for (int i = 0; i < n; i++)
        if (!visited[i]) DFS_Topo(adjList, i);
    while (top >= 0)       // 弹栈即为拓扑序列
        printf("%d ", stk[top--]);
}
```

**为什么逆后序就是拓扑序列**：

考察任意一条弧 u→v，只需证明 u 的**结束时间**（压栈时刻）晚于 v， 这样弹栈时 u 就排在 v 前面。分两种情况：

- **DFS 到达 u 时 v 尚未访问**：那么 u 会递归进入 v， v 必然先压栈、u 后压栈。✓
- **DFS 到达 u 时 v 已访问**：由于图无环，v 不可能还在当前递归栈上 （否则 v⇝u→v 构成环），所以 v 已经完成并压栈了。u 仍是后压栈的。✓

两种情况都得到"u 后压栈 ⇒ 弹栈时 u 在前"。∎

⚠️ **压栈必须在后序位置（递归返回之后）**，不能在先序位置（刚访问就压）。 先序压栈得到的序列一般**不是**拓扑序列——反例：图 0→2, 1→2， 邻接表 0:2、1:2。先序压栈：DFS(0) 压 0、压 2；DFS(1) 压 1。 栈自底向上是 0,2,1，弹栈得 1,2,0——而弧 0→2 要求 0 在 2 前，被违反了。

**这个算法直接得到的其实是"逆拓扑序列"**（若不弹栈而按压栈次序读， 得到的序列满足"后继排在前驱之前"）。所以它常被称作"DFS 逆拓扑序"。

## 完整走查

取如下 DAG（6 个顶点，7 条弧）：0→1,0→2,1→3,2→3,2→4,3→5,4→5

初始入度：

| 顶点 | 0 | 1 | 2 | 3 | 4 | 5 |
| --- | --- | --- | --- | --- | --- | --- |
| 入度 | 0 | 1 | 1 | 2 | 1 | 2 |

**用队列（Kahn）**，邻接表按编号升序：

| 步 | 取出 | 输出 | 减谁的入度 | 入度变化 | 新入队 | 容器（取出后） |
| --- | --- | --- | --- | --- | --- | --- |
| 0 | — | — | — | — | 0 |  |
| 1 | 0 | 0 | 1, 2 | 1: 1→0；2: 1→0 | 1, 2 |  |
| 2 | 1 | 0 1 | 3 | 3: 2→1 | — |  |
| 3 | 2 | 0 1 2 | 3, 4 | 3: 1→0；4: 1→0 | 3, 4 |  |
| 4 | 3 | 0 1 2 3 | 5 | 5: 2→1 | — |  |
| 5 | 4 | 0 1 2 3 4 | 5 | 5: 1→0 | 5 |  |
| 6 | 5 | 0 1 2 3 4 5 | — | — | — |  |

输出 6 个顶点 =n，无环。**拓扑序列：0 1 2 3 4 5。**

**换成栈**（其余完全不变）：

| 步 | 弹出 | 输出 | 压入 | 栈（弹出后，栈顶在右） |
| --- | --- | --- | --- | --- |
| 0 | — | — | 0 | [0] |
| 1 | 0 | 0 | 1, 2 | [1, 2] |
| 2 | 2 | 0 2 | 4 | [1, 4]（3 的入度只减到 1，不压） |
| 3 | 4 | 0 2 4 | — | [1]（5 的入度减到 1，不压） |
| 4 | 1 | 0 2 4 1 | 3 | [3] |
| 5 | 3 | 0 2 4 1 3 | 5 | [5] |
| 6 | 5 | 0 2 4 1 3 5 | — | [ ] |

**拓扑序列：0 2 4 1 3 5**——同一张图、同一份邻接表，只因容器不同就得到了另一个合法序列。

**用 DFS 逆后序**（起点 0，邻接表升序）： DFS 进入 0 → 1 → 3 → 5，5 无后继先压栈；回退压 3；回到 1 压 1； 回到 0 转 2 → 3（已访问）→ 4 → 5（已访问），压 4；压 2；最后压 0。 压栈次序自底向上为 5,3,1,4,2,0，弹栈得 **0 2 4 1 3 5**——与栈版 Kahn 恰好相同。

**这张图一共有多少个拓扑序列？** 穷举可得 **5 个**：012345012435021345021435024135

可以逐条验证：0 必在最前（唯一入度为 0 的顶点）、5 必在最后（唯一出度为 0 的顶点）、 2 必在 3 与 4 之前、1 必在 3 之前。满足这四条约束的排列恰好这 5 个。

## 拓扑序列的唯一性

**判定**：

**拓扑序列唯一 ⟺ 算法的每一步中，入度为 0 的顶点都只有一个。**

理由已在前面给出：多于一个时它们之间没有约束，交换先后仍然合法，序列必不唯一； 每步只有一个时算法全程没有任何选择余地，结果必然唯一。

**等价说法**：拓扑序列唯一 ⟺ **该 DAG 中存在一条哈密顿路径**， 即拓扑序列中**任意相邻两个顶点之间都有一条弧**。 （若相邻的 vi,vi+1 之间没有弧，把它俩交换后仍是合法拓扑序列，与唯一矛盾； 反之若条条相邻都有弧，任何交换都会违反约束。）

**唯一的例子**：0→1, 0→2, 1→2, 2→3。 入度：0:0, 1:1, 2:2, 3:1。 每一步入度为 0 的顶点分别是 0→1→2→3，全程只有一个候选， 序列唯一为 **0 1 2 3**。检验哈密顿路径：0→1 ✓、1→2 ✓、2→3 ✓，确实存在。

**不唯一的例子**：本篇走查用的那张图。第 2 步时队列里同时有 1 和 2 两个入度为 0 的顶点， 于是分叉出多条序列。

**实操判据**：手算时每一步看一眼"当前入度为 0 的有几个"。 只要出现过一次"两个及以上"，序列就不唯一；全程都是一个，序列唯一。 **不要用"图里有没有分支"来判断**——分支多但约束紧的图，序列照样可能唯一。

## 环的检测

| 方法 | 判据 | 为什么 |
| --- | --- | --- |
| **BFS 入度法** | 输出顶点数 `count < n` | 环上顶点的入度永远减不到 0，进不了队列 |
| **DFS 三色标记** | 遇到"正在访问中"（在当前递归栈上）的顶点 | 指回递归栈上的顶点就意味着形成了回路 |

c

```
// DFS 检测环（三色标记）
// 0: 未访问；1: 访问中（在递归栈上）；2: 已完成
int color[MAX];

int HasCycle_DFS(VNode adjList[], int v) {
    color[v] = 1;
    for (ArcNode *p = adjList[v].first; p; p = p->next) {
        int w = p->adjvex;
        if (color[w] == 1) return 1;                       // 指回栈上顶点 → 有环
        if (color[w] == 0 && HasCycle_DFS(adjList, w))
            return 1;
    }
    color[v] = 2;                                          // 退栈，标记已完成
    return 0;
}
```

**为什么两种颜色不够**：设图 0→1, 0→2, 1→2（无环）。 DFS 从 0 出发进 1 再进 2，2 完成；回到 0 后检查邻居 2，发现"已访问"。 若只有"访问过 / 没访问过"两态，这里会误报有环。 关键在于 2 此刻是**已完成**（color = 2）而非**访问中**（color = 1）， 只有指向"访问中"的顶点才构成环。详见 [DFS](./dfs.html)。

## AOV 网 vs AOE 网

这是本章最容易混的一组，因为两者都是 DAG、都讲"活动"。

| 对比维度 | **AOV 网** | **AOE 网** |
| --- | --- | --- |
| 全称 | Activity **On Vertex** | Activity **On Edge** |
| **活动**由什么表示 | **顶点** | **边（弧）** |
| **边 / 顶点**的含义 | 边表示先后关系，不带权 | 顶点表示**事件**（状态），边带权表示活动**持续时间** |
| 权值 | 一般无权 | 边必须带权 |
| 源点 / 汇点 | 可以有多个入度为 0、多个出度为 0 的顶点 | **有且仅有一个**源点和一个汇点 |
| 要解决的问题 | 排出一个合法顺序（拓扑排序）、判环 | 估算工期、找出关键活动（关键路径） |
| 典型场景 | 课程先修关系 | 工程进度计划 |
| 对应大纲条目 | 五（四）3 拓扑排序 | 五（四）4 关键路径 |

**判别依据只有一条：看"活动"落在顶点上还是落在边上。** 落在顶点上就是 AOV（顶点是活动，边只是箭头）；落在边上就是 AOE（边是活动、有耗时，顶点只是里程碑）。

**两者的联系**：AOE 网也是 DAG，求关键路径的第一步就是对它做拓扑排序 （按拓扑序正推事件最早发生时间）。所以**拓扑排序是关键路径的前置**，见[关键路径](./critical-path.html)。

图注：左边是一个 6 顶点的 AOV 网（有向无环图），右边是它的邻接表存储。 关键在顶点表**多出的 `count` 一列，存的正是入度**：C2 与 C4 的 `count` 是 0， 正是算法起步时要入队的两个顶点；C1 的 `count` 是 3，对应图上射入它的三条弧。 **Kahn 算法要做的事在这张图上就是两件**：反复挑 `count == 0` 的顶点输出， 沿它的 `adj` 链把每个后继的 `count` 减 1。 到[关键路径](./critical-path.html)时，只需给边结点再加一个"持续时间"字段，同一份表就能继续用。 图源：殷人昆《数据结构——用面向对象方法与 C++ 描述》（第 2 版）图8.28 AOV 网络及其邻接表表示，p386

## 复杂度分析

| 算法 | 时间 | 空间 | 来历 |
| --- | --- | --- | --- |
| BFS 入度法 | O(n+e) | O(n) | 统计入度遍历全部边 O(e)；每个顶点入队出队各一次 O(n)；每条边引起一次入度减 1，共 O(e) |
| DFS 逆后序 | O(n+e) | O(n) | 每个顶点访问一次、每条边检查一次；递归栈深度最坏 n |

两者同阶。**用邻接矩阵存储时都退化为 O(n2)**，因为找后继要扫一整行（见 [DFS](./dfs.html)）。

**空间的差别**：BFS 版是一个显式队列（长度上界 n）加一个 `indegree[]` 数组； DFS 版是递归栈（深度最坏 n）加一个结果栈。量级相同，来源不同。

## 易混淆知识点

| 一组概念 | 差别 | 判别依据 |
| --- | --- | --- |
| AOV 网 vs AOE 网 | 活动在**顶点**上 vs 在**边**上 | 问"哪个元素带着耗时"：顶点→AOV，边→AOE |
| 拓扑序列不唯一 vs 唯一 | 取决于每步入度为 0 的顶点个数 | 全程只有一个候选才唯一；等价于存在哈密顿路径 |
| 队列版 vs 栈版 Kahn | 都正确，得到不同的合法序列 | "取哪个入度为 0 的顶点"本就自由 |
| DFS 后序压栈 vs 先序压栈 | 只有**后序**压栈的逆序才是拓扑序列 | 先序压栈的反例：0→2, 1→2 |
| 逆后序 vs 逆拓扑序列 | DFS 直接得到的是逆拓扑序列，弹栈后才是拓扑序列 | 看输出方向：按压栈次序读还是按弹栈次序读 |
| `count < n` vs 图不连通 | `count < n` 说明**有环**，与连通性无关 | 非连通的 DAG 照样能排出完整拓扑序列 |
| 拓扑排序判环 vs DFS 三色判环 | 前者用入度，后者用递归栈状态 | 两种都对；DFS 版还能定位出环上的顶点 |
| 入度为 0 的顶点 vs 源点 | AOV 可以有多个入度为 0 的顶点 | AOE 才要求"有且仅有一个源点" |

**非连通的有向图能不能做拓扑排序？** 能。拓扑排序只要求无环，与连通性无关。 若图分成互不相连的几块，各块的顶点在序列中交错出现也完全合法—— 它们之间本来就没有任何约束。

**一个 DAG 的拓扑序列有多少个？** 没有简单的通项公式（这是一个 #P-完全的计数问题）， 但小规模可以按"每步入度为 0 的顶点集合"逐层枚举，本篇走查的那张图就是这样数出 5 个的。

## 本节小结

学完本篇，你应该能够：

- 给定 AOV 网，**用队列版与栈版 Kahn 算法各排出一个拓扑序列**， 并写出每一步的入度变化与容器状态。
- 用 DFS 逆后序排出拓扑序列，并解释"为什么必须在后序位置压栈"。
- 证明"拓扑序列存在 ⟺ 图无环"的两个方向。
- **判断一个 DAG 的拓扑序列是否唯一**（每步入度为 0 的顶点是否只有一个 / 是否存在哈密顿路径）， 并在不唯一时枚举出全部序列。
- 分清 AOV 与 AOE：判据是"活动落在顶点上还是边上"。

三条最关键的结论：

- **拓扑序列存在 ⟺ 图无环**；Kahn 算法输出顶点数 <n 就是有环的判据。
- **拓扑序列唯一 ⟺ 每一步入度为 0 的顶点只有一个 ⟺ 图中存在哈密顿路径。**
- **DFS 的逆后序是拓扑序列**，压栈必须在后序位置；两种实现均为 O(n+e)。

- 严蔚敏《数据结构（C 语言版）》（第 2 版）**印刷 p176**，§6.6.3： "一个无环的有向图称作有向无环图 (Directed Acycline Graph)，简称 DAG 图"； 同页以软件专业必修课的先修关系为例引入 AOV 网。
- 同书**印刷 p177**： "所谓拓扑排序就是将 AOV-网中所有顶点排成一个线性序列，该序列满足： 若在 AOV-网中由顶点 vi 到顶点 vj 有一条路径，则在该线性序列中的顶点 vi 必定在顶点 vj 之前"； 同页给出拓扑排序的四步过程，并指出"若此时输出的顶点数小于有向图中的顶点数， 则说明有向图中存在环"，以及"对给定的 AOV-网应首先判定网中是否存在环。 检测的办法是对有向图的顶点进行拓扑排序"。
