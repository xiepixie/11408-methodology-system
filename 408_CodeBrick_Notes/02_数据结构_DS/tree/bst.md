## 知识框架

本节要回答四个问题：

- BST 想解决什么？——它在"数组查得快但改得慢"和"链表改得快但查得慢"之间取了什么折中？
- 判定一棵树是不是 BST，为什么**不能**只检查每个结点与它的左右孩子？
- 删除度为 2 的结点时，用中序前驱和用中序后继替换，结果一样吗？为什么替换之后一定能转化成简单情形？
- BST 的 ASL 怎么算？**查找失败**的 ASL 又怎么算——失败结点有几个、在哪几层？

## 一、BST 想解决什么

回顾两种基本的线性结构：

| 结构 | 查找 | 插入 / 删除 | 瓶颈 |
| --- | --- | --- | --- |
| **有序数组**（折半查找） | O(log⁡n) | O(n) | 插入要移动后面所有元素 |
| **链表** | O(n) | O(1)（已定位时） | 查找只能顺序扫描 |

**这两者的短板恰好互补**：数组"查得快、改得慢"，链表"改得快、查得慢"。根因在于——**有序性靠"物理位置相邻"来维持，所以任何插入都要挪位置**。

BST 的思路是：**把有序性从"物理位置"改为"树的形状"来维持**。左子树全部小于根、右子树全部大于根，于是查找仍能像折半那样每次排除一半；而插入只需要改一两个指针，不用移动任何已有结点。

**代价是**：树的形状由插入次序决定，形状不好时"每次排除一半"的保证就没了——这正是后面 [AVL](./avl.html) 与[红黑树](./rbt.html)要修的问题。

## 二、定义与中序递增性

**二叉排序树**（Binary Sort Tree，又称二叉查找树 / 二叉搜索树）或者是一棵空树，或者是具有下列性质的二叉树：

- 若它的**左子树**不空，则左子树上所有结点的值均**小于**根结点的值
- 若它的**右子树**不空，则右子树上所有结点的值均**大于**根结点的值
- 它的左、右子树也分别是二叉排序树

**这是一个递归定义**，第 3 条不可省略——它把约束从"根与直接孩子"扩展到了"根与整棵子树的每一个结点"。c

```
typedef struct BSTNode {
    int key;
    struct BSTNode *lchild, *rchild;
} BSTNode, *BSTree;
```

### 核心推论：中序遍历得到递增有序序列

**证明（对结点数归纳）**：空树与单结点显然成立。设左右子树的中序序列各自递增。整棵树的中序序列是「左子树序列，根，右子树序列」的拼接；由定义，左子树全部 < 根 < 右子树全部，三段拼起来仍递增。∎

### 判定 BST：为什么不能只查左右孩子

**只检查"每个结点 > 左孩子且 < 右孩子"是错的**：

```
      5
     / \
    3   8
       / \
      2   9      ← 逐点检查：8 > 5 ✓、2 < 8 ✓、9 > 8 ✓、3 < 5 ✓，全过
```

但它**不是** BST：结点 2 虽然是 8 的合法左孩子，却位于**根 5 的右子树**里，违反了"右子树全部 > 根"。

**逐点检查漏掉的正是"跨层约束"**。正确的判定方法有两个：

- **中序法**：做一次中序遍历，检查序列是否严格递增（实现见 [中序遍历](./inorder.html)），O(n)
- **区间法**：递归下传取值范围，进入左子树时把上界收紧为根、进入右子树时把下界收紧为根c

```
// 区间法：检查以 T 为根的子树，所有关键字是否落在 (low, high) 开区间内
int Check(BSTree T, int low, int high) {
    if (T == NULL) return 1;
    if (T->key <= low || T->key >= high) return 0;   // 违反祖先带下来的约束
    return Check(T->lchild, low, T->key)             // 左子树的上界收紧为当前结点
        && Check(T->rchild, T->key, high);           // 右子树的下界收紧为当前结点
}
// 调用：Check(T, INT_MIN, INT_MAX)
```

上面那棵反例树里，进入 8 的左子树时区间是 (5,8)，而 2∉(5,8)，一步就被判出来。

## 三、查找操作

从根出发，把目标值 `key` 与当前结点比较：

- `key ==` 当前结点值 → 查找成功
- `key <` 当前结点值 → 在**左子树**中继续查找
- `key >` 当前结点值 → 在**右子树**中继续查找
- 走到空结点 → 查找失败c

```
// 迭代版：无递归栈开销
BSTNode *BST_Search(BSTree T, int key) {
    while (T != NULL && key != T->key) {
        if (key < T->key)
            T = T->lchild;      // 目标比当前小，只可能在左子树
        else
            T = T->rchild;      // 目标比当前大，只可能在右子树
    }
    return T;                   // 找到则返回结点指针，失败则返回 NULL
}
```

**关键量化**：查找过程走的是一条**从根到目标结点的路径**，因此比较次数=路径上的结点数=该结点所在的层次

这条式子是后面算 ASL 的全部依据。注意它数的是**结点数**（根算 1 次），与[哈夫曼树的 WPL](./huffman.html)数边的口径不同。

**每比较一次排除掉多少**：排除的是"另一棵子树的全部结点"。树形好时每次排除大约一半（O(log⁡n)），树形退化时每次只排除 1 个（O(n)）——**BST 的效率完全写在树的形状里**。

## 四、插入操作

BST 的插入基于查找：**先查 `key` 是否已存在，若不存在，就在"查找失败停下来的那个空位置"插入新结点**。c

```
int BST_Insert(BSTree *T, int key) {
    if (*T == NULL) {                                  // 查找失败的位置，就是插入位置
        *T = (BSTree)malloc(sizeof(BSTNode));
        (*T)->key = key;
        (*T)->lchild = (*T)->rchild = NULL;
        return 1;                                      // 插入成功
    }
    if (key == (*T)->key)
        return 0;                                      // 已存在，不插入（BST 不允许重复关键字）
    else if (key < (*T)->key)
        return BST_Insert(&((*T)->lchild), key);       // 递归插入左子树
    else
        return BST_Insert(&((*T)->rchild), key);       // 递归插入右子树
}
```

**参数为什么是 `BSTree *T`（二级指针）**：插入可能要**修改双亲的孩子指针**（把原来的 `NULL` 改成新结点地址）。传一级指针只能改指针指向的内容，改不了指针本身。这是链式结构插入代码的通用要求。

### 两条重要性质

**1. 新插入的结点一定是叶结点。** 因为插入位置是"查找失败停下的空位"，那里本来就没有子树。所以插入**不需要移动任何已有结点，只需修改一个指针**——这正是 BST 相对有序数组的核心优势。

**2. 不同的插入次序会构造出形态完全不同的 BST。**

以关键字集合 {45,24,53,12,37,93} 为例：

```
插入序 (45, 24, 53, 12, 37, 93)          插入序 (12, 24, 37, 45, 53, 93)

          45                                    12
        /    \                                    \
      24      53                                   24
     /  \       \                                    \
   12    37      93                                   37
                                                        \
                                                         45
                                                           \
                                                            53
                                                              \
                                                               93
   高度 3                                        高度 6（退化成单支链）
```

两棵树的**中序序列完全相同**（都是 12, 24, 37, 45, 53, 93——由集合唯一决定），但**形态与查找效率天差地别**。

**由此得到一条常用结论**：**关键字有序（或逆序）输入时，BST 退化成单支链**，查找性能与顺序查找相同。这就是引入自平衡机制的直接动机。

### 由插入序建树

反复调用插入即可：c

```
void CreateBST(BSTree *T, int str[], int n) {
    *T = NULL;
    for (int i = 0; i < n; i++)
        BST_Insert(T, str[i]);
}
```

**时间**：每次插入 O(h)，n 次共 O(nh)。树形好时 O(nlog⁡n)，退化时 O(n2)。

**一个有意思的副产品**：把无序序列建成 BST 再中序输出，就完成了排序——这本质上就是快速排序的树形版本，两者的最坏情形（已有序输入）也完全一致。

## 五、删除操作

删除是 BST 三个操作里最复杂的，因为**摘掉一个结点后必须重新接好，且不能破坏 BST 性质**。设待删结点为 z，分三种情形。

### 情形一：z 是叶结点

直接删除，把它双亲的对应指针置空。**不影响任何其他结点的相对位置**，BST 性质自然保持。

```
     45              45
    /  \    删 12   /  \
  24    53   ──→  24    53
  /
12
```

### 情形二：z 只有一棵子树

让 z 的那棵子树**顶替 z 的位置**（接到 z 的双亲上）。

**为什么合法**：z 的整棵子树中的所有关键字，与"z 相对于它的祖先们"处在同一个区间里（这正是 BST 的递归定义所保证的）。所以子树整体上移一层，与所有祖先的大小关系不变。

```
     45              45
    /  \    删 24   /  \
  24    53   ──→  12    53
  /
12
```

### 情形三：z 有两棵子树

不能直接删——两棵子树没地方同时挂。做法是**找一个"替身"**：

用 z 的**中序前驱**（左子树中的最大结点）或**中序后继**（右子树中的最小结点）的值替换 z 的值，然后转而删除那个替身结点。

**为什么替身必须是中序前驱或后继**：删除 z 后，为了保持中序序列仍然递增，顶替 z 位置的值必须是"中序序列中紧挨着 z 的那个"——只有它换上来才不会破坏与左右两侧的大小关系。

**为什么替身一定好删**：

- **中序前驱** = 左子树中一路向右走到底的结点 ⇒ 它**没有右子树**（否则就不是最大的）
- **中序后继** = 右子树中一路向左走到底的结点 ⇒ 它**没有左子树**

所以替身必然落入情形一或情形二，**递归至多再走一层就结束**。

```
原树                    删除 45（用中序前驱 37 替换）   删除 45（用中序后继 53 替换）

     45                        37                            53
    /  \                      /  \                          /  \
  24    53                  24    53                      24    93
 /  \     \                /        \                    /  \
12   37    93            12          93                12    37

                   37 是左子树最大者、无右子树，       53 是右子树最小者、无左子树，
                   替换后把它从左子树摘掉             替换后让它的右孩子 93 顶上来
```

**两种替换得到的树不同**（上面右侧两棵树形态不一样），但**都是合法的 BST**，且**中序序列相同**。

**教材（严蔚敏）的默认做法是用中序前驱**，理由是"以被删结点左子树中关键字最大的结点替代被删结点，然后从左子树中删除这个结点。此结点一定没有右子树……这样不会增加树的高度"。题目若没有指定，按这个口径答；若指定了就按题目的。

### 完整代码

**中序后继版**：c

```
void BST_Delete(BSTree *T, int key) {
    if (*T == NULL) return;                           // 没找到，什么也不做
    if (key < (*T)->key) {
        BST_Delete(&((*T)->lchild), key);
    } else if (key > (*T)->key) {
        BST_Delete(&((*T)->rchild), key);
    } else {                                          // 找到待删结点
        if ((*T)->lchild == NULL) {
            // 覆盖情形一（叶子：rchild 也为 NULL）与情形二（只有右子树）
            BSTNode *temp = *T;
            *T = (*T)->rchild;
            free(temp);
        } else if ((*T)->rchild == NULL) {
            // 情形二：只有左子树
            BSTNode *temp = *T;
            *T = (*T)->lchild;
            free(temp);
        } else {
            // 情形三：左右子树都在，取中序后继 = 右子树中最左下的结点
            BSTNode *s = (*T)->rchild;
            while (s->lchild != NULL)
                s = s->lchild;
            (*T)->key = s->key;                       // 用后继的值覆盖待删结点
            BST_Delete(&((*T)->rchild), s->key);      // 转而删除后继（它没有左子树）
        }
    }
}
```

**中序前驱版**（与教材口径一致，只改情形三）：c

```
        } else {
            // 情形三：取中序前驱 = 左子树中最右下的结点
            BSTNode *s = (*T)->lchild;
            while (s->rchild != NULL)
                s = s->rchild;
            (*T)->key = s->key;
            BST_Delete(&((*T)->lchild), s->key);      // 转而删除前驱（它没有右子树）
        }
```

**边界核对**：

| 输入 | 走到哪个分支 | 结果 |
| --- | --- | --- |
| 空树 | 第一行 `return` | 无操作 ✓ |
| 删不存在的关键字 | 递归到 `*T == NULL` | 无操作 ✓ |
| 删叶结点 | `lchild == NULL` 分支，`*T = rchild = NULL` | 双亲对应指针置空 ✓ |
| 删只有左子树的结点 | `rchild == NULL` 分支 | 左子树顶上来 ✓ |
| 删只有右子树的结点 | `lchild == NULL` 分支 | 右子树顶上来 ✓ |
| 删根结点 | 同上三种之一，`*T` 就是根指针本身 | 根被正确更新 ✓ |
| 情形三的递归 | 后继无左子树 → 必落入 `lchild == NULL` | 至多再递归一层 ✓ |

**注意 `lchild == NULL` 这个分支同时覆盖了叶结点和"只有右子树"两种情形**——叶结点的 `rchild` 也是 `NULL`，赋值后 `*T` 变成 `NULL`，正是我们要的。这是把三种情形压缩成两个分支的常见写法，读代码时别以为漏了情形一。

## 六、查找长度（ASL）的计算

这是 BST 最需要动手算的部分，**成功与失败两套算法必须都会**。

### 查找成功的 ASL
ASL成功=1n∑i=1nci,ci=结点 i 所在的层次

（假设每个关键字被查找的概率相等，均为 1/n。）

**例**：仍用上面那两棵树。

**树 (a)**（插入序 45, 24, 53, 12, 37, 93）：

```
          45          ← 第 1 层：1 个结点，各 1 次比较
        /    \
      24      53      ← 第 2 层：2 个结点，各 2 次
     /  \       \
   12    37      93   ← 第 3 层：3 个结点，各 3 次
```
ASL成功(a)=1×1+2×2+3×36=1+4+96=146≈2.33

**树 (b)**（插入序 12, 24, 37, 45, 53, 93，单支链）：各结点分别在第 1∼6 层，ASL成功(b)=1+2+3+4+5+66=216=3.5

**单支树的一般公式**：ASL成功=1+2+⋯+nn=n+12——**与顺序查找完全相同**。

### 查找失败的 ASL

失败的分析要先补上**失败结点（外部结点）**：把树中每一个空指针位置画成一个方框。

**失败结点的个数恰为 n+1**——因为二叉链表有 n+1 个空指针（推导见[树与二叉树基本概念](./concepts.html)）。

**一个失败结点的比较次数 = 它所在层次 −1**，即从根走到它所经过的**真实结点**个数（走到空指针时就发现失败了，那一步不算比较）。

**例（树 (a)）**：

```
              45
            /    \
          24      53
         /  \    /  \
       12    37 □    93        ← 53 的左空位在第 3 层 → 2 次比较
      /  \  / \     /  \
     □   □ □   □   □    □      ← 其余 6 个空位都在第 4 层 → 各 3 次比较
```

失败结点共 6+1=7 个：53 的左空位 1 个在第 3 层；12、37、93 各贡献 2 个、共 6 个在第 4 层。ASL失败(a)=1×2+6×37=2+187=207≈2.86

**例（树 (b)，单支链 12→24→37→45→53→93）**：每个结点的左空位分别在第 2∼7 层（比较次数 1∼6），最后一个结点 93 的右空位在第 7 层（比较 6 次）。ASL失败(b)=1+2+3+4+5+6+67=277≈3.86

### 三个计算要点

| 要点 | 说明 |
| --- | --- |
| 失败结点有 **n+1** 个 | 等于二叉链表的空指针数；数漏一个整个分母就错 |
| 失败的比较次数 = 层次 −1 | 走到空位才发现失败，空位本身不参与比较 |
| 分母是 **n+1** 而不是 n | 成功的 ASL 分母是 n（n 个关键字），失败的分母是 n+1（n+1 个失败区间） |

## 七、复杂度与退化

| 操作 | 最好 | 平均 | 最坏 | 说明 |
| --- | --- | --- | --- | --- |
| 查找 | O(log2⁡n) | O(log2⁡n) | O(n) | 完全取决于树高 h |
| 插入 | O(log2⁡n) | O(log2⁡n) | O(n) | 先查找再挂一个结点，查找决定时间 |
| 删除 | O(log2⁡n) | O(log2⁡n) | O(n) | 先查找再至多走一层找替身 |
| 中序遍历（输出有序序列） | O(n) | O(n) | O(n) | 与树形无关 |

**三种情形的准确含义**：

- **最好**：树的形态接近完全二叉树（也就是"和折半查找的判定树相似"），h≈log2⁡n
- **最坏**：关键字**有序或逆序**插入，树退化成单支链，h=n，ASL=(n+1)/2，**与顺序查找相同**
- **平均**：把 n 个关键字按各种可能的次序插入，共有 n! 种插入序（其中有的建出相同形态）。**可以证明，综合所有可能情况，平均查找长度仍与 log2⁡n 同数量级**

**空间复杂度**：结构本身 O(n)；查找 / 插入 / 删除的迭代实现只需 O(1) 辅助空间，递归实现需 O(h) 的栈。

### BST 与折半查找的对比

| 对比项 | 二叉排序树 | 折半查找（有序表） |
| --- | --- | --- |
| 存储 | 链式，动态 | 顺序表，**必须随机存取** |
| 查找 | 平均 O(log⁡n)，最坏 O(n) | 恒 O(log⁡n) |
| 插入 / 删除 | 只改指针，O(h) | 要移动元素，O(n) |
| 适用 | 需要**频繁插入删除**的动态查找表 | 建好后**基本不变**的静态查找表 |
| 判定树 | 树的形态就是它自己 | [折半查找的判定树](./../search/binary-search.html)是一棵**平衡的 BST** |

**这张表里最重要的一行是最后一行**：折半查找的判定树本身就是一棵二叉排序树，而且是"尽可能平衡"的那一棵。所以

**BST 的最好情形，恰好就是折半查找。** BST 付出的额外代价（指针空间、形态可能退化）换来的是"插入删除不用移动元素"。

**教材的评价**："二叉排序树上的查找和折半查找相差不大。但就维护表的有序性而言，二叉排序树更加有效，因为无需移动记录，只需修改指针即可完成对结点的插入和删除操作。因此，对于需要经常进行插入、删除和查找运算的表，采用二叉排序树比较好。"

### 从 BST 到自平衡树

BST 的全部风险集中在一句话：**树高不可控**。修补的方向也只有一个——**在插入 / 删除后主动把树"掰平"**：

- [AVL 树](./avl.html)：要求任意结点左右子树高度差 ≤1，**严格平衡**，树高 ≤1.44log2⁡n
- [红黑树](./rbt.html)：只要求任意路径上黑色结点数相同，**弱平衡**，树高 ≤2log2⁡(n+1)，换来更低的维护代价

## 易混淆知识点

| 对比项 | 一方 | 另一方 | 判别依据 |
| --- | --- | --- | --- |
| 判定 BST | **中序序列递增**或区间法 | 逐点比较结点与左右孩子，**错误** | 逐点法漏掉跨层约束（右子树里出现比根小的值） |
| 插入的新结点位置 | **一定是叶结点** | 不会插在中间 | 插入位置就是查找失败停下的空位 |
| 不同插入序的影响 | 形态不同、效率不同 | **中序序列相同** | 中序序列由关键字集合唯一决定 |
| 删除度为 2 的结点 | 用中序前驱或中序后继替换 | **不能**随便找个结点顶上 | 只有中序相邻者换上来才不破坏中序递增 |
| 前驱替换 vs 后继替换 | 两种都合法，得到的树**不同** | 中序序列相同 | 教材默认用中序前驱；题目指定则听题目 |
| 替身为什么好删 | 前驱无右子树、后继无左子树 | — | 前驱是左子树最大者、后继是右子树最小者 |
| 成功 ASL vs 失败 ASL | 分母 n，比较次数 = 层次 | 分母 n+1，比较次数 = 层次 −1 | 失败结点有 n+1 个，走到空位才发现失败 |
| 最坏情形怎么触发 | 关键字**有序或逆序**插入 | 不是"随机插入" | 有序输入使每个新结点都挂在链尾 |
| 单支 BST vs 顺序查找 | ASL=(n+1)/2，**完全相同** | — | 单支链的查找就是逐个比较 |
| BST vs 折半查找 | 动态、插入删除只改指针 | 静态、插入删除要移动元素 | 折半查找的判定树就是一棵平衡 BST |
| BST vs 堆 | 整棵树有序，中序递增 | [堆](./heap.html)只保证双亲优于孩子 | BST 查任意元素 O(h)，堆是 O(n) |
| BST 允许重复关键字吗 | 标准定义**不允许**（严格小于 / 大于） | 工程实现可扩展，但会破坏"中序严格递增" | 本篇代码遇到相等时不插入 |

## 本节小结

学完本篇，应该能够：

- **说清 BST 的设计动机**：把有序性从"物理位置相邻"改为"树的形状"来维持，于是插入删除不再需要移动元素
- **默写 BST 的递归定义**，并解释第 3 条（左右子树也是 BST）为什么不能省
- **用两种正确方法判定 BST**（中序递增 / 区间法），并给出"逐点比较左右孩子"的反例
- **默写查找、插入、删除三个算法**，说清插入用二级指针的理由、以及新结点必是叶子
- **完整处理删除的三种情形**，说明"用中序前驱或后继替换"的必要性（保持中序递增）与充分性（替身必定缺一侧子树，从而落入前两种情形）
- **算出成功与失败两种 ASL**：成功的分母是 n、比较次数 = 层次；失败的分母是 n+1、比较次数 = 层次 −1
- **说清最坏情形的触发条件**（关键字有序或逆序输入）及其后果（ASL=(n+1)/2，退化成顺序查找）
- **把 BST 与折半查找放在一起比较**：折半查找的判定树就是一棵平衡 BST，BST 用"可能退化"的风险换来了"插入删除只改指针"

**两条最关键的结论**：**中序遍历递增**是 BST 的一切性质的源头（判定、求第 k 小、删除时选替身，全都由它推出）；**BST 的效率完全写在树高里**，有序输入会让它退化成顺序查找——这就是 [AVL](./avl.html) 与[红黑树](./rbt.html)存在的理由。
