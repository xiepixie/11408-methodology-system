## 知识框架

本节要回答四个问题：

- 线索二叉树到底省了什么？——省的不是空间，而是**遍历时的那个栈**
- 为什么必须加 `ltag` / `rtag` 两个标志位？不加行不行？
- 中序线索树上找前驱和后继的算法为什么都只有两种情形？凭什么是"右子树最左下"？
- 为什么**前序线索找前驱**和**后序线索找后继**这两件事做不到？它们和另外四种情形差在哪里？

## 一、动机：那 n+1 个空指针

含 n 个结点的二叉链表里，共有 2n 个指针域，其中指向孩子的只有 n−1 个（与树中的 n−1 条边一一对应），因此空指针数=2n−(n−1)=n+1

推导详见 [树与二叉树基本概念](./concepts.html)。这 n+1 个指针域**既不存数据、也不指向任何东西，却实实在在占着空间**。

另一方面，遍历二叉树的实质是"把非线性结构线性化"——遍历完毕，每个结点在序列中都有确定的**前驱**和**后继**（第一个结点无前驱、最后一个无后继）。可是这些信息**只在遍历的动态过程中存在**，遍历一结束就丢了；下次想知道"某结点的中序后继是谁"，只能重新遍历一遍。

把这两件事撮合到一起，就是线索二叉树：

**用那 n+1 个空指针域，把遍历过程中得到的前驱 / 后继信息保存下来。**

指向前驱或后继的指针叫做**线索**（thread）；加上线索的二叉树叫**线索二叉树**；把一棵二叉树按某种次序遍历使其变成线索二叉树的过程叫**线索化**。

**线索化真正省下来的是什么**：不是存储空间（空指针本来就占着），而是

- 遍历时**不再需要栈或递归**，空间从 O(h) 降到 O(1)
- 查某个结点的前驱 / 后继从"重新遍历 O(n)"降到 O(1) 或 O(h)

## 二、结点结构与标志位

如果直接把空的 `lchild` 改成指向前驱，会立刻出问题：**拿到一个非空的 `lchild`，无法判断它指的是左孩子还是前驱**。所以必须额外记录一位信息。

线索二叉树在普通二叉链表的基础上，为每个结点增加两个**标志位** `ltag` 和 `rtag`：

| 标志 | 值为 0 | 值为 1 |
| --- | --- | --- |
| `ltag` | `lchild` 指向**左孩子** | `lchild` 指向**前驱**（线索） |
| `rtag` | `rchild` 指向**右孩子** | `rchild` 指向**后继**（线索） |

结点结构定义：c

```
typedef struct ThreadNode {
    ElemType data;
    struct ThreadNode *lchild, *rchild;
    int ltag, rtag;      // 0: 指向孩子   1: 是线索
} ThreadNode, *ThreadTree;
```

规则总结：

- 若结点**有左孩子**，则 `lchild` 指向左孩子、`ltag = 0`；否则 `lchild` 指向其**前驱**、`ltag = 1`
- 若结点**有右孩子**，则 `rchild` 指向右孩子、`rtag = 0`；否则 `rchild` 指向其**后继**、`rtag = 1`

**标志位的空间代价**：两位标志理论上只需 2 bit，但按上面的 `int` 写法实际会占 8 字节。这仍然远小于"给每个结点再加两个指针域存前驱后继"的做法——那要 2n 个指针，且原来的 n+1 个空指针照样浪费。**线索化的性价比正来自"复用已有的空指针 + 只加两位标志"。**

上图左侧是一棵中序线索二叉树（虚线箭头即线索），右侧是它在内存中的线索链表。结点格式为 `leftChild | ltag | data | rtag | rightChild`。这棵树的中序序列是 **B D A E C**：结点 B 是序列第一个，没有前驱，所以它的 `lchild` 为空且 `ltag = 1`；结点 C 是序列最后一个，`rchild` 为空且 `rtag = 1`；结点 D 两侧都是线索（`1 D 1`），分别指向前驱 B 和后继 A。 图源：殷人昆《数据结构——用面向对象方法与 C++ 描述》（第 2 版）图 5.28 中序线索二叉树及其二叉链表表示，p211

### 线索化之后还剩几个空指针

原有 n+1 个空指针，中序线索化会用掉其中 n−1 个（除首尾外，每个结点恰有一个前驱和一个后继，共 2(n−1) 个"关系"，但每个关系只占一个指针域，且每个结点最多贡献一个空的 `lchild` 和一个空的 `rchild`）。精确地说：

- 中序序列的**第一个结点没有前驱** → 它的 `lchild` 仍为空
- 中序序列的**最后一个结点没有后继** → 它的 `rchild` 仍为空
- 其余 n−1 个空指针全部被线索占用

所以**线索化后恰好剩 2 个空指针**。若采用下文的**带头结点**做法，把这两个也接到头结点上，空指针数为 **0**，链表变成一个真正的循环双向链表。

## 三、中序线索化

### 算法思想

线索化就是"**在遍历的过程中修改空指针**"。要建立线索必须同时知道两个结点：当前结点 T 和它的**前驱** `pre`。因此需要一个贯穿整个递归的指针 `pre`，始终指向**中序序列中刚刚访问过的那个结点**。

对当前结点 T 做两件事：

- **回头看**：若 `T->lchild == NULL`，T 的前驱正是 `pre`，建立前驱线索
- **回头补**：若 `pre != NULL` 且 `pre->rchild == NULL`，`pre` 的后继正是 T，建立后继线索

**为什么后继线索要"回头补"而不是当场建**：处理 T 时还不知道 T 的后继是谁（它还没被访问到）。但轮到 T 的后继时，`pre` 恰好就是 T——所以每个结点的后继线索是由它的**后继**替它补上的。这个"延迟一拍"的写法是线索化代码的关键。

### 代码
c

```
ThreadNode *pre = NULL;      // 全局指针，指向中序序列中刚访问过的结点

void InThread(ThreadTree T) {
    if (T == NULL) return;
    InThread(T->lchild);                  // ① 递归线索化左子树
    // ② 处理当前结点
    if (T->lchild == NULL) {              // 左孩子为空 → 建立指向前驱的线索
        T->lchild = pre;
        T->ltag = 1;
    } else {
        T->ltag = 0;                      // 有左孩子，标志位置 0
    }
    if (pre != NULL) {
        if (pre->rchild == NULL) {        // 前驱的右孩子为空 → 替它补上后继线索
            pre->rchild = T;
            pre->rtag = 1;
        } else {
            pre->rtag = 0;                // 前驱有右孩子，标志位置 0
        }
    }
    pre = T;                              // ③ 当前结点成为下一个结点的前驱
    InThread(T->rchild);                  // ④ 递归线索化右子树
}

// 中序线索化入口（不带头结点的版本）
void CreateInThread(ThreadTree T) {
    pre = NULL;
    if (T != NULL) {
        InThread(T);
        pre->rchild = NULL;               // 最后一个结点没有后继
        pre->rtag = 1;
    }
}
```

### 三处必须想清楚的地方

**1. 为什么中序线索化不会"沿线索转圈"**

递归 `InThread(T->lchild)` 发生在**修改 `T->lchild` 之前**（第 ① 步在第 ② 步之前），所以递归进去的一定是真正的左子树。同理，执行 `InThread(T->rchild)` 时，`T->rchild` 还没有被任何人改成线索——改它的是 T 的后继，而那件事发生在这次递归调用**返回之后**。

**前序线索化没有这个保障**，必须额外判断，见下文第七节。

**2. 为什么判断的是 `pre->rchild == NULL` 而不是 `pre->rtag`**

因为 `pre` 的右指针在此刻还没有被任何人动过。每个结点在整个线索化过程中只会当一次 `pre`，也就只有这一次机会被补上后继线索。

**3. `CreateInThread` 里最后那两行的作用**

递归结束后 `pre` 指向中序序列的最后一个结点，它没有后继。把 `rchild` 置空、`rtag` 置 1，表示"这里是线索，但指向空"，这样遍历循环 `p = Nextnode(p)` 走到它时会自然得到 `NULL` 而终止。**漏掉这两行，遍历会在最后一个结点处读到未初始化的指针。**

### 逐步走一遍

以这棵树为例（中序序列为 **D B E A C F**）：

```
        A
       / \
      B   C
     / \   \
    D   E   F
```

| 处理次序（中序） | `T` | `T->lchild` 是否为空 | 建立的前驱线索 | `pre` 的 `rchild` 是否为空 | 建立的后继线索 | 处理后 `pre` |
| --- | --- | --- | --- | --- | --- | --- |
| 1 | D | 是 | D.lchild → NULL（`pre` 为空，D 无前驱） | `pre` 为 NULL，跳过 | — | D |
| 2 | B | 否（左孩子 D） | — | 是（D 的 rchild 为空） | D.rchild → B | B |
| 3 | E | 是 | E.lchild → B | 否（B 有右孩子 E） | — | E |
| 4 | A | 否（左孩子 B） | — | 是（E 的 rchild 为空） | E.rchild → A | A |
| 5 | C | 是 | C.lchild → A | 否（A 有右孩子 C） | — | C |
| 6 | F | 是 | F.lchild → C | 否（C 有右孩子 F） | — | F |
| 收尾 | — | — | — | — | F.rchild → NULL，`rtag = 1` | — |

最终线索：`D.lchild = NULL(ltag=1)`、`D.rchild → B`、`E.lchild → B`、`E.rchild → A`、`C.lchild → A`、`F.lchild → C`、`F.rchild = NULL(rtag=1)`。剩余空指针恰为 2 个（D 的左、F 的右），与前面的推导一致。

## 四、在中序线索树上找前驱与后继

### 找后继

设结点 p，要找它的中序后继：

- **若 `p->rtag == 1`**：`p->rchild` 就是后继，O(1)
- **若 `p->rtag == 0`**：p 有右子树。按中序的定义，访问完 p 之后要去遍历它的右子树，而**遍历一棵子树时第一个被访问的是该子树中最左下的结点**。所以后继 = **右子树中最左下的结点**c

```
// 以 p 为根的子树中，中序序列的第一个结点（最左下）
ThreadNode* Firstnode(ThreadNode *p) {
    while (p->ltag == 0)      // 只要还有真正的左孩子就往左走
        p = p->lchild;
    return p;
}

// 中序后继
ThreadNode* Nextnode(ThreadNode *p) {
    if (p->rtag == 0)
        return Firstnode(p->rchild);   // 有右子树：取右子树最左下
    else
        return p->rchild;              // 无右子树：直接取线索
}
```

**注意循环条件必须写 `p->ltag == 0` 而不是 `p->lchild != NULL`**。线索化之后，`lchild` 非空并不代表有左孩子——它可能是一条指向前驱的线索。写成判空会顺着线索往回跑。这是本篇最典型的实现错误。

### 找前驱

完全对称：

- **若 `p->ltag == 1`**：`p->lchild` 就是前驱，O(1)
- **若 `p->ltag == 0`**：p 有左子树。中序中 p 之前访问的是它的左子树，而**遍历一棵子树时最后一个被访问的是该子树中最右下的结点**。所以前驱 = **左子树中最右下的结点**c

```
// 以 p 为根的子树中，中序序列的最后一个结点（最右下）
ThreadNode* Lastnode(ThreadNode *p) {
    while (p->rtag == 0)
        p = p->rchild;
    return p;
}

// 中序前驱
ThreadNode* Prenode(ThreadNode *p) {
    if (p->ltag == 0)
        return Lastnode(p->lchild);    // 有左子树：取左子树最右下
    else
        return p->lchild;              // 无左子树：直接取线索
}
```

### 不用栈的中序遍历

有了 `Firstnode` 和 `Nextnode`，中序遍历退化成一个 `for` 循环：c

```
void InOrder_Thread(ThreadTree T) {
    for (ThreadNode *p = Firstnode(T); p != NULL; p = Nextnode(p))
        visit(p);
}
```

**空间 O(1)**：只用了一个指针变量，没有栈、没有递归。

**时间 O(n)**：单次 `Nextnode` 最坏 O(h)，但整趟遍历的总代价仍是 Θ(n)——**用摊还的眼光看**：`Firstnode` 里"一路向左"走过的每条边、以及每次 `Nextnode` 走过的边，在整趟遍历中**每条边最多被走两次**（一次向下、一次通过线索跳回），总边数 n−1，故总步数 O(n)。把它算成 O(nh) 是把单次最坏乘以次数，那是明显的高估。

**反向遍历也成立**：从 `Lastnode(T)` 出发反复调用 `Prenode`，可以 O(n) 时间、O(1) 空间地**逆中序**遍历——这是普通二叉链表做不到的。

## 五、带头结点的线索链表

上面的版本里，中序第一个结点的 `lchild` 和最后一个结点的 `rchild` 都是空的。教材的规范做法是增设一个**头结点** `Thrt`，把这两头接起来：

| 指针 | 指向 |
| --- | --- |
| `Thrt->lchild` | 二叉树的**根结点**（`Thrt->ltag = 0`；空树时指向 `Thrt` 自己） |
| `Thrt->rchild` | 中序遍历访问的**最后一个结点**（`Thrt->rtag = 1`） |
| 中序**第一个**结点的 `lchild` | 头结点 `Thrt` |
| 中序**最后一个**结点的 `rchild` | 头结点 `Thrt` |

c

```
void InOrderThreading(ThreadTree *Thrt, ThreadTree T) {
    *Thrt = (ThreadNode *)malloc(sizeof(ThreadNode));
    (*Thrt)->ltag = 0;                  // 头结点的左指针指向根，是"孩子"不是线索
    (*Thrt)->rtag = 1;                  // 头结点的右指针是线索
    (*Thrt)->rchild = *Thrt;            // 初始时右指针指向自己
    if (T == NULL) {
        (*Thrt)->lchild = *Thrt;        // 空树：左指针也指向自己
    } else {
        (*Thrt)->lchild = T;            // 左指针指向根
        pre = *Thrt;                    // pre 初值为头结点，于是首结点的前驱线索指向头结点
        InThread(T);
        pre->rchild = *Thrt;            // 尾结点的后继线索指向头结点
        pre->rtag = 1;
        (*Thrt)->rchild = pre;          // 头结点的右指针指向尾结点
    }
}
```

**这样做的收益**：整个结构变成一个**循环双向链表**——从头结点出发顺着后继可以遍历全表，从头结点出发顺着前驱也可以逆序遍历全表；空指针数变为 0；遍历循环的终止条件统一成"回到头结点"，不需要判 `NULL`。

## 六、前序线索二叉树

前序次序：**根 → 左 → 右**。

### 找前序后继——简单

- 若 `p->rtag == 1`：`p->rchild` 直接是后继
- 若 `p->rtag == 0`（有右子树）：

- p **有左孩子** → 后继就是**左孩子**（前序访问完根，紧接着访问左子树的根）
- p **无左孩子** → 后继就是**右孩子**

**关键在于：这三种情形全都在 p 自己身上就能判定，不用看双亲。**

### 找前序前驱——困难

- 若 `p->ltag == 1`：`p->lchild` 直接是前驱
- 若 `p->ltag == 0`（有左孩子）：前驱**一定不在 p 的子树里**——前序先访问根、再访问子树，所以 p 的子树里的结点全排在 p 之后。前驱只能是：

- 若 p 是双亲的**左孩子** → 前驱就是**双亲**
- 若 p 是双亲的**右孩子** → 前驱是**双亲的左子树中按前序最后访问的那个结点**

两种情形**都需要先知道双亲是谁**，而二叉链表里没有双亲指针。

### 前序线索化的"转圈"问题

前序线索化的代码顺序是"先处理当前结点、再递归左右子树"，于是**递归左子树时，`T->lchild` 可能已经在上一步被改成了前驱线索**。若不加判断就递归下去，会沿着线索跑回祖先，形成**死循环**。c

```
void PreThread(ThreadTree T) {
    if (T == NULL) return;
    if (T->lchild == NULL) {          // 先处理当前结点：建立前驱线索
        T->lchild = pre;
        T->ltag = 1;
    } else {
        T->ltag = 0;
    }
    if (pre != NULL && pre->rchild == NULL) {
        pre->rchild = T;
        pre->rtag = 1;
    }
    pre = T;
    if (T->ltag == 0)                 // ← 必须判断！ltag=1 说明 lchild 是线索不是孩子
        PreThread(T->lchild);
    if (T->rtag == 0)                 // 右侧同理（rchild 也可能已被设成线索）
        PreThread(T->rchild);
}
```

**中序线索化为什么不需要这两个判断**：中序的递归左子树发生在修改 `lchild` **之前**；而 `rchild` 被改成线索是由后继完成的，那时对右子树的递归调用早已返回。**次序保护了它。** 前序把"处理当前结点"提到了最前面，这层保护就没了。

## 七、后序线索二叉树

后序次序：**左 → 右 → 根**。与前序恰好镜像。

### 找后序前驱——简单

- 若 `p->ltag == 1`：`p->lchild` 直接是前驱
- 若 `p->ltag == 0`（有左孩子）：

- p **有右孩子** → 前驱就是**右孩子**（后序中根之前访问的是右子树的根）
- p **无右孩子** → 前驱就是**左孩子**

同样，全部可以在 p 自己身上判定。

### 找后序后继——困难，分四种情形

若 `p->rtag == 1`，直接取线索。否则（p 有右子树）后序后继一定在 p 的**祖先方向**，分四种情形（这是教材给出的完整分类）：

| 情形 | 条件 | 后继 |
| --- | --- | --- |
| 1 | p 是整棵树的**根** | 后继为空（后序中根最后访问） |
| 2 | p 是双亲的**右孩子** | 后继是**双亲** |
| 3 | p 是双亲的**左孩子**，且**没有右兄弟**（双亲无右子树） | 后继是**双亲** |
| 4 | p 是双亲的**左孩子**，且**有右兄弟** | 后继是**双亲的右子树按后序遍历的第一个结点** |

**情形 4 里那个"后序第一个结点"怎么找**：从双亲的右子树根出发，**能往左就往左、不能往左就往右**，直到走到叶结点——那个叶结点就是该子树后序序列的第一个。

四种情形**全部需要双亲信息**，二叉链表做不到。

### 教材给出的解决办法

"在先序线索化树上找前驱或在后序线索化树上找后继时都比较复杂，此时若需要，可直接建立含 4 个指针的线索链表。"

也就是说，有两条可行的补救路线：

| 方案 | 做法 | 代价 |
| --- | --- | --- |
| **三叉链表** | 结点里再加一个 `parent` 指针 | 每结点多 1 个指针；可回溯，四种情形都能判 |
| **四指针线索链表**（教材方案） | 结点里同时保留 `lchild` / `rchild` 和独立的 `pred` / `succ` 两个指针 | 每结点多 2 个指针；前驱后继都是 O(1)，但完全不再复用空指针，等于放弃了线索化的初衷 |

**不改结点结构的第三条路**：从根重新做一次后序遍历，边走边记双亲——但那是 O(n)，等于没有线索化。

由此可以准确地回答一个常被问到的问题：**"二叉树线索化之后，仍然不能高效解决的是什么？"** 答案是**后序线索二叉树中求后序后继**（对称地，前序线索二叉树中求前序前驱）。理由不是"算法难写"，而是**信息不足**——所需的双亲信息根本不在二叉链表里。

## 八、三种线索化的统一规律

|  | 找后继 | 找前驱 | 难在哪 |
| --- | --- | --- | --- |
| **中序线索** | 简单：`rtag=1` 直接取；`rtag=0` 取右子树最左下 | 简单：`ltag=1` 直接取；`ltag=0` 取左子树最右下 | 无 |
| **前序线索** | 简单：有左孩子取左孩子，否则取右孩子 / 线索 | **困难**：有左孩子时需要双亲信息 | 找前驱要回溯 |
| **后序线索** | **困难**：需要双亲信息，分四种情形 | 简单：有右孩子取右孩子，否则取左孩子 / 线索 | 找后继要回溯 |

**规律不用背，可以推**：看"根"在遍历序列中的位置。

- **前序（根在最前）**：根排在整棵子树的所有结点之前，所以从根往**后**走一步一定还在子树内部（看得见），往**前**走一步必然跳出子树、落到祖先方向（看不见）→ **好找后继、难找前驱**
- **后序（根在最后）**：完全镜像 → **好找前驱、难找后继**
- **中序（根在中间）**：往前一步落在左子树里、往后一步落在右子树里，**两侧都在自己的子树内部** → 两头都好找

**一句话**：**根在哪一头，哪一头就难找**（因为要跳出子树、回溯到双亲）；中序的根在中间，所以两头都不难。这也解释了为什么线索化的默认选择是中序。

## 复杂度分析

| 操作 | 时间复杂度 | 说明 |
| --- | --- | --- |
| 中序线索化 | O(n) | 本质是一次中序遍历，每个结点常数工作；递归栈 O(h) |
| 找后继（`rtag=1`） | O(1) | 直接读线索 |
| 找后继（`rtag=0`） | O(h) | 走到右子树最左下 |
| 找前驱（`ltag=1`） | O(1) | 直接读线索 |
| 找前驱（`ltag=0`） | O(h) | 走到左子树最右下 |
| 中序遍历整棵线索树 | O(n) | **摊还**：每条边最多被走两次，总步数 O(n)，不是 O(nh) |
| 逆中序遍历整棵线索树 | O(n) | 对称 |

**空间**：

- 线索化**过程**需要 O(h) 的递归栈（最坏 O(n)）
- 线索化**完成后**，遍历只需 O(1) 辅助空间——这是线索二叉树最主要的收益
- 结构本身比普通二叉链表多两个标志位/结点

## 易混淆知识点

| 对比项 | 一方 | 另一方 | 判别依据 |
| --- | --- | --- | --- |
| `tag = 0` vs `tag = 1` | 0：指针指向**孩子** | 1：指针是**线索**，指向前驱 / 后继 | 记"0 是正常的树结构，1 是额外加的线索" |
| 判断"有没有左孩子" | 必须看 `ltag == 0` | **不能**看 `lchild != NULL` | 线索化后 `lchild` 非空可能是线索，判空会顺线索跑回祖先 |
| 线索化前 vs 线索化后的空指针数 | 前：n+1 个 | 后：不带头结点剩 **2** 个；带头结点剩 **0** 个 | 首结点无前驱、尾结点无后继 |
| 中序线索化 vs 前序线索化的递归保护 | 中序不需要判 `ltag` | 前序**必须**判 `ltag == 0` 才递归左子树 | 前序在递归之前就改了 `lchild`，会沿线索转圈 |
| 前序线索的难点 vs 后序线索的难点 | 前序：难找**前驱** | 后序：难找**后继** | 根在遍历序列的哪一头，哪一头就要回溯到双亲 |
| 线索化省的是空间还是时间 | 空间：遍历时的栈从 O(h) 降到 O(1) | 结点存储反而略增（多两个标志位） | 省的是**遍历的辅助空间**，不是结点空间 |
| 遍历线索树的时间 | O(n)（摊还） | 不是 O(nh) | 每条边最多走两次，不能拿单次最坏乘次数 |
| 三叉链表 vs 四指针线索链表 | 加 `parent`，可回溯 | 直接存 `pred` / `succ`，不再复用空指针 | 前者省空间、后者查前驱后继 O(1) |
| 后继线索由谁建立 | 由该结点的**后继**在被处理时回头补上 | 不是在处理该结点时当场建立 | 处理某结点时还不知道它的后继是谁 |
| 头结点的 `lchild` vs 尾结点的 `rchild` | 头结点 `lchild` 指根（`ltag=0`） | 尾结点 `rchild` 指头结点（`rtag=1`） | 一个是"孩子"、一个是"线索" |

## 本节小结

学完本篇，应该能够：

- **说清线索二叉树的动机**：复用二叉链表里那 n+1 个空指针域，把只在遍历过程中存在的前驱 / 后继信息固化下来；**真正省下的是遍历时的栈**，遍历空间从 O(h) 降到 O(1)
- **说明为什么必须加 `ltag` / `rtag`**：不加就无法区分一个非空指针指的是孩子还是线索
- **默写中序线索化算法**，解释 `pre` 的作用、"后继线索由后继回头补"的延迟写法，以及入口函数最后两行的必要性
- **算出线索化后剩余的空指针数**：不带头结点 2 个、带头结点 0 个
- **默写中序线索树上找前驱、后继的四段代码**，说清"右子树最左下"与"左子树最右下"的来历，并注意循环条件必须判 `tag` 而不是判空
- **写出不用栈的中序遍历**，并用摊还分析说明它是 O(n) 而不是 O(nh)
- **说清前序线索化为什么会"转圈"**，中序为什么不会
- **完整列出后序线索找后继的四种情形**，并说明它们全都需要双亲信息，因而必须借助三叉链表或四指针线索链表
- **用"根在哪一头，哪一头就难找"这条规律现推三种线索化的难易分布**，不必死记

**两条最关键的结论**：判断"有没有孩子"必须看**标志位**而不是看指针是否为空；**后序线索树上求后序后继（及前序线索树上求前序前驱）是线索化解决不了的**，根因是二叉链表里没有双亲信息。
