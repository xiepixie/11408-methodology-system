## 知识框架

本节要回答四个问题：

- 为什么"权大的靠近根"能让总代价最小？贪心为什么是对的？
- 哈夫曼树的三条形态性质（无度为 1 的结点、2n−1 个结点、树不唯一但 WPL 唯一）分别怎么推？
- WPL 除了按定义算，为什么还等于**所有非叶结点权值之和**？
- 前缀编码为什么能保证译码无歧义？这个性质是怎么从"编码对应叶结点"得到的？

## 一、问题背景

发一段只含 4 种字符 {A,B,C,D} 的报文，出现次数分别是 7,5,3,2（共 17 个字符）。

**等长编码**：4 种字符每个用 2 位（`00`/`01`/`10`/`11`），总长 17×2=34 位。

**不等长编码**：让出现次数多的字符用短码、少的用长码。若 A 用 1 位、B 用 2 位、C 与 D 各用 3 位，总长为7×1+5×2+3×3+2×3=32 位

比等长编码省 2 位。**字符种类越多、频率越不均匀，节省越显著。**

但不等长编码马上带来一个新麻烦：`0`、`01`、`010` 这样的编码集合，收到 `010` 时无法判断是 `0`+`10` 还是 `01`+`0` 还是 `010`——**译码有歧义**。所以不等长编码必须附加一个约束（前缀编码），这两件事一起构成了哈夫曼树要解决的问题：

**在"译码无歧义"的前提下，让总编码长度最短。**

## 二、术语（先把定义钉死）

| 术语 | 定义 |
| --- | --- |
| **路径** | 从树中一个结点到另一个结点之间的分支构成这两个结点之间的路径 |
| **路径长度** | 路径上的**分支数目**（数边，不数点） |
| **树的路径长度** | 从树根到每一结点的路径长度之和 |
| **权** | 赋予某个结点或边的一个量，是对某种属性的数值化描述（编码问题里就是字符的出现次数或频率） |
| **结点的带权路径长度** | 该结点到树根之间的**路径长度 × 结点上的权** |
| **树的带权路径长度（WPL）** | 树中**所有叶结点**的带权路径长度之和 |

WPL=∑k=1nwklk

其中 wk 是第 k 个叶结点的权、lk 是它到根的路径长度（**边数**）。

**两个必须记牢的边界**：

- **WPL 只统计叶结点**，内部结点即使带权也不计入
- **lk 数的是边不是点**。根到自身的路径长度是 0，不是 1。这一点与[二叉排序树的 ASL](./bst.html)（数结点数）不同，混用会让答案整体偏差一个 ∑wk

## 三、哈夫曼树的定义

假设有 n 个权值 {w1,w2,…,wn}，构造一棵含 n 个叶结点的二叉树，每个叶结点的权为 wi，其中**带权路径长度 WPL 最小**的那棵二叉树称为**最优二叉树**或**哈夫曼树**。

**同一组权值可以构造出很多棵二叉树，WPL 差别很大**。以 {7,5,2,4} 为例（对应字符 a,b,c,d）：

```
    (a) 完全二叉树         (b) 单支为主             (c) 哈夫曼树
         ●                      ●                       ●
        / \                    / \                     / \
       ●   ●                  ●   c(2)              a(7)  ●
      / \ / \                / \                        / \
   a(7)b(5)c(2)d(4)        ●   d(4)                  b(5)  ●
                          / \                             / \
                       a(7) b(5)                       c(2) d(4)

WPL = 7×2+5×2+2×2+4×2   WPL = 7×3+5×3+2×1+4×2      WPL = 7×1+5×2+2×3+4×3
    = 36                     = 46                       = 35
```

三棵树的叶结点集合完全相同，WPL 却分别是 36、46、35。**(c) 就是哈夫曼树**——在所有以 7,5,2,4 为叶权的二叉树中，35 是 WPL 的最小值。

**观察 (c) 的形态**：权值最大的 a(7) 离根最近（l=1），权值最小的 c(2)、d(4) 离根最远（l=3）。这正是最优结构的特征：

**权大的结点离根近，权小的结点离根远。**

**为什么这样最优（交换论证）**：设树中有两个叶结点 u,v，wu>wv 但 lu>lv（大权反而更深）。把它们交换位置，WPL 的变化量为Δ=(wulv+wvlu)−(wulu+wvlv)=(wu−wv)(lv−lu)<0

WPL 严格变小。所以**最优树里不可能出现"权大的比权小的更深"**。这一步就是哈夫曼贪心策略的根据：既然权最小的两个必须最深，那就先把它们配成一对放到最深处。

## 四、构造算法

**哈夫曼算法**（贪心）：

- 根据给定的 n 个权值 {w1,…,wn}，构造 n 棵**只有根结点**的二叉树，构成森林 F
- 在 F 中选取**根结点权值最小的两棵树**作为左右子树，合并为一棵新二叉树，新树根的权值 = 左右子树根权值之和
- 从 F 中删除被选中的两棵树，把新树加入 F
- 重复 ②③，直到 F 中只剩一棵树，它就是哈夫曼树

**每合并一次，森林里的树少一棵**，从 n 棵减到 1 棵需要恰好 **n−1 次合并**。

### 完整构造示例

给定权值集合 {2,3,5,7}（对应字符 D,C,B,A）：

```
初始森林： 2   3   5   7

第 1 步：最小的两个是 2 和 3，合并为 5(新)
        5*
       / \
      2   3            森林： 5*  5   7

第 2 步：最小的两个是 5*(新) 和 5(原)，合并为 10
        10
       /  \
      5*   5           森林： 10  7
     / \
    2   3

第 3 步：剩下 10 和 7，合并为 17
          17
         /  \
       10    7
      /  \
     5*   5
    / \
   2   3
```

**WPL 验算**：7×1+5×2+3×3+2×3=7+10+9+6=32

**手算要点**：每一步都要把新生成的结点**放回森林重新参与比较**（第 2 步里新生成的 5 就参与了竞争）。忘记把新结点放回去，是手算最常见的失误。

## 五、三条形态性质及其推导

### 性质 1：哈夫曼树中没有度为 1 的结点

**证明（反证 + 局部改进）**：假设最优树中某结点 u 只有一个孩子子树 C。把 u 删掉、让 C 直接挂到 u 的双亲（若 u 是根，就让 C 成为新根）。这个改动使 C 中**每个叶结点的路径长度都减少 1**，而其他叶结点不受影响。因此ΔWPL=−∑k∈Cwk<0(权值为正)

WPL 严格变小，与"原树最优"矛盾。所以最优树中不存在度为 1 的结点。∎

**从算法角度也能看出来**：哈夫曼算法每次合并**必定同时取两棵树**作为左右子树，生成的每个内部结点都恰有两个孩子。

### 性质 2：n 个叶结点的哈夫曼树共有 2n−1 个结点

**推导一（用二叉树性质）**：设度为 0、1、2 的结点数为 n0,n1,n2。由性质 1 得 n1=0；由[二叉树性质 3](./concepts.html) 得 n0=n2+1，即 n2=n0−1。于是n总=n0+n1+n2=n0+0+(n0−1)=2n0−1

代入 n0=n 即得 2n−1。

**推导二（用算法过程）**：初始有 n 个叶结点；每次合并新生成 1 个内部结点，共合并 n−1 次，新增 n−1 个结点。总数 n+(n−1)=2n−1。

**两条推导互相印证**，也说明 n2=n−1 恰好等于合并次数。这个数字直接决定了实现时数组要开多大。

### 性质 3：哈夫曼树不唯一，但 WPL 唯一

**不唯一的两个来源**：

- **左右子树可以交换**——交换不改变任何叶结点的路径长度，WPL 不变
- **权值相同的树在选取时有多种选法**——当森林里有多棵树权值并列最小时，选哪两棵都合法

**WPL 唯一**：WPL 的最小值是一个由权值集合唯一确定的数，所有哈夫曼树的 WPL 都等于这个最小值。

**一个把两点都体现出来的例子**：权值 {1,2,3,3}。

- 第 1 步：合并 1 和 2 得到新结点 3。森林变成 {3新,3,3}——**三个 3 并列最小**
- **选法 A**：合并 3新 与一个原始 3 得 6，再与剩下的 3 合并得 9 各叶深度：原始 3 在深度 1、另一个原始 3 在深度 2、1 和 2 在深度 3 WPL=3×1+3×2+1×3+2×3=3+6+3+6=18
- **选法 B**：合并两个原始 3 得 6，再与 3新 合并得 9 各叶深度：两个原始 3 都在深度 2、1 和 2 在深度 2 WPL=3×2+3×2+1×2+2×2=6+6+2+4=18

**两棵树形态不同、连"权值为 1 的字符编码有多长"都不同**（A 里是 3 位、B 里是 2 位），**但 WPL 都是 18**。

**由此得到一条判定方法**：题目给出几棵二叉树问"哪些是这组权值的哈夫曼树"，**逐棵算 WPL，等于最小值的就是**——不要凭形态判断，也不要以为哈夫曼树只有一棵。

### 补充：编码长度的上界

n 个叶结点的哈夫曼树，最长的那条根到叶路径**至多为 n−1**（每次合并至多让一条路径加深 1，共 n−1 次合并），因此**最长编码至多 n−1 位**。取到这个上界要求权值增长足够快（如斐波那契式的 1,1,2,3,5,…，每一步合并出的新结点都恰好成为下一步的最小之一）。

## 六、WPL 的两种算法

### 算法一：按定义
WPL=∑叶结点(权×到根的边数)

### 算法二：所有**非叶结点**权值之和
WPL=∑非叶结点(该结点的权值)

**证明**：在哈夫曼树中，每个内部结点的权值 = 它子树内所有叶结点权值之和（这是构造过程直接保证的）。把所有内部结点的权值加起来，等价于：**每个叶结点的权，被它的每一个内部祖先各统计了一次**。而一个叶结点的内部祖先个数 = 它到根的**边数** lk（根到该叶路径上除它自己外的每个结点都是内部结点，恰有 lk 个）。所以∑非叶w=∑kwk⋅lk=WPL◼

**验算**（上面 {2,3,5,7} 的例子）：非叶结点权值为 17,10,5，和 =32，与按定义算的 32 一致 ✓。

**这个算法在手算时快得多**：构造过程中每次合并产生的那个和，全部加起来就是 WPL——**边构造边累加，构造完 WPL 也就出来了**，根本不用回头量每片叶子的深度。

## 七、哈夫曼编码

### 编码规则

从根到叶结点的路径上，**走左分支记 0、走右分支记 1**（也可以反过来，但全树必须一致），路径上的 0/1 序列就是该叶结点对应字符的编码。

**示例**（权值 {2,3,5,7} 对应字符 {D,C,B,A}，用上面构造出的树，把 A 挂在右边）：

| 字符 | 权值 | 编码 | 编码长度 |
| --- | --- | --- | --- |
| A | 7 | `1` | 1 |
| B | 5 | `01` | 2 |
| C | 3 | `001` | 3 |
| D | 2 | `000` | 3 |

WPL=7×1+5×2+3×3+2×3=32，即用这套编码发完整篇报文需要 **32 位**（等长编码要 34 位）。

### 性质 1：哈夫曼编码是前缀编码

**前缀编码的定义**：一个编码方案中，**任何一个编码都不是其他任何编码的前缀（最左子串）**。

例如 {0,10,110,111} 是前缀编码；{0,01,010,111} 不是（`0` 是 `01` 的前缀）。

**证明**（教材给出的论证）：哈夫曼编码是**根到叶结点**路径上的分支序列。若编码 A 是编码 B 的前缀，那么路径 A 是路径 B 的最左部分，即路径 B 经过了路径 A 的终点——这说明 A 的终点**不是**叶结点（它下面还有路可走）。但哈夫曼编码对应路径的终点**一定是叶结点**，矛盾。所以任何哈夫曼编码都不会是另一个哈夫曼编码的前缀。∎

**这条证明的关键在于"字符只挂在叶结点上"**。任何"把字符挂在内部结点"的编码方案都必然不是前缀编码。

### 前缀编码为什么能保证译码无歧义

译码时从编码串左端开始，沿哈夫曼树从根往下走：遇 `0` 走左、遇 `1` 走右，**一旦到达叶结点就输出该字符并回到根**，继续处理后面的位。

因为编码互不为前缀，走到某个叶结点时**不可能存在"再多读几位会得到另一个合法字符"的情况**——那意味着当前编码是另一个编码的前缀。所以每一步的切分是**唯一确定**的，译码结果唯一。

**译码示例**：用上表译 `1001000`

| 已读 | 当前位置 | 动作 |
| --- | --- | --- |
| `1` | 叶 A | 输出 **A**，回根 |
| `0` `0` `1` | 叶 C | 输出 **C**，回根 |
| `0` `0` `0` | 叶 D | 输出 **D**，回根 |

结果：**ACD**

### 性质 2：哈夫曼编码是最优前缀编码

对包含 n 种字符的数据文件，以出现次数为权构造哈夫曼树，用它对应的编码，能使编码后的二进制文件**长度最短**。

**推理**：设字符 i 出现 wi 次、编码长度 li 位，则文件总长 =∑wili。把编码方案画成二叉树（字符在叶结点上），li 恰是叶结点到根的路径长度，于是**文件总长就是这棵树的 WPL**。因此"设计总长最短的二进制前缀编码"与"以字符频率为权构造 WPL 最小的二叉树"是同一个问题——而后者的解正是哈夫曼树。∎

**注意"最优"不等于"唯一"**：由性质 3，最优编码方案可以有多套（左右可交换、并列权值可任选），它们的**总长相同**。所以判断一套编码是不是最优，同样要算总长，不能对编码表。

## 八、构造算法的实现

由性质 2，n 个叶结点的哈夫曼树共 2n−1 个结点，可以存放在一个大小为 2n−1 的一维数组里。数组前 n 个位置放叶结点，后 n−1 个位置放合并出的内部结点。每个结点存权值、双亲下标、左右孩子下标。c

```
typedef struct {
    int weight;       // 权值
    int parent;       // 双亲下标，-1 表示尚未被合并（即仍是森林中的一棵树根）
    int lchild;       // 左孩子下标
    int rchild;       // 右孩子下标
} HTNode;

// 构建哈夫曼树：w[] 为权值数组，n 为叶结点数，ht[] 大小至少 2n-1
void CreateHuffmanTree(HTNode ht[], int w[], int n) {
    int total = 2 * n - 1;                    // 总结点数（性质 2）
    for (int i = 0; i < total; i++) {         // 初始化
        ht[i].parent = ht[i].lchild = ht[i].rchild = -1;
        ht[i].weight = (i < n) ? w[i] : 0;    // 前 n 个是叶结点
    }
    for (int i = n; i < total; i++) {         // 恰好进行 n-1 次合并
        int min1 = -1, min2 = -1;
        // 在"尚未被合并"（parent == -1）的结点中选权值最小的两个
        for (int j = 0; j < i; j++) {
            if (ht[j].parent != -1) continue;             // 已被合并，不再参与
            if (min1 == -1 || ht[j].weight < ht[min1].weight) {
                min2 = min1;                              // 原来的最小降为次小
                min1 = j;
            } else if (min2 == -1 || ht[j].weight < ht[min2].weight) {
                min2 = j;
            }
        }
        ht[i].weight = ht[min1].weight + ht[min2].weight; // 新根权值 = 两者之和
        ht[i].lchild = min1;
        ht[i].rchild = min2;
        ht[min1].parent = ht[min2].parent = i;            // 标记为"已被合并"
    }
}
```

**三处关键设计**：

| 设计 | 作用 |
| --- | --- |
| `parent == -1` 作为"仍在森林中"的标志 | 免去真的维护一个森林集合；合并时把两棵树的 `parent` 一置，它们自动退出后续竞争 |
| 循环从 `i = n` 到 `total - 1` | 恰好 n−1 轮，与"合并 n−1 次"对应 |
| 内层只扫描 `j < i` | 下标 ≥i 的结点还没生成，不必看 |

**求编码时反着走**：从每个叶结点出发，沿 `parent` 回溯到根，回溯时判断"自己是双亲的左孩子还是右孩子"来生成 0 或 1。由于是从叶往根走，**得到的编码是逆序的**，需要从后往前填入字符数组（或最后整体逆置）。

## 复杂度分析

| 操作 | 时间复杂度 | 来历 |
| --- | --- | --- |
| 构造哈夫曼树（线性选最小） | O(n2) | 共 n−1 轮合并，每轮线性扫描 O(n) 个候选找最小的两个 |
| 构造哈夫曼树（用最小堆） | O(nlog⁡n) | 建堆 O(n)；每轮两次删除最小 + 一次插入，各 O(log⁡n)，共 n−1 轮 |
| 由哈夫曼树生成全部编码 | O(∑lk)，即 O(n⋅l¯) | 每个叶结点沿 `parent` 回溯到根，走过的边数就是它的编码长度 |
| 译码一段 L 位的编码串 | O(L) | 每读一位在树上走一步，读完即止 |

**用堆优化的原理**：算法里唯一的非常数开销是"选权值最小的两棵树"，这正是[优先队列](./heap.html)的看家操作。把森林放进最小堆，选最小从 O(n) 降到 O(log⁡n)，总时间从 O(n2) 降到 O(nlog⁡n)。

**空间**：O(n)，需要 2n−1 个结点的存储；编码表另需 O(∑lk)。

## 易混淆知识点

| 对比项 | 一方 | 另一方 | 判别依据 |
| --- | --- | --- | --- |
| WPL 统计哪些结点 | **只统计叶结点** | 内部结点不计入定义式 | 定义就是"所有叶结点的带权路径长度之和" |
| 路径长度数什么 | **数边**（根到自身为 0） | 不是数结点 | WPL 用边数；[BST 的 ASL](./bst.html) 用结点数，二者差 1 |
| 哈夫曼树是否唯一 | **不唯一**（左右可换、并列权可任选） | **WPL 唯一** | 判定某树是否为哈夫曼树，要算 WPL 是否等于最小值 |
| 编码长度是否唯一 | **不唯一**——同一字符在不同哈夫曼树中长度可能不同 | 总长（WPL）唯一 | 见 {1,2,3,3} 的两种选法 |
| 哈夫曼树的度分布 | n1=0，只有度 0 和度 2 | 不是"完全二叉树" | 每次合并必取两棵树 |
| 结点总数 | 2n−1（n 为**叶结点数**） | 不是 2n、也不是 n | n0=n2+1 且 n1=0 |
| 前缀编码 vs 等长编码 | 前缀编码不定长但无歧义 | 等长编码也是前缀编码的特例 | 等长码互不为前缀，只是没有利用频率差异 |
| 前缀编码的判定 | 把编码画成二叉树，看**字符是否全在叶结点上** | 有字符落在内部结点 → 不是前缀编码 | 内部结点的编码必是其子孙编码的前缀 |
| "最优前缀编码"是否唯一 | 方案不唯一，**总长唯一** | — | 与哈夫曼树不唯一同源 |
| 构造时新结点要不要放回森林 | **必须放回**，参与后续比较 | 忘记放回是最常见的手算错误 | 森林规模每轮减 1，从 n 到 1 共 n−1 轮 |
| 哈夫曼树 vs 最优二叉搜索树 | 哈夫曼树的字符只在叶结点、无序 | BST 的关键字在所有结点、有序 | 哈夫曼树不能用来查找，它的叶结点顺序无意义 |

## 本节小结

学完本篇，应该能够：

- **准确写出 WPL 的定义**（只统计叶结点、路径长度数边），并说清它与 ASL 口径的差别
- **用交换论证说明"权大离根近"为什么最优**，从而理解贪心策略的根据
- **执行哈夫曼算法构造哈夫曼树**，并记住"新生成的结点必须放回森林参与后续比较"
- **推导三条形态性质**：无度为 1 的结点（删掉它 WPL 严格变小）、n 个叶子共 2n−1 个结点（由 n1=0 与 n0=n2+1）、树不唯一但 WPL 唯一
- **用两种方法算 WPL**，并证明"WPL = 所有非叶结点权值之和"（每片叶子的权被它的每个内部祖先各数了一次，祖先个数就是路径长度）；手算时用后者边构造边累加
- **写出哈夫曼编码并完成译码**，说清译码时"到叶结点就输出并回根"的过程
- **证明哈夫曼编码是前缀编码**（编码路径终点必是叶结点，而前缀关系要求终点不是叶结点），并说明前缀性如何保证译码无歧义
- **判定一棵给定的树是不是哈夫曼树、一套编码是不是最优编码**：都要算 WPL / 总长，不能凭形态或编码表比对

**两条最关键的结论**：**WPL = 所有非叶结点权值之和**，这是手算的最快路径；**哈夫曼树不唯一、单个字符的编码长度也可能不唯一，但 WPL 唯一**——凡是判定题一律回到算 WPL。
