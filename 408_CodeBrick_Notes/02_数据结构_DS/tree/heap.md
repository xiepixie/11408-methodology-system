## 知识框架

本节要回答四个问题：

- 堆为什么**必须**是完全二叉树？这条限制换来了什么？
- 上浮和下沉是一对镜像操作，什么时候用哪个？——判据只有一条
- 建堆明明要对 n/2 个结点各做一次 O(log⁡n) 的下沉，**为什么总时间是 O(n) 而不是 O(nlog⁡n)**？

## 一、堆是什么

**堆**（Heap）是一棵满足**堆序性**的**完全二叉树**：

- **大根堆（Max Heap）**：每个结点的值都**大于等于**其孩子的值
- **小根堆（Min Heap）**：每个结点的值都**小于等于**其孩子的值

写成序列形式（n 个元素的序列 {k1,k2,…,kn}，下标从 1 开始）：大根堆：ki≥k2i且ki≥k2i+1,小根堆：ki≤k2i且ki≤k2i+1

其中 1≤i≤⌊n/2⌋（只需对分支结点检查，叶结点自动满足）。

```
    大根堆                  小根堆
      9                       1
     / \                     / \
    7   8                   3   2
   / \ / \                 / \ / \
  4  6 5  3               7  4 8  6
```

### 三条必须理解的性质

**1. 堆不是有序的。** 堆只保证"双亲优于孩子"，**不保证左右孩子之间、也不保证同一层之间的大小关系**。观察上面的大根堆：每个"三角形"（双亲 + 两个孩子）内部双亲最大，但 7<8（同层）、4<6（同层）、6>5（跨子树）这些关系是完全自由的。

**这条性质决定了堆能做什么、不能做什么**：能 O(1) 取最值，但**查找任意元素只能 O(n) 全扫**，因为没有任何信息能指导"该往左还是往右"。

**2. 根永远是最值。** 大根堆的根是全局最大值，小根堆的根是全局最小值。

**证明**：由堆序性，根 ≥ 它的两个孩子；两个孩子又各自 ≥ 自己的孩子；沿任意一条从根出发的路径传递下去，根 ≥ 路径上的每一个结点。而任一结点都在某条从根出发的路径上，故根 ≥ 所有结点。∎

**3. 堆必须是完全二叉树——这是为了能用数组存。** [完全二叉树](./concepts.html)的层序编号连续无空洞，因此可以按编号直接放进数组，且双亲与孩子的下标能用公式算出来，**一个指针都不用存**。若允许任意形态，就必须回到二叉链表，O(1) 定位孩子的能力立刻丧失，所有下标公式全部失效。

**换个角度看这条限制**：完全二叉树是"在给定结点数下高度最小"的形态（高度 ⌈log2⁡(n+1)⌉），这同时保证了上浮 / 下沉的路径长度是 O(log⁡n)。**形态限制既换来了存储上的便利，也换来了操作上的复杂度保证。**

## 二、顺序存储与下标关系

**下标从 1 开始**（`A[1..n]`，教材与本篇代码统一采用这个约定）：

| 关系 | 公式 | 边界条件 |
| --- | --- | --- |
| 双亲 `parent(i)` | ⌊i/2⌋ | i=1 时无双亲 |
| 左孩子 `left(i)` | 2i | 2i>n 时无左孩子 |
| 右孩子 `right(i)` | 2i+1 | 2i+1>n 时无右孩子 |
| 最后一个分支结点 | ⌊n/2⌋ | — |
| 叶结点的下标范围 | ⌊n/2⌋+1∼n | — |
| 结点 i 所在层次 | ⌊log2⁡i⌋+1 | — |

**下标从 0 开始**（`A[0..n-1]`，工业语言常用）：

| 关系 | 公式 |
| --- | --- |
| 双亲 `parent(i)` | ⌊(i−1)/2⌋ |
| 左孩子 `left(i)` | 2i+1 |
| 右孩子 `right(i)` | 2i+2 |
| 最后一个分支结点 | ⌊n/2⌋−1 |

**两套约定的换算不用背**：0-base 的下标比 1-base 小 1，把 0-base 的 i 换成 i+1 代进 1-base 公式再减 1 即可。例如左孩子：2(i+1)−1=2i+1 ✓。

**做题第一步永远是看清题目用哪套约定**，否则双亲孩子会整体错一格，后面全盘皆错。

### 判定一个数组是不是堆

直接按定义查：对每个分支结点 i∈[1,⌊n/2⌋]，检查它是否优于它存在的孩子。c

```
// 判断 A[1..n] 是否为大根堆
int IsMaxHeap(int A[], int n) {
    for (int i = 1; i <= n / 2; i++) {          // 只需检查分支结点
        if (A[i] < A[2 * i]) return 0;          // 左孩子必然存在（i ≤ ⌊n/2⌋）
        if (2 * i + 1 <= n && A[i] < A[2*i+1])  // 右孩子可能不存在
            return 0;
    }
    return 1;
}
```

**时间 O(n)**，比"重新建一次堆再比较"更直接。注意 i≤⌊n/2⌋ 保证了左孩子 2i≤n 一定存在，**只有右孩子需要判越界**。

## 三、下沉调整（Sift Down）

下沉是堆操作的**最核心动作**，其余操作几乎都由它组合而来。

**场景**：某个结点 i 违反堆序（以大根堆为例，它比孩子小），而**它的两棵子树本身都已经是堆**。此时把它"沉"下去即可恢复整棵子树的堆序。

**算法**：

- 比较 i 与它的左右孩子，找出**最大的那个**（设下标为 k）
- 若最大的就是 i 自己，堆序已满足，结束
- 否则交换 A[i] 与 A[k]，然后对位置 k **继续下沉**c

```
// 大根堆下沉调整：把 A[i] 沉到合适位置，堆规模为 n（A[1..n]）
// 前提：以 i 的左右孩子为根的两棵子树本身已经是堆
void SiftDown(int A[], int i, int n) {
    int temp = A[i];                     // 暂存待下沉的值，避免每层都做三次赋值的完整交换
    for (int k = 2 * i; k <= n; k *= 2) {// k 指向 i 的左孩子，每层翻倍下移
        if (k < n && A[k] < A[k + 1])
            k++;                         // k < n 保证右孩子存在；取左右孩子中较大的
        if (temp >= A[k])
            break;                       // 已满足堆序，停止下沉
        A[i] = A[k];                     // 较大的孩子上移一层
        i = k;                           // i 跟着沉到孩子的位置
    }
    A[i] = temp;                         // 循环结束后，i 就是 temp 的最终位置
}
```

**三处细节**：

| 细节 | 作用 |
| --- | --- |
| `k < n && A[k] < A[k+1]` | `k < n` 先短路判断右孩子是否存在（k=n 时右孩子 k+1 越界）；条件顺序不能颠倒 |
| 用 `temp` 暂存 + 单向搬移 | 每层只写一次 `A[i] = A[k]`，而完整交换要写三次。等价但更省，教材的"筛选法"用的就是这种写法 |
| `A[i] = temp` 放在循环外 | 循环中 `i` 一直在往下走，最终位置只有循环结束才确定 |

**前提条件不能忘**：`SiftDown` 要求**两棵子树已经是堆**。若子树本身就乱，一次下沉不能修好——这正是建堆必须**自底向上**的原因。

**复杂度 O(log⁡n)**：下沉路径最长等于树高 ⌈log2⁡(n+1)⌉，每层常数工作。

**教材里这个操作叫"筛选法"**——"上述过程就像过筛子一样，把较小的关键字逐层筛下去，而将较大的关键字逐层选上来"。

## 四、上浮调整（Sift Up）

上浮是下沉的镜像。**场景**：某个结点比它的双亲大（大根堆），需要往上"浮"。典型用在**插入**：新元素先放到数组末尾，再从末尾向上调整。c

```
// 大根堆上浮调整：把 A[i] 沿双亲方向浮到合适位置
void SiftUp(int A[], int i) {
    int temp = A[i];
    while (i > 1 && temp > A[i / 2]) {   // i > 1 保证还没到根
        A[i] = A[i / 2];                 // 双亲下移一层
        i = i / 2;                       // i 跟着浮上去
    }
    A[i] = temp;
}
```

**复杂度 O(log⁡n)**：上浮路径最长等于树高。

### 用上浮还是用下沉——判据只有一条

**看这个结点是"比双亲优"还是"比孩子劣"。** 比双亲优（破坏了上面的堆序）就上浮，比孩子劣（破坏了下面的堆序）就下沉。

| 场景 | 用哪个 | 理由 |
| --- | --- | --- |
| 插入新元素（放在末尾） | **上浮** | 末尾元素的子树是空的，只可能与双亲冲突 |
| 删除堆顶（末元素补到根） | **下沉** | 根没有双亲，只可能与孩子冲突 |
| 建堆（自底向上） | **下沉** | 每次处理的结点，其两棵子树已经是堆 |
| 增大某元素的值（大根堆） | **上浮** | 变大了，可能优于双亲 |
| 减小某元素的值（大根堆） | **下沉** | 变小了，可能劣于孩子 |
| 删除任意位置的元素 | **两者都要试** | 末元素补进来后，与双亲、与孩子都可能冲突 |

## 五、建堆——为什么是 O(n)

把一个无序数组变成堆，有两种思路。

### 思路 A：自顶向下逐个插入（O(nlog⁡n)）

把数组看作"逐个插入"的过程：先把 A[1] 当作只有一个元素的堆，然后依次把 A[2],A[3],… 插入并上浮。第 i 个元素上浮最多 ⌊log2⁡i⌋ 层，总代价∑i=1nlog2⁡i=log2⁡(n!)=Θ(nlog⁡n)

### 思路 B：自底向上逐个下沉（O(n)）

直接把数组看成一棵完全二叉树。从**最后一个分支结点** i=⌊n/2⌋ 开始，依次往前对每个分支结点做下沉调整：c

```
// 大根堆建堆：O(n)
void BuildMaxHeap(int A[], int n) {
    for (int i = n / 2; i >= 1; i--) {   // 从最后一个分支结点倒着往前
        SiftDown(A, i, n);               // 此时 i 的两棵子树已经是堆，前提满足
    }
}
```

**为什么从 ⌊n/2⌋ 开始**：由[完全二叉树的性质](./concepts.html)，编号 >⌊n/2⌋ 的结点全是叶子，单结点天然是堆，下沉是空操作。

**为什么必须倒着走**：`SiftDown` 的前提是"两棵子树已经是堆"。倒序处理保证当轮到结点 i 时，它的孩子 2i、2i+1（编号都比 i 大）已经被处理过了。**正着走会违反前提，建出来的不是堆。**

### O(n) 的完整推导

关键洞察：**每次 `SiftDown` 的代价不是 O(log⁡n)，而是"该结点的高度"**——高度低的结点根本沉不了几层，而**绝大多数结点的高度都很低**。

把结点按**高度**（到最深叶子的距离）分类。在有 n 个结点的完全二叉树中，高度为 k 的结点**至多有 ⌈n/2k+1⌉ 个**：

| 高度 k | 结点数（约） | 每个的下沉代价 | 该层总代价 |
| --- | --- | --- | --- |
| 0（叶子） | n/2 | 0 | 0 |
| 1 | n/4 | ≤1 | n/4 |
| 2 | n/8 | ≤2 | 2n/8 |
| … | … | … | … |
| h（根） | 1 | ≤h | h |

总代价T(n)≤∑k=0hn2k+1⋅k=n2∑k=0hk2k<n2∑k=0∞k2k

**这个无穷级数收敛到 2**，推导如下：令 S=∑k=1∞k/2k=12+24+38+⋯，则2S=1+22+34+48+⋯

两式相减，2S−S=1+12+14+18+⋯=2，故 S=2。

代回得T(n)<n2×2=n⟹T(n)=O(n)

**一句话直觉**：思路 B 高效，是因为**结点数最多的那一层（叶子，占一半）代价为 0，代价最高的那个结点（根）只有一个**——代价与结点数**成反比**分布，加权和就收敛了。思路 A 反过来：结点数最多的最后一层，恰恰是上浮路径最长的一层，所以没法收敛。

**两条容易记反的结论**：

- **建堆是 O(n)，堆排序是 O(nlog⁡n)。** 堆排序 = O(n) 建堆 + n 次 O(log⁡n) 的删除堆顶，O(n)+O(nlog⁡n)=O(nlog⁡n)——**慢的是后半段，建堆本身不慢**
- O(n) 是**上界**，不是"恰好 n 次比较"。它的准确含义是"总代价与 n 成正比"

### 建堆手算示例

对 A=[4,1,3,2,16,9,10,14,8,7] 建大根堆（下标从 1 开始）。

```
初始：A = [_, 4, 1, 3, 2, 16, 9, 10, 14, 8, 7]

对应完全二叉树：
              4(1)
           /        \
        1(2)         3(3)
        /   \       /    \
     2(4)  16(5)  9(6)  10(7)
     /  \    /
  14(8) 8(9) 7(10)

n = 10，最后一个分支结点 i = ⌊10/2⌋ = 5，从 i = 5 倒着处理到 i = 1。

i = 5（值 16）：孩子只有 A[10] = 7。16 > 7，不下沉。
i = 4（值 2）： 孩子是 A[8]=14 和 A[9]=8，较大者 14。
                2 < 14，交换 → A[4]=14, A[8]=2。
                继续看 i=8：8 已是叶子（2×8=16 > 10），停止。
i = 3（值 3）： 孩子是 A[6]=9 和 A[7]=10，较大者 10。
                3 < 10，交换 → A[3]=10, A[7]=3。
                i=7 是叶子，停止。
i = 2（值 1）： 孩子是 A[4]=14 和 A[5]=16，较大者 16。
                1 < 16，交换 → A[2]=16, A[5]=1。
                继续下沉 i=5：孩子只有 A[10]=7，1 < 7，交换 → A[5]=7, A[10]=1。
i = 1（值 4）： 孩子是 A[2]=16 和 A[3]=10，较大者 16。
                4 < 16，交换 → A[1]=16, A[2]=4。
                继续下沉 i=2：孩子是 A[4]=14 和 A[5]=7，较大者 14。
                4 < 14，交换 → A[2]=14, A[4]=4。
                继续下沉 i=4：孩子是 A[8]=2 和 A[9]=8，较大者 8。
                4 < 8，交换 → A[4]=8, A[9]=4。
                i=9 是叶子，停止。

结果：A = [_, 16, 14, 10, 8, 7, 9, 3, 2, 4, 1]

              16
           /       \
         14         10
        /   \      /   \
       8     7    9     3
      / \   /
     2   4 1
```

**逐点自检**：16≥14,10 ✓；14≥8,7 ✓；10≥9,3 ✓；8≥2,4 ✓；7≥1 ✓。是大根堆。

## 六、插入

**算法**：把新元素 x 放到数组末尾（即完全二叉树的最后一个位置，这样才不破坏完全性），然后对它做 `SiftUp`。c

```
void HeapInsert(int A[], int *n, int x) {
    (*n)++;              // 堆规模加 1
    A[*n] = x;           // 放到末尾：唯一不破坏完全二叉树形态的位置
    SiftUp(A, *n);       // 向上调整
}
```

**复杂度 O(log⁡n)**。

**为什么必须放末尾**：完全二叉树要求"第 h 层从左到右连续"，能追加结点的位置只有一个——编号 n+1 处。放别处形态就破了，下标公式随之失效。

**手算示例**：在大根堆 [_,16,14,10,8,7,9,3,2,4,1] 中插入 15。

```
末尾追加：A = [_, 16, 14, 10, 8, 7, 9, 3, 2, 4, 1, 15]，n = 11

15 在下标 11，双亲下标 ⌊11/2⌋ = 5，A[5] = 7。15 > 7，交换：
    A = [_, 16, 14, 10, 8, 15, 9, 3, 2, 4, 1, 7]
15 在下标 5，双亲下标 ⌊5/2⌋ = 2，A[2] = 14。15 > 14，交换：
    A = [_, 16, 15, 10, 8, 14, 9, 3, 2, 4, 1, 7]
15 在下标 2，双亲下标 1，A[1] = 16。15 < 16，停止。

结果：A = [_, 16, 15, 10, 8, 14, 9, 3, 2, 4, 1, 7]
```

**上浮走了 2 步**，符合 O(log⁡n) 的量级（⌊log2⁡11⌋+1=4 层）。

## 七、删除堆顶

堆的"常规删除"指**删除堆顶元素**（最值），这就是优先队列的出队语义。

**算法**：

- 取出堆顶 A[1]（这是要返回的值）
- 把**最后一个元素** A[n] 搬到堆顶
- 堆规模减 1（`n--`）
- 对新堆顶做 `SiftDown`c

```
int HeapDeleteTop(int A[], int *n) {
    int top = A[1];        // 保存要返回的最值
    A[1] = A[*n];          // 末元素补到根：保持完全二叉树形态
    (*n)--;
    SiftDown(A, 1, *n);    // 新根只可能劣于孩子，所以是下沉
    return top;
}
```

**复杂度 O(log⁡n)**。

**为什么不"删掉根然后把两个子堆合并"**：那样最后一层会出现空洞，**不再是完全二叉树**，顺序存储的全部下标公式立刻失效。把末元素提上来再下沉，是唯一既保形态又只需 O(log⁡n) 的做法。

**手算示例**：对 [_,16,15,10,8,14,9,3,2,4,1,7]（n=11）删除堆顶。

```
取出 16；把 A[11] = 7 搬到 A[1]；n 变为 10：
    A = [_, 7, 15, 10, 8, 14, 9, 3, 2, 4, 1]
下沉 i=1：孩子 A[2]=15、A[3]=10，较大者 15。7 < 15，交换 → A[1]=15, A[2]=7
下沉 i=2：孩子 A[4]=8、A[5]=14，较大者 14。7 < 14，交换 → A[2]=14, A[5]=7
下沉 i=5：孩子只有 A[10]=1。7 > 1，停止。

结果：A = [_, 15, 14, 10, 8, 7, 9, 3, 2, 4, 1]，返回 16
```

**自检**：15≥14,10 ✓；14≥8,7 ✓；10≥9,3 ✓；8≥2,4 ✓；7≥1 ✓。仍是大根堆。

## 八、删除任意元素与修改优先级

这两个操作在优先队列的实际使用中很常见，做法都是"先改，再判断往哪边调"。

### 删除任意位置 i 的元素
c

```
void HeapDeleteAt(int A[], int *n, int i) {
    A[i] = A[*n];              // 用末元素填补空位，保持完全二叉树形态
    (*n)--;
    if (i > *n) return;        // 删的就是最后一个，无需调整
    // 填进来的值与原值大小关系不定：可能需要上浮，也可能需要下沉
    SiftDown(A, i, *n);        // 先试下沉
    SiftUp(A, i);              // 若下沉没动（i 未变），再试上浮
}
```

**为什么两个都要试**：末元素填到位置 i 之后，它既可能比 i 的双亲大（要上浮），也可能比 i 的孩子小（要下沉）。**但两者不会同时发生**——因为原来 A[parent(i)]≥ 原 A[i] 且原 A[i]≥ 孩子，新值只要不在这个区间内，就只会往一个方向越界。所以"先下沉再上浮"是安全的：其中至多一个会真正移动元素。

### 修改某元素的优先级

大根堆中把 A[i] 改成新值 v：

- v> 原值 → 它可能优于双亲 → **上浮**
- v< 原值 → 它可能劣于孩子 → **下沉**

两种情形都是 O(log⁡n)。

**注意**：这两个操作都要求**先知道元素在数组中的下标 i**。堆本身查找任意元素是 O(n)，所以实际使用时通常另外维护一张"元素 → 下标"的映射表，并在每次交换时同步更新。这也是"堆不适合频繁按值查找"的直接体现。

## 九、堆作为优先队列

**优先队列**（Priority Queue）是一个抽象数据类型，核心操作：

| 操作 | 语义 | 用堆实现的复杂度 |
| --- | --- | --- |
| `Insert(x)` | 插入一个带优先级的元素 | O(log⁡n) |
| `GetTop()` | 取优先级最高的元素（不删除） | O(1) |
| `ExtractTop()` | 取出并删除优先级最高的元素 | O(log⁡n) |
| `Build(A)` | 由一个数组批量建立 | O(n) |
| `DecreaseKey(i, v)` | 修改优先级 | O(log⁡n) |

**为什么堆是优先队列的标准实现**——把几种候选放在一起比就清楚了：

| 实现 | 插入 | 取最值 | 删除最值 | 问题 |
| --- | --- | --- | --- | --- |
| 无序数组 / 链表 | O(1) | O(n) | O(n) | 取最值太慢 |
| 有序数组 | O(n) | O(1) | O(1) | 插入要移动元素 |
| 有序链表 | O(n) | O(1) | O(1) | 插入要顺序查找位置 |
| 平衡二叉搜索树 | O(log⁡n) | O(log⁡n) | O(log⁡n) | 能做，但维护代价与常数都更大，且提供了用不上的"全序"能力 |
| **堆** | O(log⁡n) | O(1) | O(log⁡n) | — |

**堆的定位很清楚：它只维护"最值在顶"这一条弱得多的性质，因此比 BST 便宜；而优先队列恰好只需要这一条。** 用平衡树做优先队列属于"杀鸡用牛刀"——多出来的有序性完全用不上。

### 典型应用

| 应用 | 堆在其中的角色 |
| --- | --- |
| [哈夫曼树构造](./huffman.html) | 用**最小堆**反复取权值最小的两棵树，把构造从 O(n2) 降到 O(nlog⁡n) |
| [Dijkstra 算法](./../graph/dijkstra.html) | 用**最小堆**取"当前距离最小的未确定顶点" |
| [Prim 算法](./../graph/prim.html) | 用**最小堆**取"到生成树代价最小的顶点" |
| [堆排序](./../sorting/heap-sort.html) | 反复取堆顶得到有序序列 |
| 操作系统的进程调度 | 按优先级出队 |

## 十、Top-K 与第 k 大

这是堆最典型的独立应用，两种问法用两套不同的做法。

### 求第 k 大的元素

建**大根堆** O(n)，然后删除堆顶 k−1 次，此时堆顶就是第 k 大。

**时间 O(n+klog⁡n)**，空间 O(1)（原地建堆）。当 k 很小时接近 O(n)。

### 求最大的 k 个元素（Top-K），n 很大、k 很小

**用大小为 k 的小根堆**：

- 取前 k 个元素建一个**小根堆**（O(k)）
- 对剩下的 n−k 个元素，逐个与**堆顶**比较：

- 若该元素 > 堆顶：说明它应当进入 Top-K，而堆顶是当前 Top-K 里最小的、应当被淘汰。用它替换堆顶并**下沉**（O(log⁡k)）
- 若该元素 ≤ 堆顶：它连当前第 k 大都比不过，直接丢弃（O(1)）
- 处理完后，堆中的 k 个元素就是最大的 k 个，堆顶是其中第 k 大

**时间 O(k+(n−k)log⁡k)=O(nlog⁡k)，空间 O(k)。**

**为什么求"最大的 k 个"却用"小"根堆**——这是最容易想反的一处。因为每来一个新元素，我们要做的判断是"**它够不够格挤进 Top-K**"，而挤进去就要淘汰掉当前 Top-K 中**最小**的那个。所以堆顶必须是这 k 个里的**最小值**，才能 O(1) 完成"比较 + 淘汰"。用大根堆的话，堆顶是最大值，而最大值恰恰是最不该被淘汰的，判断和淘汰都无从下手。

**一般化的记法**：**要淘汰谁，谁就放堆顶。**

**两种做法怎么选**：n 能全部装进内存且 k 与 n 同量级时用第一种（O(n+klog⁡n)）；n 极大（如数据流、外存数据）或 k≪n 时用第二种——它只需 O(k) 空间，**且数据可以只过一遍、不必全部存下来**。

## 复杂度分析

| 操作 | 时间复杂度 | 空间复杂度 | 来历 |
| --- | --- | --- | --- |
| 建堆（自底向上下沉） | **O(n)** | O(1)（原地） | 代价按结点高度加权求和，级数 ∑k/2k=2 收敛 |
| 建堆（自顶向下插入） | O(nlog⁡n) | O(1) | ∑i=1nlog2⁡i=Θ(nlog⁡n) |
| 插入一个元素 | O(log⁡n) | O(1) | 上浮路径最长为树高 |
| 删除堆顶 | O(log⁡n) | O(1) | 下沉路径最长为树高 |
| 删除任意位置元素（已知下标） | O(log⁡n) | O(1) | 一次下沉或一次上浮 |
| 修改某元素优先级（已知下标） | O(log⁡n) | O(1) | 同上 |
| 查找最大 / 最小（堆顶） | O(1) | O(1) | 直接读 A[1] |
| **查找任意元素** | **O(n)** | O(1) | 堆序性不提供任何"往左还是往右"的指导 |
| 判定一个数组是否为堆 | O(n) | O(1) | 检查 ⌊n/2⌋ 个分支结点 |
| 求第 k 大 | O(n+klog⁡n) | O(1) | O(n) 建大根堆 + k−1 次删堆顶 |
| Top-K（k 远小于 n） | O(nlog⁡k) | O(k) | 维护大小为 k 的小根堆 |

**"查找任意元素是 O(n)"是堆最重要的能力边界**。所以"在大根堆中查找第 k 大元素的时间是 O(1)"这类说法**只在 k=1 时成立**；k≥2 时第 k 大可能在第 2 层，也可能藏在更深的任何位置。

## 易混淆知识点

| 对比项 | 一方 | 另一方 | 判别依据 |
| --- | --- | --- | --- |
| 建堆 vs 堆排序的复杂度 | 建堆 **O(n)** | 堆排序 **O(nlog⁡n)** | 堆排序 = O(n) 建堆 + n 次 O(log⁡n) 删堆顶；慢的是后半段 |
| 自底向上建堆 vs 自顶向下建堆 | 下沉，O(n) | 上浮，O(nlog⁡n) | 代价与结点数是否成反比分布 |
| 建堆为什么倒着扫 | 保证"两棵子树已是堆"这个前提 | 正着扫会违反前提，建不出堆 | `SiftDown` 的适用条件 |
| 上浮 vs 下沉 | 比双亲优 → 上浮 | 比孩子劣 → 下沉 | 破坏的是上面的堆序还是下面的 |
| 插入位置 vs 删除时的补位 | 插入放**末尾**再上浮 | 删堆顶把**末元素**补到根再下沉 | 都是为了保持完全二叉树形态 |
| 堆 vs 二叉排序树 | 只保证双亲优于孩子，**整体无序** | 整棵树有序，中序遍历递增 | 堆查任意元素 O(n)，[BST](./bst.html) 是 O(h) |
| 堆顶 vs 第 k 大 | 堆顶 O(1) | 第 k 大（k≥2）不是 O(1) | 堆不保证第 2 层就是第 2、3 大 |
| Top-K 用大根堆还是小根堆 | 求最大的 k 个用**小根堆** | 想反是最常见的错误 | **要淘汰谁，谁就放堆顶** |
| 堆的形态是否唯一 | **不唯一**：同一组数据有多个合法的大根堆 | 用"自底向上下沉"算法建出的堆是**确定的** | 画图题按算法过程走，答案唯一 |
| 大根堆的最小值在哪 | 一定在**叶结点**中 | 不一定是最后一个元素 | 若最小值是分支结点，它必大于等于自己的孩子，矛盾 |
| 0-base vs 1-base 下标 | 1-base：双亲 ⌊i/2⌋、孩子 2i / 2i+1 | 0-base：双亲 ⌊(i−1)/2⌋、孩子 2i+1 / 2i+2 | 先看题面约定，否则整体错一格 |
| 堆必须是完全二叉树 | 是硬性要求 | 不是"通常是" | 完全性是顺序存储与下标公式成立的前提 |
| 堆 vs 优先队列 | 堆是**数据结构** | 优先队列是**抽象数据类型** | 优先队列可以用别的结构实现，堆只是最合适的那个 |

## 本节小结

学完本篇，应该能够：

- **准确陈述堆的定义**（完全二叉树 + 堆序性），并说清三条推论：堆整体无序、根恒为最值、必须完全二叉树才能顺序存储
- **默写两套下标公式**并现场换算，做题前先确认题面用的是 0-base 还是 1-base
- **默写 `SiftDown` 与 `SiftUp`**，说清 `SiftDown` 的前提是"两棵子树已是堆"、以及 `k < n` 这个短路判断的作用
- **判断该用上浮还是下沉**：比双亲优就上浮、比孩子劣就下沉
- **完整推导建堆的 O(n)**：按结点高度分层加权求和，用 ∑k≥1k/2k=2（错位相减可现场推出）收敛到 O(n)；并说清"建堆 O(n)、堆排序 O(nlog⁡n)"的区别
- **手算建堆、插入、删除堆顶的逐步过程**，并用"逐点检查双亲是否优于孩子"自检
- **处理删除任意元素与修改优先级**：先补位再判断往哪边调，两个方向至多一个会真正移动
- **说清堆为什么是优先队列的标准实现**：它只维护最值在顶这一条弱性质，比平衡树便宜，而优先队列恰好只需要这一条
- **区分"第 k 大"与"Top-K"两种问法的做法**，并解释求最大的 k 个为什么用**小**根堆——要淘汰谁，谁就放堆顶

**两条最关键的结论**：**建堆是 O(n)、堆排序是 O(nlog⁡n)**，慢的是排序阶段而非建堆；**堆查找任意元素是 O(n)**，"O(1) 取最值"只对堆顶成立。
