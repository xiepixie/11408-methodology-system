# 由遍历序列构造二叉树

## 大纲定位

本篇对应 2026 考研数据结构大纲 **四（二）3 二叉树的遍历**。

这一条目由五篇分担，**本篇负责"反问题"**：已知遍历序列，还原二叉树。包括三种可行组合的构造算法、唯一性的充要条件、以及**前序 + 后序为什么不行**的完整论证与计数。

| 归本篇 | 归别篇 |
| --- | --- |
| 前序 + 中序、后序 + 中序、层序 + 中序的构造算法 | 三种深度优先遍历本身见 [前序遍历](./preorder.html)、[中序遍历](./inorder.html)、[后序遍历](./postorder.html) |
| 唯一性的充要条件、前序 + 后序的反例与计数 | 层序遍历本身见 [层序遍历](./level-order-traversal.html) |
| 不建树直接求另一种序列的手工方法 | 二叉树的定义与"左右严格有别"见 [树与二叉树基本概念](./concepts.html) |

**全篇的前提**：二叉树中各结点的值**互不相同**。有重复值时，在中序序列里"定位根"会出现歧义，唯一性讨论全部失效。

## 知识框架

本节要回答三个问题：

- 为什么"两种序列"里**必须有中序**？中序到底提供了别的序列提供不了的什么信息？
- 前序 + 后序不能唯一确定二叉树——**反例长什么样**？满足同一对前序后序的树到底有**多少棵**？
- 唯一确定的**充要条件**究竟是"满二叉树"还是别的什么？

## 一、为什么必须有中序

三种遍历序列各自能提供什么信息，是本篇全部结论的源头：

| 序列 | 能提供 | 不能提供 |
| --- | --- | --- |
| **前序**（NLR） | 首元素是根；每棵子树占一段**连续**区间，且区间首元素是该子树的根 | 左右子树的**分界位置** |
| **后序**（LRN） | 末元素是根；每棵子树占一段连续区间，区间末元素是该子树的根 | 左右子树的**分界位置** |
| **层序** | 首元素是根；每棵子树的元素**保持相对次序**（但不连续） | 左右子树的分界 |
| **中序**（LNR） | **根把序列一分为二**：根左边全在左子树、右边全在右子树 | 谁是根（要靠别的序列告诉） |

**结论一目了然**：前序、后序、层序都只解决"谁是根"，中序只解决"左右怎么分"。**两个问题都要解决，所以必须一个定根 + 中序划分。** 前序 + 后序是两把同样的钥匙配同一把锁，另一把锁没人开。

这个"划分能力"的根源在于[二叉树严格区分左右](./concepts.html)：中序序列里，根左边的元素**只可能**来自左子树，右边的**只可能**来自右子树——这是中序定义的直接推论，其他次序都做不到。

## 二、通用三步法

三种可行组合共用同一个递归骨架：

- **定根**：前序取**首**元素 / 后序取**末**元素 / 层序取**首**元素
- **划分**：在中序序列中找到根的位置 k，其**左侧**为左子树的中序序列（长度 L=k−il），**右侧**为右子树的中序序列
- **切另一条序列并递归**：按 L 把定根用的那条序列切成左右两段，递归构造；子序列为空时返回 `NULL`

**切分时把结点数算错，是这类题最常见的失分方式。** 记牢：L 只能从**中序**里数出来（根左边有几个元素），不能从前序里"看着像"来估。前序中左子树占的是紧跟根之后的 L 个位置。

## 三、前序 + 中序构造

**原理**：前序首元素是根，在中序中定位该根即可划分左右。

以前序 `ABDECFG`、中序 `DBEAFCG` 为例：

| 步骤 | 操作 | 前序序列 | 中序序列 | 确定的根 |
| --- | --- | --- | --- | --- |
| 1 | 取前序首元素 A 为根；中序中 A 左侧 DBE（3 个）为左子树、FCG 为右子树 | **A** BDECFG | DBE **A** FCG | A |
| 2 | 左子树：前序取 A 后的 3 个 = BDE，中序 DBE → 根为 B，左 D、右 E | **B** DE | D **B** E | B |
| 3 | 右子树：前序剩下 CFG，中序 FCG → 根为 C，左 F、右 G | **C** FG | F **C** G | C |
| 4 | D、E、F、G 的子序列均为空，递归结束 | — | — | D E F G |

构造结果：

```
        A
       / \
      B   C
     / \ / \
    D  E F  G
```

**自检**：对结果重新做一次前序遍历得 `ABDECFG`、中序得 `DBEAFCG`，与题目给的一致——**还原完必须回代验证**，这一步能挡住绝大多数切分错误。c

```
typedef struct TreeNode {
    char val;
    struct TreeNode *left, *right;
} TreeNode;

// pre: 前序序列, in: 中序序列
// pl,pr: 前序子序列范围; il,ir: 中序子序列范围
TreeNode* buildFromPreIn(char pre[], int pl, int pr,
                         char in[],  int il, int ir) {
    if (pl > pr) return NULL;                       // 子序列为空：空子树
    TreeNode* root = (TreeNode*)malloc(sizeof(TreeNode));
    root->val = pre[pl];                            // 前序首元素是根
    int k;
    for (k = il; k <= ir; k++)                      // 在中序中定位根
        if (in[k] == pre[pl]) break;
    int leftLen = k - il;                           // 左子树结点数，只能从中序里数
    // 前序中：根之后的 leftLen 个是左子树，再往后是右子树
    root->left  = buildFromPreIn(pre, pl + 1,           pl + leftLen, in, il,    k - 1);
    root->right = buildFromPreIn(pre, pl + leftLen + 1, pr,           in, k + 1, ir);
    return root;
}
```

**边界核对**（这四个下标是最容易写错的地方）：

| 子序列 | 前序范围 | 中序范围 | 长度是否一致 |
| --- | --- | --- | --- |
| 左子树 | [pl+1,pl+L] | [il,k−1] | 都是 L ✓ |
| 右子树 | [pl+L+1,pr] | [k+1,ir] | 都是 (ir−k) ✓ |

L=0 时左子树的前序范围是 [pl+1,pl]，满足 `pl > pr` 直接返回 `NULL` ✓；整棵树只有一个结点时 pl=pr、L=0，两个孩子都返回 `NULL` ✓。

## 四、后序 + 中序构造

**原理**：后序**末**元素是根，其余逻辑与前序 + 中序完全对称。

以后序 `DEBFGCA`、中序 `DBEAFCG` 为例：

| 步骤 | 操作 | 后序序列 | 中序序列 | 确定的根 |
| --- | --- | --- | --- | --- |
| 1 | 取后序末元素 A 为根；中序划分为左 DBE、右 FCG | DEBFGC**A** | DBE **A** FCG | A |
| 2 | 左子树：后序取前 3 个 = DEB → 根为 B | DE**B** | D **B** E | B |
| 3 | 右子树：后序剩下 FGC → 根为 C | FG**C** | F **C** G | C |

构造结果与上例相同。c

```
TreeNode* buildFromPostIn(char post[], int pl, int pr,
                          char in[],   int il, int ir) {
    if (pl > pr) return NULL;
    TreeNode* root = (TreeNode*)malloc(sizeof(TreeNode));
    root->val = post[pr];                     // 后序最后一个元素是根
    int k;
    for (k = il; k <= ir; k++)
        if (in[k] == post[pr]) break;
    int leftLen = k - il;
    // 后序中：前 leftLen 个是左子树，接着是右子树，最后一个才是根
    root->left  = buildFromPostIn(post, pl,           pl + leftLen - 1, in, il,    k - 1);
    root->right = buildFromPostIn(post, pl + leftLen, pr - 1,           in, k + 1, ir);
    return root;
}
```

**边界核对**：左子树后序范围 [pl,pl+L−1] 长度 L ✓；右子树后序范围 [pl+L,pr−1] 长度 (pr−1)−(pl+L)+1=(ir−k) ✓（因为 pr−pl+1=L+(ir−k)+1）。L=0 时左子树范围为 [pl,pl−1]，直接返回 `NULL` ✓。

## 五、层序 + 中序构造

**原理**：层序首元素是根。在中序中定位根、划分左右后，从层序序列的**剩余部分按出现顺序**筛出属于左子树的元素与属于右子树的元素，各自组成新的层序序列，递归构造。

与前序 / 后序不同，层序序列中左右子树的元素是**交替出现**的（同一层的左右子树结点混在一起），**不能按位置切分**，必须按归属筛选。

以层序 `ABCDEFG`、中序 `DBEAFCG` 为例：

| 步骤 | 操作 | 层序序列 | 中序序列 |
| --- | --- | --- | --- |
| 1 | 层序首元素 A 为根；中序左 {D,B,E}、右 {F,C,G} | **A** BCDEFG | DBE **A** FCG |
| 2 | 在剩余的 BCDEFG 中筛选：属于左子树的按序为 **BDE**，属于右子树的为 **CFG** | — | — |
| 3 | 递归：左子树用层序 BDE + 中序 DBE → 根 B；右子树用层序 CFG + 中序 FCG → 根 C | — | — |

**为什么筛选后仍是合法的层序序列**：层序序列中，同一棵子树内部的结点保持"层次由浅到深、同层从左到右"的相对次序；把不属于该子树的元素删掉，剩下的相对次序不变，因此仍是这棵子树的层序序列。c

```
TreeNode* buildFromLevelIn(char level[], int ln,
                           char in[], int il, int ir) {
    if (ln == 0 || il > ir) return NULL;
    TreeNode* root = (TreeNode*)malloc(sizeof(TreeNode));
    root->val = level[0];                    // 层序首元素是根
    int k;
    for (k = il; k <= ir; k++)               // 在中序中定位根
        if (in[k] == level[0]) break;
    // 按"是否落在中序的根左侧"把层序剩余元素分成两组，组内保持原相对次序
    char leftLevel[ln], rightLevel[ln];
    int li = 0, ri = 0;
    for (int i = 1; i < ln; i++) {
        int inLeft = 0;
        for (int j = il; j < k; j++)
            if (level[i] == in[j]) { inLeft = 1; break; }
        if (inLeft) leftLevel[li++] = level[i];
        else        rightLevel[ri++] = level[i];
    }
    root->left  = buildFromLevelIn(leftLevel,  li, in, il,    k - 1);
    root->right = buildFromLevelIn(rightLevel, ri, in, k + 1, ir);
    return root;
}
```

**代码说明**：`leftLevel` / `rightLevel` 是变长数组，每层递归各占 O(ln) 空间。内层那个 j 循环是朴素的"判断元素是否属于左子树"，每次 O(n)；把它换成一个**标记数组**（先扫一遍中序左半段，把这些字符标记为"属左"），判断降为 O(1)。见下面的复杂度分析。

## 六、前序 + 后序为什么不能唯一确定

### 反例

前序 `AB`，后序 `BA`，下面两棵树都满足：

```
    树①            树②
     A              A
    /                \
   B                  B

前序：A B          前序：A B
后序：B A          后序：B A
```

两棵树不同（`B` 一个是左孩子、一个是右孩子），前序和后序却完全一样。

**根因**：前序中 `A` 后面跟着 `B`——但"根之后先是左子树、再是右子树"，`B` 可以是左子树的全部，也可以是"左子树为空、右子树是 `B`"。后序同理。**没有任何一条信息告诉我们左子树到底占了几个元素**，而这正是中序的作用。

### 一个更能说明问题的反例

前序 `A B C`，后序 `C B A`，满足的树有 **4** 棵：

```
   ①        ②        ③        ④
   A         A         A         A
  /         /           \         \
 B         B             B         B
/           \           /           \
C            C         C             C
```

四棵树互不相同，前序都是 `ABC`、后序都是 `CBA`。

### 到底有多少棵：2k

**结论**：给定一对合法的前序 + 后序序列，满足它们的二叉树共有 2k 棵，其中 k 是**度为 1 的结点个数**（即恰好只有一个孩子的结点数）。

**推理**：

- **每个度为 1 的结点贡献一个自由的二选一**。设结点 N 只有一个孩子子树 C。把 C 挂在左边时，前序是 N⋅pre(C)⋅ε；挂在右边时是 N⋅ε⋅pre(C)——**两者完全相同**。后序同理：post(C)⋅ε⋅N 与 ε⋅post(C)⋅N 也相同。所以这个选择在前序和后序上**都不留痕迹**
- **度为 0 和度为 2 的结点不贡献自由度**。叶子没得选；度为 2 的结点两棵子树都非空，前序里"根之后先出现的那一段"必属左子树，边界被前序 + 后序联合钉死
- 各个度为 1 的结点的选择互相独立，故总数为 2k

**回代验证**：上面第一个反例中，`A` 是唯一度为 1 的结点，k=1，21=2 棵 ✓；第二个反例中 `A`、`B` 都是度为 1 的结点，k=2，22=4 棵 ✓。

### 唯一确定的充要条件

由 2k=1 得 k=0：

**前序 + 后序能唯一确定一棵二叉树，当且仅当树中不存在度为 1 的结点**（每个结点要么是叶子、要么有两个孩子）。这类二叉树称为**正则二叉树**（也叫严格二叉树）。

**注意与"满二叉树"的关系**：[满二叉树](./concepts.html)（高度 h 且恰有 2h−1 个结点）一定不含度为 1 的结点，所以它是上述条件的**特例**——常见说法"前序 + 后序只有对满二叉树才唯一"是**充分不必要**的。下面这棵树不是满二叉树，但同样能被前序 + 后序唯一确定：

```
        A
       / \
      B   E          前序：A B C D E
     / \             后序：C D B E A
    C   D            每个结点度为 0 或 2，k = 0 → 唯一
```

**一句话记法**：**度为 1 的结点是唯一的歧义来源，有几个就翻几倍。**

## 七、不建树，直接求另一种序列

考场手算时通常不需要真的把树画出来，可以用"分段递归"直接推。以已知**前序 `ABDECFG` + 中序 `DBEAFCG`，求后序**为例：

```
前序 A | BDE | CFG          ← 首元素 A 是根，按中序分出左 3 个、右 3 个
中序 DBE | A | FCG
       ↓
   后序 = 后序(左) + 后序(右) + A

左：前序 B|D|E，中序 D|B|E → 后序(左) = D E B
右：前序 C|F|G，中序 F|C|G → 后序(右) = F G C

后序 = D E B  F G C  A = DEBFGCA
```

**这个写法比画树快，也不容易漏结点**：每一步都在做"把当前区间按根切成三块"，写成缩进的分段就不会串行。做完后可以用"后序末元素 = 根"再核一遍。

## 复杂度分析

| 构造方式 | 时间复杂度 | 空间复杂度 | 来历 |
| --- | --- | --- | --- |
| 前序 + 中序（朴素） | O(n2) | O(n) | 每次在中序中线性查找根 O(n)，共 n 次；最坏（单支树）递归 n 层 |
| 前序 + 中序（预处理） | O(n) | O(n) | 先用一个数组 / 散列表记下每个关键字在中序中的下标，定位降为 O(1) |
| 后序 + 中序 | 同上 | 同上 | 完全对称 |
| 层序 + 中序（朴素） | 最坏 O(n3) | O(n2) | 每次筛选要对 O(n) 个元素各做一次 O(n) 的"是否属左"判断，且递归最坏 n 层 |
| 层序 + 中序（用标记数组） | O(n2) | O(n) | 每层筛选降为 O(n)，递归最坏 n 层 |

**为什么朴素版是 O(n2) 而不是 O(nlog⁡n)**：递归的层数取决于树高，最坏是单支树的 n 层；每层的"查找根"是 O(n)。平衡时是 O(nlog⁡n)，但复杂度按最坏算。

**为什么预处理能降到 O(n)**：查找根是唯一的非常数开销。把中序序列扫一遍、建一张"关键字 → 下标"的表（关键字是小范围整数时用数组，否则用散列表），此后每次定位 O(1)，总时间就是"每个结点被创建一次"的 O(n)。

**空间为什么是 O(n)**：递归栈深等于树高，最坏 n；预处理表 O(n)；生成的树本身 O(n)。三项同阶。

## 易混淆知识点

| 对比项 | 一方 | 另一方 | 判别依据 |
| --- | --- | --- | --- |
| 哪些组合能唯一确定 | 前序 + 中序 ✓、后序 + 中序 ✓、层序 + 中序 ✓ | 前序 + 后序 ✗、前序 + 层序 ✗、后序 + 层序 ✗ | **组合里有没有中序**——只有中序能划分左右 |
| 前序 + 后序的唯一性条件 | 准确条件：**不存在度为 1 的结点**（正则二叉树） | 常见说法"满二叉树"是**充分不必要** | 数一数度为 1 的结点有几个，k=0 才唯一 |
| 满足同一对前序 + 后序的树有几棵 | 2k（k = 度为 1 的结点数） | 不是固定的 2 棵 | 每个度为 1 的结点独立地二选一 |
| 单独一种序列能否确定 | 一般不能 | **带空标记 `#` 的前序序列可以**；**完全二叉树的层序序列可以** | 空位置是否被显式记录 / 形态是否已被约束 |
| 前序单独 vs BST 的前序单独 | 一般二叉树：不能 | **BST：能** | BST 的中序序列 = 前序排序，等于白送一条中序 |
| 层序切分 vs 前序切分 | 层序**不能**按位置切，要按归属筛 | 前序 / 后序**可以**按位置切 | 层序中左右子树元素交替出现 |
| 左子树结点数 L 从哪来 | 只能从**中序**里数（根左边的元素个数） | 不能从前序 / 后序里估 | 中序是唯一给出左右边界的序列 |
| 有重复关键字时 | 唯一性讨论全部失效 | 各结点值互不相同才成立 | 中序定位根会出现多个候选位置 |

## 本节小结

学完本篇，应该能够：

- **说清"必须包含中序"的理由**：前序 / 后序 / 层序都只能定根，只有中序能把左右子树分开；两件事都得办到才能还原
- **熟练执行三步法**：定根 → 中序划分 → 按左子树结点数切另一条序列递归；并知道 L 只能从中序里数
- **默写前序 + 中序、后序 + 中序的递归代码**，并逐个核对四个下标区间的长度自洽
- **说清层序 + 中序为什么不能按位置切**，而要按归属筛选，且筛选后仍是合法的层序序列
- **给出前序 + 后序不唯一的具体反例**（前序 `AB` / 后序 `BA` 对应两棵树；前序 `ABC` / 后序 `CBA` 对应四棵树）
- **推出满足同一对前序 + 后序的二叉树共 2k 棵**（k 为度为 1 的结点数），并由此得到唯一性的**充要条件是 k=0**，即树中不含度为 1 的结点；满二叉树只是它的特例
- **不画树直接由前序 + 中序推出后序**，用分段递归的写法

**两条最关键的结论**：能否唯一确定，判据是"**组合里有没有中序**"；前序 + 后序的歧义**全部来自度为 1 的结点**，有 k 个就有 2k 棵树。

## 教材出处

- "若二叉树中各结点的值均不相同，任意一棵二叉树结点的先序序列、中序序列和后序序列都是唯一的"以及"由二叉树的先序序列和中序序列，或由其后序序列和中序序列均能唯一地确定一棵二叉树"：严蔚敏《数据结构（C 语言版）》（第 2 版）**印刷 p125**（5.5.1 节第 2 部分"根据遍历序列确定二叉树"）
- "在先序序列中，第一个结点一定是二叉树的根结点"及随后由中序序列划分左右子树的论证，与由中序序列和后序序列确定二叉树的示例图：**印刷 p125–p126**
- 二叉树的递归定义与"二叉树的子树有左右之分，其次序不能任意颠倒"这一条，是中序具备划分能力、也是前序 + 后序产生歧义的前提：**印刷 p113**（5.2 节）
