# 后序遍历

## 大纲定位

本篇对应 2026 考研数据结构大纲 **四（二）3 二叉树的遍历**。

这一条目由五篇分担。**本篇负责后序遍历（LRN）**，其中**后序非递归是三种深度优先遍历里唯一需要额外状态的一种，两种标准解法（标记法、双栈法）在本篇讲透**，前两篇不再重复。

## 知识框架

本节要回答三个问题：

- 后序非递归到底难在哪？——不是代码长，而是模板里**缺一个状态位**
- 两种解法（标记法、双栈法）各自绕开这个困难的方式是什么？代价分别是什么？
- 什么样的任务**只能**用后序做，用前序或中序一定做不了？

## 一、访问顺序

后序遍历的访问顺序：**左子树 → 右子树 → 根结点**（LRN）。

**递归定义**：若树非空，先后序遍历左子树，再后序遍历右子树，最后访问根结点。

在遍历的固定游走路线上，每个结点被经过三次，**后序取的是第三次**——左右子树都处理完、准备回到双亲的那一刻。

对于下面的二叉树：

```
        A
       / \
      B   C
     / \   \
    D   E   F
```

后序遍历结果为：**D → E → B → F → C → A**

### 后序的语义：先算完孩子，再算自己

这一句话就是后序全部用途的来源。**任何"根的结果依赖于子树结果"的计算，都只能用后序**：

- 求树高：H(T)=max(H(TL),H(TR))+1——必须先有两棵子树的高度
- 求结点数：N(T)=N(TL)+N(TR)+1
- 释放整棵树：先释放子树，再释放根（先释放根就丢掉了指向子树的指针，子树成为无法回收的孤儿）
- 计算目录占用的磁盘空间：先算子目录

反过来，"信息从根往下传"的任务（标层号、求根到各结点的路径、复制建树）必须用前序。**判据只有一句：算根的时候需不需要子树的结果。**

## 二、后序序列的性质

### 性质 1：后序序列的最后一个元素一定是根

因为根最后才被访问。这与前序序列的第一个元素是根**对称**，二者都是[由遍历序列构造二叉树](./construct-binary-tree.html)的入手点。

### 性质 2：后序序列 = "根 → 右 → 左"（NRL）序列的逆序

**证明（对子树归纳）**：设 NRL(T) 与 LRN(T) 分别表示按两种次序得到的序列，rev(⋅) 表示逆序。

- 空树：两边都是空串，成立
- 非空树：按定义 NRL(T)=N⋅NRL(TR)⋅NRL(TL)。逆序后rev(NRL(T))=rev(NRL(TL))⋅rev(NRL(TR))⋅N由归纳假设，rev(NRL(TL))=LRN(TL)、rev(NRL(TR))=LRN(TR)，代入得rev(NRL(T))=LRN(TL)⋅LRN(TR)⋅N=LRN(T)

**验证**：上例的 NRL 序列是 **A C F B E D**，逆过来是 **D E B F C A**，正是后序序列。

这条性质是下面**双栈法**的全部依据。

**注意别记反**：后序**不是**前序（NLR）的逆序。前序 A B D E C F 的逆序是 F C E D B A，不是后序。必须先把前序改成"根→右→左"再逆。

### 性质 3：前序 + 后序不能唯一确定二叉树

两者都能定根，但都无法划分左右子树的边界。反例与完整讨论见 [由遍历序列构造二叉树](./construct-binary-tree.html)。

## 三、递归实现
c

```
typedef struct BiTNode {
    int data;
    struct BiTNode *lchild, *rchild;
} BiTNode, *BiTree;

void PostOrder(BiTree T) {
    if (T == NULL) return;   // 递归出口
    PostOrder(T->lchild);    // 先把左子树处理完
    PostOrder(T->rchild);    // 再把右子树处理完
    visit(T);                // 最后访问根 —— visit 在两次递归之后，这就是"后序"
}
```

**复杂度**：时间 O(n)；空间 O(h)（系统栈中恰为根到当前结点的路径），最坏 O(n)。

## 四、非递归实现难在哪

回到[中序遍历](./inorder.html)里那套统一模板——沿左链一路入栈、走到头就弹出、然后转向右子树。它对前序和中序都够用，因为**每个结点只需要被"处理"一次**：

- 前序：入栈那一刻访问
- 中序：出栈那一刻访问

后序不行。后序要求**左、右子树都处理完才能访问根**，而模板里结点被弹出时，我们看到的状态是模糊的：

```
栈顶是结点 X，当前 p == NULL，说明"刚从某处回来了"。可是——
   情形 ①：刚从 X 的左子树回来，X 的右子树还没去   → 不能访问 X，要转向右子树
   情形 ②：刚从 X 的右子树回来，两边都完了         → 可以访问 X，弹栈
```

**这两种情形在栈上长得一模一样**。模板缺的正是"X 的右子树处理过没有"这一个状态位。

补上这个状态位有两条路：

- **正面补**：记住"上一个被访问的结点"是谁。如果它正是 X 的右孩子，说明 X 的右子树刚完 → **标记法**
- **绕开它**：既然后序 = NRL 的逆序，而 NRL 是"每个结点只处理一次"的前序型遍历，那就先按 NRL 走一遍、把结果攒起来再整体倒出 → **双栈法**

## 五、解法一：标记法（`r` 指针）

用一个辅助指针 `r` 记录**最近一次被访问的结点**。栈顶结点 `p` 可以访问的条件是：p→rchild=NULL或p→rchild=r

前者表示它压根没有右子树，后者表示它的右子树刚刚访问完（后序中右子树最后访问的正是右子树的根）。c

```
void PostOrderFlag(BiTree T) {
    Stack S;
    InitStack(S);
    BiTNode *p = T, *r = NULL;      // r 指向最近访问过的结点
    while (p || !IsEmpty(S)) {
        if (p) {                    // 沿左链一路入栈（与统一模板相同）
            Push(S, p);
            p = p->lchild;
        } else {
            GetTop(S, p);           // 只取栈顶，不弹出 —— 因为还可能要转向它的右子树
            if (p->rchild && p->rchild != r) {
                p = p->rchild;      // 情形①：右子树还没处理，转过去
            } else {
                Pop(S, p);
                visit(p);           // 情形②：左右都完了，访问根
                r = p;              // 记录"刚访问的是它"
                p = NULL;           // 关键：置空，让下一轮继续走 else 分支去看新的栈顶
            }
        }
    }
}
```

### 三处细节，缺一不可

| 细节 | 为什么必须这样 | 写错会怎样 |
| --- | --- | --- |
| 用 `GetTop` 取栈顶而不是 `Pop` | 取出来后可能要转向它的右子树，转完还得回到它把它访问掉；提前弹出就再也找不回来 | 结点的右子树处理完后，该结点永远不会被访问 |
| 访问后置 `p = NULL` | 若不置空，`p` 仍指向刚访问过的结点，下一轮会走进 `if (p)` 分支，把它**重新入栈**并再次沿它的左链下潜 | 死循环 / 结点被重复访问 |
| `r` 只在**访问**后更新，不在入栈时更新 | `r` 的语义是"最近一个被访问过的结点"，只有它才能证明某棵右子树已经完成 | 提前更新会让还没处理的右子树被误判为已完成，整棵右子树被跳过 |

### 逐步执行（以上例的树为例）

| 步 | 当前 `p` | 动作 | 栈（底→顶） | `r` | 输出 |
| --- | --- | --- | --- | --- | --- |
| 1 | A | 入栈，向左 | A | NULL | — |
| 2 | B | 入栈，向左 | A B | NULL | — |
| 3 | D | 入栈，向左 | A B D | NULL | — |
| 4 | NULL | 栈顶 D，无右子树 → 弹出访问 | A B | D | **D** |
| 5 | NULL | 栈顶 B，右孩子 E ≠ `r`=D → 转向 E | A B | D | — |
| 6 | E | 入栈，向左 | A B E | D | — |
| 7 | NULL | 栈顶 E，无右子树 → 弹出访问 | A B | E | **E** |
| 8 | NULL | 栈顶 B，右孩子 E = `r` → 弹出访问 | A | B | **B** |
| 9 | NULL | 栈顶 A，右孩子 C ≠ `r`=B → 转向 C | A | B | — |
| 10 | C | 入栈，向左（左为空） | A C | B | — |
| 11 | NULL | 栈顶 C，右孩子 F ≠ `r`=B → 转向 F | A C | B | — |
| 12 | F | 入栈，向左 | A C F | B | — |
| 13 | NULL | 栈顶 F，无右子树 → 弹出访问 | A C | F | **F** |
| 14 | NULL | 栈顶 C，右孩子 F = `r` → 弹出访问 | A | C | **C** |
| 15 | NULL | 栈顶 A，右孩子 C = `r` → 弹出访问 | （空） | A | **A** |

输出：**D E B F C A** ✓

### 标记法的一个独有价值：栈里就是"根到当前结点的路径"

观察上表：每当栈顶是结点 X 时，栈中自底向上恰好是**从根到 X 的那条路径**。这带来两个常用的推论：

- **求某结点的所有祖先**：遍历到目标结点时，把栈从底到顶打印出来即可
- **求两个结点的最近公共祖先**：先遍历到第一个结点，把栈内容整条复制下来；继续遍历到第二个结点时，拿当前栈与副本从底部开始逐个比对，**最后一个相同的结点就是最近公共祖先**

**双栈法没有这个性质**——双栈法的 S1 里装的是待展开的兄弟分支，不是路径。凡是题目要"路径 / 祖先 / 最近公共祖先"，只能用标记法。

## 六、解法二：双栈法

依据是性质 2：**后序 = NRL 的逆序**。而 NRL（根 → 右 → 左）与前序（根 → 左 → 右）是同一类遍历——每个结点只处理一次，可以用最简单的"弹栈 + 压孩子"写法完成。把 NRL 的结果压进第二个栈，再全部弹出，就得到逆序。c

```
void PostOrderDoubleStack(BiTree T) {
    if (T == NULL) return;
    Stack S1, S2;
    InitStack(S1); InitStack(S2);
    Push(S1, T);
    while (!IsEmpty(S1)) {
        BiTNode *p;
        Pop(S1, p);
        Push(S2, p);                          // S1 的弹出序列就是 NRL，全部转存到 S2
        if (p->lchild) Push(S1, p->lchild);   // 左先入栈 → 后弹出
        if (p->rchild) Push(S1, p->rchild);   // 右后入栈 → 先弹出，保证"根→右→左"
    }
    while (!IsEmpty(S2)) {
        BiTNode *p;
        Pop(S2, p);
        visit(p);                             // S2 后进先出，弹出顺序即 NRL 的逆序 = 后序
    }
}
```

**入栈次序的判据**：想让**右**子树先被展开，右孩子就必须**后**入栈（栈后进先出）。这与[前序的"弹栈压右左"写法](./preorder.html)恰好相反——前序要左先出，所以左后入；这里要右先出，所以右后入。

### 逐步执行（同一棵树）

| 步 | 从 S1 弹出 | 压入 S1 | S1（底→顶） | S2（底→顶） |
| --- | --- | --- | --- | --- |
| 0 | — | A | A | — |
| 1 | A | B，C | B C | A |
| 2 | C | F（C 无左孩子） | B F | A C |
| 3 | F | — | B | A C F |
| 4 | B | D，E | D E | A C F B |
| 5 | E | — | D | A C F B E |
| 6 | D | — | （空） | A C F B E D |

S1 的弹出序列 **A C F B E D** 正是 NRL；S2 自顶向下弹出得到 **D E B F C A**，即后序 ✓

## 七、两种非递归方法对比

| 对比项 | 标记法（`r` 指针） | 双栈法 |
| --- | --- | --- |
| 思路 | 补上"右子树是否已处理"的状态位 | 绕开：做 NRL 再整体逆序 |
| 栈的数量 | 1 个 | 2 个 |
| 空间 | O(h)——栈中是当前路径 | O(n)——S2 最终装下全部 n 个结点 |
| 访问时机 | 边遍历边访问，**在线** | 必须先走完整棵树才开始访问，**离线** |
| 栈内容的语义 | **根到当前结点的路径** | 待展开的分支集合（S1）/ 逆序缓冲（S2） |
| 能否求祖先、最近公共祖先 | **能** | 不能 |
| 代码难度 | 较高（三处细节易错） | 较低 |
| 能否只访问部分结点就提前结束 | 能（边走边访问） | 不能（S2 要装满才开始输出） |

**选择判据**：题目只要"写出后序序列"，双栈法更好写；题目涉及**路径、祖先、边访问边判断、空间受限**，必须用标记法。

## 八、后序遍历的典型应用

### 1. 求二叉树的高度
c

```
int Depth(BiTree T) {
    if (T == NULL) return 0;         // 空树高度为 0
    int m = Depth(T->lchild);        // 先拿到左子树高度
    int n = Depth(T->rchild);        // 再拿到右子树高度
    return (m > n ? m : n) + 1;      // 最后才能算自己 —— 后序的访问时机
}
```

### 2. 统计结点数 / 叶子数 / 各度结点数
c

```
int NodeCount(BiTree T) {
    if (T == NULL) return 0;
    return NodeCount(T->lchild) + NodeCount(T->rchild) + 1;
}

int LeafCount(BiTree T) {
    if (T == NULL) return 0;
    if (T->lchild == NULL && T->rchild == NULL) return 1;   // 度为 0
    return LeafCount(T->lchild) + LeafCount(T->rchild);
}
```

把判定条件换成 `(lchild == NULL) != (rchild == NULL)` 就是统计度为 1 的结点，换成 `lchild && rchild` 就是度为 2 的结点。三者算完可以用 [n0=n2+1](./concepts.html) 自检。

### 3. 释放整棵二叉树
c

```
void DestroyBiTree(BiTree T) {
    if (T == NULL) return;
    DestroyBiTree(T->lchild);   // 先释放子树
    DestroyBiTree(T->rchild);
    free(T);                    // 最后释放自己
}
```

**必须是后序**：先 `free(T)` 会让 `T->lchild`、`T->rchild` 变成对已释放内存的访问，两棵子树将永远无法回收。

### 4. 后缀表达式求值

对表达式树做后序遍历得到**后缀表达式（逆波兰式）**。后缀式的最大好处是**不需要括号也无歧义**：

| 表达式 | 表达式树的后序序列 |
| --- | --- |
| a+b×c | `a b c * +` |
| (a+b)×c | `a b + c *` |

同一批符号，两种不同的树给出两个不同的后缀式；而它们的**中序序列都是 `a + b * c`**——这就是[中序输出会丢括号](./inorder.html)、而后序不会的原因。求值时用一个栈：遇操作数入栈，遇运算符弹两个操作数、算完把结果压回，最终栈里剩的就是答案。

### 5. 判断二叉树是否平衡

要判断某结点是否平衡，必须先知道它两棵子树的高度——又是自底向上，因此只能后序。相关内容见 [平衡二叉树（AVL）](./avl.html)。

## 复杂度分析

| 实现方式 | 时间复杂度 | 空间复杂度 | 空间是谁占的 |
| --- | --- | --- | --- |
| 递归 | O(n) | O(h)，最坏 O(n) | 系统栈；栈中恰为根到当前结点的路径 |
| 非递归（标记法） | O(n) | O(h)，最坏 O(n) | 一个显式栈，同样只装当前路径 |
| 非递归（双栈法） | O(n) | O(n) | S2 最终会装下全部 n 个结点，与树形无关 |

**时间为什么恒是 O(n)**：标记法里每个结点最多入栈一次、被 `GetTop` 查看两次（一次决定转右、一次决定访问）、出栈一次，都是常数次；双栈法里每个结点在两个栈上各进出一次。总工作量与结点数成正比。

**双栈法的 O(n) 空间不可优化**：它必须把整个遍历序列缓存下来才能逆序输出，这是"离线"算法的固有代价。

## 易混淆知识点

| 对比项 | 一方 | 另一方 | 判别依据 |
| --- | --- | --- | --- |
| 后序 = 谁的逆序 | **NRL（根→右→左）的逆序** | 不是前序（NLR）的逆序 | 逆序会把"左在右前"翻成"右在左前"，所以原序列必须先把左右调换 |
| 标记法 vs 双栈法的空间 | O(h) | O(n) | 栈里装的是"一条路径"还是"整个序列" |
| 标记法 vs 双栈法能否求祖先 | 能，栈即路径 | 不能，栈是分支集合 | 看栈内容的语义 |
| `GetTop` vs `Pop` | 后序必须先 `GetTop`（还可能要转右） | 中序可以直接 `Pop` | 结点是否还需要被第二次处理 |
| 访问后 `p = NULL` | 必须置空 | 不置空会重复入栈、死循环 | 置空是为了让下一轮走 `else` 分支继续弹栈 |
| `r` 的更新时机 | 只在**访问后**更新 | 入栈时更新会误判右子树已完成 | `r` 的语义是"最近被访问的结点" |
| 前序/中序 vs 后序的非递归 | 结点弹出一次即可定夺 | 后序弹出时状态模糊，需额外状态位 | 访问是否依赖"右子树是否已完成" |
| 该用前序还是后序 | 信息自顶向下传（层号、路径、复制、建树） | 信息自底向上汇（高度、结点数、释放、后缀式） | 算根时需不需要子树的结果 |
| 中缀式 vs 后缀式 | 中序输出丢括号，有歧义 | 后序输出无歧义，不需括号 | 前者靠优先级，后者靠位置 |
| 双栈法的入栈次序 | 先压左、后压右（要右先弹） | [前序](./preorder.html)写法是先压右、后压左（要左先弹） | 想让谁先出栈，就让谁后入栈 |

- **手工写出任意二叉树的后序序列**，并用"后序 = NRL 逆序"交叉验证
- **证明"后序 = 根→右→左序列的逆序"**，并说清它为什么**不是**前序的逆序
- **准确说出后序非递归的困难所在**：统一模板缺一个"右子树是否已处理"的状态位
- **默写标记法**，并解释三处细节：为什么用 `GetTop` 不用 `Pop`、为什么访问后要 `p = NULL`、为什么 `r` 只在访问后更新
- **默写双栈法**，说清入栈次序（先左后右）与前序写法相反的理由
- **在两种解法间做选择**：涉及路径 / 祖先 / 最近公共祖先 / 空间受限，只能用标记法
- **判断一个任务该用后序**：求高度、结点数、判平衡、释放内存、后缀表达式——凡是"算根要先有子树结果"的都是

**两条最关键的结论**：后序序列的**最后一个元素必是根**（与前序第一个元素对称，是构造二叉树的入手点）；**标记法的栈内容恰好是根到当前结点的路径**，这是它相对双栈法不可替代的价值。
