## 存储结构

### 核心约定与它的两个后果

顺序表用**一组地址连续的存储单元**依次存放线性表的元素，约定只有一条：

**第 i 个元素存放在第 i 个物理位置上。**

这条约定不占任何额外空间就表达了"ai 的直接后继是 ai+1"，但它是有代价的， 后面全部性质都是它的推论：

-

**推论一（好处）**：既然位置由位序唯一确定，元素地址就能**算**出来，不必**找**。 设第一个元素的存储地址为 LOC(a1)，每个元素占 d 个存储单元，则LOC(ai)=LOC(a1)+(i−1)×d

求这个式子只要一次乘法一次加法，与 i 的大小无关，所以按位查找是 O(1)—— 这就是**随机存取**。
-

**推论二（代价）**：插入或删除会让某些元素的位序发生变化，而位序变了物理位置就必须 跟着变，**只能靠搬运元素来恢复约定**。这就是插入删除 O(n) 的根源。

图源：殷人昆《数据结构——用面向对象方法与 C++ 描述》（第 2 版）图 2.2 顺序表的存储结构，p46。 图中用 `last` 记录最后一个元素的**下标**，因此空表是 `last = -1`；下文代码改用 `length` 记录**元素个数**，空表是 `length = 0`。两套写法等价，`last = length - 1`， 但**同一份代码里必须只用一套**，混用是顺序表代码出错最集中的地方。

### 静态分配
c

```
#define MaxSize 50            // 表的容量上限，编译期确定

typedef struct {
    ElemType data[MaxSize];   // 定长数组，直接嵌在结构体里
    int length;               // 当前表长（元素个数），不是容量
} SqList;
```

数组空间随结构体一起分配（栈上或全局区），大小在编译时就固定了。表满即无法再插入。

### 动态分配
c

```
#define InitSize 10

typedef struct {
    ElemType *data;   // 只存基地址，真正的空间用 malloc 在堆上申请
    int MaxSize;      // 当前容量，可变
    int length;       // 当前表长
} SeqList;

void InitList(SeqList &L) {
    L.data = (ElemType *)malloc(sizeof(ElemType) * InitSize);
    L.MaxSize = InitSize;
    L.length = 0;
}
```

⚠️ **动态分配 ≠ 链式存储。** 这是概念上最容易滑过去的一处：动态分配只是把"什么时候 申请这块连续空间"从编译期推迟到了运行期，申请到手的**仍然是一整块地址连续的空间**， 第 i 个元素仍然在第 i 个物理位置上，地址公式照样成立，随机存取照样是 O(1)。 真正区分顺序存储与链式存储的是"逻辑相邻是否等于物理相邻"，不是"空间什么时候申请"。

### 扩容与它的均摊代价

容量用满后要扩容，做法是**另申请一块更大的空间，把老数据整体复制过去，再释放老空间**：c

```
void IncreaseSize(SeqList &L, int len) {
    ElemType *p = L.data;
    L.data = (ElemType *)malloc(sizeof(ElemType) * (L.MaxSize + len));
    for (int i = 0; i < L.length; i++)
        L.data[i] = p[i];        // 逐个搬到新空间，这一步是 O(n)
    L.MaxSize += len;
    free(p);                      // 释放老空间，否则内存泄漏
}
```

**单次扩容的代价是 O(n)**（要复制全部 n 个元素），但扩容不是每次插入都发生。 按**倍增**策略（容量满则翻倍）连续插入 n 个元素，发生复制的时刻是容量为 1,2,4,8,… 的那几次，总复制次数为1+2+4+⋯+2⌊log2⁡n⌋<2n

平摊到 n 次插入上，每次插入分担的扩容开销小于 2 次元素复制，即**均摊 O(1)**。

⚠️ 如果扩容策略是"每次固定加 c 个位置"而非倍增，则扩容发生 n/c 次、每次复制 O(n)， 总代价 O(n2/c)，均摊退化为 O(n)。**"扩容均摊 O(1)"这个结论依赖倍增策略， 不是无条件成立的。**

## 基本操作的实现

### 按位查找

直接算地址，一步到位：c

```
bool GetElem(SqList L, int i, ElemType &e) {
    if (i < 1 || i > L.length) return false;  // 位序从 1 起算
    e = L.data[i - 1];                        // 位序 i ↔ 下标 i-1
    return true;
}
```

**位序与下标错位 1** 是顺序表代码的头号笔误来源。记法：位序是"第几个"（从 1 数）， 下标是"偏移量"（从 0 数），第 1 个元素的偏移量是 0。

### 按值查找

从头逐个比较，返回**位序**（不是下标）：c

```
int LocateElem(SqList L, ElemType e) {
    for (int i = 0; i < L.length; i++)
        if (L.data[i] == e)
            return i + 1;   // 找到，返回位序
    return 0;               // 未找到，位序 0 是非法值，可作失败标志
}
```

**平均比较次数的推导**：设查找第 i 个元素需要比较 Ci=i 次， 在等概率假设 pi=1/n 下，平均查找长度为ASL=∑i=1npiCi=1n∑i=1ni=1n⋅n(n+1)2=n+12

所以按值查找的平均时间复杂度是 O(n)。

⚠️ **顺序表的按值查找是 O(n)，即使表是有序的也仍然是 O(n)**——上面的算法根本没利用 有序性。有序顺序表要降到 O(log2⁡n) 必须换算法，即[折半查找](./../search/binary-search.html)。 "顺序表上的顺序查找"和"有序顺序表上的折半查找"是两回事。

### 插入操作

在第 i 个位置**之前**插入元素 e，需要把第 i 个到第 n 个元素**依次后移一位** （注意必须**从后往前**移，从前往后会把还没搬的元素覆盖掉）：c

```
bool ListInsert(SqList &L, int i, ElemType e) {
    if (i < 1 || i > L.length + 1) return false;  // 插入合法范围比删除多一个 n+1
    if (L.length >= MaxSize) return false;        // 表满，静态分配下无法插入
    for (int j = L.length; j >= i; j--)           // 必须从后往前，否则前面的值被覆盖
        L.data[j] = L.data[j - 1];                // 把下标 j-1 的元素挪到下标 j
    L.data[i - 1] = e;
    L.length++;
    return true;
}
```

**边界自查**：

- i=n+1（插在表尾之后）：循环 `j` 从 n 递减到 n+1，一次都不执行，直接写 `data[n] = e`，**移动 0 个元素**，正确；
- i=1（插在表头）：循环执行 n 次，全部元素后移，**移动 n 个元素**，代价最大；
- 空表插入 i=1：`length = 0`，循环不执行，`data[0] = e`，`length` 变 1，正确。

### 删除操作

删除第 i 个元素，需要把第 i+1 个到第 n 个元素**依次前移一位** （这次必须**从前往后**移）：c

```
bool ListDelete(SqList &L, int i, ElemType &e) {
    if (i < 1 || i > L.length) return false;   // 删除合法范围没有 n+1
    e = L.data[i - 1];                          // 先取出被删元素的值
    for (int j = i; j < L.length; j++)          // 从前往后，把后面的往前挪
        L.data[j - 1] = L.data[j];
    L.length--;
    return true;
}
```

**边界自查**：

- i=n（删表尾）：循环 `j` 从 n 到 n−1，不执行，**移动 0 个元素**；
- i=1（删表头）：循环执行 n−1 次，**移动 n−1 个元素**，代价最大；
- 空表删除：`length = 0`，i≥1>0 触发合法性判断，返回 `false`，正确。

**两个循环方向相反，不是巧合。** 判据是"**先动的那一格，必须是马上要被覆盖掉的那一格**"。 插入时空位在后面，所以从后往前搬；删除时空位在前面，所以从前往后搬。 方向写反的后果是同一个值被复制满整段区间。

## 平均移动次数的推导

这是顺序表这一节唯一需要动笔推的地方，两个式子的结论不同，差别恰好来自**插入位置有 n+1 种、删除位置只有 n 种**。

### 插入

在长度为 n 的表中，插入位置 i 的合法取值是 1,2,…,n+1，共 n+1 种。 在第 i 个位置插入需要移动第 i 至第 n 个元素，共 n−i+1 个。

设 pi 为在第 i 个位置插入的概率，则平均移动次数Eins=∑i=1n+1pi(n−i+1)

在**等概率假设**下 pi=1n+1，代入得Eins=1n+1∑i=1n+1(n−i+1)=1n+1(n+(n−1)+⋯+1+0)=1n+1⋅n(n+1)2=n2

### 删除

删除位置 i 的合法取值是 1,2,…,n，共 n 种。删除第 i 个元素需要移动 第 i+1 至第 n 个元素，共 n−i 个。等概率下 pi=1n：Edel=∑i=1npi(n−i)=1n((n−1)+(n−2)+⋯+1+0)=1n⋅n(n−1)2=n−12

### 两个式子的对读

|  | 插入 | 删除 |
| --- | --- | --- |
| 合法位置数 | n+1 | n |
| 在位置 i 的移动次数 | n−i+1 | n−i |
| 移动次数的取值集合 | {0,1,…,n} | {0,1,…,n−1} |
| 最大移动次数（发生在 i=1） | n | n−1 |
| 平均移动次数 | n2 | n−12 |

**两个式子都在算同一个东西：一个从 0 到某上界的等差数列的平均值。** 插入的上界是 n，平均 n/2；删除的上界是 n−1，平均 (n−1)/2。 记住这个结构比记两个式子可靠——换成"平均移动多少次"以外的问法（例如"移动次数的期望 是多少"或"最坏移动多少次"）也能立刻答上来。

⚠️ **等概率是一个显式前提，不是恒成立的事实。** 若题目改成"只在表尾插入"， 平均移动次数就是 0；若改成"只在表头插入"，就是 n。看到"平均"二字先找等概率假设， 没有这个假设 n/2 不成立。

### 例题：手算一次插入与删除

设顺序表 L 的当前内容为 (12, 25, 8, 33, 47)，length=5，容量足够。

**（1）在第 3 个位置插入 19。**

需移动第 3 至第 5 个元素，共 n−i+1=5−3+1=3 个。按代码从后往前执行：

| 步骤 | 语句 | 数组内容（下标 0…5） |
| --- | --- | --- |
| 初始 | — | `12 25 8 33 47 _` |
| j=5 | `data[5]=data[4]` | `12 25 8 33 47 47` |
| j=4 | `data[4]=data[3]` | `12 25 8 33 33 47` |
| j=3 | `data[3]=data[2]` | `12 25 8 8 33 47` |
| — | `data[2]=19` | `12 25 19 8 33 47` |
| — | `length=6` | 表为 (12,25,19,8,33,47) |

**（2）接着删除第 5 个元素（值为 33）。**

此时 n=6，需移动第 6 个元素，共 n−i=6−5=1 个：

| 步骤 | 语句 | 数组内容 |
| --- | --- | --- |
| 初始 | `e = data[4] = 33` | `12 25 19 8 33 47` |
| j=5 | `data[4]=data[5]` | `12 25 19 8 47 47` |
| — | `length=5` | 表为 (12,25,19,8,47) |

下标 5 处残留的 47 **不需要清除**——`length` 已经减到 5，下标 5 落在表外， 任何合法操作都不会读到它。这一点是顺序表"删除即改 length"的直接体现。

**（3）验证平均值。** 对 n=5 的表，插入的移动次数按位置依次为 5,4,3,2,1,0，平均 156=2.5=n2 ✓； 删除的移动次数依次为 4,3,2,1,0，平均 105=2=n−12 ✓。

## 复杂度分析

| 操作 | 时间复杂度 | 来历 |
| --- | --- | --- |
| 按位查找 | O(1) | 一次乘加算出地址，与 i 无关 |
| 按值查找 | O(n) | 平均比较 n+12 次；最坏 n 次 |
| 插入 | O(n) | 平均移动 n2 个；最坏（i=1）移动 n 个；最好（i=n+1）0 个 |
| 删除 | O(n) | 平均移动 n−12 个；最坏（i=1）移动 n−1 个；最好（i=n）0 个 |
| 动态扩容（单次） | O(n) | 复制全部元素到新空间 |
| 动态扩容（均摊，倍增策略） | O(1) | 连续 n 次插入总复制 <2n 次 |

**空间复杂度**：插入、删除、查找都只用到常数个辅助变量（循环变量 j、暂存值 e）， 所以是 O(1)。注意这里说的是**辅助空间**，不含存放表本身的那 n 个单元—— 表本身的空间是问题输入的一部分，不计入算法的空间复杂度。

## 易混淆知识点

| 易混对 | 判别依据 | 结论 |
| --- | --- | --- |
| 插入合法范围 1≤i≤n+1 vs 删除 1≤i≤n | 插入允许"插在最后一个之后"，删除没有"删第 n+1 个"这回事 | 插入多一个合法位置，这正是两个平均值不同的根源 |
| 平均移动 n/2 vs (n−1)/2 | 看移动次数的取值上界：插入是 n，删除是 n−1 | 插入 n2，删除 n−12 |
| 位序 i vs 数组下标 | 位序从 1 数，下标从 0 数 | 第 i 个元素在 `data[i-1]` |
| `length` vs `MaxSize` | 前者是当前元素个数，后者是容量上限 | 判空用 `length==0`，判满用 `length==MaxSize` |
| 动态分配 vs 链式存储 | 问"逻辑相邻是否等于物理相邻" | 动态分配的顺序表仍是顺序存储，仍支持随机存取 |
| 单次扩容 O(n) vs 均摊 O(1) | 问"这一次插入"还是"连续 n 次插入平均" | 两个数都对，回答前先看清问的是哪一个；且均摊 O(1) 依赖倍增策略 |
| 顺序**存储** vs 随机**存取** | 前者指数据怎么放，后者指访问代价与位置无关 | 顺序表是顺序存储且支持随机存取，两者不矛盾 |
| 存储密度 =1 vs 空间利用率 | 存储密度不计空闲区，空间利用率要计 | 顺序表存储密度恒为 1，但若预分配了大量空闲区，实际利用率可以很低 |

## 本节小结

学完本节，你应该能够：

- 写出**地址计算公式** LOC(ai)=LOC(a1)+(i−1)d，并用它解释顺序表为什么 支持随机存取；
- 分别写出**静态分配**与**动态分配**的结构体定义，说明二者的差别只在"何时申请空间"， 以及为什么动态分配的顺序表**不是**链式存储；
- 写出插入、删除的完整代码，说清**两个循环方向为什么相反**，并给出 i=1、i=n、 i=n+1、空表这四种边界下的行为；
- **独立推出**等概率假设下插入平均移动 n2、删除平均移动 n−12， 并指出差异来自插入的合法位置比删除多一个；
- 推出按值查找的平均查找长度 n+12，并说明为什么有序也救不了它；
- 分析动态扩容的开销：**单次 O(n)、倍增策略下均摊 O(1)**，并说明固定增量策略下 这个结论不成立。

三条最关键的结论：

- 顺序表的一切性质都来自一条约定——**第 i 个元素放在第 i 个物理位置**。 随机存取是它的红利，插删要移动元素是它的账单。
- **n2 与 n−12 的差别有确定来历**：插入的移动次数取遍 0∼n，删除取遍 0∼n−1。
- 顺序表的**存储密度为 1**，这是它相对链表唯一的空间优势；一旦按上限预分配造成大量 空闲区，这个优势就被抵消。

- [快速排序](./../sorting/quick-sort.html)、[堆排序](./../sorting/heap-sort.html)：这两个算法都要求随机存取， 因此只能在顺序存储上实现
