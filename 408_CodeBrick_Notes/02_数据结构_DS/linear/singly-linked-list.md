## 存储结构

### 结点与指针域

链式存储用**一组任意的存储单元**存放线性表的元素——这组单元可以连续，也可以不连续。 既然位置不再承载信息，元素之间的先后关系就必须**显式地存下来**：每个元素除了自身的值， 还要存一个"指示其直接后继在哪里"的信息。这两部分合起来称为一个**结点**（node）：c

```
typedef struct LNode {
    ElemType data;       // 数据域：存元素本身
    struct LNode *next;  // 指针域：存直接后继结点的地址
} LNode, *LinkList;
```

关于这个定义有三点必须说清：

- `LNode *` 和 `LinkList` 是**同一个类型的两个名字**，本质完全等价。约定俗成的用法是： 用 `LinkList L` 强调 L 是**某条链表的头指针**（代表整张表）， 用 `LNode *p` 强调 p 是**指向某个结点的指针**（代表一个结点）。这只是可读性约定， 编译器不区分。
- **指针域存的是"直接后继"，不是"某个后继"。** 若 `p->data` 是 ai， 则 `p->next->data` 一定是 ai+1。整条链的关系全部由这一层层的"直接后继"串起来。
- 单链表由头指针唯一确定，因此可以用头指针的名字来称呼整张表——头指针名是 `L`， 就把这张表简称为"表 `L`"。

```
头指针 → [data|next] → [data|next] → [data|next] → NULL
           结点1          结点2          结点3
```

**尾结点的指针域置 `NULL`，这是"到头了"的唯一标志。** 单链表没有别的办法知道自己 走到了尽头——它不像顺序表那样有一个 `length` 字段可查。

### 头指针、头结点、首元结点

这三个词长得像，指的却是三样东西，必须一次分清：

图源：殷人昆《数据结构——用面向对象方法与 C++ 描述》（第 2 版）图 2.9 带附加头结点的单链表结构，p59。 图中把头指针命名为 `first`，本文的代码里命名为 `L`，含义相同。

| 名称 | 是什么 | 存不存数据 |
| --- | --- | --- |
| **首元结点** | 存放第一个数据元素 a1 的那个结点 | 存，它是真正的数据结点 |
| **头结点** | 在首元结点**之前**附设的一个结点，其指针域指向首元结点 | 数据域**不存有效数据**（也可存表长等附加信息） |
| **头指针** | 指向链表中第一个结点的**指针变量**，它标识整张表 | 它不是结点，是一个指针 |

三者的关系随"带不带头结点"而变：

- **带头结点**：头指针 → 头结点 → 首元结点 → …
- **不带头结点**：头指针 → 首元结点 → …

⚠️ **头指针在任何情况下都必须有**——没有它就找不到这张表了。头结点则是可选的。 "这张表没有头结点"是合法说法，"这张表没有头指针"不是。

### 带头结点：它到底省掉了什么

408 的算法题面若不特别说明，**默认使用带头结点的单链表**。头结点不存数据、只占一个结点 的空间，换来的是**两类特殊情况的消失**。逐条看清它省掉了什么，比记住"要带头结点"有用得多。

**省掉的第一类特殊情况：空表与非空表的判别不统一。**

|  | 不带头结点 | 带头结点 |
| --- | --- | --- |
| 空表的表示 | `L == NULL`（头指针本身为空） | `L->next == NULL`（头结点还在） |
| 非空表 | `L` 指向首元结点 | `L` 指向头结点 |
| 头指针 `L` 会不会变 | **会**——空表变非空、删掉唯一元素，都要改 `L` | **不会**——`L` 永远指向那个头结点 |

头指针会不会变，直接决定函数签名：不带头结点时，插入删除必须能改写调用者的 `L`， 所以参数得写成 `LinkList &L`（或 `LinkList *L`）；带头结点时传值即可。

**省掉的第二类特殊情况：第 1 个位置的操作与其他位置不统一。**

在第 i 个位置插入的通用做法是"找到第 i−1 个结点，在它后面插"。 不带头结点时，i=1 没有第 0 个结点可找，只能单独写一段代码：c

```
// 不带头结点：在第 i 个位置插入元素 e —— 注意 i == 1 必须单独处理
bool ListInsertNoHead(LinkList &L, int i, ElemType e) {
    if (i < 1) return false;
    LNode *s = (LNode *)malloc(sizeof(LNode));
    if (s == NULL) return false;
    s->data = e;
    if (i == 1) {              // ← 特殊情况：要动的是头指针 L 本身，而不是某个结点的 next
        s->next = L;
        L = s;
        return true;
    }
    LNode *p = L;              // 不带头结点时，L 就是第 1 个结点
    int j = 1;                 // 所以计数器从 1 起算，而不是从 0
    while (p != NULL && j < i - 1) {
        p = p->next;
        j++;
    }
    if (p == NULL) { free(s); return false; }
    s->next = p->next;
    p->next = s;
    return true;
}
```

带头结点后，头结点可以看作"第 0 个结点"，i=1 时前驱就是它，**特判整段消失**：c

```
// 带头结点：在第 i 个位置插入元素 e —— 没有任何位置需要特判
bool ListInsert(LinkList &L, int i, ElemType e) {
    if (i < 1) return false;
    LNode *p = L;                      // p 指向头结点，视作"第 0 个结点"
    int j = 0;                          // 计数器从 0 起算
    while (p != NULL && j < i - 1) {    // 找第 i-1 个结点
        p = p->next;
        j++;
    }
    if (p == NULL) return false;        // 走到表外，说明 i 超过 length+1，非法
    LNode *s = (LNode *)malloc(sizeof(LNode));
    if (s == NULL) return false;
    s->data = e;
    s->next = p->next;                  // ① 新结点接住 p 原来的后继
    p->next = s;                        // ② p 改指向新结点
    return true;
}
```

**边界自查（带头结点版，设表长为 n）**：

- i=1：循环条件 `j < 0` 不成立，`p` 停在头结点，在头结点后插入，即插到表头，正确；
- i=n+1：循环走 n 步，`p` 停在第 n 个结点（尾结点），在其后插入，正确；
- i=n+2：循环走到 j=n 时 `p` 已是尾结点，再走一步 `p` 变 `NULL`，循环因 `p == NULL` 退出，返回 `false`，正确；
- 空表插 i=1：`p = L`（头结点），循环不执行，直接插在头结点后，正确。

**结论**：头结点的作用不是"让链表更规范"，而是**把两类边界情况变成普通情况**， 从而让插入、删除的代码里一个 `if` 都不必多写。判断某段代码写得对不对， 先看它是按哪种口径写的——**带头结点的代码里 `p` 从 `L` 起、计数器从 0 起； 不带头结点的代码里 `p` 从 `L` 起、计数器从 1 起**。这两套绝不能混。

## 建表：头插法与尾插法

### 头插法建表

每次把新结点插到**头结点之后**，于是最后读入的元素反而排在最前面，建表结果与输入顺序 **相反**，所以头插法也叫**逆序建表**。c

```
LinkList HeadInsert(LinkList &L) {
    LNode *s;
    int x;
    L = (LinkList)malloc(sizeof(LNode));   // 建头结点
    L->next = NULL;                        // 先造成一个空表，这一步不能省
    while (scanf("%d", &x) == 1) {         // 读到合法整数就继续
        s = (LNode *)malloc(sizeof(LNode));
        s->data = x;
        s->next = L->next;                 // 新结点接住原来的第一个结点
        L->next = s;                       // 头结点改指向新结点
    }
    return L;
}
```

⚠️ `L->next = NULL` 这一句看起来是"初始化"，实际上它同时决定了**第一个被插入的结点将 成为尾结点**——它的 `next` 从这里拿到 `NULL`。省掉这句，尾结点的指针域就是野值， 遍历会一路走到内存里去。

### 尾插法建表

每次把新结点接在链尾，建表结果与输入顺序**一致**。代价是必须额外维护一个**尾指针 `r`**， 始终指向当前的最后一个结点——否则每插一个元素都要从头找一遍表尾，建表就退化成 O(n2)。c

```
LinkList TailInsert(LinkList &L) {
    LNode *s, *r;
    int x;
    L = (LinkList)malloc(sizeof(LNode));   // 建头结点
    r = L;                                 // 尾指针初始指向头结点（空表时头结点就是"尾"）
    while (scanf("%d", &x) == 1) {
        s = (LNode *)malloc(sizeof(LNode));
        s->data = x;
        r->next = s;
        r = s;                             // 尾指针跟着后移
    }
    r->next = NULL;                        // 循环结束后统一封尾，比在循环里每次赋值省事
    return L;
}
```

**两种建表法的对读**：时间复杂度都是 O(n)（每个结点插入 O(1)，共 n 个）。 头插法不需要尾指针、代码更短，代价是结果逆序；尾插法保序，代价是多一个指针。 **头插法"自带逆序"这一性质本身是有用的**——链表逆置正是靠它实现的，见下文。

## 查找

### 按位查找

链表**不能算地址，只能一步一步走**，这是链式存储与顺序存储最本质的性能差别：c

```
// 返回第 i 个结点的指针；i = 0 时返回头结点
LNode *GetElem(LinkList L, int i) {
    if (i < 0) return NULL;
    LNode *p = L;
    int j = 0;
    while (p != NULL && j < i) {
        p = p->next;
        j++;
    }
    return p;          // i 超出表长时 p 为 NULL，调用方据此判失败
}
```

时间代价的来历：找第 i 个结点要走 i 步。等概率假设下平均走 1n∑i=1ni=n+12 步，最坏走 n 步，故为 O(n)。

### 按值查找
c

```
LNode *LocateElem(LinkList L, ElemType e) {
    LNode *p = L->next;                    // 从首元结点开始，头结点不存数据
    while (p != NULL && p->data != e)
        p = p->next;
    return p;                              // 找到返回结点指针，未找到 p 为 NULL
}
```

平均比较次数同为 n+12，时间复杂度 O(n)。

⚠️ **注意 `p = L->next` 而不是 `p = L`。** 带头结点时头结点的数据域没有意义， 从 `L` 开始比较会把头结点里的垃圾值也拿来比。这是"带头结点"口径下最常见的一处笔误。

## 插入与删除的通用范式

链表的插入删除只有一个动作——**改指针**。难点从来不在"改哪几个"，而在"按什么顺序改"。 下面这条范式对所有链式结构都成立，记住它就不必逐个操作去背。

**通用范式：任何一次指针修改前，先问"这个指针域里现在存着的地址，之后还有没有人需要？" 有，就必须先把它转存到别处（或者先让新结点接住它），再覆盖。**

### 后插操作（在结点 p 之后插入 s）
c

```
bool InsertNextNode(LNode *p, LNode *s) {
    if (p == NULL || s == NULL) return false;
    s->next = p->next;    // ① 先让 s 接住 p 的原后继
    p->next = s;          // ② 再让 p 指向 s
    return true;
}
```

**顺序为什么不能颠倒**：`p->next` 里存着原来的第 i 个结点的地址，而这个地址**只此一份** ——整条链上没有第二个地方存着它。若先执行 `p->next = s`，这个地址就被覆盖了， 原来 p 之后的整个后半段**永久丢失**（既找不回来也 `free` 不掉，构成内存泄漏）。 先执行 `s->next = p->next`，等于让 `s` 先把这份地址抄了一份，覆盖才安全。

⚠️ 顺序错误的后果不是"少接了一个结点"，而是**丢掉整个后半段**。举个具体的： 表为 a1→a2→a3，在 a1 后插 s，若先写 `p->next = s`， 则 `s->next` 拿到的已经是 `s` 自己的地址（或野值），a2,a3 从此不可达。

### 前插操作（在结点 p 之前插入 s）

按定义，前插需要 p 的**前驱**，而单链表只能向后走，找前驱要从头遍历，代价 O(n)。 但有一个把它降到 O(1) 的做法：c

```
// 在 p 之前插入 s：先后插，再交换两个结点的数据域
bool InsertPriorNode(LNode *p, LNode *s) {
    if (p == NULL || s == NULL) return false;
    s->next = p->next;            // ① 先把 s 后插到 p 之后
    p->next = s;
    ElemType tmp = p->data;       // ② 再交换 p 与 s 的数据域
    p->data = s->data;
    s->data = tmp;
    return true;
}
```

**为什么这样是对的**：交换数据域之后，p 这个**存储单元**里装的是新元素的值、 s 这个存储单元里装的是原来的值，而 p 在链上的位置在 s 之前—— 于是"新元素排在原元素之前"这个**逻辑要求**被满足了。 **链表的逻辑次序由指针决定、由数据域承载内容，两者可以分开操作**，这就是这个技巧的原理。

⚠️ 它的代价是：**指向原结点的外部指针会失效**。若调用方在别处保存了 `p` 并期望它一直代表 原来那个元素，交换之后 `p` 代表的就变成新元素了。题目要求"不得改变结点的相对地址"时 不能用这一招。

### 删除操作（删除第 i 个结点）
c

```
// 删除第 i 个结点，用 e 返回其值（带头结点）
bool ListDelete(LinkList &L, int i, ElemType &e) {
    if (i < 1) return false;
    LNode *p = L;
    int j = 0;
    while (p != NULL && j < i - 1) {   // 先找第 i-1 个结点（被删结点的前驱）
        p = p->next;
        j++;
    }
    if (p == NULL || p->next == NULL) return false;  // 前驱不存在，或前驱之后已无结点
    LNode *q = p->next;                // ① q 记住被删结点，这一步不能省
    e = q->data;
    p->next = q->next;                 // ② 前驱越过被删结点
    free(q);                           // ③ 最后才释放
    return true;
}
```

三个位置各有讲究：

- **`q` 必须先取**。若直接写 `p->next = p->next->next`，链是接对了，但被删结点的地址 再也拿不到，无法 `free`，构成内存泄漏。
- **`p->next == NULL` 这个判断不能少**。它拦住的是"i 恰好等于 n+1"——此时前驱找得到 （就是尾结点），但它后面没有结点可删。少了这句会解引用 `NULL`。
- **`free(q)` 必须在 `p->next = q->next` 之后**。反过来先 `free(q)` 再读 `q->next`， 读的是已释放内存，行为未定义。

**边界自查**：空表删 i=1 → `p = L`，循环不执行，`p->next == NULL` 成立，返回 `false` ✓； 删尾结点 i=n → 前驱是第 n−1 个结点，`p->next` 即尾结点，删除后前驱的 `next` 拿到 `NULL`，正确 ✓。

### 删除指定结点自身

给定 `p` 要删掉它本身，按定义需要前驱，O(n)。同样有一个 O(1) 的替代做法：c

```
// 删除结点 p 本身（p 不能是尾结点）
bool DeleteNode(LNode *p) {
    if (p == NULL || p->next == NULL) return false;   // 尾结点用此法删不掉
    LNode *q = p->next;
    p->data = q->data;      // 把后继的值搬到 p 里
    p->next = q->next;      // 再把后继从链上摘掉
    free(q);
    return true;
}
```

原理与前插的技巧同源：**删掉"p 这个存储单元"和删掉"p 里装的那个元素"是两件事**， 把后继的值搬过来、再摘掉后继，效果等价于删掉了 p 里原来的元素。

⚠️ **尾结点是这一招唯一的死角**：尾结点没有后继可以搬，只能老老实实找前驱，O(n)。 这也正是[双链表](./doubly-linked-list.html)相对单链表的价值所在——双链表里删除任意结点 （含尾结点）都是真正的 O(1)。

## 逆置

把单链表所有结点的次序反转。两种解法各有出处，都要求 O(1) 辅助空间。

### 方法一：头插法逆置

**原理**：头插法建表的结果天然是输入的逆序。把原链表从头到尾摘下每个结点、 依次头插回去，得到的就是逆序表。c

```
void ReverseList(LinkList &L) {
    LNode *p = L->next;    // p 指向第一个数据结点
    LNode *r;              // r 用于暂存 p 的后继
    L->next = NULL;        // ① 头结点断开，此刻起把 L 当作一张空表来头插
    while (p != NULL) {
        r = p->next;       // ② 先存后继，否则下一句就把它覆盖了
        p->next = L->next; // ③ 头插：p 接住当前的第一个结点
        L->next = p;       // ④ 头结点改指向 p
        p = r;             // ⑤ 处理下一个
    }
}
```

**空表与单元素的边界**：空表时 `p = NULL`，循环一次不执行，`L->next` 保持 `NULL`，正确； 单元素时循环执行一次，`r = NULL`，`p->next = NULL`，`L->next = p`，链仍是它自己，正确。

### 方法二：指针就地反转

**原理**：用三个指针 `pre`、`p`、`r` 同时前进，把每个结点的 `next` 从"指向后继" 改成"指向前驱"。c

```
void ReverseList2(LinkList &L) {
    LNode *pre, *p = L->next, *r;
    if (p == NULL) return;      // 空表直接返回
    pre = NULL;                 // 原来的首元结点将成为新的尾结点，其 next 应为 NULL
    while (p != NULL) {
        r = p->next;            // ① 先存后继——下一句就要把它毁掉
        p->next = pre;          // ② 反转指针
        pre = p;                // ③ pre、p 一起后移
        p = r;
    }
    L->next = pre;              // ④ 循环结束时 pre 指向原来的尾结点，让它当新的首元结点
}
```

**循环不变量**（这是理解本算法的关键）：每轮循环开始时，`pre` 指向**已反转部分的头**， `p` 指向**未反转部分的头**，两部分已经断开。循环结束时未反转部分为空，`pre` 正好指向 整条反转链的头。

### 两法对读

|  | 头插法逆置 | 指针就地反转 |
| --- | --- | --- |
| 依赖头结点 | **依赖**，靠 `L->next` 当插入点 | 不依赖，最后一步才用到 `L` |
| 指针变量数 | 2 个（`p`、`r`） | 3 个（`pre`、`p`、`r`） |
| 时间 / 空间 | O(n) / O(1) | O(n) / O(1) |
| 容易写错的地方 | 忘了先 `L->next = NULL` | 忘了最后 `L->next = pre` |

两者本质相同：**都是"先暂存后继，再改指针"这条通用范式的应用**， 区别只在把结点接到哪儿。**共同的死穴是那句 `r = p->next`**——两段代码里它都必须是 循环体的第一句，因为紧接着的那一句就会把 `p->next` 覆盖掉。

## 复杂度分析

| 操作 | 时间复杂度 | 来历 |
| --- | --- | --- |
| 头插法建表 | O(n) | 每个结点插入 O(1)，共 n 个 |
| 尾插法建表 | O(n) | 同上；**前提是维护了尾指针**，否则每次找尾退化为 O(n2) |
| 按位查找第 i 个 | O(n) | 走 i 步；等概率下平均 n+12 步，最坏 n 步 |
| 按值查找 | O(n) | 平均比较 n+12 次，最坏 n 次 |
| 后插（**已知** `p`） | O(1) | 只改 2 个指针，与 n 无关 |
| 前插（**已知** `p`，用交换数据域法） | O(1) | 后插 + 交换数据域，均为常数步 |
| 前插（**已知** `p`，需保持结点地址不变） | O(n) | 必须从头遍历找前驱 |
| 按位序插入第 i 个 | O(n) | 定位前驱 O(n) + 改指针 O(1) |
| 删除结点 `p` 自身（`p` 非尾结点） | O(1) | 搬数据 + 摘后继 |
| 删除结点 `p` 自身（`p` 是尾结点） | O(n) | 无后继可搬，只能找前驱 |
| 按位序删除第 i 个 | O(n) | 定位前驱 O(n) + 改指针 O(1) |
| 逆置 | O(n) | 每个结点被处理常数次，恰好遍历一遍 |
| 求表长 | O(n) | 必须走完全表数数——链表不存 `length` 字段 |

**空间复杂度**：上述所有操作都只使用常数个指针变量作为辅助，均为 O(1)。 **逆置也是 O(1)**——它是"就地"修改指针，没有开辅助数组。

⚠️ **"链表插入删除 O(1)"这句话必须带前提。** 完整表述是： **在已知操作位置（前驱指针）的前提下**，改指针本身是 O(1)； 若给的是位序 i，则总代价是 O(n)，因为定位那一步跑不掉。 判断一道题该答哪个，看题面给的是**指针**还是**位序**。

## 与顺序表的定量对比

### 时间

| 操作 | 顺序表 | 单链表 | 谁赢 |
| --- | --- | --- | --- |
| 按位查找第 i 个 | O(1)（算地址） | O(n)（走 i 步） | **顺序表**，且是数量级差距 |
| 按值查找（无序） | O(n)，平均比较 n+12 次 | O(n)，平均比较 n+12 次 | 平手 |
| 按位序插入 / 删除 | O(n)，平均移动 n2 / n−12 个**元素** | O(n)，平均走 n+12 步后改常数个**指针** | **链表**，尤其当元素体积大时 |
| 已知位置插入 / 删除 | 仍是 O(n)——元素照样得挪 | O(1) | **链表** |

⚠️ 第三行是最容易含糊的一行：两边都是 O(n)，**但两个 O(n) 的常数因子完全不同**。 顺序表搬的是**元素**（每个元素多大就搬多少字节），链表走的是**指针**（每步只读一个地址）。 元素是一个 200 字节的结构体时，顺序表要搬约 200×n/2 字节，链表只需读 n/2 个指针。 教材把这一点写成"尤其是当每个结点的信息量较大时，移动结点的时间开销就相当可观"。

### 空间

设有 n 个 `int` 元素，指针与 `int` 同宽（各 4 字节）：

|  | 顺序表 | 单链表 |
| --- | --- | --- |
| 每个元素占用 | 4 字节 | 4（数据） + 4（指针） = 8 字节 |
| n 个元素合计 | 4n | 8n |
| **存储密度** | 44=1 | 48=0.5 |
| 空间利用率 | 100%（不计空闲区） | 50% |
| 是否要求连续空间 | **是**，必须一整块 | 否，结点可散落 |
| 空间何时确定 | 预先按上限分配 | 按需申请，只受内存总量限制 |

**链表的空间劣势有多大，取决于数据域相对指针有多大**：数据域是 `int` 时存储密度 0.5， 是 100 字节的结构体时存储密度约 100104≈0.96，指针几乎不构成负担。 反过来，顺序表若按上限预分配而实际只用了一小半，其**实际**空间利用率也可以远低于 50%。 **"链表费空间"是一句有条件的话，条件是数据域小且顺序表的容量估得准。**

## 易混淆知识点

| 易混对 | 判别依据 | 结论 |
| --- | --- | --- |
| 头指针 vs 头结点 | 前者是**指针变量**，后者是**结点** | 头指针必有；头结点可选。空表时带头结点的 `L != NULL`，不带头结点的 `L == NULL` |
| 头结点 vs 首元结点 | 数据域存不存有效数据 | 头结点不存；首元结点存 a1 |
| 带头结点的判空 vs 不带头结点的判空 | 看 `L` 指向谁 | 带：`L->next == NULL`；不带：`L == NULL` |
| 带头结点计数器从 0 起 vs 不带从 1 起 | 头结点算不算"第 0 个" | 带头结点时 `p=L, j=0`；不带时 `p=L, j=1`。混用会整体错位一个结点 |
| `s->next = p->next` 在前 vs `p->next = s` 在前 | 问"被覆盖的那个地址还有没有别处存着" | 必须先让 `s` 接住，否则丢掉整个后半段 |
| 插入删除 O(1) vs O(n) | 题面给的是**指针**还是**位序** | 给指针 O(1)；给位序 O(n)（定位那一步跑不掉） |
| 头插法建表 vs 头插法逆置 | 前者从输入建新表，后者把已有表就地反转 | 二者用的是同一个指针动作，头插法建表的"逆序"性质正是逆置成立的理由 |
| 逆置的空间 O(1) vs O(n) | 是否申请了与 n 成正比的辅助存储 | 两种解法都只用常数个指针，都是 O(1)；只有"另建一张新表"的写法才是 O(n) |
| 删除结点自身 O(1) 的适用范围 | `p` 是不是尾结点 | 非尾结点可用"搬后继"法 O(1)；尾结点必须找前驱 O(n) |
| 存储密度 vs 空间利用率 | 前者只看单个结点的构成比，后者还要计空闲区 | 顺序表存储密度恒为 1，但预分配过量时实际利用率可以很低 |

## 本节小结

学完本节，你应该能够：

- 写出单链表的**结点定义**，说清 `LinkList` 与 `LNode *` 的关系，以及指针域存的为什么必须是 **直接**后继；
- 一句话分清**头指针 / 头结点 / 首元结点**，并写出两种口径下的判空条件；
- 说出头结点省掉的**两类特殊情况**（空表与非空表不统一、第 1 个位置与其他位置不统一）， 并能对照写出带头结点与不带头结点的插入代码；
- 默写**头插法**与**尾插法**建表，解释头插法为什么逆序、尾插法为什么必须维护尾指针；
- 用一条通用范式（**先暂存被覆盖的地址，再改指针**）推出后插、前插、删除的正确顺序， 并说清顺序写反的具体后果是"丢掉整个后半段"；
- 写出前插与删除自身的 O(1) 技巧，并指出各自的适用边界（外部指针会失效 / 尾结点无效）；
- 用两种方法完成**逆置**，说明它们都是 O(n) 时间、O(1) 空间，并写出各自的循环不变量；
- 给出链表每个操作复杂度的**来历**，并在被问到"插入是 O(1) 还是 O(n)"时， 先反问"给的是指针还是位序"；
- 从**时间**（按位查找、元素体积对搬运代价的影响）和**空间**（存储密度、是否要求连续） 两个维度定量对比顺序表与链表。

三条最关键的结论：

- **链表用一个指针域的空间，买断了"元素必须挨着放"这条约束。** 随之而来的是 插删不用搬元素（赚），以及无法算地址、只能顺序存取（赔）。
- **头结点不是装饰，它把两类边界情况变成了普通情况。** 带头结点的代码里一个特判都不需要。
- **指针修改的顺序不是习惯问题，是正确性问题。** 判据只有一条—— 即将被覆盖的那个地址，此刻是否还有别的地方存着它。
