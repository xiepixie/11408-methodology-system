# 循环链表

## 大纲定位

本篇对应 2026 大纲 **二、线性表 —— （二）线性表的实现 · 2 链式存储**。

⚠️ **这一条大纲条目由四篇文章分担，[单链表](./singly-linked-list.html) 是主篇，本篇只写增量。**

**主篇负责**：链式存储的全部共性内容——结点结构、头指针 / 头结点 / 首元结点辨析、 带头结点与不带头结点的完整讨论、建表、查找、**插入与删除的通用指针修改范式**、逆置、 各操作复杂度的完整来历、与顺序表的定量对比。这些内容本篇**一律不重复**。

## 知识框架

本节回答三个问题：

- "尾结点指回头部"这一处改动，为什么会波及到几乎每一段遍历代码？
- 只设尾指针不设头指针，凭什么能把两表合并从 O(n) 降到 O(1)？
- 循环双链表的"无需特判"到底省掉了哪几个 `if`？

## 增量一：判尾条件的改写

### 结构

**循环单链表**：尾结点的 `next` 不再是 `NULL`，而是指回**头结点**（带头结点时） 或**首元结点**（不带头结点时），整条链形成一个环。

图源：殷人昆《数据结构——用面向对象方法与 C++ 描述》（第 2 版）图 2.12 循环链表的示意图，p66。 图中画的是**不带头结点**的版本，尾结点指回 a1；下文的代码采用**带头结点**版本， 尾结点指回头结点 `L`。两种口径的判尾条件不同，写代码前必须先定死用哪一种。

**循环双链表**：在循环单链表的基础上，头结点的 `prior` 指向尾结点、尾结点的 `next` 指向 头结点，形成一个**双向闭合环**。

### 波及面：三处条件全变

结构上只改了一个指针，但它带来的连锁反应遍布所有遍历代码：

| 对比项 | 普通链表 | 循环链表（带头结点） |
| --- | --- | --- |
| 尾结点的指针域 | `next = NULL` | `next = L`（指回头结点） |
| 判空条件 | `L->next == NULL` | `L->next == L` |
| 遍历终止（判当前结点是否为表尾之后） | `p != NULL` | `p != L` |
| 判 `p` 是否为**尾结点** | `p->next == NULL` | `p->next == L` |

⚠️ **把 `p != L` 误写成 `p != NULL` 的后果不是"少访问一个结点"，而是死循环**—— 循环链表上根本没有 `NULL` 可以到达，指针会绕着环一直转。 反过来，在普通链表上误用 `p != L` 会漏掉整张表（`p` 从一开始就不等于 `L`， 但走到 `NULL` 后再解引用就是非法访问）。**这两条判据绝不能凭手感写， 写之前先确认这张表是不是环。**

### 基本操作

#### 结点定义
c

```
typedef struct LNode {
    int data;
    struct LNode *next;
} LNode, *LinkList;
```

与单链表**完全相同**——循环链表不改结点结构，只改指针的指向约定。

#### 初始化（带头结点）
c

```
bool InitList(LinkList *L) {
    *L = (LNode *)malloc(sizeof(LNode));
    if (*L == NULL) return false;
    (*L)->next = *L;    // 指向自身，而非 NULL —— 空表也必须是一个闭合的环
    return true;
}
```

#### 判空与遍历
c

```
bool Empty(LinkList L) {
    return L->next == L;      // 不是 L->next == NULL
}

void Traverse(LinkList L) {
    LNode *p = L->next;       // 从首元结点开始
    while (p != L) {          // 回到头结点即停止
        printf("%d ", p->data);
        p = p->next;
    }
}
```

#### 在第 i 个位置插入

指针修改的动作与单链表**逐字相同**（`s->next = p->next; p->next = s;`）， 唯一的改动在**查找前驱时的循环条件**：c

```
bool ListInsert(LinkList L, int i, int e) {
    if (i < 1) return false;
    LNode *p = L;
    int j = 0;
    while (p->next != L && j < i - 1) {   // 走到表尾（p->next == L）就停，不再往前
        p = p->next;
        j++;
    }
    if (j < i - 1) return false;          // 没走够 i-1 步就撞到表尾，说明 i 越界
    LNode *s = (LNode *)malloc(sizeof(LNode));
    if (s == NULL) return false;
    s->data = e;
    s->next = p->next;                    // 与单链表完全一致
    p->next = s;
    return true;
}
```

**边界自查**：

- 空表插 i=1：`p = L`，`p->next == L` 使循环不执行，`j = 0` 不小于 `i-1 = 0`， 于是插入。结果 `L->next = s`、`s->next = L`，环仍闭合 ✓
- 空表插 i=2：循环仍不执行，`j = 0 < 1` 成立，返回 `false` ✓
- 表长 2 插 i=3（插到表尾）：循环走 2 步后 `p` 停在第 2 个结点、`p->next == L` 退出， `j = 2` 不小于 `2`，插入在表尾，`s->next` 拿到 `L`，环闭合 ✓
- 表长 2 插 i=4：循环同样在 `j = 2` 时因 `p->next == L` 退出，`j = 2 < 3`，返回 `false` ✓

#### 删除第 i 个结点
c

```
bool ListDelete(LinkList L, int i, int *e) {
    if (i < 1) return false;
    LNode *p = L;
    int j = 0;
    while (p->next != L && j < i - 1) {
        p = p->next;
        j++;
    }
    if (p->next == L) return false;   // 前驱之后已是头结点，无结点可删
    LNode *q = p->next;
    *e = q->data;
    p->next = q->next;      // 与单链表完全一致
    free(q);                // 释放放在最后
    return true;
}
```

**边界自查**：空表删 i=1 → 循环不执行、`p->next == L` 成立，返回 `false` ✓； 表长 2 删 i=1 → 循环不执行（`j < 0` 不成立），`p = L`，`q` 为首元结点，删除正确 ✓； 表长 2 删 i=3 → 循环走到 `p` 为第 2 个结点、`p->next == L` 退出，返回 `false` ✓。

⚠️ **删除的越界判据为什么与插入不一样**（`p->next == L` vs `j < i-1`）： 插入允许 i=n+1（插在表尾之后），此时 `p` 恰好停在尾结点、`p->next == L` 成立却完全合法， 所以插入只能查"有没有走够 i−1 步"；删除没有"删第 n+1 个"这回事， 而 i=n+1（走够了步数但前驱就是尾结点）与 i>n+1（没走够就撞上表尾） **两种越界在退出时都满足 `p->next == L`**，所以删除用这一条就够了。 另外注意 `j` 的取值范围：开头已拦掉 i<1，循环又只在 `j < i-1` 成立时才自增， 于是恒有 0≤j≤i−1——**再补一句 `j > i-1` 是永远为假的死代码**。 教材的按位取值算法里确实写了这一句，那是因为它没有单独拦 i≤0， 靠它来兜住 i≤0；这里前面拦过了，就不必重复。

## 增量二：尾指针表示法

### 只设尾指针，不设头指针

普通链表用**头指针**标识整张表，代价是访问表尾要走 O(n)。 循环链表因为首尾相连，可以反过来——**只设一个尾指针 `rear`**：

| 想访问 | 表达式 | 代价 |
| --- | --- | --- |
| 尾结点 | `rear` | O(1) |
| 头结点 | `rear->next` | O(1) |
| 首元结点 | `rear->next->next` | O(1) |

这在普通单链表上做不到：普通单链表若只留尾指针，就再也回不到表头了。 **是"环"这个结构使得从任一结点都能到达任一结点，尾指针才有资格独自标识整张表。**

这条性质直接决定了**链队列**的实现方式：队列要在一端入队（表尾）、另一端出队（表头）， 两端都要 O(1)。用带尾指针的循环单链表，两端都是 O(1)， 见[队列的链式存储](./../stack-queue/queue.html)。

### 两个循环单链表的 O(1) 合并

把表 A 与表 B 首尾相接（A 在前、B 在后），两表均用尾指针表示。 所需动作只有三步：

- 把 A 的尾结点接到 B 的**首元结点**上；
- 把 B 的尾结点接回 A 的**头结点**，重新闭合成环；
- 释放 B 的头结点（多余了）。c

```
// 将 Lb 合并到 La 的尾部（两者均为尾指针，假设两表均非空）
LinkList Connect(LinkList La, LinkList Lb) {
    LNode *headA = La->next;    // 先保存 La 的头结点，下一句就要覆盖 La->next
    La->next = Lb->next->next;  // La 的尾结点接上 Lb 的首元结点
    free(Lb->next);             // 释放 Lb 的头结点（此时它已无人引用）
    Lb->next = headA;           // Lb 的尾结点接回 La 的头结点，环重新闭合
    return Lb;                  // Lb 现在是合并后表的尾指针
}
```

**逐步验算**（A=(1,2,3)、B=(4,5)，均带头结点 hA、hB）：

| 步骤 | 环的状态 |
| --- | --- |
| 初始 | hA→1→2→3→hA，`La` = 结点 3；hB→4→5→hB，`Lb` = 结点 5 |
| `headA = La->next` | `headA` = hA |
| `La->next = Lb->next->next` | 结点 3 的 `next` 改为结点 4 |
| `free(Lb->next)` | 释放 hB |
| `Lb->next = headA` | 结点 5 的 `next` 改为 hA |
| 结果 | hA→1→2→3→4→5→hA，`Lb` = 结点 5 即新尾指针 ✓ |

**为什么是 O(1)**：三步全是常数次指针赋值，**没有任何一步需要遍历**。 若两表用头指针表示，第 1 步"找 A 的尾结点"就要 O(n)，整体退化为 O(n)。 **这是尾指针表示法最有分量的一处收益。**

教材给出的语句段更短，因为它把"释放第二个表的头结点"留在正文里没写进代码 （`A`、`B` 均为尾指针）：c

```
p = B->next->next;    // p 指向 B 的首元结点
B->next = A->next;    // B 的尾结点接回 A 的头结点
A->next = p;          // A 的尾结点接上 B 的首元结点
                      // 正文另有一句：然后释放第二个表的头结点
```

两段代码语义相同，只是赋值次序不同——**都遵守同一条约束：凡是要用到 `A->next` 或 `B->next` 原值的语句，必须排在覆盖它的语句之前。**

⚠️ **两段代码都隐含"两表均非空"这个前提。** 若 B 为空表（`Lb->next == Lb`）， 尾指针 `Lb` 就是它自己的头结点，`free(Lb->next)` 会把 `Lb` 本身释放掉， 后续 `Lb->next = headA` 就是写已释放内存。自己实现时应先特判空表。

## 增量三：循环双链表免掉了哪些特判

图源：殷人昆《数据结构——用面向对象方法与 C++ 描述》（第 2 版）图 2.16 带附加头结点的双向循环链表，p69。 注意 (b) 空表：头结点仍在，只是它的 `prior` 与 `next` 都指向自身—— 这正是循环双链表初始化要写 `L->prior = L->next = L` 的原因。c

```
typedef struct DNode {
    int data;
    struct DNode *prior, *next;
} DNode, *DLinklist;

bool InitDLinkList(DLinklist *L) {
    *L = (DNode *)malloc(sizeof(DNode));
    if (*L == NULL) return false;
    (*L)->prior = *L;   // 前驱指向自身
    (*L)->next  = *L;   // 后继指向自身
    return true;
}

bool Empty(DLinklist L) {
    return L->next == L;
}

void Traverse(DLinklist L) {
    DNode *p = L->next;
    while (p != L) {         // 回到头结点即停止
        printf("%d ", p->data);
        p = p->next;
    }
}
```

### 免特判的机理

回顾[双链表](./doubly-linked-list.html)里的结构恒等式：d->next->prior=d->prior->next=d

在**非循环**双链表里，这个式子在首尾两端不成立（头结点无前驱、尾结点无后继）， 所以每段代码都要补 `if (p->next != NULL)` 之类的判断。

**在循环双链表里，每个结点都必有前驱和有后继，恒等式处处成立，那些判断整段消失**：c

```
// 循环双链表：在结点 p 之后插入结点 s
bool InsertNextDNode(DNode *p, DNode *s) {
    if (p == NULL || s == NULL) return false;
    s->next = p->next;
    p->next->prior = s;   // ← 非循环版本这里要判 p->next != NULL，循环版本不必
    s->prior = p;
    p->next = s;
    return true;
}

// 循环双链表：删除结点 p 的后继结点
bool DeleteNextDNode(DLinklist L, DNode *p) {
    if (p == NULL || p->next == L) return false;  // 后继是头结点，说明 p 已是尾结点
    DNode *q = p->next;
    p->next = q->next;
    q->next->prior = p;   // ← 非循环版本这里要判 q->next != NULL，循环版本不必
    free(q);
    return true;
}
```

⚠️ 免掉的是**判空**特判，**不是**判头结点。删除时仍必须拦住 `p->next == L`—— 头结点不是数据结点，删掉它整张表就散了。**"循环链表不用特判"这句话要精确到 "不用判 `NULL`"，而不是"不用判任何东西"。**

### 循环双链表的操作集

| 操作 | 循环单链表 | 循环双链表 |
| --- | --- | --- |
| 在已知结点**之后**插入 | O(1) | O(1) |
| 在已知结点**之前**插入 | O(n)（要找前驱） | O(1) |
| 删除已知结点**自身** | O(n)（要找前驱） | O(1) |
| 反向遍历 | 做不到 | O(n) |
| 判 `p` 是否为尾结点 | `p->next == L` | `p->next == L` |

## 增量四：应用 —— 约瑟夫问题

**约瑟夫问题**：n 个人围成一圈（编号 1∼n），从第 1 个人开始报数， 报到 m 的人出列，然后从下一个人重新报 1，如此循环直到所有人出列。求出列顺序。

图源：殷人昆《数据结构——用面向对象方法与 C++ 描述》（第 2 版）图 2.15 n=8、m=3 的约瑟夫问题示例，p68。

### 为什么用不带头结点的循环单链表

三条理由，每一条都对应结构的一个性质：

- **"围成一圈"没有逻辑上的表头**——第 n 个人的下一个就是第 1 个人， 这正是循环链表的结构语义。用普通链表就要在走到 `NULL` 时手工跳回表头。
- **每个结点都是一个"人"，没有哪个结点是不存数据的**——头结点在这里没有意义， 它反而会在报数时被当成一个人数进去。所以用**不带头结点**的版本。
- **出列就是摘结点**，圈子自然缩小；圈空了算法就结束，不需要额外的计数器。c

```
// 约瑟夫问题：输出 n 个人按报数 m 的出列序列
void Josephus(int n, int m) {
    // 1. 建表：不带头结点的循环单链表，结点依次存编号 1~n
    LNode *head = (LNode *)malloc(sizeof(LNode));
    head->data = 1;
    LNode *tail = head;
    for (int i = 2; i <= n; i++) {
        LNode *s = (LNode *)malloc(sizeof(LNode));
        s->data = i;
        tail->next = s;
        tail = s;
    }
    tail->next = head;                 // 尾指回首，成环

    // 2. 报数出列：pre 始终是 p 的前驱，方便摘除 p
    LNode *pre = tail, *p = head;
    while (p->next != p) {             // 圈内剩下超过 1 人
        for (int k = 1; k < m; k++) {  // p 从"报 1"走到"报 m"的人
            pre = p;
            p = p->next;
        }
        printf("%d ", p->data);        // 报到 m，出列
        pre->next = p->next;           // 从圈中摘除 p
        free(p);
        p = pre->next;                 // 下一轮从出列者的下一人重新报 1
    }
    printf("%d\n", p->data);           // 圈内最后一人
}
```

**代码里三处值得说清的设计**：

- **为什么要维护 `pre`**：单链表摘结点必须有前驱。若不维护 `pre`，每次出列都要绕环一整圈 去找前驱，时间从 O(nm) 涨到 O(n2+nm)。
- **循环条件为什么是 `p->next != p`**：圈内只剩 1 人时，这个人的 `next` 指向他自己。 **绝不能写成 `p != NULL`——循环链表里根本没有 `NULL`**，那样写就是死循环。
- **`for (int k = 1; k < m; k++)`**：从当前这个人（他报 1）走到报 m 的人， 要走 m−1 步，不是 m 步。写成 `k <= m` 会整体偏移一个人。

**验算**：n=5、m=3 时出列顺序为 **3, 1, 5, 2, 4**。 逐轮追踪：1,2,3 → 3 出列；从 4 起报，4,5,1 → 1 出列；从 2 起报，2,4,5 → 5 出列； 从 2 起报，2,4,2 → 2 出列；圈内只剩 4。

**时间复杂度 O(nm)**：每出列一人要走 m−1 步，共出列 n 人， 总步数约 n(m−1)。**空间 O(n)**——n 个结点是问题本身的规模， 算法只额外用了 `pre`、`p`、`k` 三个变量，辅助空间 O(1)。

⚠️ **两处容易搞反的细节**：① 出列后下一轮从**出列者的下一个人**重新报 1， 不是从原起点重新数；② m=1 时每个人报一次就出列，出列顺序就是 1,2,…,n， 代码里 `for` 循环一次都不执行，正好覆盖这个边界。

## 复杂度分析

### 循环单链表

| 操作 | 时间复杂度 | 来历 |
| --- | --- | --- |
| 判空 | O(1) | 一次比较 `L->next == L` |
| 头插 / 头删 | O(1) | 在头结点之后操作，不必遍历 |
| 尾插（只有头指针） | O(n) | 要走到表尾，n 步 |
| **尾插（有尾指针）** | O(1) | `rear` 直接就是尾结点 |
| 按位查找 | O(n) | 走 i 步，平均 n+12 |
| 按值查找 | O(n) | 平均比较 n+12 次 |
| **两表合并（均用尾指针）** | O(1) | 三次指针赋值，无遍历 |
| 遍历全表 | O(n) | 从任一结点出发都能走遍全表 |

### 循环双链表

| 操作 | 时间复杂度 | 来历 |
| --- | --- | --- |
| 在已知结点后 / 前插入 | O(1) | 4 次指针赋值，且**不需判空** |
| 删除已知结点自身 | O(1) | 2 次指针赋值，靠 `prior` 直接拿到前驱 |
| 按位查找 / 按值查找 | O(n) | 仍是顺序存取 |
| 正向 / 反向遍历 | O(n) | 两条链都闭合 |

**空间复杂度**：上述操作均只用常数个辅助指针，O(1)。 结构上循环链表**不比对应的非循环版本多占任何空间**——它只是把尾结点那个本来存 `NULL` 的指针域改成了存表头地址，**存储密度与单 / 双链表完全相同**。

**这是循环链表最划算的一点**：增量为零的空间代价，换来"从任一结点可达全表" 与"尾指针可独立标识整表"两条结构性质。

## 易混淆知识点

| 易混对 | 判别依据 | 结论 |
| --- | --- | --- |
| `p != NULL` vs `p != L` | 这张表是不是环 | 环上没有 `NULL`；用错的后果是死循环（而不是少访问一个结点） |
| 判空 `L->next == NULL` vs `L->next == L` | 同上 | 循环链表空表时头结点指向它自己 |
| 带头结点 vs 不带头结点的循环单链表 | 尾结点指回谁 | 带：指回头结点，判尾用 `p->next == L`；不带：指回首元结点，判尾用 `p->next == first` |
| 循环链表**免特判** vs **不用判任何东西** | 免掉的是判 `NULL` | 删除时仍要拦 `p->next == L`（头结点不可删） |
| 头指针表示 vs 尾指针表示 | 手里那个指针指着谁 | 尾指针能 O(1) 拿到首尾两端；头指针只能 O(1) 拿到表头 |
| 两表合并 O(1) vs O(n) | 两表是否都用**尾指针**表示 | 用头指针表示时，找第一个表的尾结点就要 O(n) |
| 循环链表空间开销 vs 双链表空间开销 | 有没有**新增**指针域 | 循环化不增加任何域，存储密度不变；双向化每结点多一个域，存储密度下降 |
| 约瑟夫的循环条件 `p->next != p` vs `p != NULL` | 圈内剩 1 人时的表现 | 剩 1 人时他的 `next` 指向自己；写 `p != NULL` 是死循环 |
| 约瑟夫走 m−1 步 vs m 步 | 当前这个人算不算"报 1" | 当前人报 1，再走 m−1 步才到报 m 的人 |

## 本节小结

学完本节，你应该能够：

- 写出循环单链表与循环双链表的**判空条件、遍历终止条件、判尾结点条件**， 并说清把 `p != L` 误写成 `p != NULL` 的后果是**死循环**；
- 指出循环化**只改一个指针的指向、不新增任何存储**，因此存储密度与非循环版本相同；
- 说明**尾指针表示法**为什么只在循环链表上成立，并列出用它能 O(1) 拿到的三个位置；
- 完整写出两个循环单链表的 O(1) 合并，逐步验算指针的变化，并指出它隐含 "两表均非空"这一前提；
- 解释循环双链表"无需特判"的机理——**结构恒等式在环上处处成立**， 并同时指出免掉的只是判 `NULL`、判头结点仍不可省；
- 用不带头结点的循环单链表实现**约瑟夫问题**，说清为什么不带头结点、 为什么要维护 `pre`、为什么内层循环走 m−1 步，并手工验算 n=5、m=3 的出列序列。

三条最关键的结论：

- **循环链表的全部代码改动集中在一处：判尾的依据从"到达 `NULL`"变成"回到起点"。** 指针修改的动作本身与单 / 双链表逐字相同。
- **尾指针能独自标识整张表，是"环"这个结构给的**；由它导出的两表 O(1) 合并， 是循环链表在算法层面最实的收益。
- **循环化的空间代价为零**。这一点使得"要不要循环"几乎总是一个只看操作需求的选择， 不需要权衡空间。

## 教材出处

- 循环链表的定义（"表中最后一个结点的指针域指向头结点，整个链表形成一个环。 由此，从表中任一结点出发均可找到表中其他结点"）、 以及**判尾条件的改写**（"在单链表中，判别条件为 `p != NULL` 或 `p->next != NULL`， 而循环单链表的判别条件为 `p != L` 或 `p->next != L`"）： 严蔚敏《数据结构（C 语言版）》（第 2 版），p38，2.5.3 节。
