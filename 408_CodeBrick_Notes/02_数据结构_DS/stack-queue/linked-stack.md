# 链栈

## 大纲定位

本篇对应 2026 大纲 **三、栈、队列和数组 →（三）栈和队列的链式存储结构**。

这一条目由两篇分担：

- **本篇《链栈》** 负责**栈**的链式实现；
- 《[链式队列](./queue.html)》负责**队列**的链式实现。

两篇的核心差异值得先记住：**链栈只需要一个指针（栈顶），链队需要两个（队头 + 队尾）**， 根源是栈的插入删除都在同一端、队列在两端。

与顺序存储的分工：数组实现的栈在《[顺序栈](./sequential-stack.html)》《[共享栈](./shared-stack.html)》， 属大纲三（二）；栈的逻辑定义与出栈序列性质在《[栈和队列的基本概念](./concepts.html)》，属三（一）。

## 知识框架

## 核心思想

链栈的三条核心特点：

- **以链表头部作为栈顶**：入栈和出栈都在表头进行，时间复杂度 O(1)；
- **无需预分配空间**：每个结点动态分配，不存在"栈满上溢"（除非内存耗尽）；
- **不支持随机访问**：要访问栈中第 i 个元素必须从栈顶依次走 i−1 步。

结点结构定义：c

```
typedef struct LinkNode {
    int data;               // 数据域
    struct LinkNode *next;  // 指针域，指向下一个结点（栈中"下面"那个元素）
} LinkNode, *LinkStack;
```

链栈的逻辑结构（栈顶在左）：text

```
top → [a₃|next] → [a₂|next] → [a₁|NULL]
      栈顶元素                 栈底元素
```

栈顶指针 `top` 始终指向链表的第一个结点，也就是栈顶元素。**栈底结点的 `next` 是 `NULL`**， 它同时也是链表的表尾。

### 为什么栈顶一定设在表头

这不是习惯，是效率决定的。假设反过来把**表尾**当栈顶：

- 入栈（在表尾插入）：单链表没有尾指针时要走到表尾，O(n)；就算加一个尾指针，也只能做到 O(1)；
- 出栈（删除表尾结点）：必须找到**表尾的前驱**才能改它的 `next`。单链表无法从一个结点回退， 只能从头再走一遍，O(n)，**加尾指针也救不了**。

而设在表头时，入栈是头插、出栈是删首结点，两者都只改动 `top` 和一个 `next`，都是 O(1)。 **"删除需要前驱"是单链表的根本约束，栈顶设在表头正是为了绕开它。**

严蔚敏教材对此的原话是："由于栈的主要操作是在栈顶插入和删除，显然以链表的头部作为栈顶是 最方便的，而且没必要像单链表那样为了操作方便附加一个头结点。"

## 操作详解

下面的代码统一采用**不带头结点**的链栈，栈顶指针以 `LinkStack *top`（指向指针的指针）传入。 教材和部分参考答案会写成 C++ 的引用形式 `LinkStack &top`，两者语义完全一致—— 都是为了让函数内部对 `top` 的修改能传回调用方。**如果写成 `LinkStack top`（传值）， 函数里 `top = s` 只改了副本，调用方的栈顶指针不会变，这是链栈代码题的头号错误。**

### 初始化与判空
c

```
void InitStack(LinkStack *top) {
    *top = NULL;               // 不设头结点，空栈就是空指针
}

bool StackEmpty(LinkStack top) {
    return top == NULL;        // 与初始化同一口径
}
```

### 入栈操作

入栈即在链表**头部插入**一个新结点。

关键步骤：

- 申请新结点，写入数据域；
- 新结点的 `next` 指向**当前栈顶**；
- 更新栈顶指针指向新结点。c

```
// 入栈（不带头结点）
bool Push(LinkStack *top, int x) {
    LinkNode *s = (LinkNode *)malloc(sizeof(LinkNode));
    if (s == NULL) return false;   // 内存分配失败——链栈唯一的"失败"来源
    s->data = x;
    s->next = *top;                // 必须先接上原栈顶
    *top = s;                      // 再让 top 指向新结点
    return true;
}
```

**第 2、3 步的顺序不能颠倒**。若先写 `*top = s;` 再写 `s->next = *top;`， 则 `s->next` 指向的是 `s` 自己，形成自环，原来整条链全部丢失（内存泄漏 + 后续遍历死循环）。 这条和单链表头插法是同一个坑。

链栈入栈**不需要判断栈满**：容量只受堆内存限制。但仍要检查 `malloc` 的返回值， 这是"栈满"在链式实现下的对应物。

### 出栈操作

出栈即**删除首结点**，并取出其数据。c

```
// 出栈（不带头结点）
bool Pop(LinkStack *top, int *x) {
    if (*top == NULL) return false;   // 栈空
    LinkNode *p = *top;               // 暂存待删结点，否则 free 时找不到它
    *x = p->data;                     // 先取数据，free 之后再读就是野指针
    *top = p->next;                   // 栈顶下移
    free(p);                          // 归还空间
    return true;
}
```

**`p` 这个临时指针不能省**：如果直接写 `*top = (*top)->next;` 再想 `free` 原结点， 那个结点的地址已经找不到了，造成内存泄漏。**"先存地址、再改指针、最后释放"** 是链式结构 删除操作的固定三步。

### 取栈顶元素
c

```
bool GetTop(LinkStack top, int *x) {
    if (top == NULL) return false;
    *x = top->data;                   // 只读，不改动任何指针
    return true;
}
```

注意这里第一个参数是传值的 `LinkStack top`——本操作不修改栈，传值在语义上就杜绝了误改。

### 带头结点的写法（对照）

有的题目会要求链栈带头结点。此时 `top` 恒指向头结点，**头结点不存数据**：c

```
// 带头结点：判空条件变了
bool StackEmpty_H(LinkStack top) { return top->next == NULL; }

bool Push_H(LinkStack top, int x) {          // 注意：不再需要二级指针
    LinkNode *s = (LinkNode *)malloc(sizeof(LinkNode));
    if (s == NULL) return false;
    s->data = x;
    s->next = top->next;                     // 插到头结点之后
    top->next = s;
    return true;
}

bool Pop_H(LinkStack top, int *x) {
    if (top->next == NULL) return false;     // 栈空
    LinkNode *p = top->next;
    *x = p->data;
    top->next = p->next;
    free(p);
    return true;
}
```

两种写法的差别只有一处根源：**头结点让"栈顶指针"这个变量本身不再需要被修改**， 于是参数不必是二级指针（或引用），代价是多占一个结点、判空条件变成 `top->next == NULL`。

**一致性检查**：判空条件与初始化必须成对。不带头结点 → `InitStack: *top = NULL` + 判空 `top == NULL`；带头结点 → `InitStack: top = malloc(...); top->next = NULL` + 判空 `top->next == NULL`。**代码题里两者写混，一定错。**

### 求栈长、遍历与销毁

这三个操作在链栈上都是 O(n)，而在顺序栈上前两个是 O(1)、第三个不存在。c

```
// 求栈长：必须从栈顶数到 NULL
int StackLength(LinkStack top) {
    int len = 0;
    for (LinkNode *p = top; p != NULL; p = p->next)
        len++;
    return len;                    // O(n)
}

// 从栈顶到栈底遍历（注意方向：无法反向遍历）
void StackTraverse(LinkStack top) {
    for (LinkNode *p = top; p != NULL; p = p->next)
        visit(p->data);            // 访问次序是 栈顶 → 栈底
}

// 销毁：逐个释放，必须先存住 next
void DestroyStack(LinkStack *top) {
    while (*top != NULL) {
        LinkNode *p = *top;
        *top = p->next;            // 先把 next 取出来
        free(p);                   // 再释放，顺序不能反
    }
}
```

**`DestroyStack` 里两句的顺序不能反**：若先 `free(p)` 再读 `p->next`， 读的是已释放内存，属于未定义行为。这与 `Pop` 里"先存地址、再改指针、最后释放"是同一条纪律。

**顺序栈没有 `DestroyStack` 这一步**（静态数组随结构体一起消失）， 但如果是动态分配的顺序栈（`malloc` 出来的数组），则只需 **一次** `free(S.base)`， 仍然是 O(1)——这是"离散分配 vs 连续分配"在释放成本上的差别。

**如果题目要求 O(1) 求栈长**，办法是给链栈加一个计数器：c

```
typedef struct {
    LinkNode *top;   // 栈顶指针
    int count;       // 当前元素个数
} LinkStackWithCount;
```

入栈 `count++`、出栈 `count--`，求长度变成 O(1)，代价是多一个字段、 且**每处修改栈的地方都必须同步维护它**——漏一处就长期不一致。 这与《[循环队列](./circular-queue.html)》里"增设 `size` 计数器"是同一种取舍。

## 复杂度分析

| 操作 | 时间复杂度 | 来历 |
| --- | --- | --- |
| 入栈 | O(1) | 一次 `malloc` + 两次指针赋值，与栈中元素个数 n 无关 |
| 出栈 | O(1) | 一次判空 + 三次指针/数据操作 + 一次 `free` |
| 取栈顶 | O(1) | 直接解引用 `top` |
| 判空 | O(1) | 一次指针比较 |
| 求栈长 | O(n) | **必须从栈顶遍历到 `NULL` 数结点**，除非额外维护计数器 |

最后一行是链栈与顺序栈的一个实质差别：顺序栈的栈长由 `top` 直接算出（O(1)）， 链栈若不加计数器就得遍历。凡是问"求栈长的复杂度"，先确认是哪种实现。

**空间复杂度**：n 个元素占 n 个结点，每个结点除数据外多一个指针域。 单次操作的辅助空间 O(1)。

### 存储密度

**存储密度** = 结点中数据本身占的空间 / 结点占用的总空间。

- 顺序栈：数组元素紧挨着排，没有任何附加信息，**存储密度 =1**；
- 链栈：设 `int` 占 4 字节、指针占 4 字节，则每个结点 8 字节里只有 4 字节是数据， **存储密度 =4/8=1/2**；若在 64 位环境下指针占 8 字节，密度降到 4/12=1/3。

所以"链式存储更省空间"是**不对的**——它省的是"预分配却没用上"的那部分， 付出的是"每个已用结点多带一个指针"的固定开销。**元素少时链栈省，元素多且容量能估准时顺序栈省。**

## 链栈 vs 顺序栈

| 对比项 | 顺序栈 | 链栈 |
| --- | --- | --- |
| 存储方式 | 静态数组，连续空间 | 链表，离散空间 |
| 容量 | 预分配 `MaxSize`，固定 | 按需 `malloc`，无固定上限 |
| 栈满（上溢） | **会发生**，`top == MaxSize-1` | **不会**，只可能 `malloc` 失败 |
| 栈空（下溢） | 会发生，`top == -1` | 会发生，`top == NULL` |
| 空间利用 | 预分配过大则浪费，过小则上溢 | 按需分配，无浪费 |
| 存储密度 | 1 | <1（每结点多一个指针域） |
| 求栈长 | O(1)（由 `top` 算出） | O(n)（需遍历，除非另设计数器） |
| 缓存性能 | 好（连续存储，局部性强） | 差（结点分散在堆上） |
| 是否需要头结点 | 不涉及 | **通常不需要** |
| 适用场景 | 容量可预估、追求常数性能 | 容量不可预估、多个栈并存 |

**"下溢"两种实现都有**：它是"对空栈做 `Pop`"这个**逻辑错误**，与存储方式无关。 **"上溢"只有顺序栈有**。把这两个混为一谈是常见失分点。

## 易混淆知识点

| 对比项 | 情况 A | 情况 B | 判别依据 |
| --- | --- | --- | --- |
| 判空条件 | 不带头结点：`top == NULL` | 带头结点：`top->next == NULL` | 看 `top` 指的是**栈顶元素**还是**头结点** |
| 参数写法 | 不带头结点：需二级指针 `LinkStack *top`（或引用 `&`） | 带头结点：一级指针即可 | 函数内是否需要修改"栈顶指针"这个变量本身 |
| 入栈两步顺序 | 正确：`s->next = *top;` 再 `*top = s;` | 错误：先改 `top` 再接 `next` → 自环 + 整条链丢失 | 新结点必须先接上旧链，才能顶替旧的头 |
| 出栈是否需要临时指针 | 需要 `p` 暂存，否则无法 `free` | 直接 `*top = (*top)->next` 会泄漏 | 释放前必须留住地址 |
| 上溢 vs 下溢 | 上溢：顺序栈专有 | 下溢：两种实现都有 | 上溢是空间问题，下溢是逻辑问题 |
| 求栈长复杂度 | 顺序栈 O(1) | 链栈 O(n) | 有没有一个能直接算出个数的量 |
| 存储密度 | 顺序栈 =1 | 链栈 <1 | 结点里有多少字节不是数据 |
| 链栈 vs 单链表 | 链栈：只在表头插删，且**通常不带头结点** | 单链表：任意位置插删，**常带头结点** | 头结点存在的意义是统一"首元结点"与其他结点的插删；链栈只在表头操作，这个意义消失了 |
| 栈顶设在表头 vs 表尾 | 表头：入栈出栈均 O(1) | 表尾：出栈需找前驱，O(n) | 单链表不能从结点回退到前驱 |

## 本节小结

学完本篇，你应该能够：

- 写出链栈的结点定义，并解释**为什么栈顶必须设在表头**（表尾出栈要找前驱，单链表做不到 O(1)）；
- 解释链栈为什么**通常不设头结点**——头结点的价值在于统一首元结点与其他结点的插删， 而链栈只在表头操作，这个价值不存在；
- 完整写出不带头结点的 `InitStack` / `StackEmpty` / `Push` / `Pop` / `GetTop`， 并说清两个易错点：入栈两步不能颠倒（否则自环）、出栈必须留临时指针（否则泄漏）；
- 把同一组函数改写成带头结点的版本，并同步改掉判空条件与参数类型；
- 区分**上溢**（顺序栈专有）与**下溢**（两者都有），并说明链栈"不会栈满"的准确含义是 "只受堆内存限制，`malloc` 失败才失败"；
- 计算存储密度并据此判断"链式一定更省空间"这句话错在哪里。

三个最关键的结论：

- **栈顶在表头是效率决定的**，不是约定俗成；
- **链栈判空条件随"带不带头结点"变化**，它必须与初始化保持同一口径；
- **链栈没有上溢但有下溢**，且求栈长是 O(n)——这两点是与顺序栈对比时最容易答错的。
