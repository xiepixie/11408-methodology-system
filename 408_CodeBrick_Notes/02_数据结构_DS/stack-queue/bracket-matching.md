# 括号匹配

## 大纲定位

这一条目由四篇分担，本篇负责**最基础的那一个栈应用**：只用一个栈、只做入栈与出栈比较。 另外三篇是《[表达式求值](./expression-eval.html)》（栈里存的东西有优先级）、 《[栈在递归中的应用](./recursion.html)》（栈由系统隐式维护）、《[双端队列](./deque.html)》（放松限制）。

本篇用到的顺序栈实现见《[顺序栈](./sequential-stack.html)》，栈的 LIFO 性质见 《[栈和队列的基本概念](./concepts.html)》，两者都不在本篇重复。

## 知识框架

## 为什么必须用栈

括号的嵌套规则要求"**最后出现的左括号最先被匹配**"，这与栈的弹出顺序完全一致。

严蔚敏教材给出了一个很好的直觉解释：把每个未匹配的左括号看成一份"**期待**"。 计算机接受第一个左括号后，期待着与它匹配的右括号出现；但如果等来的是第二个左括号， 说明"第二个括号的期待急迫性**高于**第一个"，于是第一个只能暂时靠边； 第三个左括号来了，第二个又要让位……**每读入一个左括号，栈中所有未消解的期待急迫性都降一级**； 每读入一个右括号，**栈顶那份最急迫的期待或者被消解，或者说明输入不合法**。

"急迫性最高的最先被处理"就是 LIFO，所以承载它的只能是栈。

**反过来问：能不能不用栈？** 如果**只有一种括号**（比如只有圆括号）， 可以用一个计数器代替：遇 `(` 加一、遇 `)` 减一，中途出现负数就是右括号多余， 结束时不为零就是左括号多余。但**只要有两种以上括号**，计数器就不够了—— 它记不住"当前最内层是哪一种"，无法判定 `{[)}` 这种类型交叉的错误。 **栈之所以必要，是因为要记住嵌套的"类型序列"，而不只是"个数"。** 这是本篇最值得带走的一句话。

## 算法思路

- 初始化一个空栈；
- 从左到右依次扫描表达式中的每个字符；
- 遇到**左括号** `(`、`[`、`{`：压入栈；
- 遇到**右括号** `)`、`]`、`}`：

- 若栈为空 → 右括号多余，**匹配失败**；
- 若栈非空 → 弹出栈顶元素，检查是否与当前右括号配对；不配对则**匹配失败**；
- 其他字符一律跳过（真实表达式里还有操作数和运算符）；
- 扫描结束后：栈为空 → **匹配成功**；栈非空 → 还有未消解的左括号，**匹配失败**。

## 匹配过程详解

以 `{[()]}` 为例：

| 步骤 | 当前字符 | 动作 | 栈内容（栈底→栈顶） |
| --- | --- | --- | --- |
| 1 | `{` | 左括号，入栈 | `{` |
| 2 | `[` | 左括号，入栈 | `{ [` |
| 3 | `(` | 左括号，入栈 | `{ [ (` |
| 4 | `)` | 右括号，弹出 `(`，类型配对 ✓ | `{ [` |
| 5 | `]` | 右括号，弹出 `[`，类型配对 ✓ | `{` |
| 6 | `}` | 右括号，弹出 `{`，类型配对 ✓ | 空 |

扫描结束，栈为空 → 匹配成功。

**栈的最大深度是 3**，等于表达式的**最大嵌套层数**——这个观察直接给出下面的空间复杂度。

## 三种失败情况

**失败只有三种，且检测时机各不相同**——这是本篇最容易被问到的点。

| 失败类型 | 示例 | 检测时机 | 触发的判断语句 |
| --- | --- | --- | --- |
| **类型不匹配** | `{[)}` | **弹栈比较时**（扫描中途） | `!isPaired(topChar, ch)` |
| **右括号多余** | `())` | **遇到右括号时**（扫描中途） | `top == -1` |
| **左括号多余** | `(()` | **扫描结束后** | `return top == -1` |

三种情况的逐步执行：

**`{[)}`（类型不匹配）**：`{` 入栈 → `[` 入栈（栈 `{ [`）→ 读到 `)`，栈非空， 弹出 `[`，而 `[` 与 `)` 不配对 → 在**第 3 个字符**处失败。

**`())`（右括号多余）**：`(` 入栈 → 读到 `)`，弹出 `(` 配对 ✓，栈空 → 再读到 `)`，**栈已空** → 在**第 3 个字符**处失败。

**`(()`（左括号多余）**：`(` 入栈 → `(` 入栈（栈 `( (`）→ 读到 `)`，弹出配对 ✓（栈 `(`）→ 扫描结束，**栈非空** → 在**扫描结束后**才发现失败。

**判别依据**：前两种在扫描过程中就能立刻返回失败，**第三种必须等到扫描结束**—— 因为在读完最后一个字符之前，你无法确定后面还会不会来右括号。 凡是问"哪一种失败不能在扫描过程中发现"，答案就是**左括号多余**。

## 代码实现
c

```
#include <stdbool.h>
#define MAX_SIZE 100

// 判断一对括号是否配对；必须定义在 bracketMatch 之前（或先给出函数声明）
bool isPaired(char left, char right) {
    return (left == '(' && right == ')')
        || (left == '[' && right == ']')
        || (left == '{' && right == '}');
}

bool bracketMatch(const char *str) {
    char stack[MAX_SIZE];
    int top = -1;                        // 顺序栈，top 指向栈顶元素

    for (int i = 0; str[i] != '\0'; i++) {
        char ch = str[i];

        if (ch == '(' || ch == '[' || ch == '{') {
            if (top == MAX_SIZE - 1)     // 栈满：嵌套层数超出容量
                return false;            // 顺序栈实现绕不开这一步
            stack[++top] = ch;           // 左括号入栈（前缀 ++，先移后写）
        }
        else if (ch == ')' || ch == ']' || ch == '}') {
            if (top == -1)               // 失败 2：右括号多余（栈空还要 pop）
                return false;
            char topChar = stack[top--]; // 弹栈（后缀 --，先取后移）
            if (!isPaired(topChar, ch))  // 失败 1：类型不匹配
                return false;
        }
        // 其他字符直接跳过
    }
    return top == -1;                    // 失败 3：栈非空说明左括号多余
}
```

三处值得注意：

- **`if (top == -1) return false;` 必须在弹栈之前**。如果先写 `stack[top--]` 再判断， 空栈时会读 `stack[-1]`——**越界读**，而且 `top` 还被改成了 −2。 这是"空栈时 pop"这条前置条件在代码上的体现；
- **栈满检查**是顺序栈实现必须带的。嵌套层数超过 `MAX_SIZE` 时若不检查就会越界写。 若换成《[链栈](./linked-stack.html)》实现则不需要这一句，只需检查 `malloc` 是否成功；
- **`isPaired` 要先定义或先声明**。C99 之后不允许隐式声明函数， 把它写在 `bracketMatch` 后面而又不给原型，编译不通过。

### 含其他字符的完整跟踪

真实表达式里还有操作数与运算符，它们一律跳过。以 `a * (b + [c - d]) / e` 为例：

| 步 | 字符 | 类别 | 动作 | 栈（底→顶） |
| --- | --- | --- | --- | --- |
| 1 | `a` | 其他 | 跳过 | 空 |
| 2 | `*` | 其他 | 跳过 | 空 |
| 3 | `(` | 左括号 | 入栈 | `(` |
| 4 | `b` | 其他 | 跳过 | `(` |
| 5 | `+` | 其他 | 跳过 | `(` |
| 6 | `[` | 左括号 | 入栈 | `( [` |
| 7 | `c` | 其他 | 跳过 | `( [` |
| 8 | `-` | 其他 | 跳过 | `( [` |
| 9 | `d` | 其他 | 跳过 | `( [` |
| 10 | `]` | 右括号 | 弹出 `[`，配对 ✓ | `(` |
| 11 | `)` | 右括号 | 弹出 `(`，配对 ✓ | 空 |
| 12 | `/` `e` | 其他 | 跳过 | 空 |

扫描结束、栈空 → 匹配成功。**栈的最大深度是 2**，出现在第 6 ∼ 9 步， 等于该表达式的最大括号嵌套层数 ✓。

**常见追问：`a * (b + [c - d)] / e` 会在哪一步失败？** 第 10 个字符是 `)`， 此时栈顶是 `[`，`isPaired('[', ')')` 为假 → **类型不匹配**，在第 10 个字符处失败。 注意它**不是**"右括号多余"——栈并不空。三种失败类型必须按触发的判断语句来区分。

### 用链栈实现（对照）

把数组换成《[链栈](./linked-stack.html)》后，唯一消失的是**栈满检查**：c

```
typedef struct SNode {
    char data;
    struct SNode *next;
} SNode;

bool bracketMatch_Link(const char *str) {
    SNode *top = NULL;                       // 不带头结点，NULL 即空栈
    bool ok = true;

    for (int i = 0; str[i] != '\0' && ok; i++) {
        char ch = str[i];
        if (ch == '(' || ch == '[' || ch == '{') {
            SNode *s = (SNode *)malloc(sizeof(SNode));
            if (s == NULL) { ok = false; break; }   // 取代"栈满"的失败来源
            s->data = ch; s->next = top; top = s;   // 头插入栈
        } else if (ch == ')' || ch == ']' || ch == '}') {
            if (top == NULL) { ok = false; break; } // 失败 2：右括号多余
            SNode *p = top;
            char topChar = p->data;
            top = p->next;
            free(p);
            if (!isPaired(topChar, ch)) { ok = false; break; }  // 失败 1
        }
    }
    if (ok && top != NULL) ok = false;       // 失败 3：左括号多余
    while (top != NULL) {                    // 提前退出时也要清干净，避免泄漏
        SNode *p = top; top = p->next; free(p);
    }
    return ok;
}
```

**多出来的那个 `while` 清栈循环值得注意**：数组版直接 `return false` 就完事， 链栈版**中途失败时栈里还挂着若干结点**，不释放就泄漏。 **这是链式实现相对顺序实现多出来的一项责任**，代码题里容易漏。

## 复杂度分析

| 指标 | 复杂度 | 来历 |
| --- | --- | --- |
| 时间 | O(n) | 每个字符**恰好被扫描一次**；每个左括号入栈一次、最多出栈一次，入栈出栈都是 O(1)。总操作数 ≤3n，故 O(n) |
| 空间 | O(n) | 栈的最大深度 = **表达式的最大嵌套层数**。最坏情形是全为左括号（如 `(((...(`），深度达到 n，故 O(n)；若嵌套层数有常数上界，实际只需 O(1) |

**空间复杂度的最坏情形值得说清楚**：不是"平均要 n 格"，而是**存在**一种输入 （全左括号）使栈深达到 n。像 `()()()...()` 这种同样长为 n 的输入，栈深始终不超过 1。 **复杂度写 O(n) 是因为要覆盖最坏情形。**

## 变体与推广

| 变体 | 还能用栈吗 | 关键差别 |
| --- | --- | --- |
| 只有一种括号 | 可以，但**栈可退化为一个计数器** | 不需要记类型，只需记个数 |
| 三种括号（本篇） | **必须用栈** | 要记住嵌套的类型序列 |
| 表达式里混有操作数与运算符 | 用栈，非括号字符跳过 | 与《[表达式求值](./expression-eval.html)》里"遇 `)` 弹到 `(` 为止"是同一机制 |
| XML / HTML 标签匹配 | 用栈，栈里存标签名 | 配对判断从"字符配对"变成"字符串相等" |
| 编译器的语法分析 | 用栈 | 括号匹配是它最简化的模型 |

**和表达式求值的联系**：中缀转后缀时"遇到 `)` 就不断弹出并输出，直到遇见 `(`"， 本质上就是在做一次括号匹配——只不过弹出的东西还要输出。两篇的栈操作可以互相印证。

## 易混淆知识点

| 对比项 | 情况 A | 情况 B | 判别依据 |
| --- | --- | --- | --- |
| 三种失败的检测时机 | 类型不匹配、右括号多余：**扫描中途**即可判定 | 左括号多余：**必须扫描结束**才能判定 | 读完最后一个字符前，无法确定后面还会不会来右括号 |
| 判空与弹栈的顺序 | 正确：先 `if (top == -1)` 再弹 | 错误：先弹再判 → 读 `stack[-1]`，且 `top` 变成 −2 | "空栈时 pop"违反 `Pop` 的前置条件 |
| 用栈 vs 用计数器 | 多种括号：**必须用栈** | 单一种括号：计数器足够 | 是否需要记住"嵌套的类型序列"而不只是个数 |
| 空间复杂度 | O(n)（最坏：全左括号） | 不是"总是 n" | 复杂度覆盖最坏情形；`()()()` 的栈深只有 1 |
| 栈的最大深度 | 等于**最大嵌套层数** | 不等于左括号总数 | `()()()` 有 3 个左括号但深度只有 1 |
| 匹配成功的判据 | 扫描结束且**栈空** | 只看"扫描过程中没出错" | 过程无错但栈非空 → 左括号多余，仍是失败 |
| 顺序栈实现 vs 链栈实现 | 顺序栈：要判栈满 | 链栈：只需判 `malloc` 失败 | 是否预分配了固定容量 |

## 本节小结

学完本篇，你应该能够：

- 说明括号匹配为什么用栈——把未匹配的左括号看作"期待"，急迫性最高的最先消解，正是 LIFO；
- **说清"多种括号必须用栈、单一种括号计数器就够"**，并指出栈多记住的信息是"嵌套的类型序列"；
- 完整写出括号匹配代码，包含三处边界：右括号来时先判栈空、左括号入栈前判栈满、 扫描结束后判栈空；
- 列出三种失败情况并**准确说出各自的检测时机**，指出只有"左括号多余"必须等到扫描结束；
- 给定任意表达式，画出栈的逐步变化并判定结果；
- 推导时间复杂度 O(n)（每字符扫描一次、每括号进出栈各一次）与空间复杂度 O(n) （栈深 = 最大嵌套层数，最坏为全左括号）。

三个最关键的结论：

- **栈记住的是"类型序列"，计数器只记"个数"**——这是"必须用栈"的准确理由；
- **三种失败的检测时机不同**，左括号多余只能在扫描结束时发现；
- **栈的最大深度等于最大嵌套层数**，不是左括号总数。
