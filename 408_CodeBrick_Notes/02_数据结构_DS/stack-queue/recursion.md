## 知识框架

## 什么是递归

一个函数、过程或数据结构的定义中又**直接或间接地引用了自身**，就称为递归。 用递归求解问题需要满足两个条件：

- **递归表达式**（递归步骤）：原问题能转化为一个或多个**同类型但规模更小**的子问题；
- **边界条件**（递归出口）：存在不需要再递归就能直接求解的最小规模。c

```
// 典型例子：阶乘
int Factorial(int n) {
    if (n == 0 || n == 1)          // 边界条件：递归出口
        return 1;
    return n * Factorial(n - 1);   // 递归表达式：规模减 1
}
```

严蔚敏教材把可用"分治法"递归求解的问题条件写成三条：**（1）** 能把问题转变成一个新问题， 新问题与原问题解法相同或类同，只是处理对象更小且变化有规律；**（2）** 通过这种转化能使问题简化； **（3）** 必须有一个明确的递归出口（递归的边界）。

**缺少边界条件 = 无限递归**，最终耗尽栈空间而崩溃（"栈溢出"）。 **边界条件写错**（比如上面写成 `if (n == 1)` 却传入 n=0）同样会无限递归—— 这类题目常以"下列递归函数对哪些输入不能终止"的形式出现。

### 递归的数据结构

不只算法可以递归，**数据结构本身也可以是递归定义的**：链表结点 `LNode` 的定义里 `next` 指针又指向 `LNode`；二叉树的定义是"空树，或由根和两棵**二叉树**组成"。 **数据结构是递归的，它的操作就天然适合用递归描述**——这是二叉树遍历、图的 DFS 全部写成递归的根本原因，也是本篇能被后面反复复用的原因。

## 递归的执行机制：递归工作栈

### 函数调用时系统做的三件事

在一个函数运行期间调用另一个函数，**在执行被调用函数之前**，系统需要先完成三件事：

- **保存返回地址**——记住被调函数结束后回到调用函数的哪一条指令；
- **保存调用函数的现场**——寄存器、局部变量等，以便返回后恢复；
- **传递实参**，并为被调函数分配它自己的局部变量空间。

被调函数返回时则反过来：恢复现场、按返回地址跳回、释放被调函数占用的空间。

这一套"后调用的先返回"的次序，**恰好是 LIFO**——所以承载它的数据结构只能是栈。

### 活动记录（栈帧）里有什么

图源：殷人昆《数据结构——用面向对象方法与 C++ 描述》（第 2 版）图3.11 函数递归调用时的活动记录，p105

图的左半边说明"调用—返回"是一对**成对出现的跳转**：控制流从调用点跳进被调函数， 返回时必须回到**调用点的下一条指令**——这个地址不记下来就回不去。 右半边是一条**活动记录**（严蔚敏教材称"工作记录"）的三个组成部分：

| 组成 | 作用 | 为什么必须每层一份 |
| --- | --- | --- |
| **返回地址** | 本层执行完回到哪里 | 不同层的调用点不同（可能同一处，但返回后要继续的上下文不同） |
| **局部变量** | 本层自己的临时数据 | 各层的同名局部变量是**互相独立的副本**，改一层不影响另一层 |
| **实参副本** | 本次调用传入的参数值 | 每层的 n 不同，共用一份就全乱了 |

系统为整个递归函数的运行期设立一个**递归工作栈**： **每进入一层递归就产生一个新的工作记录压入栈顶，每退出一层就从栈顶弹出一个**。 当前正在执行的那一层，其工作记录必定位于栈顶，称为**活动记录**。

### 跟踪一次完整的递归

调用 `Factorial(4)`（约定主函数为第 0 层）：text

```
调用过程（逐层压栈）              返回过程（逐层弹栈）
┌───────────────┐                ┌───────────────────┐
│ Fact(1) 第4层 │ ← 栈顶         │ return 1          │ → 弹出
├───────────────┤                ├───────────────────┤
│ Fact(2) 第3层 │                │ return 2*1  = 2   │ → 弹出
├───────────────┤                ├───────────────────┤
│ Fact(3) 第2层 │                │ return 3*2  = 6   │ → 弹出
├───────────────┤                ├───────────────────┤
│ Fact(4) 第1层 │ ← 栈底         │ return 4*6  = 24  │ → 弹出
└───────────────┘                └───────────────────┘
                                  最终结果：24
```

**最大栈深是 4**（n 层），任意时刻栈中最多同时存在 4 条工作记录。 这个数字就是下面空间复杂度分析的全部依据。

## 复杂度分析：递归特有的两条

### 时间复杂度：解递归方程

把"一次调用自身以外的工作量"记作常数 C，就能列出递归方程并**逐层展开**。以阶乘为例：T(n)=C+T(n−1)

用 n−1 代入自身：T(n−1)=C+T(n−2)，回代得 T(n)=2C+T(n−2)； 继续得 T(n)=3C+T(n−3)；一般地 T(n)=iC+T(n−i)。取 i=n：T(n)=nC+T(0)=nC+D⟹T(n)=O(n)

**这就是递归时间复杂度的标准做法：列方程 → 展开到边界 → 数一共展开了几层。**

三个必须记住来历（而不是结论）的例子：

| 递归 | 递归方程 | 展开后 | 时间复杂度 |
| --- | --- | --- | --- |
| 阶乘 `Fact(n)` | T(n)=T(n−1)+C | 展开 n 层，每层 O(1) | O(n) |
| Fibonacci 朴素递归 | T(n)=T(n−1)+T(n−2)+C | 调用树每层结点数约翻倍，共 n 层 | O(2n) |
| 汉诺塔 `Hanoi(n)` | T(n)=2T(n−1)+C | T(n)=2nC−C，移动次数 2n−1 | O(2n) |

**汉诺塔的递归结构值得单独看一眼**，因为它是"一次调用里有两处递归"的最小例子：c

```
// 把塔座 A 上的 n 个圆盘按规则搬到 C 上，B 做辅助塔
void Hanoi(int n, char A, char B, char C) {
    if (n == 1) {
        move(A, 1, C);              // 边界：直接把 1 号盘从 A 移到 C
    } else {
        Hanoi(n - 1, A, C, B);      // ① 把上面 n-1 个从 A 搬到 B，C 做辅助
        move(A, n, C);              // ② 把最大的第 n 个从 A 搬到 C
        Hanoi(n - 1, B, A, C);      // ③ 把那 n-1 个从 B 搬到 C，A 做辅助
    }
}
```

- **移动次数** M(n)=2M(n−1)+1，M(1)=1。逐层展开： M(n)=2n−1M(1)+(2n−2+⋯+2+1)=2n−1+2n−1−1=2n−1。 时间复杂度 O(2n)；
- **递归深度**：① 和 ③ 是**先后**执行的，不是同时——③ 开始时 ① 的所有栈帧早已弹出。 所以任意时刻栈中只有从根到当前结点这一条路径，深度为 n，**空间复杂度 O(n)**。

**这正是"调用次数 ≠ 递归深度"的最佳例证**：调用次数 2n−1 是指数级， 空间却只有线性。理解这一点，后面分析树与图的递归算法就不会再把两者混起来。

Fibonacci 慢的原因不是"递归本身慢"，而是**同一个子问题被反复求解**：text

```
Fibonacci(5) 的递归调用树——F(3) 算了 2 次，F(2) 算了 3 次：

           F(5)
          /    \
       F(4)    F(3)
       / \     / \
    F(3) F(2) F(2) F(1)
    / \
 F(2) F(1)
```

调用树的结点总数是指数级，而**用循环自底向上算只需 O(n)**——差距全在重复计算上。 把中间结果存下来（记忆化）同样能降到 O(n)，这说明**递归的开销来自"重复的子问题"， 不是来自"函数调用"本身**。

### 空间复杂度：等于递归深度，不是调用次数

递归函数执行时，系统要用递归工作栈存放每一层的工作记录，**这个工作栈就是递归算法的辅助空间**。 所以：S(n)=O(f(n)),f(n)=递归工作栈中工作记录个数的最大值

而"工作记录个数的最大值"就是**最大递归深度**（同时存在的栈帧数）， **不是调用的总次数**——因为一层返回后它的栈帧立刻被弹出、空间被复用。

| 递归 | 调用总次数 | **最大递归深度** | 空间复杂度 |
| --- | --- | --- | --- |
| 阶乘 `Fact(n)` | n | n | O(n) |
| Fibonacci 朴素递归 | O(2n) | **n−1** | O(n) |
| 汉诺塔 `Hanoi(n)` | 2n−1 | n | O(n) |

Fibonacci 那一行是最能说明问题的：**调用次数是指数级，空间却只有 O(n)**。 原因是调用树是**深度优先**展开的——任何时刻，从根到当前结点这一条路径上的栈帧才同时存在， 兄弟子树的栈帧早已弹出。

**这条结论会在后面反复用到**：

- 二叉树的递归遍历：递归深度 = 树高 h，空间 O(h)；最坏（单支树）h=n，退化为 O(n)； 平衡时 h=O(log⁡n)；
- 图的 DFS 递归：递归深度 = 搜索路径最大长度，最坏 O(|V|)；
- 快速排序：递归深度平均 O(log⁡n)、**最坏 O(n)**（每次划分极不平衡时）， 所以它的空间复杂度是 O(log⁡n) 平均、O(n) 最坏；
- 归并排序：递归深度恒为 O(log⁡n)，但因为还要 O(n) 的辅助数组，总空间是 O(n)。

每次看到"某递归算法空间复杂度是多少"，**先问递归深度，再问有没有额外的辅助数组**。

## 递归转非递归

### 为什么要转

三个理由，考试里都可能被问到：

- **避免栈溢出**：系统栈容量有限，递归深度过大（如 n 取十万级的线性递归）会直接崩溃；
- **消除重复计算**：如 Fibonacci，改成迭代后从 O(2n) 降到 O(n)；
- **减少调用开销**：每次调用都要压栈、传参、跳转，常数因子不小。

### 方式一：用显式栈模拟（通用）

适用于**分支递归**（一次调用里有两处以上递归调用，如树的遍历、图的 DFS）， 这类递归**不能只用简单循环替代**。做法是：用一个显式栈保存"待处理的状态"， 手动完成系统栈本来会做的事。

模板（以二叉树中序遍历为例，它是这一类的标准形态）：c

```
// 中序遍历的非递归实现：显式栈模拟系统栈
void InOrder(BiTree T) {
    BiTree stack[MaxSize];  int top = -1;   // 显式栈
    BiTree p = T;
    while (p != NULL || top != -1) {        // 还有结点没访问，或栈里还有待返回的结点
        if (p != NULL) {
            stack[++top] = p;               // 相当于"压入本层工作记录"
            p = p->lchild;                  // 相当于"递归进入左子树"
        } else {
            p = stack[top--];               // 相当于"左子树返回，弹出本层记录"
            visit(p);                       // 访问根
            p = p->rchild;                  // 相当于"递归进入右子树"
        }
    }
}
```

**对应关系值得记住**：显式栈里存的是"还没处理完的结点"，正对应系统栈里"还没返回的层"； `stack[++top] = p` 对应压入工作记录，`p = stack[top--]` 对应返回上一层。 **手写的栈只存必要状态（这里只有一个结点指针），比系统栈的完整工作记录省得多**—— 这也是显式栈版本通常更快的原因。

再看一个"用栈模拟"的最小例子（阶乘本身不需要栈，这里只为看清模拟过程）：c

```
// 用显式栈模拟递归实现阶乘（示意用途）
int Factorial_NonRecursive(int n) {
    int stack[100], top = -1;
    int result = 1;
    while (n > 1)               // 入栈阶段：模拟逐层递归调用
        stack[++top] = n--;
    while (top >= 0)            // 出栈阶段：模拟逐层递归返回
        result *= stack[top--];
    return result;
}
```

代入 n=4：入栈 4、3、2（`n` 变为 1），出栈依次乘得 2×3×4=24 ✓； n=1 或 n=0 时两个循环都不执行，返回 1 ✓（与 0!=1!=1 一致）。

### 方式二：直接改写成迭代

适用于**尾递归**和**线性递归**——递归调用的结果不再参与后续运算，或每层只有一处递归调用 且状态可以用有限个变量携带。c

```
// Fibonacci：迭代替代递归，O(2^n) → O(n) 时间，O(n) → O(1) 空间
int Fibonacci(int n) {
    if (n <= 1) return n;
    int a = 0, b = 1, c;
    for (int i = 2; i <= n; i++) {
        c = a + b;   // c = F(i)
        a = b;       // a = F(i-1)
        b = c;       // b = F(i)
    }
    return b;
}
```

这次改写同时降了**时间**（消除重复子问题）和**空间**（不再需要 O(n) 的栈帧， 只用 3 个变量）。**注意两者是分别降的**：显式栈模拟只降常数和栈溢出风险， **不降**渐进时间复杂度；只有消除了重复子问题才降时间。

**不是所有递归都能只用循环替代。** 树的遍历、图的 DFS 这类递归中， "回到上一层继续处理右子树"这件事必须记住一个**任意深度**的路径， 有限个变量装不下，**必须用显式栈**。这一点在考题里常以"下列哪个递归算法不能不用栈改写成迭代" 的形式出现。

## 易混淆知识点

| 对比项 | 情况 A | 情况 B | 判别依据 |
| --- | --- | --- | --- |
| 空间复杂度 | **最大递归深度**（同时存在的栈帧数） | 调用总次数 | 返回后栈帧立即弹出、空间被复用；Fibonacci 调用 O(2n) 次但空间只有 O(n) |
| 递归深度 vs 时间复杂度 | 深度看**一条路径有多长** | 时间看**调用树有多少结点** | 汉诺塔深度 n、结点 2n−1，两者可以差指数级 |
| 递归慢的原因 | 重复子问题（Fibonacci） | 函数调用开销 | 前者改变渐进复杂度，后者只影响常数因子 |
| 显式栈 vs 迭代 | 显式栈：分支递归（树、图）必须用 | 迭代：尾递归/线性递归可用 | 需要记住的"待返回状态"个数是否有界 |
| 转非递归降不降复杂度 | 显式栈：**时间渐进不变**，省常数与栈溢出风险 | 记忆化/迭代重排：可把 O(2n) 降到 O(n) | 是否消除了重复计算 |
| "栈溢出" vs "栈空下溢" | 栈溢出：递归太深，**系统栈**空间耗尽 | 下溢：对空栈执行 `Pop` | 一个是空间耗尽，一个是逻辑错误 |
| 递归工作栈 vs 自己写的栈 | 系统栈：每层存完整工作记录（返回地址 + 局部变量 + 实参） | 显式栈：只存你需要的那几个量 | 显式栈通常更省，因为不必保存返回地址 |
| 边界条件写法 | 边界写成 `if (n <= 1) return 1;` | 边界只写 `if (n == 1) return 1;` | 后者在 n=0 时无限递归——边界必须覆盖所有可能到达的最小规模 |

## 本节小结

学完本篇，你应该能够：

- 说出递归的两个要素，并判断一个递归函数是否会因边界条件不完整而无法终止；
- 复述函数调用前系统必须完成的三件事，并说明**为什么承载它的只能是栈**；
- 画出一条活动记录的三个组成（返回地址、局部变量、实参副本）， 并解释每层为什么必须各有一份；
- 用"列递归方程 → 逐层展开到边界"的方法求出递归算法的时间复杂度， 能独立推出阶乘 O(n)、Fibonacci O(2n)、汉诺塔 O(2n)；
- **准确回答"递归算法的空间复杂度是多少"**：等于最大递归深度，不是调用总次数； 并能立刻套用到二叉树遍历 O(h)、图 DFS O(|V|)、 快排 O(log⁡n) 平均/O(n) 最坏；
- 写出中序遍历的显式栈非递归模板，并指出栈中每个元素对应系统栈里的什么；
- 判断一个递归"能不能只用循环改写"——依据是"待返回状态的个数是否有界"。

三个最关键的结论：

- **空间复杂度 = 最大递归深度**，这是本篇迁移到树、图、排序各章时用得最多的一条；
- **时间复杂度靠解递归方程得到**，不靠记忆；调用树的结点数与深度可以差指数级；
- **分支递归必须用显式栈才能消除**，尾递归/线性递归才可以直接改成循环。
