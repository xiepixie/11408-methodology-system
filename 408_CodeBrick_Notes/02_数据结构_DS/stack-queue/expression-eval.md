# 表达式求值

## 大纲定位

本篇对应 2026 大纲 **三、栈、队列和数组 →（六）栈、队列和数组的应用**。

这一条目由四篇分担，本篇是其中**最复杂的一个栈应用**——栈里存的元素之间有**优先级关系**， 出栈时机不再由"配对"决定，而由优先级比较决定。 另外三篇是《[括号匹配](./bracket-matching.html)》（只比配对）、 《[栈在递归中的应用](./recursion.html)》（系统隐式栈）、《[双端队列](./deque.html)》（放松限制）。

**与树那一章的对接**：三种表达式（前缀/中缀/后缀）恰好对应**表达式树的先序/中序/后序遍历**， 这一层关系在本篇末尾给出，树的遍历本身见《[二叉树的中序遍历](./../tree/inorder.html)》。

## 知识框架

## 三种表达式

三者的区别只在于**运算符相对操作数的位置**：

| 类型 | 运算符位置 | 中缀 `a + b * c` 对应写法 | 需要括号吗 |
| --- | --- | --- | --- |
| **前缀**（波兰式） | 操作数**前面** | `+ a * b c` | 不需要 |
| **中缀** | 操作数**中间** | `a + b * c` | **需要**，否则无法表达 `(a+b)*c` |
| **后缀**（逆波兰式） | 操作数**后面** | `a b c * +` | 不需要 |

**为什么前缀和后缀不需要括号**：中缀表达式里，运算的先后由"优先级 + 结合性 + 括号"三者 共同决定，所以同一串符号可能有歧义；而前缀/后缀里，**每个运算符的两个操作数在位置上就被唯一确定了** （后缀是"它前面最近的两个还没被消耗的结果"），运算顺序由符号出现次序唯一确定， 不需要任何附加信息。

**三种写法的操作数顺序完全相同**（都是 `a b c`），变的只有运算符的位置—— 这是手工转换时最有用的一条检查：**转完后先核对操作数序列有没有变。**

## 优先级：栈内与栈外

中缀转后缀的核心是"**当前运算符该不该把栈里的运算符挤出来**"。 教材体系里给每个运算符定义了两个优先数：

- **栈外优先数（icp，in-coming priority）**：运算符**还在输入串里、准备进栈**时的优先级；
- **栈内优先数（isp，in-stack priority）**：运算符**已经在栈里**时的优先级。

比较规则：读到的运算符 θ2 与栈顶运算符 θ1 比， 若 isp(θ1)≥icp(θ2) 就把 θ1 弹出并输出， 继续比下一个栈顶；否则 θ2 进栈。

| 运算符 | 栈外优先级 icp（进栈时） | 栈内优先级 isp（在栈里） |
| --- | --- | --- |
| `(` | **最高** | **最低** |
| `*` `/` | 高 | 高 |
| `+` `-` | 低 | 低 |
| `)` | **最低**（从不进栈） | — |

**左括号"高进低出"不是矛盾，是两件事**：

- **栈外最高**：保证 `(` 读到时一定能进栈，不会被任何栈顶运算符挡住；
- **栈内最低**：保证它进栈后**不会被任何普通运算符弹出**——只有配对的 `)` 能把它弹掉。

这正好实现了"括号内部自成一个独立的子表达式"这件事：`(` 像一道墙， 墙内的运算符互相比较，但**永远不会越过这道墙去弹墙外的东西**。

实现时不一定真的写两张优先级表。下面的代码用一个 `priority()` 函数（`*`/`/` 为 2、 `+`/`-` 为 1、`(` 为 0），并在弹栈循环里额外加上 `stack[top] != '('` 这个条件—— 效果与"栈内 `(` 优先级最低"完全等价，而且更不容易写错。

## 中缀转后缀

### 算法步骤

从左到右扫描中缀表达式，借助一个**运算符栈**：

- 遇到**操作数**：直接输出到后缀表达式；
- 遇到 `(`：直接入栈；
- 遇到 `)`：依次弹出栈顶运算符并输出，**直到遇到 `(`**；把 `(` 弹出但**不输出**；
- 遇到**普通运算符**：把栈中优先级 **≥** 当前运算符的运算符依次弹出并输出 （遇到 `(` 就停），然后当前运算符入栈；
- 扫描结束后，把栈中剩余运算符依次弹出并输出。

### 第 4 步的 `≥` 为什么不能写成 `>`

这一步决定了**同优先级运算符的结合性**。

- 写 `≥`：读到 `+` 时，栈顶的 `-`（同优先级）**会被弹出**，于是先输出 `-`， 实现**左结合**（先算左边）；
- 写 `>`：栈顶的 `-` 不会被弹出，`+` 直接压在它上面，最后弹栈时 `+` 先输出——变成先算右边。

**具体反例**：`a - b + c`，正确结果应是 `a b - c +`（先算 a−b）。

| 扫描 | 用 `≥`（正确） | 用 `>`（错误） |
| --- | --- | --- |
| `a` | 输出 `a`；栈空 | 输出 `a`；栈空 |
| `-` | 栈空，`-` 入栈；栈 `-` | 同左 |
| `b` | 输出 `b`；输出串 `a b` | 同左 |
| `+` | 栈顶 `-` 优先级 ≥ `+`，**弹出并输出**；`+` 入栈 | 栈顶 `-` 不满足 >，**不弹**；`+` 入栈，栈 `- +` |
| `c` | 输出 `c`；输出串 `a b - c` | 输出串 `a b c` |
| 结束 | 弹 `+` → `a b - c +` ✓ | 弹 `+`、`-` → `a b c + -` ✗ |

把错误结果 `a b c + -` 求值：先算 b+c，再算 a−(b+c)——与 (a−b)+c 一般不相等 （取 a=5,b=3,c=1：正确 3，错误 1）。

**右结合的运算符要反过来**：若表达式含幂运算 `^`（右结合，232=29）， 同优先级时**不能**弹出，条件要写成严格 `>`。**判据是结合性，不是优先级本身。**

### 手算示例

把 `a + b * c - (d / e)` 转换为后缀表达式：

| 扫描元素 | 动作 | 运算符栈（底→顶） | 后缀输出 |
| --- | --- | --- | --- |
| `a` | 输出 | 空 | `a` |
| `+` | 栈空，入栈 | `+` | `a` |
| `b` | 输出 | `+` | `a b` |
| `*` | 栈顶 `+` 优先级 < `*`，不弹；入栈 | `+ *` | `a b` |
| `c` | 输出 | `+ *` | `a b c` |
| `-` | 弹 `*`（≥）、弹 `+`（≥），入栈 | `-` | `a b c * +` |
| `(` | 入栈（栈外优先级最高） | `- (` | `a b c * +` |
| `d` | 输出 | `- (` | `a b c * + d` |
| `/` | 栈顶是 `(`，停止弹出；入栈 | `- ( /` | `a b c * + d` |
| `e` | 输出 | `- ( /` | `a b c * + d e` |
| `)` | 弹 `/` 输出，弹 `(` 不输出 | `-` | `a b c * + d e /` |
| 结束 | 弹 `-` | 空 | `a b c * + d e / -` |

**结果**：`a b c * + d e / -`。

**自查两条**：① 操作数序列仍是 `a b c d e`，与原式一致 ✓； ② 运算符个数 4 个（`* + / -`），与原式一致 ✓。

### 参考代码
c

```
#include <stdbool.h>
#define MAX_SIZE 100

int priority(char op) {
    if (op == '*' || op == '/') return 2;
    if (op == '+' || op == '-') return 1;
    return 0;                       // '(' 及其他
}

bool isOperand(char ch) {
    return (ch >= 'a' && ch <= 'z') || (ch >= 'A' && ch <= 'Z')
        || (ch >= '0' && ch <= '9');
}

// 中缀转后缀。infix：输入串；postfix：输出串（调用方保证空间足够）
void infixToPostfix(const char *infix, char *postfix) {
    char stack[MAX_SIZE];
    int top = -1;                   // 运算符栈
    int j = 0;                      // postfix 的写入位置

    for (int i = 0; infix[i] != '\0'; i++) {
        char ch = infix[i];

        if (isOperand(ch)) {
            postfix[j++] = ch;                       // 操作数直接输出
        } else if (ch == '(') {
            stack[++top] = ch;                       // 左括号直接入栈
        } else if (ch == ')') {
            while (top >= 0 && stack[top] != '(')    // 弹到左括号为止
                postfix[j++] = stack[top--];
            if (top >= 0) top--;                     // 弹出 '(' 但不输出
        } else {
            // 普通运算符：弹出优先级 >= 当前运算符的栈顶元素，遇 '(' 停
            while (top >= 0 && stack[top] != '(' &&
                   priority(stack[top]) >= priority(ch))
                postfix[j++] = stack[top--];
            stack[++top] = ch;
        }
    }
    while (top >= 0)                                 // 弹出剩余运算符
        postfix[j++] = stack[top--];
    postfix[j] = '\0';
}
```

**`if (top >= 0) top--;` 这一句**：正常的合法表达式里，遇到 `)` 时栈中一定有配对的 `(`， 循环会停在它上面。但若输入是 `a)` 这种右括号多余的非法串，循环会因 `top < 0` 退出， 此时再无条件 `top--` 就会把 `top` 变成 −2，后续入栈写到 `stack[-1]`。 **加上判断相当于顺手做了一次《[括号匹配](./bracket-matching.html)》里的"右括号多余"检查。**

## 后缀表达式求值

### 算法步骤

从左到右扫描后缀表达式，使用一个**操作数栈**：

- 遇到**操作数**：压入栈；
- 遇到**运算符**：弹出栈顶两个操作数——**先弹出的是右操作数**，后弹出的是左操作数—— 计算后把结果压回栈；
- 扫描结束，栈顶（且是栈中唯一元素）就是结果。

### 弹出顺序为什么是"先右后左"

后缀表达式 `a b -` 表示 a−b。扫描时 `a` 先入栈、`b` 后入栈， 栈内自底向上是 `a b`，**栈顶是 `b`**。所以第一次弹出得到的是 `b`，也就是**右操作数**。

**反例**：后缀 `5 3 -` 应算 5−3=2。若弄反，得到 3−5=−2。 对 `+` 和 `*` 弄反看不出来（满足交换律），**只有 `-` 和 `/` 会暴露**， 所以出题时用的一定是减法或除法。

### 手算示例

求值 `3 4 2 * + 5 -`：

| 扫描元素 | 动作 | 操作数栈（底→顶） |
| --- | --- | --- |
| `3` | 入栈 | `3` |
| `4` | 入栈 | `3 4` |
| `2` | 入栈 | `3 4 2` |
| `*` | 弹右 `2`、弹左 `4`，算 4×2=8，压回 | `3 8` |
| `+` | 弹右 `8`、弹左 `3`，算 3+8=11，压回 | `11` |
| `5` | 入栈 | `11 5` |
| `-` | 弹右 `5`、弹左 `11`，算 11−5=6，压回 | `6` |

**结果 6**（对应中缀 3+4×2−5 ✓）。

### 参考代码
c

```
#include <ctype.h>
#include <stdbool.h>

// 后缀求值。postfix 中操作数为单个数字字符；ok 返回是否合法
int evalPostfix(const char *postfix, bool *ok) {
    int stack[MAX_SIZE];
    int top = -1;
    *ok = true;

    for (int i = 0; postfix[i] != '\0'; i++) {
        char ch = postfix[i];

        if (isdigit((unsigned char)ch)) {
            if (top == MAX_SIZE - 1) { *ok = false; return 0; }  // 栈满
            stack[++top] = ch - '0';
        } else {
            if (top < 1) { *ok = false; return 0; }  // 不足两个操作数：表达式非法
            int right = stack[top--];                // 先弹出的是右操作数
            int left  = stack[top--];
            int result = 0;
            switch (ch) {
                case '+': result = left + right; break;
                case '-': result = left - right; break;
                case '*': result = left * right; break;
                case '/':
                    if (right == 0) { *ok = false; return 0; }   // 除零
                    result = left / right; break;
                default:  *ok = false; return 0;                 // 非法字符
            }
            stack[++top] = result;
        }
    }
    if (top != 0) { *ok = false; return 0; }   // 结束时栈中应恰好剩 1 个结果
    return stack[top];
}
```

**`if (top < 1)` 这一句是本篇的边界重点**：遇到运算符时必须**保证栈中至少有两个操作数**。 以非法输入 `3 +` 为例——`3` 入栈后 `top = 0`，读到 `+` 时若不检查就连弹两次： 第一次 `right = 3`（`top` 变 −1），第二次读 `stack[-1]`，**越界读**，且 `top` 变成 −2。 **这正是"空栈时 pop"这条前置条件被违反的具体后果。**

**结束时 `top != 0` 也要判**：输入 `3 4` 扫描完栈里有两个数，说明运算符不够，同样非法。

## 中缀表达式直接求值：双栈算法

不先转后缀，而是**一趟扫描同时维护两个栈**——运算符栈与操作数栈。 规则与中缀转后缀完全一致，只是"输出运算符"改成"立刻用它算一次"。c

```
// 把栈顶两个操作数按 op 算一次，结果压回
static bool reduce(int *num, int *numTop, char op) {
    if (*numTop < 1) return false;
    int right = num[(*numTop)--];
    int left  = num[(*numTop)--];
    int res;
    switch (op) {
        case '+': res = left + right; break;
        case '-': res = left - right; break;
        case '*': res = left * right; break;
        case '/': if (right == 0) return false; res = left / right; break;
        default:  return false;
    }
    num[++(*numTop)] = res;
    return true;
}

int evalInfix(const char *s, bool *ok) {
    int  num[MAX_SIZE]; int numTop = -1;   // 操作数栈
    char op [MAX_SIZE]; int opTop  = -1;   // 运算符栈
    *ok = true;

    for (int i = 0; s[i] != '\0'; i++) {
        char ch = s[i];
        if (isdigit((unsigned char)ch)) {
            num[++numTop] = ch - '0';
        } else if (ch == '(') {
            op[++opTop] = ch;
        } else if (ch == ')') {
            while (opTop >= 0 && op[opTop] != '(')
                if (!reduce(num, &numTop, op[opTop--])) { *ok = false; return 0; }
            if (opTop < 0) { *ok = false; return 0; }   // 右括号多余
            opTop--;                                    // 弹出 '('
        } else {
            while (opTop >= 0 && op[opTop] != '(' &&
                   priority(op[opTop]) >= priority(ch))
                if (!reduce(num, &numTop, op[opTop--])) { *ok = false; return 0; }
            op[++opTop] = ch;
        }
    }
    while (opTop >= 0) {
        if (op[opTop] == '(') { *ok = false; return 0; }  // 左括号多余
        if (!reduce(num, &numTop, op[opTop--])) { *ok = false; return 0; }
    }
    if (numTop != 0) { *ok = false; return 0; }
    return num[numTop];
}
```

**与"先转后缀再求值"的区别只有一处**：那边把运算符**写到输出串**，这边**立刻拿去算**。 两者扫描逻辑逐字对应，所以只要掌握了中缀转后缀，双栈直接求值就是免费的。

## 前缀表达式的求值

前缀（波兰式）求值的方法与后缀**镜像**：**从右向左**扫描，遇操作数入栈， 遇运算符弹出栈顶两个操作数——**先弹出的是左操作数**，后弹出的是右操作数。

求值 `- + 3 * 4 2 5`（对应 3+4×2−5），从右往左扫描：

| 扫描（从右） | 动作 | 栈（底→顶） |
| --- | --- | --- |
| `5` | 入栈 | `5` |
| `2` | 入栈 | `5 2` |
| `4` | 入栈 | `5 2 4` |
| `*` | 弹左 `4`、弹右 `2`，算 4×2=8 | `5 8` |
| `3` | 入栈 | `5 8 3` |
| `+` | 弹左 `3`、弹右 `8`，算 3+8=11 | `5 11` |
| `-` | 弹左 `11`、弹右 `5`，算 11−5=6 | `6` |

结果 **6** ✓。

**一句话记牢**：后缀从左往右、**先弹的是右**；前缀从右往左、**先弹的是左**。 两处的"左右"都指**在原中缀表达式中的位置**。

## 表达式树：三种表达式的统一解释

把表达式画成二叉树：**叶结点是操作数，分支结点是运算符**， 每个运算符的左右子树就是它的左右操作数。`a + b * c` 的表达式树：text

```
        +
       / \
      a   *
         / \
        b   c
```

| 遍历方式 | 结果 | 对应 |
| --- | --- | --- |
| **先序**（根 左 右） | `+ a * b c` | **前缀表达式** |
| **中序**（左 根 右） | `a + b * c` | **中缀表达式** |
| **后序**（左 右 根） | `a b c * +` | **后缀表达式** |

**这个对应关系解释了本篇所有结论**：

- 前缀/后缀不需要括号，因为**树结构已经把运算顺序固定了**，先序/后序遍历能唯一还原这棵树；
- 中缀需要括号，因为**中序遍历会丢掉结构信息**——`(a+b)*c` 和 `a+b*c` 的中序序列 在不加括号时可能相同，光靠中序遍历无法唯一确定一棵树（这与"仅由中序序列不能唯一确定 二叉树"是同一件事）；
- 三种表达式的**操作数出现顺序都一样**，因为三种遍历访问叶结点的相对次序相同。

这一层关系在树那一章还会再用到，见《[二叉树的中序遍历](./../tree/inorder.html)》与 《[由遍历序列构造二叉树](./../tree/construct-binary-tree.html)》。

## 复杂度分析

| 算法 | 时间复杂度 | 来历 |
| --- | --- | --- |
| 中缀转后缀 | O(n) | 每个字符扫描一次；**每个运算符最多入栈一次、出栈一次**，入出栈均 O(1)，总操作数 ≤3n |
| 后缀求值 | O(n) | 单趟扫描；每个操作数入栈一次，每个运算符触发两次弹栈一次入栈，均摊 O(1) |
| 前缀求值 | O(n) | 同后缀，只是扫描方向相反 |
| 中缀直接求值 | O(n) | 两个栈各自的总入出栈次数仍与 n 同阶 |

**空间复杂度均为 O(n)**：

- 中缀转后缀：运算符栈最大深度 = 最大括号嵌套层数 + 连续未结算的运算符数，最坏 O(n) （如 `(((...(a)))...)` 或 `a*b*c*...` 之前的连续同级运算符）；
- 后缀求值：操作数栈最大深度出现在"操作数连续入栈"时，最坏 O(n)（如 `1 2 3 4 ... n + + ... +`）。

**均摊分析的说法**：不能说"每个字符 O(1)"就完事——遇到一个运算符时可能连续弹出好几个。 正确的论证是：**每个运算符一生只会被弹出一次**，所以整个过程的弹栈总次数不超过运算符个数， 摊到 n 个字符上仍是 O(n)。这种"总量有界"的论证方式在后面的图算法里还会用到。

## 易混淆知识点

| 对比项 | 情况 A | 情况 B | 判别依据 |
| --- | --- | --- | --- |
| isp 与 icp | **isp** = in-stack priority，**栈内**优先数 | **icp** = in-coming priority，**栈外/进栈**优先数 | 从英文全称判断，别靠位置记 |
| `(` 的优先级 | 栈外**最高**（保证能进栈） | 栈内**最低**（不被普通运算符弹出） | "高进低出"描述的是两个不同时刻 |
| 弹栈条件 `≥` 还是 `>` | 左结合运算符（`+ - * /`）用 **`≥`** | 右结合运算符（如 `^`）用 **`>`** | 判据是**结合性**，不是优先级高低 |
| 后缀求值弹出顺序 | **先弹的是右操作数** | 后弹的是左操作数 | 右操作数后入栈，所以在栈顶 |
| 前缀求值弹出顺序 | **先弹的是左操作数** | 后弹的是右操作数 | 从右向左扫描，左操作数后入栈 |
| 遇 `)` 时 `(` 的处理 | 弹出但**不输出** | 输出 | `(` 只是分隔标记，不参与计算 |
| 中缀转后缀 vs 中缀直接求值 | 前者把运算符**输出到串** | 后者把运算符**立刻拿去算** | 扫描逻辑完全相同，只差这一步 |
| 三种遍历与三种表达式 | 先序=前缀、后序=后缀，**可唯一还原树** | 中序=中缀，**丢括号后不能唯一还原** | 与"仅中序序列不能唯一确定二叉树"同源 |
| 空间复杂度 | 栈深最坏 O(n) | 不是"总是 O(n)" | 最坏输入才达到，如全括号嵌套或连续同级运算符 |
| 运算符栈的弹栈次数 | 总次数 ≤ 运算符个数（**每个只弹一次**） | 不是"每步 O(1)" | 用总量有界来论证 O(n) |

## 本节小结

学完本篇，你应该能够：

- 说明前缀/后缀为什么不需要括号，而中缀需要——并用**表达式树的三种遍历**给出统一解释；
- 复述 isp / icp 的英文全称与含义，解释 `(` 为什么"高进低出"；
- 完整执行中缀转后缀，写出每一步的栈状态与输出串，并用"操作数序列不变、运算符个数不变"自查；
- **说清第 4 步的 `≥` 为什么不能改成 `>`**，并给出反例 `a - b + c` 的两种结果与数值差异； 同时知道右结合运算符要改回 `>`；
- 执行后缀求值与前缀求值，**准确回答两者的弹出顺序为什么相反**；
- 写出中缀直接求值的双栈算法，并指出它与"转后缀"的唯一差别；
- 在代码里正确处理三处边界：遇运算符时栈中操作数不足、遇 `)` 时找不到 `(`、 扫描结束时栈中剩余元素个数不对；
- 用"每个运算符一生只弹出一次"这种**总量有界**的论证给出 O(n) 的来历。

三个最关键的结论：

- **`≥` 保证左结合**，改成 `>` 会把 `a-b+c` 算成 `a-(b+c)`；
- **后缀先弹右、前缀先弹左**，减法除法才会暴露顺序错误；
- **三种表达式 = 表达式树的三种遍历**，中缀丢括号后不能唯一还原树。
