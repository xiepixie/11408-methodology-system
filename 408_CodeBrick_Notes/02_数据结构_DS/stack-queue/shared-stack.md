# 共享栈

## 大纲定位

本篇对应 2026 大纲 **三、栈、队列和数组 →（二）栈和队列的顺序存储结构**。

这一条目由三篇分担，本篇负责其中的**空间共享方案**：

- 单个顺序栈的指针约定、入栈出栈的先后顺序在《[顺序栈](./sequential-stack.html)》里已经建立， **本篇默认你已掌握那些内容**，只讲"两个栈挤在一个数组里"之后哪些结论要改写；
- 队列的顺序存储（假溢出与队空队满判别）在《[循环队列](./circular-queue.html)》里；

## 知识框架

## 为什么需要共享栈

假设程序里要同时用两个栈，总共最多存 M 个元素。两种方案：

| 方案 | 何时上溢 | 空间利用 |
| --- | --- | --- |
| 两个**独立**顺序栈，各分配 M/2 | **任一个栈**的元素数超过 M/2 就上溢 | 差：一个满了另一个可能还空着一大半 |
| **共享栈**，共用 M 个单元 | **两个栈元素数之和**超过 M 才上溢 | 好：一个栈可以占用远超一半的空间 |

举个具体数字：M=100，某时刻栈 1 有 70 个元素、栈 2 有 20 个。

- 独立方案：栈 1 早在第 51 个元素时就上溢了，此时栈 2 那边还空着 30 个单元**却借不出来**；
- 共享方案：共 90 个元素 <100，一切正常，还能再入栈 10 个。

**共享栈成立的前提是两个栈"此消彼长"**——一个用得多时另一个用得少。 如果两个栈同时增长到接近 M/2，共享栈的优势就消失了（但也不会比独立方案更差）。

注意共享栈**并没有增加总空间**，它只是把"哪个栈用多少"的决定权从编译期推迟到了运行期。 这是典型的用"延迟绑定"换灵活性。

## 核心思想

用一个大小为 `MaxSize` 的数组 `data` 同时存放两个栈：

- **栈 1**：栈底在下标 `0`，入栈时 `top1` 从左向右增长
- **栈 2**：栈底在下标 `MaxSize-1`，入栈时 `top2` 从右向左增长

两个栈相向生长，共同利用中间的空闲区：text

```
下标:  0   1   2   ...       ...  MaxSize-2  MaxSize-1
      [s1  s1  s1] → 空闲区 ← [s2  s2        s2      ]
            ↑ top1                    ↑ top2
```

数据结构定义：c

```
#define MaxSize 10

typedef struct {
    int data[MaxSize];
    int top1;  // 栈1栈顶指针，指向栈1的栈顶元素
    int top2;  // 栈2栈顶指针，指向栈2的栈顶元素
} SharedStack;

// 初始化：两个指针都放在各自"栈底的外侧"
void InitStack(SharedStack *s) {
    s->top1 = -1;           // 栈1为空：还没占用 data[0]
    s->top2 = MaxSize;      // 栈2为空：还没占用 data[MaxSize-1]
}
```

两个初值都遵循同一条约定：**`top` 指向本栈的栈顶元素，空栈时指向"栈底再往外一格"**。 栈 1 的栈底是 `0`，往外一格是 −1；栈 2 的栈底是 `MaxSize-1`，往外一格是 `MaxSize`。 两个初值不是硬记的，是从同一条约定推出来的。

## 栈满条件为什么是 `top1 + 1 == top2`

这是本篇唯一需要推导的结论，**推导比记忆重要**，因为题目常把栈 2 的约定改掉。

按上面的约定：

- 栈 1 占用了 `data[0 .. top1]`，共 `top1 + 1` 个单元；
- 栈 2 占用了 `data[top2 .. MaxSize-1]`，共 `MaxSize - top2` 个单元；
- 空闲区是 `data[top1+1 .. top2-1]`，共 `top2 - top1 - 1` 个单元。

"栈满"的含义是**空闲区大小为 0**：top2−top1−1=0⟺top1+1=top2

也就是**两个栈顶指针相邻**。三个推论：

- 此时总元素数 =(top1+1)+(MaxSize−top2)=top2+MaxSize−top2=MaxSize， **整个数组一个空位都不剩**——共享栈**不需要牺牲存储单元**（这一点与循环队列的方案一不同， 因为共享栈有两个独立指针，`top1 == top2` 这种歧义状态根本不会出现）。
- 判满**不区分是哪个栈要入栈**：只要相邻，两个栈都不能再入。
- 若误写成 `top1 == top2`，**它拦得晚了整整一步**：两针相邻（`top1 + 1 == top2`）时 该条件还不成立，于是这次入栈被放行，`++top1` 之后才变成 `top1 == top2`—— **而这一次入栈已经把对方的栈顶元素覆盖掉了**，等下一次入栈被拦住时，数据早就丢了。 所以判满必须在"相邻"这一步拦住。 （反过来说，在**正确**的实现里 `top1 == top2` 是不可达状态，因为相邻时就已经拦住了。）

### 用 `MaxSize = 4` 把边界跑一遍

初始 `top1 = -1, top2 = 4`，空闲区 4−(−1)−1=4 格。

| 操作 | top1 | top2 | 数组内容 | 判满 `top1+1==top2` |
| --- | --- | --- | --- | --- |
| 初始 | −1 | 4 | `[_ _ _ _]` | 0=4？否 |
| 栈1 压 A | 0 | 4 | `[A _ _ _]` | 1=4？否 |
| 栈2 压 X | 0 | 3 | `[A _ _ X]` | 1=3？否 |
| 栈1 压 B | 1 | 3 | `[A B _ X]` | 2=3？否 |
| 栈1 压 C | 2 | 3 | `[A B C X]` | 3=3？**是，已满** |
| 再压任何栈 | — | — | — | 拒绝入栈 |
| 栈2 弹 X | 2 | 4 | `[A B C _]` | 3=4？否，可再入栈 |

最后一行是共享栈的价值所在：**栈 2 让出一格，栈 1 立刻就能用**。这一格在独立栈方案里 是永远借不到的。

## 操作详解

### 入栈操作

入栈前必须先判断**共享空间**是否已满，然后根据栈号移动对应指针。c

```
// stackNum: 1 表示栈1，2 表示栈2
bool Push(SharedStack *s, int stackNum, int x) {
    if (s->top1 + 1 == s->top2)   // 栈满：空闲区为 0，两个栈都不能再入
        return false;
    if (stackNum == 1)
        s->data[++s->top1] = x;   // 栈1：指针右移一格到空位，再写入
    else
        s->data[--s->top2] = x;   // 栈2：指针左移一格到空位，再写入
    return true;
}
```

两个分支都是**前缀**（`++top1` / `--top2`），原因和《[顺序栈](./sequential-stack.html)》里一样： 约定是"`top` 指向栈顶**元素**"，入栈时新元素还没有位置，必须**先把指针挪到空位**再写。

**别写成后缀**：`data[top1++] = x` 是先用旧下标写入、再移指针，会把新元素写到**当前栈顶元素 身上**（把它覆盖掉）。初始 `top1 = -1` 时更直接：写入 `data[-1]`，越界。 栈 2 同理，`data[top2--] = x` 在初始 `top2 = MaxSize` 时会写 `data[MaxSize]`，也越界。 **入栈用前缀、出栈用后缀，两边刚好相反。**

### 出栈操作

出栈前先判断**对应的那个栈**是否为空——注意判空是分栈的，判满才是共同的。c

```
bool Pop(SharedStack *s, int stackNum, int *x) {
    if (stackNum == 1) {
        if (s->top1 == -1)        // 栈1空
            return false;
        *x = s->data[s->top1--];  // 后缀：先取值，再指针左移
    } else {
        if (s->top2 == MaxSize)   // 栈2空
            return false;
        *x = s->data[s->top2++];  // 后缀：先取值，再指针右移
    }
    return true;
}
```

出栈方向与入栈严格相反：栈 1 入栈右移、出栈左移；栈 2 入栈左移、出栈右移。

### 判空、判满与栈长
c

```
bool IsEmpty1(SharedStack *s) { return s->top1 == -1; }
bool IsEmpty2(SharedStack *s) { return s->top2 == MaxSize; }
bool IsFull   (SharedStack *s) { return s->top1 + 1 == s->top2; }

int  Length1(SharedStack *s) { return s->top1 + 1; }             // 栈1元素个数
int  Length2(SharedStack *s) { return MaxSize - s->top2; }       // 栈2元素个数
int  FreeCells(SharedStack *s) { return s->top2 - s->top1 - 1; } // 剩余空位
```

| 状态 | 条件 | 由什么推出 |
| --- | --- | --- |
| 栈 1 空 | `top1 == -1` | 栈 1 底在 0，空时指向底外一格 |
| 栈 2 空 | `top2 == MaxSize` | 栈 2 底在 `MaxSize-1`，空时指向底外一格 |
| 栈满（两栈共同） | `top1 + 1 == top2` | 空闲区 `top2 - top1 - 1 == 0` |
| 栈 1 长度 | `top1 + 1` | 占用 `data[0..top1]` |
| 栈 2 长度 | `MaxSize - top2` | 占用 `data[top2..MaxSize-1]` |

**栈满不等于某一个栈满**，而是两个栈的元素总数占满了整个数组。只要另一个栈让出空间， 就可以继续入栈。

## 换一种约定：`top2` 指向空位

题目常把栈 2 的约定改成"**`top2` 指向下一个入栈位置（空位）**"，初值 `top2 = MaxSize - 1`， 入栈写成 `data[top2--] = x`。此时所有结论都要重推——推法仍然是"**空闲区有多大**"：

- 栈 1 占 `data[0 .. top1]`，共 `top1 + 1` 个（约定不变）；
- 栈 2 占 `data[top2+1 .. MaxSize-1]`，共 `MaxSize - 1 - top2` 个；
- 空闲区是 `data[top1+1 .. top2]`，共 **`top2 - top1`** 个。

于是**栈满条件变成 `top1 == top2`**：

| 项 | `top2` 指元素（本篇默认） | `top2` 指空位 |
| --- | --- | --- |
| 初值 | `top1 = -1`，`top2 = MaxSize` | `top1 = -1`，`top2 = MaxSize - 1` |
| 栈 2 判空 | `top2 == MaxSize` | `top2 == MaxSize - 1` |
| 栈 2 入栈 | `data[--top2] = x`（先移后写） | `data[top2--] = x`（先写后移） |
| 栈 2 出栈 | `x = data[top2++]`（先读后移） | `x = data[++top2]`（先移后读） |
| **栈满** | **`top1 + 1 == top2`** | **`top1 == top2`** |
| 空闲区大小 | `top2 - top1 - 1` | `top2 - top1` |

**用 `MaxSize = 4` 复核第二列**：初始 `top1 = -1, top2 = 3`，空闲 3−(−1)=4 ✓； 栈 1 压 A（`top1 = 0`，空闲 3）→ 栈 2 压 X（写 `data[3]`，`top2 = 2`，空闲 2）→ 栈 1 压 B（`top1 = 1`，空闲 1）→ 栈 1 压 C（`top1 = 2`，空闲 0，`top1 == top2 == 2`，满）。 数组 `[A B C X]` 四格全用上 ✓。

**这就是为什么本篇一直强调"推导比记忆重要"**：`top1 + 1 == top2` 只是**某一种约定**下的答案。 题目改一个字，答案就变；而"空闲区大小为 0"这句话永远不变。

## 为什么只能两个栈共享

常见追问：三个栈能不能共享一个数组？

**不能用这种方式。** 共享栈之所以成立，是因为它把两个栈的栈底钉死在数组的**两个端点**上， 让它们**相向增长**——增长方向背对背，中间的空闲区被两者共享，且**每个栈的边界只有一侧会动**。 一维数组只有两个端点，第三个栈的栈底只能放在中间某处，那么它的增长就会与左右两边同时冲突， 必须引入"整体搬移"才能维持，O(1) 的入栈保证就没了。

这个问题的正确回答方式不是"因为数组只有两端"这句结论，而是"**因为需要每个栈只有一侧边界会移动**， 而一维空间里满足这一点的位置只有两个端点"。

## 复杂度分析

| 操作 | 时间复杂度 | 来历 |
| --- | --- | --- |
| 入栈 | O(1) | 一次判满比较 + 一次下标增减 + 一次写内存，与元素个数无关 |
| 出栈 | O(1) | 一次判空比较 + 一次读内存 + 一次下标增减 |
| 判空 / 判满 | O(1) | 单次整数比较 |
| 求任一栈长度 | O(1) | 由 `top1` 或 `top2` 直接算出 |

**空间复杂度**：数组固定占 O(MaxSize)；单次操作的辅助空间 O(1)。 与两个独立栈相比，**总空间不变，但发生上溢的时刻被推迟了**——量化地说： 独立方案在 max(n1,n2)>M/2 时上溢，共享方案在 n1+n2>M 时才上溢， 而 max(n1,n2)>M/2 显然比 n1+n2>M 更容易发生。

## 易混淆知识点

| 对比项 | 情况 A | 情况 B | 判别依据 |
| --- | --- | --- | --- |
| 判满 vs 判空 | 判满：`top1 + 1 == top2`，**两栈共用一个条件** | 判空：`top1 == -1` / `top2 == MaxSize`，**每个栈各自一个** | 满是"公共空闲区耗尽"，空是"本栈没有元素"，作用域不同 |
| `top1 + 1 == top2` vs `top1 == top2` | 前者是正确的判满 | 后者拦晚一步：等它成立时，越界那次写入已经发生 | 必须在"相邻"这一步拦住；正确实现下 `top1 == top2` 不可达 |
| 共享栈判满 vs 循环队列判满 | 共享栈：**不牺牲单元**，可存满 `MaxSize` 个 | 循环队列方案一：**牺牲一个单元**，最多 `MaxSize-1` 个 | 共享栈有两个独立指针不会歧义；循环队列只有 `front`/`rear` 且首尾相接，`front==rear` 二义 |
| 入栈指针写法 | 栈1 `data[++top1]`、栈2 `data[--top2]`（前缀） | 出栈 `data[top1--]`、`data[top2++]`（后缀） | `top` 指元素 → 入栈先移后写，出栈先读后移 |
| 栈 2 的"增长" | `top2` **减小**才是增长 | 直觉上以为增长就是加 | 栈 2 从高地址向低地址生长，方向与下标增大相反 |
| 共享栈 vs 两个独立栈 | 共享：n1+n2>M 才溢出 | 独立：max(n1,n2)>M/2 就溢出 | 只有"此消彼长"时共享才占优，同时暴涨时两者一样 |

## 本节小结

学完本篇，你应该能够：

- 说明共享栈解决的是什么问题，并用一组具体数字（如 M=100、n1=70、n2=20） 说清它比两个独立栈好在哪里、什么情况下没有优势；
- 从"空闲区大小 =top2−top1−1"**推出**栈满条件 `top1 + 1 == top2`， 而不是把它当作口诀记住；
- 解释为什么判满是两栈共用、判空却是各自独立；
- 写出完整的 `Push` / `Pop`，说明为什么入栈用前缀、出栈用后缀，并指出写反后 在空栈时会分别越界访问 `data[-1]` 和 `data[MaxSize]`；
- 算出任一时刻两个栈各自的元素个数与剩余空位；
- 回答"三个栈能否共享"并给出理由（每个栈需要只有一侧边界移动，一维空间只有两个端点满足）。

三个最关键的结论：

- **栈满条件 `top1 + 1 == top2` 是从"空闲区为 0"推出来的**，改约定就重推；
- **共享栈不牺牲存储单元**，可以存满 `MaxSize` 个元素——这一点常被拿来与循环队列对比；
- **判满共用、判空各自**，混淆这两者是本篇最常见的错误。
