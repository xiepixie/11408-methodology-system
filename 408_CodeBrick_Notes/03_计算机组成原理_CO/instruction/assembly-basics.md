# x86 汇编语言基础

## 大纲定位

**四（六）高级语言程序与机器级代码之间的对应** 第 1 条： **编译器、汇编器和链接器的基本概念**。

要求：说清从源程序到可执行文件的四步转换分别由谁完成、各自的输入与输出是什么，并能读懂机器级代码的基本写法——寄存器、操作数形式、常用指令与条件转移的判断依据。

选择、循环、过程调用这三类结构怎么翻译成指令序列，见 [[03_计算机组成原理_CO/instruction/machine-level-repr.md|程序的机器级表示]]。

## 知识框架

本节回答四个问题：

- 从 `.c` 到可执行文件为什么要分成四步？每一步各自解决什么问题？
- x86 的八个通用寄存器为什么名字里带着"累加器""计数器"这类历史称呼，却又说它们是通用的？
- 内存操作数已经给出了地址，为什么还必须再写一个 `dword ptr`？
- 条件转移指令那么多个助记符，背后其实只有几条判断规则？

## 一、从源程序到可执行文件：四个工具

汇编代码不是凭空出现的——它是编译器的输出、汇编器的输入。四步流水线，**每一步的输入必须是上一步的输出，顺序不能换**：

| 工具 | 输入 | 输出 |
| --- | --- | --- |
| **预处理器**（cpp） | 源程序 `.c` | 展开宏与 `#include` 之后的 `.i` |
| **编译器**（cc1） | 预处理后的源程序 | **汇编语言**程序 `.s` |
| **汇编器**（as） | 汇编语言程序 `.s` | **可重定位目标文件** `.o`（已是机器码） |
| **链接器**（ld） | 若干 `.o` + 库文件 | **可执行目标文件** |

分成四步而不是一步做完，各有各的理由：预处理是纯文本替换，与语言语义无关；编译要做语法分析与代码生成，是最重的一步；汇编是助记符到二进制的机械翻译，一一对应；链接则要跨模块解析符号并重定位地址，**必须等所有模块都编译完才能做**。

图 4.16 可重定位目标文件与静态库的链接

图里 `main.c` 经"翻译器（cpp、cc1、as）"变成 `main.o`，再和自定义静态库 `mylib.a`、标准库 `libc.a` 里取出的模块一起送进静态链接器 `ld`，最终产出完整链接的可执行文件。**链接器的输入已经全是机器码**，它只做符号解析和地址重定位，不做任何翻译工作。

**编者注（口径）**：另有一种更粗的**两级模型**——"编译程序：高级语言 → 机器目标代码"，把编译和汇编合起来说。两种划分都有人用，区别只在粒度：细粒度里编译只到 `.s`，汇编器才产生机器码。

三个名字容易混：**汇编程序**（assembler，一个翻译工具）不是**汇编语言程序**（用汇编语言写的源代码）；**解释程序**逐句解释执行，**不产生**目标代码文件。

工具链的更完整介绍见 [[03_计算机组成原理_CO/overview/system-architecture.md|计算机系统层次结构]]。

## 二、x86 通用寄存器

x86（IA-32）有 8 个 32 位通用寄存器：

| 寄存器 | 低 16 位 | 高/低 8 位 | 习惯用途 |
| --- | --- | --- | --- |
| EAX | AX | AH / AL | 累加器，**函数返回值** |
| EBX | BX | BH / BL | 基址寄存器 |
| ECX | CX | CH / CL | 计数器（循环、移位） |
| EDX | DX | DH / DL | 数据寄存器，乘除法的高半部分 |
| ESI | SI | — | 源变址寄存器 |
| EDI | DI | — | 目的变址寄存器 |
| EBP | BP | — | **基址指针**（栈帧底部） |
| ESP | SP | — | **栈指针**（栈顶） |

名字里的"累加器""计数器"是历史遗留的**习惯用途**，不是硬性限制——除 EBP、ESP 有专用功能外，其余在多数指令里可以自由使用。这些习惯之所以还活着，是因为部分指令（如乘除法、串操作）确实隐含指定了特定寄存器。

图 3.2 IA-32 的定点寄存器组

图里的位刻度说明了子寄存器是怎么嵌套的：`EAX` 是 32 位，其低 16 位叫 `AX`，`AX` 再拆成高 8 位 `AH` 与低 8 位 `AL`。所以 `mov al, 5` **只改 `EAX` 的最低字节，其余 24 位保持不变**——这套嵌套是为了兼容 16 位、8 位时代的代码而保留下来的。

图下方还有两组本篇不展开但要认得的寄存器：**EIP**（指令指针，即 PC）与 **EFLAGS**（标志寄存器，CF/ZF/SF/OF 就住在里面），以及 6 个段寄存器。

## 三、操作数与长度前缀

指令的操作数分三类：

- `<reg>`：寄存器，如 `eax`、`ebx`
- `<mem>`：内存地址，如 `[eax]`、`[ebp-8]`、`[eax+ebx*4+8]`
- `<con>`：立即数

一条硬性限制：**两个操作数不能同时是内存**。原因在数据通路上——一条指令周期内只安排了一次数据访存，两个内存操作数意味着两次访存，需要额外的时序支持。

### `dword ptr` 是干什么的

内存操作数只给出了**地址**，并没有说要按几个字节访问，所以要加一个**长度前缀**说明宽度：

| 前缀 | 访问宽度 |
| --- | --- |
| `byte ptr` | 1 字节 |
| `word ptr` | 2 字节 |
| `dword ptr` | 4 字节（双字） |
| `qword ptr` | 8 字节 |

`cmp dword ptr [ebp-0Ch], ecx` 的意思就是"把 `[ebp-0Ch]` 处的 **4 个字节**和 `ecx` 比较"。

**当另一个操作数是寄存器时，宽度已由寄存器名确定，前缀可以省略**——`mov eax, [ebp-8]` 不必写前缀，因为 `eax` 已经说明是 4 字节。只有两个操作数都无法确定宽度时（如内存与立即数），前缀才是必需的。

## 四、常用指令

以下一律使用 **Intel 格式**：目的操作数在前，源操作数在后。

### 数据传送

| 指令 | 语法 | 功能 |
| --- | --- | --- |
| mov | `mov dst, src` | 把 src 复制到 dst |
| push | `push src` | ESP −4，再把 src 写入栈顶 |
| pop | `pop dst` | 从栈顶读出送 dst，ESP +4 |
| lea | `lea dst, [addr]` | 把**有效地址**（而非该地址处的内容）送入 dst |

**为什么 `push` 是 ESP −4**：x86 的栈**向低地址增长**。栈底在高地址，压栈时栈顶指针往下走。

```
高地址  ┌──────────────┐
        │   已入栈数据   │
        ├──────────────┤
        │  ← 压栈前 ESP  │
        ├──────────────┤
        │  新压入的 4B   │  push：ESP 先 −4，再写入
        ├──────────────┤
        │  ← 压栈后 ESP  │
低地址  └──────────────┘
```

弹栈相反：先从 ESP 处读出，再 ESP +4。`call` 压入返回地址、`ret` 弹出返回地址，同样各让 ESP 变化 4。asm

```
mov eax, ebx           ; R[eax] ← R[ebx]
mov eax, [ebp+8]       ; R[eax] ← M[R[ebp]+8]
mov [ebp-4], eax       ; M[R[ebp]-4] ← R[eax]
push eax               ; ESP−4；M[ESP] ← R[eax]
pop ebx                ; R[ebx] ← M[ESP]；ESP+4
lea eax, [edx+eax*2+8] ; R[eax] ← R[edx]+R[eax]*2+8（只算地址，不访存）
```

`lea` 名义上是"取有效地址"，但它计算的是一个通用的 基址+变址×比例+位移 表达式，所以**编译器常拿它当加法和乘法用**：`lea eax, [edx+eax]` 等价于 `add eax, edx`，且**不改变标志位**——这一点在需要保住条件码时特别有用。

### 算术与逻辑运算

| 指令 | 功能 | 示例 |
| --- | --- | --- |
| add / sub | 加 / 减，结果存回第一操作数 | `add eax, 10` |
| inc / dec | 自增 / 自减 1 | `inc eax` |
| neg | 取负（补码） | `neg eax` |
| imul | 有符号乘法（两种形式，见下） | `imul eax, ebx` |
| idiv | 有符号除法，被除数为 `edx:eax` | `idiv ecx` |
| and / or / xor | 按位与 / 或 / 异或 | `and eax, 0FH` |
| not | 按位取反 | `not eax` |
| shl / shr | 逻辑左移 / 右移 | `shl eax, 1` |
| sal / sar | 算术左移 / 右移 | `sar eax, 2` |

**`edx:eax` 是什么**：两个 32 位寄存器拼成一个 **64 位**数，**EDX 存高 32 位、EAX 存低 32 位**。乘除法都要用到它。

**`imul` 的两种形式**：

| 形式 | 写法 | 结果去哪 |
| --- | --- | --- |
| 单操作数 | `imul ebx` | 完整的 64 位积落在 **`edx:eax`** |
| 双 / 三操作数 | `imul eax, ebx` | **只保留低 32 位**存回目的寄存器，高半截丢弃 |

道理很直接：n 位 × n 位最多产生 2n 位，**硬件永远算满 64 位**，只是双操作数形式把高 32 位扔了。扔掉的部分是否含有效信息，由 **OF/CF** 报告——当高 32 位不是低 32 位符号位的符号扩展时（即结果放不进 32 位），OF 与 CF 被置 1。

除法反过来：`idiv ecx` 用 `edx:eax` 这个 64 位数作被除数，**商放 EAX、余数放 EDX**。所以除法前常见一条 `cdq` 指令——把 EAX 的符号位扩展填满 EDX，先把被除数补成正确的 64 位。

**编者注（边界）**：编译器常用 `shl eax, 1` 代替乘 2、`sar eax, 2` 代替除以 4，但**"移位等价于乘除 2 的幂"只对整数（补码或无符号）成立**。IEEE 754 浮点数是"符号位 + 阶码 + 尾数"的三段结构，整体移位会破坏这个结构——浮点数乘 2 要改的是**阶码字段**，不是把整个位串左移一位。

### 控制流

| 指令 | 功能 |
| --- | --- |
| `jmp label` | 无条件转移到 label |
| `cmp a, b` | 按 a−b 置 **ZF/SF/CF/OF** 四位，**不保存差值** |
| `test a, b` | 按 a AND b 置 ZF/SF（CF、OF 清零），**不保存结果** |
| `call label` | 把返回地址压栈（ESP −4），转移到 label |
| `ret` | 弹出返回地址（ESP +4），转移回调用点 |

条件转移指令按标志位组合分成两套：

| 助记符 | 含义 | 标志条件 |
| --- | --- | --- |
| je / jz | 相等 | ZF=1 |
| jne / jnz | 不等 | ZF=0 |
| **jl** | 小于（有符号） | SF≠OF 且 ZF=0 |
| **jle** | 小于等于（有符号） | SF≠OF 或 ZF=1 |
| **jg** | 大于（有符号） | SF=OF 且 ZF=0 |
| **jge** | 大于等于（有符号） | SF=OF 或 ZF=1 |
| **jb** | 低于（无符号） | CF=1 且 ZF=0 |
| **jbe** | 低于等于（无符号） | CF=1 或 ZF=1 |
| **ja** | 高于（无符号） | CF=0 且 ZF=0 |
| **jae** | 高于等于（无符号） | CF=0 或 ZF=1 |

十条助记符背后只有两条规则：

- **有符号看 SF 与 OF 是否一致**——SF=OF 就是"大于等于"。因为 SF=OF 只对应两种情形：差为正且未溢出（SF=0,OF=0），或差为负但发生溢出（SF=1,OF=1）；后者说明真实差值本该为正，只是溢出翻转了符号位。
- **无符号看 CF**——CF 在减法里是**借位**，有借位就说明被减数小。

再叠加一条：带"等于"的，把 ZF=1 并进去。

**编者注（辨析）**：x86 减法的 CF 是**借位**（无符号 a<b 时 CF=1），不是加法器的进位输出 Cout，两者是取反关系。推导见 [[03_计算机组成原理_CO/data-repr/alu.md|ALU 与运算电路]]。asm

```
cmp  eax, ebx
jle  done        ; 若 eax <= ebx（有符号），转移到 done
test eax, eax
jz   zero_case   ; 若 eax == 0，转移
```

## 五、机器码字节数就是指令长度

x86 是**变长指令**，一条指令的机器码可能是 1 字节，也可能十来个字节。由此得到两条常用关系：下一条指令的地址=本条指令地址+本条机器码的字节数一段代码的长度=末条指令地址−首条指令地址+末条指令长度

第二条末尾那个"+ 末条指令长度"不能省。只有当末条指令恰好是 1 字节（如 `ret`，机器码 `C3`）时，它才退化成 末−首+1。

举个例子：某指令位于 `004010AE`，机器码为 `C7 84 82 00 20 42 00 0A 00 00 00`，共 11 字节，那么下一条指令的地址就是 004010AE+11=004010B9。

反过来，**相邻两条指令地址相减，得到的就是前一条指令的长度**——这是在只知道地址、看不到机器码时推算指令长度的办法。定长指令机器（如 MIPS）里这个差值恒为 4，变长指令机器里则参差不齐，这正是 [[03_计算机组成原理_CO/instruction/cisc-vs-risc.md|CISC 与 RISC]] 最外显的一处差异。

## 六、AT&T 格式与 Intel 格式

同一条机器指令有两套书写约定：

| 区别 | AT&T | Intel |
| --- | --- | --- |
| 操作数顺序 | **源, 目的** | **目的, 源** |
| 寄存器 | `%eax` | `eax` |
| 立即数 | `$100` | `100` |
| 内存引用 | `(%eax)` | `[eax]` |
| 长度标注 | 指令后缀 `movl` / `movw` / `movb` | 操作数前缀 `dword ptr` / `word ptr` / `byte ptr` |
| 复合寻址 | `8(%edx, %eax, 2)` | `[edx+eax*2+8]` |

对照几条：

| AT&T | Intel | 含义 |
| --- | --- | --- |
| `movl $100, %eax` | `mov eax, 100` | 100→R[eax] |
| `movl %eax, (%ebx)` | `mov [ebx], eax` | R[eax]→M[R[ebx]] |
| `movl %eax, -8(%ebp)` | `mov [ebp-8], eax` | R[eax]→M[R[ebp]−8] |

**两种格式描述的是完全相同的机器码**，差别纯属书写习惯。最容易出错的一处是操作数顺序——两者恰好相反，读到 `movl %eax, %ebx` 时目的是 `ebx`，而 `mov eax, ebx` 的目的是 `eax`。

## 易混淆知识点

**1. 编译器、汇编器、链接器，谁产生机器码？**

**汇编器**。四步的产物依次是：`.i`（还是文本）→ `.s`（汇编语言，还是文本）→ `.o`（**机器码**）→ 可执行文件。

链接器的输入已经是机器码，它做的是**符号解析与地址重定位**，不做翻译。编译器的输出是汇编语言，离机器码还差一步。

**2. "汇编程序"和"汇编语言程序"是一回事吗？**

不是，一个是工具，一个是代码：

| 名称 | 是什么 |
| --- | --- |
| **汇编程序**（assembler） | 一个**翻译工具**，把汇编语言翻成机器语言 |
| **汇编语言程序** | 用汇编语言写的**源代码** |

再加上第三个：**解释程序**逐句解释执行，**不产生目标代码文件**——这是它与编译程序的根本区别。

**3. `mov al, 5` 会不会把 `EAX` 的高 24 位清零？**

不会。`AL` 是 `EAX` 的最低 8 位，写它**只影响那一个字节**，其余 24 位保持原值。

同理 `mov ax, 5` 只改低 16 位。这套嵌套关系是为兼容早期代码保留的，读代码时看到 8 位、16 位寄存器名就要意识到"其余位没动"。

**4. `lea eax, [ebx]` 和 `mov eax, [ebx]` 差在哪？**

差一次访存，也差一个语义：

|  | 做什么 | 访存 | 结果 |
| --- | --- | --- | --- |
| `lea eax, [ebx]` | 算出**地址** | **否** | eax = ebx 的值 |
| `mov eax, [ebx]` | 取出该地址处的**内容** | **是** | eax = M[ebx] |

`lea` 里的方括号是地址表达式的写法，不代表要去访问那个地址。它还有一个常被利用的副作用：**不改变标志位**。

**5. `cmp` 和 `sub` 都做减法，为什么要有两条指令？**

`sub` 保存差值并置标志位；`cmp` **只置标志位、丢弃差值**。

需要保住被减数原值时就必须用 `cmp`——否则每次比较都要先复制一份操作数。`test` 与 `and` 之间是完全一样的关系。

**6. `jl` 用 SF≠OF 判断，直接看 SF 不行吗？**

不行，会在溢出时判反。SF 只报告结果的符号位，而溢出会把符号位翻转：两个大正数相减若发生溢出，真实差值为正、SF 却是 1。

引入 OF 正是为了纠正这一点：SF≠OF 才是"真实差值为负"的可靠判据。

**7. 移位能代替乘除 2 的幂吗？**

对**整数**成立，对**浮点数不成立**。IEEE 754 是三段结构，整体移位会跨越字段边界破坏格式；浮点数乘 2 要做的是**阶码加 1**。

## 本节小结

- 四步工具链：**预处理 → 编译（出 `.s`）→ 汇编（出 `.o`，此步才产生机器码）→ 链接（出可执行文件）**，每步的输入是上一步的输出
- **链接器的输入已是机器码**，它只做符号解析与地址重定位，不做翻译
- **汇编程序**是翻译工具，**汇编语言程序**是源代码，**解释程序**逐句执行且不产生目标代码文件
- x86 有 8 个 32 位通用寄存器；**EBP 是帧指针、ESP 是栈指针**，其余名字里的用途是历史习惯
- 子寄存器嵌套：写 `AL` **只改 `EAX` 的最低字节**，其余位不动
- **两个操作数不能同时是内存**；内存操作数宽度不明时必须加 `dword ptr` 之类的**长度前缀**
- **栈向低地址增长**：push / call 让 ESP −4，pop / ret 让 ESP +4
- `lea` 算的是**有效地址、不访存、不改标志位**，因此常被编译器借去做加法与乘法
- **`edx:eax`** = EDX 高 32 位 + EAX 低 32 位拼成 64 位；`imul` 单操作数形式结果落这里，双操作数形式只留低 32 位并由 OF/CF 报告是否溢出；`idiv` 商在 EAX、余数在 EDX
- `cmp` / `test` **只置标志位不保存结果**，分别对应 `sub` / `and`
- 条件转移只有两条规则：**有符号看 SF 与 OF 是否一致，无符号看 CF（借位）**；带"等于"再并上 ZF=1
- **减法的 CF 是借位**，与加法器进位输出取反
- **机器码字节数就是指令长度**；下一条地址 = 本条地址 + 字节数；代码段长度 = 末 − 首 + 末条长度
- 移位代替乘除 2 的幂**只对整数成立**，浮点要改阶码字段
- AT&T 与 Intel 描述同一份机器码，**操作数顺序恰好相反**
