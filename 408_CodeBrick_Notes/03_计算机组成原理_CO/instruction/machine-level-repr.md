# 程序的机器级表示

## 大纲定位

**四（六）高级语言程序与机器级代码之间的对应** 第 2~4 条： **选择结构语句、循环结构语句、过程（函数）调用**的机器级表示。

要求：理解 if-else、while/for、函数调用分别被翻译成什么样的指令序列，说清条件码怎么产生、条件转移怎么判断，以及栈帧的布局、参数与返回地址在栈上的位置。

第 1 条（编译器、汇编器、链接器的基本概念）与指令本身的写法见 [[03_计算机组成原理_CO/instruction/assembly-basics.md|x86 汇编语言基础]]。

## 知识框架

本节回答四个问题：

- 机器指令里没有 `if`、没有 `for`、没有"函数"，编译器靠哪几种原料把它们表示出来？
- 比较指令只置四个标志位，怎么同时支撑有符号和无符号两套大小关系？
- 三种循环语句为什么最终都能归到同一种形态？编译器为什么偏爱"先跳到判断处"？
- 一次函数调用要安顿的东西那么多，栈帧的布局为什么**必然**长成那个样子？

## 一、原料只有三样

高级语言的控制结构，在机器级只剩三样原料：

| 原料 | 指令 | 作用 |
| --- | --- | --- |
| **条件的产生** | `cmp` / `test` 以及各类运算指令 | 把比较或运算的结果写进标志位 |
| **条件的使用** | 各类条件转移指令 | 按标志位决定要不要改写 PC |
| **无条件改流** | `jmp` / `call` / `ret` | 直接改写 PC |

所有 `if`、`while`、`for`、函数调用，都是这三样原料的不同排列。理解这一点之后，机器级表示就不再是"背模板"，而是"看编译器怎么排"。

### 条件码：四个标志位

比较指令 `cmp a, b` 按 a−b 运算，**只置标志位、不保存差值**。四个标志的含义：

| 标志 | 全称 | 置位含义（按 a−b） |
| --- | --- | --- |
| **ZF** | Zero Flag | 结果为 0，即 a=b |
| **SF** | Sign Flag | 结果的符号位为 1，即结果为负 |
| **OF** | Overflow Flag | **有符号**溢出 |
| **CF** | Carry Flag | **无符号**借位，即 a<b |

有了这四位，两套比较关系就能分开表达：

- **无符号比较看 CF 和 ZF**：CF=1 说明有借位、即"小于"；ZF=1 说明相等
- **有符号比较看 SF、OF 和 ZF**：SF=OF 说明"大于等于"，SF≠OF 说明"小于"

为什么有符号要看 SF 与 OF 是否**一致**？因为 SF=OF 只可能是两种情况：两数之差为正且未溢出（SF=0,OF=0），或两数之差为负但发生了溢出（SF=1,OF=1）——后者意味着真实差值本该是正的，只是溢出把符号位翻转了。两种情况反映的都是"大于"关系。反之 SF≠OF 就是"小于"。

完整的条件转移对照表见 [[03_计算机组成原理_CO/instruction/assembly-basics.md|x86 汇编语言基础]]。

## 二、选择结构的机器级表示

`if-else` 的通用翻译模式（写成 goto 形式）：

```
    t = 条件表达式;
    if (!t) goto false_branch;
    then 分支的语句
    goto done;
false_branch:
    else 分支的语句
done:
```

三处结构性事实：

- **条件被取反**。源码里写的是"条件成立就执行 then"，机器码里写的是"**条件不成立就跳走**"——因为顺序执行的那一路不需要跳转指令，把 then 分支放在直落路径上更省。
- **then 分支末尾必须有一条无条件 `jmp`**，否则会顺着执行到 else 分支里去。
- 两个分支汇合于同一个标号。

**示例**：取两个指针中地址较大者所指的值。c

```
int pick(int *p1, int *p2) {
    if (p1 > p2) return *p2;
    else         return *p1;
}
```
asm

```
mov eax, dword ptr [ebp+8]    ; 取参数 p1
mov edx, dword ptr [ebp+12]   ; 取参数 p2
cmp eax, edx                  ; 按 p1 - p2 置标志位
jbe L1                        ; p1 <= p2（无符号）则跳走
mov eax, dword ptr [edx]      ; 直落路径：取 *p2
jmp L2
L1:
mov eax, dword ptr [eax]      ; 取 *p1
L2:
```

这里用 `jbe`（无符号的"小于等于"）而不是 `jle`，原因是**指针按无符号整数比较**——地址没有负数。同一段 C 代码，若把 `int *` 换成 `int`，编译出来就是 `jle`。**选哪条转移指令，取决于操作数的类型是有符号还是无符号。**

## 三、循环结构的机器级表示

三种循环语句都可以归结为"**循环体 + 条件测试 + 条件跳转**"。差别只在测试放在哪、跳转往哪跳。

### 最基本的形态：do-while

```
loop:
    循环体
    t = 条件表达式;
    if (t) goto loop;
```

只需要**一条**条件转移指令，是三种形态里最省的。代价是循环体至少执行一次。

### while / for：需要一次前置判断

`while` 与 do-while 只差一个"进门前先看一眼"：

```
    t = 条件表达式;
    if (!t) goto done;
loop:
    循环体
    t = 条件表达式;
    if (t) goto loop;
done:
```

`for (init; test; update) body` 展开后与之同构，只是多了初始化与更新：

```
    init;
    t = test;
    if (!t) goto done;
loop:
    body;
    update;
    t = test;
    if (t) goto loop;
done:
```

**这个模板有个明显的浪费：条件表达式的代码出现了两次。** 条件复杂时，重复的这一份可能是十几条指令。

### 第三种形态：先跳到判断处

编译器常用的另一种排法，让判断代码只保留一份：

```
    init;
    jmp  test          ← 先无条件跳到判断处
body:
    循环体
    update
test:
    条件判断
    条件成立 → jmp body
```

代价是每次进入循环多执行一条 `jmp`，收益是**代码里只有一份判断逻辑**。识别特征很清楚：**初始化之后紧跟一条无条件 `jmp` 跳向后方，那个位置又有一条条件转移跳回来**——这一对配合就是一个循环，不是分支。

### 局部变量：在寄存器里还是在栈上

同一个循环，编译器优化与否，生成的代码形态差别很大。

**未优化时，局部变量落在栈帧里**，从 `[ebp-4]` 起向低地址排：asm

```
mov  dword ptr [ebp-8], 0     ; i = 0，i 住在栈单元 [ebp-8]
jmp  L_test
L_body:
mov  eax, [ebp-8]             ; 读 i
add  eax, 1
mov  [ebp-8], eax             ; 写回 i —— 自增要三条指令
L_test:
cmp  dword ptr [ebp-8], 10
jl   L_body
```

**优化后，局部变量被提升到寄存器**，自增就只剩一条指令：asm

```
mov  edx, 0                   ; i 住在 edx
L_body:
add  edx, 1
cmp  edx, 10
jl   L_body
```

两种形态描述的是同一段 C 代码。判断某个量是不是循环变量，看的是**谁在参与循环末尾那条 `cmp`**——它在 `[ebp-X]` 里还是在寄存器里，只反映优化级别。

**编者注（口径）**：一个存储单元的地址写成 `[ebp-8]` 这种形式，本质上就是**基址寻址**——`ebp` 是基址寄存器，`-8` 是形式地址。循环体里访问数组时出现的 `[ecx+edx*4+首地址]`，则是基址加变址加位移的**复合寻址**，展开方式见 [[03_计算机组成原理_CO/instruction/addressing-calculation.md|有效地址计算]]。

## 四、过程调用的机器级表示

### 为什么必须有栈

过程调用要为一批数据找存放空间：入口参数、返回地址、调用过程用到的寄存器、被调用过程的局部变量、返回结果。

最快的地方当然是寄存器。但寄存器有三条硬限制：

- **数量有限**，且被所有过程共享——给定时刻只能被一个过程使用
- 数组、结构这类**复杂类型的局部变量根本放不进寄存器**
- 过程可以嵌套甚至递归，**同一个过程可以同时存在多个活动实例**，各自需要一份独立的局部变量

第三条决定了这块空间必须是"后进先出"的：调用嵌套的顺序天然就是栈的顺序。于是需要一个专门的存储区域——**栈**。

每个过程在栈上有自己的一块区域，称为**栈帧**（stack frame）。一个栈由若干栈帧首尾相接构成。

### 调用与返回：指令做了什么

假设过程 P 调用过程 Q：

| 步骤 | 谁做 | 做什么 |
| --- | --- | --- |
| 1 | P | 把入口参数放到 Q 能访问到的地方 |
| 2 | P | 执行 `call Q`：**把返回地址（call 的下一条指令地址）压栈**，然后转移到 Q |
| 3 | Q | 建立栈帧：`push ebp` → `mov ebp, esp` → `sub esp, N` |
| 4 | Q | 执行过程体 |
| 5 | Q | 把返回值放到 P 能访问到的地方（约定用 EAX） |
| 6 | Q | `leave` 撤销栈帧，`ret` **弹出返回地址**并转移回 P |

**调用指令与普通转移指令的根本区别，就在第 2 步的"保存返回地址"**：`jmp` 一去不返，`call` 必须留下回来的路。

### 栈帧的布局是推出来的

x86 的栈**从高地址向低地址增长**。栈帧里各项的位置不必硬记，按上面六步的发生顺序推即可：

| 发生顺序 | 压入什么 | ESP 变化 | 结果位置 |
| --- | --- | --- | --- |
| ① 调用前 | 参数（从右向左） | 每个 −4 | 高地址侧 |
| ② `call` | 返回地址 | −4 | `[ebp+4]` |
| ③ `push ebp` | 调用者的 EBP | −4 | `[ebp]` |
| ④ `mov ebp, esp` | — | 不变 | **EBP 就位** |
| ⑤ `sub esp, N` | 为局部变量开空间 | −N | `[ebp-4]` 起向低地址排 |

第 ④ 步之后往回数，每格 4 字节：`[ebp]` 是旧 EBP，`[ebp+4]` 是返回地址，`[ebp+8]` 才轮到第一个参数。**`+8` 这个数就是这么来的**——它等于"一个旧 EBP + 一个返回地址"的宽度。

```
高地址
┌─────────────────┐
│   参数 n         │  [ebp+12]、[ebp+16] …
│   参数 1         │  [ebp+8]
│   返回地址        │  [ebp+4]    ← call 压入
├─────────────────┤
│   旧 EBP         │  [ebp]      ← push ebp
├─────────────────┤
│   局部变量 1      │  [ebp-4]
│   局部变量 2      │  [ebp-8]
│   …              │
└─────────────────┘  ← ESP（栈顶）
低地址
```

**当前栈帧的边界是 EBP 到 ESP 之间**；EBP 之上（高地址侧）已经是调用者的地盘。

栈帧指针 EBP 固定不动、栈指针 ESP 随入栈出栈移动——**用固定的帧指针访问变量比用不断移动的栈指针方便得多，也不易出错**，所以过程内对栈中信息的访问大多通过 EBP 进行。若某个过程没有局部变量，编译器往往连帧指针都不设置，以省掉这点开销。

### 参数传递：两帧共享同一块内存

上面那张图只画了一帧，会掩盖一件要紧事——**调用者帧底部的"参数区"，和被调用者帧顶部的 `[ebp+8]` 起，是同一块内存的两个视角**。

图 3.12 caller 和 add 的栈帧

图里 `caller` 把两个实参写在自己帧的底部，`call` 再压入返回地址；进入 `add` 之后，`add` 通过 `[ebp+8]`、`[ebp+12]` 读到的正是这两个数。**同一块内存，调用者从上往下写、被调用者从下往上读**——这就是参数传递的全部机制，没有额外的搬运。

图中两个 `EBP` 箭头也标出了 `push ebp; mov ebp, esp` 的效果：新的 EBP 恰好落在"EBP 在 caller 中的值"那一格上。

### 调用全过程的三个瞬间

图 3.11 过程调用过程中栈和栈帧的变化

| 瞬间 | 栈上有什么 | ESP 在哪 |
| --- | --- | --- |
| **a) 过程 Q 被调用前** | 调用者保存的寄存器 + 参数 n…1 + 返回地址 | 返回地址处 |
| **b) 过程 Q 执行中** | 再加上 EBP 旧值 + 被调用者保存的寄存器 + 非静态局部变量 | 当前帧最低处 |
| **c) 返回到过程 P 后** | 恢复成 a) 的样子 | 退回返回地址处 |

**返回之后栈必须恢复原状**，这是调用约定的底线——否则调用者接下来读到的每一个栈单元都会错位。

### 寄存器保存约定

寄存器是所有过程共享的，一个过程写了某个寄存器，另一个过程原来存在里面的值就没了。解决办法是**事先约定谁负责保存**：

| 类别 | 寄存器（IA-32） | 谁负责保存 | 含义 |
| --- | --- | --- | --- |
| **调用者保存** | EAX, ECX, EDX | 调用者 P 在 `call` 前自行保存 | 被调用者可以随便用，返回后其中的值不保证有效 |
| **被调用者保存** | EBX, ESI, EDI | 被调用者 Q 使用前 `push`、返回前 `pop` | 调用者可以放心地跨过一次调用继续使用 |

两类划分不是可有可无的规矩，而是**减少无谓保存**的手段：调用者只保存自己"跨调用还要用"的那几个，被调用者只保存自己"确实动了"的那几个。

### 一个完整的小例子
c

```
int add(int x, int y) { return x + y; }

int caller() {
    int temp1 = 125, temp2 = 80;
    int sum = add(temp1, temp2);
    return sum;
}
```

`caller` 的代码：asm

```
push ebp                       ; 保存调用者的 EBP
mov  ebp, esp                  ; 帧指针就位
sub  esp, 24                   ; 为局部变量与参数区开空间
mov  dword ptr [ebp-12], 125   ; temp1
mov  dword ptr [ebp-8], 80     ; temp2
mov  eax, dword ptr [ebp-8]
mov  [esp+4], eax              ; 第 2 个参数放在参数区高地址侧
mov  eax, dword ptr [ebp-12]
mov  [esp], eax                ; 第 1 个参数放在参数区低地址侧
call add                       ; 压入返回地址并转移；返回值在 eax
mov  dword ptr [ebp-4], eax    ; sum = 返回值
mov  eax, dword ptr [ebp-4]    ; 把 sum 作为自己的返回值
leave                          ; = mov esp, ebp ; pop ebp
ret                            ; 弹出返回地址并转移回去
```

`add` 的代码（左侧为该指令的机器码）：asm

```
55        push ebp
89 e5     mov  ebp, esp
8b 45 0c  mov  eax, dword ptr [ebp+12]   ; 取第 2 个参数 y
8b 55 08  mov  edx, dword ptr [ebp+8]    ; 取第 1 个参数 x
8d 04 02  lea  eax, [edx+eax]            ; eax = x + y
5d        pop  ebp
c3        ret
```

两处值得留意：

- **`add` 里读到的 `[ebp+8]`、`[ebp+12]`，正是 `caller` 写进 `[esp]`、`[esp+4]` 的那两个单元**——第一个参数在低地址侧，所以偏移小的 `[ebp+8]` 对应第一个参数。
- 编译器用 `lea` 而不是 `add` 完成加法。`lea` 计算的是有效地址、并不访存，这里借它的地址加法器直接算出 x+y，还不影响标志位。

### leave 指令
asm

```
leave  ≡  mov esp, ebp    ; 丢弃局部变量空间，ESP 回到保存旧 EBP 的位置
          pop ebp         ; 恢复调用者的 EBP，ESP 再 +4
```

执行完 `leave`，ESP 恰好指向返回地址，`ret` 接着把它弹进 PC。**两条指令合起来把栈帧还原成调用前的样子。**

## 易混淆知识点

**1. 为什么机器码里的条件和源码里的条件是反的？**

因为**顺序执行的那一路不需要跳转指令**。把 then 分支放在直落路径上，只需一条"条件不成立就跳走"的转移指令；反过来写则两个分支都要跳，多一条指令也多一次流水线扰动。

所以看到 `if (a > b)` 编译成 `jle`，那不是写错了——`jle` 跳走的是 else 那一路。

**2. `jle` 和 `jbe` 都是"小于等于"，什么时候用哪个？**

看操作数类型，不看数值：

|  | 用于 | 判断依据 |
| --- | --- | --- |
| `jle` | **有符号**数（`int` 等） | ZF=1 或 SF≠OF |
| `jbe` | **无符号**数（指针、`unsigned`） | CF=1 或 ZF=1 |

**指针一律按无符号比较**——地址空间里没有负地址。同一段比较代码，操作数类型一改，编译器选的转移指令就换一套。

**3. 循环变量到底在寄存器里还是在栈上？**

取决于编译器有没有开优化，与"循环怎么工作"无关：

|  | 循环变量位置 | 自增要几条指令 |
| --- | --- | --- |
| 未优化 | 栈单元 `[ebp-X]` | 3（读、加、写回） |
| 优化后 | 通用寄存器 | 1 |

两者是同一段源码的两种翻译。识别循环的依据始终是**控制流形状**（有没有往回跳的条件转移），不是变量住在哪。

**4. `call` 和 `jmp` 差在哪？`ret` 又是怎么知道该跳回哪的？**

`call` 比 `jmp` 多做一件事：**把返回地址压栈**。`ret` 不需要任何操作数，它做的就是把栈顶那个值弹出来送进 PC。

这也意味着：**`ret` 弹出的是"执行它那一刻栈顶的那个值"**。若过程体内 `push` 与 `pop` 没有配平，栈顶就不是返回地址了，`ret` 会跳到一个错误的位置。栈帧必须在返回前恢复原状，根子在这里。

**5. 调用者保存和被调用者保存，怎么记住哪几个是哪类？**

与其记名单，不如记**它们各自的承诺**：

- **调用者保存**（EAX/ECX/EDX）：被调用者可以随意覆盖。所以调用方若还要用，得自己在 `call` 之前存好。
- **被调用者保存**（EBX/ESI/EDI）：被调用者承诺"用完还你"。所以它想用就得先 `push`，返回前 `pop` 回来。

EAX 属于调用者保存这一点有个自然的旁证：**返回值就走 EAX**，它本来就注定会被被调用者改写。

**6. 栈帧和栈是一回事吗？**

不是。**栈是整块区域，栈帧是其中属于某一个过程活动实例的一段**。一个栈由若干栈帧首尾相接组成，嵌套调用有几层，栈上就有几个活动的栈帧。

递归之所以可行，正因为每次调用都获得一个**独立的新栈帧**，各自的局部变量互不干扰。

## 本节小结

- 机器级只有三样原料：**产生条件（cmp/test）、使用条件（条件转移）、无条件改流（jmp/call/ret）**，所有控制结构都是它们的排列
- `cmp` 按 a−b 置 **ZF/SF/OF/CF** 四位且不保存结果；**无符号比较看 CF，有符号比较看 SF 与 OF 是否一致**，带"等于"再并上 ZF=1
- SF=OF 表示"大于等于"，是因为它只对应"差为正且未溢出"和"差为负但溢出"两种情形，二者反映的都是真实差值为正
- `if-else` 的机器级形态：**条件取反后跳向 else，then 分支走直落路径且末尾必须有一条 `jmp`**；指针比较用无符号转移指令，整型比较用有符号转移指令
- 三种循环都归结为"循环体 + 条件测试 + 条件跳转"；**do-while 只需一条条件转移**，while/for 要多一次前置判断
- 编译器常用**"先跳到判断处"**的第三种形态：判断代码只保留一份，代价是每次进入循环多一条 `jmp`；识别循环靠**控制流形状**，与循环变量住在栈上还是寄存器里无关
- 栈存在的理由有三条：寄存器数量有限、复杂类型局部变量放不进寄存器、**嵌套与递归需要多份独立的局部变量**
- 栈帧布局是按"参数 → `call` 压返回地址 → `push ebp` → `mov ebp,esp` → `sub esp,N`"的顺序**推出来**的：`[ebp]` 旧 EBP、`[ebp+4]` 返回地址、`[ebp+8]` 起是参数、`[ebp-4]` 起是局部变量
- **调用者帧的参数区就是被调用者的 `[ebp+8]` 起**，同一块内存的两个视角，参数传递不发生额外搬运
- **EBP 固定、ESP 移动**；无局部变量的过程，编译器往往连帧指针都不设
- `call` = 压返回地址 + 转移，`ret` = 弹出栈顶送 PC；**栈帧不还原，`ret` 就会跳错**
- **调用者保存**（EAX/ECX/EDX）由调用方在 `call` 前自存；**被调用者保存**（EBX/ESI/EDI）由被调用方 `push`/`pop` 还原；返回值走 **EAX**
- `leave` ≡ `mov esp, ebp` + `pop ebp`；`lea` 算有效地址而不访存，常被编译器借去做加法
