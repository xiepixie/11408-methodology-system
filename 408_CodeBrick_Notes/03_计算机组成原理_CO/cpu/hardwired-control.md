# 硬布线控制器

## 大纲定位

**五（四）控制器的功能和工作原理**

要求：说清硬布线控制器"用组合逻辑直接产生控制信号"的原理，理解其输入来源与设计步骤，能与微程序控制器在速度、修改难度、规整性上作对比。

另一种实现方式见 [[03_计算机组成原理_CO/cpu/microprogrammed.md|微程序控制器]]；控制信号具体控制什么见 [[03_计算机组成原理_CO/cpu/single-bus-datapath.md|单总线数据通路]]。

## 知识框架

本节回答四个问题：

- 控制器要解决的问题到底是什么？
- 产生一个控制信号需要哪些输入？
- 设计过程本质上是在做什么？
- 为什么它快，又为什么难改？

## 一、控制器要解决的问题

数据通路已经把所有可能的路径都铺好了，剩下的问题只有一个：

**在第几拍，把哪几个门打开？**

控制器的全部工作就是回答这个问题。它的输出是一组控制信号（门控信号、写使能、ALU 操作码等），每个信号在每个时刻要么有效要么无效。

因此控制器可以看成一个函数：控制信号=f(操作码, 时序信号, 状态条件)

**硬布线的做法就是把这个函数直接做成逻辑门电路**——没有存储、没有查表，输入变化后经过几级门延迟，输出立刻跟着变。

## 二、三类输入

### 1. 操作码

来自 IR 的高位字段，经**指令译码器**产生各指令对应的使能信号 I1,I2,…,In。任一时刻只有当前指令对应的那一根线为 1。

例如 `ADD` 的操作码若为 `000`，译码器输出 IADD=1，其余为 0。

### 2. 时序信号

时序发生器产生节拍脉冲 T1,T2,…,Tk，指明当前处在机器周期的第几拍。

常见实现是**环形计数器**：每个时钟周期只有一个 Ti=1，逐拍右移。

> [!TIP]
>

为什么必须有节拍信号

因为同一条指令在不同拍要发**不同**的信号。只知道"当前是 ADD 指令"还不够，必须同时知道"现在是第几拍"，才能决定该开哪个门。

节拍信号就是控制器的"时间坐标"。缺了它，控制器退化成组合逻辑，也就只能做单周期 CPU 了——这正是 [[03_计算机组成原理_CO/cpu/single-cycle.md|单周期数据通路]] 中"控制信号一条指令内不变"的原因。

### 3. 状态条件

来自 PSW 和外部：

- 进位标志 CF、零标志 ZF、符号标志 SF、溢出标志 OF
- 中断请求信号
- 存储器就绪信号

状态条件让控制流能**分支**：条件转移指令要看 ZF 才知道该不该改写 PC，访存要看就绪信号才知道该不该继续。

## 三、设计过程本质上是填一张表

硬布线控制器的设计有固定套路，核心是一张二维表：

- **行**：每一个控制信号
- **列**：每一个（指令，节拍）组合
- **格子**：该信号在该情形下是否有效

填完表，每一行就是一个布尔函数的真值表，直接写出表达式即可。

### 举两个信号为例

控制信号 C1（"将 MDR 内容送入 IR"）在**取指周期第 3 拍**有效，对任何指令都成立——因为取指过程与指令种类无关：C1=T3⋅FE

控制信号 C2（"ALU 执行加法"）仅在 ADD 指令的执行周期第 1 拍有效：C2=IADD⋅T1⋅EX

若 LOAD 指令也要在执行周期第 1 拍用 ALU 算有效地址，则合并为：C2=(IADD+ILOAD)⋅T1⋅EX

> [!TIP]
>

观察表达式的形状

所有控制信号的表达式都是同一个模子：信号=(∑需要它的指令)⋅(节拍)⋅(工作周期)

括号里的"指令之和"就是**或阵列**，外层的相乘就是**与阵列**。这正是 PLA 的结构——先与后或。

### 设计步骤

- **分析每条指令的微操作序列**——列出每条指令在每个节拍需要哪些微操作
- **列出每个控制信号的逻辑表达式**——找出哪些指令的哪些节拍需要它
- **化简布尔表达式**——用卡诺图或代数方法
- **用逻辑门电路实现**图 5.28　用 PLA 电路实现的组合逻辑控制器（袁春风《计算机组成与系统结构》第 3 版，见文末教材出处）

落到电路上就是这么一块 **与阵列 + 或阵列**：输入是操作码和当前状态，经与阵列产生乘积项，再由或阵列把相关乘积项并起来，直接输出各条控制信号。

## 四、单周期与多周期的硬布线控制器

同样叫硬布线，两种 CPU 里的形态并不相同：

|  | 单周期 | 多周期 |
| --- | --- | --- |
| 控制器类型 | **纯组合逻辑** | 组合逻辑 + **状态寄存器** |
| 输入是否含节拍 | 否 | **是** |
| 一条指令内信号 | 不变 | 逐拍变化 |
| 本质 | 一张真值表 | **有限状态机** |

多周期的控制器必须记住"现在是第几步"，因此含时序逻辑，是个状态机。但它仍归类为硬布线控制器——**判据是控制信号由逻辑电路算出来，而不是从存储器读出来**。

## 五、硬布线 vs 微程序

| 对比项 | 硬布线控制器 | 微程序控制器 |
| --- | --- | --- |
| 实现方式 | 组合逻辑电路 | 控制存储器（ROM） |
| 控制信号来源 | **算**出来 | **读**出来 |
| 速度 | **快**（几级门延迟） | 较慢（要访问 CM） |
| 规整性 | 不规整，逻辑零散 | 规整，易于扩展 |
| 修改灵活性 | **难**（需重新设计电路） | **易**（改 CM 内容） |
| 适用场景 | RISC（指令集简单规整） | CISC（指令集复杂） |

> [!TIP]
>

快与难改是同一个原因

硬布线之所以快，是因为控制信号由**专门为这套指令集化简过的电路**直接算出，没有任何中间环节。

而正因为电路是"为这套指令集专门化简过的"，一旦新增或修改一条指令，那张表就变了，所有相关信号的布尔表达式都要重新化简、电路要重新设计——**本质上是重新设计硬件**。

优点和缺点来自同一个设计决策，这在硬件设计中是常态。

## 易混淆知识点

**1. 硬布线控制器里有没有存储器？**

**没有**（控制信号的来源里没有）。这正是它与微程序控制器的分界线。

多周期的硬布线控制器含有**状态寄存器**（记录当前是第几个状态），但那只是几个触发器，用于记录状态，不是用来存放控制信号的存储器。

**2. 为什么 RISC 用硬布线，CISC 用微程序？**

关键在指令集的**规模与规整程度**：

- RISC 指令少、格式统一、每条指令的执行步骤相似 ⇒ 那张表小而有规律 ⇒ 化简后电路规模可控，且能享受硬布线的速度优势
- CISC 指令多、格式各异、复杂指令的微操作序列很长 ⇒ 表极其庞大且毫无规律 ⇒ 硬布线电路难以设计和维护，改用微程序把复杂性转移到"编程"上

**3. 新增一条指令，两种控制器分别要做什么？**

|  | 硬布线 | 微程序 |
| --- | --- | --- |
| 要改什么 | 重新分析微操作序列、修改所有相关信号的布尔表达式、重新设计电路 | 在 CM 中新增一段微程序，在映射逻辑中加一条操作码到入口地址的映射 |
| 改的是 | **硬件** | **内容** |

**4. 现代 x86 处理器用哪种？**

**两者都用**。常用的简单指令由硬布线式的快速译码路径直接处理，以保证速度；少数复杂指令则查微码 ROM 展开成一串内部操作。

这也解释了为什么 x86 处理器能通过**微码更新**修补某些硬件缺陷——被修补的正是走微码路径的那部分。

## 本节小结

- 控制器要回答的问题只有一个：**在第几拍，把哪几个门打开**
- 硬布线 = 把 f(操作码,节拍,状态) 直接做成**逻辑门电路**，不存储、不查表
- 三类输入：**操作码**（经译码器）、**节拍信号**（环形计数器）、**状态条件**（PSW 等）
- **节拍信号是控制器的时间坐标**，缺了它就只能做单周期 CPU
- 设计本质是**填一张表**（行=控制信号，列=指令×节拍），再逐行写布尔表达式
- 表达式形如 (∑指令)⋅节拍⋅周期，正对应 PLA 的**先与后或**结构
- 多周期的硬布线控制器是**有限状态机**，但仍属硬布线——判据是信号"算"出来而非"读"出来
- **快与难改源自同一个决策**：电路是为这套指令集专门化简的
- RISC 用硬布线，CISC 历史上用微程序；现代 x86 **两者混合**
