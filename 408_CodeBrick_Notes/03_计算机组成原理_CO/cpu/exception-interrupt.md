## 知识框架

本节回答四个问题：

- 异常和中断按什么标准分类？分类的意义是什么？

## 一、基本概念

**中断**是 CPU 对系统内外部事件的**响应机制**：暂停当前程序，转去执行中断服务程序（ISR），处理完毕后返回原程序继续执行。

广义的"中断"按**事件来源**分成两大类：

| 类型 | 又称 | 来源 | 举例 |
| --- | --- | --- | --- |
| **内中断（异常）** | Exception | **CPU 内部** | 除零、溢出、缺页、系统调用 |
| **外中断（中断）** | Interrupt | **CPU 外部** | I/O 完成、时钟、电源异常 |

> [!TIP]
>

来源不同，导致检测时机也不同

这个分类不只是给事件贴标签，它直接决定了**什么时候检测**：

- **异常**由当前指令自身引发，因此在**指令执行过程中**就被检测到——不检测就没法继续执行
- **中断**与当前指令无关，可以等一等，因此在**指令执行结束后**才检测

这也是为什么中断响应总是发生在指令边界，而异常可能打断指令执行到一半。

## 二、异常的分类

按**处理完之后返回哪里**分三类：

| 类型 | 触发时机 | 处理后返回 | 举例 |
| --- | --- | --- | --- |
| **故障**（Fault） | 指令执行**过程中**检测到 | **重新执行**触发指令 | 缺页、非法操作码 |
| **自陷**（Trap） | 指令执行**后**（主动触发） | 执行**下一条**指令 | 系统调用、断点指令 |
| **终止**（Abort） | 严重错误 | **不返回**，终止进程 | 硬件故障、双重错误 |

> [!TIP]
>

三种返回方式的道理

- **故障**是"条件不具备"。缺页时页不在内存，处理程序把页调进来后，原来那条指令**就能成功了**，所以要重来一次
- **自陷**是"主动请求"。系统调用指令的任务已经完成（内核帮它做完了），自然接着往下走
- **终止**是"无法收拾"。硬件已经出错，机器状态不可信，重来或继续都没有意义

**返回哪里，取决于触发它的那条指令算不算已经完成。**

## 三、外中断的分类

| 类型 | 特点 | 举例 |
| --- | --- | --- |
| **可屏蔽中断**（INTR） | 可通过中断允许标志 IF 屏蔽 | I/O 设备完成 |
| **不可屏蔽中断**（NMI） | **不能被屏蔽**，优先级最高 | 电源故障、硬件错误 |

NMI 之所以不可屏蔽，是因为它报告的事件（如掉电）**不处理就来不及了**——给程序留出屏蔽它的能力反而是危险的。

## 四、检测与响应

### 检测：CPU 凭什么决定"现在响应"

CPU 并不是一发现请求就转走。响应一个**可屏蔽中断**必须**同时**满足三个条件，缺一不可：

| # | 条件 | 卡的是哪一环 | 由什么表示 |
| --- | --- | --- | --- |
| 1 | 中断源**确实提出了请求** | 有没有事 | 该中断源的中断请求触发器为 1 |
| 2 | CPU **处于开中断状态** | 准不准打断 | 允许中断触发器 EINT（x86 中的 IF）=1 |
| 3 | **一条指令执行完毕** | 现在打断安不安全 | CPU 在每条指令执行阶段结束前发出中断查询信号 |

第 3 条是中断只能在**指令边界**响应的来源——指令执行到一半时，中间结果散落在 MDR、暂存器里，此时打断根本无法准确保存现场（见 [[03_计算机组成原理_CO/cpu/instruction-cycle.md|指令执行过程]]）。

> [!TIP]
>

异常和 NMI 各绕开了哪几条

这张表也解释了三者检测时机的差别：

- **异常**绕开第 2、3 条：它由当前指令自身引发，**不处理就没法继续执行**，所以既不受开/关中断控制，也不能等到指令结束
- **NMI** 绕开第 2 条：不可屏蔽，但仍在指令边界响应
- **可屏蔽中断**：三条全要满足

**"能不能等"决定了检测时机，"要不要留否决权"决定了能不能屏蔽。** 两条判据各管一半。

### 响应：中断隐指令

中断的响应由**硬件**自动完成。这一串硬件动作有个专门名字：

> [!WARNING]
>

中断隐指令

**中断隐指令**指 CPU 响应中断时**由硬件自动执行的一系列操作**。

它叫"指令"，但**指令系统里并没有这条指令**，程序员也写不出它——它是纯硬件行为，只是借用了"指令"这个说法。

它完成三件事，一件不多一件不少：

| # | 动作 | 为什么必须在这里做 |
| --- | --- | --- |
| 1 | **关中断** | 防止保存断点的过程本身被新中断打断 |
| 2 | **保存断点**（PC、PSW） | 断点不保存就回不去；这一步**只能由硬件做**，因为软件还没拿到控制权 |
| 3 | **形成中断服务程序入口地址并送 PC** | 交出控制权 |

**不包括保存通用寄存器**——那是 ISR 里的"保护现场"，由软件完成。

关中断排在第一位是硬性的：第 2 步正在把断点写进栈里，如果这期间又响应一个中断，新的断点会覆盖或错位，**原程序再也回不去了**。这与 [[03_计算机组成原理_CO/cpu/instruction-cycle.md|指令执行过程]] 中中断周期的动作次序是同一件事。

### 哪些工作"必须"由硬件完成

"通常由硬件"和"必须由硬件"是两个不同的问题：

| 工作 | 谁做 | 说明 |
| --- | --- | --- |
| **保存断点** | **只能硬件** | 软件此刻还没接管，无从下手 |
| 关中断 | 硬件（隐指令），但 ISR 里也能用关中断指令 | 不是只能硬件 |
| **中断判优** | 硬件**或**软件 | 硬件排队器/菊花链可以判优；**软件查询法**（逐个轮询中断源）同样可以判优 |
| 保存通用寄存器 | 软件（ISR 保护现场） |  |
| 开中断 | 软件（ISR 里用开中断指令） |  |

> [!CAUTION]
>

中断判优不属于"必须由硬件"

容易想当然的一点是"响应优先级由硬件排队器决定，所以判优必须靠硬件"。

但**非向量中断**就是用软件轮询各中断源来确定中断源和优先次序的——只要存在软件实现方案，就不能叫"必须由硬件"。

真正**只能**由硬件完成的，只有**保存断点**一项。图 5.30　异常和中断的处理过程（袁春风《计算机组成与系统结构》第 3 版，见文末教材出处）

这张图给的是**控制流怎么走**：用户进程执行到第 i 条指令时发生异常或中断事件 → 控制权转到操作系统的异常/中断处理程序 → 处理完后按情况**三选一**地回来。

教材在这里定了一条重要的分界：整个中断处理分**两大阶段**——检测和响应⏟硬件⟶具体的处理过程⏟软件

**大纲五（五）只要求到"检测与响应"，也就是硬件那一半。**

图右下角那三个返回选项，正对应异常的三种类型：

| 返回方式 | 对应类型 | 例子 |
| --- | --- | --- |
| 返回到**当前**指令重新执行 | 故障（fault） | 缺页等可恢复错误 |
| 返回到**下一条**指令 | 自陷（trap） | 系统调用、断点指令 |
| **不返回**，终止进程 | 终止（abort） | 硬件故障等不可恢复错误 |

## 五、中断服务程序：软件阶段

ISR 由**软件**完成。**单级中断**（不允许嵌套）和**多级中断**（允许嵌套）的步骤不同：

| 步骤 | 单级中断 | 多级中断（允许嵌套） |
| --- | --- | --- |
| 1 | 保护现场 | 保护现场 |
| 2 | — | **开中断**（这样更高优先级中断才能打进来） |
| 3 | 中断事件处理 | 中断事件处理 |
| 4 | — | **关中断**（准备恢复现场，不能被打断） |
| 5 | 恢复现场 | 恢复现场 |
| 6 | **开中断** | 开中断 |
| 7 | 中断返回（IRET） | 中断返回（IRET） |

> [!TIP]
>

单级中断为什么只在最后开中断

单级中断全程不允许被打断，所以中间那两次开/关中断都不需要。**"开中断"只出现在最后、紧挨着中断返回之前**——目的是把中断允许状态还原，让后续程序还能响应中断。保护现场→事件处理→恢复现场→开中断→中断返回

注意**保存断点和关中断不在这个序列里**——它们属于中断隐指令，在 ISR 开始之前就由硬件做完了。

IRET 指令从栈中恢复 PC 和 PSW（含 IF 位），返回被中断的程序。

### 中断结束信号 EOI 的方向

> [!CAUTION]
>

EOI 是 CPU 发给中断控制器的

**EOI（中断结束命令）由 CPU / 中断服务程序发给中断控制器**，告诉它"这个中断我处理完了，可以放行同级或更低级的中断了"。

方向是 **CPU → 中断控制器**，不是外设 → CPU。

外设只会通过中断控制器向 CPU 发**中断请求**信号，它没有"通知 CPU 处理结束"这回事——**处理结束与否只有 CPU 自己知道**，外设无从判断。

### 特权指令

驱动程序和中断服务程序运行在**内核态**，它们要用的一批指令普通用户程序不许执行，这类指令叫**特权指令**。

| 指令 | 是否特权 | 理由 |
| --- | --- | --- |
| I/O 指令（IN / OUT） | **是** | 直接操作设备端口，乱用会破坏其他进程的设备状态 |
| 开中断 / 关中断指令 | **是** | 用户程序若能关中断，就能永久霸占 CPU |
| **中断返回指令**（IRET） | **是** | 它会恢复 PSW，**包括特权级字段**——若用户可用，就能把自己提到内核态 |
| 停机、修改页表基址、加载 PSW | 是 | 同理 |
| **系统调用指令**（陷入指令） | **否** | 它恰恰是**给用户程序准备的入口** |

> [!TIP]
>

系统调用指令为什么必须是非特权的

如果连"请求进入内核"这个动作都要特权，用户程序就永远进不了内核态——整个系统调用机制根本无法启动。

逻辑是反的：**正因为要保护内核，才必须留一扇由硬件把守的门，而这扇门本身对所有人开放。** 陷入指令就是这扇门。

## 六、中断向量与入口地址的形成

- **中断向量**：中断服务程序的**入口地址**
- **中断向量表**：以**中断类型号**为索引，存放各中断向量的表格，通常放在内存低地址区中断类型号→查中断向量表→ISR 入口地址→送 PC

确定入口地址的两种方式：

| 方式 | 做法 | 速度 |
| --- | --- | --- |
| **向量中断** | 由中断类型号直接查表 | 快 |
| **非向量中断** | 由软件轮询各设备确定中断源，再转相应处理程序 | 慢 |

> [!WARNING]
>

中断向量 ≠ 向量地址

两者差一层间接：

- **中断向量** = 中断服务程序的入口地址（表项的**内容**）
- **向量地址** = 存放该入口地址的表项**地址**

CPU 拿向量地址去访存，取出的内容才是入口地址。混起来会整体差一层。

## 七、中断优先级

多个中断同时发生时，按优先级顺序响应。总体次序：内部异常>不可屏蔽中断（NMI）>可屏蔽中断

内部异常优先级最高，因为它**直接由当前执行的指令引发**，不处理指令就无法继续（如缺页故障不处理，访存这一步根本走不下去）。

注意这是分层表述：内部异常与外中断比较时内部异常在前；**在外中断内部**，NMI 高于可屏蔽中断。

### 两种优先级

> [!WARNING]
>

响应优先级与处理优先级

|  | 由什么决定 | 能否改变 | 含义 |
| --- | --- | --- | --- |
| **响应优先级** | 硬件排队器 | **不可改变** | 同时来了先响应谁 |
| **处理优先级** | **中断屏蔽字** | **可由软件调整** | 谁能打断谁 |

两者可以不一致：一个中断被优先响应，不代表它在处理过程中不会被别人打断。

### 中断屏蔽字怎么写

每个中断源对应屏蔽字中的一位：该位为 **1 表示屏蔽**（不响应），**0 表示允许**。

> [!TIP]
>

一条规则就够

**在第 i 级的中断服务程序里，屏蔽字要屏蔽掉"处理优先级不高于自己"的所有中断——包括它自己。**Mj={1若 Lj 的处理优先级≤Li（含 j=i）0若 Lj 的处理优先级高于 Li

**为什么要屏蔽自己**：否则同级中断会不断打断自己，形成无限嵌套。

三步走：

- 把**处理优先级**顺序从高到低排成一行
- 找到本级在这行里的位置
- 本级**及其右边**（处理优先级更低的）全部置 1，左边全部置 0；再按 M4M3M2M1M0 的**位序**填进去

> [!CAUTION]
>

第 3 步的位序要单独摆

屏蔽字写成 M4M3M2M1M0 时，**最左边是 M4、最右边是 M0**，与优先级顺序没有任何关系。

算完"哪几级要屏蔽"之后，一定要按下标重新摆位。

## 八、中断嵌套

在执行 ISR 过程中，若发生更高**处理优先级**的中断，CPU 可暂停当前 ISR 转去处理它，这称为**中断嵌套**。

成立条件：当前 ISR 中已**开中断**（IF =1），且新中断的处理优先级更高。

```
主程序 → 中断 A（低）→ 中断 B（高）→ 返回 A 继续 → 返回主程序
```

每次嵌套都要额外的栈空间保存断点，因此**嵌套深度受栈大小限制**。

## 九、流水线中的精确中断

流水线让异常处理变复杂：同一时刻有多条指令处于不同阶段，可能**同时**产生异常，而且发生顺序未必等于程序顺序。

**精确中断**要求两条：

- 异常指令**之前**的所有指令都已完成（结果已写回）
- 异常指令**及其之后**的指令都没有修改机器状态

实现方式：异常发生后**只标记不立即处理**，等该指令到达 WB 段时再统一处理。之前的指令正常完成，之后的指令全部冲刷。

各段可能产生的异常：

| 阶段 | 可能的异常 |
| --- | --- |
| IF | 取指地址未对齐、取指缺页 |
| ID | 非法操作码 |
| EX | 算术溢出、地址计算错误 |
| MEM | 数据地址未对齐、数据缺页 |
| WB | 一般不产生异常 |

> [!TIP]
>

为什么必须等到 WB 段才处理

因为只有到了 WB 段，才能确定这条指令**前面的所有指令都已经完成**——流水线是按序推进的，排在它前面的指令必然更早到达 WB。

若在 EX 段发现溢出就立刻处理，可能它前面还有一条指令正在 MEM 段没做完，机器状态就不满足"精确"的第一条了。

这与 [[03_计算机组成原理_CO/cpu/pipeline-performance.md|流水线性能分析]] 中"无序执行、按序提交"的思路一致：**允许乱着算，但必须按顺序生效**。

## 例题：中断屏蔽字

**题**：五级中断 L4∼L0，屏蔽字为 M4M3M2M1M0（Mi=1 表示屏蔽 Li）。响应优先级为 L0>L1>L2>L3>L4，要求处理优先级为 L4>L0>L2>L1>L3。求 L1 的中断服务程序中的屏蔽字。

**解**：

第 1 步，处理优先级从高到低排开：L4, L0, L2, L1, L3

第 2 步，L1 排在第 4 位。

第 3 步，屏蔽 L1 自己和右边的 L3，其余（L4、L0、L2）置 0：

| 位 | M4 | M3 | M2 | M1 | M0 |
| --- | --- | --- | --- | --- | --- |
| 对应 | L4 | L3 | L2 | L1 | L0 |
| 取值 | 0 | **1** | 0 | **1** | 0 |

屏蔽字=01010

全程**没有用到响应优先级**——它只决定"同时来了先响应谁"，不参与屏蔽字的构造。屏蔽字只与处理优先级有关。

## 延伸：中断方式的性能代价

响应与处理一次中断要花掉若干个时钟周期，设备越快、中断越频繁，CPU 被占用的比例越高：CPU 占比=R/u×mf×100%

其中 R 为设备数据传输率，u 为**每次中断搬运的字节数**（由数据缓冲寄存器的宽度决定，不是默认 1 字节），m 为每次中断的开销周期数，f 为主频。

这条公式属于**大纲六（三）I/O 方式**的范围——本节只到硬件的检测与响应为止。完整的推导、算例，以及"设备快到什么程度中断方式就会丢数据"的判据，见 [[03_计算机组成原理_CO/io/programmed-interrupt.md|程序查询方式与程序中断方式]]；三种 I/O 方式的占用率横向对比见 [[03_计算机组成原理_CO/io/io-compare.md|I/O 方式对比]]。

## 易混淆知识点

**1. 异常和中断有什么区别？**

|  | 异常（内中断） | 中断（外中断） |
| --- | --- | --- |
| 来源 | CPU 内部，由当前指令引发 | CPU 外部设备 |
| 与当前指令 | **直接相关** | 无关 |
| 检测时机 | 指令执行**过程中** | 指令执行**结束后** |
| 是否可预测 | 自陷可预测，故障不可 | 随机发生 |

**2. 缺页属于中断还是异常？**

属于**异常**中的**故障**。它在 MEM 段发现页面不在主存时产生，与当前访存指令直接相关。处理完后 CPU **重新执行**引起缺页的那条指令。

**3. Cache 缺失需要异常处理吗？**

**不需要**。Cache 缺失由**硬件**自动处理（从主存调入 Cache 行），对软件完全透明，不涉及操作系统。

而缺页需要操作系统介入（调页面、更新页表），因此必须是异常。

**判据是"能不能由硬件独自解决"**——能则不必惊动软件。

**4. 自陷是"自愿"的中断吗？**

是的。自陷由程序**主动**执行特定指令触发，发生时机完全确定（写了系统调用指令就一定触发），与随机发生的外部中断不同。

正因为它是主动的、且已经执行完成，所以返回到**下一条**指令。

**5. 关中断之后，NMI 还能进来吗？**

**能**。关中断（IF =0）只屏蔽**可屏蔽中断**，NMI 顾名思义不受它控制。这也是 NMI 用来报告掉电等紧急事件的原因——它必须在任何时候都能打进来。

## 本节小结

- 异常（内中断）在指令执行**过程中**检测，中断（外中断）在指令**结束后**检测——因为异常与当前指令直接相关
- 三种异常的返回方式取决于**触发它的指令算不算已完成**：故障**重执行**、自陷**下一条**、终止**不返回**
- 响应可屏蔽中断要**同时**满足三条：**有请求**（请求触发器为 1）、**开中断**（EINT =1）、**一条指令执行完毕**；异常绕开后两条，NMI 绕开"开中断"这条
- **中断隐指令**（硬件自动）三件事：**关中断 → 保存断点 → 形成入口地址送 PC**，不含保存通用寄存器
- 关中断必须排第一，否则断点会被覆盖
- **只能由硬件完成的只有"保存断点"**；中断判优软硬件都能做
- 两阶段划分：**检测与响应由硬件，具体处理由软件**；大纲五（五）只到硬件这一半
- **单级中断** ISR 顺序：保护现场 → 处理 → 恢复现场 → **开中断** → 中断返回
- **EOI 是 CPU 发给中断控制器的**，外设只发中断请求
- **系统调用（陷入）指令不是特权指令**；I/O 指令、开/关中断、**IRET** 都是
- **中断向量**是入口地址，**向量地址**是存放它的表项地址，差一层间接
- **响应优先级**由硬件排队器定且不可改；**处理优先级**由屏蔽字定且可调
- 屏蔽字规则：屏蔽**处理优先级不高于本级**的所有中断（含自己），再按 M4⋯M0 位序填
- 中断方式 CPU 占比 =R/u×mf，**u 由数据缓冲寄存器宽度决定**
- **精确中断要等到 WB 段才处理**，因为只有此时才能确定前面的指令全部完成
- **NMI 不受关中断控制**；Cache 缺失由硬件处理，缺页由操作系统处理
