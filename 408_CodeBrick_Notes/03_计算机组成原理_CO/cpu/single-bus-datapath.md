# 单总线数据通路

## 大纲定位

**五（三）数据通路的功能和基本结构** · **五（四）控制器的功能和工作原理**

要求：读懂 CPU 内部单总线结构图，理解每个门控信号的位置与作用，能把一条指令拆成逐节拍的微操作序列并写出各拍有效的控制信号。

另一种数据通路模型见 [[03_计算机组成原理_CO/cpu/single-cycle.md|单周期数据通路]]；产生这些控制信号的电路见 [[03_计算机组成原理_CO/cpu/hardwired-control.md|硬布线控制器]]。

## 知识框架

本节回答四个问题：

- 单总线结构长什么样？门控信号怎么读？
- 为什么必须多出 Y 和 Z 两个暂存器？
- 微操作按什么规则拆成节拍？哪些操作可以挤在同一拍？
- 节拍数和时钟周期数是一回事吗？

## 一、单总线结构

CPU 内部所有部件挂在**一条内部总线**上，每个寄存器与总线之间都有一个门控信号（图中的小圈）：图 9.4　采用 CPU 内部总线方式的数据通路和控制信号（唐朔飞《计算机组成原理》第 3 版，见文末教材出处）

图上的下标 i / o 就是输入 / 输出控制：IRi 表示"内部总线 → IR"的输入控制门，PCo 表示"PC → 内部总线"的输出控制门。

采用内部总线的好处是**大大节省芯片内寄存器之间的连线**，使各部件布局更合理——这正是现代 CPU 普遍采用它的原因。代价则是下面这条约束。

> [!CAUTION]
>

一条约束决定了一切

**每个节拍，内部总线上只能传送一个数据。**

两个数据要传，就必须拆成两拍。整篇的节拍拆分规则都是从这一条推出来的。

## 二、为什么必须有 Y 和 Z

与非总线（专用连线）结构相比，单总线结构**多出了两个寄存器 Y 和 Z**。它们不是可有可无的暂存器，而是被 ALU 的电路性质和总线的独占性**逼出来**的。

根源在于：**ALU 是组合逻辑电路，自身不存数**。运算期间它的两个输入端必须**同时**保持有效，输出也只在输入稳定时才有效。

| 暂存器 | 存在理由 |
| --- | --- |
| **Y** | ALU 的双输入端需要两个操作数**同时**有效，而单总线一拍只能送一个 ⇒ 必须先把第一个操作数暂存进 Y，下一拍再从总线送第二个。Y 的内容送 ALU **不经过总线**，因此两个操作数能在同一拍到齐 |
| **Z** | ALU 算完时总线可能正被"送第二个操作数"占用；更关键的是，输出若直接接总线，会经总线**反馈回 ALU 的输入端**影响运算 ⇒ 用 Z 暂存结果，等总线空出再送目的寄存器 |

> [!TIP]
>

Y 和 Z 的动机不同，要分开理解

两者都叫"暂存器"，但解决的是两个不同的问题：

- **Y 解决"输入凑不齐"**——总线的时间独占性造成的
- **Z 解决"输出回灌"**——组合逻辑电路的反馈通路造成的

含混地说一句"用来暂存数据"，等于两个理由都没答到。

> [!WARNING]
>

三总线结构下 Y、Z 可以省掉

三总线结构中，源操作数、目的操作数、结果各走一条总线，不存在"一拍只能传一个"的瓶颈：两个操作数可以同时到达 ALU，结果也有专用通路送回，不会回灌输入端。

因此 **Y、Z 都不再需要，节拍数也随之减少**。

"为什么单总线需要 Y、Z 而三总线不需要"，答案完全在于总线条数决定了同时能传几个数据。

## 三、控制信号的写法

不同教材和不同的通路图，门控信号的符号并不统一：

| 记法 | 门控写法 | 常见的暂存器命名 |
| --- | --- | --- |
| 下标式 | PCo、MARi | Y、Z |
| 后缀式 | `PCout` / `MARin` | Y/Z、A/AC、T/SR 等 |

符号虽异，不变量只有三条：

- **源**寄存器给 `out`，**目的**寄存器给 `in`
- **访存**另给读写命令（`MemR` / `MemW`）
- **ALU 操作**单独给一个信号（如 `Add`）

因此读一张陌生的通路图时，只需先找到这三类信号分别叫什么，剩下的写法自然对应得上。

### MDR 是双端口，有四个门控信号

MDR 一头连**内部总线**、一头连**数据总线 DB**（要和主存交换数据），所以它的门控信号是**四个**而不是两个：

| 数据方向 | 典型信号名 | 用在哪一拍 |
| --- | --- | --- |
| DB → MDR | `MDRinE` | **主存读**，与 `MemR` 同拍 |
| MDR → 内部总线 | `MDRout` | 把读回的数据送 IR / 送 Y / 送寄存器 |
| 内部总线 → MDR | `MDRin` | **写主存前**把待写数据装进 MDR |
| MDR → DB | `MDRoutE` | **主存写**，与 `MemW` 同拍 |

带 **E** 的是外部（External，即 DB 一侧），不带 E 的是内部总线一侧。

把访存那两拍写成不带 E 的信号，数据根本没到主存那一侧——**这是理解 MDR 结构与否的分水岭**：MDR 不是一个普通寄存器，而是跨在两条总线之间的桥。

## 四、节拍拆分规则

### 什么样的操作可以挤在同一拍

判据只有一条：**不抢总线、不抢部件的操作才能同拍**。

典型例子是 PC 自增。(PC)+1→PC 由 PC 旁边**专门的加 1 逻辑**完成，全程不碰内部总线，因此可以和访存挤在同一个节拍里，不必单独占一拍。

### 节拍数 ≠ 时钟周期数

为了讲清数据流，通常把"M(MAR)→MDR"写成一个节拍。但一次主存访问的实际耗时远大于一个时钟周期。

设"从发出主存读命令到数据送到 MDR 共需 5 个时钟周期"，则取指阶段的时钟周期数是1 (送地址)+5 (主存读)+1 (送 IR)=7 个时钟周期

而节拍数只有 3。**"几个微操作节拍"和"几个时钟周期"是两个不同的量**，后者必须把访存的延迟拍数算进去。

## 五、取指周期：所有指令共用

| 节拍 | 微操作 | 有效控制信号 |
| --- | --- | --- |
| T1 | MAR←(PC) | `PCout, MARin` |
| T2 | MDR←M(MAR)，PC←(PC)+1 | `MemR, MDRinE, PC+1` |
| T3 | IR←(MDR) | `MDRout, IRin` |
| T4 | 指令译码 | 无 |

译码不占总线也不传数据，因此这一拍没有有效的门控信号。

## 六、三类指令的执行周期

**① 寄存器–寄存器型：`ADD R0, R1`**，功能 (R0)+(R1)→R0

| 节拍 | 微操作 | 控制信号 |
| --- | --- | --- |
| T4 | (R0)→Y | `R0out, Yin` |
| T5 | (R1)+(Y)→Z | `R1out, ALU(add), Zin` |
| T6 | (Z)→R0 | `Zout, R0in` |

**双操作数运算固定是三拍**：先进 Y、再运算进 Z、最后 Z 写回。这个三拍模式是单总线结构的直接后果。

> [!CAUTION]
>

不可交换的运算：谁进 Y，谁走总线

ALU 的两个输入端是**不对称**的：一个固定接 Y，另一个接内部总线。教材把运算写成(总线上的操作数) op (Y)→Z

——**写在前面的是走总线的那个**（上表 T5 的 (R1)+(Y)→Z 正是这个形状）。

加法、与、或这些**可交换**的运算，两个操作数谁进 Y 都算得对，所以从加法的例子里看不出这条约定。**减法、比较不行**：

判据：**被减数走总线，减数进 Y。** 摆反了，算出来的是相反数。

以 `SUB (R0), R1`（功能 M[(R0)]−(R1)→M[(R0)]）的执行周期为例：

| 节拍 | 微操作 | 控制信号 | 说明 |
| --- | --- | --- | --- |
| T4 | (R0)→MAR | `R0out, MARin` | 目的地址送 MAR |
| T5 | M(MAR)→MDR | `MemR, MDRinE` | 取出被减数 |
| T6 | (R1)→Y | `R1out, Yin` | **减数进 Y** |
| T7 | (MDR)−(Y)→Z | `MDRout, ALU(sub), Zin` | **被减数走总线** |
| T8 | (Z)→MDR | `Zout, MDRin` | 结果送 MDR，内总线侧 |
| T9 | M(MAR)←(MDR) | `MDRoutE, MemW` | 写回主存，DB 侧 |

若按加法的习惯把 (MDR) 送 Y、(R1) 走总线，得到的是 (R1)−M[(R0)]，**符号正好反掉**。

遇到一张陌生的通路图时，先看清 ALU 的哪个输入端接 Y——**图上的约定优先于任何记忆**。

**② 取数型：`LOAD R0, (R1)`**，功能 M[(R1)]→R0

| 节拍 | 微操作 | 控制信号 |
| --- | --- | --- |
| T4 | (R1)→MAR | `R1out, MARin` |
| T5 | M(MAR)→MDR | `MemR, MDRinE` |
| T6 | (MDR)→R0 | `MDRout, R0in` |

**③ 存数型：`STORE (R1), R0`**，功能 (R0)→M[(R1)]

| 节拍 | 微操作 | 控制信号 |
| --- | --- | --- |
| T4 | (R1)→MAR | `R1out, MARin` |
| T5 | (R0)→MDR | `R0out, MDRin` |
| T6 | (MDR)→M(MAR) | `MDRoutE, MemW` |

> [!TIP]
>

对照 ② 和 ③ 的第二拍

同样是"→MDR"，信号完全不同：

- 取数是 **DB** 把数据打进 MDR，用 `MDRinE`
- 存数是**内部总线**把数据打进 MDR，用 `MDRin`

数据从哪一侧进来，就用哪一侧的门控信号。

## 例题一：访存加法，结果回寄存器

**题**：写出 `ADD R0, (R1)`（功能 (R0)+M[(R1)]→R0）从取指到执行完毕的全部节拍。

| 节拍 | 微操作 | 控制信号 | 说明 |
| --- | --- | --- | --- |
| T1 | (PC)→MAR | `PCout, MARin` | 取指 |
| T2 | M(MAR)→MDR，(PC)+1→PC | `MemR, MDRinE, PC+1` | 取指 |
| T3 | (MDR)→IR | `MDRout, IRin` | 取指、译码 |
| T4 | (R1)→MAR | `R1out, MARin` | 送操作数地址 |
| T5 | M(MAR)→MDR | `MemR, MDRinE` | 取操作数 |
| T6 | (MDR)→Y | `MDRout, Yin` | 一个操作数进暂存器 |
| T7 | (R0)+(Y)→Z | `R0out, ALU(add), Zin` | 另一个操作数走总线，运算 |
| T8 | (Z)→R0 | `Zout, R0in` | 结果写回 |

共 8 拍，其中访问主存的是 **T2、T5** 两拍（取指一次 + 取操作数一次）。

## 例题二：结果写回主存

**题**：写出功能为 (R0)+M[(R1)]→M[(R1)] 的指令的执行周期节拍（取指周期已完成）。

与例题一的区别只在结果的去向——回主存而不是回寄存器，因此 MDR 的四个信号全都会用上：

| 节拍 | 微操作 | 控制信号 | 说明 |
| --- | --- | --- | --- |
| T4 | (R1)→MAR | `R1out, MARin` | 先把地址送 MAR 才能访存 |
| T5 | M(MAR)→MDR | `MemR, MDRinE` | 从 DB 读出操作数 |
| T6 | (MDR)→Y | `MDRout, Yin` | 被加数送入暂存器 |
| T7 | (R0)+(Y)→Z | `R0out, ALU(add), Zin` | 另一操作数走内总线，运算 |
| T8 | (Z)→MDR | `Zout, MDRin` | 结果送 MDR，**内总线侧** |
| T9 | M(MAR)→ 写入 | `MDRoutE, MemW` | 写回主存，**DB 侧** |

两个关键点：

- T8 用 `MDRin`（内总线 → MDR）、T9 用 `MDRoutE`（MDR → DB），方向不能写反
- **MAR 从 T4 装入后全程不用重装**，因为读和写的是同一个存储单元

## 教材例题：间接寻址的加法 `ADD @X`

教材给出的是带**间址周期**的完整三周期样本：

| 周期 | 微操作序列 |
| --- | --- |
| **取指** | (PC)→MAR → 发读命令 → 主存 → MDR → (MDR)→IR → (PC)+1→PC |
| **间址** | (MDR)→MAR（形式地址）→ 发读命令 → 主存 → MDR（有效地址）→ (MDR)→Ad(IR) |
| **执行** | (MDR)→MAR（有效地址）→ 发读命令 → 主存 → MDR（操作数）→ (MDR)→Y → (AC)+(Y)→Z → (Z)→AC |

**间址周期的作用就是把"形式地址"换成"有效地址"**：读一次主存，把读回的有效地址填回 IR 的地址码字段，执行周期再拿它去访存取真正的操作数。

因此间接寻址比直接寻址**多一次访存**——这一条在 [[03_计算机组成原理_CO/cpu/instruction-cycle.md|指令执行过程]] 中已经出现过，在这里得到了逐拍的印证。加载可视化中...

## 易混淆知识点

**1. Y 和 Z 是程序员可见的吗？**

**不可见**。两者纯属单总线结构的实现细节，指令集里没有任何指令能触碰它们。换成三总线结构，它们就不存在了。

**2. `MDRout` 和 `MDRoutE` 有什么区别？**

`MDRout` 把 MDR 的内容送到**内部总线**（给 IR、Y 或某个寄存器用），`MDRoutE` 把它送到**数据总线**（给主存用）。两者是 MDR 的两个不同输出端口，可以在不同节拍分别开启。

**3. 为什么运算结果不能直接从 ALU 送回目的寄存器？**

因为 ALU 的输出端如果直接挂上内部总线，而它的一个输入端也从内部总线取数，就形成了 **输出 → 总线 → 输入** 的反馈回路。组合逻辑电路一旦有反馈，输出会不断影响自身输入，结果不确定。Z 把这个回路切断了。

**4. 单总线 CPU 的一条指令要几个节拍？**

没有固定答案，取决于指令要做多少次总线传送。经验规律：

| 动作 | 占用节拍 |
| --- | --- |
| 取指 | 3 拍（送地址、访存、送 IR） |
| 每访存一次 | 2 拍（送 MAR、访存） |
| 双操作数运算 | 3 拍（进 Y、运算进 Z、Z 写回） |
| 结果回主存 | 2 拍（进 MDR、写主存） |

按指令的实际数据流把这些段拼起来即可。

## 本节小结

- 单总线结构的核心约束：**每个节拍总线上只能传一个数据**
- **Y 解决"ALU 输入凑不齐"**（总线的时间独占性），**Z 解决"输出回灌输入"**（组合逻辑的反馈通路）——两者动机不同
- **三总线结构下 Y、Z 可以省掉**，因为不存在一拍只传一个的瓶颈
- **MDR 是双端口**，有四个门控信号；带 E 的通向数据总线，不带 E 的通向内部总线
- 同拍判据：**不抢总线、不抢部件**。PC 自增有专用加 1 逻辑，可并入访存那一拍
- **节拍数 ≠ 时钟周期数**，后者要算入主存访问的延迟
- 双操作数运算固定三拍（进 Y → 运算进 Z → Z 写回），这是单总线的直接后果
- ALU 两个输入端**不对称**，运算写成 (总线) op (Y)→Z；不可交换的运算按**被减数走总线、减数进 Y**摆，摆反了差一个符号
- 间址周期把**形式地址换成有效地址**，间接寻址比直接寻址多一次访存
