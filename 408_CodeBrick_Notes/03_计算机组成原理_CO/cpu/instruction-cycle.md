# 指令执行过程

## 大纲定位

**五（二）指令执行过程**

要求：能把一条指令的执行拆成取指、间址、执行、中断四个子周期，说清每个子周期的任务与数据流向，并写出典型指令的微操作序列。

各部件的功能见 [[03_计算机组成原理_CO/cpu/cpu-overview.md|CPU 的功能和基本结构]]；这些微操作在具体电路上如何实现见 [[03_计算机组成原理_CO/cpu/single-bus-datapath.md|单总线数据通路]]。

## 知识框架

本节回答四个问题：

- 一条指令的执行为什么要拆成四个子周期？拆分的依据是什么？
- 四个子周期各自的数据流是什么样的？
- CPU 怎么知道自己现在处在哪个子周期？
- 指令周期、机器周期、时钟周期是什么关系？

## 一、四个子周期

一条指令的完整执行过程可以划分为四个子周期：取指周期→间址周期（可选）→执行周期→中断周期（可选）

> [!TIP]
>

四个子周期的划分依据：访存目的不同

这四个阶段**都要访问存储器**，区别只在于访存的目的：

| 子周期 | 访存是为了 |
| --- | --- |
| **取指周期** | 取**指令** |
| **间址周期** | 取操作数的**有效地址** |
| **执行周期** | 取**操作数**（当指令为访存指令时） |
| **中断周期** | 保存**程序断点** |

这就是为什么划分成这四段——每一次访存都要占用完整的一个存储周期，是天然的时间分界点。理解了这一条，四个周期的名字就不必硬记。

四个子周期中**只有取指周期是每条指令都有的**：

- **间址周期**只在采用间接寻址时出现
- **中断周期**只在本条指令结束时确有中断请求才进入

因此不同指令的指令周期长度差别很大。无条件转移指令 `JMP X` 在执行阶段既不访存也无复杂运算，转移地址完全可以在取指阶段的后期就送入 PC——**它的指令周期几乎等于取指周期**。而乘法指令的执行阶段要做多轮加法和移位，执行周期远长于加法指令。图 8.5　指令周期示意图（唐朔飞《计算机组成原理》第 3 版，见文末教材出处）

## 二、取指周期

**任务**：从内存中读取指令，送入 IR。

由于所有指令的取指操作**完全相同**（都是"按 PC 指的地址读一个指令字回来"），取指周期是唯一可以画出统一数据流图的公共阶段。

| 步骤 | 微操作 | 说明 |
| --- | --- | --- |
| 1 | (PC)→MAR | PC 的内容（指令地址）送 MAR，再送地址总线 |
| 2 | 1→R | CU 经控制总线发出读命令 |
| 3 | M[MAR]→MDR | 主存把指令经数据总线送入 MDR |
| 4 | (MDR)→IR | 指令送入指令寄存器 |
| 5 | OP(IR)→CU | 操作码送控制单元译码 |
| 6 | (PC)+1→PC | PC 自增，指向下一条指令 |

> [!WARNING]
>

PC 自增为什么必须放在取指周期

因为**转移指令在执行周期要改写 PC**。如果把自增留到指令末尾再做，转移刚写进去的目标地址就会被加掉。

先增后改还带来一个副产品：取指周期结束后，PC 里已经是"下一条指令的地址"。相对寻址正是以这个值为基准，转移指令只需给出位移量即可。

第 6 步中的"+1"是简写。实际增量取决于**编址方式与指令字长**：按字节编址、32 位定长指令，则每次加 4。可变长指令则要按本条指令的实际字节数递增，这个值在译码后才能确定。

## 三、间址周期

**任务**：当指令采用间接寻址时，取出操作数的**有效地址**。

**触发条件**：指令中的寻址特征位表明是间接寻址。

| 步骤 | 微操作 | 说明 |
| --- | --- | --- |
| 1 | Ad(IR)→MAR | 指令中的形式地址送 MAR |
| 2 | 1→R | 读内存 |
| 3 | M[MAR]→MDR | 读出的内容就是**有效地址** |
| 4 | (MDR)→MAR | 有效地址送 MAR，为执行周期访存做准备 |

多重间接寻址时重复上述过程，直至取到最终有效地址。

> [!TIP]
>

间址周期取的是地址，不是操作数

这是最容易混的一点。间址周期结束时，MDR 里装的是**一个地址**，不是数据。真正的操作数要到**执行周期**才被取出来。

也就是说，一条间接寻址的访存指令要访问主存**三次**：取指一次、取有效地址一次、取操作数一次。

## 四、执行周期

**任务**：完成指令规定的操作。

> [!WARNING]
>

执行周期没有统一的数据流

前三个子周期的操作对所有指令都一样，唯独执行周期**因指令而异**——可能是 CPU 内部寄存器间传送，可能是访存读写，也可能是 ALU 运算。因此执行周期无法画出统一的数据流图，只能逐条指令分析。

这也是控制器设计的难点所在：取指部分是固定电路，执行部分才需要按操作码分支。

以几类典型指令为例（设为单地址格式，隐含使用 ACC）：

### 加法指令 `ADD X`（直接寻址）
ACC←ACC+M[X]

| 步骤 | 微操作 |
| --- | --- |
| 1 | Ad(IR)→MAR |
| 2 | M[MAR]→MDR |
| 3 | (ACC)+(MDR)→ACC |

### 存数指令 `STA X`
M[X]←ACC

| 步骤 | 微操作 |
| --- | --- |
| 1 | Ad(IR)→MAR |
| 2 | (ACC)→MDR |
| 3 | 1→W，(MDR)→M[MAR] |

### 无条件转移指令 `JMP X`

| 步骤 | 微操作 |
| --- | --- |
| 1 | Ad(IR)→PC |

转移指令的执行周期最简单，只需改写 PC，**不访存**。

### 条件转移指令 `BZ X`

| 步骤 | 微操作 |
| --- | --- |
| 1 | 若 ZF=1，则 Ad(IR)→PC；否则不操作 |

条件转移的判断依据来自 PSW 中的标志位，而标志位是**前一条运算指令**留下的——这正是 PSW 存在的意义。

## 五、中断周期

**任务**：保存断点，转入中断服务程序。

CPU 在每条指令**执行阶段结束前**发出中断查询信号；若有请求，则进入中断周期。

| 步骤 | 微操作 | 说明 |
| --- | --- | --- |
| 1 | 0→EINT | **关中断**，防止保存断点的过程被打断 |
| 2 | (SP)−1→SP，(SP)→MAR | 栈指针减 1，准备压栈 |
| 3 | 1→W | 发写命令 |
| 4 | (PC)→MDR，(MDR)→M[MAR] | 断点（PC 的值）经数据总线存入存储器 |
| 5 | 中断服务程序入口地址 →PC | 为下一个取指周期做好准备 |

> [!CAUTION]
>

关中断为什么必须排在最前面

第 2~4 步正在把断点写进栈里。如果这期间又来一个中断被响应，新的中断会再压一个断点，两次压栈的目标地址由同一个 SP 决定——**断点会被覆盖或错位，原程序再也回不去了**。

因此顺序是硬性的：**先关中断，再保存断点**。这个次序在异常与中断一章还会反复出现。

保存断点用的存储器地址由 CU 提供（如栈指针的内容），而不是由指令给出——中断周期完全是硬件自主完成的，程序里没有任何一条指令对应它。

## 六、CPU 怎么知道自己在哪个周期

既然四个子周期的访存动作外形相似（都是"送地址、发命令、收数据"），CPU 必须有办法区分当前处在哪一段。

做法是在 CPU 内设置**四个标志触发器**，分别对应取指、间址、执行、中断四个工作周期。任一时刻只有一个被置 1，用它来选通对应的微操作序列。

| 触发器 | 对应周期 |
| --- | --- |
| FE | 取指周期 |
| IND | 间址周期 |
| EX | 执行周期 |
| INT | 中断周期 |

这四个触发器的状态就是控制器的"当前状态"，控制器据此决定下一步发什么信号——这一思路在 [[03_计算机组成原理_CO/cpu/hardwired-control.md|硬布线控制器]] 中会展开成完整的状态机。

四者之间的流转关系是固定的，每条边的**跳转条件**都能从前面几节推出来：

读这张图要抓住三点：

| 边 | 由什么决定 | 什么时候判 |
| --- | --- | --- |
| FE → IND 还是 FE → EX | 指令的**寻址特征位** | 取指周期译码后 |
| IND → IND | 是否**多重间接寻址** | 每取到一层地址后 |
| EX → INT 还是 EX → FE | 是否**确有中断请求且允许中断** | 执行阶段结束前的中断查询 |

**四个触发器任一时刻只有一个为 1**，所以这是一张真正的状态图，而不是流程示意——箭头就是触发器的置位/复位动作。

## 七、三种周期的关系

| 名称 | 定义 |
| --- | --- |
| **时钟周期**（节拍、T 周期） | CPU 的最小时间单位，T=1/f |
| **机器周期**（CPU 周期） | 完成一个基本操作（典型如一次访存）所需的时间，含若干时钟周期 |
| **指令周期** | 取出并执行一条完整指令所需的全部时间 |

指令周期≥机器周期≥时钟周期

> [!TIP]
>

三者的关系不是固定倍数

这个不等式取"≥"而不是">"，是有原因的：

- **单周期 CPU** 中，一条指令在**一个时钟周期**内完成，此时三者**相等**
- **多周期 CPU** 中，指令周期含多个机器周期，机器周期又含多个时钟周期
- 现代流水线 CPU 中，一条指令的指令周期跨多个时钟周期，但**平均每个时钟周期完成一条指令**

因此"一个指令周期包含几个机器周期"没有通用答案，取决于 CPU 的设计方式和具体指令。

## 易混淆知识点

**1. 机器周期一定等于存取周期吗？**

不一定，但常常按存取周期来取。机器周期的宽度由**最耗时的基本操作**决定，而在多数机器中最慢的基本操作就是一次访存，因此教材常直接用存取周期作为机器周期。若 CPU 内部有比访存更慢的操作（少见），则以那个为准。

**2. 取指周期一定是一个机器周期吗？**

不一定。若指令字长大于存储字长，取一条指令需要**多次访存**，取指周期就要占多个机器周期。例如存储字长 16 位、指令字长 32 位时，取指要访存两次。

**3. "指令周期"和"CPU 周期"是一回事吗？**

不是。**CPU 周期是机器周期的别名**，指的是四个子周期中的一段；指令周期是整条指令的全过程。两个名字长得像，含义差一个数量级。

**4. 中断周期属于指令周期吗？**

属于。中断周期是指令周期的第四个子周期，发生在**本条指令执行结束之后、下一条指令取指之前**。所以中断是"指令级"响应的——CPU 不会在一条指令执行到一半时中途响应中断（异常除外，见 [[03_计算机组成原理_CO/cpu/exception-interrupt.md|异常和中断机制]]）。

## 本节小结

- 四个子周期：**取指 → 间址（可选）→ 执行 → 中断（可选）**
- 划分依据是**访存目的不同**：取指令 / 取有效地址 / 取操作数 / 存断点
- 只有**取指周期**每条指令都有，且是唯一有统一数据流的阶段
- **PC 自增必须在取指周期完成**，否则会覆盖转移指令写入的目标地址
- 间址周期取的是**有效地址**而非操作数；间接寻址的访存指令共访存**三次**
- **执行周期因指令而异**，无法画统一数据流图
- 中断周期的动作顺序是硬性的：**关中断 → 保存断点 → 转入服务程序**
- CPU 用**四个工作周期标志触发器**区分当前所处的子周期
- 指令周期≥机器周期≥时钟周期，单周期 CPU 中三者相等
