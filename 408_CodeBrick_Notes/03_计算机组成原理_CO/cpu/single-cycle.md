# 单周期数据通路

## 大纲定位

**五（三）数据通路的功能和基本结构**

要求：能读懂给定的数据通路图，指出某条指令在通路上的数据流向，以及各控制信号在该指令下的取值。

把同一条指令拆到多个周期执行的做法见 [[03_计算机组成原理_CO/cpu/multi-cycle.md|多周期数据通路]]；另一种常见的通路结构见 [[03_计算机组成原理_CO/cpu/single-bus-datapath.md|单总线数据通路]]。

## 知识框架

本节回答四个问题：

- 数据通路是怎么"搭"出来的——为什么恰好需要这些部件？
- 每条指令在通路上走哪条路径？控制信号取什么值？
- 单周期的时钟周期由什么决定？
- 单周期为什么必须用专用数据通路，不能用单总线？

> [!TIP]
>

两种数据通路模型

本文采用 MIPS 风格的教学模型（RegDst、ALUSrc、MemToReg 这套信号命名），它的优点是把"指令如何流过通路"画得非常直观，是理解流水线的必要铺垫。

另一种是单总线结构 + 微操作传送语句（(PC)→MAR 这种写法），见 [[03_计算机组成原理_CO/cpu/single-bus-datapath.md|单总线数据通路]]。两种模型描述的是同一件事，只是抽象层次不同。

## 一、单周期的基本思想

**每条指令在一个时钟周期内完成**。

这意味着一条指令要用到的所有部件必须**同时**在空间上展开、一次走完，不能分时复用。由此推出两个直接后果：

- 指令存储器和数据存储器**必须分开**（哈佛结构）。因为 lw 指令在同一个周期内既要取指令又要读数据，一个存储器办不到
- 需要**多个加法器**。计算 PC+4 和计算分支目标地址是两件事，同一周期内都要做，不能共用 ALU

## 二、部件是怎么推出来的

从"要执行哪些指令"出发，每个部件都是某个功能的必要条件：

| 指令要做什么 | 因此必须有 | 部件 |
| --- | --- | --- |
| 记住取哪条指令 | 一个能保存地址的状态元件 | **PC** |
| 按地址取出指令 | 一个只读的存储部件 | **指令存储器** |
| 读写通用寄存器 | 两读一写的多端口存储 | **寄存器堆** |
| 运算、算地址、比较 | 一个算术逻辑部件 | **ALU** |
| 访问内存数据 | 可读可写的存储部件 | **数据存储器** |
| 把 16 位立即数与 32 位数运算 | 位数补齐 | **符号扩展单元** |
| 算 PC+4、算分支目标 | 与 ALU 并行的加法电路 | **加法器** ×2 |
| 在多个数据来源中挑一个 | 由控制信号选通 | **多路选择器 MUX** |

寄存器堆需要**两个读端口**是因为 R 型指令要同时读 rs 和 rt——如果只有一个读端口，读两个操作数就得占两个周期，单周期立刻不成立。

## 三、控制信号

| 信号 | 作用 |
| --- | --- |
| **RegDst** | 选择目的寄存器编号的来源（R 型用 rd，I 型用 rt） |
| **ALUSrc** | 选择 ALU 的第二操作数（寄存器值 或 立即数） |
| **MemToReg** | 选择写回寄存器的数据（ALU 结果 或 内存读出值） |
| **RegWrite** | 允许写寄存器堆 |
| **MemRead** | 读数据存储器 |
| **MemWrite** | 写数据存储器 |
| **Branch** | 分支控制，与 ALU 的零标志相与后决定 PC 的来源 |
| **Jump** | 无条件转移控制，选中"拼接出来的跳转目标"作为下条指令地址 |
| **ExtOp** | 扩展器的方式：**1 符号扩展**（立即数是有符号数）、**0 零扩展**（立即数是逻辑常量） |
| **ALUOp** | 告知 ALU 控制部件本条指令要做哪类运算 |

> [!TIP]
>

控制信号的两种角色

这些信号可以分成两类，分清楚它们有助于理解控制器设计：

- **选择类**（RegDst、ALUSrc、MemToReg、Branch）：控制 MUX 挑哪一路。挑错了结果就错，但不会破坏状态
- **写使能类**（RegWrite、MemWrite）：控制状态元件**要不要真的写进去**。这类信号必须绝对准确——错误地置 1 会污染寄存器或内存

因此在无关项（don't care）的处理上两类不同：**选择类信号可以是 x，写使能类信号绝不能是 x**。sw 指令的 RegDst 是 x（反正不写寄存器），但 RegWrite 必须明确为 0。

## 四、各类指令的数据通路

### R 型指令（add / sub / and / or / slt）

格式：`op | rs | rt | rd | shamt | funct`

数据流：

- PC → 指令存储器，取出指令
- 指令中的 rs、rt 字段 → 寄存器堆，读出两个操作数
- 两个操作数 → ALU，执行 funct 指定的运算
- ALU 结果 → 寄存器堆，写入 rd 号寄存器

控制信号：`RegDst=1, ALUSrc=0, MemToReg=0, RegWrite=1, MemRead=0, MemWrite=0, Branch=0, Jump=0`

### lw 指令（取数）

格式：`lw rt, imm(rs)`，功能：rt←M[rs+imm]

数据流：

- 取指令
- 读寄存器 rs
- 符号扩展 imm（16 位 → 32 位）
- ALU 计算 rs + 立即数，得到有效地址
- 有效地址 → 数据存储器，读出数据
- 读出的数据 → 寄存器堆，写入 rt

控制信号：`RegDst=0, ALUSrc=1, MemToReg=1, RegWrite=1, MemRead=1, MemWrite=0, Branch=0, Jump=0`

### sw 指令（存数）

格式：`sw rt, imm(rs)`，功能：M[rs+imm]←rt

数据流：

- 取指令
- 读寄存器 rs 和 rt
- 符号扩展 imm
- ALU 计算基址 + 偏移 = 有效地址
- rt 的值 → 数据存储器，写入有效地址

控制信号：`RegDst=x, ALUSrc=1, MemToReg=x, RegWrite=0, MemRead=0, MemWrite=1, Branch=0, Jump=0`

### beq 指令（相等则转移）

格式：`beq rs, rt, label`，功能：若 rs = rt，则 PC←PC+4+imm×4

数据流：

- 取指令，同时另一个加法器算出 PC+4
- 读寄存器 rs 和 rt
- ALU 计算 rs − rt，得到零标志 Zero
- 符号扩展并左移 2 位的偏移量 + (PC+4) = 分支目标地址
- 若 Zero =1 且 Branch =1，则 PC ← 分支目标地址；否则 PC ← PC+4

控制信号：`RegDst=x, ALUSrc=0, MemToReg=x, RegWrite=0, MemRead=0, MemWrite=0, Branch=1, Jump=0`

> [!WARNING]
>

beq 用 ALU 做减法，不用专用比较器

判断"两数是否相等"完全可以用一个异或电路做，为什么要动用 ALU？

因为**减法器已经在那里了**。既然 ALU 本来就要支持减法，让它顺带产生一个 Zero 标志几乎不增加成本；而单独加一个比较器则要多一块电路、多一条通路。这是硬件设计中反复出现的取舍——**复用已有部件优于新增部件**。

同理，分支目标地址用的是一个**独立的加法器**而不是 ALU，因为 ALU 这个周期正忙着做减法，而单周期里没有第二个时刻可用。

### j 指令（无条件转移）

格式：`j target`，指令中给出 26 位目标地址字段。

数据流只有一条：把跳转目标地址拼出来送 PC，**寄存器堆和数据存储器全程不参与**。PC←PC31:28⏟当前 PC 的高 4 位 ∥ target25:0⏟指令给的 26 位 ∥ 00⏟按字对齐，低 2 位恒 0

控制信号：`RegDst=x, ALUSrc=x, MemToReg=x, RegWrite=0, MemRead=0, MemWrite=0, Branch=0, Jump=1`

> [!WARNING]
>

拼接式跳转的边界：跳不出当前 256 MB 段

26 位目标字段左移 2 位后能覆盖 228 B = 256 MB，剩下的高 4 位是**照抄当前 PC 的**，不是算出来的。

因此 j 只能在当前这个 256 MB 区段内跳转，跨段必须改用寄存器间接转移（`jr`）。**"拼接"和"相加"是两种不同的目标地址生成方式**：

| 指令 | 目标地址怎么来 | 能跳多远 |
| --- | --- | --- |
| **beq**（相对寻址） | PC+4 + 符号扩展(imm16) ×4 | 以当前位置为中心的 ±128 KB |
| **j**（伪直接寻址） | 高 4 位**拼接** + 26 位字段 ×4 | 当前 256 MB 段内任意位置 |

相对寻址靠加法，能正能负但范围小；伪直接寻址靠拼接，范围大但出不了段。图 5.16　完整的单周期数据通路（袁春风《计算机组成与系统结构》第 3 版，见文末教材出处）

这张图是把前面按指令类型逐步搭出来的几张通路（R 型 / I 型运算 / load-store / 分支 / 无条件转移）**合并**的结果。合并的方法很机械：同一个部件的输入端如果有多个来源，就在那里插一个 MUX，并为它引一个控制信号。图上带下划线的名字就是控制器要产生的全部控制信号。

## 五、控制信号汇总表

| 指令 | RegDst | ALUSrc | MemToReg | RegWrite | MemRead | MemWrite | Branch | Jump |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| R 型 | 1 | 0 | 0 | 1 | 0 | 0 | 0 | 0 |
| lw | 0 | 1 | 1 | 1 | 1 | 0 | 0 | 0 |
| sw | x | 1 | x | 0 | 0 | 1 | 0 | 0 |
| beq | x | 0 | x | 0 | 0 | 0 | 1 | 0 |
| j | x | x | x | 0 | 0 | 0 | 0 | 1 |

x 表示无关项（don't care）。

表中未列 **ExtOp**：上面五条指令用到立即数的地方（lw/sw 的偏移、beq 的位移）都按**有符号数**处理，ExtOp 恒为 1；R 型和 j 根本不经过扩展器，取 x。只有 `ori`、`andi` 这类把立即数当**逻辑常量**的指令才取 0（零扩展）。**判据是立即数该不该有符号，不是指令属于哪一类。**

控制器的实现就是把这张表当作真值表：**输入是操作码，输出是每个控制信号**，逐列写出逻辑表达式即可。这类组合逻辑通常用 PLA 实现。

## 六、时钟周期由关键路径决定

单周期的 CPI 恒为 1，因此性能完全取决于时钟周期能压到多短。而时钟周期必须**装得下最慢的那条指令**——通常是 lw，因为它是唯一串起全部五个环节的指令。

lw 的一个指令周期包含：T≥tPC 锁存延迟+t取指令+t寄存器取数+tALU+t存储器取数+t寄存器建立+t时钟扭斜

> [!TIP]
>

别漏掉两头的三项

最容易被忽略的是首尾三项，它们不属于"干活"的时间，却必须算进去：

- **锁存延迟**（Clk-to-Q）：时钟沿到来后，PC 的输出稳定下来还需要一小段时间
- **建立时间**（setup time）：数据必须在下一个时钟沿**之前**就稳定，且提前量不小于建立时间，否则写入的值不确定
- **时钟扭斜**（clock skew）：时钟信号到达芯片各处的时刻并不完全一致，必须留出裕量

中间四项是各功能部件的组合逻辑延迟。**只算中间四项会低估时钟周期。**

其他指令的路径更短——R 型不访存，beq 连写回都没有——但它们**同样要等满一个时钟周期**。这就是单周期效率低的根源：为最慢的指令买单，所有指令一起付账。

## 七、单周期为什么不能用单总线

> [!CAUTION]
>

单周期数据通路不可能采用 CPU 内部单总线结构

理由很直接：内部单总线**同一时刻只能传送一个数据**。

而执行一条指令至少要在总线上传好几趟——取指要走一趟（PC→MAR、MDR→IR），读操作数走一趟，写结果又走一趟。这些传送**必须分时**进行，也就必须占用**多个时钟周期**。

一旦需要多个时钟周期，它就不是单周期 CPU 了。

所以单周期 CPU 必须用**专用数据通路**——部件之间直接连线，多路数据同时流动，代价是连线多、电路复杂、部件利用率低（一条指令期间大部分部件是闲置的）。

反过来也成立：**单总线数据通路一定是多周期的**。这就是为什么那类通路的每一步都要数时钟周期。

| 数据通路结构 | 同时可传数据 | 必然的周期数 |
| --- | --- | --- |
| **单总线** | 1 路 | 多周期 |
| 多总线 | 若干路 | 多周期（周期数变少） |
| **专用数据通路** | 不受限 | 可做到单周期 |

## 易混淆知识点

**1. 单周期 CPU 执行一条指令时，控制信号会变化吗？**

**不会**。控制信号由**组合逻辑**直接从操作码译出，在整个时钟周期内保持同一组值。

这一点很容易想反——"一条指令要做取指、读寄存器、运算、写回那么多步，信号怎么可能不变？"关键在于：单周期里这些步骤是**同时在空间上展开**的（各部件在通路的不同位置同时工作，数据像水一样从头流到尾），不是在时间上分步进行的。

**控制信号随步骤变化的是多周期 CPU**，因为多周期的控制器是状态机，每个状态发一组不同的信号。

**2. 单周期的时钟频率是高还是低？**

**低**。时钟周期要装下最慢指令的完整通路延迟，因此频率被压得很低。这是单周期性能差的直接原因——CPI 虽然只有 1，但每个周期都很长。

**3. R 型指令不访存，是不是就快一些？**

在单周期里**不会**。所有指令的执行时间都等于一个时钟周期，R 型指令走完自己的路径后只能空等，直到周期结束。

正是这个浪费催生了多周期设计：**让每条指令只占它实际需要的周期数**。

**4. 图中的 x（无关项）能随便取值吗？**

功能上可以，电路上不行。x 表示"取 0 或 1 都不影响本条指令的执行结果"，逻辑化简时可以自由指定以简化电路。但如前所述，**写使能类信号不允许是 x**——它们决定要不要真的改写状态。

## 本节小结

- 单周期的定义：**每条指令在一个时钟周期内完成**，CPI 恒为 1
- 由此推出：指令存储器与数据存储器**必须分开**，且需要**多个加法器**
- 寄存器堆需要**两个读端口**，否则 R 型指令读两个操作数就要占两个周期
- 控制信号分**选择类**与**写使能类**；只有选择类可以取无关项 x
- beq 复用 ALU 做减法产生 Zero 标志，体现"复用已有部件优于新增部件"
- 时钟周期 = 关键路径（通常是 lw），**必须计入锁存延迟、建立时间、时钟扭斜**
- 单周期一条指令内**控制信号保持不变**（组合逻辑译出）；多周期才逐步变化
- **单周期不能用单总线结构**，必须用专用数据通路；反之单总线必然多周期
- 分支目标地址 = PC+4 + 符号扩展(imm) ×4（立即数以字为单位，需左移 2 位）
- **j 由 Jump 信号选通**，目标地址靠**拼接**得到（PC 高 4 位 ∥ target26 ∥ 00），因此**跳不出当前 256 MB 段**；beq 靠**相加**，范围小但可正可负
- **ExtOp** 决定符号扩展还是零扩展，判据是**立即数该不该带符号**
