# Cache 的基本原理

## 大纲定位

**三（六）1　Cache 的基本原理**

要求：理解 Cache 依据的局部性原理、Cache 行的组成、一次访存的完整流程，掌握命中率与平均访问时间的计算。

本条之后的三条——映射方式、替换算法、写策略——各有专篇。

## 知识框架

本节回答五个问题：

- CPU 和主存之间为什么要插一层 Cache？凭什么这层小小的存储器能起作用？
- Cache 的一行里，除了数据还存了什么？为什么必须存这些？
- 命中率怎么算？题目不直接给命中次数时怎么办？
- 平均访问时间为什么有两个公式？该用哪一个？
- 多级 Cache 的公式和单级有什么不同？

## 一、Cache 的由来

CPU 的时钟周期已进入亚纳秒级，而 DRAM 的访问时间在百纳秒级——两者相差约两个数量级。若 CPU 每次取指令和数据都直接访问主存，绝大部分时间都消耗在等待上。

解决办法：在 CPU 与主存之间插入一层容量小、速度快的 **SRAM**，存放主存中**部分内容的副本**。

问题随之而来：Cache 容量只有主存的几千分之一，**凭什么能显著提高命中率**？

答案是程序访问存储器的行为并非随机的，而是高度集中的——这就是局部性原理。

### 局部性原理

| 类型 | 含义 | 典型来源 |
| --- | --- | --- |
| **时间局部性** | 刚被访问的单元，近期很可能**再次**被访问 | 循环体、计数器、累加变量 |
| **空间局部性** | 刚被访问的单元，其**相邻**单元近期也很可能被访问 | 顺序执行的指令、数组的连续元素 |

Cache 正是同时利用了这两点：把刚访问的数据留下来（利用时间局部性），并且**一次调入一整块**而不是一个字节（利用空间局部性）。

> [!TIP]
>

两种局部性要分开判断

判断一段程序的局部性时，两者的判据不同，结论也可能相反：

| 判什么 | 依据 |
| --- | --- |
| **时间**局部性 | 同一个单元被访问了几次。≥2 次才有；每个元素只碰一次就没有 |
| **空间**局部性 | 访问的地址是否**顺序推进**。按行优先遍历二维数组有；按列跳跃访问则很差 |

顺序遍历一个大数组是最典型的"**无时间局部性、有空间局部性**"——每个元素只读一次，但地址是连续的。

反过来，按列遍历行优先存储的二维数组：每次跨过一整行的距离，调入 Cache 的一整块里只用了一个元素，空间局部性被完全浪费。

## 二、块与行

为便于 Cache 与主存交换信息，两者的空间都被划分成**大小相等**的区域：

| 名称 | 位于 | 说明 |
| --- | --- | --- |
| **块**（block） | 主存 | Cache 与主存之间的**信息交换单位** |
| **行**（line）/ 槽（slot） | Cache | 存放一个主存块的区域 |

于是"Cache 与主存以块为单位传输"这句话有了确切含义：**一次缺失调入的是一整块，不是一个字节**。这既是空间局部性的利用方式，也是后续所有地址划分的基础。

### 一行里存了什么

Cache 行不只有数据。完整构成是：[ V⏟有效位  Tag⏟标记  Data⏟数据块  (D)⏟脏位  (⋅)⏟替换算法位 ]

| 字段 | 为什么必须有 | 何时存在 |
| --- | --- | --- |
| **有效位 V** | 系统启动或复位时，Cache 行里是随机内容。有效位标记这一行**是否装入过有效数据** | 总是 |
| **标记 Tag** | 一个 Cache 行在不同时刻会装过不同的主存块，必须记录"**现在装的是谁**" | 总是 |
| 数据块 | 从主存搬来的那一整块 | 总是 |
| 脏位 D | 该行被写过、与主存不一致 | 仅**写回**策略 |
| 替换算法位 | 如 LRU 位 | 需要替换决策时 |

> [!WARNING]
>

判命中的完整条件有效位=1 且 标记相符

两个条件缺一不可。若只比较标记，上电后 Cache 行里的随机内容完全可能碰巧与地址匹配，就会把垃圾数据当成命中。

有效位还有一个用途：**把某行的有效位清零，就等于淘汰了该行中的主存块**，这个操作称为**冲刷（flush）**。它比"真的擦除数据"高效得多。

标记字段具体怎么从地址中切出来，见 [[03_计算机组成原理_CO/storage/cache-mapping.md|Cache 和主存之间的映射方式]]。

## 三、访存流程

图 7.26　带 cache 的 CPU 的访存操作过程（袁春风《计算机组成与系统结构（第 3 版）》p236）

CPU 需要取指令或读数据时：

- 先检查 Cache 中有没有——**判命中**（有效位 + 标记）
- **命中**：直接从 Cache 读取，不访问主存
- **缺失**：从主存中把该地址所在的**整个主存块**复制到 Cache，同时把所需数据送给 CPU

图中虚线框内是缺失处理：取出主存块 → 在 Cache 中找一个对应的空闲行 → **一边把数据送 CPU、一边把整块装入 Cache**。这两条支路是**并行**的，不是先装入再转发。

整个过程**由硬件自动完成，对程序员完全透明**——程序中没有任何指令需要显式操作 Cache。这是 Cache 与虚拟存储器最大的区别（后者的缺页必须由操作系统介入）。

## 四、命中率
H=NcNc+Nm

其中 Nc 为命中次数，Nm 为缺失次数。缺失率 M=1−H。

### 由访问模式推算命中率

上式的前提是已知命中与缺失的次数。实际分析程序时，这两个数要自己从访问模式推出来，依据仍是块的概念：

**第一步，一块能装几个元素：**n=块大小单个元素大小

**第二步，顺序遍历时，每块只有首次访问缺失**，块内其余 n−1 次都命中：H=n−1n=1−1n

**例**：块大小 64 B，数组元素为 `int`（4 B），按存储顺序遍历。n=64÷4=16⟹H=1516=93.75%

这个结果说明：即使**完全没有时间局部性**（每个元素只读一次），仅靠空间局部性，命中率也能达到 93.75%。

### 局部性被破坏时会怎样

反过来，若访问步长跨越了整个块，情况会急剧恶化。判据是**工作集是否超过 Cache 的数据容量**：Cache 数据容量=行数×块大小

**例**：Cache 8 行、块 64 B，数据容量 8×64=512 B。某二维数组每行 1024 B，若按**列**访问，每次跨越 1024 B。1024 B>512 B

走完一列回到起点时，先前调入的块**早已被后续的块反复替换掉**，于是每次访问都缺失：H≈0

> [!TIP]
>

根因要说完整

"跨步大、空间局部性差"只描述了现象。完整的因果链是：步长跨块→工作集>Cache 数据容量→反复冲突替换→回来时已被换出→每次都缺失

关键的一环是**与 Cache 数据容量比较**。若工作集小于 Cache 容量，即使步长很大，第二遍遍历时仍然全部命中。

另需注意语句的**访存次数**：`a[i] = a[i] / x` 这类"读改写"语句会编译成一读一写，**一个元素访存 2 次**，统计总次数时不能按 1 次算。

## 五、平均访问时间

Cache 与主存的配合方式有两种，对应两个不同的公式。

### 模型一：先访 Cache，未命中再访主存（串行）
ta=H⋅tc+(1−H)(tc+tm)=tc+(1−H)⋅tm

缺失时，访问 Cache 花掉的时间**已经浪费了**，还要再花一次主存时间。

### 模型二：同时访问 Cache 和主存（并行）
ta=H⋅tc+(1−H)⋅tm

两者同时启动，命中则中止主存访问。缺失时的代价里**不含 Cache 时间**。

### 该用哪一个

两个模型算出的结果不同，必须从题目条件判断：

| 条件的描述方式 | 对应模型 |
| --- | --- |
| "同时访问 / 并行启动 Cache 和主存""命中则中止主存访问" | 模型二 |
| "先访 Cache，未命中再访主存""缺失后从主存调入" | 模型一 |
| 只给出「**命中时间**」和「**缺失损失**」 | 模型一的等价形式 |

第三种最常见，它的等价形式是：ta=命中时间+缺失率×缺失损失

这里「缺失损失」（miss penalty）指的是相对命中而言的**额外**开销，所以一次缺失的总代价是 命中时间 + 缺失损失，而不是只有缺失损失。

## 六、效率与加速比

**效率**衡量平均访问时间离 Cache 本身有多近：e=tcta

**加速比**衡量引入 Cache 后访存快了几倍：S=tmta

**算例**：tc=5 ns、tm=100 ns、H=0.98，按同时访问模型ta=0.98×5+0.02×100=6.9 ns,S=1006.9≈14.5

命中率 98% 换来约 14 倍的提速——这是 Cache 值得存在的量化理由。也可以反过来看：命中率若降到 90%，ta 变成 0.9×5+0.1×100=14.5 ns，加速比只剩约 6.9 倍。**命中率的微小变化会被缺失代价放大**。

## 七、多级 Cache

现代 CPU 普遍设置 L1、L2，甚至 L3。多级的公式与单级同构，只是把"未命中之后去主存"换成"未命中之后去下一级"。

### 局部命中率与全局命中率

| 记号 | 名称 | 含义 |
| --- | --- | --- |
| H1 | L1 命中率 | 在**全部**访问中 L1 命中的比例 |
| H2 | L2 的**局部**命中率 | 在 **L1 未命中的那些访问**中，L2 命中的比例 |
| (1−H1)H2 | L2 的**全局**命中率 | 在全部访问中由 L2 命中的比例 |

> [!WARNING]
>

公式里代的是局部命中率

若条件给出的是 L2 的**全局**命中率 G2，必须先还原成局部命中率：H2=G21−H1

两者混用会使结果整体偏小。

### 两种模型同样要区分
同时访问：ta=H1tc1+(1−H1)[H2tc2+(1−H2)tm]串行访问：ta=tc1+(1−H1)[tc2+(1−H2)tm]

差别只在 tc1 的位置：**串行**提到括号外（每次访问都先付一遍 L1 时间），**同时**乘在 H1 上（只有命中才计入）。

**算例**：tc1=2 ns、tc2=10 ns、tm=200 ns、H1=0.9、H2=0.8（局部），同时访问模型ta=0.9×2+0.1×(0.8×10+0.2×200)=1.8+4.8=6.6 ns

## 例题

**例**：Cache 访问时间 tc=10 ns，主存访问时间 tm=100 ns，命中率 H=0.95。分别按两种模型求平均访问时间，并求同时访问模型下的效率与加速比。

**解**：

同时访问模型：ta=0.95×10+0.05×100=9.5+5=14.5 ns

先访 Cache 模型：ta=10+0.05×100=15 ns

两者相差 0.5 ns，正好是"缺失时白花的那次 Cache 访问时间" (1−H)⋅tc=0.05×10。

同时访问模型下：e=1014.5≈69%,S=10014.5≈6.9

## 易混淆知识点

**1. Cache 容量这么小，为什么能有 90% 以上的命中率？**

因为程序的访问不是均匀散布在整个地址空间的。局部性原理意味着**任一时刻，程序实际活跃的地址范围（工作集）远小于它的地址空间**。Cache 只需装下工作集，而不是装下整个程序。

这也解释了前面那个反例：一旦工作集超出 Cache 容量，命中率会断崖式下跌。

**2. Cache 缺失时，为什么要调入一整块而不是只调所需的那个字节？**

为了利用空间局部性。既然相邻单元很可能马上被访问，一次把整块调入，后续对块内其他地址的访问就都能命中。

从代价看也划算：主存访问的时间主要花在寻址和启动上，多传几十个字节的**边际成本很低**。

**3. Cache 和虚拟存储器都是"缓存"，为什么一个由硬件管理、一个由操作系统管理？**

关键在缺失代价的量级。Cache 缺失约几十到上百个时钟周期，用软件处理的开销本身就超过了缺失代价，只能做进硬件；缺页约 105 个周期，多花几百个周期让操作系统做精细决策完全值得，还能顺便完成磁盘 I/O、页面置换等硬件难以承担的工作。

## 本节小结

- Cache 存放主存内容的**副本**，依据是程序的**局部性原理**
- 时间局部性看"同一单元是否重访"，空间局部性看"地址是否顺序推进"，两者分开判断
- **块**是主存与 Cache 的信息交换单位，Cache 中存放一块的区域叫**行**
- Cache 行 = 有效位 + 标记 + 数据（+ 脏位 + 替换位）
- **判命中 = 有效位为 1 且标记相符**；把有效位清零即淘汰该行，称为冲刷
- 缺失时调入**整块**，且"送 CPU"与"装入 Cache"并行进行
- Cache 由**硬件**管理，对程序员透明
- 顺序遍历时 H=1−1/n，其中 n= 块大小 ÷ 元素大小
- 工作集超过 Cache 数据容量（行数 × 块大小）时会反复冲突替换，H≈0
- 平均访问时间两个模型：串行 ta=tc+(1−H)tm；并行 ta=Htc+(1−H)tm
- 给「命中时间 + 缺失损失」时用串行形式，缺失总代价 = 命中时间 + 缺失损失
- 多级 Cache 中，公式代入的是**局部**命中率，全局命中率需先还原
