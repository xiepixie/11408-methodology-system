# Cache 写策略

## 大纲定位

**三（六）4　Cache 写策略**

要求：理解 Cache 一致性问题的来源，掌握写直达与写回、写分配与非写分配的规则与代价，知道脏位的作用及其对 Cache 容量的影响。

## 知识框架

本节回答四个问题：

- 为什么只有"写"会引出问题，"读"不会？
- 写命中时，主存该不该立刻跟着改？
- 写不命中时，该不该把这块先调进来？
- 这些策略如何影响 Cache 每一行要存的位数？

## 一、一致性问题的来源

Cache 中的内容是主存内容的**副本**。副本一旦被修改，就产生了"以谁为准"的问题。

**读**操作不会破坏一致性——读 Cache 与读主存得到相同的值。问题全部由**写**引出。

一致性问题有三个来源：

| 来源 | 说明 |
| --- | --- |
| **CPU 写 Cache** | Cache 行被更新，若主存未同步，则主存中的副本变成旧值 |
| **I/O 设备直接读写主存** | 如磁盘通过 DMA 方式直接访问主存。若 Cache 中的内容已被 CPU 修改而主存未更新，传给 I/O 设备的就是旧值；反过来，若 I/O 设备修改了主存块，对应的 Cache 行就失效了 |
| **多个 CPU 共享主存** | 各 CPU 有各自的 Cache。某个 CPU 修改了自己 Cache 中的内容后，对应的主存块以及其他 CPU 中对应的 Cache 行都变为无效 |

写策略要解决的正是第一个来源；后两个来源需要额外的硬件协议配合。

> [!TIP]
>

写策略的本质是一个权衡性能（少访问主存）⟷一致性（与主存同步）

同步得越勤，一致性越好，但主存带宽消耗越大。两个极端就是下面的写直达与写回。

写策略分为两个**相互独立**的维度：

- **写命中**（Cache 中有该块的副本）：要不要立刻同步主存？
- **写不命中**（Cache 中没有副本）：要不要先把这块调入 Cache？

## 二、写命中：写直达与写回

### 写直达（Write Through）

**规则**：每次写 Cache 的同时，**也把这次写发往主存**。CPU 写⟶Cache 更新⟶主存同步更新

| 优点 | Cache 与主存**始终一致**；外部设备读主存永远得到最新值；硬件简单，**不需要脏位** |
| --- | --- |
| 缺点 | 每次写都要占用主存带宽，而主存比 Cache 慢一至两个数量级 |

**缓解手段：写缓冲器（Write Buffer）**。CPU 把写请求放进一个 FIFO 缓冲器就继续执行，由缓冲器异步地写入主存，CPU 不必等待。

但缓冲器满了之后 CPU 仍会被阻塞——**写缓冲器只能吸收突发的写，不能消除写直达的持续带宽压力**。

### 写回（Write Back）

**规则**：只写 Cache，**不立即**写主存。等到这一行被**替换**时，若它被修改过，才整行写回主存。CPU 写→Cache 更新，脏位置 1→ 该行被替换时 若脏位为 1 则写回主存

| 优点 | 大幅减少主存访问；**对同一行的多次写只产生一次主存写** |
| --- | --- |
| 缺点 | Cache 与主存**可能不一致**；需要**脏位**；多核与 DMA 场景需额外的一致性协议 |

**关键硬件：脏位（Dirty Bit）**。每行 1 位，标识该行"被改过、与主存不同步"。

> [!WARNING]
>

脏位的意义在于避免无意义的写回

被替换的行若脏位为 0，说明从未被写过，主存中的副本仍然有效，**可以直接覆盖**，不必写回。

若没有脏位，每次替换都得写回一次，写回策略的性能优势就消失了大半。

### 对比

|  | 写直达 | 写回 |
| --- | --- | --- |
| 主存同步时机 | 每次写都同步 | 该行被替换且脏时才同步 |
| 一致性 | 始终一致 | 可能不一致 |
| **脏位** | **不需要** | **每行 1 位** |
| 主存写带宽 | 高 | 低 |
| 对 DMA / 多核 | 友好（外设直接读到新值） | 需一致性协议或显式冲刷 |
| 硬件复杂度 | 简单 | 较复杂 |

## 三、写不命中：写分配与非写分配

### 写分配（Write Allocate）

**规则**：写不命中时，**先把对应的主存块调入 Cache**，再在 Cache 中执行写。

预期这一块接下来还会被访问，先调入可以让后续访问受益。

### 非写分配（No Write Allocate）

**规则**：写不命中时**直接写主存**，不调入 Cache。

预期这次写是一次性的，调入反而挤占 Cache 空间。

## 四、两种主流搭配

两个维度原则上可以任意组合，四种都是合法配置，但实际系统中有两种稳定搭配：

| 写命中 | 写不命中 | 为什么这样配 |
| --- | --- | --- |
| **写直达** | **非写分配** | 反正每次写都要写主存，调入 Cache 并不能省下这次写，还白占一行 |
| **写回** | **写分配** | 写回靠"多次写合并成一次写回"获益，那就应该让数据先进 Cache，才有合并的机会 |

两种搭配各自内部自洽：**同步得勤就别费劲调块，要靠推迟同步获益就得先把块拿进来**。

### 各种情形下动了哪几级存储

| 情形 | Cache 内容 | 脏位 | 写主存 | 调入块 | 触发脏行写回 |
| --- | --- | --- | --- | --- | --- |
| 写直达 + 写命中 | 变 | 无此位 | **是** | 否 | 否 |
| 写直达 + 写不命中（非写分配） | 不变 | 无此位 | **是** | 否 | 否 |
| 写回 + 写命中 | 变 | **置 1** | 否 | 否 | 否 |
| 写回 + 写不命中（写分配） | 变 | **置 1** | 否 | **是** | 被替换行脏则**是** |

两条速记：**写直达一定写主存、永远没有脏位**；**写回只动 Cache 并置脏位，主存写推迟到替换时**。

## 五、写策略对 Cache 容量的影响

Cache 每一行的非数据位随策略变化，这直接影响总容量的计算：每行位数=1⏟有效位+t⏟标记+8×块大小⏟数据+[1]⏟脏位：仅写回+[⌈log2⁡k⌉]⏟LRU 位：需替换决策时

> [!TIP]
>

两个容量口径要分清

- **标记阵列位数**：只算非数据位（有效位 + 标记 + 脏位 + 替换位）
- **Cache 总容量**：非数据位 **加上**数据区

两者相差约二十倍，是两个不同的量。

## 六、多核环境下的写回（拓展）

多核场景中，写回策略必须配合**总线侦听协议**（如 MESI）来维持一致性。MESI 用四个状态描述每个 Cache 行：

| 状态 | 含义 |
| --- | --- |
| M（Modified） | 本核独占，且已被修改、与主存不同步 |
| E（Exclusive） | 本核独占，但与主存同步 |
| S（Shared） | 多核共享，与主存同步 |
| I（Invalid） | 无效 |

大纲不要求展开 MESI，理解"**写回策略在多核下需要硬件一致性协议支持**"即可。

## 例题

**例**：Cache 数据区容量 4 KB，4 路组相联，块大小 64 B，主存地址 32 位，采用**写回**策略与 LRU 替换。求每行的非数据位数、标记阵列总位数与 Cache 总容量；若改为写直达，非数据位数变为多少。

**解**：

**第一步，定各字段位数。**行数=4 KB64 B=64,组数=644=16

- 块内地址 =log2⁡64=6 位
- 组号 =log2⁡16=4 位
- 标记 =32−6−4=22 位

**第二步，数每行的非数据位。** 写回策略有脏位；4 路组相联的 LRU 需 log2⁡4=2 位：1⏟有效位+22⏟标记+1⏟脏位+2⏟LRU 位=26 位标记阵列总位数=64×26=1664 位

**第三步，算总容量。**每行位数=26+64×8⏟数据 512 位=538 位总容量=64×538=34432 位=4304 B≈4.2 KB

**第四步，改为写直达。** 没有脏位，每行非数据位变为 1+22+2=25 位，标记阵列共 64×25=1600 位——比写回少 64 位，正好是 64 行各少 1 个脏位。

## 易混淆知识点

**1. 写命中和写不命中两个维度是独立的吗？**

是的。写直达 / 写回解决的是**命中时如何同步**，写分配 / 非写分配解决的是**不命中时是否调入**。理论上有 2×2=4 种组合，都是合法配置，只是实际常用其中两种。

**2. 脏位是 Cache 的还是主存的？**

是 **Cache 行**的属性，每行 1 位。主存没有脏位——它是"被同步"的那一端，不需要标记自己是否最新。

**3. 写缓冲器和写回缓冲器是一回事吗？**

不是，服务的策略不同：

|  | 配合哪种策略 | 缓存的是什么 |
| --- | --- | --- |
| **写缓冲器**（Write Buffer） | 写直达 | 待写入主存的**写请求** |
| **写回缓冲器**（Write Back Buffer） | 写回 | 被替换出来的**脏行** |

两者的共同目的是让"写主存"这件事异步化，不阻塞 CPU。

**4. 采用写回策略时，Cache 与主存一定不一致吗？**

不一定。某行若从未被写过（脏位为 0），它与主存就是一致的。"可能不一致"说的是**存在不一致的可能**，不是任何时刻都不一致。

**5. 为什么写直达对 DMA 更友好？**

因为主存中的内容永远是最新的。DMA 设备直接从主存读数据时，不需要任何额外机制就能拿到正确的值。

而写回策略下，最新数据可能还留在 Cache 里没写回，此时 DMA 从主存读到的是旧值——必须靠一致性协议或显式冲刷 Cache 来解决。

## 本节小结

- 一致性问题有三个来源：**CPU 写 Cache**、**I/O 设备直接读写主存**、**多 CPU 共享主存**
- 读不破坏一致性，问题全部由写引出
- **写直达**：每次写都同步主存，始终一致，**无脏位**，主存带宽压力大
- **写回**：只写 Cache 并置脏位，替换时才按脏位决定是否写回，性能高，**每行需 1 位脏位**
- 写缓冲器只能吸收突发写，不能消除写直达的持续带宽压力
- **写分配**：写不命中时先调入再写；**非写分配**：直接写主存不调入
- 两种主流搭配：**写直达 + 非写分配**、**写回 + 写分配**
- 每行位数 = 有效位 + 标记 + 数据 + [脏位] + [LRU 位]，后两项按策略与映射方式决定
- 「标记阵列位数」不含数据区，「Cache 总容量」含，两者是不同的量
- 多核下的写回需要 MESI 等一致性协议支持
