# Cache 和主存之间的映射方式

## 大纲定位

**三（六）2　Cache 和主存之间的映射方式**

要求：掌握直接映射、全相联映射、组相联映射三种方式的规则与硬件实现，能据此划分主存地址的字段、确定各字段位数与取值，并计算 Cache 的总容量。

## 知识框架

本节回答四个问题：

- 主存的块调进 Cache 时，放在哪一行？这个位置由谁决定？
- 主存地址为什么被切成三段？每段的位数由什么定？
- 三种映射方式看似各不相同，它们之间有没有统一的关系？
- Cache 的总容量为什么大于它的数据容量？

## 一、映射要解决的问题

主存容量远大于 Cache。主存的某一块要调进 Cache 时，必须先回答一个问题：**它该放进哪一行？**

这个问题必须有确定的答案，否则 CPU 拿到一个主存地址后，无从知道该去 Cache 的哪个位置寻找。

所谓**映射方式**，就是对这个问题的不同回答：

| 回答 | 名称 |
| --- | --- |
| 只能放在唯一确定的那一行 | **直接映射** |
| 可以放在任意一行 | **全相联映射** |
| 只能放进唯一确定的那一组，组内任意一行 | **组相联映射** |

三种方式的差别，就是**约束强弱**的差别。约束越强，查找越快、硬件越省，但冲突越多。

## 二、直接映射

### 规则

主存块号为 j 的块，只能放入 Cache 的第 jmod2c 行（2c 为 Cache 行数）：Cache 行号=主存块号mod2c

图 7.27　cache 和主存之间的直接映射方式（袁春风《计算机组成与系统结构（第 3 版）》p238）

### 块群：理解映射关系的钥匙

把主存按**每 2c 块为一组**切开，每一组称为一个**块群**。于是：主存=若干块群×2c 块/块群

**每个块群里的 2c 个块，与 Cache 的 2c 行一一对应**——块群内第 0 块进第 0 行，第 1 块进第 1 行，依此类推。

这就把"取模"这件事讲清楚了：主存块号=块群号⏟高位×2c+块群内序号⏟低位

块群内序号正好就是 Cache 行号，而**块群号正好就是标记（tag）**。

> [!TIP]
>

标记到底是什么标记=块群号

Cache 的第 i 行随时可能装着任何一个块群的第 i 块。既然行号已经由位置本身确定，**只需再记住"它来自哪个块群"就能唯一确定是哪一块**——这就是标记存在的全部理由。

所以标记不是"剩下的高位"这么随意，它有确切含义。理解这一点，tag=⌊块号/行数⌋ 这个式子就不用背了。

### 地址划分

主存地址被分成三段：[ 标记⏟t 位  |  Cache 行号⏟c 位  |  块内地址⏟b 位 ]

硬件为什么能这么省事：**行号就是地址中间那几位，直接取出来即可**，不需要真的做除法或取模——因为除以 2c 取余，等价于取二进制低 c 位。

### 特点

- 硬件最简单：只需 **1 个比较器**（只可能在那一行）
- 冲突最严重：**相隔 2c 个块的主存块争同一行**，即使 Cache 大部分是空的，它们也会互相驱逐（抖动）
- 命中率相对最低

## 三、全相联映射

### 规则

主存块可以放入 Cache 的**任意一行**，没有任何位置约束。

图 7.30　全相联映射方式下主存块和 cache 行对应关系（袁春风《计算机组成与系统结构（第 3 版）》p241）

### 地址划分

没有位置约束，也就**没有行号字段**：[ 标记⏟即完整的主存块号  |  块内地址⏟b 位 ]

用块群的语言说：全相联相当于**整个主存只有一个块群**，块群号就是块号本身，所以标记等于完整的主存块号。

### 特点

- 冲突率最低、命中率最高：只要 Cache 还有空行就不会发生冲突
- 硬件开销最大：判命中要把地址中的标记**与所有行的标记同时比较**，有多少行就要多少个比较器
- 因此只用于行数很少的场合，如 TLB

## 四、组相联映射

### 规则

Cache 分成 2q 个**组**，每组 2s 行（称 2s 路组相联）。主存块号为 j 的块，只能进第 jmod2q 组，**组内任意一行**：Cache 组号=主存块号mod2q

图 7.32　组相联映射方式下主存块和 cache 行对应关系（袁春风《计算机组成与系统结构（第 3 版）》p243）

块群的说法照样成立，只是这次**每 2q 块为一个块群**，块群内第 i 块进第 i 组。标记仍然等于块群号。

### 硬件实现

图 7.31　组相联映射方式的硬件实现（袁春风《计算机组成与系统结构（第 3 版）》p243）

图中是 2 路组相联，五个编号对应五个动作：

- 用地址中的**组号**选中一组
- 把地址中的**标记**与该组两行的标记**分别送入两个比较器**
- 比较结果与该行的**有效位**相与
- 命中的那一路打开三态门放出数据
- 两路的命中信号相或，得到 hit 信号，经多路选择器输出

**2s 路组相联就是 2s 个比较器并联**——这直接解释了硬件开销为什么随路数增长。

### 三种方式其实是一条连续谱

组相联并不是"第三种方式"，而是**含有两个端点的通用形式**：

| 路数 k | 组数 | 退化为 |
| --- | --- | --- |
| k=1 | 组数 = 行数 | **直接映射**（每组一行，进哪组就是进哪行） |
| 1<k<N | 介于两者之间 | 组相联 |
| k=N（行数） | 组数 = 1 | **全相联**（只有一组，组内任意行） |

理解了这条谱，三种方式的所有对比都可以推出来，不必分别记忆。

## 五、地址字段的划分

### 统一关系

设主存地址 n 位，则无论哪种映射：n=t+c+b

| 字段 | 位数由谁决定 |
| --- | --- |
| 块内地址 b | b=log2⁡(块大小) |
| 行号 / 组号 c | 直接映射 c=log2⁡(行数)；组相联 c=log2⁡(组数)；全相联 c=0 |
| 标记 t | t=n−c−b（剩余高位） |

### 从"容量"到"行数"的中间步

题目常给的是 **Cache 数据容量**而非行数，中间隔着一步：行数=Cache 数据容量块大小,组数=行数k

单位也要先统一：块大小若写作"4 个字、每字 32 位"，先折成 4×32÷8=16 字节。

### 位区间的写法

字段除了位数，还要能写成位区间 [高:低]。规则是从第 0 位起由低到高排：块内地址=[b−1:0],行号/组号=[b+c−1:b],标记=[n−1:b+c]

### 从地址算出各字段的取值

前面算的是位数，实际使用时还要由一个具体地址算出各字段的值：主存块号=⌊地址块大小⌋,组号=块号modS,标记=⌊块号S⌋

反过来可以由字段还原地址，用来自检：块号=标记×S+组号

> [!WARNING]
>

先剥块内地址，再取模

不能拿字节地址直接对组数取模。必须**先除以块大小**剥掉块内地址得到块号，再对组数取模。

原因回到块群：取模操作的对象是"块"，不是"字节"。字节地址里还混着块内地址那几位。

## 六、Cache 的总容量

Cache 的每一行除了数据，还要存放判命中和管理所需的信息：每行位数=1⏟有效位+t⏟标记+8×块大小⏟数据+[1]⏟脏位+[⋅]⏟替换算法位总容量=行数×每行位数

后两项是条件项：

- **脏位**只在**写回策略**下存在，写直达没有脏位（见 [[03_计算机组成原理_CO/storage/cache-write-policy.md|Cache 写策略]]）
- **替换算法位**只在需要替换决策时存在——直接映射没有选择余地，因而不需要

所以"Cache 是 64 KB"这句话通常指**数据区容量**，实际占用的存储器件要更多。

## 七、两条容易算错的边界

### 一、数组占几个主存块——首址不对齐要多算一块
块数=⌈首址的块内地址+数组总字节数块大小⌉

分子里那个**首址的块内地址**是关键。首址若正好落在块边界上（块内地址为 0），块数就是"总字节数 ÷ 块大小"；若不对齐，则首尾各占半块，**块数要多 1**。

**例**：数组 8192 B、块大小 64 B。

- 首址块对齐：8192/64=128 块
- 首址的块内地址为 32：⌈(32+8192)/64⌉=129 块

页数同理：⌈(页内地址+总长)/页大小⌉。

### 二、虚拟地址能不能直接切出组号

采用虚拟存储时，CPU 先拿到的是虚拟地址，而 Cache 用的是物理地址——是否必须等 TLB 翻译完？

> [!TIP]
>

判据

当 **组号位数 + 块内地址位数 ≤ 页内地址位数**时：log2⁡(组数)+log2⁡(块大小)≤log2⁡(页大小)

这几位落在页内地址范围内，而**页内地址在虚拟地址和物理地址中完全相同**（地址翻译只替换高位的页号），因此可以直接从虚拟地址切出组号和块内地址，与 TLB 查询**并行**进行。

**但标记必须来自物理地址**——它落在页号那一段，不翻译拿不到。

这条判据解释了现代 CPU 为什么能把"查 TLB"和"选 Cache 组"两件事重叠起来做，从而把地址翻译的延迟隐藏掉。

## 例题

**例**：按字节编址，主存地址 32 位。Cache 采用 4 路组相联，数据区容量 64 KB，块大小 64 B，采用写回策略。求各字段的位数与位区间；地址 `0000 8B3CH` 落在哪一组、标记是多少；Cache 总容量是多少。

**解**：

**第一步，补出行数与组数。**行数=64 KB64 B=1024,S=10244=256

**第二步，定位数与位区间。**

| 字段 | 位数 | 位区间 |
| --- | --- | --- |
| 块内地址 | log2⁡64=6 | [5:0] |
| 组号 | log2⁡256=8 | [13:6] |
| 标记 | 32−6−8=18 | [31:14] |

**第三步，算字段取值。** `0000 8B3CH` =35644。块号=⌊3564464⌋=556,块内地址=35644−556×64=60组号=556mod256=44,标记=⌊556256⌋=2

还原自检：(2×256+44)×64+60=35644 ✓

**第四步，算总容量。** 写回策略，每行带脏位：每行位数=1+18+64×8+1=532 位总容量=1024×532=544768 位=66.5 KB

数据区 64 KB，标记与控制位另占 2.5 KB——这就是总容量大于数据容量的来源。

## 易混淆知识点

**1. 标记为什么不能省？**

因为**行号只能确定"位置"，不能确定"内容"**。Cache 第 5 行随时可能装着主存里任何一个块群的第 5 块。标记记录的正是"来自哪个块群"，它和行号合起来才唯一确定一个主存块。

全相联没有行号字段，所以标记必须是完整的块号——信息量守恒。

**2. 判命中只看标记相等就够了吗？**

不够。完整条件是 **有效位 = 1 且标记相等**，两者缺一不可。

有效位标记这一行有没有装入过有效数据。计算机刚上电时 Cache 内容是随机的，某一行的标记完全可能碰巧与地址匹配，若不检查有效位就会把随机数据当成命中。

**3. 组相联的"路数"越多越好吗？**

不是。路数增加会降低冲突率，但**每一路都要配一个比较器**，硬件成本和比较延迟同步上升。路数增加到一定程度后，命中率的提升变得很小，而代价仍在线性增长。这就是实际 CPU 多取 2 路、4 路、8 路而不取更高的原因。

## 本节小结

- 映射方式回答的是"主存块该放进 Cache 哪一行"，三种方式对应三种约束强弱
- **标记 = 块群号**；块群指主存中每 S 块（S 为组数或行数）构成的一组，与 Cache 的行/组一一对应
- 地址划分：n=t+c+b；直接映射 c=log2 行数，组相联 c=log2 组数，全相联 c=0
- 行数 = 数据容量 ÷ 块大小，是从容量到位数的必经中间步
- 取模的对象是**块**不是字节：先除块大小剥掉块内地址，再取模
- 标记 =⌊ 块号 /S⌋，反过来 块号 = 标记 ×S+ 组号
- 三种方式是一条连续谱：k=1 是直接映射，k= 行数是全相联
- 比较器个数：直接映射 1 个、k 路组相联 k 个、全相联等于行数
- 判命中的完整条件是**有效位 =1 且标记相等**
- 总容量 = 行数 ×（有效位 + 标记 + 数据 + 脏位 + 替换位），后两项是条件项
