# 总线概述与分类

## 知识框架

本节回答四个问题：

- 部件之间为什么要共用一组导线，而不是两两拉专线？这样做换来了什么、付出了什么？
- 一根线该归到数据线还是控制线，判据是什么？
- 总线带宽为什么**只统计数据传输的时间**，把地址传送和总线仲裁排除在外？
- 突发传送和信号线复用都改动了地址的传法，为什么一个提高传输率、另一个不提高？

## 一、总线是怎么被选中的

部件之间的互连方式只有两种：

- **分散连接**——每两个部件之间拉一条单独的线路；
- **总线连接**——把多个部件挂到一组公共传输线上，分时共享。

分散连接的线路数随部件数**平方级增长**，加一个部件就要向已有的每个部件各拉一条线。总线连接把这件事压成了线性：新部件只要接上那组公共导线即可。教材把总线连接的优点概括为两条——**灵活**（新部件容易加，部件可以在使用同一总线的机器之间互换）与**成本低**（一组导线被所有部件共享）。

代价也只有一条，而且是本质的：**一组导线在同一时刻只能承载一次传输**，所以总线可能成为**通信瓶颈**。

后面几乎所有总线机制都是在还这笔债：

| 共享带来的问题 | 对应机制 |
| --- | --- |
| 多个部件同时想发送 | 总线判优／[[03_计算机组成原理_CO/bus/bus-arbitration.md|总线仲裁]] |
| 发送方与接收方速度不一致 | [[03_计算机组成原理_CO/bus/bus-timing.md|总线定时]]（同步／异步／半同步） |
| 一条总线拖不动所有速度档次的设备 | 分层总线 + 桥接器 |
| 从设备准备数据时总线空转 | 分离事务、突发传送 |

所以"总线"这个词后面跟着的一长串概念，不是并列的知识点，而是**同一个折中带出来的一串补丁**。

### 主设备与从设备

- **主设备**（Master）：对总线有控制权，能发起传输；
- **从设备**（Slave）：只能响应主设备发来的命令，对总线没有控制权。

一次完整的总线操作称为**总线周期**（总线事务），从主设备取得总线到释放总线为止。

## 二、三组信号线的分工

系统总线通常由一组数据线、一组地址线、一组控制线构成。

| 总线类型 | 承载什么 | 位数 | 方向 |
| --- | --- | --- | --- |
| 数据总线（DB） | 源部件与目的部件之间被传输的**信息本身** | 总线宽度，与机器字长有关 | 双向 |
| 地址总线（AB） | 源数据／目的数据所在的主存单元或 I/O 模块地址 | 决定寻址空间，n 位对应 2n 个单元 | 单向，由 CPU 送出 |
| 控制总线（CB） | 定时信号与命令信息 | 视控制信号种类而定 | 有出有入 |

教材对控制线的定义是**排除法**：除地址线和数据线以外的通信线都称为控制线，时钟、复位、总线请求、总线回答都在其中。

### 一条可执行的判据

三类线的划分不看信号的名字，只看它**在这次传输里扮演什么角色**：

**被搬运的东西走数据线；描述"这次搬运该怎么进行"的信号走控制线。**

| 信息 | 走哪条线 | 理由 |
| --- | --- | --- |
| 指令 | 数据线 | 取指时，指令就是从主存被读出的那份内容 |
| 操作数、运算结果 | 数据线 | 内容 |
| I/O 接口的**命令字** | 数据线 | CPU 把一个字写进接口的控制寄存器，这个字本身是被搬运的内容 |
| I/O 接口的**状态字** | 数据线 | 同上，是从状态寄存器读回的一个字 |
| **中断类型号** | 数据线 | 中断响应周期里由接口送出的一个编号，是内容 |
| 地址 | 地址线 | 除非地址／数据线复用，见第六节 |
| **请求／应答等握手信号** | **控制线** | 它不携带内容，只表达"我要传"和"我收到了" |
| 读／写命令、总线请求 BR、总线授权 BG | 控制线 | 同上 |

> [!TIP]
>

"命令字"的归属不由名字决定

命令字里有"命令"二字，容易被划到控制线。判据不是名字，而是**它是不是一个需要被搬运的数据字**：命令字是 CPU 写给接口的一个字，走数据线；而 `MREQ`、`IOWR` 这类电平信号本身就是控制动作，走控制线。

## 三、总线的层次

按连接对象，总线分三层：

| 层次 | 连接对象 | 特点 |
| --- | --- | --- |
| 片内总线 | 芯片内部，如 CPU 内各寄存器与 ALU 之间 | 最快，芯片内走线 |
| 系统总线 | CPU、主存、I/O 接口之间 | 机器内部的核心总线 |
| 通信总线（外总线） | 计算机与外设／其他计算机之间 | 如 USB、以太网 |

现代机器的系统总线不是一条，而是**按速度分层的若干条，层与层之间用桥接器（芯片组）连接**：

图 8.3　外设、设备控制器和 CPU 及主存的互连（袁春风《计算机组成与系统结构（第 3 版）》p280）

这张图能读出四条结论：

- **越靠近 CPU 的总线越快。** 处理器总线（前端总线）最快，存储器总线次之，I/O 总线最慢——越往外挂的设备越多、走线越长、要兼容的标准越杂，这三项都压制频率。
- **速度档次不同的总线之间必须经桥接器。** 北桥（MCH，主存控制器集线器）连接处理器总线、存储器总线和显卡；南桥（ICH，I/O 控制器集线器）挂各种 I/O 总线。桥接器负责速度匹配与协议转换，两条速度不同的总线不能直接对接。
- **分层的动机就是第一节那条债。** 若所有设备挂在同一条总线上，整条总线只能按最慢设备设计；分层之后，慢设备的拖累被隔离在外层。
- 传统芯片组是 CPU + 北桥 + 南桥三芯片；北桥的存储器控制功能被并进 CPU 芯片后，出现了 CPU + PCH 的双芯片结构。

## 四、总线的性能指标

| 指标 | 定义 |
| --- | --- |
| 总线宽度 | 数据线的条数，决定一次能并行传多少位 |
| 总线时钟频率 | 总线的**基础时钟**频率 f |
| **总线工作频率** | **每秒实际传送数据的次数** |
| 总线带宽 | 总线的**最大数据传输率** |
| 总线寻址能力 | 由地址线位数决定，n 位对应 2n 个单元 |
| 总线定时方式 | 同步／异步／半同步 |
| 总线传送方式 | 非突发／突发 |
| 总线负载能力 | 能挂接的总线设备数目，一般指扩展槽个数 |

其中最容易失手的是**时钟频率与工作频率的区分**。

### 时钟频率与工作频率
工作频率=时钟频率×每个时钟周期传送的次数

早期总线一个时钟周期传一次数据，两者相等。现在有些总线一个时钟周期传 2 次（双沿）或 4 次（四倍并发，quad pumped），工作频率就是时钟频率的 2 倍或 4 倍。

工作频率的本征单位是 **MT/s**（每秒百万次传送）。习惯上写成 MHz，那只是"每秒多少次"这个量纲上的等价说法，**它不是基础时钟**。例如某前端总线实际时钟频率 333MHz，采用四倍并发，传输速率为 1333MT/s，习惯上称 1333MHz。

由此得到一张口径判别表：

| 给出的量 | 它是什么 | 是否还要乘倍数 |
| --- | --- | --- |
| 总线**时钟**频率 f | 基础时钟，**不含**倍数 | **要乘**每周期传送次数 |
| 总线**工作**频率／传输速率／MT/s／GT/s | 等效传送频率，**已含**倍数 | **不再乘**，直接乘字节宽度 |
| DDR3-1333、FSB 1333MHz 这类型号或产品名 | 一律是等效传输速率 | **不再乘** |

之所以两个数常常同时出现，是因为其中一个在解释另一个的来历：写"每个时钟周期传送 4 次、工作频率 1333MHz"时，那个 4 是在说明 333×4=1333 这件事，倍数已经用掉了。

## 五、总线带宽：定义边界比公式重要

教材定义：**总线带宽指总线的最大数据传输率，即总线在进行数据传输时单位时间内最多可传输的数据量，不考虑总线裁决、地址传送等所花的时间。**B=W×F/N

W 为总线宽度（字节），F 为总线时钟频率，N 为完成一次数据传送所用的时钟周期数，F/N 即工作频率。写成工作频率的形式就是总线带宽=工作频率×总线宽度（位）8

### 为什么要把非数据时间排除在外

这不是为了让公式好算，而是因为**带宽要衡量的是总线本身的能力，不是某次传输的实际表现**。

设想把地址传送、仲裁、等待周期全部计入：得到的数值会随着**数据块长度**（块越长，一次地址被摊得越薄）、**从设备速度**（慢设备插的等待周期多）、**当时有几个主设备在争总线**而变化。同一条总线在不同场合会算出完全不同的"带宽"，这个量就失去了横向比较两条总线优劣的作用。

把非数据阶段剔除后，带宽只由**总线宽度**和**工作频率**这两个设计参数决定——它们恰好是设计者能选的东西。于是带宽变成一个干净的**上界**：

实际吞吐率永远不高于总线带宽；数据块越长、非数据开销被摊得越薄，实际吞吐越接近带宽。

**突发传送正是逼近这个上界的手段**：把一次地址摊到整块数据上。这句话反过来也成立——正因为带宽是上界，所以"提高带宽"和"缩短一次事务的时间"是两件不同的事，见下面的例 2。

## 六、突发传送与信号线复用

### 突发传送

**非突发**方式在每个传送周期内先传地址、再传数据：地址、数据、地址、数据……

**突发（burst，也译猝发）传送**在传送开始时只给出数据块的**首地址**，随后连续传送块内后续数据，后续地址默认为前一个地址加上一个数据所占的单元数：首地址→数据1→数据2→⋯→数据n

因为无须在地址线上传送后续地址，**在总线宽度和总线时钟频率相同的情况下，突发传送的数据传输率高于非突发传送**。存储器总线读一个 Cache 块正是这个场景——CPU 要的本来就是整块，见 [[03_计算机组成原理_CO/storage/cache-mapping.md|Cache 的地址映射]]。

### 信号线复用

有些总线没有单独的地址线，地址信息通过数据线传送，称为**地址线与数据线复用**。

- **收益**：**减少信号线数量**，降低引脚数与成本；
- **代价**：传地址时数据线被占着，这段时间一个字节的数据也传不了。

所以复用换来的是线数，不是速度——它反而让一次事务多占周期。

把两者放在一起，就能区分"改动了地址的传法"这一类措施到底影响什么：

| 措施 | 数据传输率 | 原因 |
| --- | --- | --- |
| 增加总线宽度 | 提高 | 每次传的字节数变多 |
| 提高总线工作频率 | 提高 | 每秒传送的次数变多 |
| 支持突发传送 | 提高 | 后续地址不再占用总线时间 |
| 采用地址／数据线复用 | **不提高** | 地址阶段反过来要占用数据线 |

**判据是：这项措施是让数据阶段跑得更快，还是只是把非数据阶段挪了位置。** 突发是把地址阶段消掉，复用是把地址阶段搬进数据线里。

## 七、多通道存储器总线

并联多套独立的存储器总线即为多通道，**n 个通道的总带宽是单通道的 n 倍**——各通道并行工作，互不占用彼此的数据线。

图 8.4　Intel Core i7 中各类存储器以及核之间的互连（袁春风《计算机组成与系统结构（第 3 版）》p282）

图中处理器支持三通道 DDR3-1333 内存条插槽，存储器总线宽度 64 位、每秒传送 1333M 次，单通道带宽 1333M×64/8=10.664GB/s，三通道合计约 32GB/s——正是这个线性倍增关系的实例。

## 例题

**例 1（时钟频率口径 + 多通道）**：某存储器总线时钟频率为 200MHz，每个时钟周期传送 2 次数据，总线宽度 64 位，采用双通道。求单通道带宽与总带宽。

**解**：给出的是**时钟频率**，倍数因子还没算进去，需要先折算工作频率。工作频率=200MHz×2=400 M次/s单通道带宽=400×106×648=3200 MB/s=3.2 GB/s双通道总带宽=3.2×2=6.4 GB/s

若改成给"工作频率 400MHz"，第一步就该跳过——倍数已经含在里面了。

**例 2（带宽与事务时间的分界）**：某同步总线时钟频率 40MHz，总线宽度 32 位，支持突发传送。一次读事务的构成为：1 个时钟周期传送首地址，2 个等待周期，随后连续 4 个时钟周期各传送一个 32 位数据。求 (1) 该总线的带宽；(2) 这次事务的实际用时与平均传输速率。

**解**：

(1) 带宽只看数据阶段的稳态速率。数据阶段每个时钟周期传 4B：B=40×106×4=160 MB/s

(2) 事务时间要把所有周期都数进去。时钟周期 T=1/40MHz=25ns：t=(1+2+4)×25ns=175 ns平均速率=4×4 B175 ns≈91.4 MB/s

两个数都对，但回答的是两个问题：160MB/s 是这条总线**能跑到的上限**，91.4MB/s 是**这次事务实际跑出来的**。差距来自那 3 个非数据周期。若把突发长度从 4 拉长到 16，非数据周期仍是 3 个，平均速率就会向 160MB/s 靠拢——这就是第五节说的"突发逼近上界"。

## 易混淆知识点

**1. 总线带宽和实际数据传输率是一回事吗？**

不是。带宽是**只按数据阶段算出来的上界**，与地址传送、仲裁、等待周期无关；实际传输率是"传完的数据量 ÷ 事务总时间"，非数据开销全部计入。凡是问"这条总线的带宽／最大数据传输率"，只算数据阶段；凡是问"传完一个块要多久""一次事务至少需要多少时间"，才把地址周期和等待周期加进去。

**2. 一条总线上能同时有多对设备通信吗？**

不能。任一总线周期内只有一个主设备控制总线，由它选中一个从设备一对一通信。这正是共享带来的瓶颈，也是需要判优机制的原因。由此可以直接推出：单总线结构中，CPU 读主存的同时不可能向打印机送数据——总线已被占用。

**3. 并行总线一定比串行总线快吗？**

不一定，现代高速总线里通常相反。并行传输要求同时发出的所有位在另一端同时到达，频率越高、走线越长，**串扰**与**时钟偏移（skew）**越严重，最快位与最慢位的到达时间差被放大到超过一个时钟周期，采样就会出错。串行传输每次只在一对线上传一位，位与位之间不存在对齐问题，时延的细微变化不影响其他位，因而频率可以提得高得多，再用多通道组合把总带宽堆上去。展开见 [[03_计算机组成原理_CO/bus/bus-standard.md|总线标准]]。

**4. 加宽总线和提高频率，哪条路更划算？**

两者对带宽都是线性贡献，但代价不同：加宽要增加引脚与走线，成本和串扰同时上升；提频受信号完整性限制。现代设计普遍选择"窄而快的串行链路 + 多通道并联"，本质上是把加宽的粒度从"一条线"换成了"一条完整链路"。

**5. 增加总线宽度和采用地址／数据线复用，都改了信号线，为什么效果相反？**

前者增加的是**数据阶段每周期的搬运量**，直接抬高带宽；后者只是把地址挪到数据线上传，数据阶段并没有变快，反而多占了周期。复用换的是引脚数与成本，不是速度。

## 本节小结

- 总线是**分时共享**的公共传输线，优点是灵活、成本低，代价是可能成为**通信瓶颈**；判优、定时、分层、突发都是在还这笔债
- 同一时刻只有一个主设备控制总线，主设备发起传输，从设备只能响应
- 划分数据线／控制线的判据：**被搬运的内容走数据线，描述搬运方式的信号走控制线**；命令字、状态字、中断类型号都是内容
- 控制线的教材定义是排除法：除地址线和数据线以外的通信线都是控制线
- 越靠近 CPU 的总线越快；速度档次不同的总线之间必须经**桥接器**相连
- 工作频率 = 时钟频率 × 每周期传送次数；给出"工作频率／MT/s／型号"时**不再乘**倍数
- **总线带宽 =W×F/N= 工作频率 × 总线宽度/8**，定义上**不计入总线裁决与地址传送时间**
- 带宽被定义成只算数据阶段，是为了让它只取决于宽度与工作频率这两个设计参数，从而成为一个可横向比较的**上界**
- 突发传送只传首地址、后续地址自动递增，传输率高于非突发；地址／数据线复用只减少信号线数量，**不提高**传输率
- n 通道存储器总线的总带宽 = 单通道 ×n
