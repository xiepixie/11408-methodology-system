# 不恢复余数除法（加减交替法）

## 大纲定位

**支撑条目：二（二）3　乘/除运算**

大纲原文只有一句：「乘/除法运算的**基本原理**，乘法电路和除法电路的**基本结构**。」——**没有点名加减交替法**。本篇是支撑这一条目的具体算法之一，要求到基本原理层次即可。

除法器的部件构成、寄存器初值与两类异常，见总述篇 [乘除运算的基本原理与实现结构](https://www.codebrick.tech/co-full/posts/data-repr/multiply-divide-circuit.html)；本篇的推导起点是 [[03_计算机组成原理_CO/data-repr/restoring-division.md|恢复余数除法]]。

读法建议：能推出"正 1 减、负 0 加"这条规则，而不是背下来。**实际计算机普遍采用这一算法**，所以除法器的结构基本都以它为背景。

## 知识框架

本节回答四个问题：

- 恢复余数那一步能不能省？凭什么能省？
- "正 1 减、负 0 加"是怎么从代数式里掉出来的？
- 既然全程不恢复，为什么最后一步余数为负时还要恢复一次？
- 把"步数不固定"变成"步数固定"，对硬件意味着什么？

## 一、恢复那一步能省掉，是一次代数化简

[[03_计算机组成原理_CO/data-repr/restoring-division.md|恢复余数法]]里，第 i 步的中间余数是 Ri=2Ri−1−Y。走到下一步时分两种情况。

**情况一：Ri⩾0（够减，上商 1）**

不需要恢复，直接左移再试减：Ri+1=2Ri−Y

**情况二：Ri<0（不够减，上商 0）**

按恢复余数法，要走三步：**恢复 → 左移 → 试减**。Ri+1=2(Ri+Y)⏟恢复−Y=2Ri+2Y−Y=2Ri+Y

**化简结果里没有"恢复"这一步了。** 展开式告诉我们：与其"加回 Y、左移、再减 Y"，不如直接"左移、加 Y"——**两者恒等**。恢复余数法的三步操作≡左移后做一次加法

**这就是"不恢复余数"的全部依据。它不是一个近似或简化，是一个恒等式。**

## 二、规则：正 1 减，负 0 加

把两种情况合起来：Ri⩾0⟹上商 1,  Ri+1=2Ri−YRi<0⟹上商 0,  Ri+1=2Ri+Y

教材把它概括成六个字：**"正、1、减，负、0、加"**——中间余数为正就上商 1、下一步做减法；为负就上商 0、下一步做加法。

**每一步固定一次加法或一次减法**，加法与减法交替出现，所以又叫**加减交替法**。

> [!WARNING]
>

符号要在左移之前读

单符号位表示的余数，**左移时符号位会被第一个数值位顶掉**。比如 `0.1011` 左移得 `1.0110`，看着像负数，其实它只是原来那个正余数的两倍。

所以"这一步该加还是该减"永远取决于**左移之前**那个余数的符号，不能读左移之后的符号位。

（若改用双符号位书写，左移按算术左移处理，高位符号位才是真符号——这时读左移之后的高位符号位也是对的。两种写法别混。）

## 三、末位为什么还要修正一次

全程不恢复，靠的是"下一步的左移会把这笔账消掉"。2(Ri+Y)−Y=2Ri+Y

等式成立的前提是**后面还有一次左移**。而最后一步之后没有下一步了——如果末位商 0（末位余数为负），这个负余数就没有机会被"消化"，它就是最终输出的余数。

余数不能是负数（原码除法中余数应与被除数同号），所以必须真正恢复一次：R修正=Rn+Y

**一句话：中间步骤的"不恢复"是把恢复延迟到下一步做掉了；最后一步没有下一步，只好当场做。**

## 四、步数固定换来了什么

|  | 恢复余数法 | 加减交替法 |
| --- | --- | --- |
| 每步操作次数 | 1 或 2 次（不够减要多做一次加法） | **恰好 1 次** |
| 总步数 | **不固定** | **固定 n 步** |
| 末尾处理 | 不需要 | 末位余数为负时修正一次 |
| 控制逻辑 | 需要"要不要恢复"的条件分支 | 每步结构完全相同，只是加或减 |
| 实际采用 | 很少 | **普遍采用** |

对硬件而言，"步数固定"的价值比"平均少做几次加法"大得多：

- **时序可预测**：除法指令的周期数是常数，便于流水线调度和时序设计
- **控制逻辑规整**：每次循环内的步骤完全相同，差别仅在做加还是做减，**一位符号位就能决定**，不需要额外的状态
- **计数器可以直接管到底**：计数器初值置 n，减到 0 就结束，不必考虑"这一步是不是要多走一趟"

所以教材说这种方法"运算中每次循环内的步骤都是规整的"——规整比快更值钱。

## 五、算法流程

```
输入：被除数 |X|、除数 |Y|
初始：R = |X| 的高位部分，Q = |X| 的低位部分

R = R - |Y|              // 首次试减：溢出判据，产生 Q_n
if R >= 0: 上商 1 -> 商溢出，停止
else:      上商 0（不计入商），不恢复，继续

for i = 1 to n:
    s = sign(R)          // ★ 必须在左移之前记下符号
    (R, Q) 同步左移一位
    if s >= 0: R = R - |Y|    // 上一步余数为正 → 减
    else:      R = R + |Y|    // 上一步余数为负 → 加
    Q 末位上商：R >= 0 记 1，R < 0 记 0

if R < 0:
    R = R + |Y|          // 末位商 0，余数须真正恢复一次
```

> [!WARNING]
>

首次试减的口径与恢复余数法完全相同

第一次减出来的那位商是**溢出判据**（商的第 n 位），不是第一位商。n 位商全都从"左移之后"的加减开始产生。把它当成第一位商，整条商会错位一位。

> [!TIP]
>

教材写法差异

有的教材先移位后加减，有的先加减后移位；有的用单符号位，有的用双符号位。**逻辑等价，中间表格不同。** 认准一种写到底。

## 六、补码加减交替法（了解）

上面讨论的是原码除法。补码除法也可以用加减交替，规则形式相同但判据换成"同号异号"：

| 判断 | 操作 |
| --- | --- |
| 被除数与除数**同号** | 初始做**减法** |
| 被除数与除数**异号** | 初始做**加法** |
| 余数与除数**同号** | 上商 1，下一步做减 |
| 余数与除数**异号** | 上商 0，下一步做加 |
| 末位 | 恒置 1 |

商直接就是补码表示，不需要单独处理符号。

> [!WARNING]
>

"末位恒置 1"是补码除法专属

它是一个简化约定：不管末位余数是正是负，商的末位一律置 1，带来的精度损失最大为 2−n。

这与原码加减交替法"末位余数为负才修正"是**两套不同的收尾方式**，不能互换套用。看清题目用的是原码除法还是补码除法。

## 例题

**例**：用加减交替法计算 0.1001÷0.1101（定点小数，4 位数值位）。

这是[[03_计算机组成原理_CO/data-repr/restoring-division.md|恢复余数除法]]例题的同一组数据，可以直接对照两者的差别。|X|=0.1001,|Y|=0.1101,[−|Y|]补=1.0011

| 步骤 | 上一步余数符号 | 操作 | 余数 R | 商位 |
| --- | --- | --- | --- | --- |
| 初始 | — |  | `0.1001` |  |
| 首次试减 | — | 0.1001+1.0011=1.1100 | `1.1100`（负） | Qn=0 → 不溢出，不计入商，**不恢复** |
| 左移 |  |  | `1.1000` |  |
| 第 1 步 | 负 | R+Y=1.1000+0.1101=0.0101 | `0.0101`（正） | q1=1 |
| 左移 |  |  | `0.1010` |  |
| 第 2 步 | 正 | R−Y=0.1010+1.0011=1.1101 | `1.1101`（负） | q2=0 |
| 左移 |  |  | `1.1010` |  |
| 第 3 步 | 负 | R+Y=1.1010+0.1101=0.0111 | `0.0111`（正） | q3=1 |
| 左移 |  |  | `0.1110` |  |
| 第 4 步 | 正 | R−Y=0.1110+1.0011=0.0001 | `0.0001`（正） | q4=1 |

末位余数为正，**无需修正**。

**商** =0.1011，**余数** =0.0001×2−4

核对：1116×1316+1256=144256=916=0.10012 ✓

**与恢复余数法的对照**：商和余数完全相同，但恢复余数法为这 4 位商做了 7 次加减（含 2 次纯恢复），加减交替法只做了 5 次（1 次首次试减 + 4 步），**且每一步的操作次数都是 1**。

## 易混淆知识点

**1. "不恢复余数"是不是一个近似算法？**

不是。2(Ri+Y)−Y=2Ri+Y 是**恒等式**，两种算法在每一步得到的中间余数、每一位商、最终余数**完全相同**。

加减交替法省掉的只是"加回去又减掉"这个来回，不是省掉了精度。这一点从上面的对照例题能直接看出来。

**2. 为什么中间步骤不用恢复，末位却要？**

因为"不恢复"依赖的是**下一步的左移把这笔账带过去**。2(Ri+Y)−Y=2Ri+Y

左边有个因子 2，它来自"左移"。最后一步之后没有左移了，恒等式失去成立条件，那个负余数就必须当场加回来。

**换个角度：中间的"不恢复"是把恢复推迟合并到下一步，末位无处可推。**

**3. 判断加还是减，看哪个余数的符号？**

看**上一步的余数**（左移之前）的符号，不是左移之后的、也不是本步算出来的。

单符号位表示时，左移会把符号位顶掉，左移后的最高位不再是符号。这是这个算法最容易做反的一处。

**4. 加减交替法一定比恢复余数法快吗？**

**平均更快，但最好情况下不快。** 如果所有商位都是 1（每步都够减），恢复余数法一次恢复都不做，两者操作次数相同。

加减交替法真正的优势不在平均速度，而在**步数固定**——时序可预测、控制逻辑规整、计数器直接管到底。硬件设计里确定性往往比平均性能更值钱。

**5. 原码加减交替和补码加减交替的收尾方式能互换吗？**

不能。原码版是"末位余数为负则加一次除数修正"，补码版是"末位恒置 1"。前者精确，后者是带已知误差上界（2−n）的简化约定。**混用会算出一个既不精确也不符合该约定的结果。**

**6. 例题是定点小数，换成定点整数要改哪几处？**

算法骨架一个字都不用改——**"正 1 减、负 0 加"、每步固定一次加减、末位余数为负要修正一次，三条全部照搬**。要改的只是小数点约定带来的四处口径：

|  | 定点小数（本篇例题） | 定点整数 |
| --- | --- | --- |
| 被除数怎么扩展 | **低位**补 n 个 0 | **高位**补 n 个 0 |
| R / Q 初值 | R = 被除数，Q = 全 0 | R = 全 0，Q = 被除数 |
| 首次试减 | R 初值非 0，**必须做**，Qn=1 即溢出 | R 初值全 0，商必不超过 n 位，**可省** |
| 最终余数 | R 被左移了 n 次，真实余数 =R×2−n | R 里就是真实余数，**不用还原** |

判据只有一句：**看 0 补在被除数的高位还是低位。** 补在低位（小数）则首次试减不能省、余数要乘 2−n；补在高位（整数）则两者都不必。

省掉首次试减时，第一步的"上一步余数符号"取 R 的初值 0，按非负处理，所以**第一步做减法**——与有首次试减时的第一次操作一致。

而 2n 位被除数除以 n 位除数（双精度除法）不做任何扩展，R 初值装被除数高 n 位，这时首次试减是**唯一的溢出判据，绝不能省**。三种情形的对照见[总述篇](https://www.codebrick.tech/co-full/posts/data-repr/multiply-divide-circuit.html)。

## 本节小结

- 恢复那一步能省，依据是**恒等式** 2(Ri+Y)−Y=2Ri+Y——"恢复 + 左移 + 减"等价于"左移 + 加"，不是近似
- 规则六个字：**正、1、减，负、0、加**；每步固定一次加或一次减，加减交替出现
- **判加减看上一步（左移之前）的余数符号**；单符号位下左移会顶掉符号位，读左移后的最高位必错
- **末位余数为负仍要修正一次** R+Y，因为"不恢复"依赖后续的左移，末位之后没有左移可依赖
- 首次试减的口径与恢复余数法相同：那位商是**溢出判据**，不计入 n 位商
- 换成定点整数时算法骨架不变，只改口径：**0 补在被除数高位**（R 初值全 0）⇒ 首次试减可省、余数不用乘 2−n；补在低位（小数）则两者都要
- 加减交替法的真正价值是**步数固定**——时序可预测、控制逻辑规整（一位符号位即可决定加或减）、计数器直接管到底；它是实际计算机普遍采用的除法算法
- 平均比恢复余数法快，但商位全 1 时两者操作次数相同
- **补码加减交替法**按"同号减、异号加"起步，按"余数与除数同号上商 1"迭代，**末位恒置 1**——这套收尾与原码版不可互换
