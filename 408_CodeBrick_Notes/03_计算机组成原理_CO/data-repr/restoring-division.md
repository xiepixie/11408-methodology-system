# 恢复余数除法

## 大纲定位

**支撑条目：二（二）3　乘/除运算**

大纲原文只有一句：「乘/除法运算的**基本原理**，乘法电路和除法电路的**基本结构**。」——**没有点名恢复余数法**。本篇是支撑这一条目的具体算法之一，要求到基本原理层次即可。

除法器的部件构成、寄存器初值、被除数扩展与两类异常，见总述篇 [乘除运算的基本原理与实现结构](https://www.codebrick.tech/co-full/posts/data-repr/multiply-divide-circuit.html)。

读法建议：说清"试减—上商—恢复—左移"这个骨架的每一步为什么必须存在。恢复余数法是[[03_计算机组成原理_CO/data-repr/non-restoring-division.md|加减交替法]]的台阶，手推一遍即可。

## 知识框架

本节回答四个问题：

- 手算除法是"除数逐位右移"，机器为什么改成"余数左移"？
- 不够减的时候，为什么非要把除数加回去不可？
- 第一次试减产生的那一位商，为什么不算进商里？
- 恢复余数法慢在哪？慢到什么程度值得换算法？

## 一、从手算除法说起

手算 10011101÷1011：

- 拿被除数的高几位与除数相减，**够减上商 1，不够减上商 0**
- 得到的差是**中间余数**；把除数向右挪一位，再与中间余数比较
- 重复第 2 步，直到商的位数够为止

计算机做的事一模一样——**通过"中间余数减除数"来得到每一位商**。差别只在两处工程改造。

### 改造一：除数不动，改成余数左移

手算是"除数右移"，因为纸上写起来方便。硬件里除数放在除数寄存器 Y 里不动更省事，于是把相对运动倒过来：除数右移一位⟺中间余数左移一位

两者的相对位置变化完全相同。**这是"余数左移"的全部理由——不是什么新原理，只是把参照系换了一下。**

（乘法器里"被乘数不动、部分积右移"是同一个思路的镜像，见[总述篇](https://www.codebrick.tech/co-full/posts/data-repr/multiply-divide-circuit.html)。）

### 改造二：够不够减，靠"减了再看符号"

纸上人眼一比就知道够不够减，硬件没有这个能力。它的办法是：**先减了再说，然后看结果的符号位**。R−Y⟺R+[−Y]补

- 结果符号位为 0（非负）：够减，**上商 1**，这个差就是新的中间余数
- 结果符号位为 1（负）：不够减，**上商 0**，但这个差是个错误的中间余数

于是就有了"恢复"这一步的必要性。

## 二、为什么不够减一定要恢复

不够减时算出来的 R−Y 是负数，它**不是**这一步应有的中间余数——应有的中间余数是"没减之前的那个 R"。

下一步要在这个中间余数的基础上左移再试减。如果拿着错的 R−Y 继续走，后面每一步都错。所以必须把减掉的除数加回来：R←(R−Y)+Y

**"恢复余数"这个名字就是字面意思：把中间余数恢复成试减之前的样子。** 它是一次纯粹的撤销操作，不产生任何新信息——这也正是它显得浪费的地方。

> [!TIP]
>

判断够不够减，只看一位

中间余数用补码表示时，"是否够减"完全等价于"减出来的结果符号位是 0 还是 1"。

所以除法器的控制逻辑只需要 ALU 输出的**一位符号位**，就能决定上商 0 还是 1、要不要恢复。整个除法的控制信息量小得惊人。

## 三、算法与三条口径

原码除法中符号与数值分开处理：

- **商的符号** = 被除数符号 ⊕ 除数符号
- **数值部分**取绝对值单独做
- **余数的符号**与被除数相同

下面只讨论数值部分。

### 完整流程

```
输入：被除数 |X|、除数 |Y|
初始：R = |X| 的高位部分，Q = |X| 的低位部分

R = R - |Y|                  // 首次试减：溢出判据
if R >= 0: 上商 1 -> 溢出，停止
else:      上商 0，R = R + |Y|   // 恢复，该商位不计入结果

for i = 1 to n:
    (R, Q) 同步左移一位       // Q 的最高位移入 R 的最低位，Q 空出末位
    R = R - |Y|              // 试减
    if R >= 0:
        Q 的末位上商 1        // 够减，保留 R
    else:
        Q 的末位上商 0        // 不够减
        R = R + |Y|          // 恢复余数
```

### 首次试减那一位商，为什么不计入商

这是本节最容易出错的口径问题。

除法的普遍形式是 **2n 位 ÷ n 位 = n 位商**。第一次减出来的那一位商，按位序算是**第 n 位**——也就是商的第 n+1 个数位。它一旦为 1，商就要占 n+1 位，超出了 n 位商寄存器能装的范围。首次试减的商位 Qn=1⟺商溢出

**所以它的作用是溢出判据，不是商的第一位。** 真正的 n 位商 Qn−1∼Q0 全都从"左移之后"的试减开始产生。

把它当成第一位小数商，整条商会错位一位（恰好小一半）。

> [!WARNING]
>

什么时候可以省掉首次试减

能省的条件是 **R 的初值为全 0**，即两个 n 位正整数相除、被除数高位补 n 个 0 的情形（单精度除法）。这时商必定不超过 n 位，**不可能溢出**，判据自然多余。

条件不是"只要是整数除法"。如果被除数本来就是 2n 位（双精度除法，R 初值装的是被除数高 n 位），首次试减是**唯一的溢出判据**，绝不能省——跳过它硬走 n 步，会得到一个看似正常实则荒谬的结果。

对**定点小数**除法（浮点尾数），首次试减产生的 Qn=1 意味着商的数值溢出到了整数部分。按定点小数的规矩这是溢出；但作为浮点尾数时可以靠右规救回来，所以有的实现会保留 Qn 继续算下去。

## 例题

**例**：用恢复余数法计算 0.1001÷0.1101（定点小数，4 位数值位）。|X|=0.1001,|Y|=0.1101,[−|Y|]补=1.0011

中间余数用一位符号位表示，"减除数"由"加除数的补"实现。

| 步骤 | 操作 | 余数 R | 商位 |
| --- | --- | --- | --- |
| 初始 |  | `0.1001` |  |
| 首次试减 | 0.1001+1.0011=1.1100 | `1.1100`（负） | Qn=0 → 不溢出，不计入商 |
| 恢复 | 1.1100+0.1101=0.1001 | `0.1001` |  |
| 左移 |  | `1.0010` |  |
| 第 1 步 | 1.0010+1.0011=0.0101 | `0.0101`（正） | q1=1，保留 |
| 左移 |  | `0.1010` |  |
| 第 2 步 | 0.1010+1.0011=1.1101 | `1.1101`（负） | q2=0 |
| 恢复 | 1.1101+0.1101=0.1010 | `0.1010` |  |
| 左移 |  | `1.0100` |  |
| 第 3 步 | 1.0100+1.0011=0.0111 | `0.0111`（正） | q3=1，保留 |
| 左移 |  | `0.1110` |  |
| 第 4 步 | 0.1110+1.0011=0.0001 | `0.0001`（正） | q4=1，保留 |

**商** =0.1011，**余数** =0.0001×2−4

核对：1116×1316+1256=143256+1256=144256=916=0.10012 ✓

> [!TIP]
>

从这张表能直接读出恢复余数法的代价

4 个商位里有 1 个是 0，就多做了 1 次加法。加上首次试减后的那次恢复，本例一共做了 **7 次加减**才得到 4 位商。

而**每一位商本来只需要 1 次减法**。多出来的 3 次全部是"撤销"，不产生任何新的商位。

## 易混淆知识点

**1. "余数左移"和"除数右移"是两种不同的算法吗？**

不是，是同一件事的两种参照系。手算写在纸上，除数右移看着自然；硬件里除数寄存器不动、余数寄存器左移更省电路。**两者的相对位置变化完全相同，得到的商和余数一模一样。**

**2. 左移的是谁？只有 R 还是 R 和 Q 一起？**

**R 和 Q 同步左移。** Q 的最高位移入 R 的最低位（相当于把被除数的下一位"喂"给中间余数），Q 空出的最低位用来接收本步的商。

所以运算中途 Q 里是"一部分被除数/中间余数、一部分商"，只有最后一步才全是商。这条规律见[总述篇](https://www.codebrick.tech/co-full/posts/data-repr/multiply-divide-circuit.html)。

**3. 最终余数为什么要乘 2−n？**

因为整个过程中余数被左移了 n 次，每次左移等于 ×2。R 寄存器里的值相对于真实余数被放大了 2n 倍，所以真实余数是 R×2−n。

定点整数除法不存在这个问题——那里 R 里就是真实余数，因为被除数本身就在整数位上。**要不要乘 2−n，看题目是定点小数还是定点整数。**

**4. 上商几次？左移几次？**

在 2n÷n 的普遍形式下：**上商 n+1 次、左移 n 次**。第一次上的商 Qn 是溢出判据，不计入 n 位商。

只有当 R 初值全 0（n 位正整数相除）时，才是上商 n 次、左移 n 次。

**5. 恢复余数法在真实计算机里用吗？**

基本不用。教材原话是"在计算机中很少采用恢复余数除法，而普遍采用不恢复余数除法"。

它的价值在于**它是加减交替法的推导起点**——不先理解"为什么要恢复"，就无法理解"为什么可以不恢复"。见 [[03_计算机组成原理_CO/data-repr/non-restoring-division.md|不恢复余数（加减交替）除法]]。

## 本节小结

- 机器除法与手算同源：**用中间余数减除数得到每一位商**，够减上商 1、不够减上商 0
- **"余数左移"只是把手算的"除数右移"换了参照系**，除数在寄存器里不动更省电路
- 硬件判断够不够减的办法是"先减再看符号位"，因此控制逻辑只需 ALU 输出的**一位符号位**
- 不够减时必须**恢复余数**（加回除数），因为负的中间余数不能作为下一步的起点；这是一次纯撤销，不产生新信息
- **首次试减产生的商位是溢出判据**（Qn=1 即商超出 n 位），不计入商；只有 R 初值全 0（n 位正整数相除）时才可省略
- R 与 Q **同步左移**，Q 的最高位喂给 R，Q 空出的末位接收商
- 定点小数除法的最终余数需乘 2−n 还原，因为过程中被左移了 n 次
- 恢复余数法的短板：**每步操作次数不固定**（不够减时要 2 次加减），统计上约一半步骤要恢复，控制逻辑需要条件分支——这三点催生了加减交替法
