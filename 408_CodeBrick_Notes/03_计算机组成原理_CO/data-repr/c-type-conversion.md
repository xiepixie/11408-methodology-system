# C语言中的数据类型与转换

## 大纲定位

**二（三）整数的表示和运算**（1 无符号整数、2 带符号整数）

要求：能在无符号与带符号两种解释之间转换，掌握位扩展与位截断的规则及其保值性，并说明宽度与符号性同时改变时的处理顺序。整型与浮点型之间的转换涉及 **二（四）1 浮点数的表示**。

编码本身的定义见 [[03_计算机组成原理_CO/data-repr/true-value-machine.md|真值与机器数：四种编码的定义]]；浮点格式的有效位数见 [[03_计算机组成原理_CO/data-repr/float-repr.md|浮点数表示（IEEE 754）]]。

## 知识框架

本节回答四个问题：

- 同一串位，改一个类型名值就变了——**变的到底是什么**？
- 短类型转长类型要补位，补 0 还是补符号位由谁决定？**为什么补符号位不改变数值**？
- 宽度和符号性同时改变时，两件事的先后顺序为什么**不能颠倒**？
- int 转 float 明明"从 32 位变成了 32 位、量级还变大了"，为什么反而会丢东西？

## 一、位串本身没有类型

寄存器和内存单元里只有 0 和 1。**类型不是数据的属性，是程序对数据的解释方式。**

同样的 8 位 `10000000`：

| 解释为 | 值 |
| --- | --- |
| 无符号整数 | 128 |
| 带符号整数（补码） | −128 |

编译器根据变量声明决定生成哪条指令，指令决定这串位被当成什么读。**位没变，指令变了。**

| 类型 | 编码方式 | 8 位范围 |
| --- | --- | --- |
| 无符号整数 | 纯二进制，所有位都是数值位 | 0∼255 |
| 有符号整数 | 补码，最高位是符号位 | −128∼127 |

现代计算机的有符号整数一律用补码，理由在 [[03_计算机组成原理_CO/data-repr/true-value-machine.md|真值与机器数]]：零唯一、加减法统一为加法、比原码多表示一个最小负数。

### C 语言整数类型

| 类型 | 典型位宽 | 有符号范围 | 无符号范围 |
| --- | --- | --- | --- |
| char | 8 | −128∼127 | 0∼255 |
| short | 16 | −32768∼32767 | 0∼65535 |
| int | 32 | −231∼231−1 | 0∼232−1 |
| long | 32/64 | 取决于平台 | 取决于平台 |

未写 `unsigned` 则默认为有符号类型。位宽随机器和编译器不同而不同——`long` 在 32 位机上通常是 4 字节，在 64 位机上通常是 8 字节，与机器字长一致；指针的宽度也等于机器字长。

## 二、相同字长：位模式不变，解释方式变
c

```
short x = -4321;
unsigned short y = (unsigned short)x;
// x = -4321, y = 61215
```

两者的二进制完全相同（`0xEF1F`），只是 x 按补码解释、y 按无符号解释。

规律直接来自补码定义。n 位有符号数 x 转为无符号数 u：u={xx≥0x+2nx<0

所以 `(unsigned short)(-1)` =−1+216=65535。

> [!TIP]
>

为什么 `(unsigned)(-1)` 总是该类型的最大值

−1 的补码是**全 1**（见[[03_计算机组成原理_CO/data-repr/number-encoding.md|编码的转换与书写]]），全 1 按无符号读就是 2n−1，正是最大值。

这条在任何位宽下都成立，是一个很稳的自查点。

## 三、变宽：补 0 还是补符号位

| 源类型 | 扩展方式 | 规则 |
| --- | --- | --- |
| 有符号数 | **符号扩展** | 高位全部填充符号位 |
| 无符号数 | **零扩展** | 高位全部填 0 |

c

```
short x = -4321;           // 0xEF1F
int   y = x;               // 符号扩展 → 0xFFFFEF1F，值仍为 -4321

unsigned short u = 61215;  // 0xEF1F
unsigned int   v = u;      // 零扩展   → 0x0000EF1F，值仍为 61215
```

### 符号扩展为什么保值

用补码的按权展开就能一步看出来。n 位补码：X=−bn−1⋅2n−1+∑i=0n−2bi2i

扩展到 n+1 位、把符号位复制一份：X′=−bn−1⋅2n+bn−1⋅2n−1+∑i=0n−2bi2i=−bn−1⋅2n−1+∑i=0n−2bi2i=X

关键在于 −2n+2n−1=−2n−1：**新添的负权和被顶上去的旧符号位正好抵消回原来的负权。** 复制多少份都一样，所以从 8 位扩到 32 位可以一次补完。

零扩展保值的理由更直白：无符号数的高位权都是正的，填 0 什么也没加。

## 四、变窄：截断

直接丢弃高位，只保留低位。**丢掉的位再也回不来。**c

```
int   x = 165537;          // 0x000286A1
short y = (short)x;        // 截断为 0x86A1，按 short 读 = -31071
```

165537 超出 short 的范围（−32768∼32767），截断后语义完全改变，而且**不会触发任何错误提示**。

从数值上看，截断到 n 位等价于对 2n 取模，再按目标类型的符号性解释这个余数。165537mod65536=34465=0x86A1，最高位为 1，按 short 读就是 34465−65536=−31071。

## 五、宽度和符号性同时变

这是最容易出错的一种，因为两件事同时发生，而**顺序是固定的**。

> [!CAUTION]
>

规则：扩展按"源类型"的符号性做，解释按"目标类型"来按源类型符号性扩展/截断到目标宽度⏟第一步⟶按目标类型的符号性解释这串位⏟第二步

**先看源类型决定怎么补位，再看目标类型决定怎么读。**c

```
short si = -32767;
unsigned int ui = si;
```

| 步 | 做什么 | 结果 |
| --- | --- | --- |
| 0 | `si` 是 short，−32767 的 16 位补码 | `0x8001` |
| 1 | 源类型 short 是**有符号**的 ⇒ **符号扩展**到 32 位 | `0xFFFF8001` |
| 2 | 目标类型 unsigned int ⇒ 按**无符号**解释这 32 位 | 232−32767 |

32767=215−1⇒ui=232−(215−1)=232−215+1=4294934529

> [!WARNING]
>

顺序反了会怎样

若先按无符号解释再扩展：把 `si` 当 unsigned short 读成 216−32767=32769，再零扩展得到 32769，与正确结果相差 40 亿。

**扩展的依据永远是源类型的声明**——`si` 声明为 short，它在参与扩展时就是有符号的，与目标类型无关。

另需留意 −32767 与 −215 差 1：−32767=−(215−1)，故结果是 232−215+1，不是 232−215−1。

**反向的例子**（长转短再转回来）：c

```
int   i  = 32777;     // 0x00008009
short si = i;         // 截断低 16 位 → 0x8009，按 short 读 = -32759
int   j  = si;        // si 是 short（有符号）→ 符号扩展 → 0xFFFF8009 = -32759
```

j=−32759，不是 32777——截断丢掉的高位回不来了，而截断后最高位恰好是 1，符号扩展只会把它当负数补回去。

记忆钩子：**"补位问出身，读数问去向。"** 补零还是补符号，看它原来是什么类型；补完之后这串位算多少，看它现在是什么类型。

## 六、整型与浮点型之间

| 转换方向 | 会发生什么 | 根源 |
| --- | --- | --- |
| int → float | **不溢出，但可能丢精度** | int 最多 31 位有效数字 > float 的 24 位 |
| int → double | 安全 | double 有 53 位有效位，覆盖 32 位 int |
| float → double | 安全 | 范围和精度都只增不减 |
| double → float | 可能**溢出**，也可能**丢精度** | 范围更小、有效位更少 |
| float/double → int | 小数部分**向零截断**，可能**溢出** | int 没有小数部分，范围也更小 |

**int → float 为什么会丢东西**：float 是 32 位，int 也是 32 位，位数没少，但**分配方式变了**——float 拿出 8 位去存量级，只剩 24 位有效数字。c

```
int   n = 0x7FFFFFFF;   // 2147483647，有效位 31 位
float f = (float)n;     // 只装得下 24 位有效数字，必须舍入
int   m = (int)f;       // m 不等于 n
```

**换来的是范围**：float 能表示 1038 量级，int 只到 2×109。范围和精度的这笔交易，就是浮点格式的本质。

> [!TIP]
>

一条判断"往返是否无损"的通用思路

`(源类型)(中间类型)x == x` 是否恒成立，只看中间类型能否**同时**装下源类型的范围和有效位数：

- `i == (int)(double)i` **恒成立**：double 的 53 位有效位 > int 的 32 位
- `i == (int)(float)i` **不恒成立**：float 只有 24 位有效位
- `f == (float)(double)f` **恒成立**：double 是 float 的超集
- `f == (float)(int)f` **不恒成立**：int 没有小数部分

## 七、混合运算：无符号会"传染"

C 语言规定：**同一个表达式里同时出现无符号数和带符号数时，带符号数被转换成无符号数**，整个比较/运算按无符号进行。

这条规则把第二节的"位模式不变、解释变"直接搬进了运算语义，后果相当反直觉：c

```
int x = -1;
if (x < 0u) { /* 不会执行 */ }
```

−1 被当成 232−1，比 0 大得多。同理，用 `unsigned` 做循环变量再写 `i >= 0` 会成为永真条件，循环无法退出。

**隐式类型提升顺序**：char→int→long→double←float

低类型自动向高类型转换。注意这条链讲的是**宽度/种类**的提升，与"无符号优先"是两回事。

### 判据：怎么判断一个表达式会不会按无符号算

"只要出现 `unsigned` 就按无符号"是一句半对的话——**宽度不同时它是错的**。完整判断只有三步，按顺序走：

- **先做整型提升**：比 `int` 窄的类型（`char`、`short`，**无论带不带 `unsigned`**）一律先升成 `int`。因为 `int` 装得下 `unsigned short` 的全部取值（0∼65535<231），升完两边都是 `int`，**根本走不到第 2 步**。
- **提升后比宽度**：无符号的那一方**不窄于**带符号的一方时，带符号数转成无符号——"传染"只在这一格发生。
- **带符号的一方更宽**时：它装得下无符号方的全部取值，于是把无符号数转成这个更宽的**带符号**类型，整个表达式按带符号算。

| 表达式（32 位 int） | 提升后两边的类型 | 按什么算 | 结果 |
| --- | --- | --- | --- |
| `-1 < 0u` | int vs unsigned int（等宽） | **无符号** | 假 |
| `-1 < (unsigned short)0` | int vs **int**（第 1 步就化解了） | 带符号 | **真** |
| `-1 < 0ul`（`long` 为 64 位） | long vs unsigned long（等宽） | 无符号 | 假 |
| `-1L < 0u`（`long` 为 64 位） | long vs long（第 3 步，64 位装得下 32 位无符号） | 带符号 | 真 |

**哪些写法会悄悄带进无符号**，看到就要走上面三步：

- 字面量后缀 `u` / `U` / `ul`
- 声明为 `unsigned` 的变量
- **`sizeof` 的结果**——类型是 `size_t`，无符号。所以 `int i = -1; if (i < sizeof(x))` 恒为**假**，这是最隐蔽的一种

三样都没有，表达式就一律按带符号算，不必担心传染。

## 例题

**例 1**：32 位机器上执行下列代码，写出 `y`、`z` 的值（十六进制机器数与十进制真值）。c

```
short        x = -4321;
unsigned int y = x;
unsigned int z = (unsigned short)x;
```

`x` 的 16 位补码：65536−4321=61215=0xEF1F。

- **`y`**：源类型是 `short`（**有符号**）⇒ 符号扩展到 32 位 ⇒ `0xFFFFEF1F`，按无符号读 =232−4321=4294962975
- **`z`**：先被显式转成 `unsigned short`（位模式不变，值变为 61215），此时源类型是**无符号**的 ⇒ 零扩展 ⇒ `0x0000EF1F` =61215

两者相差 232−216=4294901760。**多一次显式转换，改变的不是位串，而是扩展时依据的符号性。**

**例 2**：判断下列关系表达式在 32 位机器上是否恒成立（`i` 为 int，`f` 为 float，`d` 为 double，均不取 ±∞ 和 NaN）。

| 表达式 | 恒成立？ | 理由 |
| --- | --- | --- |
| `i == (int)(float)i` | ✗ | int 有效位可达 31 位 > float 的 24 位，转换时被舍入 |
| `i == (int)(double)i` | ✓ | double 有 53 位有效位，32 位 int 全部装得下 |
| `f == (float)(double)f` | ✓ | double 的范围与精度都是 float 的超集 |
| `d == (float)d` | ✗ | double 转 float 可能丢有效数字，也可能溢出 |
| `f == -(-f)` | ✓ | 浮点取负只翻转符号位 S，尾数和阶码一位不动 |

判据统一是那一条：**中间类型能否同时容纳源类型的范围和有效位数。**

## 易混淆知识点

**1. 强制类型转换会改变内存里的位吗？**

**整型之间同宽度转换不会**（只改解释）；**变宽会**（添了高位）；**变窄会**（丢了高位）；**整型与浮点型互转会**（重新编码，位模式完全无关）。

判据：只要"编码方式"没变（都是二进制位串的同一种排布），转换就是纯解释；一旦跨越了整数编码与浮点编码，就是真的重新算了一遍。

**2. 符号扩展和零扩展，看目标类型还是源类型？**

**看源类型。** 这是本节唯一需要死记的方向，其余都能推。

理由：扩展这个动作发生在"还没换解释"之前，它要保住的是**原来那个值**。原来是有符号的，就得按有符号的方式保值。

**3. `short si = -32767; unsigned int ui = si;` 和 `unsigned short us = -32767; unsigned int ui2 = us;` 结果一样吗？**

不一样，差了整整 232−216。

| 写法 | 源类型符号性 | 扩展方式 | 结果 |
| --- | --- | --- | --- |
| `short si` | 有符号 | 符号扩展 | 232−215+1 |
| `unsigned short us` | 无符号 | 零扩展 | 216−215+1=32769 |

**同一串位 `0x8001`，源类型的声明决定了它被补成 `0xFFFF8001` 还是 `0x00008001`。**

**4. int 转 float 会溢出吗？**

不会。float 的范围（∼1038）远大于 int（∼2×109），任何 int 都落在 float 的范围内。**丢的是精度，不是范围。**

反过来 float 转 int 两种问题都有：小数部分被截断（精度），大数值放不进 int（溢出）。

**5. "向零截断"和"四舍五入"一样吗？**

不一样。浮点转整型用的是**向零取整**：1.9999→1，−1.9999→−1。

注意负数：向零截断得到的是 −1，比原值**大**；若按"向下取整"则应得 −2。两者在负数上结果不同。

**6. 为什么无符号和带符号混合运算要规定"按无符号"，而不是反过来？**

因为反过来会丢值。把无符号数转成同宽度的带符号数，超过 2n−1 的那一半会变成负数，**信息直接错乱**；而带符号数转无符号只是换了个解释，位串还在。标准选了"位串不动"的那一边。

这不代表结果就对——`-1 < 0u` 为假正是这条规则的产物。**它只保证行为确定，不保证符合直觉。**

## 本节小结

- **类型是解释方式，不是数据属性**；位串本身不带类型，由指令决定怎么读
- 相同字长转换：位模式不变，值按 u=x+2n（x<0）换算
- 变宽：**有符号做符号扩展，无符号做零扩展**；符号扩展保值的根据是 −2n+2n−1=−2n−1
- 变窄：截断高位，等价于对 2n 取模后按目标类型解释，且**不报错**
- 宽度与符号性同时变时顺序固定：**先按源类型符号性扩展/截断，再按目标类型解释**——"补位问出身，读数问去向"
- `(unsigned)(-1)` 是该类型的最大值（全 1）
- int → float **不溢出但可能丢精度**（24 位有效位）；int → double 安全（53 位）；浮点 → int **向零截断**且可能溢出
- 判断往返是否无损，只看中间类型能否同时容纳源类型的**范围**与**有效位数**
- 混合运算判据三步：**先整型提升**（`char`/`short` 一律升 `int`，`-1 < (unsigned short)0` 因此为真）→ 等宽时**带符号转无符号**（`-1 < 0u` 为假）→ 带符号更宽时按带符号算；`sizeof` 返回无符号是最隐蔽的传染源
- 用 unsigned 做循环变量的 `i >= 0` 永真，循环退不出
