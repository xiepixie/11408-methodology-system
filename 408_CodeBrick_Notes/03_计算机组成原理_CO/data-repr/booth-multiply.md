# Booth 乘法（补码一位乘）

## 大纲定位

**支撑条目：二（二）3　乘/除运算**

大纲原文只有一句：「乘/除法运算的**基本原理**，乘法电路和除法电路的**基本结构**。」——**没有点名 Booth 算法**。本篇是支撑这一条目的具体算法之一，作用是把"补码怎么直接相乘"这个原理讲透，要求到基本原理层次即可。

乘法为什么能化成"移位 + 加"、乘法器的部件构成、原码乘与补码乘的分界，见总述篇 [乘除运算的基本原理与实现结构](https://www.codebrick.tech/co-full/posts/data-repr/multiply-divide-circuit.html)。

读法建议：理解 Booth 怎么让符号位直接参与运算，而不是记住那张位对表。手推一遍即可，不必追求速度。

## 知识框架

本节回答四个问题：

- 原码一位乘的流程照搬到补码上会错在哪一位？
- Booth 凭什么只看乘数的**相邻两位**就把符号问题解决了？
- 为什么要在乘数最低位下面再补一个 Q−1？
- 加进了减法之后，右移为什么必须是**算术**右移？

## 一、补码坏在最高位

[原码一位乘](https://www.codebrick.tech/co-full/posts/data-repr/multiply-divide-circuit.html)把符号位摘出去单独异或，数值位当成两个无符号数处理，所以每步只需"加或不加"。

补码不能这么用，问题出在**最高位的权重**。n 位补码的真值是y=−Yn−12n−1+∑i=0n−2Yi2i

最高位带的是**负**权重 −2n−1，其余位是正权重。如果照原码的流程，把 Yn−1 当成普通位、遇到 1 就加一次 X，那就等于把 −2n−1X 算成了 +2n−1X——**符号位的贡献被算反了**。

出路有两条：要么先取绝对值转成原码（多两次求补、符号还要单独处理），要么想办法**让这个负权重自己在运算中体现出来**。Booth 走的是第二条路。

## 二、Booth 递推：从补码定义直接推出来

Booth 算法不是凑出来的规则，它是上面那个真值式的一次代数变形。

关键一步是**错位相减**：把每一项 Yi2i 写成 Yi2i+1−Yi2i，然后重新配对。y=−Yn−12n−1+Yn−22n−2+⋯+Y121+Y020=−Yn−12n−1+(Yn−22n−1−Yn−22n−2)+⋯+(Y021−Y020)=(Yn−2−Yn−1)2n−1+(Yn−3−Yn−2)2n−2+⋯+(0−Y0)20

写成通式（约定 Y−1=0）：y=∑i=0n−1(Yi−1−Yi)2i

**这个式子里再也没有"哪一位是符号位"的区别了**——每一项的形式完全一致，最高位的负权重已经被吸收进 (Yn−2−Yn−1) 这个差里。正数和负数从此同等对待。

于是x×y=∑i=0n−1x(Yi−1−Yi)2i

按乘法器"部分积右移"的老办法整理成递推式：[Pi+1]补=[2−1(Pi+(Yi−1−Yi)x)]补,i=0,1,…,n−1

(Yi−1−Yi) 只能取 −1、0、+1 三个值，对应的操作正好是**减 x、不动、加 x**。

## 三、规则表：位对的含义
Yi（当前位）, Yi−1（前一位，即更低的那一位）

| Yi | Yi−1 | Yi−1−Yi | 操作 |
| --- | --- | --- | --- |
| 0 | 0 | 0 | 部分积不变 |
| 0 | 1 | +1 | 部分积 +[x]补 |
| 1 | 0 | −1 | 部分积 +[−x]补 |
| 1 | 1 | 0 | 部分积不变 |

**直觉解释**：把乘数看成若干段连续的 1。一段连续的 1（比如 `0111`）等于「段末位的下一位权重减去段首位权重」，也就是 1000−0001。所以

- `01`（从低位看到 0→1）：**一段 1 的开始**，加 x
- `10`（1→0）：**一段 1 的结束**，减 x
- `00` 或 `11`：段的中间或段外，什么都不做

**遇到连续的 1 或连续的 0 都可以跳过加法直接右移**，这是 Booth 除了处理符号之外的额外收益——乘数里 0/1 段越长，实际做的加减越少。

### 附加位 Q−1 从哪来

递推式里 i=0 时要用到 Y−1，而乘数最低位下面本来没有位。约定 Y−1=0 是从推导里直接来的（原式最后一项是 (0−Y0)20）。

硬件上就是在乘数寄存器最低位之外**再挂一个一位的触发器 Q−1，初值置 0**。每次右移时，Q 的最低位移进 Q−1，于是下一步比较的又是新的相邻两位。

**Q−1 不是"多存一位数"，它是让第一步也有"前一位"可看的补位。**

## 四、为什么必须是算术右移

原码乘法的部分积永远非负，右移补 0 就行。Booth 引入了减法，**部分积可以是负数**——这时右移补 0 会把一个负数变成正数，整个运算就毁了。

所以 [A∣Q∣Q−1] 的右移必须是**算术右移**：最高位（符号位）保持不变，用它自己的值填补空出的高位。这与[[03_计算机组成原理_CO/data-repr/shift-operations.md|定点数的移位运算]]里"补码右移补符号位"是同一条规则。

一句话：**加进减法 ⇒ 部分积可能为负 ⇒ 右移必须补符号位。** 三者是因果链，不是三条要背的规则。

## 五、寄存器与算法步骤
[A∣Q∣Q−1]

| 寄存器 | 初值 | 结束时 |
| --- | --- | --- |
| A（部分积） | 0 | 乘积的**高 n 位** |
| Q（乘数寄存器） | [y]补 | 乘积的**低 n 位** |
| Q−1（附加位） | 0 | 无意义，丢弃 |
| X（被乘数寄存器） | [x]补 | 不变 |

算法（n 位补码整数，共 n 轮）：

- 置 A=0，Q=[y]补，Q−1=0
- 看 (Q0, Q−1)：`01` 则 A+=[x]补；`10` 则 A+=[−x]补；`00`/`11` 不动
- 对 [A∣Q∣Q−1] 整体**算术右移一位**
- 重复 2–3 共 n 次
- 乘积就是 [A∣Q] 这 2n 位

> [!WARNING]
>

两种书写约定，别混着抄

本站采用**定点整数、单符号位、n 轮、每轮都移位**的写法（与袁春风教材一致）。

另一种常见写法针对**定点小数**：部分积和被乘数取双符号位，乘数多取一位附加位，**共 n+1 步而最后一步只加不移**。两种写法结果相同，中间过程的表格长度不同。

**认准一种写到底**，混着抄会多移一位或少移一位。

## 例题

**例**：用 Booth 算法计算 x=+7、y=−6，机器字长 4 位（含符号位）。[x]补=0111,[−x]补=1001,[y]补=1010

初始：A=0000，Q=1010，Q−1=0。

| 轮次 | (Q0,Q−1) | 操作 | A | Q | Q−1 |
| --- | --- | --- | --- | --- | --- |
| 初始 | — | — | `0000` | `1010` | `0` |
| 1　加减 | `0,0` | 不动 | `0000` | `1010` | `0` |
| 1　右移 | — | 算术右移 | `0000` | `0101` | `0` |
| 2　加减 | `1,0` | A+[−x]补 | `1001` | `0101` | `0` |
| 2　右移 | — | 算术右移 | `1100` | `1010` | `1` |
| 3　加减 | `0,1` | A+[x]补 | `0011` | `1010` | `1` |
| 3　右移 | — | 算术右移 | `0001` | `1101` | `0` |
| 4　加减 | `1,0` | A+[−x]补 | `1010` | `1101` | `0` |
| 4　右移 | — | 算术右移 | `1101` | `0110` | `1` |

乘积 $= [A \mid Q] = $ `1101 0110`。

核对：−42 的 8 位补码是 `11010110` ✓，而 7×(−6)=−42 ✓

**看两处细节**：

- 第 3 轮 `0011` 是 1100+0111 丢掉最高进位的结果——这正是[[03_计算机组成原理_CO/data-repr/complement-add.md|补码加法模 2n]] 的正常行为。
- 第 2 轮右移时 A 从 `1001` 变成 `1100`：最高位的 1 被**复制**了一份填进来。若这里补 0 得到 `0100`，后面全盘皆错。

## 易混淆知识点

**1. Booth 算法为什么不用管符号？**

因为符号位的负权重已经在**推导阶段**被吸收了。y=∑(Yi−1−Yi)2i 这个式子里，每一位的形式完全一致，Yn−1 不再是特殊的一位。

**是数学变形消掉了符号问题，不是算法里有一个"处理符号"的步骤。** 所以整个流程从头到尾没有出现过异或、也没有取绝对值。这也是它"控制线路比较简明、在计算机中普遍采用"的原因。

**2. (Q0,Q−1) 到底哪个是"当前位"？**

Q0（乘数寄存器最低位）是当前位 Yi，Q−1 是**更低的那一位** Yi−1，也就是上一轮被移出去的那位。

判据是差值 Yi−1−Yi：

- Q0=0, Q−1=1 即 (Yi,Yi−1)=(0,1)，差值 +1，**加**
- Q0=1, Q−1=0，差值 −1，**减**

顺序记反就会把加减做反。一个自查方法：**Q0 是刚要被用掉的那位，Q−1 是上一轮刚用完的那位。**

**3. 需要执行几轮？最后一轮要不要移位？**

看采用的是哪套约定：

| 约定 | 轮数 | 最后一轮 |
| --- | --- | --- |
| 定点整数、单符号位（本篇） | n | 照常移位 |
| 定点小数、双符号位 | n+1 | **只加减，不移位** |

两者结果一致。做题时看题面给的寄存器位宽和初始表格是哪一种。

**4. Booth 与原码一位乘的对比**

|  | 原码一位乘 | Booth 乘法 |
| --- | --- | --- |
| 处理对象 | 原码（需先取绝对值） | 补码（直接算） |
| 符号 | 单独异或 | 自动包含在运算中 |
| 每步可能的操作 | 加 / 不加 | 加 / **减** / 不加 |
| 对 ALU 的要求 | 只需加法 | **必须能加也能减** |
| 右移方式 | 逻辑右移即可 | **必须算术右移** |
| 主要用途 | 浮点尾数（原码小数）运算 | 带符号整数运算 |

后三行是连锁的：引入减法 ⇒ 部分积可能为负 ⇒ 右移要补符号位 ⇒ ALU 要支持减法。

**5. 双符号位在这里是干什么用的？**

在双符号位约定下，部分积累加过程中可能暂时出现 `01.xxxx`（绝对值超过 1）的中间状态——**这不是错误**，右移一位就回到正常范围。双符号位就是为容纳这种暂时越界准备的，与[[03_计算机组成原理_CO/data-repr/complement-add.md|溢出判别]]里的变形补码是同一套机制。

本篇用单符号位整数写法时不会遇到这个现象，因为整数没有"绝对值超过 1"这回事。

## 本节小结

- 补码不能照搬原码乘法，根本原因是**最高位带负权重** −2n−1，当成正权重算就把符号算反了
- Booth 递推来自补码真值式的**错位相减**变形：y=∑i=0n−1(Yi−1−Yi)2i，其中约定 Y−1=0；变形后每一位形式一致，**符号问题在数学上就消失了**
- 位对规则：`01` 加 [x]补、`10` 加 [−x]补、`00`/`11` 不动；直觉是"一段连续 1 的开始与结束"
- **遇到连续的 1 或连续的 0 可跳过加法直接右移**，效率高于原码一位乘
- Q−1 是为让第一轮也有"前一位"可比而设的附加位，初值 0，不属于乘数本身
- **引入减法 ⇒ 部分积可能为负 ⇒ 右移必须是算术右移**（补符号位），这三件事是一条因果链
- 结束时 A 存乘积高 n 位、Q 存低 n 位，Q−1 丢弃
- 两套书写约定（整数 n 轮每轮移位 / 小数 n+1 步末步不移位）结果相同，**不可混用**
