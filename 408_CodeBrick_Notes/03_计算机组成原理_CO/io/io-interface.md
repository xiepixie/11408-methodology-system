# I/O接口

## 大纲定位

**六（二）I/O 接口（I/O 控制器）**

- I/O 接口的功能和基本结构
- I/O 端口及其编址

要求：说清 I/O 接口承担哪几项职能、内部由哪些部件构成、三类端口各走哪条总线，以及独立编址与统一编址在**指令**和**地址空间**上的差别。

接口在整机中的位置见 [[03_计算机组成原理_CO/io/io-overview.md|I/O 系统概述]]，接口所挂的总线见 [[03_计算机组成原理_CO/bus/bus-overview.md|总线概述]]。

## 知识框架

本节回答四个问题：

- 接口的四项职能不是罗列出来的——它们分别是被什么逼出来的？
- 命令字和状态字走数据线还是控制线？为什么这条最容易判反？
- "三类端口"是三个物理寄存器吗？
- 独立编址的"独立"，独立的是地址值还是译码通路？

## 一、接口的职能是被三重不匹配逼出来的

外设与主机在工作速度、数据格式、控制协议上都不一致（推导见 [[03_计算机组成原理_CO/io/io-overview.md|I/O 系统概述]]）。接口的每一项职能，都是在消解其中一条：

| 职能 | 具体做什么 | 消解哪条不匹配 |
| --- | --- | --- |
| **数据缓冲** | 接口内设数据缓冲寄存器，先收下再转交 | **速度**：主存和 CPU 寄存器快、外设慢 |
| **错误或状态检测** | 用状态寄存器记录就绪 / 忙 / 缺纸 / 传输出错 | **速度**：让 CPU 知道现在能不能动手 |
| **控制和定时** | 接收命令字与定时信号，协调内部资源与外设的动作先后 | **协议**：不同设备的操作序列不同 |
| **数据格式转换** | 串-并转换的移位寄存器、电平转换、A/D 与 D/A | **格式**：位流、模拟量转成总线上的并行数字信号 |

没有缓冲寄存器，快慢两端就没法交接；没有状态寄存器，CPU 只能盲发命令；没有控制逻辑，一条"读扇区"翻译不成磁头动作；没有格式转换，串行位流上不了并行总线。**四项职能不是四个要背的词，是四个缺一不可的零件。**

接口在物理上有两副面孔：**主机侧的内部接口**通过 I/O 总线连 CPU 和主存，**设备侧的外部接口**通过连接器插座和电缆连外设。所谓"USB 口""网口"，指的都是外部接口那一侧。

## 二、接口的基本结构

图 8.7 I/O 接口的通用结构

左边是 I/O 总线侧的数据线、地址线、控制线；中间是数据缓冲寄存器、状态 / 控制寄存器和 I/O 控制逻辑（含地址译码）；右边是面向具体外设的界面控制逻辑与连接器插座。

把这张图的连线关系单独抽出来：

```
        CPU 侧（I/O 总线）              I/O 接口                设备侧
                          ┌──────────────────────────┐
                     ┌───→│  数据端口（数据缓冲寄存器） │←──→ 外设数据
                     │    ├──────────────────────────┤
   数据线 ←────双向───┼───→│  命令端口（控制寄存器）    │───→ 外设控制信号
                     │    ├──────────────────────────┤
                     └───→│  状态端口（状态寄存器）    │←─── 外设状态信号
                          ├──────────────────────────┤
   地址线 ──────────────→ │  地址译码 / 设备选择电路   │
   控制线 ──────────────→ │  （读/写、时序控制逻辑）   │───→ 外设控制时序
                          └──────────────────────────┘
```

> [!CAUTION]
>

命令字和状态字走的是数据线

这是这张图最容易画反的地方。

- CPU 下命令 → 把命令字**当数据写**进控制寄存器 → 走**数据线**
- CPU 查状态 → 把状态字**当数据读**回来 → 走**数据线**
- **中断类型号**同理，在中断响应周期由设备经**数据线**送回 CPU

**控制线上跑的不是内容，是时序**：读 / 写信号、M―/IO、中断响应信号这类"什么时候做什么动作"的指挥信号。地址线负责选中是哪个端口。

一句话：**内容走数据线，选谁走地址线，何时做走控制线。**

理由并不玄——数据线是接口里唯一一条**双向的、按字宽成批搬内容**的通路。命令字和状态字都是若干位的编码，本质就是内容，没有理由另开一套线。

### 三类 I/O 端口

接口中**可被 CPU 访问的寄存器**统称 I/O 端口：

| 端口类型 | 存放内容 | 方向 |
| --- | --- | --- |
| 数据端口 | 输入 / 输出数据 | 可读可写 |
| 状态端口 | 就绪、忙、完成、出错等状态信息 | CPU 只读 |
| 命令端口 | CPU 发出的控制命令 | CPU 只写 |

> [!WARNING]
>

端口是逻辑概念，不是物理寄存器的个数

状态寄存器和控制寄存器在**传送方向上相反**，而且 CPU 对它们的访问在**时间上通常错开**（先查状态、后下命令）。既然不会同时用，有的接口就把两者**合二为一**：同一个物理寄存器，高几位当状态位段读、低几位当控制位段写。

所以"状态端口和控制端口可以是同一个寄存器"是**成立**的。

> [!WARNING]
>

主存地址不属于任何一类端口

查询和中断方式下 CPU 自己访存，主存地址只在 CPU 内部周转，压根不出现在接口上。

只有 **DMA 方式**才把主存起始地址交给 DMA 控制器持有——因为只有它需要脱离 CPU 自己发起访存。见 [[03_计算机组成原理_CO/io/dma.md|DMA 方式]]。

## 三、I/O 端口的编址

接口里的寄存器要能被指令指名道姓地访问，就得给它们编号。两种编号方案：

### 独立编址（端口映射 I/O）

所有 I/O 端口单独编号，构成一个**与主存地址空间平行的独立 I/O 地址空间**。主存地址空间和I/O 地址空间是两套彼此独立的空间

两套空间从**地址码的形式上无法区分**——同一个二进制数既可能是主存单元号，也可能是端口号。因此必须靠**指令**来表明本次访问打的是哪一套：CPU 执行 IN / OUT 这类专用 I/O 指令时，产生的是 I/O 读 / I/O 写总线事务，控制线上的 M―/IO 信号随之翻转，两条译码通路各认各的。

| 指令 | 方向 |
| --- | --- |
| `IN AL, port` | I/O 端口 → **通用寄存器** |
| `OUT port, AL` | **通用寄存器** → I/O 端口 |

> [!CAUTION]
>

"独立"指译码通路独立，不是地址值不重叠

既然靠控制信号区分，**同一个地址值 `0x60` 完全可以既是某个主存单元、又是某个 I/O 端口**，硬件不会混淆。

把"独立编址"理解成"两套地址值不许相同"，是最常见的误判。

还有一条容易被跳过的前提：**I/O 指令的另一端是接口里的端口，不是设备本体**。"IN / OUT 在通用寄存器与设备之间传送数据"是错的，正确说法是"在通用寄存器与 **I/O 端口**之间传送"。

**优点**：端口数远少于主存单元，只需少量地址线，译码简单、寻址快；程序里 I/O 操作一眼可辨。 **缺点**：I/O 指令通常只提供简单的传送操作，寻址方式少，程序设计灵活性差。

### 统一编址（存储器映射 I/O）

从主存地址空间中划出一段分配给 I/O 端口，两者**共用一套编号**。主存地址空间=真正的主存+I/O 端口

既然在同一个空间的不同地址段里，**靠地址范围就能区分**访问的是端口还是主存单元，因而**不需要专门的 I/O 指令**——普通的访存指令（load / store、MOV）就能存取端口。

这一步换来的灵活性相当可观：所有访存指令、所有寻址方式都能用在端口上，`and` / `or` / `test` 这类指令可以直接对控制寄存器和状态寄存器按位操作；保护机制也不用另起炉灶，直接复用分段或分页存储管理。

**代价**：I/O 端口占掉一部分主存地址空间；程序里看到一个地址，不容易判断它指向的是真内存还是设备。

### 两种方式对照

| 特性 | 独立编址 | 统一编址 |
| --- | --- | --- |
| 地址空间 | **两套**，互相平行 | **一套**，分段共用 |
| 靠什么区分 | **控制信号**（M―/IO）＋专用指令 | **地址范围** |
| 使用指令 | 专用 I/O 指令（IN / OUT） | 普通访存指令（load / store、MOV） |
| 占用主存空间 | 否 | 是 |
| 寻址方式 | 少 | 全部可用 |
| 典型架构 | Intel 处理器架构（64K 个 I/O 地址编号） | 多数 RISC 架构，如 RISC-V、MIPS |

实际系统常两种并存：x86 既有 IN / OUT 访问的独立编址端口，也把显存等大块资源做成存储器映射。

## 例题

**例**：某机地址线 20 位，采用统一编址方式，把地址空间**最高的 4 KB** 分配给 I/O 端口，每个端口 8 位。求可用的主存空间，以及该机最多可编址多少个 I/O 端口。

**解**：统一编址下端口与主存瓜分同一个地址空间。地址空间总量=220 B=1 MB=1048576 B可用主存=1048576−4096=1044480 B=1020 KB

每个端口 8 位 = 1 B，占一个地址编号，故端口数 =4096=4K 个。

换成独立编址，这台机器的主存仍是完整的 1 MB——端口另有一套自己的地址空间。**"占不占主存空间"是两种编址方式唯一的实质代价差别**，其余差异都在指令与译码上。

## 易混淆知识点

**1. 状态字和命令字走数据线还是控制线？**

**数据线**。它们是"内容"，不是"时序"。中断类型号同理。控制线上只有读 / 写、M―/IO、中断响应这类指挥信号。

**2. 三类端口一定是三个独立的物理寄存器吗？**

不一定。状态位和控制位方向相反、访问时刻错开，可以合用同一个物理寄存器的不同位段。**端口是逻辑上的访问单位，不是物理计数单位。**

**3. 独立编址时，端口地址会和主存地址相同吗？**

**可能**。两套空间各走各的译码通路，靠控制信号区分，地址值相同不会引起混淆。

**4. 统一编址下还需要 IN / OUT 指令吗？**

不需要。地址范围已经把两者分开了，普通访存指令就能访问端口——这正是统一编址最大的收益：**寻址方式和指令种类全盘复用**。

**5. I/O 接口和 I/O 端口是同一个东西吗？**

不是，差一个层级。**接口是整个控制部件**（还包含地址译码、界面控制逻辑等 CPU 访问不到的部分），**端口只是接口中可被 CPU 访问的那些寄存器**。一个接口通常含多个端口。

## 本节小结

- 接口的四项职能——**数据缓冲、状态检测、控制定时、格式转换**——分别消解速度、协议、格式三重不匹配
- 接口有**内部接口**（连 I/O 总线）和**外部接口**（连电缆和外设）两副面孔
- **内容走数据线，选谁走地址线，何时做走控制线**；命令字、状态字、中断类型号都走数据线
- 三类端口是**逻辑概念**，状态端口与命令端口可合用一个物理寄存器
- **主存地址不属于接口内容**，只有 DMA 控制器才持有它
- **独立编址**：两套地址空间，靠 M―/IO 控制信号＋专用 I/O 指令区分，地址值**可以相同**
- **统一编址**：一套地址空间分段共用，靠地址范围区分，不需要专用 I/O 指令，但占用主存空间
- I/O 指令的另一端是**通用寄存器与端口**，不是设备本体
