# DMA直接存储器访问

## 大纲定位

**六（三）I/O 方式**

- DMA 方式

DMA 控制器的组成，DMA 传送过程。

要求：说清 DMA 控制器由哪些寄存器构成、每个寄存器为什么必须存在，完整复述预处理 / 数据传送 / 后处理三阶段，辨明 DMA 请求与中断请求争的不是同一样东西，并说出三种数据传送方式各自成立的条件。

前一档方式为什么撑不住，见 [[03_计算机组成原理_CO/io/programmed-interrupt.md|程序查询方式与程序中断方式]]；DMA 争夺的总线控制权由谁裁决，见 [[03_计算机组成原理_CO/bus/bus-overview.md|总线概述]]。

## 知识框架

本节回答四个问题：

- DMA 请求和中断请求，请求的分别是什么？为什么这一条决定了两者的响应时刻不同？
- DMA 控制器里那几个寄存器，能不能从"它要独立访存"这一个前提推出来？
- 停止 CPU 访存、周期挪用、交替访存，各自在什么条件下才划算？
- 用了 DMA 就不需要中断了吗？

## 一、DMA 要拆掉的是哪一堵墙

中断方式已经把外设准备数据的时间还给了 CPU，但它留下一段没法再压缩的开销：**每传一个数据，CPU 都要被打断一次，走一遍"响应 + 保护现场 + 搬数据 + 恢复现场 + 返回"**。

对高速设备，这一段是致命的。数据传输率越高，中断频率越高，直到 T准备<T中断 那条线被越过——不是慢，是**丢数据**。

所以 DMA 改的不是"CPU 被打断得太频繁"，而是更根本的一条：

**数据凭什么要经过 CPU？**

查询方式和中断方式的数据通路都是三段：设备接口 → CPU 寄存器 → 主存。CPU 在中间纯粹是个搬运工。DMA（Direct Memory Access，直接存储器存取）把这一段短路掉：设备接口↔DMA 控制器控制总线主存

数据在设备接口与主存之间**直接**流动，CPU 不在这条通路上。

> [!WARNING]
>

DMA 控制器里的数据缓冲寄存器不改变通路的两端

DMAC 内部确实有一个数据缓冲寄存器（DR），但它只是过渡缓冲。**通路的两端仍然是"设备接口 ↔ 主存"**，说成"数据通路在设备接口和 DMA 控制器之间"是错的。

## 二、核心辨析：DMA 请求的是总线控制权

DMA 和中断都采用"请求—响应"的方式，很容易被当成同一类机制。它们的分界只有一句话：

> [!CAUTION]
>

中断请求的是处理器的执行权，DMA 请求的是总线的控制权

- **中断**：设备请求 CPU **执行一段程序**（ISR）。CPU 让出的是自己的执行时间。
- **DMA**：控制器请求**接管总线**，自己去发地址、发读写信号、走数据线。CPU 让出的是总线，程序照跑。

这一条差别把后面一串结论全带出来了：

|  | 程序中断方式 | DMA 方式 |
| --- | --- | --- |
| 请求的对象 | **CPU 的执行权** | **总线控制权** |
| 谁来裁决 | 中断判优电路（中断优先级体系） | **总线仲裁**机制 |
| 响应时刻 | **一条指令执行结束后** | **一个存储周期（总线事务）结束后** |
| CPU 让出什么 | 一段执行时间 | 一段总线占用时间 |
| 数据经过 CPU | 是 | **否** |
| 传送单位 | 字 / 字节 | **数据块** |
| 中断请求在其中的作用 | 请求传送数据 | **报告整块传送完成** |

**响应时刻的粒度差异是推出来的，不用背**：中断要交出执行权，就必须等到一条指令做完、PC 和 PSW 干净可恢复的时刻；DMA 只要占用总线，总线的最小不可分割单位是一个存储周期，所以在存储周期边界就能切换。**粒度取决于让出的东西的最小完整单位。**

同理，**当 CPU 与 DMA 同时要访存时 DMA 优先**：外设的数据不及时取走会丢（磁盘转过去了就得再等一圈），而 CPU 被推迟一两个存储周期只是慢一点。**"耽误不起的先走"是这里唯一的判据。**

## 三、DMA 控制器的组成

要让控制器脱离 CPU 自己完成一次块传送，它至少得知道四件事：**往哪写、还剩多少、数据暂存在哪、这次是读还是写**。四个寄存器由此一一对应：

| 寄存器 | 存什么 | 为什么必须有 |
| --- | --- | --- |
| **AR** 主存地址寄存器 | 当前传送数据在主存中的地址，每传一个自动增量 | 控制器要**自己发地址上总线**——这是查询 / 中断方式下 CPU 才做的事 |
| **WC** 字计数器 | 还需传送的数据个数，每传一个自动减 1 | 传送要能**自己判断何时结束**，减到 0 就是终点 |
| **DR** 数据缓冲寄存器 | 设备与主存之间过渡的一个数据 | 设备侧与总线侧的时序、位宽不同，需要一拍缓冲 |
| **CR** 命令 / 状态寄存器 | CPU 写入的传送方向与控制命令、当前状态 | 一次传送是输入还是输出，得先说清 |

此外还有**中断请求电路**（传送结束时向 CPU 发中断）和**控制 / 时序逻辑**（发总线请求、接管总线、发读写信号）。有的 DMAC 还设**设备地址寄存器**，用来指明本次传送对应哪台设备。

> [!WARNING]
>

"每传一个字"里的"字"有多宽

它的宽度就是 **DR（数据缓冲寄存器）的宽度**，由题面给出（常见 8 / 16 / 32 / 64 位）。

**AR 每次的增量 = DR 的字节数**，算总线请求次数时也用它。不要默认按 1 字节。

```
   ┌─────────┐                                  ┌─────────┐
   │   CPU   │                                  │  主存    │
   └────┬────┘                                  └────┬────┘
        │                                            │
   ═════╪══════════════ 系统总线 ═══════════════════╪═════
        │                     │                      │
        │  ①设参数/③完成中断   │ ②数据直接在这两者之间走 │
        │                ┌────┴─────┐                │
        └───────────────→│ DMA 控制器 │←──────────────┘
                         │ AR WC DR CR│
                         └────┬─────┘
                              │  设备数据
                         ┌────┴─────┐
                         │   外设    │
                         └──────────┘
```

CPU 只在 ① 和 ③ 出现，② 整段它完全不在场。

## 四、DMA 传送过程

### 预处理（初始化）——CPU 参与

CPU 执行一段初始化程序：

- **准备内存区**：输入则申请并初始化缓冲区，输出则先把数据在主存里准备好
- **设置传送参数**：主存首址 → AR，传送个数 → WC，传送方向 → CR，设备地址 → 设备地址寄存器
- 发出"启动 DMA 传送"命令，然后**调度 CPU 去执行其他进程**

> [!TIP]
>

这一步用的是程序查询方式

CPU 写 DMAC 的寄存器是同步、确定、瞬间完成的动作，不值得为它设一次中断——直接用 I/O 指令写端口即可。**三种 I/O 方式在一次真实传送里是分工协作的**，见下文第六节。

### 数据传送——CPU 不参与

DMAC 接管总线，逐个数据搬运。每传一个：

- 设备把数据送入 DR（或从 DR 取走）
- DMAC 把 AR 的内容送地址总线，在读 / 写线上发出命令
- 数据经数据总线在 DR 与主存之间传送
- AR←AR+DR 的字节数，WC←WC−1
- 若 WC≠0，回到第 1 步

整段**不需要 CPU 执行任何指令**。

### 后处理——CPU 参与

WC=0 时，DMAC 向 CPU 发出"DMA 结束"中断请求。CPU 响应后在中断服务程序里做善后：校验数据是否正确、决定是否继续下一批、必要时重新设置 DMAC 参数。

## 五、三种数据传送方式及其适用条件

DMAC 与 CPU 共享主存，两者都要访存时就产生冲突。三种解法**不是好坏排序，而是三套适用条件不同的方案**。

### 停止 CPU 访存

DMA 传送期间，DMAC 向 CPU 发停止信号，CPU 交出地址线、数据线和有关控制线，直到整块数据传完才收回。

- **控制最简单**
- 代价：CPU 在整段时间里基本处于不工作或保持状态
- **适用条件：数据传输率很高的设备做成组数据传送**——只有传输率足够高，一整块的传送时间才够短，把 CPU 停这么久才不至于太亏

> [!TIP]
>

这种方式对主存也是浪费

即使外设很快，**两个数据之间的准备间隔仍然远大于一个存取周期**。CPU 停着不访存、外设又在准备下一个数据，主存这段时间是空闲的——主存利用率并没有被发挥出来。

工程上的补救是在 DMA 接口里加一个小容量存储器：设备先与它交换，再由它成批与主存交换，从而缩短占用总线的时间。

### 周期挪用（周期窃取）

每当设备发出 DMA 请求，就**挪用一个（或几个）存储周期**去访存，传完一个数据立即释放总线；设备不请求时 CPU 照常访存。这是一种**单数据传送方式**。

请求到来时有三种情形：

| 情形 | 结果 |
| --- | --- |
| CPU 此刻不需要访存（如正在执行耗时较长的运算指令） | 不冲突，直接用 |
| CPU 正在访存 | 等这个存取周期结束，CPU 才让出总线 |
| CPU 也正要访存 | **冲突，DMA 优先**——CPU 延后一两个存取周期再访存 |

> [!WARNING]
>

一次挪用的实际代价不止一个存储周期

每挪用一次，都要走完**申请总线控制权 → 建立总线控制权 → 归还总线控制权**这三步。所以对主存来说只占了一个存储周期，**对 DMA 接口而言实质要占 2～5 个存储周期**（取决于逻辑线路的延迟）。

由此推出它的适用条件：**外设的读 / 写周期要大于主存周期**——设备两个数据之间的间隔得足够长，才够摊掉这几个周期的开销。

这是**应用最广泛**的一种：既完成了 I/O 传送，又较好地发挥了 CPU 与主存的效率。

### DMA 与 CPU 交替访存

把一个 CPU 工作周期分成两个分周期，一个专供 DMAC 访存、另一个专供 CPU 访存。

- 总线控制权由分周期信号直接切换，**不需要申请、建立、归还的过程**，切换几乎不花时间
- CPU 与 DMAC 各有独立的访存地址寄存器、数据寄存器和读 / 写信号，总线实质变成受两个分周期控制的多路转换器
- CPU **既不停止运行也不进入等待**，DMA 传送速率很高
- 代价：硬件逻辑复杂得多
- **适用条件：CPU 的工作周期比主存存取周期长**——只有一个 CPU 周期里塞得下两次访存，切分才成立

### 三者对照

| 方式 | CPU 受影响 | 控制复杂度 | 成立条件 |
| --- | --- | --- | --- |
| 停止 CPU 访存 | 大（整段停摆） | **低** | 高传输率设备的**成组**传送 |
| 周期挪用 | 小（延后一两个存取周期） | 中 | **外设读写周期 > 主存周期** |
| 交替访存 | **无** | **高** | **CPU 工作周期 > 主存存取周期** |

**三行的条件读下来是一条清晰的因果链**：CPU 让出的时间越少，对时序配合的要求就越苛刻，硬件也越复杂。

### 同一块数据，三种方式各占 CPU 多久

把三者放到同一组参数下，差别立刻变成数量级。设一块共 n 个数据、主存存取周期为 Tm、设备**两个数据之间的间隔**（准备一个数据的时间）为 Td，且 Td≫Tm（这个前提对绝大多数外设都成立）。

| 方式 | CPU 被剥夺的时间 | 怎么来的 |
| --- | --- | --- |
| 停止 CPU 访存 | ≈n×Td | CPU 从块首停到块尾，**设备准备数据的那些间隔也一并停着** |
| 周期挪用 | ≈n×Tm | 只在每次实际访存时让出一个存取周期，间隔期间 CPU 照跑 |
| 交替访存 | ≈0 | 两个分周期互不重叠，CPU 一个周期也没少 |

关键是第一行**不是 n×Tm**：停止 CPU 访存停的是"整块传送的全过程"，而整块传送的时间由设备速度决定，不是由主存决定。两者的比值正好是T停机T挪用≈TdTm

举个数：n=1024、Tm=100 ns、Td=1 μs 时，停止 CPU 访存要让 CPU 停摆约 1024 μs，周期挪用只占掉约 102.4 μs，相差 10 倍——正是 Td/Tm。**这个比值就是上面那条 tip"停止 CPU 访存对主存也是浪费"的定量形态。**

也正因如此，停止 CPU 访存只在 Td 逼近 Tm（设备快到几乎不用等）时才划算，这与它的适用条件"数据传输率很高的设备做成组传送"是同一句话的两种说法。

## 六、一次磁盘传送里，三种 I/O 方式是分工的

三种 I/O 方式常被当成互斥的三选一，但一次真实的磁盘读写里它们是**配合使用**的：

图 8.24 DMA 方式进行磁盘数据传送过程

| 阶段 | 用哪种方式 | 为什么 |
| --- | --- | --- |
| 设置传送参数（初始化 DMAC） | **程序查询** | CPU 主动写寄存器，同步完成，不值得中断 |
| 寻道 | **中断** | 磁头移动是毫秒级机械动作，CPU 不能干等 |
| 查找扇区 | **中断** | 同上 |
| **连续读写数据** | **DMA** | 数据率高、成批传送，逐个数据中断扛不住 |
| 传送结束、校验 | **中断** | 一次性事件，通知 CPU 做后处理 |

所以"用了 DMA 就不用中断了"是错的——**DMA 的开头（准备）和结尾（完成通知）都要靠中断**。DMA 做的是把中断从"每传一个数据一次"降到"每传一块一次"。

## 例题

**例 1（DMA 的 CPU 占比，并与中断方式对照）**：某机主频 1 GHz，某外设数据传输率 2 MB/s，接口数据缓冲寄存器 32 位。改用 DMA 方式后每次传送一块 4 KB 数据，DMA 的预处理与后处理合计 200 条指令，CPI = 5。求 CPU 用于该设备 I/O 的时间占比。

**解**：

**① 把指令条数折成时钟周期**（公式要的是周期数，题面给的是指令条数）：m=200 条×5=1000 时钟周期

**② DMA 每秒被触发多少次**（以**块**为单位）：N=2×106 B/s4096 B/块≈488.28 次/秒

**③ 占比**（数据传送阶段完全由 DMAC 完成，不计入 CPU）：488.28×10001×109≈4.88×10−4=0.0488%

同一台设备在 [[03_计算机组成原理_CO/io/programmed-interrupt.md|程序查询方式与程序中断方式]] 的例 2 里用中断方式算出的占比是 **75%**。差距的来源只有一处：**中断以 4 B 为单位触发，DMA 以 4096 B 为单位触发**，频率相差 1024 倍。

> [!CAUTION]
>

这类计算里最容易出错的两处

- **传送单位不是"1 字节"**。中断方式的 u 由数据端口 / 缓冲寄存器位宽给出，DMA 方式的单位是**块大小**。单位取错，结果会整体偏离若干倍。
- **指令条数必须乘 CPI 才是周期数**，而且预处理与后处理的指令数要**先相加再乘**。

**例 2（总线请求次数）**：某 DMA 控制器的数据缓冲寄存器为 32 位，一次传送一个 2 KB 的数据块。DR 每装满一次就向总线仲裁器发一次总线请求，问传送这一块期间共发出多少次总线请求？

**解**：先把两边统一到**位**再除。N=2048 B×832 位=1638432=512 次

直接用 2048÷32 会得到 64，差 8 倍——**字节和位不能混除**。若 DR 是 64 位，则 16384÷64=256 次。

## 易混淆知识点

**1. DMA 请求和中断请求是一回事吗？**

不是，这是本节最核心的分界。**中断请求的是 CPU 的执行权，DMA 请求的是总线控制权。** 由此推出：中断走中断判优、在**指令结束后**响应；DMA 走总线仲裁、在**存储周期结束后**响应。

**2. "DMA 全程不需要 CPU"对吗？**

不对。三个阶段里只有**数据传送阶段**完全不需要 CPU：

- **预处理**：CPU 执行指令设置 AR / WC / CR ——**需要 CPU**
- **数据传送**：DMAC 控制总线逐个搬运——不需要 CPU
- **后处理**：DMAC 发中断，CPU 执行 ISR 校验善后——**需要 CPU**

正确表述是"DMA **传送过程**不需要 CPU 干预"。

**3. DMA 传送完成后靠什么通知 CPU？**

靠**中断**。DMA 没有取代中断，而是把中断频率从"每个数据一次"降到"每块一次"。

**4. 周期挪用会让 CPU 变慢吗？**

会，但幅度有限：每挪用一次，CPU 的访存被推迟一两个存取周期。高速设备下挪用频繁，CPU 的有效速度会明显下降——但仍远好于中断方式下 CPU 亲自搬每一个数据。

**5. 三种传送方式里哪种"最好"？**

问题本身不成立，它们的**成立条件不同**：成组高速传送用停止 CPU 访存；外设读写周期大于主存周期用周期挪用；CPU 工作周期长于主存存取周期才能用交替访存。周期挪用之所以最常见，是因为它的条件在多数机器上都满足。

**6. DMA 优先于 CPU 访存，是因为 DMA 更重要吗？**

不是重要性，是**时限**。外设的数据不及时取走会被覆盖或错过（磁盘转过去要等一整圈），CPU 延后一两个存储周期只是慢一点。判据永远是"**谁耽误不起**"。

## 本节小结

- DMA 把数据通路从"设备接口 → CPU 寄存器 → 主存"缩成"**设备接口 ↔ 主存**"，CPU 不在通路上
- **中断请求的是 CPU 执行权，DMA 请求的是总线控制权**——这是两者一切差别的根源
- 由此：中断走中断判优、在**指令结束**后响应；DMA 走**总线仲裁**、在**存储周期结束**后响应
- DMAC 四个核心寄存器 **AR / WC / DR / CR**，分别对应"往哪写 / 还剩多少 / 暂存在哪 / 读还是写"
- **AR 的增量 = DR 的字节数**，"一个字"多宽由 DR 位宽决定
- 三阶段：**预处理**（CPU 设参数，用查询方式）→ **数据传送**（DMAC 控制，CPU 不参与）→ **后处理**（发中断，CPU 善后）
- **停止 CPU 访存**：控制最简单，适用于高传输率设备的成组传送
- **周期挪用**：应用最广；实际占用 2～5 个存储周期（申请 / 建立 / 归还），适用于**外设读写周期 > 主存周期**
- **交替访存**：CPU 完全不受影响、无需申请归还，但要求 **CPU 工作周期 > 主存存取周期**，硬件复杂
- 同一块数据下 CPU 被剥夺的时间：停止访存 ≈nTd（**按设备速度算，不是按主存周期算**）、周期挪用 ≈nTm、交替访存 ≈0，前两者之比 =Td/Tm
- CPU 与 DMA 争用主存时 **DMA 优先**，判据是"谁耽误不起"，不是重要性
- **DMA 没有取代中断**：开头的准备阶段和结尾的完成通知都靠中断
