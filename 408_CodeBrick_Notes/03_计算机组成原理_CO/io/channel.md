# 通道方式

## 大纲定位

> [!WARNING]
>

本条已不在现行大纲内

现行 408 大纲 **六（三）I/O 方式**只列了三条：程序查询方式、程序中断方式、DMA 方式，**没有通道方式**。

**那为什么还留着这一节**：通道是 DMA 之上的一层。把"DMA 只能搬一段参数固定的数据，通道能自己取指令执行一串 I/O 任务"这个层级关系搞清楚，反过来能把仍在纲内的 **DMA 的能力边界**看得更准——DMA 控制器做什么、不做什么。

**怎么分配时间**：[[03_计算机组成原理_CO/io/programmed-interrupt.md|程序查询方式与程序中断方式]] 和 [[03_计算机组成原理_CO/io/dma.md|DMA 方式]] 才是正事。本节读一遍建立层级感即可，不必记忆细节。

## 知识框架

本节回答四个问题：

- DMA 已经不经过 CPU 了，通道还能再省下什么？
- 通道和 DMA 的分界线画在哪一条能力上？
- 通道指令和 I/O 指令是一回事吗？
- 三种通道的差别是什么？各适合接什么设备？

## 一、DMA 在大系统里撞上的墙

在小型机和微机里，DMA 已经够用：几台高速设备各配一个 DMA 接口，成组数据传送不经过 CPU。

但设备一多，DMA 这套结构就开始崩：

| 问题 | 原因 |
| --- | --- |
| **硬件成本高** | 每台设备都要配一个专用 DMA 接口 |
| **控制复杂** | 众多 DMA 接口同时访问主存，冲突仲裁的逻辑迅速膨胀 |
| **CPU 仍被占用** | 每一次传送的参数都得 CPU 去设，接口一多，光初始化就吃掉大量 CPU 时间；频繁的周期挪用还会拖慢 CPU |

关键在第三条：**DMA 卸掉了"搬运"，没卸掉"组织"**。谁先传、传到哪、传完接着传什么，仍然是 CPU 在一次次安排。

于是往前再走一步的方向就明确了：**把"组织 I/O"这件事也交出去**。

## 二、通道是什么：能执行通道程序的专用处理器

**通道**是负责管理 I/O 设备、实现主存与 I/O 设备之间交换信息的部件，可以视为**一种具有特殊功能的处理器**。

它与 DMA 控制器的分界，就在一条能力上：

> [!CAUTION]
>

分界线：能不能自己取指令执行

- **DMA 控制器**是**定制硬件**。它的行为由 CPU 预先写进 AR / WC / CR 的那几个参数完全决定，做完一次就停下等下一次设置。它**不取指令**。
- **通道**有**自己的指令系统**（通道指令）。CPU 只发一条启动命令，通道就从**主存**里取出一段**通道程序**并执行，自主完成设备选择、数据传送、缓冲管理、错误处理，直到整批任务完成才向 CPU 发一次中断。

**能否自己取指令执行，是"控制器"和"处理器"的分水岭。**

但通道也**不是一个完整的处理器**，它受两条限制：

- **指令类型单一**——硬件比较简单，能执行的基本只有与 I/O 操作有关的指令
- **没有自己的内存**——通道程序放在主机的主存里，通道与 CPU **共享内存**

而且它**必须由 CPU 的 I/O 指令来启动、停止或改变工作状态**，是**从属于 CPU 的一个专用处理器**，不能独立工作。

## 三、通道指令与 I/O 指令不是一回事

这两个名字很像，但分属两套指令系统：

|  | I/O 指令 | 通道指令 |
| --- | --- | --- |
| 属于谁的指令系统 | **CPU 的**指令系统的一部分 | **通道自身**的指令 |
| 由谁译码执行 | **CPU** | **通道** |
| 存放在哪 | 用户 / 内核程序里，和普通指令混排 | 由管理程序放在**主存**中，由通道取出执行 |
| 干什么 | 在有通道的机器里，**不实现数据传送**；只负责启 / 停 I/O 设备、查询通道与设备状态 | **实现真正的 I/O 操作**：读、写、磁带走带、磁盘找道等 |
| 又称 | — | **通道控制字**（CCW） |

一条通道指令通常要指明：参与传送的数据在主存中的**首地址**、传送的**字节数**（或末地址）、所选设备的**设备码**、以及本次操作的**命令码**。位数因此比普通指令长得多。

若干条通道指令组成一段**通道程序**，完成"某台外设与主存之间传送一批信息"这样一个完整任务。CPU 执行一条 I/O 指令启动通道⟶通道从主存取通道程序并执行⟶任务全部完成后发一次中断

## 四、层级关系：一层管一层
CPU⟶通道⟶设备控制器⟶I/O 设备

| 层级 | 执行什么 | 负责什么 |
| --- | --- | --- |
| **CPU** | I/O 指令 | 发出"启动通道"命令，之后不再过问 |
| **通道** | 通道程序 | 选设备、组织数据传送、缓冲管理、错误处理 |
| **设备控制器** | 通道命令 | 直接驱动某台设备完成传送 |
| **I/O 设备** | — | 物理读写 |

这是一棵扇出的树：**一个通道可以连多个设备控制器，一个设备控制器又可以控制若干台同类型设备**。因而少数几个通道就能管理相当多的设备——CPU 面对的不再是几十个接口，而是几个通道。

> [!TIP]
>

通道数量少反而会成为瓶颈

通道价格昂贵，机器里配的数量有限。若某台设备通往主存的路径上，通道或控制器已被占用，这台设备就启动不了——这就是 I/O 系统的"瓶颈"现象。

解法不是加通道，而是**增加设备到主机之间的通路**：把一台设备接到多个控制器上、一个控制器接到多个通道上，形成多通路 I/O 系统。这既缓解了瓶颈，又提高了可靠性——个别通道或控制器故障不会让设备与主存之间断路。

## 五、三种通道及其适用场景

通道按**信息交换方式**分三种。三者的差别可以用一个问题串起来：**同一时刻，通道能不能同时为多台设备服务？**

### 字节多路通道（Byte Multiplexor Channel）

按**字节交叉**方式工作。通道内含许多**非分配型子通道**（可达几十到数百个），每个子通道接一台设备，各子通道以**时间片轮转**的方式共享主通道：A 子通道传完一个字节就让出主通道给 B，B 传完让给 C，轮完一圈再回到 A。

送往主机的数据流因此是交织的：A1,B1,C1,…,A2,B2,C2,…

- **粒度**：一个字节
- **适用**：**大量低速设备**（键盘、终端、字符打印机）。只要通道扫描各子通道的速率足够快，而设备速率又不高，就不会丢信息
- **不适用**：高速设备——轮转一圈的时间撑不住

### 选择通道（数组选择通道，Block Selector Channel）

按**数组（成块）**方式传送，可以连接多台高速设备，但只含**一个分配型子通道**：一段时间内只能执行一道通道程序、只为一台设备服务。

某台设备一旦占用该通道，就**独占到底**——即使它中途没有数据要传、通道闲置，也不允许别的设备插进来，直到它传完释放。

- **粒度**：一整块
- **适用**：**少数高速设备**的成块传送（磁盘、磁带）
- **代价**：**通道利用率低**，独占期间的空隙全部浪费

### 数组多路通道（Block Multiplexor Channel）

把前两者的长处合起来：既按**数组方式**传送（保住高速率），又含**多个非分配型子通道**（保住分时并行）。某台设备传完一块后就让出通道，另一台可以接上。

- **粒度**：一块，但设备之间可以**按块交替**
- **适用**：**多台高、中速设备**——这是三者中最实用的一种

### 对照

| 通道类型 | 传送粒度 | 同时服务多台设备 | 子通道类型 | 适用设备 |
| --- | --- | --- | --- | --- |
| **字节多路** | 字节 | **是**（字节交叉轮转） | 非分配型，数量多 | 大量**低速**设备 |
| **选择** | 数据块 | **否**（独占） | 分配型，仅一个 | 少数**高速**设备 |
| **数组多路** | 数据块 | **是**（按块交替） | 非分配型，多个 | 多台**高、中速**设备 |

**一句话串起来**：字节多路牺牲速率换并行，选择通道牺牲并行换速率，数组多路把粒度调到"块"这一档，两头都要。

## 六、I/O 系统演进的四个阶段

把通道放回整条演进线上，才看得清它补的是哪一格：

| 阶段 | 形态 | CPU 从中脱身的部分 |
| --- | --- | --- |
| 一 | **直接连接**（早期，无接口） | — |
| 二 | **接口模块与 DMA** | 中断使 CPU 与外设并行；DMA 让数据不经过 CPU |
| 三 | **通道结构** | **组织 I/O 的工作**也交出去，CPU 只发启动命令 |
| 四 | **I/O 处理机**（外围处理机） | 基本独立于主机工作，还能做码制变换、格式处理、数据块检错纠错 |

每一步的方向都是同一个：**降低 CPU 在 I/O 中的介入程度**。这条轴的完整刻度见 [[03_计算机组成原理_CO/io/io-compare.md|I/O 方式对比]]。

## 易混淆知识点

**1. 通道和 DMA 控制器的根本区别是什么？**

**能否自己取指令执行。** DMA 控制器是定制硬件，行为由 CPU 预置的参数决定；通道有自己的指令系统，能从主存取出通道程序并执行。其余差别（能管几台设备、灵活性、CPU 介入频率）都是这一条的推论。

**2. 通道是完整的处理器吗？**

不是。它**指令类型单一**、**没有自己的内存**（通道程序放在主存里，与 CPU 共享），而且**必须由 CPU 启动**，不能独立工作。它是"从属于 CPU 的专用处理器"。

**3. 通道指令就是 I/O 指令吗？**

不是。**I/O 指令属于 CPU 的指令系统，由 CPU 执行**；在有通道的机器里它不传数据，只负责启停设备、查状态。**通道指令属于通道，由通道执行**，它才是真正完成读写的那一层，又称通道控制字（CCW）。

**4. 字节多路通道为什么不能接高速设备？**

它靠时间片轮转在几十上百个子通道之间切换，**一台设备两次被服务之间要等其余子通道轮完一圈**。设备速率一高，这段间隔就撑不住，数据会丢。

**5. 选择通道速率高，为什么还要数组多路通道？**

因为选择通道**独占**：某台设备占用期间，即使它没数据可传、通道空转，别的设备也进不来，**通道利用率很低**。数组多路通道保留了成块传送的高速率，又允许设备按块交替使用通道。

**6. 现代 PC 里有通道吗？**

没有。微机用 **DMA + 总线主控**（bus mastering，即设备可以主动申请并接管总线）达到了近似效果。通道方式主要存在于大中型机环境。

## 本节小结

- DMA 卸掉了"搬运"，**没卸掉"组织"**——设备一多，光设置参数就吃掉大量 CPU 时间，这是通道出现的动因
- **通道 = 能执行通道程序的专用处理器**；与 DMA 控制器的分界是**能否自己取指令执行**
- 通道**不是完整处理器**：指令类型单一、无自己的内存（与 CPU 共享主存）、必须由 CPU 启动
- **I/O 指令属于 CPU**（在有通道的机器里只负责启停与查状态）；**通道指令属于通道**，又称**通道控制字 CCW**，它才实现真正的数据传送
- 层级：**CPU → 通道 → 设备控制器 → 设备**；一个通道连多个控制器，一个控制器连多台设备
- 通道数量少会成为**瓶颈**，解法是增加设备到主机的**通路**（多通路 I/O 系统）
- **字节多路通道**：字节交叉轮转，多子通道并行，接**大量低速**设备
- **选择通道**：成块传送但**独占**通道，利用率低，接**少数高速**设备
- **数组多路通道**：成块传送 + 多子通道**按块交替**，接**多台高中速**设备，最实用
- I/O 系统演进四阶段：直接连接 → 接口与 DMA → **通道** → I/O 处理机，方向始终是降低 CPU 的介入程度
