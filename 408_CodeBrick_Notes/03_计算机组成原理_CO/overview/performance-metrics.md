# 计算机的性能指标

## 大纲定位

**一（二）计算机性能指标**

内容：吞吐量、响应时间；CPU 时钟周期、主频、CPI、CPU 执行时间；MIPS、MFLOPS、GFLOPS、TFLOPS、PFLOPS、EFLOPS、ZFLOPS。

要求：能写出 CPU 执行时间与指令条数、CPI、时钟周期之间的关系，并说清这三个因子各由计算机系统的哪一层决定、为什么互相制约；能用 Amdahl 定律算出局部加速带来的整体收益及其上限；知道 MIPS 与 FLOPS 各自度量什么、边界在哪。

各层次的划分与 ISA 的位置见 [[03_计算机组成原理_CO/overview/system-architecture.md|计算机系统层次结构]]；CPI 里那部分"等待"的来源见 [[03_计算机组成原理_CO/storage/cache-performance.md|Cache 性能分析]] 与 [[03_计算机组成原理_CO/cpu/pipeline-performance.md|流水线性能指标]]。

## 知识框架

本节回答四个问题：

- 说一台机器"快"，到底是在说吞吐率还是响应时间？两者能互相推出来吗？
- CPU 执行时间被拆成三个因子后，每个因子分别由计算机系统的哪一层决定？
- 为什么单看主频、单看指令条数、单看 MIPS，结论都可能是反的？
- 只把系统的一部分加速，整体最多能快多少？天花板由什么定？

## 一、两个基本指标：吞吐率与响应时间

衡量一个计算机系统的性能，有两个基本指标：

- **吞吐率**（throughput，也称**吞吐量**）：单位时间内所完成的工作量；
- **响应时间**（response time，也称执行时间或等待时间）：从作业提交开始到作业完成所用的时间。

两者不能互相推出来。提高吞吐率的手段（多核并行、批处理、深度流水）往往会让**单个任务**的响应时间变长；反过来，为压低响应时间而做的优化（提前唤醒、抢占调度）会牺牲总吞吐。它们是两个独立的优化目标。

如果不考虑具体应用背景而直接比较计算机性能，则大多用**程序的执行时间**来衡量：完成同样工作量所需时间最短的那台机器性能最好。

### 时间的口径必须先说清

操作系统调度处理器时，一段时间内会让多个进程轮流使用 CPU。因此在某个用户程序执行期间，还可能有其他用户程序和操作系统程序在执行——**用户感觉到的执行时间并不是这个程序真正的执行时间**。

| 口径 | 包含什么 |
| --- | --- |
| **用户 CPU 时间** | 真正用于执行**该用户程序代码**的时间 |
| 系统 CPU 时间 | CPU 执行**操作系统程序**（系统调用等）的时间 |
| CPU 时间 | 上面两者之和 |
| **响应时间**（墙钟时间） | CPU 时间 + 等待 I/O 完成的时间 + CPU 被其他用户程序占用的时间 |

由此引出一对必须分开的概念：

**系统性能**指系统的**响应时间**，它与 CPU 相关，同时也与 CPU 以外的部分有关； **CPU 性能**指**用户 CPU 时间**，它只包含 CPU 运行用户程序代码的那段时间。

下面所有公式度量的都是**用户 CPU 时间**这一口径，不含 I/O 等待，也不含其他程序占用。

## 二、时钟周期与主频

一条指令的执行被分成若干步骤，每一步都要有相应的控制信号；这些信号何时发出、作用多久，都需要定时信号来同步。因此计算机必须能产生同步的时钟定时信号，也就是 **CPU 的主脉冲信号**。

- **时钟周期**（clock cycle）：主脉冲信号的**宽度**，是 CPU 工作的最小时间单位；
- **主频**（clock rate，时钟频率）：主脉冲信号的频率，是时钟周期的倒数。Tc=1f

主频 2 GHz 意味着每秒 2×109 个时钟周期，每个周期 0.5 ns。

### 时钟周期的长短由什么决定

时钟脉冲信号由**机器脉冲源**（晶振）发出，经**整形和分频**后形成。但周期到底能压到多短，不由晶振决定，而由电路本身决定：

时钟周期以**相邻两个状态单元之间组合逻辑电路的最大延迟**为基准确定。

理由是一条硬约束：信号必须在**一个周期之内**，从上一级寄存器出发、穿过中间的组合逻辑、稳定地到达下一级寄存器的输入端。所有这样的路径中最长的一条，就把周期的下限钉死了——这条路径称为**关键路径**。

由此可以直接推出三种 CPU 的时钟周期各取多长：

| CPU 类型 | 相邻状态单元之间隔着什么 | 因此时钟周期 = | 一个周期内完成 |
| --- | --- | --- | --- |
| [[03_计算机组成原理_CO/cpu/single-cycle.md|单周期]] | 一条指令的**全部**组合逻辑 | **最耗时那条指令**的完整执行时间 | 一条完整指令（CPI = 1，但周期极长） |
| [[03_计算机组成原理_CO/cpu/multi-cycle.md|多周期]] | 一个执行步骤的组合逻辑（中间插了寄存器） | **单个步骤**的关键路径，远短于单周期 | 一条指令的一个阶段（CPI > 1） |
| [[03_计算机组成原理_CO/cpu/pipeline-basic.md|流水线]] | 一个流水段的组合逻辑 + 段间锁存器 | **最长流水段**的延迟 + 锁存器开销 | 每条指令的一个流水段 |

这张表也解释了多周期和流水线为什么能提主频：它们在数据通路中间插入了状态单元，把原本一整条的长路径**切断**成若干短路径，最长的那一段就短了。

> [!WARNING]
>

一个时钟脉冲不等于开始一条新指令

只有**单周期 CPU** 才是一条指令一个时钟周期。多周期和流水线 CPU 上，一条指令都要跨越多个时钟周期。

流水线的"每个周期完成一条指令"说的是理想稳态下的**吞吐**：每个周期有一条指令**流出**，同时有一条指令流入，但流水线里同时装着好几条指令，每一条都还要走完剩下的段。

同一型号的 CPU，主频越高执行越快；但**不同型号之间不能仅凭主频比较性能**——原因在下一节。

## 三、CPI

**CPI**（cycles per instruction）表示执行一条指令所需的时钟周期数。它有两个层次的含义，混起来就会出问题：

- 对**一条特定指令**而言，CPI 指执行该指令所需的时钟周期数，是一个确定的值；
- 对**一个程序或一台机器**而言，综合 CPI 指该程序（或该机器指令集中的所有指令）执行所需的**平均**时钟周期数。

程序总时钟周期数可以从指令条数和 CPI 两头算：总时钟周期数=IC×CPI=∑i=1n(CPIi×Ci)

其中 Ci 是第 i 类指令的条数。若已知各类指令在程序中所占的比例 Fi，则综合 CPI 是加权平均：CPI=∑i=1n(CPIi×Fi)=总时钟周期数总指令条数

与 CPI 互为倒数关系的是 **IPS**（instructions per second），每秒执行的指令条数：IPS=fCPI

### 程序的 CPI 不是一个常数

上面那个加权平均只算了"指令本身在理想情况下要几个周期"。**真实程序的 CPI 还要加上执行过程中被迫等待的周期**，其中最大的一块是 Cache 缺失：CPI有效=CPI理想+每条指令平均访存次数×缺失率×缺失代价

代入一组数看量级：理想 CPI 为 1.0，每条指令平均访存 1.3 次，缺失代价 100 个周期。缺失率 5% 时CPI有效=1.0+1.3×0.05×100=7.5

缺失率降到 2%，CPI 降到 1.0+1.3×0.02×100=3.6。**缺失率变动 3 个百分点，CPI 变了一倍还多**——存储层次的影响完全盖过了指令本身。

除 Cache 缺失外，流水线冒险造成的阻塞、分支预测失败的开销，也都会计入实测的 CPI。

一句话分清两层：

**一条指令的 CPI 由指令类型和微体系结构决定；一个程序的 CPI 是运行时测出来的，跟访存行为、缺失率、冒险全部相关。**

## 四、CPU 执行时间：三个因子各由谁决定

把上面几个量拼起来，就是本节的核心公式：T=IC×CPI×Tc=IC×CPIf

IC 是程序的指令条数，Tc 是时钟周期，f 是主频。它还有一个等价写法：T=总时钟周期数f=总时钟周期数×Tc

CPU 的性能可以看成用户 CPU 时间的倒数，因此两台机器的性能之比就是它们用户 CPU 时间之比的**倒数**。

### 三个因子分属三个不同的层次

这是本节最有用的一张表。三个因子不是并列的三个数字，而是**分别由计算机系统的三个不同层次决定**的——这正是它们可以被独立优化、也会互相打架的原因：

| 因子 | 由哪一层决定 | 具体受什么影响 | 谁能改动它 |
| --- | --- | --- | --- |
| **IC 指令条数** | **ISA 与编译器** | 指令集的表达能力（一条指令能干多少活）、编译优化的质量 | 指令集设计者、编译器 |
| **CPI** | **处理器的实现**（微体系结构） | 数据通路结构、流水线深度与冒险处理、Cache 组织与命中率 | 硬件设计者 |
| **Tc 时钟周期** | **电路与器件工艺** | 关键路径上的门延迟、器件工艺水平 | 电路设计者、工艺 |

从上往下读，这是一条完整的推理链：

**程序要跑多久 = 一共要执行多少条指令（软件层说了算）× 平均每条要几个周期（处理器组织说了算）× 每个周期多长（电路工艺说了算）。**

三个因子分属三层，也就意味着优化手段可以从三个方向分别下手：提高时钟频率打的是 Tc，改进数据通路结构和 Cache 打的是 CPI，做编译优化或增强指令功能打的是 IC。

### 三个因子互相制约

但它们并不独立——**三个因素是相互制约的**。改一个通常会把另一个顶上去：

| 想优化的因子 | 常见手段 | 被顶上去的因子 |
| --- | --- | --- |
| 降低 Tc（提主频） | 把流水线切得更细 | **CPI 上升**：段数增多后，冒险和预测失败的代价按段数放大 |
| 降低 IC | 用功能更强的复杂指令 | **CPI 与 Tc 双双上升**：单条指令要拆成更多步骤，关键路径也变长 |
| 降低 CPI | 只保留简单定长指令 | **IC 上升**：同样的活要用更多条指令来干 |

因此有一条结论：**对于解决同一个问题的不同程序，即使在同一台机器上，指令条数最少的那个也不一定执行得最快**——两个代码序列的指令构成不同，加权后的 CPI 就不同，指令条数少的那个可能全是高 CPI 的指令。

同样地，提高时钟频率往往会对 CPU 结构带来影响、使其他指标变差，所以**主频提高几倍，速度不会同倍数提高**。

[[03_计算机组成原理_CO/instruction/cisc-vs-risc.md|CISC 与 RISC 的分歧]]正好落在这张表上：CISC 走的是压 IC 的路线，代价是 CPI 高、Tc 难压；RISC 走的是压 CPI 和 Tc 的路线，代价是 IC 大。两条路线争的不是谁的公式对，而是三个因子的乘积在哪种组合下更小。

## 五、Amdahl 定律：局部加速的整体收益

只把系统的一部分变快，整体能快多少？

**阿姆达尔定律**（Amdahl's law）是计算机系统设计中重要的定量原则之一，1967 年由 IBM 360 系列机的主要设计者阿姆达尔提出。它的基本思想是：

对系统中某个硬件部分、或软件中某个部分进行更新所带来的**系统性能改进程度**，取决于**该部分被使用的频率、或其执行时间占总执行时间的比例**。

### 两种表达形式

教材给出的两种形式，一种算时间，一种算倍数：改进后的执行时间=改进部分执行时间改进部分的改进倍数+未改进部分执行时间整体改进倍数=1改进部分执行时间比例改进部分的改进倍数+未改进部分执行时间比例

记可加速部分占原执行时间的比例为 p、该部分的加速倍数为 n，则未改进部分比例为 1−p，整体加速比为S=1(1−p)+pn

方法只有一句话：**把总时间拆成"能加速的"和"不能加速的"两段，只除能加速的那一段。**

### 三个边界值

| 条件 | 加速比 | 含义 |
| --- | --- | --- |
| 1−p=0（全部可加速） | S=n | 上界，加速比等于局部加速倍数 |
| p=0（无一可加速） | S=1 | 下界，改了等于没改 |
| n→∞（局部无限加速） | S→11−p | **加速比的上限** |

第三行是这条定律真正的分量所在：**不可加速的那部分是整体性能的天花板**。哪怕把占总时间 90% 的高频部件加快 10 倍，整体也只能快到 5.26 倍；把它加快到无穷倍，整体也只能到 10 倍。

**为什么 1/(1−p) 一定是上限**，从分母就能看出来：分母 (1−p)+p/n 由两项组成，加大 n 只能把 p/n 这一项往 0 压，**压不动 (1−p)——它是与 n 无关的常数项**。所以分母不管怎么优化都降不到 1−p 以下，S 就只能从下方无限逼近 1/(1−p)，取不到、更超不过。

想改进系统整体性能，不能只盯着加速某个部件——**整体性能仍然受慢速部件的制约**。

### 上限反过来用：先判有没有解

上限这条不只是用来"感慨一下"。给定的条件如果是**倒过来的**——不给 n、而是给一个整体加速目标 S目标，问局部要加速多少倍——那么第一步不是列方程，而是拿 S目标 和 1/(1−p) 比大小：

- S目标≥11−p：**无解**。局部加速倍数取到无穷大都达不到，方程解出来会得到 n→∞ 这种结果；
- S目标<11−p：有解，回代 S=1(1−p)+p/n 反解 n 即可。

举个数：可加速部分占 p=75%，上限就是 1/(1−0.75)=4 倍。那么"要求整体提速到 4 倍"这个目标从一开始就不成立，不必去算；而"提速到 3 倍"是可行的，反解10.25+0.75/n=3⟹0.25+0.75n=13⟹n=0.751/3−0.25=9

局部要快 9 倍，整体才快 3 倍——**局部投入与整体收益之间是严重不对称的，S 越靠近上限，所需的 n 涨得越猛。**

### 这条定律的适用范围

它适用于对特定任务的**一部分**进行优化的所有情况，可以是硬件优化，也可以是软件优化。两个方向的典型用法：

- **判断优化值不值得做**。系统中异常处理程序的执行时间只占整个程序运行时间非常小的一部分，即使把它优化得再好，对整个系统带来的性能提升也几乎为零。**优化的收益上界由被优化部分的时间占比决定**，与优化本身做得多漂亮无关。
- **判断并行化的天花板**。把 p 理解成"程序中可并行部分的占比"、n 理解成"核数"，同一个公式就给出了多核的加速比上限——串行段的占比决定了核数堆到多少都突破不了的那条线，见 [[03_计算机组成原理_CO/cpu/multiprocessor.md|多处理器基本概念]]。

## 六、MIPS 与 FLOPS

### MIPS

**MIPS**（million instructions per second）表示平均每秒执行多少**百万条指令**：MIPS=ICT×106=fCPI×106

它反映的是机器执行**定点指令**的速度。但用 MIPS 比较不同机器有时并不客观，原因有两条，都是硬伤：

- **不同机器的指令集不同，指令的功能强度不等**。机器 M1 上一条指令能干的事，在 M2 上可能要好几条指令才能完成。同样的指令条数完成的功能可能完全不同——一台机器 MIPS 高，可能只是因为它的指令做的事少。
- **不同机器的 CPI 和时钟周期也不同**，同一条指令在不同机器上所用的时间也不同。

还有两个派生说法：**峰值 MIPS** 是特意选一组能使平均 CPI 最小的指令组合算出来的，实际性能通常比它差；**相对 MIPS** 是相对于某个公认参考机型的倍数值。

### FLOPS 系列

与 MIPS 相对应、用来表示**浮点操作速度**的指标是 **MFLOPS**（million floating-point operations per second），每秒执行多少百万次浮点运算。

关键差别只有一处：**FLOPS 基于所完成的操作次数，而不是指令数**。一条浮点指令可能完成不止一次浮点运算，反过来也有大量指令根本不做浮点运算。

| 指标 | 数量级 | 中文 |
| --- | --- | --- |
| MFLOPS | 106 | 百万次浮点运算/秒 |
| GFLOPS | 109 | 十亿次 |
| TFLOPS | 1012 | 万亿次 |
| PFLOPS | 1015 | 千万亿次 |
| EFLOPS | 1018 | 百亿亿次 |
| ZFLOPS | 1021 | 十万亿亿次 |

相邻两级之间差 103，顺序按 M、G、T、P、E、Z 排。

## 七、K/M/G 的两种含义

同一个字母在不同语境下取值不同，这不是笔误而是两套约定：

| 场景 | K | M | G |
| --- | --- | --- | --- |
| **存储容量、地址空间** | 210=1024 | 220 | 230 |
| **速率、频率、运算次数** | 103=1000 | 106 | 109 |

分界的依据是**这个量是不是由二进制位数决定的**：存储容量由地址位数决定（n 位地址对应 2n 个单元），所以走 2 的幂；时间和次数与二进制无关，所以走 10 的幂。

因此 1 KB=1024 B，而 1 GHz=109 Hz、1 PFLOPS=1015 次/秒。

## 八、基准程序

**基准程序**（benchmarks）是专门用于性能评测的一组程序，能较好地反映机器运行实际负载时的性能——在不同机器上运行相同的基准程序，比较运行时间即可评测性能。它是一个**测试程序集**，由一组程序组成，而不是单个程序。

用一组程序而不是一个程序，是为了避免单一负载的偏向。但这也带来一个新问题：**同一组程序在两台机器上可能给出方向相反的结论**——程序 P1 在 M2 上更快，程序 P2 却在 M1 上更快。这时的做法是取所有程序执行时间的**算术平均值或几何平均值**来综合评价；如果进一步考虑每个程序的使用频度而采用**加权平均**，结果会更准确。

基准程序的另一个局限更根本：硬件或编译器可能针对基准程序中的**关键代码**做特殊优化，使评测结果不能代表处理一般负载的能力。

**例 1（三个因子怎么合成执行时间）**

某机器主频 1.6 GHz，指令分三类，CPI 分别为：访存类 5、运算类 2、转移类 3。程序 Q 共 5×107 条指令，三类指令的比例依次为 25%、60%、15%。求 Q 的综合 CPI、总时钟周期数、CPU 执行时间与该机器运行 Q 时的 MIPS。

**解**　先加权求综合 CPI：CPI=0.25×5+0.60×2+0.15×3=1.25+1.20+0.45=2.9

再求总时钟周期数：总时钟周期数=5×107×2.9=1.45×108

除以主频得执行时间：T=1.45×1081.6×109=9.0625×10−2 s=90.625 ms

MIPS 直接用主频与 CPI 求：MIPS=1.6×1092.9×106≈551.7

三个量凑齐后，剩下的全是同一个公式的变形——这就是这个公式的用法。

**例 2（局部加速的收益与上限）**

某程序在某机器上执行需 200 s，其中浮点部件的工作时间占 70%。若把浮点部件加速到原来的 4 倍、其余部分不变，整体加速比是多少？若把浮点部件无限加速，整体加速比最多是多少？

**解**　先拆段：不可加速部分占 1−p=0.3，一秒也不会变。T新=200×(0.3+0.74)=200×0.475=95 sS=20095=10.475≈2.11

浮点部件快了 4 倍，整体只快到 2.11 倍。令 n→∞ 得上限：Smax=11−p=10.3≈3.33

也就是说，无论浮点部件做到多快，这个程序都不可能快过 3.33 倍——剩下那 30% 的时间就是天花板。

## 易混淆知识点

**1. "速度提高到原来的 1.5 倍"和"时间减少 50%"是一回事吗？**

不是，两者作用在公式的不同侧：

| 表述 | 数学含义 | 时间变为原来的 |
| --- | --- | --- |
| 速度**提高到原来的 1.5 倍** / 性能是原来的 1.5 倍 | 加速倍数 n=1.5 | 1/1.5≈0.667 |
| 速度**提高了 50%** | 新速度 = 旧速度 ×1.5，即 n=1.5 | ≈0.667 |
| 时间**减少了 50%** | 直接作用在时间上 | 0.5 |

判据：**"速度""性能"这类词描述的是时间的倒数，要取倒数才落到时间上；"时间"直接乘。**

**2. 响应时间就是 CPU 时间吗？**

不是。响应时间还包含等待 I/O 完成的时间、CPU 被其他用户程序占用的时间，以及执行操作系统程序的时间。公式 T=IC×CPI/f 算出来的是**用户 CPU 时间**，已经是纯 CPU 口径，不能再往里加别的。

对应地，**系统性能**指响应时间，**CPU 性能**指用户 CPU 时间，两者不等价。

**3. 主频高的机器一定快吗？**

不一定。T=IC×CPI×Tc，主频只是三个因子之一，另外两个因子可能把优势吃掉。

更进一步：提高主频这个动作本身往往会使其他指标变差（例如把流水线切细导致 CPI 上升），所以**即使别的条件相同，主频提高 k 倍，速度也达不到 k 倍**。

**4. 指令条数少的程序一定跑得快吗？**

不一定，即使是在**同一台机器**上。两个代码序列的指令构成不同，加权后的 CPI 就不同：条数少的那个可能全是高 CPI 的访存和乘除指令，总时钟周期数反而更多。

比较执行时间要看**总时钟周期数**，也就是 IC×CPI 这个乘积，不能只看其中一个因子。

**5. 程序的 CPI 是常数吗？**

不是。指令集只定死了"每条指令理想情况下要几个周期"，实测的 CPI 还要加上 Cache 缺失、流水线阻塞、分支预测失败带来的等待周期。同一个程序换一组输入数据、换一种 Cache 配置，测出来的 CPI 都会变。

**6. MIPS 大就一定好吗？**

不一定，且不适合跨指令集比较。MIPS 数的是**指令条数**，不是完成的工作量。指令功能弱的机器完成同一任务需要更多条指令，MIPS 反而可能更高。厂商标称的还常常是**峰值 MIPS**，实际性能比它差。

FLOPS 在这一点上略好，因为它数的是**浮点运算次数**而非指令条数，与指令集的强弱脱钩——但它只覆盖浮点负载。

## 本节小结

- 两个基本指标：**吞吐率**（单位时间完成的工作量）与**响应时间**（从提交到完成的总时间），互相独立
- **系统性能 = 响应时间；CPU 性能 = 用户 CPU 时间**，两者不等价；公式算的都是用户 CPU 时间
- 时钟周期由**相邻状态单元之间组合逻辑的最大延迟**（关键路径）决定；单周期取最耗时指令，多周期取单步关键路径，流水线取最长流水段
- **一个时钟脉冲不等于开始一条新指令**，只有单周期 CPU 才是一条指令一个周期
- 核心公式：T=IC×CPI×Tc=IC×CPIf
- **三个因子分属三层**：IC 由 **ISA 与编译器**决定，CPI 由**处理器实现**决定，Tc 由**电路与工艺**决定
- 三个因子**互相制约**：提主频常抬高 CPI，压指令条数常抬高 CPI 和 Tc；因此**指令条数最少的程序不一定最快**
- CPI 分两层：**一条指令的 CPI** 由指令类型和微架构定；**程序的 CPI** 是实测值，含 Cache 缺失、阻塞与预测失败的等待
- Amdahl 定律：S=1(1−p)+p/n；n→∞ 时上限为 11−p，**不可加速部分就是天花板**
- 上限成立的理由：分母中 (1−p) 是**与 n 无关的常数项**，加大 n 只压得动 p/n，压不动它
- 反过来给定整体加速目标时，**先拿它和 11−p 比大小**：不小于上限就无解，小于才回代反解 n
- 优化的收益上界由**被优化部分的时间占比**决定，与优化本身做得多好无关
- **MIPS 数指令条数**，不适合跨指令集比较；**FLOPS 数浮点运算次数**，不是指令条数
- **存储容量用 210，速率与频率用 103**
- 基准程序是**一组**程序；结论冲突时取算术/几何/加权平均；局限是可能被针对性优化
