## 知识框架

本节回答 6 个问题：

- IPv6 把地址从 32 位扩到 128 位，地址空间扩大的倍数是 **4 倍**还是别的数？
- IPv6 首部**比 IPv4 长了一倍**（40 vs 20 字节），为什么反而说它"简化了、转发更快"？
- 零压缩 `::` 为什么**只能用一次**？用两次到底会导致什么后果——是"不好看"还是"真的还原不出来"？
- IPv6 取消了子网掩码，那前缀长度还怎么表示？`/60` 这样的写法和 IPv4 的 `/24` 是一回事吗？
- IPv6 明明取消了首部检验和，出了错谁来兜底？
- 双栈和隧道两种过渡技术，各自付出的代价是什么？

## 一、为什么需要 IPv6

IPv4 使用 32 位地址，全部地址空间只有 232≈43 亿个。[[04_计算机网络_CN/network/ip-addressing.md|CIDR]] 把分配颗粒度从"3 档、档间差 256 倍"细化到"逐位可调"，[[04_计算机网络_CN/network/nat.md|NAT]] 让一个全球地址能撑起整个专用网 —— 这两项技术把 IPv4 的寿命拉长了很多年，但它们改变的都是**分配效率**，地址总数一个也没多。

事实上互联网号码分配机构 IANA 早在 2011 年就把最后的 /8 地址块分配完毕。**分配效率再高，也无法从 43 亿个地址里变出第 44 亿个。**

IPv6 是唯一从根上解决这件事的方案：它把地址长度加到 **128 位**，地址空间变成 2128≈3.4×1038。

## 二、IPv6 引进的主要变化

这一节直接对应大纲的"IPv6 的主要特点"，八条要能说全：

| # | 变化 | 具体是什么 |
| --- | --- | --- |
| 1 | **更大的地址空间** | 从 32 位增大到 128 位 |
| 2 | **扩展的地址层次结构** | 地址空间很大，可以划分出更多层次 |
| 3 | **灵活的首部格式** | 定义了许多可选的**扩展首部**，路由器对扩展首部不做处理（逐跳扩展首部除外），处理效率因此提高 |
| 4 | **改进的选项** | 选项放在有效载荷中而不是首部里，可以包含新选项；IPv4 的选项是固定不变的、放在首部的可变部分 |
| 5 | **允许协议继续扩充** | IPv4 的功能是固定不变的，IPv6 留了扩充余地 |
| 6 | **支持即插即用（自动配置）** | 因此 IPv6 **不需要使用 DHCP** |
| 7 | **支持资源的预分配** | 支持实时视像等要求保证带宽和时延的应用（靠流标号字段） |
| 8 | **首部改为 8 字节对齐** | IPv4 首部是 4 字节对齐 |

### 地址空间扩大了多少倍

这一处最容易答错。地址长度从 32 位变成 128 位，是长度的 4 倍；但**地址数量**是2128232=296

也就是**扩大了 296 倍**，不是 4 倍。2128≈3.4×1038，这个量级大到什么程度：如果整个地球表面（含陆地和水面）都铺满计算机，IPv6 允许每平方米拥有 7×1023 个地址；如果以每微秒分配 100 万个地址的速度分配，需要 1019 年才能分完。

### 一个容易忽略的推论：IPv6 不需要 DHCP

第 6 条说"支持即插即用（自动配置），因此不需要使用 DHCP"。这是因为 IPv6 节点**启用协议时就能自动生成本地链路地址**（见后面的地址分类），无须任何服务器参与。

注意区分：**"不需要"不等于"不能用"**。实际网络中仍然有 DHCPv6，用于下发 DNS 服务器地址等无法自动生成的信息。教材口径是"IPv6 支持即插即用、不需要 DHCP"。

### 术语上的一点变化

IPv6 仍然支持无连接传送，但把协议数据单元 PDU 称为**分组**（packet）而不是 IPv4 的**数据报**（datagram）。多数教材（包括谢希仁）为方便起见仍沿用"数据报"，把分组和数据报当同义词。

## 三、IPv6 首部格式

IPv6 数据报由两大部分组成：**基本首部**（固定 40 字节）+ **有效载荷**（不超过 65535 字节）。有效载荷里允许有零个或多个**扩展首部**，再后面才是数据部分。

**注意：扩展首部不属于基本首部，它们算在有效载荷里。** 这一点在算长度时是关键。

### 八个字段

| 字段 | 位数 | 说明 |
| --- | --- | --- |
| 版本（Version） | 4 | 固定为 6 |
| 通信量类（Traffic Class） | 8 | 区分不同数据报的类别或优先级，作用类似 IPv4 的区分服务 |
| 流标签（Flow Label） | 20 | 标识一条"流"，流经路径上的路由器都保证指明的服务质量。传统电子邮件、非实时数据用不上，置 0 即可 |
| 有效载荷长度（Payload Length） | 16 | **除基本首部以外**的字节数（**所有扩展首部都算在有效载荷之内**），最大 65535 |
| 下一个首部（Next Header） | 8 | 相当于 IPv4 的协议字段或选项 |
| 跳数限制（Hop Limit） | 8 | 等同于 IPv4 的 TTL，最大 255，每跳减 1，减到 0 丢弃 |
| 源地址 | 128 |  |
| 目的地址 | 128 |  |

**数一数：一共只有 8 个字段。** IPv4 的固定首部有 12 个字段。**首部长度增大了一倍，字段数反而减少了三分之一**——这就是"简化"的确切含义。

**"下一个首部"字段的两种含义**要分清：

- 数据报**没有**扩展首部时：作用和 IPv4 的协议字段完全一样，值指出基本首部后面的数据该交给哪个高层协议（6 = TCP，17 = UDP）
- 数据报**有**扩展首部时：值标识后面**第一个扩展首部**的类型

### 相对 IPv4 砍掉了什么，为什么

| 砍掉的字段 | 理由 |
| --- | --- |
| 首部长度 | IPv6 首部**固定 40 字节**，长度无须再表示 |
| 服务类型 | 其功能由**通信量类 + 流标号**两个字段实现 |
| 总长度 | 改用**有效载荷长度**（不含基本首部），首部长度既然固定，就没必要再报总长 |
| 标识、标志、片偏移 | 分片功能挪进**分片扩展首部** |
| 协议 | 改用**下一个首部**字段 |
| 检验和 | **加快路由器处理速度**（见下） |
| 选项 | 改用**扩展首部**实现 |

改名的一处：TTL → **跳数限制**（作用完全相同，只是名称与作用更一致——见 [[04_计算机网络_CN/network/ip-datagram.md|IPv4 数据报格式]] 里 TTL 那段"从秒改跳"的历史，IPv6 直接把名字也改对了）。

### 取消检验和之后谁来兜底

这是最值得推一层的：IPv6 敢取消首部检验和，是因为**上下两层已经把差错检测做完了**：

- **数据链路层**对检测出有差错的帧直接丢弃（如以太网的 CRC）
- **运输层**：使用 UDP 时，检测出有差错的用户数据报就丢弃；使用 TCP 时，检测出有差错的报文段就**重传**，直到正确送达

既然下层丢、上层重传，网络层再算一遍就是纯粹的重复劳动。而这份重复劳动的代价在 IPv4 里特别贵——因为 TTL 每跳都变，检验和**每跳都得重算**（见 [[04_计算机网络_CN/network/ip-datagram.md|IPv4 数据报格式]]）。**"每跳付出的成本 × 完全重复的收益"，取消是必然的。**

### 首部长了一倍，为什么反而更快

三条理由，缺一不可：

- **长度固定。** IPv4 路由器每收到一个数据报都要先读首部长度字段、判断有没有选项；IPv6 首部永远是 40 字节，直接偏移取字段即可。
- **不必逐一检查选项。** IPv4 数据报若使用了选项，转发路径上**每一个路由器都必须检查首部中的所有选项**，看是否与本路由器有关，这要花掉相当的时间。IPv6 把选项功能挪到扩展首部，基本首部的"下一个首部"字段一看就知道有没有需要本路由器处理的东西，**路由器对扩展首部不做处理**（逐跳扩展首部除外）。
- **不用重算检验和。** 每跳省掉一次 20 字节的反码求和。

**所以"简化"指的是每跳的处理复杂度，不是字节数。** 把这两件事分开，就不会觉得"更长却更快"矛盾。

### 扩展首部

IPv6 用**扩展首部**实现可选功能。所有扩展首部的第一个字段都是 8 位的"下一个首部"，靠它串成一条链：

```
IPv6 基本首部 → 扩展首部1 → 扩展首部2 → TCP/UDP首部 → 数据
 (Next=扩展1)    (Next=扩展2)  (Next=TCP)
```

RFC 8200 定义了六种扩展首部，使用多个时应按此顺序出现（**高层首部总是放在最后**）：

- 逐跳选项
- 路由选择
- **分片**
- 鉴别
- 封装安全有效载荷
- 目的站选项

## 四、IPv6 地址表示

### 冒号十六进制记法

128 位地址按 16 位一组分成 8 组，每组用 4 位十六进制数表示，组间用冒号分隔：

```
2001:0db8:85a3:0000:0000:8a2e:0370:7334
```

对比一下，如果沿用 IPv4 的点分十进制，同一个地址要写成 16 段：

```
104.230.140.100.255.255.255.255.0.0.17.128.150.10.255.255
```

—— 这正是换记法的原因。

### 两条压缩规则

**规则一：省略每组的前导零。** `0db8` → `db8`，`0000` → `0`。 ⚠️ **只能省前导零，不能省组内其他位置的 0**。`CD30` 不能写成 `CD3`——那表示的是 `0CD3`，是完全不同的值。

**规则二：零压缩。** 一连串**连续的全零组**可以用一对冒号 `::` 取代：

```
FF05:0:0:0:0:0:0:B3     →     FF05::B3
```

### 零压缩为什么只能用一次

答案不是"规定如此"，而是**用两次就真的还原不出来**。

`::` 本身**不携带"我代表了几组零"这个信息**，还原时靠的是"总共必须凑够 8 组，已经写出来的有 k 组，那么 `::` 就代表 8−k 组零"这个减法。这个减法只有在 `::` 唯一时才有唯一解。

举个反例：`2001::25de::cade`。已写出 3 组（2001、25de、cade），需要补 5 组零，但**这 5 组该怎么分配到两个 `::` 上**？可以是 1+4、2+3、3+2、4+1 —— **四种不同的地址都符合这个写法**。既然还原不唯一，这个写法就是非法的。

所以规定"在任一地址中只能使用一次零压缩"，本质是**为了保证零压缩有一个不含糊的解释**。

### 例题 1：压缩与还原

**题目**（自造数据）： (1) 把 `2001:0DA8:0000:0000:0207:0000:0000:1234` 尽量压缩。 (2) 把 `FE80::2AA:FF:FE9A:4CA2` 还原成完整的 8 组形式。

**(1) 压缩**

**第 1 步：先做规则一，去掉每组的前导零。**

*为什么先做这个*：两条规则互不干扰，先做简单的，剩下的形状更容易看清。

```
2001 : da8 : 0 : 0 : 207 : 0 : 0 : 1234
```

**第 2 步：找出连续全零组的游程。**

*为什么这么做*：零压缩只能作用于**连续**的全零组，先把游程标出来才能选。

这里有**两处**游程，各含 2 组：第 3~4 组、第 6~7 组。

**第 3 步：只能选一处压缩。**

*为什么这么做*：上一小节推过了——压两处就还原不出来。两处长度相同时压最左边那处。2001:da8::207:0:0:1234

**第 4 步：验算能否唯一还原。**

*为什么这么做*：这是判断一个 IPv6 缩写是否合法的通用办法。

显式写出的组：`2001`、`da8`、`207`、`0`、`0`、`1234`，共 6 组 → `::` 必须代表 8−6=2 组零 → 唯一还原为 `2001:0da8:0000:0000:0207:0000:0000:1234` ✓ 与原地址一致。

**(2) 还原**

**第 1 步：数出显式写出了几组。**

`FE80`、`2AA`、`FF`、`FE9A`、`4CA2` —— **5 组**。

**第 2 步：用减法定出 `::` 代表几组零。**

8−5=3 组。

**第 3 步：补零并补齐每组的前导零。**FE80:0000:0000:0000:02AA:00FF:FE9A:4CA2

*验算*：8 组 × 16 位 = 128 位 ✓。

### 合法性判定：哪些写法是错的

用上面那套"数组数 + 减法"就能判所有情况。以 60 位前缀 `12AB00000000CD3`（十六进制 15 个字符）为例，它的合法写法有：

```
12AB:0000:0000:CD30:0000:0000:0000:0000/60
12AB::CD30:0:0:0:0/60
12AB:0:0:CD30::/60
```

而下面这些是**非法或表示了别的地址**：

| 写法 | 问题 |
| --- | --- |
| `12AB:0:0:CD3/60` | **非法**：不能把 16 位组 `CD30` 末尾的 0 省掉（只能省前导零）；而且只有 4 组，不足 8 组又没有 `::` |
| `12AB::CD30/60` | **合法但不是这个地址**：它表示 `12AB:0:0:0:0:0:0:CD30` |
| `12AB::CD3/60` | **合法但不是这个地址**：它表示 `12AB:0:0:0:0:0:0:0CD3` |
| `2001::25de::cade` | **非法**：用了两次 `::`，还原不唯一 |
| `2001:0:0:1::1` | **合法**。`::` 只用了一次，显式 5 组，`::` 代表 3 组零，唯一还原为 `2001:0000:0000:0001:0000:0000:0000:0001`。地址里有两段零串而只压了其中一段，这完全允许 |

最后一行值得单独强调：**"原始地址中有两段连续零"并不会让缩写非法**——就零压缩这条规则而言，非法的判据只有一个，就是 `::` 出现了不止一次；至于"省了组内末尾的零"（如 `CD3`）那是**规则一**的违例，两条规则各判各的。上面例题 1 的答案 `2001:da8::207:0:0:1234` 正是"有两段连续零、只压了一段"这种情形。

### 与点分十进制混用

冒号十六进制记法还可以带一个点分十进制后缀，这在 IPv4 向 IPv6 过渡阶段很有用：

```
0:0:0:0:0:0:128.10.2.1     →  零压缩后  →  ::128.10.2.1
```

⚠️ 注意：**冒号分隔的每个值是 2 字节（16 位），而点分十进制每部分是 1 字节（8 位）**，两种记法的单位不同，别混着数。

### 前缀表示

CIDR 的斜线记法仍然可用，含义与 IPv4 相似：`/n` 表示前 n 位是网络前缀。

**但 IPv6 取消了子网掩码。** 前缀长度只能用 `/n` 表达，不再有"255.255.255.0"这种等价写法——128 位的掩码写出来太长，而且既然 CIDR 记法已经足够，掩码就是冗余的。

### 例题 2：求子网前缀

**题目**（自造数据）：某接口地址为 `2001:0db8:00a1:2c30:0250:56ff:fe8a:1b7c/58`。求它所在的子网前缀。

**第 1 步：算出 58 位落在第几组。**

*为什么这么做*：每组 16 位，前缀在组边界上时直接截断即可；不在组边界上才需要动二进制。

58=3×16+10 → 前 3 组（`2001`、`0db8`、`00a1`）**整组保留**；第 4 组只保留**高 10 位**，其余 6 位置 0；第 5~8 组**整组置 0**。

**第 2 步：处理第 4 组。**

*为什么这么做*：这是唯一需要展开二进制的一组。0x2c30=0010 1100 00⏟保留的高 10 位 11 0000⏟置 0 的低 6 位⟶0010 1100 0000 0000=0x2c00

**第 3 步：拼出结果并压缩。**2001:0db8:00a1:2c00:0000:0000:0000:0000/58⟶2001:db8:a1:2c00::/58

**第 4 步：验算。**

*为什么这么做*：子网前缀必须满足"低 128−58=70 位全为 0"。

第 4 组低 6 位为 0，第 5~8 组共 64 位全 0，合计 6+64=70 位 ✓。

本例的关键在第 2 步。若前缀长度恰好是 16 的倍数（如 /48、/64），这一步会"隐身"，直接按组截断就对；一旦不是 16 的倍数，就必须把那一组展开成二进制。**和 IPv4 里"只有跨字节的那个字节要动二进制"是同一套思路。**

## 五、IPv6 地址类型

IPv6 数据报的目的地址可以是以下三种基本类型之一：

| 类型 | 说明 |
| --- | --- |
| **单播（Unicast）** | 传统的点对点通信，标识一个接口 |
| **多播（Multicast）** | 一点对多点，数据报发送到一组计算机中的**每一个** |
| **任播（Anycast）** | IPv6 新增。终点是一组计算机，但数据报**只交付其中的一个**，通常是按路由算法得出的距离最近的一个 |

**IPv6 没有广播。** 广播被当作多播的一个特例来处理——原来 IPv4 靠广播完成的事（如 ARP 那样的"问一嗓子"），IPv6 全部改用多播。

**地址是给接口的，不是给节点的。** IPv6 把实现 IPv6 的主机和路由器统称为**节点**；一个节点可能有多个接口，IPv6 给节点的**每一个接口**指派一个地址。所以一个多接口节点可以有多个单播地址，其中任何一个都能当作到达该节点的目的地址。

### 常用地址分类

| 地址类型 | 地址块前缀 | CIDR 记法 | 占 IPv6 地址总数 |
| --- | --- | --- | --- |
| 未指明地址 | 00…0（128 位） | `::/128` | 仅此一个 |
| 环回地址 | 00…1（128 位） | `::1/128` | 仅此一个 |
| 多播地址 | 11111111 | `FF00::/8` | **1/256** |
| 本地站点单播地址 | 1111111011 | `FEC0::/10` | 1/1024 |
| 本地链路单播地址 | 1111111010 | `FE80::/10` | 1/1024 |
| 全球单播地址 | — | — | 用得最多的一类 |

四条要点：

- **未指明地址 `::`**：全 0，**不能用作目的地址**，只能被"还没有配置到标准 IP 地址的主机"当作源地址使用。类比 IPv4 的 `0.0.0.0`。
- **环回地址 `::1`**：作用和 IPv4 的 `127.0.0.1` 一样。
- **本地站点单播地址 `FEC0::/10`**：给"使用 TCP/IP 但没有连到互联网"的内部网络用，能内部通信但不能和互联网上的主机通信。**用途和 IPv4 的专用地址（见 [[04_计算机网络_CN/network/nat.md|NAT]]）是一样的。**
- **本地链路单播地址 `FE80::/10`**：**节点启用 IPv6 时就自动生成**（此时它甚至还没连到任何网络），只在单一链路上使用、不会被转发出去。这正是前面"IPv6 支持即插即用、不需要 DHCP"的实现基础。

### 全球单播地址的划分

RFC 4291 的划分方法非常灵活，可以是下面任何一种：

```
① [                 节点地址 (128 位)                    ]

② [   子网前缀 (n 位)   |      接口标识符 (128-n 位)      ]

③ [ 全球路由前缀 (n 位) | 子网标识符 (m 位) | 接口标识符 (128-n-m 位) ]
```

其中**接口标识符**相当于 IPv4 的主机号。第 ③ 种就是三级划分。

## 六、从 IPv4 向 IPv6 过渡

"规定一个日期，从这一天起所有路由器一律改用 IPv6"显然不可行——互联网规模太大。过渡只能**逐步演进**，且必须**向后兼容**：IPv6 系统必须能够接收和转发 IPv4 分组，并能为 IPv4 分组选择路由。

### 双协议栈（Dual Stack）

一部分主机或路由器**同时装有 IPv4 和 IPv6 两套协议栈**，记为 IPv6/IPv4，表明它同时具有 IPv6 地址和 IPv4 地址。

```
        应用层
        运输层
    ┌─────┬─────┐
    │IPv4 │IPv6 │      ← 两套网络层协议并存
    └─────┴─────┘
      链路层及以下
```

**双栈主机怎么知道对方该用哪种地址？靠 DNS 查询。** DNS 返回 IPv4 地址就用 IPv4，返回 IPv6 地址就用 IPv6。

**代价**：每个节点都要安装并维护两套协议，开销太大。所以过渡时期更常用下面的隧道技术。

### 隧道（Tunneling）

要点是：**IPv6 数据报要进入 IPv4 网络时，把它整个封装成 IPv4 数据报的数据部分**；离开 IPv4 网络时再取出来，交给 IPv6 协议栈。

三条关键：

- **隧道两端必须是双栈路由器**（入口要能封装、出口要能解封装）
- **在隧道中传送时，IPv4 数据报的源地址是隧道入口、目的地址是隧道出口**，与原 IPv6 数据报的源/目的地址无关
- 原来的 IPv6 数据报在穿越过程中**什么都没变**，就像在一条隧道里通过

这个"整个封装进另一个数据报"的手法在网络层出现过不止一次：[[04_计算机网络_CN/network/nat.md|VPN]] 的加密隧道、[[04_计算机网络_CN/network/mobile-ip.md|移动 IP]] 里归属代理转发到转交地址，用的都是同一套 IP-in-IP 思路。**认出这个共同结构，三处就变成一处。**

### 翻译（Translation）

当通信双方一个只支持 IPv4、另一个只支持 IPv6 时，需要在两者之间做协议转换，思路类似 [[04_计算机网络_CN/network/nat.md|NAT]]，代表方案是 NAT64/DNS64。

谢希仁教材在过渡策略里只展开了**双协议栈**与**隧道技术**两种，翻译作为了解即可。

## 易混淆知识点

**1. 地址空间扩大的是 296 倍，不是 4 倍**

4 倍说的是地址**长度**（位数），数量是 2128/232=296。

**2. IPv6 首部更长但更快**

40 字节 vs 20~60 字节，但字段数从 12 降到 8，且长度固定、不必逐个检查选项、不必重算检验和。"简化"指的是**每跳的处理复杂度**。

**3. 有效载荷长度不含基本首部，但含所有扩展首部**

IPv6 数据报总长=40+有效载荷长度，而扩展首部算在有效载荷里。

**4. `::` 只能出现一次，理由是还原不唯一**

`::` 不携带"代表几组零"的信息，靠"8 减去已写出的组数"这个减法还原，两个 `::` 就有多解。**但"原地址里有两段连续零"完全不影响缩写合法性**——只压其中一段是允许的。

**5. 只能省前导零，不能省组内末尾的零**

`CD30` 写成 `CD3` 表示的是 `0CD3`，完全是另一个值。

**6. 取消了首部检验和，也取消了子网掩码**

前者因为链路层丢弃差错帧、运输层重传差错报文段，网络层再算是重复；后者因为 CIDR 的 `/n` 记法已经够用，128 位掩码写出来太长。

**7. IPv6 不允许路由器分片**

数据报太大时路由器不分片，而是返回 ICMPv6"分组太大"报文，让源主机减小长度。**分片只在源主机进行**，且靠分片扩展首部实现（见 [[04_计算机网络_CN/network/ip-fragment.md|IP 分片与重装]]）。

**8. IPv6 没有广播，用多播替代**

三种地址类型是单播、多播、**任播**。任播是 IPv6 新增的——"交付给一组接口中最近的那一个"。

**9. 地址指派给接口，不是节点**

一个多接口节点可以有多个单播地址，任何一个都能到达它。

**10. 不需要 DHCP ≠ 不能用 DHCPv6**

"支持即插即用、不需要 DHCP"是 IPv6 的八条主要变化之一，实现基础是本地链路地址能自动生成。实际网络中 DHCPv6 仍用于下发 DNS 等信息。

## 本节小结

整节可以按"**扩容 → 简化 → 表示 → 过渡**"四段来还原：

- **扩容**：地址从 32 位到 128 位，数量扩大 296 倍（不是 4 倍）。八条主要变化里，除了地址空间，还要能说出扩展的层次结构、灵活的首部格式、改进的选项、允许继续扩充、支持即插即用（因此不需要 DHCP）、支持资源预分配、首部改为 8 字节对齐。
- **简化**：首部固定 40 字节、字段从 12 个减到 8 个。砍掉首部长度（固定了）、服务类型（并入通信量类与流标号）、总长度（改用有效载荷长度）、分片三字段（挪进扩展首部）、协议（改用下一个首部）、检验和（下层丢弃、上层重传，网络层重复）、选项（改用扩展首部）。**"更长却更快"的确切含义是每跳处理复杂度下降**：长度固定、不必逐个检查选项、不必重算检验和。
- **表示**：冒号十六进制 + 两条压缩规则。**只能省前导零**；**零压缩只能用一次，因为 `::` 不携带"代表几组零"的信息，靠 8 减已写组数这个减法还原，两个 `::` 就有多解**。判断任何缩写合法性的通用办法就是"数组数 + 减法 + 看还原是否唯一"。前缀仍用 `/n`，但**子网掩码被取消**。求子网前缀时，只有"前缀长度不是 16 的倍数"的那一组需要展开二进制。
- **地址类型**：单播 / 多播 / **任播**，**没有广播**。地址给接口不给节点。`::` 只能作源地址，`::1` 是环回，`FEC0::/10` 相当于 IPv4 专用地址，**`FE80::/10` 启用协议时自动生成**——这是即插即用的实现基础。
- **过渡**：双栈（每节点装两套协议栈，靠 DNS 返回的地址类型决定用哪套，代价是开销大）与隧道（把 IPv6 数据报整个封进 IPv4 数据报，两端必须是双栈路由器，隧道中的源/目的地址是隧道入口与出口）。**隧道这套 IP-in-IP 手法与 VPN、移动 IP 的做法完全同构。**
- **NAT 与 IPv6 的定位**：NAT 延缓地址耗尽，IPv6 才是根治。

## 教材出处

- 谢希仁《计算机网络》（第 7 版）：**IPv6 引进的主要变化**（本篇第一节那八条），见印刷版 **p150**（4.5.1 IPv6 的基本首部）——原文逐条列出"(1) 更大的地址空间……把地址从 IPv4 的 32 位增大到 4 倍，即增大到 128 位，使地址空间增大了 296 倍"；"(6) 支持即插即用（即自动配置）。因此 IPv6 不需要使用 DHCP"；"(8) IPv6 首部改为 8 字节对齐（即首部长度必须是 8 字节的整数倍）。原来的 IPv4 首部是 4 字节对齐"。同页还说明"IPv6 数据报由两大部分组成，即基本首部和后面的有效载荷……有效载荷允许有零个或多个扩展首部……但请注意，所有的扩展首部并不属于 IPv6 数据报的基本首部"，以及术语上"将协议数据单元 PDU 称为分组，而不是 IPv4 的数据报"。
- 同书 **p150–p151**：**相对 IPv4 砍掉了哪些字段**，逐条给出理由——"取消了首部长度字段，因为它的首部长度是固定的（40 字节）……取消了检验和字段，这样就加快了路由器处理数据报的速度。我们知道，在数据链路层对检测出有差错的帧就丢弃。在运输层，当使用 UDP 时，若检测出有差错的用户数据报就丢弃。当使用 TCP 时，对检测出有差错的报文段就重传，直到正确传送到目的进程为止。因此在网络层的差错检测可以精简掉"；并结论"由于把首部中不必要的功能取消了，使得 IPv6 首部的字段数减少到只有 8 个（虽然首部长度增大了一倍）"。同页给出各字段定义，其中有效载荷长度"指明 IPv6 数据报除基本首部以外的字节数（所有扩展首部都算在有效载荷之内）"。
- 同书 **p152**：扩展首部的六种类型与顺序（逐跳选项、路由选择、分片、鉴别、封装安全有效载荷、目的站选项），"当使用多个扩展首部时，应按以上的顺序出现。高层首部总是放在最后"；以及**为什么扩展首部让转发更快**——"IPv4 的数据报若在其首部中使用了选项，则在数据报转发路径中的每一个路由器，都必须检查首部中的所有选项，看是否与本路由器有关。这必然要花费相当的时间。IPv6 把原来 IPv4 首部中选项的功能都放在扩展首部中……这就使得路由器能够迅速判断待转发的 IPv6 数据报有无需要本路由器处理的选项"。同页给出三种地址类型（单播、多播、任播），并说明"IPv6 没有采用广播的术语，而是将广播看作多播的一个特例"，以及"IPv6 给节点的每一个接口（请注意，不是给某个节点）指派一个 IPv6 地址"。
- 同书 **p152–p153**：地址空间的量级——"如果整个地球表面（包括陆地和水面）都覆盖着计算机，那么 IPv6 允许每平方米拥有 7×1023 个 IP 地址。如果地址分配速率是每微秒分配 100 万个地址，则需要 1019 年的时间才能将所有可能的地址分配完毕"。
- 同书 **p153**：**零压缩只能用一次的理由**——"冒号十六进制记法可以允许零压缩，即一连串连续的零可以为一对冒号所取代……**为了保证零压缩有一个不含糊的解释，规定在任一地址中只能使用一次零压缩**"；点分十进制后缀"在这种记法中，冒号所分隔的每个值是两个字节（16 位）的值，但点分十进制每个部分的值是一个字节（8 位）的值"；以及 60 位前缀 `12AB00000000CD3` 的三种合法写法与三种非法/歧义写法（`12AB:0:0:CD3/60` "不能把 16 位地址 CD30 块中的最后的 0 省略"、`12AB::CD30/60` "这表示 12AB:0:0:0:0:0:0:CD30"、`12AB::CD3/60` "这表示 12AB:0:0:0:0:0:0:0CD3"）。同页末明确"**但是，IPv6 取消了子网掩码**"。
