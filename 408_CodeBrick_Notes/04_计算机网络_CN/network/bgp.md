## 一、为什么域间不能用 IGP

**BGP 的必要性**：RIP 和 OSPF 都只能在一个自治系统 AS 内部工作。若没有 BGP，那么分布在全世界数以万计的 AS **都将是一个个没有联系的孤岛**。正是有了 BGP 这种黏合剂，才使这么多 AS 孤岛连成一个完整的互联网。

不能沿用 IGP 的理由有三条，**每一条卡在不同的地方**：

### 理由一：规模——链路状态数据库和 Dijkstra 都撑不住

连接在互联网主干网上的路由器，必须对任何有效的 IP 地址都能在转发表中找到匹配的网络前缀。谢希仁给出的数量级是：主干网路由器**一个转发表的项目数甚至可达到 50 万个网络前缀**。

- 若用**链路状态**协议，每一台路由器都要维持一个极大的链路状态数据库；
- 对这样大的主干网用 **Dijkstra 算最短路径时花费的时间也太长**。

### 理由二：度量不可比——"代价 1000"在不同 AS 里意思不同

各 AS 自己运行选定的 IGP，并使用本 AS 指明的路径度量。于是当一条路径通过几个不同 AS 时，**要想对这样的路径计算出有意义的代价是不太可能的**：

对某 AS 来说，代价为 1000 可能表示一条比较长的路由。但对另一 AS，代价为 1000 却可能表示不可接受的坏路由。

所以域间**不能比大小**，**比较合理的做法是在自治系统之间交换"可达性"信息**（即"可到达"或"不可到达"）——"到达网络前缀 N 可经过自治系统 ASX"。

### 理由三：策略——最短的路不一定是允许走的路

AS 之间的路由选择**必须考虑有关策略**，这些策略包括政治、安全或经济方面的考虑：

- 某条路径使用代价很高、或很不安全；
- AS1 要给 AS2 发数据，本来经 AS3 最好，但 **AS3 不愿意让这些数据报通过自己的网络**，即使 AS1 愿意付费；
- 反过来 AS3 可能愿意让**某些付了服务费的**相邻 AS 的数据报通过。

这些策略由网络管理人员对每个路由器设置，**但这些策略并不是自治系统之间的路由选择协议本身**——协议只提供"能表达策略"的能力，具体策略是配置。

**三条理由合起来给出 BGP 的口径**：BGP 只能是力求选择出一条**能够到达目的网络前缀且比较好的路由（不能兜圈子）**，**而并非要计算出一条最佳路由**。

❗ **"BGP 找最短路径"是错的。** 这不是措辞讲究，是三条理由的直接推论：度量不可比（找不出最短），策略优先（就算找出来也不一定能走）。

## 二、BGP 路由：路径向量

BGP 采用**路径向量（path vector）**路由选择协议，与距离向量（RIP）和链路状态（OSPF）都有很大区别。

### 2.1 BGP 路由的格式

```
BGP 路由 = “前缀，BGP 属性” = “前缀, AS-PATH, NEXT-HOP”
```

| 字段 | 含义 |
| --- | --- |
| **前缀** | 通告的 BGP 路由**终点**（子网前缀） |
| **AS-PATH**（自治系统路径） | 这条路由**所经过的自治系统序列**。BGP 路由每经过一个 AS，就把它的自治系统号 ASN 加入 AS-PATH |
| **NEXT-HOP**（下一跳） | 通告的 BGP 路由**起点** |

**一个必须掰清的点**：AS-PATH **只指出通过哪些自治系统，不指出路由中途要通过哪些路由器**。这正是"域间只交换可达性"的具体形态——AS 内部长什么样，外面不需要知道，也不该知道（理由二、三）。

### 2.2 路径向量凭什么能防环

收到一条路由，**只要发现 AS-PATH 里有自己的 AS 号，就说明形成了环路，直接丢弃**。

这是**结构性**防环，和距离向量的补丁式防环完全不是一个级别：

|  | 距离向量的水平分割 | 路径向量 |
| --- | --- | --- |
| 携带的信息 | 只有一个距离数值 | **完整的 AS 序列** |
| 能挡住 | **只有两点环** | **任意长度的环** |
| 为什么 | 只知道"从谁学来的"，不知道更远处的来路 | 环必然使本 AS 号出现在路径里，一看便知 |
| 有没有上限 | 必须靠 16 这类约定截断 | **不需要上限** |

### 2.3 例题 1：环路检测与 AS-PATH 选路

**题目（自造数据）**：某边界路由器位于 **AS5**，就同一个目的前缀 X 收到三条 BGP 路由：

| 编号 | BGP 路由 |
| --- | --- |
| ① | 前缀 X，AS-PATH = `AS2 AS3 AS7`，NEXT-HOP = Ra |
| ② | 前缀 X，AS-PATH = `AS4 AS7`，NEXT-HOP = Rb |
| ③ | 前缀 X，AS-PATH = `AS2 AS5 AS6 AS7`，NEXT-HOP = Rc |

问：（a）哪些路由会被直接丢弃？（b）在剩下的路由中，若**只按 AS-PATH 长度**选，选哪一条？

**解**

**（a）环路检测**——逐条查 AS-PATH 里有没有本 AS 号 `AS5`：

| 编号 | AS-PATH | 含 AS5？ | 处理 |
| --- | --- | --- | --- |
| ① | `AS2 AS3 AS7` | 否 | 保留 |
| ② | `AS4 AS7` | 否 | 保留 |
| ③ | `AS2 AS5 AS6 AS7` ← 第二个就是 **AS5** | **是** | **直接丢弃** |

*这一步为什么放在最前面*：环路路由是**无效**路由，留着参与选路只会污染结果。**先滤环，再选优**——顺序反过来，可能选中一条根本走不通的路。

*③ 为什么是环*：这条路由声称"经过 AS2 → AS5 → AS6 → AS7 可以到 X"。可 AS5 就是我自己。如果我采纳它，我到 X 的路会先绕出去再绕回自己，**分组在 AS5 和外面之间来回打转**。

**（b）按 AS-PATH 长度选路**：

| 编号 | AS-PATH | 长度 |
| --- | --- | --- |
| ① | `AS2 AS3 AS7` | 3 |
| ② | `AS4 AS7` | **2** |

选 **②**，NEXT-HOP 为 Rb。

⚠️ **上面这一问最要紧的限定在这里**：它只是"若**只按 AS-PATH 长度**选"。**真实的 BGP 选路第一优先级是 LOCAL_PREF（本地优先级），不是 AS-PATH 长度。** 也就是说，如果管理员把 ① 的 LOCAL_PREF 设得更高（比如 AS3 是自家花钱买了带宽的合作方），BGP 会选 ①，尽管它更长。

**这正是"策略优先于长度"的具体样子**——AS-PATH 长度只是众多属性中的一条，而且不是第一条。

BGP 选路时主要考虑的属性（408 只要求了解 AS-PATH 最短这一条，其余仅供理解优先级顺序）：

| 顺序 | 属性 | 作用 |
| --- | --- | --- |
| 1 | **LOCAL_PREF**（本地优先级） | 在本 AS 内部传递，值**越大越优先**。这是管理员表达商业策略的主要手柄 |
| 2 | **AS_PATH**（AS 路径长度） | 经过的 AS 越少越优先 |
| 3 | **NEXT_HOP** | 到下一跳的 IGP 代价 |
| — | **MED**（多出口鉴别） | 用于影响**外部 AS** 选择进入本 AS 的入口 |

## 三、边界路由器与两次递归查找

### 3.1 边界路由器

一个 AS 中有两种不同功能的路由器：**边界路由器**（边界网关）和**内部路由器**。一个 AS **至少要有一个边界路由器**和相邻 AS 的边界路由器直接相连。正是有了边界路由器，AS 之间才能利用 BGP 交换可达性路由信息。

### 3.2 例题 2：从一条 BGP 路由到一行转发表

**题目**：AS2 内的路由器 Rx 收到了 BGP 路由「前缀 X，AS-PATH = `AS1`，NEXT-HOP = R1」，其中 R1 是 **AS1 内的**边界路由器。AS2 内与 R1 直接相连的本方边界路由器是 R2；AS2 内部跑 OSPF，Rx 到 R2 的最短路的第一跳是 R3。求 Rx 转发表中关于前缀 X 的那一行。

**解**

这需要**两次递归查找**。

**第一次：把 BGP 路由的起点换成本 AS 内认得的地址。**

原来的 BGP 路由是「R1→X」。问题在于：**起点 R1 并不在 AS2 中，AS2 中的路由器都不能识别 R1。** 于是把起点改为 R1 的对等端 R2：“R1→X”⟹“R2→R1→X”

*这一步为什么这么做*：R2 位于 AS2 内，因此 **AS2 里面的所有路由器都能把分组转发到 R2**，到了 R2 再经 R1，最后到达前缀 X。**换起点，就是把一个"外部世界的地址"翻译成"本 AS 内可路由的地址"。**

**第二次：用内部网关协议找到"到 R2 的下一跳"。**

Rx 查本 AS 的 IGP（这里是 OSPF）算出的最短路，得知从 Rx 到 R2 的最佳路由中，**下一跳是 R3**。

*这一步为什么这么做*：转发表里能写的是**下一跳**，不是"终点"。BGP 告诉你"去 R2 就对了"，但"怎么去 R2" 是 AS 内部的事，只有 IGP 知道。**BGP 管跨 AS 的方向，IGP 管本 AS 内的路。两者必须接力。**

**答**：Rx 转发表增加一行：

| 前缀匹配 | 下一跳 |
| --- | --- |
| X | R3 |

**推广**：AS2 内的每一台路由器都做同样的两步。R3 自己也会算出它到 R2 的下一跳并写进转发表。于是任何到达 Rx 的、目的为 X 的分组，都会沿Rx→R3→R2→R1→X

一路走下去。

**两次递归查找是 BGP 最容易被跳过、也最能体现"域间/域内接力"的一步**。记住这句话就够：**BGP 给的是"经过哪些 AS"，IGP 给的是"下一跳是谁"，转发表要的是后者，所以必须翻译两次。**

实际转发表中，"前缀匹配"用 CIDR 记法表示；由于路由器有两个以上接口，"下一跳"用**进入该路由器的接口的 IP 地址**表示。

## 四、eBGP 与 iBGP

|  | **eBGP**（外部 BGP） | **iBGP**（内部 BGP） |
| --- | --- | --- |
| 连接谁 | **不同 AS** 的两个对等端 | **同一 AS** 的两个对等端 |
| 是否要直连 | 通常直连 | **可以不直连**（只要 IGP 路由可达即可） |

❗ **eBGP 和 iBGP 不是两个不同的协议。** 它们遵循同样的协议 BGP，使用**同样的报文格式**、具有**同样的属性类型**。**唯一的不同点是发送 BGP 路由通告时的规则有所不同。**

### 转告规则——只有一条要背

| 从哪学来 | 能否告诉同 AS 内的 iBGP 对等端 | 能否告诉不同 AS 的 eBGP 对等端 |
| --- | --- | --- |
| 从 **eBGP** 对等端收到 | ✅ 可以 | ✅ 可以 |
| 从 **iBGP** 对等端收到 | ❌ **不能**转告给同一个 AS 内的**其他 iBGP 对等端** | ✅ 可以 |

**"从 iBGP 学来的不再转告给 iBGP"这一条为什么必须存在**：iBGP 对等端之间**不使用 AS-PATH 防环**——因为在同一个 AS 内部传递，AS 号根本不会变化，环路检测失效。所以只能靠这条"只转一跳"的规则，来防止路由在 AS 内部循环通告。代价是：**AS 内所有跑 BGP 的路由器必须两两建立 iBGP 会话（全连接网格）**，这也是大型 AS 需要路由反射器等机制的原因（超出 408 范围，了解即可）。

另外，边界路由器根据本 AS 管理员规定的策略，**可以拒绝某些路由**（收到后即删除掉），只在 iBGP 连接上转发符合规定策略的 BGP 路由。策略生效的位置就在这里。

## 五、四种报文与 TCP 封装

BGP 使用 **TCP 端口 179**；BGP 报文作为 TCP 报文的**数据部分**来传送，四种类型的 BGP 报文具有同样的首部。

| 报文 | 功能 |
| --- | --- |
| **OPEN** | 建立 BGP 连接，协商参数（AS 号、保持时间等） |
| **UPDATE** | 通告新路由或撤销失效路由，携带路径属性 |
| **KEEPALIVE** | 保持连接活跃，周期性发送（默认约 60 s 一次），也用于确认 OPEN |
| **NOTIFICATION** | 报告错误，随后关闭连接 |

**为什么 BGP 用 TCP，而 RIP 用 UDP、OSPF 直接用 IP？** 三个协议的选择各有各的道理，一起对比才记得住：

| 协议 | 封装 | 为什么 |
| --- | --- | --- |
| **RIP** | UDP 520 | 每 30 s 就重发一次**完整**路由表，丢了下一轮自然补上，**不需要可靠传输** |
| **OSPF** | 直接封装在 IP 中，协议号 89 | 洪泛要跨越多跳、要发给"所有路由器"而非某个端口；**可靠性由 OSPF 自己的 LSAck 与序列号实现**，不需要 TCP |
| **BGP** | TCP 179 | AS 之间的路由信息量大（可达 50 万前缀）、**只在变化时增量通告**，一条 UPDATE 丢了不会自动重来；对可靠性要求高，**用 TCP 就不必自己实现确认与重传** |

**抓住这条主线**：**周期全量重发 → 不需要可靠（RIP）；自己实现了可靠 → 不需要 TCP（OSPF）；增量通告且量大 → 必须可靠且不想自己造轮子（BGP）。** 三个选择都是"可靠性从哪来"的不同答案。

## 六、三类自治系统（策略的现实基础）

互联网中的 AS 数量极多、连接图相当复杂，但归纳起来可以分三大类。**这一节讲的其实是钱**：

| 类型 | 特征 | 付费关系 |
| --- | --- | --- |
| **末梢 AS**（stub AS） | 只把分组发给直连的 AS、或从直连 AS 接收分组，**不会把来自其他 AS 的分组再转发到另一个 AS** | **必须向所连接的 AS 付费**才能发送或接收分组 |
| **穿越 AS**（transit AS） | 拥有很好的高速通信干线的主干 AS，为别人转发分组 | 收费 |
| **对等 AS**（peering AS） | 两个 AS 直接互连、互相交换流量 | **免费**（互不收费） |

**多归属 AS（multihomed AS）**：末梢 AS 也可以同时连接到两个或两个以上的 AS。好处是**增加连接的可靠性**——若有一条连接出现故障，还有另一条可用。

❗ **多归属 AS 仍然是末梢 AS，不是穿越 AS。** 设 AS5 是多归属末梢 AS，同时连着 AS2 和 AS3。那么：

- AS5 **不能**把 AS3 发来的分组转发到 AS2；
- AS5 **也不能**把 AS2 发来的分组转发到 AS3；
- AS5 **甚至不能把 `AS5 - AS2 - AS4` 这样的 BGP 路由信息通告给 AS3**。

**注意第三条**：拒绝转发不是靠"收到了再丢弃"，而是靠**根本不通告这条路由**——不通告，别人就不会把流量往这边送。**策略是在路由通告层面执行的，不是在转发层面。** 这是本节最值得带走的一句。

## 七、三大路由协议总对照

| 对比项 | RIP | OSPF | BGP |
| --- | --- | --- | --- |
| 类别 | IGP | IGP | **EGP** |
| 算法 | 距离向量 | 链路状态 | **路径向量** |
| 交换什么 | 整张路由表（距离） | 本机链路状态 | **前缀 + AS-PATH + NEXT-HOP** |
| 封装 | UDP 520 | IP 协议号 89 | **TCP 179** |
| 作用范围 | 小型 AS 内 | 中大型 AS 内 | **AS 之间** |
| 规模上限 | 15 | 靠区域划分扩展 | 整个互联网 |
| 选路依据 | 跳数最少 | 代价最小 | **策略最优**（LOCAL_PREF 优先于 AS-PATH 长度） |
| 防环 | 上限 16 截断 + 水平分割（只挡两点环） | LSDB 一致性 | **AS-PATH 结构性防环**（任意长度） |
| 收敛 | 慢 | 快（< 100 ms 量级） | 慢，**但对稳定性的要求高于速度** |

## 易混淆知识点

**1. BGP 基于 TCP（179），不是 UDP**

三行一起记：**RIP → UDP 520；OSPF → IP 协议号 89；BGP → TCP 179**。而且要知道各自的理由（见第五节的对比表），比死记稳。

**2. BGP 不求"最短路径"，只求"可达且合策略、不兜圈子"**

度量不可比（跨 AS 的代价没有公共含义）+ 策略优先，两条合起来决定了这个口径。"BGP 找最短路"是错的。

**3. AS-PATH 长度不是第一优先级**

真实选路里 **LOCAL_PREF 排在 AS-PATH 之前**。408 只要求了解"AS-PATH 最短优先"，但要清楚它只是众多属性之一，而且不是最优先的那一条——否则就无法解释"策略最优"这四个字。

**4. eBGP 与 iBGP 不是两个协议**

报文格式、属性类型完全一样，**唯一区别是发送路由通告时的规则**。iBGP 的存在是为了把从 eBGP 学到的外部路由传遍本 AS 内部。

**5. 从 iBGP 学来的路由，不能再转告给同 AS 内其他 iBGP 对等端**

因为 AS 内部传递时 AS 号不变，AS-PATH 防环失效，只能靠"只转一跳"这条规则挡住内部循环。代价是 iBGP 需要全连接网格。

**6. AS-PATH 里是 AS 号，不是路由器**

它**不指出路由中途要通过哪些路由器**。所以拿到 BGP 路由后必须做两次递归查找，才能填出转发表里的"下一跳"。

**7. 多归属 AS 仍是末梢 AS**

连了两家不等于变成穿越 AS。它不转发过路流量，而且**不会向一家通告经由另一家的路由**——策略在通告层面执行。

**8. 路径向量防环不需要"最大值"这种上限**

它靠"看见自己就丢"，任意长度的环都挡得住；不像 RIP 必须用 16 去截断。

## 本节小结

**为什么必须有 BGP**：没有它，全世界数以万计的 AS 就是一个个孤岛。域间不能沿用 IGP 有三条理由——**规模**（主干网转发表可达 50 万前缀，LSDB 太大、Dijkstra 太慢）、**度量不可比**（同一个"代价 1000"在不同 AS 里含义完全不同，所以只能交换可达性）、**策略**（最短的路不一定是允许走的路，且策略含政治、安全、经济考虑）。三条合起来给出 BGP 的口径：**力求找到能到达目的前缀且比较好、不兜圈子的路由，而非最佳路由。**

**路径向量**：BGP 路由 = 前缀 + AS-PATH + NEXT-HOP。AS-PATH 是所经过的 AS 序列，**只记 AS 不记路由器**。防环靠"AS-PATH 里出现自己的 AS 号就丢弃"，是**结构性**防环——挡得住任意长度的环，也不需要 16 这样的上限，比水平分割强一个量级。例题里 ③ 因含 AS5 被直接丢弃，剩下的按 AS-PATH 长度选 ②（长度 2）；但真实选路 LOCAL_PREF 优先级高于 AS-PATH，**这才是"策略最优"的落点**。

**两次递归查找**：BGP 给的 NEXT-HOP 是**对方 AS 里**的路由器，本 AS 认不得。第一次把起点换成本方边界路由器（"R1→X" 变成 "R2→R1→X"），第二次用 IGP 查出"到 R2 的下一跳是谁"，填进转发表。**BGP 管跨 AS 的方向，IGP 管本 AS 内的路，两者接力。**

**eBGP 与 iBGP**：同一个协议、同样的报文与属性，**只有通告规则不同**。从 eBGP 学来的可以随便转告；**从 iBGP 学来的不能再转告给同 AS 内的其他 iBGP 对等端**——因为 AS 内部传递时 AS-PATH 不变、防环失效。iBGP 对等端可以不直连。

**报文与封装**：OPEN / UPDATE / KEEPALIVE / NOTIFICATION 四种，TCP 端口 179。三大协议的封装选择各有理由：RIP 周期全量重发所以不需要可靠；OSPF 自己用 LSAck 和序列号实现了可靠所以不需要 TCP；BGP 增量通告且信息量巨大，必须可靠又不想自己造轮子。

**三类 AS**：末梢（付费、不转发过路流量）、穿越（收费的主干）、对等（免费互连）。多归属末梢 AS 连了两家仍是末梢，它**不会把经由一家的路由通告给另一家**——**策略在路由通告层面执行，不在转发层面**。

## 教材出处

- 谢希仁《计算机网络》（第 7 版）**4.6.4 外部网关协议 BGP**，印刷版 **p168–p172**：

- BGP 的必要性见 **p168**——"若没有协议 BGP，那么分布在全世界数以万计的 AS 都将是一个个没有联系的孤岛。正是由于有了 BGP 这种黏合剂，才使得这么多的 AS 孤岛能够连接成一个完整的互联网"。
- 不能用 IGP 的**第一个原因（规模）**在 **p168**——"目前在互联网的主干网路由器中，一个转发表的项目数甚至可达到 50 万个网络前缀。如果使用链路状态协议，则每一个路由器必须维持一个很大的链路状态数据库。对于这样大的主干网用 Dijkstra 算法计算最短路径时花费的时间也太长"；**度量不可比**同页——"对某 AS 来说，代价为 1000 可能表示一条比较长的路由。但对另一 AS，代价为 1000 却可能表示不可接受的坏路由"，并给出"比较合理的做法是在自治系统之间交换'可达性'信息"。
- **第二个原因（策略）**在 **p168**——"自治系统 AS 之间的路由选择必须考虑有关策略……这些策略包括政治、安全或经济方面的考虑"；AS3 不愿让 AS1 的数据报通过、以及"这些策略并不是自治系统之间的路由选择协议本身"同在此页。
- BGP 的口径见 **p169**——"边界网关协议 BGP 只能是力求选择出一条能够到达目的网络前缀且比较好的路由（不能兜圈子），而并非要计算出一条最佳路由"；"BGP 采用了路径向量（path vector）路由选择协议，它与距离向量协议（如 RIP）和链路状态协议（如 OSPF）都有很大的区别"。边界路由器与内部路由器的区分、"一个 AS 至少要有一个边界路由器"也在此页。
- eBGP / iBGP 的关系与转告规则见 **p170**——"eBGP 和 iBGP 并不是两个不同的协议……在这两种不同连接上传送的 BGP 报文，都遵循同样的协议 BGP，使用同样的报文格式和具有同样的属性类型。唯一的不同点就是在发送 BGP 路由通告时的规则有所不同"；"从 eBGP 对等端收到的 BGP 路由，可通过 iBGP 告诉同 AS 内的对等端。反过来也是可以的……**但是，从 iBGP 对等端收到 BGP 路由，不能转告给同一个 AS 内不同 iBGP 的对等端**"。同页给出边界路由器"可以拒绝某些路由（收到这种路由后即删除掉）"。
- BGP 路由格式见 **p170**——"BGP 路由 = '前缀，BGP 属性' = '前缀, AS-PATH, NEXT-HOP'"；"'BGP 路由'必须指出通过哪些自治系统 AS，但不指出路由中途要通过哪些路由器"。
- **两次递归查找**见 **p171**——"这需要经过两次递归查找。首先，Rx 要把这条 BGP 路由的起点进行转换……路由的起点 R1 并不在 AS2 中。AS2 中的路由器都不能识别 R1……其次，Rx 要利用内部网关协议，找到从 Rx 到 R2 的最佳路由中的下一跳"；同页说明转发表中"前缀匹配"用 CIDR 记法、"下一跳"用进入该路由器的接口的 IP 地址表示。
- 三类 AS 与多归属 AS 见 **p171–p172**——"可以把 AS 划分为……末梢 AS（stub AS）、穿越 AS（transit AS）和对等 AS（peering AS）"；"末梢 AS 必须向所连接的 AS 付费才能发送或接收分组"；"多归属 AS 可以增加连接的可靠性，因为若有一条连接出现故障，那么还有另一条连接可用"；**关键的一句**——"末梢 AS 不是穿越 AS，它不允许分组穿越自己的自治系统。末梢 AS5 也不能把（AS5-AS2-AS4）这样的 BGP 路由信息通告给 AS3"。
- BGP 报文的封装见 **p175**——"BGP 报文是作为 TCP 报文的数据部分来传送的……四种类型的 BGP 报文具有同样的首部"。
