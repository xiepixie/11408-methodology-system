# ARP 地址解析协议

## 大纲定位

**四（三）4 ARP 协议、DHCP 协议与 ICMP 协议** 中的 **ARP** —— 属「四、网络层 →（三）IPv4」。

⚠️ 同属四（三）4 的另外两个协议**不在本篇**：**DHCP** 写在 [[04_计算机网络_CN/application/ftp-dhcp.md|FTP 与 DHCP]]（该篇按目录归在应用层，但 DHCP 承载的是网络层这一条大纲条目），**ICMP** 写在 [[04_计算机网络_CN/network/icmp.md|ICMP 协议]]。

**"IP 地址端到端不变、MAC 地址逐跳改变"这条贯穿性结论的完整推演集中在本篇**，包括跨多跳时每条链路上四个地址各是什么、一次通信要调用几次 ARP。 "该不该走路由器"（直接交付 / 间接交付的判据）写在 [[04_计算机网络_CN/network/ip-addressing.md|IP 编址]]，本篇从"已经判完了"接着讲。 交换机凭 MAC 地址表转发帧、与 ARP 的分工，见 [[04_计算机网络_CN/datalink/switch-learning.md|以太网交换机]]。

## 知识框架

本节回答 5 个问题：

- 既然帧最终是按 MAC 地址送达的，**为什么不干脆全网只用 MAC 地址**，把 ARP 和 IP 地址都省掉？
- ARP 请求为什么必须广播、响应为什么可以单播？这一对不对称是怎么定下来的？
- 跨了两台路由器的一次通信，**要调用几次 ARP**？每条链路上的源/目的 MAC 与源/目的 IP 分别填什么？
- 回程为什么需要的 ARP 次数比去程**少**？少的那几次是被什么机制省掉的？
- ARP 缓存条目为什么要设**有效期**？永久缓存会坏在哪里？

## 一、ARP 解决什么问题

网络层用 IP 地址选路，但数据帧在链路上传送时，最终必须使用链路层的 **MAC 地址**（48 位物理地址）。两者格式不同（32 位 vs 48 位），**不存在任何简单的映射关系**——不可能靠计算从 IP 算出 MAC。

ARP（Address Resolution Protocol）就是用来补这一环的：**已知 IP 地址，求同一网络上对应接口的 MAC 地址。**

方向要记牢：**ARP 是"已知 IP 求 MAC"**。反方向"已知 MAC 求 IP"的是 RARP（逆地址解析协议），它的功能现在已经被 [[04_计算机网络_CN/application/ftp-dhcp.md|DHCP]] 完全覆盖，早已不再使用。

### 为什么不能只用 MAC 地址

这个问题值得单独推一遍，它是整套编址体系的地基。

假设取消 IP 地址、全网只用 MAC 地址寻址，会撞上两堵墙：

**第一堵墙：全世界的网络是异构的。** 以太网、无线局域网、点对点链路、卫星链路……各自使用不同格式的硬件地址。要让这些异构网络互通，就得在每个交界处做复杂的地址格式转换，而且每引入一种新的链路技术就要改一遍所有设备。

**第二堵墙：MAC 地址没有层次，转发表压不下去。** MAC 地址是出厂时烧在网卡里的，与"这台机器接在哪个网络上"毫无关系——地理上相邻的两台机器，MAC 地址可以毫不相干。这意味着路由表**没法按前缀聚合**，只能逐条记录全世界每一块网卡的位置。这张表既存不下也查不快。

IP 编址一次解决两件事：它是**统一的**（屏蔽底层异构性），又是**分层的**（网络号 + 主机号，可以按前缀聚合，见 [[04_计算机网络_CN/network/ip-addressing.md|IP 编址]]）。代价就是需要 ARP 在每一段链路的两端做一次"逻辑地址 → 物理地址"的翻译——而这份代价是完全自动、对用户不可见的。

**反过来只用 IP 不用 MAC 也不行**：数据报到了目的网络之后，还得在这个局域网里找到具体那块网卡，而网卡认的就是 MAC 地址。

## 二、ARP 的工作过程

### 同一网络内

主机 A（192.168.1.10）要发数据给同一网络内的主机 B（192.168.1.20），但不知道 B 的 MAC。

步骤：

- A 先查自己的 **ARP 高速缓存**，命中就直接用
- 未命中，A 在本网络内**广播**一个 ARP 请求分组，其中写明"我要找 192.168.1.20 的 MAC"，**同时把自己的 IP→MAC 映射也写进去**
- 网络内所有主机都收到这个广播，但只有 IP 匹配的 B 会理睬
- B **先把 A 的映射写入自己的缓存**，然后以**单播**方式发回 ARP 响应，告知自己的 MAC
- A 收到响应，把 B 的映射写入缓存

### 请求广播、响应单播：这对不对称从哪来

这不是规定，是**信息不对称的必然结果**：

- **请求时**，A 手上只有 B 的 IP，没有 B 的 MAC，帧的目的 MAC 字段**填不出来**——只能填广播地址（全 1），让网内所有站都收下再各自判断。
- **响应时**，B 已经从请求分组里读到了 A 的 IP 和 MAC（第 2 步里 A 主动带上的），完全可以**精确地单播**回去。若也用广播，网内其他主机白收一遍，纯属浪费。

第 2 步里"A 主动把自己的映射写进请求"这个设计还有个后果：**收到请求的一方顺手就把请求方的映射缓存了**。这一条会在第四节的例题里直接省掉几次 ARP。

### 跨网络时

A（192.168.1.10）要发给另一个网络的主机 D（192.168.2.50）。

A 用目的 IP 与自己的掩码做按位与，发现 D 不在本网络（判据见 [[04_计算机网络_CN/network/ip-addressing.md|IP 编址]]），于是**不会**去广播找 D 的 MAC——广播帧根本出不了本网络，找也找不到。

A 要做的是把数据报交给**默认网关**，所以它需要的是**网关的 MAC**。

**要害在于：A 封装的帧里，目的 MAC 是网关的，而 IP 数据报里的目的 IP 仍然是 D 的。** 这两个字段属于两个不同的层，各管各的事——MAC 管"这一跳送到谁手上"，IP 管"最终送到哪"。

## 三、四种典型的 ARP 调用场景

不管拓扑多复杂，ARP 的调用只有四种情形，区别只在"发送方是主机还是路由器"和"目的是否在本网络"：

| 情形 | 发送方 | 目的主机的位置 | ARP 要解析的是谁的 MAC |
| --- | --- | --- | --- |
| ① | 主机 | **同一网络**上的另一台主机 | **目的主机**自己 |
| ② | 主机 | 另一个网络上的主机 | 本网络上那台**路由器**（默认网关）的接口 |
| ③ | 路由器 | 与本路由器**同一网络**上的主机 | **目的主机**自己 |
| ④ | 路由器 | 还要再经过下一个路由器 | **下一跳路由器**的接口 |

四种情形可以归结成同一句话：**ARP 解析的永远是"下一跳"的 MAC，而不是"最终目的"的 MAC。** 当"下一跳"恰好就是最终目的（情形 ① ③）时，两者才重合。

复杂拓扑无非是这四种情形的反复使用。

## 四、例题：跨两台路由器的逐跳地址与 ARP 次数

**题目**（自造数据）：网络拓扑如下，所有设备的 ARP 缓存初始为空。

```
H1 ── [ 网络 N1 ] ── R1 ── [ 网络 N2 ] ── R2 ── [ 网络 N3 ] ── H2
```

| 设备接口 | IP 地址 | MAC 地址 |
| --- | --- | --- |
| H1 | 192.168.1.10 | MAC-H1 |
| R1 接 N1 的接口 | 192.168.1.1 | MAC-R1a |
| R1 接 N2 的接口 | 10.0.0.1 | MAC-R1b |
| R2 接 N2 的接口 | 10.0.0.2 | MAC-R2a |
| R2 接 N3 的接口 | 172.16.5.1 | MAC-R2b |
| H2 | 172.16.5.20 | MAC-H2 |

问：(1) H1 发一个数据报给 H2，全程要调用几次 ARP？(2) 三条链路上帧的源/目的 MAC 与数据报的源/目的 IP 分别是什么？(3) 随后 H2 回复 H1，还需要几次 ARP？

**第 1 步：先数跳数。**

*为什么这么做*：ARP 是"逐跳"的协议，每一跳的发送方都要先知道本跳接收方的 MAC。所以**跳数决定了 ARP 次数的上限**。

数据报要经过三条链路：N1、N2、N3，即 **3 跳**（H1→R1、R1→R2、R2→H2）。

**第 2 步：逐跳判断"这一跳的发送方需要谁的 MAC"。**

*为什么这么做*：套用上一节的四种情形表，每一跳单独判一次。

| 第几跳 | 发送方 | 情形 | 需要解析的 MAC | 是否已在缓存 |
| --- | --- | --- | --- | --- |
| 1（N1） | H1 | ②（目的不在本网络） | R1 的 N1 接口（192.168.1.1） | 空 → **需 ARP** |
| 2（N2） | R1 | ④（还要经下一个路由器） | R2 的 N2 接口（10.0.0.2） | 空 → **需 ARP** |
| 3（N3） | R2 | ③（目的在本网络） | H2（172.16.5.20） | 空 → **需 ARP** |

**答（1）：3 次 ARP。** 一般化：冷缓存下，经过 n 台路由器的通信有 n+1 跳，需要 n+1 次 ARP。

**第 3 步：逐条链路填四个地址。**

*为什么这么做*：这是整道题的核心——把"IP 端到端不变、MAC 逐跳改变"具体到每一个字段上，光背结论是不够的。

| 链路 | 帧·源 MAC | 帧·目的 MAC | 数据报·源 IP | 数据报·目的 IP |
| --- | --- | --- | --- | --- |
| N1 | MAC-H1 | **MAC-R1a** | 192.168.1.10 | 172.16.5.20 |
| N2 | **MAC-R1b** | **MAC-R2a** | 192.168.1.10 | 172.16.5.20 |
| N3 | **MAC-R2b** | **MAC-H2** | 192.168.1.10 | 172.16.5.20 |

**答（2）：** 见表。**右边两列一个字都没变，左边两列每一行全变。**

注意两处细节：

- 路由器 R1 在 N1 上用的是 MAC-R1a、在 N2 上用的是 MAC-R1b。**一台路由器每个接口都有自己独立的 MAC 地址和 IP 地址**，因为每个接口分属不同的网络。
- 每一跳的源 MAC 都是"本跳发送方在本网络上那个接口的 MAC"，目的 MAC 都是"本跳接收方在本网络上那个接口的 MAC"。**MAC 地址对从来不跨网络。**

**第 4 步：回程为什么只要 1 次 ARP。**

*为什么这么做*：这一步考的是"ARP 请求带发送方自己的映射"这个设计的后果，不是死记。

去程发生了三次 ARP 请求，每次请求分组里都带着请求方自己的 IP→MAC 映射，收到请求的一方会顺手缓存下来。于是去程结束时，各设备的缓存变成：

| 设备 | 从去程学到了什么 |
| --- | --- |
| R1 | H1 的映射（从 H1 的请求里学到）；R2 的映射（从 R2 的响应里学到） |
| R2 | R1 的映射（从 R1 的请求里学到）；H2 的映射（从 H2 的响应里学到） |
| H2 | **只学到了？** —— H2 收到的是 R2 发来的**ARP 请求**，请求里带着 R2 的映射 → H2 缓存了 R2 |

咦，那 H2 其实也有 R2 的映射了。逐跳再判一次回程：

| 第几跳 | 发送方 | 需要解析 | 缓存里有吗 |
| --- | --- | --- | --- |
| 1（N3） | H2 | R2 的 N3 接口 | **有**（去程 R2 的 ARP 请求带来的） |
| 2（N2） | R2 | R1 的 N2 接口 | **有**（去程 R1 的 ARP 请求带来的） |
| 3（N1） | R1 | H1 | **有**（去程 H1 的 ARP 请求带来的） |

**答（3）：0 次。** 回程一次 ARP 都不需要——去程的三次 ARP 请求恰好把回程所需的三条映射全部"顺路"装进了对方的缓存。

**本例真正的收获在这里**：ARP 请求携带发送方自身映射，不是一个可有可无的优化，它把"一去一回"的 ARP 开销从 6 次直接压到 3 次。若把这个设计去掉，则回程要重新做 3 次 ARP。**若题面明确规定"ARP 请求不携带发送方映射"或"只有响应方写缓存"，则回程仍需 3 次、合计 6 次——先看清给定的口径。**

## 五、ARP 高速缓存

每台主机和路由器都维护一张 ARP 高速缓存（ARP cache），存放**本网络上**各主机和路由器的 IP→MAC 映射：

| IP 地址 | MAC 地址 | 类型 | 剩余有效期 |
| --- | --- | --- | --- |
| 192.168.1.1 | MAC-R1a | 动态 | 2 分钟 |
| 192.168.1.20 | MAC-B | 动态 | 12 分钟 |
| 192.168.1.99 | MAC-X | **静态** | 永不过期 |

- **动态条目**：ARP 学到的，有生存时间（常见 2~20 分钟），到期自动删除
- **静态条目**：管理员手工配置，不会过期

### 为什么必须设有效期

这是本节最容易被忽略、却最能说明设计意图的一条。

**理由一：映射会失效。** 一台主机换了网卡，MAC 地址就变了；一个 IP 地址也可能被回收后分给别的机器。如果缓存永不过期，A 会一直用一个已经不存在的 MAC 去发帧，**帧发出去石沉大海，而 A 完全察觉不到**——因为链路层不会告诉它"没人收"。

**理由二：过期是唯一的自愈机制。** ARP 没有任何"通知对方映射已失效"的机制。唯一能让错误映射消失的办法，就是**等它自己过期**，然后重新广播一次问出正确的答案。所以有效期不能太长，太长意味着故障恢复慢。

**理由三：也不能太短。** 缓存的意义就是省广播。若有效期只有几秒，每发几个数据报就要广播一次 ARP，网络会被广播帧淹没——ARP 请求是广播，广播域内**每一台主机**都要收下并处理，代价按主机数放大。

所以有效期是在"故障恢复快"和"广播开销小"之间取的折中。

## 六、ARP 的定位与特点

- **ARP 是网络层协议**。它是与 IP 配套使用的三个协议之一（另两个是 [[04_计算机网络_CN/network/icmp.md|ICMP]] 和 IGMP，见 [[04_计算机网络_CN/network/multicast.md|IP 多播]]）。有的教材因为它服务于链路层封装而说它"跨越网络层与数据链路层"，按谢希仁的口径，它属于**网际层（IP 层）**。
- **ARP 报文直接封装在链路层帧中**（以太网帧类型字段 = 0x0806），**不封装在 IP 数据报里**。这一点和 ICMP、IGMP 正好相反——后两者是封装在 IP 数据报的数据部分里的。
- **ARP 只在同一个广播域内工作**。ARP 请求是广播帧，路由器隔离广播域、不转发广播帧，所以 ARP 请求出不了本网络。这也正是"跨网络要解析网关 MAC 而不是目的主机 MAC"的根本原因。
- **ARP 是即插即用的**，不需要管理员配置任何东西。

### ARP 欺骗

ARP 协议没有任何认证机制：任何主机都可以发出伪造的 ARP 响应，声称"网关的 IP 对应的是我的 MAC"。受害主机把这个映射缓存下来后，所有本该发给网关的数据就都送到了攻击者手上，形成**中间人攻击**。

这个漏洞是 ARP 设计年代的产物——它假设局域网内所有站都是可信的。了解即可。

## 易混淆知识点

**1. ARP 请求广播，ARP 响应单播**

请求时不知道目标 MAC，帧的目的 MAC 字段填不出来，只能广播；响应时已经从请求分组里读到了请求方的 MAC，单播即可。这是信息不对称的必然结果，不是随手规定。

**2. 跨网络通信解析的是网关的 MAC，不是目的主机的 MAC**

A 构造的帧目的 MAC 填网关的 MAC，但 IP 数据报的目的 IP 仍然是最终目的主机的 IP。两个字段属于两层，各管各的。

**3. ARP 解析的永远是"下一跳"，不是"最终目的"**

四种典型情形归结成的就是这一句。只有当下一跳恰好就是最终目的时，两者才重合。

**4. MAC 地址逐跳变化，IP 地址端到端不变**

例题第 3 步那张表是这条结论的完整展开。NAT 是唯一会改 IP 地址的例外，见 [[04_计算机网络_CN/network/nat.md|NAT]]。

**5. 一台路由器的每个接口各有自己的 IP 和 MAC**

R1 在 N1 侧是 MAC-R1a，在 N2 侧是 MAC-R1b。把路由器当成"一个 MAC 地址"会导致逐跳表全填错。

**6. ARP 报文不封装在 IP 数据报里**

ARP 直接封装在以太网帧中（类型字段 0x0806）。相比之下 ICMP、IGMP 都是封装在 IP 数据报数据部分里的。

**7. ARP 不能跨路由器工作**

请求是广播帧，路由器隔离广播域。所以 ARP 的作用范围严格等于一个广播域（一个网络 / 一个 VLAN）。

**8. 缓存有效期不是可有可无的细节**

ARP 没有"撤销映射"的机制，过期是唯一的自愈手段。太长则故障恢复慢，太短则广播泛滥。

## 本节小结

本节的主线是"**为什么需要翻译，翻译在哪一跳做，做完之后怎么省**"：

- **两套地址是必需的**。只用 MAC 撞两堵墙：异构网络地址格式不统一、MAC 无层次导致转发表压不下去；只用 IP 则无法在局域网内定位到具体网卡。IP 提供统一且分层的寻址，MAC 负责一跳内的实际交付，ARP 在每段链路的两端做翻译。
- **请求广播 / 响应单播的不对称，来自信息不对称**：请求时目的 MAC 字段填不出来只能广播；响应时已经从请求里读到了对方的 MAC，可以精确单播。而请求分组主动携带发送方自身映射这一设计，让"收到请求的一方顺手缓存请求方"成为可能。
- **ARP 解析的永远是下一跳的 MAC**。四种典型情形（主机→本网主机 / 主机→外网 / 路由器→本网主机 / 路由器→下一跳路由器）本质是同一条规则的四种落地；再复杂的拓扑也只是这四种的反复。
- **跨 n 台路由器 = n+1 跳 = 冷缓存下 n+1 次 ARP**。每条链路上源/目的 MAC 全部改变，源/目的 IP 一个字不动——这是本篇例题那张表的全部内容，也是网络层综合题反复用到的展开方式。
- **回程能省掉全部 ARP**，靠的就是去程三次请求把三条映射顺路装进了对方缓存。若题目明确否定这个机制，答案要按双倍算。
- **缓存必须有有效期**：ARP 没有撤销机制，过期是唯一的自愈手段；太长故障恢复慢，太短广播泛滥。
- **ARP 是网络层协议但报文直接封装在链路帧里**（类型 0x0806），且只在一个广播域内有效——这两条一起解释了"为什么跨网络必须先解析网关"。

## 教材出处

- 谢希仁《计算机网络》（第 7 版）：ARP 的定位，见印刷版 **p119**（4.2 网际协议 IP）——"与协议 IP 配套使用的还有三个协议：地址解析协议 ARP、网际控制报文协议 ICMP、网际组管理协议 IGMP"，其中"ARP 画在最下面，因为 IP 经常要使用这个协议"。同页说明 RARP"现在已被淘汰不使用了"。
- 同书 **p133**（4.2.4 地址解析协议 ARP）：ARP 存在的理由——"IP 地址和下面链路层的 MAC 地址之间由于格式不同而不存在简单的映射关系（例如，IP 地址有 32 位，而链路层的 MAC 地址是 48 位）。此外，在一个网络上可能经常会有新的主机加入进来，或撤走一些主机。更换网络适配器也会使主机的 MAC 地址改变"，解决办法是"在主机的 ARP 高速缓存中存放一个从 IP 地址到 MAC 地址的映射表，并且这个映射表还经常动态更新（新增或超时删除）"；同页指出 DHCP"已经包含了协议 RARP 的功能"。
- 同书 **p134**：请求广播、响应单播——"虽然 ARP 请求分组是广播发送的，但 ARP 响应分组是普通的单播，即从一个源地址发送到一个目的地址"；以及**回程省 ARP 的机制**："主机 A 在发送其 ARP 请求分组时，就把自己的 IP 地址到 MAC 地址的映射写入 ARP 请求分组。当主机 B 收到 A 的 ARP 请求分组时，就把主机 A 的这一地址映射写入主机 B 自己的 ARP 高速缓存中。以后主机 B 向 A 发送数据报时就很方便了"。本篇例题第 4 步的结论即由此而来。
- 同书 **p135**：**缓存必须设有效期**的论证——教材举的例子是主机 B 更换网络适配器后 MAC 地址变化，"A 在其 ARP 高速缓存中查找到 B 原先的 MAC 地址，并使用该 MAC 地址向 B 发送数据帧。但 B 原先的 MAC 地址已经失效了，因此 A 无法找到主机 B。但是过了一段不长的生存时间，A 的 ARP 高速缓存中已经删除了 B 原先的 MAC 地址，于是 A 重新广播发送 ARP 请求分组，又找到了 B"。同页给出**使用 ARP 的四种典型情况**（图 4-19），本篇第三节那张表即依此重排。
- 同书 **p135–p136**：为什么不能只用 MAC 地址——"由于全世界存在着各式各样的网络，它们使用不同的 MAC 地址。要使这些异构网络能够互相通信就必须进行非常复杂的 MAC 地址转换工作……即使是对分布在全世界的以太网 MAC 地址进行寻址，也是极其困难的。然而 IP 编址把这个复杂问题解决了"。同书 **p141** 从转发表规模的角度补上另一半理由："能不能在转发表中不使用 IP 地址而直接使用 MAC 地址呢？不行……在转发表中直接使用 MAC 地址，那就会带来更多的麻烦，甚至无法找到对方的机器"。[[04_计算机网络_CN/network/ip-fragment.md|上一篇IP 分片与重装]][[04_计算机网络_CN/network/icmp.md|下一篇ICMP 协议]]
