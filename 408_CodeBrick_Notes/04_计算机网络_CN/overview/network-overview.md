## 知识框架

本节回答 5 个问题：

- 把一堆计算机连起来就叫计算机网络吗？"自治"和"互连"这两个词分别排除了什么？
- 电路交换要独占线路，为什么打电话用它反而合适、传计算机数据就不合适？
- 分组交换比报文交换快，快在哪一步？能不能把"快多少"算出来？
- 既然分组越小流水线效果越好，为什么不把分组切成 1 字节？
- "广播式"和"点对点"是按什么分的，为什么局域网几乎都是广播式？

计算机网络这一章的概念看着零散，其实主线只有一条：**通信资源怎么分配**。电路交换是"先占满再用"，报文交换是"用多少占多少、但一次占很久"，分组交换是"用多少占多少、而且每次只占一小会儿"。后面网络分类、性能指标乃至整本书的可靠传输与拥塞控制，都是在这条主线上继续往下走。

## 什么是计算机网络

计算机网络是**若干自治的计算机系统**，通过通信设备与线路互连起来，并由功能完善的网络软件实现资源共享和信息传递的系统。

定义里有两个词是用来排除东西的：

- **自治**：每台计算机都能独立运行，没有主从关系。带一堆哑终端的大型主机系统不算网络——终端没有独立处理能力，它只是主机的外设。
- **互连**：机器之间必须有通信通道能交换数据。共享一台打印机、靠 U 盘拷来拷去，都不构成网络。

网络由若干**节点**（计算机、集线器、交换机、路由器等）和连接这些节点的**链路**组成。若干网络再通过路由器互连，构成**互连网**。

### internet 与 Internet

这两个词长得几乎一样，含义完全不同：

- **internet**（互连网）：**通用名词**，泛指由多个计算机网络互连而成的网络，不要求使用特定协议。任意两个网络用路由器连起来就是一个 internet。
- **Internet**（互联网 / 因特网）：**专用名词**，特指当前全球最大的、由美国 ARPANET 发展而来、采用 TCP/IP 协议族的那个特定网络。

判据只有一条：**首字母大写、且指的是"世界上那一个"，才是 Internet**。

用户通过**互联网服务提供商（ISP）** 接入 Internet。ISP 拥有通信线路、路由器等设备，并从管理机构申请到成块的 IP 地址，再分配给自己的用户。ISP 之间也有层次：本地 ISP 接入地区 ISP，地区 ISP 再接入主干 ISP，这就是互联网"网络的网络"这个说法的由来。

## 计算机网络的组成

同一个网络，从三个角度看会得到三种不同的拆法。这三种拆法**不是三选一，而是三个正交的切面**：

**1）从组成部分看**：硬件（主机、通信链路、交换设备）、软件（网络操作系统、应用程序）、协议三大部分。协议是网络的核心——硬件和软件解决"能不能传"，协议解决"传成什么样才算对"。

**2）从工作方式看**：**边缘部分**与**核心部分**。边缘部分是所有连接到互联网、供用户直接使用的主机，通信方式分客户-服务器方式与对等（P2P）方式；核心部分由大量网络和路由器组成，**为边缘部分提供连通性和交换服务**。注意：路由器属于核心部分，它不叫主机。

**3）从功能组成看**：**通信子网**与**资源子网**。通信子网由传输介质、通信设备及相关协议组成，负责数据传输（对应五层模型的下三层）；资源子网由主机、软件、数据等组成，向用户提供共享服务（对应上两层）。

三种拆法的对应关系：**核心部分 ≈ 通信子网**，**边缘部分 ≈ 资源子网**。但"边缘/核心"强调的是**位置**（谁在网络的哪一端），"资源/通信子网"强调的是**职责**（谁负责传、谁负责用），所以主机上运行的 TCP/IP 协议栈下三层，位置上属边缘、职责上属通信子网。

## 计算机网络的功能

- **数据通信**：最基本、最重要的功能，其余功能都建立在它之上
- **资源共享**：软件、数据、硬件资源共享，提高利用率
- **分布式处理**：把复杂任务分配给多台计算机协同处理
- **提高可靠性**：各台计算机通过网络互为备份
- **负载均衡**：把任务均衡分配给网络中各台计算机

后四条都要靠第一条兜底：没有可靠的数据通信，"互为备份"反而会因为同步失败而降低可靠性。

## 三种交换方式

在这一节里，"交换"指的是**按某种方式动态地分配传输线路的资源**。三种交换方式的差别，全部落在"**一次分配多久、分配多少**"上。

### 电路交换

传统电话网络采用的方式。通信必须经过三个步骤：**建立连接（占用通信资源）→ 通话（一直占用通信资源）→ 释放连接（归还通信资源）**。建立起来的是一条**专用物理通路**，通路上的资源在通信期间不会被其他用户占用。

优点：

- 数据直达，**中间节点不做任何存储转发**，传输时延就是发送时延加端到端传播时延
- 数据按序到达，不存在失序
- 不同通信对使用彼此独立的信道，**没有冲突**
- 通路一旦建立，实时性强

缺点：

- **建立连接时间长**，且建连期间线路还没开始传数据
- 通信期间独占线路，**线路利用率低**。计算机数据是突发式的：一次网页浏览里真正在传数据的时间可能不到 1%，其余时间线路空占着
- 灵活性差，通路上任一节点或链路故障都要重新建立连接
- **难以实现差错控制**，中间节点不存储数据，也就没有条件做检错重传

为什么打电话适合电路交换？因为话音是**连续**的：一旦接通，两端几乎一直在占用带宽，"独占"没有浪费。而计算机数据是**突发**的，独占等于把带宽扔掉。这条判据比记结论有用——凡是"通信时间远大于建连时间、且期间持续有数据"的场景，电路交换都不吃亏。

### 报文交换

发送方把整个报文（数据加上目的地址等控制信息）发给相邻节点，节点**完整接收并存储整个报文**后，再查转发表转发到下一个节点，直到目的地。这就是**存储转发**。

优点：

- 无须建立连接，可随时发送
- 线路分配灵活，可动态选空闲链路，故障时可换路径
- 线路利用率高，报文只在实际传输时占用链路
- **支持差错控制**：节点缓存了整份报文，有条件检错并要求重传

缺点：

- **存储转发时延高**：每一跳都必须把整份报文收完才能往下发，这个"收完"的代价被跳数乘了一遍
- 缓存开销大：报文长度没有上限，节点必须准备大容量缓存
- 报文越长出错概率越大，一出错要重传整份报文

### 分组交换

在报文交换的基础上加一条限制：**报文必须先切成长度受限的分组（packet）**，每个分组带上自己的控制信息（源地址、目的地址、序号等），独立地存储转发。

优点：

- 分组长度受限，节点**缓存需求小且可预估**
- 分组可以**流水线式**转发：第 1 个分组正在第 2 跳上传输时，第 2 个分组已经可以在第 1 跳上传输——这是分组交换时延低于报文交换的**唯一来源**
- 某个分组出错只需重传该分组
- 线路利用率高（统计时分复用：谁有数据谁用，不预留）

缺点：

- 每个分组都要带首部，**开销与分组数成正比**
- 分组可能乱序到达（数据报方式），需在目的端重排
- 存储转发本身仍有时延，且排队时延不可控——分组交换**无法保证端到端带宽**

图源：谢希仁《计算机网络》（第 7 版）图 1-11「三种交换的比较」，印刷版 **p17**。图中 P1∼P4 表示 4 个分组；最下方一行归纳了三者在数据传送阶段的特点：电路交换是"比特流直达终点"，报文与分组交换都是"存储转发"，区别只在存储转发的单位是整份报文还是一个分组。

### 把"快多少"算出来

上面那张图里，分组交换的三角形比报文交换的短——短多少是可以直接算的。设：

- 报文数据长度 D 比特，切成 n 个分组，每个分组的首部为 H 比特
- 源到目的之间共 k 段链路（即 k−1 个中间节点），每段链路速率 R、传播时延 d
- 忽略处理时延与排队时延

**报文交换**：每一跳都要把整份报文收完再发，共发送 k 次：T报文=k⋅DR+k⋅d

**分组交换**：这是关键一步。最后一个分组到达终点的时刻，等于"**第一个分组走完全程**"再加上"**后面 n−1 个分组在最后一跳上依次排出**"。第一个分组走完全程要发送 k 次，后面每个分组只额外贡献 1 次发送时延（因为它们在前面各跳上是与别的分组**并行**的）：T分组=(k+n−1)⋅D/n+HR+k⋅d

(k+n−1) 这个系数就是流水线的全部秘密：报文交换的系数是 k⋅n 量级（把 D 看成 n 个分组则等价于 k⋅n 个分组时长），分组交换降到了 k+n−1。**跳数越多、分组数越多，二者差距越大**。

**电路交换**：设建立连接耗时 Ts、释放连接耗时忽略。数据在建连后一路直达，不做存储转发：T电路=Ts+DR+k⋅d

注意它的发送时延只算**一次**——这是电路交换唯一的优势所在。

### 例题 1：三种交换方式的时延对比

**题**：主机 A 经 B、C 两个中间节点向 D 发送一份 D=3000 比特的报文。三段链路速率均为 R=1 Mbit/s，每段传播时延 d=5 ms。忽略处理与排队时延。电路交换的建连时间为 200 ms。分组交换把报文切成 3 个分组，先忽略分组首部。求三种方式下 D 收完全部数据的时刻。

**解**：链路段数 k=3。

**（1）报文交换**

每跳发送时延 3000106=3 ms，共 3 跳：T报文=3×3+3×5=9+15=24 ms

这一步为什么这么做：报文交换的定义就是"整份收完才转发"，所以 3 ms 这个发送时延在每一跳上都要**完整重来一遍**，不能重叠。

**（2）分组交换**

每个分组 3000/3=1000 比特，发送时延 1000106=1 ms：T分组=(3+3−1)×1+3×5=5+15=20 ms

这一步为什么这么做：(k+n−1) 中的 k=3 是第一个分组走完三跳，n−1=2 是后两个分组在最后一跳上排队排出。它们在前两跳上都是与第一个分组**同时**在传的，所以不重复计。

**（3）电路交换**T电路=200+3000106+3×5=200+3+15=218 ms

这一步为什么这么做：建连的 200 ms 是**净损失**，期间一个比特都没传；建连之后中间节点不存储，所以 3 ms 的发送时延只出现一次。

**结论**：20<24≪218。数据量小的时候电路交换被建连时间彻底拖垮；分组交换靠流水线比报文交换省下 4 ms。

**边界检查**：把报文换成 3×107 比特（30 Mbit）呢？此时电路交换 =200+30000+15=30215 ms，报文交换 =3×30000+15=90015 ms。**电路交换反超**了——因为发送时延只算一次的优势随数据量线性放大，而 200 ms 的建连成本被摊薄成了千分之七。这正是"**传送时间远大于建连时间时电路交换的传输速率较快**"这句结论的来历。

### 例题 2：分组是不是越小越好

**题**：条件同例题 1（D=3000 比特，k=3，R=1 Mbit/s，d=5 ms），但每个分组要加 H=40 比特首部。分别取 n=3,30,300，求总时延；并求使总时延最小的分组数。

**解**：代入 T=(k+n−1)⋅D/n+HR+kd：

| 分组数 n | 每分组长度 | 发送时延 | 系数 k+n−1 | 总时延 |
| --- | --- | --- | --- | --- |
| 3 | 1000+40=1040 bit | 1.04 ms | 5 | 5×1.04+15=20.20 ms |
| 30 | 100+40=140 bit | 0.14 ms | 32 | 32×0.14+15=19.48 ms |
| 300 | 10+40=50 bit | 0.05 ms | 302 | 302×0.05+15=30.10 ms |

n 从 3 加到 30，时延下降；再加到 300，时延反而暴涨。**存在一个最优分组数**。

把总时延展开：T=1R[(k−1)Dn+(k−1)H+D+nH]+kd

方括号里只有两项与 n 有关：(k−1)Dn 随 n 增大而减小（流水线收益），nH 随 n 增大而增大（首部开销）。对 n 求导置零：−(k−1)Dn2+H=0⟹n∗=(k−1)DH

代入数值：n∗=2×300040=150≈12.25，取整后 n=12，此时每分组 250+40=290 比特，总时延 14×0.29+15=19.06 ms——确实低于上表中的任何一行。

这一步为什么这么做：把"分组该切多小"从经验判断变成了两项的**此消彼长**。流水线收益正比于 1/n，首部开销正比于 n，两条曲线必然交出一个最低点。所以"分组越小时延越低"只在 n<n∗ 时成立，**这是一条有条件的结论，不是普遍规律**。

顺带解释了两件工程事实：跳数 k 越多（n∗ 越大）分组该切得越小；首部 H 越大（n∗ 越小）分组该切得越大——这就是以太网 1500 字节 MTU 相对 14 字节帧首部的取舍逻辑。

### 三种交换方式对比

| 对比项 | 电路交换 | 报文交换 | 分组交换 |
| --- | --- | --- | --- |
| 建立连接 | 需要 | 不需要 | 不需要 |
| 独占线路 | 是 | 否 | 否 |
| 存储转发 | 否 | 是（整个报文） | 是（单个分组） |
| 发送时延计几次 | **1 次** | k 次 | k+n−1 次（分组时长） |
| 节点缓存开销 | 无 | 高且无上限 | 低且可预估 |
| 是否支持差错控制 | 不支持 | 支持 | 支持 |
| 数据是否按序到达 | 是 | 是 | 否（数据报方式） |
| 额外控制信息 | 建连时一次 | 每报文一份 | **每分组一份** |
| 线路利用率 | 低 | 高 | 非常高 |
| 能否保证带宽 | **能** | 不能 | 不能 |
| 适用场景 | 连续大量数据、传送时间远大于建连时间 | 容忍时延的批量数据 | 突发性数据通信 |

判断三者的一句话判据：**看"一次占用的粒度"**——电路交换占的是整条通路的整段时间，报文交换占的是一跳链路的一整份报文时间，分组交换占的是一跳链路的一个分组时间。粒度越细，利用率越高、时延越低、开销越大。

### 分组交换的两种方式

分组交换内部又分**数据报方式**和**虚电路方式**：

| 对比项 | 数据报 | 虚电路 |
| --- | --- | --- |
| 建立连接 | 不需要 | 需要（建立虚电路） |
| 路由选择 | 每个分组独立选路 | 建立时确定路径，后续分组沿同一路径 |
| 分组是否携带完整地址 | 每个分组带完整目的地址 | 只带虚电路号 |
| 分组顺序 | 可能乱序到达 | 按序到达 |
| 节点故障 | 只丢失该节点上的分组，其余分组绕行 | 经过该节点的**全部**虚电路失效 |
| 可靠性由谁负责 | 高层协议 | 网络层 |
| 代表 | IP 网络（因特网） | X.25、帧中继、ATM |

**因特网采用的是数据报方式的分组交换**。虚电路虽然要"建立连接"，但它建立的是**逻辑通路**——链路资源仍然是统计复用的，并不像电路交换那样被独占。

这两种方式的展开（含网络层如何为上层提供服务）在[[04_计算机网络_CN/network/network-layer-functions.md|网络层功能与服务]]，本篇只做定位。

## 计算机网络的分类

### 按覆盖范围

| 类型 | 覆盖范围 | 典型技术 |
| --- | --- | --- |
| 广域网 WAN | 几十到几千公里 | PPP |
| 城域网 MAN | 一个城市范围 | 以太网技术为主 |
| 局域网 LAN | 几十米到几公里 | 以太网、Wi-Fi |
| 个人区域网 PAN | 几米范围 | 蓝牙 |

范围只是表象，真正的分界是**谁拥有它、以及用什么技术做介质访问控制**：局域网由单一组织拥有，可以用共享信道加争用协议（CSMA/CD、CSMA/CA）；广域网跨越运营商，只能用点对点链路加路由。所以"用交换机连起来的两栋楼"是 LAN，"用运营商专线连起来的两个城市"是 WAN，哪怕后者物理距离更近也一样。

### 按使用者

- **公用网**：电信公司建设运营，面向公众（交钱就能用）
- **专用网**：某组织或部门自建，不对外开放（如军事网、铁路网）

### 按交换方式

电路交换网络、报文交换网络、分组交换网络（分组交换网络再分数据报 / 虚电路）。

### 按传输技术

这一条是分类里最要紧的，因为它直接决定了数据链路层要不要做介质访问控制：

- **广播式网络**：所有联网计算机共享一个公共通信信道，一台发送、所有机器都能收到，各自检查目的地址决定是否接收。**必须解决"多台同时发怎么办"**——这就是介质访问控制的由来。局域网普遍采用广播式
- **点对点网络**：每条物理线路只连接一对节点，没有争用问题，但两台没有直连的机器之间必须靠中间节点**存储转发**——这就是路由选择的由来

**一句话判据**：信道是不是被多方共享。共享 → 广播式 → 需要 MAC 协议；独占 → 点对点 → 需要路由算法。整本《计算机网络》的数据链路层和网络层，基本就是沿这两条分支各自展开的。

### 按拓扑结构

| 拓扑结构 | 特点 | 弱点 | 常用于 |
| --- | --- | --- | --- |
| 总线型 | 建网容易，增减节点方便，节省线路 | 重负载时冲突多、效率低；总线故障影响全网 | 早期以太网 |
| 星型 | 便于集中控制和管理，单条线路故障只影响一个节点 | 中央设备是单点故障源 | 局域网（最常见） |
| 环型 | 信号沿环单向传输，时延可预测 | 单点故障可能断环 | 令牌环局域网 |
| 网状型 | 冗余路径多，可靠性高 | 控制复杂，线路成本高 | 广域网核心 |

注意**物理拓扑与逻辑拓扑可以不一致**：用集线器连成的星型网络，逻辑上仍是一条总线（所有端口共享一个冲突域）；换成交换机之后，物理上还是星型，逻辑上才真正变成点对点。

### 按传输介质

有线网络（双绞线、同轴电缆、光纤）和无线网络（无线电、微波、红外、卫星）。

## 性能指标一览

这里只给概念，公式与推导在[[04_计算机网络_CN/overview/performance-metrics.md|性能指标]]：

- **速率**：数据的传送速率，单位 bit/s。通常指**额定速率**，不是实际运行速率
- **带宽**：两个含义——信号的频带宽度（Hz），或网络中某信道的**最高数据率**（bit/s）。本书中默认第二种
- **吞吐量**：单位时间内通过某网络（或信道、接口）的**实际数据量**，上限是带宽
- **时延**：发送时延 + 传播时延 + 处理时延 + 排队时延
- **时延带宽积**：传播时延 × 带宽，代表链路上"正在飞行"的比特数
- **往返时间 RTT**：数据往返一次所需的时间
- **利用率**：信道有数据通过的时间占比。利用率上升时时延**非线性**上升

## 易混淆知识点

**1. 分组交换一定比电路交换好吗？**

不一定，判据是**数据量与建连时间的比值**。例题 1 的边界检查算得很清楚：3000 比特时电路交换要 218 ms、分组交换只要 20 ms；换成 30 Mbit 之后电路交换 30.2 s、报文交换 90 s，电路交换反而赢。**电路交换的发送时延只算一次**，这个优势随数据量线性放大；建连时间是固定成本，会被大数据量摊薄。

**2. 报文交换和分组交换的根本区别**

二者都是存储转发，区别只在**存储转发的单位**。因为分组小，才能让"前一个分组在下一跳传"与"后一个分组在本跳传"同时发生，总发送次数从 k⋅n 降到 k+n−1。**流水线是分组交换低时延的唯一来源**，不是"因为分组小所以快"这种含糊说法。

**3. 分组越小越好吗？**

不是。总时延 = 流水线收益项 (k−1)DnR + 首部开销项 nHR + 常数，最优分组数 n∗=(k−1)D/H。小于 n∗ 时切细有收益，大于 n∗ 时首部开销反噬。

**4. 数据报 / 虚电路容易与"电路交换"混淆**

虚电路建立的是**逻辑通路**：链路带宽仍然是统计复用的，别的虚电路照样能在同一条链路上传数据。电路交换建立的是**物理独占通路**，通信期间那份资源谁也拿不走。判据：**资源是被预留了，还是只被记了一笔路径**。

**5. 边缘部分 / 核心部分与资源子网 / 通信子网是不是一回事？**

不是同一个切面。前者按**位置**分（谁在网络的两端、谁在中间），后者按**职责**分（谁负责传输、谁负责使用）。主机上的 TCP/IP 下三层，位置上在边缘、职责上属通信子网。

**6. 局域网一定是广播式、广域网一定是点对点吗？**

这是"通常如此"而不是定义。分类依据是**信道是否被多方共享**：早期总线以太网、Wi-Fi 是共享信道所以要 CSMA；全交换机组网的以太网每个端口一个冲突域，逻辑上已经是点对点了。反过来无线广域网也可以是广播式。

## 本节小结

- 计算机网络 = **自治**的计算机 + **互连**的通信通道 + 网络软件。"自治"排除了主机-哑终端系统，"互连"排除了靠 U 盘的资源共享。
- **internet 是通用名词**（任意互连而成的网络），**Internet 是专用名词**（全球那一个 TCP/IP 网络）；用户经 ISP 接入，ISP 分本地/地区/主干三级。
- 网络组成有三个正交切面：**组成部分**（硬件/软件/协议）、**工作方式**（边缘/核心）、**功能组成**（资源子网/通信子网）。核心 ≈ 通信子网、边缘 ≈ 资源子网，但一个按位置分、一个按职责分。
- 网络的**功能**有五条：**数据通信**（最基本、最重要）、资源共享、分布式处理、提高可靠性（各机互为备份）、负载均衡。后四条都要靠第一条兜底——没有可靠的数据通信，"互为备份"反而会因同步失败而降低可靠性。
- 交换 = **动态分配传输线路资源**。三种方式的差别全在"一次占用的粒度"：电路交换占整条通路整段时间，报文交换占一跳链路一整份报文时间，分组交换占一跳链路一个分组时间。
- **电路交换**必须经历建立连接 → 通话 → 释放连接三步；优点是直达、按序、无冲突、可保证带宽，缺点是建连慢、独占线路利用率低、无法差错控制。适合"通信时间远大于建连时间且期间持续有数据"的场景。
- **报文交换**存储转发整份报文：无须建连、线路灵活、可差错控制，但每一跳都要把整份报文收完，时延被跳数乘一遍，且缓存无上限。
- **分组交换**存储转发定长受限的分组：**流水线是它比报文交换快的唯一来源**，总发送次数从 k⋅n 降到 k+n−1。代价是每分组一份首部、可能乱序、无法保证带宽。
- 三个可直接套用的时延式：T报文=kDR+kd；T分组=(k+n−1)D/n+HR+kd；T电路=Ts+DR+kd。**电路交换的发送时延只算一次**是它唯一的结构性优势。
- **最优分组数 n∗=(k−1)D/H**：流水线收益 ∝1/n、首部开销 ∝n，必然交出一个最低点。所以"分组越小越好"只在 n<n∗ 时成立。跳数越多该切得越小，首部越大该切得越大。
- 分组交换内部分**数据报**（每分组带完整地址、独立选路、可能乱序、可靠性交高层）与**虚电路**（带虚电路号、沿固定路径、按序、节点故障导致整条虚电路失效）。因特网用数据报。虚电路是**逻辑**通路，与电路交换的**物理独占**通路不同。
- 网络分类五个维度：覆盖范围（PAN/LAN/MAN/WAN）、使用者（公用/专用）、交换方式、**传输技术（广播式/点对点）**、拓扑结构。其中传输技术最关键——共享信道推出介质访问控制，独占链路推出路由选择，这是数据链路层与网络层两大分支的源头。
- 物理拓扑不等于逻辑拓扑：集线器组的星型网逻辑上是总线，交换机组的星型网逻辑上才是点对点。

## 教材出处

- 谢希仁《计算机网络》（第 7 版）印刷版 **p13**（1.3.2 互联网的核心部分）给出电路交换的定义与三步骤：这种必须经过"**建立连接（占用通信资源）→ 通话（一直占用通信资源）→ 释放连接（归还通信资源）**"三个步骤的交换方式称为电路交换；同页强调"电路交换的一个重要特点就是在通话的全部时间内，通话的两个用户始终占用端到端的通信资源"。
- 同书印刷版 **p13** 定义交换本身："从通信资源的分配角度来看，交换（switching）就是按照某种方式**动态地分配传输线路的资源**。"
- 同书印刷版 **p16** 把三种方式在数据传送阶段的特点归纳为三句话：电路交换是"整个报文的比特流连续地从源点直达终点"，报文交换是"整个报文先传送到相邻节点，**全部存储下来后**查找转发表，转发到下一个节点"，分组交换是"**单个分组**（这只是整个报文的一部分）传送到相邻节点，存储下来后查找转发表，转发到下一个节点"。
- 同书印刷版 **p17**（图 1-11 下方）给出本篇例题 1 边界检查所依据的那句结论："若要连续传送大量的数据，且其传送时间远大于连接建立时间，则电路交换的传输速率较快……由于一个分组的长度往往远小于整个报文的长度，因此分组交换比报文交换的时延小，同时也具有更好的灵活性。"
- 同书印刷版 **p16**（表 1-1 分组交换的优点）把分组交换的优点归为四条：高效（动态分配传输带宽、对通信链路逐段占用）、灵活（为每一个分组独立地选择最合适的转发路由）、迅速（以分组作为传送单位，不先建立连接就能发送）、可靠（保证可靠性的网络协议 + 分布式多路由的分组交换网）。
- 同书印刷版 **p3** 说明术语来历：全国科学技术名词审定委员会将 internet、internetwork、interconnection network 的译名均推荐为"互联网"，注释中说"又称互连网"，并提醒"联"和"连"并不是同义字。[[04_计算机网络_CN/overview/architecture.md|下一篇体系结构与参考模型]]
