## 知识框架

本节回答 5 个问题：

- 为什么不能用一台服务器存下全世界的域名？分布式是怎么切分的——按"域"切还是按别的什么切？
- 递归查询和迭代查询的差别，能不能用一句不依赖记忆的话说清？
- 一次完整解析要发多少个报文？递归和迭代的报文数一样吗？时延呢？
- 缓存到底省掉了哪一段？只缓存了半路的地址算不算命中？
- DNS 为什么用 UDP？既然用了 UDP，为什么又保留 TCP 端口 53？

其中第 3 个问题是能算的：给定各段单程时延，两种方式的报文数相同、总时延不同，差在"谁替谁跑腿"。这是本节唯一需要动笔的地方。

## 一、DNS 要解决什么，以及为什么必须分布

用户与互联网上某台主机通信必须知道对方的 IP 地址，但人记不住 32 位地址。DNS 的功能就是**把便于人使用的机器名字转换为 IP 地址**。

追问一层：**机器在处理 IP 数据报时为什么不直接用域名？** 因为 IP 地址长度是固定的 32 位（IPv6 是 128 位，也定长），而域名长度不固定，定长字段机器处理起来快得多。这是"分层各司其职"的一个具体例子：人友好的标识在应用层，机器友好的标识在网络层。

再追问一层：**为什么不能只用一台域名服务器？** 教材给了两条理由，二者性质不同：

- **性能**：互联网规模太大，单台服务器会因过负荷而无法工作；
- **可靠性**：一旦这台服务器出故障，整个互联网就会瘫痪。

所以 DNS 被设计成**联机分布式数据库系统**，并采用客户服务器方式。它的效率来源是"大多数名字都在本地解析，只有少量解析需要在互联网上通信"。

## 二、层次域名空间

### 语法规则

域名由**标号（label）序列**组成，标号之间用点（英文句号）隔开。级别最低的写在最左边，最高的顶级域名写在最右边：

```
mail . cctv . com
 |      |      |
三级域名  二级域名  顶级域名
```

DNS 对标号的规定（这几条是有确切数值的，值得记）：

| 规则 | 数值 |
| --- | --- |
| 单个标号长度 | 不超过 **63** 个字符 |
| 完整域名总长 | 不超过 **255** 个字符 |
| 字符集 | 英文字母、数字，以及连字符 `-`；不能有其他标点 |
| 大小写 | **不区分**（`CCTV` 与 `cctv` 等效） |

DNS **既不规定一个域名要包含多少级下级域名，也不规定每一级代表什么意思**。各级域名由其上一级的管理机构管理，最高的顶级域名由 ICANN 管理。

> [!WARNING]
>

域名里的"点"和 IP 地址里的"点"没有对应关系

点分十进制 IP 地址一定包含 **3 个**点；域名里点的数目**不一定是 3 个**（`com` 有 0 个，`www.pku.edu.cn` 有 3 个，`a.b.c.d.e.com` 有 5 个）。这两个"点"的含义完全不同：前者是 4 个字节的分隔符，后者是层次的分隔符。

还有一条概念边界：**域名只是逻辑概念，不代表计算机所在的物理地点**。互联网的名字空间按机构组织划分，与物理网络无关，与 IP 地址中的"子网"也没有关系。所以"同一个二级域名下的主机一定在同一个网段"是错的。

### 顶级域名的三类

| 类型 | 说明 | 例子 |
| --- | --- | --- |
| 国家顶级域名 nTLD（又记 ccTLD） | 采用 ISO 3166 国家代码 | `cn`、`us`、`uk`、`jp` |
| 通用顶级域名 gTLD | 按用途分类 | 最先确定的 7 个：`com`、`net`、`org`、`int`、`edu`、`gov`、`mil` |
| 基础结构域名 | **只有一个**，用于反向域名解析 | `arpa` |

我国在 `cn` 下把二级域名分成两大类：**类别域名** 7 个（`ac`、`com`、`edu`、`gov`、`mil`、`net`、`org`）和**行政区域名** 34 个（`bj`、`js` 等）。

注意 `edu`、`gov`、`mil` 这三个作为**顶级**域名时是美国专用的，而作为 `cn` 下的**二级**域名时指中国的对应机构——`edu.cn` 与 `edu` 不是同一件事。

### 域名树

中央电视台和清华大学都有一台机器叫 `mail`，但它们的域名不同（`mail.cctv.com` 与 `mail.tsinghua.edu.cn`）——**唯一性由整条路径保证，不由叶子的名字保证**。一个单位拿到域名后，可以自己决定是否继续划分子域，**不必由上级机构批准**。

## 三、域名服务器：按"区"划分，不按"域"

这是本节最容易被跳过、却直接决定"权威域名服务器管什么"的一条。

如果每一级域名都配一台域名服务器，服务器数量太多、效率反而低。DNS 的办法是划分**区（zone）**：

**一个服务器所负责管辖的（有权限的）范围叫作区。区可能等于或小于域，但一定不能大于域。**

举例：`abc` 公司有下属部门 `x` 和 `y`。

- 若公司只设一个区 `abc.com`，那么**区 `abc.com` 和域 `abc.com` 指同一件事**；
- 若公司划分两个区 `abc.com` 与 `y.abc.com`，则域 `abc.com` 里含两个区，各设一台权限域名服务器。

一句话：**DNS 服务器的管辖范围以"区"为单位，不以"域"为单位；区是域的子集**。另外，一个区中的所有节点必须是**连通**的——不能把域树上互不相邻的两块拼成一个区。

### 四类域名服务器

| 类型 | 知道什么 | 在层次结构里吗 |
| --- | --- | --- |
| **根域名服务器** | 所有顶级域名服务器的域名和 IP 地址 | 在，最高层 |
| **顶级域名服务器（TLD）** | 在该顶级域名下注册的所有二级域名 | 在 |
| **权限域名服务器** | 它所负责的那个**区**内全部主机的域名→IP 映射 | 在 |
| **本地域名服务器** | 缓存 + 代主机去查 | **不在**，独立于这个层次之外 |

几条容易被记成错版本的细节：

- **根域名服务器通常不直接给出答案**。它"也没有存放这种信息"，只告诉本地域名服务器下一步该找哪个顶级域名服务器。
- **权限域名服务器也可能给不出最终答案**。当它管不到被查的那一段时，同样是告诉客户下一步该找哪个权限域名服务器。
- **13 是"域名"的个数，不是机器的台数**。全世界根域名服务器只使用 13 个不同 IP 地址的域名（`a.rootservers.net` … `m.rootservers.net`），但实际是 13 **套装置**，每套在很多地点安装镜像，靠**任播（anycast）**让路由把 DNS 客户送到最近的一台。
- **主域名服务器与辅助域名服务器**：为提高可靠性，数据会复制到几台服务器。**更改数据只能在主域名服务器上进行**，主服务器定期把数据复制到辅助服务器——这保证了一致性，也解释了为什么区传送需要 TCP。
- **本地域名服务器离用户很近**，一般不超过几个路由器的距离；如果被查的主机恰好属于同一个本地 ISP，它自己就能答，根本不用问别人。

## 四、域名解析过程

### 两种查询方式：一句话判据

不要背"谁负责查"，记这一句：

**递归 = 我替你查完再给你答案；迭代 = 我只告诉你下一个该问谁，你自己去问。**

由此立刻能推出负担落在谁身上：递归把负担压给**被查方**（它要一路查到底），迭代把负担留给**查询方**（它要一轮轮自己发请求）。

实际部署里通常是混合的：**主机 → 本地域名服务器用递归**（主机太弱，也不该让每台主机都懂 DNS 层次），**本地域名服务器 → 根/TLD/权限用迭代**（否则根服务器要替全世界跑腿，扛不住）。

但要留一条边界：**本地域名服务器也可以采用递归**，取决于最初的查询请求报文里设置的要求。所以"本地到根一定是迭代"是错的，正确说法是"通常采用迭代"。

### 教材原图：两种方式的完整 8 步

假定主机 `m.xyz.com` 要查主机 `y.abc.com` 的 IP 地址。

图源：谢希仁《计算机网络》（第 7 版）「DNS 查询举例」(a)，印刷 p267。图中虚线框内是迭代查询部分：箭头全部以本地域名服务器为一端来回，根与顶级域名服务器之间**没有**直接连线——它们从不互相转发查询，只把地址回给本地服务器。

8 个步骤是：

- 主机 `m.xyz.com` 向本地域名服务器 `dns.xyz.com` 进行**递归**查询
- 本地域名服务器向**根**域名服务器查询（下面转为迭代）
- 根告诉本地：下一步应查顶级域名服务器 `dns.com` 的 IP 地址
- 本地向顶级域名服务器 `dns.com` 查询
- `dns.com` 告诉本地：下一步应查权限域名服务器 `dns.abc.com` 的 IP 地址
- 本地向权限域名服务器 `dns.abc.com` 查询
- `dns.abc.com` 告诉本地所查主机的 IP 地址
- 本地把查询结果告诉主机 `m.xyz.com`

图源：谢希仁《计算机网络》（第 7 版）「DNS 查询举例」(b)，印刷 p267。与 (a) 对照着看差别一目了然：这张图里根与顶级域名服务器之间**有**箭头，顶级域与权限之间也有——因为每一级都在"替上一级去问"，答案要沿着同一条链原路返回。本地域名服务器只出现在链条的两端。

**两张图放在一起，差别可以归纳成一句**：迭代图里所有箭头都连着本地服务器（星形），递归图里箭头首尾相接形成一条链（链形）。

### 报文数：两种方式都是 8 个

这一点常被想当然地记成"递归少一些"。教材对两张图都明确写了 8 个 UDP 报文。原因是：

- 迭代：主机↔本地 1 个来回（2 个），本地分别问根、TLD、权限各 1 个来回（6 个），共 8 个；
- 递归：主机↔本地、本地↔根、根↔TLD、TLD↔权限各 1 个来回，也是 4 个来回共 8 个。

**报文数相同，差的是这些报文在谁与谁之间跑。** 这直接决定了时延和负载分布——下面算一次。

### 例题 1：两种查询方式的报文数与总时延

**题目**（自造数据）：主机 `m.xyz.com` 查询 `y.abc.com`。各段**单程**传播+处理时延如下表，本地域名服务器缓存为空，忽略报文传输时延。分别求（1）本地采用迭代、（2）本地采用递归两种情形下的报文数与总时延。

| 链路段 | 单程时延 |
| --- | --- |
| 主机 ↔ 本地域名服务器 | 2 ms |
| 本地 ↔ 根域名服务器 | 50 ms |
| 本地 ↔ 顶级域名服务器 | 30 ms |
| 本地 ↔ 权限域名服务器 | 20 ms |
| 根 ↔ 顶级域名服务器 | 20 ms |
| 顶级 ↔ 权限域名服务器 | 15 ms |

**第 1 步：确定报文数。** 两种方式各需 4 个来回，即 4×2=8 个 UDP 报文。

*这一步为什么这么做*：报文数只取决于"问了几级"，与谁去问无关。被查的域名有三级要走（根、TLD、权限），加上主机与本地之间的那一次，共 4 个来回。

**第 2 步：迭代情形，把 8 段路逐段列出来。** 迭代时每一段都以本地服务器为一端：2⏟主机→本地+50+50⏟本地↔根+30+30⏟本地↔TLD+20+20⏟本地↔权限+2⏟本地→主机=204 ms

*这一步为什么这么做*：迭代的每一次查询都是"本地发出、本地收回"，所以每一级都要计**双程**。这正是"迭代图是星形"在数值上的体现。

**第 3 步：递归情形，按链条顺序列出来。**2⏟主机→本地+50⏟本地→根+20⏟根→TLD+15⏟TLD→权限+15⏟权限→TLD+20⏟TLD→根+50⏟根→本地+2⏟本地→主机=174 ms

*这一步为什么这么做*：递归时答案沿原链返回，每一段各走一个来回，但走的是**服务器之间**那些较短的链路（根↔TLD 只有 20 ms，而本地↔TLD 要 30 ms）。所以递归省下的是"绕回本地再出去"的那段路。

**第 4 步：比较。**

|  | 报文数 | 总时延 | 负担落在谁身上 |
| --- | --- | --- | --- |
| 本地采用迭代 | 8 | **204 ms** | 本地域名服务器（发 4 次、收 4 次） |
| 本地采用递归 | 8 | **174 ms** | 根、TLD 服务器（要替下家跑腿） |

**答**：两种方式都是 8 个报文；迭代 204 ms，递归 174 ms，递归快 30 ms。

**这个结论要不要推广？** 不要。递归更快只在"服务器之间的链路比本地到各级服务器的链路更短"时成立——本例里根↔TLD（20 ms）确实比本地↔TLD（30 ms）短。若根与 TLD 隔在地球两端，递归反而更慢。**真正稳定的差别不是快慢，而是负载落在谁身上**：这才是根域名服务器坚持只做迭代的原因。

### 例题 2：缓存命中的两种程度

**题目**（同上表数据，本地采用迭代）：（1）本地域名服务器缓存里已有 `y.abc.com` 的 A 记录；（2）缓存里没有 A 记录，但有 `com` 顶级域名服务器的地址。分别求报文数与时延。

**情形 1：直接命中。** 本地不必问任何人：报文数=2,t=2+2=4 ms

**情形 2：只缓存了半路。** 本地可以**跳过根**，直接向 `com` 顶级域名服务器发查询：报文数=2+2×2=6,t=2+(30+30)⏟TLD+(20+20)⏟权限+2=104 ms

*这一步为什么这么做*：缓存里存的不一定是最终答案，也可能是"从何处获得域名映射信息的记录"。存了 TLD 地址就等于把 4 个来回砍成 3 个——**这是缓存最主要的收益来源**，因为它减掉的恰好是最贵的那一段（本地↔根，双程 100 ms）。

**答**：情形 1 为 2 个报文、4 ms；情形 2 为 6 个报文、104 ms。相比全程 204 ms，情形 2 省了 100 ms（约 49%），而这 100 ms 全部是根域名服务器的负担。

这两个数字合起来解释了教材那句话：缓存"不仅可以大大减轻根域名服务器的负荷，而且也能够使互联网上的 DNS 查询请求和回答报文的数量大为减少"。

### 完整流程（混合方式）

## 五、DNS 缓存

主机和域名服务器都会缓存查询结果。缓存里存的**不只是最终 IP**，还包括"从何处获得域名映射信息"的记录——所以才有例题 2 情形 2 那种"半路命中"。

一致性怎么保证？靠**计时器 + TTL**：

- 域名服务器为每项内容设置计时器，超过合理时间就删掉（教材举例"每个项目只存放两天"）；
- 权限域名服务器在回答查询时，**在响应中指明这条绑定的有效存在时间**（TTL）。

这里有一个明确的权衡，值得单独记：

**增大 TTL → 减少网络开销，但域名改动后旧记录会多存活一段时间；减小 TTL → 提高域名转换的准确性，但查询报文变多。**

缓存不只在服务器上。许多主机在启动时就从本地域名服务器下载名字和地址数据库，并维护自己最近使用域名的高速缓存，只在本地缓存找不到时才去问域名服务器。这解释了浏览器地址栏里"改了 DNS 却不生效"的现象——链条上有**主机缓存 → 本地服务器缓存**两级，都要过期才行。

## 六、资源记录类型

DNS 中每条记录称为**资源记录**（Resource Record, RR），格式为 (域名, TTL, 类别, 类型, 值)。

| 类型 | 含义 | 示例 |
| --- | --- | --- |
| A | 域名 → IPv4 地址 | `www.example.com` → `93.184.216.34` |
| AAAA | 域名 → IPv6 地址 | `www.example.com` → `2606:2800:…` |
| CNAME | 域名的别名（指向另一个**域名**） | `blog.example.com` → `www.example.com` |
| MX | 邮件交换记录（收该域邮件的服务器） | `example.com` → `mail.example.com`（优先级 10） |
| NS | 该区的权限域名服务器 | `example.com` → `ns1.example.com` |
| PTR | IP 地址 → 域名（反向解析，走 `arpa`） | `93.184.216.34` → `www.example.com` |

两条链式关系要理清：

- **CNAME 不直接给 IP**：查到 CNAME 后还要再查目标域名的 A 记录，所以一次"看似一步"的解析可能是两趟。
- **MX 也不直接给 IP**：MX 返回的是邮件服务器的**域名**，发送方 MTA 还要再查它的 A 记录才知道往哪连（见[[04_计算机网络_CN/application/email.md|电子邮件]]）。

`A` 记录是最常见的一种，凡是题面只说"域名解析"而未指明类型，默认就是在查 A 记录。

## 七、DNS 与传输层

**DNS 使用端口 53**，UDP 和 TCP 都用：

| 场景 | 传输层 | 原因 |
| --- | --- | --- |
| 普通查询/响应 | **UDP** 53 | 报文短小、一问一答，省去建连的开销 |
| 响应超过 512 字节 | TCP 53 | UDP 报文长度受限，需要可靠分段传输 |
| 区传送（主→辅助服务器同步整个区的数据） | TCP 53 | 数据量大且必须完整、有序、可靠 |

**为什么查询用 UDP 而不用 TCP？** 逐层追问一遍：

- DNS 查询一问一答，用 UDP 只需一个请求包 + 一个响应包；若用 TCP，三报文握手 + 数据 + 四报文释放，代价是好几倍。
- DNS 对实时性敏感——它是几乎所有网络应用的第一步，它慢一切都慢。
- 丢包的代价很低：超时重发一个小报文即可，不值得为此维护连接状态。
- 服务器侧还有一层考虑：UDP 无连接，服务器不必为每个查询保存连接状态，同样的硬件能扛住多得多的并发。

**边界**：DNS 并非"只用 UDP"。响应超过 512 字节或做区传送时会切换到 TCP。所以"DNS 只使用 UDP"是错的，"DNS 的查询通常使用 UDP"才对。

## 易混淆知识点

**1. 递归和迭代不要搞反**

递归 = 被查方替你查到底，迭代 = 被查方告诉你去问谁。默认部署是"主机→本地"递归、"本地→其他"迭代，但**本地到根也可以是递归**，取决于查询请求报文里的设置。写成"必须"就错了。

**2. 两种方式的报文数一样，都是 8 个**

差别在时延分布和负担归属，不在报文条数。

**3. 区（zone）不等于域（domain）**

权限域名服务器管辖的是**区**，区可以等于域也可以小于域，但**绝不能大于域**。"一个域一定对应一台权限域名服务器"是错的。

**4. 本地域名服务器不在 DNS 层次结构中**

根、TLD、权限三者构成层次结构；本地域名服务器独立于这个层次，它只是主机的代理 + 缓存。

**5. 13 是根域名服务器的"域名"个数，不是机器台数**

13 个不同 IP 地址的域名 `a.rootservers.net` … `m.rootservers.net`，背后是 13 套装置、在全球很多地点部署镜像，靠任播就近服务。

**6. 根域名服务器一般不直接给出被查域名的 IP**

它没有存这种信息，只指路到顶级域名服务器。权限域名服务器同理，管不到时也只指路。

**7. DNS 不只用 UDP**

区传送和大响应用 TCP，端口同样是 53。

**8. CNAME 与 MX 都不直接返回 IP**

两者返回的都是**域名**，还要再查一次 A 记录。所以"配了 MX 记录就不用配 A 记录"是错的。

**9. 域名的层次与 IP 的子网层次无关**

名字空间按机构组织划分，与物理网络、与 IP 子网划分都没有关系。域名相邻不意味着地址相邻。

**10. 域名里点的个数不固定**

IP 点分十进制固定 3 个点，域名不是。

## 本节小结

按这条主线能自己重讲一遍就算过：

- **DNS 把域名转换成 IP**；机器不用域名是因为 IP 定长好处理。必须分布式的两条理由是**性能**（单机过负荷）和**可靠性**（单点故障即全网瘫痪）。
- **层次域名空间**：标号序列、右高左低；单标号 ≤ 63 字符、全域名 ≤ 255 字符、不区分大小写。顶级域三类：国家（ccTLD）、通用（gTLD，最先 7 个）、基础结构（只有 `arpa`）。域名是逻辑概念，与物理位置和 IP 子网无关。
- **服务器按"区"划分不按"域"**：区 ⊆ 域，区内节点必须连通。四类服务器中前三类在层次里、本地服务器不在。根只有 13 个域名而非 13 台机器，靠任播分流；改数据只能在主域名服务器上做。
- **递归 vs 迭代的判据**："替你查到底"还是"告诉你问谁"。由此推出负担归属：递归压被查方、迭代压查询方。默认混合部署，但都不是强制。
- **报文数两种方式都是 8 个**；时延差在报文跑在哪些链路上。用例题那组数据能自己重算出 204 ms（迭代）与 174 ms（递归），并且知道"递归更快"依赖于服务器之间链路更短这个前提。
- **缓存分两级、两种程度**：主机缓存与本地服务器缓存；命中最终 A 记录（4 ms / 2 报文）与只命中半路的 TLD 地址（104 ms / 6 报文）都算命中，后者省掉的正是最贵的那段。一致性靠 TTL，TTL 大小是"开销 ↔ 准确性"的权衡。
- **资源记录**：A / AAAA / CNAME / MX / NS / PTR；CNAME 与 MX 返回的都是域名，需要再查一次 A。
- **传输层**：查询用 UDP 53（短小、一问一答、丢了重发便宜、服务器不留状态），区传送与大响应用 TCP 53。

## 教材出处

- **谢希仁《计算机网络》（第 7 版）印刷 p261**，6.1.1 节：「从理论上讲，整个互联网可以只使用一个域名服务器……然而这种做法并不可取。因为互联网规模很大，这样的域名服务器肯定会因过负荷而无法正常工作，而且一旦域名服务器出现故障，整个互联网就会瘫痪。」——本篇"为什么必须分布"两条理由的出处。同页还写明「为什么机器在处理 IP 数据报时要使用 IP 地址而不使用域名呢？这是因为 IP 地址的长度是固定的 32 位……而域名的长度并不是固定的，机器处理起来比较困难」。
- **印刷 p262**，6.1.2 节：「DNS 规定，域名中的标号都由英文字母和数字组成，每一个标号不超过 63 个字符……由多个标号组成的完整域名总共不超过 255 个字符。」同页：「域名中的『点』和点分十进制 IP 地址中的『点』并无一一对应的关系。」以及「DNS 既不规定一个域名需要包含多少个下级域名，也不规定每一级的域名代表什么意思」。
- **印刷 p263**，6.1.2 节：顶级域名三大类（国家顶级域名 nTLD、通用顶级域名 gTLD 最先确定的 7 个、基础结构域名只有 `arpa` 一个），以及我国 `cn` 下"类别域名"7 个与"行政区域名"34 个的划分。
- **印刷 p264**，6.1.2 节末：「互联网的名字空间是按照机构的组织来划分的，与物理的网络无关，与 IP 地址中的『子网』也没有关系。」6.1.3 节开头：「一个服务器所负责管辖的（或有权限的）范围叫作区(zone)……但在一个区中的所有节点必须是能够连通的。」
- **印刷 p265**：「区可能等于或小于域，但一定不能大于域」；以及四类域名服务器的划分。
- **印刷 p266**：「全世界的根域名服务器只使用 13 个不同 IP 地址的域名……实际上，在互联网中是由 13 套装置构成这 13 组根域名服务器的」「由于根域名服务器采用了任播(anycast)技术，因此当 DNS 客户向某个根域名服务器的 IP 地址发出查询报文时，互联网上的路由器就能找到离这个 DNS 客户最近的一个根域名服务器」；以及「在许多情况下，根域名服务器并不直接把待查询的域名直接转换成 IP 地址（根域名服务器也没有存放这种信息），而是告诉本地域名服务器下一步应当找哪一个顶级域名服务器进行查询」。
- **印刷 p267**，6.1.4 节：递归查询与迭代查询的定义原文——「所谓递归查询就是：如果主机所询问的本地域名服务器不知道被查询域名的 IP 地址，那么本地域名服务器就以 DNS 客户的身份，向其他根域名服务器继续发出查询请求报文（即替该主机继续查询），而不是让该主机自己进行下一步的查询」；「迭代查询的特点是这样的：当根域名服务器收到本地域名服务器发出的迭代查询请求报文时，要么给出所要查询的 IP 地址，要么告诉本地域名服务器：『你下一步应当向哪一个域名服务器进行查询』」。同页末句是本篇那条边界的依据：「当然，本地域名服务器也可以采用递归查询，这取决于最初的查询请求报文的设置要求使用哪一种查询方式。」两张图即本篇引用的图 6-4(a)(b)。
