# 输入输出应用程序接口

2026 大纲 **五（一）4 输入/输出应用程序接口**，补充说明点名四项：**字符设备接口**、**块设备接口**、**网络设备接口**、**阻塞/非阻塞 I/O**。

## 速查

| 🔴 **"接口"在这一章出现三次，指三样东西** | **硬件 I/O 接口** = 设备控制器（[[01_操作系统_OS/05_IO管理/device-concept.md|设备的基本概念与分类]]，插在主板上）；**应用程序 I/O 接口** = 内核向应用暴露的系统调用与三套设备语义（本篇，写在头文件里）；**驱动程序接口** = 驱动向内核暴露的一组同名函数（[[01_操作系统_OS/05_IO管理/driver-interface.md|设备驱动程序接口]]） |
| --- | --- |
| 🔴 **统一的是调用形式，分开的是语义单位** | 都用文件描述符 + open/close/read/write；但同一句 `read` 对键盘、磁盘、网卡**背后能提供的保证完全不同**，硬合成一套要么退化成最小公倍数（磁盘的随机寻址都用不上），要么每个应用自己判断设备类型 |
| **字符设备接口** | 键盘、鼠标、打印机、串口、终端；单位是**单个字符**，**不可寻址**，核心操作 `get`/`put`，接口里不存在"块号"这个参数，只有"下一个" |
| **块设备接口** | 磁盘、SSD、U 盘；单位是**数据块**（512 B~4 KB），**可寻址**、可随机访问；`read`/`write` 指定块号，另有**内存映射文件接口** |
| **网络设备接口** | 网卡；用 **socket**：`socket`/`bind`/`listen`/`connect`/`send`/`recv` |
| 🔴 **网络为什么另起一套** | ① 要先**建立连接**、指定对端地址与端口——`read`/`write` 的参数表里没地方放 ② 一台主机同时有很多条连接，打开设备文件拿到的是**整块网卡**，分不清读的是哪条 ③ 数据是**报文**，有边界、可丢失、可乱序——块设备保证"写进去能原样读出"、字符设备保证"按序到达"，网络两条都不保证 |
| **内存映射接口省掉什么** | `read()` 路径上数据要走"设备 → 内核缓冲区 → 用户缓冲区"两趟，映射后**第二趟没有了**；代价是错误不再由返回值报告，而以缺页/访问异常出现（详见[[01_操作系统_OS/03_内存管理/memory-mapped-file.md|内存映射文件]]） |
| 🔴 **同名函数分属两条边界** | 本篇的 `open/read/write` 是**系统调用**（内核 → 应用，跨用户态/内核态，参数是 fd 与用户空间地址）；驱动接口里同名的是**内核内部的函数指针**（驱动 → 内核，全程内核态，参数是内核对象）。名字相同是刻意设计（下传时不必改名） |
| **`ioctl` 为什么必须留** | `read`/`write` 的参数表只能表达"从哪儿搬多少字节"；设置串口波特率、弹出光驱、查询磁盘几何**根本不是数据传输**。它是这套统一接口上**唯一合法的逃生口**，参数含义由具体设备自定义 |
| **阻塞 I/O（同步传输）** | 进程**自己**调阻塞原语从运行态转**阻塞态**、挂到设备等待队列；完成后由**中断处理程序**唤醒转**就绪态**。状态路径是 运行 → 阻塞 → 就绪 → 运行，中间**两次**转换 |
| **非阻塞 I/O（异步传输）** | 调用立即返回"**这一刻实际读到了多少字节**"，可能少于请求数甚至为 0；进程始终在就绪/运行态，必须自己**轮询** |
| 🔴 **非阻塞 ≠ 异步** | 判据是**谁把数据搬完**：非阻塞只保证"这次调用不卡住"，剩下的**进程自己**反复调 `read` 去搬；异步由**内核**搬完整批再通知进程**一次**。"非阻塞"回答"调用会不会卡"，"异步"回答"传输由谁完成" |
| 🔴 **选哪一种：看这个进程还有没有别的事可做** | 有（界面要保持响应、服务器同时伺候上千连接）→ 非阻塞或异步；没有（批处理读完才能算）→ **用阻塞更好**：让出 CPU 提高系统整体吞吐，空转轮询等于退回[[01_操作系统_OS/05_IO管理/io-control.md|轮询式 I/O 控制]]那种忙等 |

## 一、为什么"统一"里还要分三套

统一接口的目标是应用程序**用同一种调用形式**访问所有设备，Unix/Linux 把它推到极致叫"**一切皆文件**"——普通文件、设备、管道、socket 都通过文件描述符访问。但调用形式能统一，**语义单位统一不了**：

`read(fd, buf, 100)` 对键盘意味着"给我 100 个字符，来一个算一个"； 对磁盘意味着"从第 k 块开始给我 100 字节，我可以随时跳到第 900 块去读"； 对网卡意味着"从这条已建立的连接上收 100 字节，对端还可能随时断开"。

| 接口 | 适用设备 | 语义单位 | 能不能寻址 | 典型调用 |
| --- | --- | --- | --- | --- |
| **字符设备接口** | 键盘、鼠标、打印机、串口、终端 | 单个字符（字节流） | **不能** | `get`/`put`（每次一个字符）；库层再封装成行输入 |
| **块设备接口** | 磁盘、SSD、U 盘 | 数据块（512 B~4 KB） | **能**（每块有块号） | `read`/`write` 指定块号；另有**内存映射文件接口** |
| **网络设备接口** | 网卡 | 报文/字节流，且带**连接**语义 | 不适用 | `socket`/`bind`/`listen`/`connect`/`send`/`recv` |

字符设备由"不可寻址"派生出两条实际约定：**行缓冲**——逐字符调系统调用代价太高（每个字符一次用户态/内核态切换），所以终端驱动通常把输入攒成**一行**再交给应用，这就是在终端敲字符时按回车前程序收不到东西的原因，输入期间用户进程被挂起；**输出侧的阻塞条件**——进程把一行送入缓冲区后即可继续，若它已有第二行要输出而第一行还没被取完，进程就得阻塞。

网络则单独抽象出 **socket（套接字）**：它是**一条通信端点的抽象**，创建时指定协议族与类型，绑定本地地址，再连接到对端；之后才退化成"像文件一样"用文件描述符收发。**先有连接这层抽象，才谈得上"一切皆文件"。**

## 二、系统调用这一组名字

| 系统调用 | 功能 |
| --- | --- |
| `open` | 打开设备/文件，返回**文件描述符** |
| `close` | 关闭，释放描述符与相关内核结构 |
| `read` | 从设备读数据到用户缓冲区 |
| `write` | 把用户缓冲区数据写向设备 |
| `ioctl` | 设备特定的控制操作 |

这张表与[[01_操作系统_OS/05_IO管理/driver-interface.md|设备驱动程序接口]]那张长得几乎一样，是因为上层调用被逐层"下传"：应用调 `read` 系统调用 → 设备独立软件查到该设备的驱动 → **调用这个驱动的 `read` 函数指针**。

## 三、阻塞、非阻塞与异步

非阻塞与异步都"立即返回"，但**返回时数据在哪里、后面还要不要你自己动手**完全不同：

|  | **非阻塞 I/O** | **异步 I/O** |
| --- | --- | --- |
| 调用立即返回吗 | 是 | 是 |
| 返回时数据传完了吗 | **可能只传了一部分，甚至一点没传** | 没传完，但**内核承诺会替你传完** |
| 谁负责把数据搬进用户缓冲区 | **进程自己**——下次再调 `read` 接着搬 | **内核**——传完了才通知你 |
| 进程之后要做什么 | **反复查**（轮询），直到凑够需要的数据 | **什么都不用做**，等通知（信号/回调/完成事件） |
| 一次逻辑读要调几次 | 可能很多次 | **一次** |

一句话判据：**非阻塞把"等"推给进程自己去轮询；异步把"等"和"搬"都留在内核，只在全部完成时通知一次。**

## 四、统一接口的边界

有了这套接口，应用程序可以用相同的方式访问不同设备，差异被关在下面两层（设备独立软件与驱动）里。代价是：**统一接口表达不了的东西，只能靠 `ioctl` 和 socket 这类"专用出口"补**。这也是这一条大纲会把三套接口和阻塞/非阻塞一起点名的原因——它们描述的正是这套"统一"的边界在哪里。

## 本节小结

- **统一的是调用形式，分开的是语义单位**：字符设备按字符 get/put 且不可寻址；块设备按块 read/write 且可随机访问（另有内存映射形态，省掉内核缓冲区到用户缓冲区那次拷贝）；网络因连接语义、多条并发连接、报文不可靠三条特性而另起 socket。
- **同一组函数名分属两条边界**：本篇的是内核向应用的系统调用，驱动接口里的是驱动向内核的函数指针；`ioctl` 是统一接口上唯一合法的逃生口。
- **阻塞与非阻塞的差别落在进程状态上**（会不会被切走），**非阻塞与异步的差别落在谁把数据搬完**；进程还有别的事可做才用非阻塞/异步，否则阻塞反而提高系统整体吞吐。教材出处

- 字符设备输入时缓冲区暂存一行数据、输入期间用户进程被挂起，以及输出侧的阻塞条件：汤小丹《计算机操作系统》6.7.2 节，印刷 p210
- 系统调用与库函数的关系（C 库函数与系统调用大体一一对应，Win32 API 不一一对应）：同书 6.6.1 节，印刷 p205
- 同步传输即阻塞方式、异步传输即非阻塞方式：孙钟秀、费翔林《操作系统教程》（第 6 版）4.2.1 节，印刷 p129
