# I/O软件层次结构

2026 大纲 **五（一）3 I/O 软件层次结构**，补充说明点名四层：中断处理程序、驱动程序、设备独立软件、用户层 I/O 软件。

## 速查

| 🔴 **归层唯一判据** | **这一步的代码换一种设备要不要重写？** 要重写 → 驱动程序；不用重写但在内核态 → 设备独立软件；在用户态 → 用户层；由中断信号触发、处理的是中断机制本身 → 中断处理程序 |
| --- | --- |
| 🔴 **哪一层真正碰硬件细节** | 只有**驱动程序**。中断处理程序虽画在最底层，但它面对的是**硬件中断机制**（判中断源、保存现场、唤醒进程），不是某台设备的寄存器布局。层次图的上下表达的是调用与响应方向，不是"离硬件多近" |
| 🔴 **哪些跑在用户态** | 只有**用户层 I/O 软件**（库函数、系统调用封装、SPOOLing 守护进程）。其余三层全在内核态——四层之间只有第 1 层与第 2 层之间那一次态切换 |
| 🔴 **差错处理归哪层** | 按**能不能就地消化**分。驱动先扛（传输出错就地重传，连续多次仍失败才上报）；设备独立软件只管**驱动处理不了**的，并决定是终止请求进程还是只通知它。离硬件越近，越知道这个错误是不是暂时性的 |
| **两类错误** | **暂时性错误**（电源波动、网络丢包）靠重试纠正；**持久性错误**（掉电、盘面划痕）需查明原因，个别可由 OS 消化（如把坏块记入坏块表） |
| **术语对齐** | 考纲用词是「设备独立软件」，教材里的"与设备无关的 I/O 软件""设备无关性软件"是**同一层** |
| **LUT 三项** | 逻辑设备名 → 物理设备名 → 驱动程序入口地址。同一套机制支撑 **I/O 重定向**；同类设备只要还有一台可用，进程就不会被阻塞 |
| 🔴 **分层的代价** | ① **每多一道层间边界就多一次内存拷贝**（一次 `read()` 至少走"设备 → 内核缓冲区 → 用户缓冲区"两趟）② 一次用户态/内核态切换 ③ 参数校验、名字映射、权限检查的判断开销 |
| **代价的三个落点** | [[01_操作系统_OS/05_IO管理/buffer.md|缓冲公式]]里的 **M** 就是那次拷贝的量化；[[01_操作系统_OS/03_内存管理/memory-mapped-file.md|内存映射文件]]省掉内核缓冲区到用户缓冲区那一趟；**DMA** 省掉"设备 → CPU 寄存器 → 内存"里 CPU 寄存器那一趟 |
| **与「设备驱动程序接口」的分工** | 本篇讲**层**（四层职责、边界、每步归谁）；那篇讲**接口**（函数签名、五步处理过程、写法怎样随控制方式变） |

## 一、为什么要分层：四条设计目标推出四层

I/O 软件的分层不是"为了整齐"，是四条互相冲突的设计目标逼出来的：

| 设计目标 | 若不分层会怎样 | 于是切出哪一层 |
| --- | --- | --- |
| **设备无关性**：程序员写程序时尽量与具体物理设备无关 | 换一台打印机就要改应用程序 | **设备独立软件**（做命名映射、统一块大小） |
| **出错处理**：错误尽量在靠近硬件的位置解决，不让高层感知 | 一次磁盘重试的抖动要一路冒泡到用户程序 | **驱动程序**（重试）+ 设备独立软件（报告） |
| **同步/异步**：进程发出 I/O 后要能被阻塞、也要能继续跑 | 每个应用都得自己写等待与唤醒逻辑 | **中断处理程序**（负责唤醒） |
| **屏蔽硬件细节**：上层不该知道控制器有几个寄存器 | 每个应用都要懂每种控制器 | **驱动程序**（唯一与硬件相关的一层） |

推导链是这样的：

要让上层不改代码就能换设备 ⇒ 必须有一层专门吸收设备差异 ⇒ 这层必须知道寄存器布局，于是它**每种设备一份**（驱动程序） ⇒ 既然每种设备一份，那些**与设备无关的公共动作**（命名、权限、缓冲、分配、通用差错）就不该在每份驱动里各写一遍 ⇒ 抽出来放到驱动之上（设备独立软件） ⇒ 设备完成时要能主动通知，且这套通知机制是**硬件中断机制**而非某台设备的语义 ⇒ 再切一层（中断处理程序） ⇒ 应用不该直接调内核，得有库函数封装、有些功能（如 SPOOLing）在内核外做更合适 ⇒ 最上面一层（用户层 I/O 软件）

## 二、各层的功能

**第 1 层：用户层 I/O 软件（用户态）**——提供 open/close/read/write/ioctl 等系统调用接口（详见[[01_操作系统_OS/05_IO管理/io-api.md|输入输出应用程序接口]]）与库函数封装（`printf`、`scanf` 这类；C 库函数与系统调用大体一一对应，Windows 的 Win32 API 则**不**与系统调用一一对应）；[[01_操作系统_OS/05_IO管理/spooling.md|SPOOLing]] 的守护进程运行在内核之外，但仍属 I/O 系统。

**第 2 层：设备独立软件（内核态）**：

| 功能 | 具体做什么 |
| --- | --- |
| **驱动程序的统一接口** | 要求每个驱动与 OS 之间的接口相同或相近，使新增驱动变容易；并把抽象设备名映射到具体驱动的入口 |
| **设备保护** | 禁止用户直接访问设备，检查访问权限 |
| **缓冲管理** | 为字符设备与块设备分别配置单缓冲、双缓冲、循环缓冲、缓冲池，详见[[01_操作系统_OS/05_IO管理/buffer.md|缓冲区管理]] |
| **差错控制** | 只处理**驱动程序处理不了**的错误 |
| **设备分配与回收** | 独占设备必须由系统统一分配，详见[[01_操作系统_OS/05_IO管理/device-allocation.md|设备分配与回收]] |
| **提供与设备无关的逻辑块大小** | 不同磁盘扇区大小可能不同，本层把它们统一成大小一致的**逻辑数据块**再交给上层 |

设备独立性的落点是**逻辑设备表 LUT（Logical Unit Table）**：逻辑设备名→物理设备名→驱动程序入口地址

这和地址变换是同一个套路：应用程序里用**逻辑地址**、系统用**物理地址**，中间靠页表；应用程序里用**逻辑设备名**、系统用**物理设备名**，中间靠 LUT。都是"引入一层间接，换取上层不必知道下层的具体位置"。

**第 3 层：设备驱动程序（内核态）**——**唯一与设备硬件细节相关**的一层，每种设备一份。接收上层的抽象命令（`read` 一个盘块号），转换为具体的低层操作序列（柱面号、磁头号、扇区号，写进控制器寄存器），启动设备并在完成后向上报告。详见[[01_操作系统_OS/05_IO管理/driver-interface.md|设备驱动程序接口]]。

**第 4 层：中断处理程序（内核态）**——进程发出 I/O 请求后通常被阻塞，直到数据传输结束产生 I/O 中断。工作流程：① 检查设备状态寄存器，**判断中断产生的原因** → ② 若传输出错，向上层报告并尝试重新执行 → ③ 若正常结束，**唤醒**等待该数据传输的进程使其转为就绪态 → ④ 若还有排队的 I/O 请求，通知相关软件启动下一个。

## 三、一次读磁盘的完整流程：每步标出所属层次

| 步骤 | 所属层次 | 这一步为什么归它 |
| --- | --- | --- |
| ① | **用户层 I/O 软件** | 发生在用户态，只是发起调用 |
| ② ③ | **设备独立软件** | 参数校验、缓冲命中、名字映射、权限检查、排队与阻塞——全都与是哪台设备无关 |
| ④ | **设备驱动程序** | 要写具体控制器的寄存器、要知道用轮询还是 DMA，换设备就得重写 |
| ⑤ | **硬件** | 控制器与设备自己完成 |
| ⑥ ⑦ | **中断处理程序** | 面向硬件中断机制：判原因、报错误、唤醒进程 |
| ⑧ | **驱动程序 + 设备独立软件** | 驱动把数据从控制器搬出，设备独立软件拷入用户缓冲区 |
| ⑨ | **用户层 I/O 软件** | 回到用户态，系统调用返回 |

> [!TIP]
>

设备独立软件与驱动程序的界限是浮动的

教材提到，这条界限**因 OS 和设备而略有浮动**：出于效率考虑，本该由设备独立软件做的事有时被下放到驱动里。判据仍是"换设备要不要重写"，但具体系统的切法可以不同。

## 本节小结

- 四层自上而下是**用户层 I/O 软件 → 设备独立软件 → 设备驱动程序 → 中断处理程序 → 硬件**，由设备无关性、出错处理、同步/异步、屏蔽硬件细节四条设计目标推出；归层判据是"换设备要不要重写"。
- 设备独立软件管统一接口、设备保护、缓冲、差错控制、分配回收、统一逻辑块大小，并靠 **LUT** 落实设备独立性与 I/O 重定向；驱动是唯一碰硬件细节的一层，中断处理程序面向硬件中断机制并负责唤醒。
- 分层的代价是**每多一层多一次数据拷贝**外加一次态切换——缓冲公式里的 M、内存映射文件、DMA 分别对应这笔代价的量化与两种省法。教材出处

- 与设备无关软件的五项功能（驱动程序统一接口、缓冲、错误报告、分配与释放专用设备、提供与设备无关的块大小）、逻辑设备名与 I/O 重定向、逻辑设备表 LUT：汤小丹《计算机操作系统》6.5.1~6.5.4 节，印刷 p199–203
- 暂时性错误与持久性错误的区分及处理分工：同书 6.5.2 节，印刷 p200
- I/O 软件的四条设计考虑与分层结构、一次读操作的完整步骤、中断处理程序的工作流程：孙钟秀、费翔林《操作系统教程》（第 6 版）4.2.1~4.2.2 节，印刷 p129–131
