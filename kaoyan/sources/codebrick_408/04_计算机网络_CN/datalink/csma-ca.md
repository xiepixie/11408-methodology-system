本节回答 6 个问题：

## 一、无线为什么用不了 CSMA/CD

CSMA/CD 的立身之本是**边发边听**。谢希仁把无线做不到这件事的原因说得很清楚（印刷 p413）：

**原因一：收发信号强度差距太大，物理上盖不住。**

教材原文："由于无线信道的传输条件特殊，其信号强度的动态范围非常大，因此在 802.11 适配器上接收到的信号强度往往会远远小于发送信号的强度（信号强度可能相差百万倍）。因此无线局域网的适配器无法实现碰撞检测。"

**注意这是原理性的、不是工艺性的。** 站点自己的发射信号就在天线上，功率是接收信号的百万倍量级；要在这样的背景下分辨出远处一个微弱信号的叠加，等于在耳边喊话的同时去听隔壁房间的耳语。这不是"电路做精一点就行"。

**原因二：检测到"空闲"，信道其实未必空闲。**

无线电波传播距离有限、还会被障碍物挡住。于是出现有线网络里不存在的一类结构性问题——**隐蔽站**。

教材归纳的三条（印刷 p413）：

- 无线局域网的适配器无法实现碰撞检测；
- **检测到信道空闲，其实信道可能并不空闲**；
- 即使硬件上能实现碰撞检测，**也无法检测出隐蔽站问题带来的碰撞**。

**原因三：无线上一次碰撞的代价比有线大得多。**

教材（印刷 p413）："无线局域网显然可以使用 CSMA，但无法使用碰撞检测……一旦开始发送数据，就一定把整个帧发送完毕；一旦发生碰撞，整个信道资源的浪费就比较严重。"

以太网"不希望发生碰撞，但并不怕发生碰撞"，因为撞了立刻停、只浪费一小段；无线撞了要把整帧发完才知道。**代价结构变了，策略就必须从"检测"改成"避免"。**

## 二、隐蔽站与暴露站

### 隐蔽站（Hidden Station）

```
   A ←--通信范围--→ B ←--通信范围--→ C
          A 和 C 互相听不到对方
```

A 和 C 都能与 B 通信，但 A 与 C 相距过远（或中间有高楼、高山阻隔），**彼此检测不到对方发送的信号**。A 正在给 B 发数据时，C 监听信道发现"空闲"，也开始给 B 发——**在 B 处产生碰撞，而 A 和 C 谁都检测不到**。

教材的定义（印刷 p413）："所谓隐蔽站，就是它发送的信号检测不到，但却能产生碰撞。这里 C 是 A 的隐蔽站，A 也是 C 的隐蔽站。"

**注意"隐蔽"是相互的**，不是单向的。也不是"信号弱"，而是**在接收方处叠加、在发送方处不可见**——碰撞的发生地和检测地被空间分开了。这正是载波监听机制失效的根源：**监听的是"我这里"忙不忙，而碰撞发生在"对方那里"。**

### 暴露站（Exposed Station）

```
   A ←--→ B ←--→ C ←--→ D
```

B 正在给 A 发数据，C 听到了 B 的信号，判定"信道忙"，于是不敢给 D 发。但实际上 C→D 的传输与 B→A 的传输**互不干扰**（A 听不到 C，D 听不到 B），C 白等了。

### 一句话对照

| 问题 | 判断错在哪 | 后果 | 802.11 的处理 |
| --- | --- | --- | --- |
| **隐蔽站** | **该判忙的判成了闲**（听不到远处的发送方） | 发生碰撞且无人察觉 | RTS/CTS + NAV |
| **暴露站** | **该判闲的判成了忙**（听到了与自己无关的发送方） | 信道空转，利用率下降 | 无专门机制，视为性能损失 |

**记忆锚点**：隐蔽站是"**该停的没停**"，暴露站是"**不该停的停了**"。两者都是载波监听的误判，方向相反。

## 三、CSMA/CA 的基本思想

CA = Collision **Avoidance**，**碰撞避免**。教材（印刷 p413）：CA 的含义是"协议的设计是要尽量减少碰撞发生的概率"。

既然无法在碰撞发生后"检测"到它，就把功夫全花在**发生之前**：

| 手段 | 干什么 | 对付的问题 |
| --- | --- | --- |
| **物理载波监听** | 检测信号强度是否超过门限 | 本站听得见的发送方 |
| **虚拟载波监听（NAV）** | 用别人帧首部里的"占用时长"字段算出信道忙到什么时候 | **听得见 CTS 但听不见发送方**的隐蔽站 |
| **强制退避** | 即使信道空闲，也要先等 DIFS 再随机退避 | 多个站同时看到信道变空闲 |
| **链路层 ACK** | 用显式确认代替碰撞检测 | 发送方无法自知成败 |
| **RTS/CTS 预约** | 用短帧先把信道占下来 | 隐蔽站；同时压低碰撞代价 |

其中 NAV 与 ACK 是**替代品**（替代做不成的碰撞检测），退避与 RTS/CTS 是**预防措施**。

**一个关键推论：CSMA/CA 必须有链路层 ACK。** CSMA/CD 不需要逐帧确认，因为它能直接看到有没有撞；CSMA/CA 看不到，就只能靠接收方"我收到了"来倒推。教材（印刷 p414）："无线站点每通过无线局域网发送完一帧后，要等到收到对方的确认帧后才能继续发送下一帧。这就是链路层确认。"**这是 CSMA/CA 与 CSMA/CD 最本质的差别之一。**

## 四、DCF 基本接入流程

802.11 的 MAC 层用**分布协调功能 DCF**（Distributed Coordination Function）实现 CSMA/CA，所有实现都必须支持它。

### 什么时候可以不退避直接发

教材给了一条明确结论（印刷 p417）：**当站点想发送数据、并检测到信道连续空闲时间超过 DIFS 时，即可立即发送数据，而不必经过争用期。**

必须经过争用期（即必须退避）的只有三种情况：

- 要发送数据时检测到**信道忙**；
- 已发出的数据帧**未收到确认**，需要重传；
- **接着发送后续的数据帧**（连发时每帧之间都要重新争用）。

第 3 条的用意是**防止一个站长期垄断发送权**（印刷 p417）：若一站要连续发若干帧，不管有没有别人争用，都必须重新进入争用期。这条常被忽略——"信道我已经占着了，接着发不就行了？"不行。

### 推迟接入 vs 退避

教材专门区分了这两个词（印刷 p416），它们对应退避计时器的两种状态：

| 术语 | 信道状态 | 计时器状态 | 目的 |
| --- | --- | --- | --- |
| **推迟接入**（defer access） | **忙** | **冻结**，保留剩余值不变 | 等待争用期到来 |
| **退避**（backoff） | **空闲**（且已过 DIFS） | **倒计时** | 在争用期里公平竞争 |

**冻结而不是清零，是这个协议里最讲究的一处设计。** 已经等过很久的站保留它的剩余时隙数，下一轮从剩余值继续倒数，因此**等得越久越先发**。如果每次重新随机取值，长期等待的站可能永远抢不到——冻结机制把"已经等了多久"变成了一种可继承的优先级。

教材的例子（印刷 p416）：C 的退避时隙数为 3、D 为 9。经过 3 个时隙后 C 获得发送权开始发送，信道转忙，**D 随即冻结其剩余的 6 个时隙**；下一个争用期到来时 D 从 6 继续倒数，而不是重新摇一个 0~15 的数。

## 五、帧间间隔（IFS）

802.11 用不同长度的帧间间隔给不同优先级的帧排队——**间隔越短，优先级越高**。

| 间隔 | 全称 | 用途 | 相对长度 |
| --- | --- | --- | --- |
| **SIFS** | Short IFS | ACK、CTS、分片后续帧 | **最短** |
| **PIFS** | PCF IFS | 集中协调功能 PCF 使用 | 中等 |
| **DIFS** | DCF IFS | 普通数据帧、RTS | **最长** |

关系：**SIFS < PIFS < DIFS**。

### SIFS 为什么必须比 DIFS 短

教材给的推理（印刷 p415）分两层：

**第一层：为什么 ACK 之前要有一段间隔（SIFS）。** 接收方 B 收完数据帧后不能瞬间回 ACK——它要先做 CRC 校验，校验无差错还要**从接收状态转为发送状态**，这些动作需要时间。SIFS 就是留给这套动作的。

**第二层：为什么这段间隔必须比 DIFS 短。** B 在做校验的这段时间里信道是空闲的。若不加约束，别的站会以为"信道空了"就抢着发，把即将到来的 ACK 撞掉。于是标准规定：**想新发起传输的站必须等满更长的 DIFS**。这样在 SIFS 到 DIFS 这段差值里，只有 ACK 有资格发出。

教材原话："802.11 标准定义了比 SIFS 更长的时间间隔 DIFS，并且规定，凡在空闲时间想发送数据的站点，必须等待时间 DIFS 后才能发送。这就保证了确认帧 ACK 得以优先发送。这个重要措施使得在这段时间（DATA + SIFS + ACK），整个信道好像是 A 和 B 专用的。"

**所以 SIFS 短不是"反应快"，是协议刻意安排的优先级。** 判断某个帧该等 SIFS 还是 DIFS，看它是"接着上一次传输往下走"（→ SIFS）还是"新发起一次传输"（→ DIFS）。CTS、ACK、分片后续帧属前者；数据帧、RTS 属后者。

### 一组具体数值

教材给了 802.11g 的参数（印刷 p416）：**时隙 =9 μs，SIFS =10 μs，DIFS 比 SIFS 长两个时隙，因此 DIFS =28 μs。**DIFS=SIFS+2×时隙=10+2×9=28 μs

这条关系（DIFS = SIFS + 2 个时隙）在不同标准里数值不同，但**结构是通用的**。题目若只给 SIFS 和时隙长度而没给 DIFS，就用它推。

时隙长度的定义也值得一记（印刷 p416）：**在下一个时隙开始时，每个站点都能检测出在前一个时隙开始时信道是否忙**——时隙不能短于"检测 + 反应"所需的时间。

## 六、争用窗口与退避

### 规则

站点进入争用期时，在 0∼CW 个时隙中随机取一个整数作为退避时隙数，设置退避计时器，然后按第四节的规则倒计时/冻结。

教材对 CW 的规定（印刷 p416–p417）：

- **802.11 标准本身并未规定争用窗口 CW 的初始值**，但建议 CW 最小值可取 **15**、最大值 **1023**；
- **每重传一次，争用窗口的数值就近似加倍地增大**，即CW新=2×(CW旧+1)−1

- 增大到 1023 后不再增大。

按这条递推：

| 阶段 | CW | 可选时隙数 | 平均退避时隙 |
| --- | --- | --- | --- |
| 首次争用 | 15 | 16 | 7.5 |
| 第 1 次重传 | 31 | 32 | 15.5 |
| 第 2 次重传 | 63 | 64 | 31.5 |
| 第 3 次重传 | 127 | 128 | 63.5 |
| 继续重传 | 逐次近似加倍 |  |  |
| 封顶后 | **1023** | 1024 | 511.5 |

⚠️ **口径提示**：CW 的初值与逐次取值在不同教材、不同 802.11 修订版里写法不一，**标准本身也没有强制初值**。谢希仁给的是"初值建议 15、封顶 1023、每次近似加倍"。**做题时一律以题面给出的窗口参数为准**；题面没给，就按上面这条递推与上下界走。

### 与 CSMA/CD 退避的三点区别

| 维度 | CSMA/CD 截断二进制指数退避 | CSMA/CA 争用窗口 |
| --- | --- | --- |
| **什么时候退避** | 只在**碰撞之后** | 信道忙、重传、连发后续帧都要；**首次遇到忙信道就要退** |
| **时槽的物理含义** | 争用期 2τ（51.2 μs @10 Mb/s） | 802.11 定义的时隙（如 802.11g 为 9 μs） |
| **计时器能否冻结** | **不能**，退避时间一次算定 | **能**，信道转忙就冻结、保留剩余值 |
| 窗口上界 | 210−1=1023 个时槽 | 建议上界同为 1023 个时隙 |

**最值得记的是"退避的触发条件"这一行**：CSMA/CD 是**冲突后**退避（信道空闲就直接发），CSMA/CA 是**发送前**就可能要退避。原因还是那句——CSMA/CA 没有碰撞检测，撞了代价高，所以把成本前置到"预防"上。

第二值得记的是**冻结**：CSMA/CD 没有这个机制。

## 七、RTS/CTS 与虚拟载波监听

### 机制

为了解决隐蔽站带来的碰撞，802.11 允许发送站对信道进行**预约**（印刷 p417）：

- **RTS**（Request To Send）：发送方先发一个很短的控制帧，首部里写明"我将要占用信道一段时间：SIFS+CTS+SIFS+DATA+SIFS+ACK"；
- **CTS**（Clear To Send）：接收方（AP）等 SIFS 后回一个控制帧，首部里写"A 站和我通信，要占用信道：SIFS+DATA+SIFS+ACK"；
- 凡听到 RTS 或 CTS 的其他站，把这段时长写进自己的 **NAV**（Network Allocation Vector，网络分配向量），在倒计时期间视信道为"虚拟忙"，不发起新传输；
- 教材补了一条常被漏掉的（印刷 p417）：**随后 A 发送的 DATA 帧首部里也写了 DATA+SIFS+ACK，没收到 RTS/CTS 的站收到 DATA 帧后也能设置 NAV**。

### NAV 为什么能治隐蔽站

隐蔽站 C 听不到 A（这正是"隐蔽"的定义），但 C 与 AP 之间是通的——**只要 C 能和 AP 通信，它就一定听得到 AP 发的 CTS**。CTS 一发，所有能与 AP 通信的站全部沉默，A 就拿到了独占时间。

**这就是"虚拟"载波监听的含义**：C 并没有在物理层听到任何信号，它是**通过读别人帧里的一个数字**判定信道忙的。物理监听回答"现在有没有人在发"，虚拟监听回答"接下来这段时间会不会有人在发"——后者能跨越"听不见发送方"这个障碍。

### 两个 NAV 长度不同

- 由 **RTS** 设的 NAV =SIFS+TCTS+SIFS+TDATA+SIFS+TACK
- 由 **CTS** 设的 NAV =SIFS+TDATA+SIFS+TACK

两者相差 SIFS+TCTS。

**道理很直白：NAV 写的是"从这一帧结束的那一刻起，信道还要被占多久"。** RTS 结束时 CTS 还没发，所以要把 CTS 及其前面的 SIFS 算进去；CTS 结束时 CTS 已经发完了，自然不算。**判断任何一个 NAV 值，都从"这一帧发完之后还剩哪些环节"往后数**，不要背死公式。

### RTS/CTS 的代价与收益

教材算了这笔账（印刷 p418）：

**代价**：多浪费 RTS+SIFS+CTS+SIFS 的信道时间。

**为什么仍划算**："由于这两种控制帧都很短，其长度分别为 **20 字节和 14 字节**，与数据帧（最长可达 **2346 字节**）相比开销不算大。相反，若不使用这种控制帧，则一旦发生碰撞而导致数据帧重发，浪费的时间就更多了。"

**核心逻辑：把碰撞从"长帧之间"挪到"短帧之间"。** 撞 RTS 只损失 20 字节的时间，撞数据帧要损失最多 2346 字节的时间——即便 RTS 撞了，代价也小两个数量级。

**因此 RTS/CTS 是可选的**（印刷 p418）："信道预约不是强制性规定。各站可以自己决定使用或不使用信道预约。看来，只有当数据帧的长度超过某数值时，使用 RTS 帧和 CTS 帧才比较有利。"实现上就是一个 **RTS 门限**：帧长超过门限才启用。短帧用 RTS/CTS 反而得不偿失。

**RTS/CTS 也不能消灭碰撞。** 教材明说（印刷 p418）：有的站可能没收到 RTS/CTS/NAV，仍会在中途发送，与 RTS 或 CTS 相撞；A 若收不到 CTS，就不能发数据帧，必须重传 RTS。**"避免"从来不是"消除"。**

## 八、例题

### 例题 1：计算两种 NAV 值

**题目**（自造数据）：某 802.11 无线局域网数据率为 8 Mb/s，SIFS =10 μs，DIFS =28 μs，时隙 =9 μs。RTS 帧长 20 字节，CTS 帧长 14 字节，ACK 帧长 14 字节，数据帧长 200 字节。所有帧均以 8 Mb/s 发送，忽略传播时延。求： （1）各帧的传输时延； （2）站 A 发出的 RTS 帧中写入的 NAV 值； （3）AP 回送的 CTS 帧中写入的 NAV 值； （4）两者之差，并说明差在哪个环节。

**解答：**

**第 1 步：算传输时延。**T=L (字节)×88×106 b/s

数据率取 8 Mb/s，1 字节恰好对应 1 μs：

| 帧 | 长度 | 传输时延 |
| --- | --- | --- |
| RTS | 20 B | 20 μs |
| CTS | 14 B | 14 μs |
| DATA | 200 B | 200 μs |
| ACK | 14 B | 14 μs |

这一步为什么这么做：所有时间量必须统一到同一单位才能相加。**帧长给的是字节、速率给的是比特每秒，中间必须乘 8**——这是最常见的失分点。

**第 2 步：RTS 里的 NAV。**

从 RTS **发完之后**开始数，还要经过：SIFS → CTS → SIFS → DATA → SIFS → ACK。NAVRTS=10+14+10+200+10+14=258 μs

这一步为什么这么做：NAV 的语义是"**从本帧结束起**，信道还要忙多久"。所以起点是 RTS 结束的那一刻，RTS 自身的 20 μs **不计入**。把后续环节按顺序列全再相加，不要跳过任何一个 SIFS——本例中有三个 SIFS。

**第 3 步：CTS 里的 NAV。**

从 CTS 发完之后数，还剩：SIFS → DATA → SIFS → ACK。NAVCTS=10+200+10+14=234 μs

**第 4 步：求差并解释。**258−234=24 μs=SIFS+TCTS=10+14

差的正是"CTS 那一段"（CTS 本身的传输时间加上它前面的 SIFS）。RTS 发完时 CTS 还没发生，要算进去；CTS 发完时它自己已经过去了，不算。

这一步为什么重要：它验证了第七节那条"从本帧发完之后往后数"的通用方法。**只要按这个方法数，任何一个帧（包括 DATA 帧）里的 NAV 都能推出来**，不需要背三个公式。作为检验：DATA 帧里的 NAV 应是 SIFS+TACK=10+14=24 μs。

**答案**：（1）见表；（2）258 μs；（3）234 μs；（4）差 24 μs，即 SIFS+TCTS。

### 例题 2：RTS/CTS 值不值——两种方案的时间对比

**题目**（沿用例题 1 的参数）：站 A 检测到信道忙、进入争用期，随机退避时隙数为 5。求从"信道变为空闲"起算，到 A 收到 ACK 为止的总时间： （1）不使用 RTS/CTS； （2）使用 RTS/CTS； （3）RTS/CTS 多花了多少时间，占比多少； （4）若数据帧改为 2000 字节，重算（3），并解释 RTS 门限的意义。

**解答：**

**第 1 步：不使用 RTS/CTS。**T1=DIFS+退避+TDATA+SIFS+TACK=28+5×9+200+10+14=28+45+200+10+14=297 μs

这一步为什么这么做：信道变空闲后先等满 DIFS 才能开始倒计时（第四节的规则），所以 DIFS 在退避**之前**。退避时间 = 时隙数 × 时隙长度。

**第 2 步：使用 RTS/CTS。**T2=DIFS+退避+TRTS+(SIFS+TCTS+SIFS+TDATA+SIFS+TACK)⏟=NAVRTS=258=28+45+20+258=351 μs

这一步为什么这么做：RTS 之后的全部环节，正好就是例题 1 算出的 NAVRTS——**NAV 的物理含义本来就是"这一帧之后的剩余占用时间"**，可以直接复用，不必重新展开。这是一次很好的自洽性检验。

**第 3 步：200 字节数据帧的开销比。**Δ=351−297=54 μs=TRTS+SIFS+TCTS+SIFS=20+10+14+10占比=54297≈18.2%

**第 4 步：2000 字节数据帧。**

TDATA=2000 μs：T1′=28+45+2000+10+14=2097 μsT2′=28+45+20+(10+14+10+2000+10+14)=2151 μsΔ=54 μs （不变）,占比=542097≈2.6%

这一步为什么重要：**RTS/CTS 的绝对开销是固定的 54 μs，与数据帧长无关**；而它避免的损失（一次碰撞要白发一整帧）**随数据帧长线性增长**。所以帧越长越该用、帧越短越不该用——这正是"RTS 门限"这个设计的全部理由：拿帧长和门限比一下，就能判断这笔账划不划算。

粗略地看：只要碰撞概率乘上"重发一整帧的时间"超过 54 μs，开 RTS/CTS 就是赚的。2000 字节时重发一帧要 2000 μs，碰撞概率只要超过约 2.7% 就值；200 字节时要超过 27% 才值——差了一个数量级。

**答案**：（1）297 μs；（2）351 μs；（3）多花 54 μs，约 18.2%；（4）2000 字节时仍多花 54 μs，但只占约 2.6%，故长帧才启用 RTS/CTS。

### 例题 3：冻结机制下的退避推演

**题目**（沿用例题 1 的参数）：站 C 和 D 在同一争用期分别随机取到退避时隙数 3 和 9。已知 C 一旦获得发送权就占用信道 297 μs，随后信道再次空闲。若此后无其他站争用，问 D 还要等待多少个退避时隙才能发送？D 是否需要重新随机取值？

**解答：**

**第 1 步：第一个争用期。**

C 和 D 同时倒计时。经过 3 个时隙，C 的计时器归零，C 开始发送，信道转忙。

此时 D 已经倒数了 3 个时隙，剩余 9−3=6 个。

**第 2 步：D 的计时器冻结。**

信道转忙 → D **冻结**计时器，保留剩余值 6，进入"推迟接入"状态。

这一步为什么这么做：这是第四节区分的两个状态。信道忙时是**推迟接入 + 冻结**，不是退避。**冻结保留的是剩余值 6，不是原值 9，也不是清零。**

**第 3 步：信道再次空闲后。**

C 占用 297 μs 结束，信道空闲。D 先等满 DIFS（28 μs），然后从**剩余的 6** 继续倒计时。还需等待=6×9=54 μs

**第 4 步：是否重新随机取值。**

**不需要。** 只有在"发出的帧未收到确认、要重传"时才会把争用窗口加倍并重新取值。D 这次是被冻结、不是重传失败，剩余值原样继承。

这一步为什么重要：它把"冻结"和"窗口加倍"两件事分开了。冻结是**同一次发送尝试内**的暂停/继续；窗口加倍是**上一次尝试失败后**的重新开始。混起来会得出"D 要在 0∼31 里重新摇一个数"这种错误结论。

也正是靠这个机制，D 只需再等 6 个时隙，而任何**新来的**站要从 0∼15 重新摇（平均 7.5 个时隙）。**等得久的站被系统性地照顾了**——这是 CSMA/CD 完全不具备的性质（CSMA/CD 的适配器对历史碰撞无记忆）。

**答案**：还要等 6 个退避时隙（54 μs，另需先等满 DIFS）；不需要重新随机取值。

## 九、CSMA/CD 与 CSMA/CA 对比

| 对比项 | CSMA/CD | CSMA/CA |
| --- | --- | --- |
| 应用场景 | 有线总线以太网（802.3） | 无线局域网（802.11） |
| 能否检测碰撞 | **能**（边发边听） | **不能**（收发功率差百万倍） |
| 核心策略 | **检测**到碰撞后停发 | 发送前**避免**碰撞 |
| 链路层确认 | **无**（靠上层保证可靠性） | **必须有**（逐帧 ACK） |
| 退避时机 | 只在**碰撞之后** | 信道忙 / 重传 / 连发后续帧 |
| 退避计时器 | 一次算定，**不冻结** | 信道忙则**冻结**、保留剩余值 |
| 退避时槽 | 争用期 2τ | 802.11 定义的时隙 |
| 帧间间隔 | 无（只有帧间隙） | SIFS / PIFS / DIFS，用于优先级 |
| 虚拟载波监听 | 无 | **有**（NAV） |
| 信道预约 | 无 | RTS/CTS（可选，按帧长门限） |
| 关键长度约束 | **最小**帧长（保证撞得到） | 无最小帧长要求；有 RTS **门限**（决定用不用预约） |

最后一行值得单独看：CSMA/CD 靠"帧不能太短"来保证碰撞可检测；CSMA/CA 根本不检测碰撞，所以没有这条约束，它关心的反而是"帧够不够长，长到值得为它做预约"。**两个协议对帧长的关切方向是相反的。**

## 易混淆知识点

**1. CA 是"碰撞避免"不是"碰撞消除"**

CSMA/CA 不能完全避免碰撞：两个站的退避计时器可能同时归零；没收到 RTS/CTS 的站可能中途插入撞掉 RTS 或 CTS。它只是**大幅降低概率**。

**2. CSMA/CA 必须有链路层 ACK，CSMA/CD 不需要**

根因是能不能检测碰撞。CSMA/CD 能自知成败，CSMA/CA 只能靠对方告诉它。这一条是两个协议最本质的差别，比"有线/无线"更根本。

**3. 退避的触发条件不同**

CSMA/CD 是**碰撞后**才退避，信道空闲就直接发；CSMA/CA 是**发送前**就可能要退避（检测到信道忙、重传、连发后续帧三种情况）。但注意：**若信道连续空闲超过 DIFS 且是首次发送，CSMA/CA 也可以不退避直接发**——不是"任何时候都要退避"。

**4. 争用窗口的上界要以题面为准**

谢希仁给的是"标准未规定初值，建议最小 15、最大 1023，每重传一次近似加倍"。不同教材写法不一。**题目给了窗口参数就用题目的**，别硬套某个记忆中的数字。

**5. 冻结 ≠ 清零 ≠ 重新取值**

信道转忙时计时器**冻结并保留剩余值**，下一轮从剩余值继续。只有"帧未被确认、要重传"时才把窗口加倍并重新随机取值。

**6. NAV 是给"旁观者"设的，发送方自己不设**

发送方自己知道要占多久，不需要 NAV。NAV 是写在 RTS/CTS/DATA 首部里、给周围听得到的第三方用的"虚拟忙倒计时"。

**7. NAV 值从"本帧发完之后"起算**

本帧自身的传输时间不计入自己写的 NAV。RTS 里的 NAV 比 CTS 里的多一个 SIFS+TCTS。

**8. RTS/CTS 是可选的，且只对长帧划算**

它的绝对开销固定（RTS+SIFS+CTS+SIFS），而收益随帧长增长，所以实现上设一个 RTS 门限，超过才启用。

**9. 隐蔽站与暴露站方向相反**

隐蔽站"该停的没停"（漏判忙），会造成碰撞；暴露站"不该停的停了"（误判忙），只造成空转。802.11 只用 RTS/CTS 处理前者，对后者没有专门机制。

**10. 无线网用 CA、有线以太网用 CD**

"以太网使用 CSMA/CA"是错的。以太网 = CSMA/CD（且现代交换式以太网连 CSMA/CD 都不用了），Wi-Fi = CSMA/CA。

## 本节小结

无线用不了 CSMA/CD 有三条原因，都是原理性的：① 自己的发射功率是接收功率的百万倍量级，物理上分辨不出叠加；② 隐蔽站的存在让"检测到空闲"不等于"信道空闲"；③ 无线撞了只能把整帧发完才知道，一次碰撞的代价远大于有线。代价结构变了，策略就从"检测"改成"避免"。

**隐蔽站**是"该判忙的判成了闲"——碰撞发生在接收方处，而发送方看不见；**暴露站**是"该判闲的判成了忙"——听到了与自己无关的传输而白等。前者造成碰撞，后者造成空转；802.11 只处理前者。

CSMA/CA 用五件事替代和预防：物理载波监听、**虚拟载波监听 NAV**、强制退避、**链路层 ACK**、RTS/CTS 预约。其中 ACK 与 NAV 是"检测不到碰撞"的替代品——**CSMA/CA 必须逐帧 ACK，这是它与 CSMA/CD 最本质的差别**。

**DCF 接入**：信道连续空闲超过 DIFS 且是首次发送，可以直接发不退避；只有"检测到信道忙""重传""连发后续帧"三种情况必须进争用期。第三条是为了防止一个站长期垄断。

**推迟接入 vs 退避**是两个状态：信道忙时计时器**冻结**（保留剩余值），信道空闲过了 DIFS 才**倒计时**。冻结让"已经等了多久"变成可继承的优先级，这是 CSMA/CD 没有的机制。

**帧间间隔**用长度编码优先级，SIFS < PIFS < DIFS。SIFS 存在是因为接收方要做 CRC 校验并从收转发；SIFS 必须比 DIFS 短，是为了让 ACK 抢在任何新发起者之前。判断某帧等哪个间隔：接续上一次传输的等 SIFS（CTS/ACK/分片后续帧），新发起的等 DIFS（DATA/RTS）。DIFS=SIFS+2×时隙（802.11g：10+18=28 μs）。

**争用窗口**建议初值 15、上界 1023，每重传一次按 CW新=2(CW旧+1)−1 近似加倍；标准本身未规定初值，做题以题面为准。

**RTS/CTS 与 NAV**：RTS 与 CTS 首部里写"信道还要被占多久"，听得到的第三方据此设 NAV 作虚拟忙。隐蔽站听不到发送方，但一定听得到 AP 的 CTS——这就是 NAV 治隐蔽站的全部机理。NAV 值从**本帧发完之后**起算，因此 RTS 里的比 CTS 里的多 SIFS+TCTS。RTS 20 B、CTS 14 B，数据帧最长 2346 B，预约把碰撞从长帧之间挪到短帧之间；开销绝对值固定、收益随帧长增长，所以设 RTS 门限，只有长帧才启用。预约也消灭不了碰撞。
