## 知识框架

本节回答 5 个问题：

- 万维网到底是什么——一种网络、一个协议，还是别的什么？它和 Internet 是什么关系？
- 万维网**必须**解决哪几个问题？URL、HTTP、HTML 这三样东西是被哪几个问题逼出来的？
- URL 的四个部分各管什么？哪些部分区分大小写、哪些可以省略？
- 超文本和超媒体差在哪？"分布式的"超媒体系统比"非分布式的"多了什么麻烦？
- 说"WWW 就是 HTTP"错在哪一层？

第 2 个和第 4 个问题是本节真正的骨架。把万维网的三大标准当成三个孤立名词记，遇到变体就没有依托；把它们当成"四个问题的四个答案"，就能自己推。

## 一、万维网是什么

**万维网 WWW（World Wide Web）是一个大规模的、联机式的信息储藏所，英文简称为 Web，而不是什么特殊的计算机网络。**

三个限定词要拆开看：

- **大规模**：文档分布在全世界的站点上，数目不受限制；
- **联机式**：文档不是预先打包发给你的，是你要看时才从远端取回来；
- **信息储藏所**：它是**内容**的集合，不是**线路**的集合。

最后半句"而不是什么特殊的计算机网络"是关键：**WWW 不是一种网络**。

### WWW 与 Internet 的关系

|  | Internet | WWW |
| --- | --- | --- |
| 是什么 | 网络基础设施（基于 TCP/IP 协议族） | 建立在 Internet 之上的一种**应用** |
| 提供什么 | 主机之间的通信能力 | 联机的、超链接组织的信息访问 |
| 上面还有什么 | Email、FTP、DNS、P2P…… | — |

判据：**Internet 不用 WWW 照样能跑（收邮件、传文件、查 DNS）；WWW 离开 Internet 一步也走不了。** 这是"承载"关系，不是"等同"关系。

### 分布式服务与链接的一致性问题

万维网提供的是**分布式**服务：站点可以相隔数千公里，每台主机上的文档**独立进行管理**。

这里藏着一个很少被讲、却是万维网**结构性代价**的问题：

- **非分布式**超媒体系统里，所有文档都在同一台机器的磁盘上，因此文档之间的链接**可以做一致性检查**，系统能保证所有链接都有效、一致；
- **万维网**把大量信息分布在整个互联网上，对文档的增加、修改、删除、重命名**都不需要（实际上也不可能）通知**互联网上成千上万的节点。

结论：**万维网文档之间的链接经常会不一致。** 主机 A 上的文档 X 指向主机 B 上的文档 Y，B 的管理员某天删掉了 Y，A 的那条链接就失效了——**而 B 并没有责任必须通知 A**。

这就是"死链"（404）在万维网上无法根除的原因：它不是实现上的疏忽，是分布式自治这个设计选择的直接后果。愿意付这个代价，换来的是任何人都能不经审批地发布内容并链接到任何地方——这正是万维网能长成今天这个规模的前提。

## 二、万维网必须解决的四个问题

比起把 URL / HTTP / HTML 当三个并列名词背下来，更省力也更能迁移的做法是记住**它们各自在回答哪个问题**。教材把万维网的设计任务拆成四问：

| # | 问题 | 答案 | 一句话 |
| --- | --- | --- | --- |
| 1 | 怎样**标志**分布在整个互联网上的万维网文档？ | **URL** | 给每份文档一个全网唯一的地址 |
| 2 | 用什么**协议**来实现万维网上的各种链接？ | **HTTP** | 规定客户与服务器之间怎么要、怎么给 |
| 3 | 怎样使不同作者创作的不同风格的文档，都能在各种主机上显示出来，同时让用户清楚哪里存在超链接？ | **HTML** | 用统一的标记语言描述内容与结构 |
| 4 | 怎样使用户能够很**方便地找到**所需的信息？ | **搜索工具** | 检索与搜索引擎 |

**第 4 个问题常被漏掉**，但它恰恰说明为什么"WWW = URL + HTTP + HTML"这个三要素说法只是近似：三大标准解决的是"能不能访问到"，搜索工具解决的是"知不知道去访问什么"。有 URL 却不知道该输入哪个 URL，万维网对普通用户就是不可用的。

三者的协作关系：

万维网以**客户服务器方式**工作：浏览器是用户主机上的万维网客户程序（"浏览器"和"万维网客户"是同义词），文档所驻留的主机运行服务器程序。在客户程序主窗口上显示出的万维网文档称为**页面（page）**。

## 三、URL 统一资源定位符

### URL 是什么

URL 用来表示从互联网上得到的**资源位置**和**访问这些资源的方法**。

两件事各占一半：**位置**（在哪）和**方法**（用什么协议去取）。这解释了为什么协议名必须写在 URL 里——同一份资源可能有多种取法。

这里的"资源"指互联网上可以被访问的任何对象：文件目录、文件、文档、图像、声音，以及与互联网相连的任何形式的数据。**互联网上的所有资源都有一个唯一确定的 URL。**

### 一般形式
⟨协议⟩://⟨主机⟩:⟨端口⟩/⟨路径⟩

```
https://www.codebrick.tech:443/cn-blog/posts/application/www.html
└─┬─┘   └────────┬─────────┘└┬┘└──────────────┬──────────────────┘
 协议        主机          端口            路径
```

| 部分 | 说明 | 能省吗 |
| --- | --- | --- |
| 协议 | 访问资源使用的协议，最常用 `http`，其次 `ftp` | 不能。后面的 `://` 是规定格式，**必须写上** |
| 主机 | 文档所存放主机的域名，通常以 `www` 开头，但**这并不是硬性规定**；也可以直接用 IP 地址 | 不能 |
| 端口 | 服务监听的端口号 | **通常可省**，省略即取协议默认端口（HTTP 80、HTTPS 443）；不用默认端口时**必须写明** |
| 路径 | 资源在主机上的位置，可以很长，其中可含多个 `/` | 可省。省掉后 URL 就指向该站点的**主页（homepage）** |

### 大小写规则

这一条经常被记成"URL 不区分大小写"，是不完整的：

**URL 的"协议"和"主机名"部分，字母不区分大小写；但"路径"中的字符有时要区分大小写。**

原因不难推：协议名由标准定义、主机名由 DNS 解析（DNS 本身不区分大小写），这两段的解释权在协议和 DNS 手上；而**路径**最终要交给服务器的文件系统去查，区不区分大小写取决于**那台服务器的操作系统**——Linux 区分，Windows 通常不区分。所以这是一条"取决于实现"的规则，不是协议规定。

### 主页（homepage）

省掉路径后，URL 指向一个主页。主页可以是下列三种情况之一：

- 一个 WWW 服务器的最高级别的页面；
- 某个组织或部门定制的页面或目录，从这里可链接到与本组织有关的其他站点；
- 某个人自己设计的、描述本人情况的页面。

### URL 与 URI

URI（Uniform Resource Identifier）是更广义的概念，用于**标识**资源；URL 是 URI 的一种，不仅标识资源，还指明了如何**定位**（访问）它。所有 URL 都是 URI，反之不然。408 中一般不严格区分。

### URL 不止用于万维网

用户使用 URL 并非只能访问万维网页面，还能通过 URL 使用其他互联网应用（如 `ftp://`）。**更重要的是用户在使用这些应用时只用一个程序——浏览器。** 这是万维网影响力的一个来源：它把原本互不相干的多种应用收进了同一个入口。

## 四、超文本与超媒体

| 概念 | 定义 | 内容包含 |
| --- | --- | --- |
| **超文本（hypertext）** | 包含**指向其他文档的链接**的文本 | 仅文本信息 |
| **超媒体（hypermedia）** | 超文本系统的扩充 | 文本之外还有图形、图像、声音、动画以及视频图像等 |

判据只有一条：**差别在文档内容，不在链接机制。** 两者都靠超链接把信息源连起来，超媒体只是把"能被链接和被嵌入的东西"扩展到了多媒体。

**超文本是万维网的基础。** 一个超文本由多个信息源链接成，这些信息源可以分布在世界各地，数目不受限制。

现代网页基本都是超媒体——包含文字、图片、视频，并通过 HTML 的 `<a>` 标签互相链接：html

```
<!-- HTML 中的超链接 -->
<a href="https://www.codebrick.tech/">访问 CodeBrick</a>
```

## 五、万维网的工作流程

以打开 `https://www.example.com` 为例：

- **浏览器解析 URL**：提取协议（https）、主机（`www.example.com`）、端口（默认 443）、路径（`/`）；
- **DNS 解析**：把主机名转换成 IP 地址（细节见 [[04_计算机网络_CN/application/dns.md|DNS 域名系统]]）；
- **建立 TCP 连接**：与服务器的对应端口建立 TCP 连接（HTTPS 还要 TLS 握手）；
- **发送 HTTP 请求**：`GET / HTTP/1.1`；
- **服务器响应**：返回 HTML 文档及状态码；
- **解析 HTML**：浏览器发现其中引用的图片、CSS、JS 等资源，**对每个资源重复第 2~5 步**；
- **渲染页面**：把所有资源组合起来显示。

第 6 步是这条流程里唯一"会分叉"的一步，也是万维网性能问题的总来源：**一个完整的网页加载通常涉及几十个甚至上百个 HTTP 请求**。HTTP/1.1 的持久连接、HTTP/2 的多路复用，全都是针对这一步的优化——具体怎么省、省多少个 RTT，见 [[04_计算机网络_CN/application/http.md|HTTP 协议]]，本篇不重复。

## 六、静态网页与动态网页

| 特性 | 静态网页 | 动态网页 |
| --- | --- | --- |
| 文件形式 | 服务器上预先存好的 HTML 文件 | 由服务器程序根据请求动态生成 |
| 内容 | 固定不变 | 随用户、时间、参数变化 |
| 服务端开销 | 小（读文件即可） | 大（需要执行程序） |
| 可缓存性 | 高，代理服务器容易缓存 | 低，同一 URL 对不同用户可能返回不同内容 |
| 例子 | 文档、博客文章 | 搜索结果、用户主页、购物车 |

判据是**"这份 HTML 在请求到达之前是否已经存在"**。408 只要求理解概念区别，不要求掌握具体实现技术。

顺带一条与前面呼应：动态网页难以缓存，正是因为它破坏了"同一 URL → 同一份内容"这个假设——[[04_计算机网络_CN/application/http.md|HTTP 协议]]里代理服务器的缓存收益，主要来自静态资源。

## 七、WWW 与 HTTP 的关系

这是本节最容易含糊的一处概念辨析。把两者放在不同的层面上看就清楚了：

- **WWW 是一个信息系统的整体概念**——包括 URL、HTTP、HTML 三个核心标准，搜索工具，再加上海量的网页资源和它们之间的超链接关系；
- **HTTP 是 WWW 中负责传输的那个协议**——它只解决"怎样把文档从服务器传到浏览器"这一个问题。

更硬的一条判据来自应用层的通则：**应用层协议只是网络应用的一部分**。万维网这个应用包含浏览器、万维网服务器、文档格式标准 HTML，以及应用层协议 HTTP。HTTP 定义的是浏览器与服务器之间传送的报文类型、格式和序列；而**浏览器如何显示一个页面、服务器用多线程还是多进程来实现，都不是 HTTP 所定义的内容**。

打个比方：WWW 像一座城市的整体设施（道路 + 建筑 + 居民 + 地图），HTTP 只是其中的"快递服务"。城市里的快递可以换公司，城市还是那座城市。

## 易混淆知识点

**1. WWW 和 Internet 不是一回事**

Internet 是基础设施（TCP/IP），WWW 是建立在其上的一种应用。Internet 还承载 Email、FTP、DNS 等应用，它们都不属于 WWW。反过来 WWW 离开 Internet 无法存在。

**2. WWW 不是一种计算机网络**

教材的原话是"而不是什么特殊的计算机网络"。它是**信息储藏所**，不是线路的集合。

**3. WWW 使用的协议不止 HTTP**

核心传输协议是 HTTP/HTTPS，但加载一个页面还要用到 DNS、TCP，HTTPS 还要 TLS。URL 里也允许写 `ftp://`。

**4. 超文本与超媒体的差别在内容，不在链接**

超文本只含文本 + 链接；超媒体在此基础上加入图形、图像、声音、动画、视频。链接机制是一样的。

**5. URL 只有协议和主机名不区分大小写**

路径部分**有时**要区分——取决于服务器操作系统的文件系统，不是协议规定。"URL 全部不区分大小写"是错的。

**6. `www` 开头不是硬性规定**

主机名通常以 `www` 开头只是习惯；主机名也可以直接写成点分十进制 IP 地址。

**7. 端口省略 ≠ 没有端口**

省略表示"用该协议的默认端口"（HTTP 80、HTTPS 443）。不用默认端口时必须显式写出。

**8. 万维网的链接不保证一致**

分布式导致文档独立管理、增删改名都不通知别人，所以链接经常失效。这是设计代价而非缺陷——非分布式超媒体系统才能保证所有链接有效一致。

**9. 主页不等于"网站首页"**

教材列的三种情况里，"某个组织定制的页面或目录""某个人描述自己情况的页面"都算主页。它指的是"省掉路径后 URL 指向的那个页面"。

**10. URL 是 URI 的子集**

URI 只负责标识，URL 还负责定位。所有 URL 都是 URI，反之不成立。

**11. 静态/动态的判据是"请求到达前 HTML 是否已存在"**

不是"页面上有没有动画"，也不是"内容会不会变"。

## 本节小结

按这条主线能自己重讲一遍就算过：

- **万维网是大规模、联机式的信息储藏所，不是一种计算机网络**。它建立在 Internet 之上，是应用而非基础设施；Internet 没有 WWW 照样跑，WWW 离开 Internet 不能存在。
- **万维网提供分布式服务，代价是链接无法保证一致**。非分布式超媒体系统能做链接一致性检查，万维网做不到——文档独立管理，增删改名不通知别人。死链是分布式自治的必然结果，不是实现疏忽。
- **三大标准是被四个问题逼出来的**：怎样标志文档 → URL；用什么协议实现链接 → HTTP；怎样让不同风格的文档都能显示、并让用户看见链接 → HTML；怎样方便地找到信息 → 搜索工具。第四问常被漏，但它说明三要素只是近似说法。
- **URL = 位置 + 访问方法**，四段 `协议://主机:端口/路径`。`://` 必写；端口可省（省则取默认端口）；路径可省（省则指向主页）。**只有协议和主机名不区分大小写，路径由服务器文件系统决定。** 主页有三种情况。URL 是 URI 的一种。
- **超文本 vs 超媒体的差别在文档内容**：前者仅文本 + 链接，后者加入图形、图像、声音、动画、视频。超文本是万维网的基础。
- **万维网以客户服务器方式工作**，浏览器 = 万维网客户，显示出的文档称为页面。加载一个页面要对每个引用资源重复"DNS → TCP → 请求 → 响应"，因此一次加载常涉及几十上百个 HTTP 请求——这是所有 HTTP 连接优化的起点。
- **静态 vs 动态的判据是"请求到达前这份 HTML 是否已存在"**；动态网页难缓存，因为它破坏了"同一 URL → 同一份内容"的假设。
- **WWW ⊃ HTTP**：应用层协议只是网络应用的一部分。浏览器怎么渲染、服务器用多线程还是多进程，都不是 HTTP 定义的内容。

- **印刷 p274**，6.4.1 节：链接一致性那一段是本篇第一节末尾的依据——「在非分布式系统中，各种信息都驻留在单个计算机的磁盘中。由于各种文档都可从本地获得，因此这些文档之间的链接可进行一致性检查。所以，一个非分布式超媒体系统能够保证所有的链接都是有效的和一致的。万维网把大量信息分布在整个互联网上。每台主机上的文档都独立进行管理。对这些文档的增加、修改、删除或重新命名都不需要（实际上也不可能）通知到互联网上成千上万的节点。这样，万维网文档之间的链接就经常会不一致」。同页给出万维网必须解决的**四个问题**及其答案（URL / HTTP / HTML / 搜索工具），以及「万维网以客户服务器方式工作……在一个客户程序主窗口上显示出的万维网文档称为页面(page)」。6.4.2 节开头：「统一资源定位符 URL 是用来表示从互联网上得到的资源位置和访问这些资源的方法……显然，互联网上的所有资源，都有一个唯一确定的 URL。」
- **印刷 p275**，6.4.2 节：URL 各部分的规则——「在协议后面的『😕/』是规定的格式，必须写上」「主机名是万维网文档所存放的主机的域名，通常以 www 开头，但这并不是硬性规定。主机名用点分十进制的 IP 地址代替也是可以的」「这是因为这个端口号通常就是协议的默认端口号（例如，协议 HTTP 的默认端口号为 80），因此就可以省略。但如不使用默认端口号，那么就必须写明现在所使用的端口号」；以及主页的三种情况。
- **印刷 p276**：大小写规则原文——「URL 的『协议』和『主机名』部分，字母不区分大小写。但『路径』中的字符有时要区分大小写。」同页：「用户使用 URL 并非仅仅能够访问万维网的页面，而且还能够通过 URL 使用其他的互联网应用程序，如 FTP 或 USENET 新闻组等。更重要的是，用户在使用这些应用程序时，只使用一个程序，即浏览器。」
- **印刷 p260**，第 6 章引言：本篇第七节那条判据的出处——「应用层协议与网络应用并不是同一个概念。应用层协议只是网络应用的一部分。例如，万维网应用是一种基于客户/服务器体系结构的网络应用。万维网应用包含很多部件，有万维网浏览器、万维网服务器、万维网文档的格式标准，以及一个应用层协议。万维网的应用层协议是 HTTP……而万维网浏览器如何显示一个万维网页面，万维网服务器是用多线程还是用多进程来实现，则都不是 HTTP 所定义的内容。」
