## 知识框架

本节回答 6 个问题：

- 主机号全 0 和全 1 为什么**不能分配给主机**？这条规定是"因为要留作网络地址和广播地址"，还是反过来？
- 一个 /24 划成 8 个子网之后，可用主机地址从 254 掉到 240 —— 少掉的 14 个去哪了？"每划一次减 2"这个说法对吗？
- 子网掩码明明可以从 IP 地址算出来（分类编址时代确实如此），为什么 CIDR 之后它成了**必须显式携带**的信息？
- 路由聚合能把 4 条路由变成 1 条，那能不能把任意几条都聚起来？**聚合过头**会发生什么？
- 一个目的地址同时匹配 /22、/24、/25 三条路由，为什么"最具体的赢"是对的？如果反过来选最短的会怎样？
- VLSM 分配为什么必须**从大到小**？倒过来分会卡在哪一步？

## 一、地址的两级结构

IP 地址是给"接口"分配的、在全世界范围内唯一的 32 位标识符。它采用**两级结构**：IP 地址::={ ⟨网络号⟩, ⟨主机号⟩ }

- **网络号**标志主机（或路由器）所连接到的网络，在整个互联网范围内必须唯一
- **主机号**标志该网络内的这台主机，在该网络内必须唯一

两级合起来在全网唯一。这个结构带来的最大收益不在寻址，而在**转发表的规模**：

互联网上的主机数以十亿计，网络数只有百万量级。路由器如果按主机查表，表根本存不下、更查不快；改成"先找到目的**网络**，到了目的网络再直接交付目的主机"，表的规模就被压缩了三到四个数量级。

**记住这条：地址分层的第一目的是压缩转发表，不是方便人记忆。** 后面的子网划分、CIDR、路由聚合，全部是这条动机的延伸。

一个直接推论：**不连网的主机没有 IP 地址**。因为 IP 地址里含网络号，而网络号描述的正是"连到了哪个网络"。

## 二、分类编址

早期把 32 位地址按固定位置切分，分为五类：

| 类别 | 首位模式 | 网络号位数 | 第一字节范围 | 主机号位数 | 可指派的网络数 | 每网最大主机数 |
| --- | --- | --- | --- | --- | --- | --- |
| A 类 | 0xxxxxxx | 8 | 1~126 | 24 | 27−2=126 | 224−2=16777214 |
| B 类 | 10xxxxxx | 16 | 128~191 | 16 | 214=16384 | 216−2=65534 |
| C 类 | 110xxxxx | 24 | 192~223 | 8 | 221=2097152 | 28−2=254 |
| D 类 | 1110xxxx | — | 224~239 | — | 多播地址 | 见 [[04_计算机网络_CN/network/multicast.md|IP 多播]] |
| E 类 | 1111xxxx | — | 240~255 | — | 保留 | — |

三处细节要能解释，不能只背：

**A 类的网络数为什么是 27−2 而不是 27。** A 类网络号占 8 位但首位固定为 0，只剩 7 位可用，理论 128 个。减掉的两个是：网络号**全 0** 保留表示"本网络"；网络号 **127** 保留作本地软件环回测试（127.0.0.1 之类）。所以可指派的是 126 个。

**B、C 类的网络数为什么不减 2。** 它们的网络号里没有类似"全 0 表示本网络"和"127 表示环回"这两处占用。早期资料曾说 B 类的 128.0.0.0 和 C 类的 192.0.0.0 不指派，但现在这两个网络地址**已经可以指派了**。

**主机数为什么一律减 2。** 见下一节——这是本节最该弄清的一处。

### 主机号全 0 与全 1 的推导

课本上的说法是"全 0 是网络地址，全 1 是广播地址，都不能给主机"。但这话的**因果方向**其实是反的，理解方向才不会记混：

**不是"因为它们被占用了所以不能分配"，而是"因为需要一个不指向任何具体主机的写法，才把这两个值征用了"。**

具体来说，IP 层有两件事必须能写成一个 32 位地址：

**（一）指代"网络本身"。** 路由表里的每一条目要说"目的是某某网络"，这个"某某网络"得能写下来。用主机号全 0 表示：`5.0.0.0` 就是"网络号 5 的那个网络"。所以在 IP 地址被解读成"某网络里的某主机"这个框架下，主机号 = 0 的位置**被占去表达网络本身了**，它再也不能同时表示一台主机——否则"5.0.0.0"到底是个网络还是那台主机，无法区分。

**（二）指代"这个网络上的所有主机"。** 广播必须能写成一个目的地址。全 1 在很多协议里都表示"所有"，于是主机号全 1 表示"网络号 Y 的那个网络上的全部主机"，即**直接广播地址**。

两个值一征用，剩下能分给主机的就只有 2n−2 个。

**边界一：什么时候不减 2。** 这条规定作用在"主机号"上。**点对点链路**（如 [[04_计算机网络_CN/datalink/ppp.md|PPP]] 链路）上只有两个接口，用 /31 分配（主机位只有 1 位，21−2=0）显然荒谬，所以传统做法是给点对点链路分 **/30**：4 个地址减 2，正好剩 2 个可用，一头一个。做题时看到"两台路由器之间的链路要占 4 个地址"，来源就是这里。

**边界二：全 0 / 全 1 说的是主机号，不是整个地址。** 主机号全 1 的地址（如 `192.168.1.255`）是**直接广播**地址，路由器**可以**转发它到目的网络再广播；而 `255.255.255.255`（整个地址全 1）是**受限广播**地址，任何路由器都**不转发**。两者不是一回事。

### 特殊 IP 地址（按"能不能做源地址 / 目的地址"分）

只列"这些地址有特殊含义"是不够的，真正要分清的是它们**出现在哪个位置**：

| 网络号 | 主机号 | 可作源地址 | 可作目的地址 | 含义 |
| --- | --- | --- | --- | --- |
| 全 0 | 全 0 | ✅ | ❌ | 本网络上的本主机（主机启动、尚未获得地址时使用，如 DHCP 请求） |
| 全 0 | X | ✅ | ❌ | 本网络上主机号为 X 的主机 |
| 全 1 | 全 1 | ❌ | ✅ | **受限广播**：只在本网络上广播，任何路由器都不转发 |
| Y | 全 1 | ❌ | ✅ | **直接广播**：对网络号为 Y 的网络上的所有主机广播 |
| 127 | 非全 0 非全 1 的任意值 | ✅ | ✅ | 本地软件**环回测试**，数据报不进入任何网络 |

三条读法：

- **广播地址只能做目的地址。** 想想就明白：一个数据报的"发送者"不可能是"所有主机"。同理，[[04_计算机网络_CN/network/multicast.md|多播地址]] 也只能做目的地址。
- **全 0 网络号的地址只能做源地址。** 它的意思是"本网络"，而"本网络"是个相对说法，写进目的地址后路由器无法解读该往哪转。
- **环回地址源、目的都能用**，因为它压根不出主机——数据报由本机协议软件直接处理，不发送到任何网络。所以 `ping 127.0.0.1` 成功只能说明本机协议栈正常，跟网卡、网线、网关**一点关系都没有**。

### 分类编址垮在哪里

问题是**地址利用率**，而且是两头都不合适：

- 一个 B 类网络给 65534 个主机地址，实际单位可能只用几百个 —— 剩下六万多个地址被这个单位"锁死"，别人用不了
- 一个 C 类网络只有 254 个 —— 一个需要 300 台主机的单位就够不上，只能去申请 B 类，于是又浪费六万多个

也就是说，**颗粒度只有三档，档与档之间差 256 倍**，绝大多数单位的真实需求都卡在两档之间。子网划分（把大块切细）和 CIDR（取消档位、连续可调）就是分别从两个方向解决这件事的。

## 三、子网划分

### 基本思想：从主机号里借位

在**网络号不变**的前提下，从主机号的高位借若干位当**子网号**，把两级地址变成三级：

```
分类编址：  [  网络号  |            主机号            ]

子网划分：  [  网络号  |  子网号  |      主机号       ]
                        ↑ 从主机号高位借来的位
```

关键性质：**子网划分对外不可见**。外部路由器看到的仍然是那一个网络号，转发到本单位的边界路由器为止；进了单位内部，才由内部路由器按子网号继续分。这一条是子网划分能"不惊动全网"就把一个网络切开的原因。

例：C 类地址 192.168.1.0/24（主机号 8 位），借 3 位做子网号：

- 子网号 3 位 → 可划 23=8 个子网
- 主机号剩 5 位 → 每个子网可用 25−2=30 台主机

### 划完之后可用主机数为什么变少

这是最容易被"每划一次减 2"这个错误口诀带偏的地方。**正确的算法是：每个子网各自减 2，然后加起来。**

拿上面的例子对账：

|  | 划分前 | 划分后 |
| --- | --- | --- |
| 地址总数 | 256 | 8×32=256（一个没多一个没少） |
| 网络地址（主机号全 0） | 1 个 | **8 个** |
| 广播地址（主机号全 1） | 1 个 | **8 个** |
| 可分配给主机 | 256−2=254 | 8×(32−2)=240 |

少掉的是 254−240=14 个。这 14 个是怎么来的：8×2⏟划分后 8 个子网各占 2 个−2⏟划分前本来就占了 2 个=14

**推广到一般情形**：把一个网络划成 k 个等长子网，可用主机地址减少 2k−2 个。**代价随子网数线性增长**——这就是"子网别切得太碎"的定量依据，而不是一句感觉。

**反过来看**：如果题目问"划成 k 个子网后总可用地址数"，正确做法永远是"算出每个子网的主机位数 m，答 k×(2m−2)"，而不是拿 2n−2 去减什么。

### 子网掩码

子网掩码是一串连续的 1 后接一串连续的 0，1 的个数等于**网络前缀的长度**（网络号 + 子网号）。它的唯一用途是：网络（子网）地址=IP 地址&子网掩码

例：192.168.1.0 借 3 位做子网 →

```
IP地址:      192.168.1.  [xxx | xxxxx]
子网掩码:    255.255.255.[111 | 00000]
           = 255.255.255.224      →  CIDR 记法 /27
```

**掩码为什么在 CIDR 之后成了必须显式携带的信息。** 分类编址时代，看第一个字节就知道网络号占几位，掩码是**可以推出来的**（A 类 255.0.0.0、B 类 255.255.0.0、C 类 255.255.255.0），所以常常不写。CIDR 取消了类别，前缀长度变成任意值 —— 同一个 `192.168.1.100`，配 /24 属于 `192.168.1.0`，配 /20 属于 `192.168.0.0`，配 /26 属于 `192.168.1.64`。**没有掩码，一个 IP 地址就无法确定它属于哪个网络。** 所以现在掩码（或等价的 /n 记法）必须随地址一起给出。

### 常用掩码对照

| 前缀 | 点分十进制 | 末字节二进制 | 地址数 | 可用主机数 |
| --- | --- | --- | --- | --- |
| /24 | 255.255.255.0 | 00000000 | 256 | 254 |
| /25 | 255.255.255.128 | 10000000 | 128 | 126 |
| /26 | 255.255.255.192 | 11000000 | 64 | 62 |
| /27 | 255.255.255.224 | 11100000 | 32 | 30 |
| /28 | 255.255.255.240 | 11110000 | 16 | 14 |
| /29 | 255.255.255.248 | 11111000 | 8 | 6 |
| /30 | 255.255.255.252 | 11111100 | 4 | 2 |

这张表不必硬背，记住生成规则更稳：**末字节的值 = 256−2(32−n)**（当 24<n≤32）。比如 /27：256−25=224；/29：256−23=248。

### 例题 1：给定 IP 与掩码，求网络地址、广播地址、可用范围

**题目**（自造数据）：IP = 192.168.1.130，掩码 = 255.255.255.224。

**第 1 步：只对"有变化"的那个字节做二进制运算。**

*为什么这么做*：掩码是 255 的字节，与运算后原样保留；掩码是 0 的字节，与运算后必为 0。真正要动脑的只有那个既不是 255 也不是 0 的字节。

前三字节掩码是 255.255.255 → 原样保留 192.168.1。只需处理末字节。

```
130   = 100 00010
掩码 224 = 111 00000
```

**第 2 步：按位与得网络地址。**

```
  100 00010
& 111 00000
-----------
  100 00000  = 128
```

网络地址 = **192.168.1.128/27**

**第 3 步：主机位全置 1 得广播地址。**

*为什么这么做*：广播地址的定义就是"网络前缀不变、主机号全 1"。

```
  100 11111  = 159
```

广播地址 = **192.168.1.159**

**第 4 步：可用范围与数量。**

- 首个可用 = 网络地址 + 1 = 192.168.1.**129**
- 末个可用 = 广播地址 − 1 = 192.168.1.**158**
- 可用主机数 = 25−2=30

*验算*：158−129+1=30 ✓ 与公式一致。

### 例题 2：VLSM 变长子网划分

**题目**（自造数据）：某单位分到 172.20.0.0/16，下设 4 个部门，分别需要 1000、500、200、60 台主机。要求用变长子网掩码（VLSM）划分，给出各部门网段，并指出剩余可用空间的起点。

**第 1 步：把需求换算成主机位数与前缀长度。**

*为什么这么做*：需求给的是"能用的主机数"，而地址块是 2 的幂，必须先找出**最小的、能满足 2m−2≥ 需求 的 m**。

| 部门 | 需求 | 主机位 m | 可用数 2m−2 | 前缀 32−m | 块大小 2m |
| --- | --- | --- | --- | --- | --- |
| 甲 | 1000 | 10 | 1022 | **/22** | 1024 |
| 乙 | 500 | 9 | 510 | **/23** | 512 |
| 丙 | 200 | 8 | 254 | **/24** | 256 |
| 丁 | 60 | 6 | 62 | **/26** | 64 |

逐个验一下"最小"：m=9 时 29−2=510<1000，不够，所以甲必须 m=10；m=8 时 254<500，所以乙必须 m=9；m=7 时 126<200，所以丙必须 m=8；m=5 时 30<60，所以丁必须 m=6。

**第 2 步：按块从大到小依次分配。**

*为什么必须从大到小*：每个地址块的起始地址必须**按自身块大小对齐**（一个 /22 块的起点必须是 1024 的倍数）。如果先分小块，就会在地址空间里留下"位置不对齐"的空洞——比如先把 172.20.0.0~172.20.0.63 给了丁，那么接下来给甲的 /22 就只能从 172.20.4.0 起（172.20.0.0 已被占、172.20.1.0 不是 1024 的倍数），凭空浪费 960 个地址。**从大到小分，每个块自然落在对齐点上，一点不浪费。**

| 部门 | 网段 | 掩码 | 地址范围 | 可用主机 | 起点是否对齐 |
| --- | --- | --- | --- | --- | --- |
| 甲 | **172.20.0.0/22** | 255.255.252.0 | 172.20.0.0 ~ 172.20.3.255 | 1022 | 0 是 1024 的倍数 ✓ |
| 乙 | **172.20.4.0/23** | 255.255.254.0 | 172.20.4.0 ~ 172.20.5.255 | 510 | 1024 是 512 的倍数 ✓ |
| 丙 | **172.20.6.0/24** | 255.255.255.0 | 172.20.6.0 ~ 172.20.6.255 | 254 | 1536 是 256 的倍数 ✓ |
| 丁 | **172.20.7.0/26** | 255.255.255.192 | 172.20.7.0 ~ 172.20.7.63 | 62 | 1792 是 64 的倍数 ✓ |

对齐验算用的是"该块起点相对 172.20.0.0 的偏移量"：甲起点偏移 0，乙 1024，丙 1536，丁 1792。每个偏移都能被自己的块大小整除。

**第 3 步：相邻性验算与剩余空间。**

*为什么这么做*：VLSM 的正确性判据是"块与块首尾相接、不重叠、不留缝"。

- 甲末 172.20.3.255 → 乙首 172.20.4.0 ✓ 相接
- 乙末 172.20.5.255 → 丙首 172.20.6.0 ✓ 相接
- 丙末 172.20.6.255 → 丁首 172.20.7.0 ✓ 相接
- 丁末 172.20.7.63 → **剩余空间从 172.20.7.64 起**，一直到 172.20.255.255

**第 4 步：反面验算——倒着分会怎样。**

若按 60 → 200 → 500 → 1000 的顺序分，逐块跟一遍（偏移量仍相对 172.20.0.0 计）：

| 顺序 | 部门 | 块大小 | 起点必须是几的倍数 | 上一块用到哪 | 实际起点 | 跳过（空洞） |
| --- | --- | --- | --- | --- | --- | --- |
| 1 | 丁 /26 | 64 | 64 | — | 偏移 0（172.20.0.0） | 0 |
| 2 | 丙 /24 | 256 | 256 | 偏移 64 | 偏移 **256**（172.20.1.0） | **192** |
| 3 | 乙 /23 | 512 | 512 | 偏移 512 | 偏移 512（172.20.2.0） | 0 |
| 4 | 甲 /22 | 1024 | 1024 | 偏移 1024 | 偏移 1024（172.20.4.0） | 0 |

空洞只有一处：**172.20.0.64 ~ 172.20.0.255 这 192 个地址被跳了过去**。第 3、4 步没有再产生空洞，是因为前面几块加起来恰好凑到了下一块要求的对齐点上（64+192+256=512、512+512=1024）——**别想当然地以为"每一步都会浪费一大截"。**

这 192 个地址也不是完全作废，但它**再也装不下一个大于 /26 的整块**：只能拆成 172.20.0.64/26 与 172.20.0.128/25 两块另作他用。**空洞的代价不在数量，在于它把连续空间打碎成了对不齐的碎片。**

**这就是"从大到小"的定量理由**——不是习惯，是对齐约束逼出来的，而且可以一句话证明：块大小都是 2 的幂，按从大到小排列时，任一块前面所有块的大小之和一定是本块大小的整数倍，所以**每一块的起点天然落在对齐点上，空洞恒为 0**（本例从大到小分时四块首尾相接，用到 172.20.7.63 为止，一个地址都没跳过）。倒着分则没有这个保证，空洞是否出现、出现多少，完全看数字凑不凑巧。

## 四、CIDR 无分类编址

CIDR（Classless Inter-Domain Routing）彻底抛弃 A/B/C 类的概念，用 **IP 地址/前缀长度** 表示一个地址块：

```
192.168.1.0/24    → 前 24 位是网络前缀，后 8 位是主机号
10.0.0.0/8        → 前 8 位是网络前缀
172.16.128.0/20   → 前 20 位是网络前缀
```

一个 CIDR 地址块 a.b.c.d/n 含 232−n 个地址（**全 0 和全 1 的主机号都算在内**）。

| 前缀 | 地址数 | 相当于分类网络 |
| --- | --- | --- |
| /16 | 65536 | 1 个 B 类 |
| /20 | 4096 | 16 个 C 类 |
| /22 | 1024 | 4 个 C 类 |
| /23 | 512 | 2 个 C 类 |
| /24 | 256 | 1 个 C 类 |

CIDR 相对分类编址的两处改进：

- **前缀长度连续可调**，颗粒度从"3 档、档间差 256 倍"变成"逐位可调、档间差 2 倍"，浪费上限从 256 倍降到 2 倍
- **允许把多个连续块合并成一条路由通告**（下一节），这是压缩全球转发表的关键手段

注意 CIDR 的两个方向别混：**向下切细**是子网划分（借主机位当子网位，前缀变长）；**向上合并**是路由聚合/构成超网（前缀变短）。两者是同一把尺子往相反方向拧。

## 五、路由聚合与"聚合过头"

### 聚合怎么算

路由聚合就是把若干个连续地址块合成一个更短前缀的块，用一条路由通告出去。算法只有一步：**求所有块网络地址的最长公共前缀。**

例：4 个连续的 /24：

```
192.168.0.0   → 11000000 10101000 000000|00 . 0
192.168.1.0   → 11000000 10101000 000000|01 . 0
192.168.2.0   → 11000000 10101000 000000|10 . 0
192.168.3.0   → 11000000 10101000 000000|11 . 0
                                   ↑ 前 22 位相同，第 23 位起分岔
```

最长公共前缀 22 位 → 聚合为 **192.168.0.0/22**。

**能聚成一条的条件是什么**：这个 /22 覆盖的 1024 个地址，恰好被这 4 个 /24 **不多不少地填满**。所以聚合能否"干净"，取决于两条：

- 这些块**连续**（地址空间上首尾相接、无空洞）
- 合起来的总大小是 2 的幂，且**起点按这个大小对齐**

两条有一条不满足，就聚不成一条干净的路由。

### 聚合过头：把不属于自己的地址也吸进来

强行去聚不满足条件的块，公共前缀会被迫变得很短，**短到把不属于自己的地址也罩进来**。

#### 例题 3：判断能否聚合，并给出正确的聚合方案

**题目**（自造数据）：某机构分到三个地址块：`203.0.113.64/26`、`203.0.113.128/26`、`203.0.113.192/26`。注意 `203.0.113.0/26` 属于**另一家单位**。问：能否把这三块聚成一条路由？若不能，最少要通告几条？

**第 1 步：把三个网络地址的末字节写成二进制，找最长公共前缀。**

*为什么这么做*：前 24 位（203.0.113）三块完全相同，分歧只可能出现在末字节的高位上。

```
 64 = 01 000000
128 = 10 000000
192 = 11 000000
      ↑
   第 25 位就已经不同（0/1/1），第 26 位也不同（1/0/1）
```

第 25 位上出现了 0 和 1 两种取值 → **公共前缀只有 24 位**。

**第 2 步：写出强行聚合的结果，并检查它罩住了什么。**

*为什么这么做*：聚合的正确性判据不是"能不能算出一个前缀"，而是"算出来的这个块里有没有不属于我的地址"。

强行聚合 → `203.0.113.0/24`，覆盖 203.0.113.0 ~ 203.0.113.255 共 256 个地址。

而本机构实际拥有的只有 3×64=192 个地址。多罩进来的 64 个正是 **`203.0.113.0/26`——那是另一家单位的**。

**这个后果有多严重**：一旦本机构按 /24 通告，全网发往 203.0.113.0~203.0.113.63 的分组也会被引到本机构来（若这条 /24 恰好是最长匹配的话）。另一家单位的流量被劫走，而本机构又交付不了。**所以"能算出公共前缀"绝不等于"可以聚合"。**

**第 3 步：退而求其次，分组聚合。**

*为什么这么做*：既然三块凑不成一个干净的 2 的幂，就找**能凑成干净块的子集**。

- 128 与 192：`10 000000` 与 `11 000000`，公共前缀 **25 位** → `203.0.113.128/25`
- 验证：/25 覆盖 128~255 共 128 个地址，正好等于两块 /26 之和，**一个多余的地址都没有** ✓
- 64 这一块：64 是 01000000，它与前两块凑不成 2 的幂对齐的整块，只能单独通告 `203.0.113.64/26`

**答案：不能聚成一条；最少通告 2 条** —— `203.0.113.64/26` 与 `203.0.113.128/25`。

**第 4 步：反思——如果那 4 个 /26 都属于本机构呢？**

那就能聚成 `203.0.113.0/24` 一条：4 个 /26 共 256 个地址，起点 0 对齐，不多不少。**同一个前缀形式，是否合法完全取决于"这个块里的地址是不是全都归我"。** 这也解释了一件反直觉的事：**从路由表的一行 `X/22` 上，看不出它是由哪几个子块聚合而成的**，所以判断"某地址是否真属于该机构"不能只看匹配上了，必须结合更具体的路由。

## 六、最长前缀匹配

### 规则与理由

一个目的地址可能同时匹配转发表里的多条路由。规则是：**选前缀最长的那一条。**

理由不是约定，是可以推的：**前缀越长，地址块越小，说明这条路由知道得越"具体"。**

- `X/22` 匹配意味着"目的地在这 1024 个地址里的某处，我把它交给某个方向"
- `X/24` 匹配意味着"目的地在这 256 个地址里"，是前者的**子集**，且信息更精确
- 一个地址块的路由能被更细的路由覆盖，只可能是因为**那 256 个地址被单独安排了去向**（比如被划给了某家单位、或者内部另有更优路径）

所以选长的，就是选那条**专门为这一小块地址设置的**路由。反过来若选短的，那条更具体的路由就永远不会被命中——它的存在毫无意义，转发表里所有细路由都成了摆设。

**两条特殊路由**：

- **主机路由**（特定主机路由）：前缀 `a.b.c.d/32`，只匹配唯一一个地址，是最具体的路由，在转发表中排最前面。用于网络排错、控制或安全需要。
- **默认路由**：前缀 `0.0.0.0/0`，掩码全 0，与任何目的地址相与结果都是全 0，因此**永远匹配**。它是最不具体的，只有其他所有路由都不匹配时才轮到它。

于是查表流程可以概括为：**主机路由 → 按前缀由长到短逐行 → 默认路由**。按这个顺序排表还有个好处：**从第一行开始查，只要匹配上就可以立即停止**，不必扫完整张表。

把主机路由和默认路由**单列成两步**，是教材给出的分组转发算法的写法，方便照着做题。要清楚它和另一种说法是**同一件事**：主机路由不过是"前缀长度 = 32"、默认路由不过是"前缀长度 = 0"，三步合起来仍然只是**一次**最长前缀匹配——按前缀由长到短排表时，/32 天然排在最前、/0 天然排在最后。所以**不存在"先查普通路由、查不到再单独查一遍默认路由"的两趟流程**，看到哪种表述都不必改主意。

### 分组转发算法的完整流程

把上面这些规则合起来，就是路由器（和主机）收到一个待转发分组时走的完整流程：

流程里体现了三条已经讲过的规则：**主机路由排最前**（最具体）、**按前缀由长到短逐行**（最长前缀匹配的实现方式）、**默认路由兜底**（永远匹配，所以放最后）。**命中即停**——不必扫完整张表。

### 例题 4：最长前缀匹配

**题目**（自造数据）：某路由器的转发表如下。分别求目的地址 `10.1.41.77`、`10.1.44.9`、`10.1.60.1` 的下一跳。

| 目的网络 | 下一跳 |
| --- | --- |
| 10.1.41.0/24 | C |
| 10.1.40.0/22 | B |
| 10.1.32.0/20 | A |
| 0.0.0.0/0 | D |

**第 1 步：先把每条路由的覆盖区间算出来。**

*为什么这么做*：与其对每个目的地址逐条做按位与，不如一次性把区间算清楚，之后全部题目都变成"落在哪个区间里"的判断。区间 = [网络地址, 网络地址 + 232−n − 1]。

| 路由 | 块大小 | 覆盖区间 |
| --- | --- | --- |
| 10.1.41.0/24 | 256 | 10.1.**41**.0 ~ 10.1.**41**.255 |
| 10.1.40.0/22 | 1024 | 10.1.**40**.0 ~ 10.1.**43**.255 |
| 10.1.32.0/20 | 4096 | 10.1.**32**.0 ~ 10.1.**47**.255 |
| 0.0.0.0/0 | 全部 | 任意 |

第三字节的算法：/22 的块大小是 1024 = 4 个 /24，所以起点 40 覆盖 40~43；/20 的块大小是 4096 = 16 个 /24，起点 32 覆盖 32~47。

**第 2 步：逐个目的地址判断落在哪些区间里，取最长。**

**`10.1.41.77`**：

- 落在 /24（第三字节 = 41）✓
- 落在 /22（41 ∈ 40~43）✓
- 落在 /20（41 ∈ 32~47）✓
- 落在 /0 ✓

四条全中，取最长 **/24 → 下一跳 C**

**`10.1.44.9`**：

- /24？第三字节 44 ≠ 41，✗
- /22？44 ∉ 40~43，✗
- /20？44 ∈ 32~47，✓
- /0 ✓

取最长 **/20 → 下一跳 A**

**`10.1.60.1`**：

- /24 ✗（60 ≠ 41）；/22 ✗（60 ∉ 40~43）；/20 ✗（60 ∉ 32~47）
- 只剩 /0 ✓

**走默认路由 → 下一跳 D**

**第 3 步：回头看这张表说明了什么。**

三个地址各自命中不同长度的前缀，正好演示了转发表的分层结构：/20 是一张"大网兜底"，/22 在里面挖了一块单独安排，/24 又在 /22 里再挖一块。**每加一条更长的前缀，就是从上一层里"抠出一小块另作安排"。** 最长前缀匹配就是保证这些"抠出来的安排"真的生效的机制。

## 七、直接交付与间接交付

主机（或路由器）发送 IP 数据报时，第一件事是判断目的主机是否连接在**本网络**上：

**判据**：把**目的 IP 地址**与**本网络的子网掩码**按位与，看结果是否等于本网络的网络前缀。

- **相等 → 直接交付**：目的主机就在本网络上。用 [[04_计算机网络_CN/network/arp.md|ARP]] 解析**目的主机自己**的 MAC 地址，封装成帧直接发出，不经过路由器。
- **不等 → 间接交付**：目的主机不在本网络。用 ARP 解析**默认网关（路由器）**的 MAC 地址，把数据报交给路由器，后续的事情全部由路由器负责。

⚠️ 一处极易错的细节：与运算用的是**目的 IP 地址**和**本机的掩码**，而不是"源 IP 与目的 IP 各自算一遍再比"。后一种写法在两台主机掩码不同时会给出错误结论。

默认网关是主机的一项配置参数（与 IP 地址、掩码一起配），它**必须与本主机在同一网络内**——否则主机连它的 MAC 都解析不到，这个配置就是死的。

这个判断是几乎所有网络层综合题的第一步：**先判直接还是间接交付，再决定 ARP 解析谁的 MAC，最后才谈帧里填什么地址。** 后两步见 [[04_计算机网络_CN/network/arp.md|ARP 地址解析协议]]。

## 易混淆知识点

**1. 可用主机数是 2m−2，但"减少的总量"不是每划一次减 2**

m 是**主机位数**，不是总位数。把一个网络划成 k 个等长子网，总可用地址减少的是 2k−2 个，因为划分后有 k 个网络地址和 k 个广播地址，而划分前只有 1 组。

**2. 减 2 减的是主机号，/30 与 /31 的处境不同**

/30 有 2 位主机号，22−2=2，正好够一条点对点链路两端。/31 只有 1 位，按常规算法可用数为 0——所以点对点链路传统上分 /30，一条链路吃掉 4 个地址。

**3. 受限广播 vs 直接广播**

`255.255.255.255` 是受限广播，**任何路由器都不转发**；`Y.255.255.255`（主机号全 1）是直接广播，路由器**可以**把它转发到目的网络再广播。两者不能混为一谈。

**4. 广播地址与多播地址只能做目的地址，全 0 网络号只能做源地址**

理由分别是"发送者不可能是所有主机"和"'本网络'是相对说法，写进目的地址路由器无法解读"。

**5. 掩码是"切割工具"，不是地址**

同一个 IP 地址配不同掩码属于不同网络。CIDR 之后掩码无法从地址推出，必须显式携带——这是它与分类编址时代最本质的区别。

**6. 按位与只需处理"有变化的那个字节"**

掩码是 255 的字节原样抄 IP，掩码是 0 的字节直接写 0，只对那个中间字节做二进制运算。这不是偷懒，是减少出错面。

**7. 能算出公共前缀 ≠ 可以聚合**

聚合的判据是"聚出来的块里的地址是否全部属于本机构"。前缀被迫变短就会把邻居的地址也吸进来，造成流量被错误引导。反过来，从转发表的一行 `X/22` 上看不出它由哪几个子块聚成，所以"匹配上"不等于"真属于"。

**8. VLSM 必须从大到小分配**

因为每个块的起点必须按自身块大小对齐。从大到小分时，任一块前面所有块的大小之和必是本块大小的整数倍，起点天然对齐，**空洞恒为 0**；倒着分就没有这个保证，后面的大块只能跳到下一个对齐点，跳过去的那一段成为空洞（本篇例题 2 里是 192 个地址），且只能再拆成更小的块使用。

**9. 最长前缀匹配选最"具体"的路由**

/32（主机路由）最具体，排在最前；/0（默认路由）最不具体，排在最后。若反过来选最短的，所有细粒度路由都会失效。

**10. A 类网络号 1~126，不是 0~127**

0 开头保留表示"本网络"，127 开头保留作环回测试，两个都从可指派范围里扣掉，所以是 27−2=126。B、C 类没有对应的扣除，网络数不减 2。

## 本节小结

整节可以串成一条"**颗粒度不断变细、代价不断被算清**"的主线：

- **地址两级结构的第一动机是压缩转发表**——按网络查表比按主机查表小三四个数量级。后面所有机制都是这条动机的延伸。
- **主机号全 0、全 1 被征用**，是因为 IP 层必须能写出"网络本身"和"该网络的全部主机"这两个概念，不是因为它们"被占了"。所以可用主机数是 2m−2；点对点链路因此要分 /30。特殊地址的真正分界不是"长什么样"，而是**能做源地址还是目的地址**：广播/多播只能做目的，全 0 网络号只能做源，环回两者皆可（因为它压根不出主机）。
- **分类编址垮在颗粒度**：只有 3 档、档间差 256 倍。子网划分从内部把大块切细，代价是可用地址减少 2k−2 个（每个子网各自赔上一对网络地址与广播地址）——**代价随子网数线性增长**，这是"别切太碎"的定量依据。
- **CIDR 取消档位，前缀逐位可调**，浪费上限从 256 倍降到 2 倍；同时使掩码从"可推出"变成"必须显式携带"。子网划分（前缀变长）与路由聚合（前缀变短）是同一把尺子的两个方向。
- **聚合的判据是"聚出来的块里有没有别人的地址"**，不是"能不能算出公共前缀"。不连续、不对齐就会被迫把前缀缩短，把邻居的地址一起罩进来。凑不成一条时，退而求其次找**能凑成 2 的幂对齐块的子集**分组聚合。
- **最长前缀匹配是让"细粒度安排"生效的机制**：每条更长的前缀，都意味着从上层地址块里抠出一小块另作安排；选最长就是尊重这个安排。查表顺序是主机路由 → 前缀由长到短 → 默认路由，命中即停。
- **VLSM 从大到小分配**，是被"块起点必须按块大小对齐"逼出来的：从大到小分时，前面所有块的大小之和必是本块大小的整数倍，起点天然对齐、**空洞恒为 0**；倒着分则要跳到下一个对齐点，跳过的那段成为空洞（例题 2 里是 192 个地址），只能再拆成更小的块使用。
- **发送前先判直接 / 间接交付**：目的 IP 与本机掩码按位与，与本网络前缀比。相等就 ARP 解析目的主机，不等就 ARP 解析默认网关。这是所有网络层综合题的第一步。

- 谢希仁《计算机网络》（第 7 版）：IP 地址的两级结构，见印刷版 **p123–p124**（4.2.2 IP 地址）——"IP 地址 ::= {<网络号>，<主机号>}"，且"IP 地址中包含网络号就表明，不连网的主机就没有 IP 地址"。

- 同书 **p125**：分类编址的浪费——"一个 A 类网络地址块的主机号数目超过了 1677 万个……一个 C 类网络地址块可指派的主机号只有 254 个。但不少单位需要有 300 个以上的 IP 地址，那么干脆申请一个 B 类网络地址块……这样就浪费了不少的地址资源"；以及子网划分的定位："在 IP 地址的主机号中，插入一个子网号，把两级的 IP 地址变为三级的 IP 地址"。
- 同书 **p127**：地址掩码——"地址掩码（常简称为掩码）由一连串 1 和接着的一连串 0 组成，而 1 的个数就是网络前缀的长度……把二进制的 IP 地址和地址掩码进行按位 AND 运算，即可得出网络地址"，并以 128.14.35.7/20 → 128.14.32.0/20 为例；同页表 4-3 给出常用 CIDR 地址块与"包含的地址数"，并注明"在'包含的地址数'中把全 1 和全 0 的主机号都计算在内了"。
- 同书 **p140**：分层寻址压缩转发表——"如果用目的地址直接查找转发表，那么这种结构的转发表就会非常庞大，使得查找过程非常之慢……先查找目的网络（网络前缀），在找到了目的网络之后，就把分组在这个网络上直接交付目的主机。由于互联网上的网络数远远小于主机数，这样就可以大大压缩转发表的大小"。
- 同书 **p141**【例 4-2】：直接交付与间接交付的判据——"主机 H1 先把要发送的分组的目的地址和本网络 N1 的子网掩码按位进行 AND 运算，得出运算结果。如果运算结果等于本网络 N1 的前缀，就表明目的主机连接在本网络上；否则，就必须把分组发送到路由器 R1"。
- 同书 **p142–p143**（4.3.2 最长前缀匹配）：**聚合过头**的原始论证。教材用公司 A、公司 B 的例子说明，公司 B 把自己的三个 /24 聚合成 128.1.24.0/22 后，"这个前缀和原来的前缀在形式上是一样的，但实际的区别是很大的：在图 4-26 左边的网络前缀中包含地址 128.1.24.1，但公司 B 的聚合后的网络前缀则不包含这个地址"，原因是"在转发表中的项目 128.1.24.0/22 并未说明是由哪几个子网聚合而成的"。最长前缀匹配规则的表述是："如果一个分组在转发表中可以找到多个匹配的前缀，那么就应当选择前缀最长的一个作为匹配的前缀……网络前缀越长，其地址块就越小，因而路由就越具体"，并给出按前缀长短排表、"只要检查到匹配的，就不必再继续往下查找"的做法。本篇例题 3 的数据为自造，论证思路承自该处。
- 同书 **p143**：主机路由与默认路由——"假定这个特定主机的点分十进制 IP 地址是 a.b.c.d，那么在转发表中对应于主机路由的网络前缀就是 a.b.c.d/32……主机路由在转发表中都放在最前面"；"用一个特殊前缀 0.0.0.0/0 来表示默认路由。这个前缀的掩码是全 0……用全 0 的掩码和任何目的地址进行按位 AND 运算，结果一定是全 0，即必然是和转发表中的 0.0.0.0/0 相匹配的"。同书 **p144** 给出完整的分组转发算法。[[04_计算机网络_CN/network/ip-datagram.md|上一篇IP 数据报格式]][[04_计算机网络_CN/network/ip-fragment.md|下一篇IP 分片与重装]]
