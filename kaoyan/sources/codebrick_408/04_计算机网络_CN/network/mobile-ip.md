## 知识框架

本节回答 5 个问题：

- 主机换个网络就重新 DHCP 拿个新地址，不也能上网？**移动 IP 到底多解决了什么**？
- 移动节点在外地明明有了新地址，为什么还要**死抱着**原来那个归属地址不放？
- 转交地址在整个互联网上**并不唯一**——多个移动节点可以共用同一个转交地址。这不会乱套吗？
- 为什么"B 发给 A"必须绕道归属代理，而"A 发给 B"却可以直接发？这个**不对称**是设计缺陷吗？
- 移动节点从一个外地网络又移动到另一个外地网络时，谁负责更新？**旧的登记要不要注销**？

## 一、移动 IP 解决什么问题

正常情况下，主机换了网络就必须换 IP 地址（例如通过 DHCP 重新获取）。但 IP 地址一变，会产生一个致命后果：

**TCP 连接是用四元组（源 IP、源端口、目的 IP、目的端口）标识的。** 源 IP 一变，这条连接在双方眼里就成了两条不同的连接——已有的 TCP 连接必然中断（见 [[04_计算机网络_CN/transport/tcp-connection.md|TCP 连接管理]]）。

移动 IP 的目标就是：**让移动节点在切换网络时保持原有 IP 地址不变**，使 TCP 连接不中断、对上层应用完全透明。

### 划清一条边界：什么不算移动 IP

笔记本关机、搬到另一个办公室、开机后由 DHCP 分到新 IP、重新打开网页——这**不是**移动 IP。

区别在于：DHCP 那套流程里，**IP 地址变了、原有的连接断了、只是又重新建了新的连接**。移动 IP 强调的是**移动过程中 IP 地址不变、会话不中断**。

这条边界几乎是这一节最常被拿来考的一处：**判据不是"换了网络还能上网"，而是"换网络时地址变没变、连接断没断"。**

### 一个便于记忆的类比

移动 IP 的思路和"毕业后怎么继续联系同学"一模一样：

一个班的大学生毕业时各奔东西，事先谁都不知道自己未来工作单位的准确通信地址。办法很简单——**彼此留下各自的家庭地址（永久地址）**。要和某位同学联系，只要写信到他的家庭地址，请其家长把信件转交一下即可。得知该同学的新地址后，就可以直接联系了。

对照过来：家庭地址 = **归属地址**，家长 = **归属代理**，转交 = **隧道转发**。

## 二、三个功能实体与两个地址

### 两个地址

| 地址 | 别名 | 归谁所有 | 变不变 |
| --- | --- | --- | --- |
| **归属地址**（home address） | 永久地址、原始地址 | 属于**归属网络**的地址块 | **永久不变** |
| **转交地址**（care-of address, CoA） | — | 属于**被访网络**的地址块 | 每换一个被访网络就换一个 |

**转交地址的网络号必须与被访网络一致**——否则被访网络的路由器无法把分组交付给它，这条地址就是死的。

**永久地址与归属网络的关联是不变的。** 这是整套机制的基点：不管移动节点跑到哪，全世界发给它的分组仍然会被路由到归属网络。

### 三个功能实体

| 实体 | 位置 | 职责 |
| --- | --- | --- |
| **移动节点**（移动站） | 在不同网络间移动的主机 | 拥有永久的归属地址；到外地后获得转交地址 |
| **归属代理**（home agent） | **归属网络**上的路由器 | **截获**发往移动节点归属地址的分组，用隧道转发到转交地址 |
| **外地代理**（foreign agent） | **被访网络**上的路由器 | 为移动节点创建转交地址；把转交地址通知归属代理；解封装隧道分组并交付给移动节点 |

两个代理都是"既是路由器、也是主机"的双重身份——它们作为代理的特定功能是在**应用层**完成的。

移动节点所**原始连接**到的网络叫**归属网络**（home network），它移动到的网络叫**被访网络**（visited network）或**外地网络**（foreign network）。

### 转交地址不唯一，为什么不乱套

这一条最反直觉，但它揭示了外地代理是怎么工作的。

**事实**：转交地址**在互联网中并不具有唯一性**。外地代理可以给好几个移动节点指派**同样的**转交地址，甚至把**自己的 IP 地址**直接指派为移动节点的转交地址。

**为什么不会混乱**：因为外地代理向连接在被访网络上的移动节点发送数据报时，**不使用 [[04_计算机网络_CN/network/arp.md|ARP]]**，而是**直接使用这个移动节点的 MAC 地址**。（移动节点首次和外地代理通信时，外地代理就记录下了它的 MAC 地址。）

推一层就清楚了：转交地址的唯一作用是**把分组从互联网引到外地代理这里**。一旦分组到了外地代理手上，"该交给本网络上的哪一台移动节点"这个问题，外地代理是靠自己维护的那张（移动节点 ↔ MAC 地址）表来回答的——**根本没用到转交地址**。所以转交地址不必唯一。

**还要记住两点**：

- 转交地址是供**移动节点、归属代理、外地代理**三方使用的，**各种应用程序都不使用它**。应用程序看到的永远是归属地址。
- 移动节点本身也可以充当外地代理，此时的转交地址叫**同址转交地址**（co-located care-of address）。

- **好处**：移动节点可以移动到**任何**网络，不必担心那里有没有可用的外地代理
- **代价**：移动节点需要额外的软件，使自己能充当外地代理，并且必须能接收发往转交地址的数据报

## 三、通信过程

设通信者 B 要和移动节点 A 通信。B 并不知道 A 在哪，它只知道 A 的**永久地址**。

### 四个关键步骤

**① B → 归属代理。** B 用 A 的**永久地址**作为目的地址正常发送。分组按常规路由被送到归属网络，被 A 的**归属代理截获**。

⚠️ **只有当 A 离开归属网络时，归属代理才截获发给 A 的数据报。** A 在家的时候一切照常，归属代理不做任何事。

**② 归属代理 → 外地代理（隧道）。** 归属代理已经知道 A 的转交地址（靠前面的登记），于是把 B 发来的数据报**再封装**：新数据报的目的地址是**转交地址**。这里用的就是 [[04_计算机网络_CN/network/ipv6.md|IPv6 过渡]] 与 [[04_计算机网络_CN/network/nat.md|VPN]] 里那套**隧道技术（IP-in-IP）**。

**③ 外地代理拆封并交付。** 外地代理把收到的封装数据报**拆封**，取出 B 发送的原始数据报，转发给 A。**这个原始数据报的目的地址仍然是 A 的永久地址**——这正是"对上层透明"的落点：A 的 TCP/应用层看到的目的地址从头到尾没变过。A 同时也从原始数据报里得到了 B 的 IP 地址。

**④ A → B 直接发送。** A 仍然用**自己的永久地址**作为源地址、B 的 IP 作为目的地址，直接发出去。**这个数据报显然没有必要再通过 A 的归属代理转发。**

### 那个不对称：为什么去要绕、回不用绕

去程绕道，是因为 **B 不知道 A 在哪**——它手上只有归属地址，只能寄到"老家"由归属代理转交。

回程不绕，是因为 **A 完全知道 B 在哪**——B 的 IP 地址就明明白白写在收到的那个原始数据报的源地址栏里，A 直接发就行。

**所以这个不对称不是缺陷，是"谁掌握对方位置信息"这个不对称的直接后果。** 但它确实带来了效率问题，就是下一节的三角形路由。

### 需要新增的四类协议

为了支持移动性，网络层要附加以下新功能：

| # | 协议 | 做什么 |
| --- | --- | --- |
| 1 | **移动节点 → 外地代理的协议** | 移动节点接入被访网络时必须向外地代理**登记**以获得临时转交地址；离开该被访网络时要向这个被访网络**注销**其原来的登记 |
| 2 | **外地代理 → 归属代理的登记协议** | 外地代理向移动节点的归属代理登记它的转交地址 |
| 3 | **归属代理数据报封装协议** | 归属代理收到发给移动节点的数据报后，再封装为一个新的数据报，目的地址为转交地址，然后转发 |
| 4 | **外地代理拆封协议** | 外地代理收到封装好的数据报后取出原始数据报，发送给移动节点 |

### 继续移动到第三个网络：旧登记要不要注销

设 A 原先在被访网络 N₁，现在移动到另一个被访网络 N₂：

- A 向 N₂ 的外地代理登记，获得 N₂ 里的新转交地址
- N₂ 的外地代理把这个新转交地址告诉 A 的**归属代理**
- 此后归属代理就把收到的、发送给 A 的数据报封装后转发到 **N₂ 的外地代理**

**关键点：N₁ 的外地代理并不需要去归属代理注销那个旧的转交地址。** 因为 N₂ 的外地代理的登记动作会**直接取代**旧记录——归属代理那里只保留最新的一条。

注意这里和上一节表格第 1 行的"注销"不矛盾：**注销发生在移动节点与它离开的那个外地代理之间**（本地的登记状态要清掉），而**归属代理那边的转交地址是靠新登记覆盖的**，不需要旧外地代理再去销一次。两处说的是不同的登记。

还要注意：在 A 从 N₁ 移动到 N₂ 的前后，**数据报始终由同一个归属代理转发**，只是转发的目的地从 N₁ 换成了 N₂。归属代理是永远不变的那个锚点。

## 四、间接路由选择与三角形路由问题

上面这套"分组先发到归属网络、再由归属代理转发"的做法称为**间接路由选择**（indirect routing）：源站并不知道移动节点的当前地址，把数据报发往移动节点的归属网络，以后的工作都由归属代理来完成。

### 三角形路由选择问题

间接路由选择会引起数据报转发的低效，文献中称为**三角形路由选择问题**（triangle routing problem）：

本来 B 和 A 之间可能存在一条**更短更有效**的路由，但现在数据报必须走"B → 归属代理 → 外地代理"这**两条边**，而不是"B → A"这**一条边**。三个点连成一个三角形，走两边不走一边——名字就是这么来的。

**看一个极端例子**：如果 **B 所在的网络恰好就是 A 到达的被访网络**呢？那么 B 发数据报给 A 本来是"在同一个网络上直接交付"，**根本不需要经过任何路由器**。但因为 B 并不知道 A 的位置，发给 A 的数据报只好**两次穿越广域网**（先跑到归属网络，再跑回来），既浪费时间，也增加了网上不必要的通信量。

**注意：低效只出现在"去程"。** 回程（A → B）是直接发的，只走一条边。所以三角形路由是个**单向**的效率问题。

## 五、直接路由选择

解决三角形路由问题的一种方法是**直接路由选择**，代价是**增加复杂性**。

### 基本做法

让通信者 B 创建一个**通信者代理**（correspondent agent）：

- 通信者代理向 A 的**归属代理**询问 A 在被访网络的转交地址
- 由**通信者代理**（而不是归属代理）把数据报用隧道技术发送到被访网络的外地代理
- 外地代理拆封，把数据报转发给移动节点

这样数据报就不必绕道归属网络，走的是"B → 被访网络"这一条边。

### 引出的两个新问题

**问题一：怎么问到转交地址？** 需要增加一个**移动用户定位协议**（mobile-user location protocol），用来让通信者代理向移动节点的归属代理查询转交地址。

**问题二：移动节点又移动了怎么办？** 这个问题的解法引入了一个新角色——**锚外地代理**（anchor foreign agent）：**移动节点首次漫游到的那个被访网络的外地代理**。

流程是这样的：

- B 的通信者代理从 A 的归属代理得到 A 漫游到的被访网络 N₁ 的外地代理，这个就是**锚外地代理**
- 通信者代理把 B 发给 A 的数据报再封装后，发送到**锚外地代理**
- 锚外地代理拆封后把数据报发送给 A
- **A 移动到另一个被访网络 N₂**
- A 向 N₂ 的**新外地代理**登记
- **新外地代理把 A 的新转交地址告诉锚外地代理**
- 此后锚外地代理收到发给 A 的封装数据报时，就用 A 的**新转交地址**对数据报**再封装一次**，发送到 N₂ 的新外地代理，由它拆封后转发给 A

同理，A 再漫游到别的网络时，那个网络的外地代理**仍然是和锚外地代理联系**。

**锚外地代理的作用可以一句话概括：它取代归属代理，成为新的"转发锚点"。** 通信者代理只需要记住锚外地代理这一个地址，后续 A 怎么移动都由锚外地代理跟进——代价是数据报多经过一次封装/转发。

### 两种路由选择的对比

|  | 间接路由选择 | 直接路由选择 |
| --- | --- | --- |
| 谁做隧道封装 | **归属代理** | **通信者代理** |
| 去程路径 | B → 归属代理 → 外地代理 → A（三角形） | B → 锚外地代理 → （必要时再转）→ A |
| 需要的额外协议 | 登记 + 封装 + 拆封 | 再加**移动用户定位协议** |
| 移动节点再移动时谁跟进 | 归属代理（新外地代理直接登记覆盖） | **锚外地代理** |
| 复杂性 | 较低 | **较高** |

### 移动性管理

上面讨论的这些新增措施和协议，文献中统称为**移动性管理**（mobility management，也常简译作移动管理）。移动性管理涉及的面比上面讨论的还要宽——例如**安全问题**也是必须要解决的（归属代理凭什么相信"我是 A 的外地代理"这句话？没有认证，任何人都能把 A 的流量劫走）。

## 易混淆知识点

**1. 转交地址动态变化，归属地址永久不变**

移动节点每到一个新的被访网络就获得新的转交地址；归属地址与归属网络的关联始终不变。**应用程序永远只看到归属地址**，转交地址只供移动节点、归属代理、外地代理三方使用。

**2. 接收数据要经过归属代理，发送数据不需要**

不对称的根源是"谁知道对方的位置"：B 不知道 A 在哪，只能寄到老家；A 从收到的分组里就能读出 B 的 IP，可以直接发。**这不是缺陷，但它导致了三角形路由问题（且该问题只出现在去程）。**

**3. 关机换网络重新拿 IP 不算移动 IP**

判据不是"换网络还能上网"，而是"换网络时 IP 变没变、TCP 连接断没断"。

**4. 转交地址在互联网上并不唯一**

外地代理可以给多个移动节点指派同一个转交地址，甚至用自己的 IP 当转交地址。因为**外地代理向移动节点交付时不用 ARP，直接用记录下来的 MAC 地址**。

**5. 归属代理只在移动节点"不在家"时才截获**

移动节点在归属网络上时，一切按常规路由走，归属代理不做任何特殊处理。

**6. 移动到新的被访网络时，旧外地代理不必去归属代理注销**

新外地代理的登记会直接覆盖旧记录。但移动节点**离开某个被访网络时确实要向该被访网络注销本地登记**——两处说的是不同的登记，别混。

**7. 隧道封装后，内层数据报的目的地址仍是归属地址**

外层目的地址才是转交地址。外地代理拆封后交给移动节点的，是**目的地址为归属地址**的原始数据报——这是"对上层透明"的落点。

**8. 锚外地代理是直接路由选择才有的角色**

它是移动节点**首次**漫游到的那个被访网络的外地代理，在直接路由选择中取代归属代理成为转发锚点。间接路由选择里没有这个概念。

**9. 同址转交地址 = 移动节点自己充当外地代理**

好处是可以移动到任何网络、不依赖当地有没有外地代理；代价是移动节点需要额外软件。

## 本节小结

本节的推导链条是"**为什么不能换地址 → 换了怎么办 → 转发绕远了怎么办**"：

- **移动 IP 要保住的是 IP 地址不变**，因为 TCP 连接由四元组标识，地址一变连接必断。**判据不是"换网络还能上网"（那是 DHCP 就能做到的），而是"地址变没变、会话断没断"。**
- **两个地址各司其职**：**归属地址**永久不变、与归属网络的关联恒定，全世界发给移动节点的分组仍然被路由到归属网络；**转交地址**属于被访网络，随位置变化。应用程序只看得到归属地址。
- **转交地址不必唯一**——因为它的唯一作用是"把分组引到外地代理这里"，而"交给本网络上的哪一台移动节点"是外地代理靠记录的 MAC 地址回答的（**交付时不用 ARP**）。理解这一点，"多个移动节点共用一个转交地址"就不再反直觉。
- **通信过程四步**：B 用归属地址发 → 归属代理**截获**（仅当移动节点不在家）并**隧道封装**（外层目的 = 转交地址）→ 外地代理**拆封**并交付（内层目的仍是归属地址，因此对上层透明）→ 移动节点用归属地址作源地址**直接回复**，不经归属代理。
- **去绕回不绕的不对称，源于"谁知道对方位置"这个信息不对称**，不是设计缺陷。但它导致**三角形路由选择问题**：本来一条边能到，现在要走两条边；极端情况下 B 就在移动节点所在的被访网络里，数据报却要两次穿越广域网。**该问题只出现在去程。**
- **直接路由选择**是解法：由**通信者代理**（而非归属代理）做隧道封装，代价是要新增**移动用户定位协议**，并引入**锚外地代理**——移动节点首次漫游到的那个外地代理，取代归属代理成为转发锚点，后续移动由它逐级再封装转发。
- **四类新增协议**要能说全：移动节点→外地代理的登记/注销、外地代理→归属代理的登记、归属代理的封装、外地代理的拆封。移动节点再移动时，**新外地代理的登记直接覆盖归属代理里的旧记录，旧外地代理不必注销**。
- 这些措施统称**移动性管理**，其中**安全**（凭什么相信一个自称外地代理的实体）是必须但本节未展开的一环。

## 教材出处

- 谢希仁《计算机网络》（第 7 版）：移动 IP 的基本概念与那个"毕业留家庭地址"的类比，见印刷版 **p437**（9.6 移动 IP）——"一个班级的大学生在毕业时都将同时走向各自的工作岗位。由于事先并不知道自己未来的工作单位的准确通信地址，那么怎样才能继续和这些同学保持联系呢？……就是彼此都留下各自的家庭地址（即永久地址）。若要和某同学联系，只要写信到该同学的永久地址，请其家长把信件转交一下即可"。
- 同书 **p437**：三个实体与两个地址的定义——"移动站 A 必须有一个原始地址（相当于上面提到的家庭地址），即永久地址，或归属地址。移动站原始连接到的网络 N₁ 叫作归属网络。永久地址和归属网络的关联是不变的"；"归属代理通常就是连接在归属网络上的路由器，然而它作为代理的特定功能则是在应用层完成的。归属代理既是路由器，也是主机"；"被访网络中使用的代理叫作外地代理，它通常就是连接在被访网络上的路由器（当然也充当主机）。外地代理的一个任务就是要为移动站 A 创建一个临时地址，叫作转交地址。**转交地址的网络号显然必须和被访网络一致**。外地代理的另一个功能就是及时把移动站 A 的转交地址通知 A 的归属代理"。
- 同书 **p437**：**转交地址不唯一**的两点说明——"第一，转交地址是供移动站、归属代理以及外地代理使用的，各种应用程序都不使用这种转交地址；第二，转交地址在互联网中并不具有唯一性。这就是说，外地代理可以给好几个移动站指派同样的转交地址，甚至把自己的 IP 地址指派为移动站的转交地址。这样做并不会引起混乱。这是因为当外地代理要向连接在被访网络上的移动站发送数据报时，并不会像通常那样使用地址解析协议 ARP，而是直接使用这个移动站的 MAC 地址（当移动站首次和外地代理通信时，外地代理就记录下这个移动站的 MAC 地址）"。同页给出**同址转交地址**："移动站本身也可以充当外地代理……使用同址转交地址的好处是移动站可以移动到任何网络，而不必担心外地代理的可用性。但缺点是移动站需要有额外的软件，使之能够充当自己的外地代理"。
- 同书 **p438**：**四个转发步骤**——"① B 发送给 A 的数据报的目的地址是 131.8.6.7。此数据报被 A 的归属代理截获了（**只有当 A 离开归属网络时，归属代理才能截获发给 A 的数据报**）。② 由于归属代理已经知道了 A 的转交地址，因此归属代理把 B 发来的数据报进行再封装，新的数据报的目的地址是……A 现在的转交地址。新封装的数据报发送到被访网络的外地代理。这里使用的就是……隧道技术或 IP-in-IP。③ 被访网络中的外地代理把收到的封装的数据报进行拆封，取出 B 发送的原始数据报，然后转发给移动站 A。**这个数据报的目的地址是 131.8.6.7，就是 A 的永久地址**。A 收到 B 发送的原始数据报后，也得到了 B 的 IP 地址。④ 如果现在 A 要向 B 发送数据报，那么情况就比较简单。A 仍然使用自己的永久地址作为数据报的源地址，用 B 的 IP 地址作为数据报的目的地址。**这个数据报显然没有必要再通过 A 的归属代理进行转发**"。同页列出四类新增协议（移动站到外地代理的协议、外地代理到归属代理的登记协议、归属代理数据报封装协议、外地代理拆封协议）。
- 同书 **p438**：**继续移动时不必注销**——"当移动站离开被访网络时，外地代理并不需要注销其在归属代理登记的转交地址。这是因为当移动站接入到另一个网络时，这个新的被访网络的外地代理就会到移动站的归属代理登记该移动站现在的转交地址，这样就取代了原来旧的转交地址"；以及"我们注意到，在 A 的这次移动前后，数据报都是由相同的归属代理转发的"。
- 同书 **p438**：**间接路由选择与三角形路由问题**——"像图 9-23 所示的数据报转发过程，又称为间接路由选择。这是因为源站并不知道移动站的当前地址，而是把数据报发往移动站的归属网络，以后的工作都由归属代理来完成"；"这种间接路由选择，可能会引起数据报转发的低效，文献中称之为三角形路由选择问题。意思是，本来在 B 和 A 之间可能有一条更有效的路由，但现在要走另外两条路……设想一个极端的例子。如果 B 所在的网络就是 A 到达的被访网络。在这种情况下，B 发送数据报给 A 就是在同一个网络上非常简便的直接交付，根本不需要使用路由器"，其后果是"只好让发送给 A 的数据报两次穿越广域网，既浪费了时间，也增加了网上不必要的通信量"（**p439**）。
- 同书 **p439**：**直接路由选择与锚外地代理**——"解决这个问题的一种方法是使用直接路由选择，但这是以增加复杂性为代价的。这种方法就是让通信者 B 创建一个通信者代理，让这个通信者代理向归属代理询问到移动站在被访网络的转交地址，然后由通信者代理（而不是由归属代理）把数据报用隧道技术发送到被访网络的外地代理，最后再由这个外地代理拆封，把数据报转发给移动站"；两个必须解决的问题是"增加一个协议，即移动用户定位协议，用来使通信者代理向移动站的归属代理查询移动站的转交地址"与"当移动站再移动到其他网络时，怎样得到移动站的位置信息"。同页给出锚外地代理的定义与七步流程："我们把移动站首次漫游到的被访网络的外地代理称为锚外地代理"，"新外地代理把 A 的新转交地址告诉锚外地代理。当锚外地代理收到发给 A 的封装数据报后，就用 A 的新转交地址对数据报进行再封装，然后发送给被访网络 N₂ 上的新外地代理，在拆封后转发给移动站 A"。同页最后说明"移动性管理……涉及的面比以上所讨论的问题还要宽些，例如，安全问题也是必须要解决的"。[[04_计算机网络_CN/network/multicast.md|上一篇IP 多播与 IGMP]][[04_计算机网络_CN/network/router.md|下一篇路由器与三层转发]]
