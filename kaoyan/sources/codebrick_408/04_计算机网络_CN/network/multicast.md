## 知识框架

本节回答 6 个问题：

- 多播省下来的到底是**谁的**开销？服务器的、还是链路的？省在哪一步？
- 多播数据报的目的地址写的是"多播组标识符"，那**源地址**写什么？为什么不能也写多播地址？
- D 类地址有 28 位可用，以太网多播 MAC 只有 23 位可用 —— **被丢掉的是哪 5 位**？（不是笼统的"高 5 位"，要能指出具体是哪几个二进制位）
- 32 个 IP 多播地址映射到同一个 MAC，主机怎么办？在**哪一层**补救？
- IGMP 只在本地子网工作，那"互联网范围的多播"是谁在管？
- 多播路由为什么比单播路由复杂得多？至少要能说出三条区别。

## 一、单播、广播、多播

| 通信方式 | 发送份数 | 接收者 | 目的地址类型 |
| --- | --- | --- | --- |
| **单播** | 每个接收者单独发一份 | 一对一 | 普通（A/B/C 类）IP 地址 |
| **广播** | 发一份，子网内**所有**主机都收到 | 一对全部 | 广播地址（如 255.255.255.255） |
| **多播** | 发一份，只有**加入了该多播组**的主机收到 | 一对多（部分） | **D 类**地址 |

### 多播省的是什么

假设要向 90 台主机发同一份视频数据：

- **单播**：源主机要发 90 份，每份沿各自路径走完全程
- **多播**：源主机只发 **1 份**，这一份在传输路径上**遇到分岔点时才复制**

两处收益要分开说，它们的受益方不同：

- **服务器侧**：发送份数从 90 降到 1，源主机的 CPU 与出口带宽压力降到 1/90
- **网络侧**：在从源到各接收者的共享路径上，原本要并行跑 90 份完全相同的数据，现在只跑 1 份；只有到了路径分岔的地方才复制。**共享路径越长、接收者越多，节省越大。**

这条"**只在分岔点复制**"的性质，正是下文"多播转发树"要保证的东西。

## 二、IP 多播地址

### D 类地址

D 类地址的前 4 位固定为 `1110`，因此范围是 **224.0.0.0 ~ 239.255.255.255**。

每一个 D 类地址标志一个多播组。前 4 位固定后还剩 **28 位**，所以理论上可标志228=268435456

个多播组（超过 2.6 亿个）。主机可以随时加入或离开任何一个多播组。

### 四条必须能推的性质

**（1）多播地址只能用作目的地址，不能用作源地址。**

理由：多播地址标识的是"一组接收者"，而一个数据报的发送者永远是**某一台确定的机器**。写成多播地址，接收方将无法知道"该回给谁"，差错报告、往返测量全部无从谈起。**多播数据报的源地址仍然是发送方自己的普通单播 IP 地址。**

**（2）对多播数据报不产生 ICMP 差错报文。**

理由（见 [[04_计算机网络_CN/network/icmp.md|ICMP 协议]]）：一个多播数据报可能被成千上万台主机收到，若每台都因某种原因回一个差错报文，源点会被瞬间淹没。

一个直接推论：**在 ping 命令后面键入一个多播地址，将永远不会收到响应。**

**（3）多播是"尽最大努力交付"，不保证交付到组内的所有成员。** 这一条与 IP 本身的服务模型一致，多播没有额外的可靠性保证。

**（4）多播只能用于 UDP，不能用于 TCP。**

理由：TCP 建立的是**一对一**的端到端连接，靠三次握手确定唯一的对端、靠确认与重传保证可靠。这一整套机制在"一对多"的场景下根本无法定义——向谁握手？谁的确认算数？谁没确认就要重传？所以多播只能架在无连接的 [[04_计算机网络_CN/transport/udp.md|UDP]] 上。

### 多播数据报与普通 IP 数据报的两处区别

- 目的地址使用 **D 类 IP 地址**
- 首部中的**协议字段值为 2**，表明使用网际组管理协议 IGMP（对照：ICMP 是 1，见 [[04_计算机网络_CN/network/ip-datagram.md|IPv4 数据报格式]]）

## 三、IP 多播地址到以太网多播 MAC 的映射

IP 多播分两种：**只在本局域网上进行的硬件多播**，和**在互联网范围进行的多播**。后者在最后阶段仍然要落到局域网上用硬件多播交付给组内成员——所以硬件多播是绕不开的一环。

### 地址块的来历

- IANA 拥有的以太网地址块高 24 位是 `00-00-5E`，所以 TCP/IP 使用的以太网地址范围是 `00-00-5E-00-00-00` ~ `00-00-5E-FF-FF-FF`
- 以太网 MAC 地址中，**第 1 字节的最低位为 1 时即为多播地址**（见 [[04_计算机网络_CN/datalink/ethernet.md|以太网与 IEEE 802.3]]）。把 `00` 的最低位置 1 得到 `01`，于是多播地址范围是 `01-00-5E-…`
- 但 IANA 只拿出 223 个地址，即 **`01-00-5E-00-00-00` ~ `01-00-5E-7F-FF-FF`** 作为以太网多播地址

所以：**48 位多播 MAC 中，前 25 位固定不变，只有后 23 位可用。**

为什么是 25 位固定而不是 24 位？因为第 4 字节的最高位也被固定为 0（`00` ~ `7F` 意味着第 4 字节的最高位恒为 0）。24+1=25。

### 被丢弃的是哪 5 位

D 类 IP 地址可供分配的有 **28 位**，而多播 MAC 只有 **23 位**可用。28−23=5 位必须丢掉。

**具体是哪 5 位**——这一处光记"高 5 位"是不够的，要能指出位置：

```
D 类 IP 地址（32 bit）
   byte1      byte2      byte3      byte4
 +--------+ +--------+ +--------+ +--------+
 |1110wxyz| |abbbbbbb| |cccccccc| |dddddddd|
 +--------+ +--------+ +--------+ +--------+
      ^^^^   ^ \-------------------------/
       |     |            这 23 bit 保留
       |     +--  a  = byte2 的最高位
       +-------- wxyz = byte1 的低 4 位     这 4+1 = 5 bit 被丢弃

以太网多播 MAC（48 bit）
   byte1      byte2      byte3      byte4      byte5      byte6
 +--------+ +--------+ +--------+ +--------+ +--------+ +--------+
 |00000001| |00000000| |01011110| |0bbbbbbb| |cccccccc| |dddddddd|
 +--------+ +--------+ +--------+ +--------+ +--------+ +--------+
    0x01       0x00       0x5E      ^\------------------------/
  \-------------------------------/           照抄 IP 的低 23 bit
       前 25 bit 固定（含 byte4 的最高位 0）
```

数一遍：被丢的 5 位 = **IP 地址第 1 字节的低 4 位** + **第 2 字节的最高位**。 保留的 23 位 = **第 2 字节的低 7 位** + **第 3 字节（8 位）** + **第 4 字节（8 位）** = 7+8+8=23 ✓

**这就是为什么"第一字节 224~239 全都无所谓、第二字节要减 128"**：224~239 这 16 个值差别正好在第 1 字节的低 4 位上，全被丢了；第 2 字节的最高位也被丢，所以第 2 字节只有低 7 位有效。

### 多对一：32 个 IP 对应 1 个 MAC

丢掉 5 位意味着 25=32 个不同的 IP 多播地址会映射到**同一个**多播 MAC 地址。

从地址总数上也能对上：228÷223=25=32。

**补救办法：主机收到多播帧后，还要在 IP 层根据 IP 数据报首部的目的 IP 地址做一次过滤**，把不属于自己所在多播组的数据报丢弃。

注意补救的**层次**：网卡（链路层）按 MAC 过滤会误收 32 个组里的帧，**必须由 IP 层再过滤一次**。这是"两层各按各的地址过滤、下层粗上层细"的典型例子。

### 例题：正反两个方向的映射

**题目**（自造数据）： (1) 把 IP 多播地址 `232.196.201.7` 映射为以太网多播 MAC 地址。 (2) 反过来：一共有多少个 D 类 IP 地址会映射到 `01-00-5E-44-C9-07`？请写出其中最小和最大的两个。

**(1) 正向映射**

**第 1 步：确认这是合法的 D 类地址。**

*为什么这么做*：只有 D 类地址才有这个映射；第 1 字节必须在 224~239 之间。

232=11101000，前 4 位是 `1110` ✓ 是 D 类。

**第 2 步：前 3 字节写死。**

*为什么这么做*：多播 MAC 的前 25 位固定，前 3 个字节永远是 `01-00-5E`（第 4 字节最高位为 0 是第 25 位的约束，下一步处理）。

MAC 的前三字节 = `01-00-5E`

**第 3 步：处理 IP 的第 2 字节——把最高位清零。**

*为什么这么做*：这是唯一需要动二进制的一步。第 2 字节的最高位属于被丢弃的 5 位，只有低 7 位参与映射；而 MAC 第 4 字节的最高位恒为 0，正好接得上。196=1⏟丢弃1000100⏟保留的低 7 位⟶01000100=0x44=68

**第 4 步：IP 的第 3、4 字节整字节照抄。**

*为什么这么做*：这两个字节共 16 位，全部落在保留的 23 位里，不做任何改动。

201=0xC9，7=0x07

**第 5 步：拼出答案。**01-00-5E-44-C9-07

*验算*：MAC 第 4 字节 `0x44 = 0100 0100`，最高位为 0 ✓，落在 `00` ~ `7F` 的合法区间内。

**(2) 反向映射**

**第 1 步：数出有多少个自由位。**

*为什么这么做*：反向问题就是"哪些位在正向映射中被丢了"——被丢的位可以任取，就是自由位。

被丢的 5 位是"第 1 字节的低 4 位"和"第 2 字节的最高位"，共 25=32 个 D 类 IP 地址映射到同一个 MAC。

**第 2 步：还原第 1 字节的取值范围。**

*为什么这么做*：第 1 字节 = `1110` + 4 位自由位，取遍 0000~1111。11100000=224到11101111=239

即第 1 字节可以是 **224 ~ 239 的任意一个**（共 16 种）。

**第 3 步：还原第 2 字节的取值。**

*为什么这么做*：MAC 第 4 字节 `0x44` = 低 7 位的值 68；第 2 字节的最高位是自由的，可以是 0 也可以是 1。

- 最高位取 0 → 第 2 字节 = 68
- 最高位取 1 → 第 2 字节 = 68+128=196

共 2 种。

**第 4 步：第 3、4 字节被完全确定。**

MAC 第 5、6 字节是 `C9`、`07`，原样对应 IP 的第 3、4 字节 → **201** 和 **7**，没有自由度。

**第 5 步：合成答案。**

总数 = 16×2×1×1=32 ✓ 与第 1 步一致。

- 最小的：`224.68.201.7`
- 最大的：`239.196.201.7`
- 题目里的 `232.196.201.7` 也在这 32 个之中

**第 6 步：这个结果说明了什么。**

一台主机若加入了多播组 `232.196.201.7`，它的网卡会被配置成接收 MAC `01-00-5E-44-C9-07` 的帧。此时若同一局域网上有人向 `224.68.201.7` 发多播数据报，**这台主机的网卡照样会收下**——因为两个 IP 映射到同一个 MAC。只有到了 IP 层，比对目的 IP 发现不是 `232.196.201.7`，才会丢弃。**上一小节说的"IP 层二次过滤"，防的就是这 31 个"冒名者"。**

## 四、IGMP 网际组管理协议

### IP 多播需要两种协议

多播路由器怎么知道本局域网上有没有某个多播组的成员？这就要靠 **IGMP**（Internet Group Management Protocol，网际组管理协议）。

但**仅有 IGMP 是不够的**。连接在局域网上的多播路由器还必须和互联网上的其他多播路由器协同工作，才能把多播数据报用最小代价送到所有组成员那里——这需要**多播路由选择协议**。

**两种协议的分工要分清：**

| 协议 | 管什么 | 作用范围 |
| --- | --- | --- |
| **IGMP** | 让本地多播路由器知道**本局域网上**有没有某个组的成员 | **只在本地子网** |
| **多播路由选择协议** | 在多播路由器之间传播组成员信息、构造转发树 | 互联网范围 |

**IGMP 明确不管什么**：它**不知道** IP 多播组包含多少成员，也**不知道**这些成员分布在哪些网络上。它只回答一个本地问题："我这个子网里，还有没有人在这个组里？"

### IGMP 的定位

- IGMP 是 IP 的配套协议，属于**网络层**，与 [[04_计算机网络_CN/network/icmp.md|ICMP]]、[[04_计算机网络_CN/network/arp.md|ARP]] 并列
- IGMP **使用 IP 数据报传递其报文**（IGMP 报文 + IP 首部构成 IP 数据报），协议字段值为 **2**
- 但它同时**向 IP 提供服务**，所以通常不把它看成一个单独的协议，而是**整个网际协议 IP 的一个组成部分**

### 两个阶段的工作过程

**第一阶段：加入多播组。**

某台主机加入新的多播组时，向**该多播组的多播地址**发送一个 IGMP 报文，声明自己要成为该组的成员。本地多播路由器收到后，再利用多播路由选择协议把这种**组成员关系转发给互联网上的其他多播路由器**。

注意报文是发往**组地址**而不是路由器地址——这样同一子网里其他已经在组内的主机也能听到，为后面的抑制机制留了余地。

**第二阶段：周期性探询。**

组成员关系是**动态**的（主机可能悄无声息地关机、退出）。本地多播路由器要**周期性地探询**本局域网上的主机，看它们是否还是组的成员。

判据是：

- 只要**有一台**主机对某个组响应，路由器就认为**这个组是活跃的**
- 一个组在经过**几次**探询后仍然没有一台主机响应，路由器就认定本网络上的主机都已离开该组，**不再把这个组的成员关系转发给其他多播路由器**

为什么用"探询 + 超时"而不是"退出时主动通知"？因为主机可能直接断电、来不及通知。**周期性探询是唯一对"非正常离开"也有效的机制**——这与 [[04_计算机网络_CN/network/arp.md|ARP 缓存必须设有效期]] 是同一个道理。

### IGMP 怎么控制自己的开销

IGMP 报文本身也要占带宽，设计上做了三件事把开销压住：

- **主机与多播路由器之间的所有通信都使用 IP 多播。** 只要有可能，携带 IGMP 报文的数据报都用**硬件多播**传送。于是在支持硬件多播的网络上，**没有参加 IP 多播的主机根本收不到 IGMP 报文**，完全不受打扰。
- **探询时只发一个报文问所有组。** 多播路由器探询组成员关系时，只需要对所有的组发送**一个**请求信息的询问报文，而不必对每一个组各发一个。默认的询问速率是**每 125 秒一次**，通信量很小。
- **多个多播路由器会选出一个来探询。** 同一个网络上连接了几个多播路由器时，它们能迅速有效地选出其中一个负责探询，所以**路由器数量增加不会导致 IGMP 通信量成倍增长**。

### IGMP 两阶段的时序

这张图要读出两点：**加入是主机主动的、离开是路由器"探不出来"才认定的**；以及**询问报文是一个报文问所有组、且用硬件多播发出**，所以没参加任何多播的主机根本收不到它。

## 五、多播路由选择

多播路由选择的本质是：为每一个 **（源主机，多播组）** 二元组构造一棵**多播转发树**。

- 转发树保证每个分组在**每条链路上只传送一次**（这正是第一节说的"只在分岔点复制"）
- **不同的多播组**对应不同的转发树
- **同一个多播组、源主机不同**，转发树也不同
- 树结构天然不存在环路

### 为什么多播路由比单播路由复杂得多

三条区别，都要能说：

**（1）触发更新的事件不同。** 单播路由通常只在**网络拓扑发生变化**时才需要更新路由。而多播成员随时可以加入或离开——**拓扑一点没变，转发行为却必须跟着变**。多播转发必须动态适应组成员的变化。

**（2）转发依据不同。** 单播路由器只看目的地址就能决定往哪转。多播路由器**不能仅凭多播数据报的目的地址决定转发**，还必须考虑这个数据报**从哪里来**、**要到哪里去**——因为同一个组、不同的源，转发树不同。（例：组内主机 E 向 F 发，路由器要往一个方向转；F 向 E 发，就得往另一个方向转。）

**（3）发送者不必是成员。** 一台**没有参加任何多播组**的主机，照样可以向任何多播组发送多播数据报。而且多播数据报经过的许多网络，也**不一定有组成员**。所以"是不是成员"和"能不能发"是两件独立的事。

多播路由选择协议的具体细节 408 不作要求，知道转发树的概念与上面三条区别即可。

## 易混淆知识点

**1. 多播地址只能做目的地址**

多播数据报的源地址是发送方的普通单播地址。理由是"发送者永远是某一台确定的机器"。同样只能做目的地址的还有广播地址（见 [[04_计算机网络_CN/network/ip-addressing.md|IP 编址]]）。

**2. 被丢弃的 5 位是"第 1 字节的低 4 位 + 第 2 字节的最高位"**

不是笼统的"高 5 位"。能指出具体位置，才能正确回答"哪些 IP 映射到同一个 MAC"这类反向问题。保留的 23 位 = 第 2 字节低 7 位 + 第 3 字节 + 第 4 字节。

**3. 多播 MAC 映射是多对一，补救在 IP 层**

228/223=32 个 IP 映射到同一 MAC。网卡按 MAC 过滤会误收，必须由 IP 层按目的 IP 再过滤一次。**下层粗、上层细。**

**4. 前 25 位固定，不是 24 位**

`01-00-5E` 是 24 位，再加上第 4 字节的最高位恒为 0（地址上限是 `7F`），共 25 位。所以可变的是 23 位而不是 24 位。

**5. IGMP 只在本地子网工作**

它不知道多播组的总成员数，也不知道成员分布在哪些网络。互联网范围的多播靠**多播路由选择协议**。两种协议缺一不可。

**6. IGMP 协议字段值是 2，ICMP 是 1**

两个相邻的值容易混。多播数据报的协议字段值也是 2。

**7. 多播只用于 UDP，不用于 TCP**

TCP 是一对一的连接，握手、确认、重传三套机制在一对多下都无法定义。

**8. 对多播数据报不产生 ICMP 差错报文**

因此 ping 一个多播地址永远收不到响应。理由是防"响应爆炸"。

**9. 多播转发不能只看目的地址**

同一个组、不同的源，转发树不同，所以还要看"从哪来"。这是多播路由与单播路由最本质的区别之一。

**10. 非成员也能向多播组发送**

"是不是组成员"决定的是"能不能收"，不决定"能不能发"。

## 本节小结

本节按"**为什么要多播 → 地址怎么定 → 地址怎么落到硬件 → 谁来管成员 → 谁来选路**"五步展开：

- **多播省的是两笔开销**：源主机的发送份数（90 → 1），以及共享路径上重复传输的份数。收益的机制是"**只在分岔点复制**"，这也是后面"转发树"要保证的性质。
- **D 类地址（224.0.0.0 ~ 239.255.255.255）标识多播组**，前 4 位固定 `1110`，剩 28 位 → 228 个组。四条必须能推的性质：只能做目的地址（发送者必须是确定的一台机器）、不产生 ICMP 差错报文（防响应爆炸，所以 ping 多播地址无响应）、尽最大努力交付、只能用 UDP（TCP 的握手/确认/重传在一对多下无法定义）。多播数据报的协议字段值是 **2**。
- **映射到硬件多播时丢掉 5 位**，而且要能指出是哪 5 位：**IP 第 1 字节的低 4 位 + 第 2 字节的最高位**。保留的 23 位是第 2 字节低 7 位 + 第 3、4 字节。MAC 前 25 位固定（`01-00-5E` 的 24 位 + 第 4 字节最高位为 0）。**32 个 IP 映射到同一个 MAC**，网卡会误收，必须由 **IP 层按目的 IP 二次过滤**——下层粗、上层细。
- **IGMP 只回答本地问题**："我这个子网里还有没有人在这个组里"。它不知道组的总成员数与分布。两阶段：加入时向组地址发报文声明；之后路由器**周期性探询**（125 秒），有一台响应即认为组活跃，连续几次无响应即认定组已空。**用"探询 + 超时"而不是"退出时通知"，是因为主机可能直接断电**——与 ARP 缓存设有效期同理。IGMP 用三条措施压住自己的开销（全程用硬件多播、一个报文问所有组、多路由器选一个来问）。
- **互联网范围的多播靠多播路由选择协议**，本质是为每个（源，组）构造一棵转发树，保证每条链路只传一次。
- **多播路由比单播复杂的三条理由**：组成员变化会在拓扑不变时触发更新；转发不能只看目的地址、还要看从哪来；发送者不必是组成员、路径上的网络也不必有成员。

## 教材出处

- 谢希仁《计算机网络》（第 7 版）：**D 类地址与多播的基本性质**，见印刷版 **p180**（4.7.1 IP 多播的一些基本概念）——"D 类 IP 地址的前四位是 1110，因此 D 类地址范围是 224.0.0.0 到 239.255.255.255。我们就用每一个 D 类地址标志一个多播组。这样，D 类地址共可标志 228 个多播组"；"多播数据报也是'尽最大努力交付'，不保证一定能够交付多播组内的所有成员。因此，多播数据报和一般的 IP 数据报的区别就是它使用 D 类 IP 地址作为目的地址，并且首部中的协议字段值是 2，表明使用网际组管理协议 IGMP"；"多播地址只能用于目的地址，而不能用于源地址。此外，对多播数据报不产生 ICMP 差错报文。因此，若在 PING 命令后面键入多播地址，将永远不会收到响应"。同页还说明 IP 多播分为"只在本局域网上进行硬件多播"与"在互联网的范围进行多播"两种。
- 同书 **p180**（4.7.2 在局域网上进行硬件多播）：**映射规则的全部依据**——"互联网号码指派管理局 IANA 拥有的以太网地址块的高 24 位为 00-00-5E，因此 TCP/IP 协议使用的以太网地址块的范围是从 00-00-5E-00-00-00 到 00-00-5E-FF-FF-FF。在第 3 章 3.3.5 节已讲过，以太网 MAC 地址字段中的第 1 字节的最低位为 1 时即为多播地址……但 IANA 只拿出 223 个地址，即 01-00-5E-00-00-00 到 01-00-5E-7F-FF-FF 的地址作为以太网多播地址。或者说，在 48 位的多播地址中，前 25 位都固定不变，只有后 23 位可用作多播。但 D 类 IP 地址可供分配的有 28 位。这 28 位中只有后 23 位才映射到以太网多播地址中的后 23 位，因此是多对一的映射关系……即 28 位中的前 5 位不能用来构成以太网多播地址"。教材给出的实例是"IP 多播地址 224.128.64.32（即 E0-80-40-20）和另一个 IP 多播地址 224.0.64.32（即 E0-00-40-20）转换成以太网的多播地址都是 01-00-5E-00-40-20。因此收到多播数据报的主机，还要在 IP 层利用 IP 数据报首部的 IP 地址进行过滤，把不是本主机要接收的数据报丢弃"。本篇例题为自造数据，"被丢的 5 位具体是哪几位"由该处的位图（图 4-59）逐位对照得出。
- 同书 **p181**（4.7.3 网际组管理协议 IGMP 和多播路由选择协议）：**IGMP 的作用范围**——"图 4-60 强调了 IGMP 的本地使用范围。请注意，IGMP 并非在互联网范围内对所有多播组成员进行管理的协议。IGMP 不知道 IP 多播组包含的成员数，也不知道这些成员都分布在哪些网络上。IGMP 协议是让连接在本地局域网上的多播路由器知道本局域网上是否有主机（严格讲，是主机上的某个进程）参加或退出了某个多播组"；以及"显然，仅有 IGMP 协议是不能完成多播任务的。连接在局域网上的多播路由器还必须和互联网上的其他多播路由器协同工作……这就需要使用多播路由选择协议"。
- 同书 **p182**：**IGMP 的定位与两阶段工作过程**——"和网际控制报文协议 ICMP 相似，IGMP 使用 IP 数据报传递其报文（即 IGMP 报文加上 IP 首部构成 IP 数据报），但它也向 IP 提供服务。因此，我们不把 IGMP 看成是一个单独的协议，而是属于整个网际协议 IP 的一个组成部分"；第一阶段"当某台主机加入新的多播组时，该主机应向多播组的多播地址发送一个 IGMP 报文，声明自己要成为该组的成员。本地的多播路由器收到 IGMP 报文后，还要利用多播路由选择协议把这种组成员关系转发给互联网上的其他多播路由器"；第二阶段"本地多播路由器要周期性地探询本地局域网上的主机，以便知道这些主机是否还继续是组的成员。只要有一台主机对某个组响应，那么多播路由器就认为这个组是活跃的。但一个组在经过几次的探询后仍然没有一台主机响应，多播路由器就认为本网络上的主机已经都离开了这个组"。同页给出 IGMP 控制开销的三条措施，其中"默认的询问速率是每 125 秒发送一次"。
- 同书 **p181–p182**：**多播路由比单播复杂的三条理由**——"多播转发必须动态地适应多播组成员的变化（这时网络拓扑并未发生变化）。请注意，单播路由选择通常在网络拓扑发生变化时才需要更新路由"；"多播路由器在转发多播数据报时，不能仅仅根据多播数据报中的目的地址，而是还要考虑这个多播数据报从什么地方来和要到什么地方去"；"多播数据报可以由没有加入多播组的主机发出，也可以通过没有组成员接入的网络"。[[04_计算机网络_CN/network/ipv6.md|上一篇IPv6]][[04_计算机网络_CN/network/mobile-ip.md|下一篇移动 IP]]
