# 指令流水线的基本概念与实现

## 大纲定位

**五（六）1、2　指令流水线的基本概念、指令流水线的基本实现**

要求：理解流水线把指令拆段重叠执行的思想，能画时空图，掌握吞吐率、加速比、效率三个指标的定义与计算。

流水线运行中的三类冲突见 [[03_计算机组成原理_CO/cpu/pipeline-hazard.md|流水线冒险]]；超标量等进一步的并行技术见 [[03_计算机组成原理_CO/cpu/pipeline-performance.md|流水线性能分析]]。

## 知识框架

本节回答四个问题：

- 流水线是从哪一步推出来的？为什么恰好是五段？
- 段间寄存器为什么不能省？
- 三个性能指标各自衡量什么？三者什么关系？
- 什么样的指令系统适合流水线？

## 一、基本思想

将指令的执行过程分成多个阶段，每个阶段由专用硬件完成，多条指令**同时处于不同阶段**。

> [!TIP]
>

流水线是从多周期继续往前推一步得到的

回顾一下三种设计的演进：

|  | 一条指令占 | 部件利用率 |
| --- | --- | --- |
| **单周期** | 1 个长周期 | 低——一条指令期间大部分部件闲置 |
| **多周期** | 若干个短周期 | 高——部件跨阶段复用，但**同一时刻仍只有一条指令**在执行 |
| **流水线** | 若干个短周期 | 最高——**不同指令同时占用不同部件** |

多周期解决了"一条指令内部件闲置"的问题，但没解决"某一时刻大部分部件仍然闲置"——因为机器里始终只有一条指令。

流水线的做法是：**既然 IF 段做完就空出来了，那就立刻让下一条指令进来**。硬件规模几乎不变，吞吐率却提高了数倍。

## 二、为什么是五段

五段的划分不是约定，而是从**单周期数据通路的关键路径**上切出来的。lw 指令要依次经过：取指→读寄存器→ALU 算地址→访存→写回寄存器

这五个环节各自使用**不同的部件**，且前一环节的输出正是后一环节的输入。在每个自然分界处切一刀，就得到五段：

| 阶段 | 缩写 | 操作 | 用到的部件 |
| --- | --- | --- | --- |
| 取指 | **IF** | 从指令存储器取指令，PC+4 | 指令存储器、PC |
| 译码/读寄存器 | **ID** | 译码操作码，读寄存器堆 | 译码器、寄存器堆读口 |
| 执行 | **EX** | ALU 运算或计算存储器地址 | ALU |
| 访存 | **MEM** | 读/写数据存储器 | 数据存储器 |
| 写回 | **WB** | 将结果写回寄存器堆 | 寄存器堆写口 |

**各段使用不同部件是流水线能成立的前提**——如果两段抢同一个部件，它们就不能重叠。指令存储器与数据存储器必须分开，正是因为 IF 和 MEM 要同时工作。

不访存的指令（如 R 型）在 MEM 段**空过**，不做任何事但仍要占一个周期。这看似浪费，却是必需的：所有指令走同样的段数，才能保证写回的顺序与程序顺序一致。

## 三、段间寄存器

每个流水段之后必须设置**段间寄存器**（流水线寄存器、锁存器）：

```
IF  →  IF/ID  →  ID  →  ID/EX  →  EX  →  EX/MEM  →  MEM  →  MEM/WB  →  WB
```

> [!CAUTION]
>

没有段间寄存器，五条指令的信号会互相覆盖

组合逻辑电路的输出只在输入稳定时才有效。IF 段刚取出的指令，下一个周期就会被**新的一条指令**冲掉——因为 IF 段已经在给下一条指令服务了。

所以每一段的输出必须在周期末尾**锁进寄存器**，供下一段在下一周期使用。段间寄存器不仅锁存数据，还要锁存**这条指令后续各段要用的全部控制信号**——控制信号是在 ID 段一次性译出的，却要用到 WB 段，只能一路随着指令往下传。

段间寄存器本身有延迟，必须计入时钟周期：Δt=max(Δt1,Δt2,…,Δtk)+t寄存器图 6.5　5 段流水线数据通路及段寄存器（袁春风《计算机组成与系统结构》第 3 版，见文末教材出处）

对照单周期数据通路可以看出：**流水线唯一的结构改动就是插入这四条竖直的段寄存器**，部件本身一个没变。

> [!WARNING]
>

流水线不缩短单条指令的执行时间

单条指令仍要经过全部 k 个段，总延迟为 k⋅Δt，甚至**可能比非流水线时更长**——因为 Δt 按最慢段取值，还要加上段间寄存器的延迟。

流水线提升的是**吞吐率**：满载时每个时钟周期都有一条指令完成。

这与 [[03_计算机组成原理_CO/storage/memory-interleave.md|多模块存储器]] 中"每个存储体并没有变快"是同一个道理——**并行提高的是总量，不是单件速度**。

## 四、时空图

以连续 5 条指令为例（每段耗时 Δt）：

```
        Δt  2Δt  3Δt  4Δt  5Δt  6Δt  7Δt  8Δt  9Δt
I1      IF   ID   EX  MEM   WB
I2           IF   ID   EX  MEM   WB
I3                IF   ID   EX  MEM   WB
I4                     IF   ID   EX  MEM   WB
I5                          IF   ID   EX  MEM   WB
```

完成 5 条指令共需 (5+5−1)×Δt=9Δt。

一般地，k 段流水线执行 n 条指令：T=(k+n−1)⋅Δt

这个式子可以直接读出来：**第一条指令花 k 拍走完全程（填满流水线），之后每拍出一条**，还剩 n−1 条。

图中左上角和右下角的空白，就是流水线的**建立时间**和**排空时间**——这两块空白是加速比达不到 k 的全部原因。

## 五、三个性能指标

### 吞吐率 TP

单位时间完成的指令条数：TP=n(k+n−1)⋅Δt

当 n≫k 时趋近**最大吞吐率**：TPmax=1Δt

### 加速比 S

与不使用流水线（顺序执行）相比的提速倍数：S=顺序执行时间流水线执行时间=k⋅n⋅Δt(k+n−1)⋅Δt=knn+k−1

当 n≫k 时 S→k，即**理想加速比等于段数**。

### 效率 E

各流水段的平均利用率：E=Sk=nn+k−1

0<E≤1，当 n≫k 时 E→1。

> [!TIP]
>

效率就是时空图里的面积比

时空图的总面积是 k×(k+n−1) 个格子，其中被指令占用的格子只有 k×n 个，其余是建立和排空阶段的空白。E=k⋅nk⋅(k+n−1)=nn+k−1

**画出时空图后直接数格子，比套公式更不容易错**——尤其是有停顿时，停顿造成的空泡也是空白格子。

三者关系：S=k⋅E,TP=nT

## 例题

**例 1**：5 段流水线，每段时间均为 2 ns，执行 100 条指令，求 TP、S、E。

k=5，n=100，Δt=2 ns：T=(5+100−1)×2=208 nsTP=100208 ns≈4.81×108 条/sS=5×100100+5−1=500104≈4.81E=100104≈96.2%

校验：顺序执行需 100×5×2=1000 ns，S=1000/208≈4.81，一致。

**例 2**：某 4 段流水线各段延迟为 60 ps、80 ps、70 ps、90 ps，段间寄存器延迟 10 ps。求时钟周期与最大吞吐率。Δt=max(60,80,70,90)+10=100 psTPmax=1100 ps=1010 条/s=10 GIPS

注意**不是各段延迟之和**（300 ps）——那是非流水线时一条指令的耗时。流水线的时钟周期只由最慢段决定，这也说明**各段延迟越不均衡，浪费越大**：本例中 60 ps 的那一段每个周期要空等 40 ps。

## 六、流水线的分类

| 分类标准 | 类型 | 说明 |
| --- | --- | --- |
| 按级别 | 部件级流水线 | 部件内部流水（如浮点加法器） |
|  | **处理机级流水线** | 指令执行级别（IF-ID-EX-MEM-WB） |
|  | 处理机间流水线 | 多台处理机串接，宏流水线 |
| 按功能 | 单功能流水线 | 只完成一种功能 |
|  | 多功能流水线 | 可配置为多种功能 |
| 按可否并行 | **静态流水线** | 同一时刻只能按一种功能工作 |
|  | 动态流水线 | 各段可同时按不同功能工作 |
| 按有无反馈 | **线性流水线** | 数据单向流动，无反馈 |
|  | 非线性流水线 | 存在反馈回路，某些段多次经过 |

指令流水线讨论的默认对象是**处理机级、线性、静态**流水线。

## 七、什么样的指令系统有利于流水线

流水线要跑得顺，靠的是**每一段的工作量都可预测、都能在一个时钟周期内做完**。指令系统的三个设计选择直接决定这一点：

| 指令系统特点 | 对流水线的具体好处 |
| --- | --- |
| **指令格式规整且定长** | 定长 ⇒ IF 段每周期固定取一条，不必先解析长度再决定取几字节；格式规整 ⇒ 寄存器号位置固定，ID 段可以边译码边读寄存器 |
| **指令和数据按边界对齐存放** | 对齐 ⇒ 每次访存**只需一个存储周期**。不对齐的数据跨越边界，要**访存两次再拼接**，MEM 段时间就不固定了 |
| **只有 Load/Store 能访问存储器** | 只有这两类指令真正经过 MEM 段，其余指令空过；否则运算指令也要访存，MEM 段的工作量随指令而变 |

**三条是同一个诉求的三种说法：让每一段的耗时固定下来。**

> [!TIP]
>

边界对齐这一条最容易漏

前两条一眼能看出和流水线有关，"数据按边界对齐"却像是存储器章节的事。关键在于把它翻译成时间：不对齐⇒一次访存变两次⇒MEM 段时长不确定⇒各段不再均衡

流水线最怕"这条指令的某一段特别慢"——时钟周期得按最慢的来，所有指令一起陪绑。

对齐规则本身见 [[03_计算机组成原理_CO/data-repr/data-alignment.md|数据对齐与大小端]]。

这三条正是 RISC 的设计特征，所以说 **RISC 天生适合流水线**——它不是碰巧适合，而是照着流水线的需求设计出来的。详见 [[03_计算机组成原理_CO/instruction/cisc-vs-risc.md|CISC 与 RISC]]。

## 易混淆知识点

**1. 流水线段数越多越好吗？**

不是。段数增多会带来四个问题：

- 段间寄存器引入更多延迟，占时钟周期的比例上升，限制频率进一步提高
- 单条指令经历的周期数增加，**延迟变大**
- 冒险的停顿代价更大（要丢弃的错误指令更多）
- 控制逻辑急剧复杂

实际设计中段数是性能与复杂度的折中。

**2. 各段时间不等时，Δt 怎么取？**

取**最慢段的延迟 + 段间寄存器延迟**。比最慢段快的流水段每周期都会空等，这就是流水线瓶颈带来的效率损失。设计时应尽量让各段时间均衡。

**3. 加速比能超过段数 k 吗？**

**不能**。S=knn+k−1，分母恒大于 n（只要 k>1），所以 S<k 恒成立，只在 n→∞ 时趋近 k。

有停顿时还会更低。若有人算出 S>k，一定是把顺序执行时间算错了。

**4. 为什么流水线适合 RISC 而非 CISC？**

见上一节的三条。CISC 指令长度不等、寻址方式复杂、运算指令也能访存，难以划分出耗时均匀的流水段。

现代 x86 的做法是在前端把 CISC 指令**翻译成内部的类 RISC 微操作**，后端仍按流水线执行——相当于在硬件里补上了 RISC 的形态。

## 本节小结

- 流水线是多周期的下一步：**多周期让部件跨阶段复用，流水线让不同指令同时占用不同部件**
- 五段划分来自单周期关键路径的五个环节，**各段用不同部件**是能重叠的前提
- 段间寄存器不仅锁存数据，还要**把控制信号一路传到 WB 段**
- T=(n+k−1)Δt；顺序执行 T=nkΔt
- TPmax=1/Δt；S=knn+k−1<k；E=S/k=nn+k−1
- **效率就是时空图的面积比**，画图数格子比套公式稳
- 流水线**不缩短单条指令延迟**，只提升吞吐率
- 各段延迟不均衡时，快的段每周期都在空等
- 有利于流水线的三个指令系统特点：**格式规整定长**、**按边界对齐**、**只有 Load/Store 访存**——都是为了让各段耗时固定
