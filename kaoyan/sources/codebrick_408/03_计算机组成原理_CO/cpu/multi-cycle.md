# 多周期数据通路

## 大纲定位

**五（三）数据通路的功能和基本结构**

要求：理解把一条指令拆到多个时钟周期执行的动机，说清各阶段共享功能部件的方式与中间寄存器的必要性。

单周期通路的结构见 [[03_计算机组成原理_CO/cpu/single-cycle.md|单周期数据通路]]；控制状态机的具体实现见 [[03_计算机组成原理_CO/cpu/hardwired-control.md|硬布线控制器]] 与 [[03_计算机组成原理_CO/cpu/microprogrammed.md|微程序控制器]]。

## 知识框架

本节回答四个问题：

- 单周期哪里不好，非改不可？
- 拆成多个周期后，为什么必须新增一批寄存器？
- 哪些部件可以复用？省下了什么？
- 多周期的控制器为什么必须是状态机？

## 一、单周期的两个毛病

**毛病一：时钟周期被最慢的指令绑架。**

单周期的时钟周期取最复杂指令（通常是 lw）的完整通路延迟。而 beq 只需走到 ALU 就结束了，却要空等到周期末尾。指令越简单，浪费越多。

**毛病二：部件利用率极低。**

一条 R 型指令执行期间，数据存储器完全闲置；一条 beq 执行期间，寄存器堆的写端口完全闲置。为了让所有指令都能在一个周期内跑完，硬件被迫按"最大并发"配置，其中大部分时刻都在闲着。

> [!TIP]
>

还有一个不容易看到的毛病：存储器的写时序

单周期设计中把存储器**理想化**了——假定每次写操作都由时钟边沿触发，且时钟到来时地址、数据、写使能都已稳定。

实际的存储器写操作不是边沿触发的，而是一个**组合逻辑过程**：当写使能有效、且地址和数据已稳定时，经过一个写操作时间后数据被写入。这里的关键要求是——**地址和数据必须在写使能有效之前就先稳定下来**。

单周期通路无法保证这个先后顺序，地址、数据和写使能之间存在**竞争**（race）：三者在同一个周期里同时变化，谁先稳定无法控制。因此**用实际存储器的单周期数据通路不能可靠工作**。

多周期天然地解决了这个问题：先在第 n 周期确认地址和数据已稳定，再让写使能在第 n+1 周期有效。**把一件事拆到两个周期做，先后顺序就被时钟钉死了。**

## 二、多周期的基本思想

将每条指令的执行拆分为若干个**阶段**，每个阶段占一个时钟周期：

- 每个阶段内**最多完成一次访存、或一次寄存器读写、或一次 ALU 操作**
- 各阶段的执行结果在下个时钟到来时保存到相应的寄存器中
- 时钟周期的宽度以**最复杂的单个阶段**为准，通常取一次存储器读写的时间

于是时钟周期从"最慢指令的全程"缩短到"最慢的一步"，而不同指令可以占用**不同数目**的周期。

## 三、为什么必须新增中间寄存器

这是多周期设计中最本质的一处改动。

单周期里，一条指令的中间结果**根本不需要保存**——数据从指令存储器一路流到寄存器堆写入端，全程都在组合逻辑里，靠电信号自己"挂"在导线上。

一旦拆成多个周期，情况完全变了：**跨周期的数据必须存进状态元件**。因为下一个周期一到，同一个部件就要被别的操作占用，导线上的值立刻被冲掉。

| 寄存器 | 存放内容 | 不存会怎样 |
| --- | --- | --- |
| **IR** | 从内存取出的指令 | MEM 阶段存储器要读数据，指令输出被覆盖 |
| **MDR** | 从内存读出/待写入的数据 | 同上 |
| **A** | 寄存器堆读出的第一个操作数 | EX 阶段寄存器堆输出已不保证有效 |
| **B** | 寄存器堆读出的第二个操作数 | 同上 |
| **ALUOut** | ALU 的运算结果 | 下周期 ALU 要算别的，结果被冲掉 |

> [!WARNING]
>

IR 是多周期特有的，单周期不需要

单周期中指令存储器的输出在整个时钟周期内**保持不变**（这个周期里只做一次取指），因此不必额外锁存。

多周期中存储器被**复用**——IF 阶段取指令，MEM 阶段读写数据——指令信息会被数据覆盖。所以必须在 IF 阶段就把指令锁存到 IR 中，供后续所有阶段使用。

**IR 的存在，正是"部件复用"付出的代价。** 这五个中间寄存器就是流水线段间寄存器的前身。

> [!TIP]
>

A、B 需要写使能吗

PC、IR、寄存器堆只在需要时才写入新值，其他情况下不能写，因此**必须有写使能信号**。

而 A、B 是纯粹的临时寄存器，每来一个时钟都可以改变它们的值，改错了也不会有后果（下个用到它们的阶段会重新装载）。所以 **A、B 无须写使能控制信号**。

判断一个寄存器要不要写使能，就看它的值**是否需要跨越多个周期保持**。

## 四、五个执行阶段

### 阶段 1：取指（IF）
IR←M[PC],PC←PC+4

- 从内存读取指令送入 IR
- **复用 ALU** 计算 PC+4（单周期需要一个专门的加法器，多周期不用了）

### 阶段 2：译码 / 读寄存器（ID）
A←Reg[IR25:21],B←Reg[IR20:16]ALUOut←PC+(SEXT(IR15:0)≪2)

- 读出 rs、rt 对应的寄存器值到 A、B
- 同时**提前**计算分支目标地址

> [!TIP]
>

提前算分支地址是不是浪费

这一步在指令还没译完码时就做了，如果本条不是分支指令，算出的地址直接丢弃。

但它**不浪费**——这个周期里 ALU 本来就闲着（操作数刚读出来还没送到），顺手算一个地址是零成本的。而如果不算，等确认是分支指令后再算，就要多花一个周期。

**用闲置资源做一件可能有用的事，这是投机执行最朴素的形式**，与流水线中的分支预测同源。

注意在指令被译码之前，所有指令做的操作是**完全一样**的——这正是 IF、ID 两个阶段能设计成公共阶段的前提。

### 阶段 3：执行 / 地址计算（EX）

| 指令类型 | ALU 操作 | 结果送入 |
| --- | --- | --- |
| R 型 | A op B（由 funct 决定） | ALUOut |
| lw / sw | A + SEXT(imm) | ALUOut（有效地址） |
| beq | A − B，检查 Zero | 若相等则直接更新 PC |

### 阶段 4：访存 / R 型完成（MEM）

- **lw**：MDR←M[ALUOut]
- **sw**：M[ALUOut]←B
- **R 型**：Reg[IR15:11]←ALUOut（R 型在此阶段结束）

### 阶段 5：写回（WB，仅 lw 需要）
Reg[IR20:16]←MDR

## 五、各指令所需周期数

| 指令类型 | 周期数 | 阶段 |
| --- | --- | --- |
| **lw** | **5** | IF → ID → EX → MEM → WB |
| R 型 | 4 | IF → ID → EX → MEM（在此写回） |
| sw | 4 | IF → ID → EX → MEM |
| beq | 3 | IF → ID → EX |
| 无条件跳转 j | 3 | IF → ID → EX |

lw 比 R 型多一个周期：R 型的结果已经在 ALUOut 里，MEM 阶段可以直接写回寄存器堆；而 lw 的数据在 MEM 阶段才刚从内存读进 MDR，还需要再花一个周期才能写进寄存器。

## 六、控制器必须是状态机
图 5.26　指令执行状态转换图（袁春风《计算机组成与系统结构》第 3 版，见文末教材出处）

单周期的控制器是纯组合逻辑：**输入操作码，输出一组信号**，一步到位。

多周期不行——同一条指令在不同周期要发**不同**的信号。控制器必须知道"现在是这条指令的第几步"，这个信息不在指令里，只能由控制器自己记住。**能记住状态的电路就是时序逻辑，也就是状态机。**

每个状态对应一个时钟周期、发出一组控制信号，再根据操作码决定下一个状态。不同指令走不同的分支路径，**路径有多长，这条指令就占几个时钟周期**。

## 七、单周期与多周期对比

| 对比项 | 单周期 | 多周期 |
| --- | --- | --- |
| 时钟周期 | **最慢指令**决定 | **最慢单步**决定 |
| CPI | 恒为 1 | 3~5（视指令类型） |
| 控制信号 | 一条指令内**不变** | **逐周期变化** |
| 硬件利用率 | 低（大量部件闲置） | 高（部件跨阶段复用） |
| 存储器 | 必须分开（哈佛结构） | 可用**单一**存储器 |
| 加法器 | 需要多个 | 复用 ALU 即可 |
| 中间寄存器 | 不需要 | **必需**（IR/MDR/A/B/ALUOut） |
| 控制逻辑 | 组合逻辑 | **时序逻辑**（状态机） |

> [!WARNING]
>

CPI 变大不等于性能变差

多周期的 CPI 从 1 涨到 4 左右，看起来是退步。但别忘了性能公式：执行时间=指令数×CPI×时钟周期

多周期把**时钟周期**大幅缩短了。若单周期的时钟周期是多周期的 5 倍，而平均 CPI 只有 4，那么多周期反而更快。

**孤立地看 CPI 或频率都会得出错误结论，必须看乘积。**

## 例题

**例**：某程序的指令构成为 R 型 40%、lw 30%、sw 15%、beq 10%、j 5%。求在多周期 CPU 上的平均 CPI。

按上表的周期数加权平均：CPI=0.40×4+0.30×5+0.15×4+0.10×3+0.05×3=1.6+1.5+0.6+0.3+0.15=4.15

若该多周期 CPU 的时钟周期为 2 ns，则平均每条指令耗时 4.15×2=8.3 ns。作为对比，同样的通路做成单周期时，时钟周期要按 lw 的全程延迟取（设为 10 ns），每条指令耗时 10 ns——**多周期更快**。

## 易混淆知识点

**1. 多周期的时钟周期一定等于存取周期吗？**

不一定，但通常按它取。时钟周期由**最复杂的单个阶段**决定，而在多数设计中最慢的一步就是访存，所以教材常直接取一次存储器读写的时间。若某设计中 ALU 比访存还慢，则以 ALU 延迟为准。

**2. 多周期中 PC+4 为什么可以复用 ALU，单周期不行？**

单周期里 ALU 在同一个周期要算有效地址或做减法，腾不出手；多周期里 IF 阶段的 ALU 是空闲的，正好用来算 PC+4。

**这是"部件复用"最直接的例子**：把操作错开到不同时刻，同一个部件就能干多份活，硬件成本随之下降。

**3. 中间寄存器是程序员可见的吗？**

**不可见**。IR、MDR、A、B、ALUOut 全部是实现细节，指令集里没有任何指令能触碰它们。换一种 CPU 实现方式（比如单周期），它们就不存在了。

**4. beq 只用 3 个周期，是因为它简单吗？**

准确说是因为它**不访存也不写寄存器**。EX 阶段算完减法、判完 Zero，PC 就可以直接更新，后面两个阶段没有事情要做。

而 sw 虽然也不写寄存器，却要访存，所以是 4 个周期。**周期数由"最后一个有实际动作的阶段"决定。**

## 本节小结

- 单周期的两个毛病：**时钟周期被最慢指令绑架**、**部件利用率极低**；还有实际存储器的写时序**竞争问题**
- 多周期思想：每阶段最多完成一次访存 / 一次寄存器读写 / 一次 ALU 操作，时钟周期以**最慢单步**为准
- 跨周期的数据必须存进状态元件，因此新增 **IR、MDR、A、B、ALUOut** 五个中间寄存器
- **IR 的存在是部件复用的代价**；A、B 因不需跨周期保持而**无须写使能**
- ID 阶段提前算分支地址属于**零成本投机**——那个周期 ALU 本就闲着
- 控制器必须是**状态机**，因为同一条指令在不同周期要发不同信号
- 多周期 CPI 涨到 4 左右但时钟周期大幅缩短，**必须看乘积才能比较性能**
- 五个中间寄存器是**流水线段间寄存器的前身**
