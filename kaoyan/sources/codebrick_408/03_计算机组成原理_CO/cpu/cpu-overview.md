# CPU 的功能和基本结构

## 大纲定位

**五（一）CPU 的功能和基本结构**

要求：说清 CPU 由运算器和控制器两大部分构成，能指出 PC、IR、MAR、MDR、ACC、PSW 等寄存器各自的功能与位数依据，并区分哪些对程序员可见。

指令如何在这些部件上流动见 [[03_计算机组成原理_CO/cpu/instruction-cycle.md|指令执行过程]]；数据通路的具体连线见 [[03_计算机组成原理_CO/cpu/single-cycle.md|单周期数据通路]]。

## 知识框架

本节回答四个问题：

- CPU 里的部件不是规定的，而是**推出来**的——从功能出发能推出哪些部件？
- 每个寄存器的位数由什么量决定？
- 哪些寄存器对程序员可见？判据是什么？
- 数据通路里有什么、没有什么？

## 一、CPU 的功能

CPU 的职责可以概括为五项：

| 功能 | 含义 |
| --- | --- |
| **指令控制** | 控制程序的顺序执行，即决定"下一条执行哪条" |
| **操作控制** | 产生完成每条指令所需的控制命令，送往各功能部件 |
| **时间控制** | 对各种操作加以**时间上**的控制，即何时发出、持续多久 |
| **数据加工** | 对数据进行算术运算和逻辑运算 |
| **中断处理** | 响应并处理异常与外部请求 |

其中前三项都属于控制器。教材把控制器的基本功能进一步压缩成三个动作：**取指令、分析指令、执行指令**——五项功能就是围绕这三个动作展开的。

## 二、部件是怎么推出来的

CPU 的结构不必死记。从"取指令、分析指令、执行指令"这三个动作出发，每个部件都是某项功能的**必要条件**：

| 要做什么 | 因此必须有 | 部件 |
| --- | --- | --- |
| 自动取指令 | 一个专门存放**当前指令地址**的寄存器 | **PC** |
| 分析指令 | 一个存放**当前指令**的寄存器，和一个对操作码译码的部件 | **IR** + 指令译码器 |
| 执行指令 | 一个能发出各种**操作命令序列**的部件 | **CU** |
| 算术逻辑运算 | 存放操作数的寄存器，和实现运算的部件 | 通用寄存器 + **ALU** |
| 处理异常和特殊请求 | 一套检测与响应机制 | **中断系统** |

由此得到 CPU 的四大组成部分：CPU=ALU+寄存器组+CU+中断系统

习惯上按功能归并成两大块：**运算器**（ALU 及其外围寄存器）与**控制器**（CU、PC、IR 及时序部件）。图 8.2　CPU 的内部结构（唐朔飞《计算机组成原理》第 3 版，见文末教材出处）

图中间那条竖线是 **CPU 内部数据总线**——本章后面所有微操作都在这条总线上发生。

### 为什么还需要 MAR 和 MDR

上面的推导里没有出现 MAR 和 MDR，因为它们不是由"指令怎么执行"推出来的，而是由**CPU 怎么与主存打交道**推出来的。

CPU 通过系统总线访问主存，而总线上的地址和数据必须**稳定保持一段时间**（直到主存完成一次读写），不能只出现一个瞬间。CPU 内部的寄存器随时可能被其他微操作改写，无法承担这个任务。因此需要一对专用的**锁存**寄存器：

- **MAR** 锁住这次访存的地址，直到访存结束
- **MDR** 锁住这次访存的数据（读出的或待写入的）

> [!TIP]
>

MAR 和 MDR 在 CPU 内部

两者都是 **CPU 的寄存器**，不属于主存。它们是 CPU 与主存之间的唯一通道——**所有访存操作都要经过这一对寄存器**，无论取指令还是取数据。

早期教材有把 MAR/MDR 画在主存一侧的画法，那是逻辑示意，实际实现中它们位于 CPU 内。

## 三、各寄存器的功能

### 运算器一侧

| 部件 | 名称 | 功能 |
| --- | --- | --- |
| ALU | 算术逻辑单元 | 执行加减法、与或非等操作 |
| ACC | 累加器 | 存放操作数和运算结果 |
| MQ | 乘商寄存器 | 乘除运算时存放乘数/商 |
| X | 通用操作数寄存器 | 暂存参与运算的操作数 |

### 控制器一侧

| 部件 | 名称 | 功能 |
| --- | --- | --- |
| PC | 程序计数器 | 存放**下一条**指令的地址，顺序执行时自动递增 |
| IR | 指令寄存器 | 存放**当前正在执行**的指令 |
| MAR | 存储器地址寄存器 | 锁存要访问的存储器地址 |
| MDR | 存储器数据寄存器 | 锁存读出或待写入的数据 |
| CU | 控制单元 | 对 IR 中的操作码译码，产生控制信号 |
| PSW | 程序状态字寄存器 | 存放条件码（CF、ZF、SF、OF）与其他状态信息 |

> [!WARNING]
>

PSW 归哪一侧

条件码由 **ALU 在运算时产生**，但 PSW 作为一个状态寄存器，其内容供**控制器**在执行条件转移时读取判断。因此它同时跨在两侧，多数教材将其归入控制器的"控制和状态寄存器"一类。

产生者是运算器，使用者是控制器——记住这条关系比记归属更有用。

常见的四个标志位：

| 标志 | 含义 |
| --- | --- |
| **CF**（进位标志） | 无符号运算产生进位/借位 |
| **ZF**（零标志） | 运算结果为 0 |
| **SF**（符号标志） | 运算结果为负 |
| **OF**（溢出标志） | 有符号运算溢出 |

## 四、各寄存器的位数

寄存器的宽度由**各自不同**的量决定，不能用同一个数套：

| 寄存器 | 宽度取决于 | 举例 |
| --- | --- | --- |
| **PC** | 能寻址到的**指令地址**范围 | 主存 4 GB 按字节编址 ⇒ 32 位 |
| **IR** | **指令字长** | 32 位定长指令字 ⇒ 32 位 |
| **MAR** | 存储器**地址**位数，决定最大寻址空间 | 同 PC 的基准 |
| **MDR** | **存储字长**（等于数据总线宽度） | 与机器字长不一定相等 |

> [!WARNING]
>

按边界对齐时 PC 可以省掉低位

如果指令**按字边界对齐**存放（32 位指令一律放在 4 的倍数地址上），那么指令地址的**低 2 位恒为 0**，这两位不携带信息，PC 不必存它们。

主存 4 GB、按字节编址、32 位定长指令字、指令按字边界对齐：PC 位数=32−log2⁡4=30 位,IR 位数=32 位

只有明确说明"按字边界对齐"时才能省这几位，否则按满位算。

### 哪些部件的位数一定等于机器字长

机器字长的定义是 **CPU 一次能处理的二进制位数**，因此：

| 部件 | 一定等于机器字长？ | 理由 |
| --- | --- | --- |
| **ALU** | **是** | 机器字长的定义就是 ALU 的宽度 |
| **通用寄存器** | **是** | 要装得下 ALU 的操作数和结果 |
| 指令寄存器 IR | 否 | 等于**指令字长**，可与机器字长不等 |
| 浮点寄存器 | 否 | 由浮点格式决定（32 位机上的双精度寄存器是 64 位） |
| MDR | 否 | 等于**存储字长** |

## 五、哪些寄存器程序员可见

> [!CAUTION]
>

判据只有一条

**汇编指令能不能直接读它、写它，或者通过指令的副作用改变它**——能，就是可见；不能，就是 CPU 的内部脚手架，对程序员透明。

按这条判据：

| 程序员可见（属于 ISA） | 程序员透明（实现细节） |
| --- | --- |
| **PC** 程序计数器 | **MAR** 存储器地址寄存器 |
| 通用寄存器组（GPRs） | **MDR** 存储器数据寄存器 |
| **PSW / 条件码寄存器** | **IR** 指令寄存器 |
| 栈指针 SP、**基址寄存器**、变址寄存器 | **微指令寄存器**、控制存储器 |
|  | 流水线段间锁存器、TLB、Cache 行 |

右边一列的共同点：**它们的装入和使用全部由硬件在取指、译码、访存过程中自动完成**，指令集里根本没有能碰到它们的指令。MAR/MDR 是访存的中转站，IR 是取指的落点；微指令寄存器属于控制器的一种实现方式——换成硬布线控制器它就不存在了，自然不可能进入指令集架构。

> [!TIP]
>

PC 可见这一点容易想反

PC 确实不能像通用寄存器那样用 `MOV` 随便读写，但"不能随便读写"不等于"不可见"。

`jmp`、`call`、`ret`、条件分支这些指令的语义**本质就是改写 PC**。程序员能通过指令控制它、也能感知它的值（`call` 会把返回地址即 PC 压栈）。因此 **PC 属于 ISA，是可见的**。

条件码寄存器的情况类似但更微妙：教材称它"对用户来说是**部分**透明的"——条件码由硬件自动设置，程序员通常不直接写它，但可以被条件转移指令测试，部分标志位（如进位标志）还能用专门的指令置位和复位。能被指令读到，就算可见。

## 六、数据通路的两类元件

数据通路由两类元件搭成：

| 类别 | 别名 | 特点 | 包括 |
| --- | --- | --- | --- |
| **操作元件** | 组合逻辑元件 | 输出**只由当前输入决定**，不存储状态，无需时钟 | **ALU**、**多路选择器 MUX**、加法器、译码器、扩展器 |
| **状态元件** | 时序逻辑元件 | 能**保存状态**，由时钟边沿更新 | **PC**、**通用寄存器组**、各类寄存器、存储器 |

判别方法：**撤掉输入后它还记不记得东西**。ALU 撤掉输入立刻失忆，是操作元件；PC 会一直记着地址等下一个时钟沿，是状态元件。

> [!TIP]
>

数据通路里有什么、没有什么

**有**：

- ALU、MUX 等操作元件
- PC、寄存器组等状态元件
- 异常事件的**检测**电路——溢出标志、地址越界、缺页信号，正是从数据通路的运算和访存路径上引出来的

**没有**：

- 产生控制信号的**控制部件**

分工是清楚的：**数据通路负责"数据往哪走、怎么算"，控制器负责"什么时候走、走哪条"**。控制信号是从控制器**送进**数据通路的，不是数据通路自己产生的。

## 易混淆知识点

**1. PC 存的是当前指令地址还是下一条指令地址？**

严格说，PC 中始终存放**下一条**将要执行的指令的地址。

不过取指令时序上有个细节：取指周期开始时 PC 送 MAR，此刻 PC 里装的是**当前**这条指令的地址；随后 PC 立即自增，于是取指周期**结束时** PC 已经指向下一条。两种说法描述的是同一个寄存器在不同时刻的值。

**2. 为什么 PC 的自增要放在取指周期，而不是等指令执行完？**

因为转移指令在**执行周期**要改写 PC。如果自增留到最后做，转移刚写进去的目标地址就会被加掉。

先增后改的顺序还带来一个便利：相对寻址的基准天然就是"下一条指令地址"，转移目标只需给出位移量。

**3. 机器字长、指令字长、存储字长是一回事吗？**

三个独立的量：

| 名称 | 定义 |
| --- | --- |
| 机器字长 | CPU 一次能处理的二进制位数（= ALU 宽度） |
| 指令字长 | 一条指令占的位数（可变长指令没有单一值） |
| 存储字长 | 一个存储单元存放的位数（= MDR 宽度） |

三者可以互不相等。常见设计中会让它们成整数倍关系以简化寻址，但这是设计选择而非必然。

## 本节小结

- CPU 的部件可以从功能**推出来**：取指 ⇒ PC，分析 ⇒ IR + 译码器，执行 ⇒ CU，运算 ⇒ ALU + 寄存器，异常 ⇒ 中断系统
- CPU 四大部分：**ALU + 寄存器组 + CU + 中断系统**；归并为运算器与控制器两块
- **MAR/MDR 由访存需求推出**——总线上的地址和数据必须锁存住；两者在 **CPU 内部**，所有访存都经过它们
- PC 位数看**地址范围**（按字边界对齐可省低位），IR 位数看**指令字长**，MDR 位数看**存储字长**
- **ALU 和通用寄存器的位数一定等于机器字长**；IR、浮点寄存器、MDR 不一定
- 可见性判据：**指令能否读写或改变它**。PC、通用寄存器、PSW、基址寄存器**可见**；MAR、MDR、IR、微指令寄存器**透明**
- 数据通路 = **操作元件**（组合逻辑，ALU/MUX）+ **状态元件**（时序逻辑，PC/寄存器组）
- 数据通路**包含**异常检测电路，**不包含**产生控制信号的控制部件
