## 知识框架

本节回答四个问题：

- 外设为什么不能直接挂在系统总线上？中间那一层到底解决了什么？
- 接口把速度差抹平之后，主机与外设之间还剩下什么问题没解决？
- 三种 I/O 方式排在同一条线上，这条线量的是什么？
- CPU 能访问到设备本体吗？它实际操作的对象是什么？

## 一、外设与主机之间的三重不匹配

计算机里 CPU 与主存是一套高速、同步、格式统一的部件；外设则完全相反。三者的差距可以拆成三条：

| 不匹配 | 具体表现 |
| --- | --- |
| **速度** | 键盘每秒产生几十字节，SSD 每秒几个 GB，CPU 每秒执行上亿条指令 |
| **信号格式** | 外设可能是串行位流、模拟量、机械脉冲，总线上跑的是并行数字信号 |
| **控制协议** | 磁盘要"寻道—找扇区—读"，打印机要"送字符—启动"，各不相同 |

三条都成立，就意味着**外设不可能直接接到系统总线上**——总线只有一套时序和一套电气规范，它没法同时迁就几十种设备。

于是必须在中间加一层：**每类外设配一个专属的部件，对上说总线的话，对下说设备的话**。这个部件就是 **I/O 接口**，也叫设备控制器、I/O 控制器、适配器、接口卡。

图 8.3 外设、设备控制器和 CPU 及主存的互连

这张整机图把接口层的位置画得很清楚：CPU 经处理器总线与存储器总线连主存；外设则通过**各自的控制器**挂在 I/O 总线上——USB 控制器之于鼠标键盘、以太网卡之于网线、磁盘控制器之于硬盘。

由此得到一条贯穿全章的通路：CPU 和主存⟷I/O 总线⟷I/O 接口⟷电缆⟷外设

**CPU 从来不与设备本体对话，它对话的对象永远是控制器。**

## 二、CPU 看得见的只有端口

接口内部会有一批寄存器，其中**允许 CPU 访问的那些**统称 **I/O 端口**。按用途分三类：

| 端口 | 存什么 | CPU 的操作 | 对应哪种不匹配 |
| --- | --- | --- | --- |
| **数据端口** | 待传输的数据 | 可读可写 | 速度（缓冲）、格式（串并转换） |
| **状态端口** | 设备状态：就绪 / 忙 / 出错 | 只读 | 速度（让 CPU 知道何时能动手） |
| **命令端口** | CPU 下发的控制命令 | 只写 | 协议（把"读扇区"这类动作翻译给设备） |

三类端口不是随便定的——**它们正好一一对应上面三重不匹配**。缓冲寄存器解决速度和格式，状态寄存器解决"什么时候可以传"，命令寄存器解决"这台设备该怎么驱动"。

> [!WARNING]
>

主存地址不在这张表里

查询方式和中断方式下，数据要经过 CPU 中转，**主存地址只在 CPU 内部周转，根本不出现在接口上**。

只有 **DMA 方式**例外——它要让控制器自己去访存，所以必须把主存起始地址交给 DMA 控制器保存。这是 DMA 与前两种方式在结构上的第一处分野，详见 [[03_计算机组成原理_CO/io/dma.md|DMA 方式]]。

端口怎么编号、CPU 用什么指令访问，见 [[03_计算机组成原理_CO/io/io-interface.md|I/O 接口与端口编址]]。

## 三、接口解决了"能不能连"，没解决"何时传"

装上接口以后，主机与外设物理上通了。但还剩一个问题没人管：

**设备什么时候准备好？CPU 怎么知道？**

外设是异步的——按键什么时候被按下、磁头什么时候转到目标扇区，CPU 事先无从知晓。围绕这一个问题的不同答案，就长出了不同的 I/O 方式：

| 谁来解决"何时" | 做法 | 名称 |
| --- | --- | --- |
| **CPU 自己反复去问** | 循环读状态端口，直到"就绪"位置 1 | **程序查询方式** |
| **设备主动来报** | 设备就绪时发中断请求，CPU 在指令边界响应 | **程序中断方式** |
| **连搬运也不劳驾 CPU** | 控制器自己拿总线、自己访存，整块传完才报一次 | **DMA 方式** |
| **连组织都交出去** | 专用处理器执行通道程序，自主完成一串 I/O 任务 | **通道方式**（纲外） |

四行之间的差别，可以统一到**一条量**上：CPU 介入 I/O 的程度

- 程序查询：**全程占用**，等待期间 CPU 什么别的都干不了
- 程序中断：**每传一个数据介入一次**，等待期间 CPU 去跑别的程序
- DMA：**每传一块介入两次**（开头设参数、结尾收中断），传输期间完全不在场
- 通道：**每发一次 I/O 指令介入一次**，一串数据块由通道自己组织

这不是四个并列的知识点，而是**同一条轴上的四个刻度**。横向的定量对比见 [[03_计算机组成原理_CO/io/io-compare.md|I/O 方式对比]]。

> [!TIP]
>

"越靠后越好"是有代价的

每往后走一格，CPU 省下的时间是拿硬件换来的：中断方式要中断控制器和判优电路，DMA 要一整套能主控总线的控制器，通道要一个能取指执行的专用处理器。

所以低速简单设备用查询方式不是"落后"，是**硬件成本与收益算下来更划算**。

## 四、I/O 系统的软硬件构成
I/O 系统=I/O 硬件+I/O 软件

**I/O 硬件**：外部设备、I/O 接口（设备控制器）、I/O 总线。

**I/O 软件**：I/O 指令（属于 CPU 指令系统，且是**特权指令**）、中断服务程序、设备驱动程序、与设备无关的 I/O 管理软件。

> [!TIP]
>

I/O 指令为什么必须是特权指令

I/O 指令直接读写接口中的端口。如果用户程序能随意执行它，就能越过操作系统改写别的进程正在使用的设备状态——打印到一半的文件、正在写的磁盘扇区都不再安全。

所以它只能在内核态使用；用户程序想做 I/O，只能通过系统调用请操作系统代劳。特权指令的完整清单见 [[03_计算机组成原理_CO/cpu/exception-interrupt.md|异常和中断机制]]。

外部设备按数据的流向分为输入设备（键盘、鼠标、扫描仪）、输出设备（显示器、打印机）和既能读又能写的外存储设备（磁盘、SSD、光盘）。按速率则从每秒几十字节到每秒几个 GB 不等——**这个跨度本身就是 I/O 系统要设计成分层结构的原因**：不可能用一套机制同时伺候好键盘和固态盘。

## 易混淆知识点

**1. 设备、接口、端口是三个层次吗？**

是，而且层层包含：

| 层次 | 是什么 | 举例 |
| --- | --- | --- |
| **设备** | 完成物理动作的本体 | 显示器、键盘、磁盘驱动器、打印机 |
| **接口** | 介于设备与 I/O 总线之间的控制部件 | 显卡、网卡、磁盘控制器、USB 控制器、可编程中断控制器 |
| **端口** | 接口内部**可被 CPU 访问的寄存器** | 数据端口、状态端口、命令端口 |

判据：名字里带**控制器 / 适配器 / 卡**的，基本都在接口层；CPU 的 I/O 指令**只能打到端口这一层**，够不到设备本体。

**2. "DMA 只适用于高速设备"这句话对吗？**

不对，它把**典型场景**说成了**硬约束**。

DMA 没有"设备必须多快"的门槛，只要设备接口支持 DMA 协议就能用，接一个慢速设备完全合法，只是收益不大——每块数据要等很久才凑齐，DMA 的批量优势发挥不出来。

反过来的说法才是硬的：**高速设备不能用中断方式**，因为中断频率会高到 CPU 处理不过来甚至丢数据。判据见 [[03_计算机组成原理_CO/io/programmed-interrupt.md|程序查询方式与程序中断方式]]。

**3. 接口和总线是一回事吗？**

不是。**总线是公共的传输通路，接口是挂在总线上的一个部件。** 一条 I/O 总线上会挂许多接口，每个接口伺候一类设备。总线负责"信号怎么跑、什么时候跑"，接口负责"这台设备该怎么伺候"。总线本身的组成与定时见 [[03_计算机组成原理_CO/bus/bus-overview.md|总线概述]]。

**4. 用了 DMA 就不用中断了吗？**

不是。DMA 传完一块数据后，**通知 CPU 靠的仍然是中断**。DMA 做的不是取消中断，而是把中断从"每传一个数据一次"降到"每传一块一次"。

## 本节小结

- 外设与主机存在**速度、信号格式、控制协议**三重不匹配，因此外设必须经 I/O 接口才能接入总线
- 完整通路：**CPU 和主存 — I/O 总线 — I/O 接口 — 电缆 — 外设**；CPU 永远不直接对话设备本体
- 接口中可被 CPU 访问的寄存器称为 **I/O 端口**，分**数据 / 状态 / 命令**三类，正好对应三重不匹配
- **主存地址不属于接口内容**，只有 DMA 方式才把它交给控制器保存
- 接口解决"能不能连"，**不解决"设备何时就绪"**——三种 I/O 方式正是这个问题的三种答案
- 四种方式排在同一条轴上，量的是 **CPU 介入 I/O 的程度**：查询（全程）→ 中断（每个数据一次）→ DMA（每块两次）→ 通道（每次 I/O 指令一次）
- 往后走省下的 CPU 时间是用**硬件复杂度**换的，低速设备用查询方式是合算的选择
- **I/O 指令是特权指令**，用户程序只能通过系统调用发起 I/O
