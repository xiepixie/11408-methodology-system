# I/O方式对比

## 大纲定位

**六（三）I/O 方式**

- 程序查询方式　2. 程序中断方式　3. DMA 方式

要求：本节不引入新概念，专做三条的横向对照。读完应当能把三种方式放到同一条轴上定位，说出每一次"升档"具体放掉了 CPU 的哪一部分工作，并判断某个设备该用哪一档。

各自的机制见 [[03_计算机组成原理_CO/io/programmed-interrupt.md|程序查询方式与程序中断方式]] 与 [[03_计算机组成原理_CO/io/dma.md|DMA 方式]]；纲外的通道方式见 [[03_计算机组成原理_CO/io/channel.md|通道方式]]。

## 知识框架

本节回答三个问题：

- 三种方式排在同一条线上，这条线量的是什么？
- 查询 → 中断、中断 → DMA 这两次跃迁，放掉的**不是同一样东西**。分别是什么？
- 什么条件下必须往后升一档？——判据是性能，还是别的？

## 一、一条轴：CPU 介入 I/O 的程度

三种（连同纲外的通道是四种）I/O 方式不是四个并列的知识点，而是**同一条轴上的四个刻度**：程序查询⏟全程占用⟶程序中断⏟每个数据一次⟶DMA⏟每块两次⟶通道⏟每次 I/O 任务一次

轴上量的是**CPU 介入 I/O 的程度**：

| 方式 | CPU 什么时候必须在场 | 一次传送 n 个数据，CPU 介入几次 |
| --- | --- | --- |
| **程序查询** | 从启动设备到最后一个数据传完，**全程** | 全程占用，无法离开 |
| **程序中断** | 每个数据就绪时被打断一次 | n 次 |
| **DMA** | 块开始时设参数、块结束时收中断 | **2 次**（与 n 无关） |
| **通道** | 发出一条启动通道的 I/O 指令、收一次结束中断 | **2 次**（与块数也无关） |

**最后一列是这张表的重点**：中断方式的 CPU 开销与数据个数成正比，DMA 与之无关。这条比例关系的断裂，就是 DMA 存在的全部意义。

## 二、两次跃迁，放掉的不是同一样东西

轴上相邻两档之间的差别，很容易被笼统说成"CPU 更省了"。但**两次"省"省的是完全不同的东西**：

### 查询 → 中断：放掉的是「等待」

程序查询方式下，CPU 与外设**串行工作**：设备准备数据的那一整段时间里，CPU 反复读状态端口，执行的指令对程序毫无贡献。

中断方式把这一段还给了 CPU——设备准备数据期间，CPU 去跑别的程序，两者**并行**。

> [!CAUTION]
>

中断并没有减少 I/O 本身的 CPU 开销

恰恰相反，**单次中断的开销通常比单次查询更大**：它多了保存断点、保护现场、恢复现场、中断返回这几步。

中断方式换来的是"等待时间可以被别的程序用掉"，**不是"搬一个数据更便宜了"**。下面第四节的算例会直接给出一组反直觉的数字。

### 中断 → DMA：放掉的是「搬运」

中断方式下，数据仍然走"设备接口 → CPU 寄存器 → 主存"这条三段通路，CPU 是不可替代的搬运工，所以每个数据都得惊动它一次。

DMA 把通路短路成"**设备接口 ↔ 主存**"，控制器自己发地址、自己发读写信号。CPU 不再是通路的一部分，于是介入次数从 n 掉到 2。

### DMA → 通道：放掉的是「组织」

DMA 卸掉了搬运，但每一次块传送的参数还得 CPU 去设。设备一多，光初始化就吃掉大量 CPU 时间。通道把"先传哪台、传到哪、传完接着做什么"这层组织工作也接了过去——CPU 只发一条启动命令。

**三次跃迁连起来看**：等待⟶搬运⟶组织

每一步都把 CPU 的一类工作剥离出去，剥离的顺序是从最外层（等）到最内层（管）。

> [!TIP]
>

越靠后越好，但代价是硬件

中断方式要中断控制器和判优电路，DMA 要一整套能主控总线的控制器，通道要一个能取指执行的专用处理器。

所以低速简单设备用查询方式不是"落后"——**成本与收益算下来它更划算**。

## 三、三种方式全面对照

| 特性 | 程序查询 | 程序中断 | DMA |
| --- | --- | --- | --- |
| **数据通路的两端** | 设备接口 → **CPU 寄存器** → 主存 | 设备接口 → **CPU 寄存器** → 主存 | **设备接口 ↔ 主存**（不进 CPU） |
| **谁持有主存地址、谁发起访存** | CPU | CPU | **DMA 控制器** |
| **传送单位** | 字 / 字节（由端口位宽定） | 字 / 字节（由端口位宽定） | **数据块** |
| **CPU 与外设的关系** | **串行** | **并行** | **并行** |
| **CPU 介入频率** | 全程 | 每个数据一次 | 每块两次 |
| **请求的是什么** | 不请求（CPU 主动查） | **CPU 的执行权** | **总线控制权** |
| **由谁裁决** | — | 中断判优 | **总线仲裁** |
| **响应时刻** | 查到即处理 | **指令执行结束后** | **存储周期结束后** |
| **是否需要中断机制** | 否 | 是 | **是**（报告块传送完成） |
| **硬件成本** | 最低 | 中断控制器 | DMA 控制器 |
| **主要适用场景** | 低速设备、简单系统 | 中低速设备 | 高速、成批传送 |

> [!WARNING]
>

"适用场景"是典型情况，不是硬约束

DMA 没有"必须接高速设备"的门槛，接慢速设备完全合法，只是收益不大。

反过来的说法才是硬的：**高速设备不能用中断方式**，因为会丢数据。凡是出现"**仅**适用于""**所有**""**必须**"这类绝对化措辞的表述，先怀疑。

> [!CAUTION]
>

数据通路那一行最容易记岔

DMAC 内部的数据缓冲寄存器只是过渡缓冲，**不改变通路的两端**。"数据通路在设备接口和 DMA 控制器之间"是错的——两端始终是**设备接口和主存**。

## 四、定量：三种方式的 CPU 占比

三个公式共用同一副骨架：CPU 占比=每秒介入次数×单次介入的时钟周期数主频 f

差别只在**"每秒介入次数"怎么算**：

| 方式 | 每秒介入次数 | 单次开销 |
| --- | --- | --- |
| **定时查询** | R/u（u = 每次传送字节数） | 单次查询的周期数 |
| **程序中断** | R/u | m = 响应 + 处理的周期数 |
| **DMA** | R/Bs（Bs = 块大小，字节） | m = 预处理 + 后处理的周期数 |

其中 R 是设备数据传输率（B/s）。公式的完整推导与逐步算例见 [[03_计算机组成原理_CO/cpu/exception-interrupt.md|异常和中断机制]]；两种查询模型（独占查询 100%、定时查询套公式）的区分见 [[03_计算机组成原理_CO/io/programmed-interrupt.md|程序查询方式与程序中断方式]]。

> [!CAUTION]
>

两个通用失分点

- **u 由数据端口 / 缓冲寄存器的位宽决定**，不是默认 1 字节。题面里"I/O 数据端口 32 位""每次传送一个 16 字节的数据"给的就是 u。
- **指令条数要乘 CPI 才是周期数**，且各部分开销**先相加再乘**。

### 一组并排的数字

同一台设备、同一台机器，三种方式各算一遍。

| 参数 | 值 |
| --- | --- |
| CPU 主频 f | 1 GHz |
| 设备数据传输率 R | 1 MB/s |
| 数据缓冲寄存器 | 32 位，故 u=4 B |
| 单次查询开销 | 100 个时钟周期 |
| 单次中断开销 m | 400 个时钟周期 |
| DMA 块大小 Bs | 4 KB；单次 DMA 的预处理 + 后处理同样 400 个周期 |

**定时查询**：(106/4)×100109=2.5×107109=2.5%

**程序中断**：(106/4)×400109=108109=10%

**DMA**：(106/4096)×400109≈9.77×104109≈0.0098%

> [!WARNING]
>

中断的数字比查询还大——这不是算错了

2.5%<10% 是真的：单次中断（400 周期）比单次查询（100 周期）贵，而两者的介入次数完全相同。

但这两个百分比**含义不同**：

- 查询方式的 2.5% 之外，CPU 还必须**守在这台设备旁边**——定时查询要求它按节拍回来查，独占查询更是把 100% 的时间钉在这里
- 中断方式的 10% 之外，CPU 的时间**是自由的**，可以跑任何别的程序

**中断方式的优势从来不在这个百分比上，而在于它把剩下的时间变成了可支配的时间。**

DMA 那一档才是百分比意义上的碾压：介入次数从 R/u 掉到 R/Bs，直接降了 Bs/u=1024 倍。

## 五、什么时候必须升档

判据分两层，先物理后性能：

**第一层是物理判据，不容商量**：T设备准备一个数据>T中断响应+中断处理

不成立就会**丢数据**——上一个数据还没被 ISR 搬走，设备已经把下一个覆盖上去。这不是"慢一点"，是功能上不可用。

**第二层才是性能判据**：物理上成立，但 CPU 占比高到挤占正常计算，同样要换 DMA。

**往回降档也有条件**：设备极慢（每秒几十字节）、系统极简单、不值得为它配中断控制器，程序查询方式就是合适的选择——这时候 CPU 占比本来就可以忽略。

## 易混淆知识点

**1. 三种方式的分界线到底是什么？**

**CPU 介入 I/O 的程度**。查询是全程占用，中断是每个数据一次，DMA 是每块两次。三者不是并列的三个方案，是同一条轴上的三个刻度。

**2. 中断方式比查询方式省 CPU 开销吗？**

**不省，通常还更贵**。它省的是**外设准备数据期间的等待时间**——那段时间从空转变成了可以跑别的程序。判断这类说法的口径：看省的是"每次传送的开销"还是"等待的时间"。

**3. 为什么中断在指令边界响应，DMA 在存储周期边界响应？**

因为两者**让出的东西的最小完整单位不同**。中断要交出 CPU 的执行权，得等一条指令做完、PC 和 PSW 干净可恢复；DMA 只要占用总线，总线的最小不可分割单位是一个存储周期。**粒度由让出的对象决定，不用背。**

**4. CPU 和 DMA 同时要访存，为什么 DMA 优先？**

不是重要性，是**时限**。外设数据不及时取走会丢失（磁盘转过去要等一整圈），CPU 延后一两个存储周期只是慢一点。判据永远是"谁耽误不起"。

**5. 用了 DMA 就不需要中断了吗？**

不是。DMA 传完一块仍然靠**中断**通知 CPU 做后处理。DMA 把中断从"每个数据一次"降到"每块一次"，不是取消中断。

**6. DMA 一定比中断快吗？**

对**单个数据**而言不一定——DMA 有申请总线、建立总线控制权的固定开销。它的优势体现在**成批传送**上：块越大，固定开销被摊得越薄。传一个字节还要走一遍 DMA 流程，反而不划算，这也是低速设备用中断更合理的原因。

## 本节小结

- 三种（含通道是四种）I/O 方式是**同一条轴上的刻度**，轴量的是 **CPU 介入 I/O 的程度**
- 一次传送 n 个数据：查询**全程占用**，中断介入 **n 次**，DMA 介入 **2 次**（与 n 无关）——比例关系的断裂是 DMA 的意义所在
- 三次跃迁放掉的是**不同的东西**：查询→中断放掉**等待**，中断→DMA 放掉**搬运**，DMA→通道放掉**组织**
- **中断没有减少 I/O 的 CPU 开销**（单次更贵），它把等待时间变成了可支配时间
- 数据通路：查询和中断都是"设备接口 → **CPU 寄存器** → 主存"，DMA 是"**设备接口 ↔ 主存**"
- 请求的对象不同：中断请求 **CPU 执行权**（走中断判优，指令边界响应），DMA 请求**总线控制权**（走总线仲裁，存储周期边界响应）
- 三个占比公式共用一副骨架，差别只在**每秒介入次数**：查询与中断为 R/u，DMA 为 R/Bs
- **u 由数据端口位宽决定**，不是默认 1 字节；指令条数要**先相加再乘 CPI**
- 升档判据分两层：先看 T准备>T响应+处理 是否成立（不成立会**丢数据**），再看 CPU 占比是否可接受
- "适用场景"是典型情况不是硬约束：DMA 可接慢速设备，但**高速设备不能用中断**
