# 计算机系统层次结构

## 大纲定位

**一（一）计算机系统层次结构**

包含四个子项：计算机系统的基本组成；计算机硬件的基本结构；计算机软件和硬件的关系；计算机系统的工作原理（"存储程序"工作方式，高级语言程序与机器语言程序之间的转换，程序和指令的执行过程）。

要求：能从"存储程序"这一条前提推出计算机必须有哪些部件；能按顺序说出计算机系统的各个层次并指出软硬件的分界面；能完整描述一行高级语言代码到硬件执行之间发生的全部转换。

性能怎么度量见 [[03_计算机组成原理_CO/overview/performance-metrics.md|计算机的性能指标]]；一条指令在 CPU 各部件上的具体流动见 [[03_计算机组成原理_CO/cpu/instruction-cycle.md|指令执行过程]]。

## 知识框架

本节回答四个问题：

- "存储程序"这一条前提，能推出计算机必须有哪些部件？
- 计算机的层次为什么恰好是"硬件 — 微程序 — 机器语言 — 操作系统 — 汇编 — 高级语言"这个顺序？相邻两层能不能对调？
- 软件和硬件的分界画在哪一层？为什么必须有这样一个分界？
- 一行高级语言代码要经过几次转换才能被硬件执行？翻译和解释的分界在哪？

## 一、五大部件是怎么推出来的

冯·诺依曼在研究 EDVAC 机时提出"存储程序"思想。这个思想只有一句话：

**程序和数据事先存入存储器，机器启动后自动逐条取出并执行，中途无须人工干预。**

五大部件不需要背，它们是这一句话的**必要条件**：

| 这句话要求什么 | 因此必须有 | 部件 |
| --- | --- | --- |
| 程序和数据要能"事先存进去"并保持住 | 一个能保存二进制信息、按地址存取的部件 | **存储器** |
| 程序和原始数据要从外界进来 | 一条把外部信息转成机内表示的通路 | **输入设备** |
| 结果要送到外界 | 一条把机内表示转成外部形式的通路 | **输出设备** |
| 指令要"自动逐条取出并执行" | 一个能取指、译码、按节拍发出控制命令的部件 | **控制器** |
| 指令最终要完成算术与逻辑运算 | 一个执行运算的部件 | **运算器** |

教材把冯·诺依曼结构的基本思想归纳为四条：

- 采用**"存储程序"**的工作方式；
- 由**运算器、控制器、存储器、输入设备、输出设备**五个基本部件组成；
- 存储器不仅能存放数据，也能存放指令，**形式上数据和指令没有区别，但计算机应能区分它们**；控制器应能控制指令的自动执行；运算器应能进行加减乘除四种基本算术运算，也能进行逻辑运算；操作人员通过输入/输出设备使用计算机；
- 计算机内部**以二进制形式**表示指令和数据；每条指令由**操作码**和**地址码**两部分组成，操作码指出操作类型，**地址码指出操作数的地址**；由一串指令组成程序。

### 为什么必须是二进制

这一条不是习惯，是三个互相独立的理由叠加的结果：

| 理由 | 说明 |
| --- | --- |
| **器件容易做** | 二进制只有两种基本状态，用有两个稳定状态的物理器件就能表示一位；而制造有多个稳定状态的物理器件要困难得多。高低电位、脉冲的有无、脉冲的正负极性，都能很可靠地表示 0 和 1 |
| **规则简单** | 二进制的编码、计数和运算规则都很简单，可以直接用开关电路实现 |
| **与逻辑天然对应** | 1 和 0 正好对应逻辑命题的"真"与"假"，逻辑运算和逻辑判断都有了现成的实现方式，算术运算也能通过逻辑门电路方便地实现 |

三条缺一不可：只有第一条，二进制只是"好造"；加上后两条，它才同时是"好算"和"好判断"的。

### 地址码里装的是地址

第 4 条里"地址码指出操作数的**地址**"这半句，决定了取操作数是一次**额外的访存**，而不是从指令里直接读走。只有立即寻址这一种方式，操作数才真的写在指令字里面——那是寻址方式中的特例，不是通例。各种寻址方式如何从地址码算出真正的操作数地址，见 [[03_计算机组成原理_CO/instruction/addressing-modes.md|数据寻址方式]]。

### CPU 靠什么区分指令和数据

既然指令和数据在存储器里形式上没有区别，"计算机应能区分它们"这个要求就必须由别的东西来兑现。

区分它们的信息**不在内容里，而在时序里**：

- **取指周期**里从主存取回的内容，CPU 一律当作**指令**送去译码；
- **执行周期**里从主存取回的内容，一律当作**数据**送去运算。

这条办法之所以成立，是因为 CPU 自己知道当前处在指令周期的哪个阶段——阶段是控制器的内部状态，与存储器里的 0/1 无关。

反过来看，别的判据都无法承担这个任务：操作码译码发生在"已经确定它是指令之后"，是结果不是原因；寻址方式是指令内部的字段，同样要先取回指令才谈得上；而冯·诺依曼机的指令和数据**共用同一个存储器、同一套地址空间**，也不存在按存储位置划分的可能。

### 从以运算器为中心到以存储器为中心

早期冯·诺依曼机**以运算器为中心**：I/O 与存储器之间的数据传送都要经过运算器中转。这个结构的代价很直接——每传一个字节都要占用运算器，CPU 干不了别的事。

现代计算机改为**以存储器为中心**：I/O 设备可以不经运算器直接与主存交换数据，代表就是 [[03_计算机组成原理_CO/io/dma.md|DMA 方式]]。两种说法各有各的适用对象：描述冯·诺依曼机的原始特征时是前者，描述现代计算机结构时是后者。

## 二、计算机硬件的基本结构

现代计算机把运算器、控制器和各类寄存器做在一个芯片里，称为 **CPU**。

| 部件 | 内部构成与职责 |
| --- | --- |
| **CPU** | **数据通路**（ALU + 通用寄存器等）执行运算并暂存操作数；**控制器**对指令译码、生成控制信号，指挥数据通路做正确的操作 |
| **存储器** | 内存包括**主存**和 **Cache**；外存包括磁盘、固态硬盘等直接与主存交换信息的存储器，以及海量后备存储器 |
| **外部设备** | 由**机械部分**（设备本身）和**电子部分**（设备控制器）组成，两部分通常可以分开 |
| **I/O 接口** | 即设备控制器、I/O 控制器、I/O 模块，外设通过它连到主机上。键盘接口、显卡、网卡都是设备控制器 |
| **总线** | 传输信息的介质，CPU、主存和 I/O 模块通过总线互连 |

CPU 内部各寄存器的功能与位数依据，见 [[03_计算机组成原理_CO/cpu/cpu-overview.md|CPU 的功能和基本结构]]。

CPU 与主存之间通过**地址线、数据线、控制线**三组信号线相连，三者的分工是固定的：

- MAR 中的地址信息直接送到**地址线**上；
- 控制器送出的读/写信号走**控制线**，指出这次传送的方向；
- MDR 与**数据线**双向相接：写操作时把 MDR 的内容送上数据线，读操作时把数据线上的内容接收进 MDR。

## 三、软件和硬件的关系

### 一台完整的计算机系统 = 硬件系统 + 软件系统

前面两节讲的都是硬件。但**计算机系统**这个词涵盖的是两大部分：

- **硬件**是计算机的实体部分，由看得见摸得着的各种电子元器件、各类光电机设备的实物组成，主机与外部设备都在其内；
- **软件**看不见摸不着，是人们事先编制的、具有各类特殊功能的程序，通常存放在主存或辅存中。

两者的依赖是**双向**的，这一点比"计算机由两部分组成"这句话本身更要紧：

- 往上看，软件的发展**充分发挥硬件已有的功能**、提高机器的工作效率——同一批硬件配上更好的编译器和操作系统，实际效能会差出很多；
- 往下看，软件性能的发挥又**必须依托硬件的支撑**——再好的算法也跑不过硬件给定的时钟周期和存储带宽。

所以评价一台机器的好坏，看的是**软硬件功能的总和**，而不是任何一侧单独的参数。这也解释了为什么性能评价必须靠实际跑程序来测，见 [[03_计算机组成原理_CO/overview/performance-metrics.md|计算机的性能指标]] 里的基准程序一节。

### 两类软件

| 类别 | 定义 | 举例 |
| --- | --- | --- |
| 系统软件 | 管理整个计算机系统、监控服务，使系统资源得到合理调度，是其他软件运行的环境 | 操作系统、语言处理程序（编译器/汇编器/解释器）、标准程序库、数据库管理系统、网络软件、服务程序（诊断、调试、连接程序） |
| 应用软件 | 用户根据自身任务需要所编制的各种程序 | 科学计算程序、数据处理程序、过程控制程序、办公软件、浏览器 |

判据不在"谁写的"，而在**这个程序服务的对象是机器还是用户的具体任务**：编译器不解决任何具体应用问题，它服务的是"让别的程序能跑起来"，所以是系统软件；一个自己写的排序小程序哪怕再底层，服务的仍是某个具体任务，属应用软件。

### 软硬件在逻辑功能上等价

同一个功能既可以用硬件实现，也可以用软件实现，从使用者的角度看逻辑功能是等价的。浮点运算就是典型例子：既可以由硬件浮点部件完成，也可以由一段软件子程序模拟，结果一样，只是硬件实现快得多。

由此带来一个更重要的结论：**软硬件的功能分界不是固定的**。随着集成电路技术的发展，原先由软件承担的功能会不断被硬件接管——操作系统的一部分被固化到只读存储器里（称为固件）就是这样一个例子。软硬件的交界面在历史上一直在向上移动。

划到哪里合适，是一个成本与性能的权衡，也是计算机体系结构研究的核心问题之一。指令集设计上的 [[03_计算机组成原理_CO/instruction/cisc-vs-risc.md|CISC 与 RISC 之争]]，本质上就是这条界线画在哪里的分歧。

## 四、层次结构：顺序是被"谁实现谁"锁死的

计算机系统自底向上分为多级，每一级都是一台"机器"：

| 级 | 这一级是什么机器 | 它的语言由谁执行 |
| --- | --- | --- |
| 第五级 | **高级语言机器 M4** | 用编译程序翻译成汇编语言程序 |
| 第四级 | **汇编语言机器 M3** | 用汇编程序翻译成机器语言程序 |
| 第三级 | **操作系统机器 M2** | 用机器语言解释操作系统 |
| 第二级 | **传统机器 M1**（机器语言机器） | 用微程序解释机器指令 |
| 第一级 | **微程序机器 M0**（微指令系统） | **由硬件直接执行微指令** |

只有 M0 是**实际机器**——它的语言（微指令）由硬件电路直接执行，不需要任何程序去翻译。它上面的每一级都是**虚拟机器**：这一级并不真实存在，是下面那一级用软件或固件"装出来"的，使用者感觉不到中间的转换过程。

### 顺序为什么不能动

层次的顺序不是约定，而是被一条规则锁死的：

**每一级只能由紧邻的下一级来实现**——上一级的每条语句，要么被下一级**翻译**成一串下一级的语句，要么被下一级的程序逐条**解释**执行。

谁被谁实现，谁就在上面。逐对检查：

| 相邻两级 | 为什么下面那级必须在下面 |
| --- | --- |
| M0 与硬件 | 微指令是硬件电路能直接响应的最小单位，下面没有别的东西了，链条到此终止 |
| M1 与 M0 | 一条机器指令要拆成一串微操作才能落到电路上，这串微操作就是一段微程序。**机器指令是由微程序解释执行的** |
| M2 与 M1 | 操作系统本身就是一批用机器指令写成的程序。它在 M1 之上扩充出一批"广义指令"（系统调用），供上层调用 |
| M3 与 M2 | 汇编程序是运行在操作系统提供的环境里的一个普通程序。**所有语言处理系统都必须在操作系统提供的计算机环境中运行** |
| M4 与 M3 | 高级语言与底层机器结构无关，必须先落到与机器绑定的符号层（汇编语言），才能继续往下落到二进制 |

两处对调之所以不成立，理由都很硬：

- **汇编与高级语言对调不成立**。汇编语言的每条语句与机器语言的某条语句一一对应，摆脱不了具体机器的指令系统，每台机器都要有一种与之对应的汇编语言；高级语言则与机器结构无关。把"不需要知道机器长什么样"的一层放到"必须知道机器长什么样"的一层下面，等于让前者去实现后者，做不到。
- **操作系统与汇编对调不成立**。汇编器只是操作系统上的一个进程；反过来，操作系统不可能运行在汇编器之上。

M4 再往上还可以延伸出**应用语言机器**，它面向某类特定问题，由应用程序包翻译到下一级。往上的延伸没有终点，往下的延伸有——终点就是硬件。

### 微程序机器不是每台机器都有

M0 这一级只在采用**微程序控制器**的 CPU 上存在。如果控制器用**硬布线**方式实现，控制信号由组合逻辑电路直接从操作码和节拍信号译出，根本没有"微指令"这种东西，M1 的下面就直接是电路。两种控制器的对比见 [[03_计算机组成原理_CO/cpu/hardwired-control.md|硬布线控制器]] 与 [[03_计算机组成原理_CO/cpu/microprogrammed.md|微程序控制器]]。

也就是说，这张层次表描述的是**一种常见的组织方式**，不是每台计算机都必须逐级具备的物理构造。

### 另一种画法：抽象层

有的教材不按"虚拟机器"来分，而按**抽象层**来分。两种画法说的是同一件事：

| 多级机器的画法 | 抽象层的画法 |
| --- | --- |
| 应用语言机器 / 高级语言机器 M4 | 应用程序 / 高级语言 |
| 汇编语言机器 M3 | 汇编语言 |
| 操作系统机器 M2 | 操作系统 |
| 传统机器 M1 | **ISA（指令集体系结构）** |
| 微程序机器 M0 | **微体系结构** |
| —— | 逻辑电路 |
| —— | 器件 / 物理实现 |

抽象层的画法把硬件一侧拆得更细：微体系结构由**逻辑电路**实现，每个基本的逻辑电路又按特定的**器件技术**实现。

### 透明性

一个存在的事物或概念，从某个角度看似乎不存在、感觉不到它实际存在，就称它对这个角度是**透明**的。

层次结构的价值正在于此：每一层向上提供一个简洁接口，把自己的实现细节藏起来。系统程序员看到的底层机器级的概念性结构和功能特性，对应用程序员来说是透明的。

不同的人工作在不同的层次上，看到的"计算机"因此并不是同一台：

| 用户 | 工作在哪一层 | 他看到的机器 |
| --- | --- | --- |
| 最终用户 | 应用程序层 | 一个应用软件 |
| 应用程序员（高级语言程序员） | 语言处理系统层 | 高级语言虚拟机 |
| 汇编语言程序员 | 汇编程序层 | 汇编语言虚拟机 |
| 系统管理员 | 操作系统层 | 操作系统虚拟机 |
| 系统程序员（机器语言程序员） | **ISA 层** | 配置了指令系统的机器语言机器 |

## 五、ISA：软件和硬件的分界面

从应用问题一路转换到机器语言程序，涉及的概念全部属于软件范畴；而机器语言程序要在硬件上跑起来。**软件与硬件之间需要一个界面**，这个界面就是 **ISA**（instruction set architecture，指令集体系结构）。

### 为什么必须有这样一个界面

因为软件和硬件的演进速度完全不同，而且必须能各自独立地往前走。ISA 承担的是一份**契约**的角色：

- 对硬件设计者：只要实现了 ISA 规定的全部指令语义，内部怎么组织完全自由——几级流水线、Cache 多大、是否乱序，都不影响契约；
- 对软件：只要程序由 ISA 规定的指令组成，就能在任何遵循该 ISA 的处理器上运行，不必因为换了一代实现而重写。

没有这份契约，每换一次硬件实现，全部软件都要重做一遍。

### ISA 规定什么

ISA 是软件和硬件之间接口的一个**完整定义**，它定义了一台计算机可以执行的所有指令的集合，每条指令规定了执行什么操作、操作数存放在哪里、操作数是什么类型。具体包括：

- 指令格式、指令操作类型
- 指令的操作数类型、寻址方式、可访问地址空间大小
- 程序可访问的寄存器个数、位数和编号
- 控制寄存器的定义
- I/O 空间的编址方式
- 中断结构
- 机器工作状态的定义和切换
- 输入/输出结构和数据传送方式
- 存储保护方式

一句话概括：**ISA 就是软件能感知到的那部分，也称软件可见部分**。哪些寄存器属于 ISA、哪些是实现的脚手架，判据见 [[03_计算机组成原理_CO/cpu/cpu-overview.md|CPU 的功能和基本结构]] 里"程序员可见"那一节。

### ISA 与微体系结构

ISA 是对指令系统的**规定**，而具体实现的组织称为**微体系结构**（microarchitecture，简称微架构）。两者在不同层面上：

**ISA 定义"做什么"，微体系结构决定"怎么做"。微体系结构是软件不可感知的部分。**

教材给的判别例子很干脆：加法器采用**串行进位**还是**并行进位**实现，属于微体系结构范畴——因为无论用哪种，加法指令的语义（两个数相加，结果送目的寄存器，置标志位）完全一样，软件看不出区别。

同一套 ISA 可以有很多种微架构。x86 这一套 ISA 下，历代处理器的组织方式各不相同，但都能跑同一份可执行文件。

换个角度说同一件事：**一台机器有没有乘法指令，是结构问题；乘法指令用什么方式实现，是组成问题。** 两台机器指令系统相同，只能说明它们结构相同，实现方式完全可以不同。

> [!CAUTION]
>

微体系结构不是"物理实现层"

这是本节最容易绕进去的一处。微体系结构是 **ISA 的逻辑实现**，和物理实现之间还隔着逻辑电路层。

| 层 | 回答的问题 | 例子 |
| --- | --- | --- |
| ISA | 有哪些指令、寄存器、寻址方式？ | x86-64、RISC-V |
| **微体系结构** | 用什么样的数据通路和控制器去执行这些指令？ | 几级流水线、Cache 多大、是否乱序 |
| 逻辑电路 | 这些部件用什么门电路搭？ | 加法器用超前进位还是行波进位 |
| **物理实现** | 用什么器件、什么工艺、什么版图造出来？ | 晶体管尺寸、制程 |

同一套微架构可以换用不同工艺去生产，两层关注的是两件事。

## 六、高级语言程序与机器语言程序之间的转换

### 三层语言

编程语言分成两类：**高级语言**与底层计算机结构无关；**低级语言**与运行程序的机器的底层结构密切相关，通常称为**机器级语言**——机器语言和汇编语言都属于机器级语言。

| 语言 | 特点 | 硬件能否直接执行 |
| --- | --- | --- |
| 机器语言 | 用二进制编码的机器指令，每条指令是一个 0/1 序列 | **能** |
| 汇编语言 | 机器语言的符号表示，用简短英文符号与二进制代码建立对应关系 | 不能 |
| 高级语言 | 与底层结构无关，接近人的表达习惯 | 不能 |

硬件能直接执行的**只有机器语言程序**。硬件描述语言（Verilog / VHDL）不在这张表里——它描述的是**电路**，经综合后变成电路而不是变成指令。

### 翻译程序有三类

包含自动转换程序的软件开发工具统称**语言处理系统**，其中执行转换的那个程序称为**翻译程序**：它把一种编程语言表示的程序，转换为等价的另一种编程语言程序。被翻译的称为源语言和源程序，生成的称为目标语言和目标程序。

翻译程序有三类：

| 翻译程序 | 输入 | 输出 |
| --- | --- | --- |
| **汇编程序**（汇编器 assembler） | 汇编语言源程序 | 机器语言目标程序 |
| **解释程序**（解释器 interpreter） | 源程序 | —— 按执行顺序逐条翻译成机器指令并**立即执行** |
| **编译程序**（编译器 compiler） | 高级语言源程序 | 汇编语言或机器语言目标程序 |

### 翻译与解释的分界

两者的分界不在"翻不翻译"，而在**翻译的成果留不留下来**：

|  | 编译 | 解释 |
| --- | --- | --- |
| 处理粒度 | **一次性**处理整个源程序 | **逐条**处理源程序中的语句 |
| 是否产生目标程序 | **产生**，落成文件 | **不产生** |
| 翻译与执行的关系 | 先全部译完，再执行目标程序 | 译一句立即执行一句 |
| 重复执行同一段代码 | 源程序不变就**不必再译** | 每次重复执行都要**重新翻译** |
| 执行效率 | 高 | 低（翻译开销分摊不掉） |

"把高级语言源程序转换成机器目标代码**文件**"这件事，只有编译程序做得到——解释器不留下文件，汇编器的输入不是高级语言，链接器的输入不是源程序。

汇编程序则是三者中最简单的一个，因为汇编语言的每条语句与机器语言的某条语句**一一对应**，翻译过程几乎是查表替换。汇编语言的具体语法与伪指令见 [[03_计算机组成原理_CO/instruction/assembly-basics.md|汇编语言基础]]。

### 从源程序到可执行文件

以 C 语言为例，四个阶段：

```
hello.c → [预处理 cpp] → hello.i → [编译 cc1] → hello.s → [汇编 as] → hello.o → [链接 ld] → hello
```

| 阶段 | 工具 | 输入 → 输出 | 做了什么 |
| --- | --- | --- | --- |
| 预处理 | cpp | .c → .i | 处理以 `#` 开头的命令，例如把 `#include` 后面的 .h 文件内容嵌入源程序。**输出仍是源程序文件** |
| 编译 | cc1 | .i → .s | 生成汇编语言源程序文件 |
| 汇编 | as | .s → .o | 生成**可重定位目标文件**。它是二进制文件，代码已经是机器指令，直接打开显示的是乱码 |
| 链接 | ld | .o → 可执行文件 | 把多个可重定位目标文件和标准库函数**合并**成一个**可执行目标文件** |

顺序被文件类型锁死：每一步的输出正好是下一步的输入。编译器只吃 `.i` 吐 `.s`，汇编器只吃 `.s` 吐 `.o`，链接器只吃 `.o`。把汇编排到编译前面，汇编器根本拿不到 `.s` 文件。

值得注意的是，**链接是必需的一步**，即使源程序只有一个文件——因为 `printf` 这样的库函数并不在你的 `.o` 里，它在标准库的可重定位目标模块中，要靠链接器合并进来。

## 七、程序和指令的执行过程

可执行文件生成后放在外存里。启动执行时，操作系统内核把它加载到主存，把第一条指令的地址放进 PC，随后 CPU 就开始自动循环。

一条指令的执行分四步：

| 步 | 做什么 | 涉及的部件 |
| --- | --- | --- |
| 1 | **取指令**：PC 的内容送 MAR → 地址线；控制器送出读信号；主存读出指令送数据线；MDR 接收后传送到 IR | PC → MAR → 主存 → MDR → IR |
| 2 | **指令译码**：控制器根据 IR 中指令的操作码生成控制信号，送到各执行部件 | IR → 控制器 → 各部件 |
| 3 | **取操作数并运算**：按 IR 中指定的寄存器编号选出操作数送 ALU 输入端，在 ALUop 控制下完成运算 | 通用寄存器组 → ALU |
| 4 | **写结果或访存**：运算类指令把结果写回指定寄存器并置标志位；取数/存数指令把 ALU 结果作为地址送地址线，读写主存 | ALU → 寄存器组 / 主存 |

### PC 是怎么更新的

CPU 要能自动执行下一条指令，就必须自动得到下一条指令的地址：

- **定长指令字系统**：取指令的同时把 PC 加上指令长度即可，不必等译码；
- **变长指令字系统**：指令有多长要译码之后才知道，因此要在译码后才能确定 PC 该加多少。

无论哪种，结论是一样的：**一条指令执行结束时，PC 中一定是下一条指令的地址**。转移指令的做法是在执行阶段直接改写 PC，把这个"下一条"换成别的地址。

### 定时

指令执行过程中的所有操作都有先后顺序，需要定时信号来同步。CPU 中所有操作都由**时钟信号**定时，时钟信号的宽度就是一个**时钟周期**。

一条指令的执行时间包含**一个或多个**时钟周期——这正是 CPI 这个指标存在的原因，详见 [[03_计算机组成原理_CO/overview/performance-metrics.md|计算机的性能指标]]。

## 易混淆知识点

**1. 微体系结构和物理实现是一回事吗？**

不是，中间隔着逻辑电路层。微体系结构是 **ISA 的逻辑实现**，回答"用什么样的数据通路和控制器执行这些指令"；物理实现回答"用什么器件、什么工艺造出来"。同一套微架构可以换不同工艺生产，两者关注的是两件事。

判据：**软件感知不到的、且还没落到具体电路的组织方式**，属于微体系结构。加法器用串行进位还是并行进位，是微体系结构问题；这个进位链具体用哪几种门搭，才是逻辑电路问题。

**2. 六级层次里的"微程序机器"是每台计算机都有的吗？**

不是。只有采用**微程序控制器**的 CPU 才有微指令这一级。硬布线控制器直接用组合逻辑从操作码和节拍信号译出控制信号，M1 下面就是电路，没有 M0。

层次表描述的是一种常见组织方式，不是硬性构造要求。

**3. 汇编程序、编译程序、解释程序、翻译程序是什么关系？**

**翻译程序是统称**，下辖三类：

|  | 输入 | 输出 | 一一对应？ |
| --- | --- | --- | --- |
| 汇编程序 | 汇编语言 | 机器语言 | **是**，几乎是查表替换 |
| 编译程序 | 高级语言 | 汇编语言或机器语言，**生成目标程序** | 否，一条语句可展开成多条 |
| 解释程序 | 源程序 | 逐条翻译并立即执行，**不生成目标程序** | 否 |

链接程序**不是**翻译程序：它的输入输出都是机器语言，做的是合并与符号解析，不发生语言之间的转换。

**4. "以运算器为中心"和"以存储器为中心"哪个是对的？**

看在描述什么。**冯·诺依曼机的原始特征**是以运算器为中心，I/O 与存储器之间的传送都要经运算器中转；**现代计算机**已改为以存储器为中心，I/O 可以绕过运算器直接与主存交换数据。两句话都对，对象不同。

**5. 指令和数据在存储器里能靠内容区分吗？**

不能。二者形式上完全相同，都是 0/1 串，同一段二进制既可以被译码成指令，也可以被当作数据参与运算。区分它们的是**取它的那个时刻 CPU 处在指令周期的哪个阶段**——阶段信息在控制器里，不在存储器里。

**6. 计算机体系结构和计算机组成有什么区别？**

**体系结构是程序员能看到的属性**（指令集、数据类型、存储器寻址技术、I/O 机理等，大都是抽象属性）；**组成是如何实现这些属性**，包含大量对程序员透明的硬件细节。

一台机器**有没有**乘法指令，是体系结构问题；乘法指令**怎么实现**（专用乘法器还是用加法器加移位循环若干次），是组成问题。两台机器指令系统相同，只能说明结构相同，组成方式可以完全不同。

## 本节小结

- 五大部件是**"存储程序"这一条前提的必要条件**，不必背：要存 ⇒ 存储器，要进出 ⇒ 输入/输出设备，要自动取指 ⇒ 控制器，要运算 ⇒ 运算器
- 用二进制的三个理由：**两稳态器件易制造、编码与运算规则简单、与逻辑真假天然对应**
- 指令 = 操作码 + 地址码，**地址码给的是操作数的地址**，不是操作数本身
- 指令和数据形式相同，CPU 靠**指令周期的阶段**区分：取指周期取的是指令，执行周期取的是数据
- 计算机系统 = **硬件系统 + 软件系统**；软件发挥硬件功能，软件性能又依托硬件支撑，机器好坏取决于**软硬件功能的总和**
- 系统软件 vs 应用软件的判据：**服务对象是机器本身，还是用户的某个具体任务**
- 软硬件在**逻辑功能上等价**，分界线不固定、历史上一直向上移动（固件即一例）
- 层次顺序被"**每一级只能由紧邻的下一级实现**"锁死：硬件 → 微程序机器 M0 → 传统机器 M1 → 操作系统机器 M2 → 汇编语言机器 M3 → 高级语言机器 M4
- **只有 M0 是实际机器**，其上各级都是虚拟机器；M0 本身只在微程序控制器的 CPU 上存在
- **ISA 是软硬件的分界面**，是一份让软硬件各自独立演进的契约；它规定的是"软件可见部分"
- ISA 定义"做什么"，**微体系结构定义"怎么做"且软件不可感知**；微体系结构与物理实现之间还隔着逻辑电路层
- 体系结构 = 程序员可见的属性；组成 = 这些属性如何实现
- 翻译程序是统称，含**汇编程序、编译程序、解释程序**；编译**生成**目标程序，解释**不生成**
- 源程序到可执行文件：**预处理 → 编译 → 汇编 → 链接**，顺序被文件类型锁死
- 一条指令四步：取指 → 译码 → 取数运算 → 写回/访存；**指令执行结束时 PC 中一定是下一条指令的地址**
- 一条指令的执行时间包含**一个或多个**时钟周期
- 下层的实现细节对上层**透明**
