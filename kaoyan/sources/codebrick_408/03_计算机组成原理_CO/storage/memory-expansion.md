# 主存和 CPU 之间的连接

## 大纲定位

**三（四）3　主存和 CPU 之间的连接**

要求：掌握位扩展、字扩展与字位同时扩展的方法，能确定所需芯片数量、地址线与数据线的连接方式、片选信号的产生逻辑，并写出各芯片对应的地址范围。

芯片本身的内部结构（存储阵列、地址复用、刷新）见 [[03_计算机组成原理_CO/storage/sram-dram.md|SRAM 与 DRAM]]；由芯片组装成内存条并接入存储器总线见 [DRAM 芯片与内存条](https://www.codebrick.tech/co-full/posts/storage/dram-memory-module.html)。

## 知识框架

本节回答四个问题：

- 单个存储芯片装不下所需的主存，怎么用多片拼出来？
- 拼的时候，地址线、数据线、控制线各自怎么接？
- 多片芯片之间，靠什么决定这次访问的是哪一片？
- 为什么片选信号一定用**高位**地址产生，用低位会怎样？

## 一、芯片规格的读法

存储芯片的规格写作 c×b：**c 个存储单元，每个单元 b 位**。

例如 4K×4 表示 4096 个单元、每单元 4 位，总容量 4096×4=16 Kbit =2 KB。

> [!WARNING]
>

c 是单元数，不是字节数

这是本节最容易出错的地方。4K×4 的芯片：

- 容量是 **2 KB**（按字节算）
- 但 c=4K=4096 **个单元**，片内地址需要 log2⁡4096=12 位

若误把 c 当成 2 KB 去取对数，会得到 11 位——**片内地址少一位，片选逻辑和地址范围会全盘错位**。

判断依据：**片内地址的位数由"单元数"决定，与每个单元多少位无关**。芯片有多少根地址引脚，取决于它要区分多少个单元。

一个存储系统的需求同样用这两个量描述：主存共 M 个单元、每单元 w 位。扩展要做的，就是用规格为 c×b 的芯片凑出 M×w。

## 二、位扩展：把字长补够

**当 b<w**，即单片的位数不够，需要位扩展。

**做法**：多片**并联**——地址线、控制线全部共享，数据线**各接一段**。

**例**：用 4K×4 的芯片构成 4K×8 的存储器。片数=wb=84=2 片

| 连接 | 方式 |
| --- | --- |
| 地址线 | 两片**完全相同**，都接 A11∼A0 |
| 数据线 | 片 0 接 D3∼D0，片 1 接 D7∼D4 |
| 片选 CS― | 两片**接同一个信号**，同时被选中 |

关键在于理解这个结构的含义：**同一个地址会同时落到所有片上，每片各出一部分位，拼成一个完整的字。** 因为所有片总是一起工作，位扩展**不需要片选译码**。

图 7.10　DRAM 芯片的扩展（袁春风《计算机组成与系统结构（第 3 版）》p216）

教材这张图是 8 片 16M×8 位扩展成 64 位：同一组行列地址 (i,j) 广播到全部 8 片，DRAM0 出第 0∼7 位、DRAM1 出第 8∼15 位，直到 DRAM7 出第 56∼63 位，由存储控制器拼成一个 64 位的双字。

> [!TIP]
>

位扩展与数据对齐的关系

上图揭示了一件事：这样的结构一次只能读出**地址连续且对齐的 8 个字节**——第 0∼7 单元、第 8∼15 单元、……、第 8k∼8k+7 单元。

所以若一个 4 字节的 int 起始地址为 6（占第 6、7、8、9 单元），它**跨越了两组**，必须访问两次存储器；若起始地址是 4 的倍数，一次即可。

**这就是数据需要对齐的硬件原因**——它不是编译器的偏好，而是主存物理组织方式的直接后果。详见 [[03_计算机组成原理_CO/data-repr/data-alignment.md|数据对齐与大小端]]。

## 三、字扩展：把容量补够

**当 c<M**，即单片的单元数不够，需要字扩展。

**做法**：低位地址各片共享（片内寻址），**高位地址经译码器产生片选信号**，每次只选中一片。

**例**：用 4K×8 的芯片构成 16K×8 的存储器。片数=Mc=16K4K=4 片

- 片内地址 log2⁡4K=12 位，各片都接 A11∼A0
- 高 2 位 A13A12 送 2-4 译码器，四个输出分别接四片的 CS―
- 数据线各片都接 D7∼D0（位数已够，无须扩展）

| A13A12 | 选中 | 地址范围 |
| --- | --- | --- |
| 00 | 芯片 0 | `0000H ~ 0FFFH` |
| 01 | 芯片 1 | `1000H ~ 1FFFH` |
| 10 | 芯片 2 | `2000H ~ 2FFFH` |
| 11 | 芯片 3 | `3000H ~ 3FFFH` |

**位扩展与字扩展的根本差别**：位扩展是"所有片一起出力，各出一部分位"；字扩展是"每次只有一片工作，其余不选中"。前者不需要译码，后者必须译码。

## 四、字位同时扩展

b<w 且 c<M 时两者都要做。**先按位扩展分组，再按字扩展在组间译码**。

**例**：用 4K×4 的芯片构成 16K×8 的存储器。每组片数=84=2,组数=16K4K=4,总片数=2×4=8

- **组内 2 片**：地址线相同、数据线分高低 4 位、**片选相同**
- **组间 4 组**：高 2 位地址经 2-4 译码器产生 4 个片选，每个片选同时接到该组的 2 片上总片数=wb⏟位扩展倍数×Mc⏟字扩展倍数

## 五、地址线的分配

设芯片单元数为 c、存储系统总单元数为 M，则地址线的划分是确定的：[ 片选译码⏟log2⁡(M/c) 位，高位  |  片内地址⏟log2⁡c 位，低位 ]

- **低 log2⁡c 位**：直接接各芯片的地址引脚，用于在片内选单元
- **高 log2⁡(M/c) 位**：送译码器，用于选片

## 六、控制信号的连接

画主存与 CPU 的连接图时，只画地址线和数据线是不完整的，下面几根控制信号必须交代：

| 信号 | 方向 | 接到哪里 | 作用 |
| --- | --- | --- | --- |
| MREQ―（访存请求） | CPU → 存储器 | **译码器的使能端** | 只有 CPU 确实要访存时，译码器才输出片选 |
| R/W― | CPU → 各芯片 | 读写控制端 | 决定本次是读还是写 |
| OE―（输出使能） | CPU → 各芯片 | 输出三态门 | 读操作时打开数据输出，避免总线冲突 |
| WE―（写使能） | CPU → 各芯片 | 写控制端 | 写操作时有效 |

> [!TIP]
>

译码器的使能端为什么要接访存信号

地址总线上任何时刻都有电平——CPU 执行不访存的指令时，地址线上残留的也是某个值。若译码器一直使能，它就会持续输出某个片选，导致 CPU 并未访存却选中了某片。

把 MREQ― 接到使能端，等于给译码加了一道"确实要访存"的闸门。

如果还要把某段地址空间留给 I/O 或其他芯片，可以在使能端再串一个由更高位地址构成的门电路（例如仅当 A15A14― A13― 有效时才使能）。

## 七、译码方式

| 方式 | 做法 | 特点 |
| --- | --- | --- |
| **全译码** | 高位地址**全部**参与译码 | 每个地址唯一对应一个单元，**无地址重叠**；译码电路较复杂 |
| **部分译码** | 只用部分高位地址译码，其余悬空 | 电路简单，但**存在地址重叠**（多个地址对应同一物理单元） |
| **线选法** | 用单根高位地址直接作片选（低电平有效） | 最简单，但浪费地址空间，且任何时刻只能选中一片 |

地址重叠的成因：悬空的那几位取任何值都不影响选片结果，于是若干个不同的地址落到了同一个物理单元上。

## 八、为什么片选用高位地址

这条规则背起来容易，但**反过来会怎样**才是它的实质。

| 接法 | 结果 |
| --- | --- |
| **高位地址接译码器**（常规做法） | 同一片内的地址**连续**。片 0 占 `0000H~0FFFH`，片 1 占 `1000H~1FFFH`……地址范围是整齐的区间 |
| 低位地址接译码器 | 相邻地址落在**不同芯片**上：地址 0 在片 0、地址 1 在片 1、地址 2 在片 2……每片内部的地址不再连续 |

后一种接法并不是错误，它是另一种有意的设计——**交叉编址**。两者的取舍在于目标不同：

|  | 连续编址（高位选片） | 交叉编址（低位选片） |
| --- | --- | --- |
| 模块号取自 | 地址**高位** | 地址**低位** |
| 片内地址 | 连续 | 不连续 |
| 目的 | 地址空间整齐，便于分区管理 | **并行访问，提高带宽** |
| 连续访问时 | 集中在一片内，无法并行 | 依次落到不同模块，可以流水重叠 |

交叉编址的详细分析见 [[03_计算机组成原理_CO/storage/memory-interleave.md|多体交叉存储器]]。

## 例题

**例**：某 8 位机主存地址 16 位（A15∼A0），按字节编址。现要在 `8000H ~ 9FFFH` 这段地址上用 2K×8 的 RAM 芯片构建存储区。求该区域容量、片选逻辑与各芯片的地址范围。

**解**：

**第一步，求容量。**9FFFH−8000H+1=2000H=213 B=8 KB

**第二步，找出恒定不变的高位——它就是片选条件。** 把区间两端写成二进制对齐比较：

```
8000H = 100 0 0000 0000 0000
9FFFH = 100 1 1111 1111 1111
        ↑↑↑
      A15 A14 A13 恒为 100，其余各位跑遍全 0 到全 1
```

区间内恒有 A15=1, A14=0, A13=0，故片选（低电平有效）为CS―=A15⋅A14―⋅A13――

**第三步，确定片数与地址线分配。**片数=8 KB2 KB=4 片

- 片内地址 log2⁡2K=11 位，接 A10∼A0
- 剩下的 A12A11 送 2-4 译码器区分四片
- 译码器使能端接第二步得到的 A15A14― A13―

| 芯片 | A12A11 | 地址范围 |
| --- | --- | --- |
| 0 | 00 | `8000H ~ 87FFH` |
| 1 | 01 | `8800H ~ 8FFFH` |
| 2 | 10 | `9000H ~ 97FFH` |
| 3 | 11 | `9800H ~ 9FFFH` |

这三步的顺序是通用的：**容量由区间长度定 → 恒定高位定片选 → 变化位从高到低依次分给译码器和片内地址**。

## 易混淆知识点

**1. 位扩展既然"所有片同时选中"，那还能说某个地址落在哪一片吗？**

要分清是在哪一层讨论。

"位扩展不需片选译码"说的是**字长这一层**——各片同时出力，各出几位，凑成一个字。

但如果上层按**字节**编址，而每片一次只出 1 字节，那么"某个字节地址落在哪一片"仍然是有答案的：**字节地址的低 log2⁡(片数) 位就是片号**。此时它在效果上等同于按字节交叉的多体结构。

两种说法描述的是同一个物理连接，只是观察的粒度不同。

**2. 全译码一定比部分译码好吗？**

不是好坏问题，是取舍。全译码无地址重叠、地址空间利用充分，但译码电路更复杂；部分译码电路简单、成本低，代价是地址重叠——在地址空间远大于实际需求的小系统里，重叠并不构成实际问题。

**3. 扩展后主存的存取周期会变吗？**

不会。扩展只是把多片并联或分区，**存取周期由单个芯片的特性决定**，与片数无关。想缩短有效存取时间要靠别的手段（如多体交叉、Cache），不是靠增加芯片数量。

## 本节小结

- 芯片规格 c×b 中，**c 是单元数不是字节数**；片内地址位数 =log2⁡c
- **位扩展**补字长：各片地址线共享、数据线分段、片选相同，**不需要译码**
- **字扩展**补容量：低位地址片内共享，**高位地址经译码器产生片选**，每次只选一片
- 字位同时扩展：先位扩展分组，再字扩展译码；**总片数 =wb×Mc**
- 地址线划分：低 log2⁡c 位接片内，高 log2⁡(M/c) 位接译码器
- 译码器使能端要接 MREQ―，防止 CPU 未访存时误选片
- 全译码无地址重叠；部分译码电路简单但有重叠；线选法最简单也最浪费
- **高位选片使片内地址连续**；低位选片则退化为交叉编址，目标是并行带宽而非连续性
- 位扩展的物理结构决定了一次只能读出对齐的若干字节——这是**数据需要对齐的硬件原因**
- 由地址范围反求连接：区间长度定容量 → 恒定高位定片选 → 变化位分给译码器与片内地址
