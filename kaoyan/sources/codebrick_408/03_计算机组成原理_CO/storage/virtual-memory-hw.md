# 虚拟存储器

## 大纲定位

**三（七）虚拟存储器**

- 虚拟存储器的基本概念
- 页式虚拟存储器 —— 基本原理，页表，地址转换，TLB（快表）
- 段式虚拟存储器的基本原理
- 段页式虚拟存储器的基本原理

**注意四条之间的深度差**：第 2 条列出了四个子项，要求掌握到能完成地址转换的程度；第 3、4 条只有「基本原理」四字，没有子项，知道结构与转换步骤即可。

## 知识框架

本节回答五个问题：

- 主存明明装不下所有程序，为什么程序还能正常运行？
- 虚拟地址怎么变成物理地址？谁来做这件事？
- 页表放在主存里，那每访问一次数据岂不是要访问两次主存？
- TLB、页表、Cache 三者同时存在时，一次访存到底走了什么流程？
- 段式与页式的本质差别在哪？

## 一、虚拟存储器的基本概念

### 要解决的三个问题

| 问题 | 虚拟存储器的回答 |
| --- | --- |
| 程序比主存大怎么办 | 只把当前用到的部分放主存，其余留在磁盘，用到时再调入 |
| 多个程序同时运行，如何互不干扰 | 每个进程有各自独立的虚拟地址空间，彼此看不见 |
| 程序编译时不知道会被装到哪，地址怎么定 | 程序一律使用虚拟地址，装到哪由硬件翻译时决定 |

于是形成了这样的分工：**程序使用虚拟地址（逻辑地址），硬件在访存时把它翻译成物理地址。** 主存相当于磁盘的 Cache——两者是同一种"用小而快的存储器缓存大而慢的存储器"的思想，只是层次不同。

### 与 Cache 的类比

虚拟存储器和 Cache 的机制高度同构，对照着记效率最高：

|  | Cache ↔ 主存 | 主存 ↔ 磁盘（虚存） |
| --- | --- | --- |
| 传输单位 | 块（行） | **页** |
| 未命中叫什么 | 缺失（miss） | **缺页** |
| 未命中代价 | 几十~上百个时钟周期 | 约 105 个时钟周期 |
| 由谁处理未命中 | **硬件**自动完成 | **操作系统**介入处理 |
| 写策略 | 写回或写直达 | **一律写回**（磁盘太慢） |
| 映射方式 | 直接/组相联/全相联 | 相当于**全相联**（任一虚页可放任一页框） |

> [!TIP]
>

为什么虚存必须用全相联和写回

两条都源于同一个原因——**缺页代价太大**（比 Cache 缺失高三个数量级）。

既然一次缺页要花约 105 个周期，就值得用最灵活的映射把缺页率压到最低，也值得多花时间做查找。同理，写直达要求每次写都同步到磁盘，代价完全无法接受，所以只能写回。

## 二、页式虚拟存储器

### 地址的划分

虚拟地址空间和物理地址空间都按**固定大小**切成页：虚拟地址=[ 虚页号 VPN⏟高位  |  页内地址⏟低位 ]物理地址=[ 实页号（页框号）⏟高位  |  页内地址⏟低位 ]

页内地址的位数由页大小决定：页大小 2k 字节，页内地址就是 k 位。

> [!WARNING]
>

翻译只换高位段

地址转换**只把虚页号换成实页号，页内地址原样保留**——位数和取值都不变。

由此得到一条常用推论：**实页号的位数由物理地址位数决定，与虚拟地址位数无关**。虚拟地址 32 位、物理地址 24 位是完全正常的（虚拟空间可以比物理空间大得多，这正是虚存的意义），此时虚页号 20 位而实页号只有 12 位。

**位区间的写法**：32 位虚拟地址、4 KB 页时页内地址=VA[11:0],虚页号=VA[31:12]

### 页表与页表项

**页表**是虚页号到实页号的映射表，存放在主存中，由操作系统维护，**每个进程一张**。页表在主存中的首地址记录在**页表基址寄存器**中。

图 7.40　主存中的页表示例（袁春风《计算机组成与系统结构（第 3 版）》p256）

页表项的主要字段：

| 字段 | 别名 | 作用 |
| --- | --- | --- |
| 存放位置 | 实页号 / 页框号 | 装入位为 1 时指向主存页框；为 0 时给出磁盘上的位置 |
| **装入位** | 有效位、存在位 | 该页是否已调入主存 |
| **修改位** | 脏位 | 该页是否被写过，换出时据此决定要不要写回磁盘 |
| 使用位 | 访问位、替换控制位 | 配合替换策略（如 LRU、FIFO） |
| 访问权限位 | 保护位 | 可读 / 可写 / 可执行 |
| 禁止缓存位 |  | 该页是否允许装入 Cache，用于保证数据一致性 |

按装入位和存放位置，虚页分三种状态：

| 状态 | 装入位 | 存放位置 |
| --- | --- | --- |
| 已缓存页 | 1 | 主存页框号 |
| 未缓存页 | 0 | 磁盘地址（已分配空间，尚未调入） |
| 未分配页 | 0 | 空 |

### 地址转换过程

图 7.42　分页式虚存的地址转换（袁春风《计算机组成与系统结构（第 3 版）》p259）

四步：

- 页表基址寄存器给出页表首址
- 以**虚页号为下标**定位到对应的页表项
- 检查装入位；为 1 则取出实页号
- 实页号与页内地址**拼接**成物理地址物理地址=实页号 ‖ 页内地址

这里的 ‖ 是**位串拼接**而非算术加。等价的算术写法是 实页号×页大小+页内地址——因为页内地址的位数正好等于页大小的位数，两种写法结果相同。

### 地址转换由谁完成

地址转换由 **MMU**（Memory Management Unit，存储管理部件）完成，TLB 是它的一部分。

| 检查项 | 由谁检查 | 不满足的后果 |
| --- | --- | --- |
| 装入位 =0 | MMU | 触发**缺页异常**，转操作系统处理 |
| 访问权限不符 | MMU | 触发**访问越权异常** |
| Cache 是否命中 | Cache 控制器 | 在 MMU 交出物理地址**之后**才登场 |

顺序是固定的：**先翻译、后访存**。MMU 把虚拟地址翻成物理地址（这期间可能触发 TLB 缺失、缺页、越权），拿到物理地址之后 Cache 才开始查找。

### 缺页的处理

缺页是**异常（exception）**而非中断——它由当前指令的访存动作引发，是**同步**的。习惯上也称"缺页中断"，但按异常与中断的定义，它属于异常。

处理过程：

- MMU 发现装入位为 0，触发缺页异常
- 操作系统的缺页处理程序按存放位置字段从磁盘读出该页
- 找一个空闲页框存放；若无空闲页框，则选一页换出（**根据修改位决定是否写回磁盘**）
- 更新页表
- **返回发生缺页的那条指令，重新执行**

> [!WARNING]
>

返回点是原指令本身

这一条有可计数的后果：由于该指令要重新执行，**同一次访存会把地址转换的过程走两遍**——第一遍触发缺页，第二遍才成功。统计访存次数或 TLB 查询次数时，这一次容易被漏掉。

对照 [[03_计算机组成原理_CO/cpu/exception-interrupt.md|异常和中断处理]]：缺页属于**故障（fault）**类异常，故障的返回点就是当前指令。

### 多级页表

页表的项数由虚拟地址空间大小决定，可能非常大。以 32 位虚拟地址、4 KB 页为例：页表项数=232212=220,每项 4 B⇒页表大小=4 MB

而这是**每个进程**都要有一张的。全部常驻主存显然不合适。

**两级页表**把虚页号再切成两段：[ 页目录索引⏟一级  |  页表索引⏟二级  |  页内地址⏟不变 ]

转换要走两跳：页目录基址寄存器 → 页目录项（给出二级页表的基址）→ 页表项（给出实页号）。

代价是**访存次数增加**：TLB 缺失时，两级页表要访问 2 次主存才能拿到实页号，再加 1 次取数据。收益是二级页表可以按需建立，没有用到的地址区间不必为它分配页表。

64 位系统通常采用四级页表。

## 三、TLB（快表）

### 为什么需要

页表在主存中，这意味着**一次访存要变成两次**：先访存查页表，再访存取数据。这个代价无法接受。

解决办法与 Cache 完全相同——**把最近用过的页表项缓存起来**。这个缓存就是 **TLB**（Translation Lookaside Buffer，快表），用 SRAM 实现，容量很小（几十到上千项）。TLB 之于页表，正如 Cache 之于主存

### TLB 的映射方式

TLB 项数少，**常采用全相联**（查找时并行比较所有项），也可以采用组相联。

采用组相联时，字段切分方式与 Cache 同构，只是**被切的对象是虚页号**：VPN=[ TLB 标记⏟高位  |  TLB 组号⏟log2⁡(TLB 组数) 位 ]

其中 TLB 组数 = TLB 项数 ÷ 路数。

> [!WARNING]
>

切的是虚页号，不是虚拟地址

TLB 组号取自**虚页号的低位**，不是虚拟地址的低位。虚拟地址的低位是页内地址，与 TLB 无关——TLB 缓存的是"虚页号 → 实页号"的映射，页内地址根本不参与。

**例**：虚拟地址 30 位、页大小 4 KB、TLB 共 16 项 2 路组相联。

- 页内地址 = VA[11:0]，虚页号 = VA[29:12]，共 18 位
- TLB 组数 =16÷2=8，故 TLB 组号 3 位 = VA[14:12]
- TLB 标记 =18−3=15 位 = VA[29:15]

### TLB 表项的构成

TLB 项是"带标记的页表项副本"，与页表项并不完全相同：

| 字段 | 宽度由谁决定 |
| --- | --- |
| TLB 标记 | 虚拟地址位数（虚页号位数减去组号位数） |
| 实页号 | **物理**地址位数 |
| 有效位 / 脏位 / 替换算法位 | 与地址位数无关 |

由此可知：虚拟地址位数变化时，**只有标记字段的宽度跟着变**，实页号和控制位都不受影响。

TLB 装满后同样需要替换，常用 LRU。**命中时也要更新最近使用记录**，否则替换决策会出错。

## 四、TLB、页表与 Cache 的联合访问

图 7.43　TLB 和 cache 的访问过程（袁春风《计算机组成与系统结构（第 3 版）》p260）

图中三层俱全：上部是主存中的页目录与页表，中部是 TLB（虚页号切成标记与组索引，两路并行比较后经多路选择器输出实页号），下部是 Cache（物理地址切成标记、组索引与块内地址）。

注意**页内地址那 12 位自始至终没有进入 TLB**，它直接旁路到物理地址的低位——这正是前面"翻译只换高位"的图示。

### 完整流程
虚拟地址→查 TLB→{命中→得实页号缺失→查页表→{装入位=1→得实页号，回填 TLB装入位=0→缺页异常→OS 调页→重执行

拿到物理地址后才轮到 Cache：命中则直接返回数据，缺失则访问主存并装入 Cache。

### 八种组合中有三种不可能

TLB、页表、Cache 三者各有命中与否，共 8 种组合，其中 3 种在逻辑上不可能出现：

| TLB | 页表 | Cache | 可能 | 说明 |
| --- | --- | --- | --- | --- |
| 命中 | 命中 | 命中 | ✓ | 最快路径 |
| 命中 | 命中 | 缺失 | ✓ | 需访问主存取数据 |
| 命中 | 缺失 | 命中 | **✗** | 见判据一 |
| 命中 | 缺失 | 缺失 | **✗** | 见判据一 |
| 缺失 | 命中 | 命中 | ✓ | 查页表得地址，数据恰在 Cache 中 |
| 缺失 | 命中 | 缺失 | ✓ | 查页表并访问主存 |
| 缺失 | 缺失 | 命中 | **✗** | 见判据二 |
| 缺失 | 缺失 | 缺失 | ✓ | 缺页，最慢路径 |

> [!TIP]
>

两条判据

**判据一：TLB 命中 ⇒ 该页必在主存。** TLB 项是页表项的副本，能在 TLB 里命中，说明这一项曾经有效。因此 "TLB 命中 + 页表缺失" 自相矛盾。

这条判据依赖一个前提：**操作系统换出某页时，必须同步让对应的 TLB 项失效**。否则 TLB 里会残留已失效的映射，判据就被破坏了。

**判据二：页不在主存 ⇒ Cache 不可能命中。** Cache 缓存的是主存内容，主存里都没有的东西，Cache 里不可能有。

## 五、段式虚拟存储器

页式按**固定大小**等分地址空间，段式则按**程序的逻辑结构**划分成长度不等的段——代码段、数据段、栈段等。

虚拟地址是**二维**的：[ 段号⏟  |  段内地址⏟ ]

图 7.45　分段式虚存的地址转换（袁春风《计算机组成与系统结构（第 3 版）》p263）

转换过程：段表基址寄存器 → 加段号定位到段表项 → 取出**段首址** → 与段内地址**相加**得物理地址。

段表项的关键字段：

| 字段 | 作用 |
| --- | --- |
| 段首址（段基址） | 该段在主存中的起始地址 |
| **段长** | 该段的长度 |
| 装入位 | 该段是否已调入主存 |

> [!TIP]
>

段长是段式在硬件上的实质增量

段是**变长**的，所以必须检查「段内地址 < 段长」，越界则触发异常。

页式不需要这个检查——页是定长的，页内地址的**位数**天然就限死了它的取值范围，硬件上不可能越界。

另一处差别随之而来：段式的物理地址靠**相加**而非拼接，因为段首址不必对齐到 2 的幂边界。

## 六、段页式虚拟存储器

先分段、段内再分页。虚拟地址切成**三段**：[ 段号⏟  |  段内页号⏟  |  页内地址⏟ ]

转换要查两张表：

- 用**段号**查段表，取出的是**该段页表的基址**（注意不是段基址）
- 用**段内页号**查该段的页表，取出实页号
- 实页号与页内地址拼接成物理地址

因此**无 TLB 时，一次访存需要 3 次主存访问**：查段表 1 次、查页表 1 次、取数据 1 次。

段页式兼有两者的性质：**段对程序员可见**（保留了逻辑划分与共享保护的便利），**页对程序员透明**（消除了外碎片）。

### 三者对比

|  | 页式 | 段式 | 段页式 |
| --- | --- | --- | --- |
| 划分依据 | 等长，硬件决定 | 变长，程序逻辑决定 | 先分段，段内分页 |
| 虚拟地址切几段 | 2 | 2 | 3 |
| 表项关键字段 | 实页号 | 段首址 + 段长 | 段表存页表基址；页表存实页号 |
| 地址合成方式 | 拼接 | 相加，需越界检查 | 拼接 |
| 无 TLB 时访存次数 | 2 | 2 | **3** |
| 对程序员 | 透明 | **不透明** | 段不透明、页透明 |
| 碎片 | 内碎片 | 外碎片 | 内碎片 |

段的共享与保护策略、外碎片的紧凑、页面置换算法属于操作系统的内容，本节不展开。

## 例题

**例**：某系统虚拟地址 32 位、物理地址 24 位、页大小 4 KB。页表部分内容如下（装入位为 1 才有效）。求虚拟地址 `0008 2840H` 对应的物理地址。

| 虚页号（十进制） | 装入位 | 实页号 |
| --- | --- | --- |
| 128 | 1 | 0x00A |
| 129 | 0 | — |
| **130** | 1 | **0x018** |
| 131 | 1 | 0x0C3 |

**解**：

**第一步，定各字段位数。** 页大小 4 KB ⇒ 页内地址 log2⁡4096=12 位。

- 虚页号 =32−12=20 位 = VA[31:12]
- 页内地址 =12 位 = VA[11:0]
- 实页号 =24−12=12 位（由**物理**地址位数决定）

**第二步，切出字段的值。** 十六进制下每位对应 4 个二进制位，低 3 位十六进制正好是 12 位页内地址：0008 2840H⇒虚页号=0x00082,页内地址=0x840

**第三步，查页表。** 页表的虚页号列按十进制编号，需先换算：0x82=8×16+2=130

查第 130 项，装入位 =1，实页号 = `0x018`。

**第四步，拼接。**PA=0x018⏟12 位实页号 ‖ 0x840⏟12 位页内地址=0x018840

算术验算：0x018=24，24×4096+0x840=98304+2112=100416=0x18840 ✓

## 易混淆知识点

**1. 虚拟地址位数一定大于物理地址位数吗？**

不一定，两者相互独立。虚拟地址空间大于物理空间是常见情形（这正是"用磁盘扩充主存"的意义），但也有物理地址位数更大的系统（如 32 位虚拟地址配 36 位物理地址的物理地址扩展）。做题时**两个位数分别读题给条件**，不要相互推导。

不变的只有一条：**页内地址位数由页大小决定，虚实两侧一致**。

**2. 缺页和 Cache 缺失有什么本质区别？**

除了代价相差三个数量级，最关键的区别是**由谁处理**：Cache 缺失由**硬件**自动完成，对软件完全透明；缺页必须由**操作系统**介入（要访问磁盘、要更新页表、可能要选择换出页面），因而必须以异常的形式陷入内核。

这也解释了为什么缺页要用异常机制而 Cache 缺失不用。

**3. 页式虚拟存储器的页表放在哪里？TLB 呢？**

页表在**主存**中（本身也占用物理内存，属于进程的内核空间部分）；TLB 在 **CPU 内部**，用 SRAM 实现。

正因为页表在主存，才需要 TLB 来避免"访存两次"。

**4. 段页式为什么不能只查一次表？**

因为段表项存放的是**该段页表的基址**，而不是最终的物理地址。拿到页表基址后，还必须再用段内页号查一次页表才能得到实页号。两级表的信息是分开存放的，缺一步都拿不到最终地址。

## 本节小结

- 虚拟存储器解决三个问题：主存容量不足、多进程隔离、程序的地址无关性
- 主存之于磁盘，正如 Cache 之于主存；但缺页由**操作系统**处理，Cache 缺失由**硬件**处理
- 虚存相当于**全相联**映射且**一律写回**，两者都源于缺页代价极高
- 地址转换只换高位段：物理地址=实页号‖页内地址，**页内地址位数与取值均不变**
- 实页号位数由**物理**地址位数决定，与虚拟地址位数无关，两者可以不等
- 页表项含装入位、修改位、使用位、访问权限位；页表在主存，每进程一张
- 缺页是**同步异常**中的**故障**，处理后**重新执行原指令**
- 多级页表用于压缩页表占用，代价是 TLB 缺失时访存次数增加
- TLB 是页表的 Cache，常用全相联；组相联时切的是**虚页号**而非虚拟地址
- TLB 项 = 标记 + 实页号 + 控制位，虚拟地址加宽只影响标记宽度
- 两条判据：**TLB 命中 ⇒ 页必在主存**；**页不在主存 ⇒ Cache 不可能命中**
- 段式：段表项 = 段首址 + 段长，地址靠**相加**且需**越界检查**
- 段页式：三段切分，段表存**页表基址**，无 TLB 时访存 **3** 次
