# 层次化存储器的基本结构

## 大纲定位

**三（二）层次化存储器的基本结构**

要求：理解层次结构要解决的矛盾及其依据，说清 Cache–主存、主存–辅存两个层次各自解决什么问题、由谁管理、传输单位与映射方式有何不同，并能判断程序的局部性。

存储器的分类见 [[03_计算机组成原理_CO/storage/memory-overview.md|存储器的分类]]；两个层次的细节分别见 [[03_计算机组成原理_CO/storage/cache-concept.md|Cache 的基本原理]] 与 [[03_计算机组成原理_CO/storage/virtual-memory-hw.md|虚拟存储器]]。

## 知识框架

本节回答五个问题：

- 存储系统要同时满足哪几个互相冲突的要求？
- 层次结构凭什么能同时逼近这几个要求？
- 这条阶梯上有四级器件，为什么"缓存关系"只算两组？
- 两个层次的差别，能不能用同一套语言描述？
- 块大小、页大小这些参数为什么不是越大越好？

## 一、三重矛盾

计算机对存储系统有三个同时提出、却互相冲突的要求：速度快容量大成本低

没有任何**单一**存储技术能同时满足：

| 技术 | 快 | 大 | 便宜 |
| --- | --- | --- | --- |
| SRAM | ✓ | ✗ | ✗ |
| DRAM | 中 | 中 | 中 |
| 磁盘 | ✗ | ✓ | ✓ |

层次结构的解法是：**把它们叠起来用**，让 CPU"看到"的是一个速度接近最快层、容量接近最大层、每位成本接近最低层的存储系统。

这个方案能成立，靠的是一个前提——**程序的局部性原理**。

## 二、局部性原理

| 类型 | 含义 | 典型来源 |
| --- | --- | --- |
| **时间局部性** | 刚被访问的单元，近期很可能**再次**被访问 | 循环体、计数变量 |
| **空间局部性** | 刚被访问的单元，其**相邻**单元近期也很可能被访问 | 顺序执行的指令、数组元素 |

局部性意味着：**任一时刻，程序实际活跃的地址范围（工作集）远小于它的地址空间**。因此只需把工作集放进高速小容量层，就能让绝大多数访问都在这一层完成。

### 怎么判断一段程序的局部性

两种局部性的判据不同，要**分开判断、分别给出理由**：

| 判什么 | 依据 |
| --- | --- |
| **时间**局部性 | 数同一个单元被访问了几次。≥2 次才有 |
| **空间**局部性 | 看地址是否**顺序推进**。连续访问有；大跨步或随机访问没有 |

三类典型情形：

| 访问模式 | 时间局部性 | 空间局部性 |
| --- | --- | --- |
| 顺序遍历一遍（每个元素只碰一次） | 无 | **有** |
| 反复遍历同一小块数据 | **有** | **有** |
| 大跨步 / 随机访问 | 无 | 无 |

> [!TIP]
>

第一行最值得体会

"顺序遍历一遍"是**没有时间局部性的**——每个元素读一次就再也不碰了。但它仍然有很好的空间局部性，因而命中率依然可以很高。

这说明两种局部性是**独立**的，笼统地说"局部性好"或"局部性差"没有信息量。典型的反例是按列遍历行优先存储的二维数组：每次跨过一整行，调入的整块里只用了一个元素，空间局部性被完全浪费。

## 三、层次的整体形状

按器件从上到下排列，存储系统是一条阶梯：

三个指标沿这条阶梯**同向变化**：自上而下，**速度递减、容量递增、每位价格递减**。正因为三者的排序完全一致，任何一级都不能省——去掉上面的会变慢，去掉下面的会装不下。

> [!TIP]
>

阶梯有四级，缓存关系却只有两组

**寄存器不构成一个缓存层次。** 判据是有没有"命中与否"的判断：Cache 和主存都要先查"要的东西在不在本级"，不在才向下一级要；而寄存器由指令**显式指名**（`add R1, R2` 里的 R1、R2 是写死在指令中的），由编译器分配，不存在查找、命中、替换这一套机制。

所以下面只讨论 **Cache–主存**与**主存–辅存**这两组。

## 四、两个层次

整个存储体系由两个独立的"缓存"层次串联而成。

### Cache–主存层次

| 项目 | 内容 |
| --- | --- |
| 解决的问题 | **CPU 与主存的速度差距** |
| 上层 / 下层 | Cache（SRAM）／ 主存（DRAM） |
| 管理者 | **硬件**自动管理，对所有软件透明 |
| 传输单位 | **块**（通常 64 B） |
| 映射方式 | 直接 / 组相联为主 |
| 未命中处理 | 硬件自动从主存调入 |

### 主存–辅存层次

| 项目 | 内容 |
| --- | --- |
| 解决的问题 | **主存的容量不足** |
| 上层 / 下层 | 主存（DRAM）／ 辅存（磁盘、SSD） |
| 管理者 | **操作系统**管理，硬件提供支持（MMU、TLB） |
| 传输单位 | **页**（通常 4 KB） |
| 映射方式 | **全相联** |
| 未命中处理 | 触发**缺页异常**，由 OS 从磁盘调入 |

### 统一对照

| 对比项 | Cache–主存 | 主存–辅存 |
| --- | --- | --- |
| 上下层速度比 | 约 10:1 | 约 105:1 |
| 传输单位 | 块（64 B） | 页（4 KB） |
| **映射方式** | 直接 / 组相联 | **全相联** |
| **管理者** | **硬件** | **操作系统** |
| 替换算法 | 硬件实现的 LRU 等 | 软件实现的近似 LRU |
| 写策略 | 写直达或写回 | **一律写回** |
| 未命中代价 | 几十~上百个时钟周期 | 约 105 个时钟周期 |
| 对程序员 | 完全透明 | 呈现为虚拟地址空间 |

> [!TIP]
>

三处差别都源自同一个原因

表中加粗的三行——映射方式、管理者、写策略——**全部由"未命中代价相差三个数量级"决定**：

- 代价高 ⇒ 值得用最灵活的**全相联**把缺失率压到最低，也值得花时间查找
- 代价高 ⇒ 值得让**软件**介入做精细决策，多花几百个周期无所谓
- 代价高 ⇒ 写直达（每次写都同步到磁盘）完全不可接受，只能**写回**

反过来，Cache 缺失只有几十个周期，用软件处理的开销本身就超过了缺失代价，因此只能做进硬件；映射方式也必须选查找快的直接或组相联。

**两个层次遵循完全相同的原理，差别只在参数规模。**

## 五、平均访问时间

把两个层次串联起来分析。

**Cache–主存级**（暂不考虑缺页）：t1=Hc⋅tc+(1−Hc)⋅tm

**再计入缺页**：t2=Hm⋅t1+(1−Hm)⋅td

其中 Hc 为 Cache 命中率，Hm 为主存命中率（不缺页的概率），td 为磁盘访问时间。

上式的 t1 用的是**同时访问**模型。若条件描述的是"先访 Cache、未命中再访主存"，应换成 t1=tc+(1−Hc)tm。两种模型的判据见 [[03_计算机组成原理_CO/storage/cache-concept.md|Cache 的基本原理]]。

### 缺页率虽低，影响却很大

**算例**：Hc=0.95、tc=2 ns、tm=50 ns；Hm=0.9998、td=5 ms。t1=0.95×2+0.05×50=4.4 nst2=0.9998×4.4+0.0002×5×106=4.4+1000≈1004 ns

缺页率只有万分之二，却把平均访问时间从 4.4 ns 拉到约 1 μs——**磁盘访问的代价太大，极低的缺失率也会主导平均值**。

这解释了为什么虚拟存储器要不惜代价压低缺页率（全相联、精细的替换算法），而 Cache 可以容忍 5% 的缺失率。

## 六、设计参数的权衡

层次结构中的每个参数都是双刃的，没有"越大越好"。

### Cache 的参数

| 参数增大 | 好处 | 代价 |
| --- | --- | --- |
| 容量 | 命中率提高 | 成本上升，访问延迟增大 |
| **块大小** | 空间局部性利用更充分 | 块数减少导致冲突增加；**未命中代价增大** |
| 相联度 | 冲突缺失减少 | 比较器增多，延迟增大 |

块大小的影响是非单调的：太小则浪费空间局部性，太大则块数减少、冲突增多，且每次缺失要搬运更多数据。存在一个最优值。

### 页大小

| 页大小 | 好处 | 代价 |
| --- | --- | --- |
| 大 | 页表项少、TLB 覆盖范围大、磁盘传输效率高 | **内部碎片**大 |
| 小 | 内部碎片小 | 页表大、TLB 缺失率高 |

> [!TIP]
>

为什么块是 64 B 而页是 4 KB

两者都是"一次传输多少"的选择，量级却差了 64 倍。原因在于下层介质的特性：

- **主存**的访问延迟主要是电路延迟，多传几十字节的**边际成本很低**，但也没必要太大
- **磁盘**的访问延迟绝大部分花在寻道和旋转上（毫秒级），数据传输本身几乎不占时间。既然启动一次这么贵，**就应该一次多搬一些**

所以页远大于块，本质上是被磁盘的机械特性决定的。

## 易混淆知识点

**1. 层次结构是三层还是两层？**

看从哪个角度说。按**器件**列举是多层（寄存器、Cache、主存、辅存）；按**缓存关系**划分则是两个层次（Cache–主存、主存–辅存）。

大纲和真题多数情况下问的是后者——因为"两个层次"对应两套完全不同的管理机制。

**2. 主存既是上层又是下层，矛盾吗？**

不矛盾。主存相对 Cache 是下层（被缓存的一方），相对辅存是上层（缓存方）。这正是"层次"的含义——每一层都同时扮演两个角色。

**3. 局部性是程序的性质还是硬件的性质？**

是**程序的性质**。硬件只是利用了它——如果一个程序完全随机地访问整个地址空间，任何层次结构都无法提速。

因此优化程序的访问模式（如调整循环顺序使其符合数组的存储顺序）能显著提升性能，这也是"软硬件协同"的典型体现。

## 本节小结

- 存储系统的三重矛盾：**速度快、容量大、成本低**，无单一技术能同时满足
- 层次结构成立的前提是**程序的局部性原理**——工作集远小于地址空间
- 阶梯自上而下为**寄存器 → Cache → 主存 → 辅存**，速度递减、容量递增、每位价格递减，三者**同向变化**
- **寄存器不算一个缓存层次**——它由指令显式指名，没有"命中与否"的判断
- 时间局部性看"同一单元是否重访"，空间局部性看"地址是否顺序推进"，**两者独立判断**
- 顺序遍历一遍是"无时间局部性、有空间局部性"的典型
- 两个层次：**Cache–主存**（硬件管理、传输块）与**主存–辅存**（OS 管理、传输页）
- 两者的映射方式、管理者、写策略三处差别，**全部源自未命中代价相差三个数量级**
- 缺页率虽极低，但因代价巨大，仍会主导平均访问时间
- 块大小与页大小都存在最优值；**页远大于块，是被磁盘的机械特性决定的**
