# 总线仲裁

## 大纲定位

**六（一）1　总线的基本概念**（相关背景）

现行 408 大纲「总线」一章只列三条：总线的基本概念、总线的组成及性能指标、总线事务和定时。**总线仲裁（判优控制）本身不是其中的单列条目。**

保留本篇的理由：总线事务的第一阶段就是"申请分配"，[[03_计算机组成原理_CO/io/dma.md|DMA 方式]] 抢占总线也要经过判优。不知道"谁来决定总线归谁"，这两处就只能背流程。**读它是为了补一层机制上的直觉，三种方式的线数公式不必背。**

总线事务的四个阶段见 [[03_计算机组成原理_CO/bus/bus-timing.md|总线事务与定时]]；总线共享带来的瓶颈见 [[03_计算机组成原理_CO/bus/bus-overview.md|总线概述与分类]]。

## 知识框架

本节回答三个问题：

- 总线明明只是一组导线，为什么必须额外配一套判优机制？
- 集中式的三种方式为什么恰好是"线最少最慢／线最多最快／居中"这样排开的？它们之间是不是一条连续的取舍谱？
- 去掉中央仲裁器之后，各设备靠什么自己分出胜负？

## 一、判优机制是共享的必然结果

总线上连接着多个部件，什么时候由哪个部件发送信息、如何防止信息丢失、如何避免多个部件同时发送，都要由**总线控制器**统一管理。它主要包括两块：**判优控制（仲裁逻辑）** 与 **通信控制（定时）**。

所有设备按对总线有无控制功能分成两类：

- **主设备**：对总线有控制权，能发起传输；
- **从设备**：只能响应主设备发来的命令，对总线没有控制权。

总线上的信息传送由主设备启动。当**多个主设备同时要使用总线**时，就由总线控制器的判优、仲裁逻辑按一定的优先等级顺序确定哪个主设备能使用总线；只有获得使用权的主设备才能开始传送数据。

仲裁的基本流程：

- 设备发出**总线请求**（BR）；
- 仲裁逻辑按优先策略选出一个设备；
- 向该设备发出**总线授权／总线同意**（BG）；
- 设备建立**总线忙**（BS）信号并占用总线，传输完成后释放。

按控制逻辑放在哪里，判优分两类：**集中式**（控制逻辑集中在一处，如放在 CPU 中）与**分布式**（控制逻辑分散在各部件上）。

## 二、三种集中式仲裁：一条连续的取舍谱

三种方式常被当作三个孤立方案背下来。其实它们解决的是**同一件事**，差别只在实现手段。

仲裁器要把"总线归你了"这条信息送到某一个设备手上。设备有 n 个，这条信息的信息量就是 ⌈log2⁡n⌉ 比特。**把这几个比特送出去，有三种编码方式**——三种仲裁方式正是这三种编码：

| 编码方式 | 信息藏在哪里 | 对应的仲裁方式 |
| --- | --- | --- |
| 串行传递 | **时间**里（传到第几跳就是第几号设备） | 链式查询 |
| 二进制编码广播 | **编码**里（⌈log2⁡n⌉ 条线上的组合） | 计数器定时查询 |
| 独热码直连 | **空间**里（哪条专线有效就是哪个设备） | 独立请求 |

信息论上这是一条连续的谱：**越舍得用线数把信息并行铺开，就越省时间**。下面逐个看。

### 链式查询：把信息编进时间

所有设备共享一条 BR 线；BG 信号从总线控制部件出发，**串行地从一个接口送到下一个接口**。

```
总线控制部件 ──BG──→ 设备0 ──BG──→ 设备1 ──BG──→ 设备2 ──→ ...
                  │          │          │
                  BR─────────┴──────────┴──→ 总线控制部件
```

BG 到达某个接口时，如果该接口有请求，BG 就**不再往下传**，该接口获得使用权并建立 BS 忙信号；没有请求则原样传给下一个。

于是"授权给谁"这个信息完全由**传了几跳**表达——只用一条 BG 线，代价是每多一个设备就多一跳延迟。

**控制线数**：3 条（BR、BG、BS），**与设备数无关**。

| 优点 | 缺点 |
| --- | --- |
| 只需很少几根线就能按优先次序实现总线控制 | 优先级由物理连接顺序固定，离控制部件最近的优先级最高 |
| 扩充设备非常容易 | 优先级低的设备可能很难获得请求 |
|  | **对电路故障很敏感**：BG 传递路径上一处断开，下游设备全部收不到授权 |

### 计数器定时查询：把信息编成二进制

与链式相比，**多了一组设备地址线，少了一根 BG 线**。

```
总线控制部件 ──计数值（设备地址线）──→ 广播给所有设备
                                    │
              设备比较自身编号与计数值，相符且有请求则获得使用权
```

控制部件收到 BR 后，在总线未被使用（BS = 0）时启动内部计数器，通过设备地址线向各设备**广播**一组地址信号；某个请求占用总线的设备其地址与计数值一致时获得使用权，此时终止计数查询。

信息被编成二进制数广播出去，线数从"与 n 无关"上升到 ⌈log2⁡n⌉，换来的是**不再逐跳传递**——所有设备同时收到计数值，比较是并行的。

**控制线数**：⌈log2⁡n⌉+2 条（设备地址线 + BR + BS）。

这种方式还带来一个链式做不到的能力——**优先级可编程**：

| 计数起点 | 效果 |
| --- | --- |
| 每次从 0 开始 | 优先级按 0,1,…,n−1 降序固定不变，等价于固定优先级 |
| 从上一次计数的终止点开始 | 循环轮转，各设备使用总线的优先级相等 |
| 初始值由程序设置 | 优先次序可任意改变 |

代价是控制线数增加、控制也较复杂；好处是**对电路故障不如链式查询敏感**——广播不存在"断链导致下游全灭"。

### 独立请求：把信息铺在空间上

每一台设备都有**一对**专用的总线请求线 BRi 和总线同意线 BGi。

```
设备0 ──BR₀──→ ┐                    ┌──BG₀──→ 设备0
设备1 ──BR₁──→ ├─ 总线控制部件 ──┤──BG₁──→ 设备1
设备2 ──BR₂──→ ┘   （排队电路）    └──BG₂──→ 设备2
```

控制部件中有一排队电路，**同时看到所有请求**，根据优先次序一次选出赢家，直接从对应的 BGi 送出授权。

信息完全铺在空间上（独热码），线数升到 O(n)，换来**一拍到位**的响应。

**控制线数**：2n+1 条（n 条 BR + n 条 BG + BS）。

| 优点 | 缺点 |
| --- | --- |
| **响应速度快**，不需要串行传递也不需要计数 | 控制线数量多 |
| 优先次序控制灵活，可通过程序改变 | 总线控制部件更复杂，硬件开销最大 |
| 单个设备的连线故障不影响其他设备 |  |

### 三者对照

| 特性 | 链式查询 | 计数器定时查询 | 独立请求 |
| --- | --- | --- | --- |
| 授权信息的编码 | 时间（跳数） | 二进制编码 | 独热码 |
| 控制线数 | 3 | ⌈log2⁡n⌉+2 | 2n+1 |
| 线数随 n 的增长 | 常数 | 对数 | 线性 |
| 判优速度 | 慢 | 中 | 快 |
| 优先级 | 固定（由连接顺序决定） | 可变（计数起点可编程） | 灵活可编程 |
| 硬件复杂度 | 低 | 中 | 高 |
| 对电路故障的敏感度 | 高（断链下游全灭） | 中 | 低 |

教材在比较线数时说的是"链式查询中仅用两根线确定总线使用权、计数器查询中大致用 log2⁡n 根线、独立请求需采用 2n 根线"——那是只数**用于确定使用权**的线（BR/BG/设备地址线）。上表在此基础上另计了 1 条 BS 忙线。两种口径差一个常数，**关键是增长阶：常数、对数、线性**。

## 三、分布式仲裁

没有中央仲裁器，每个设备自带仲裁逻辑，控制逻辑分散在与总线连接的各个部件上。各设备把自己的**仲裁号**（优先级编号）送到共享的仲裁总线上，所有设备同时比较，编号最大（或最小）者获胜。

- 优点：无单点故障，扩展灵活，不依赖某个中心部件；
- 缺点：每个设备都要配一套仲裁逻辑电路，总硬件量上升。

## 例题

**例 1（线数随规模的增长）**：某系统分别接入 4 台、16 台、64 台主设备，比较三种集中式仲裁方式所需的控制线数。

**解**：直接代入三个公式。

| 设备数 n | 链式查询 3 | 计数器定时查询 ⌈log2⁡n⌉+2 | 独立请求 2n+1 |
| --- | --- | --- | --- |
| 4 | 3 | 2+2=4 | 9 |
| 16 | 3 | 4+2=6 | 33 |
| 64 | 3 | 6+2=8 | 129 |

设备数翻两番（4 → 64），链式一根线没多，计数器只从 4 涨到 8，独立请求却从 9 涨到 129。**三条曲线的形状——水平、对数、直线——就是这三种编码方式在硬件上的直接投影。** 也正因为如此，设备很多时独立请求几乎不可用，而设备少时它的线数代价可以忽略、速度优势却全额保留。

## 易混淆知识点

**1. 链式查询"对电路故障敏感"，敏感在哪里？**

敏感在 **BG 的传递路径**上。BG 要沿着设备链逐级往下传，链路中任意一处断开或某个接口的传递逻辑失效，**下游所有设备都收不到授权**，等于被整体摘除。计数器方式是广播，独立请求是专线，都没有这种"一处坏、一片死"的结构。

**2. 计数器定时查询的优先级到底是固定的还是可变的？**

取决于**计数起点**，这正是它的灵活之处：每次从 0 开始计数，优先级就按设备编号降序固定；从上一次终止点继续计数，就成了循环轮转、各设备优先级相等；初值由程序设置，则优先次序可以任意安排。链式查询没有这个自由度——它的优先级写死在物理连线顺序里。

**3. 优先级固定为什么会导致低优先级设备长期得不到总线？**

链式查询中 BG 由近及远传递，靠前的设备只要有请求就把 BG 截下。若靠前的设备频繁请求，BG 永远传不到后面，后面的设备就长期拿不到总线（饥饿）。计数器方式的"从上次终止点继续"正是针对这一点的修正：让起点轮转，每个设备都有机会排在前面。

**4. 独立请求"速度最快"，快在哪一步？**

快在**判优这一步**。所有请求同时到达排队电路，一次比较就选出赢家，与设备数无关；链式要等 BG 逐跳传递，计数器要等计数值数到目标编号。三者在数据传输阶段的速度并无差别——仲裁方式只影响"从提出请求到拿到总线"这段时间。

**5. 集中式和分布式的分界在哪？**

看**仲裁逻辑放在哪里**：集中在一处（如 CPU 内的总线控制部件）就是集中式，分散在各个部件上就是分布式。链式、计数器、独立请求三种都是集中式——它们的差别只在中央仲裁器与设备之间**用什么方式连线**，仲裁的决策权始终在中央。

## 本节小结

- 判优机制是总线**分时共享**的必然产物：多个主设备同时请求时，必须有一套逻辑决定使用权归谁
- 按控制逻辑的位置分**集中式**与**分布式**；集中式又分链式查询、计数器定时查询、独立请求三种
- 三者本质是"把 ⌈log2⁡n⌉ 比特的授权信息送出去"的三种编码：**串行传递、二进制广播、独热直连**
- 控制线数依次为 3、⌈log2⁡n⌉+2、2n+1，增长阶是**常数、对数、线性**；判优速度依次为慢、中、快
- 这是一条**用线数换响应时间**的连续谱，不是三个孤立方案
- 链式查询优先级由物理连接顺序固定，且**对电路故障敏感**——BG 传递路径一处断开，下游设备全部收不到授权
- 计数器定时查询的优先级由**计数起点**决定：从 0 开始等于固定优先级，从上次终止点继续等于循环轮转，初值可由程序设置
- 独立请求速度最快、优先次序最灵活，代价是控制线随设备数线性增长
- 分布式仲裁无中央仲裁器，各设备把仲裁号送上共享仲裁总线同时比较，无单点故障但每个设备都要配仲裁逻辑
