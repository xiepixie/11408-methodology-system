# 浮点数表示（IEEE 754）

## 大纲定位

**二（四）1　浮点数的表示：IEEE 754 标准**

要求：掌握单精度/双精度的字段划分与偏置常数，能在机器数与真值之间双向转换，识别规格化数、非规格化数与三类特殊值，并知道表数范围与精度各由谁决定。

移码的定义与性质见 [[03_计算机组成原理_CO/data-repr/true-value-machine.md|真值与机器数：四种编码的定义]]；浮点数的加/减运算（对阶、尾数运算、规格化、舍入）见 [[03_计算机组成原理_CO/data-repr/float-arithmetic.md|浮点数运算]]。

## 知识框架

本节回答五个问题：

- 总位数固定时，阶码和尾数怎么分？为什么**范围和精度必然此消彼长**？
- 阶码为什么用**移码**，不用补码也不用原码？
- 尾数的最高位为什么可以**不存**？省下这一位换来了什么，又欠下了什么？
- 阶码全 0 和全 1 被拿去表示特殊值，**代价是什么**？三类特殊值为什么这样划分？
- "能表示"和"能**精确**表示"差在哪？

## 一、浮点数的一般格式：一次分配决定一切
N=(−1)S×M×2E

- S：符号位（0 正 1 负）
- E：阶码（指数），决定**表示范围**
- M：尾数（有效数字），决定**精度**

**为什么需要浮点数**：定点数把全部位都用来存有效数字，位权是固定的。想表示 1030 就得摆出上百位；想表示 10−30 又得往小数端摆上百位。而实际计算里，一个数往往只需要六七位有效数字，真正变化剧烈的是**量级**。

浮点数的做法是**把"量级"和"有效数字"分开存**：拿出几位专门记录小数点该往哪儿浮动，剩下的位全部用于有效数字。同样 32 位，定点整数只能覆盖 ±231，单精度浮点能覆盖 ±1038。

代价也是明摆着的：**总位数是定死的**。1⏟S+k⏟阶码+m⏟尾数=总位数

阶码多一位，指数范围翻倍，但尾数就少一位、有效数字少一位。**范围与精度在同一份预算里抢位置**，这是浮点数所有权衡的源头。

## 二、阶码为什么用移码

阶码要能表示负指数，所以必须是一种带符号编码。候选有原码、补码、移码，IEEE 754 选了移码。理由有两条，第二条更关键。

### 理由一：比大小可以直接按位串比

移码的定义是"真值加偏置常数"，加完之后真值的顺序被**原样保留**到无符号整数的顺序里。于是阶码在高位、尾数在低位这样一排，**整个浮点数的位串按无符号整数比大小，结果就是数值的大小**（同号的前提下）。

比较两个浮点数不必先解码阶码，一条整数比较指令就够了。补码做不到：补码里 −1 是全 1，按无符号读是最大值，负指数会排到正指数后面去。

### 理由二：把"两个极端位串"腾到了数轴两端

这一条常被忽略，却更决定格式设计。

IEEE 754 需要一些位串来表示 0、∞、NaN 这类"不是普通实数"的东西。这些位串必须**从原本能表示实数的编码里挖走**。挖哪两个？

| 阶码编码 | 全 0 代表的指数 | 全 1 代表的指数 | 挖走它们等于 |
| --- | --- | --- | --- |
| 补码 | 0 | −1 | 在数轴**正中间**挖两个洞 |
| **移码** | **最小指数** | **最大指数** | 只切掉数轴的**两个末梢** |

移码下，全 0 和全 1 恰好是指数的两个端点。把它们征用为特殊标记，损失的只是最极端的量级——而那个量级本来也接近溢出，用处不大。**换成补码，被挖掉的就是最常用的 20 和 2−1 附近，格式当场废掉。**

> [!TIP]
>

偏置常数为什么是 2k−1−1 而不是 2k−1

一般移码的偏置常数取 2k−1，IEEE 754 取 2k−1−1（单精度 127，双精度 1023）。

原因就是上一段：全 0 和全 1 被征用后，可用阶码只剩 1∼2k−2。偏置取小 1，能让剩下这段**正负指数的分布更均衡**——单精度实际指数范围是 −126∼+127，正向多一格，因为全 1 被拿走的是正端。若偏置仍取 128，范围会变成 −127∼+126，负端多一格；两者都不对称，标准选了前者，同时也让最大量级略大一点。

## 三、尾数为什么隐含最高位 1

**规格化**要求尾数写成 1.f 的形式：小数点前恰好一位非零数字。

在**二进制**下，非零数字只有 1 这一种可能。所以规格化尾数的最高位**恒为 1**——存一个永远不变的常数是纯粹的浪费。

IEEE 754 把它省掉，称为**隐藏位**：字段里只存小数点后面的 f，读的时候自动在前面补回 `1.`。真值=(−1)S×1.f×2E−bias

**换来的**：单精度 23 位字段表示 **24 位**有效数字，双精度 52 位字段表示 **53 位**，白赚一位精度。

**欠下的**：1.f≥1 恒成立，**这个格式表示不出 0**。

隐藏位这件事本身，就逼出了下一节的整张特殊值表——**0 必须靠一条额外约定挤进来**。

> [!TIP]
>

换个基数就没这个便宜可占

有些早期格式的基数取 16（如 IBM 370 短浮点数），规格化尾数的最高一位十六进制数码可以是 1∼F 中任意一个，**没有"恒为 1"这回事**，隐藏位无从谈起。

基数取 2 才有隐藏位——这是 IEEE 754 把基数定死为 2 的收益之一。

## 四、字段划分

| 字段 | 单精度 float（32 位） | 双精度 double（64 位） |
| --- | --- | --- |
| 符号 S | 1 位，[31] | 1 位，[63] |
| 阶码 E | 8 位，[30:23] | 11 位，[62:52] |
| 尾数 f | 23 位，[22:0] | 52 位，[51:0] |
| 偏置常数 bias | 27−1=127 | 210−1=1023 |
| **有效位数** | **24 位**（含隐藏位） | **53 位**（含隐藏位） |
| 规格化数的指数范围 | −126∼+127 | −1022∼+1023 |

## 五、五类取值：这张表是怎么被划出来的

不要把下表当成五条要背的规则。它是从**"必须给 0 腾个位置"**这一个需求推出来的。

| 阶码 E | 尾数 f | 含义 | 真值 |
| --- | --- | --- | --- |
| 全 0 | =0 | ±0 | 正零、负零，比较时相等 |
| **全 0** | ≠0 | **非规格化数** | (−1)S×0.f×21−bias |
| 全 1 | =0 | ±∞ | 如 1/0 |
| 全 1 | ≠0 | NaN | 如 −1、0/0、∞−∞ |
| 1∼2k−2 | 任意 | 规格化数 | (−1)S×1.f×2E−bias |

**推导链**：

- 隐藏位使 1.f≥1，**0 表示不出来** ⇒ 必须征用一个位串专门表示 0。
- 征用哪个？按第二节的结论，只能从数轴末梢下手，于是取**阶码全 0**。为了让 ±0 都有编码，规定阶码全 0 **且**尾数全 0 时为 ±0，符号由 S 决定。
- 阶码全 0 被征用后，尾数不全 0 的那些位串（223−1 个）就闲置了。**丢掉可惜**——把它们改成"隐藏位为 0"来解释，即 0.f，正好能表示比最小规格化数还小的一批数，称为**非规格化数**。
- 数轴一端征用了，另一端（阶码全 1）对称地拿去表示"超出范围"和"没有定义"：尾数全 0 表 ±∞，尾数不全 0 表 **NaN**。
- 剩下的阶码 1∼2k−2 才是规格化数。所以单精度真实指数是 1−127=−126 到 254−127=+127。

### 非规格化数的指数为什么是 1−bias

这是全节最容易记错也最能讲出道理的一处。

非规格化数的阶码字段是全 0，按常规解码应得指数 0−127=−127。但标准规定它的指数是 −126，即 1−bias。

**为什么**：为了和最小规格化数**无缝衔接**。

|  | 值 |
| --- | --- |
| 最大非规格化数（指数取 −126） | (1−2−23)×2−126 |
| 最小规格化数 | 1.0×2−126 |
| **两者之差** | 2−23×2−126=2−149 |
| 相邻非规格化数之间的间隔 | 2−23×2−126=2−149 |

后两行**完全相等**——从非规格化区跨到规格化区，数的疏密没有任何跳变，衔接处是平滑的。

如果指数取 −127，最大非规格化数只有约 0.5×2−126，和最小规格化数之间会留下一个宽度约为 2−127 的**空洞**，比该处相邻数的间隔大了 222 倍。

非规格化数存在的全部意义就是**填补 0 到最小规格化数之间的空隙**，让下溢变成"渐进"的而不是"一步归零"。指数取 1−bias 是让这个填补做得严丝合缝的唯一取值。

### 无穷与 NaN 为什么要分开

两者都用阶码全 1，靠尾数区分，因为它们回答的是两个不同的问题：

- ∞ 表示**结果超出了能表示的范围，但方向是确定的**。1/0+=+∞，参与后续运算仍有意义（5+∞=∞）。
- NaN 表示**结果根本没有定义**。0/0、∞−∞、−1 说不出该是正是负、是大是小。

把它们合并成一种，5+(+∞) 就无法给出确定结果了。**分开的收益是：程序遇到溢出可以继续算下去，遇到无定义才需要中断。**

## 六、两个方向的转换

### 机器数 → 真值

- 十六进制展开成 32 位二进制
- 按 1 / 8 / 23 切开
- **先看阶码是不是全 0 或全 1**——这一步决定走哪条公式
- 规格化数：e=E−127，尾数前面补回隐藏位 `1.`
- 写成 (−1)S×1.f×2e

### 真值 → 机器数

- 把绝对值写成二进制（整数部分 + 小数部分）
- 规格化成 1.xxx×2e
- E=e+127，转 8 位二进制
- 小数点后的位填进尾数字段，**右边补 0 补满 23 位**
- 拼成 32 位再按四位一组转十六进制

> [!TIP]
>

常用二进制小数速查

0.5=2−1=0.12，0.25=0.012，0.125=0.0012，0.0625=0.00012。

0.375=0.25+0.125=0.0112，0.4375=0.25+0.125+0.0625=0.01112，0.75=0.112。

把要转的小数拆成这几个的和，比反复乘 2 快得多。

## 七、范围与精度：四个数不要混

| 问的是 | 单精度的答案 | 怎么来的 |
| --- | --- | --- |
| **最小规格化正数** | 1.0×2−126 | Emin=1，e=1−127=−126，尾数最小是 1.0 |
| **最小正数**（含非规格化） | 2−149 | 非规格化最小：2−23×2−126 |
| **最大正数** | (2−2−23)×2127=2128−2104 | Emax=254，e=127，尾数最大是 1.11…1=2−2−23 |
| **能精确表示的最大整数** | 224 | 有效位只有 24 位，224+1 就已经存不下了 |

> [!WARNING]
>

第三行和第四行是两个完全不同的问题

- "**能表示的**最大正数"问的是**范围上限**——由**阶码位数**决定，答案是 2128−2104，一个天文数字。
- "**能精确表示的**最大整数"问的是**精度上限**——由**尾数位数**决定，答案是 224，只有一千六百多万。

超过 224 之后，浮点数仍然"表示得出"更大的整数，只是**表示得不精确**了：224+1 会被存成 224，因为要写下它需要 25 位有效数字。范围和精度分别由两个字段决定，问法里"能表示"和"能精确表示"这几个字必须逐字读。

### 由此得到的选型判据

给定一段取值范围，选整型还是浮点型，只需两步：

- **范围够不够**：n 位补码整数的范围是 [−2n−1, 2n−1−1]。
- **精度够不够**：浮点数只有 24 位（单精度）/ 53 位（双精度）有效位，超过 224 / 253 的整数就不能保证精确。

**范围装得下就用整型**：精确、且运算快。只有范围装不下时才考虑浮点，此时还要回头检查有效位数。

例如某量的取值可达 ±240：32 位整数装不下（上限 231−1）；单精度范围够，但只有 24 位有效位，240 量级的整数存不准；所以必须用**双精度**（53 位有效位 >40）。

关于 int 与 float 相互转换时具体丢什么，见 [[03_计算机组成原理_CO/data-repr/c-type-conversion.md|C 语言中的数据类型与转换]]。

## 八、哪些数能被精确表示

**判据只有一条：一个十进制小数能用有限位二进制小数精确表示，当且仅当它化成最简分数后，分母是 2 的幂。**

| 数 | 最简分数 | 分母 | 能否精确表示 |
| --- | --- | --- | --- |
| 2.0 | 2/1 | 1=20 | ✓ |
| 2.5 | 5/2 | 21 | ✓ |
| 1.25 | 5/4 | 22 | ✓ |
| 0.4375 | 7/16 | 24 | ✓ |
| **1.2** | 6/5 | **5** | **✗** |
| 0.1 | 1/10 | 2⋅5 | ✗ |

分母里只要含有 2 以外的质因子（5、3……），二进制展开就是无限循环的，只能截断存储。这就是 `0.1 + 0.2 != 0.3` 的根源。原理见 [[03_计算机组成原理_CO/data-repr/number-system.md|进位计数制与转换]]。

## 九、舍入

尾数放不下时必须舍入。IEEE 754 规定四种模式：

| 模式 | 规则 | 别名 |
| --- | --- | --- |
| **就近舍入（中间值取偶）** | 舍到最近的可表示数；**正好在两个可表示数正中间时，取尾数末位为 0（偶数）的那个** | 默认模式 |
| 朝 +∞ 舍入 | 总取数轴上右边那个可表示数 | 正向舍入、朝上舍入 |
| 朝 −∞ 舍入 | 总取数轴上左边那个可表示数 | 负向舍入、朝下舍入 |
| 朝 0 舍入 | 直接截断丢弃多余位，取更靠近原点的那个 | 截断、恒舍法 |

**就近舍入的实际操作分两种情况**：

- **不是正中间**（多数情况）：就是普通的"0 舍 1 入"——看被丢弃部分是大于还是小于半个末位。
- **正好是正中间**：此时"就近"无从选择，强制让结果的**最低有效位为 0**。若舍入后末位是 1，则末位加 1；否则不变。

**二进制下"是不是正中间"有一条机械判据**——只看**被丢弃的那串位**：

| 被丢弃位串 | 与半个末位比 | 怎么做 |
| --- | --- | --- |
| `0…` | 不足一半 | **舍**，保留位不动 |
| `1…` 且后面**还有 1** | 超过一半 | **入**，保留位加 1 |
| `1 000…0`（首位 1、其后全 0） | **恰好一半** | 取偶：保留位末位是 1 就加 1，是 0 就不动 |

**演示**（尾数只保留 4 位，就近舍入）：

| 原尾数 | 保留位 | 丢弃位 | 判定 | 结果 |
| --- | --- | --- | --- | --- |
| 1.0110 0100 | `0110` | `0100` | 首位 0 → 舍 | `0110` |
| 1.0110 1100 | `0110` | `1100` | 首位 1 且后有 1 → 入 | `0111` |
| 1.0110 1000 | `0110` | `1000` | 恰好一半，末位 0 → 不动 | `0110` |
| 1.0111 1000 | `0111` | `1000` | 恰好一半，末位 1 → 加 1 | `1000` |

后两行的丢弃位完全相同，只因保留位末位的奇偶不同，处理就相反——**"取偶"只在这两行生效**。

> [!TIP]
>

判据只需要两个信号，不必留下整串丢弃位

上表的三行判定，实际只用到被丢弃位串的两个信息：

- **舍入位** R：紧挨保留位的**第一个**被丢弃位
- **粘位** S：其余所有被丢弃位的**逻辑或**（"后面还有没有 1"）

于是判定写成一条式子——设保留位末位为 L，则进位⟺R⋅(S+L)

R=0 一律舍；R=1 且 S=1 一律入；R=1,S=0 是"恰好一半"，此时由 L 定夺（L=1 才进位），正是取偶。

这解释了为什么硬件不必保存全部被丢弃的位：**无论丢掉多少位，只要一个 R 和一个 S 就够了**，S 用一个"只要来过 1 就永久置 1"的粘滞触发器累积，名字即由此而来。

> [!TIP]
>

为什么"中间值取偶"，而不是统一进位

统一"逢中进位"会让误差**单向累积**——每次都往大的一侧偏，一长串运算下来结果系统性偏高。取偶则让中间值一半向上、一半向下（因为末位是 0 还是 1 大致各半），**误差期望为 0**。

这是"取偶"唯一的理由，与位模式好不好看无关。

> [!WARNING]
>

取偶不是主规则

"就近舍入（中间值取偶数）"是**模式名**。绝大多数情况下被丢弃的部分并不是恰好一半，取偶规则**根本不会触发**，要做的就是普通的 0 舍 1 入。

**先判断"是不是正中间"，再决定用哪条。** 反过来就会算错。

## 十、怎么比大小

移码阶码的设计就是为了这件事：

- **先看符号位**。S=0 的一定大于 S=1 的（±0 除外）。
- **同为正数**：直接把整个 32 位当无符号整数比，大的就大——阶码在高位、尾数在低位，字典序正好等于数值序。
- **同为负数**：**反过来**——位模式作为无符号数越大，绝对值越大，值反而越小。

第 3 条最容易翻车。两个负浮点数，谁的阶码大谁的绝对值大，而绝对值大的那个**更小**。稳妥的做法是把两个数的符号和真实指数都写出来再下结论。

## 例题

**例 1（机器数 → 真值）**：某单精度机器数为 `C154 0000H`，求它表示的实数。

展开成 32 位：`1 10000010 10101000000000000000000`

- S=1，为负数
- E=100000102=130，既不是全 0 也不是全 1，属规格化数，e=130−127=3
- 尾数字段 `1010100…`，补回隐藏位得 1.101012=1+0.5+0.125+0.03125=1.65625x=−1.65625×23=−13.25

反向验算：13.25=1101.012=1.101012×23 ✓

**例 2（真值 → 机器数）**：把 +65.5 写成单精度机器数。

- 写成二进制：65.5=1000001.12
- 规格化：1.0000011×26
- 阶码：E=6+127=133=100001012
- 尾数字段取小数点后的位并**右补 0 补满 23 位**：`00000110000000000000000`

拼成 `0 10000101 00000110000000000000000`，四位一组转十六进制：0100⏟4 0010⏟2 1000⏟8 0011⏟3 0000⋯0000⏟0000=4283 0000H

两道题走的是同一条路，方向相反。**每次都先看阶码是不是全 0 或全 1**——这一步决定用规格化公式还是非规格化公式。

## 易混淆知识点

**1. 非规格化数的指数是 −127 还是 −126？**

单精度是 −126，即 1−bias；双精度是 −1022。

判据：**非规格化数的指数与最小规格化数的指数相同**。记住"两者共用同一个指数、只是隐藏位一个是 0 一个是 1"，就不会写成 −127。这个约定的目的是让两个区间无缝衔接（见第五节）。

**2. 阶码全 0 一定是 0 吗？**

不是。阶码全 0 只说明"走非规格化解释"，还要看尾数：

| 阶码 | 尾数 | 是什么 |
| --- | --- | --- |
| 全 0 | 全 0 | ±0 |
| 全 0 | 不全 0 | 非规格化数，是**非零**的极小数 |

同理阶码全 1 也不一定是 ∞，尾数不全 0 时是 NaN。**阶码只决定分支，尾数决定分支内的取值。**

**3. 最小正数和最小规格化正数差多少？**

差了整个非规格化区间。单精度：

- 最小规格化正数 =2−126≈1.18×10−38
- 最小正数（非规格化）=2−149≈1.40×10−45

两者相差 223 倍。**题面里有没有"规格化"三个字，答案差七个数量级。**

**4. 有效位数 23 位还是 24 位？**

**字段是 23 位，有效数字是 24 位**，差的那一位是隐藏位。双精度对应 52 / 53。

只有规格化数才有隐藏位 1；**非规格化数的隐藏位是 0**，它的有效数字随着前导零增多而减少——这也是非规格化区精度逐渐退化的原因。

**5. 两个浮点数位模式不同，值一定不同吗？**

不一定。+0（`00000000H`）和 −0（`80000000H`）位模式不同但比较时相等。此外多个不同的 NaN 位模式都表示 NaN，且 NaN **与任何数（包括它自己）比较都不相等**。

所以"用整数比较指令比浮点数"这条捷径有两个例外：±0 和 NaN。硬件的浮点比较指令会单独处理它们。

**6. 阶码用移码，尾数用什么码？**

尾数用**原码**：符号单独放在 S 位，尾数字段只存绝对值的小数部分，不做取反加 1。

所以浮点数取负只需把 S 位翻转，一位都不用动尾数。这也是为什么同一个正数的定点补码表示和浮点尾数会有一段相同的位序列，而负数不会——负数的补码和原码不同。

## 本节小结

- 浮点数把**量级**和**有效数字**分开存；总位数固定，**阶码位数与尾数位数此消彼长**，即范围与精度的取舍
- 阶码用**移码**：既让位串顺序等于数值顺序（可整体按无符号比大小），又把全 0/全 1 这两个待征用的位串推到了**数轴两端**
- 偏置常数取 2k−1−1 而非 2k−1，因为两端各被征用一个阶码
- 二进制规格化尾数最高位**恒为 1**，故隐藏不存；23 位字段表示 **24 位**有效数字。代价是**表示不出 0**，从而逼出整张特殊值表
- 五类取值由"给 0 腾位置"一路推出：阶码全 0 → ±0 / **非规格化数**；阶码全 1 → ±∞ / **NaN**；其余为规格化数
- **非规格化数的指数固定为 1−bias**（单精度 −126），取这个值才能与最小规格化数无缝衔接，间隔恰为 2−149
- ∞ 与 NaN 分开，是为了区分"超范围但方向确定"和"无定义"
- 最小规格化正数 2−126；最小正数 2−149；最大正数 2128−2104；**能精确表示的最大整数 224**——前三个由阶码决定，最后一个由尾数决定
- 能精确表示 ⇔ 最简分数的分母是 2 的幂
- 四种舍入模式；**就近舍入只有正中间时才用"取偶"**，取偶的目的是让误差不单向累积。判据只需**舍入位 R**（第一个被丢弃位）与**粘位 S**（其余位之或）两个信号：**进位 ⟺R⋅(S+L)**，L 为保留位末位；R=1,S=0 才是"恰好一半"，取偶只在这一格生效
- 比大小：正数按位模式直接比；**负数反过来**，位模式大的值反而小；±0 与 NaN 是例外
