# 指令系统的基本概念

## 大纲定位

**四（一）指令系统的基本概念**

要求：说清一条指令必须携带哪些信息，理解指令由操作码与地址码两部分构成，能按显式地址码的个数区分三地址、二地址、一地址、零地址指令，并分清指令字长、机器字长、存储字长三者。

位段怎么划分、操作码怎么编码见 [[03_计算机组成原理_CO/instruction/instruction-design.md|指令格式与扩展操作码]]；地址码该怎么解释见 [[03_计算机组成原理_CO/instruction/addressing-modes.md|寻址方式]]。

## 知识框架

本节回答四个问题：

- 一条指令至少要说清哪几件事？这几件事怎么落成指令的两大字段？
- 为什么绝大多数机器的指令里**没有**"下一条指令地址"这个字段？
- 三/二/一/零地址指令的差别到底在哪——是**能力**上的差别，还是**约定**上的差别？
- 指令字长、机器字长、存储字长互相是什么关系？

## 一、一条指令必须携带哪些信息

指令系统不是设计者随手规定的一张表。从冯·诺依曼结构的"存储程序"工作方式出发，可以推出一条指令必须明显或隐含地包含四项信息：

| 必须说清的事 | 为什么必须有 |
| --- | --- |
| **操作码** | 不说做什么，硬件无从产生控制信号 |
| **源操作数或其地址** | 不说操作谁，运算部件拿不到输入 |
| **结果的地址** | 不说结果放哪，算完就丢了 |
| **下条指令地址** | 程序要能自动往下走 |

第四项是关键的一处设计取舍。**如果每条指令都显式写出下条指令地址，指令会长得离谱**——地址字段每多一个，指令字长就多出一整个地址的位宽，而绝大多数指令后面跟的就是紧挨着的那一条。

于是硬件替它记账：**程序计数器 PC 既存放指令地址，又具备计数功能**。顺序执行时只要把 PC 的值加上指令长度，下条地址就自动出来了；只有转移指令打破顺序时，才由指令自己给出目标地址。第四项因此从指令字里消失。

**编者注（推导）**：早期确实存在四地址指令，第四个地址就是下条指令地址。PC 的引入把这一整个地址字段从每一条指令里省掉了——这是"用一个寄存器换掉全部指令的一个字段"的典型划算买卖。PC 在取指周期自增的时序细节见 [[03_计算机组成原理_CO/cpu/instruction-cycle.md|指令执行过程]]。

剩下三项归并后，指令的通用结构就是两段：操作码（OP）⏟做什么+地址码⏟对谁做、结果放哪

- **操作码**指定操作类型（传送、加法、移位、转移等），位数决定这台机器能区分多少种操作
- **地址码**指定操作数的来源与结果的去处，可以是主存地址、寄存器编号、I/O 端口，也可以直接是一个立即数

## 二、ISA：软件能看见的那一层

一台计算机能执行的机器指令的集合称为**指令集体系结构**（Instruction Set Architecture，ISA），也就是指令系统。它是**硬件与软件之间的约定界面**：规定了程序员和编译器能看见、能用的一切，而把"怎么实现"留给硬件设计者。

判据只有一条：**换一款实现同一 ISA 的处理器，这个东西会不会变？**

不会变的属于 ISA——否则老程序换机器就跑不了；会变的属于微架构。

| ISA 规定（软件可见，换实现也不变） | 微架构决定（实现细节，可以随芯片改） |
| --- | --- |
| 指令格式与指令集 | 主频、时钟周期 |
| 通用寄存器的**个数与位数** | 流水线级数、是否超标量 |
| 寻址方式 | Cache 的容量与层次 |
| 数据类型与字长 | 控制器用微程序还是硬布线 |
| 异常与中断模型 | 内部总线结构、加法器的进位方式 |
| 存储器模型（编址方式、字节序） | 数据通路是单总线还是多总线 |

这条界线解释了一件常被忽略的事：同一份 x86 可执行文件能在跨越二十年的处理器上运行，正是因为这二十年里变的全是右列。左列一动，二进制兼容立刻破裂。

图 4.5 MIPS 指令格式（R 型）

指令格式在 ISA 里是以**位段划分**的形式规定死的：`OP` 占 [31:26] 共 6 位，`rs`/`rt`/`rd` 各 5 位，`shamt` 5 位，`func` 6 位。寄存器号占 5 位，直接意味着这套 ISA 有 25=32 个通用寄存器——**字段位宽就是软件可见规格本身**。

## 三、按地址码个数分类

指令的地址码个数不是越多越好，也不是越少越好，而是一条**"显式写出"与"隐含约定"之间的连续取舍**。

核心认识：**地址码减少时，信息并没有消失，只是从指令字里挪到了约定里。**

### 三地址指令
OPA1, A2, A3(A1) OP (A2)→A3

三个地址全部显式给出。源操作数不被破坏，编译器调度自由度最大，代价是指令最长。

### 二地址指令
OPA1, A2(A1) OP (A2)→A1

把"结果地址"和"第一个源地址"**合并成同一个**。省下一整个地址字段，代价是 A1 原来的值被覆盖——若后面还要用，编译器得先复制一份。

### 一地址指令
OPA1(ACC) OP (A1)→ACC

再省一个：另一个源操作数和结果都**隐含约定在累加器 ACC 里**。

这里有一个容易被跳过的分叉：**对单目运算**（取反、取负、加 1），这唯一的地址既是操作数地址、也是结果地址，根本不需要 ACC；**对双目运算**，才需要 ACC 来接住缺掉的那一个操作数和结果。

### 零地址指令
OP

地址码全部消失，分两种情形：

- **本身就没有操作数**：空操作 `NOP`、停机 `HLT` 之类
- **操作数隐含在栈顶**：栈型指令的操作数总是来自栈顶，`ADD` 弹出栈顶两个数相加、把结果压回栈顶

### 这条取舍链正好对应四种指令系统风格

按"操作数位置怎么指定"划分，教材给出四种风格，与上面的地址码个数一一呼应：

| 风格 | 操作数在哪 | 典型指令形态 | 代价 |
| --- | --- | --- | --- |
| **累加器型** | 一个操作数与结果恒在 ACC | 一地址 | 复杂表达式要反复进出 ACC，程序变长 |
| **栈型** | 操作数恒在栈顶 | 零地址 / 一地址 | 指令字最短，但表达式的求值顺序被写死，不灵活 |
| **通用寄存器型** | 立即数、寄存器、存储单元皆可 | 二地址 / 三地址 | 指令较长，但调度灵活 |
| **Load/Store 型** | 只有取数/存数指令能访存，运算全在寄存器间 | 三地址 | 指令条数变多，但长度与执行时间高度一致 |

前两种只在早期机器和虚拟机（如 Java 虚拟机）里使用；现代通用处理器基本都是后两种。**Load/Store 型的"规整"正是流水线得以高效运转的前提**，这条线索会在 [[03_计算机组成原理_CO/instruction/cisc-vs-risc.md|CISC 与 RISC]] 里接上。

## 四、操作类型

指令系统设计要满足**完备性**——所提供的操作类型足以编制任何可计算的程序。常见的分类如下：

| 类别 | 典型指令 | 说明 |
| --- | --- | --- |
| 算术与逻辑运算 | ADD, SUB, CMP, MUL, DIV, AND, OR, NOT, NEG, XOR, INC, DEC | 双目与单目运算 |
| 移位 | 算术移位、逻辑移位、循环移位 | 一条指令移多位时用桶形移位器实现 |
| 数据传送 | MOV, LOAD, STORE | 寄存器之间、寄存器与存储单元之间 |
| 串操作 | 串传送、串比较、检索 | 对字符串整体操作 |
| 顺序控制 | JMP, 条件转移, CALL, RET, 跳步 | 通过把目标地址送入 PC 实现 |
| CPU 控制 | 停机、开/关中断、模式切换 | 多为**特权指令**，只能在内核态执行 |
| 输入输出 | IN, OUT | 统一编址时可由访存指令代劳，无须单设 |

两处值得注意：

- **调用指令与转移指令的根本区别在于是否保存返回地址**。`CALL` 必须把下条指令地址存起来，`RET` 再取回送入 PC；`JMP` 一去不返，不需要保存。
- **输入输出指令不是必需的**。当 I/O 端口与主存**统一编址**时，普通访存指令就能读写端口，这类机器可以完全不设 IN/OUT。

指令系统设计还要满足另外三条原则：**兼容性**（高档机兼容低档机的指令系统，保护软件投资）、**均匀性**（运算指令应能处理多种数据类型）、**可扩充性**（操作码留出编码空间供后续扩充）。最后一条直接指向 [[03_计算机组成原理_CO/instruction/instruction-design.md|扩展操作码]] 的设计。

## 五、指令字长、机器字长、存储字长

三个"字长"名字相近，含义完全不同：

| 名称 | 定义 | 由什么决定 |
| --- | --- | --- |
| **机器字长** | CPU 一次能处理的数据位数 | ALU 位宽、通用寄存器宽度 |
| **指令字长** | 一条指令的二进制长度 | 操作码长度 + 地址码长度 × 地址码个数 |
| **存储字长** | 存储器一个单元的位数 | **编址单位** |

三者可以相等，也可以互不相等。**早期计算机三者相等**——访问一个存储单元就恰好取出一条完整指令或一个完整数据，控制方式因而非常简单。随着数据类型增多、存储容量增大，指令字长逐渐变得可变，出现单字长、双字长指令，控制电路随之复杂化，而多字长指令要**多次访存才能取出一条完整指令**，反过来拖慢 CPU。

"单字长""双字长"里的那个**字，指的是机器字长**，不是存储字长。教材给的例子把这个基准摆得很清楚：IBM 370 的指令字长可变，有 16 位（半个字）、32 位（一个字）、48 位（一字半）三种；Intel 8086 则有 8、16、24、32、40、48 位六种。所以单字长指令=机器字长,双字长指令=2×机器字长,半字长指令=12×机器字长

而"这条指令要访存几次才取得完"是另一个问题——那要拿指令字长去除**编址单位**。机器字长 32 位、按字节编址时，一条双字长指令是 64 位 = 8 字节，占 8 个存储单元；若该机一次能取 32 位，就要取两次。**两个除数不要混：命名看机器字长，取指次数看编址单位与访存宽度。**

因此设计上有一条经验：**把使用频度高的指令（数据传送、算术逻辑运算）设计成单字长或短字长格式**，把长格式留给不常用的指令。

**编者注（口径）**：指令存放在按字节编址的内存里，为便于取指和地址计算，**指令字长通常取 8 的整数倍**。算出来不是 8 的倍数就要向上圆整，这一步的具体做法见 [[03_计算机组成原理_CO/instruction/instruction-design.md|指令格式与扩展操作码]]。

## 易混淆知识点

**1. 零地址指令是"没有操作数"，还是"操作数不在指令里"？**

两种都有，必须分开：

| 情形 | 例子 | 操作数在哪 |
| --- | --- | --- |
| 真的没有操作数 | `NOP`、`HLT` | 不存在 |
| 操作数被隐含 | 栈型机器的 `ADD` | **栈顶**，由 SP 指出 |

"零地址"描述的是**指令字里没有地址字段**，不等于这条指令不碰数据。

**2. 二地址指令为什么会破坏源操作数，三地址就不会？**

因为二地址指令的结果地址与第一个源地址是**同一个字段**——写结果时必然覆盖那个源操作数。三地址指令的结果有独立字段，源操作数原封不动。

这不是硬件能力的差别，而是**字段够不够用**的差别：省下一个地址字段的代价，就是必须让某两件事共用一个地址。

**3. 指令字长变了，机器字长会跟着变吗？**

不会。两者由完全不同的东西决定：**机器字长看 ALU 和通用寄存器有多宽，指令字长看这条指令的各字段加起来有多少位**。

一台机器字长 32 位的处理器，完全可以同时拥有 16 位、32 位、48 位三种长度的指令。

**4. ISA 里为什么写着"通用寄存器个数"，却不写"Cache 容量"？**

拿判据去套：换一款实现同一 ISA 的处理器，寄存器个数**不能变**——指令里的寄存器号字段只有那么宽，程序直接按编号访问它们，变了程序就跑不了。而 Cache 容量变了，**程序的行为完全不变**，只是快慢有别，所以它属于微架构。

同一判据可以用来处理任何一个"这属不属于 ISA"的疑问：**它变了会不会让已编译好的程序失效**。

**5. "指令系统"和"指令集体系结构"是两个东西吗？**

不是，是同一个东西的两个名字。ISA 的中文全称是指令集体系结构，简称就是指令系统。

## 本节小结

- 一条指令必须携带四项信息：**操作码、源操作数地址、结果地址、下条指令地址**
- 第四项被 **PC 的计数功能**吸收，所以指令字里通常没有它——这是"用一个寄存器省掉每条指令一个字段"的取舍
- 指令 = **操作码 + 地址码**；操作码位数决定可区分的操作种类，地址码指定操作数来源与结果去处
- **ISA 是软硬件的约定界面**，判据是"换一款实现同一 ISA 的处理器，它会不会变"——寄存器个数属 ISA，主频、流水线级数、Cache 容量属微架构
- 地址码个数减少时，**信息没有消失，只是从指令字挪进了隐含约定**：二地址靠结果与源共用地址，一地址靠 ACC，零地址靠栈顶
- 一地址指令的那个地址，对**单目运算**兼作操作数地址与结果地址，对**双目运算**才需要 ACC 补位
- 四种指令系统风格（累加器型 / 栈型 / 通用寄存器型 / Load-Store 型）正是这条取舍链的具体化
- 调用指令与转移指令的根本区别是**是否保存返回地址**
- I/O 端口与主存**统一编址**时可以不设专门的输入输出指令
- 指令系统设计四原则：**完备性、兼容性、均匀性、可扩充性**
- **机器字长看 ALU 与寄存器宽度，指令字长看各字段之和，存储字长由编址单位决定**，三者互相独立
- 早期机器三种字长相等；现代机器指令字长可变，多字长指令需多次访存取指，故常用指令做成短格式
- **"单字长/双字长/半字长指令"以机器字长为基准命名**；而取指要访存几次看的是编址单位与访存宽度——两个除数不要混
