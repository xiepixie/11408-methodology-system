# CISC 与 RISC 的基本概念

## 大纲定位

**四（五）CISC 和 RISC 的基本概念**

要求：说清两种设计风格各自的由来与主要特征，能在指令长度、指令格式种类、寻址方式、寄存器数量、访存方式、控制器实现、平均 CPI 等维度上把两者对照起来，并理解 RISC 的这些特征为什么是互相支撑的一整套。

硬布线与微程序控制器的具体实现见 [[03_计算机组成原理_CO/cpu/hardwired-control.md|硬布线控制器]] 与 [[03_计算机组成原理_CO/cpu/microprogrammed.md|微程序控制器]]；流水线的工作方式见 [[03_计算机组成原理_CO/cpu/pipeline-basic.md|指令流水线的基本概念]]。

## 知识框架

本节回答四个问题：

- CISC 的复杂化不是设计失误，它当年在解决什么问题？后来又为什么走不下去了？
- RISC 的那一串特征是并列的清单，还是有一条主线把它们串起来？
- "指令定长"和"指令格式种类少"是不是同一件事？
- 同一段机器代码，从哪些地方能看出它属于哪一类风格？

## 一、CISC：复杂化是怎么发生的

CISC（Complex Instruction Set Computer，复杂指令集计算机）的复杂化有两条并行的推力。

**推力一：软件兼容。** 计算机系统的软件价格相对硬件不断上升，用户希望已开发的软件能被继承。新机种因此必须包含旧机种的**全部**指令和寻址方式，于是同一系列机的指令系统只增不减，越来越庞大。DEC 的 VAX-11/780 就有 16 种寻址方式、9 种数据格式、303 条指令。

**推力二：缩小与高级语言的语义差距。** 编译器的任务是把每条高级语言语句翻成一串机器指令。如果机器指令本身就接近高级语言语句的功能，编译器的活儿就轻松得多——早期编译技术薄弱时，这是一条很自然的思路。

两条推力共同作用的结果，是这样一套指令系统：

| 特征 | 具体表现 |
| --- | --- |
| 指令数量多 | 数百条甚至上千条 |
| **指令长度可变** | 一条指令从 1 字节到十几字节不等 |
| **指令格式种类多** | 字段切分方式有很多套，连操作码位数都可能不同 |
| 寻址方式多 | 支持复杂寻址，可以内存对内存操作 |
| 访存不受限 | 运算指令可以直接操作内存单元 |
| 通用寄存器少 | 早期只有 8 个 |
| 控制器实现 | 微程序控制（便于实现复杂指令） |
| 执行周期 | 不同指令所需周期数差异极大 |

### 为什么走不下去

对大量典型程序的统计给出了一条著名的经验规律——**80-20 规律**：典型程序中 **80% 的语句只使用了处理器 20% 的指令**，而且这些指令都属于取数、加法、转移之类的简单指令。

这条规律的杀伤力在于它同时否掉了复杂化的两个理由：

- **收益低**：付出巨大代价添加的复杂指令，使用概率只有 20%
- **还有反作用**：复杂指令的存在让简单指令的执行速度也提不上去——控制器要兼顾所有指令，译码路径和时序被最复杂的那条拖住

代价则是实打实的。统计表明，典型 CISC 计算机中**控制器约占 60% 的芯片面积**，而且让设计、验证和实现都更加困难。复杂指令系统还对"减少机器代码、降低指令执行数、为提高流水性能而优化生成代码"这些方向全都不利。

## 二、RISC：一条主线串起全部特征

RISC（Reduced Instruction Set Computer，精简指令集计算机）常被理解成"指令变少了"，但**精简指令本身不是目的**——目的是**通过简化指令使计算机结构更合理，从而提高性能**。

主线只有一条：**减少指令的执行周期数**。

程序的执行时间可以分解成三个因子：P=I×C×T

- I：程序编译后的机器指令条数
- C：每条指令平均所需的机器周期数
- T：每个机器周期的执行时间

RISC 用简单指令的组合去替代 CISC 的复杂指令，**I 反而变大了**（比 CISC 多 20%~40%）。但 RISC 的大多数指令只用一个机器周期完成，C 小得多；结构简单使完成一个操作所经过的数据通路更短，T 也大幅下降。三者相乘，总账仍然是 RISC 划算。

顺着"压低 C 和 T"这条主线，RISC 的七条特征就都能推出来：

| 特征 | 它在压低哪个因子 |
| --- | --- |
| ① 只选取使用频度高的简单指令，复杂功能由简单指令组合实现 | 让每条指令都能在短周期内完成 → C、T |
| ② **指令长度固定、指令格式种类少、寻址方式种类少** | 译码路径短且规整 → T |
| ③ **只有取数/存数（Load/Store）指令访存**，其余操作都在寄存器内完成 | 消除"访存"这个长延迟环节对运算指令的污染 → C |
| ④ CPU 中有大量通用寄存器 | 变量常驻寄存器，减少访存次数 → C |
| ⑤ **采用流水线技术，大部分指令在一个时钟周期内完成** | 直接压低 C |
| ⑥ 控制器采用**组合逻辑（硬布线）控制**，不用微程序控制 | 省掉查微程序存储器的时间 → T |
| ⑦ 采用优化的编译程序 | 指令少有利于编译器优化 → I |

**这七条不是七个独立的选择，而是一个互相支撑的整体。** 譬如②让③更容易实现，②③一起让⑤成为可能，⑤要求⑥（微程序控制的查表延迟撑不住单周期节拍），而①使⑥的电路规模可控——绕成一个闭环。

**编者注（边界）**：商品化的 RISC 机通常不是纯 RISC，上述特征不是所有 RISC 机全部具备。反过来，现代 x86 处理器在外部维持 CISC 接口，内部把复杂指令翻译成**微操作**、用类似 RISC 的核心执行——两条路线在实现层已经大幅趋同。

## 三、指令定长 ≠ 指令格式种类少

教材在描述 RISC 时把三件事写在同一条里——"寻址方式少、指令格式少、指令长度一致"。这三件事**互相独立**，必须分开理解：

| 维度 | 问的是 | CISC | RISC |
| --- | --- | --- | --- |
| **指令长度** | 一条指令占几个字节 | 变长（1~15 字节） | **定长**（如一律 32 位） |
| **指令格式种类** | 这些位**怎么切分成字段**，一共有几套切法 | 多，连操作码位数都可能不同 | **少**，且各套之间字段位置尽量对齐 |
| **寻址方式种类** | 有多少种解释地址码的方式 | 多，含内存对内存 | 少 |

定长完全可以配上很多种格式——同样 32 位，切法可以有几十种。RISC 两样都要。

**格式种类少为什么这么重要**：因为它让**译码可以与读寄存器并行**。以典型的 RISC 指令集为例，无论 R 型、I 型还是 S 型指令，源寄存器号永远落在同一段位上——CPU 根本不必等译码结果出来，就可以拿这几位去读寄存器堆。格式一乱，这一步只能串行等待，流水线的译码段立刻被拉长。

所以"精简"精简的从来不只是指令条数，而是四样东西一起：指令条数↓指令长度统一指令格式种类↓寻址方式↓

## 四、Load/Store 架构

RISC 中，只有 `LOAD`（内存 → 寄存器）和 `STORE`（寄存器 → 内存）两类指令可以访存，**所有运算都在寄存器之间进行**。

```
# Load/Store 风格：计算 A + B 存入 C
LOAD  R1, [A]
LOAD  R2, [B]
ADD   R3, R1, R2     ; 纯寄存器运算
STORE R3, [C]
```

```
# 允许直接访存的风格
ADD [C], [A], [B]    ; 一条指令完成，内部却要三次访存
```

上面那条 `ADD [C], [A], [B]` 正是"指令数少"的代价所在：它的执行时间取决于三次访存，与一条寄存器加法完全不在一个量级。**指令条数少不等于执行快。**

Load/Store 的真正收益是**规整**：把访存这个高延迟、时间不确定的动作隔离到两条专门的指令里，其余所有指令的执行时间都变得整齐划一。指令的长度和执行时间一致，流水线才切得均匀。

## 五、寄存器数量改变了参数传递方式

寄存器多不只带来"少访存"这一个好处，它还改变了**函数调用的约定**：

|  | 通用寄存器 | 参数怎么传 |
| --- | --- | --- |
| **RISC** | 多（典型为 32 个） | **前几个参数走寄存器**，超出的才压栈；返回值也走寄存器 |
| **CISC**（早期 x86） | 少（8 个） | 寄存器不够分，参数**普遍压栈**，被调用方从栈帧里按偏移读取 |

收益很直接：**一次调用省掉好几次访存**。参数放栈上意味着调用方写内存、被调用方再读内存；放寄存器则完全不碰内存。函数调用在真实程序里极其频繁，这点开销累积起来相当可观。栈帧与参数传递的细节见 [[03_计算机组成原理_CO/instruction/machine-level-repr.md|程序的机器级表示]]。

**编者注（辨析）**：x86-64 也用寄存器传参，它不是 CISC 吗？

是。但这恰好说明**寄存器传参的前提是"寄存器够多"**——x86-64 把通用寄存器从 8 个扩到 16 个之后才有条件这么做。"RISC 多采用寄存器传参"描述的是它的典型做法，而不是一条只有 RISC 才能满足的排他性定义。

## 六、控制器：硬布线还是微程序

|  | 微程序控制 | 硬布线控制 |
| --- | --- | --- |
| 怎么产生控制信号 | 把每条指令分解为微操作序列，存在控制存储器（ROM）里，逐条取出 | 用**组合逻辑电路**直接产生 |
| 速度 | 慢（每个微操作都要访问一次控制存储器） | 快（一级组合逻辑延迟） |
| 修改 | 改 ROM 内容即可，灵活 | 要重新设计电路，困难 |
| 适合 | 指令复杂、种类多 | 指令简单、规整、数量少 |

两者的分工是**被指令系统逼出来的**，而不是设计者的偏好：

- CISC 指令种类多、每条指令的微操作序列长且各不相同——用组合逻辑实现，电路规模会爆炸，所以只能用微程序把复杂性搬进 ROM 里。
- RISC 指令少而规整，硬布线的电路规模完全可控，于是可以享受组合逻辑的速度优势。

这也回到了第二节的主线：**微程序控制的查表延迟撑不住"大部分指令一个周期完成"这个目标**，选硬布线不是偏好，而是必需。

## 七、从机器代码上能看出什么

两种风格的差异并不停留在概念层面，它们在生成的机器代码上留下了三处可以直接观察到的痕迹。

**痕迹一：指令长度是否参差。** 这是最外显的一条。定长指令机器上，任意相邻两条指令的地址差恒为同一个数（如 4）；变长指令机器上，这个差值随指令不同而变化。

```
00401020  55            push ebp                     ← 1 字节
0040105E  39 4D F4      cmp  dword ptr [ebp-0Ch],ecx ← 3 字节
00401066  D1 E2         shl  edx,1                   ← 2 字节
0040107F  C3            ret                          ← 1 字节
```

同一段代码里出现 1、2、3 字节三种长度，说明这是变长指令机器。RISC 则相反——定长指令字是它整套设计的地基，格式规整、译码与流水线都建立在这个前提上。

**痕迹二：运算类指令能不能直接带内存操作数。** 上面那条 `cmp` 是比较指令，一个操作数却直接是内存单元 `[ebp-0Ch]`。在 Load/Store 架构里这是不允许的——比较之前必须先 `LOAD` 到寄存器。**内存操作数出现在非 Load/Store 指令上，就说明这台机器不是 Load/Store 架构。**

**痕迹三：寄存器的组织方式。** 少量、带专用名称的寄存器（`eax`、`ebp`、`ecx` 这类历史称呼）是 CISC 的典型特征；大量、按编号排列且用途高度对称的寄存器组（32 个通用寄存器）则是 RISC 的做法。这一条不构成独立判据，但能把观察结果落到具体架构上。

三处痕迹互相印证的原因，正是第二节那个闭环：**定长指令、Load/Store、大寄存器组是同一套设计的三个侧面**，很难只出现其中一样。

## 核心对比表

| 特性 | CISC | RISC |
| --- | --- | --- |
| 指令集规模 | 大（数百条） | 小（几十条） |
| **指令长度** | **变长** | **定长** |
| **指令格式种类** | **多** | **少，且字段位置对齐** |
| 寻址方式 | 多种复杂方式 | 少 |
| 内存访问 | 指令可直接访存 | **只有 Load/Store 访存** |
| 通用寄存器 | 少 | 多 |
| 过程调用传参 | 多用栈 | 多用寄存器 |
| 控制器实现 | 微程序（ROM） | 硬布线（组合逻辑） |
| 平均 CPI | 远大于 1 | **接近 1** |
| 流水线 | 难以直接实现，需先拆成微操作 | **整套设计就是为流水线服务的** |
| 编译器要求 | 低 | 高（依赖编译优化） |

## 易混淆知识点

**1. "RISC 大多数指令在一个时钟周期内完成"——这句话说的是延迟还是吞吐？**

**吞吐**。必须分清两个量：

| 量 | 含义 | 五级流水线的值 |
| --- | --- | --- |
| **延迟**（一条指令走完全程） | 从取指到写回经过几个周期 | **5 个周期** |
| **吞吐**（每周期完成几条） | 稳态下平均每个时钟周期完成多少条 | **1 条/周期**，即 CPI ≈1 |

这句话说的是第二行——流水线满载后，每来一个时钟就有一条指令从末端走出来。**不是**说一条指令从头到尾只花一个周期（那是单周期 CPU 的特征，而单周期 CPU 的时钟周期长得离谱）。

两句话不矛盾：**每条指令仍要走 5 个周期，但 5 条指令是重叠着走的。** CISC 做不到这一点，是因为它的指令复杂度差异太大，没法均衡地切成流水段。

**2. 指令条数少，是不是就等于程序跑得快？**

不等于。执行时间是 P=I×C×T 三个因子的乘积，指令条数只是 I。

RISC 的 I 比 CISC **大** 20%~40%，靠的是把 C 和 T 压下去才赢的。反过来，CISC 那条 `ADD [C], [A], [B]` 虽然只算一条指令，执行时间却由三次访存决定。

**3. 定长指令和格式种类少，是一回事吗？**

不是，是两个独立维度。定长说的是"一条指令占多少位"，格式种类说的是"这些位怎么切分成字段、有几套切法"。

同样 32 位定长，切法可以有几十种。RISC 两样都要——**定长让取指简单，格式少让译码能与读寄存器并行**。

**4. RISC 是不是"难以采用流水线"？**

恰好相反。RISC 的定长指令、规整格式、Load/Store 架构，**整套设计就是为流水线服务的**：定长使取指周期固定，格式规整使译码与读寄存器可并行，Load/Store 使访存集中在固定的一段。

难以直接流水的是 CISC——变长指令使取指边界不确定，指令复杂度悬殊使各段无法均衡。现代 x86 的做法是先把复杂指令拆成微操作，再对微操作流水。

**5. 微程序控制"灵活"，为什么 RISC 反而不用？**

因为灵活的代价是速度。微程序控制每产生一组控制信号都要访问一次控制存储器，这个延迟和 RISC"大部分指令一个周期完成"的目标直接冲突。

而 RISC 指令少且规整，硬布线的组合逻辑规模完全可控，"设计复杂、修改困难"这个缺点的分量因此变得很轻。**技术选择取决于指令系统给了什么前提条件。**

**6. 现在还有纯粹的 CISC 和纯粹的 RISC 吗？**

基本没有。现代 x86 在外部维持 CISC 接口以保证软件兼容，内部把复杂指令翻译成微操作、用类似 RISC 的核心执行。

RISC 阵营也在变复杂——随着处理器速度和芯片密度提高，RISC 系统日趋复杂。RISC 最终没有在个人计算机与服务器市场取代 x86，主要原因有两条：**软件的向后兼容性**（用户先期投资的软件换架构就要重新投入），以及 CISC 吸收了部分 RISC 技术后性能大幅提升。而在移动设备和嵌入式领域，RISC 处理器则占据绝对优势。

## 本节小结

- CISC 的复杂化由两条推力造成：**软件向后兼容**（指令只增不减）与**缩小机器指令和高级语言的语义差距**
- **80-20 规律**：80% 的语句只用到 20% 的指令，且都是简单指令——这条规律同时否掉了复杂化的收益与理由
- CISC 的代价是实打实的：控制器约占**60% 的芯片面积**，设计、验证与实现都更困难
- RISC 的目的**不是精简指令本身**，而是通过简化结构提高性能；主线是**减少指令的执行周期数**
- 执行时间 P=I×C×T；RISC 的 I 反而比 CISC **多 20%~40%**，靠压低 C 与 T 取胜
- RISC 七条特征互相支撑：简单指令、**格式规整（定长 + 格式少 + 寻址方式少）**、Load/Store、大量通用寄存器、流水线、**硬布线控制**、优化编译
- **指令定长 ≠ 指令格式种类少**，是两个独立维度；格式种类少的价值在于**让译码与读寄存器并行**
- Load/Store 的收益是**规整**而非条数——把高延迟的访存隔离到两条指令里，其余指令执行时间才整齐
- 寄存器多改变了调用约定：**RISC 前几个参数走寄存器，CISC 寄存器不够故多用栈**
- 控制器选择是被指令系统逼出来的：**微程序的查表延迟撑不住"一个周期完成一条指令"**，所以 RISC 必须用硬布线
- "大多数指令一个时钟周期完成"说的是 **CPI ≈1 的吞吐**，不是一条指令只走一个周期
- 机器代码上的三处痕迹：**指令长度是否参差**、**运算指令能否直接带内存操作数**、**寄存器组织方式**——三者同源于同一套设计
- 现代处理器多为混合架构：x86 外部保持 CISC 接口、内部用 RISC 风格的微操作执行
