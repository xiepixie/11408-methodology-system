# 假脱机技术（SPOOLing）

2026 大纲 **五（二）3 假脱机技术（SPOOLing）**，属「设备独立软件」层。

## 速查

| **SPOOLing 是什么** | Simultaneous Peripheral Operations On-Line，"在**联机**情况下实现的**同时**外围操作"。用多道程序模拟脱机时的外围控制机——效果像脱机，实际并没有离开主机 |
| --- | --- |
| **三个前提条件** | ① **通道技术**：外围操作要能脱离 CPU 自行完成传送，否则"同时"就无从谈起 ② **多道程序设计**：输入/输出进程要与用户进程并发（单道系统里模拟程序一跑用户程序就停，等于没解决）③ **高速随机外存（通常为磁盘）作后援**：井要大容量、长驻留、**可随机存取**（输出进程按队列取某个进程的数据），磁带做不到随机存取所以做不了井 |
| **三个特点（缺一不算讲全）** | **① 提高了 I/O 速度**：I/O 对象从低速设备变成磁盘；**② 将独占设备改造为共享设备**：系统并没真给谁分配设备，只分了空闲盘块和 I/O 请求表；**③ 实现了虚拟设备功能**：每个进程都认为自己独占一台逻辑设备 |
| 🔴 **②③ 最容易只写一半** | **② 是系统视角**说"设备被共享了"，**③ 是进程视角**说"我以为我独占"。同一件事的两面，但是两条独立结论 |
| 🔴 **打印机物理上仍一次只打一份，凭什么说共享** | 判据是**进程有没有被独占设备卡住**。进程申请到的是**输出井里一块盘块 + 一张请求打印表**，写进去就能返回继续跑。设备的独占性没变，变的是进程不必等到设备空闲才能推进 |
| 🔴 **不会因打印机死锁，破坏的是"互斥"** | 打印机原本是互斥使用的独占资源，占着它别人就得等，所以能进循环等待环。SPOOLing 后进程申请的是**磁盘盘块**（可共享，申请了立刻拿到），物理打印机只被后台的假脱机打印进程独家使用，**没有第二个进程去争** → 互斥条件不成立。⚠️ 这只是把打印机移出候选名单，系统仍可能因别的独占资源（磁带机、绘图仪）死锁 |
| 🔴 **井 vs 缓冲区** | 井在**磁盘**、缓冲区在**内存**；判据是**数据要驻留多久、量有多大**：井要容纳多个进程排队等待处理的全部数据，缓冲区服务于一次正在进行的传输、取走即释放。两者是**串联的两级**，不是二选一 |
| 🔴 **一个井文件不能放多个进程的数据** | 教材规定"一个文件仅存放某一个进程的输入（或输出）数据"。因为输出进程是按队列**逐个任务**取数据去打印的，混在一起就无法切分，打印结果会串 |
| **SPOOLing vs 脱机技术** | 脱机靠**专用外围机 + 磁带**，在主机运行**前/后**进行、与主机不同时工作；SPOOLing 靠**软件（多道程序）+ 磁盘**，与主机**同时**运行 |

## 一、从脱机技术到假脱机

20 世纪 50 年代，为缓和 CPU 高速与 I/O 设备低速的矛盾，人们引入**脱机输入/输出技术**：用**专门的外围控制机**先把低速设备上的数据搬到高速磁带/磁盘上，主机需要时直接从高速设备读，输出反之。代价是要多买一台外围控制机，而且它与主机**不同时工作**。

多道程序技术出现后，一个自然的想法是**用一道程序去模拟那台外围控制机**：

有了多道程序 ⇒ 可以专门开一道程序守在低速输入设备旁，把数据源源不断搬到磁盘（模拟脱机输入） ⇒ 再开一道程序守在低速输出设备旁，把磁盘上的数据慢慢送出去（模拟脱机输出） ⇒ 这两道程序与用户程序**在同一台主机上同时运行** ⇒ 效果与脱机相同，却不需要外围控制机

## 二、SPOOLing 系统的组成

| 组件 | 位置 | 说明 |
| --- | --- | --- |
| **输入井** | 磁盘 | 模拟脱机输入时的磁盘，收容输入设备送来的数据 |
| **输出井** | 磁盘 | 模拟脱机输出时的磁盘，收容用户程序的输出数据 |
| **输入缓冲区** | 内存 | 暂存输入设备送来的数据，再转入输入井；缓和 CPU 与磁盘的速度差 |
| **输出缓冲区** | 内存 | 暂存从输出井取出的数据，再送往输出设备 |
| **输入进程**（预输入进程） | —— | 模拟脱机输入的外围控制机：设备 → 输入缓冲区 → 输入井 |
| **输出进程**（缓输出进程） | —— | 模拟脱机输出的外围控制机：输出井 → 输出缓冲区 → 设备 |
| **井管理程序** | —— | 控制作业与磁盘井之间的信息交换；进程发出 I/O 请求时由 OS 调用它去读输入井或写输出井 |

井里的数据**以文件的形式**组织管理，称为**井文件**：一个井文件只存放某一个进程的输入（或输出）数据，所有进程的输入（输出）文件**链接成一个输入（输出）队列**，输出进程按队列次序逐个处理。

## 三、共享打印机：SPOOLing 的典型应用

假脱机打印系统由三部分组成：**磁盘缓冲区**（即输出井，其中可设置空盘块队列、满盘块队列等）、**打印缓冲区**（设在内存，缓和 CPU 与磁盘的速度差）、**假脱机管理进程**与**假脱机打印进程**。

用户进程发出打印请求后，系统**并不把打印机分配给它**，而是由**假脱机管理进程**做两件事：① 在磁盘缓冲区中为它**申请一个空闲盘块**，把要打印的数据送进去暂存；② 为它**申请一张空白的用户请求打印表**，填入打印要求（数据在井中的位置、份数、格式等），再把这张表**挂到假脱机文件队列（请求打印队列）上**。这两件事做完，虽然一个字都还没印出来，但**对用户进程而言打印请求已经得到满足**。

真正的打印由**假脱机打印进程**负责：打印机空闲时从队列**队首摘取一张请求打印表** → 按表中要求把数据从**输出井**传送到**内存缓冲区** → 交付打印机打印 → 完成后再看队列，非空则重复，**队列为空则把自己阻塞**，直到再有打印请求时被唤醒。

> [!TIP]
>

守护进程是同一思路的另一种实现

把假脱机管理进程取消，改为给打印机建一个**守护进程（daemon）**：由守护进程为用户在磁盘缓冲区申请空闲盘块并返回盘块首址，用户进程自己生成一份"请求打印文件"放进假脱机文件队列（目录）。**守护进程是允许使用打印机的唯一进程**，其他进程一律只能写文件、不能直接碰设备。

推广到一般结论就是：**凡是要把独占设备改造成可共享设备，都可以为它配一个守护进程 + 一个假脱机文件队列。**

## 本节小结

- SPOOLing 用多道程序 + 磁盘模拟脱机时的外围控制机，三个前提是**通道技术**、**多道程序设计**与**高速随机外存作后援**；组成是输入井/输出井、输入/输出缓冲区、输入/输出进程与井管理程序，井中数据以**井文件**形式组织并链成队列。
- 三个特点分处三个层面：**提高 I/O 速度**（性能）、**把独占设备改造为共享设备**（系统视角的并发）、**实现虚拟设备功能**（进程视角的抽象）。
- 共享打印机的落法是"申请盘块 + 填请求打印表挂队列即返回，后台进程按队列逐份打印"；由此**不会因打印机死锁**，破坏的是**互斥**条件。教材出处

- SPOOLing 建立在通道技术与多道程序技术基础上、以高速随机外存为后援，四部分组成（输入井/输出井、输入/输出缓冲区、输入/输出进程、井管理程序），井文件与井队列的组织：同书 6.6.2 节，印刷 p206–207
