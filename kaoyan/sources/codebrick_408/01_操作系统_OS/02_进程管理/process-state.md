# 进程状态与转换

2026 大纲 **二（一）2 进程/线程的状态与转换**。

## 速查

| **三状态怎么推出来** | ① 占着 CPU 吗？占着 ⇒ **运行**；② 没占着的话，**除 CPU 外的资源齐了吗**？齐了 ⇒ **就绪**，没齐 ⇒ **阻塞** |
| --- | --- |
| 🔴 **就绪与阻塞的分界** | 就绪缺的只有 CPU，一给就能跑；阻塞态把 CPU 给它也跑不了 |
| **运行态有几个** | 单处理机同一时刻只有一个；**多处理机可以有多个**，有几个 CPU 就最多几个 |
| **五状态 = 三状态 +** | **创建态**（已申请 PCB，资源尚未配齐，不可调度）+ **终止态**（已停止执行，等待回收 PCB 与其余资源） |
| 🔴 **"运行→就绪"以抢占式为前提** | **非抢占式调度里根本没有这条边**——进程上了 CPU 只有自己阻塞或结束才下来。题干说"非抢占式"，涉及这条边的选项可直接排除 |
| 🔴 **三类不可能的转换** | **就绪→阻塞**（发 I/O 请求只能由正在运行的进程做出，就绪态一条指令都执行不了）、**阻塞→运行**（事件完成只能回到就绪，中间少不了调度这一步）、**终止→任何状态** |
| 🔴 **运行→阻塞 vs 阻塞→就绪，谁发起** | 判据是"谁知道该等什么"：只有正在运行的进程知道自己缺哪个资源 ⇒ 运行→阻塞由**进程自身主动**；阻塞后不再运行、不可能自我唤醒 ⇒ 阻塞→就绪必然**被动**，由 OS 或中断处理程序完成 |
| 🔴 **挂起不等于内存不足** | 发起者有四类：**终端用户、父进程请求、负荷调节、操作系统需要**。前三类与内存够不够毫无关系——**动因是"要让它静止下来"，换出外存只是手段** |
| **挂起把两态各劈成两半** | 活动就绪 Readya / 静止就绪 Readys、活动阻塞 Blockeda / 静止阻塞 Blockeds（后者也叫挂起就绪、挂起阻塞，两套名字都要认得） |
| 🔴 **挂起与阻塞正交** | 挂起看**进程映像在内外存哪一边**、由外力发起、靠激活解除；阻塞看**等不等事件**、由自己发起、靠事件完成解除。正因正交才有 2×2 四种组合，挂起不是"第四种状态" |
| 🔴 **两条最容易漏的边** | **静止阻塞 → 静止就绪**（进程虽在外存，它等的事件照样会完成）、**创建 → 静止就绪**（资源与性能不允许时不给新建进程分配主存，先放外存不参与调度） |
| **线程也有三种基本状态** | 执行、就绪、阻塞，**转换关系与进程完全一致** |
| 🔴 **线程没有独立的挂起态** | 挂起的物理动作是把**进程映像换出外存**，而地址空间整个进程共享，没法只换出一条执行流。教材口径：挂起某进程时其**所有线程一起被挂起**。"线程七状态模型"不成立 |
| 🔴 **同一句"线程阻塞"，两类实现结果相反** | 判据是**内核认不认识线程**：内核支持的线程各自是内核眼中的调度对象，一个阻塞不影响其他；线程库支持的线程对内核不可见，内核把**整个进程**置为阻塞 ⇒ **一个阻塞，全部阻塞** |
| **用户级线程的两级状态** | 线程库维护的线程状态 + 内核维护的进程状态，**打架时以内核那一级为准**。这也解释了用户级线程用不上多核 |
| **状态队列** | 就绪队列（常按优先级排）、按阻塞原因分开的若干阻塞队列、存放未使用 PCB 的空闲队列 |

## 一、五状态模型与六条合法转换

| 转换 | 触发条件 | 由谁完成 | 前提 |
| --- | --- | --- | --- |
| 创建→就绪 | 系统完成创建，资源分配到位 | 操作系统（创建原语） | 内存等资源允许 |
| 就绪→运行 | 调度程序选中该进程 | 调度程序 | — |
| 运行→就绪 | 时间片用完，或被更高优先级进程抢占 | 操作系统/调度程序 | **必须是抢占式调度** |
| 运行→阻塞 | 主动请求等待某事件（I/O、P 操作、申请资源失败） | **进程自身**（主动） | 进程必须正在运行 |
| 阻塞→就绪 | 所等事件已发生（I/O 完成、V 操作） | 操作系统/中断处理程序（被动） | — |
| 运行→终止 | 正常结束、异常结束或被外界终止 | 进程自身/操作系统 | — |

时间片轮转、抢占式优先级这类算法必然是抢占式的，先来先服务、非抢占式短作业优先里不会出现"运行→就绪"。抢占与非抢占的分界见 [[01_操作系统_OS/02_进程管理/scheduling-concept.md|调度的基本概念与目标]]。

## 二、挂起与七状态模型

挂起（Suspend）是把进程**换出到外存**、使之处于静止状态的操作，与之对应的是**激活**（Active）。四类发起者的具体场景：

| 发起者 | 场景 |
| --- | --- |
| **终端用户** | 用户发现自己程序运行可疑，希望暂停下来研究执行情况或修改程序 |
| **父进程请求** | 父进程要查看、修改某个子进程，或协调各子进程的活动 |
| **负荷调节的需要** | 系统负荷过重、已影响到实时任务的响应时，把不重要的进程挂起以保证系统正常运行 |
| **操作系统的需要** | OS 要检查资源使用情况或进行记账；以及虚拟存储系统中内存吃紧，把进程换出外存 |

引入挂起后，原来的就绪态和阻塞态各自按"在不在内存、参不参与调度"分裂成两个。"活动/静止"是汤小丹教材的命名，"挂起就绪/挂起阻塞"是另一种常见叫法，指的是同一批状态——**两套名字都要认得**：

| 教材命名 | 别称 | 含义 |
| --- | --- | --- |
| **活动就绪** Readya | 就绪 | 未被挂起的就绪态，在内存中，可以接受调度 |
| **静止就绪** Readys | 挂起就绪 | 已被挂起，进程映像在外存，**不再被调度执行** |
| **活动阻塞** Blockeda | 阻塞 | 未被挂起的阻塞态，在内存中等事件 |
| **静止阻塞** Blockeds | 挂起阻塞 | 已被挂起，进程映像在外存，同时还在等事件 |

图源：汤小丹《计算机操作系统》图 2-8 具有创建、终止和挂起状态的进程状态图，印刷 p39

对着图把完整的边清单过一遍（前四条直接由 Suspend / Active 两个原语给出）：

| 转换 | 什么时候发生 |
| --- | --- |
| 活动就绪 → 静止就绪 | 挂起 |
| 静止就绪 → 活动就绪 | 激活（换入内存） |
| 活动阻塞 → 静止阻塞 | 挂起 |
| 静止阻塞 → 活动阻塞 | 激活 |
| 执行 → 静止就绪 | 正在运行的进程被挂起（如用户或父进程发出 Suspend） |
| 活动阻塞 → 活动就绪 | 事件完成（这就是五状态里的"阻塞→就绪"） |
| **静止阻塞 → 静止就绪** | 进程在外存期间，它等待的事件完成了 |
| **创建 → 活动就绪** | 系统性能和内存容量都允许，创建工作全部完成，直接进内存待调度 |
| **创建 → 静止就绪** | 考虑当前资源状况与性能要求，**不给新建进程分配主存**，先放外存、不参与调度——此时创建工作尚未完成 |

## 三、线程的状态与转换

|  | 线程库支持的线程（用户级线程） | 内核支持的线程（内核级线程） |
| --- | --- | --- |
| 谁维护线程状态 | 用户空间的线程库 | 内核 |
| 内核眼里的调度对象 | 只有进程 | 每个线程 |
| 一个线程执行阻塞式系统调用 | 内核不知道有线程，把**整个进程**置为阻塞态；同进程其余线程即使在线程库里记着"就绪"，也拿不到 CPU | 内核只把**这一个线程**置为阻塞态，同进程的其他线程照样可被调度 |
| 结论 | **一个阻塞，全部阻塞** | 一个阻塞不影响其他 |

两类线程的实现细节见 [[01_操作系统_OS/02_进程管理/thread.md|线程]]；执行状态转换的那组原语与状态队列的三种组织方式见 [[01_操作系统_OS/02_进程管理/process-control.md|进程的组织与控制]]。一条含挂起的完整事件序列，逐步走出每次转换与转换次数统计（想在时间轴上看清状态怎么跳时展开）

单处理机系统采用**抢占式**优先级调度，优先级 P1 > P2 > P3。三个进程创建完成后依次发生：t0 调度程序开始工作；t1 P1 发出 I/O 请求；t2 P1 的 I/O 完成；t3 内存紧张，操作系统挂起 P3；t4 P1 执行完毕；t5 内存恢复充裕，操作系统激活 P3。

| 时刻 | 发生的转换 | 这一步为什么这么走 |
| --- | --- | --- |
| t0 | P1：就绪→运行 | 三个都在就绪队列，抢占式优先级下选优先级最高的 P1 |
| t1 | P1：运行→阻塞P2：就绪→运行 | I/O 请求只能由正在运行的进程发出，所以是"运行→阻塞"而非"就绪→阻塞"；CPU 空出来必须重新调度，就绪者中 P2 优先级最高 |
| t2 | P1：阻塞→就绪P2：运行→就绪P1：就绪→运行 | 事件完成只能把 P1 送回**就绪**（没有"阻塞→运行"）；P1 优先级高于正在运行的 P2，抢占式下 P2 被踢回就绪；再调度，P1 上 CPU |
| t3 | P3：活动就绪→静止就绪 | 挂起的是就绪态进程，落到静止就绪；P3 本来就没在 CPU 上，不影响运行者 |
| t4 | P1：运行→终止P2：就绪→运行 | 正常结束；CPU 空出，就绪者中只剩 P2（P3 在静止就绪，**不参与调度**） |
| t5 | P3：静止就绪→活动就绪 | 激活换入内存，重新参与调度；但 P2 正在运行且此刻无更高优先级者抢它，P2 继续 |

共 **10** 次状态转换：就绪→运行 4 次、运行→就绪 **1** 次、运行→阻塞 1 次、阻塞→就绪 1 次、运行→终止 1 次、活动就绪→静止就绪 1 次、静止就绪→活动就绪 1 次。末态：P1 终止、P2 运行、P3 就绪。

把"抢占式"改成"非抢占式"，t2 处 P2 不会被踢下 CPU（没有"运行→就绪"这条边），P1 只能停在就绪态等 P2 让出，转换次数减少 2 次。**调度方式是这类推演的隐含前提，题干不写就要自己认出来。**

## 本节小结

- 三状态由两个追问推出（占不占 CPU、除 CPU 外资源齐不齐）；五状态补上创建态与终止态；六条合法转换里**只有"运行→就绪"依赖抢占式调度**，而就绪→阻塞、阻塞→运行、终止→任何状态三类永不发生。
- 挂起的动因是"要让它静止下来"（四类发起者），换出外存只是手段；**挂起与阻塞是正交的两个维度**，2×2 组合出活动/静止的就绪与阻塞，构成七状态模型。
- 线程有执行/就绪/阻塞三态且转换与进程相同，但**没有独立挂起态**；一个线程阻塞会不会拖垮全进程，取决于**内核认不认识线程**。教材出处

- 汤小丹《计算机操作系统》2.2.2 进程的基本状态及转换，印刷 p36：就绪、执行、阻塞三种状态的定义，以及"多处理机系统中则有多个进程处于执行状态"
- 汤小丹《计算机操作系统》2.2.3 挂起操作和进程状态的转换，印刷 p38：引入挂起的四类原因（终端用户、父进程请求、负荷调节、操作系统需要）；活动就绪 Readya / 静止就绪 Readys / 活动阻塞 Blockeda / 静止阻塞 Blockeds 的命名与四条转换；"创建→静止就绪"的条件
- 汤小丹《计算机操作系统》图 2-8 具有创建、终止和挂起状态的进程状态图，印刷 p39
- 汤小丹《计算机操作系统》2.7.3 线程的状态和线程控制块，印刷 p78：线程运行的三个状态，"线程状态之间的转换和进程状态之间的转换是一样的"；"在把某个进程挂起时，该进程中的所有线程也都将被挂起"
- 汤小丹《计算机操作系统》2.8.1 线程的实现方式，印刷 p80：用户级线程"当线程执行一个系统调用时，不仅该线程被阻塞，而且进程内的所有线程会被阻塞"
