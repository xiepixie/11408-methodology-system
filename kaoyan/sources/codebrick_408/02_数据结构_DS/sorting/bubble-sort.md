# 冒泡排序

## 大纲定位

本篇对应 2026 大纲 **七、排序 （四）起泡排序（bubble sort）**（即冒泡排序，两个名字指同一个算法，本篇统一用"冒泡"）。

分工边界：

- 本篇负责冒泡排序本身——**算法不变量、提前终止的判据与它对最好情况的决定作用、比较与交换次数的推导、稳定性证明、与简单选择排序的对照**。
- 冒泡排序是**交换类**排序的基础形式；它的改进版 [快速排序](./quick-sort.html)（一次交换可消除多个逆序对）在另一篇。
- "每趟确定一个元素最终位置"这一族性质的横向用法在 [由中间状态反推排序算法](./identify-state.html)。
- 稳定性、"一趟"的定义等公共概念在 [排序的基本概念](./concepts.html)。

## 知识框架

本节回答四个问题：

- 每一趟结束后数组处于什么状态？为什么这个状态比插入排序的"前缀有序"要强？
- 最好情况 O(n) 是算法本身的性质，还是某个可选优化的产物？
- 一次交换要写几条赋值语句？这为什么导致同为 O(n2) 的冒泡排序实际比直接插入排序慢？
- 冒泡排序为什么稳定？把哪个符号写错就不稳定了？

## 核心思想

从头到尾扫一遍，**逐对比较相邻的两个元素**，若逆序（前者大于后者）就交换。一趟扫完，当前未排序区里最大的元素必然被一路交换到区间末尾——像气泡浮到顶端一样。然后未排序区缩小一个，重复。

### 算法不变量

**第 i 趟（i=1,2,…）结束后，数组末尾的 i 个元素是整个序列中最大的 i 个，且已按升序排好、位置永不再变。前 n−i 个元素只经历过相邻交换。**

"末尾 i 个是**全局**最大的 i 个"这一句比插入排序的"前缀局部有序"强得多——它意味着**每趟至少有一个元素到达最终位置**。这一族性质（交换类与选择类共有、插入类与归并类没有）是判别中间状态的核心线索。

同时要注意后半句：**前 n−i 个元素只经历过相邻交换**。这是冒泡与堆排序的分界——两者的尾部看起来一模一样（都是"最大的 i 个已就位"），但堆排的前部必须满足堆序，冒泡的前部一般不满足。

以升序为例，每一趟的效果：

```
第 1 趟：把最大元素交换到 a[n-1]
第 2 趟：把次大元素交换到 a[n-2]
  ...
第 n-1 趟：整个序列有序（若中途某趟无交换则可提前结束）
```

## 操作详解

### 基本实现
c

```
void BubbleSort(int a[], int n) {
    for (int i = 0; i < n - 1; i++) {          // 最多 n-1 趟
        for (int j = 0; j < n - 1 - i; j++) {  // 已就位的末尾 i 个不再参与比较
            if (a[j] > a[j + 1]) {             // 严格大于才交换 —— 稳定性靠这里
                int tmp = a[j];
                a[j] = a[j + 1];
                a[j + 1] = tmp;                // 一次交换 = 3 条赋值
            }
        }
    }
}
```

内层上界 `n - 1 - i` 是关键：第 i 趟（i 从 0 计）时末尾已有 i 个元素就位，比较到 `a[n-2-i]` 与 `a[n-1-i]` 为止即可，再往后比就是白做。

边界：`n <= 1` 时外层循环条件 `0 < n - 1` 不成立，直接返回，**空表与单元素表安全**。

### 提前终止优化

若某一趟**一次交换都没发生**，说明当前未排序区内已经没有任何逆序的相邻对——而"任意相邻对都不逆序"等价于"整个区间有序"，因此后续所有趟都可以跳过。c

```
void BubbleSort(int a[], int n) {
    for (int i = 0; i < n - 1; i++) {
        bool swapped = false;                  // 本趟是否发生过交换
        for (int j = 0; j < n - 1 - i; j++) {
            if (a[j] > a[j + 1]) {
                int tmp = a[j];
                a[j] = a[j + 1];
                a[j + 1] = tmp;
                swapped = true;
            }
        }
        if (!swapped) break;                   // 本趟无交换 ⇒ 已有序，直接结束
    }
}
```

**"相邻对都不逆序 ⇒ 整体有序"为什么成立？** 因为 ≤ 具有传递性：若 a0≤a1、a1≤a2、…、am−1≤am，则任意 ai≤aj (i<j)。这是冒泡排序独有的便利——它只看相邻对，所以"局部无逆序"直接推出"全局有序"。快速排序、堆排序都没有这样简单的终止判据。

**这个判断不是可有可无的：最好情况 O(n) 完全由它提供。** 没有 `swapped` 标志时，即使输入已经有序，外层循环也会照样跑满 n−1 趟、做 n(n−1)/2 次比较，最好情况也是 O(n2)。本篇后续所有"最好 O(n)"的说法，都以带这个标志的版本为准。

### 不变量的证明

上面那条不变量"第 i 趟后末尾 i 个元素已就位"，为什么成立？

**证明第 1 趟**：内层循环从 j=0 走到 j=n−2，每一步都把 a[j] 与 a[j+1] 中较大者留在右边。设当前区间的最大值初始在下标 p。当 j 走到 p 时，比较 a[p]（最大值）与 a[p+1]，因为它最大，必然发生交换，最大值移到 p+1；接下来 j=p+1，同样的道理它又移到 p+2……**最大值一旦被扫描指针"接住"，就会被一路推到末尾**。所以第 1 趟结束时 a[n−1] 一定是全局最大值，且它已在最终位置。

**归纳**：第 i 趟只在 a[0..n−1−i] 上工作，把这个子区间的最大值推到 a[n−1−i]。由归纳假设，a[n−i..n−1] 已经是最大的 i 个且有序，而子区间的最大值不大于它们，所以放在 a[n−1−i] 处正合适。◻

这个证明同时解释了内层上界为什么可以写成 `n - 1 - i`——已就位的部分不需要再参与比较。

### 更强的提前终止：记录最后一次交换的位置

`swapped` 标志只回答了"有没有交换"。更多的信息其实就在手边：**本趟最后一次交换发生在哪个位置**。

设本趟最后一次交换发生在 j=last（即交换了 a[last] 与 a[last+1]），那么 a[last+1..] 这一段在本趟中**再也没有发生过交换**，说明它们两两之间已经不逆序；又因为 a[last+1] 是被从左边推过来的、不小于它左边扫过的所有元素，所以 **a[last+1..n−1] 整段都已经就位**。于是下一趟只需在 a[0..last] 上做。c

```
void BubbleSort(int a[], int n) {
    int m = n - 1;                             // 本趟内层循环的右边界
    while (m > 0) {
        int last = 0;                          // 本趟最后一次交换的位置
        for (int j = 0; j < m; j++) {
            if (a[j] > a[j + 1]) {
                int tmp = a[j]; a[j] = a[j + 1]; a[j + 1] = tmp;
                last = j;
            }
        }
        m = last;                              // 下一趟只需处理 a[0..last]
    }
}
```

`m = last` 一句同时完成了两件事：**若本趟无交换则 `last` 仍为 0，`m` 变 0，循环自然结束**（等价于 `swapped` 标志）；**若有交换，则一次可能跳过好几趟**。

举个能看出差别的例子：`{2, 1, 3, 4, 5, 6, 7, 8}`。

| 版本 | 过程 | 趟数 |
| --- | --- | --- |
| 标志位版 | 第 1 趟交换 (2,1) 后有序，但 `swapped` 为真；第 2 趟扫完无交换才终止 | **2** |
| 最后交换位置版 | 第 1 趟唯一一次交换发生在 j=0，故 `m = 0`，直接结束 | **1** |

两种写法排序结果完全一致（5000 组随机数据验证），只是后者对"局部无序"的输入更省一趟。

这一段的价值不在于多背一段代码，而在于示范一件事：**不变量越强，能省的工作就越多**。从"有没有交换"到"最后在哪交换"，多用了一点点信息，就把终止条件收紧了。

### 逐趟推演

**例一**：`{5, 3, 4, 1, 2}`

| 趟 | 本趟的比较与交换 | 本趟结果 | 已就位 |
| --- | --- | --- | --- |
| 1 | (5,3)换 (5,4)换 (5,1)换 (5,2)换 | 3 4 1 2 **5** | 5 |
| 2 | (3,4)不换 (4,1)换 (4,2)换 | 3 1 2 **4 5** | 4,5 |
| 3 | (3,1)换 (3,2)换 | 1 2 **3 4 5** | 3,4,5 |
| 4 | (1,2)不换 → 本趟无交换，提前终止 | **1 2 3 4 5** | 全部 |

合计比较 4+3+2+1=10 次，交换 8 次（= 24 条赋值）。

**例二**（含相等关键字，用于观察稳定性）：`{49, 38, 65, 97, 76, 13, 27, 49*}`

| 趟 | 结果 |
| --- | --- |
| 1 | 38 49 65 76 13 27 49* **97** |
| 2 | 38 49 65 13 27 49* **76 97** |
| 3 | 38 49 13 27 49* **65 76 97** |
| 4 | 38 13 27 49 49* **65 76 97** |
| 5 | 13 27 38 49 49* **65 76 97** |
| 6 | 本趟无交换 → 提前终止 |

注意第 4 趟：`49` 与 `49*` 在某一时刻成为相邻对，比较条件 `a[j] > a[j+1]` 即 `49 > 49` 为假，**不交换**，两者的先后关系被保住。最终 `49` 仍在 `49*` 前面。

本例共 6 趟（比 n−1=7 少一趟），这正是提前终止起作用的表现——**冒泡排序的趟数取决于初始序列**，这一点与直接插入排序、简单选择排序（都固定 n−1 趟）不同。

## 复杂度分析

### 比较次数

第 i 趟（i 从 1 计）做 n−i 次比较。若跑满 n−1 趟：KCNmax=∑i=1n−1(n−i)=n(n−1)2≈n22

在**逆序**输入上取到：每一趟都发生交换，`swapped` 恒为真，一趟也省不掉。KCNmin=n−1

在**正序**输入上取到：第 1 趟扫完一次交换都没有，立即终止。

平均情况仍是 O(n2)：只要序列中还存在任何逆序对，本趟就会有交换、就必须再来一趟；随机输入下几乎总要跑到接近 n−1 趟。

### 交换次数与移动次数

**关键观察：冒泡排序的一次交换，恰好消除一个逆序对**（交换的是相邻的两个元素，它们的先后关系翻转，而它们与其他任何元素的相对次序都没变）。而排序结束时逆序对数为 0。因此交换次数=原序列的逆序对数

于是三种情况一目了然：

| 输入 | 逆序对数 | 交换次数 | 移动次数（×3） |
| --- | --- | --- | --- |
| 正序 | 0 | 0 | 0 |
| 逆序 | n(n−1)2 | n(n−1)2 | 3n(n−1)2≈3n22 |
| 随机（期望） | n(n−1)4 | n(n−1)4 | 3n(n−1)4≈3n24 |

随机情况下逆序对数的期望为 n(n−1)/4：任取一对下标 (i,j)，i<j，两元素构成逆序的概率是 1/2，而这样的下标对共 (n2)=n(n−1)/2 个。

**"一次交换 = 3 条赋值"是冒泡排序最重要的常数因子。** 直接插入排序的一次"后移"只写一条赋值 `A[j+1] = A[j]`，而它的后移次数同样等于逆序对数。所以在同一个输入上：冒泡的赋值次数直接插入的赋值次数≈3×逆序对数1×逆序对数=3

这就是"两者同为 O(n2)，但直接插入排序实际快 3～5 倍"的来源——差的不是量级，是常数。

### 汇总

| 指标 | 结果 | 取到该值的输入 |
| --- | --- | --- |
| 最好时间复杂度 | O(n) | 正序，**且实现里带"本趟无交换即终止"的判断** |
| 最坏时间复杂度 | O(n2) | 逆序：比较 n(n−1)/2 次，移动 3n(n−1)/2 次 |
| 平均时间复杂度 | O(n2) | 随机：交换约 n(n−1)/4 次，移动约 3n(n−1)/4 次 |
| 空间复杂度 | O(1) | 只需 `tmp` 与 `swapped` 两个变量 |
| 趟数 | **与初始序列有关**，1∼n−1 趟 | 已有序时 1 趟即止 |
| 稳定性 | **稳定** | 见下 |
| 存储结构 | 顺序表、链表均可 | 只比较和交换**相邻**元素，链表上改指针即可 |

### 稳定性证明

冒泡排序是**稳定**的。

证明：唯一会改变元素相对次序的动作是相邻交换，其触发条件是 `a[j] > a[j+1]`——**严格大于**。两个关键字相等的元素若成为相邻对，条件为假，不交换；若不相邻，则它们中间隔着的元素要么比它们大、要么比它们小，交换只会发生在"一大一小"之间，无法把这两个相等元素的先后关系翻转过来。

**改一个符号就不稳定**：把 `a[j] > a[j+1]` 写成 `a[j] >= a[j+1]`，相等的相邻元素也会互换。反例 `[2a, 2b]`：正确版本输出 `2a, 2b`；错误版本第 1 趟就交换成 `2b, 2a`。

### 例题：由逆序对数直接算出交换次数

对序列 (3,8,7,4,1,5,2,6) 做升序冒泡排序，需要多少次交换？多少次移动（赋值）？

**解**：交换次数 = 逆序对数，所以只要数逆序对。逐个元素统计"它后面有几个比它小的"：

| 元素 | 3 | 8 | 7 | 4 | 1 | 5 | 2 | 6 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 其后比它小的个数 | 2 | 6 | 5 | 2 | 0 | 1 | 0 | 0 |

（例如 8 后面比它小的是 7、4、1、5、2、6，共 6 个。）逆序对数=2+6+5+2+0+1+0+0=16

所以**交换 16 次、移动 16×3=48 次**。

**为什么这么算对**：一次相邻交换恰好消除一个逆序对（被交换的两个元素先后关系翻转，它们与其他元素的相对次序不变），而排序结束时逆序对数为 0，所以交换次数必然等于初始逆序对数。

**顺带一个对照**：同一个序列用 [直接插入排序](./insertion-sort.html)，后移次数也是 **16**（后移同样消除一个逆序对），但每次只写 1 条赋值，共 16 条——**是冒泡 48 条的三分之一**。这一组数字把"两者同为 O(n2)、插入排序实际快 3 倍"落到了具体数上。

### 链式存储上的冒泡排序

冒泡排序只比较和交换**相邻**元素，而"相邻"在链表上就是"当前结点与它的后继"，因此它是少数几个能直接用于链表的排序之一：

- 用一个指针从头结点开始逐对比较 `p->data` 与 `p->next->data`；
- 逆序时**交换两个结点的数据域**即可（若记录很大，也可以改成摘链重接，但那样要多维护前驱指针）；
- 每趟结束把"已就位"的尾部缩短一个，或用上面的 `last` 指针记录本趟最后一次交换的结点。

复杂度不变，仍是 O(n2)——链表并没有省掉比较，只是省掉了下标运算。可用于链表的还有 [直接插入排序](./insertion-sort.html)、[简单选择排序](./selection-sort.html)、[二路归并排序](./merge-sort.html)、[基数排序](./radix-sort.html)。

### 适用场景与边界

- **基本有序的小规模数据**：提前终止让它接近 O(n)，代码也最短。
- **n 稍大就不该用**：移动次数是直接插入排序的 3 倍，而两者复杂度同阶——同样是 O(n2) 时，直接插入排序几乎在所有维度上都不劣。
- **链式存储可用**，这是它相对折半插入、希尔、快排、堆排的一个优势；但由于只能相邻交换，链表上的收益有限。
- **记录很大时不该用**：每次交换要搬 3 次整条记录，此时应选 [简单选择排序](./selection-sort.html)（最多 3(n−1) 次移动）。

## 易混淆知识点

| 对比项 | A | B | 判别依据 |
| --- | --- | --- | --- |
| **最好情况是否 O(n)** | 带 `swapped` 标志：O(n) | 不带标志：仍跑满 n−1 趟，O(n2) | 最好情况的结论**依赖实现**。答题时默认按带提前终止的版本，但要知道这个前提 |
| **冒泡就位的 vs 快排就位的** | 冒泡：就位的一定是当前未排序区的**全局最值** | 快排：就位的是**枢轴**，不一定是极值 | 拿就位的那个元素与两侧比：冒泡就位元素在最右且大于左边所有；快排枢轴只保证"左边全 ≤ 它、右边全 ≥ 它" |
| **冒泡 vs 堆排的中间状态** | 两者尾部都是"最大的 k 个已就位" | 前部：堆排必须满足堆序，冒泡一般不满足 | 按完全二叉树检查前部：ai≥a2i+1 且 ai≥a2i+2（0 起下标）。满足是堆排，不满足是冒泡 |
| **冒泡 vs 简单选择** | 冒泡：比较次数随输入变，交换次数最坏 n(n−1)/2 | 简单选择：比较次数恒 n(n−1)/2，交换次数最多 n−1 | 问"比较次数会不会随输入变"和"记录大不大"。记录大选简单选择，输入基本有序选冒泡 |
| **稳定 vs 不稳定** | 冒泡：**稳定** | 简单选择：**不稳定** | 同为 O(n2) 的交换型算法，差别在于冒泡只交换相邻元素（不可能跨越相等元素），选择排序的交换是远距离的 |
| **交换 vs 移动** | 交换次数 = 逆序对数 | 移动次数 = 3 × 交换次数 | 一次交换写三条赋值。数"移动次数"时别把交换按 1 次算 |

## 本节小结

学完本节，应该能够：

- **写出算法不变量**："第 i 趟后末尾 i 个是全局最大的 i 个且已就位，前部只经历过相邻交换"
- **给定序列逐趟写出结果**，并判断第几趟会因"无交换"而提前终止
- **说清提前终止的判据为什么正确**（相邻对无逆序 ⇒ 整体有序，靠 ≤ 的传递性），以及**最好情况 O(n) 完全依赖这个判断**
- **推出三种情况的比较与移动次数**：最坏 n(n−1)/2 次比较、3n(n−1)/2 次移动；最好 n−1 次比较、0 次移动；随机时交换次数期望 n(n−1)/4
- **用"交换次数 = 逆序对数"** 一句话导出上面三行
- **解释为什么同为 O(n2) 却比直接插入排序慢**：一次交换 3 条赋值 vs 一次后移 1 条赋值
- **证明其稳定性**，并给出把 `>` 写成 `>=` 的反例
- **与简单选择排序做四维对照**（比较次数是否随输入变、交换次数、稳定性、适用记录大小）

两条最关键的结论：

- **交换次数恒等于逆序对数**——冒泡排序全部的计数结论都从这一句推出来。
- **最好 O(n) 是"提前终止判断"的产物，不是算法骨架自带的性质。**

## 教材出处

- 起泡排序的算法步骤、算法描述（算法 8.4，其中用 `flag` 标记某趟是否发生交换、无交换则不再执行下一趟）、以 {49,38,65,97,76,13,27,49} 为例的逐趟过程（图 8.3，第六趟无交换即完成排序）：严蔚敏《数据结构（C 语言版）》（第 2 版），p242–p243
- 最好情况（正序）只需一趟、n−1 次比较且不移动记录；最坏情况（逆序）KCN=n(n−1)/2、RMN=3n(n−1)/2（每次交换要移动 3 次记录）；空间复杂度 O(1)：同书 p243
- 算法特点（稳定排序；可用于链式存储结构；移动记录次数较多，平均时间性能比直接插入排序差）：同书 p243
