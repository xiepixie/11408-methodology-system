# 计数排序

## 大纲定位

**本篇不在 2026 大纲范围内。** 大纲第七章"排序"只列到 **（十）基数排序**，计数排序不是其中任何一条的内容。

保留本篇的理由有两条：

- **它是理解 [基数排序](./radix-sort.html) 的前置。** 基数排序每一趟"按当前位分配-收集"，在顺序存储下的标准实现就是一次计数排序；而基数排序对"每趟必须稳定"的要求，落到实现上就是本篇第 3 步"**从后往前**扫描"这一个细节。不看这一篇，"为什么分配必须稳定"就只能死记。
- **它背后的"计数数组 / 标记数组"是一种通用的空间换时间手法**——当关键字取值范围有限时，用一个下标即取值的数组直接统计频次或标记存在性，可以把很多需要 O(nlog⁡n) 或 O(n2) 的问题压到 O(n)。这套手法在算法设计里反复出现，值得单独掌握一次。

**复习时的定位**：了解即可，不必按大纲条目的深度准备。真正需要掌握到"能手工模拟"的是 [基数排序](./radix-sort.html)。

## 知识框架

本节回答三个问题：

- 不比较元素，凭什么能确定每个元素的位置？
- 为什么要先做前缀和？前缀和的每一格具体表示什么？
- 为什么第 3 步必须**从后往前**扫描？从前往后会怎样？

## 核心思想

比较排序的信息来源是"两两比较的结果"，因而受 Ω(nlog2⁡n) 下界约束（推导见 [排序的基本概念](./concepts.html)）。计数排序换了一个信息来源：

对每个元素 x，只要知道**比 x 小的元素有多少个**，就能直接算出 x 在结果中的下标——完全不需要把 x 与任何元素比较。

而"比 x 小的元素有多少个"可以靠**统计频次 + 前缀和**在线性时间内一次性算出来。

三个特点：

- **非比较排序**：只统计每个值出现的次数，不做元素间的大小比较；
- **空间换时间**：需要额外的计数数组和输出数组；
- **要求元素取值范围有限**：适合整数且取值范围 k 不太大的场合。

### 算法步骤

设待排序数组 `A[0..n-1]`，元素取值范围为 [0,k]。

- **计数**：建计数数组 `C[0..k]`，扫描 `A`，统计每个值出现的次数——此时 `C[v]` = 值等于 v 的元素个数；
- **累加（前缀和）**：令 `C[v] += C[v-1]`（v 从 1 到 k）——此时 **`C[v]` = 值 ≤v 的元素总个数**；
- **输出**：**从后往前**扫描 `A`，对每个元素 `A[i]`，把它放到输出数组的下标 `C[A[i]] - 1` 处，然后 `C[A[i]]--`。

**第 2 步之后 `C[v]` 的含义要说准**：值 ≤v 的元素共有 `C[v]` 个，它们在最终结果里占据下标 0 到 `C[v] - 1`；其中值恰为 v 的那些元素排在最后，所以**值为 v 的最后一个元素的下标就是 `C[v] - 1`**。每放置一个，就把 `C[v]` 减 1，下一个值为 v 的元素自然落到前一格。c

```
// A: 输入数组，B: 输出数组，n: 元素个数，k: 最大值（取值范围 [0, k]）
void CountingSort(int A[], int B[], int n, int k) {
    int *C = (int *)malloc((k + 1) * sizeof(int));
    if (C == NULL) return;
    for (int i = 0; i <= k; i++)
        C[i] = 0;                    // 计数数组清零

    for (int i = 0; i < n; i++)
        C[A[i]]++;                   // 第 1 步：C[v] = 值为 v 的元素个数

    for (int i = 1; i <= k; i++)
        C[i] += C[i - 1];            // 第 2 步：C[v] = 值 <= v 的元素总个数

    for (int i = n - 1; i >= 0; i--) {   // 第 3 步：必须从后往前，见下文
        B[C[A[i]] - 1] = A[i];           // C[A[i]]-1 就是 A[i] 的最终下标
        C[A[i]]--;                       // 同值的下一个元素往前挪一格
    }
    free(C);
}
```

边界：`n = 0` 时三个循环里只有清零那一个会执行，`B` 不被写入，安全；`k` 必须 ≥ 数组中的最大值，否则 `C[A[i]]` 越界——**调用者必须保证取值范围的正确性**，这是计数排序的使用前提而不是实现缺陷。

### 逐步推演

以 `A = {2, 5, 3, 0, 2, 3, 0, 3}` 为例（n=8，k=5）：

**第 1 步——计数：**

| 值 v | 0 | 1 | 2 | 3 | 4 | 5 |
| --- | --- | --- | --- | --- | --- | --- |
| `C[v]` | 2 | 0 | 2 | 3 | 0 | 1 |

**第 2 步——前缀和：**

| 值 v | 0 | 1 | 2 | 3 | 4 | 5 |
| --- | --- | --- | --- | --- | --- | --- |
| `C[v]` | 2 | 2 | 4 | 7 | 7 | 8 |

含义举例：`C[3] = 7` 表示值 ≤3 的元素共 7 个，因此**最后一个** 3 应放在下标 6。

**第 3 步——从后往前放置：**

| 扫描 | `A[i]` | 当前 `C[A[i]]` | 放入 | 更新后 |
| --- | --- | --- | --- | --- |
| `A[7]` | 3 | 7 | `B[6] = 3` | `C[3] = 6` |
| `A[6]` | 0 | 2 | `B[1] = 0` | `C[0] = 1` |
| `A[5]` | 3 | 6 | `B[5] = 3` | `C[3] = 5` |
| `A[4]` | 2 | 4 | `B[3] = 2` | `C[2] = 3` |
| `A[3]` | 0 | 1 | `B[0] = 0` | `C[0] = 0` |
| `A[2]` | 3 | 5 | `B[4] = 3` | `C[3] = 4` |
| `A[1]` | 5 | 8 | `B[7] = 5` | `C[5] = 7` |
| `A[0]` | 2 | 3 | `B[2] = 2` | `C[2] = 2` |

结果：`B = {0, 0, 2, 2, 3, 3, 3, 5}`

### 为什么第 3 步必须从后往前

**这是本篇唯一真正需要理解的地方**，也是它作为基数排序前置的价值所在。

前缀和给出的是"值为 v 的元素中，**最后一个**该放在哪"。因此放置的顺序必须与"最后一个"这个描述匹配：

- **从后往前扫描 `A`**：先遇到的是原序列中**靠后**的那个 v，把它放到**靠后**的位置；后遇到的靠前的 v 放到靠前的位置。相对次序被完整保留 ⇒ **稳定**。
- **从前往后扫描 `A`**：先遇到的是原序列中**靠前**的那个 v，却被放到了"最后一个 v"的位置。于是原本靠前的跑到了后面，相对次序被整体**反转** ⇒ **不稳定**。

用上面的例子验证：`A` 中三个 3 分别在下标 2、5、7，记为 3a,3b,3c。

| 扫描方向 | 放置次序 | 结果中三个 3 的次序 |
| --- | --- | --- |
| 从后往前（正确） | 3c→B[6]，3b→B[5]，3a→B[4] | 3a,3b,3c ✓ 保持原序 |
| 从前往后（错误） | 3a→B[6]，3b→B[5]，3c→B[4] | 3c,3b,3a ✗ 完全反转 |

**这正是 [基数排序](./radix-sort.html) 要求"每趟分配必须稳定"的落地形式**：基数排序在顺序存储下每趟就是一次计数排序，若这一趟从前往后扫，低位排好的成果就会被本趟反转掉。

（若改用链式实现，把元素依次**追加到队尾**、收集时**先进先出**，就天然稳定，不存在扫描方向的问题——这也是教材的链式基数排序用队列的原因。）

## 复杂度分析

设 n 为元素个数，k 为元素取值范围。

四个循环的开销依次是 O(k)（清零）、O(n)（计数）、O(k)（前缀和）、O(n)（输出），合计：T(n)=O(n+k)

**三种情况完全一样**——循环边界只由 n 和 k 决定，与元素排列无关。

| 指标 | 结果 | 说明 |
| --- | --- | --- |
| 最好 / 最坏 / 平均时间 | 均为 O(n+k) | 与初始序列完全无关；当 k=O(n) 时为线性 O(n) |
| 空间复杂度 | O(n+k) | 计数数组 O(k) + 输出数组 O(n) |
| 稳定性 | **稳定** | 前提是第 3 步从后往前扫描 |
| 存储结构 | **只适合顺序存储** | 要用计数值直接定位下标，链式存储无法随机存取 |

**适用条件**：取值范围 k 不能太大。当 k≫n 时（比如对 10 个 32 位整数排序，k=232），计数数组的大小和清零、前缀和两个 O(k) 循环都会把它拖垮——**此时它既不省时也不省空间**。

这正是基数排序存在的理由：把一个大值域的关键字**拆成 d 位**，每位的值域只有 r（十进制 r=10），用 d 趟小值域的计数排序代替一趟大值域的计数排序，O(k) 的代价就被压成了 O(d⋅r)。

## 易混淆知识点

| 对比项 | A | B | 判别依据 |
| --- | --- | --- | --- |
| **计数排序 vs 基数排序** | 计数排序：**一趟**，直接按完整关键字的值分桶，值域 k | 基数排序：**d 趟**，每趟只看一位，值域 r | 判据是"值域太大怎么办"。k 大时拆位，就变成了基数排序 |
| **前缀和之后 `C[v]` 的含义** | 值**等于** v 的个数（第 1 步后） | 值**小于等于** v 的个数（第 2 步后） | 两步之间含义变了。做题时先确认现在处在哪一步 |
| **扫描方向与稳定性** | 从后往前：稳定 | 从前往后：同值元素次序**完全反转** | 因为前缀和给的是"最后一个该放哪" |
| **是否受 Ω(nlog⁡n) 约束** | 计数排序、基数排序：不受 | 全部比较类：受 | 判据是"有没有做元素间的比较"。用值当下标不算比较 |
| **空间 O(k) vs O(n+k)** | 只算计数数组：O(k) | 加上输出数组：O(n+k) | 计数排序**必须**有输出数组（不能原地），所以标准答案是 O(n+k) |

## 本节小结

学完本节，应该能够：

- **说清计数排序的信息来源**："比 x 小的元素有多少个"，因此不受比较排序下界约束
- **说准前缀和之后 `C[v]` 的含义**：值 ≤v 的元素总个数，也就是"值为 v 的最后一个元素的下标 + 1"
- **手工模拟三步过程**，写出计数数组、前缀和数组与每一步的放置位置
- **解释第 3 步为什么必须从后往前**，并说明从前往后会让同值元素的次序**完全反转**
- **把这条结论接到 [基数排序](./radix-sort.html) 上**：这正是"每趟分配必须稳定"在顺序实现下的落地形式
- **推出 O(n+k) 时间与 O(n+k) 空间**，并说清 k≫n 时它为什么会退化——以及基数排序如何用"拆位"化解这个问题

一条最关键的结论：**计数排序的稳定性不是附赠的，而是靠"从后往前扫描"换来的**；它是基数排序正确性的地基。

## 教材出处

⚠️ **两本教材里都有"计数排序"，但讲的都不是本篇这个算法**——同名不同物， 拿书对照时务必先看清定义。

- 严蔚敏《数据结构（C 语言版）》（第 2 版）p271，第 8 章习题（6）： "有一种简单的排序算法，叫做计数排序……**表中所有待排序的关键字互不相同**， 计数排序算法针对表中的每个记录，**扫描待排序的表一趟，统计表中有多少个记录的关键字 比该记录的关键字小**。假设针对某一个记录，统计出的计数值为 c， 那么这个记录在新的有序表中的合适的存放位置即为 c。"
- 殷人昆《数据结构——用面向对象方法与 C++ 描述》（第 2 版）p442，习题 9.25： 同一思路，"为每个元素增加一个计数域 `count`，用于存放在已排好序的序列中 该元素前面的元素数目"，并要求说明**最多需要做 n(n−1)/2 次排序码比较**。

**两本书说的是"按排名计数"，本篇讲的是"按取值计数（前缀和）"，是两个不同的算法**：

|  | 教材习题里的「计数排序」 | 本篇的计数排序 |
| --- | --- | --- |
| 数什么 | 对每个元素，数**有多少元素比它小** | 对每个**取值**，数**出现了几次** |
| 怎么定位 | 计数值直接就是它的最终下标 | 对计数数组求前缀和，再倒序回填 |
| 前提 | **关键字必须互不相同** | 关键字取值范围有限（0…k） |
| 比较次数 | n(n−1)/2 | **0 次关键字比较** |
| 时间 | Θ(n2) | Θ(n+k) |
| 稳定性 | 不涉及（关键字互异） | 稳定（倒序回填保证） |

教材那个版本本质上是**用比较统计排名**，仍属比较排序，逃不掉 Ω(nlog⁡n) 的下界； 本篇这个版本**不做任何关键字比较**，靠取值直接寻址，所以才能突破那个下界。 基数排序内层用到的是**本篇这一个**。
