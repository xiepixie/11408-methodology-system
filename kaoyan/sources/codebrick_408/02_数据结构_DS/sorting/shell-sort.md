# 希尔排序

## 大纲定位

本篇对应 2026 大纲 **七、排序 （六）希尔排序（shell sort）**（又称缩小增量排序）。

分工边界：

- 本篇负责希尔排序本身——**它对插入排序做了哪两点改进、d-有序这个不变量、增量序列的约束与它对复杂度的决定作用、不稳定的具体反例、为什么不能用于链表**。
- 直接插入排序的框架与哨兵在 [直接插入排序](./insertion-sort.html)，本篇的每一趟就是"增量为 d 的插入排序"，不再重复。
- 插入排序的另一条改进路线（只减少比较、不减少移动）在 [折半插入排序](./binary-insertion-sort.html)。两条路线的对照是本篇的一条主线。
- 稳定性、"一趟"的定义等公共概念在 [排序的基本概念](./concepts.html)。

## 知识框架

本节回答四个问题：

- 直接插入排序在什么条件下快？希尔排序怎么**人为制造**这两个条件？
- 一趟（一个增量 d）结束后，数组处于什么状态？"d-有序"这个说法精确指什么？
- 增量序列必须满足什么约束？为什么 Shell 的原始序列 n/2,n/4,…,1 最坏还是 O(n2)？
- 为什么它不稳定？为什么它不能用在链表上？

## 插入排序的增量优化

直接插入排序有两个"快"的条件：

- **待排记录个数少**时快（因为它是 O(n2)，n 小则常数占优）；
- **序列基本有序**时快（后移次数 = 逆序对数，逆序对少则内层循环几乎不执行）。

希尔排序同时**制造**这两个条件：

- 先按一个较大的增量 d1 把序列分成 d1 组，每组只有约 n/d1 个元素——**条件 1 达成**；
- 组内做插入排序时，元素一步能跨越 d1 个位置，远距离的逆序对被成批消除，序列迅速趋于有序——**为后续趟的条件 2 铺路**；
- 增量逐步缩小，组越来越大但序列越来越有序；最后一趟 dt=1 是对一个"几乎有序"的序列做整体插入排序——**条件 2 达成**，这一趟虽然 n 大，但逆序对已所剩无几。

**关键在于两个条件是错开满足的**：大增量的趟满足条件 1，小增量的趟满足条件 2。整体效率因此突破了 O(n2) 的瓶颈。

### 算法不变量：d-有序

**用增量 d 做完一趟后，序列是 d-有序的**：对任意下标 i，都有 A[i]≤A[i+d]。等价说法是——把下标按模 d 分成 d 组 {0,d,2d,…}、{1,1+d,…}、…，**每一组内部各自有序**。

两点必须说清：

- **d-有序 ≠ 整体有序**。前缀通常仍然是乱的（A[0] 未必是最小值），只有"隔着 d 看"才有序。这是它与所有其他算法中间状态的分界点。
- **后一趟不会破坏前一趟的成果**：可以证明，对一个已经 d1-有序的序列再做 d2-有序处理，结果仍然保持 d1-有序。所以增量缩小的过程是"有序性单调累积"的，最后一趟 d=1 时序列已经非常接近有序。

工作原理示意（d=4,2,1）：

```
原始序列:  [8, 5, 2, 9, 3, 7, 1, 6]

d=4:  分组 {8,3} {5,7} {2,1} {9,6}  →  各组插入排序
      [3, 5, 1, 6, 8, 7, 2, 9]        ← 此时"隔 4 看"处处有序

d=2:  分组 {3,1,8,2} {5,6,7,9}      →  各组插入排序
      [1, 5, 2, 6, 3, 7, 8, 9]        ← "隔 2 看"处处有序（隔 4 看仍有序）

d=1:  整体插入排序（此时逆序对极少，移动次数很少）
      [1, 2, 3, 5, 6, 7, 8, 9]
```

## 操作详解
c

```
void ShellSort(int A[], int n) {
    for (int d = n / 2; d >= 1; d /= 2) {      // 增量序列 n/2, n/4, ..., 1
        for (int i = d; i < n; i++) {          // 从第 d 个元素起，交替处理各组
            int temp = A[i];                   // 暂存待插元素
            int j = i - d;                     // 同组的前驱在 i-d 处
            while (j >= 0 && A[j] > temp) {    // 与直接插入排序唯一的差别：步长 d 而不是 1
                A[j + d] = A[j];               // 后移一个"步长"
                j -= d;
            }
            A[j + d] = temp;
        }
    }
}
```

三处细节：

- **没有显式的"分组再分别排序"**。外层 `i` 从 d 一直走到 n−1，**交替**处理各组的元素（i=d 属第 0 组、i=d+1 属第 1 组……）。效果与"一组一组排完"完全等价，因为不同组的元素之间从不比较，处理次序不影响结果。
- **`j >= 0` 不能省**。这里没有哨兵可用——`A[0]` 是真实数据，d 组各有各的"组内起点"，一个哨兵挡不住 d 个方向。这也是希尔排序与直接插入排序在写法上唯一实质性的差别。
- **边界**：`n <= 1` 时 `d = 0`，外层循环条件 `d >= 1` 不成立，直接返回；`n = 2` 时 `d = 1`，退化成一趟普通插入排序。都正确。

### 增量序列

增量序列的选择直接决定希尔排序的时间复杂度。常见的几种：

| 增量序列 | 取值方式 | 示例（n=16） | 最坏时间复杂度 |
| --- | --- | --- | --- |
| Shell 原始序列 | di=⌊n/2i⌋ | 8, 4, 2, 1 | O(n2) |
| Hibbard 序列 | di=2i−1 | 15, 7, 3, 1 | O(n1.5) |
| Knuth 序列 | di=(3i−1)/2 | 13, 4, 1 | O(n1.5) 量级 |

**没有特别说明时按 Shell 原始序列**（d=n/2,n/4,…,1）。

增量序列必须满足两条约束：

**① 最后一个增量必须为 1。** 只有 d=1 那一趟会比较相邻元素。若最后一趟的增量是 2，下标为奇数与偶数的两组元素**从头到尾没有互相比较过一次**，结果必然不是有序的。

**② 各增量之间不应有 1 之外的公因子。** 这一条解释了为什么 Shell 的原始序列最坏是 O(n2)——因为 n/2,n/4,… 全是 2 的倍数，**下标同奇偶的元素在最后一趟之前从不跨组交流**。

构造一个坏输入就能看清：取 n 个互不相同的数，把**较大的一半按升序放在偶数下标上，较小的一半按升序放在奇数下标上**。此时对 d=n/2,n/4,…,2 的每一趟，同组元素的下标同奇偶（因为增量都是偶数），而各奇偶类内部本来就有序——**这些趟一次移动都做不了**，全是空转。所有工作都堆到最后一趟 d=1，而那一趟面对的序列有约 n2/8 个逆序对，退化成 O(n2) 的插入排序。

| n | d≥2 各趟的移动次数 | d=1 那一趟的移动次数 | n2/8 |
| --- | --- | --- | --- |
| 16 | 全为 0 | 36 | 32 |
| 64 | 全为 0 | 528 | 512 |
| 256 | 全为 0 | 8 256 | 8 192 |
| 1024 | 全为 0 | 131 328 | 131 072 |

Hibbard 序列 1,3,7,15,… 相邻两项互素，就没有这个毛病，最坏能压到 O(n1.5)。

### 逐趟推演

**例一**（n=10，Shell 原始增量 d=5,3,1）：`{49, 38, 65, 97, 76, 13, 27, 49*, 55, 04}`

**第一趟 d=5**——分成 5 组，每组 2 个：

```
组0: A[0]=49, A[5]=13  →  13, 49
组1: A[1]=38, A[6]=27  →  27, 38
组2: A[2]=65, A[7]=49* →  49*, 65
组3: A[3]=97, A[8]=55  →  55, 97
组4: A[4]=76, A[9]=04  →  04, 76
```

结果：`13 27 49* 55 04 49 38 65 97 76`

**第二趟 d=3**——分成 3 组：

```
组0: A[0]=13, A[3]=55, A[6]=38, A[9]=76  →  13, 38, 55, 76
组1: A[1]=27, A[4]=04, A[7]=65           →  04, 27, 65
组2: A[2]=49*, A[5]=49, A[8]=97          →  49*, 49, 97
```

结果：`13 04 49* 38 27 49 55 65 97 76`

**第三趟 d=1**——整体插入排序：

结果：`04 13 27 38 49* 49 55 65 76 97`

注意最终结果里 `49*`（原本在下标 7）排在了 `49`（原本在下标 5）**前面**——两个相等元素的次序被翻转了。这是不稳定性的一次现场演示，下面给出更小、更清楚的最小反例。

**例二**（n=8，d=4,2,1）：`{49, 38, 65, 97, 76, 13, 27, 49*}`

| 趟 | 增量 | 分组 | 结果 |
| --- | --- | --- | --- |
| 1 | d=4 | {49,76} {38,13} {65,27} | 49 13 27 49* 76 38 65 97 |
| 2 | d=2 | {49,27,76,65} | 27 13 49 38 65 49* 76 97 |
| 3 | d=1 | 整体 | 13 27 38 49 49* 65 76 97 |

这一例最终 `49` 仍在 `49*` 前面——**没出事不等于稳定**。判定不稳定只需要一个反例，判定稳定则必须证明所有输入都不会出事。

### 不稳定性：最小反例

**最小反例：`{2a, 2b, 1, 3}`**（n=4，Shell 原始增量 d=2,1）

| 趟 | 增量 | 分组与组内排序 | 结果 |
| --- | --- | --- | --- |
| 初始 | — | — | 2a 2b 1 3 |
| 1 | d=2 | 组0：A[0]=2a, A[2]=1 → 排成 1, 2a（**2a 从下标 0 跳到下标 2**）组1：A[1]=2b, A[3]=3 → 已有序，不动 | 1 **2b** **2a** 3 |
| 2 | d=1 | 整体插入排序，此时已有序，无移动 | 1 **2b** **2a** 3 |

排序后 `2b` 排在 `2a` 前面，**故希尔排序不稳定**。

**根源**：`2a` 与 `2b` 被分到了**不同的组**（下标 0 与 1 对 d=2 不同余），各组独立排序时**互相看不见对方**——`2a` 因为组内的 1 比它小而被迫后跳两格，跳的过程中越过了与它相等的 `2b`，而这次"越过"从来没有经过两者之间的一次比较。

对比一下：直接插入排序里，`2a` 想越过 `2b` 必须先与 `2b` 比较一次，而 `A[j] > temp` 在相等时为假，越不过去；希尔排序把这次比较**从流程里删掉了**，稳定性也就跟着没了。

一句话记法：**跨组跳跃 = 越过了从未与之比较的元素 = 可能不稳定。** 快速排序（枢轴远距离换位）、简单选择排序（远距离交换）、堆排序（堆顶与末元素交换）不稳定的根源都是同一句话。

## 复杂度分析

### 时间

**最好情况（初始已有序）**：每趟对每个 i≥d 做恰好 1 次比较（`A[j] > temp` 立刻为假）、0 次移动。对 Shell 原始增量，趟数 t=⌊log2⁡n⌋，总比较次数∑k(n−dk)=n⋅t−∑kdk≈nlog2⁡n−n

即 Θ(nlog2⁡n)。（n=1024 时实测恰为 10×1024−1023=9217 次比较、0 次移动。）

**最坏情况**：用 Shell 原始增量时是 O(n2)，构造方式见上文的"奇偶分离"输入。

**平均情况**：希尔排序的精确分析涉及尚未完全解决的数学问题，至今没有公认最优的增量序列。教材给出的经验结论是：**当 n 在某个特定范围内时，希尔排序所需的比较和移动次数约为 n1.3**；当增量序列取 dk=2t−k+1−1 时可证明时间复杂度为 O(n1.5)。

**考试口径**：平均记 **约 O(n1.3)**，最坏（Shell 原始增量）记 O(n2)。

### 空间

O(1)——只需要 `temp`、`d`、`i`、`j` 等常数个辅助变量，与 n 无关。

### 汇总

| 指标 | 结果 | 说明 |
| --- | --- | --- |
| 最好时间复杂度 | Θ(nlog2⁡n) | 已有序：每趟只比较、不移动 |
| 最坏时间复杂度 | O(n2) | Shell 原始增量 + 奇偶分离输入 |
| 平均时间复杂度 | 约 O(n1.3) | 经验值，取决于增量序列 |
| 空间复杂度 | O(1) | 常数个辅助变量 |
| 趟数 | 等于增量序列的长度 t | Shell 原始增量时 t=⌊log2⁡n⌋ |
| 稳定性 | **不稳定** | 反例 `{2a, 2b, 1, 3}` |
| 存储结构 | **只能用顺序表** | 见下 |

### 为什么不能用于链表

算法每一步都要访问"当前元素往前数第 d 个位置"（`A[j-d]`、`A[j+d]`）。在顺序表上这是一次下标加减，O(1)；在链表上要从当前结点重新走 d 步，O(d)，而且链表**无法反向走**（单链表更是只能向后）。跨越式访问正是希尔排序全部效率的来源，链表上这条路直接断了。

同样因为需要随机存取而不能用于链表的还有 [折半插入排序](./binary-insertion-sort.html)、[快速排序](./quick-sort.html)、[堆排序](./heap-sort.html)；可以用于链表的是直接插入、冒泡、简单选择、归并、基数。

### 与直接插入排序的对照

| 对比项 | 直接插入排序 | 希尔排序 |
| --- | --- | --- |
| 平均时间复杂度 | O(n2) | 约 O(n1.3) |
| 一次移动跨越的距离 | 1 个位置 | d 个位置 |
| 优化的是 | — | **移动次数**（远距离逆序对被成批消除） |
| 稳定性 | 稳定 | **不稳定** |
| 存储结构 | 顺序表、链表均可 | 只能顺序表 |
| 适用场景 | n 小或基本有序 | n 中等、初始无序 |

与 [折半插入排序](./binary-insertion-sort.html) 放在一起看，插入排序的两条改进路线就很清楚了：

- **折半插入**：只优化查找（比较次数 O(n2)→Θ(nlog2⁡n)），移动不变 ⇒ 总复杂度**不变**；
- **希尔**：优化移动（让元素一步跨 d 格），比较也跟着减少 ⇒ 总复杂度**真的降了**。

这两条路线的对照说明了一件事：**O(n2) 插入排序的瓶颈在移动，谁动了移动谁才真正提速。**

## 易混淆知识点

| 对比项 | A | B | 判别依据 |
| --- | --- | --- | --- |
| **d-有序 vs 整体有序** | 一趟后：间隔 d 的各子序列各自有序 | 排完后：相邻元素处处有序 | 只有 d=1 时两者才等价。这也是"最后一个增量必须为 1"的原因 |
| **希尔的一趟 vs 一个组** | 一趟 = 用**一个增量**把全部 d 个组都排完 | 一个组只是一趟里的一部分 | 数趟数时按增量个数数，不按组数数 |
| **希尔 vs 归并的中间状态** | 希尔：有序是**跳着的**（间隔 d） | 归并：有序是**连续段**（段长 2k） | 先按段长 2、4 切开看段内是否有序，不行再按 d=n/2,n/4 抽子序列验证 |
| **谁优化了比较，谁优化了移动** | 折半插入：优化比较，总复杂度不变 | 希尔：优化移动，总复杂度真降 | 看改动落在"找插入位置"还是"元素移动的步长"上 |
| **稳定性** | 直接插入：稳定 | 希尔：不稳定 | 判据是"元素会不会越过一个从未与它比较过的相等元素"。跨组跳跃就会 |
| **能否用于链表** | 直接插入：可以 | 希尔、折半插入、快排、堆排：不可以 | 判据是"要不要按下标做随机存取"。要跳 d 格就不行 |

## 本节小结

学完本节，应该能够：

- **说清希尔排序改进插入排序的两个着力点**（减少每组的记录个数、让序列快速趋于基本有序），并解释这两个条件是如何在不同趟上错开满足的
- **写出不变量"一趟后序列 d-有序"**，并说清 d-有序不等于整体有序、后一趟不会破坏前一趟的 d-有序性
- **给定序列和增量序列，逐趟写出结果**（含分组过程）
- **说出增量序列的两条约束**：最后一个必须为 1；各值不应有 1 之外的公因子——并能用"奇偶分离"输入解释 Shell 原始增量为什么最坏是 O(n2)
- **用 `{2a, 2b, 1, 3}` 举出不稳定的反例并推到底**，说明根源是"跨组跳跃越过了从未与之比较的相等元素"
- **说清它不能用于链表**：跨越式访问在链表上退化成 O(d)，而跨越正是它全部效率的来源
- **把它与折半插入排序对照**，得出"优化移动才真正降复杂度"的结论

两条最关键的结论：

- **希尔排序是本章唯一时间复杂度取决于增量序列的算法**，因此谈它的复杂度必须先说清用的是哪个增量序列。
- **跨组跳跃既是它提速的原因，也是它不稳定的原因**——同一个机制的两面。
