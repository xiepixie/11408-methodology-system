# 快速排序

## 大纲定位

本篇对应 2026 大纲 **七、排序 （七）快速排序**。

分工边界：

- 本篇负责快速排序本身——**划分（Partition）的完整过程与两种写法、递归树与三种情况的复杂度推导、递归深度即空间复杂度、最坏情况的触发条件与枢轴选取策略、不稳定的反例、"每趟至少一个元素就位"这一性质的精确表述**。
- 它是 [起泡排序](./bubble-sort.html) 的改进版（一次不相邻的交换可消除多个逆序对），起泡排序的基本框架在那一篇。
- 与 [二路归并排序](./merge-sort.html) 的递归结构对称性（"先划分后递归" vs "先递归后合并"）两篇都写，本篇从快排一侧讲。
- 稳定性、"一趟"的定义等公共概念在 [排序的基本概念](./concepts.html)。

## 知识框架

本节回答五个问题：

- 一趟划分到底做了什么？为什么说"枢轴到达最终位置"，而这个位置又**不一定是**极值的位置？
- 划分的两种常见写法（挖坑法、两端交换法）差别在哪？为什么内层循环的 `>=` 和 `<=` 不能写成 `>` 和 `<`？
- 最好 O(nlog2⁡n) 与最坏 O(n2) 分别怎么推出来？最坏在什么输入上触发？
- 为什么它的空间复杂度不是 O(1)？O(log2⁡n)∼O(n) 具体指什么？
- 为什么它不稳定？为什么它难以用在链表上？

## 核心思想

快速排序是**分治法**在排序上的实现，由起泡排序改进而来：

起泡排序每次只交换相邻的两个记录，**一次交换只能消除一个逆序对**。如果能通过两个不相邻记录的一次交换消除多个逆序对，速度就会大大提高——快速排序的一次交换正是如此。

三步：

- **划分（Partition）**：在待排序表中取一个记录作为**枢轴**（pivot，通常取第一个），经过一趟处理，使**所有关键字小于枢轴的记录都排到它前面、所有大于枢轴的都排到它后面**，枢轴自身落在分界处；
- **递归（Recurse）**：对枢轴左、右两个子表分别递归执行同样的过程；
- **合并（Combine）**：**不需要**——划分本身已经保证了子表之间的顺序关系，子表各自有序后整体就有序了。

### 算法不变量

**一趟划分结束后，枢轴到达它在最终有序序列中的位置，此后永不移动；它左边的元素全部 ≤ 它，右边的元素全部 ≥ 它。**

这条不变量与冒泡、选择类的"每趟一个元素就位"同族，但有一个关键差别：

|  | 就位的是谁 | 位置在哪 |
| --- | --- | --- |
| 冒泡 / 简单选择 / 堆排 | 当前未排序区的**全局最值** | 固定在区间的一端 |
| **快速排序** | **枢轴**，通常不是极值 | 落在区间**中间某处**，位置随数据而变 |

因此判别一个中间状态是不是快排的结果，要找的是"**存在某个元素，它左边全部不大于它、右边全部不小于它**"，而不是"某一端聚集了最值"。

## 操作详解

### 主框架
c

```
void QuickSort(int A[], int low, int high) {
    if (low < high) {                            // 子表长度大于 1 才需要排
        int pivotPos = Partition(A, low, high);  // 划分，返回枢轴的最终位置
        QuickSort(A, low, pivotPos - 1);         // 递归排左子表
        QuickSort(A, pivotPos + 1, high);        // 递归排右子表（枢轴不参与）
    }
}
```

递归出口是 `low >= high`，即子表长度 ≤1——**长度为 0 或 1 的表天然有序**。注意递归调用里**不包含 `pivotPos` 本身**，因为它已经就位；漏掉这个减 1 / 加 1 会导致无限递归。

### 划分写法一：挖坑法

以第一个元素为枢轴，先把它**暂存**起来（腾出一个"坑"），然后 `low` 与 `high` 两个指针从两端交替向中间扫描，**每找到一个该换到对面去的元素，就把它填进当前的坑里，同时在它原来的位置制造一个新坑**。c

```
int Partition(int A[], int low, int high) {
    int pivot = A[low];                 // 枢轴暂存，A[low] 成为第一个"坑"
    while (low < high) {
        while (low < high && A[high] >= pivot)
            high--;                     // 从右往左找第一个 < pivot 的
        A[low] = A[high];               // 填进左边的坑，A[high] 成为新坑
        while (low < high && A[low] <= pivot)
            low++;                      // 从左往右找第一个 > pivot 的
        A[high] = A[low];               // 填进右边的坑，A[low] 成为新坑
    }
    A[low] = pivot;                     // low == high，把枢轴填进最后一个坑
    return low;                         // 返回枢轴的最终位置
}
```

**三处不能改的地方：**

- **`>=` 与 `<=` 不能写成 `>` 与 `<`。** 若写成 `A[high] > pivot`，当序列中存在与枢轴**相等**的元素时，两个内层循环都会在它那里停住而不移动指针，外层 `while (low < high)` 反复空转——**死循环**。举例：`A = [5, 5]`，`pivot = 5`。用 `>` 时，`A[high] = 5 > 5` 为假，`high` 不动；填坑后 `A[low] = 5 < 5` 为假，`low` 也不动；`low < high` 仍成立，无限循环。用 `>=` 则 `high` 会一路减到与 `low` 相遇，正常退出。
- **两个内层循环里的 `low < high` 不能省。** 否则指针会越过对方，读到区间之外。
- **必须先扫 `high` 再扫 `low`**（当枢轴取自 `A[low]` 时）。因为第一个坑在左端，只有从右边找一个小元素来填才不会覆盖有效数据。若枢轴取自 `A[high]`，则扫描次序必须反过来。

### 划分写法二：两端交换法

另一种同样常见的写法：两个指针分别停在"该去右边的元素"和"该去左边的元素"上，**直接交换这两个元素**，最后再把枢轴与分界位置交换。c

```
int Partition2(int A[], int low, int high) {
    int pivot = A[low];
    int i = low, j = high;
    while (i < j) {
        while (i < j && A[j] >= pivot) j--;   // 右指针找 < pivot 的
        while (i < j && A[i] <= pivot) i++;   // 左指针找 > pivot 的
        if (i < j) { int t = A[i]; A[i] = A[j]; A[j] = t; }
    }
    int t = A[low]; A[low] = A[i]; A[i] = t;  // 枢轴与分界处交换
    return i;
}
```

两种写法**都是正确的划分**，但**划分后的具体排列可能不同**（相等元素与非枢轴元素的落点不一样），枢轴位置则通常相同。以 `{49, 38, 65, 97, 76, 13, 27, 49*}` 为例：

| 写法 | 一趟划分结果 | 枢轴位置 |
| --- | --- | --- |
| 挖坑法 | `27 38 13 [49] 76 97 65 49*` | 下标 3 |
| 两端交换法 | `13 38 27 [49] 76 97 65 49*` | 下标 3 |

**答题时按题目给的代码走**；若题目没给代码，按挖坑法（教材算法 8.5 的写法）。**不要把两种写法的中间状态混着用**——这是这一块最容易出错的地方。

### 一趟划分的完整推演

对 `{49, 38, 65, 97, 76, 13, 27, 49*}` 用**挖坑法**执行一趟划分（`pivot = A[0] = 49`）：

| 步 | low | high | 动作 | 数组状态（`_` 表示当前的坑） |
| --- | --- | --- | --- | --- |
| 0 | 0 | 7 | `pivot = A[0] = 49` 暂存 | `_ 38 65 97 76 13 27 49*` |
| 1 | 0 | 7 | high 扫描：`A[7] = 49* >= 49`，`high--` | `_ 38 65 97 76 13 27 49*` |
| 2 | 0 | 6 | `A[6] = 27 < 49`，停；`A[0] = A[6]` | `27 38 65 97 76 13 _ 49*` |
| 3 | 0→2 | 6 | low 扫描：`A[0]=27 <= 49` `low++`；`A[1]=38 <= 49` `low++`；`A[2]=65 > 49` 停 | `27 38 65 97 76 13 _ 49*` |
| 4 | 2 | 6 | `A[6] = A[2]` | `27 38 _ 97 76 13 65 49*` |
| 5 | 2 | 5 | high 扫描：`A[5]=13 < 49`，停；`A[2] = A[5]` | `27 38 13 97 76 _ 65 49*` |
| 6 | 3 | 5 | low 扫描：`A[3]=97 > 49`，停；`A[5] = A[3]` | `27 38 13 _ 76 97 65 49*` |
| 7 | 3 | 5→3 | high 扫描：`A[5] = 97 >= 49` `high--`；`A[4] = 76 >= 49` `high--`；此时 `low == high == 3`，内层循环因 `low < high` 不成立而停 | `27 38 13 _ 76 97 65 49*` |
| 8 | 3 | 3 | 外层 `while (low < high)` 也不成立，退出；`A[3] = pivot` 填掉最后一个坑 | `27 38 13 **49** 76 97 65 49*` |

结果：枢轴 49 落在下标 3；左侧 `{27, 38, 13}` 全部 ≤49，右侧 `{76, 97, 65, 49*}` 全部 ≥49。

### 整个排序过程

继续对左右子表递归：

| 趟（递归层） | 本层处理的子表 | 本层新归位的元素 | 全表状态 |
| --- | --- | --- | --- |
| 初始 | — | — | 49 38 65 97 76 13 27 49* |
| 第 1 趟 | `[0,7]` | 49 | 27 38 13 **49** 76 97 65 49* |
| 第 2 趟 | `[0,2]`、`[4,7]` | 27、76 | 13 **27** 38 **49** 49* 65 **76** 97 |
| 第 3 趟 | `[0,0]`、`[2,2]`、`[4,5]`、`[7,7]` | 49* | 13 27 38 49 **49*** 65 76 97 |

**第 1 趟只有 1 个元素归位，第 2 趟新增 2 个（累计 3 个）**——这个计数规律见下文"每趟到位几个元素"。

## 复杂度分析

### 时间：最好情况

若每次划分都把子表**均匀地分成两半**，则对长度为 n 的表：

- 划分本身要让 `low` 与 `high` 走完整个区间，共约 n 次比较，记为 Cn；
- 之后是两个长度约 n/2 的子问题。

递推式：T(n)=Cn+2T(n/2)

逐层展开：T(n)≤n+2T(n/2)≤n+2(n2+2T(n/4))=2n+4T(n/4)≤2n+4(n4+2T(n/8))=3n+8T(n/8)  ⋮≤kn+2kT(n/2k)

当 2k=n 即 k=log2⁡n 时递归到底，T(1) 是常数，于是T(n)≤nlog2⁡n+nT(1)=O(nlog2⁡n)

**直观理解**：递归树是一棵平衡二叉树，**树高 log2⁡n，每一层所有子表的长度加起来是 O(n)，每层做 O(n) 次比较**，故总计 O(nlog2⁡n)。

### 时间：最坏情况

若每次划分都极端不平衡——枢轴恰好是当前子表的最大值或最小值——则一侧子表为空、另一侧有 n−1 个元素，递归树退化成一条**单支链**，深度为 n。第 i 趟需要 n−i 次比较：KCNmax=∑i=1n−1(n−i)=n(n−1)2≈n22

即 O(n2)——退化到简单排序的水平。

**触发条件（这是必须记准的一条）**：**取第一个元素为枢轴时，初始序列已经有序（正序或逆序）**。

- 正序输入：`A[low]` 是最小值，右扫描找不到比它小的，`high` 一路减到 `low`，左子表为空；
- 逆序输入：`A[low]` 是最大值，右扫描第一步就停下，交换后左子表拿到 n−1 个元素。

两种情况实测的递归深度都是 n−1（n=100 时深度 99）。

**这里有个反直觉之处值得记住**：所有其他 O(n2) 算法在"已有序"输入上跑得最快（插入 O(n)、冒泡 O(n)），**快速排序偏偏在"已有序"输入上跑得最慢**。原因是它的效率来自"划分得均不均匀"，而不是来自"逆序对多不多"。

### 时间：平均情况

可以证明，在各种初始排列等概率出现的假设下，快速排序的平均时间复杂度为 O(nlog2⁡n)，且**在所有内部排序方法中平均常数因子最小**——它的内层循环只做一次比较和一次赋值，且访问模式是从两端向中间的顺序扫描，对缓存友好。这就是"n 较大且初始记录无序时，快速排序是最快的内部排序方法"这一结论的来源。

### 空间：递归深度就是空间复杂度

快速排序**不需要与 n 同阶的辅助数组**，但它是递归的，执行时需要一个栈保存每层的 `low`、`high` 等参数。**最大递归调用层数 = 递归树的深度**，所以：

| 情况 | 递归树深度 | 空间复杂度 |
| --- | --- | --- |
| 最好（每次均分） | ⌈log2⁡(n+1)⌉ | O(log2⁡n) |
| 平均 | O(log2⁡n)（实测 n=1023 时约 2log2⁡n） | O(log2⁡n) |
| 最坏（每次极端不均） | n | O(n) |

**说快排空间复杂度是 O(1) 是错的。** 它不用辅助数组不代表不用空间——递归栈是实打实的开销，最坏情况下 n=105 就足以把栈撑爆。

（一个常见的工程做法是：每层**先递归较短的那一侧**，较长的一侧改用循环处理。这样栈深度可以被压到 O(log2⁡n)，代价是代码变复杂。）

### 枢轴选取策略

最坏情况的根源是"枢轴选得太偏"，所以优化都围绕枢轴展开：

- **随机选取枢轴**：在 `[low, high]` 中随机挑一个下标与 `A[low]` 交换，再执行标准划分。这样**任何固定的输入都不会稳定触发最坏情况**（对手无法针对性构造），期望复杂度 O(nlog2⁡n)。
- **三数取中法**：比较 `A[low]`、`A[mid]`、`A[high]` 三者，取**中间值**的那个记录调到 `A[low]` 再划分。它专门针对"输入基本有序"这一最常见的坏情形——对已有序的输入，中间值恰好就是中位数，划分完全平衡。实测：n=1000 的正序输入，取首元素时递归深度 999，三数取中时只有 9（log2⁡1000≈10）。
- **小子表改用直接插入排序**：递归到子表长度小于某个阈值（如 10）时改调 [直接插入排序](./insertion-sort.html)。理由是小规模下插入排序的常数因子更小，且省掉了递归调用的开销。

### 每趟到位几个元素

这是一个需要说准的计数：

- **第 1 趟**：只有 1 个枢轴归位。
- **第 k 趟**（k≥2）：对上一趟产生的每个**非空**子表各做一次划分，各归位 1 个。子表个数最多 2k−1 个，但空子表不产生枢轴，所以第 k 趟新归位的个数≤2k−1,前 k 趟累计归位≤2k−1

实测 `{3, 8, 7, 4, 1, 5, 2, 6}`：第 1 趟归位 1 个，第 2 趟归位 2 个（累计 3 个）。

因此判断"某状态能否是快排第 2 趟的结果"，要数满足分界性质的元素个数：**至少 2 个（左右子表各贡献 1 个，若某侧为空则更少）、最多 3 个**。这一判据的完整用法见 [由中间状态反推排序算法](./identify-state.html)。

### 稳定性：不稳定

**最小反例：`{3a, 3b, 2}`**

| 步 | 动作 | 结果 |
| --- | --- | --- |
| 初始 | `pivot = A[0] = 3a`，`low = 0, high = 2` | `_ 3b 2` |
| 1 | high 扫描：`A[2] = 2 < 3` 停；`A[0] = A[2]` | `2 3b _` |
| 2 | low 扫描：`A[0] = 2 <= 3` `low++`；`A[1] = 3b <= 3` `low++`，`low == high = 2` 退出 | `2 3b _` |
| 3 | `A[2] = pivot = 3a` | `2 3b 3a` |

排序后 `3b` 排在 `3a` 前面，相对次序被改变，**故不稳定**。

**根源**：枢轴 `3a` 被从下标 0 直接搬到下标 2，一步跨过了与它相等的 `3b`，而这个跨越过程中两者从未被直接比较过——与 [希尔排序](./shell-sort.html)、[简单选择排序](./selection-sort.html)、[堆排序](./heap-sort.html) 不稳定的根源完全相同。

### 为什么难以用于链表

划分过程需要**定位子表的下界和上界，并让两个指针从两端向中间相向移动**。链表上：

- 单链表无法反向移动，`high--` 做不到；
- 即使用双链表，也无法 O(1) 地知道"子表的末尾在哪"，每次都要遍历。

所以快速排序适合顺序结构，很难用于链式结构。链表上要做 O(nlog⁡n) 排序，应选 [二路归并排序](./merge-sort.html)——它只需要顺序访问。

### 汇总

| 指标 | 最好 | 平均 | 最坏 | 说明 |
| --- | --- | --- | --- | --- |
| 时间复杂度 | O(nlog2⁡n) | O(nlog2⁡n) | O(n2) | 最坏在"初始有序 + 取首元素为枢轴"时触发 |
| 空间复杂度 | O(log2⁡n) | O(log2⁡n) | O(n) | 全部来自**递归栈**，深度 = 递归树高 |
| 稳定性 | **不稳定** |  |  | 反例 `{3a, 3b, 2}` |
| 趟数 | **与初始序列有关** |  |  | 等于递归树的深度 |
| 存储结构 | **适合顺序表**，难用于链表 |  |  | 需要定位上下界、双向扫描 |
| 每趟特征 | 枢轴到达最终位置，**不一定是极值** |  |  | 与冒泡/选择的"全局最值就位"要分清 |

## 易混淆知识点

| 对比项 | A | B | 判别依据 |
| --- | --- | --- | --- |
| **快排就位的 vs 冒泡就位的** | 快排：**枢轴**，位置在区间中间某处 | 冒泡：当前区间的**全局最值**，位置在一端 | 看就位元素在哪、是不是极值。中间状态里"某元素左边全 ≤ 它、右边全 ≥ 它"是快排的指纹 |
| **最坏情况的触发输入** | 快排：**已有序**（正序或逆序）时最坏 | 插入/冒泡：**已有序**时最好 | 快排的效率取决于划分是否均匀，与逆序对多少无关 |
| **空间 O(1) vs O(log⁡n)** | 堆排序：真正的 O(1) | 快排：O(log2⁡n)∼O(n)，来自递归栈 | 问"有没有递归"。有递归就必须把栈深度算进空间复杂度 |
| **`>=` vs `>`** | `A[high] >= pivot`：正确 | `A[high] > pivot`：存在相等元素时**死循环** | 反例 `[5, 5]`：用 `>` 时两个指针都不动，外层 `while` 空转 |
| **挖坑法 vs 两端交换法** | 挖坑法：只做单向赋值，最后枢轴填坑 | 两端交换法：成对交换，最后枢轴与分界处交换 | 两者枢轴位置通常相同，**但中间排列不同**。按题给代码走，题目没给就按挖坑法 |
| **快排 vs 归并的递归结构** | 快排：**先划分后递归**（划分做实事，回来什么都不做） | 归并：**先递归后合并**（下去什么都不做，回来才做实事） | 看"工作量"落在递归调用之前还是之后 |
| **平均最快 vs 最坏最优** | 快排：平均最快，但最坏 O(n2) | 归并、堆排：任何输入下都保证 O(nlog2⁡n) | 要求"对任意输入都保证 O(nlog⁡n)"时，快排出局 |

## 本节小结

学完本节，应该能够：

- **手动模拟一趟划分**，逐步写出 `low`、`high` 的移动与数组状态，并说清枢轴最终落在哪
- **说清 `>=` / `<=` 不能改成 `>` / `<`**，并用 `[5, 5]` 说明改了会死循环
- **区分挖坑法与两端交换法**，知道两者划分结果可能不同、答题应按题给代码
- **推出最好情况**：T(n)=Cn+2T(n/2) 展开成 kn+2kT(n/2k)，k=log2⁡n 时得 O(nlog2⁡n)；并用"树高 log2⁡n × 每层 O(n)"复述
- **推出最坏情况**：递归树退化成单支链，KCN=∑i=1n−1(n−i)=n(n−1)/2，即 O(n2)
- **说准最坏的触发条件**：初始序列有序（正序或逆序）且取首元素为枢轴——并解释为什么"已有序"对快排反而是最坏输入
- **说清空间复杂度来自递归栈**，最好 O(log2⁡n)、最坏 O(n)，绝不是 O(1)
- **说出三种枢轴优化**（随机化、三数取中、小表转插入排序）各自针对什么问题
- **数清第 k 趟到位元素的个数**：第 1 趟 1 个，前 k 趟累计最多 2k−1 个
- **用 `{3a, 3b, 2}` 举出不稳定的反例并推到底**
- **说清它为什么难以用于链表**

三条最关键的结论：

- **快排的效率取决于划分是否均匀，与逆序对多少无关**——这解释了它"最怕有序输入"这一与其他 O(n2) 算法完全相反的特性。
- **空间复杂度 = 递归深度 = 递归树高**，这是本章唯一一个空间复杂度随输入变化的算法。
- **一趟划分让枢轴就位，但枢轴不一定是极值**——判别中间状态时靠"左小右大的分界元素"，不靠"某端聚集最值"。

- 算法特点："记录非顺次的移动导致排序方法是不稳定的"；"排序过程中需要定位表的下界和上界，所以适合用于顺序结构，很难用于链式结构"；"当 n 较大时，在平均情况下快速排序是所有内部排序方法中速度最快的一种"：同书 p246
