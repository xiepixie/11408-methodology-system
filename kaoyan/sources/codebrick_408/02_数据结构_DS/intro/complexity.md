# 算法和算法评价

## 大纲定位

本篇对应 2026 大纲 **一、基本概念（二）算法的基本概念**。

大纲对数据结构这一科的总体要求里，另有一条与本篇直接相关：「**能够对算法进行基本的时间复杂度 与空间复杂度的分析**」。这是一条**能算**级别的要求，所以本篇不停在"知道有大 O 这回事"，而要做到 **给一段没见过的代码，能自己数出基本操作次数、写出复杂度；给一个递归式，能自己解出量级**。

这一条要求的内容全部由本篇承担：算法的定义与五个特性、好算法的评价标准、时间复杂度 （基本操作、语句频度、大 O 与 Ω、Θ、最好/最坏/平均、递归式求解）、 空间复杂度（辅助空间、原地工作、递归栈深度）。

**分工边界**：同章的**一（一）数据结构的基本概念**——三要素、逻辑结构、存储结构、抽象数据 类型——不在本篇，在《[数据结构的基本概念](./concepts.html)》里讲。本篇只借用"同一运算在不同存储 结构下效率不同"这个结论作为动机，不重复讲存储结构本身。

本篇里练出来的分析方法，后面每一章都会直接用上：树与图的遍历用**递归栈深度**估空间， 查找一章用**平均查找长度**这套加权平均的思路，排序一章几乎每个算法都要给出 最好/最坏/平均三档时间与一档空间。**这一篇学不扎实，后面每章都要重新卡一次。**

## 知识框架

本节回答五个问题：

- **一段步骤描述，凭什么判定它是不是"算法"？** —— 五个特性是五条否决项，任一条不满足就不是。
- **为什么可以只数"基本操作"，而不用数每一条语句？** —— 因为大 O 丢掉了低次项和系数， 而基本操作的频度与总频度只差低次项和系数。
- **循环怎么数、递归怎么解？** —— 循环归结为七种基本形态；递归归结为"逐层展开"与"主定理"。
- **"最坏"和"O"是同一件事吗？** —— 不是。最坏说的是**挑哪个输入**，O 说的是 **函数之间的关系**，两者正交。
- **空间复杂度里最容易漏的是什么？** —— 递归工作栈。它的量级等于**递归深度**， 不是递归调用的总次数。

## 算法的定义与五个特性

**算法（Algorithm）是为了解决某类问题而规定的一个有限长的操作序列。**

一个算法必须同时满足以下五个特性，缺一条就不是算法：

| 特性 | 含义 | 不满足的反例 |
| --- | --- | --- |
| **有穷性** | 必须总是在执行**有穷步**后结束，且每一步都必须在**有穷时间**内完成 | `while (1) x++;` 永不结束；操作系统的主循环也不结束 |
| **确定性** | 每种情况下应执行的操作都有确切规定，**不产生二义性**，执行者与阅读者都能明确其含义 | "把较大的那个放前面"——两个数相等时怎么办没规定 |
| **可行性** | 所有操作都能通过**已经实现的基本运算执行有限次**来完成 | "取 π 的全部小数位并求和"——基本运算做不完 |
| **输入** | 有**零个或多个**输入 | 打印固定字符串的算法就没有输入，这是允许的 |
| **输出** | 有**一个或多个**输出 | 无输出的算法没有任何意义 |

三处最容易被绕的地方：

- **有穷性 ≠ 确定性**。有穷性强调"**会停下来**"，确定性强调"**不会有歧义**"。一段代码可能 含义完全明确却死循环（违反有穷性），也可能几步就结束却在某种输入下不知道该走哪个分支 （违反确定性）。
- **输入可以是 0 个，输出不能是 0 个**。这条不对称是纯记忆项，但记的时候可以想理由： 没有输入的算法仍然能算出东西（比如打印九九乘法表），没有输出的算法则连"算出了什么"都无从 谈起。
- **有穷性还包含"每一步在有穷时间内完成"**。一个只有三步、但其中一步要遍历无穷集合的过程， 同样不满足有穷性。

### 算法与程序的区别

|  | 算法 | 程序 |
| --- | --- | --- |
| 有穷性 | **必须**有穷 | **可以**无穷（操作系统、服务器主循环） |
| 描述方式 | 自然语言、流程图、伪代码、程序设计语言都可以 | 必须是某种程序设计语言写成 |
| 可执行性 | 不要求机器能直接执行 | 必须机器可执行 |
| 与数据结构的关系 | 算法作用在某种数据结构上；换存储结构，同一算法的实现和效率都会变 | 程序是算法 + 数据结构的具体落地 |

### 好算法的四条标准

判定"是不是算法"用五个特性，判定"是不是**好**算法"用另外四条：

- **正确性**：在合理的数据输入下，能在有限的运行时间内得到正确结果。
- **可读性**：首先便于人理解和交流，其次才是机器可执行性。难懂的算法容易藏错误，也难以调试 和修改。
- **健壮性**：输入数据非法时能做出适当反应或进行相应处理，而不是产生莫名其妙的输出或直接崩溃。
- **高效性**：包括**时间高效**（执行效率高）与**低存储量需求**（占用辅助空间少）两个方面。

有的教材把第 4 条拆成"高效率"和"低存储量需求"两条，于是列出五条标准——**这只是同一件事的 不同切分方式**，两种说法都对。本篇按四条讲，但要知道"高效性"里含着时间与空间两个维度。

时间与空间常常是此消彼长的：为了降低时间复杂度多开一个数组，空间复杂度就上去了；反之亦然。 所以"高效"不是单一指标，而是一个权衡。通常情况下，由于运算空间较为充足，人们以**时间复杂度** 作为衡量算法优劣的主要指标。

## 时间复杂度：从语句频度到大 O

### 为什么不能直接跑一遍计时

**事后统计法**（把算法写成程序跑一遍，测运行时间）有两个致命问题：一是结果受机器速度、 编译器质量、操作系统调度的影响，换台机器结论就变；二是必须先把算法实现出来才能比较， 而我们希望在**动手写之前**就能判断优劣。

所以采用**事前分析估算法**：抛开硬件与软件环境，只统计算法中**基本操作的执行次数**， 把它作为时间度量。

### 语句频度与 T(n)

一条语句的**重复执行次数**称为该语句的**语句频度**。若假定每条语句执行一次所需的时间都是 一个单位时间，那么算法的执行时间就可以用**所有语句频度之和** T(n) 来度量，它是问题规模 n 的函数。

先完整算一遍，看清楚 T(n) 是怎么来的：c

```
/* 求 n×n 矩阵所有元素之和 */
int MatrixSum(int a[][N], int n) {
    int sum = 0;                      /* 频度 1 */
    for (int i = 0; i < n; i++)       /* 条件判断执行 n+1 次（最后一次判断为假才跳出） */
        for (int j = 0; j < n; j++)   /* 对每个 i 判断 n+1 次，共 n(n+1) 次 */
            sum += a[i][j];           /* 频度 n²，这是基本操作 */
    return sum;                       /* 频度 1 */
}
```
T(n)=1+(n+1)+n(n+1)+n2+1=2n2+2n+3

注意两处细节：

- **循环的条件判断要多算一次**。`for (i = 0; i < n; i++)` 的循环体执行 n 次，但条件 `i < n` 被判断了 n+1 次——最后那次判断为假，才跳出循环。这是手算频度时最常漏的一处。
- **内层循环的判断次数是 n(n+1) 而不是 n2**，因为内层循环每被进入一次就要多判断一次。

### 只数基本操作就够了

上面这样逐条数太累，而且对稍复杂的算法几乎做不到。观察 T(n)=2n2+2n+3 与最内层语句的 频度 n2：**两者只差常数系数和低次项**。而大 O 恰好要丢掉常数系数和低次项，所以直接数最 内层那条语句就够了。

**基本操作**（也叫基本语句）指的是：算法中**重复执行次数与算法执行时间成正比**的语句， 它对运行时间的贡献最大。找基本操作的可操作办法：

**找到嵌套最深、执行次数最多的那条语句。** 循环里找最内层的循环体；有多段并列时， 分别找各段的基本操作再取量级最大者；涉及函数调用时，要钻进被调函数里去找。

按语义再挑一次会更贴题：查找类算法的基本操作是**关键字比较**，排序类算法的基本操作是 **比较**和**移动（交换）**，这也是后面几章统一使用的口径。

### 大 O 记号的定义与计算规则

**定义**：若存在正的常数 c 和 n0，使得对所有 n≥n0 都有 T(n)≤c⋅f(n)， 则记 T(n)=O(f(n))。

拆开看这个定义在说什么：

- c 的存在意味着**常数系数被忽略**——3n 和 100n 都是 O(n)；
- n0 的存在意味着**只关心 n 足够大以后的行为**——小规模上谁快谁慢，大 O 不管；
- 不等号方向是 ≤，所以大 O 描述的是 T(n) 的**渐近上界**。

由此得到三条计算规则：

- **多项式取最高次项**：若 T(n)=amnm+am−1nm−1+⋯+a1n+a0 是一个 m 次 多项式，则 T(n)=O(nm)。低次项与所有系数一律丢掉。
- **加法规则（两段并列）**：T(n)=T1(n)+T2(n)=O(f(n))+O(g(n))=O(max(f(n),g(n)))。
- **乘法规则（两层嵌套）**：T(n)=T1(n)×T2(n)=O(f(n))×O(g(n))=O(f(n)⋅g(n))。

乘法规则有一个常用的特例：若 T1(n)=O(c)（c 是与 n 无关的常数），则 T(n)=O(c⋅f(n))=O(f(n))——**任何非零正常数在大 O 里都属于同一数量级，记为 O(1)**。 所以 `for (i = 0; i < 10000; i++) x++;` 的时间复杂度仍然是 O(1)：循环次数再多，只要**不随 n 增长**，就是常数阶。

### O、Ω 与 Θ

大纲要求「算法的基本概念」，这三个渐近记号是一套，只认得 O 是不完整的：

| 记号 | 定义 | 描述的是 | 直观说法 |
| --- | --- | --- | --- |
| T(n)=O(f(n)) | 存在 c>0, n0，使 n≥n0 时 T(n)≤c⋅f(n) | 渐近**上界** | 增长率**不超过** f(n) |
| T(n)=Ω(g(n)) | 存在 c>0, n0，使 n≥n0 时 T(n)≥c⋅g(n) | 渐近**下界** | 增长率**不低于** g(n) |
| T(n)=Θ(h(n)) | T(n)=O(h(n)) 且 T(n)=Ω(h(n)) | 上下界**同阶** | 增长率**就是** h(n) |

三条必须说清的性质：

- **上界不唯一**。T(n)=3n+2 既是 O(n)，也是 O(n2)、O(n3)——定义只要求"不超过"。 写 O(n3) 不算错，但没有信息量，所以**习惯上给出最紧的上界**。同理 Ω 要给最大的下界。
- **Θ 具有对称性**：若 f(n)=Θ(g(n))，则 g(n)=Θ(f(n))。O 和 Ω 没有 这个性质（它们是"在……之中"的关系）。
- **O 与"最坏情况"是两件事**。教材里习惯用 O 描述最坏代价、用 Ω 描述最好代价， 这是**惯例**，不是定义。严格地说，O/Ω/Θ 刻画的是**两个函数之间的增长关系**， 最好/最坏刻画的是**在同一个 n 下挑哪个输入**。两者正交：顺序查找的**最好**情况是 Θ(1)、**最坏**情况是 Θ(n)、**平均**情况是 Θ(n)，三档各自都可以用三种记号 描述。

## 非递归算法：七种循环形态

绝大多数非递归代码的复杂度分析，都可以归到下面七种形态或它们的组合上。下面这段代码整体可编译 运行，每一段单独看即是一种形态：c

```
long long LoopPatterns(int n) {
    long long x = 0;
    int i, j;

    /* 形态 1：单层线性循环 —— 循环体执行 n 次，O(n) */
    for (i = 0; i < n; i++)
        x++;

    /* 形态 2：嵌套且内外层独立 —— n × n 次，O(n²) */
    for (i = 0; i < n; i++)
        for (j = 0; j < n; j++)
            x++;

    /* 形态 3：嵌套且内层上界依赖外层 —— 1+2+…+n = n(n+1)/2 次，O(n²) */
    for (i = 1; i <= n; i++)
        for (j = 1; j <= i; j++)
            x++;

    /* 形态 4：循环变量倍增 —— 循环体执行 ⌊log₂n⌋+1 次，O(log n) */
    i = 1;
    while (i <= n) {
        x++;
        i = i * 2;
    }

    /* 形态 5：循环变量折半 —— 循环体执行 ⌊log₂n⌋ 次，O(log n) */
    i = n;
    while (i > 1) {
        x++;
        i = i / 2;
    }

    /* 形态 6：循环变量平方后与 n 比 —— 执行 ⌊√n⌋+1 次，O(√n) */
    for (i = 0; i * i <= n; i++)
        x++;

    /* 形态 7：两段并列 —— 加法规则，O(max(n, n²)) = O(n²) */
    for (i = 0; i < n; i++)
        x++;
    for (i = 0; i < n; i++)
        for (j = 0; j < n; j++)
            x++;

    return x;
}
```

| 形态 | 判别特征 | 精确次数 | 量级 |
| --- | --- | --- | --- |
| 1 单层线性 | 循环变量按常数步长走完 [0,n) | n | O(n) |
| 2 嵌套独立 | 内层上界与外层变量无关 | n×m（上面代码里 m=n） | O(nm)，代码中即 O(n2) |
| 3 嵌套相关 | 内层上界是外层变量 | 1+2+⋯+n=n(n+1)2 | O(n2) |
| 4 倍增 | 循环变量**乘以**常数 | ⌊log2⁡n⌋+1 | O(log⁡n) |
| 5 折半 | 循环变量**除以**常数 | ⌊log2⁡n⌋ | O(log⁡n) |
| 6 平方比较 | 条件形如 `i*i <= n` | ⌊n⌋+1 | O(n) |
| 7 并列 | 两段顺序执行 | 相加 | 取量级较大者 |

形态 4 和形态 5 差一次，值得把过程走一遍——问"精确执行多少次"时，差的就是这一次：

- 形态 4（`i = 1; while (i <= n) i *= 2;`）：循环体在 i=1,2,4,… 时进入，只要 2t≤n 就还会进一次，所以次数是满足 2t≤n 的 t (t≥0) 的个数，即 ⌊log2⁡n⌋+1。 取 n=8 检验：i 依次取 1,2,4,8，循环体执行 **4** 次，而 ⌈log2⁡8⌉=3—— 可见这里**不能写成** ⌈log2⁡n⌉。
- 形态 5（`i = n; while (i > 1) i /= 2;`）：从 n 开始每次折半，到 1 为止，走了 ⌊log2⁡n⌋ 步。取 n=8 检验：8→4→2→1，执行 **3** 次 =log2⁡8。

差别的来源很简单：形态 4 的循环体在 i=1 时就执行了一次（"从 1 开始撑到 n"）， 形态 5 的循环体在 i=1 时不再执行（"从 n 缩到 1"）。**看循环体在边界值上执不执行**， 就不会记混。

### 例题一：步长随外层变化的双重循环

分析下面代码段的时间复杂度。c

```
long long StepGrows(int n) {
    long long count = 0;
    for (int i = 1; i <= n; i++)
        for (int j = 1; j <= n; j += i)   /* 步长是 i，不是 1 */
            count++;
    return count;
}
```

**第一步：确定基本操作。** 嵌套最深的语句是 `count++`，它就是基本操作，只需数它执行了多少次。

**第二步：固定外层，算内层。** 对给定的 i，内层的 j 依次取 1, 1+i, 1+2i,…， 只要不超过 n 就继续。因此内层执行次数为 ⌊n−1i⌋+1，它不超过 ni+1。

这一步为什么要算成 ⌊(n−1)/i⌋+1 而不是 n/i：j 从 1 起步、每次加 i， 能取到的值是 1+ki (k≥0)，条件 1+ki≤n 等价于 k≤(n−1)/i， 于是 k 有 ⌊(n−1)/i⌋+1 个取值。

**第三步：对外层求和。**总次数=∑i=1n(⌊n−1i⌋+1) ≤ n+n∑i=1n1i=n+nH(n)

其中 H(n)=∑i=1n1i 是**调和级数**，有 H(n)≈ln⁡n+0.5772。 因此总次数是 Θ(nln⁡n)=Θ(nlog⁡n)——换底只差一个常数因子，在大 O 里无差别。

**第四步：核对。** 按上式估算与实际计数对照：

| n | 实际执行次数 | nlog2⁡n | n2 |
| --- | --- | --- | --- |
| 8 | 24 | 24.0 | 64 |
| 16 | 61 | 64.0 | 256 |
| 100 | 573 | 664.4 | 10 000 |
| 1000 | 8 053 | 9 965.8 | 1 000 000 |

实际值贴着 nlog2⁡n 走，与 n2 越拉越开，验证了结论。

**答**：时间复杂度 O(nlog⁡n)；空间复杂度 O(1)（只用了 `count`、`i`、`j` 三个变量）。

**可迁移的一点**：看到双重循环别条件反射写 O(n2)。真正决定量级的是**内层实际执行了多少次**， 而内层的执行次数由三样东西决定：起点、终点、**步长**。这里变的是步长；形态 3 里变的是终点。

## 递归算法：递归式的求解

递归算法的时间复杂度通常先写成一个**递归方程**（递推式），再求解。递归方程有两个部分： **递归项**（子问题的代价）和**非递归项**（把子问题的解合起来所花的代价），另外必须给出**边界 条件**（递归出口的代价）。

### 方法一：逐层展开（迭代法）

思路是把递归式反复代入自身，直到出现规律，再用边界条件收尾。**这是最通用的方法，主定理管不了 的递归式也能解。**

**实例 1（线性递归）**：T(n)=T(n−1)+n，T(1)=1c

```
long long Fact(int n) {
    if (n <= 1) return 1;          /* 递归出口 */
    return n * Fact(n - 1);        /* 问题规模每次减 1 */
}
```

`Fact` 本身每层只做常数次操作，对应 T(n)=T(n−1)+1；若把每层的常数代价换成 n （例如每层都要扫一遍长度为 n 的数组），就得到上面的递归式。展开：T(n)=T(n−1)+n=T(n−2)+(n−1)+n=T(n−3)+(n−2)+(n−1)+n  ⋮=T(1)+2+3+⋯+n=1+(n(n+1)2−1)=n(n+1)2

故 T(n)=Θ(n2)。若非递归项是常数（T(n)=T(n−1)+1），同样展开可得 T(n)=Θ(n)—— 这就是 `Fact` 以及单链表递归遍历的量级。

**实例 2（二分递归）**：T(n)=T(n/2)+1，T(1)=1c

```
/* 在升序数组 a[low..high] 中折半查找 key，找到返回下标，找不到返回 -1 */
int BinSearch(int a[], int low, int high, int key) {
    if (low > high) return -1;             /* 出口：区间为空，查找失败 */
    int mid = low + (high - low) / 2;      /* 这样写而非 (low+high)/2，避免相加溢出 */
    if (a[mid] == key) return mid;
    else if (a[mid] > key)
        return BinSearch(a, low, mid - 1, key);   /* key 更小，只进入左半区间 */
    else
        return BinSearch(a, mid + 1, high, key);  /* key 更大，只进入右半区间 */
}
```

每层只做常数次比较，且**只进入一个子区间**，规模减半，于是 T(n)=T(n/2)+1。展开：T(n)=T(n2)+1=T(n4)+2=⋯=T(n2k)+k

令 n2k=1 得 k=log2⁡n，代回：T(n)=T(1)+log2⁡n=1+log2⁡n， 故 T(n)=Θ(log⁡n)。

**实例 3（每层产生两个子问题、规模只减 1）**：T(n)=2T(n−1)+1，T(1)=1（汉诺塔）

汉诺塔把 n 个盘从 A 移到 C 的做法是：先把上面 n−1 个盘借 C 移到 B，再把第 n 号盘直接从 A 移到 C，最后把 B 上的 n−1 个盘借 A 移到 C。两次规模为 n−1 的递归加一次移动， 正好就是 T(n)=2T(n−1)+1。T(n)=2T(n−1)+1=2(2T(n−2)+1)+1=4T(n−2)+2+1=8T(n−3)+4+2+1=⋯=2kT(n−k)+(2k−1)

令 k=n−1：T(n)=2n−1T(1)+2n−1−1=2n−1，故 T(n)=Θ(2n)。 取 n=1,2,3,4 检验，移动次数分别是 1,3,7,15，与 2n−1 逐个吻合。

### 方法二：递归树

把每一层的**非递归代价**摊在树上，逐层求和。适合 T(n)=aT(n/b)+f(n) 这一类。

以归并排序的 T(n)=2T(n/2)+n 为例：

- 第 i 层（根为第 0 层）有 2i 个子问题，每个子问题规模为 n/2i；
- 每个子问题的非递归代价（归并一趟）是 n/2i；
- 因此**该层总代价** =2i×n2i=n——**每一层都是 n，与层号无关**；
- 层数：规模从 n 折半到 1，共 log2⁡n+1 层。

总代价 =n×(log2⁡n+1)=Θ(nlog⁡n)。

"每层 O(n)、共 O(log⁡n) 层，故 O(nlog⁡n)"——这句话就是递归树法的完整推导， 后面归并排序、快速排序的复杂度都是这么来的，不要当成需要背的结论。

### 方法三：主定理（可用形式）

对形如T(n)=aT(nb)+f(n),a≥1, b>1

的递归式，记 d=logb⁡a，把 nd 与 f(n) 比较：

| 情形 | 条件 | 结论 |
| --- | --- | --- |
| 1 | f(n) 比 nd **低一个多项式量级**：存在 ε>0 使 f(n)=O(nd−ε) | T(n)=Θ(nd) |
| 2 | f(n) 与 nd **同阶**：f(n)=Θ(nd) | T(n)=Θ(ndlog⁡n) |
| 3 | f(n) 比 nd **高一个多项式量级**：存在 ε>0 使 f(n)=Ω(nd+ε)，且存在常数 c<1 使 n 充分大时 af(n/b)≤cf(n) | T(n)=Θ(f(n)) |

**一句话用法**：算出 nlogb⁡a，跟 f(n) 比谁大，**大的赢**；一样大就再乘一个 log⁡n。

| 递归式 | a | b | nlogb⁡a | f(n) | 谁大 | 结论 | 出现在 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| T(n)=T(n/2)+O(1) | 1 | 2 | n0=1 | 1 | 同阶 | Θ(log⁡n) | 折半查找 |
| T(n)=2T(n/2)+O(1) | 2 | 2 | n | 1 | n 大 | Θ(n) | 二叉树遍历、求树的结点数 |
| T(n)=2T(n/2)+O(n) | 2 | 2 | n | n | 同阶 | Θ(nlog⁡n) | 归并排序、快排的平均情形 |
| T(n)=2T(n/2)+O(n2) | 2 | 2 | n | n2 | n2 大 | Θ(n2) | —— |

**边界（必须知道）**：主定理只适用于**规模按倍数缩小**的 T(n)=aT(n/b)+f(n)。 对**规模按常数递减**的 T(n)=T(n−1)+f(n)、T(n)=2T(n−1)+f(n)，主定理**不适用**， 只能用逐层展开——上面的实例 1 和实例 3 就是这一类。这也是为什么逐层展开必须掌握， 不能只背主定理。

二叉树遍历那一行要加一句限定：T(n)=2T(n/2)+O(1) 描述的是**平衡**二叉树。一般的二叉树 应写成 T(n)=T(k)+T(n−1−k)+O(1)（左子树 k 个结点、右子树 n−1−k 个结点）， 不论 k 取什么，展开后每个结点恰好被访问一次，总代价都是 Θ(n)——结论不变， 但推导过程不同。

## 最好、最坏与平均情况

有些算法的基本操作频度**不只与问题规模 n 有关，还与输入数据本身有关**。这时同一个 n 会对应 不同的执行次数，于是分三档讨论。

| 情况 | 定义 | 说明 |
| --- | --- | --- |
| **最好时间复杂度** | 算法计算量可能达到的**最小值** | 容易求，但实际意义有限——最好情况出现的概率通常极小 |
| **最坏时间复杂度** | 算法计算量可能达到的**最大值** | 给出运行时间的上界保证，**默认讨论的就是它** |
| **平均时间复杂度** | 所有可能输入**按等概率出现**时，计算量的**加权平均值** | 最贴近实际，但往往需要概率统计知识，有时难以确定 |

**三档比较的是同一个 n 下的不同输入，不是不同的 n。** 这是最容易走神的一点。 以直接插入排序为例：n=1000 时，若输入已经升序，只需 n−1 次比较、0 次移动，是最好情况 O(n)；若输入恰好逆序，每个元素都要一路移到最前面，是最坏情况 O(n2)。**规模没变， 变的是输入的初始状态。**

### 平均情况的前提是"各输入等概率"

以在长度为 n 的数组中顺序查找为例。假设待查元素在 n 个位置上出现的可能性**均相同** （各为 1/n），查找成功时比较次数的平均值为1n∑i=1ni=n+12

于是平均时间复杂度是 O(n)，与最坏情况同一量级——两者只差系数，不差量级。

**前提变了，结论就变。** 若已知待查元素有 50% 的概率就在第 1 个位置，其余 n−1 个位置均分 剩下的 50%，则平均比较次数为0.5×1+∑i=2n0.5n−1×i=0.5+n+24

取 n=4 核对：等概率时是 4+12=2.5 次，而按上式是 0.5+64=2.0 次； n=10 时分别是 5.5 次与 3.5 次。**量级仍是 O(n)，但常数变了。** 这说明"平均"这个词 永远附带一个概率分布假设，**题目不说明分布时，默认就是等概率**；一旦题目给了别的分布， 就必须按给定分布重算。

### 默认取最坏

对时间复杂度的度量，人们更关心最坏情况和平均情况。但平均情况往往难以确定，因此**除非特别指明， 讨论的时间复杂度一律指最坏情况下的时间复杂度**，也就是算法执行时间的上界。后面各章沿用这个 约定，只在排序一章会同时给出三档。

## 常见量级与增长直觉

常见时间复杂度按数量级递增排列：O(1)<O(log⁡n)<O(n)<O(nlog⁡n)<O(n2)<O(n3)<O(2n)<O(n!)<O(nn)

| 复杂度 | 名称 | 典型算法 |
| --- | --- | --- |
| O(1) | 常数阶 | 数组按下标访问、散列查找（理想情况） |
| O(log⁡n) | 对数阶 | 折半查找、二叉排序树查找（平均） |
| O(n) | 线性阶 | 顺序查找、遍历一遍数组或链表 |
| O(nlog⁡n) | 线性对数阶 | 快速排序（平均）、归并排序、堆排序 |
| O(n2) | 平方阶 | 直接插入排序、起泡排序、简单选择排序 |
| O(n3) | 立方阶 | 三重循环（如 Floyd 算法） |
| O(2n) | 指数阶 | 穷举所有子集、汉诺塔 |
| O(n!) | 阶乘阶 | 穷举所有排列 |

光看排序不够，要建立"差多少"的量感。假设一台机器每秒执行 109 次基本操作：

| 规模 | log2⁡n | n | nlog2⁡n | n2 | n3 | 2n |
| --- | --- | --- | --- | --- | --- | --- |
| n=10 | 3.3 | 10 | 33 | 100 | 1 000 | 1 024 |
| n=103 | 10 | 103 | ≈104 | 106（1 ms） | 109（1 秒） | ≈10301 |
| n=106 | 20 | 106（1 ms） | ≈2×107（20 ms） | 1012（约 17 分钟） | 1018（约 32 年） | 无法完成 |

三条可以记住的量感：

- **log⁡n 几乎等于免费**：n 从一千涨到一百万（103 倍），log2⁡n 只从 10 涨到 20。 所以把 O(n) 改进成 O(log⁡n) 的收益是巨大的，这正是折半查找、二叉排序树、B 树存在的理由。
- **nlog⁡n 与 n 差得不多**：n=106 时也只差 20 倍。所以基于比较的排序做到 O(nlog⁡n) 已经很接近线性了。
- **n2 到 n3 是灾难性的一跳**：同样 n=106，一个是十几分钟，另一个是几十年。 指数阶 O(2n) 则在 n 稍大时就完全不可用。

**注意**：大 O 描述的是增长趋势，只在 n 足够大时才有意义。O(n) 的算法**不一定**比 O(n2) 的算法快——若前者是 1000n、后者是 n2，则 n<1000 时反而是后者更快。 这也是为什么实际的排序实现常在子问题规模很小时切换成直接插入排序。

## 空间复杂度

空间复杂度 S(n)=O(g(n)) 度量的是算法运行过程中**临时占用的辅助存储空间**的量级。

**不算在内的**：程序本身的指令、常数、以及**输入数据本身占用的空间**——后者由问题决定， 与算法无关，把它算进来所有算法就都是 O(n) 了，失去了比较的意义。 **算在内的**：算法执行时额外申请的变量、数组、以及**递归工作栈**。

| 空间复杂度 | 含义 | 例子 |
| --- | --- | --- |
| O(1) | **原地工作**（in-place），只用常数个额外变量 | 起泡排序、直接插入排序、简单选择排序、堆排序 |
| O(log⁡n) | 递归深度为 log⁡n | 折半查找（递归实现）、快速排序（平均） |
| O(n) | 需要与输入规模同量级的辅助空间 | 归并排序的辅助数组、快速排序（最坏的递归栈） |

对照一组原地与非原地的实现：c

```
/* 原地逆置：S(n) = O(1)，全程只用了 i、j、t 三个额外变量 */
void Reverse(int a[], int n) {
    int i = 0, j = n - 1, t;
    while (i < j) {                     /* i == j 时中间那个元素不用换，直接停 */
        t = a[i]; a[i] = a[j]; a[j] = t;
        i++; j--;
    }
}

/* 借助辅助数组逆置：S(n) = O(n)，多开了一个长度为 n 的数组 */
void ReverseCopy(int a[], int n) {
    int *b = (int *)malloc(sizeof(int) * n);
    for (int i = 0; i < n; i++) b[i] = a[n - 1 - i];
    for (int i = 0; i < n; i++) a[i] = b[i];
    free(b);                            /* 申请了就要释放 */
}
```

两者时间复杂度都是 O(n)，空间复杂度一个 O(1)、一个 O(n)——**这是"时间相同、空间不同" 最干净的一组对照**，也说明为什么评价算法时两个指标都要给。

### 递归算法的空间复杂度 = O(递归深度)

这是本篇最需要练熟的一点，因为后面树、图、排序三章反复要用。

每调用一次函数，系统就在栈顶为它分配一块存储区（**活动记录**，含实参、返回地址、局部变量）， 函数返回时释放。递归调用相当于多层嵌套调用，所以：

**当每层递归只占用常数空间时，空间复杂度 = 递归工作栈的最大深度，也就是"同时存在于栈上的 递归层数的最大值"。**

**关键在于"最大深度"而不是"调用总次数"。** 递归是深度优先展开的：某一层的左边分支彻底做完 并出栈之后，右边分支才入栈，**两者不会同时在栈上**。所以栈上最多只有从根到某个叶子的一条路径。

用两个只差一处的例子把这一点逼出来：c

```
/* A：只递归一边 —— 时间 O(log n)，递归深度 O(log n) */
int BinSearch(int a[], int low, int high, int key) {
    if (low > high) return -1;
    int mid = low + (high - low) / 2;
    if (a[mid] == key) return mid;
    else if (a[mid] > key)
        return BinSearch(a, low, mid - 1, key);
    else
        return BinSearch(a, mid + 1, high, key);
}

/* B：两边都递归 —— 统计 key 在区间中出现了几次 */
int CountKey(int a[], int low, int high, int key) {
    if (low > high) return 0;
    int mid = low + (high - low) / 2;
    int c = (a[mid] == key) ? 1 : 0;
    return c + CountKey(a, low, mid - 1, key)
             + CountKey(a, mid + 1, high, key);   /* 左右两边都要进 */
}
```

|  | 递归式 | 时间 | 递归树上同时在栈的层数 | 空间 |
| --- | --- | --- | --- | --- |
| A `BinSearch` | T(n)=T(n/2)+O(1) | O(log⁡n) | 根到叶一条路径 | O(log⁡n) |
| B `CountKey` | T(n)=2T(n/2)+O(1) | O(n) | 仍是根到叶一条路径 | O(log⁡n) |

**结论**：A 与 B 的形状只差"进一个子区间"还是"进两个子区间"，**时间从 O(log⁡n) 变成 O(n)，空间却都是 O(log⁡n)**。时间数的是**递归树的结点总数**，空间数的是**递归树的高度**， 两者是不同的量。

按这条口径过一遍后面会遇到的典型情形：

| 算法 | 递归深度 | 其他辅助空间 | 空间复杂度 | 深度为什么是这个值 |
| --- | --- | --- | --- | --- |
| 阶乘 / 单链表递归遍历 | n | O(1) | O(n) | 规模每次只减 1，要减 n 次才到底 |
| 折半查找（递归） | ⌊log2⁡n⌋+1 | O(1) | O(log⁡n) | 规模每次减半 |
| 汉诺塔 | n | O(1) | O(n) | 规模每次减 1；时间虽是 O(2n)，栈上仍只有一条路径 |
| 二叉树先序遍历（递归） | 树高 h | O(1) | 最坏 O(n)、平衡时 O(log⁡n) | 深度就是树高；单支树时 h=n |
| 归并排序 | O(log⁡n) | 辅助数组 O(n) | O(n) | 两项取**较大**者，n>log⁡n |
| 快速排序 | 平均 O(log⁡n)、最坏 O(n) | O(1) | 平均 O(log⁡n)、最坏 O(n) | 划分越均匀树越矮；**若每次划分都把区间切成 0 和 n−1**（例如输入已有序且取首元素为枢轴），递归退化成一条长度为 n 的链 |

### 形参占不占空间

一条容易被误传的说法是"传值调用会拷贝整个数组，所以要算进空间复杂度"。在 **C 语言里这句话 需要修正**：

- **数组作形参会退化成指针**。`void f(int a[], int n)` 与 `void f(int *a, int n)` 完全等价， 调用时传的是首地址，**不产生数组拷贝**，只占一个指针的空间，是 O(1)。
- **结构体按值传入才会真的拷贝**。若把一个含有长度为 `MaxSize` 的数组成员的顺序表结构体 `SqList L` 按值传给函数，每层调用都会复制一整份，这部分空间必须算入；写成 `SqList *L` 或（在类 C 描述里）`SqList &L` 就不会。
- 因此在递归函数里，**尽量传指针/引用而非结构体本身**——否则空间复杂度会从 O(深度) 变成 O(深度×结构体大小)。

## 易混淆知识点

| 易混对象 | 判别依据 | 结论 |
| --- | --- | --- |
| 有穷性 vs 确定性 | 问"它会不会停"还是问"它会不会有歧义" | 有穷性管"停不停"，确定性管"歧义有没有" |
| 算法 vs 程序 | 允不允许无穷执行；必不必须用程序设计语言写 | 算法必须有穷、可用自然语言/流程图描述；程序可以无穷、必须可执行 |
| 最坏情况 vs 大 O | 一个在挑**输入**，一个在描述**函数关系** | 两者正交。最好情况也能用 O 写，最坏情况也能用 Θ 写 |
| O vs Θ | 上界成立就能写 O；要写 Θ 必须上下界同阶 | 3n+2 是 O(n2)（对，但松），是 Θ(n)（紧） |
| 时间复杂度 vs 实际运行时间 | 大 O 丢掉了系数与低次项 | O(n) 的算法在小规模上可能比 O(n2) 的慢 |
| 循环体次数 vs 条件判断次数 | 判断比执行多一次（最后一次判断为假才退出） | `for(i=0;i<n;i++)`：循环体 n 次、条件判断 n+1 次 |
| `i=1;while(i<=n)i*=2` vs `i=n;while(i>1)i/=2` | 看循环体在边界值上执不执行 | 前者 ⌊log2⁡n⌋+1 次，后者 ⌊log2⁡n⌋ 次；n=8 时是 4 次与 3 次 |
| 递归的时间 vs 递归的空间 | 时间数递归树的**结点总数**，空间数递归树的**高度** | `CountKey` 时间 O(n)、空间 O(log⁡n)，两者可以差一个量级 |
| 主定理 vs 逐层展开 | 递归式是 T(n/b)（除法型）还是 T(n−1)（减法型） | 除法型两者都行；**减法型只能逐层展开**，主定理不适用 |
| 空间复杂度算不算输入数据 | 输入所占空间由问题决定，与算法无关 | 只算**辅助空间**；对 n 个元素排序，那 n 个元素的空间不计入 |
| 原地工作 vs 不需要额外内存 | 原地工作要求辅助空间是**常数级**，不是零 | 起泡排序交换时用的那个临时变量不影响它是 O(1) |

## 本节小结

学完这一节，应该能做到：

- 用**五个特性**逐条否决一段"步骤描述"，并对每一条说出一个具体反例；说清**有穷性与确定性** 的分工，以及**输入可以为 0 个、输出不能为 0 个**这条不对称。
- 说出**算法与程序**的三处区别，以及好算法的**四条评价标准**（正确性、可读性、健壮性、高效性）， 并知道"高效性"里同时含着时间与空间。
- 对给定代码段，**找出基本操作、数清循环次数、写出精确的 T(n) 再取量级**；能算对 `for` 循环的条件判断次数（比循环体多 1 次）。
- 认出**七种循环形态**，尤其能区分倍增（⌊log2⁡n⌋+1 次）与折半 （⌊log2⁡n⌋ 次），并能处理**步长随外层变化**这类内层次数不固定的情形。
- 写出**大 O、Ω、Θ** 的定义，说清上界不唯一、Θ 有对称性、 以及"最坏"与"O"是两个正交的概念。
- 用**逐层展开法**求解 T(n)=T(n−1)+f(n)、T(n)=T(n/2)+f(n)、T(n)=2T(n−1)+f(n) 三类递归式； 用**递归树**推出 T(n)=2T(n/2)+n 的 Θ(nlog⁡n)；用**主定理**快速判定 T(n)=aT(n/b)+f(n)，并知道主定理**对减法型递归式不适用**。
- 说清**最好/最坏/平均**三档比较的是同一个 n 下的不同输入；写出顺序查找在等概率假设下的平均 比较次数 n+12，并知道**换一个概率分布结论就要重算**。
- 排出常见量级的大小顺序，并能说出 log⁡n 近乎免费、n2→n3 是灾难性一跳这类量感。
- 分析**空间复杂度**：只算辅助空间；判定一个算法是否**原地工作**；把**递归工作栈**算成 O(递归深度)，并说清"深度是递归树的高度，不是结点总数"。

三个最关键的结论：

- **时间复杂度分析的是基本操作的执行次数，不是运行时间。** 大 O 丢掉了常数系数与低次项， 只在 n 足够大时才有意义。
- **递归的时间与空间量级可以相差很大。** 时间数的是递归树的结点总数，空间数的是递归树的高度； `CountKey` 那个例子里前者 O(n)、后者 O(log⁡n)。
- **主定理只管"规模按倍数缩小"的递归式。** 遇到 T(n)=T(n−1)+f(n) 一律逐层展开， 这是求解递归式的兜底方法。

## 教材出处

- 严蔚敏《数据结构（C 语言版）》（第 2 版），p11：算法的定义（"为了解决某类问题而规定的一个 有限长的操作序列"）与**五个特性**的完整表述；评价算法优劣的四条标准（正确性、可读性、 健壮性、高效性）。
- 同书 p12：**语句频度**的定义（"一条语句的重复执行次数"）；"算法分析并非精确统计实际执行时间， 而是针对语句的执行次数做出估计"；**基本语句**的定义（"重复执行次数和算法的执行时间成正比的 语句"）；矩阵乘法的逐句频度统计示例。
- 同书 p13：大 O 的定义（存在 C 与 n0 使 n≥n0 时 T(n)≤Cf(n)，描述增长率的 上限）；**定理 1.1**（m 次多项式的时间复杂度为 O(nm)，可忽略低次幂项与最高次幂的系数）； 以及"递归算法的时间复杂度通常用递归方程表示，涉及递归方程求解"。
- 同书 p13~p14：常量阶、线性阶、立方阶、对数阶四个分析示例；常见时间复杂度按数量级递增的排列 （常量阶、对数阶、线性阶、线性对数阶、平方阶、立方阶、k 次方阶、指数阶）。
- 同书 p15：**最好、最坏、平均时间复杂度**的定义——平均时间复杂度是"按照输入实例以**等概率** 出现时算法计算量的加权平均值"；顺序查找在等概率假设下平均频度为 n/2 的推导； 以及"除特别指明外，均指最坏情况下的时间复杂度"这条默认约定。
- 同书 p15~p16：**空间复杂度**的定义——只分析算法实现时所需的**辅助存储空间**，输入数据所占 存储量取决于问题本身、与算法无关；以及时间与空间"可能此消彼长"的权衡。
- 同书 p65~p67：函数调用与返回时系统各做的三件事、**递归工作栈**与活动记录的进栈/退栈过程 （以 `Fact` 的逐层活动记录图为例）；汉诺塔问题的递归解法与"规模减 1"的分解方式。
- 殷人昆《数据结构——用面向对象方法与 C++ 描述》（第 2 版），p33~p34：大 O 表示法的一般提法 （"当且仅当存在正整数 c 和 n0 使 T(n)≤cf(n) 对所有 n≥n0 成立"）与线性、平方、 指数、常数四个函数的验证例子；**加法规则**；量级序列 c<log2⁡n<n<nlog2⁡n<n2<n3<2n<3n<n!。
- 同书 p35：**乘法规则**及其常数特例（"任何非 0 正常数都属于同一数量级，记为 O(1)"）； 各函数随 n 增长的数值对照表；**渐近空间复杂度**的定义，明确指出计入的是 "排序算法中为移动数据所需的临时工作单元、**递归算法中所需的递归工作栈**"。
- 同书 p36~p37：**Ω 记号**的定义（存在 c 与 n0 使 n≥n0 时 T(n)≥cg(n)） 与"取最紧下界"的约定；**Θ 记号**的定义（上下界同阶）及其对称性；顺序搜索在最好、最坏、 平均三档下分别为 Ω(1)、O(n)、Θ(n) 的完整分析。

主定理不在上述两本教材的正文中，本篇把它作为**求解 T(n)=aT(n/b)+f(n) 的工具**给出， 并同时给出逐层展开法——后者才是两本教材共同采用的方法，也是减法型递归式唯一可用的方法。
