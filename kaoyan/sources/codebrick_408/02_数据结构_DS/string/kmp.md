## 知识框架

本节回答 5 个问题：

- 失配时模式串到底能向右滑多远？这个距离凭什么可以**只看模式串**就算出来？
- `next[j] = k + 1` 里那个 **+1** 是从哪冒出来的？换个下标约定它会不会消失？
- 求 next 的代码里 `k = next[k]` 为什么是对的？——它不是技巧，是**模式串对自身做 KMP**。
- KMP 凭什么是 O(n+m)？"i 不回退"只说明了一半，另一半是 j 的回退总量也有界。
- nextval 在什么输入上真能省比较，什么输入上和 next 一模一样？

## 从 BF 的浪费出发

以主串 S="aaaaaab"、模式串 T="aaab" 为例，看 BF 是怎么做的（n=7，m=4）：

| 趟 | 对齐起点 | 比较的主串位置 | 比较次数 | 结果 |
| --- | --- | --- | --- | --- |
| 1 | 1 | i=1,2,3,4 | 4 | 第 4 个字符失配（a≠b），i 退回 2 |
| 2 | 2 | i=2,3,4,5 | 4 | 第 4 个字符失配，i 退回 3 |
| 3 | 3 | i=3,4,5,6 | 4 | 第 4 个字符失配，i 退回 4 |
| 4 | 4 | i=4,5,6,7 | 4 | 匹配成功，返回位置 4 |

照上表数一遍主串每个位置被读了几次：位置 4 被四趟全读到，读了 4 遍；位置 3 与位置 5 各读了 3 遍。KMP 要消掉的就是这些重复读取。

**一般化。** 设本趟比到 Si 与 Tj 时失配（j>1），此刻我们**确切知道**：T1T2⋯Tj−1=Si−j+1Si−j+2⋯Si−1

于是问题可以精确地提出来：

主串指针 i 保持不动，模式串应该向右滑到什么位置，使得 Si 与模式串的**第 k 个**字符继续比较？

要让这次滑动**不漏掉任何可能的匹配**，滑过去之后模式串的前 k−1 个字符必须与主串中 Si 之前那 k−1 个字符对上，即(1)T1T2⋯Tk−1=Si−k+1⋯Si−1

而由已知的部分匹配结果，Si−k+1⋯Si−1 正是 Tj−k+1⋯Tj−1（它们都是那 j−1 个已匹配字符的后 k−1 个）。代入 (1) 得(2)T1T2⋯Tk−1=Tj−k+1⋯Tj−1

**式 (2) 里已经没有主串了。** 它只对模式串 T 提要求：T1⋯Tj−1 这一段的**长度为 k−1 的前缀**与**长度为 k−1 的后缀**必须相等。

这就是 KMP 全部魔法的来源：**滑动距离只由模式串自身决定，可以在看到主串之前一次性算好。**

同时，为了不漏解、又滑得尽量远，k 要取**满足式 (2) 的最大值**——k 越大滑得越少但越保险，k 越小滑得越远；取最大的 k 就是"在不漏掉任何可能匹配的前提下滑得最远"。

## next 数组的定义

把上面求出的那个最大 k 记作 next[j]：

next[j] 表示：当模式串第 j 个字符与主串中相应字符失配时，模式串中需要重新与该主串字符比较的**字符位置**。

形式化定义（T 长度为 m）：next[j]={0,j=1max{k∣1<k<j,  T1⋯Tk−1=Tj−k+1⋯Tj−1},该集合非空1,其他情况

三行分别对应三种处境：

- **j=1**：模式串第一个字符就失配了，模式串内部已无信息可用，规定 next[1]=0。这个 0 是**哨兵值**，不是位置——0 不是任何合法位置，正好用来表示"退无可退，主串指针该前进一位了"。
- **中间那行**：存在长度为 k−1 的相等前后缀，取最大的 k。
- **其他情况**：T1⋯Tj−1 没有任何非空的相等前后缀，模式串只能整体挪到与 Si 对齐、从第 1 个字符重比，故 next[j]=1。

由此还能推出一条**恒等式**（m≥2 时）：next[2]≡1

因为 T1⋯Tj−1 在 j=2 时只有一个字符 T1，一个长度为 1 的串的**真**前缀和**真**后缀都只能是空串，长度 0，故 k−1=0，k=1。这条恒等式后面用来**判别题目用的是哪一种 next 口径**，很好使。

### 那个 +1 到底是怎么来的

把定义换个说法：

令 ℓ = T1⋯Tj−1 的**最长相等前后缀的长度**，则 next[j]=ℓ+1。

很多人在这里记混，是因为把两个不同性质的量混为一谈了：

| 量 | 性质 | 在 T="abaab⋯"、j=6 时 |
| --- | --- | --- |
| ℓ | **长度**：相等前后缀有多长 | T1⋯T5="abaab"，最长相等前后缀是 `"ab"`，ℓ=2 |
| next[j] | **位置**：下一个该比第几个字符 | next[6]=3 |

**+1 就是"长度 → 位置"的换算。**

推理只有一步：滑动到位之后，模式串的前 ℓ 个字符（T1⋯Tℓ）已经和主串中 Si 之前的 ℓ 个字符对齐并且相等——这是式 (2) 保证的，**不需要再比一次**。既然位置 1∼ℓ 都不用比了，那么下一个要与 Si 比较的就是位置 ℓ+1。

而"长度为 ℓ 的前缀恰好占据位置 1∼ℓ、下一个位置是 ℓ+1"这件事，**成立的前提是位置从 1 开始编号**。

这也就回答了一个常被问起的问题：**换成下标从 0 开始，这个 +1 会不会消失？** 会。0 起点约定下，长度为 ℓ 的前缀占据下标 0∼ℓ−1，下一个下标就是 ℓ 本身——数组里直接存长度即可，不必 +1。两种口径的全部差异都源于这一处换算，详见下方[两种 next 口径](#两种-next-口径怎么认)。

### 手工求 next 数组

**操作步骤**（对每个 j 从 1 到 m）：

- 写出 T1⋯Tj−1，即**第 j 个字符前面那一段**（不含第 j 个字符本身）。
- 找它的**最长相等前后缀**（前缀不能是整串，后缀也不能是整串），记长度为 ℓ。
- next[j]=ℓ+1。特别地 next[1]=0。

以 T="abaabcac" 为例（m=8，下标从 1 开始）：

| j | Tj | T1⋯Tj−1 | 最长相等前后缀 | ℓ | next[j]=ℓ+1 |
| --- | --- | --- | --- | --- | --- |
| 1 | a | （空） | — | — | **0**（规定） |
| 2 | b | `"a"` | 无 | 0 | 1 |
| 3 | a | `"ab"` | 无 | 0 | 1 |
| 4 | a | `"aba"` | `"a"` | 1 | 2 |
| 5 | b | `"abaa"` | `"a"` | 1 | 2 |
| 6 | c | `"abaab"` | `"ab"` | 2 | 3 |
| 7 | a | `"abaabc"` | 无 | 0 | 1 |
| 8 | c | `"abaabca"` | `"a"` | 1 | 2 |

next[]=0, 1, 1, 2, 2, 3, 1, 2

三个容易做错的地方：

- **第 5 行**：`"abaa"` 的相等前后缀是 `"a"` 而不是 `"aa"`——前缀 `"aa"` 是 T1T2="ab"，不是 `"aa"`。**前缀必须从第 1 个字符起连续取**，不能挑着取。
- **第 6 行**：`"abaab"` 的相等前后缀取 `"ab"`（ℓ=2），不能取 `"a"`（ℓ=1）——要**最长**的。
- **第 7 行**：`"abaabc"` 以 `c` 结尾，而串首是 `a`，连长度 1 的相等前后缀都没有，ℓ=0，next[7]=1。

**口诀**：*看第 j 个字符前面那一段，找它最长的"头尾相同段"，长度加 1。*

## 求 next 的算法：模式串对自身做 KMP

手工能求，但代码里不能对每个 j 都从头找一遍前后缀（那是 O(m2) 甚至更差）。真正的做法是**递推**：已知 next[j]，求 next[j+1]。

### 递推关系

设 next[j]=k，按定义这意味着T1⋯Tk−1=Tj−k+1⋯Tj−1,且 k−1 是最长的

现在要求 next[j+1]，也就是要找 T1⋯Tj 的最长相等前后缀。分两种情形：

**情形 A：Tj=Tk。** 把已有的等式两边各接上一个字符：左边接 Tk，右边接 Tj，二者相等，于是T1⋯Tk−1Tk=Tj−k+1⋯Tj−1Tj

相等前后缀的长度从 k−1 变成 k，所以next[j+1]=k+1=next[j]+1

**情形 B：Tj≠Tk。** 长度为 k−1 的那个前后缀**扩展不下去**了，只能退而求其次，找 T1⋯Tj−1 的**次长**相等前后缀，再试着扩展。问题变成：次长的是多少？

**关键结论**：T1⋯Tj−1 的所有相等前后缀里，比 k−1 短的那些，**恰好就是 T1⋯Tk−1 的相等前后缀**。

证明只要一行：设长度 ℓ<k−1 的前后缀相等，即 T1⋯Tℓ 等于 T1⋯Tj−1 的长度为 ℓ 的后缀。而 T1⋯Tj−1 的长度为 ℓ 的后缀，同时也是 Tj−k+1⋯Tj−1 的长度为 ℓ 的后缀（因为 ℓ<k−1，落在这一段里面）；由 T1⋯Tk−1=Tj−k+1⋯Tj−1，它又等于 T1⋯Tk−1 的长度为 ℓ 的后缀。所以 ℓ 是 T1⋯Tk−1 的相等前后缀长度。反向同理。

于是**次长相等前后缀的长度 = T1⋯Tk−1 的最长相等前后缀长度 =next[k]−1**，对应的位置就是 next[k]。所以：k←next[k],再回到情形 A/B 重新判断

一直退到 Tj=Tk（回到情形 A），或者退到 k=0（连长度 1 的都没有，此时 next[j+1]=1）。

### 这一步为什么"和 KMP 匹配过程完全一致"

把两段代码的动作并排看：

|  | KMP 匹配 | 求 next |
| --- | --- | --- |
| 谁在往前走（永不后退） | 主串指针 i | 模式串指针 j |
| 谁在回退 | 模式串指针 j | 辅助指针 k |
| 比较的两个字符 | Si 与 Tj | Tj 与 Tk |
| 相等时 | i++, j++ | j++, k++，并记下 next[j]=k |
| 不等时 | j←next[j] | k←next[k] |
| 退到 0 时 | i++, j++（主串右移一位） | j++, k++（next[j]=1） |

**结构逐行同构。** 所谓"求 next 是模式串对自身做 KMP"，说的就是：把模式串 T 当作主串、同时又当作模式串，用 KMP 跑一遍，边跑边把"当前匹配上的前缀长度"记进 next 数组。k 的角色就是匹配里的 j，k←next[k] 的角色就是匹配里的 j←next[j]。

**这也解释了为什么求 next 时可以放心用 next[k]**：k=next[j]<j，next[k] 在更早的迭代里已经算好了，是可用的已知量。递推没有循环依赖。

### 代码实现
c

```
// 求 next 数组（串下标从 1 开始，T[0] 闲置不用，m 为模式串长度）
void getNext(char T[], int next[], int m) {
    int j = 1, k = 0;     // j 是"主串"指针（走的是 T 自己），k 是模式串指针
    next[1] = 0;          // 哨兵：第 1 个字符失配时退无可退
    while (j < m) {       // 只需算到 next[m]，所以 j 走到 m-1 为止
        if (k == 0 || T[j] == T[k]) {
            j++;
            k++;
            next[j] = k;  // 情形 A：前后缀能扩展一位，长度 k-1 → k，位置为 k
        } else {
            k = next[k];  // 情形 B：退到次长相等前后缀，继续试
        }
    }
}
```

逐条对照上面的推导：

- **`k == 0`**：已经退无可退。此时 j++, k++ 使 k 变成 1，即 next[j+1]=1——与定义式第三行"其他情况取 1"一致。把 `k == 0` 写在 `||` 左边是必需的：**短路求值保证不会去访问 `T[0]`**（那个位置是闲置的）。
- **`next[j] = k`（在 `j++, k++` 之后）**：赋的是**新的** j 和**新的** k。旧值满足"T1⋯Tk−1 与 Tj−k+1⋯Tj−1 相等且 Tj=Tk"，加一位后长度为 knew−1，位置为 knew。这就是"ℓ+1"的代码形态。
- **循环条件 `j < m`**：next[j] 的定义只用到 T1⋯Tj−1，所以算 next[m] 时 j 最多走到 m−1。写成 `j <= m` 会越界写 `next[m+1]`。

### 逐步执行（T="abaabcac"）

每一行是一次循环迭代，`—` 表示该次迭代没有写入 next：

| 迭代 | 进入时 j,k | 判断 | 动作 | 写入 |
| --- | --- | --- | --- | --- |
| 1 | 1, 0 | k=0 | j=2,k=1 | next[2]=1 |
| 2 | 2, 1 | T2=b≠T1=a | k=next[1]=0 | — |
| 3 | 2, 0 | k=0 | j=3,k=1 | next[3]=1 |
| 4 | 3, 1 | T3=a=T1=a | j=4,k=2 | next[4]=2 |
| 5 | 4, 2 | T4=a≠T2=b | k=next[2]=1 | — |
| 6 | 4, 1 | T4=a=T1=a | j=5,k=2 | next[5]=2 |
| 7 | 5, 2 | T5=b=T2=b | j=6,k=3 | next[6]=3 |
| 8 | 6, 3 | T6=c≠T3=a | k=next[3]=1 | — |
| 9 | 6, 1 | T6=c≠T1=a | k=next[1]=0 | — |
| 10 | 6, 0 | k=0 | j=7,k=1 | next[7]=1 |
| 11 | 7, 1 | T7=a=T1=a | j=8,k=2 | next[8]=2 |
| — | 8, 2 | j<m 不成立 | 退出 | — |

结果 0,1,1,2,2,3,1,2，与上面手工求解表逐格一致。**迭代 8→9 连退两次**，正是情形 B 的递归回退在起作用。

## KMP 匹配过程

### 代码实现
c

```
// KMP 匹配算法（串下标从 1 开始，S[0]/T[0] 闲置不用）
// 返回 T 在 S 中首次出现的起始位置；失败返回 0
int KMP(char S[], char T[], int next[], int n, int m) {
    int i = 1, j = 1;
    while (i <= n && j <= m) {
        if (j == 0 || S[i] == T[j]) {
            i++;                  // 主串指针只会前进，从不回退
            j++;
        } else {
            j = next[j];          // 失配：i 不动，模式串右滑到 next[j]
        }
    }
    if (j > m)
        return i - m;             // 匹配成功，i 停在匹配段之后一位
    else
        return 0;                 // 匹配失败
}
```

与 [BF](./bf.html) 的代码逐字对比，**只有两处不同**：

- 判断条件多了 `j == 0 ||`
- `else` 分支从 `i = i - j + 2; j = 1;` 变成 `j = next[j];`

第 2 处是主角：i 不再出现在 `else` 分支里，**这就是"主串指针不回溯"的全部实现**。

第 1 处 `j == 0` 值得单独说清楚。它由 `j = next[j]` 产生（只有 next[1]=0），含义是"模式串的第 1 个字符都失配了，模式串内部无信息可用"。此时执行 `i++, j++`，效果是：i 前进一位，j 从 0 回到 1——**模式串整体右移一位，从头开始与主串下一个字符比较**。

要注意这一步**不是一次字符比较**，它只是一次指针调整；统计比较次数时不应把它算进去。也正因为 `j == 0` 写在 `||` 左边短路，代码不会去访问闲置的 `T[0]`。

- i 的取值序列是 1,2,3,3,4,5,6,7,7,8,9,10——**单调不减**，主串每个字符最多被读几次，下一节会给出上界；

## 为什么是 O(n+m)：摊还分析

"主串指针不回溯"只说明了 i 最多前进 n 步，**没有排除另一种坏情况：i 不动，j 一路 `next` 回退很多次**。真的证明 O(n)，必须把这两类步数一起数。用摊还分析（把 j 的回退记在 j 之前的增长账上）：

**匹配阶段。** 每次循环迭代恰好落进两个分支之一：

| 分支 | 对 i 的影响 | 对 j 的影响 |
| --- | --- | --- |
| **前进分支**（j=0 或 Si=Tj） | i+=1 | j+=1 |
| **回退分支**（失配） | 不变 | j←next[j]，因 next[j]<j，故 j **至少减 1** |

于是：

- **前进分支的次数 ≤n**。因为 i 从 1 出发、单调递增、循环条件要求 i≤n，最多执行 n 次。
- **j 的增量总和 ≤ 前进分支次数 ≤n**。因为 j 只在前进分支增加，且每次只加 1。
- **j 的减量总和 ≤ 增量总和 +j 的初值 =n+1**。因为 j 始终非负（最小到 0 就转入前进分支），减掉的总量不可能超过"曾经加进去的总量加上起始值"。
- **回退分支的次数 ≤ j 的减量总和 ≤n+1**。因为每次回退至少减 1。

两类相加，总迭代次数 ≤2n+1，即**匹配阶段 O(n)**。

这就是 j 的回退"不会积少成多"的原因：**j 每退一格，之前必然有某一格是靠 i 前进一步换来的**；i 总共只走 n 步，j 也就总共只能退 n 格左右。

**预处理阶段。** `getNext` 的结构与匹配完全同构（j 扮演 i、k 扮演 j），把上面四条里的 n 换成 m、i 换成 j、j 换成 k，逐条成立，故**求 next 是 O(m)**。

**合计**：

| 阶段 | 时间 | 依据 |
| --- | --- | --- |
| 求 next 数组 | O(m) | j 单调不减且 ≤m；k 的减量总和不超过增量总和 |
| KMP 匹配 | O(n) | i 单调不减且 ≤n；j 的减量总和不超过增量总和 |
| **总体** | O(n+m) | 两阶段串行 |

**空间复杂度 O(m)**：一个长度为 m 的 next（或 nextval）数组，与主串长度无关。这是 KMP 相对 [BF 的 O(1)](./bf.html) 付出的代价。

**两条常被记反的边界**： ① O(n+m) 是**最坏情形**的上界，不只是平均——这正是 KMP 相对 BF 的核心改进（BF 的最坏是 O(nm)）。 ② 但"最坏更优"不等于"平均更快"。一般文本上 BF 的实际执行时间也接近 O(n+m)，KMP 只在主串与模式串之间存在大量部分匹配时才明显占优。KMP 更本质的价值是**主串只从头到尾扫一遍、可以边读入边匹配**，处理来自外设的大文件时无需回头重读。

## nextval：next 的修正值

### 问题在哪

next 数组有一处可以看出来的浪费：**如果 Tj=Tnext[j]，那么退到 next[j] 之后必然还是失配。**

理由很直接：刚刚是 Si≠Tj 才失配的；如果 Tnext[j] 和 Tj 是同一个字符，那么 Si 与它比较的结果只能还是不等。这一次比较是**可以预知结果的**，属于纯粹的浪费。

看 T="aaaab"，next[]=0,1,2,3,4。拿它去匹配 S="aaabaaaab"：

i=4 时 S4=b 与 T4=a 失配，按 next 要依次退到 j=3,2,1 再比三次——而 T3=T2=T1=a，**这三次比较的结果早就注定是不等**。逐步走完：用 next 共 12 次字符比较，用 nextval 只需 9 次，**恰好省掉这 3 次**。

### 修正规则
nextval[j]={nextval[next[j]],Tj=Tnext[j]next[j],Tj≠Tnext[j]

并规定 nextval[1]=0（同 next）。

注意上式在相等时取的是 nextval[next[j]] 而**不是** next[next[j]]——因为 next[j]<j，nextval[next[j]] 已经算好，且它本身已经是"跳到底"的结果，一步到位，不必再链式地跳第二次。这也保证了手工求解可以**从左到右一遍过**。

### 手工求 nextval

**先把 next 求出来，再逐个修正。** 对每个 j：若 Tj=Tnext[j] 则 nextval[j]=nextval[next[j]]，否则 nextval[j]=next[j]。

以 T="abaabcac" 为例：

| j | Tj | next[j] | Tnext[j] | 是否相等 | nextval[j] |
| --- | --- | --- | --- | --- | --- |
| 1 | a | 0 | — | — | 0（规定） |
| 2 | b | 1 | a | b≠a | 1 |
| 3 | a | 1 | a | a=a | 0（取 nextval[1]） |
| 4 | a | 2 | b | a≠b | 2 |
| 5 | b | 2 | b | b=b | 1（取 nextval[2]） |
| 6 | c | 3 | a | c≠a | 3 |
| 7 | a | 1 | a | a=a | 0（取 nextval[1]） |
| 8 | c | 2 | b | c≠b | 2 |

nextval[]=0, 1, 0, 2, 1, 3, 0, 2

### 代码实现
c

```
// 求 nextval 数组（串下标从 1 开始，T[0] 闲置不用）
void getNextval(char T[], int nextval[], int m) {
    int j = 1, k = 0;
    nextval[1] = 0;
    while (j < m) {
        if (k == 0 || T[j] == T[k]) {
            j++;
            k++;
            if (T[j] != T[k])
                nextval[j] = k;            // 与 next 相同：退到 k 后还有得比
            else
                nextval[j] = nextval[k];   // 退到 k 后必然再失配，直接沿用 k 的结果
        } else {
            k = nextval[k];                // 回退时也用修正后的表，收敛更快
        }
    }
}
```

与 `getNext` 的差别只在两处：写入前多一次 `T[j] != T[k]` 判断；回退用 `nextval[k]` 而不是 `next[k]`。注意此处 `T[j]` 与 `T[k]` 都是 `j++, k++` **之后**的新值，正好对应修正规则里的 Tj 与 Tnext[j]。

### nextval 在什么输入上真能省，什么输入上白做

判据只有一条：**nextval[j]≠next[j] 当且仅当 Tj=Tnext[j]**，即模式串里存在"某个字符与它的 next 所指向的那个字符相同"。

| 模式串形态 | next vs nextval | 原因 |
| --- | --- | --- |
| T="aaaab"（长串重复字符） | 0,1,2,3,4 vs 0,0,0,0,4，**差别最大** | 每个 Tj 都与 Tnext[j] 相同，回退链被一次压平 |
| T="abaabcac"（部分重复） | 0,1,1,2,2,3,1,2 vs 0,1,0,2,1,3,0,2，**3 处不同** | 只在 j=3,5,7 处 Tj=Tnext[j] |
| T="abcde"（**各字符互不相同**） | 0,1,1,1,1 vs 0,1,1,1,1，**完全相同** | j≥2 时 next[j]≡1，而 Tj≠T1 恒成立，修正条件永不触发 |

所以：

- **模式串字符两两不同时，nextval 与 next 逐格相同，优化白做。**
- **模式串中重复字符越多、自相似度越高，nextval 省得越多**；极端情形 T=am−1b，一次失配原本要退 m−1 次，用 nextval 一步退到 0。

还有三条边界要一起记住：

- **nextval 不改变时间复杂度。** 用 next 已经是 O(n+m)（上面的摊还分析对 nextval 同样成立），nextval 优化的是常数因子，不是量级。
- **nextval 不改变匹配结果。** 被跳过的都是"结果已知为不等"的比较，返回的位置与用 next 完全一致。
- **nextval[j] 不再具有"最长相等前后缀 +1"的含义**，它只是一张跳转表。**问"最长相等前后缀"时必须用 next，不能用 nextval。**

## 易混淆知识点

| 对比项 | 一方 | 另一方 | 判别依据 |
| --- | --- | --- | --- |
| **ℓ（长度） vs next[j]（位置）** | 最长相等前后缀的**长度** | 下一个该比较的**字符位置** | 1 起点约定下 next[j]=ℓ+1；问"长度"答 ℓ，问"退到第几个字符"答 ℓ+1 |
| **next vs nextval** | 保留"最长相等前后缀 +1"的语义 | 只是跳转表，语义已丢失 | 问最长相等前后缀必须用 next；问"实际比较了几次"用 nextval |
| **前缀 vs 子串** | 前缀必须**从第 1 个字符起连续取** | 子串可以从任意位置起 | 求 `"abaa"` 的相等前后缀时，前缀只能是 `a`/`ab`/`aba`，不能挑成 `"aa"` |
| **相等前后缀要"真"** | 前缀不能是整串，后缀也不能是整串 | — | 否则任何串的"最长相等前后缀"都是它自己，定义失效 |
| **j=0 vs j=1** | 退无可退，下一轮 i++,j++ | 模式串第 1 个字符，是合法位置 | j=0 由 next[1]=0 产生，代表哨兵而非位置 |
| **KMP 最坏 O(n+m) vs BF 最坏 O(nm)** | KMP 有最坏保证 | BF 只在一般文本上实际接近 O(n+m) | 看是问"最坏"还是问"实际／一般情况" |
| **时间 O(n+m) vs 空间 O(m)** | 两阶段串行相加 | 只与模式串长度有关 | 空间里没有 n：next 数组只由 T 决定 |
| **两种 next 口径** | next[1]=0（位置，1 起点） | next[0]=−1（长度，0 起点） | 见下表 |

### 两种 next 口径怎么认

这是真正会踩的一处：**同一个模式串，不同教材给出的 next 表可以整体差 1，甚至连数组下标范围都不一样。** 把三种常见写法并排放一次：

|  | **位置口径**（本文，1 起点） | **长度口径**（0 起点） | **部分匹配表 PM** |
| --- | --- | --- | --- |
| 串的下标范围 | T[1..m]，T[0] 闲置 | T[0..m−1] | T[1..m] |
| next 的下标范围 | next[1..m] | next[0..m−1] | pm[1..m] |
| 首项（哨兵） | next[1]=0 | next[0]=−1 | pm[1]=0 |
| 存的是什么 | 失配后该比模式串**第几个字符**（位置） | T[0..j−1] 最长相等前后缀的**长度**（在 0 起点下也正是下一个下标） | T[1..j] 最长相等前后缀的**长度**（不移位、不加 1） |
| 失配时怎么写 | `j = next[j]`；`j == 0` 时 `i++, j++` | `j = next[j]`；`j == -1` 时 `i++, j++` | 需先换算，通常不直接用于匹配 |
| T="abaabcac" 的表 | 0 1 1 2 2 3 1 2 | −1 0 0 1 1 2 0 1 | 0 0 1 1 2 0 1 0 |
| 与本文口径的换算 | — | next0[j]=next1[j+1]−1 | next1[j]=pm[j−1]+1，且 next1[1]=0 |

**三条判别方法，按可靠性排序：**

- **题面若给了 next 的定义式或已填好的部分表格，一律照题面。** 这是最高优先级——口径是题目设定的，不是习惯决定的。
- **看首项和第二项。** 位置口径下 next[1]=0 且 next[2]≡1（前面推过的恒等式）；长度口径下首项是 −1；若看到首项 0、第二项也是 **0**，那就是部分匹配表 PM，不是位置口径。
- **看代码里的哨兵判断。** `if (j == 0 || ...)` 是位置口径；`if (j == -1 || ...)` 是长度口径。若代码里串从 `T[1]` 开始存、`T[0]` 闲置或存串长，也一定是位置口径。

**本文与站内可视化统一采用位置口径（next[1]=0）**，与严蔚敏《数据结构（C 语言版）》一致。做题时先花五秒确认题目用的是哪一种，否则整个数组会整体错位一格，后面全错。

## 本节小结

学完本篇，应该能做到：

- **从"失配时已匹配段等于模式串前缀"这一条事实出发，自己推出式 (2)**，并说清 KMP 为什么可以只看模式串就决定滑动距离。
- **默写 next 的定义式**（三行分段），并解释 next[1]=0 是哨兵、next[2]≡1 是恒等式。
- **讲清 next[j]=ℓ+1 里 +1 的来历**：ℓ 是长度、next[j] 是位置，+1 是 1 起点编号下的长度→位置换算；换成 0 起点它就消失。
- **手工求任意模式串的 next 与 nextval**，并知道求前缀时不能挑着取、要取最长、前后缀都必须是"真"的。
- **推出 `k = next[k]` 的正确性**：T1⋯Tj−1 中短于 k−1 的相等前后缀，恰好是 T1⋯Tk−1 的相等前后缀，所以次长的长度就是 next[k]−1。
- **说出"求 next 就是模式串对自身做 KMP"的具体对应**：j↔i、k↔j、k=next[k]↔j=next[j]。
- **默写 `getNext` / `KMP` / `getNextval` 三段代码**，并解释 `k == 0` 短路、`next[j] = k` 赋的是新值、循环条件为什么是 `j < m`。
- **用摊还分析证明 O(n+m)**，而不是只说"i 不回退"。
- **判断 nextval 在给定模式串上有没有收益**：模式串字符两两不同则完全无收益；重复字符越多收益越大。
- **从题面认出用的是哪一种 next 口径**，并完成两种口径之间的换算。

三个最关键的结论：

- **滑动距离只由模式串自身决定**——这是 KMP 能做预处理的唯一理由，也是整个算法的支点。
- **O(n+m) 的一半来自"i 不回退"，另一半来自"j 的回退总量不超过 i 的前进总量"**。只讲前一半是不完整的证明。
- **nextval 只改常数因子，不改量级，也不改匹配结果**；而且它丢掉了"最长相等前后缀"的语义，问语义时必须回到 next。
