## 线性表的定义

**线性表**（Linear List）是由 n（n≥0）个**数据特性相同**的元素构成的**有限序列**， 记为：L=(a1, a2, …, ai, …, an)

其中 n 称为线性表的**长度**，n=0 时称为**空表**。

定义里有三个词是判据，缺一个就不是线性表：

| 判据 | 含义 | 反例 |
| --- | --- | --- |
| **数据特性相同** | 所有元素属于同一数据对象，占用相同大小的存储空间 | 一个数组里既放 `int` 又放结构体，不构成线性表 |
| **有限** | 元素个数 n 是有限的 | 无穷序列不是线性表 |
| **序列** | 元素之间有确定的先后次序，相邻元素构成序偶关系 | 集合无序，不是线性表 |

⚠️ **"序列"这个词承载的信息量最大**。它意味着元素之间的关系不是由元素的值决定的，而是由 **位置**决定的：把 (3,1,2) 和 (1,2,3) 看作同一个集合是对的，看作同一个线性表就是错的。 后面所有的"按位查找""在第 i 个位置插入"之所以有意义，全部依赖这一点。

### 非空线性表的四条特征

对非空的线性表（更一般地，对任何线性结构），有：

- 存在**唯一**的一个被称作"第一个"的元素，它没有直接前驱；
- 存在**唯一**的一个被称作"最后一个"的元素，它没有直接后继；
- 除第一个之外，每个元素**有且仅有一个**直接前驱；
- 除最后一个之外，每个元素**有且仅有一个**直接后继。

这四条合起来就是"**一对一**"关系的精确表述，也是线性结构与树（一对多）、图（多对多）的 分界线。

**术语精确化**：ai−1 是 ai 的**直接前驱**，ai+1 是 ai 的**直接后继**。 去掉"直接"二字含义就变了——a1…ai−1 都是 ai 的前驱，但直接前驱只有 ai−1 一个。描述链表的指针指向时必须用"直接后继"，因为指针域存的是 ai+1 的位置，不是 "某个后继"的位置。

## 逻辑结构与存储结构：为什么必须分两层

这是本篇最需要立住的一条，因为线性表这一章后面所有的对比、所有的辨析都建立在它上面。

**逻辑结构**回答的是"数据元素之间有什么关系"，它是**面向问题**的，与计算机无关。 线性表的逻辑结构就是上面那四条特征，不多不少。

**存储结构**（物理结构）回答的是"这些关系在内存里怎么表示出来"，它是**面向机器**的。 同一个逻辑结构可以有多种存储结构。

分两层的价值在于：**逻辑结构决定了能做什么，存储结构决定了做得快不快。**

举例说明这句话的分量：线性表的逻辑结构要求"能取到第 i 个元素"，这是逻辑层的承诺， 顺序表和链表都必须兑现；但顺序表兑现它只要 O(1)，链表要 O(n)。 **"能不能做"是逻辑结构的事，"要花多少代价"是存储结构的事。**

反过来，如果不分层，会立刻出现两类说不清的问题：

| 混淆的说法 | 为什么错 | 正确表述 |
| --- | --- | --- |
| "线性表是用数组实现的" | 把逻辑结构和它的一种实现绑死了 | 线性表**可以**用顺序存储（数组）实现，也可以用链式存储实现 |
| "链表不是线性表" | 用存储结构去否定逻辑结构 | 链表是线性表的一种**存储结构**，其逻辑结构仍是线性表 |
| "顺序存储的一定能随机存取" | 把两个不同层面的"顺序"混为一谈 | 见下面的辨析 |

### 表示逻辑关系的两条路

在存储层，"ai 的直接后继是 ai+1"这件事只有两种表示办法：

- **用地址的相邻性隐式表示**——把 ai+1 放在 ai 的紧后面。这就是**顺序存储**。 逻辑相邻即物理相邻，关系不占额外空间，代价是元素必须"排队站好"，插一个人就得全体后移。
- **用一个显式的指针表示**——在 ai 的存储单元里额外放一个字段，写上 ai+1 的位置。 这就是**链式存储**。关系占了额外空间，换来的是元素可以散落在任何地方，插入只要改指针。

**顺序表与链表的一切差异，都是从这一个分叉推出来的**，不需要分别背两张表。 下面那张对比表的每一行，你都应该能反推回这个分叉。

## 线性表的抽象数据类型

抽象数据类型（ADT）把"这个结构对外承诺哪些操作"和"这些操作怎么实现"分开。 线性表的基本操作清单如下：

| 操作 | 含义 | 前置条件 |
| --- | --- | --- |
| `InitList(&L)` | 构造一个空表 L | 无 |
| `DestroyList(&L)` | 销毁表 L，释放其占用的空间 | L 已存在 |
| `ClearList(&L)` | 将 L 重置为空表（结构还在） | L 已存在 |
| `ListEmpty(L)` | 判空 | L 已存在 |
| `ListLength(L)` | 返回表长 n | L 已存在 |
| `GetElem(L, i, &e)` | **按位查找**：用 e 返回第 i 个元素 | L 已存在且 1≤i≤n |
| `LocateElem(L, e)` | **按值查找**：返回第一个值为 e 的元素的位序 | L 已存在 |
| `ListInsert(&L, i, e)` | 在第 i 个位置**之前**插入元素 e | 1≤i≤n+1 |
| `ListDelete(&L, i)` | 删除第 i 个元素 | 1≤i≤n |
| `TraverseList(L)` | 遍历，依次访问每个元素 | L 已存在 |

三点必须说清的约定，否则后面代码的边界会全部对不上：

- **位序从 1 开始**。第 1 个元素的位序是 1，不是 0。而顺序表底层数组的下标从 0 开始， 所以第 i 个元素存在 `data[i-1]`——这个"错位 1"是顺序表代码里最容易写反的地方。
- **插入位置的合法范围是 1≤i≤n+1，删除是 1≤i≤n**。 插入比删除多出的那个 n+1，对应"插在表尾之后"，此时不需要移动任何元素。
- `&` 表示该参数会被操作修改（C++ 的引用传参）。凡是可能改变表本身（表长、首地址、 头指针）的操作都带 `&`，只读操作不带。教材与考纲的算法描述沿用这套写法。

**这些操作是怎么被挑出来的？** 判据是"**是否只能由结构的实现者完成**"。 求表中最大值、判断表是否有序、合并两个表，这些都能用上面的基本操作**组合**出来， 所以不进基本操作清单；而插入、删除要直接操纵存储结构本身（移动元素或改指针）， 使用者无法用别的操作拼出来，所以必须进清单。 一元多项式相加、集合求并这类应用，本质上就是基本操作的组合。

## 两大存储结构的对比与选型

### 对比表

| 比较维度 | 顺序表 | 链表 | 差异的来历 |
| --- | --- | --- | --- |
| 存取方式 | **随机存取**，O(1) | **顺序存取**，O(n) | 地址可由公式算出 vs 必须顺链走 |
| 按位查找 | O(1) | O(n) | 同上 |
| 按值查找 | O(n)（无序时） | O(n) | 两者都要逐个比较 |
| 插入 / 删除 | O(n)，平均移动约半个表 | 改指针 O(1)，但**定位前驱** O(n) | 逻辑相邻绑定物理相邻 vs 不绑定 |
| 空间分配 | 预先分配，需估计上限 | 按需申请，只受内存总量限制 | 是否要求整块连续空间 |
| 存储密度 | 1 | <1 | 链表每结点多一个指针域 |
| 空间碎片 | 需要一整块连续空间 | 结点可散落，不要求连续 | 同上 |

⚠️ **"链表插入删除 O(1)"是一句需要加限定的话。** 完整表述是： **在已知待操作位置的前驱结点指针的前提下**，链表的插入、删除本身是 O(1)； 若给的是位序 i，则要先花 O(n) 找到前驱，总代价仍是 O(n)。 所以链表真正的优势场景是"**边遍历边增删**"——遍历的开销本来就要付，增删是顺手做的， 此时才真的省下了顺序表的元素移动。

### 存储密度

**存储密度** =数据元素本身占用的存储量整个结点占用的存储量

它衡量的是"为了维护结构，你额外付出了多少空间"。

- 顺序表的元素之间靠地址相邻表达关系，不存任何额外字段，故存储密度 =1（不计空闲区）。
- 单链表每个结点多一个指针域。若数据域是 `int`（4 字节），指针也是 4 字节， 则存储密度 =44+4=0.5——**一半的空间花在了指针上**。
- 数据域越大，指针的相对开销越小。若数据域是一个 100 字节的结构体， 存储密度就是 100104≈0.96，指针几乎不构成负担。

**这条推论比数值本身重要**：链表的空间劣势**只在数据域很小的时候才显著**。 一条"链表比顺序表费空间"的笼统结论是站不住的——若表长难以预估，顺序表按上限 预分配造成的空闲区浪费，往往远超链表的指针开销。

### 选型判据

把上面所有对比收敛成四条可执行的判据：

| 应用特征 | 选择 | 理由 |
| --- | --- | --- |
| 表长变化大、事先难以估计规模 | **链表** | 顺序表要么溢出，要么按上限预分配造成浪费 |
| 表长稳定、事先容易确定 | **顺序表** | 存储密度为 1，且不必付指针开销 |
| 主要操作是按位序取值，很少增删 | **顺序表** | 随机存取 O(1) 是链表给不了的 |
| 频繁在表中间插入、删除 | **链表** | 不必移动元素；结点信息量越大，这个优势越明显 |

## 易混淆知识点

| 易混对 | 判别依据 | 结论 |
| --- | --- | --- |
| **线性表** vs **线性结构** | 线性结构是一类结构的统称，线性表是其中最基本的一种 | 栈、队列、串也是线性结构，但它们是**操作受限**的线性表 |
| **逻辑结构** vs **存储结构** | 问"这句话离开计算机还成立吗"——成立的是逻辑结构 | "元素之间一对一"是逻辑结构；"元素地址连续"是存储结构 |
| **顺序存储** vs **顺序存取** | 前者说的是**数据怎么放**，后者说的是**怎么访问** | 顺序表是顺序**存储**但支持随机**存取**；链表是链式存储且只能顺序存取。两个"顺序"毫无关系 |
| **随机存取** vs **随机数** | 随机存取 = 存取任一元素的代价与其位置无关 | 与概率无关，"随机"是 random access 的直译 |
| **前驱** vs **直接前驱** | 是否要求"紧挨着" | a1 是 a5 的前驱但不是直接前驱；链表指针域存的是**直接**后继 |
| **表长 n** vs **数组容量 MaxSize** | 前者是当前元素个数，后者是预分配的上限 | 顺序表判满用 n=MaxSize，判空用 n=0，两者不能混用 |
| **空表** vs **表不存在** | 空表是"已初始化但长度为 0"，表不存在是"没初始化" | `ListEmpty` 的前置条件是"L 已存在"，空表仍是一个合法的线性表 |

## 本节小结

学完本节，你应该能够：

- 用**数据特性相同、有限、序列**三条判据，判断一个给定的数据集合是不是线性表；
- 说出非空线性表的**四条特征**，并据此解释为什么线性表属于"一对一"的线性结构；
- 分清**逻辑结构**与**存储结构**分属两个层面，能指出"线性表是用数组实现的"这类说法错在哪；
- 把顺序表与链表的全部差异，**从"关系靠地址相邻表示还是靠指针表示"这一个分叉推出来**， 而不是分别背两张表；
- 写出线性表基本操作的**参数含义与合法范围**（插入 1≤i≤n+1、删除 1≤i≤n、 位序从 1 起算），并说明哪些操作需要 `&`；
- 计算**存储密度**，并据此判断"链表费空间"这句话在什么条件下成立、什么条件下不成立；
- 面对一个具体应用，用四条选型判据定下该用顺序表还是链表。

两条最关键的结论：

- **逻辑结构决定能做什么，存储结构决定做得快不快。** 线性表的两种存储结构对外承诺的 基本操作完全一致，差的只是每个操作的代价。
- **顺序表与链表的所有差异同源**：顺序表用地址相邻隐式表示逻辑关系，链表用指针显式表示。 前者省了关系的空间、赔上了位置的自由；后者反之。
