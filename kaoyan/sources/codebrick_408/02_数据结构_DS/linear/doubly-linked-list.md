# 双链表

## 大纲定位

本篇对应 2026 大纲 **二、线性表 —— （二）线性表的实现 · 2 链式存储**。

⚠️ **这一条大纲条目由四篇文章分担，[单链表](./singly-linked-list.html) 是主篇，本篇只写增量。**

**主篇负责**：链式存储的全部共性内容——结点结构与指针含义、头指针 / 头结点 / 首元结点辨析、 带头结点与不带头结点的完整讨论、建表（头插 / 尾插）、查找、**插入与删除的通用指针修改范式**、 逆置、各操作复杂度的完整来历、与顺序表的定量对比。这些内容本篇**一律不重复**。

**本篇只负责双链表相对单链表的四处增量**：

- 结点多一个 `prior` 指针域，以及由它导出的**结构恒等式**；
- **插入必须修改 4 个指针**，以及这 4 步的先后约束；
- **删除只需修改 2 个指针**，以及边界上的额外判断；
- `prior` 把"找前驱"从 O(n) 降到 O(1) 之后，**哪些操作的复杂度跟着变了**， 以及为此付出的空间代价。

首尾相连的版本（循环双链表）在[循环链表](./circular-linked-list.html)里讲。

## 知识框架

本节回答三个问题：

- 加一个 `prior` 指针，究竟买到了什么？只是"能往回走"这么简单吗？
- 插入的 4 个指针，哪些顺序是**必须**的、哪些是自由的？判据是什么？
- 为什么插入要改 4 个指针，删除只要改 2 个？这个 4 和 2 是怎么数出来的？

## 增量一：结点结构与结构恒等式
c

```
typedef struct DNode {
    ElemType data;
    struct DNode *prior, *next;   // 相对单链表，只多了 prior 这一个域
} DNode, *DLinklist;
```

```
┌───────┬──────┬───────┐
│ prior │ data │ next  │
└───────┴──────┴───────┘
```

与单链表一样，双链表通常也设**头结点**。在**非循环**双链表中：

- 头结点的 `prior` 为 `NULL`（它没有前驱）；
- 尾结点的 `next` 为 `NULL`（它没有后继）；
- 判空条件仍是 `L->next == NULL`，与带头结点的单链表一致。

### 结构恒等式

对双链表中**任意一个有后继、有前驱**的结点 `d`，恒有：d->next->prior=d->prior->next=d

**这个式子是双链表所有指针操作的验算工具。** 它说的是：从 `d` 往后走一步再往回走一步， 必须回到 `d`；从 `d` 往前走一步再往后走一步，也必须回到 `d`。

一次插入或删除写完之后，把受影响的每个结点代入这个式子检查一遍，就能查出绝大多数断链错误 ——**"改了 `next` 却忘了改配套的 `prior`"是双链表的唯一一类新增错误**， 而它在这个式子里必然暴露：等号会不成立。

⚠️ 注意式子成立的**前提**：`d` 既有前驱又有后继。在非循环双链表中， 头结点没有前驱、尾结点没有后继，代入会解引用 `NULL`。 这也正是下文每一处 `if (p->next != NULL)` 判断的由来——**它们全都是在补这个前提**。

## 增量二：插入的 4 步指针修改

在结点 `p` **之后**插入新结点 `s`。数一数涉及哪些指针域：

| 待修改的指针域 | 应指向 | 属于哪个结点 |
| --- | --- | --- |
| ① `s->next` | `p` 的原后继 | 新结点 |
| ② `p->next->prior` | `s` | `p` 的原后继 |
| ③ `s->prior` | `p` | 新结点 |
| ④ `p->next` | `s` | `p` |

**为什么是 4 个**：新结点 `s` 要嵌进 `p` 与 `p` 的原后继之间， 这条链上被打断的连接有两处（`p` ↔ 原后继 各一个方向），每处要接两个方向， 新结点自己有两个指针域要填。合起来正好 4 个。c

```
// 在 p 结点之后插入结点 s（非循环双链表）
bool InsertNextDNode(DNode *p, DNode *s) {
    if (p == NULL || s == NULL) return false;
    s->next = p->next;          // ① 先让 s 接住 p 的原后继
    if (p->next != NULL)        //    p 是尾结点时没有原后继，跳过 ②
        p->next->prior = s;     // ②
    s->prior = p;               // ③
    p->next = s;                // ④ 最后才覆盖 p->next
    return true;
}
```

### 顺序的约束究竟有几条

**不是"4 步必须严格按 ①②③④"，而是只有一条硬约束**——把它拆清楚， 就不必死记这个顺序：

**①、② 必须在 ④ 之前。**

理由与[单链表的通用范式](./singly-linked-list.html)完全一致：`p->next` 里存着"原后继"的地址， 而这份地址在链上只此一处；④ 会覆盖它。所以凡是需要用到"原后继"的语句 （① 要读它、② 要通过它访问 `prior`），都必须排在 ④ 前面。

至于 ③（`s->prior = p`），它读的是 `p` 本身、写的是 `s` 的域，与 `p->next` 无关， **放在 4 步中的任何位置都正确**。

⚠️ 顺序写错的后果要说具体：若把 ④ 提到 ① 之前，`p->next` 已经变成 `s`， 此时 ① 执行 `s->next = p->next` 得到的是 `s` 自己的地址——链表就地成环， `s` 之后的整个后半段**永久丢失**，遍历会死循环。

### 按位序插入

若给的是位序而不是指针，就要先定位。**带头结点时，在第 i 个结点之前插入可以直接用 `p->prior`，不需要像单链表那样绕道找前驱**：c

```
// 在带头结点的双链表 L 中第 i 个位置之前插入元素 e
bool ListInsert_DuL(DLinklist &L, int i, ElemType e) {
    DNode *p = GetElem_DuL(L, i);    // 定位第 i 个结点，O(n)
    if (p == NULL) return false;     // i 不合法
    DNode *s = (DNode *)malloc(sizeof(DNode));
    if (s == NULL) return false;
    s->data = e;
    s->prior = p->prior;             // ① s 接住 p 的前驱
    p->prior->next = s;              // ② 前驱的后继改指向 s（带头结点时 p->prior 必存在）
    s->next = p;                     // ③
    p->prior = s;                    // ④
    return true;
}
```

这里 `p->prior->next = s` 不需要判空，**因为带头结点保证了任何数据结点都有前驱**—— 即使 p 是首元结点，它的前驱也是头结点。这是头结点在双链表上的又一处收益。

**总代价 O(n)**：定位第 i 个结点 O(n) + 4 次指针赋值 O(1)。 **只有当题面直接给出结点指针时，插入才是 O(1)。**

## 增量三：删除的 2 步指针修改

删除结点 `p` 的后继结点 `q`：

| 待修改的指针域 | 应指向 |
| --- | --- |
| ① `p->next` | `q` 的后继 |
| ② `q->next->prior` | `p` |

**为什么只要 2 个**：`q` 整个结点都要被释放，它自己的两个指针域**不必维护** （马上就 `free` 掉了）。剩下的只是把 `q` 两侧的邻居重新接上——两个方向，两个指针。

图源：殷人昆《数据结构——用面向对象方法与 C++ 描述》（第 2 版）图 2.19 双向循环链表的删除算法，p73。 书上画的是**双向循环**链表，但删除时"改两个指针"的动作与非循环双链表完全相同； 差别只在非循环版本要额外判断被删结点是不是尾结点（尾结点没有后继，第 ② 步跳过）。c

```
// 删除 p 结点的后继结点（非循环双链表）
bool DeleteNextDNode(DNode *p) {
    if (p == NULL || p->next == NULL) return false;   // p 之后无结点可删
    DNode *q = p->next;         // 先记住被删结点，否则无法 free
    p->next = q->next;          // ① p 越过 q
    if (q->next != NULL)        //    q 是尾结点时没有后继，跳过 ②
        q->next->prior = p;     // ②
    free(q);                    // 最后才释放，此前 q->next 还要被读
    return true;
}
```

**边界自查**：

- `p` 是尾结点 → `p->next == NULL`，返回 `false`，正确；
- `q` 是尾结点 → ① 让 `p->next` 拿到 `NULL`，`p` 成为新的尾结点；② 跳过，正确；
- 表中只有一个数据结点、`p` 是头结点 → `q` 即该结点，删除后 `L->next == NULL`，回到空表，正确。

⚠️ 三处次序不能动：**`q` 必须先取**（否则 `free` 不掉，内存泄漏）、 **`free(q)` 必须最后**（②要读 `q->next`，先释放就是读已释放内存）、 **② 里的 `q->next` 要在 ① 之后读也无妨**——因为 ① 改的是 `p->next`，没有动 `q->next`。

## 增量四：`prior` 换来了什么，赔了什么

### 赚：三类操作降了复杂度

| 操作（均设已知结点指针 `p`） | 单链表 | 双链表 | 差别的来历 |
| --- | --- | --- | --- |
| 访问 `p` 的**后继** | O(1) | O(1) | 都有 `next` |
| 访问 `p` 的**前驱** | O(n) | O(1) | 单链表只能从头遍历找 |
| 在 `p` **之后**插入 | O(1) | O(1) | 都不需要前驱 |
| 在 `p` **之前**插入 | O(1)，但要**交换数据域**（结点地址会变） | O(1)，**不必交换**，结点地址不变 | 双链表直接用 `p->prior` |
| 删除 `p` **自身**（`p` 非尾结点） | O(1)，但要**搬后继数据** | O(1)，直接摘 | 同上 |
| 删除 `p` **自身**（`p` **是尾结点**） | O(n)，无后继可搬，只能找前驱 | O(1) | **这一行是双链表最实的收益** |
| 反向遍历整表 | 做不到（除非先逆置） | O(n) | `prior` 链本身就是一条反向链 |

⚠️ **最容易被含糊过去的是倒数第二行。** 单链表"删除已知结点 O(1)"的技巧 （把后继的数据搬过来再摘掉后继）**对尾结点无效**，而且会改变结点的相对地址。 双链表没有这个死角：**任意已知结点都能真正 O(1) 删除，且不动其他结点的地址。**

### 赔：空间与维护成本

| 代价 | 具体是多少 |
| --- | --- |
| 空间 | 每结点多一个指针域。设 `data` 与指针同为 4 字节，则结点从 8 字节涨到 12 字节，**存储密度从 48=0.5 降到 412≈0.33** |
| 插入的维护量 | 从 2 个指针涨到 4 个 |
| 删除的维护量 | 从 1 个指针涨到 2 个 |
| 出错面 | 新增一整类错误：改了 `next` 忘了改配套的 `prior`（用结构恒等式验算可查出） |

这是一次典型的**以空间换时间**：多付约 50% 的结点空间和一倍的指针维护量， 换来前驱访问从 O(n) 到 O(1)。**值不值取决于应用里"需要前驱"的操作占多大比重**—— 只做单向遍历和尾部追加的场景，双链表纯亏。

## 复杂度分析

| 操作 | 时间复杂度 | 来历 |
| --- | --- | --- |
| 按位查找第 i 个 | O(n) | 仍须逐个走，平均 n+12 步。**双向不等于随机存取** |
| 按值查找 | O(n) | 平均比较 n+12 次 |
| 已知结点后插 | O(1) | 4 次指针赋值 |
| 已知结点前插 | O(1) | 4 次指针赋值，靠 `p->prior` 直接定位 |
| 已知结点删除其后继 | O(1) | 2 次指针赋值 |
| **已知结点删除自身** | O(1) | 2 次指针赋值；**含尾结点**，这是相对单链表的关键改进 |
| 按位序插入 / 删除 | O(n) | 定位 O(n) + 改指针 O(1)，定位那一步跑不掉 |
| 正向 / 反向遍历 | O(n) | 各走一遍 |

**空间复杂度**：所有操作只用常数个辅助指针，均为 O(1)。 结构本身的额外开销体现在存储密度上，与算法的空间复杂度是两回事。

⚠️ 教材在给双链表的按位序插入 / 删除算法标复杂度时写的是 O(n)， 因为它的算法里**包含了定位第 i 个结点的那一步**。看到"双链表插入是 O(1) 还是 O(n)" 这类问法，判据仍然是：**题面给的是指针还是位序。**

## 易混淆知识点

| 易混对 | 判别依据 | 结论 |
| --- | --- | --- |
| 插入改 4 个指针 vs 删除改 2 个 | 被删结点自身的指针域要不要维护 | 插入的新结点要"活下去"，两个域都得填；被删结点马上释放，它的域不必管 |
| ①② 必须在 ④ 前 vs ③ 位置自由 | 该语句是否读取 `p->next` 里的**原**值 | 只有读原后继的语句受约束；`s->prior = p` 不读 `p->next`，放哪都行 |
| 非循环双链表要判 `p->next != NULL` vs 循环双链表不用判 | 结构上是否存在"没有后继"的结点 | 循环结构里 `p->next` 永远有效，判断可省，见[循环链表](./circular-linked-list.html) |
| 双链表**可双向遍历** vs 支持**随机存取** | 能否由位序直接算出地址 | 双链表仍是顺序存取，按位查找仍是 O(n)；"双向"只是多了一个走法 |
| 单链表删除已知结点 O(1) vs 双链表 O(1) | 尾结点算不算在内、结点地址变不变 | 单链表的 O(1) 靠搬数据，对尾结点无效且会改结点地址；双链表是真 O(1)，无死角 |
| 结构恒等式 d->next->prior=d 何时成立 | `d` 是否有后继 | 非循环双链表的尾结点代入会解引用 `NULL`；循环双链表则处处成立 |
| 存储密度 0.5（单链表）vs ≈0.33（双链表） | 数一数一个结点里有几个指针 | 数据域越大，两者的差距越不显著 |
| 头结点的 `prior` | 非循环 vs 循环 | 非循环双链表头结点 `prior` 为 `NULL`；循环双链表头结点 `prior` 指向尾结点 |

## 本节小结

学完本节，你应该能够：

- 写出双链表的结点定义，并说清它相对单链表**只多了一个 `prior` 域**；
- 默写**结构恒等式** d->next->prior=d->prior->next=d， 并用它验算自己写的插入 / 删除代码；同时说清这个式子在非循环双链表的**首尾两端不成立**；
- 数出插入要改的 **4 个**指针、删除要改的 **2 个**指针，并解释这两个数字是怎么数出来的 （被删结点自身的域不必维护）；
- 说出插入 4 步中**唯一的硬约束**是"读原后继的语句必须排在覆盖 `p->next` 之前"， 并给出顺序写反的具体后果（就地成环、后半段丢失）；
- 写出非循环双链表插入 / 删除中**每一处判空的理由**——它们全是在补结构恒等式的前提；
- 列出 `prior` 使哪些操作降了复杂度，特别是**删除尾结点从 O(n) 变成 O(1)**， 以及为此付出的空间代价（存储密度 0.5→≈0.33）；
- 在被问"双链表插入是 O(1) 还是 O(n)"时，先分清题面给的是**指针**还是**位序**。

两条最关键的结论：

- **双链表买到的不是"能往回走"，而是"任意已知结点都能真 O(1) 地删除和前插，且不改动 其他结点的地址"**。单链表用交换数据域也能做到近似效果，但对尾结点无效，且结点地址会变。
- **双链表的全部新增出错点只有一类**：改了一个方向的指针，忘了改配套的另一个方向。 结构恒等式就是查这一类错的工具。

## 教材出处

- 双链表的提出动机（"在单链表中，查找直接后继结点的执行时间为 O(1)， 而查找直接前驱的执行时间为 O(n)"）、结点结构 `DuLNode` 的 C 语言定义： 严蔚敏《数据结构（C 语言版）》（第 2 版），p39，2.5.4 节。
- 结构恒等式 `d->next->prior = d->prior->next = d`，以及 "**在插入结点时需要修改四个指针，在删除结点时需要修改两个指针**"， 连同带头结点双链表的插入算法 2.13 与删除算法 2.14：同书 p40。 该页同时给出：这两个算法的时间复杂度均为 O(n)——因为算法中包含了定位第 i 个结点的一步。
