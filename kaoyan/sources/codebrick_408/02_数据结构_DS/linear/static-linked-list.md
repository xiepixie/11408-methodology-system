# 静态链表

## 大纲定位

本篇对应 2026 大纲 **二、线性表 —— （二）线性表的实现 · 2 链式存储**。

⚠️ **这一条大纲条目由四篇文章分担，[单链表](./singly-linked-list.html) 是主篇，本篇只写增量。**

**主篇负责**：链式存储的全部共性内容——结点结构与指针含义、头指针 / 头结点 / 首元结点辨析、 带头结点与不带头结点的完整讨论、建表、查找、**插入与删除的通用指针修改范式**、逆置、 各操作复杂度的完整来历、与顺序表的定量对比。这些内容本篇**一律不重复**。

**本篇只负责静态链表相对单链表的三处增量**：

- **游标机制**——用数组下标代替内存地址，以及"为什么这样替换是可行的"；
- **备用空闲链表**——没有 `malloc`/`free` 可用时，结点空间自己怎么管；
- **适用场景与局限**——它同时继承了数组和链表的哪些缺点，以及在什么条件下仍然值得用。

⚠️ **静态链表是一个"存储实现"层面的变体，不是新的逻辑结构。** 它的逻辑结构仍然是线性表， 链上的插入删除范式与单链表**逐字对应**——把 `p->next` 换成 `space[i].cursor` 即可。 判断你有没有真学会它，就看能不能把主篇里的每一段代码机械地翻译过来。

## 知识框架

本节回答三个问题：

- 指针换成数组下标，链表的哪些性质保住了、哪些丢了？判据是什么？
- 没有 `malloc`/`free`，"哪块空间是空闲的"这件事怎么记？
- 静态链表既不能随机存取、容量又固定，那它凭什么还存在？

## 增量一：游标代替指针

### 替换为什么可行

先把问题拆到最小：链表对"指针域"的要求究竟是什么？

**只有一条——它必须能唯一定位到直接后继结点。**

内存地址能做到，所以动态链表成立。但**数组下标同样能做到**：只要所有结点都住在同一个数组 `space[]` 里，一个下标 `i` 就唯一确定了 `space[i]` 这个结点。于是把指针域换成一个整型下标， 链式结构的一切逻辑照样成立——这就是**静态链表**。

这个下标称为**游标**（cursor）。它与指针的对照关系是逐项的：

| 动态链表 | 静态链表 | 说明 |
| --- | --- | --- |
| `LNode *p` | `int i` | 指针变量 → 整型下标 |
| `p->data` | `space[i].data` | 取数据域 |
| `p->next` | `space[i].cursor` | 取指针域 |
| `p = p->next` | `i = space[i].cursor` | 后移一步 |
| `p == NULL` | `i == 0` | 到链尾（约定下标 0 不作数据结点用） |
| `malloc(sizeof(LNode))` | `Malloc_SL(space)` | 申请一个结点 |
| `free(p)` | `Free_SL(space, i)` | 归还一个结点 |

**左右两列可以机械互换。** 主篇里插入的两句 `s->next = p->next; p->next = s;`，翻译过来就是 `space[j].cursor = space[k].cursor; space[k].cursor = j;`—— 连"哪句在前"的约束都完全一样（先让新结点接住原后继，再覆盖）。

### 结点定义
c

```
#define MAXSIZE 100

typedef struct {
    ElemType data;  // 数据域
    int cursor;     // 游标：直接后继结点在数组中的下标；0 表示链尾
} SLinkList[MAXSIZE];
```

⚠️ 这里 `SLinkList` 被定义成一个**数组类型**（长度 `MAXSIZE` 的结构体数组）， 不是结构体类型。所以函数参数写 `SLinkList space` 时，传进去的实际是数组首地址， 函数内对 `space[i]` 的修改**会作用到实参上**——这一点与传结构体是不同的。

### 两条约定

静态链表要正常工作，必须先定死两条约定，否则代码的每一处判断都会飘：

- **下标 0 不用来存数据元素**，它专门作**备用链表的头结点**。 于是"游标为 0"就可以安全地当作"没有后继"的标志， 起到动态链表里 `NULL` 的作用。
- **数据链表的头结点下标另用一个变量记住**（下文代码里叫 `head`）。 它相当于动态链表的头指针。

### 存储示意

设 `MAXSIZE = 8`，数据链表当前为 (A, B, C)，头结点占下标 1：

```
下标:    0    1    2    3    4    5    6    7
data:    -    -    C    B    A    -    -    -
cursor:  5    4    0    2    3    6    7    0
         ↑    ↑
      备用链  数据链
      头结点  头结点
```

从这张表里读出两条链：

- **数据链**：`head = 1` → `space[1].cursor = 4` → `space[4]`（A）→ `cursor = 3` → `space[3]`（B）→ `cursor = 2` → `space[2]`（C）→ `cursor = 0`，链尾。 读出的序列是 (A,B,C) ✓
- **备用链**：`space[0].cursor = 5` → `space[5]` → `cursor = 6` → `space[6]` → `cursor = 7` → `space[7]` → `cursor = 0`，链尾。空闲位置是 {5,6,7}。

⚠️ **数据在数组里的物理次序与它在链上的逻辑次序毫无关系**： A 住在下标 4，B 在 3，C 在 2，而逻辑次序是 A→B→C。 **这正是"链式"的含义**——若两者一致，它就退化成顺序表了。 所以**下标不是位序**，"取第 3 个元素"仍然只能沿游标走三步。

## 增量二：备用空闲链表

### 为什么需要它

动态链表里，"哪块内存是空闲的"由操作系统的堆管理器负责，程序只管 `malloc`/`free`。 静态链表**没有这个后台**：数组是一次性开好的一整块，程序自己必须知道 "这 100 个格子里哪些还没被占用"。

朴素办法是给每个格子加一个"是否占用"标志位，但那样找空闲格子要 O(n) 扫描。 **更好的办法是——把所有空闲格子也串成一条链。** 于是：

**静态链表里同时存在两条链**：一条是**数据链**（存有效元素）， 一条是**备用链**（串起所有空闲结点）。二者共用同一个数组、共用同一套游标机制。

申请结点 = 从备用链头部摘一个；回收结点 = 往备用链头部挂回去。**都是 O(1)。**

### 初始化：把整个数组串成备用链
c

```
void InitList(SLinkList space) {
    for (int i = 0; i < MAXSIZE - 1; i++)
        space[i].cursor = i + 1;    // 每个格子指向下一个格子
    space[MAXSIZE - 1].cursor = 0;  // 最后一个格子的游标置 0，表示备用链到头了
}
```

初始化后的状态：

```
下标:   0    1    2    3   ...  MAXSIZE-2  MAXSIZE-1
cursor: 1    2    3    4   ...  MAXSIZE-1     0
```

此时备用链是 0→1→2→⋯→MAXSIZE−1→0，全部空闲。

### 申请与回收
c

```
// 从备用链表申请一个空闲结点，返回其下标；返回 0 表示空间已满
int Malloc_SL(SLinkList space) {
    int i = space[0].cursor;                // 备用链的第一个空闲结点
    if (i)                                   // i == 0 说明备用链已空
        space[0].cursor = space[i].cursor;   // 备用链头后移一位
    return i;
}

// 把下标为 k 的结点归还给备用链表
void Free_SL(SLinkList space, int k) {
    space[k].cursor = space[0].cursor;   // ① 被回收结点接住原来的备用链首结点
    space[0].cursor = k;                  // ② 备用链头改指向它
}
```

**这两段代码就是主篇里的"头插"和"头删"。** `Malloc_SL` 是从备用链头部删一个结点， `Free_SL` 是往备用链头部插一个结点——顺序约束（先接住、再覆盖）也一模一样。 认出这一点，就不必单独记它们。

⚠️ **回收采用"后进先出"**：最近被释放的结点会最先被重新分配。 这不是设计上的讲究，而是"头插头删最省事"的自然结果——**只有头部操作才是 O(1)**， 若要按下标顺序回收，就得遍历备用链找插入位置，退化成 O(n)。

## 基本操作

### 插入
c

```
// 在下标为 k 的结点之后插入新元素 e
bool InsertAfter(SLinkList space, int k, ElemType e) {
    int j = Malloc_SL(space);           // 申请一个空闲结点
    if (j == 0) return false;           // 空间已满，插入失败
    space[j].data = e;
    space[j].cursor = space[k].cursor;  // ① 新结点接住 k 的原后继
    space[k].cursor = j;                // ② k 改指向新结点
    return true;
}
```

①② 的顺序不能颠倒，理由与[单链表](./singly-linked-list.html)的通用范式完全相同： `space[k].cursor` 里存的"原后继下标"只此一份，② 会覆盖它。

### 删除
c

```
// 删除下标为 k 的结点之后的那个结点
bool DeleteAfter(SLinkList space, int k) {
    int j = space[k].cursor;            // j 是被删结点的下标，必须先取
    if (j == 0) return false;           // k 之后已经没有结点了
    space[k].cursor = space[j].cursor;  // ① k 越过被删结点
    Free_SL(space, j);                  // ② 归还给备用链（相当于 free）
    return true;
}
```

⚠️ **`Free_SL` 这一步不能省。** 动态链表里忘了 `free` 只是内存泄漏，程序还能跑； 静态链表里忘了归还，那个格子就**永远回不到备用链**，数组会被慢慢"漏"光， 最后 `Malloc_SL` 全部返回 0。

### 查找
c

```
// 从 head 指向的数据链上按值查找，返回结点下标；未找到返回 0
int LocateElem(SLinkList space, int head, ElemType e) {
    int i = space[head].cursor;   // 从头结点的后继（首元结点）开始
    while (i != 0) {              // i == 0 相当于动态链表的 p == NULL
        if (space[i].data == e)
            return i;
        i = space[i].cursor;      // 沿游标后移一步
    }
    return 0;
}
```

### 例题：手工走一遍两条链

设 `MAXSIZE = 8`，初始化后 `head` 已申请到下标 1 并置 `space[1].cursor = 0`（空数据链）， 备用链为 0→2→3→⋯→7→0。依次执行三次头部插入 `InsertAfter(space, 1, 'C')`、`InsertAfter(space, 1, 'B')`、`InsertAfter(space, 1, 'A')`：

| 操作 | 申请到的下标 | 数据链 | 备用链 |
| --- | --- | --- | --- |
| 初始 | — | 1→0（空） | 0→2→3→4→5→6→7→0 |
| 插入 `'C'` | 2 | 1→2(C)→0 | 0→3→4→5→6→7→0 |
| 插入 `'B'` | 3 | 1→3(B)→2(C)→0 | 0→4→5→6→7→0 |
| 插入 `'A'` | 4 | 1→4(A)→3(B)→2(C)→0 | 0→5→6→7→0 |

此刻数组的完整状态，正是上文"存储示意"那张表。

接着执行 `DeleteAfter(space, 4)`——删除 A 之后的那个结点（即 B，下标 3）：

| 子步骤 | 语句 | 效果 |
| --- | --- | --- |
| 取被删下标 | `j = space[4].cursor` | j=3 |
| ① 越过 | `space[4].cursor = space[3].cursor` | `space[4].cursor` 由 3 变为 2 |
| ② 回收 | `space[3].cursor = space[0].cursor` | `space[3].cursor` 由 2 变为 5 |
| ② 回收 | `space[0].cursor = 3` | 备用链头由 5 变为 3 |

删除后的状态：

```
下标:    0    1    2    3    4    5    6    7
data:    -    -    C    -    A    -    -    -
cursor:  3    4    0    5    2    6    7    0
```

- 数据链：1→4(A)→2(C)→0，读出 (A,C) ✓
- 备用链：0→3→5→6→7→0，下标 3 已回到空闲池 ✓

**下一次调用 `Malloc_SL` 会拿到下标 3**——刚回收的那一个，这就是"后进先出"的直接体现。 注意 `space[3].data` 里残留的 `'B'` 无需清除：它已不在数据链上，任何合法遍历都读不到它。 **这与顺序表删除后不必清理表外残值是同一个道理。**

## 增量三：适用场景与局限

### 复杂度

| 操作 | 时间复杂度 | 来历 |
| --- | --- | --- |
| 按位查找第 i 个 | O(n) | 下标不是位序，仍须沿游标走 i 步 |
| 按值查找 | O(n) | 平均比较 n+12 次 |
| 插入（已知前驱下标） | O(1) | 一次 `Malloc_SL` + 两次游标赋值 |
| 删除（已知前驱下标） | O(1) | 两次游标赋值 + 一次 `Free_SL` |
| 按位序插入 / 删除 | O(n) | 定位前驱 O(n) + 改游标 O(1) |
| `Malloc_SL` / `Free_SL` | O(1) | 只在备用链头部操作 |

**与动态链表的复杂度逐项相同**——这正是"逻辑结构没变、只换了实现"的体现。

**空间复杂度**：算法本身只用常数个整型变量，O(1)； 结构上要预先分配 `MAXSIZE` 个结点的数组，与实际表长无关。

### 与动态链表的对比

| 对比项 | 静态链表 | 动态链表 |
| --- | --- | --- |
| 结点空间来源 | 预分配的数组，一次开好 | 堆，`malloc` 按需申请 |
| 指针域内容 | 数组下标（整数） | 内存地址 |
| 空闲空间管理 | **自己维护备用链** | 交给堆管理器 |
| 容量 | **固定，须预先确定** | 只受内存总量限制 |
| 插入 / 删除 | 不移动元素，改游标 O(1) | 不移动元素，改指针 O(1) |
| 随机存取 | **不支持** | 不支持 |
| 内存碎片 | 无（就一块数组） | 频繁分配释放可能产生 |
| 跨进程 / 序列化 | **可直接整块拷贝**，下标与地址无关 | 指针失效，必须重建 |

### 它凭什么还存在

静态链表**同时继承了两边的缺点**：数组的"容量固定"和链表的"不能随机存取"。 既然如此，它凭什么不被淘汰？答案在上表最后一行——

**游标是相对的，地址是绝对的。**

一个存指针的链表，一旦把它的字节整块搬到别的地方（另一个进程的地址空间、 一个文件、一段共享内存），所有指针立刻全部失效，因为它们记的是**旧位置的绝对地址**。 静态链表存的是**数组内的相对下标**，整块搬到哪里，链的结构都不会坏。

由此得到它成立的三类条件：

- **语言不提供指针**（如早期 Fortran、BASIC）——这是它被发明出来的原始理由；
- **不能使用进程私有的地址**——典型是**多进程共享内存**：同一块共享内存映射到不同进程 时基址不同，指针不通用，下标通用；
- **结构要被整体持久化或传输**——存盘、跨机器传输时，下标天然可用，指针必须重建。

⚠️ **别把它的适用条件说成"节省空间"或"效率更高"**——两条都不成立： 它的存储密度不比动态链表高（照样每个结点多一个整型域），复杂度也逐项相同。 **它换来的是"位置无关性"，代价是容量固定。**

## 易混淆知识点

| 易混对 | 判别依据 | 结论 |
| --- | --- | --- |
| 数组**下标** vs 元素**位序** | 下标是它住在数组的第几格，位序是它在链上排第几 | 二者无关。静态链表里下标 4 的元素完全可能是链上第 1 个 |
| 静态链表 vs 顺序表 | 逻辑相邻是否等于物理相邻 | 顺序表是；静态链表不是——它只是"住在数组里的链表" |
| 静态链表 vs 动态链表 | 指针域存的是下标还是地址 | 逻辑结构、复杂度逐项相同，差别只在空间从哪来、谁管空闲 |
| 游标 =0 vs 指针 = `NULL` | 都是"没有后继"的标志 | 前提是**约定下标 0 不作数据结点用**，否则 0 是一个合法结点 |
| 备用链头（下标 0） vs 数据链头（`head`） | 一条串空闲格子，一条串有效元素 | 两条链共用同一个数组，各走各的，互不干扰 |
| `Malloc_SL` 返回 0 vs 返回有效下标 | 备用链是否已空 | 返回 0 必须当作"申请失败"处理，直接拿去写数据会破坏下标 0 那个头结点 |
| 删除后要不要清 `data` | 该格子还在不在数据链上 | 不必清。已从数据链摘下，合法遍历读不到它 |
| 静态链表"不移动元素" vs "支持随机存取" | 前者说的是插删，后者说的是查找 | 插删确实不移动元素，但查找仍是 O(n)，两者不矛盾 |
| 静态链表的优势是"省空间" vs "位置无关" | 数一数存储密度 | 省空间不成立（照样多一个整型域）；真正的优势是下标与绝对地址无关 |

## 本节小结

学完本节，你应该能够：

- 说清游标替换指针为什么可行——**链表对指针域的唯一要求是"能唯一定位直接后继"**， 数组下标同样满足；并能把主篇的每一段链表代码机械翻译成游标版本；
- 写出静态链表的结点定义与**两条约定**（下标 0 作备用链头、数据链头另存一个变量）， 并解释为什么有了第一条，"游标为 0"才能安全地当作链尾标志；
- 从一张 `data` / `cursor` 表里**读出两条链**（数据链与备用链），并指出 **数组下标与链上位序毫无关系**；
- 写出 `Malloc_SL` 与 `Free_SL`，并认出它们就是备用链上的**头删**与**头插**， 由此解释回收为什么是后进先出；
- 完整手工模拟一次"申请 → 插入 → 删除 → 回收"，给出每一步之后两条链的状态；
- 说明静态链表的复杂度与动态链表**逐项相同**，因此它的价值不在效率；
- 给出它成立的三类条件（语言无指针、共享内存、整体持久化 / 传输）， 并说清共同的机理是**下标相对、地址绝对**。

三条最关键的结论：

- **静态链表不是新的数据结构，是链式存储的另一种实现。** 把 `p->next` 换成 `space[i].cursor`，主篇的一切结论原样成立。
- **备用链的存在，是因为没有 `malloc`/`free` 可用**——空闲空间的账必须自己记， 而"串成一条链、只在头部操作"是让申请与回收都保持 O(1) 的办法。
- **它的真实优势是位置无关性**，不是省空间也不是更快；代价是容量必须预先定死。

## 教材出处

⚠️ 严蔚敏《数据结构（C 语言版）》（第 2 版）**在第 2 章线性表里没有设置静态链表的独立小节**， 静态链表在该书中是作为**链式基数排序**的实现载体出现的。因此本篇只引该处：

- 静态链表的结点类型与表类型定义（`SLCell` 中用 `int next` 作为游标域， `SLList` 中的数组 `r` 作为"静态链表的可利用空间"，并注明 **`r[0]` 为头结点**）： 严蔚敏《数据结构（C 语言版）》（第 2 版），p258，8.5 节链式基数排序。 书中写明采用静态链表的理由是"以便于更有效地存储和重排记录"—— 重排记录时只改游标、不搬记录本身，这与本篇讲的"插删不移动元素"是同一件事。

本篇其余内容（备用空闲链表的申请与回收机制、与动态链表的对比、适用场景） 在该书中没有对应页可引，故不标注出处。
