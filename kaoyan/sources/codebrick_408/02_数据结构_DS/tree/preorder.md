# 前序遍历

## 大纲定位

本篇对应 2026 考研数据结构大纲 **四（二）3 二叉树的遍历**。

这一条目由五篇分担，**本篇只负责前序遍历（NLR）**：访问时机、递归实现、两种非递归实现、前序序列的性质与典型应用。

| 前序非递归的"弹栈压右左"写法及其正确性 | **三种遍历共用的"沿左链入栈"统一模板集中写在 [中序遍历](./inorder.html)**，本篇只给它的前序变体，不重复讲原理 |
| 前序序列的性质、前序驱动的建树与复制 | 由遍历序列**还原**二叉树见 [由遍历序列构造二叉树](./construct-binary-tree.html) |

## 知识框架

本节要回答三个问题：

- 三种深度优先遍历的递归代码**长得一模一样**，凭什么产生三种不同的序列？
- 前序非递归为什么必须**先压右孩子、后压左孩子**？压反了会得到什么序列？
- 前序遍历"先处理根、再处理子树"的次序，决定了它适合做哪一类事、不适合做哪一类事？

## 一、访问顺序

前序遍历的访问顺序：**根结点 → 左子树 → 右子树**（NLR，N = Node、L = Left、R = Right）。

对于下面这棵二叉树：

```
        A
       / \
      B   C
     / \   \
    D   E   F
```

前序遍历序列为：**A → B → D → E → C → F**

递推过程：

- 访问根结点 A
- 前序遍历左子树（以 B 为根）：访问 B → 遍历 B 的左子树 D → 遍历 B 的右子树 E
- 前序遍历右子树（以 C 为根）：访问 C → C 无左子树 → 遍历 C 的右子树 F

### 三种遍历的差别只有一处

二叉树由三部分组成：**根 D、左子树 L、右子树 R**。三者的全排列有 6 种，若**限定"先左后右"**，就只剩 3 种：DLR、LDR、LRD，分别叫先（根）序、中（根）序、后（根）序遍历。

也就是说：**三种遍历的递归代码，抹掉那一行 `visit` 之后完全相同**。它们的递归执行路径也完全相同——都是"向左下走到底、回溯、向右下走"这条固定的游走路线。差别只在于：沿这条路线经过每个结点时，**在哪一次经过它的时候把它记下来**。

每个结点在这条路线上恰好被经过三次：

```
             ①第一次经过（下行进入）  → 记下来就是【前序】
            ↙   A   ↖
           ↙    ↑    ↖
    ②第二次经过（左子树返回、准备进右子树）→ 记下来就是【中序】
                ↑
    ③第三次经过（右子树返回、准备回到双亲）→ 记下来就是【后序】
```

理解了这一点，"给一棵树同时写出三种序列"就不用做三遍：**沿这条固定路线走一遍**，同时准备三张纸，每经过一个结点就往对应的纸上记一次。

## 二、手工求前序序列

考场上不写代码，用下面这个机械步骤即可，不会漏也不会重：

- 从根出发，**沿路线绕树一圈**（想象用笔沿树的外轮廓逆时针画一条闭合曲线）
- 每个结点在曲线上会被"擦到"三次（左侧、下方、右侧）
- 前序只记**左侧那一次**（中序记下方那次，后序记右侧那次）

以上图为例，绕行顺序为 A(左) B(左) D(左) D(下) D(右) B(下) E(左) … 只取"左侧"那些：**A B D E C F**。

这个方法的价值在"一次绕行同时得到三个序列"。分别做三遍很容易在深层结点处走错分支。

## 三、递归实现

递归实现直接对应前序遍历的定义：c

```
typedef struct BiTNode {
    char data;
    struct BiTNode *lchild, *rchild;
} BiTNode, *BiTree;

void PreOrder(BiTree T) {
    if (T == NULL) return;   // 递归出口：空子树什么都不做
    visit(T);                // 访问根结点 —— visit 在两次递归调用之前，这就是"前序"
    PreOrder(T->lchild);     // 递归遍历左子树
    PreOrder(T->rchild);     // 递归遍历右子树
}
```

把 `visit(T)` 移到两次递归调用**之间**即为中序遍历，移到两次递归调用**之后**即为后序遍历。三份代码只有这一行的位置不同。

### 复杂度的来历

**时间 O(n)**：`PreOrder` 对每个结点恰好被调用一次（另有 n+1 次对空指针的调用，也是常数工作），每次调用内部的工作量是常数，故总时间 Θ(n)。

**空间 O(h)，最坏 O(n)**：递归本身不额外分配数据结构，占用的是**系统栈**。任一时刻栈中的栈帧对应"从根到当前结点的那条路径"，所以栈深等于树高 h。

- 最坏：单支树（退化成链），h=n，空间 O(n)
- 最好：完全二叉树，h=⌈log2⁡(n+1)⌉，空间 O(log⁡n)

**注意"最好情况"不等于"平均情况"**：随机插入建出的二叉树平均高度是 O(log⁡n) 量级，但这是关于输入分布的结论，不能写成"前序遍历的空间复杂度是 O(log⁡n)"。给定一棵具体的树，空间就是它的高度。

## 四、非递归实现

### 写法一：弹栈访问，先压右后压左

递归本质上是系统替我们维护了一个调用栈。前序遍历的特殊之处在于：**访问发生在进入结点的第一时间**，此后左右子树的处理互不依赖。所以只要用一个栈保存"待处理的子树根"，弹一个访问一个即可。

关键思路：

- 将根结点入栈
- 循环：弹出栈顶结点并访问
- **先压右孩子、再压左孩子**
- 栈空时遍历结束c

```
void PreOrderNonRecursive(BiTree T) {
    if (T == NULL) return;
    BiTree stack[MAXSIZE];
    int top = -1;
    stack[++top] = T;                 // 根结点入栈
    while (top >= 0) {
        BiTNode *p = stack[top--];    // 弹出栈顶并访问：前序在"进入"时就访问
        visit(p);
        // 栈是后进先出，想让左子树先被弹出，就必须让它后入栈
        if (p->rchild != NULL)
            stack[++top] = p->rchild; // 右孩子先入栈
        if (p->lchild != NULL)
            stack[++top] = p->lchild; // 左孩子后入栈
    }
}
```

**为什么必须先压右**：栈是后进先出，**后入栈的先出栈**。前序要求左子树整体先于右子树被访问，所以左孩子必须后入栈。

**压反了会得到什么**：先压左、后压右，则每次都先展开右子树，得到的是 **NRL 序列**（根 → 右 → 左）。上例会输出 **A C F B E D**。这个序列本身也有用——**它的逆序恰好是后序序列**（D E B F C A），这正是[后序遍历的双栈法](./postorder.html)的原理。

**栈的逐步变化**（以上例的树为例）：

| 步骤 | 弹出并访问 | 压入 | 栈内容（栈顶在右） |
| --- | --- | --- | --- |
| 0 | — | A | [A] |
| 1 | A | C, B | [C, B] |
| 2 | B | E, D | [C, E, D] |
| 3 | D | — | [C, E] |
| 4 | E | — | [C] |
| 5 | C | F | [F] |
| 6 | F | — | [] |

输出序列：**A B D E C F**，与递归结果一致。

**栈的最大深度**：**不超过 h+1，因此空间同样是 O(h)**（最坏 O(n)，退化成单支链时）。

推理：弹出一个结点时会一次压入它的**两个**孩子，所以栈里可能出现两个深度相同的结点；除此之外，每一层至多留下**一个**尚未展开的右分支。因此栈中元素的深度自底向上严格递增、只有栈顶两个可能相等，栈的高度至多是 h+1。

**常见的误解是"它会装下整整一层"**——不会。上表里栈最大只到 3 个元素（树高 3）。对完全二叉树同样可以验证：n=4095（树高 12）时这个写法的栈峰值是 **12**，不是最后一层的 2048 个结点。**两种非递归写法的空间是同阶的**，真正的差别在栈内容的**语义**（见下表），不在量级。

### 写法二：统一模板的前序变体

三种深度优先遍历有一个共用的非递归框架——**沿左链一路入栈，走到头再回退向右**。它的完整推导写在 [中序遍历](./inorder.html)，这里只给前序变体：**把访问动作从"出栈时"提前到"入栈时"**。c

```
void PreOrder_Template(BiTree T) {
    Stack S; InitStack(S);
    BiTree p = T;
    while (p != NULL || !IsEmpty(S)) {
        if (p != NULL) {
            visit(p);          // ← 与中序的唯一差别：入栈前就访问（根在最前）
            Push(S, p);
            p = p->lchild;     // 一路向左
        } else {
            Pop(S, p);         // 左边走到头，回退
            p = p->rchild;     // 转向右子树
        }
    }
}
```

**两种写法怎么选**：

|  | 写法一（弹栈压右左） | 写法二（统一模板） |
| --- | --- | --- |
| 代码长度 | 更短，思路更直白 | 略长 |
| 栈的最大深度 | 至多 h+1（弹一个结点压两个孩子，栈顶可能有两个同深度结点） | 至多 h（栈中是当前路径上尚未访问的祖先） |
| 空间量级 | O(h)，最坏 O(n) | O(h)，最坏 O(n)——**两者同阶** |
| 能否改写成中序/后序 | 不能，只适用于前序 | **能**，改 `visit` 的位置即可推出中序；后序还要加标记 |
| 栈内容的含义 | 待处理的子树根集合 | 从根到当前结点的路径 |

需要"知道当前结点到根的路径"时（例如求某结点的所有祖先），必须用写法二——写法一的栈里存的是一堆并列的兄弟分支，不是路径。

## 五、前序序列的性质

| 性质 | 说明 | 依据 |
| --- | --- | --- |
| **首元素必是根** | 前序序列的第一个元素一定是整棵树的根 | 前序先访问根 |
| **子树在序列中连续** | 任一子树的所有结点在前序序列中占据一段**连续区间**，且该子树的根在区间最前 | 递归定义直接给出 |
| **NRL 的逆序 = 后序** | "根 → 右 → 左"序列反过来读就是"左 → 右 → 根" | 逆序把 NRL 变成 LRN |
| **前序 + 中序可唯一确定** | 前序定根、中序划分左右 | 见 [构造二叉树](./construct-binary-tree.html) |
| **前序 + 后序不能唯一确定** | 结点只有一个孩子时无法判断左右 | 见 [构造二叉树](./construct-binary-tree.html)（含反例） |
| **与 BST 结合** | BST 的前序序列可**单独**确定这棵 BST | 中序序列由前序排序即得，等价于已知前序 + 中序 |

### 前序序列与 DFS 的关系

树的前序遍历就是图的**深度优先搜索**（DFS）在树上的特例：都是"能往深处走就往深处走，走不动了回退"。差别只有两点：

- 图可能有环、可能有重复路径，DFS 必须维护 `visited[]` 数组；**树天然无环且路径唯一，所以不需要**
- 图的邻接点没有"左右"之分，遍历次序取决于存储结构（邻接表的链接顺序）；树的左右子树次序是确定的

同理，[层序遍历](./level-order-traversal.html)就是 [BFS](./../graph/bfs.html) 在树上的特例。

## 六、前序遍历的典型应用

前序的特征是**先处理根、再处理子树**，所以它适合"信息自顶向下传递"的任务。

### 1. 按前序序列建立二叉链表

给定一个含空指针标记（用 `#` 表示空树）的前序字符序列，可以直接递归建树——因为读到一个字符时，它就是当前子树的根，后面紧跟的正是它的左子树、再后面是右子树：c

```
void CreateBiTree(BiTree *T) {
    char ch;
    scanf("%c", &ch);
    if (ch == '#') {          // '#' 表示空树，递归出口
        *T = NULL;
    } else {
        *T = (BiTNode *)malloc(sizeof(BiTNode));
        (*T)->data = ch;                  // 先生成根结点 —— 对应前序的 visit
        CreateBiTree(&((*T)->lchild));    // 递归建左子树
        CreateBiTree(&((*T)->rchild));    // 递归建右子树
    }
}
```

**为什么建树必须用前序而不能用中序**：读到一个字符时必须马上知道"它是谁的什么"。前序序列里，根出现在子树之前，因此可以先造好根、再往下挂；中序序列里根夹在两棵子树中间，读到它时左子树已经读完但还不知道该挂到谁下面。这就是"**前序适合自顶向下构造**"的含义。

补空标记 `#` 是必要的：不加空标记，前序序列**不能**唯一确定二叉树；加上空标记后可以，因为每个空位置都被显式记录了。

### 2. 复制一棵二叉树

复制的动作次序与前序完全同构：先复制根，再递归复制左右子树。c

```
void Copy(BiTree T, BiTree *NewT) {
    if (T == NULL) { *NewT = NULL; return; }
    *NewT = (BiTNode *)malloc(sizeof(BiTNode));
    (*NewT)->data = T->data;                 // 复制根结点 —— 前序的 visit 位置
    Copy(T->lchild, &((*NewT)->lchild));     // 递归复制左子树
    Copy(T->rchild, &((*NewT)->rchild));     // 递归复制右子树
}
```

### 3. 输出表达式的前缀式

把表达式树按前序遍历输出，得到的就是**前缀表达式（波兰式）**；中序得到中缀式（缺括号）、后序得到后缀式（逆波兰式）。例如表达式树对应 a×b−c 时，前序输出 `-*abc`。

### 4. 需要"祖先信息"的自顶向下计算

如"给每个结点标上它的层号"、"求根到每个叶子的路径"——这类任务必须在**进入结点时**就把从双亲带下来的信息写好，正是前序的时机：c

```
// 输出每个结点的层号（根为第 1 层）
void PrintLevel(BiTree T, int level) {
    if (T == NULL) return;
    printf("%c:%d ", T->data, level);   // 进入时即可确定层号（信息由双亲传下）
    PrintLevel(T->lchild, level + 1);
    PrintLevel(T->rchild, level + 1);
}
```

### 前序做不了什么

凡是**需要先知道子树结果才能算根**的任务，前序都不适用，必须用后序：求树的高度、求结点总数、判断是否平衡、释放整棵树的内存（先释放根会丢掉子树指针）。判据很简单：**信息是从上往下流还是从下往上汇**——往下流用前序，往上汇用后序。

## 复杂度分析

| 实现方式 | 时间复杂度 | 空间复杂度 | 空间是谁占的 |
| --- | --- | --- | --- |
| 递归 | O(n) | O(h)，最坏 O(n) | 系统栈，栈中恰为根到当前结点的路径 |
| 非递归写法一（弹栈压右左） | O(n) | O(h)，最坏 O(n) | 显式栈，栈中是待展开的子树根，深度至多 h+1 |
| 非递归写法二（统一模板） | O(n) | O(h)，最坏 O(n) | 显式栈，栈中恰为当前路径 |
| 中序线索树上的遍历 | O(n) | O(1) | 不用栈，见[线索二叉树](./threaded-binary-tree.html) |

**时间为什么恒是 O(n)**：每个结点入栈一次、出栈一次、访问一次，各是常数工作，与树的形态无关。**时间不因树退化而变差，只有空间会**——这是遍历与查找（BST 查找会因退化从 O(log⁡n) 恶化到 O(n)）最本质的区别。

## 易混淆知识点

| 对比项 | 一方 | 另一方 | 判别依据 |
| --- | --- | --- | --- |
| 非递归入栈次序 | 前序写法一：**先压右、后压左** | 压反了得到 NRL 序列 | 栈后进先出，想先出必须后入 |
| 前序 vs 中序的非递归 | 前序在**入栈时**访问 | 中序在**出栈时**访问 | 统一模板下二者只差 `visit` 的位置 |
| 前序 + 中序 vs 前序 + 后序 | 前者唯一确定 | 后者不唯一 | 中序能划分左右子树，后序不能 |
| 前序序列 vs 带空标记的前序序列 | 单独不能确定二叉树 | 加 `#` 后可以确定 | 空位置是否被显式记录 |
| 前序适用 vs 后序适用 | 信息自顶向下传（层号、路径、复制、建树） | 信息自底向上汇（高度、结点数、释放内存） | 算根时需不需要子树的结果 |
| 递归的空间 vs 写法一的空间 | 递归栈恒等于树高 h | 写法一至多 h+1，**同为 O(h)** | 两者量级相同；差别在栈里装的是"路径"还是"待展开的分支"，不是装得下多少 |
| 前序遍历 vs 图的 DFS | 无需 `visited` 数组 | 必须有 `visited` | 树无环、每个结点只有一条来路 |
| 时间复杂度 vs 空间复杂度 | 恒 O(n)，与形态无关 | 随树高变化，O(log⁡n) 到 O(n) | 遍历必须碰每个结点，但栈只装一条路径 |

## 本节小结

学完本篇，应该能够：

- **说清三种深度优先遍历的唯一差别**：递归路线相同，只是在每个结点被经过的三次中选了不同的一次记录
- **手工写出任意二叉树的前序序列**，并用"绕树一圈、按左/下/右三个位置分别记录"的方法一次得到三种序列
- **默写前序的递归实现**，并说明空间复杂度 O(h) 来自系统栈里存的那条根到当前结点的路径
- **默写前序的两种非递归实现**，说清"先压右后压左"的理由，以及压反后得到的 NRL 序列反过来就是后序
- **在两种非递归写法之间做选择**：需要当前路径信息时只能用统一模板版
- **判断一个任务该用前序还是后序**：信息自顶向下传用前序，自底向上汇用后序
- **用前序驱动建树与复制**，并解释为什么建树必须补 `#` 空标记

**两条最关键的结论**：前序非递归的入栈次序是"**右先左后**"，理由是栈的后进先出；前序序列**单独**不能确定一棵二叉树，配上中序才能，配上后序仍然不能。
