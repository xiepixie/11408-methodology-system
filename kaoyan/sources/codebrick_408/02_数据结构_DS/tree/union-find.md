## 知识框架

本节要回答四个问题：

- 为什么"用森林表示集合"是这个问题的正确建模？森林的哪条性质被用上了？
- 朴素实现最坏是 O(n)，**具体是被什么样的操作序列卡到最坏的**？
- 按秩合并为什么能把树高压到 O(log⁡n)？——这条**能证明**
- "路径压缩 + 按秩合并 = O(α(n))"里的 O(α(n)) 是**单次**的还是**摊还**的？三种优化组合的复杂度分别是什么口径？

## 一、问题：动态连通性

给一堆元素，反复做两件事：

- **合并**：把两个元素所在的集合并成一个
- **查询**：判断两个元素是不是在同一个集合里

朴素做法是给每个元素记一个"集合编号"，查询 O(1)，但**合并要遍历整个集合改编号**，最坏 O(n)，m 次合并就是 O(mn)。并查集就是专门优化这类"**动态**连通性"问题的数据结构。

**为什么森林是对的建模**：

- 一个集合内部的元素之间**没有顺序要求**，只需要有个统一的"代表"能让大家认出彼此
- 树天然有唯一的根，**根就是天然的代表元**
- 判断"是否同集合"退化成"根是否相同"
- 合并两个集合，只需**把一个根挂到另一个根下**——O(1) 次指针修改，不用碰集合里的其他元素

关键是：**这个问题从头到尾只需要"往上找根"，从来不需要"往下找孩子"**。因此[双亲表示法](./general-tree.html)（每个结点只存一个 `parent` 下标）是最贴合的存储，一个整型数组就够，连指针都不用。

这是"**先有操作需求、后选存储结构**"的典型例子：三种一般树存储结构中，双亲表示法的短板是"找孩子要 O(n)"，而并查集恰好一次也不需要找孩子。

## 二、存储结构
c

```
#define MAX 100
int parent[MAX];   // parent[i] 存储元素 i 的双亲下标；根结点存 -1

// 初始化：每个元素自成一个集合
void Init(int n) {
    for (int i = 0; i < n; i++)
        parent[i] = -1;    // -1 表示"我就是根"
}
```

初始状态下每个元素都是一棵单结点的树，森林里有 n 棵树、n 个集合。

**根的两种约定**（做题时看清题面用的是哪种）：

| 约定 | 找根的循环 | 附加好处 |
| --- | --- | --- |
| `parent[root] = -1` | `while (parent[x] != -1) x = parent[x];` | 直观 |
| `parent[root] = root`（指向自己） | `while (parent[x] != x) x = parent[x];` | 不用判负，代码更短 |
| `parent[root] = -size`（负数记集合元素个数） | `while (parent[x] >= 0) x = parent[x];` | **顺带得到集合大小**，可直接做"按规模合并" |

第三种是教材插图里采用的写法，见下文第六节。**本篇正文统一用第一种（根存 −1）**。

## 三、朴素实现与它的最坏情形

### 朴素 Find

从元素 x 出发，沿 `parent` 链一直向上，直到 `parent[x] == -1`：c

```
int Find(int x) {
    while (parent[x] != -1)
        x = parent[x];
    return x;          // 返回 x 所在集合的根（代表元）
}
```

**时间 O(h)**，h 为该元素所在树的高度。

### 朴素 Union
c

```
void Union(int x, int y) {
    int rx = Find(x);
    int ry = Find(y);
    if (rx != ry)
        parent[rx] = ry;    // 让 rx 挂到 ry 下面
}
```

**时间 O(h)**，主要花在两次 `Find` 上；真正的挂接只有一次赋值。

**注意 `Union` 操作的对象是"两个根"，不是"两个元素"**。直接写 `parent[x] = y` 是错的——那会把 x 从它原来的树里拽出来，破坏原集合的结构。

### 最坏情形具体长什么样

朴素实现的最坏是 O(n)，**它是被下面这个操作序列卡出来的**：

```
Init(n) 后依次执行： Union(0,1), Union(1,2), Union(2,3), ..., Union(n-2, n-1)

第 1 步 Union(0,1)：Find(0)=0, Find(1)=1, parent[0]=1
        1
        |
        0

第 2 步 Union(1,2)：Find(1)=1, Find(2)=2, parent[1]=2
        2
        |
        1
        |
        0

第 k 步 Union(k-1,k)：把整棵高度为 k-1 的树挂到单结点 k 下面
   ...

最终形成一条长度为 n 的链：  n-1 ← n-2 ← ... ← 1 ← 0
```

此后每次 `Find(0)` 都要走 n−1 步。**根因是：朴素 `Union` 总是把"前者的根"挂到"后者的根"下，完全不看两棵树的规模**，于是一棵高树被挂到了一个单结点下面，高度加 1。

**修好它有两条独立的思路**：

- **别让树长高**：合并时看清两棵树的规模，让**小的挂到大的下面** → 按秩合并 / 按规模合并
- **走过就把路铺平**：既然 `Find` 已经走了一趟，顺手把这一路上的结点全部直接挂到根上 → 路径压缩

两条思路互不冲突，可以同时用。

## 四、按秩合并

维护一个 `rank[]` 数组记录每棵树的**高度上界**（"秩"）。合并时让**秩小的树挂到秩大的树下面**：c

```
int rank_[MAX];    // rank_[i]：以 i 为根的树的高度上界

void Init(int n) {
    for (int i = 0; i < n; i++) {
        parent[i] = -1;
        rank_[i] = 0;      // 单结点树的高度记为 0
    }
}

void Union(int x, int y) {
    int rx = Find(x), ry = Find(y);
    if (rx == ry) return;              // 已在同一集合，什么也不做
    if (rank_[rx] < rank_[ry]) {
        parent[rx] = ry;               // 矮树挂到高树下：整棵树的高度不变
    } else if (rank_[rx] > rank_[ry]) {
        parent[ry] = rx;
    } else {
        parent[ry] = rx;               // 等高时任选一个作根
        rank_[rx]++;                   // 只有等高合并才会让高度 +1
    }
}
```

`rank` 是 C++ 标准库里的名字，在 C 里也容易与其他标识符撞名，代码中写作 `rank_`。

### 定理：按秩合并后，任一棵树的高度 h 满足 h≤⌊log2⁡n⌋

**证明（先证一个更强的引理）**：**秩为 h 的树至少含 2h 个结点。**

对 h 归纳：

- h=0：单结点树，1=20 ✓
- 设结论对 <h 成立。一棵树的秩变成 h，只可能发生在"两棵秩均为 h−1 的树等高合并"这一种情形（另外两个分支里秩不变）。由归纳假设，两棵树各至少 2h−1 个结点，合并后至少 2h−1+2h−1=2h 个 ✓

于是若整个并查集共 n 个元素，任一棵树的结点数 ≤n，故 2h≤n，即h≤log2⁡n◼

**所以按秩合并把 `Find` 和 `Union` 的**最坏**时间从 O(n) 降到 O(log⁡n)**——注意这是**最坏**复杂度，不是摊还的，每一次操作都有这个保证。

**从上面的证明还能看出一件事**：秩只在"两棵等高树合并"时才增加，而这需要结点数翻倍。所以**秩增长得非常慢**——n=106 时秩最多 19。

## 五、路径压缩

`Find` 已经从 x 走到了根，这一路经过的所有结点其实都属于同一个集合、根也都是同一个。**既然走都走了，顺手把它们全部直接挂到根上**，下次再查这些结点只需一步。c

```
// 路径压缩 Find（递归版）
int Find(int x) {
    if (parent[x] == -1)
        return x;
    parent[x] = Find(parent[x]);   // 递归找根，返回途中顺手把 x 直接挂到根上
    return parent[x];
}

// 路径压缩 Find（迭代版，无递归栈开销）
int Find(int x) {
    int root = x;
    while (parent[root] != -1)     // 第一趟：先找到根
        root = parent[root];
    while (x != root) {            // 第二趟：把路径上的结点全部改挂到根
        int next = parent[x];      // 先存好原来的双亲，否则改了就找不到了
        parent[x] = root;
        x = next;
    }
    return root;
}
```

**图示**（压缩前 → 压缩后，`Find(4)` 触发）：

```
压缩前              执行 Find(4) 之后
   0                     0
   |                  / /| \
   1                 1 2 3  4       ← 路径上的 1、2、3、4 全部直接挂到根 0
   |
   2
   |
   3
   |
   4
```

### 三个必须理解的点

- **路径压缩不改变集合的划分**。它只改 `Find` 路径上结点的 `parent` 指向，**这些结点本来就在同一个集合里**——集合的成员一个没变，只是树被压扁了
- **单次 `Find` 不会因为压缩而变慢**。压缩的额外工作量与这趟路径的长度同阶，最多让常数翻倍
- **压缩后 `rank` 不再等于真实树高，只是一个上界**。路径压缩会降低实际树高，但**不去更新 `rank`**——因为精确维护 `rank` 需要重新扫描整棵子树，代价太大；而上界已经足够保证前面那条定理的复杂度结论

### 只用路径压缩的复杂度

单独使用路径压缩（配朴素合并）时，单次 `Find` 的**最坏**仍可能是 O(n)（第一次查一条长链），但**摊还**到每次操作上是 O(log⁡n)——因为那条长链被压平一次之后就再也不长了，代价被后续操作分摊掉了。

**"最坏"和"摊还"必须分清**：按秩合并给的是**每一次**都不超过 O(log⁡n) 的硬保证；路径压缩给的是**平均到每次操作**不超过 O(log⁡n)，个别操作仍可能更慢。

## 六、按规模合并与"根存负数"的技巧

按秩合并比较的是**树高**；另一种等效做法是比较**集合元素个数**，称为**按规模合并**（union by size）：让元素少的树挂到元素多的树下。

它的复杂度保证同样是 O(log⁡n)，理由更直观：**一个结点的深度只有在它所在的树被挂到另一棵不小于它的树下时才增加 1，而这会让它所在集合的规模至少翻倍**；规模从 1 翻到 n 最多翻 log2⁡n 次，所以任一结点的深度不超过 log2⁡n。

按规模合并有一个实现上的便利：**把根的 `parent` 直接存成"集合元素个数的相反数"**，一个数组同时兼任两职：c

```
int parent[MAX];   // 非根：存双亲下标（非负）；根：存 -（集合元素个数）

void Init(int n) {
    for (int i = 0; i < n; i++) parent[i] = -1;   // 每个集合 1 个元素
}

int Find(int x) {
    while (parent[x] >= 0) x = parent[x];         // 负数即为根
    return x;
}

void Union(int x, int y) {
    int rx = Find(x), ry = Find(y);
    if (rx == ry) return;
    if (parent[rx] > parent[ry]) {                // 注意是负数：值大 = 规模小
        parent[ry] += parent[rx];                 // ry 规模更大，累加规模
        parent[rx] = ry;                          // 小的挂到大的下面
    } else {
        parent[rx] += parent[ry];
        parent[ry] = rx;
    }
}
```

**比较方向容易写反**：存的是负数，所以 `parent[rx] > parent[ry]` 表示 **rx 的集合更小**。写代码时把它读成"绝对值小的挂到绝对值大的下面"就不会反。

**额外收益**：求"某元素所在集合有多少个元素"变成 O(1)（`-parent[Find(x)]`），这在很多应用里是要用的。

上图从 12 个各自独立的单元素集合出发，逐批处理等价对：(a) 是初始状态，每个根都标着 [−1]（集合只有 1 个元素）；(b) 处理 4 对不相交的等价关系，各自形成 [−2] 的两元素集合；(c) 继续处理时开始出现"树挂到树下"，根上的计数变成 [−3]、[−4]；(d) 处理最后一对 11≡0 时，规模为 2 的那棵树整体挂到了规模为 3 的树下，得到 [−5]。 **注意图中根结点存的是"集合元素个数的负值"**，与本篇正文统一采用的"根存 −1"是两种不同的约定——这张图用的正是上面讲的**按规模合并**写法，读图时先看清这一点。 图源：殷人昆《数据结构——用面向对象方法与 C++ 描述》（第 2 版）图 6.10 使用并查集处理等价对、形成等价类的过程，p268

## 七、完整手算示例

### 例 1：朴素 Union（无优化）

初始集合 {0,1,2,3,4}，依次执行 `Union(0,1)`、`Union(2,3)`、`Union(1,3)`、`Union(0,4)`。朴素 `Union` 让**前者的根**挂到**后者的根**下。

```
初始状态：每个元素独立（parent 均为 -1）
  0    1    2    3    4

第 1 步 Union(0,1)：Find(0)=0, Find(1)=1 → parent[0]=1
  1    2    3    4
  |
  0

第 2 步 Union(2,3)：Find(2)=2, Find(3)=3 → parent[2]=3
  1    3    4
  |    |
  0    2

第 3 步 Union(1,3)：Find(1)=1, Find(3)=3 → parent[1]=3
       3    4
      / \
     1   2
     |
     0

第 4 步 Union(0,4)：Find(0)：0→1→3，根为 3；Find(4)=4 → parent[3]=4
         4
         |
         3
        / \
       1   2
       |
       0
```

**`parent` 数组变化过程**：

| 操作 | parent[0] | parent[1] | parent[2] | parent[3] | parent[4] |
| --- | --- | --- | --- | --- | --- |
| 初始 | -1 | -1 | -1 | -1 | -1 |
| Union(0,1) | 1 | -1 | -1 | -1 | -1 |
| Union(2,3) | 1 | -1 | 3 | -1 | -1 |
| Union(1,3) | 1 | 3 | 3 | -1 | -1 |
| Union(0,4) | 1 | 3 | 3 | 4 | -1 |

此时查 `Find(0)` 需要走 3 步（0→1→3→4）。

### 例 2：接着做一次带路径压缩的 `Find(0)`

```
压缩前              执行 Find(0) 之后
     4                    4
     |                  / | \
     3                 3  1  0      ← 路径 0→1→3→4 上的 0、1、3 全部直挂到根 4
    / \                |
   1   2               2
   |
   0
```

**`parent` 数组**：`parent[0]` 由 1 变为 **4**、`parent[1]` 由 3 变为 **4**、`parent[3]` 保持 **4**（本来就直接挂在根上）、`parent[2]` **不变**（仍为 3，它不在这次 `Find` 的路径上）。

**这个例子说明两件事**：① 路径压缩只动**这一趟走过的**结点，旁支（如结点 2）不受影响；② 压缩后集合成员一个没变，仍是 {0,1,2,3,4}。

## 八、复杂度总表

| 实现方式 | `Find` | `Union` | 口径 | 依据 |
| --- | --- | --- | --- | --- |
| 朴素（无优化） | O(n) | O(n) | 最坏 | 可被"依次 `Union(i-1,i)`"卡成一条长链 |
| **仅**按秩 / 按规模合并 | O(log⁡n) | O(log⁡n) | **最坏**（每次都有硬保证） | 秩为 h 的树至少 2h 个结点 ⇒h≤log2⁡n |
| **仅**路径压缩 | O(log⁡n) | O(log⁡n) | **摊还**（单次仍可能 O(n)） | 长链被压平一次后不再重现，代价被后续操作分摊 |
| 路径压缩 **+** 按秩合并 | O(α(n)) | O(α(n)) | **摊还** | 经典结果；α 为反阿克曼函数 |

**空间**：O(n)——一个 `parent[]` 数组；按秩合并额外一个 `rank[]` 数组，按规模合并则可以把规模塞进 `parent[]` 的负数里，不需要第二个数组。

### 关于 α(n)

α(n) 是**反阿克曼函数**，增长极其缓慢。对于任何实际可能出现的 n（哪怕是宇宙中的原子数量级），α(n) 都不超过 **5**，所以工程上把它当作常数。

**但它不是常数**：α(n) 确实随 n 增长而增长，只是慢到没有实际意义。表述时写"**接近常数**"或"**近似 O(1)**"是准确的，写成"就是 O(1)"不严谨。

**"摊还"的准确含义**：m 次操作的**总**时间是 O(m⋅α(n))，**平均**到每次操作是 O(α(n))；**个别单次操作仍可能更慢**（比如第一次查一条尚未被压缩的长路径）。凡是问"单次最坏"的，答案不是 O(α(n))。

## 九、典型应用

### 1. Kruskal 算法中的判环

[Kruskal 算法](./../graph/kruskal.html)按权值从小到大考察每条边，需要判断"加入这条边会不会形成回路"。等价的问法是：**这条边的两个端点是不是已经连通了？**——正好是并查集的查询操作。

- 初始化并查集，每个顶点自成一个集合
- 将所有边按权值排序
- 依次取权值最小的边 (u,v)，执行 `Find(u)` 与 `Find(v)`
- 若两个根**不同**：u、v 尚未连通，**选中该边**并执行 `Union(u, v)`
- 若两个根**相同**：u、v 已连通，加入该边会形成回路，**跳过**
- 选够 n−1 条边即得最小生成树

**这里体现了并查集不可替代的价值**：如果每次都用 DFS/BFS 判连通，单次就是 O(n+e)；并查集把它降到接近常数。

### 2. 等价类划分

给出若干"等价关系"对 (a,b)，把所有相互等价的元素归入同一类。做法：每读入一对就执行 `Union(a, b)`；全部处理完后，`Find` 值相同的元素属于同一等价类。

**为什么并查集恰好适配等价关系**：等价关系的三条性质与并查集的行为一一对应——

| 等价关系的性质 | 并查集里的体现 |
| --- | --- |
| 自反性（a≡a） | 初始化时每个元素自成一集，`Find(a) == Find(a)` 恒真 |
| 对称性（a≡b⇒b≡a） | `Union` 与查询都不区分参数次序 |
| 传递性（a≡b,b≡c⇒a≡c） | 合并后三者同根，查询自动返回同一个代表元 |

上一节的教材插图演示的就是这个过程。

### 3. 连通分量计数

初始把计数器置为 n（每个元素一个集合），每次**成功**的 `Union`（两个根不同）让计数器减 1。处理完所有边后，计数器的值就是**连通分量个数**。

**判断无向图是否连通**：处理完所有边后计数器是否为 1。 **判断无向图是否有环**：若某次 `Union` 时两个端点的根已经相同，说明存在回路。

### 并查集做不到什么

| 不支持的操作 | 原因 |
| --- | --- |
| **删除元素、把集合拆开** | 合并是把根挂上去，"拆分"需要知道谁挂在谁下面——而双亲表示法只存向上的边，找孩子是 O(n)；路径压缩更是把原始结构彻底破坏了 |
| **枚举某个集合的所有元素** | 同上，没有向下的指针 |
| **求两个集合的交集** | 并查集只维护"划分"，不维护集合内部的任何结构 |

**判据一句话**：**并查集只回答"是不是一伙的"，不回答"这一伙都有谁"。** 需要后者时得另开一个数组或链表来记。

## 易混淆知识点

| 对比项 | 一方 | 另一方 | 判别依据 |
| --- | --- | --- | --- |
| 按秩合并的复杂度口径 | O(log⁡n)，**最坏** | — | 每次操作都有硬保证，由"秩为 h 的树至少 2h 个结点"证得 |
| 路径压缩的复杂度口径 | O(log⁡n)，**摊还** | 单次最坏仍可能 O(n) | 第一次查长链时压缩本身就要走完全程 |
| 两者结合的复杂度口径 | O(α(n))，**摊还** | 不是单次最坏 | m 次操作总时间 O(mα(n)) |
| α(n) 是不是常数 | **不是**，只是增长极慢（实际 ≤5） | 说"接近常数"对，说"就是 O(1)"不严谨 | 反阿克曼函数确实随 n 增长 |
| `rank` 是不是真实树高 | 压缩前是；**压缩后只是上界** | — | 路径压缩降低实际高度但不更新 `rank` |
| 按秩合并 vs 按规模合并 | 比较树高 | 比较元素个数 | 都能保证 O(log⁡n)；按规模可用负数塞进 `parent` 数组 |
| 路径压缩改变了什么 | 只改 `Find` 路径上结点的 `parent` | **不改变集合的划分** | 成员一个没变，只是树被压扁 |
| `Union` 的操作对象 | 两个**根** | 不是两个元素 | 直接 `parent[x] = y` 会把 x 从原树里拽出来 |
| 并查集用哪种一般树存储 | **双亲表示法** | 不是孩子表示法 | 全部操作只往上走，一次也不找孩子 |
| 并查集能做 vs 不能做 | 判断"是不是一伙的"、数连通分量 | 不能删除、拆分、枚举集合成员 | 只存向上的边 |
| 根的三种约定 | −1 / 指向自身 / −size | — | 看题面；第三种顺带给出集合大小 |

## 本节小结

学完本篇，应该能够：

- **说清"用森林表示不相交集合"为什么是正确建模**：根天然是代表元，判同集合退化成判根相同，合并只需一次指针修改；并说明为什么选[双亲表示法](./general-tree.html)——全部操作只往上走
- **默写 `Init` / `Find` / `Union` 的朴素实现**，并**构造出把它卡到 O(n) 的具体操作序列**（依次 `Union(i-1, i)` 形成长链），说清根因是合并时不看两棵树的规模
- **默写按秩合并**，并**证明**"秩为 h 的树至少含 2h 个结点"，由此得到树高 ≤log2⁡n
- **默写路径压缩的递归版与迭代版**，说清它不改变集合划分、以及为什么 `rank` 在压缩后只是上界
- **分清三种优化组合的复杂度口径**：按秩合并是**最坏** O(log⁡n)、路径压缩是**摊还** O(log⁡n)、两者结合是**摊还** O(α(n))
- **手算 `parent` 数组的逐步变化**，包括一次路径压缩后哪些下标改了、哪些没改
- **说明并查集在 Kruskal 中扮演的角色**（判环 = 判两端点是否已连通），以及等价关系三性质与并查集行为的对应
- **说出并查集做不到的事**：删除、拆分、枚举集合成员

**两条最关键的结论**：**按秩合并的 O(log⁡n) 是最坏保证、路径压缩与两者结合的复杂度是摊还的**，问"单次最坏"时不能答 O(α(n))；**路径压缩只改路径上结点的双亲指向，集合的划分丝毫未变**。
