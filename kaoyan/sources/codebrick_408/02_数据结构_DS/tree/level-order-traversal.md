## 知识框架

本节要回答三个问题：

- 层序为什么**必须**用队列？换成栈会得到什么？为什么它不能像前中后序那样写成递归？
- 基本的层序遍历只输出一串结点，怎么改造成"知道每个结点在第几层"？
- 判定完全二叉树为什么用层序最方便？判定条件的准确写法是什么？

## 一、访问顺序

层序遍历从根所在的第 1 层开始，**自上而下、每层自左至右**依次访问每个结点。

```
        A          第 1 层: A
       / \
      B   C        第 2 层: B C
     / \   \
    D   E   F      第 3 层: D E F

层序遍历结果: A → B → C → D → E → F
```

### 为什么必须用队列

层序要求的次序是"离根近的先访问，同样近的按从左到右"。用队列驱动时：

- 根先入队
- 每次取队头结点 p 并访问，把 p 的左孩子、右孩子**依次入队**
- 队列先进先出，所以第 k 层的结点全部排在第 k+1 层的结点之前；同一层内，谁先入队谁先出队，而入队次序正是"双亲从左到右、每个双亲先左孩子后右孩子"，恰好就是同层从左到右

**换成栈会怎样**：栈后进先出，取出根后压入左右孩子，下一轮取出的是刚压进去的孩子，于是立刻往深处走——得到的是深度优先的次序（具体是哪一种取决于压栈次序），**层次结构完全丢失**。

**为什么层序不能写成递归**：递归调用栈天然是后进先出，函数返回的次序决定了它只能做深度优先。要用递归"模拟"层序，只能靠"逐层重来"（第 k 轮只输出第 k 层）这类做法，时间会退化到 O(nh)。**层序是四种遍历里唯一不是递归定义的**，这也是它在教材里被单列的原因。

## 二、基本实现
c

```
typedef struct BiTNode {
    char data;
    struct BiTNode *lchild, *rchild;
} BiTNode, *BiTree;

void LevelOrder(BiTree T) {
    if (T == NULL) return;
    BiTree queue[MAXSIZE];              // 辅助队列，存的是结点指针
    int front = 0, rear = 0;
    queue[rear++] = T;                  // 根结点入队
    while (front != rear) {             // 队非空
        BiTree p = queue[front++];      // 队头出队
        visit(p);                       // 访问当前结点
        if (p->lchild != NULL)
            queue[rear++] = p->lchild;  // 左孩子先入队，保证同层从左到右
        if (p->rchild != NULL)
            queue[rear++] = p->rchild;  // 右孩子后入队
    }
}
```

**这段代码用的是"非循环"的顺序队列**：`front` 与 `rear` 只增不回绕，靠 `MAXSIZE` 开够大来回避溢出。它能跑对，但存在**假溢出**——`rear` 到头时前面出队腾出的空间用不上。规范写法是把它换成**循环队列**（入队 `rear = (rear+1) % MAXSIZE`、出队 `front = (front+1) % MAXSIZE`），或者用链队列。

由于每个结点恰好入队一次，整个遍历过程的入队总次数是 n，所以只要 `MAXSIZE` >n，上面的简化写法就不会越界；但队列同时容纳的结点数其实远小于 n（见下文复杂度分析），用循环队列可以把空间从 n 降到"最大宽度"。

## 三、按层分组：让每个结点知道自己在第几层

基本版输出的是一串扁平的序列，分不出层。要分层，关键在于**在每一轮循环开始时把当前队列长度记下来**——那个数字恰好就是当前这一整层的结点数：c

```
void LevelOrderByLevel(BiTree T) {
    if (T == NULL) return;
    BiTree queue[MAXSIZE];
    int front = 0, rear = 0;
    queue[rear++] = T;
    int level = 0;
    while (front != rear) {
        int cnt = rear - front;      // 关键：此刻队列里恰好是完整的一层
        level++;
        printf("第 %d 层：", level);
        while (cnt--) {              // 一次内层循环刚好处理完这一层
            BiTree p = queue[front++];
            printf("%c ", p->data);
            if (p->lchild) queue[rear++] = p->lchild;
            if (p->rchild) queue[rear++] = p->rchild;
        }
        printf("\n");
    }
}
```

**为什么"此刻队列里恰好是完整的一层"**：进入外层循环时，上一层的结点已全部出队，而它们的孩子（即当前层的全部结点）都已入队，且当前层还没有任何结点出队去生成下一层。这个不变量在每轮外层循环开始时都成立。

由这个写法直接派生出：

| 派生任务 | 做法 |
| --- | --- |
| **求树的高度** | 外层循环执行了几轮，树就有几层 |
| **求树的最大宽度** | 取所有轮次中 `cnt` 的最大值 |
| **输出每个结点的层号** | 用当前的 `level` |
| **求最后一层的结点** | 最后一轮外层循环处理的那批 |
| **自底向上的层序** | 把每层结果压栈，最后逐层弹出 |
| **之字形（蛇形）遍历** | 奇数层正序输出、偶数层把该层结果逆序输出 |

## 四、用层序判定完全二叉树

[完全二叉树](./concepts.html)的形态特征是"前 h−1 层满、第 h 层从左到右连续"。翻译成层序遍历的语言就是：

**把空孩子也当作结点入队**，则一旦从队列中取出一个**空**结点，此后队列中**不允许**再出现任何非空结点。c

```
int IsCompleteBinaryTree(BiTree T) {
    if (T == NULL) return 1;                 // 空树按完全二叉树处理
    BiTree queue[MAXSIZE];
    int front = 0, rear = 0;
    queue[rear++] = T;
    while (front != rear) {
        BiTree p = queue[front++];
        if (p != NULL) {
            queue[rear++] = p->lchild;       // 注意：空孩子也要入队，不加 if 判断
            queue[rear++] = p->rchild;
        } else {
            // 取出了一个空结点，检查后面是否还有非空结点
            while (front != rear) {
                if (queue[front++] != NULL) return 0;   // 空结点之后还有实结点 → 不完全
            }
        }
    }
    return 1;
}
```

**正确性**：若树是完全二叉树，按层序把空位也算上，实结点的编号是 1..n 连续的，空位全部排在 n 之后，所以第一个空结点之后一定全是空。反之，若某个实结点排在某个空位之后，说明编号出现了空洞，与"编号 1..n 连续"矛盾。

**易错点**：判定代码里孩子入队时**不能加 `if (p->lchild)` 判断**。加了就等于把空位跳过去了，编号空洞被抹平，任何二叉树都会被判成完全二叉树。这是本节最容易写错的一行。

## 五、层序序列的性质

| 性质 | 说明 |
| --- | --- |
| **第一个元素是根** | 与前序相同 |
| **层序单独不能确定二叉树** | 层序序列只给出"谁在谁前面"，不给出父子归属。例如层序 `A B` 对应"B 是 A 的左孩子"与"B 是 A 的右孩子"两棵不同的树 |
| **层序 + 中序可唯一确定** | 层序首元素定根，中序划分左右，再从层序中按归属筛出两组子序列递归。算法见 [构造二叉树](./construct-binary-tree.html) |
| **层序 + 前序 / 层序 + 后序不能确定** | 三者都定不了左右边界，理由与"前序 + 后序不行"相同 |
| **完全二叉树的层序序列 = 它的顺序存储数组** | 顺序存储就是按层序编号放，二者定义等价。所以对完全二叉树，层序序列**单独**就能唯一确定这棵树 |
| **层序序列不能直接判断祖先关系** | 只能判断层次先后。`X` 排在 `Y` 前面只说明 `X` 的层次不深于 `Y`，不说明 `X` 是 `Y` 的祖先 |

## 六、层序与图的 BFS

树的层序遍历就是图的**广度优先搜索**在树上的特例。二者的对应关系：

| 树的层序 | 图的 BFS | 差别的原因 |
| --- | --- | --- |
| 队列驱动，根先入队 | 队列驱动，起点先入队 | 相同 |
| **不需要** `visited[]` 数组 | **必须**有 `visited[]` | 树无环、每个结点只有一条来路；图可能有环、有多条路径 |
| "层号"就是到根的**边数** | "层号"就是到起点的**最短路径长度**（边数） | 同一件事；这正是 [BFS 求无权图最短路径](./../graph/bfs-shortest.html) 的原理 |
| 孩子次序由左右子树决定 | 邻接点次序由存储结构（邻接表链接顺序）决定 | 树的左右是有序的 |
| 结点只入队一次 | 结点只入队一次（靠 `visited` 保证） | — |

同理，[前序遍历](./preorder.html)是 [DFS](./../graph/dfs.html) 在树上的特例。**DFS 与 BFS 的分界只有一条：待处理结点存在栈里还是队列里。**

## 复杂度分析

| 指标 | 复杂度 | 来历 |
| --- | --- | --- |
| 时间 | O(n) | 每个结点恰好入队一次、出队一次、访问一次，各是常数工作 |
| 空间 | O(n) | 辅助队列；峰值等于遍历过程中队列同时容纳的最大结点数 |

**空间的准确来历**：队列的峰值长度取决于树的**宽度**，而不是高度——这与前中后序遍历（栈深 = 树高）正好互补。

- **完全二叉树**：峰值恰为 ⌈n/2⌉。峰值出现在最后一个分支结点出队、把它的孩子送进队列的那一刻。（n=1∼199 全部验证过，峰值与 ⌈n/2⌉ 逐个吻合。）
- **单支树（退化成链）**：任一时刻队列里最多只有 1 个结点，空间 O(1)——**恰好是前中后序遍历最坏的那种树**

**由此得到一条实用结论**：树越"宽"，层序越费空间、深度优先越省；树越"深"，反之。二者的最坏情形互不重叠，题目问"哪种遍历更省空间"时必须先看树形。

## 易混淆知识点

| 对比项 | 一方 | 另一方 | 判别依据 |
| --- | --- | --- | --- |
| 层序 vs 前中后序的驱动结构 | 队列（FIFO） | 栈（LIFO，含系统栈） | 队列产生广度优先，栈产生深度优先 |
| 层序 vs 前中后序的空间瓶颈 | 树的**最大宽度**，完全二叉树时 ⌈n/2⌉ | 树的**高度** h | 一个怕宽、一个怕深，最坏情形正好相反 |
| 层序能否写成递归 | 不能（天然非递归） | 前中后序天然递归 | 递归栈是 LIFO，做不出 FIFO 的次序 |
| 判完全二叉树时孩子入队 | **空孩子也必须入队** | 普通层序遍历里空孩子不入队 | 加了 `if` 判空就抹平了编号空洞，任何树都会被判成完全 |
| 层序序列的确定性 | 一般二叉树：不能唯一确定 | **完全二叉树：能**唯一确定 | 完全二叉树的层序序列等价于其顺序存储数组 |
| 层序 + 中序 vs 层序 + 前序 | 前者能唯一确定 | 后者不能 | 只有中序能划分左右子树 |
| 层序序列的先后 vs 祖先关系 | 只能说明层次不深于 | 不能说明是祖先 | 同一层的结点也有先后 |
| 树的层序 vs 图的 BFS | 不需要 `visited` | 必须有 `visited` | 树无环、来路唯一 |
| 顺序队列 vs 循环队列 | 直接 `rear++` 会假溢出 | 取模回绕可复用空间 | 队列容量是否需要与最大宽度相当而非 n |

## 本节小结

学完本篇，应该能够：

- **写出任意二叉树的层序序列**，并说清队列的 FIFO 性质如何同时保证"层次由浅到深"和"同层从左到右"
- **解释层序为什么不能写成递归**：递归栈是后进先出，只能做深度优先
- **默写基本层序遍历代码**，并指出简化版顺序队列的假溢出问题与循环队列的改法
- **写出按层分组的层序遍历**，说清"进入外层循环时队列里恰好是完整一层"这个不变量，并由它派生出求高度、求最大宽度、输出层号、之字形遍历
- **写出判定完全二叉树的层序算法**，并说明为什么**空孩子也必须入队**
- **判断哪些序列组合能唯一确定二叉树**：层序 + 中序可以；层序单独、层序 + 前序、层序 + 后序都不行；但**完全二叉树的层序序列单独就够**
- **说清层序的空间复杂度由树的宽度决定**，与深度优先遍历（由高度决定）的最坏情形正好互补

**两条最关键的结论**：判完全二叉树时**空孩子必须入队**，否则算法退化成"任何树都是完全二叉树"；层序的空间瓶颈是**宽度**（完全二叉树时 ⌈n/2⌉），前中后序的空间瓶颈是**高度**。
