## 知识框架

本节要回答四个问题：

- 已经有 AVL 了，为什么还要红黑树？——AVL 到底"贵"在哪一步？
- 给一棵着了色的二叉树，**怎么机械地判断它是不是红黑树**？

## 一、为什么还要红黑树

[AVL 树](./avl.html)已经把树高钉死在 1.44log2⁡n 以内，查找非常快。它的问题出在**维护成本**：

- **插入**至多一次调整，代价可控
- **删除**可能从删除位置一路旋转到根，最多 O(log⁡n) 次旋转

对"查得多、改得少"的场景 AVL 很划算；但对**插入删除极其频繁**的场景（进程调度队列、内存管理的空闲块表、通用有序容器），每次删除都可能触发连锁旋转，代价就显出来了。

**红黑树的策略是放松平衡条件**：不要求左右子树高度严格相差不超过 1，只要求**任意一条从某结点到叶子的路径上，黑色结点的数量相同**。

代价是树可能比 AVL 高出将近一倍（最坏 2log2⁡(n+1) 对 1.44log2⁡(n+2)），换来的是**插入最多转 2 次、删除最多转 3 次**——**旋转次数有常数上界，与树高无关**。

**一句话概括这场交易**：**红黑树用"查找时多走几层"换"修改时少转几次"。** 判断该选谁，就看这两件事在具体场景里哪件更频繁。

## 二、五条性质与黑高

红黑树是一棵**二叉排序树**，并且**同时满足**以下五条性质：

| 编号 | 性质 | 说明 |
| --- | --- | --- |
| ① | 每个结点是**红色**或**黑色** | 只需 1 bit 额外空间 |
| ② | **根结点是黑色** | — |
| ③ | **叶结点（NIL）是黑色** | 这里的"叶结点"指外部的**空结点**，不是普通意义上没有孩子的内部结点 |
| ④ | **红结点的两个孩子都是黑色** | 等价于"不存在两个连续的红结点"，简称**不红红** |
| ⑤ | 从任一结点到其所有叶结点（NIL）的路径上，**黑色结点数目相同** | 简称**黑高相等** |

c

```
typedef enum { RED, BLACK } Color;

typedef struct RBNode {
    int key;
    Color color;
    struct RBNode *left, *right, *parent;   // 调整时需要向上回溯，所以存双亲指针
} RBNode;
```

**为什么红黑树的结点通常带 `parent` 指针**：插入和删除的调整都要看**祖父**和**叔 / 兄弟**结点，必须能向上走。这与[线索二叉树里"前序找前驱需要三叉链表"](./threaded-binary-tree.html)是同一类需求。

### 性质 ③ 的准确含义

**这里的"叶结点"是 NIL 空结点（外部结点），不是普通的叶子。**

```
        13(黑)
       /      \
     8(红)     17(红)
    /   \       /    \
 NIL   NIL    NIL    NIL       ← 这些才是性质 ③ 说的"叶结点"，全部为黑
```

**画红黑树时一定要把 NIL 画出来**，否则数黑高时必然出错——性质 ⑤ 数的路径终点正是这些 NIL。

### 黑高的定义

**黑高（Black Height）** bh(x)：从结点 x 出发（**不含 x 自己**）到任一叶结点（NIL）的路径上**黑色结点的个数**（**NIL 计入**）。

由性质 ⑤，这个数与选哪条路径无关，所以 bh(x) 是良定义的。**整棵树的黑高 = 根结点的黑高。**bh(NIL)=0,bh(x)=bh(child)+[child 是黑色]

## 三、判定一棵树是不是红黑树

这是一件完全机械的事，按下面三步走：

**第一步：查性质 ② —— 根是不是黑色？**

**第二步：查性质 ④ —— 有没有"红结点的孩子还是红的"？** 扫一遍所有红结点，看它的两个孩子（含 NIL）是否都是黑的。

**第三步：查性质 ⑤ —— 自底向上算黑高。** 对每个结点，分别算它左、右两棵子树的黑高，**若两边不相等，立刻判否**；相等则把该结点的黑高记为「孩子黑高 + 孩子是否为黑」，继续往上算。

### 例：判定下面这棵树

```
              13(黑)
            /        \
        8(红)          17(红)
        /    \         /     \
    1(黑)  11(黑)   15(黑)   25(黑)
       \                     /    \
      6(红)              22(红)   27(红)
```

**第一步**：根 13 是黑 ✓

**第二步**：红结点有 8、17、6、22、27。 8 的孩子 1、11 都是黑 ✓；17 的孩子 15、25 都是黑 ✓；6、22、27 的孩子都是 NIL（黑）✓。**无红红** ✓

**第三步**：自底向上算黑高（NIL 黑高为 0）：

| 结点 | 颜色 | 左子树黑高 | 右子树黑高 | 是否相等 | 该结点黑高 |
| --- | --- | --- | --- | --- | --- |
| 6 | 红 | NIL → 0+1=1 | NIL → 0+1=1 | ✓ | 1 |
| 1 | 黑 | NIL → 1 | 6 是红 → bh(6)+0=1 | ✓ | 1 |
| 11 | 黑 | 1 | 1 | ✓ | 1 |
| 8 | 红 | 1 是黑 → 1+1=2 | 11 是黑 → 1+1=2 | ✓ | 2 |
| 15 | 黑 | 1 | 1 | ✓ | 1 |
| 22 | 红 | 1 | 1 | ✓ | 1 |
| 27 | 红 | 1 | 1 | ✓ | 1 |
| 25 | 黑 | 22 是红 → 1+0=1 | 27 是红 → 1 | ✓ | 1 |
| 17 | 红 | 15 是黑 → 1+1=2 | 25 是黑 → 1+1=2 | ✓ | 2 |
| **13** | 黑 | 8 是红 → 2+0=2 | 17 是红 → 2+0=2 | ✓ | **2** |

三步全过 → **是红黑树** ✓

**顺带验证"最长 ≤ 2 倍最短"**：最短的根到 NIL 路径是 13→8→11→NIL（经过 3 个内部结点，另外 13→8→1→NIL 与 13→17→15→NIL 也是 3 个），最长的是 13→17→25→22→NIL（经过 4 个内部结点），4≤2×3 ✓

### 常见的三种"不是红黑树"

| 反例 | 违反 |
| --- | --- |
| 根是红色 | 性质 ② |
| 某红结点的孩子仍是红色 | 性质 ④ |
| 左子树黑高 2、右子树黑高 3 | 性质 ⑤ |

**注意性质 ⑤ 不是"左右子树高度相同"**。红黑树完全允许左右子树的**实际高度**相差很多（只要黑结点数相同、红结点分布不同即可）。把它读成"高度平衡"是最常见的误解。

## 四、两条核心结论及其证明

### 结论一：最长路径 ≤ 2 × 最短路径

设某结点的黑高为 bh。

- **最短的路径**：全部由黑结点组成（一个红的都没有），长度为 bh
- **最长的路径**：红黑交替（性质 ④ 禁止红红相邻，所以红结点最多只能占一半，且不能两个连着），黑结点 bh 个、红结点至多 bh 个，总长度至多 2bh最长路径最短路径≤2bhbh=2◼

**这条结论说明红黑树"歪"是有限度的**——虽然不像 AVL 那样左右几乎等高，但两侧的差距永远锁在 2 倍以内。

### 结论二：含 n 个内部结点的红黑树，高度 h≤2log2⁡(n+1)

**引理**：以 x 为根的子树至少含 2bh(x)−1 个内部结点。

**证明（对 x 的高度归纳）**：

- x 是 NIL 时，bh(x)=0，子树含 20−1=0 个内部结点 ✓
- x 是内部结点时，它的两个孩子的黑高至少是 bh(x)−1（孩子若为黑则恰为 bh(x)−1，若为红则仍为 bh(x)）。由归纳假设，每个孩子的子树至少含 2bh(x)−1−1 个内部结点，加上 x 自己：2(2bh(x)−1−1)+1=2bh(x)−1◼

**主证明**：设树高为 h（根到最深 NIL 经过的内部结点数）。由性质 ④，**任一条根到 NIL 的路径上，红结点数不超过总数的一半**，所以黑结点数至少是 h/2，即根的黑高 bh(root)≥h/2。代入引理：n≥2bh(root)−1≥2h/2−1

即 n+1≥2h/2，两边取对数得h≤2log2⁡(n+1)◼

**含义**：红黑树的高度是 O(log⁡n)，因此查找、插入、删除都是 O(log⁡n)——**与 AVL 同量级，只是常数因子大一些**（2 对 1.44）。

## 五、插入

红黑树的插入分两步：**按 BST 规则插入 → 着色并调整**。

- 按[二叉搜索树](./bst.html)的规则找到插入位置，挂上新结点
- 新结点**染为红色**
- 若破坏了红黑性质，则通过**变色**和**旋转**修复c

```
void rbInsert(RBTree *T, int key) {
    RBNode *z = createNode(key);
    z->color = RED;          // 新结点一律染红，理由见下
    bstInsert(T, z);         // 按 BST 规则挂到查找失败的位置
    rbInsertFixup(T, z);     // 修复可能被破坏的性质
}
```

### 为什么新结点必须染红

看两种选择各会破坏什么：

| 染色 | 后果 |
| --- | --- |
| **染黑** | 新结点所在的那条路径黑结点数比其他路径多 1 → **必定**破坏性质 ⑤，而性质 ⑤ 是全局的，修起来要动整棵树 |
| **染红** | 性质 ⑤ 完全不受影响（红结点不计入黑高）；只**可能**破坏性质 ④（当它的双亲也是红色时） |

**判据是"必定破坏 vs 可能破坏、全局 vs 局部"**：染红最坏只违反一条局部性质（不红红），而且修复时可以就地变色 / 旋转；染黑必然违反一条全局性质。**所以染红。**

**一个推论**：如果新结点的双亲是**黑色**，插入后什么都不用做——直接结束。这是最常见的情形。

### 插入后调整：看**叔结点**的颜色

只有当**双亲也是红色**时才需要调整（违反性质 ④）。设当前结点为 z、双亲为 P、祖父为 G、P 的兄弟（即 z 的**叔结点**）为 U。

**为什么参照物是叔结点**：问题是"P 和 z 都是红的"。修复思路是把 P 染黑，但这会让 P 这一侧的黑高 +1，破坏性质 ⑤——除非**同时把 U 也染黑、把 G 染红**（这样 G 以下两侧黑高同时 +1 又同时被 G 的变红抵消）。所以**能不能用纯变色解决，取决于 U 是不是红的**。

以 P 是 G 的**左孩子**为例（右孩子情形完全镜像）：

**情形一：叔结点 U 为红色 —— 纯变色，向上迭代**

- 把 P 和 U 都染**黑**，把 G 染**红**
- 令 z 指向 G，继续向上检查（G 变红后可能与它的双亲又构成红红）

```
        G(黑)                    G(红) ← 新的 z，继续向上检查
       /    \        变色        /    \
    P(红)   U(红)     ──→     P(黑)  U(黑)
    /                          /
  z(红)                      z(红)
```

**为什么这样不破坏性质 ⑤**：G 以下的每条路径，都恰好经过 P 或 U 中的一个。它们各自 +1 个黑，而 G 由黑变红 −1 个黑，**净变化为 0** ✓

**这一情形不做旋转，只是把矛盾上移了两层**，最坏迭代到根（O(log⁡n) 次变色）。

**情形二：叔结点 U 为黑色，且 z 与 P 构成"折线" —— 先旋转成直线**

z 是 P 的**右**孩子而 P 是 G 的**左**孩子（方向拐弯），对 P 做**左旋**，把 z 转上来，就变成了情形三。

```
        G(黑)                     G(黑)
       /    \      对 P 左旋      /    \
    P(红)   U(黑)     ──→      z(红)   U(黑)
       \                       /
       z(红)                 P(红)   ← 交换角色后，P 与 z 成为一条直线
```

**情形三：叔结点 U 为黑色，且 z 与 P 构成"直线" —— 旋转 + 变色，终止**

- 把 P 染**黑**、G 染**红**
- 对 G 做**右旋**（P 是 G 的左孩子时）

```
        G(黑)                    P(黑)
       /    \      对 G 右旋     /    \
    P(红)   U(黑)     ──→     z(红)   G(红)
    /                                    \
  z(红)                                  U(黑)
```

**为什么这样不破坏性质 ⑤**：旋转前，经过 U 的路径黑数比经过 z 的多 1（因为 P 是红的不计）。旋转后 P 变黑升为子树根，G 变红降为它的右孩子——**经过 z 的路径多了一个黑（P），经过 U 的路径少了一个黑（G 变红）又多了一个（P），净持平** ✓ 且 P 是黑的，不会与上层构成红红，**调整终止**。c

```
void rbInsertFixup(RBTree *T, RBNode *z) {
    while (z->parent && z->parent->color == RED) {   // 只有双亲为红才需要修复
        if (z->parent == z->parent->parent->left) {  // 双亲是祖父的左孩子
            RBNode *uncle = z->parent->parent->right;
            if (uncle && uncle->color == RED) {
                // 情形一：叔结点为红 —— 纯变色，问题上移两层
                z->parent->color = BLACK;
                uncle->color = BLACK;
                z->parent->parent->color = RED;
                z = z->parent->parent;
            } else {
                if (z == z->parent->right) {
                    // 情形二：折线 —— 对双亲左旋，转成直线（下面按情形三处理）
                    z = z->parent;
                    leftRotate(T, z);
                }
                // 情形三：直线 —— 双亲染黑、祖父染红，对祖父右旋，终止
                z->parent->color = BLACK;
                z->parent->parent->color = RED;
                rightRotate(T, z->parent->parent);
            }
        } else {
            // 镜像处理：双亲是祖父的右孩子，把上面的左右全部互换
            // 情形二改为对双亲右旋，情形三改为对祖父左旋
        }
    }
    T->root->color = BLACK;    // 兜底：无论中途怎么变，最后把根染黑，保证性质 ②
}
```

**最后那行 `T->root->color = BLACK` 不是可有可无的**：情形一会把祖父染红，若祖父恰好是根，性质 ② 就被破坏了。统一在末尾把根染黑最省事——**根由红变黑会让所有路径的黑高同时 +1，性质 ⑤ 仍然满足。**

**旋转次数**：情形一不旋转；情形二旋转 1 次后必进入情形三；情形三旋转 1 次后终止。所以**插入最多旋转 2 次**，其余开销是 O(log⁡n) 次变色上溯。

## 六、删除

红黑树的删除分两步：先按 BST 规则删除结点，再修复可能被破坏的红黑性质。

### 第一步：BST 删除（与普通 BST 相同）

- 被删结点**无孩子** → 直接删除
- 被删结点**有一个孩子** → 用孩子替代
- 被删结点**有两个孩子** → 找中序后继（或前驱），把后继的值复制过来，转化为删除后继结点（**后继最多只有一个右孩子**）

详见 [BST 的删除](./bst.html)。经过转化，**实际被移除的结点最多只有一个孩子**。

### 第二步：看被实际移除的结点是什么颜色

| 被移除结点的颜色 | 后果 |
| --- | --- |
| **红色** | 红结点不计入黑高、且删掉它不会产生红红（它的孩子都是黑的），**五条性质全部保持，直接结束** |
| **黑色** | 从该位置到叶子的所有路径黑高**减 1**，破坏性质 ⑤，**必须调整** |

调整时引入"**双重黑**"的概念：设 x 是顶替被删黑结点位置的那个结点（可以是真实结点，也可以是 NIL 哨兵）。把缺失的那一重黑色**记账在 x 上**，称 x 携带了"双重黑"。**调整的目标就是把这重多余的黑色消化掉。**

**为什么删除要看兄弟结点、而插入看叔结点**：插入的问题是"我这一侧多了个红"，要找**同层的另一半**（叔）来一起变色；删除的问题是"我这一侧少了个黑"，**只能从兄弟那一侧借**——要么把兄弟的黑借过来，要么让整棵子树一起少一个黑（把矛盾上移）。**参照物由"缺什么、向谁要"决定。**

### 四种情形

以 x 是其双亲 P 的**左孩子**为例（右孩子完全对称）。设 w 为 x 的**兄弟结点**。

**情形 1：兄弟 w 是红色 —— 转化为其余情形**

```
       P(黑)                      W(黑)
      /     \       →            /     \
   x(双黑)  W(红)              P(红)    Wr
           /   \              /   \
         Wl     Wr        x(双黑)  Wl
```

操作：w 染黑、P 染红，对 P **左旋**。

**效果**：旋转后 x 的新兄弟是原来的 Wl，由性质 ④（w 是红的，孩子必黑）可知它一定是**黑色**——于是转化为情形 2 / 3 / 4 继续处理。**这一步不解决问题，只是把"兄弟是红的"这个碍事的情况消掉。**

**情形 2：兄弟 w 是黑色，且 w 的两个孩子都是黑色 —— 把矛盾上移**

```
        P(任意色)                   P(双黑或直接染黑)
       /         \       →         /          \
    x(双黑)      W(黑)          x(普通黑)     W(红)
                /   \                        /   \
             Wl(黑) Wr(黑)                Wl(黑) Wr(黑)
```

操作：w 染**红**，把 x 的双重黑**上移给双亲 P**。

- 若 P 原本是**红色**：直接把 P 染黑，多余的那重黑被吸收，**调整结束**
- 若 P 是**黑色**：P 成为新的双重黑结点，令 x=P 继续向上迭代
- 最坏迭代到根，此时直接去掉那一重黑（整棵树的黑高减 1，五条性质仍然满足）

**为什么把 w 染红是对的**：x 那一侧缺一个黑，w 那一侧就主动也少一个黑，两侧重新齐平；代价是整棵以 P 为根的子树黑高少了 1，这个亏欠交给上层去补——**这正是"上移"的含义**。

**这是四种情形里唯一会迭代的一种。**

**情形 3：兄弟 w 是黑色，w 的近侄（左孩子）红、远侄（右孩子）黑 —— 转化为情形 4**

```
        P                      P
       / \                    / \
      x   W(黑)     →        x   Wl(黑)
         /   \                     \
      Wl(红) Wr(黑)                W(红)
                                     \
                                     Wr(黑)
```

操作：Wl（近侄）染黑、w 染红，对 w 做**右旋**。

**效果**：旋转后 x 的新兄弟是 Wl（黑），它的**远侄**变成了原来的 w（红）——转化为情形 4。

**"近侄 / 远侄"的定义**：以 x 相对于兄弟 w 的方位来说，离 x 近的那个侄子叫近侄、远的叫远侄。x 是左孩子时，w 的左孩子是近侄、右孩子是远侄；x 是右孩子时反过来。**这个方位关系在镜像情形下会左右互换，是最容易搞反的一处。**

**情形 4：兄弟 w 是黑色，w 的远侄（右孩子）红 —— 一步终结**

```
        P(任意色)                    W(取原 P 的颜色)
       /         \       →         /       \
     x(双黑)     W(黑)          P(黑)      Wr(黑)
                /   \           /   \
              Wl    Wr(红)   x(普通黑) Wl
```

操作：w 取 P 原来的颜色、P 染**黑**、Wr（远侄）染**黑**，对 P 做**左旋**。

**为什么能一步终结**：左旋后，x 这一侧的路径多经过了一个黑结点 P，双重黑被消化掉；而 w 这一侧原本经过的 Wr 由红变黑，恰好补上了旋转带来的黑高损失；w 继承 P 的颜色则保证了更上层看到的黑高完全没变。**三处变色一处旋转，各司其职，调整结束。**

### 四种情形的转化关系

```
情形 1 ──→ 情形 2 / 3 / 4      （消掉"兄弟是红的"）
情形 3 ──→ 情形 4              （把近侄红转成远侄红）
情形 4 ──────────→ 结束        （一步终结）
情形 2 ──→ 上移，最多 O log n 次迭代
```

**旋转次数**：情形 2 不旋转（只变色 + 上移）；情形 1、3、4 各旋转 1 次，且路径最长是 **情形 1 → 情形 3 → 情形 4**。所以**删除最多旋转 3 次**。

## 七、红黑树与 AVL 树的对比

| 对比项 | 红黑树 | AVL 树 |
| --- | --- | --- |
| 平衡条件 | 黑高相等（**弱平衡**） | 左右子树高度差 ≤1（**严格平衡**） |
| 最大高度 | 2log2⁡(n+1) | 1.44log2⁡(n+2) |
| 查找效率 | 略低（树可能更高） | 更优 |
| 插入的旋转次数 | ≤2 | ≤2（一次调整，双旋算两次基本旋转） |
| **删除的旋转次数** | **≤3（常数）** | **O(log⁡n)（可能连锁）** |
| 插入 / 删除的变色或高度更新 | O(log⁡n) 次变色上溯 | O(log⁡n) 次高度更新 |
| 每结点额外空间 | 1 bit 颜色 | 一个高度（或 2 bit 平衡因子） |
| 适用场景 | **插入删除频繁**的通用有序容器 | **查找密集**、修改较少 |

**判据一句话**：**查得多用 AVL，改得多用红黑树。** 两者的查找、插入、删除都是 O(log⁡n)，差别在常数因子与"删除是否会连锁旋转"。

**注意"插入旋转次数都是 ≤2"这一行**：AVL 插入至多做**一次平衡调整**，但若是 LR / RL 双旋，含 2 次基本旋转。所以按**基本旋转次数**算，两者相同；真正拉开差距的是**删除**那一行。

### 红黑树与 2-3-4 树的等价

红黑树可以等价地转化为一棵 **2-3-4 树**（即 4 阶 [B 树](./../search/b-tree.html)）：把每个**红结点与它的黑色双亲"合并"成同一个 B 树结点**即可。

- 黑结点 + 0 个红孩子 → B 树的 **2 结点**（1 个关键字）
- 黑结点 + 1 个红孩子 → B 树的 **3 结点**（2 个关键字）
- 黑结点 + 2 个红孩子 → B 树的 **4 结点**（3 个关键字）

**性质 ⑤（黑高相等）在 B 树那边就是"所有叶结点在同一层"**；**性质 ④（不红红）保证了合并后每个 B 树结点最多 3 个关键字**。理解了这个对应，红黑树那些看似古怪的调整规则，本质上就是 B 树的**结点分裂与合并**。

## 复杂度分析

| 操作 | 时间复杂度 | 说明 |
| --- | --- | --- |
| 查找 | O(log⁡n) | 树高 ≤2log2⁡(n+1) |
| 插入 | O(log⁡n) | 查找位置 O(log⁡n) + 调整（最多 2 次旋转 + O(log⁡n) 次变色） |
| 删除 | O(log⁡n) | 查找位置 O(log⁡n) + 调整（最多 3 次旋转 + O(log⁡n) 次变色） |
| 单次旋转 / 变色 | O(1) | 只改常数个指针或颜色位 |
| 中序遍历 | O(n) | 与树形无关 |

**空间复杂度**：O(n)——每个结点多 1 bit 颜色，实现上通常还带一个 `parent` 指针。

**"旋转次数是常数、变色次数是 O(log⁡n)"这个区分很重要**：旋转要修改多个指针、代价高；变色只改 1 bit、代价极低。红黑树的设计恰恰是**把昂贵的操作压成常数、把便宜的操作留给 O(log⁡n)**。

## 易混淆知识点

| 对比项 | 一方 | 另一方 | 判别依据 |
| --- | --- | --- | --- |
| 性质 ③ 里的"叶结点" | 指**外部的 NIL 空结点** | 不是"没有孩子的内部结点" | 画树时必须把 NIL 画出来，否则黑高必数错 |
| 性质 ⑤ 说的"相同" | **黑色结点数**相同 | 不是"高度相同"、也不是"结点总数相同" | 红黑树允许左右子树实际高度相差近一倍 |
| 插入调整看谁 | **叔结点**的颜色 | 删除看**兄弟结点**的颜色 | 插入是"多了个红，找同层另一半一起变色"；删除是"少了个黑，只能从兄弟那侧借" |
| 新结点染红还是染黑 | **必须染红** | 染黑**必定**破坏性质 ⑤ | 染红最多破坏性质 ④（局部），染黑必破坏性质 ⑤（全局） |
| 插入后双亲是黑色 | **什么都不用做** | — | 唯一可能被破坏的性质 ④ 没被触发 |
| 删除后要不要调整 | 被实际移除的是**红**结点 → 不用调整 | 是**黑**结点 → 必须调整 | 红结点不计入黑高 |
| 哪种情形会迭代 | **插入情形一**（叔红）与**删除情形 2**（兄弟黑 + 双侄黑） | 其余情形都在常数步内终止 | 它们是"把矛盾上移"而非"就地解决" |
| 旋转次数上界 | 插入 ≤2、删除 ≤3 | AVL 删除是 O(log⁡n) | 这是红黑树相对 AVL 的核心优势 |
| 近侄 vs 远侄 | 离 x 近的那个侄子 | 镜像情形下左右互换 | x 是左孩子时，w 的左孩子是近侄 |
| 红黑树 vs AVL 该选谁 | 改得多选红黑树 | 查得多选 AVL | 唯一实质差别是删除会不会连锁旋转 |
| 最长路径与最短路径 | 最长 ≤ **2 倍**最短 | 不是"相等"也不是"相差 1" | 最短全黑长 bh、最长红黑交替长 ≤2bh |
| 树高上界 | 2log2⁡(n+1) | AVL 是 1.44log2⁡(n+2) | 由"黑结点至少占一半"推出 |

## 本节小结

学完本篇，应该能够：

- **默写红黑树的五条性质**，并准确说出性质 ③ 里的"叶结点"指 NIL 空结点、性质 ⑤ 说的是黑结点**个数**而非高度
- **算出任意结点的黑高**（不含自身、NIL 计入），并用它**机械地判定一棵着色二叉树是不是红黑树**：查根黑 → 查无红红 → 自底向上比左右子树黑高
- **证明"最长路径不超过最短路径的两倍"**：最短全黑长 bh，最长红黑交替长 ≤2bh
- **证明树高 h≤2log2⁡(n+1)**：先证"黑高为 bh 的子树至少含 2bh−1 个内部结点"，再用"黑结点至少占路径一半"得到 bh≥h/2
- **解释新结点为什么必须染红**：染黑必定破坏全局的性质 ⑤，染红最多破坏局部的性质 ④
- **说出插入调整的三种情形**（叔红纯变色上移、叔黑折线先转直、叔黑直线转 + 变色终止）及"最多旋转 2 次"
- **说出删除调整的四种情形**（兄弟红先转化、兄弟黑双侄黑上移、兄弟黑近侄红转情形 4、兄弟黑远侄红一步终结）及"最多旋转 3 次"，并指出情形 2 是唯一会迭代的
- **解释插入看叔结点、删除看兄弟结点的理由**：一个是"多了红要找人一起变色"，一个是"少了黑只能向兄弟借"
- **在红黑树与 AVL 之间做选择**：查得多选 AVL、改得多选红黑树；实质差别只在删除会不会连锁旋转

**两条最关键的结论**：红黑树的全部平衡保证来自"**不红红**"（性质 ④）与"**黑高相等**"（性质 ⑤）这两条的合力，由它们直接推出"最长 ≤ 2 倍最短"与 h≤2log2⁡(n+1)；**红黑树的旋转次数有常数上界（插入 ≤2、删除 ≤3）**，这是它相对 AVL 的唯一实质优势。
