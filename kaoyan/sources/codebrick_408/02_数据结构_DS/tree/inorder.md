## 一、访问顺序

中序遍历的访问顺序：**左子树 → 根结点 → 右子树**（LNR）。

以下面的二叉树为例：

```
        A
       / \
      B   C
     / \   \
    D   E   F
```

中序遍历序列为：**D → B → E → A → C → F**

递归过程展开：

- 先递归遍历 A 的左子树（以 B 为根）
- 再递归遍历 B 的左子树（以 D 为根）
- D 无左子树，访问 D；D 无右子树，返回
- 访问 B
- 递归遍历 B 的右子树，访问 E
- 左子树遍历完毕，访问 A（根结点）
- 递归遍历 A 的右子树（以 C 为根）
- C 无左子树，访问 C
- 递归遍历 C 的右子树，访问 F

### 中序访问时机的直观理解

每个结点在遍历的固定游走路线上会被经过三次（详见 [前序遍历](./preorder.html) 里的"三次经过"图）。**中序取的是第二次**——左子树已经处理完、右子树还没开始的那一刻。

由此得到一个**几何直观**：把二叉树的所有结点垂直投影到一条水平线上（保持左子树在左、右子树在右），**从左到右读出来的顺序就是中序序列**。

```
        A
       / \
      B   C
     / \   \
    D   E   F

投影到水平线：   D   B   E   A   C   F
```

这个直观解释了两件事：为什么中序能"把树摊平成有序序列"，以及为什么中序是[线索二叉树](./threaded-binary-tree.html)的首选次序——中序序列在图上就是从左到右的自然次序，前驱后继的几何位置一目了然。

## 二、中序与二叉排序树

**二叉排序树（BST）的定义**是：左子树所有结点的值 < 根 < 右子树所有结点的值，且左右子树也是 BST。把这个定义和中序的访问次序（先左、再根、后右）放在一起，立刻得到：

**对 BST 做中序遍历，得到的一定是递增有序序列。**

**证明（对结点数归纳）**：空树与单结点显然成立。设左右子树的中序序列各自递增（归纳假设），则整棵树的中序序列是「左子树序列，根，右子树序列」的拼接。由 BST 的定义，左子树全部 < 根 < 右子树全部，因此三段拼起来仍然递增。

**逆命题也常用**：如果一棵二叉树的中序序列不是递增的，它就一定不是 BST。**这是判定 BST 最可靠的方法**——比"逐个结点检查它比左孩子大、比右孩子小"可靠得多，后者是错的：

```
      5
     / \
    3   8
       / \
      2   9      ← 8 > 5、2 < 8、9 > 8，逐点检查全过
```

但中序序列是 **3 5 2 8 9**（5>2，不递增），所以它不是 BST——结点 2 虽然是 8 的左孩子（局部合法），却位于根 5 的右子树里（全局非法）。**局部检查会漏掉这种跨层违规，中序检查不会。**

由这条性质派生出的常用结论：

| 结论 | 依据 |
| --- | --- |
| BST 中序序列的第 k 个元素就是第 k 小的关键字 | 中序序列即升序序列 |
| BST 中某结点的**中序后继**就是它在升序中的下一个值 | 同上；具体位置见 [BST](./bst.html) 与[线索二叉树](./threaded-binary-tree.html) |
| 同一关键字集合、不同插入序建出的 BST 形态不同，但**中序序列完全相同** | 中序序列 = 该集合的升序排列，与形态无关 |
| BST 的前序序列可单独确定这棵 BST | 把前序排序即得中序，于是等价于"前序 + 中序" |

## 三、递归实现
c

```
typedef struct BiTNode {
    int data;
    struct BiTNode *lchild, *rchild;
} BiTNode, *BiTree;

void InOrder(BiTree T) {
    if (T == NULL) return;   // 递归出口
    InOrder(T->lchild);      // 先把左子树整个处理完
    visit(T);                // 访问根 —— visit 夹在两次递归之间，这就是"中序"
    InOrder(T->rchild);      // 再处理右子树
}
```

**复杂度**：时间 O(n)（每个结点恰访问一次，每次常数工作）；空间 O(h)，h 为树高——占用的是系统栈，任一时刻栈中的栈帧恰好是"从根到当前结点的那条路径"。最坏（单支树）O(n)，完全二叉树时 O(log⁡n)。

递归写法简洁，但栈帧由系统分配，深度不可控；树退化时可能栈溢出。下面的非递归实现把这个栈显式地拿到手里。

## 四、非递归实现：三种遍历共用的统一模板

### 从递归里"抠出"栈

递归做了什么？沿着左链一路下潜，每下潜一层就把当前结点压进系统栈（等会儿要回来访问它、还要处理它的右子树）；潜到空指针就回退一层，访问那个结点，然后转去它的右子树。

把系统栈换成自己的栈，就是下面这段代码：c

```
void InOrder_NonRecursive(BiTree T) {
    Stack S;
    InitStack(S);
    BiTree p = T;
    while (p != NULL || !IsEmpty(S)) {   // 两个条件缺一不可，见下文
        if (p != NULL) {
            Push(S, p);        // 当前结点入栈：它的右子树还没处理，暂时不能丢
            p = p->lchild;     // 一路向左，直到左子树为空
        } else {
            Pop(S, p);         // 左边走到头了，回退一层
            visit(p);          // 此刻它的左子树已全部访问完 —— 中序的访问时机
            p = p->rchild;     // 转向右子树，重复"一路向左"
        }
    }
}
```

### 这段代码在维护什么不变量

**循环不变量**：栈中自底向上存放的，恰好是**当前正在处理的子树的所有祖先中"左子树已处理完、根未访问、右子树未处理"的那些结点**——换句话说，是一条从根出发、还欠着"访问自己 + 处理右子树"的路径。

三个动作对应三个阶段：

| 代码动作 | 含义 | 为什么此时该做 |
| --- | --- | --- |
| `Push(S, p); p = p->lchild;` | 记账后下潜 | 中序要求左子树先于根，所以见到结点先欠着，往左走 |
| `Pop(S, p); visit(p);` | 还账：访问 | 能弹出说明它的左子树已经全部走完，轮到它了 |
| `p = p->rchild;` | 转右 | 根访问完，最后一步是右子树，且此后再不需要这个结点，所以它已经出栈 |

### 循环条件为什么是"`p != NULL` 或栈非空"

这两个条件各自管一种"还有活没干完"的情形，缺一不可：

- **只写 `!IsEmpty(S)`**：初始时栈是空的（根还没入栈），循环根本不会开始；而且每次转向右子树后（`p = p->rchild`）若栈恰好空了，右子树就会被整个丢掉
- **只写 `p != NULL`**：`p` 走到最左端变成 `NULL` 时循环就结束了，栈里那一串祖先永远不会被访问

**判据**：`p != NULL` 表示"还有一棵子树没下潜"，`!IsEmpty(S)` 表示"还有祖先没还账"。两者只要有一个成立，遍历就没结束。

### 逐步执行（以上例的树为例）

| 步骤 | 操作 | 栈内容（底→顶） | 访问结点 |
| --- | --- | --- | --- |
| 1 | A 入栈，向左 | A | — |
| 2 | B 入栈，向左 | A, B | — |
| 3 | D 入栈，向左 | A, B, D | — |
| 4 | p 空，弹出 D 并访问 | A, B | **D** |
| 5 | 转向 D 的右子树（空），弹出 B 并访问 | A | **B** |
| 6 | 转向 B 的右子树，E 入栈，向左 | A, E | — |
| 7 | p 空，弹出 E 并访问 | A | **E** |
| 8 | 转向 E 的右子树（空），弹出 A 并访问 | （空） | **A** |
| 9 | 转向 A 的右子树，C 入栈，向左 | C | — |
| 10 | p 空，弹出 C 并访问 | （空） | **C** |
| 11 | 转向 C 的右子树，F 入栈，向左 | F | — |
| 12 | p 空，弹出 F 并访问 | （空） | **F** |

最终访问顺序：**D → B → E → A → C → F**，与递归结果一致。

**栈的最大深度**：观察上表，栈里存的始终是"当前结点到根的路径"，所以最大深度恰为树高 h，空间 O(h)，与递归实现相同。

### 用这个模板派生前序和后序

**前序**：只需把 `visit` 从"出栈时"提前到"入栈前"——前序要求根在左右子树之前，而入栈那一刻正是第一次见到这个结点：c

```
if (p != NULL) {
    visit(p);          // ← 唯一改动：提前到这里
    Push(S, p);
    p = p->lchild;
} else {
    Pop(S, p);
    p = p->rchild;
}
```

**后序改不动，必须加东西。** 原因是：后序要求"左、右都处理完才访问根"，而模板里结点**只被弹出一次**。弹出的那一刻，我们无法区分它是

- "刚从左子树回来，右子树还没去"，还是
- "右子树也回来了，可以访问了"

这两种状态在栈上长得一模一样。解决办法只有两条：**记住上一个被访问的结点**（标记法，用 `r` 指针判断右子树是否刚被访问完），或者**换个角度绕开这个问题**（双栈法，先做 NRL 再整体逆序）。两种做法的完整推导见 [后序遍历](./postorder.html)。

**这正是"后序非递归最难"的准确原因**——不是代码长，而是模板里缺少一个状态位。理解这一层，后序那两种写法就都是自然产物，不需要死记。

### 三种遍历非递归的统一对照

| 遍历 | 访问时机 | 需不需要额外状态 | 空间 |
| --- | --- | --- | --- |
| 前序 | 入栈前（第一次见到） | 不需要 | O(h) |
| 中序 | 出栈时（左子树已完） | 不需要 | O(h) |
| 后序 | 出栈时且右子树已完 | **需要**：`r` 指针（标记法）或第二个栈（双栈法） | O(h) / O(n) |

## 五、中序遍历的典型应用

### 1. 判定一棵二叉树是不是 BST

做一次中序遍历，检查序列是否严格递增。实现上不必真的存下整个序列，只需记住上一个访问的值：c

```
int pre = INT_MIN;        // 上一个中序访问到的关键字
int ok = 1;

void CheckBST(BiTree T) {
    if (T == NULL || !ok) return;
    CheckBST(T->lchild);
    if (T->data <= pre) ok = 0;   // 中序序列必须严格递增
    pre = T->data;                // 更新"上一个"
    CheckBST(T->rchild);
}
```

边界注意：`pre` 的初值不能用 0（关键字可能是负数），也不能只在根处初始化一次却在多次调用间残留。若关键字可以取到类型最小值，改用"是否已访问过第一个结点"的布尔标志更稳妥。

### 2. 求 BST 中第 k 小的关键字

中序遍历到第 k 个访问的结点就是答案，遍历中计数即可，一旦计满立即返回，平均只需走 O(h+k) 步。

### 3. 中序线索化

线索化的实质是"在遍历过程中把空指针改成指向前驱/后继的线索"。中序之所以是首选，是因为**中序线索树上找前驱和后继都简单**（前驱是左子树最右下、后继是右子树最左下），而前序线索找前驱、后序线索找后继都需要双亲信息。完整内容见 [线索二叉树](./threaded-binary-tree.html)。

### 4. 输出中缀表达式

对表达式树做中序遍历得到中缀式，但**会丢括号**：(a+b)×c 与 a+b×c 的表达式树不同，中序序列却都是 `a+b*c`。要恢复必须在遍历时按子树优先级补括号。**这正是中缀式需要括号、而前缀式与后缀式不需要的根本原因**——见 [后序遍历](./postorder.html) 中的后缀表达式。

## 复杂度分析

| 实现方式 | 时间复杂度 | 空间复杂度 | 空间是谁占的 |
| --- | --- | --- | --- |
| 递归 | O(n) | O(h)，最坏 O(n) | 系统栈；栈中恰为根到当前结点的路径 |
| 非递归（统一模板） | O(n) | O(h)，最坏 O(n) | 显式栈；栈中同样是当前路径 |
| 中序线索树上遍历 | O(n) | O(1) | 不用栈，沿线索走，见[线索二叉树](./threaded-binary-tree.html) |

**时间为什么恒是 O(n)**：每个结点恰好入栈一次、出栈一次、访问一次。虽然"一路向左"这个内层动作看上去像嵌套循环，但所有内层步数加起来正好等于入栈总次数 n——用**摊还**的视角看，总时间是 Θ(n)，与树的形态无关。

**空间为什么是 O(h) 而不是 O(n)**：栈里装的是一条路径，不是一层结点。这一点与[前序的"弹栈压右左"写法](./preorder.html)不同，后者栈里可能装下整整一层。

## 易混淆知识点

| 对比项 | 一方 | 另一方 | 判别依据 |
| --- | --- | --- | --- |
| 中序非递归 vs 前序非递归（专用写法） | 先一路入栈到最左，再弹出访问 | 弹出栈顶就访问，然后压右、压左 | 访问发生在"下潜途中"还是"回退时" |
| 统一模板中前序 vs 中序 | `visit` 在 `Push` 之前 | `visit` 在 `Pop` 之后 | 只有这一行位置不同 |
| 后序为什么不能直接套模板 | 前中序结点弹一次就够 | 后序弹出时无法区分"左回来"还是"右回来" | 模板缺一个状态位，需 `r` 指针或双栈 |
| 判定 BST：中序法 vs 逐点比较法 | 中序序列严格递增即为 BST，**正确** | 只比较结点与其左右孩子，**错误** | 逐点法漏掉跨层违规（如右子树里出现比根小的值） |
| BST 的中序序列 vs 形态 | 中序序列由关键字集合唯一决定 | 形态由插入次序决定 | 不同插入序 → 不同形态 → 相同中序 |
| 循环条件 `p != NULL` vs 栈非空 | 表示"还有子树没下潜" | 表示"还有祖先没还账" | 必须用"或"连接；去掉任一个都会漏结点 |
| 中缀式 vs 前缀/后缀式 | 中序输出会丢括号 | 前序/后序输出无歧义 | 中缀依赖优先级与括号，前后缀靠位置就能定序 |
| 中序线索 vs 前序/后序线索 | 找前驱、后继都简单 | 前序难找前驱、后序难找后继 | 根在遍历序中的位置决定回溯方向，见[线索二叉树](./threaded-binary-tree.html) |

## 本节小结

学完本篇，应该能够：

- **手工写出任意二叉树的中序序列**，并用"结点垂直投影到水平线、从左往右读"这个直观快速校验
- **证明 BST 的中序序列递增**，并用它判定一棵树是不是 BST；说清"逐点比较左右孩子"为什么是错的
- **默写非递归中序的统一模板**，说清循环不变量（栈中是当前结点的未还账祖先路径）和为什么循环条件必须是"`p` 非空**或**栈非空"
- **由模板派生出前序非递归**（把 `visit` 提到入栈前），并解释后序为什么派生不出来——弹栈时缺一个"右子树是否已处理"的状态位
- **说清空间复杂度 O(h) 的来历**：栈里装的是一条从根到当前结点的路径，不是一层结点
- **说出中序的典型用途**：判定 BST、求第 k 小、中序线索化、输出中缀式（并知道它会丢括号）

**两条最关键的结论**：BST 的中序序列递增，这条性质既是判定依据也是"求第 k 小"的基础；非递归三种遍历共用同一套栈框架，**前序与中序只差 `visit` 的位置，后序必须额外记录"上次访问的结点"**。

- 遍历的复杂度分析（时间 O(n)；辅助空间为栈的最大容量即树的深度，最坏 O(n)）：**印刷 p125**
