# 双端队列

## 知识框架

## 核心思想

双端队列（Double Ended Queue, Deque）是**前端和后端都允许插入和删除**的线性表。

- **栈和队列都是它的特例**：只在一端插入删除就退化为栈；一端只插、另一端只删就退化为队列；
- **受限双端队列**：对某一端的操作加以限制，得到"输入受限"与"输出受限"两种。

408 关心的**不是 deque 本身怎么实现**（实现就是循环队列的两端版）， 而是**"某个序列能否由某种受限双端队列产生"**——这是一道纯粹的模拟与推理题。

双端队列的逻辑结构：text

```
  前端 front                      后端 rear
    ↕                               ↕
 ┌──────┬──────┬──────┬──────┬──────┐
 │  a₁  │  a₂  │  a₃  │  a₄  │  a₅  │
 └──────┴──────┴──────┴──────┴──────┘
  可插入/删除                    可插入/删除
```

图源：殷人昆《数据结构——用面向对象方法与 C++ 描述》（第 2 版）图3.27 双端队列的基本操作，p127

图里六个操作两两成对：`EnQueueHead` / `EnQueueTail` 是两端插入， `DeQueueHead` / `DeQueueTail` 是两端删除，`getHead` / `getTail` 是两端读取（不改变队列）。 **把其中若干个操作"禁用"，就得到本篇要讨论的各种受限形式。**

### 三种类型的操作权限

| 类型 | 前端 front | 后端 rear |
| --- | --- | --- |
| 双端队列 | 可插入、可删除 | 可插入、可删除 |
| **输入受限**双端队列 | **只能删除** | 可插入、可删除 |
| **输出受限**双端队列 | 可插入、可删除 | **只能插入** |

**读法**：受限的是**动作**，不是端。

- **输入受限** = "输入（插入）只能在一端进行"，于是**插入只能在 rear**，**删除两端都行**；
- **输出受限** = "输出（删除）只能在一端进行"，于是**删除只能在 front**，**插入两端都行**。

**自检**：把上表最后一格读成"后端只能删除"就说明理解反了——那样删除就变成两端都可以， 与"输出受限"矛盾。**受限的那种动作在表里只应出现一次。**

## 输出序列判定：这一节是本篇的全部考法

题型固定为：**输入序列为 1,2,3,4（依次到达），问某个输出序列能否由某种受限双端队列产生。** 与《[栈和队列的基本概念](./concepts.html)》里的出栈序列判定同源，方法仍是**模拟**， 但每种受限形式有自己的可用动作集。

### 输入受限：一条能一眼判定的规则

**只能从 rear 插入**，元素按 1,2,3,… 的顺序进入，所以：

**队列内的元素永远按编号递增排列**——front 端是队内最小的，rear 端是队内最大的； 还没入队的元素，编号一定大于队内所有元素。

于是每一步能输出的**只有队内的最小值或最大值**（必要时先把后面的元素插进来，把最大值抬高）。 这条规则把判定变成了一眼可查的事。

**判定示例：4 1 3 2 —— 可以产生**

| 步 | 动作 | 队列（front→rear） | 输出 |
| --- | --- | --- | --- |
| 1 | 1、2、3、4 依次从 rear 入队 | `1 2 3 4` | — |
| 2 | 从 rear 删除 | `1 2 3` | 4 |
| 3 | 从 front 删除 | `2 3` | 1 |
| 4 | 从 rear 删除 | `2` | 3 |
| 5 | 从任一端删除 | 空 | 2 |

输出 4 1 3 2 ✓。**注意这个序列栈是产生不了的**（下面会用到）。

**判定示例：4 2 1 3 —— 不能产生**

| 步 | 动作 | 队列（front→rear） | 输出 |
| --- | --- | --- | --- |
| 1 | 1、2、3、4 入队（要输出 4 必须先让它进来） | `1 2 3 4` | — |
| 2 | 从 rear 删除 | `1 2 3` | 4 |
| 3 | 需要输出 2，但队内最小是 1、最大是 3 | — | **卡住** |

2 夹在中间，两端都够不着，**判定失败**。

### 输出受限：老老实实模拟

**两端都能插入、只能从 front 删除**。因为可以从前端"插队"，队内元素不再保证递增， 没有上面那样的简洁规则，只能模拟。**技巧是倒着想：要先输出谁，就把谁安排到 front。**

**判定示例：3 1 2 4 —— 可以产生**

| 步 | 动作 | 队列（front→rear） | 输出 |
| --- | --- | --- | --- |
| 1 | 1 从 rear 入 | `1` | — |
| 2 | 2 从 rear 入 | `1 2` | — |
| 3 | 3 从 **front** 入（插队） | `3 1 2` | — |
| 4 | 从 front 删 3 次 | 空 | 3, 1, 2 |
| 5 | 4 入队后删除 | 空 | 4 |

输出 3 1 2 4 ✓。**这个序列栈也产生不了**（它含"大、小、中"模式 3,1,2）。

**判定示例：4 2 1 3 —— 可以产生**（对照上面输入受限的失败）

| 步 | 动作 | 队列（front→rear） | 输出 |
| --- | --- | --- | --- |
| 1 | 1 从 rear 入 | `1` | — |
| 2 | 2 从 **front** 入 | `2 1` | — |
| 3 | 3 从 rear 入 | `2 1 3` | — |
| 4 | 4 从 **front** 入 | `4 2 1 3` | — |
| 5 | 从 front 连删 4 次 | 空 | 4, 2, 1, 3 |

**判定示例：4 1 3 2 —— 不能产生**（对照上面输入受限的成功）

要先输出 4，说明 4 必须已经入队并位于 front，此时 1、2、3 也都已入队， 队内必须恰好是 `4 1 3 2`。倒着剥：4 是最后插入的，在 front 端，合法； 剥掉后剩 `1 3 2`，其中**最后插入的是 3**，但它位于**中间**—— 插入只能在两端，**不可能把 3 放到中间**，矛盾。**判定失败**。

### 两个集合的关系

把"输入 1..n 时能产生的输出序列集合"分别记作 S栈、S输入受限、 S输出受限、Sdeque。

**1）栈的集合真包含于两种受限 deque 的集合。**

- 包含：输入受限 deque 的 **rear 端可插可删**，只用 rear 端就是一个栈； 输出受限 deque 的 **front 端可插可删**，只用 front 端也是一个栈。 所以栈能做的，两者都能做。
- 真包含（严格更大）：4 1 3 2 输入受限能产生、栈不能（栈弹出 4 之后栈顶是 3，取不到 1）； 3 1 2 4 输出受限能产生、栈不能（含禁用模式"大、小、中"）。

**2）输入受限与输出受限互不包含。**

| 序列 | 栈 | 输入受限 | 输出受限 |
| --- | --- | --- | --- |
| 4 1 3 2 | ✗ | **✓** | ✗ |
| 4 2 1 3 | ✗ | ✗ | **✓** |
| 3 1 2 4 | ✗ | ✓ | ✓ |

前两行说明：**两个集合各自有对方没有的元素**，谁也不包含谁。 所以"输入受限比输出受限强"或反过来的说法都是错的。

**3）队列的集合最小**：只有恒等序列 12⋯n 一种，是上述所有集合的子集。

综上：S队列⊊S栈⊊S输入受限, S输出受限⊊Sdeque

（中间两项之间无包含关系。）

### 再练四个序列（输入 1234）

| 序列 | 栈 | 输入受限 | 输出受限 | 说明 |
| --- | --- | --- | --- | --- |
| 1234 | ✓ | ✓ | ✓ | 每个元素进来就出去；这也是**队列**唯一能产生的序列 |
| 4321 | ✓ | ✓ | ✓ | 全部入队后从一端全部取出，三者都做得到 |
| 3241 | ✓ | ✓ | ✓ | 栈能做的，两种受限 deque 一定也能做 |
| 4213 | ✗ | ✗ | ✓ | 输入受限在输出 4 之后卡在"2 在中间"；输出受限可以靠前端插队排出 `4 2 1 3` |

**第三行的验证**（3241 用栈）：压 1、2、3 → 弹 3 → 弹 2 → 压 4 → 弹 4 → 弹 1 ✓。 既然栈能做，按"栈是两种受限 deque 的特例"，两种受限 deque 自动也能做，**不必再逐个模拟**—— 这条推理能在考场上省掉一半工作量。

**第四行的输入受限验证**：要输出 4 必须先把 1、2、3、4 全部从 rear 入队， 队内为 `1 2 3 4`；删 rear 得 4，队内 `1 2 3`；下一个要 2，但队内最小是 1、最大是 3， **2 在中间，两端都够不着** ✗。

**考场做法**：题目问"下列哪个序列不能由输入受限双端队列产生"， 先用**输入受限的递增规则**扫一遍，找那个"要输出的元素既不是队内最小也不是队内最大"的； 问输出受限时，用**倒着剥端点**的办法：把目标序列从后往前看， 检查每一步"最后插入的那个元素是否位于当时的某一端"。

## 实现代码

两种受限 deque 都用**循环数组**实现，指针移动沿用《[循环队列](./circular-queue.html)》的取模口径： `front` 指向队头元素，`rear` 指向队尾元素的**下一个位置**， 判空 `front == rear`，判满 `(rear + 1) % MaxSize == front`（牺牲一个单元）。

### 输入受限双端队列

只允许从 rear 插入，两端都可删除。c

```
#define MaxSize 50
typedef struct {
    int data[MaxSize];
    int front, rear;   // front 指向队头元素，rear 指向队尾元素的下一个位置
} InputRestrictedDeque;

void InitDeque(InputRestrictedDeque *dq) { dq->front = dq->rear = 0; }

// 唯一的插入方式：从 rear 端插入
bool InsertRear(InputRestrictedDeque *dq, int x) {
    if ((dq->rear + 1) % MaxSize == dq->front) return false;  // 队满
    dq->data[dq->rear] = x;                    // rear 指的是空位，先写入
    dq->rear = (dq->rear + 1) % MaxSize;       // 再前进
    return true;
}

// 从 front 端删除
bool DeleteFront(InputRestrictedDeque *dq, int *x) {
    if (dq->front == dq->rear) return false;   // 队空
    *x = dq->data[dq->front];
    dq->front = (dq->front + 1) % MaxSize;
    return true;
}

// 从 rear 端删除：rear 要先后退一格才指到有效元素
bool DeleteRear(InputRestrictedDeque *dq, int *x) {
    if (dq->front == dq->rear) return false;   // 队空
    dq->rear = (dq->rear - 1 + MaxSize) % MaxSize;  // 先退，+MaxSize 防负数
    *x = dq->data[dq->rear];                   // 再取值
    return true;
}
```

`DeleteRear` 里的 `(dq->rear - 1 + MaxSize) % MaxSize` **必须加 `MaxSize`**： `rear` 为 0 时 `(0-1) % MaxSize` 在 C 中得到 −1（C 的取模对负被除数返回负余数）， 直接当下标就越界了。这一点在《[循环队列](./circular-queue.html)》里已经推过。

另外注意 `DeleteRear` 是**先退指针再取值**，而 `InsertRear` 是**先写值再前进**—— 因为 `rear` 指的是"下一个空位"，取值前必须先退到有效元素上。

### 输出受限双端队列

两端都能插入，只能从 front 删除。c

```
typedef struct {
    int data[MaxSize];
    int front, rear;
} OutputRestrictedDeque;

// 从 rear 端插入
bool InsertRear2(OutputRestrictedDeque *dq, int x) {
    if ((dq->rear + 1) % MaxSize == dq->front) return false;
    dq->data[dq->rear] = x;
    dq->rear = (dq->rear + 1) % MaxSize;
    return true;
}

// 从 front 端插入：front 指向队头元素，要先退一格腾出位置
bool InsertFront(OutputRestrictedDeque *dq, int x) {
    if ((dq->rear + 1) % MaxSize == dq->front) return false;
    dq->front = (dq->front - 1 + MaxSize) % MaxSize;  // 先退，再写
    dq->data[dq->front] = x;
    return true;
}

// 唯一的删除方式：从 front 端删除
bool DeleteFront2(OutputRestrictedDeque *dq, int *x) {
    if (dq->front == dq->rear) return false;
    *x = dq->data[dq->front];
    dq->front = (dq->front + 1) % MaxSize;
    return true;
}
```

**两端的"移动方向"是镜像的**：`front` 端插入让 `front` **减小**、删除让它**增大**； `rear` 端插入让 `rear` **增大**、删除让它**减小**。 四个操作里，**指向有效元素的那一端（`front`）插入前先退、取值前不退； 指向空位的那一端（`rear`）插入时不退、取值前先退**——判据仍然是那条老规矩： **指针指着有效元素就"先腾位再写"，指着空位就"先写再移"。**

## 复杂度分析

| 操作 | 时间复杂度 | 来历 |
| --- | --- | --- |
| 前端插入 / 删除 | O(1) | 一次判满或判空 + 一次取模 + 一次读写内存 |
| 后端插入 / 删除 | O(1) | 同上 |
| 判空 / 判满 | O(1) | 一到两次整数比较 |

**空间复杂度**：数组固定占 O(MaxSize)，与实际元素个数无关； 单次操作的辅助空间 O(1)。采用"牺牲一个单元"的判满方案时，可用容量为 `MaxSize - 1`。

## 易混淆知识点

| 对比项 | 情况 A | 情况 B | 判别依据 |
| --- | --- | --- | --- |
| 输入受限 vs 输出受限 | 输入受限：**插入**只在 rear，删除两端可 | 输出受限：**删除**只在 front，插入两端可 | 受限的是"输入（插入）"还是"输出（删除）"这个**动作**；受限的动作在权限表里只出现一次 |
| 两个集合的强弱 | 各自有对方产生不了的序列 | — | 4132 只有输入受限能产生，4213 只有输出受限能产生 |
| 与栈的关系 | 栈的合法序列，两种受限 deque **一定**也能产生 | 反之不成立 | 只用"可插可删"的那一端就退化成栈 |
| 判定方法 | 输入受限：队内递增，只能出最小或最大 | 输出受限：无简洁规则，模拟或倒着剥端点 | 插入是否只在一端决定了队内是否保持有序 |
| `front` 端插入 vs `rear` 端插入 | `front` 端：先 `front--`（取模），再写 | `rear` 端：先写，再 `rear++`（取模） | `front` 指有效元素、`rear` 指空位 |
| `rear` 端删除 | 先 `rear--`（取模），再取值 | `front` 端删除：先取值，再 `front++` | 同上 |
| 取模是否要 `+MaxSize` | 指针**减小**时必须加 | 指针**增大**时不必 | C 的 `%` 对负被除数返回负值 |
| 双端队列 vs 循环队列 | 双端队列：两端都动 | 循环队列：`rear` 只增、`front` 只增 | 是否存在指针后退的操作 |

## 本节小结

学完本篇，你应该能够：

- 写出双端队列三种形式的操作权限表，并**用"受限的是动作"这条读法自检**， 不再把"输出受限"的后端写成"只能删除"；
- 说明栈和队列分别是双端队列在什么限制下的特例；
- 用**输入受限的递增规则**（队内 front 最小、rear 最大，每次只能出最小或最大） 快速判定序列可否产生，并在失败时指出"卡在哪个元素、它为什么两端都够不着"；
- 用**模拟 / 倒着剥端点**的方法判定输出受限能否产生某序列；
- 记住并能复现三个判别用的具体序列：4132（只有输入受限能）、 4213（只有输出受限能）、3124（两种受限都能、栈不能）；
- 写出两种受限 deque 的循环数组实现，四个端点操作的指针移动方向与取模写法都正确。

三个最关键的结论：

- **栈的合法序列集合真包含于两种受限双端队列各自的集合**，而**两种受限形式互不包含**；
- **输入受限的队内元素始终递增**，这条性质把判定变成一眼可查；输出受限没有这条捷径；
- **指针指有效元素就"先腾位"，指空位就"先写入"**——这条规则贯穿顺序栈、循环队列和本篇。
