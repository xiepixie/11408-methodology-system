## 存储结构定义
c

```
#define MaxSize 50          // 栈的最大容量，编译期确定
typedef struct {
    int data[MaxSize];      // 存放栈中元素，静态分配
    int top;                // 栈顶指针（这里是数组下标，不是 C 指针）
} SqStack;
```

三点说明：

- `top` 在 408 的代码里通常是 **`int` 型下标**，不是真正的指针。教材里"栈顶指针"是一个 逻辑称呼，落到 C 上就是"数组下标"。
- `MaxSize` 是**编译期常量**，数组随结构体一起分配。这决定了顺序栈**一定存在栈满**这件事—— 与《[链栈](./linked-stack.html)》最本质的区别就在这一行。
- 严蔚敏教材用的是**动态分配 + 真指针**的写法：结构体里放 `SElemType *base, *top;` 与 `int stacksize;`，初始化时 `malloc` 出 `stacksize` 个单元。此时"元素个数"是 `top - base`， 栈满条件写成 `top - base == stacksize`。两种写法的**逻辑完全一致**，只是把"下标"换成了 "指针差"，做题时看清题面给的是哪一种即可。

## 栈顶指针的两种约定

| 约定 | 初始值 | 栈顶元素 | 栈空条件 | 栈满条件 | 元素个数 | 入栈 | 出栈 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| **甲：`top` 指向栈顶元素** | `top = -1` | `data[top]` | `top == -1` | `top == MaxSize - 1` | `top + 1` | 先 `++top`，再赋值 | 先取值，再 `top--` |
| **乙：`top` 指向栈顶元素的下一个位置** | `top = 0` | `data[top - 1]` | `top == 0` | `top == MaxSize` | `top` | 先赋值，再 `top++` | 先 `--top`，再取值 |

### 为什么两种约定的操作顺序恰好相反

把两条约定各自当成一个**不变量**（invariant），要求它在每次操作前后都成立，顺序就被唯一确定了：

- **约定甲的不变量**："`top` 处存的是有效元素"。入栈时新元素还没地方放，必须**先把指针挪到 一个空位**（`++top`），再写入，写完不变量恢复。出栈时 `top` 处正是要取的元素，所以**先取值**， 取完那个位置就失效了，再 `top--`。
- **约定乙的不变量**："`top` 处是空位"。入栈时 `top` 已经指着空位，所以**直接写入**， 写完这个位置不再是空位，指针必须后移（`top++`）。出栈时 `top` 处是空位、`top-1` 才是元素， 所以**先 `--top`** 让指针落到元素上，再取值。

**验证方法**：随便挑一个约定，画出"空栈 → 压 A → 压 B → 弹 → 弹"五个时刻的数组与 `top`， 检查每一时刻不变量是否成立。不变量一旦被打破，说明操作顺序写反了。

### 约定甲下的越界反例（说明顺序不能随便换）

若在约定甲（`top` 初值 −1）下把入栈误写成 `data[top++] = x;`：

- 空栈时 `top = -1`，这句先用旧值 −1 做下标写入 `data[-1]`——**越界写**，随后 `top` 才变成 0；
- 接着 `Pop` 会取 `data[top--]`，即 `data[0]`，而 `data[0]` 从未被赋值。

所以**约定甲入栈必须用前缀 `++top`**。同理若把出栈误写成 `*x = S->data[--S->top];`， 弹出的是 `data[top-1]`，会跳过真正的栈顶元素。

**408 的默认口径**：题面若不特别说明，多按 `top = -1`（约定甲）理解；但只要题面给出了初值 或给出了栈空条件，**一律以题面为准**，不要拿默认口径去覆盖题目条件。

## 操作详解

### 初始化与判空
c

```
void InitStack(SqStack *S) {
    S->top = -1;               // 约定甲：-1 表示"还没有任何有效元素"
}

bool StackEmpty(SqStack S) {
    return S.top == -1;        // 与初始化保持同一口径，二者必须成对改动
}
```

初始化与判空是**同一条约定的两面**。凡是把 `InitStack` 改成 `top = 0` 的题目，`StackEmpty` 必然同步改成 `top == 0`，代码填空题常在这里设点。

### 入栈操作

将新元素压入栈顶。入栈前必须判断栈是否已满（**栈满上溢**）。

关键步骤（约定甲）：

- 判断栈是否已满（`top == MaxSize - 1`）——**下标最大只能到 `MaxSize - 1`**， 若写成 `top == MaxSize` 则会先越界写一格才发现满；
- 栈顶指针加 1（`++top`），落到空位上；
- 将新元素放入该位置。c

```
// 入栈操作（约定甲：top 初值 -1，指向栈顶元素）
bool Push(SqStack *S, int x) {
    if (S->top == MaxSize - 1)  // 栈满，上溢；注意是 MaxSize-1 不是 MaxSize
        return false;
    S->data[++S->top] = x;      // 前缀 ++：先把指针移到空位，再写入
    return true;
}
```

### 出栈操作

弹出栈顶元素。出栈前必须判断栈是否为空（**栈空下溢**）。c

```
// 出栈操作（约定甲）
bool Pop(SqStack *S, int *x) {
    if (S->top == -1)           // 栈空，下溢
        return false;
    *x = S->data[S->top--];     // 后缀 --：先用当前 top 取值，再移指针
    return true;
}
```

**注意"出栈"并不擦除数组里的数据**：`data[top+1]` 里的旧值仍然存在，只是逻辑上不属于栈了。 下一次入栈会把它覆盖掉。所以"出栈后数组内容不变、只有 `top` 变了"是正确的描述。

### 获取栈顶元素（GetTop）

仅读取栈顶元素，**不修改栈顶指针**，栈的状态不变。c

```
bool GetTop(SqStack S, int *x) {
    if (S.top == -1)
        return false;
    *x = S.data[S.top];         // 只读取，不移动指针
    return true;
}
```

注意这里参数用的是 `SqStack S`（传值）而不是指针——因为本操作**不应该修改栈**， 传值在语义上就杜绝了误改。`Push`/`Pop` 必须传指针，否则修改不会传回调用方。

### 约定乙的完整实现（对照）
c

```
// 约定乙：top 初值 0，指向栈顶元素的下一个空位
void InitStack2(SqStack *S) { S->top = 0; }

bool Push2(SqStack *S, int x) {
    if (S->top == MaxSize) return false;   // 栈满：空位已经跑到数组外
    S->data[S->top++] = x;                 // 后缀 ++：先写入，再移指针
    return true;
}

bool Pop2(SqStack *S, int *x) {
    if (S->top == 0) return false;         // 栈空
    *x = S->data[--S->top];                // 前缀 --：先移指针，再取值
    return true;
}
```

把两组代码并排看，**四个前缀/后缀恰好全部相反**——这就是上面"不变量"分析的直接结果。

### 教材的动态分配写法（真指针版，对照）

严蔚敏教材用两个**真指针** `base` 与 `top` 加一个 `stacksize`：c

```
#define MAXSIZE 100
typedef struct {
    int *base;        // 栈底指针，初始化后始终指向栈底
    int *top;         // 栈顶指针，指向栈顶元素的上一个位置
    int stacksize;    // 栈可使用的最大容量
} SqStack;

bool InitStack(SqStack *S) {
    S->base = (int *)malloc(MAXSIZE * sizeof(int));
    if (S->base == NULL) return false;   // 分配失败，栈结构不存在
    S->top = S->base;                    // 初值：top 与 base 相等 → 栈空
    S->stacksize = MAXSIZE;
    return true;
}

bool Push(SqStack *S, int e) {
    if (S->top - S->base == S->stacksize) return false;  // 栈满
    *S->top++ = e;                                       // 先写入，再后移
    return true;
}

bool Pop(SqStack *S, int *e) {
    if (S->top == S->base) return false;                 // 栈空
    *e = *--S->top;                                      // 先前移，再取值
    return true;
}
```

它与本篇的**约定乙**逐条对应：

| 项 | 下标版（约定乙） | 教材的指针版 |
| --- | --- | --- |
| 栈空 | `top == 0` | `S.top == S.base` |
| 栈满 | `top == MaxSize` | `S.top - S.base == S.stacksize` |
| 元素个数 | `top` | `S.top - S.base` |
| 栈顶元素 | `data[top-1]` | `*(S.top - 1)` |
| 入栈 | `data[top++] = x` | `*S.top++ = e` |
| 出栈 | `x = data[--top]` | `e = *--S.top` |

**"指针差就是下标"**——`S.top - S.base` 与下标版的 `top` 是同一个量。 看到教材式写法不必重新理解，把 `S.top - S.base` 在心里换成 `top` 即可。

两种写法唯一的实质差别是**空间来源**：教材版用 `malloc` 动态申请，容量可以在运行时决定 （甚至在栈满时 `realloc` 扩容）；本篇的静态数组版容量在编译期就定死了。 但**两者都属于顺序存储、都会栈满**，与链栈仍然是两回事。

### 完整跟踪一段操作序列

设 `MaxSize = 4`、采用约定甲，执行 `Push(A) → Push(B) → Pop → Push(C) → Push(D) → Push(E) → Pop → Pop`：

| 步 | 操作 | 判断 | top | 数组 `data[0..3]` | 返回 |
| --- | --- | --- | --- | --- | --- |
| 0 | 初始化 | — | −1 | `_ _ _ _` | — |
| 1 | `Push(A)` | −1≠3，不满 | 0 | `A _ _ _` | true |
| 2 | `Push(B)` | 0≠3 | 1 | `A B _ _` | true |
| 3 | `Pop` | 1≠−1，非空 | 0 | `A B _ _`（B 仍在，但已不属于栈） | true，取回 B |
| 4 | `Push(C)` | 不满 | 1 | `A C _ _`（**C 覆盖了 B**） | true |
| 5 | `Push(D)` | 不满 | 2 | `A C D _` | true |
| 6 | `Push(E)` | 不满 | 3 | `A C D E` | true |
| 7 | `Pop` | 非空 | 2 | `A C D E` | true，取回 E |
| 8 | `Pop` | 非空 | 1 | `A C D E` | true，取回 D |

**两个观察**：第 3 步之后 `data[1]` 里还留着 `B`，但它已经不在栈内， 第 4 步被 `C` 覆盖——这说明**"出栈"只是移动指针，不擦除数据**； 第 6 步之后 `top == 3 == MaxSize - 1`，此时再 `Push` 会被判满拒绝， 而数组确实已经写满 4 格，**判满条件与实际容量吻合**。

## 复杂度分析

| 操作 | 时间复杂度 | 来历 |
| --- | --- | --- |
| 入栈 `Push` | O(1) | 一次比较 + 一次下标自增 + 一次写内存，操作数与栈中元素个数 n 无关 |
| 出栈 `Pop` | O(1) | 一次比较 + 一次读内存 + 一次下标自减，同样与 n 无关 |
| 取栈顶 `GetTop` | O(1) | 数组随机存取，由 `top` 一次算出地址 |
| 判空 / 判满 | O(1) | 一次整数比较 |
| 求栈长 | O(1) | 约定甲为 `top + 1`，约定乙为 `top`，直接算出 |

**空间复杂度**：栈本身占 O(MaxSize)，**与实际存了几个元素无关**（静态数组一次分配到位）； 单次操作的**辅助空间**是 O(1)。

**和顺序表比一比**：顺序表在第 i 个位置插入要把后面 n−i 个元素整体后移，平均 O(n)。 顺序栈之所以能做到 O(1)，**唯一原因是它把插入删除位置锁死在了末端**——限制换来了效率。 这也说明"操作受限"不是缺点，而是设计目的。

## 顺序栈的空间困境

顺序栈必须**事先猜一个 `MaxSize`**，猜大了浪费、猜小了上溢，这是它无法回避的问题：

- 若程序里要同时用两个栈，各开一个 `MaxSize/2` 的数组，很可能出现"一个已经满了、 另一个还空着一大半"——解法是《[共享栈](./shared-stack.html)》：两个栈背靠背放进同一个数组， 栈满条件变成 `top1 + 1 == top2`；
- 若元素个数**完全无法预估**，解法是《[链栈](./linked-stack.html)》：按需 `malloc`， 代价是每个结点多一个指针域、存储密度下降、缓存局部性变差。

三者的选择标准很清楚：**容量可预估且要快 → 顺序栈；两个栈此消彼长 → 共享栈； 容量完全不可预估 → 链栈。**

## 易混淆知识点

| 对比项 | 情况 A | 情况 B | 判别依据 |
| --- | --- | --- | --- |
| 栈满条件 | 约定甲：`top == MaxSize - 1` | 约定乙：`top == MaxSize` | 看 `top` 指的是**元素**还是**空位**；指元素时最大合法下标就是 `MaxSize-1` |
| 入栈写法 | 约定甲：`data[++top] = x` | 约定乙：`data[top++] = x` | "先移后写"还是"先写后移"，由不变量决定，不能凭手感 |
| 出栈写法 | 约定甲：`x = data[top--]` | 约定乙：`x = data[--top]` | 同上，与入栈恰好相反 |
| 元素个数 | 约定甲：`top + 1` | 约定乙：`top` | 约定甲的 `top` 从 −1 起步，所以要 +1 |
| 上溢 vs 下溢 | 上溢：栈满还 `Push` | 下溢：栈空还 `Pop` | 上溢只在**顺序**存储出现（链栈没有）；下溢是逻辑层面的，任何实现都有 |
| `Pop` vs `GetTop` | `Pop` 改变 `top` | `GetTop` 不改变 `top` | 操作后栈长是否变化 |
| 顺序栈 vs 顺序表 | 顺序栈插入删除只在末端，O(1) | 顺序表任意位置插入删除，平均 O(n) | 是否需要移动元素 |
| 栈的**存储**空间 vs 操作的**辅助**空间 | 数组本身 O(MaxSize) | 每次操作 O(1) | 问"空间复杂度"时先确认问的是哪一个 |

## 本节小结

学完本篇，你应该能够：

- 写出顺序栈的结构定义，说明 `top` 是下标而非指针，并解释顺序栈为什么必然存在上溢；
- 给定任意一种 `top` 约定，**现场推出**栈空、栈满、元素个数三个表达式，以及入栈出栈的 前缀/后缀顺序——依据是"`top` 处存的是元素还是空位"这一不变量；
- 指出把约定甲的入栈写成 `data[top++] = x` 会在空栈时越界写 `data[-1]`，并说清后果；
- 完整写出 `InitStack` / `StackEmpty` / `Push` / `Pop` / `GetTop` 五个函数， 每个都带正确的边界判断；
- 解释顺序栈各操作为什么是 O(1)（操作数与 n 无关），并与顺序表插入的 O(n) 对照说明 "限制换效率"。

三个最关键的结论：

- **一切都从"top 指哪儿"推出来**，不要分开背两套公式；
- **约定甲的栈满是 `top == MaxSize - 1`**，写成 `MaxSize` 会先越界再报满；
- **上溢是顺序存储独有的**，它直接导出了共享栈与链栈两条改进路线。
