# Dijkstra 算法

## 大纲定位

本篇对应 2026 大纲 **五、图 （四）图的基本应用 2. 最短路径**。

**分工边界**：这一条由三篇分担，各管一类图。

| 篇 | 适用图 | 求什么 | 时间 |
| --- | --- | --- | --- |
| [BFS 最短路径](./bfs-shortest.html) | 无权图 / 边权全相等 | 单源 | O(n+e) |

| [Floyd](./floyd.html) | 带权图，可含负权边（不含负权回路） | **所有顶点对** | O(n3) |

## 知识框架

本节回答四个问题：

- 为什么"每轮选 `dist` 最小的顶点、把它的最短路径钉死"这件事是安全的？
- `dist[]`、`visited[]`、`path[]` 三个数组各自回答什么问题？少一个会怎样？
- 负权边为什么会破坏正确性？给一个具体的图，Dijkstra 会在哪一步出错？
- O(n2) 与 O(elog⁡n) 各自的来历是什么？什么图上该用哪个？

## 核心思想：按路径长度递增的次序确定最短路径

Dijkstra 把顶点分成两组：

- **S**：**已经确定**最短路径的顶点集合（初始只含源点 v0）；
- **V−S**：尚未确定的顶点集合。

算法**按各顶点与 v0 之间最短路径长度递增的次序**，逐个把 V−S 中的顶点搬进 S。 每搬进一个顶点，就用它去**松弛**（改进）其余顶点的距离估计。

三个数组各司其职：

| 数组 | 回答的问题 | 少了它会怎样 |
| --- | --- | --- |
| `dist[v]` | 源点到 v 的**当前最短距离估计** | 无法比较、无法松弛 |
| `visited[v]` | v 的最短路径**是否已确定** | 已定好的顶点会被反复选中，算法不收敛 |
| `path[v]` | 最短路径上 v 的**前驱顶点** | 只能报出距离，**答不出"路径是什么"** |

**松弛（Relaxation）**：若 dist[u]+w(u,v)<dist[v], 则 dist[v]←dist[u]+w(u,v), path[v]←u

含义是"经过 u 再到 v 比现在已知的走法更短，那就改走这条"。

### 贪心为什么正确

**命题**：每一轮选出的"未访问顶点中 `dist` 最小的顶点 u"，它当前的 `dist[u]` 就是源点到 u 的真实最短距离，可以永久确定。

**证明（反证）**：设 S 是已确定的集合，u 是 V−S 中 `dist` 最小的顶点。 假设真实最短距离 δ(u)<dist[u]，那么这条更短的路径上必然存在**第一个落在 V−S 中的顶点** x （因为路径起点 v0∈S、终点 u∈V−S）。x 之前的顶点全在 S 中， 所以 dist[x] 已经在 x 的前驱被并入 S 时被松弛到位，即 dist[x]=δ(x)。

又因为**所有边权非负**，从 x 走到 u 的那一段长度 ≥0，故dist[x]=δ(x)≤δ(u)<dist[u]

这说明 V−S 中存在一个 `dist` 比 u 更小的顶点 x，与"u 是最小的"矛盾。∎

**请注意这个证明用到"边权非负"的确切位置**——就是 δ(x)≤δ(u) 那一步。 只有非负权才能保证"路径越走越长"，从而"先确定的一定不会被后来的路径改短"。 一旦允许负权，这一步立刻失效，整个算法随之崩塌。下面会给出具体反例。

### 与 Prim 的关系

两者的骨架完全相同：**初始化 → 选最小 → 并入 → 松弛**。唯一的差别在松弛式：

|  | 松弛式 | 语义 |
| --- | --- | --- |
| **Prim** | `lowcost[v] = min(lowcost[v], cost[u][v])` | v 到**树**的距离，不累加 |
| **Dijkstra** | `dist[v] = min(dist[v], dist[u] + w(u,v))` | v 到**源点**的距离，要累加 |

少了那个 `dist[u] +`，"最短路径"就变成了"最小生成树"。见 [Prim](./prim.html)。

## 算法实现（邻接矩阵版）
c

```
#define INF 0x3f3f3f3f
#define MAX_V 100

int  graph[MAX_V][MAX_V];   // 邻接矩阵，无边处为 INF，对角线为 0
int  dist[MAX_V];           // 源点到各顶点的最短距离
int  visited[MAX_V];        // 最短路径是否已确定
int  path[MAX_V];           // 最短路径上各顶点的前驱

void dijkstra(int n, int src) {
    for (int i = 0; i < n; i++) {
        dist[i] = INF;
        visited[i] = 0;
        path[i] = -1;
    }
    dist[src] = 0;
    path[src] = src;         // 约定源点的前驱是自己，作为回溯的终止标志

    for (int i = 0; i < n; i++) {
        // ① 选最小：在未访问顶点中挑 dist 最小的 u
        int u = -1, minDist = INF;
        for (int j = 0; j < n; j++)
            if (!visited[j] && dist[j] < minDist) {
                minDist = dist[j];
                u = j;
            }
        if (u == -1) break;  // 剩余顶点 dist 全为 INF → 都不可达，提前结束
        visited[u] = 1;      // ② 确定：u 的最短路径就此钉死，之后不再改动

        // ③ 松弛 u 的所有未访问邻接顶点
        for (int v = 0; v < n; v++) {
            if (!visited[v] && graph[u][v] != INF
                && dist[u] + graph[u][v] < dist[v]) {
                dist[v] = dist[u] + graph[u][v];
                path[v] = u;
            }
        }
    }
}
```

### 三处实现细节

**1. `INF` 为什么写成 `0x3f3f3f3f` 而不是 `INT_MAX`？**

`0x3f3f3f3f` ≈1.06×109，足够大（大于任何合理的路径长度和）， 而且 `INF + INF = 0x7e7e7e7e` 仍在 `int` 范围内**不会溢出**。 若取 `INT_MAX`，一旦某处发生 `INF + w` 的加法就会整型溢出变成负数， "∞ 加一点点"反而成了最小值，松弛判断会做出完全相反的决定。

**2. 松弛条件里要不要再写一个 `dist[u] != INF`？**

**不需要**。`u == -1` 的提前 `break` 已经保证被选中的 u 一定可达 （`dist[u] < INF`，否则它不会被选中）。 有些教材版本在松弛条件里多写一个 `dist[u] != INF`， **两种写法等价**，多写的那一句只是把"选点阶段已经保证的事"再确认一次，不影响结果。

代码里的另一处保护 `graph[u][v] != INF` 则是**必需**的： 它拦住了"u 到 v 根本没有边"的情况，避免 `dist[u] + INF` 这种无意义的加法。 在 `0x3f3f3f3f` 的取值下，即使不写这一句也不会溢出成负数， 但会让 `dist[v]` 被更新成一个巨大的有限值，从而丢掉"不可达"的语义。

**3. `path[src] = src` 这个约定**

它让回溯循环可以用 `path[v] == v` 作为终止条件。若改成 `path[src] = -1`， 则回溯条件要相应改成 `v != -1`——**两种写法各自自洽，不能混用**。 本篇统一采用 `path[src] = src`。

## 完整走查

以下带权**有向图**（6 个顶点，弧与权全部列出）：

| 弧 | 权 | 弧 | 权 |
| --- | --- | --- | --- |
| 0→1 | 10 | 2→4 | 10 |
| 0→3 | 30 | 3→2 | 20 |
| 0→4 | 100 | 3→4 | 60 |
| 1→2 | 50 | 5→0 | 5 |

注意顶点 5 只有出弧、没有入弧，所以**从 0 出发到不了 5**——这正好用来检验代码的 "不可达"分支。求源点 0 到其余各顶点的最短路径：

**第 1 轮**：未访问顶点中 dist[0]=0 最小，选 u=0，确定。 松弛 0 的三条出弧：0→1 得 10<∞，更新；0→3 得 30<∞，更新； 0→4 得 100<∞，更新。

**第 2 轮**：未访问中最小的是 dist[1]=10，选 u=1，确定。 松弛 1→2：10+50=60<∞，更新 dist[2]=60，path[2]=1。

**第 3 轮**：未访问中最小的是 dist[3]=30，选 u=3，确定。 松弛 3→2：30+20=50<60，**更新 dist[2]=50，path[2]=3**（前驱从 1 改成 3）； 松弛 3→4：30+60=90<100，更新 dist[4]=90，path[4]=3。

**第 4 轮**：未访问中最小的是 dist[2]=50，选 u=2，确定。 松弛 2→4：50+10=60<90，**更新 dist[4]=60，path[4]=2**。

**第 5 轮**：未访问中最小的是 dist[4]=60，选 u=4，确定。顶点 4 无出弧，无松弛。

**第 6 轮**：未访问的只剩顶点 5，dist[5]=∞，`u == -1`，**提前结束**。

汇总表（加粗表示该顶点已确定）：

| 轮次 | 选中 u | dist[0] | dist[1] | dist[2] | dist[3] | dist[4] | dist[5] | 本轮松弛 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 初始 | — | 0 | ∞ | ∞ | ∞ | ∞ | ∞ | — |
| 1 | 0 | **0** | 10 | ∞ | 30 | 100 | ∞ | 0→1, 0→3, 0→4 |
| 2 | 1 | **0** | **10** | 60 | 30 | 100 | ∞ | 1→2：10+50=60 |
| 3 | 3 | **0** | **10** | 50 | **30** | 90 | ∞ | 3→2：30+20=50；3→4：30+60=90 |
| 4 | 2 | **0** | **10** | **50** | **30** | 60 | ∞ | 2→4：50+10=60 |
| 5 | 4 | **0** | **10** | **50** | **30** | **60** | ∞ | 无出弧 |
| 6 | 无 | **0** | **10** | **50** | **30** | **60** | ∞ | 提前结束 |

`path[]` 的同步变化：

| 轮次 | path[0] | path[1] | path[2] | path[3] | path[4] | path[5] |
| --- | --- | --- | --- | --- | --- | --- |
| 初始 | 0 | −1 | −1 | −1 | −1 | −1 |
| 1 | 0 | 0 | −1 | 0 | 0 | −1 |
| 2 | 0 | 0 | 1 | 0 | 0 | −1 |
| 3 | 0 | 0 | **3** | 0 | **3** | −1 |
| 4 | 0 | 0 | 3 | 0 | **2** | −1 |
| 5–6 | 0 | 0 | 3 | 0 | 2 | −1 |

**手算自检的两条纪律**：

- **一旦某顶点被选中并加粗，它的 `dist` 就不能再变**。 若你在后面的轮次里发现自己改了已加粗顶点的值，说明前面某一步选错了顶点。
- **每轮选中顶点的 `dist` 必须单调不减**：本例是 0,10,30,50,60，确实递增。 若出现"后选中的比先选中的还小"，一定是算错了。

### 路径回溯
c

```
// 打印从 src 到 dest 的最短路径（递归先打印前面的部分，天然正序）
void printPath(int path[], int dest) {
    if (path[dest] == dest) {      // 到达源点（约定 path[src] == src）
        printf("%d", dest);
        return;
    }
    if (path[dest] == -1) {        // 不可达
        printf("(不可达)");
        return;
    }
    printPath(path, path[dest]);   // 先打印前驱一侧
    printf(" → %d", dest);
}
```

**还原 0→4**：path[4]=2→path[2]=3→path[3]=0→path[0]=0（到达源点，停）。 逆序翻转得 **0→3→2→4**，验算长度 30+20+10=60=dist[4] ✓。

注意这条路径与"0→4 那条权 100 的直连弧"完全不同，也与第 2 轮临时算出的 "0→1→2" 不同——**中途被改过两次前驱的顶点，正是最容易在手算里写错的地方**。

## 负权边：为什么不行

Dijkstra 的正确性证明依赖"边权非负"。一旦出现负权边，"已确定的顶点不会再变短"这个前提就失效了。

**反例**（三个顶点的有向图）：0→ 5 1,1→ −3 2,0→ 3 2

**逐步执行**：

| 轮次 | 选中 u | dist[0] | dist[1] | dist[2] | 说明 |
| --- | --- | --- | --- | --- | --- |
| 初始 | — | 0 | ∞ | ∞ |  |
| 1 | 0 | **0** | 5 | 3 | 松弛 0→1 得 5；0→2 得 3 |
| 2 | **2** | **0** | 5 | **3** | 未访问中 dist[2]=3 最小，选中并**永久确定为 3** |
| 3 | 1 | **0** | **5** | **3** | 松弛 1→2：5+(−3)=2<3，但 visited[2] 已为真，**不会更新** |

**结果**：Dijkstra 输出 dist[2]=3。 **真实答案**：0→1→2 的长度是 5+(−3)=2，比 3 更短。**算法给出了错误答案。**

错在哪一步？错在第 2 轮："顶点 2 当前 `dist` 最小，所以它已经最优"—— 这个推断的隐含前提是"后面再怎么绕路都只会更长"。负权边打破了这个前提。

**边界要分清**：

- **含负权边（但无负权回路）** → 用 **Bellman-Ford** 算法（408 不要求实现，但要知道它的存在）， 或用 [Floyd](./floyd.html) 求全源。
- **含负权回路** → 最短路径**根本不存在**（绕一圈就更短，可以无限减小）。
- **含 0 权边** → **Dijkstra 完全可以处理**。证明里用的是"≥0"而不是">0"。 "非负"与"正"是两个不同的条件，别混。

## 复杂度分析

**朴素实现 O(n2)**：

- 外层循环 n 轮；
- 每轮做两件事：线性扫描找 `dist` 最小的未访问顶点（O(n)）， 以及扫描邻接矩阵的一整行做松弛（O(n)）。

故总时间 n×O(n)=O(n2)。**注意这个复杂度与边数无关**—— 即使图上只有 n−1 条边，邻接矩阵的每一行仍要扫满。

**堆优化 O(elog⁡n)**：改用邻接表 + 最小堆（优先队列）。

- 松弛操作总共发生至多 e 次，每次要在堆中调整一个元素，O(log⁡n)，合计 O(elog⁡n)；
- 取最小值总共 n 次，每次 O(log⁡n)，合计 O(nlog⁡n)。

两项相加为 O((n+e)log⁡n)；连通图上 e≥n−1，简写为 O(elog⁡n)。

| 指标 | 朴素（邻接矩阵） | 堆优化（邻接表 + 最小堆） |
| --- | --- | --- |
| 时间 | O(n2) | O(elog⁡n) |
| 空间 | O(n) 辅助 + O(n2) 存图 | O(n) 辅助 + O(n+e) 存图 |
| 适合 | 稠密图（e 接近 n2） | 稀疏图（e≪n2） |

**选择依据要代数比较，不要背**：当 e≈n2 时，elog⁡n=n2log⁡n>n2，朴素更优； 当 e≈n 时，elog⁡n=nlog⁡n≪n2，堆优化更优。

**求所有顶点对的最短路径**：对每个顶点各跑一次 Dijkstra，代价 n×O(n2)=O(n3)， 与 [Floyd](./floyd.html) 同阶。但 Floyd 代码更简洁，且能处理负权边。

## 易混淆知识点

| 一组概念 | 差别 | 判别依据 |
| --- | --- | --- |
| Dijkstra vs Prim | 松弛式一个累加（到源点）、一个不累加（到树） | 看更新式里有没有 `dist[u] +` |
| Dijkstra vs BFS | 前者按**权和**递增取点，后者按**边数**递增取点 | 边权是否全相等；相等时两者等价 |
| Dijkstra vs Floyd | 单源 vs 全源；贪心 vs 动态规划；不支持负权 vs 支持负权 | 见 [BFS 最短路径](./bfs-shortest.html) 的三算法选型表 |
| 负权边 vs 非正权 | Dijkstra 允许 0 权，只禁负权 | 证明里用的是 ≥0，不是 >0 |
| 负权边 vs 负权回路 | 前者只是让 Dijkstra 失效，后者让最短路径**不存在** | 问"绕一圈总权是不是负的" |
| `dist[]` vs `path[]` | 一个答"多远"，一个答"怎么走" | 题目问"写出最短路径"就必须有 `path[]`，两者不能互推 |
| 已确定顶点 vs 未确定顶点 | 前者 `dist` 永不再变 | 手算时把已确定的加粗，改了就是算错 |
| O(n2) vs O(elog⁡n) | 前者与边数无关，后者与边数线性相关 | 代入具体 n,e 比大小 |

**为什么每轮选中顶点的 `dist` 一定单调不减？** 因为新产生的 `dist` 值都是"某个已确定顶点的 `dist` + 一个非负边权"，不可能小于已确定的值。 这条性质是手算时最好用的自检——比重算一遍快得多。

**同一轮里有两个顶点 `dist` 并列最小，选哪个？** 任选其一，不影响最终的 `dist[]`（最短距离是图的固有量）， 但可能影响 `path[]`（即选出哪一条最短路径），因为最短路径可能不唯一。

## 本节小结

学完本篇，你应该能够：

- 给定带权有向图与源点，**逐轮填出 `dist[]` 与 `path[]` 两张表**， 并用"已确定顶点的值不再变""每轮选中值单调不减"两条自检。
- 由 `path[]` 回溯出完整最短路径，并验算它的长度等于 `dist[]`。
- 完整叙述贪心正确性的反证法证明，**指出它在哪一步用到了"边权非负"**。
- 给出 Dijkstra 在负权边上出错的具体反例，并逐步执行说明它在第几轮、因为什么而错。
- 写出朴素版 C 代码，解释 `INF` 取 `0x3f3f3f3f` 的原因、`u == -1` 提前退出的作用， 以及"松弛条件里的 `dist[u] != INF` 可写可不写"。
- 独立推出 O(n2) 与 O(elog⁡n) 的来历，并据此在给定 n,e 下选实现方式。

三条最关键的结论：

- **贪心正确性 = "边权非负 ⇒ 路径只会越走越长 ⇒ 先确定的不会被改短"**； 负权边打破这一条，Dijkstra 随之失效（但 0 权无妨）。
- **`dist[]` 答距离、`path[]` 答路径**，两者不能互推；`visited[]` 保证每个顶点只被确定一次。
- **O(n2) 与边数无关（适合稠密图），O(elog⁡n) 与边数线性相关（适合稀疏图）**； 对所有顶点各跑一次就是 O(n3)，与 Floyd 同阶。

## 教材出处

- 严蔚敏《数据结构（C 语言版）》（第 2 版）**印刷 p171**，§6.6.2： 把顶点分成两组——"第一组 S：已求出的最短路径的终点集合（初始时只包含源点 v0）； 第二组 V−S：尚未求出最短路径的顶点集合"， "算法将按各顶点与 v0 间最短路径长度递增的次序，逐个将集合 V−S 中的顶点加入到集合 S 中去"； 同页用反证法证明"下一条最短路径……或者是边 (v0,x)， 或者是中间只经过 S 中的顶点而最后到达顶点 x 的路径"。
- 同书**印刷 p171**：算法的辅助数据结构——一维数组 `S[i]` 记录终点 vi 是否已确定最短路径长度。
- 同书**印刷 p174**（算法分析）： "求解最短路径的主循环共进行 n−1 次，每次执行的时间是 O(n)，所以算法的时间复杂度是 O(n2)。 如果用带权的邻接表作为有向图的存储结构，则虽然修改 D 的时间可以减少， 但由于在 D 向量中选择最小分量的时间不变，所以时间复杂度仍为 O(n2)。" 同页并指出"只希望找到从源点到某一个特定终点的最短路径"与求全部终点同样复杂。
- 同书**印刷 p174**：求每一对顶点之间的最短路径的两种方法—— 调用 n 次迪杰斯特拉算法，或采用弗洛伊德算法，"两种算法的时间复杂度均为 O(n3)， 但后者形式上较简单"。
