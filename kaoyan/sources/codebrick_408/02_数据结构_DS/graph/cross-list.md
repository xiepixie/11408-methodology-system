# 十字链表与邻接多重表

## 大纲定位

本篇对应 2026 大纲 **五、图 （二）图的存储及基本操作 3. 邻接多重表、十字链表**。

**分工边界**：

- **本篇**负责这两种"改良版链式存储"：结构域的含义、建表、遍历模板、删边、 以及最重要的一件事——**它们各自是为了解决邻接表的哪一处具体短板**。
- **邻接表**本身见[邻接表](./adjacency-list.html)；本篇把它当成已知前提， 只在"它做不到什么"这一点上回顾。
- 四种存储结构的横向对比表在**本篇的《易混淆知识点》**， 两两对比（矩阵 vs 表）在[邻接矩阵](./adjacency-matrix.html)那一篇。

⚠️ **两种结构不可互换**：十字链表**只用于有向图**，邻接多重表**只用于无向图**。 把这一条记成"两个名字对两种图"是不够的——下面会说清为什么必然如此。

## 知识框架

本节回答四个问题：

- 邻接表在有向图上到底缺什么？为什么"再建一张逆邻接表"不是好办法？
- 一个弧结点怎么可能同时挂在两条链上？"十字"这个名字指的是什么？
- 邻接表在无向图上到底缺什么？为什么"每条边两个结点"会带来实际麻烦？
- 邻接多重表上遍历一个顶点的所有边，为什么不能写成 `p = p->ilink`？

## 十字链表（有向图）

### 它要解决的问题

有向图用邻接表存时，第 i 条链上的结点个数只是顶点 vi 的**出度**； 要求入度就必须遍历整张表，代价 O(n+e)（见[邻接表](./adjacency-list.html)）。

一个直接的补救是再建一张**逆邻接表**——但那意味着**同一条弧被存了两份独立的结点**， 增删弧时两张表都要改，稍有不慎就不一致。

**十字链表的做法是：一条弧仍然只有一个结点，但让这个结点同时挂在两条链上。** 可以理解为"把邻接表和逆邻接表叠在一起，共用同一批弧结点"。

### 结点结构

**弧结点**（5 个域）：

```
| tailvex | headvex | hlink | tlink | info |
```

| 字段 | 含义 |
| --- | --- |
| tailvex | 弧尾顶点编号（起点） |
| headvex | 弧头顶点编号（终点） |
| hlink | 指向**弧头相同**的下一条弧（把所有射入同一顶点的弧串起来） |
| tlink | 指向**弧尾相同**的下一条弧（把所有射出同一顶点的弧串起来） |
| info | 弧的权值等信息（可选） |

**顶点结点**（3 个域）：

```
| data | firstin | firstout |
```

| 字段 | 含义 |
| --- | --- |
| data | 顶点数据 |
| firstin | 指向以该顶点为**弧头**的第一条弧（第一条入弧） |
| firstout | 指向以该顶点为**弧尾**的第一条弧（第一条出弧） |

**"十字"这个名字的来历**：每个弧结点上引出两个指针，`tlink` 往右走（同弧尾）， `hlink` 往下走（同弧头），两个方向在结点处交叉成十字。 **任意一个弧结点都同时躺在恰好两条链上**——它的弧尾顶点的出弧链，和它的弧头顶点的入弧链。

### 结构示意

有向图 ⟨V0,V1⟩, ⟨V0,V2⟩, ⟨V2,V1⟩：

```
顶点数组
[0] V₀  firstin = NULL                    firstout → (0,1) → (0,2) → NULL   （tlink 链）
[1] V₁  firstin → (0,1) → (2,1) → NULL    firstout = NULL                   （hlink 链）
[2] V₂  firstin → (0,2) → NULL            firstout → (2,1) → NULL
```

读法：弧结点 (0,1) 同时出现在 V0 的 `firstout` 链和 V1 的 `firstin` 链上， 它只有**一份实体**。沿 `firstout + tlink` 走一遍就数出出度， 沿 `firstin + hlink` 走一遍就数出入度。

图注：左边是含 5 个顶点、6 条弧的有向图。右边的 Nodetable 是顶点表，每个顶点有 **两个**指针列（firstin 与 firstout）；右侧 EdgeLinkedList 里的 6 个方框就是 6 个弧结点， **数量与弧数完全相同，没有任何一条弧被存两次**。 注意从顶点表射出的箭头有两组：一组接到"以我为终点的弧"，一组接到"以我为起点的弧"， 而它们指向的是**同一批方框**。这就是十字链表相对"邻接表 + 逆邻接表"的全部优势所在。 图源：殷人昆《数据结构——用面向对象方法与 C++ 描述》（第 2 版）图8.11 有向图的十字链表表示，p363

### 存储结构（C 语言）
c

```
#define MAX_VERTEX_NUM 20

typedef struct ArcBox {
    int tailvex, headvex;              // 该弧的弧尾、弧头顶点的位置
    struct ArcBox *hlink, *tlink;      // 分别为弧头相同、弧尾相同的弧的链域
    InfoType *info;                    // 该弧相关信息的指针（可选）
} ArcBox;

typedef struct VexNode {
    VertexType data;
    ArcBox *firstin, *firstout;        // 分别指向该顶点的第一条入弧和出弧
} VexNode;

typedef struct {
    VexNode xlist[MAX_VERTEX_NUM];     // 表头向量（顺序存储）
    int vexnum, arcnum;                // 有向图当前的顶点数和弧数
} OLGraph;
```

### 建表与求度

**建表**（时间复杂度与建邻接表相同，O(n+e)）：

- 初始化顶点数组，每个顶点的 `firstin`、`firstout` 都置 NULL。
- 对每条弧 ⟨vi,vj⟩ 创建一个弧结点，置 `tailvex = i`、`headvex = j`。
- 用**头插法**把它同时插入 vi 的出弧链（经 `tlink`）与 vj 的入弧链（经 `hlink`）。c

```
// 插入弧 <i, j>：一个结点，两次头插
void insertArc(OLGraph *G, int i, int j) {
    ArcBox *p = (ArcBox *)malloc(sizeof(ArcBox));
    p->tailvex = i;  p->headvex = j;  p->info = NULL;

    p->tlink = G->xlist[i].firstout;   // 插入 i 的出弧链
    G->xlist[i].firstout = p;

    p->hlink = G->xlist[j].firstin;    // 插入 j 的入弧链
    G->xlist[j].firstin = p;
    // 两次头插各 O(1)，且两条链共享同一个 p —— 这是十字链表的关键一步
    G->arcnum++;
}
```

**求度**（两个方向都只走自己那条链）：c

```
int outDegree(OLGraph *G, int v) {          // 出度：firstout + tlink
    int d = 0;
    for (ArcBox *p = G->xlist[v].firstout; p; p = p->tlink) d++;
    return d;
}

int inDegree(OLGraph *G, int v) {           // 入度：firstin + hlink
    int d = 0;
    for (ArcBox *p = G->xlist[v].firstin; p; p = p->hlink) d++;
    return d;
}
```

**注意两条链用的推进指针不同**：出弧链走 `tlink`（弧尾相同），入弧链走 `hlink`（弧头相同）。 把它们写反，程序不会崩，但会沿着错误的链跑出错误的结果——这是十字链表代码最典型的错处。 记法：**从 `firstout` 出发用 `t`link（tail 相同），从 `firstin` 出发用 `h`link（head 相同）**， 首字母是对上的。

**代价对照**：

| 操作 | 邻接表 | 逆邻接表 | 十字链表 |
| --- | --- | --- | --- |
| 求出度 | O(deg+) | O(n+e) | O(deg+) |
| 求入度 | O(n+e) | O(deg−) | O(deg−) |
| 存储的弧结点数 | e | e | e |
| 增删一条弧需改动 | 1 处 | 1 处 | 2 条链，但只 1 个结点 |

十字链表**没有**增加空间量级（仍是 O(n+e)），只是弧结点多了 2 个指针域、 顶点结点多了 1 个指针域，换来入度查询从 O(n+e) 降到 O(deg−)。 这是一次典型的"用常数级空间换量级时间"的设计。

## 邻接多重表（无向图）

### 它要解决的问题

无向图用邻接表存时，边 (vi,vj) 在 vi 和 vj 的链上**各有一个独立结点**。 只要操作对象是"边"而不是"顶点"，这两个分身就会带来麻烦：

- **删除一条边**：要在两条链里分别找到并释放两个结点，还要保证不漏删；
- **给边做标记**（例如"这条边已被搜索过"）：标记了一个分身，另一个分身仍是未标记的；
- **对每条边恰好处理一次**（输出所有边、求边权之和）：会重复计数，必须另想去重办法。

**邻接多重表的做法是：每条边只用一个边结点，让它被两个端点的链共享。**

### 结点结构

**边结点**（6 个域）：

```
| mark | ivex | ilink | jvex | jlink | info |
```

| 字段 | 含义 |
| --- | --- |
| mark | 标志域，标记该边是否被搜索过 |
| ivex | 该边依附的一个顶点编号 |
| ilink | 指向下一条依附于 **ivex** 的边 |
| jvex | 该边依附的另一个顶点编号 |
| jlink | 指向下一条依附于 **jvex** 的边 |
| info | 边的权值等信息（可选） |

**顶点结点**（2 个域）：

```
| data | firstedge |
```

`firstedge` 指向第一条依附于该顶点的边。

图注：左边的无向图有 4 个顶点、3 条边。右边 NodeTable 每个顶点只有**一个**指针 （对比十字链表的两个——无向边没有方向，不需要区分入与出）； Edge Linked List 里只有 **3 个**边结点，与边数相等，而同一个图用邻接表要 6 个。 每个边结点里有两个端点编号和两个后继指针，箭头从两个不同顶点射向同一个方框—— 这就是"一个结点被两条链共享"的实际样子。 图源：殷人昆《数据结构——用面向对象方法与 C++ 描述》（第 2 版）图8.10 无向图的邻接多重表表示，p362

### 存储结构（C 语言）
c

```
#define MAX_VERTEX_NUM 20

typedef struct EBox {
    int mark;                          // 访问标记（边级别）
    int ivex, jvex;                    // 该边依附的两个顶点的位置
    struct EBox *ilink, *jlink;        // 分别指向依附这两个顶点的下一条边
    InfoType *info;                    // 该边信息指针（可选）
} EBox;

typedef struct VexBox {
    VertexType data;
    EBox *firstedge;                   // 指向第一条依附该顶点的边
} VexBox;

typedef struct {
    VexBox adjmulist[MAX_VERTEX_NUM];
    int vexnum, edgenum;               // 无向图当前的顶点数和边数
} AMLGraph;
```

除了多出一个 `mark` 标志域，**邻接多重表所需的存储量与邻接表相同**—— 邻接表用 2e 个"三域结点"，邻接多重表用 e 个"六域结点"，总域数是同一量级。

### 建表：一个完整的手推例子

这是理解"一个结点挂两条链"的关键，务必自己跟着画一遍。

无向图有 4 个顶点、4 条边，按 e1=(0,1)、e2=(0,2)、e3=(1,2)、e4=(2,3) 的顺序 **头插**建表。每插一条边 (i,j)，就把这个新结点分别插到 Vi 链头和 Vj 链头。

逐步过程：

| 插入 | V0 链 | V1 链 | V2 链 | V3 链 |
| --- | --- | --- | --- | --- |
| 初始 | ∧ | ∧ | ∧ | ∧ |
| e1=(0,1) | e1 | e1 | ∧ | ∧ |
| e2=(0,2) | e2→e1 | e1 | e2 | ∧ |
| e3=(1,2) | e2→e1 | e3→e1 | e3→e2 | ∧ |
| e4=(2,3) | e2→e1 | e3→e1 | e4→e3→e2 | e4 |

把每一步走的是哪个指针标出来（∧ 表示 NULL）：

```
V0.firstedge → e2(0,2) ─ilink→ e1(0,1) ─ilink→ ∧
V1.firstedge → e3(1,2) ─ilink→ e1(0,1) ─jlink→ ∧
V2.firstedge → e4(2,3) ─ilink→ e3(1,2) ─jlink→ e2(0,2) ─jlink→ ∧
V3.firstedge → e4(2,3) ─jlink→ ∧
```

两个要点：

- **全图只有 4 个边结点**（邻接表要 8 个），但四条顶点链加起来经过了 8 次， 因为每个结点被两条链各穿过一次。
- **同一个结点 e1 既在 V0 链上又在 V1 链上，但推进用的指针不同**： 从 V0 进来时 V0 是它的 `ivex` 端，往下走 `ilink`； 从 V1 进来时 V1 是它的 `jvex` 端，往下走 `jlink`。

**走哪条链取决于"当前顶点是这条边的哪一端"**——这是邻接多重表全部操作的统一模板：c

```
// 遍历依附于顶点 v 的所有边（通用模板）
for (EBox *p = G->adjmulist[v].firstedge; p != NULL;
     p = (p->ivex == v) ? p->ilink : p->jlink) {
    // 对端顶点 = (p->ivex == v) ? p->jvex : p->ivex
}
```

⚠️ **不能写成 `p = p->ilink`**。给一个反例：在上表的 V2 链上从 e4 出发， e4 的 `ivex` 是 2，走 `ilink` 到 e3；但 e3=(1,2) 的 `ivex` 是 **1** 不是 2， 它的 `ilink` 指向的是 V1 链上的下一条边 e1，而不是 V2 链上的 e2。 硬写 `p->ilink` 会从 V2 的链上**跳到 V1 的链上**，遍历结果既漏边又串边。 这是本篇代码最容易写错的一处。

### 删边：只删一个结点

删除边 (vi,vj) 时，把**同一个结点**从两条链上分别摘除，然后只 `free` 一次：c

```
// 把边结点 e 从顶点 v 的边链表中摘除
void detach(AMLGraph *G, int v, EBox *e) {
    EBox *p = G->adjmulist[v].firstedge, *pre = NULL;
    while (p != e) {                              // 沿 v 的链找 e 的前驱
        pre = p;
        p = (p->ivex == v) ? p->ilink : p->jlink; // 推进同样要判端
    }
    EBox *next = (e->ivex == v) ? e->ilink : e->jlink;
    if (pre == NULL)
        G->adjmulist[v].firstedge = next;         // e 是链头
    else if (pre->ivex == v)
        pre->ilink = next;                        // 前驱经 ilink 链到 e
    else
        pre->jlink = next;                        // 前驱经 jlink 链到 e
}

// 删除边 (i, j)
void deleteEdge(AMLGraph *G, int i, int j, EBox *e) {
    detach(G, i, e);
    detach(G, j, e);
    free(e);            // 只 free 一次 —— 这就是"删边只删一个结点"
    G->edgenum--;
}
```

**修改前驱指针时同样要判端**：前驱 `pre` 是经 `ilink` 还是经 `jlink` 链到 `e` 的， 取决于 `pre` 的哪一端是 v。这与遍历时的判断是同一条规则。

对比邻接表：无向边 (vi,vj) 在那里是**两个独立结点**，删边要在两条链里各找一次、各 `free` 一次， 而且两个结点内容相同、地址不同，无法用"是不是同一个指针"来配对，只能靠比对顶点编号。

### mark 标志位的作用

需要**对每条边恰好处理一次**的操作（输出所有边、统计边权和、给边打标记）： 邻接多重表把 `mark` 置位即可，因为每条边本来就只有一个结点。c

```
// 在邻接多重表上对每条边恰好处理一次（以 DFS 框架为例）
void DFS(AMLGraph *G, int v) {
    visited[v] = 1;                               // 顶点标志照常要有
    for (EBox *p = G->adjmulist[v].firstedge; p != NULL;
         p = (p->ivex == v) ? p->ilink : p->jlink) {
        if (!p->mark) {
            p->mark = 1;                          // 这条边处理过了，从另一端进来时不再处理
            int u = (p->ivex == v) ? p->jvex : p->ivex;
            if (!visited[u]) DFS(G, u);
        }
    }
}
```

**mark 是"边"的访问标志，不能代替顶点的 `visited[]`**——两个标志各管各的： `visited[]` 防止顶点被重复访问，`mark` 防止同一条边经由两个端点被处理两次。 只留 `mark`：图中存在环时顶点会被重复访问；只留 `visited[]`： 统计边权和时每条边会被算两次。**两者不是冗余关系。**

邻接表上要做同样的事，只能靠额外手段：开一张"边是否已处理"的表， 或者约定"只处理 i<j 的那一份"。前者费空间，后者对多重边失效。

### 建表走查：十字链表的两条链

取有向图 ⟨0,1⟩, ⟨0,2⟩, ⟨2,1⟩, ⟨1,0⟩， 按这个次序头插建表。每插一条弧 ⟨i,j⟩，就把新结点插到 Vi 的出弧链头（经 `tlink`）和 Vj 的入弧链头（经 `hlink`）：

| 插入 | V0 出弧链 | V1 出弧链 | V2 出弧链 | V0 入弧链 | V1 入弧链 | V2 入弧链 |
| --- | --- | --- | --- | --- | --- | --- |
| 初始 | ∧ | ∧ | ∧ | ∧ | ∧ | ∧ |
| ⟨0,1⟩ | (0,1) | ∧ | ∧ | ∧ | (0,1) | ∧ |
| ⟨0,2⟩ | (0,2)→(0,1) | ∧ | ∧ | ∧ | (0,1) | (0,2) |
| ⟨2,1⟩ | (0,2)→(0,1) | ∧ | (2,1) | ∧ | (2,1)→(0,1) | (0,2) |
| ⟨1,0⟩ | (0,2)→(0,1) | (1,0) | (2,1) | (1,0) | (2,1)→(0,1) | (0,2) |

**读出度入度**：

| 顶点 | 出度（出弧链长） | 入度（入弧链长） |
| --- | --- | --- |
| V0 | 2 | 1 |
| V1 | 1 | 2 |
| V2 | 1 | 1 |

**自检**：出度之和 =4、入度之和 =4，都等于弧数 e=4 ✓ （见[图的基本概念](./concepts.html)）。

**再数一遍结点**：整张表只有 **4 个弧结点**，与弧数相同。 若改用"邻接表 + 逆邻接表"，两张表各 4 个，共 **8 个**，还要保证增删弧时两边同步。 **十字链表用同样 4 个结点同时支持两个方向的查询**——两条链只是两组指针，不是两份数据。

## 复杂度总览

### 四种图存储结构对比

| 存储结构 | 适用图 | 空间 | 求出度 | 求入度 | 判两点相邻 | 删一条边 |
| --- | --- | --- | --- | --- | --- | --- |
| 邻接矩阵 | 有向 / 无向 | O(n2) | O(n) | O(n) | O(1) | O(1) |
| 邻接表 | 有向 / 无向 | O(n+e) | O(deg+) | O(n+e) | O(deg) 最坏 O(n) | 无向图要删 2 个结点 |
| **十字链表** | **有向图** | O(n+e) | O(deg+) | O(deg−) | O(deg+) | 1 个结点，摘 2 条链 |
| **邻接多重表** | **无向图** | O(n+e) | — | — | O(deg) | **1 个结点**，摘 2 条链 |

（无向图不分出度入度，故邻接多重表求度为 O(deg)。）

### 建表时间

| 存储结构 | 建表时间 | 为什么 |
| --- | --- | --- |
| 邻接矩阵 | O(n2+e) | 初始化整张矩阵就要 O(n2) |
| 邻接表 | O(n+e) | n 个表头 + 每条边 O(1) 头插 |
| 十字链表 | O(n+e) | 同上，每条弧做两次 O(1) 头插 |
| 邻接多重表 | O(n+e) | 同上 |

## 易混淆知识点

| 一组概念 | 差别 | 判别依据 |
| --- | --- | --- |
| 十字链表 vs 邻接多重表 | 前者**只用于有向图**，后者**只用于无向图** | 看结点域：有 `tailvex`/`headvex`（分头尾）的是十字链表；有 `ivex`/`jvex`（不分主次）的是邻接多重表 |
| 顶点结点有几个指针 | 十字链表 2 个（firstin、firstout），邻接多重表 1 个（firstedge） | 边有没有方向：有方向才需要分开挂入弧与出弧 |
| `hlink` vs `tlink` | `hlink` 串弧头相同的弧，`tlink` 串弧尾相同的弧 | 首字母对齐：从 `firstin` 出发走 `h`link，从 `firstout` 出发走 `t`link |
| `ilink` vs `jlink` | 指向依附于 `ivex` / `jvex` 的下一条边 | **不能固定选一个**，要看当前顶点是这条边的哪一端 |
| 十字链表 vs 邻接表+逆邻接表 | 前者一份弧结点挂两条链，后者两份独立结点 | 数结点：十字链表 e 个，两张表加起来 2e 个，且需同步维护 |
| 邻接多重表 vs 邻接表（无向） | 边结点 e 个 vs 2e 个 | 问"删一条边要 free 几次"：1 次是多重表，2 次是邻接表 |
| `mark` vs `visited[]` | 前者标记**边**，后者标记**顶点** | 问"防的是哪种重复"：边被两端各处理一次 → mark；顶点被环绕回来 → visited |
| 空间量级 vs 实际域数 | 四种链式结构都是 O(n+e) | 量级相同不代表常数相同：多重表边结点比邻接表边结点多了 mark 与一组指针 |

## 本节小结

学完本篇，你应该能够：

- 判断一道题该用十字链表还是邻接多重表，并说出**判据是"图有没有方向"而不是死记名字**。
- 画出给定有向图的十字链表、给定无向图的邻接多重表，标清每个结点的各个域与每条链的走向。
- 说清十字链表求入度为什么是 O(deg−)，而邻接表是 O(n+e)。
- 写出邻接多重表上"遍历依附于某顶点的所有边"的通用模板，并解释**为什么推进指针必须判端**。
- 说清删边操作在邻接表与邻接多重表上的差别，以及 `mark` 与 `visited[]` 各自防的是哪种重复。

三条最关键的结论：

- **十字链表 = 有向图；邻接多重表 = 无向图。** 前者为求入度而生，后者为"边只存一份"而生。
- **两者的共同设计思想是"一个边/弧结点挂在两条链上"**，因此空间仍是 O(n+e)， 但每次推进都必须先判断"当前顶点是这条边的哪一端"。
- **邻接多重表让删边、标记边、按边遍历都退化成一次操作**，因为分身消失了。

## 教材出处

- 严蔚敏《数据结构（C 语言版）》（第 2 版）**印刷 p158**，§6.4.3： "十字链表(Orthogonal List) 是有向图的另一种链式存储结构。可以看成是将有向图的邻接表 和逆邻接表结合起来得到的一种链表"；同页给出弧结点 5 个域 （`tailvex`、`headvex`、`hlink`、`tlink`、`info`）与顶点结点 3 个域的定义。
- 同书**印刷 p159**：十字链表的 C 语言存储表示 `OLGraph`； "建立十字链表的时间复杂度和建立邻接表是相同的……既容易找到以 vi 为尾的弧， 也容易找到以 vi 为头的弧，因而容易求得顶点的出度和入度"。
- 同书**印刷 p159**，§6.4.4： "在邻接表中每一条边 (vi,vj) 有两个结点，分别在第 i 个和第 j 个链表中， 这给某些图的操作带来不便。例如……对已被搜索过的边作记号或删除一条边等， 此时需要找到表示同一条边的两个结点"——这正是邻接多重表的设计动机。
- 同书**印刷 p160**：边结点 6 个域（`mark`、`ivex`、`ilink`、`jvex`、`jlink`、`info`） 与顶点结点 2 个域；"除了在边结点中增加一个标志域外，邻接多重表所需的存储量和邻接表相同"。
