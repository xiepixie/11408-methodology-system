# 邻接矩阵

## 大纲定位

本篇对应 2026 大纲 **五、图 （二）图的存储及基本操作 1. 邻接矩阵**。

**分工边界**：

- **本篇**负责邻接矩阵这一种结构：定义、C 语言表示、建图、求度、各类基本操作的代价、 矩阵幂的路径计数含义，以及"什么图该选它"的定量依据。

## 知识框架

本节回答四个问题：

- 为什么"顶点信息"和"边信息"要分成两个数组存，不能合成一个？
- 无权图和带权图的邻接矩阵，无边时分别填什么？填 0 和填 ∞ 各自会带来什么后果？
- 邻接矩阵上的每一类操作，代价从哪里来？哪些是 O(1)、哪些必须扫一整行、哪些必须扫全表？
- Ak[i][j] 为什么等于 i 到 j 长度为 k 的路径条数？

## 核心思想：用二维数组直接编码"关系"

图不能用顶点在数组里的位置来表示边（见[图的基本概念](./concepts.html)）， 于是最直接的办法是**开一张 n×n 的表，把"i 与 j 之间有没有边"这件事逐格记下来**。

设 G=(V,E) 有 n 个顶点，其**邻接矩阵**是 n 阶方阵 A：A[i][j]={1,(vi,vj)∈E 或 ⟨vi,vj⟩∈E0,否则

若 G 是网（带权图），则改为：A[i][j]={wi,j,(vi,vj)∈E 或 ⟨vi,vj⟩∈E0,i=j∞,否则

这里的 ∞ 在程序里取一个"比所有边权之和都大"的有限常数（教材记作 `MaxInt`）。

**两个数组，不是一个**：矩阵只记录关系，顶点本身的数据（名字、编号、附加信息）要另开一个 一维顶点表 `vex[n]` 存。矩阵的下标 i 与顶点表下标 i 一一对应，这层对应关系就是 "顶点 → 矩阵下标"的映射。缺了顶点表，你只知道"0 号和 1 号相邻"，却不知道 0 号是谁。

### 无向图示例

```
图:  0 — 1        邻接矩阵:
     |   |          0  1  2  3
     3 — 2        0 [0, 1, 0, 1]
                  1 [1, 0, 1, 0]
                  2 [0, 1, 0, 1]
                  3 [1, 0, 1, 0]
```

**无向图的邻接矩阵一定是对称矩阵**：(vi,vj) 与 (vj,vi) 是同一条边， 所以 A[i][j]=A[j][i] 必然成立。这不是巧合，是无向边"无序顶点对"这个定义的直接后果。

对称性可以换成一半的空间：只存上三角或下三角，共 n(n−1)2 个元素 （不含对角线；含对角线则为 n(n+1)2）。压缩存储的下标换算与 [特殊矩阵的压缩存储](./../stack-queue/special-matrix.html)完全一致。

### 有向图示例

有向图 ⟨0,1⟩, ⟨0,2⟩, ⟨2,1⟩：

```
邻接矩阵:
     0  1  2
  0 [0, 1, 1]
  1 [0, 0, 0]
  2 [0, 1, 0]
```

**有向图的邻接矩阵不一定对称**。A[i][j]=1 只说明有一条 i→j 的弧， A[j][i] 是不是 1 与它无关。

图注：左、中、右三例分别是无向图、含双向弧的有向图、以及一个由两个互不相连的部分组成的 有向图。看右边那张矩阵——它被虚线切成了对角上的两块，块外全是 0。 **一个图有几个互不相通的部分，就能把邻接矩阵重排成几块对角块**，块外恒为 0； 这正是"邻接矩阵按行扫描找不到跨块的边"这一事实的矩阵形态。 图源：殷人昆《数据结构——用面向对象方法与 C++ 描述》（第 2 版）图8.5 图的邻接矩阵表示，p351

## 存储结构与建图
c

```
#define MaxVertexNum 100       // 最大顶点数
#define INFINITY 65535         // 表示无穷大（用于带权图，须大于所有可能的路径长度和）

// 无权图
typedef struct {
    char vex[MaxVertexNum];                     // 顶点表：下标 i ↔ 顶点 i
    int  edge[MaxVertexNum][MaxVertexNum];      // 邻接矩阵（0/1）
    int  vexNum, edgeNum;                       // 顶点数、边数
} MGraph;

// 带权图
typedef struct {
    char vex[MaxVertexNum];
    int  edge[MaxVertexNum][MaxVertexNum];      // 权值，无边时为 INFINITY
    int  vexNum, edgeNum;
} WGraph;
```
c

```
// 初始化无向无权图
void initGraph(MGraph *G, int n) {
    G->vexNum = n;
    G->edgeNum = 0;
    for (int i = 0; i < n; i++)
        for (int j = 0; j < n; j++)
            G->edge[i][j] = 0;          // 无权图用 0 表示"无边"
}

// 添加无向边
void addEdge(MGraph *G, int u, int v) {
    G->edge[u][v] = 1;
    G->edge[v][u] = 1;   // 无向图必须对称赋值：漏掉这一行，从 v 出发就找不到 u
    G->edgeNum++;        // 一条无向边只让 edgeNum 加一次，不是两次
}
```

带权图的初始化与无权图**不同**，是全篇最容易写错的一处：c

```
// 初始化带权图：无边填 INFINITY，对角线填 0
void initWGraph(WGraph *G, int n) {
    G->vexNum = n;
    G->edgeNum = 0;
    for (int i = 0; i < n; i++)
        for (int j = 0; j < n; j++)
            G->edge[i][j] = (i == j) ? 0 : INFINITY;
    // 对角线为 0：顶点到自己的路径长度是 0，这一条被 Floyd 直接依赖，
    // 若填成 INFINITY，Floyd 的第一轮松弛就全废了。
}
```

**为什么无权图填 0、带权图填 ∞**：无权图里矩阵元素表示"有没有边"， 0 是"没有"的自然编码；带权图里元素表示"走过去的代价"， "没有边"意味着代价无穷大，填 0 会被最短路径算法当成"免费直达"。 **同一个 0，在两种矩阵里含义相反**——这是带权图与无权图之间最典型的误用点。

## 度的计算

**无向图**：顶点 i 的度 = 第 i 行（等价地第 i 列）中非零元素的个数。c

```
// 无向图求顶点 i 的度：只需扫一行，因为矩阵对称，扫列结果相同
int degree(MGraph *G, int i) {
    int d = 0;
    for (int j = 0; j < G->vexNum; j++)
        if (G->edge[i][j] != 0)
            d++;
    return d;
}
```

**有向图**：

| 量 | 计算方法 | 代价 |
| --- | --- | --- |
| 出度 OD(i) | 第 i **行**非零元素个数 | O(n) |
| 入度 ID(i) | 第 i **列**非零元素个数 | O(n) |
| 度 TD(i) | OD(i)+ID(i) | O(n) |

c

```
// 有向图一次扫描同时求出度和入度：
// 第 i 行给出度，第 i 列给入度，两者下标互换，可以在同一个循环里取
void directedDegree(MGraph *G, int i, int *outD, int *inD) {
    *outD = *inD = 0;
    for (int j = 0; j < G->vexNum; j++) {
        if (G->edge[i][j] != 0) (*outD)++;  // 第 i 行 → 以 i 为弧尾 → 出度
        if (G->edge[j][i] != 0) (*inD)++;   // 第 i 列 → 以 i 为弧头 → 入度
    }
}
```

**邻接矩阵求入度只要 O(n)**，这一点是它相对邻接表的实质优势—— 邻接表求入度必须遍历整张表，代价 O(n+e)。十字链表就是为了在链式结构上补回这一条而设计的。

## 完整走查：从矩阵读出一切

给出一个 5 顶点带权**有向图**的邻接矩阵（∞ 表示无弧）：

|  | v0 | v1 | v2 | v3 | v4 |
| --- | --- | --- | --- | --- | --- |
| **v0** | 0 | 3 | ∞ | 7 | ∞ |
| **v1** | ∞ | 0 | 2 | ∞ | ∞ |
| **v2** | ∞ | ∞ | 0 | 4 | 1 |
| **v3** | ∞ | ∞ | ∞ | 0 | 5 |
| **v4** | ∞ | ∞ | ∞ | ∞ | 0 |

**① 有多少条弧？** 数非对角线的非 ∞ 元素： 第 0 行 2 个、第 1 行 1 个、第 2 行 2 个、第 3 行 1 个、第 4 行 0 个，共 **6 条弧**。 *注意有向图不用除以 2，无向图才要。*

**② 各顶点的出度、入度？**

| 顶点 | 出度（数第 i 行） | 入度（数第 i 列） | 度 |
| --- | --- | --- | --- |
| v0 | 2（到 v1,v3） | 0 | 2 |
| v1 | 1（到 v2） | 1（来自 v0） | 2 |
| v2 | 2（到 v3,v4） | 1（来自 v1） | 3 |
| v3 | 1（到 v4） | 2（来自 v0,v2） | 3 |
| v4 | 0 | 2（来自 v2,v3） | 2 |

**自检**：出度之和 =2+1+2+1+0=6，入度之和 =0+1+1+2+2=6， 两者相等且等于弧数 ✓（见[图的基本概念](./concepts.html)）。

**③ 这个矩阵为什么不对称？** 因为图是有向的。若把它当成无向图的矩阵读， 就会把 6 条弧误读成 6 条无向边、把出入度合并——**读矩阵前先看它对不对称，这是第一步**。

**④ 它是不是 DAG？** 矩阵是**严格上三角**的（所有非 ∞ 的非对角元都在对角线右上方）， 说明所有弧都从小编号指向大编号，**不可能绕回来**，所以一定无环。 反过来说，**一个有向图是 DAG 当且仅当存在一种顶点编号方式，使其邻接矩阵成为严格上三角矩阵**—— 这种编号方式正是[拓扑排序](./topological-sort.html)给出的拓扑序列。

**⑤ 顶点 v0 到 v4 有几条路径？各多长？**v0→v3→v4 长 7+5=12；v0→v1→v2→v4 长 3+2+1=6； v0→v1→v2→v3→v4 长 3+2+4+5=14。共 3 条，最短的是 6 （这一问的一般解法见 [Dijkstra](./dijkstra.html)）。

## 矩阵幂：路径条数

**结论**：Ak[i][j] 等于从 vi 到 vj、**长度恰好为 k** 的路径条数（路径允许重复顶点）。

**推导（对 k 归纳）**：k=1 时 A1=A，A[i][j] 就是长度为 1 的路径（即边）的条数，成立。 设 Ak−1[i][t] 已经是 i→t 长度 k−1 的路径条数，那么Ak[i][j]=∑t=0n−1Ak−1[i][t]⋅A[t][j]

右边的含义是：把长度为 k 的路径按"倒数第二个顶点是谁"分类，若倒数第二个顶点是 t， 则这类路径的条数 = (i 到 t 长度 k−1 的条数) × (t 到 j 有没有边)。 对所有 t 求和不重不漏，正是矩阵乘法的定义。∎

**算例**：取上面那个 4 顶点无向图（0−1,1−2,2−3,3−0，即一个四元环）：A=(0101101001011010)A2=(2020020220200202)A3=(0404404004044040)

逐格核对：A2[0][0]=2——从 0 出发走两步回到 0，路径是 0→1→0 与 0→3→0， 确实 2 条。A2[0][2]=2——0→1→2 与 0→3→2，确实 2 条。 A2[0][1]=0——四元环是二部图，不存在长度为偶数的 0→1 路径，与 [图的基本概念](./concepts.html)里"二部图无奇回路"的染色论证一致。

这个结论几乎不需要真的去算 Ak（O(n3) 一次乘法太贵），它的价值在于**解释**： 让你看懂"邻接矩阵是一个可以做代数运算的对象"，而 Floyd 的三重循环正是同一类"矩阵逐步合成" 的思路（区别是 Floyd 把加法换成 min、乘法换成加法）。

## 各类操作的代价从哪里来

| 操作 | 时间复杂度 | 代价的来历 |
| --- | --- | --- |
| 判断 (vi,vj) 是否为边 | O(1) | 一次二维数组下标访问，与图的规模无关 |
| 插入 / 删除一条边 | O(1) | 改一个（无向图两个）矩阵元素 |
| 求某顶点的度 | O(n) | 必须扫完一整行才知道哪些位置非零 |
| 求某顶点的全部邻接点 | O(n) | 同上；即使该顶点只有 1 条边，也要扫 n 格 |
| 统计边数 | O(n2) | 非零元素散落在整张表里，只能全表扫描 |
| 插入 / 删除一个顶点 | O(n2) | 要挪动矩阵的行与列 |
| DFS / BFS 全图遍历 | O(n2) | 每个顶点各扫一行找邻接点，n 个顶点共 n×n 格 |

**空间复杂度 O(n2)，与边数完全无关**——这是邻接矩阵的核心特征，也是它的核心代价： 一个 1000 个顶点、只有 2000 条边的图，邻接矩阵要 106 个格子，其中 99.6% 是 0。

**适用场景的定量判据**：当 e 与 n2 同量级（稠密图）时，邻接矩阵的 O(n2) 空间没有浪费， 而且换来了 O(1) 判边；当 e≪n2（稀疏图）时应改用[邻接表](./adjacency-list.html)。

## 易混淆知识点

**1. 判断"两个顶点是否相邻"，邻接矩阵 O(1)、邻接表 O(n)，差别的根在哪？**

判据是：**这条信息是"被直接寻址"的，还是"要被搜索"的**。 邻接矩阵把 (i,j) 这对下标直接映射成一个内存地址，所以是查表； 邻接表把顶点 i 的所有邻居串成一条链，要判 j 在不在里面就得走一遍链， 最坏情况链长为 n−1。

**2. 邻接矩阵 vs 邻接表：完整对照**

| 对比维度 | 邻接矩阵 | 邻接表 | 判别依据 |
| --- | --- | --- | --- |
| 空间 | O(n2)，与 e 无关 | O(n+e) | 边稠密到什么程度：e 接近 n2 选矩阵 |
| 判两点是否相邻 | O(1) | O(deg⁡(v))，最坏 O(n) | 是否需要频繁随机判边 |
| 求某顶点全部邻接点 | O(n)（必扫整行） | O(deg⁡(v))（只走自己的链） | 顶点的度是否远小于 n |
| 求无向图顶点的度 | O(n) | O(deg⁡(v)) | 同上 |
| 求有向图的**入度** | O(n)（扫一列） | O(n+e)（必须遍历全表） | **这是十字链表存在的理由** |
| 统计边数 | O(n2) | O(n+e) | 邻接表按顶点顺序扫一遍即可 |
| 增删边 | O(1) | 插入 O(1)，删除 O(deg⁡(v)) | 链表删除要先找到前驱 |
| 增删顶点 | O(n2) | O(1) 增 / O(n+e) 删 | 矩阵要挪行挪列 |
| 遍历全图（DFS/BFS） | O(n2) | O(n+e) | 见[DFS](./dfs.html)与[BFS](./bfs.html)的复杂度推导 |
| 表示是否唯一 | **唯一** | **不唯一**（链上结点次序取决于建表次序） | 由此导致遍历序列的唯一性也不同 |

**3. 带权图矩阵里的 0 和 ∞，什么时候各写哪个？**

判据只有一句：**问自己这一格表示的是"有无"还是"代价"**。

- 对角线 A[i][i]：顶点到自己代价为 0，写 **0**。
- 无边的 A[i][j]（i≠j）：代价无穷，写 **∞**。
- 权值恰好为 0 的边：写 **0**，此时"0"与"对角线的 0"含义一致（代价为 0）， 但与"无边"必须能区分开——所以带权图**不能**用 0 表示无边。

**4. 无向图矩阵能压缩成一半，为什么有向图不能？**

判据是对称性。无向图 A[i][j]=A[j][i] 恒成立，上三角已经包含全部信息； 有向图 A[i][j] 与 A[j][i] 是两条不同的弧，各存各的，不能省。

**5. 邻接矩阵的表示唯一，为什么？**

因为一旦确定了"顶点 → 下标"的编号，矩阵的每一格都被图唯一决定，没有任何自由度。 邻接表则不然：同一个顶点的边链表可以是任意顺序，建表次序不同表就不同。 **这个差别会一路传导到遍历序列的唯一性**（见[DFS](./dfs.html)）。

## 本节小结

学完本篇，你应该能够：

- 给出一个图（有向 / 无向 / 带权），**当场写出它的邻接矩阵**，并正确处理对角线与无边格。
- 从矩阵反推图的性质：由对称性判有向无向、由行和列分别求出度入度、由非零元个数求边数 （无向图要除以 2）。
- 用 C 语言写出邻接矩阵的类型定义、初始化与建边，并说清"无向图为什么要对称赋值" "带权图为什么不能用 0 表示无边"。
- 说清每一类操作代价的来历，据此在**具体的 n 与 e** 下给出选型建议，而不是背"稠密用矩阵"。
- 解释 Ak[i][j] 的组合含义，并用小规模矩阵验证。

三条最关键的结论：

- **空间 O(n2) 与边数无关**——这既是邻接矩阵的优点（判边 O(1)）也是它的缺点（稀疏图浪费）。
- **无向图矩阵必对称**，可压缩到 n(n−1)2；有向图行和 = 出度、列和 = 入度。
- **求有向图的入度：邻接矩阵 O(n)，邻接表 O(n+e)**——这条差距是[十字链表](./cross-list.html)的设计动机。

- [特殊矩阵的压缩存储](./../stack-queue/special-matrix.html)：无向图矩阵压缩用的就是对称矩阵那一套下标换算
- [Dijkstra 算法](./dijkstra.html)：朴素实现直接基于邻接矩阵，复杂度 O(n2)
- [Floyd 算法](./floyd.html)：整个算法就是在邻接矩阵上做三重循环的"矩阵逐步合成"
- [Prim 算法](./prim.html)：朴素实现同样以邻接矩阵为前提
