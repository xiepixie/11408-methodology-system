# 广度优先搜索（BFS）

## 大纲定位

本篇对应 2026 大纲 **五、图 （三）图的遍历 2. 广度优先搜索**。

**分工边界**：

- **本篇**负责 BFS 本身：队列驱动的机制、两种存储结构下的复杂度来历、BFS 生成树与它的层次性质、 遍历序列的不唯一性、以及"为什么必须在入队时置 `visited`"。
- **DFS** 是同一条大纲下的第 1 小项，见 [DFS](./dfs.html)。 **DFS 与 BFS 的完整对照表放在 [DFS](./dfs.html) 那一篇的《易混淆知识点》**，本篇不再重复。
- **BFS 求无权图最短路径**属五（四）2 最短路径，是 BFS 的应用而非遍历本身， 完整讲解（d[]、path[]、正确性证明、路径还原）在 [BFS 最短路径](./bfs-shortest.html)； 本篇只给出"BFS 树上根到各点的路径就是最短路径"这条性质及其一句话理由。
- **拓扑排序**的 Kahn 算法用的是同一套队列框架，但属五（四）3，见[拓扑排序](./topological-sort.html)。

## 知识框架

本节回答四个问题：

- 换一个队列就把"深入"变成了"逐层"，队列到底做了什么？
- BFS 的时间复杂度与 DFS 完全相同，为什么？两者的差别只体现在哪里？
- `visited` 应该在**入队时**置位还是**出队时**置位？置错会怎样？
- BFS 生成树有一条 DFS 树没有的性质——原图的每条边最多跨越一层，为什么？

## 核心思想：一圈一圈往外扩

BFS 的策略是：**先访问起点，再访问它的全部邻接点，然后访问这些邻接点的全部未访问邻接点， 依此类推。** 类比是水波扩散——石子落点是起点，波纹一圈圈向外推。

要做到"先访问的顶点，其邻接点也先被访问"，就必须记住"哪些顶点已经访问过、但它们的邻居还没展开"， 并且**按记录的先后次序**去展开。这正是**队列（FIFO）**的语义。

**把队列换成栈，同一份代码就变成了 DFS。** 这句话说明：遍历的"策略"不在算法骨架里， 而在辅助容器的取出顺序里。BFS 与 DFS 的代码框架几乎一模一样， 差别只有"下一个展开谁"这一条。

三个要素：

- **队列**：保存已访问、但邻接点尚未全部展开的顶点。
- **`visited[]`**：防止顶点重复入队。图中有环，没有它会死循环。
- **层次**：从起点出发，第 k 层的顶点距离起点恰好 k 条边。

```
层次 0:  v₀
层次 1:  v₁  v₂  v₃      （v₀ 的邻接顶点）
层次 2:  v₄  v₅           （层次 1 顶点的未访问邻接顶点）
...
```

## 算法步骤

- 访问起始顶点 v，置 `visited[v] = true`，将 v 入队。
- 队列非空时循环：

- 队头顶点 u 出队；
- 依次检查 u 的每个邻接点 w：若 `visited[w] == false`，则访问 w、 置 `visited[w] = true`、把 w 入队。
- 队列为空时，从 v 出发可达的所有顶点均已访问。

对**非连通图**，一次 BFS 只能访问一个连通分量。 需要在外层循环遍历所有顶点，对仍未访问的顶点再次启动 BFS—— **启动次数 = 无向图连通分量个数**，与 DFS 完全相同。

⚠️ **`visited[w] = true` 必须与"入队"同时发生，不能等到 w 出队时才置。** 反例：图 0−1, 0−2, 1−2。若出队时才置位：0 出队 → 1、2 都入队（此时都未置位）； 1 出队置位 → 检查邻居 2，2 仍未置位 → **2 再次入队**；队列里出现两个 2， 顶点被访问两次。在稠密图上这种重复会指数级放大。 **"入队即置位"是 BFS 的硬纪律**，对应 DFS 的"访问即置位"。

## 邻接矩阵实现
c

```
#define MAX_VERTEX 100

int visited[MAX_VERTEX];
int Graph[MAX_VERTEX][MAX_VERTEX];   // 邻接矩阵
int n;                                // 顶点数

void BFS(int v) {
    int queue[MAX_VERTEX], front = 0, rear = 0;
    printf("%d ", v);        // 访问起始顶点
    visited[v] = 1;
    queue[rear++] = v;       // 入队与置位同时完成
    while (front != rear) {
        int u = queue[front++];              // 出队
        for (int w = 0; w < n; w++) {        // 扫一整行才能找齐 u 的邻接点
            if (Graph[u][w] == 1 && !visited[w]) {
                printf("%d ", w);
                visited[w] = 1;
                queue[rear++] = w;
            }
        }
    }
}

// 遍历整个图（处理非连通图）
void BFSTraverse(void) {
    for (int i = 0; i < n; i++)
        visited[i] = 0;
    for (int i = 0; i < n; i++) {
        if (!visited[i])
            BFS(i);
    }
}
```

**这个顺序队列不会溢出，也不需要循环队列。** 因为"入队即置位"保证了 **每个顶点最多入队一次**，所以 `rear` 最大只到 n，容量 `MAX_VERTEX` 够用。 如果把置位挪到出队时，这个前提就不成立了，`rear` 会越界—— 这是上一节那条纪律在代码层面的又一处后果。

**复杂度 O(n2) 的来历**：每个顶点入队一次、出队一次，共 O(n) 次出队； 每次出队后的 for 循环固定跑 n 次（不管该顶点有几个邻居）。故 n×n=O(n2)。

## 邻接表实现
c

```
typedef struct ArcNode {
    int adjvex;              // 邻接顶点编号
    struct ArcNode *next;
} ArcNode;

typedef struct {
    int data;                // 顶点数据
    ArcNode *first;          // 边链表头指针
} VNode;

VNode AdjList[MAX_VERTEX];

void BFS_AdjList(int v) {
    int queue[MAX_VERTEX], front = 0, rear = 0;
    printf("%d ", v);
    visited[v] = 1;
    queue[rear++] = v;
    while (front != rear) {
        int u = queue[front++];
        ArcNode *p = AdjList[u].first;
        while (p != NULL) {                  // 只走 u 自己的边链表
            int w = p->adjvex;
            if (!visited[w]) {
                printf("%d ", w);
                visited[w] = 1;
                queue[rear++] = w;
            }
            p = p->next;                     // 推进必须在 if 之外，否则死循环
        }
    }
}
```

**复杂度 O(n+e) 的来历**，与 DFS 的拆法完全一致：

- **顶点部分**：每个顶点入队一次、出队一次，固定开销 O(1)，共 O(n)； 外层 `BFSTraverse` 的扫描也是 O(n)。
- **边部分**：每个边结点在整个过程中被检查恰好一次（它挂在某个顶点的链上， 而那个顶点只被出队展开一次）。有向图 e 个边结点，无向图 2e 个，都是 O(e)。

相加得 O(n+e)。**BFS 与 DFS 时间复杂度完全相同**，因为两者对"顶点"和"边"的访问次数一模一样， 只是次序不同。

## 完整走查：BFS 序列与层次

仍取 [DFS](./dfs.html) 那篇用过的无向图（顶点 0∼6），便于对照：E={(0,1),(0,2),(1,3),(1,4),(2,5),(2,6),(4,5)}

邻接表按编号升序：

| 顶点 | 边链表 |
| --- | --- |
| 0 | 1 → 2 |
| 1 | 0 → 3 → 4 |
| 2 | 0 → 5 → 6 |
| 3 | 1 |
| 4 | 1 → 5 |
| 5 | 2 → 4 |
| 6 | 2 |

从顶点 0 出发：

| 步 | 出队顶点 | 检查其邻居 | 新入队 | 队列状态（出队后） | 已输出 |
| --- | --- | --- | --- | --- | --- |
| 0 | — | — | 0 |  | 0 |
| 1 | 0 | 1, 2 | 1, 2 |  | 0 1 2 |
| 2 | 1 | 0(已), 3, 4 | 3, 4 |  | 0 1 2 3 4 |
| 3 | 2 | 0(已), 5, 6 | 5, 6 |  | 0 1 2 3 4 5 6 |
| 4 | 3 | 1(已) | — |  | 0 1 2 3 4 5 6 |
| 5 | 4 | 1(已), 5(已) | — |  | 0 1 2 3 4 5 6 |
| 6 | 5 | 2(已), 4(已) | — |  | 0 1 2 3 4 5 6 |
| 7 | 6 | 2(已) | — |  | 0 1 2 3 4 5 6 |

**BFS 序列：0 1 2 3 4 5 6**，层次划分为L0={0},L1={1,2},L2={3,4,5,6}

**与 DFS 的对照**：同一张图、同一个起点、同一份邻接表， DFS 序列是 **0 1 3 4 5 2 6**，BFS 序列是 **0 1 2 3 4 5 6**。 DFS 在第 2 步就一头扎到 3 号顶点（离起点 2 条边），BFS 则把离起点 1 条边的顶点全部处理完才往下走。

**序列的不唯一性**：BFS 序列同样取决于起点与邻接点的检查次序。 若把顶点 0 的链改成 `2 → 1`、顶点 1 的链改成 `4 → 3 → 0`、顶点 2 的链改成 `6 → 5 → 0`， 得到的 BFS 序列是 **0 2 1 6 5 4 3**——层次划分不变（L1={1,2}、L2={3,4,5,6}）， 但同层内部的次序变了。

**层次划分是唯一的，同层内部的次序不唯一。** 这是 BFS 比 DFS 稳定的地方， 也正是它能拿来求最短路径的根据：距离由层号决定，与同层内部次序无关。 用邻接矩阵存储时按下标扫行，起点确定后序列唯一。

## BFS 生成树与它的层次性质

把**所有"引起顶点首次被访问"的边**挑出来，加上全部顶点，得到 **BFS 生成树**。 非连通图上每个连通分量各产生一棵，合称 **BFS 生成森林**。

上例的 BFS 树边为 (0,1),(0,2),(1,3),(1,4),(2,5),(2,6)，共 6=n−1 条； 唯一的非树边是 (4,5)。

**性质一：树上从根到任一顶点的路径，就是原图中从根到该顶点边数最少的路径。** 一句话理由：顶点 w 首次被访问时是从某个第 k 层顶点展开出来的，所以它在第 k+1 层； 而 BFS 是把第 k 层全部处理完才处理第 k+1 层的，若存在更短的路径，w 早就该在更早的层出现。 完整证明与 d[]/path[] 的实现见 [BFS 最短路径](./bfs-shortest.html)。

**性质二（DFS 树没有的）：无向图中任意一条边的两个端点，层号之差不超过 1。**∀(u,v)∈E:|d(u)−d(v)|≤1

**为什么**：设 d(u)=k。当 u 出队展开时，v 要么早已被访问（层号 ≤k）， 要么就在这一刻被访问，层号 =k+1。两种情况都满足 d(v)≤k+1； 对称地 d(u)≤d(v)+1。所以差不超过 1。∎

上例的非树边 (4,5)：d(4)=d(5)=2，差为 0，符合。

这条性质是 BFS 树"扁宽"、DFS 树"细长"的形式化表述： **BFS 树上不存在跨越两层及以上的原图边**，而 DFS 树上非树边可以连接很远的祖先与后代。

由性质二可以直接得到**二部图的 BFS 判定法**：跑一遍 BFS 求出每个顶点的层号 d(v)， 然后检查每条边——

- 若**每条边**的两端层号奇偶性都不同（即差恰为 1），按层号奇偶把顶点分成两组就是一个合法二分， 图是二部图；
- 若存在**同层边** (u,v)（d(u)=d(v)=k），则"根→u"（k 条边）+ 边 (u,v) + "v→根"（k 条边）构成一条长度为 2k+1 的**奇数长度闭合回路**， 由此图中必含奇环，**不是二部图**（判定定理见[图的基本概念](./concepts.html)）。

上例的同层边 (4,5) 就说明这个图不是二部图：0−1−4−5−2−0 正是一个长度为 5 的奇环。

图注：左图顶点旁的数字是访问次序，虚线把顶点按"距起点的层"切开—— 一层处理完才推进到下一层，虚线就是波纹的形状。右图是把"首次到达"用的那些边抽出来构成的 BFS 树。与 [DFS](./dfs.html) 那篇同一张原图的 DFS 树对比：这里 A 直接连着 B,C,D 三个孩子， 树很矮很宽；DFS 树则是一条长链。**同一个图，两种遍历给出形状完全不同的生成树。** 图源：殷人昆《数据结构——用面向对象方法与 C++ 描述》（第 2 版）图8.13 广度优先搜索示例，p366

## 两个直接应用

### 1. 求连通分量个数（非连通图的完整遍历）
c

```
int countComponents(void) {
    for (int i = 0; i < n; i++) visited[i] = 0;
    int cnt = 0;
    for (int i = 0; i < n; i++)
        if (!visited[i]) { BFS(i); cnt++; }   // 每启动一次 BFS 就多一个分量
    return cnt;
}
```

**走查**：设图有 7 个顶点，边为 (0,1),(1,2),(3,4),(5,6)。 外层循环：i=0 未访问 → `BFS(0)` 访问 {0,1,2}，`cnt=1`； i=1,2 已访问，跳过；i=3 → `BFS(3)` 访问 {3,4}，`cnt=2`； i=5 → `BFS(5)` 访问 {5,6}，`cnt=3`。**连通分量数 = 3。**

同时得到 **BFS 生成森林**：三棵树的边分别是 {(0,1),(1,2)}、{(3,4)}、{(5,6)}， 共 4 条边 =n−k=7−3，与[图的基本概念](./concepts.html)里"生成森林有 n−k 条边"一致 ✓。

⚠️ 这条**只对无向图成立**。有向图上外层循环启动 BFS 的次数与强连通分量个数没有对应关系。

### 2. 判定二部图

把前面那条"任意边跨层不超过 1"的性质落成代码：给每个顶点染一个色（用层号的奇偶）， 再检查有没有同色的边。c

```
int color[MAX_VERTEX];      // -1 未染色；0 / 1 两种颜色

// 返回 1 表示是二部图。对非连通图要对每个分量各跑一次
int isBipartite(int n) {
    for (int i = 0; i < n; i++) color[i] = -1;
    int queue[MAX_VERTEX];

    for (int s = 0; s < n; s++) {
        if (color[s] != -1) continue;       // 该分量已处理过
        int front = 0, rear = 0;
        color[s] = 0;
        queue[rear++] = s;
        while (front != rear) {
            int u = queue[front++];
            ArcNode *p = AdjList[u].first;
            while (p != NULL) {
                int w = p->adjvex;
                if (color[w] == -1) {
                    color[w] = 1 - color[u];   // 相邻必异色 → 层号奇偶交替
                    queue[rear++] = w;
                } else if (color[w] == color[u]) {
                    return 0;                  // 同色边 → 存在奇环 → 不是二部图
                }
                p = p->next;
            }
        }
    }
    return 1;
}
```

**两处要点**：

- **外层的 `for (s)` 循环不能省**。二部图判定要对**每个连通分量**各做一次， 否则非连通图只判了一部分。
- **`else if (color[w] == color[u])` 里的 `else` 不能丢**。 w 已染色时才需要检查冲突；刚染上的色必然是异色，重复检查是多余的。

用本篇走查那张图跑：color[0]=0；1,2 染 1；3,4,5,6 染 0。 检查边 (4,5)：两端都是 0，**同色** → 返回 0，不是二部图 ✓ （与前面找到的奇环 0−1−4−5−2−0 一致）。

## 复杂度分析

| 存储方式 | 时间复杂度 | 来历 |
| --- | --- | --- |
| 邻接表 | O(n+e) | 每个顶点入队/出队各一次（O(n)）+ 每个边结点被检查一次（O(e)） |
| 邻接矩阵 | O(n2) | 每个顶点出队一次，每次都要扫一整行 n 格 |

**空间复杂度 O(n)**，两部分：

- `visited[]`：O(n)，与图形态无关。
- **辅助队列**：因为"入队即置位"，每个顶点最多入队一次，队列长度上界为 n。 最坏情形是**星形图**（一个中心顶点连着其余 n−1 个顶点）：从中心出发， 第一步就把 n−1 个顶点全压进队列，队列长度达到 n−1。

**BFS 与 DFS 空间同为 O(n)，但最坏形态相反**： BFS 在"扁"的图（星形）上队列最长，DFS 在"长"的图（链形）上递归最深。 这也是为什么在很深但分支很少的图上 BFS 更省空间，在很宽但很浅的图上 DFS 更省空间。

## 易混淆知识点

**1. `visited` 在入队时置还是出队时置？**

判据：**问"两次入队之间，有没有机会再次通过检查"**。 出队时才置位，意味着一个顶点在队列里等待期间仍是"未访问"状态， 它的其他邻居出队时会再次把它入队。所以必须**入队即置位**。 （DFS 对应的纪律是"访问即置位、递归之前置位"，见 [DFS](./dfs.html)。）

**2. BFS 序列唯一吗？层次划分唯一吗？**

- **序列不唯一**：起点不同、邻接点检查次序不同都会改变序列。
- **层次划分唯一**：d(v) 是图的固有量（从起点到 v 的最短边数），与遍历实现无关。

判据是：**这个量是不是只由"图 + 起点"决定**。层号是，序列不是。

**3. BFS 能求带权图最短路径吗？**

不能。BFS 的"最短"指的是**边数最少**。带权图里"边最少"与"权和最小"是两回事。 反例：0→1 权 100，0→2 权 1，2→1 权 1。 BFS 认为 0→1 是最短（1 条边），但真正的最小权路径是 0→2→1（权和 2）。 带权图必须用 [Dijkstra](./dijkstra.html)。

**4. BFS 与树的层序遍历有什么区别？**

层序遍历是 BFS 在树上的**特例**。差别只有一处：树里不存在环，一个结点不可能从两条路径到达， 所以层序遍历**不需要 `visited[]`**。图有环，必须有。 见[二叉树的层序遍历](./../tree/level-order-traversal.html)。

**5. 用 BFS 统计连通分量，和用 DFS 统计有区别吗？**

没有区别，都等于外层循环启动遍历的次数。这条**只对无向图成立**—— 有向图上启动次数与强连通分量个数无关。

- 独立推出 O(n+e) 与 O(n2) 两个复杂度，并解释 BFS 与 DFS 时间同阶、空间来源不同的原因。
- 画出 BFS 生成树，指出非树边，并用"任意边跨层不超过 1"这条性质检验自己的画法。
- 说清 BFS 求最短路径的适用边界：只适用于无权图（或所有边权相等的图）。

三条最关键的结论：

- **队列 → 逐层扩展**；把队列换成栈就变成 DFS，算法骨架不变。
- **`visited` 必须在入队时置位**，这同时保证了正确性与"每个顶点最多入队一次"。
- **层次划分唯一、序列不唯一**；BFS 树上任意一条原图边的两端层号之差不超过 1。
