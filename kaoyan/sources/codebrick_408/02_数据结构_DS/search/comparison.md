## 知识框架

本节回答 4 个问题：

- **所有查找方法能不能放进一个统一的坐标系？坐标轴是哪几根？**
- **给一个场景，按什么顺序问问题才能唯一定位到一种方法？**
- **各方法的 ASL 与失败 ASL 的分母，为什么长得那么不一样？**
- **散列查找"最快"，为什么还需要那么多别的方法？**

## 三条技术路线的总账

前八条大纲条目里的方法，只走了三条路：

| 路线 | 缩小候选范围的手段 | 代表方法 | 保留全序？ | 支持动态增删？ |
| --- | --- | --- | --- | --- |
| **线性表** | 靠关键字比较，每次排除一部分 | 顺序、折半、分块 | 折半/分块要求（部分）有序 | 顺序、分块可以；**折半不行** |
| **树表** | 把"排除一半"固化成树的分支，且可随增删调整 | BST、AVL、红黑树、B 树、B+ 树 | 是（中序遍历有序） | **全部支持** |
| **散列表** | 由关键字直接算出地址，一步到位 | 拉链法、开放定址法 | **否** | 支持（开放定址法删除受限） |

**一句话总结这三条路的取舍**：

**线性表用简单换效率，树表用空间和维护代价换动态性，散列表用有序性换速度。**

**字符串模式匹配**（大纲六（八））在这个坐标系里是特殊的一条： 它的"查找对象"不是一个关键字而是**一个子串**，比较的单位是字符而不是关键字， 因此不适用 ASL 那一套度量，也不在本篇的对比表内。 算法见[《BF 算法》](./../string/bf.html)与[《KMP 算法》](./../string/kmp.html)。

## 总表：适用条件 · ASL · 有序性 · 动态性

这是本篇的核心表。四栏分别对应选型时要问的四个问题。

| 查找方法 | 存储结构要求 | 是否要求有序 | 平均查找长度 | 支持动态增删 | 展开 |
| --- | --- | --- | --- | --- | --- |
| **顺序查找（无序表）** | 顺序表或链表均可 | 否 | 成功 n+12；失败 n 或 n+1 | ✅ 直接追加 | [→](./sequential-search.html) |
| **顺序查找（有序表）** | 顺序表或链表均可 | 是 | 成功 n+12；失败 n2+nn+1 | ⚠️ 要维持有序，插入需移动 | [→](./sequential-search.html) |
| **折半查找** | **必须顺序表**（要随机访问） | **必须有序** | 成功 ≈log2⁡(n+1)−1；失败 ≈log2⁡(n+1) | ❌ **不支持** | [→](./binary-search.html) |
| **分块查找** | 顺序表 + 索引表 | **块间**有序，块内无序 | 顺序索引 b+12+s+12，最优 n+1 | ✅ 块内随便放 | [→](./block-search.html) |
| **二叉排序树（BST）** | 二叉链表 | 中序有序 | 平均 O(log2⁡n)；**最坏 O(n)**（退化成单支树） | ✅ | [→](./../tree/bst.html) |
| **平衡二叉树（AVL）** | 二叉链表 + 平衡因子 | 中序有序 | O(log2⁡n)，**最坏也是** | ✅（插删可能触发旋转） | [→](./../tree/avl.html) |
| **红黑树** | 二叉链表 + 颜色位 | 中序有序 | O(log2⁡n)，树高 ≤2log2⁡(n+1) | ✅（插删的调整次数比 AVL 少） | [→](./../tree/rbt.html) |
| **B 树** | 多路平衡查找树（外存） | 是 | O(log⌈m/2⌉⁡n) 次磁盘 I/O | ✅（分裂/合并） | [→](./b-tree.html) |
| **B+ 树** | 多路平衡树 + 叶结点链表 | 是 | 同上，且**路径长度恒定** | ✅ | [→](./b-plus-tree.html) |
| **散列查找（拉链法）** | 指针数组 + 同义词链表 | **否** | 取决于 α：成功 ≈1+α2 | ✅ **删除最方便** | [→](./hash-chaining.html) |
| **散列查找（开放定址）** | 一维数组 | **否** | 取决于 α，须 α<1 | ⚠️ 删除只能打墓碑 | [→](./hash-open-addressing.html) |

⚠️ **表里三处最容易记错的**：

- **有序表的顺序查找，成功 ASL 与无序表相同**（都是 n+12）—— 有序性只能帮你"提前放弃"，帮不了"提前找到"；
- **折半查找是唯一一个"不支持动态"的**——不是算法不支持插入， 而是顺序有序表的插入代价 O(n) 会吃掉 O(log⁡n) 的查找收益；
- **BST 的最坏是 O(n)**，AVL / 红黑树 / B 树的最坏都是对数级—— 这正是"为什么需要平衡"的答案。

### 失败 ASL 的分母：一张对照表

各方法的失败 ASL 分母**互不相同**，这是本章最集中的错误来源。判据只有一条： **数一数有多少个互不等价的失败入口**（详见[《查找基本概念》](./concepts.html)）。

| 查找方法 | 失败入口是什么 | 分母 |
| --- | --- | --- |
| 顺序查找（无序表） | 只有一种（扫完全表） | 不需求平均 |
| 顺序查找（有序表） | n 个关键字切出的开区间 | n+1 |
| 折半查找 | 判定树的外部结点 | n+1 |
| 二叉排序树 | BST 的空指针位置 | n+1 |
| 分块查找 | 由索引查找法与块内查找法共同决定 | 按定义逐入口数 |
| **散列查找** | **散列函数的值域**（能作为查找起点的地址） | **值域大小**（除留余数法即 p，**不是表长 m、更不是 n**） |

## ASL 汇总与来历

**成功 ASL 的分母永远是元素个数 n**，各方法的差别全在分子上。

| 查找方法 | 成功 ASL | 失败 ASL | **怎么来的** |
| --- | --- | --- | --- |
| 顺序查找（无序） | n+12 | n（无监视哨）/ n+1（有监视哨） | 第 i 个元素比 i 次，1n∑i=n+12 |
| 顺序查找（有序） | n+12 | n2+nn+1 | 失败分子是 (1+2+⋯+n)+n，最后一段区间只比 n 次 |
| 折半查找 | n+1nlog2⁡(n+1)−1≈log2⁡(n+1)−1 | ≈log2⁡(n+1) | 满二叉判定树 1n∑j=1hj⋅2j−1 求和 |
| 分块查找（顺序索引） | b+12+s+12=s2+2s+n2s | 逐入口累加 | 两段查找串联；s=n 时取最小值 n+1 |
| 分块查找（折半索引） | ≈log2⁡(ns+1)+s2 | 逐入口累加 | 索引段换成折半的平均比较次数 |
| BST 查找 | 平均 O(log2⁡n)，最坏 O(n) | 同量级 | 比较次数 = 结点层数；树形由插入顺序决定 |
| AVL 查找 | O(log2⁡n) | O(log2⁡n) | 高度受最少结点数递推 Nh=Nh−1+Nh−2+1 约束，见[《平衡二叉树》](./../tree/avl.html) |
| 红黑树查找 | O(log2⁡n) | O(log2⁡n) | 树高 ≤2log2⁡(n+1)，见[《红黑树》](./../tree/rbt.html) |
| B 树 / B+ 树 | O(log⌈m/2⌉⁡n) 次 I/O | 同量级 | 树高上下界见[《B 树》](./b-tree.html) |
| 散列查找 | 取决于 α 与冲突处理方法 | 通常大于成功 ASL | 见下表 |

### 散列查找的理论 ASL

设装填因子 α=nm：

| 冲突处理方法 | 查找成功 ASL | 查找失败 ASL |
| --- | --- | --- |
| 线性探测法 | 12(1+11−α) | 12(1+1(1−α)2) |
| 平方探测 / 伪随机探测 | −1αln⁡(1−α) | 11−α |
| 链地址法（拉链法） | 1+α2 | α+e−α |

**三条能从公式直接读出的结论**：

- **散列表的 ASL 只与 α 有关，与 n 无关**——这就是"接近 O(1)"的准确含义， 前提是把 α 控制住；
- **线性探测的失败 ASL 分母是 (1−α)2**，恶化得最快，这是堆积的量化代价；
- **拉链法的公式里没有 11−α**，所以 α≥1 时仍然有意义， 而开放定址法在 α→1 时发散。

⚠️ **题目给了具体的表就必须直接计算，不许套这张表的公式**—— 理论公式假设关键字均匀随机分布，与具体一张表通常对不上。

## 选型：按四个问题依次收窄

给一个应用场景选查找方法，按下面的顺序问，四问之内必定收敛。

逐条说明每个分支的判据：

| 场景 | 选择 | **判据** |
| --- | --- | --- |
| **只需精确匹配，不要有序** | 散列查找 | 散列表的存储位置与关键字大小无关，天然不支持范围查询；反过来说，不需要范围查询时它没有对手 |
| 频繁插入删除 + 散列 | **拉链法** | 开放定址法删除只能打墓碑，墓碑积累会拖垮性能 |
| 表长已知、极少删除 + 散列 | 开放定址法 | 省掉指针空间 |
| **数据在外存 / 数据量极大** | B 树 / B+ 树 | 度量指标从"比较次数"变成"磁盘 I/O 次数"，必须把树高压到个位数 |
| 外存 + 大量范围查询 | **B+ 树** | 叶结点链表让范围查询降到 O(logm⁡n+k) |
| **静态 + 表很小** | 顺序查找 | 折半的常数开销（算 mid、收缩区间）在小 n 时反而更贵 |
| **静态 + 有序 + 顺序存储** | 折半查找 | 静态表可以先付一次排序代价，此后每次查找都享受 O(log⁡n) |
| 静态 + 访问概率高度倾斜 | 顺序查找（按概率降序排列） | ∑PiCi 可远小于 n+12，见[《顺序查找》](./sequential-search.html) |
| **动态 + 内存 + 要最坏可控** | AVL / 红黑树 | BST 最坏退化成 O(n)；平衡结构把最坏也压在 O(log⁡n) |
| 动态 + 读多写少 | AVL | AVL 比红黑树更"平衡"，查找略快，代价是插删旋转更频繁 |
| 动态 + 写多读多 | 红黑树 | 平衡条件更宽松，插删的调整次数更少 |
| **动态 + 只需一般效率 + 实现要简单** | 分块查找 | O(n) 介于顺序与折半之间，插入删除只需在块内放/摘一个元素 |
| **要在一段文本里找子串** | 字符串模式匹配 | 查找对象是子串不是关键字，见[《KMP 算法》](./../string/kmp.html) |

### 三条常被问到的选型判断

**为什么不是所有场景都用散列？** 因为散列表放弃了全序：不能范围查询、不能有序输出、不能求前驱后继、不能求最值。 只要需求里出现"最大的 k 个""在某区间内的全部""按序打印"，散列表就出局。

**为什么内存里用 AVL / 红黑树、外存里用 B 树？** 因为**度量指标不同**。内存里衡量的是比较次数，二路分支就够； 外存里衡量的是磁盘 I/O 次数，必须让一次 I/O 读进尽可能多的关键字，于是要多路分支。 **同一棵 AVL 树放到磁盘上，30 层就是 30 次 I/O，完全不可用。**

**折半查找和二叉排序树是什么关系？** 折半查找的判定树就是一棵形态最好、由 n 唯一确定的 BST。 差别在于**判定树是"算"出来的、不占存储、不可修改**，BST 是"存"下来的、 占用指针空间、可以插入删除。**这正是静态与动态的分水岭。**

## 复杂度总表

| 查找方法 | 平均时间 | 最坏时间 | 空间 | **最坏情形怎么触发** |
| --- | --- | --- | --- | --- |
| 顺序查找 | O(n) | O(n) | O(1) | 目标在扫描的另一端，或查找失败 |
| 折半查找 | O(log2⁡n) | O(log2⁡n) | O(1)（递归实现 O(log2⁡n)） | 目标在判定树最底层 |
| 分块查找 | O(n)（最优块长） | O(n) | O(n)（索引表） | 块长取成 1 或 n，退化为顺序查找 |
| BST 查找 | O(log2⁡n) | **O(n)** | O(n) | **按有序序列依次插入**，树退化成单支链 |
| AVL 查找 | O(log2⁡n) | O(log2⁡n) | O(n) | 高度被平衡条件压住，无退化情形 |
| 红黑树查找 | O(log2⁡n) | O(log2⁡n) | O(n) | 同上，最坏树高 2log2⁡(n+1) |
| B 树 / B+ 树 | O(log⌈m/2⌉⁡n) | 同左 | O(n) | 每个结点都只有 ⌈m/2⌉−1 个关键字（半满） |
| 散列查找 | O(1)（α 受控时） | **O(n)** | O(m) 或 O(m+n) | **全部关键字互为同义词**，退化成一条链 / 一段连续探测区 |

⚠️ **两个"O(n) 最坏"必须能说出触发条件**： BST 是**按有序序列插入**；散列是**全部关键字同义**。 只写结论不写触发条件，等于没掌握。

## 易混淆知识点

| 易混对象 | 区别 | **判别依据** |
| --- | --- | --- |
| 静态查找表 vs 动态查找表 | 前者只查不改，后者边查边改 | 看需求里有没有"频繁插入删除"。有 → 折半查找、（严格意义上的）有序顺序表出局 |
| 折半查找 vs 二叉排序树 | 判定树由 n 唯一确定、不占存储、不可改；BST 形态由插入顺序决定、占指针空间、可增删 | 问"树形唯一吗"：判定树唯一，BST 不唯一 |
| BST vs AVL vs 红黑树 | 最坏高度：n / O(log⁡n) 且更严 / ≤2log2⁡(n+1) | 问"最坏情况能退化吗"：BST 能，后两者不能。AVL 更平衡（查找快），红黑树调整少（插删快） |
| AVL vs B 树 | 都是平衡树，但一个二路（内存）、一个多路（外存） | 问"度量的是比较次数还是磁盘 I/O 次数" |
| B 树 vs B+ 树 | 关键字/子树个数关系不同；B+ 树数据全在叶、叶结点成链 | 详见[《B+ 树》](./b-plus-tree.html)的对比表 |
| 散列查找"最快"却不能通用 | 它**放弃了全序** | 需求里出现范围查询、有序输出、求最值 → 散列出局 |
| 拉链法 vs 开放定址法 | 删除方式、α 上限、是否堆积 | 频繁删除 → 拉链法；表长已知且少删 → 开放定址法 |
| 成功 ASL 的分母 vs 失败 ASL 的分母 | 成功恒为 n；失败是"失败入口数"，各方法不同 | 见「失败 ASL 的分母：一张对照表」 |
| 散列失败 ASL 的分母是 m 还是 p | 是 **H 的值域大小**（除留余数法即 p） | p<m 时下标 ≥p 的位置**能被探测到，但不能作为起点** |
| 时间复杂度相同就等价吗 | 不等价 | AVL 与 B 树都是 O(log⁡n)，但外存场景下 B 树快一个数量级——**底数与常数在实际选型里是决定性的** |
| 分块查找的 ASL 是 n 还是 n+1 | n+1 | b+12+s+12 里的两个 12 加起来是 1 |
| 字符串模式匹配算不算查找 | 按 2026 大纲**算**（六（八）） | 但它比较的是字符、查的是子串，不套 ASL 那一套，见[《KMP 算法》](./../string/kmp.html) |

## 本节小结

学完本篇，应当能够：

- 把全部查找方法归入**线性表 / 树表 / 散列表**三条技术路线，并说清三条路的取舍： **线性表用简单换效率，树表用空间与维护代价换动态性，散列表用有序性换速度**；
- 复述总表的四栏——**存储结构要求、是否要求有序、ASL、是否支持动态增删**， 并能对任一方法当场填出这四栏；
- 说出各方法**失败 ASL 分母**的取法，尤其是散列查找的分母是**散列函数值域大小**， 与其余方法（n+1）完全不同；
- 写出各方法 ASL 的表达式**并说出它的来历**，而不是只背结论；
- 按 **"要不要范围查询 → 内存还是外存 → 静态还是动态 → 增删多不多"** 四问 为给定场景选出方法，并说出每一步的判据；
- 解释**为什么内存用 AVL / 红黑树而外存用 B 树**（度量指标从比较次数变成磁盘 I/O 次数）；
- 解释**为什么散列查找最快却不能通用**（放弃了全序，不支持范围查询与有序输出）；
- 说出两个"最坏 O(n)"的**触发条件**：BST 按有序序列插入、散列全部关键字同义；
- 知道**树形查找属大纲六（五）、字符串模式匹配属六（八）**，它们的原理分别在树、串两组文章里。

两条最关键的结论：**选型的第一问永远是"要不要保持有序"——这一问就把散列表和其余方法分开了**； **时间复杂度相同不等于性能相同，外存场景下底数与常数才是决定性的。**

## 教材出处

- 严蔚敏《数据结构（C 语言版）》（第 2 版）7.5 节「小结」，p229： 按线性表、树表、散列表三类组织查找表的总纲； 表 7.5「顺序查找、折半查找和分块查找的比较」给出三者在时间复杂度、查找特点、 适用情况三个维度的对照——顺序查找"算法简单，对表结构无任何要求，但查找效率较低"， 适用于"任何结构的线性表，不经常做插入和删除"；折半查找"对表结构要求较高， 查找效率较高"，适用于"有序的顺序表，不经常做插入和删除"； 分块查找"效率介于折半查找和顺序查找之间"，适用于"块间有序、块内无序的顺序表， 经常做插入和删除"。
- 同页表 7.6「折半查找和二叉排序树查找的比较」：两者时间复杂度同为 O(log2⁡n)， 但折半查找"数据结构采用有序的顺序表，插入和删除操作需移动大量元素"， 适用于"不经常做插入和删除的静态查找表"；二叉排序树查找"插入和删除操作无需移动元素， 只需修改指针"，适用于"经常做插入和删除的动态查找表"。
- 同页还给出：二叉排序树"在形态均匀时性能最好，而形态为单支树时其查找性能则退化为 与顺序查找相同"；B- 树"是一种在外存文件系统中常用的动态索引技术"； 以及散列表"不是以关键字比较为基础进行查找的……不仅平均查找长度和记录总数无关， 而且可以通过调节装填因子，把平均查找长度控制在所需的范围内"。
- 同书 p227 表 7.3：四种冲突处理方法在等概率下的理论平均查找长度 （本篇「散列查找的理论 ASL」那张公式表的出处）。
