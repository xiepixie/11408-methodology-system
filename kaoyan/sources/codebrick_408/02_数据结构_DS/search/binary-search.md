# 折半查找（二分查找）

## 大纲定位

本篇对应 2026 大纲 **六、查找 （四）折半查找法**。

**分工边界**：本篇负责折半查找本身——算法、判定树的构造与形态、树高、 成功与失败 ASL 的完整推导、以及"为什么只能用于有序的顺序表"。

- ASL 与判定树的通用定义在 [《查找基本概念》](./concepts.html)；

- 折半的思想被固化成显式树结构后就是[《二叉排序树》](./../tree/bst.html)与 [《平衡二叉树》](./../tree/avl.html)——它们对应大纲六（五），**在树那一章讲**；
- 折半思想在排序里的应用见[《折半插入排序》](./../sorting/binary-insertion-sort.html)。

## 知识框架

本节回答 4 个问题：

- **折半查找为什么必须"有序 + 顺序存储"，两个条件缺一不可？**
- **判定树是怎么由 n 唯一确定的？为什么它的形态与关键字的具体取值无关？**
- **树高 ⌈log2⁡(n+1)⌉ 是怎么来的？成功 ASL 的那个 log2⁡(n+1)−1 又是怎么推的？**
- **`mid` 取下界还是上界，到底改变了什么、没改变什么？**

## 算法

### 核心思想

折半查找每次把候选区间**砍掉一半**：

- 用 `low`、`high` 标记当前候选区间的两端，`mid` 是区间中点；
- 拿 `key` 与 `a[mid]` 比较：相等则成功；`key` 小则候选区间收缩为左半段；`key` 大则收缩为右半段；
- 区间为空（`low > high`）时判定失败。

n 个元素最多砍 ⌈log2⁡(n+1)⌉ 次就砍到空，所以 1000 个元素最多比 10 次 ——与顺序查找的 1000 次相比，这就是 O(n) 与 O(log⁡n) 的差距。

**两个前提缺一不可**：表必须**有序**（否则"key 小就往左"这条推断不成立）， 且必须**顺序存储**（否则取不到 a[mid]）。「为什么必须"有序 + 顺序存储"」一节会把这两条各自的必要性说透。 下文一律假设升序。

### 代码
c

```
// 折半查找（非递归）
// a[0..n-1] 为升序有序数组，n 为元素个数，key 为目标值
// 返回下标；返回 -1 表示查找失败
int BinarySearch(int a[], int n, int key) {
    int low = 0, high = n - 1, mid;
    while (low <= high) {              // 注意是 <=：low == high 时区间里还剩一个元素，必须查
        mid = low + (high - low) / 2;  // 等价于 (low+high)/2，但避免 low+high 溢出
        if (a[mid] == key)
            return mid;                // 查找成功
        else if (a[mid] > key)
            high = mid - 1;            // a[mid] 已被排除，所以是 mid-1 而不是 mid
        else
            low = mid + 1;             // 同理，mid+1 保证区间严格缩小，循环必然终止
    }
    return -1;                         // 区间为空，查找失败
}
```

三处边界，逐条说清**为什么必须这么写**：

| 写法 | 写错会怎样 |
| --- | --- |
| `while (low <= high)` | 写成 `<` 时，区间收缩到只剩一个元素（`low == high`）就退出了，**最后一个候选没被检查**。例如 `a = {5}`、`key = 5`：`low = high = 0`，条件 `0 < 0` 为假，直接返回 -1，漏判 |
| `high = mid - 1` / `low = mid + 1` | 写成 `high = mid` 或 `low = mid`，当区间只剩两个元素时 `mid` 恒等于 `low`，区间不再缩小，**死循环** |
| `mid = low + (high-low)/2` | 直接写 `(low+high)/2` 在 `low`、`high` 都接近 `INT_MAX` 时会**加法溢出**成负数，`a[mid]` 越界。408 的表长不会这么大，写 `(low+high)/2` 不算错，但知道这个改写是加分项 |

**空表**：`n = 0` 时 `low = 0`、`high = -1`，循环条件 `0 <= -1` 为假，直接返回 -1，正确。

## 判定树

### 判定树的构造规则

判定树把折半查找在某张表上的**全部可能执行路径**画成一棵二叉树：

- **内部结点**（圆形）= 被拿来比较的那个 `mid` 位置的元素；
- 左子树 = `key < a[mid]` 之后继续查的那半个区间的判定树；
- 右子树 = `key > a[mid]` 之后继续查的那半个区间的判定树；
- **外部结点**（方形，失败结点）= 区间收缩为空的位置，共 n+1 个。

构造方法就是把算法**递归展开**：对区间 [low,high] 取 mid 做根， 再对 [low,mid−1] 与 [mid+1,high] 递归。

⚠️ **判定树的形态只由两件事决定：元素个数 n，与 `mid` 的取整方式。** 它与关键字的具体取值**无关**——因为取 `mid` 的时候只用到了下标，没用到值。 这就是为什么"给一个长度 11 的有序表求 ASL"，不管表里装的是什么数，答案都一样。

### 完整算例（n=11）

以有序表 {7,10,13,16,19,29,32,33,37,41,43} 为例，下标 0∼10， `mid` 向下取整。

**逐层展开**：

| 区间 | mid | 取到的元素 | 左子区间 | 右子区间 |
| --- | --- | --- | --- | --- |
| [0,10] | 5 | 29 | [0,4] | [6,10] |
| [0,4] | 2 | 13 | [0,1] | [3,4] |
| [6,10] | 8 | 37 | [6,7] | [9,10] |
| [0,1] | 0 | 7 | 空 | [1,1] → 10 |
| [3,4] | 3 | 16 | 空 | [4,4] → 19 |
| [6,7] | 6 | 32 | 空 | [7,7] → 33 |
| [9,10] | 9 | 41 | 空 | [10,10] → 43 |

得到的判定树：

```
                    [29]                ← 第 1 层
                  /       \
              [13]          [37]        ← 第 2 层
             /    \        /    \
           [7]   [16]   [32]   [41]     ← 第 3 层
             \      \      \      \
            [10]   [19]   [33]   [43]   ← 第 4 层
```

第 3 层的 7、16、32、41 都来自只剩 2 个元素的区间。以 [0,1] 为例： mid=⌊(0+1)/2⌋=0 取到 7，左区间 [0,−1] 为空、右区间 [1,1] 只剩 10。 **所以这四个结点都只有右孩子**——这不是画错，是向下取整的必然结果。

### 判定树的形态规律

| 性质 | 说明 | **怎么用** |
| --- | --- | --- |
| 判定树是一棵**平衡二叉排序树** | 中序遍历得到原有序表；任意结点左右子树高度差不超过 1 | 可以直接套用[平衡二叉树](./../tree/avl.html)的高度分析 |
| 向下取整时，若区间元素数为**偶数**，左子树结点数比右子树**少 1** | 区间大小 m 时，左子树 ⌊m−12⌋ 个、右子树 ⌈m−12⌉ 个 | 手画时先算左右子树各几个结点，比一格一格数快 |
| 树高 h=⌈log2⁡(n+1)⌉=⌊log2⁡n⌋+1 | 见下面的推导 | 最坏比较次数就是 h |
| 成功查找的比较次数 = 该元素所在的**层数** | 从根走到它经过几个内部结点 | 逐层统计即可求成功 ASL |
| 失败查找的比较次数 = 该外部结点**父结点的层数** | 外部结点不含关键字，不参与比较 | 逐个外部结点统计即可求失败 ASL |

### 树高为什么是 ⌈log2⁡(n+1)⌉

判定树是**平衡**的：每次把区间分成尽可能相等的两半，所以除最后一层外每层都填满。 一棵高度为 h 的二叉树最多容纳 2h−1 个结点，最少容纳 2h−1 个结点 （前 h−1 层填满再加一个）。于是2h−1≤n≤2h−1

由右半边 n≤2h−1 得 h≥log2⁡(n+1)；由左半边 2h−1≤n 得 h≤log2⁡n+1。h 是整数，故h=⌈log2⁡(n+1)⌉=⌊log2⁡n⌋+1

这两个表达式对一切 n≥1 **恒等**（可逐个验证：n=1 时都是 1，n=7 时都是 3， n=8 时都是 4）。严蔚敏教材写的是后一种形式，很多题目写前一种，**不是两个不同的结论**。

## ASL 计算

### 查找成功
ASL成功=1n∑i=1nli(li 为第 i 个元素在判定树中的层数)

沿用上面 n=11 的判定树：

| 层数 | 结点 | 结点数 |
| --- | --- | --- |
| 1 | 29 | 1 |
| 2 | 13, 37 | 2 |
| 3 | 7, 16, 32, 41 | 4 |
| 4 | 10, 19, 33, 43 | 4 |

ASL成功=1×1+2×2+3×4+4×411=1+4+12+1611=3311=3

**通用公式的推导**（不要只背结论）。取最整齐的情形 n=2h−1，此时判定树是**满二叉树**， 第 j 层恰有 2j−1 个结点。等概率下：ASL成功=1n∑j=1hj⋅2j−1

利用恒等式 ∑j=1hj⋅2j−1=(h−1)2h+1（对 h 归纳即可验证： h=1 时两边都是 1，h=2 时都是 5，h=3 时都是 17），并代入 2h=n+1、 h=log2⁡(n+1)：ASL成功=(h−1)(n+1)+1n=h(n+1)−nn=n+1nlog2⁡(n+1)−1

n 较大时 n+1n→1，得到常用的近似式：ASL成功≈log2⁡(n+1)−1

代入 n=7 验证精确式：87×3−1=177≈2.43， 与逐层统计 1+2×2+3×47=177 一致 ✓

**这就是"折半查找的时间复杂度是 O(log2⁡n)"的来历**： 平均比较次数是 log2⁡(n+1)−1，最坏比较次数是 ⌈log2⁡(n+1)⌉， 两者都是 log2⁡n 的量级。

### 查找失败

失败查找终止于外部结点，共 n+1 个（证明见[《查找基本概念》](./concepts.html)）， 比较次数等于该外部结点**父结点的层数**。

仍以 n=11 为例，外部结点共 12 个，逐个推导：

| 失败区间 | 探测路径 | 比较次数 |
| --- | --- | --- |
| key<7 | 29→13→7→左空 | 3 |
| 7<key<10 | 29→13→7→10→左空 | 4 |
| 10<key<13 | 29→13→7→10→右空 | 4 |
| 13<key<16 | 29→13→16→左空 | 3 |
| 16<key<19 | 29→13→16→19→左空 | 4 |
| 19<key<29 | 29→13→16→19→右空 | 4 |
| 29<key<32 | 29→37→32→左空 | 3 |
| 32<key<33 | 29→37→32→33→左空 | 4 |
| 33<key<37 | 29→37→32→33→右空 | 4 |
| 37<key<41 | 29→37→41→左空 | 3 |
| 41<key<43 | 29→37→41→43→左空 | 4 |
| key>43 | 29→37→41→43→右空 | 4 |

按比较次数汇总：

| 比较次数 | 外部结点数 |
| --- | --- |
| 3 | 4 |
| 4 | 8 |

第 3 层的 7、16、32、41 各只有右孩子，各贡献 1 个空的左子树 → 4 个"比较 3 次"的外部结点； 其余 8 个来自第 4 层四个叶结点（10、19、33、43）各自的两个空子树。**4 + 8 = 12 = n+1** ✓ASL失败=3×4+4×812=12+3212=4412=113≈3.67

**通用近似式**：满二叉树情形（n=2h−1）下所有 n+1=2h 个外部结点都在同一层， 父结点层数都是 h，故 ASL失败=h=log2⁡(n+1)。一般情形介于 h−1 与 h 之间， 故常写作ASL失败≈log2⁡(n+1)

⚠️ **分母是 n+1 不是 n**。这是本章最常见的一处错误。判据很机械： **画出判定树，数方框有几个**。

## `mid` 取上界与取下界：改变了什么

`mid = \lfloor(low+high)/2\rfloor` 是默认口径。若改成向上取整 mid=⌈(low+high)/2⌉，同一个 n=11 的表得到的树是：

```
                    [29]                ← 第 1 层
                  /       \
              [13]          [37]        ← 第 2 层
             /    \        /    \
          [10]   [19]   [33]   [43]     ← 第 3 层
           /      /      /      /
         [7]   [16]   [32]   [41]       ← 第 4 层
```

奇数长度的区间取到的中点不变（根仍是 29，第 2 层仍是 13、37）， 但**只剩 2 个元素的区间会取到靠右的那个**（[0,1] 取下标 1 即 10，7 落进左子树）。

**变了什么，没变什么**：

|  | 向下取整 | 向上取整 |
| --- | --- | --- |
| 树的形态 | — | **是向下取整树的镜像** |
| 每层的结点**个数** | 1, 2, 4, 4 | 1, 2, 4, 4（**相同**） |
| ASL成功 | 3 | 3（**相同**） |
| ASL失败 | 113 | 113（**相同**） |
| 查 10 需要几次 | 4 次（29→13→7→10） | **3 次**（29→13→10） |
| 查 7 需要几次 | 3 次 | **4 次** |

**为什么两棵树的 ASL 必然相同**（这不是本例的巧合）：设当前区间有 m 个元素。 向下取整时，mid 距区间左端 ⌊m−12⌋ 格，于是左子树 ⌊m−12⌋ 个结点、 右子树 ⌈m−12⌉ 个；向上取整时恰好反过来。也就是说**每一步只是把左右两棵子树的 规模互换**，递归下去整棵树就是镜像。镜像不改变任何结点的层数分布， 所以**成功 ASL 与失败 ASL 一定相等**。

（已对 n=1∼200 逐个枚举两种取整方式的判定树，成功/失败比较次数的分布完全一致。）

⚠️ 所以取整方向的真正影响是：**改变了某个具体元素的比较次数**， 不改变平均值。题目问"查找 X 需要比较几次"时，必须先确认取整方式； 问"ASL 是多少"时，两种取整给出同一个答案。

## 为什么必须"有序 + 顺序存储"

这两个条件各自封杀了一类结构，缺一不可。

**为什么必须有序**：折半查找每次比较之后要断言"目标只可能在左半边"或"只可能在右半边"。 这个断言唯一的依据就是"左半边全部小于 a[mid]、右半边全部大于 a[mid]"。 表无序时这条断言不成立，被丢掉的那一半里可能就藏着目标。所以**无序数组不能折半查找**—— 即使它支持随机访问。

**为什么必须顺序存储**：折半查找要在 O(1) 时间内取到 a[mid]。链表不支持随机访问， 定位第 mid 个结点要从头走 mid 步。把这个代价算进去，一次折半查找的总代价变成O(log⁡n)⏟比较次数×O(n)⏟每次定位 mid=O(nlog⁡n)

**比直接顺序扫一遍的 O(n) 还慢**。所以**有序链表不能折半查找**——不是"不允许"， 是这么做没有意义。

顺带解释了另一条结论：折半查找**不适用于动态查找表**。 顺序存储的有序表插入一个元素平均要移动一半元素，O(n) 的维护代价会吃掉 O(log⁡n) 的查找收益。要既快又能动态增删，就得把判定树的分支结构**显式存下来** ——那就是[二叉排序树](./../tree/bst.html)与[平衡二叉树](./../tree/avl.html)。

## 复杂度

| 指标 | 复杂度 | **怎么来的** |
| --- | --- | --- |
| 最好时间 | O(1) | 第一次取的 `mid` 恰好命中 |
| 最坏时间 | O(log2⁡n) | 比较次数等于判定树高度 ⌈log2⁡(n+1)⌉ |
| 平均时间 | O(log2⁡n) | ASL成功=n+1nlog2⁡(n+1)−1≈log2⁡(n+1)−1 |
| 空间 | O(1) | 只用 `low`、`high`、`mid` 三个变量；**递归写法是 O(log⁡n)**，因为递归栈深度等于树高 |

⚠️ 空间那一行的括号是常被忽略的一处：**非递归实现 O(1)、递归实现 O(log2⁡n)**， 差别来自递归栈。

## 易混淆知识点

| 易混对象 | 区别 | **判别依据** |
| --- | --- | --- |
| 成功 ASL 的分母 vs 失败 ASL 的分母 | n vs n+1 | 画判定树：圆圈有 n 个，方框有 n+1 个。分子按谁求和，分母就取谁的个数 |
| 取整方向对 ASL 的影响 | **不影响** ASL；只影响**某个具体元素**的比较次数 | 两棵树互为镜像，层数分布完全相同 |
| ⌈log2⁡(n+1)⌉ vs ⌊log2⁡n⌋+1 | 两者恒等，是同一个数的两种写法 | 代入验证：n=8 时都等于 4 |
| 树高 h vs 平均比较次数 | h 是**最坏**比较次数；ASL≈log2⁡(n+1)−1 是平均 | 问"最多比较几次"答 h；问"平均比较几次"答 ASL |
| 有序链表能否折半 | **不能** | 判据是"能否 O(1) 取到中间元素"。链表取 a[mid] 要 O(n)，总代价反而升到 O(nlog⁡n) |
| 无序数组能否折半 | **不能** | 判据是"丢掉的那一半能否被证明不含目标"。无序时证明不了 |
| 折半查找的判定树 vs 二叉排序树 | 判定树是**特定形态**的平衡 BST，由 n 唯一确定；BST 的形态由**插入顺序**决定 | 问"树形唯一吗"：判定树唯一，BST 不唯一 |
| 折半查找 vs 折半插入排序 | 前者是查找方法；后者是用折半**定位插入位置**的排序方法，仍要移动元素 | 见[折半插入排序](./../sorting/binary-insertion-sort.html)：比较次数降到 O(nlog⁡n)，移动次数仍是 O(n2) |
| 非递归 vs 递归实现的空间 | O(1) vs O(log2⁡n) | 有没有递归栈 |

## 本节小结

学完本篇，应当能够：

- 写出折半查找的非递归 C 代码，并说清 `low <= high`、`high = mid-1`、`low = mid+1` 三处写错会分别导致**漏判最后一个元素**和**死循环**；
- 给定一个有序表，**逐区间展开画出判定树**，标出 n 个内部结点与 n+1 个外部结点；
- 说明判定树的形态**只由 n 与取整方式决定，与关键字取值无关**；
- 推导树高 h=⌈log2⁡(n+1)⌉=⌊log2⁡n⌋+1；
- 逐层统计求出**成功 ASL**，并能从满二叉树情形推出 ASL成功=n+1nlog2⁡(n+1)−1≈log2⁡(n+1)−1；
- 逐个外部结点求出**失败 ASL**（分母 n+1），并知道近似式 ≈log2⁡(n+1)；
- 说清取整方向**只改变个别元素的比较次数、不改变 ASL**，并能给出"两棵树互为镜像"的理由；
- 分别论证"必须有序"与"必须顺序存储"，并算出链表上强行折半的总代价 O(nlog⁡n)。

两条最关键的结论：**判定树的形态由 n 唯一确定，所以 ASL 与表里装什么数无关**； **折半查找的两个前提分别封杀了无序数组与有序链表，它只服务于静态有序顺序表。**

## 教材出处

- 严蔚敏《数据结构（C 语言版）》（第 2 版）7.2.2 节「折半查找」，p193： "折半查找要求线性表必须采用顺序存储结构，而且表中元素按关键字有序排列"。
- 同书 p195：折半查找判定树，并给出与本篇完全相同的算例——长度为 11 的有序表， "比较 1 次的只有一个根结点，比较 2 次的有两个结点，比较 3 次和 4 次的各有四个结点"， ASL=111(1+2×2+3×4+4×4)=3。
- 同书 p196：判定树深度为 ⌊log2⁡n⌋+1；外部结点与内部结点的定义； 满二叉树情形下的求和推导得 ASL=n+1nlog2⁡(n+1)−1， n 较大时近似为 log2⁡(n+1)−1；以及"折半查找不适用于数据元素经常变动的线性表"。
