## 散列查找的基本概念

### 思路：用计算代替比较

前面所有查找方法——顺序、折半、分块、树表——都以**关键字之间的比较**为基础， 查找时间必然与表长挂钩。散列查找换了一条路：

在**记录的存储位置 p** 与它的**关键字 key** 之间建立一个确定的对应关系 H， 使 p=H(key)。查找时直接算出地址，不需要反复比较。

这个对应关系 H 叫**散列函数**（哈希函数），p 叫**散列地址**。 按散列函数把记录存进一片连续地址空间，这片空间就是**散列表**（通常是一维数组， 散列地址就是数组下标）。

**代价是什么**：散列表的存储位置由关键字算出，**与关键字的大小顺序完全无关**。 所以散列表**不能做范围查询、不能有序输出、不能求前驱后继**。 这是它与树表结构的根本分野——[B+ 树](./b-plus-tree.html)保留全序，散列表放弃全序。

### 冲突与同义词

关键字的取值集合通常远远大于地址空间。以标识符为例：不超过 8 位、字母开头的字母数字串 有 1012 量级那么多，而编译器的符号表只有一千个槽位。 **把 1012 个可能的关键字映射到 103 个地址上，冲突不可避免。**

- **冲突**：key1≠key2 但 H(key1)=H(key2)；
- **同义词**：具有相同散列地址的两个关键字互称同义词。

所以散列查找必须同时研究**两个**问题：

- **如何构造散列函数**（尽量少产生冲突）——见「散列函数的构造」；
- **如何处理冲突**（冲突发生后怎么办）——「拉链法：用链表装同义词」讲拉链法， 开放定址法见[另一篇](./hash-open-addressing.html)。

⚠️ **冲突不可能被消除，只能被减少**。任何"设计一个不冲突的散列函数"的思路在 关键字空间大于地址空间时都是不成立的。

### 装填因子
α=表中填入的记录数 n散列表的长度 m

α 标志散列表的装满程度。α 越大，再填记录时发生冲突的可能性越大， 查找时需要比较的关键字个数也越多。

⚠️ **散列表的 ASL 是 α 的函数，而不是 n 的函数。** 这是散列查找与所有其他查找方法 最本质的区别——不管 n 有多大，只要控制住 α，就能把平均查找长度限定在一个范围内。 "接近 O(1)"这句话的准确含义就在这里。

## 散列函数的构造

构造散列函数要考虑：散列表长度、关键字长度、关键字的分布情况、计算函数的时间、 记录的查找频率。两条原则：

- 计算要简单，每个关键字只对应一个散列地址；
- 函数的**值域必须落在表长范围内**，且计算出的地址分布应尽量均匀。

常用方法：

| 方法 | 做法 | 适用情形 |
| --- | --- | --- |
| **直接定址法** | H(key)=key 或 H(key)=a⋅key+b | 关键字集合小且连续，**绝不冲突**，但空间浪费大 |
| **数字分析法** | 关键字位数比地址位数多时，**挑出分布最均匀的若干位**做地址 | 关键字集合**事先已知**，且各位分布不均 |
| **平方取中法** | 取 key2 的中间几位。中间位受关键字每一位的影响都大 | 关键字各位分布不均，且不知道分布规律 |
| **折叠法** | 把关键字分成位数相同的几段相加，取和的后几位 | 地址位数少、关键字位数多，且难以直接找出分散的几位 |
| **除留余数法** | H(key)=keymodp，p 取**不大于表长的最大质数** | **最常用、适用范围最广** |

### 除留余数法：p 为什么要取质数
H(key)=keymodp,p≤m

**为什么 p≤m**：keymodp 的值域是 0∼p−1。只有 p≤m 才能保证 算出的地址一定落在表内。

**为什么 p 取质数**——这一条要能说出理由，不能只背结论。

若 p 是合数，设 d 是 p 的一个因子。那么**所有 d 的倍数**这类关键字， 算出来的地址也全是 d 的倍数——地址空间里有 pd 分之一的位置被反复争抢， 其余位置永远空着。

**举个能立刻验算的例子**：设 p=10（合数），关键字恰好都是 5 的倍数：

| key | 5 | 15 | 25 | 35 | 45 |
| --- | --- | --- | --- | --- | --- |
| keymod10 | **5** | **5** | **5** | **5** | **5** |

五个关键字全部撞在地址 5 上，其余九个地址一个都用不到。换成质数 p=11：

| key | 5 | 15 | 25 | 35 | 45 |
| --- | --- | --- | --- | --- | --- |
| keymod11 | 5 | 4 | 3 | 2 | 1 |

完全散开。**质数没有除 1 和自身以外的因子，所以关键字里隐含的任何周期性 （都是某个数的倍数、都以某个数字结尾）都不会被 mod 运算放大成地址上的聚集。**

**取"不大于表长的最大质数"** 则是为了在满足 p≤m 的前提下把值域用满： 表长 m=100 时取 p=97，表长 m=13 时取 p=13（13 本身就是质数）， 表长 m=15 时取 p=13。

⚠️ **p 与 m 未必相等**。当 p<m 时，下标 p∼m−1 这一段**永远不会成为 任何一次查找的起点**——这直接决定了失败 ASL 的分母，见「ASL 计算：完整算例」与 [《开放定址法》](./hash-open-addressing.html)里的完整算例。

## 拉链法：用链表装同义词

### 结构

**链地址法**（拉链法）的思路：把具有相同散列地址的记录放在**同一个单链表**里， 称为**同义词链表**。有 m 个散列地址就有 m 条链表，用数组 `HT[0..m-1]` 存放各链表的头指针。

```
下标:  0       1       2       ...     m-1
槽位: [头指针] [头指针] [头指针] ...    [头指针]
       ↓       ↓       ↓              ↓
      链表    链表    链表            链表
```

**拉链法的三个特性**，都来自"用链表存冲突元素"这一个决定：

- **表不会满**。链表长度不受限制，α **可以大于 1**；
- **删除简单**。直接在链表里摘掉结点即可，**不需要删除标记**；
- **不产生堆积**。散列地址不同的记录落在**不同的链表**里，互不干扰—— 这是与开放定址法最重要的差别。

### 数据结构与代码
c

```
#define M 13   // 散列表槽位数，本例中 p 也取 13

typedef struct Node {
    int key;
    struct Node *next;
} Node;

typedef struct {
    Node *head;      // 该槽位的链表头指针
} HashTable[M];
```
c

```
// 查找：返回结点指针，NULL 表示查找失败
Node* search(HashTable ht, int key) {
    int idx = key % M;            // 一次计算定位到槽位，这一步不算关键字比较
    Node *p = ht[idx].head;
    while (p != NULL) {
        if (p->key == key)
            return p;             // 查找成功
        p = p->next;              // 每前进一步就是一次关键字比较
    }
    return NULL;                  // 走到链尾仍未找到，查找失败
}
```
c

```
// 插入：已存在则不重复插入；否则头插到对应链表
void insert(HashTable ht, int key) {
    if (search(ht, key) != NULL)
        return;                       // 先查后插，避免重复
    int idx = key % M;
    Node *newNode = (Node*)malloc(sizeof(Node));
    newNode->key = key;
    newNode->next = ht[idx].head;     // 头插法：O(1)，但链内顺序与插入顺序相反
    ht[idx].head = newNode;
}
```
c

```
// 删除：找到并摘除结点，返回是否删除成功
int delete_key(HashTable ht, int key) {
    int idx = key % M;
    Node *p = ht[idx].head, *pre = NULL;
    while (p != NULL && p->key != key) {
        pre = p;
        p = p->next;
    }
    if (p == NULL) return 0;          // 不存在
    if (pre == NULL) ht[idx].head = p->next;   // 删的是链头
    else pre->next = p->next;
    free(p);
    return 1;
}
```

⚠️ **`pre == NULL` 那一支不能少**：删链头结点时要改的是数组里的头指针， 不是某个前驱的 `next`。漏掉这一支，删除第一个结点就会失效。

**头插 vs 尾插**：头插是 O(1)，尾插要走到链尾是 O(L)，但尾插保持插入顺序。 **两种做法算出的成功 ASL 完全相同**——因为一条长度为 L 的链， 不管顺序如何，其中各元素的比较次数都是 1,2,⋯,L 这一组数。 只有"**某个特定关键字要比较几次**"这个问题的答案会不同。

## ASL 计算：完整算例

### 建表

设散列函数 H(key)=keymod13，关键字序列 (19,14,23,1,68,20,84,27,55,11,10,79)，共 12 个，用拉链法处理冲突， **按插入顺序尾插**。

逐个算散列地址：

| key | 19 | 14 | 23 | 1 | 68 | 20 | 84 | 27 | 55 | 11 | 10 | 79 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |
| H(key) | 6 | 1 | 10 | 1 | 3 | 7 | 6 | 1 | 3 | 11 | 10 | 1 |

得到散列表：

| 槽位 | 链表 | 链长 Lj |
| --- | --- | --- |
| 0 | 空 | 0 |
| 1 | 14 → 1 → 27 → 79 | 4 |
| 2 | 空 | 0 |
| 3 | 68 → 55 | 2 |
| 4 | 空 | 0 |
| 5 | 空 | 0 |
| 6 | 19 → 84 | 2 |
| 7 | 20 | 1 |
| 8 | 空 | 0 |
| 9 | 空 | 0 |
| 10 | 23 → 10 | 2 |
| 11 | 11 | 1 |
| 12 | 空 | 0 |

校验：4+2+2+1+2+1=12 ✓ 与关键字个数一致。装填因子 α=1213≈0.92。

### 查找成功的 ASL
ASL成功=1n∑i=1nCi

Ci 是查找第 i 个元素所需的**关键字比较次数**，等于它在链表中的位置 （第 1 个结点比 1 次、第 2 个比 2 次……）。

- 链头的 6 个关键字（14、68、19、20、23、11）各比 1 次；
- 链上第 2 个的 4 个关键字（1、55、84、10）各比 2 次；
- 第 3 个的 27 比 3 次；
- 第 4 个的 79 比 4 次。ASL成功=1×6+2×4+3+412=6+8+3+412=2112=1.75

**通用写法**：一条长度为 L 的链贡献 1+2+⋯+L=L(L+1)2 次比较， 所以ASL成功=1n∑jLj(Lj+1)2

代入验证：4⋅52+2⋅32×3+1⋅22×2=10+9+2=21， 2112=1.75 ✓

### 查找失败的 ASL

**分母是散列函数的值域大小**（本例 H(key)=keymod13，值域 0∼12，共 **13** 个入口）， **不是 n=12，也不一定是表长**。

⚠️ **这里有两种计数口径，必须先看清题目要求。**

| 口径 | "走到链尾发现 NULL"算不算一次比较 | 长度 L 的链贡献 | 全表结果 |
| --- | --- | --- | --- |
| **口径 A（严蔚敏教材）** | **算** | L+1 | n+rr=α′+1 |
| **口径 B（只数关键字比较）** | **不算**（与 NULL 比较不是关键字比较） | L | nr=α′ |

（r 为散列函数值域大小；当 r=m 时 α′=α。）

**口径 A**——严蔚敏教材的算法把"单元/指针域为空"也计作一次判断， 空槽比 1 次即可确定失败，长度 4 的链要比 5 次：ASL失败=1+5+1+3+1+1+3+2+1+1+3+2+113=2513≈1.92

**口径 B**——只统计与真实关键字的比较，空槽 0 次：ASL失败=0+4+0+2+0+0+2+1+0+0+2+1+013=1213≈0.92

两个结果恰好相差 1，因为每个入口都差了"和 NULL 比的那一次"。

⚠️ **两种口径的判别与应对**：

- 题目若明确写了"**空指针也算一次比较**"或给出了教材算法，按**口径 A**；
- 题目若只说"求平均查找长度"，多数复习材料按**口径 B**（此时 ASL失败 恰好等于装填因子 α， 与理论结论"拉链法失败 ASL 约为 α"对得上）；
- **答题时把口径写出来**（"设走到空指针不计入比较次数"），阅卷可辨。

**注意与开放定址法的差别**：开放定址法遇到空位**必须算 1 次比较** （那是一次真实的单元访问，用来判定"这里是空的，所以失败"）， 不存在口径分歧。所以两种冲突处理方法**失败 ASL 的数法本来就不同**， 不要把其中一边的习惯搬到另一边。

### 理论结论

在等概率、散列函数均匀的假设下：

| 指标 | 公式 | 与本例对照 |
| --- | --- | --- |
| ASL成功 | ≈1+α2 | 1+0.46=1.46 vs 直接计算 1.75 |
| ASL失败 | ≈α+e−α | 0.92+0.40=1.32 vs 口径 B 的 0.92 |

⚠️ **理论公式与直接计算通常对不上，这是正常的。** 理论公式的前提是"关键字在各地址上均匀随机分布"，而具体的一张表总有它自己的偏斜。 **题目给了具体的表就必须直接计算，不许套公式**；只有在题目只给 α 时才用理论公式估算。

## 复杂度与装填因子

| 操作 | 平均时间复杂度 | 最坏时间复杂度 | **怎么来的** |
| --- | --- | --- | --- |
| 查找 | O(1+α) | O(n) | 1 次计算散列地址 + 平均扫过 α 个链表结点；最坏是全部 n 个关键字都是同义词，退化成一条长为 n 的链 |
| 插入 | O(1+α) | O(n) | 先查找（O(1+α)）再头插（O(1)） |
| 删除 | O(1+α) | O(n) | 先查找再摘链结点，O(1) 完成摘除 |

**空间复杂度** O(m+n)：m 个头指针 + n 个链结点（每个结点还要多存一个 `next` 指针）。

**α 可以大于 1**：链表长度不受限，n 超过 m 只会让平均链长超过 1， 不会"装不下"。工程上 α 取到 1 附近仍然可用；α 明显大于 1 时 平均链长变长，O(1+α) 里的 α 项开始主导，就该扩容重散列了。

**最坏情形怎么触发**：所有关键字都是同义词。例如 H(key)=keymod13 而关键字 恰好都是 13 的倍数——全部落进槽位 0，散列表退化成一条单链表，查找变成 O(n)。 **这正是散列函数设计与 p 取质数的重要性所在。**

## 易混淆知识点

| 易混对象 | 区别 | **判别依据** |
| --- | --- | --- |
| 冲突 vs 查找失败 | 冲突是两个不同关键字算出同一地址；失败是表中确实没有这个关键字 | 两者互不蕴含：发生了冲突，查找**仍可能成功** |
| 同义词 vs 关键字相等 | 同义词是**散列地址**相同、关键字**不同** | key1≠key2 但 H(key1)=H(key2) |
| 成功 ASL 的分母 vs 失败 ASL 的分母 | 成功用**元素个数 n**；失败用**散列函数值域大小 r** | 数"失败查找能从哪些地址出发"：只有 H 能取到的地址才算 |
| 失败 ASL 的分母是表长 m 还是模数 p | 是 **p**（更一般地是 H 的值域大小） | p<m 时下标 p∼m−1 永远不会是查找的起点，不参与平均 |
| 拉链法失败计数：空链算 0 次还是 1 次 | 两种口径都存在，相差恰好 1 | 看题目是否把"指针域为空"算作一次判断。**答题时写明所用口径** |
| 拉链法 vs 开放定址法遇到空位的计数 | 拉链法有口径分歧；开放定址法**一律算 1 次** | 开放定址法访问那个空单元是一次真实的表访问，用它判定失败 |
| α 能否大于 1 | 拉链法**可以**；开放定址法**必须 <1** | 问"表会不会满"：链表不会满，开放定址法的元素必须挤在表内 |
| 头插法 vs 尾插法对 ASL 的影响 | **对 ASL 无影响**，只影响个别关键字的比较次数 | 一条长度 L 的链，比较次数集合恒为 {1,2,⋯,L} |
| 直接计算 ASL vs 套理论公式 | 给了具体表必须直接计算 | 理论公式基于"均匀随机散列"假设，与具体表通常对不上 |
| 散列表能否范围查询 | **不能** | 存储位置由 H 算出，与关键字大小顺序无关。要范围查询就得用 [B+ 树](./b-plus-tree.html) |

### 拉链法 vs 开放定址法

| 比较维度 | 拉链法 | 开放定址法 |
| --- | --- | --- |
| 冲突处理 | 同义词挂在同一条链表上 | 按探测序列在表内找空位 |
| 装填因子 | 可以 >1 | 必须 <1 |
| 删除操作 | **直接摘除链结点** | 只能**逻辑删除**（打删除标记），否则截断探测链 |
| 堆积（聚集） | **不会产生**——不同地址在不同链上 | 会产生，线性探测尤其严重 |
| 空间开销 | 每个结点多一个指针；结点动态申请 | 无指针开销，但要预留空位 |
| 表长是否需预知 | 不需要，链表动态增长 | 需要，且要留出余量 |
| 适用场景 | 表长不确定、**频繁插入删除** | 表长已知、**较少删除** |

## 本节小结

学完本篇，应当能够：

- 说清散列查找的思路——**在存储位置与关键字之间建立函数关系，用一次计算代替一串比较**， 以及它放弃的东西：**有序性**（不能范围查询、不能有序输出）；
- 定义**冲突**与**同义词**，并说明冲突在关键字空间大于地址空间时**不可能被消除**；
- 写出**装填因子** α=n/m，并解释"散列表的 ASL 是 α 的函数而不是 n 的函数"；
- 列出五种散列函数构造方法及各自适用情形，重点掌握**除留余数法**；
- 说清 p 为什么要取**不大于表长的最大质数**：p≤m 保证地址落在表内， 取质数保证关键字里隐含的周期性不被放大成地址聚集（能举出 p=10 与 p=11 的对比例子）；
- 写出拉链法的查找、插入、删除三段 C 代码，并说清删链头结点要单独处理；
- 给定关键字序列与散列函数，**画出拉链法散列表**，并算出成功 ASL（分母 n） 与失败 ASL（分母 = **散列函数值域大小**）；
- 说清失败 ASL 的**两种计数口径**（空链算 0 次还是 1 次），并在答题时写明所用口径；
- 解释拉链法的 α 为什么可以大于 1、为什么不产生堆积、为什么删除比开放定址法简单。

两条最关键的结论：**失败 ASL 的分母是散列函数的值域大小，既不是元素个数也不一定是表长**； **拉链法把同义词隔离在各自的链上，因此不产生堆积、删除无需打标记、装填因子可以大于 1。**

## 教材出处

- 严蔚敏《数据结构（C 语言版）》（第 2 版）7.4.1 节「散列表的基本概念」，p220： 散列函数与散列地址、散列表、冲突和同义词的定义—— "对不同的关键字可能得到同一散列地址……这种现象称为冲突。 具有相同函数值的关键字对该散列函数来说称作同义词"； 以及"散列查找法主要研究以下两方面的问题：（1）如何构造散列函数；（2）如何处理冲突"。
- 同书 7.4.2 节「散列函数的构造方法」，p221–p223：构造散列函数要考虑的五个因素与两条原则； 数字分析法、平方取中法、折叠法、除留余数法。其中除留余数法： "假设散列表表长为 m，选择一个不大于 m 的数 p，用 p 去除关键字， 除后所得余数为散列地址……这个方法的关键是选取适当的 p，一般情况下， 可以选 p 为小于表长的最大质数。例如，表长 m=100，可取 p=97"。
- 同书 7.4.3 节，p224：链地址法——"把具有相同散列地址的记录放在同一个单链表中， 称为同义词链表。有 m 个散列地址就有 m 个单链表， 同时用数组 `HT[0..m-1]` 存放各个链表的头指针"；例 7.2 给出的关键字序列 (19,14,23,1,68,20,84,27,55,11,10,79) 与 H(key)=keymod13 正是本篇算例的出处。
- 同书 p227–p228：装填因子的定义与"散列表的平均查找长度是 α 的函数， 而不是记录个数 n 的函数"；表 7.3 给出链地址法的理论平均查找长度 （成功 1+α2，失败 α+e−α）； p228 用例 7.2 的数据直接计算得 ASLsucc=1.75、ASLunsucc=1.92 （该书把"指针域为空"计作一次比较，即本篇的口径 A），并指出 "链地址法的平均查找长度小于开放地址法"、"链地址法的结点空间是动态申请的， 无需事先确定表的容量，因此更适用于表长不确定的情况"。
