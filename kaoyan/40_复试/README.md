# 复试 Course / Exam Atlas

> 类型：Atlas
> 状态：Atlas 工作稿，待人工确认；当前只建立 AI / Machine Learning 学习支线，其他复试模块按真实需要再建。

复试阶段不只是在背“标准答案”。真正要准备的是：面对导师连续追问时，能不能把自己的基础、项目、研究兴趣和技术判断组织成一条可以继续推导的解释链。

## 这册解决什么

当前先承担一个最小责任：给复试阶段的技术学习建立总入口，并把已经开始的 AI / Machine Learning 学习从数学一、408 主线中分离出来，避免把“考研初试知识”与“研究兴趣探索”混在同一个 Owner 中。

当前母问题是：

> **怎样在复试前形成足够宽的人工智能知识地图，同时通过真实学习过程判断自己愿意往哪个方向继续研究？**

## 与现有初试体系的关系

复试学习会大量 **Use** 现有数学一与 408 的 Owner，但不复制它们：

- 线性代数、微积分、概率统计的基础定义与考研范围机制，优先回到 `../10_数学一/`；
- 算法、数据结构、系统基础需要时回到 `../30_408/`；
- 面向 ML/DL 新出现的矩阵微积分、信息论、连续优化、随机过程等，只在真实算法要求时补充，不为了“数学基础”另起一套百科全书。

## Stop Boundary

当前**不提前建立**以下资产：

- 英语自我介绍、项目陈述、导师问答等复试模块；
- CV / NLP / Scientific ML 等方向的独立 Handbook；
- 某个研究方向的论文阅读树；
- AI 算法的完整 LaTeX 正文。

它们都等真实学习、面试准备或方向选择触发后再决定 Owner。

## 当前路由

如果问题是：

- “AI 各领域分别解决什么，怎么连接？” → 进入 [人工智能与机器学习 Atlas](10_人工智能与机器学习/README.md)；
- “刚学完一个算法，我的理解对不对？” → 先写入该分支 `inbox.md`，做 Model Diff；
- “某个机制已经稳定，需要长推导/例题” → 再建立 Topic / Bridge / Integration 的 Canonical `.tex`；
- “数学这里卡住了” → 先判断能否直接 Use 数学一现有 Owner；只有超出现有 Owner 的新数学才在 AI 分支补建。
