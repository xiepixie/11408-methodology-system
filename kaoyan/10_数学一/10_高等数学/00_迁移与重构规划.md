# 高等数学旧库迁移与重构规划

状态：架构与 Source Routing 已确认；12 Topic、5 个内部 Bridge、H-I01 与 B00--B08 Cross-Subject Bridge 已建立 Canonical 工作稿，待人工确认和陌生题验证。

## 1. 目标

将旧 `学习领域/归档/高等数学/` 从“教材章节 + 技巧 + 综合题”集合重构为当前认知系统中的稳定资产。

旧笔记只是 Source Corpus，不直接复制为 Canonical Handbook。

迁移目标不是：

$$
\text{Old File}_i\rightarrow\text{New File}_i
$$

而是：

$$
\boxed{
\text{Legacy Corpus}
\xrightarrow{\text{Diff + Split}}
\text{Topic / Internal Bridge / Cross-Subject Bridge / Integration / Topic Practice / Subject Rules / Extension}
}
$$

## 2. 强制路由顺序

迁移任何一段旧内容时依次问：

1. 它是在解释一个机制本身吗？→ Topic；
2. 它是在解释两个已有 Owner 为什么能接吗？→ Bridge；
3. 它是在一个完整问题里组合多个成熟模块吗？→ Integration；
4. 它是在告诉单一问题族做题时看什么、第一步做什么、何时换路吗？→ 与对应 Topic / Bridge / Integration 共置的训练 Markdown；若该控制稳定跨多个训练专题且有证据支撑，才晋升 Subject Rules；
5. 它是真连接但明显超出数学一核心吗？→ Extension；
6. 它只是表面相似、容易诱发错误迁移吗？→ Anti-Bridge；
7. 都不是，或证据不足 → 暂不进入稳定资产。

同一机制只能有一个完整解释 Owner。

## 5. 当前最重要的重复消除

迁移时必须主动消除以下旧重复：

1. 极限/连续/导数之间反复出现的“点态 vs 邻域”反例；
2. Topic03 的有限 Taylor 与 Topic11 的 Taylor series；
3. Topic07 的 Jacobian/Hessian 与 Topic08/线代中的 determinant/二次型；
4. Topic05 反常积分与 Topic10 级数判敛；
5. Topic09 四类积分各自重复参数化、定向和对称性规则；
6. 所有“机制说明”和“题目中怎样选机制”的混写。

解决方式不是删知识，而是决定唯一 Owner 后让其他位置 Use / Bridge。

## 6. Main Text / Appendix / Topic Practice / Subject Rules 边界

$$
\boxed{MainText=Understanding,\qquad Appendix=Coverage/Extension,\qquad Practice=Local\ Operational\ Control,\qquad SubjectRules=Cross\!\text{-}Topic\ Control}
$$

旧稿中下列内容默认不抢占主干：

- Fréchet derivative 的一般抽象版本；
- Lebesgue/Tonelli/DCT；
- 完整 Hilbert space 理论；
- companion matrix / matrix exponential；
- 单位根筛选等明显超出数学一核心的工具。

只有它们能显著澄清核心机制时，正文保留最小解释；否则标 Extension 或暂不迁移。

## 7. 逐册工作流程

每处理一个 Topic：

1. 读取该 Topic 的所有 Source Pack，而不是只读同名旧文件；
2. 做 Handbook Diff：保留 / 冲突 / 重复 / 越界 / 缺失；若确认用户自有原笔记存在事实、机制、边界或计算硬错误，**先直接回修原 Source**，不能只在 Canonical 里绕开；
3. 先锁 Mother Problem 与 Ownership；
4. 按 `Problem → Naive Approach → Failure → Mechanism → Invariant → Cost` 重构正文；每个核心机制再走一次“**直觉预判 → 对象钉死 → 细节放大 → 微扰校准**”，保证能形成脑内图像，又不会丢掉数学资格；
5. 把跨 Owner 内容改成 Use / Bridge；
6. 把单一问题族的操作性技巧分流到同目录训练 Markdown；只有跨多个训练专题稳定复用且有证据支撑的控制才晋升 Subject Rules；
7. 加最小反例、边界和独立 Verification；同时至少指出一个最容易发生第一次偏离的细节（符号、方向、端点、定义域、分支、量词或严格性）；
8. 交用户审阅；
9. 用户确认后再晋升状态并同步依赖/Publication。
