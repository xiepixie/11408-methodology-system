# 图示语义与视觉推理规范

> **Owner**：本文件拥有 I.P.A.R.A 全仓跨学科、跨载体的**图示语义规则**：画图前怎样回读具体手册并确定插入位置、这张图具体要画什么、一张图为什么存在、视觉变量各自代表什么、怎样选择图型、怎样避免图像偷偷引入题设没有的结构，以及怎样做语义验收。
>
> **边界**：专题训练中的图意图占位、集中图审、图形 Owner 与复用生命周期由 [`topic_practice_writing_spec.md`](topic_practice_writing_spec.md) 拥有；TikZ/PGF 的版心、节点、端口、路由、字号、主题色、暗亮 SVG 与编译工程由 [`latex_layout_spec.md`](latex_layout_spec.md) 拥有；真题题图的忠实重建、semantic id、不得泄露答案等 Source Fidelity 规则由 [`exam_source_conversion_spec.md`](exam_source_conversion_spec.md) 拥有。

## 1. 核心原则：图是推理接口，不是装饰层

图只有在能**压缩推理、暴露结构、支持预测或阻断误读**时才值得存在。

一张图的价值不是“比文字好看”，而是让读者更容易完成至少一种任务：

- 在计算前看出方向、维数、符号、可达性、层级、状态或结构类型；
- 把多步作用、变换、信息流或状态迁移压成可复原的母图；
- 直接比较两个容易混淆的对象、表示或机制；
- 看见公式不容易显露的空间、区域、边界、包含、正交、交叠或不变量；
- 发现某个错误推理在视觉上究竟错在哪里；
- 把“同一对象”“不同表示”“真实作用”“推理顺序”等容易偷换的层次明确拆开。

若一张表、三行公式、一个短列表或一个简单文本流程已经更清楚，就不要为了视觉丰富再造图。

> **删掉一张没有认知收益的图，也属于图审完成。**

## 2. 先定位正文，再进入解释、编码与工程三层

任何正式图形都经过三层，但在三层之前还有一个不能跳过的前置步骤：**先回到它要服务的具体手册正文，确定插入位置与上下文。**

```text
正文定位：这张图插在哪里；前文已经讲了什么；后文马上要用什么
→ 解释层：为什么画；它负责压缩哪一步推理；禁止读者多推出什么
→ 语义编码层：位置、距离、角度、大小、箭头、线型、颜色、区域分别表示什么
→ 工程呈现层：节点、端口、路由、画幅、字号、主题、SVG、PDF、Markdown 怎样稳定呈现
```

四步不得倒置：

- 不能脱离手册上下文，先凭“这个知识点适合画图”就开始设计；
- 不能先调 TikZ 坐标，再想“这图到底说明什么”；
- 不能用颜色和箭头补救尚未厘清的关系；
- 不能让为了避让而产生的排版位置，被误读为知识上的高低、早晚或因果；
- 不能让同一个视觉符号同时承担两种关系，再靠长图例解释。

全仓统一顺序：

```text
回读目标手册与目标小节
→ 确定准确插入位置
→ 写清图前内容规划
→ 建立视觉解释契约
→ 选择语义编码
→ 决定图型与拓扑
→ 根据当前版心与样式偏好做几何布局
→ 生成图源与派生视图
→ 语义验收
→ 实际阅读视图验收
```

### 2.1 图前正文定位：没有插入位置，就不开始画

开始任何新图源前，必须先读目标文档的实际内容。最低要求不是“看见一个待补图占位”，而是读清：

- 占位所在的完整小节；
- 占位前一段已经给出的定义、公式、例子或结论；
- 占位后一段准备继续推导、比较或训练的内容；
- 若这张图承担整节总结、跨小节母图或 Bridge 接口，则继续回读它真正覆盖的全部相关段落，不能只看局部两三行。

插图位置必须具体到“**放在什么内容之后、什么内容之前**”。例如：

- 定义或对象刚建立，后文马上需要几何直觉：放在正式定义之后、第一次依赖该直觉的推理之前；
- 两个概念容易混淆：先把两个概念分别定义清楚，再紧接对照图，随后进入判别规则或例题；
- 一张图负责总结一整段机制：等组成要素都讲完以后再放，不能把未定义对象提前塞进图中；
- 反例图：紧跟错误直觉或错误命题之后，让图直接显示失败位置，再接文字解释。

**如果执行者说不清“这张图为什么正好插在这里”，说明正文与图片的关系还没有想清楚，暂停画图。**

### 2.2 图前内容规划：先把“图里到底有什么”写成清单

确定插入位置后，为每张真正准备新画的图写一份简短规划。规划不要求长期留在最终正文，但在建立 TikZ/PGF 源之前必须明确：

1. **目标文件与小节**：文件名、标题层级；
2. **准确插入点**：放在哪一段/公式/例子之后，哪一段之前；
3. **前文已经讲清的内容**：图不能重新承担正文已经完成的长解释；
4. **后文需要图提供的帮助**：读完图以后，读者接下来应该更容易看懂、判断或计算什么；
5. **图中必须出现的对象**：具体列出点、向量、曲线、区域、矩阵块、状态、箭头、标签、数值等；
6. **图中必须表达的关系**：例如正交、包含、投影、映射、状态迁移、同一对象不同表示；
7. **图中明确不画的内容**：哪些细节由正文承担，哪些关系容易造成误读而必须省略；
8. **复用判断**：已有图能否直接承担同一解释责任；若不能，差异具体在哪里；
9. **呈现草案**：单图还是对照图、是否需要坐标轴、是否需要局部说明或独立卡片。这里只决定信息结构，不先锁死厘米数、颜色或装饰。

一个合格的规划应能让另一个人只看这九项，就知道“**为什么在这里插图、图里画什么、哪些东西不能画**”。如果仍只能写出“画一个直观示意图”“展示一下关系”，信息还不够具体。

一个最小例子：假设正文刚讲完“同一向量在不同基下有不同坐标”，下一段准备推出过渡矩阵关系。此时图前规划应该写成类似：

```text
插入位置：在“坐标依赖所选基”的解释之后，过渡矩阵公式之前
前文已知：几何向量 v 没有改变，改变的是基与坐标列
后文用途：让读者在看矩阵公式前先分清“对象”和“表示”
必须出现：同一个 v、两组基、两列不同坐标、明确的同一对象对应关系
明确不画：不把两组基默认画成正交；不画成 v 被某个算子变成另一个向量
```

这比“画一张基变换示意图”多不了几行，却能直接约束后续所有几何和箭头设计。

## 3. 视觉解释契约：内容规划完成后再回答六问

任何需要长期维护的语义图，在进入绘图阶段前都必须能回答：

1. **解释责任**：删掉这张图后，哪一步理解、预测、检索或校验会明显变差？
2. **对象**：图中的点、向量、区域、曲线、节点、矩阵块、状态、报文分别代表什么真实对象？
3. **关系或动作**：连线、箭头、包含、正交、平行、重合、颜色、位置分别表达什么？
4. **必须保持的不变量**：图最应该让读者看见什么没有变？例如对象不变但坐标变、span 不变但基变、身份不变但状态变、输入空间不变但表示变。
5. **允许丢失的信息**：为了压缩推理，这张图刻意不表达什么？例如只表达维数不表达具体方向，只表达拓扑不表达真实距离，只表达先后不表达耗时比例。
6. **禁止误读**：读者最可能从图上多推出什么题设并未保证的结论？怎样通过选例、布局、符号或最短图注主动消除？

第 4～6 问是硬门槛。图如果视觉漂亮，却偷偷引入额外对称、因果、比例、唯一性、单调性、周期性或概率大小，属于**语义错误**，不是审美问题。

## 4. 先决定是否需要图，再决定画成什么

新图至少应满足一个“不可替代视觉责任”：

- **空间责任**：位置、方向、距离、角度、区域、交并、正交、投影、主轴；
- **作用责任**：对象经过算子、函数、协议、算法或状态迁移后发生什么；
- **表示责任**：同一对象在不同坐标、基、编码、变量或视图下如何表示；
- **结构责任**：矩阵块、层级、组成、邻接、依赖骨架、资源关系；
- **过程责任**：时间顺序、事件链、控制流、信息流、回退与反馈；
- **对照责任**：正确/错误、一般/边界、可行/不可行、同解/仅公共解等关键区别。

如果只是为了“有一张图”，不画。

如果现有图已经承担**相同解释责任**，优先复用而不是重画。具体资产 Owner 与复用路径由 `topic_practice_writing_spec.md` 管理。

## 5. 六类基础视觉语法：选择最弱但足够的一类

图型由解释责任决定，不由学科名决定。

| 视觉语法 | 适合表达 | 必须守住 | 典型误用 |
|---|---|---|---|
| **空间 / 几何图** | 位置、方向、距离、角度、区域、交并、正交、投影、主轴 | 需要度量时保持真实比例/角度；只示意拓扑时明确不承诺距离 | 用示意位置暗示真实长度、概率或大小 |
| **作用 / 映射图** | 输入经过算子后变成什么、信息在哪一步丢失、对象如何搬运 | 箭头必须是真实作用、变换或信息流 | 用箭头表达等价、相似、包含或“有关” |
| **表示 / 坐标图** | 同一对象在不同基、坐标、变量、编码或视图中的表示 | 明确区分“对象不变”与“表示改变” | 把两套表示画成两个不同对象 |
| **结构 / 组成图** | 矩阵块、层级、数据结构、组件、依赖骨架 | 位置主要表达组成/邻接/层级，不默认表达时间与几何距离 | 上下摆放就被误读成因果或时间 |
| **过程 / 状态图** | 时间顺序、状态迁移、协议流程、算法步骤、失败回退 | 主阅读方向固定；反馈与支路和主路径分层 | 把静态包含关系强行流程化 |
| **对照 / 反例图** | 两个易混对象、一般情形与边界情形、正确模型与错误模型 | 只改变待比较变量，其余尽量保持一致 | 同时改变多个条件，无法判断差异来源 |

需要组合语法时，必须明确**主语法**是什么，其他层只做辅助。若一张图需要三套以上主语法才能说清，优先拆图。

## 6. 视觉变量必须有明确语义

进入具体坐标和样式前，逐项判断以下变量是否承担知识：

- 横向位置；
- 纵向位置；
- 距离；
- 角度；
- 大小；
- 颜色；
- 线型；
- 箭头方向；
- 区域嵌套；
- 透明度；
- 重叠与遮挡关系。

### 6.1 度量图与结构示意图必须区分

**度量图**中，距离、角度、斜率、面积、比例本身就是知识，因此必须尽量保真。

**结构示意图**中，主要表达拓扑、层级、依赖或可达性，图上距离通常没有数值含义。此时必须避免让布局产生伪定量直觉。

### 6.2 排版位置不得冒充知识位置

为了避让把节点上移、下移、错开，只是工程布局；除非视觉契约明确声明，否则不能被读成：

- 更高层；
- 更早或更晚；
- 更重要；
- 更大；
- 更可能；
- 更接近。

必要时通过对齐、分区、图例或正文一句话消除歧义。

### 6.3 颜色只做辅助编码

颜色不能成为唯一信息通道。关键差异至少还应由下面一种方式承载：

- 位置；
- 线型；
- 形状；
- 文字/数学标签；
- 区域边界；
- 箭头端型。

这样即使灰度打印、色觉差异或主题切换，核心语义仍存在。

## 7. 关系符号语义：不是所有关系都画成箭头

全仓默认关系编码：

- **真实作用 / 变换 / 状态迁移 / 信息流**：有向箭头；
- **等价 / 同一对象不同表示**：双向对应、等号、等价符号或并列对齐；只有真的强调转换动作时才用方向箭头；
- **包含 / 从属**：集合包含、嵌套区域或层级连接；不用因果箭头；
- **正交 / 平行 / 相交 / 重合**：用几何关系本身表达；
- **依赖 / 调用**：只有确实存在读取或调用方向时使用有向边，否则使用无向关联或正文链接；
- **推理顺序 / 阅读顺序**：若只是读图顺序，必须与真实数学/系统动作使用不同线型、端型或分区。

同一张图出现两类以上边语义时，必须通过线型、箭头端型、分区或极短图例区分。

> 如果需要很长图例才能说明“这条箭头和那条箭头不是一个意思”，通常说明应该拆图。

## 8. 一般规律必须攻击“特殊例子偷带结构”

### 8.1 一般性优先

当图用于解释一般规律时，示意对象应尽量选择**一般位置、一般形态、非退化情形**。

例如：

- 解释反射生成周期，不用内部额外对称的正弦单峰冒充一般母段；
- 解释两个子空间同维但不相同，不把它们偶然画成重合；
- 解释仿射集与子空间区别，不把平移量偶然取成零；
- 解释特征方向，不把所有示例向量都偶然落在特征线上；
- 解释概率支撑，不让区域形状偶然带出题设没有的独立性或对称性直觉。

### 8.2 特殊对象必须忠实

若研究对象本身就是圆、偶函数、正弦、中心对称区域、对称矩阵等特殊对象，就必须忠实保留其真实结构。规则禁止的是“用特殊对象冒充一般性”，不是禁止研究特殊对象。

### 8.3 额外不变量攻击

图完成后反向问：

- 是否偶然产生更小周期？
- 是否额外出现对称轴、对称中心、奇偶性？
- 是否额外出现单调区间、重根、正交、平行或共线？
- 是否把一般包含画成了相等？
- 是否把“可能”画成了“唯一”？
- 是否把“存在一个”画成了“只有一个”？

如果正文只需要“$2d$ 是一个周期”，示意图至少要避免同时暗示“$d$ 也是周期”。可以通过端点值不等、峰谷错位或非对称母段主动排除伪周期。

## 9. 对照图必须遵守单变量原则

对照图的任务是让读者回答“**究竟是哪一个条件造成差异**”。因此：

1. 只改变当前要比较的变量；
2. 其余坐标范围、比例、基准线、标签位置、视口尽量一致；
3. 左右/上下子图顺序固定；
4. 不让一边使用更鲜艳颜色、更大字号或更大画幅造成价值判断；
5. 若无法保持其他条件相同，改用两张独立图并在正文明确比较维度。

典型适用：

- 单射 / 非单射；
- 可去 / 跳跃 / 无穷 / 振荡间断；
- 代数重数相同但几何重数不同；
- 有公共解但不同解集 / 完全同解；
- 正定 / 半正定 / 不定；
- 正确状态迁移 / 错误状态迁移。

## 10. 图必须声明“保留什么”和“丢掉什么”

视觉压缩必然丢信息。问题不在于丢失，而在于**无意识丢失**。

例如：

- 四个基本子空间图可以精确表达维数、正交和映射关系，但未必表达具体数值坐标；
- 网络层级图表达封装与相邻关系，不表达真实物理距离；
- 状态机表达合法迁移，不表达每个状态平均停留时间；
- 二次型主轴图表达旋转消去交叉项，不必把所有等值线数值都画出。

正文、图注或图的结构必须让读者知道当前图属于哪种抽象层级。

---

## 11. 图内文字只负责定位，不负责重新讲课

图内优先保留：

- 标准数学符号；
- 对象名；
- 极短动作名；
- 必要状态名；
- 必要数值、单位；
- 极短结论标记。

因果解释、口诀、长句、使用说明留在正文。

### 11.1 术语跟随当前学科与当前手册，不用私有黑话替代标准表达

图中标注首先服从它所服务的那一册手册，而不是执行者临时发明一套更“抽象”的说法：

- 优先使用当前学科教材、考纲与 Canonical Handbook 已经采用的正式名称；
- 一个对象在正文中叫什么，图中原则上也叫什么，不为了“图上显得高级”临时换近义词；
- 某个跨领域术语即使在更高阶数学中是合法术语，只要当前手册没有定义、考研语境也不依赖它，就不要直接拿来当图中核心标签；确实有解释价值时，必须先在正文给出清楚定义，再在图中使用；
- 不用私有口诀、隐喻或缩写代替可直接说清的关系。例如当前任务只是表达“多个原像分支分别贡献密度并求和”，就直接这样写，不必另造一个只有作者理解的名称；
- 图内文字应比正文短，但“短”不能靠造词实现。标准术语太长时，优先使用已经定义的数学符号，并把完整解释留在紧邻正文或图注。

因此这里禁止的是**未经定义、不能从当前手册复原的私有黑话**，不是把所有跨领域专业术语列成禁词。判断标准很简单：读者只读当前手册，能否准确知道这个词指什么、为什么出现在这里。

数学记号继续遵守全仓定界符规范，例如绝对值写作 `$\lvert x\rvert$`、Jacobian 的绝对值写作 `$\left\lvert\det\dfrac{\partial(u,v)}{\partial(x,y)}\right\rvert$`。

## 12. 语义验收顺序

每张图先做语义验收，再做美观验收。

### 第一层：数学 / 系统事实

- 点、端点、交点、开闭区间、渐近线、方向、权值、位宽、状态和标签是否正确？
- 图中关系能否回代定义、公式或机制？
- 反例是否真的把“不相等 / 冲突 / 失败”的位置画出来，而不是只在标题里宣称？

### 第二层：解释责任

- 图是否真的承担原先声明的解释责任？
- 删掉它以后是否确实损失理解、预测或检查能力？
- 是否混入第二个本应拆开的解释任务？

### 第三层：额外结构攻击

- 是否偷带额外周期、对称、因果、比例、唯一性、概率大小或时间长度？
- 是否把示意距离误当真实距离？
- 是否把排版上下关系误当层级或先后？

### 第四层：视觉编码与术语一致性

- 同一种箭头是否始终表示同一种关系？
- 同一种颜色/线型是否始终承担同一类辅助语义？
- 图中是否存在未经严格定义的非标准生造术语？

### 第五层：实际阅读视图与工程验收

通过前四层后，再进入 `latex_layout_spec.md`。工程验收不只看孤立 SVG 是否能编译，还要看它放回原手册后的真实阅读效果：

- 图在目标插入位置是否自然承接前文、服务后文，而不是打断叙事；
- 当前版心下画幅是否舒展，正文与图之间是否有清楚的视觉边界；
- 文字、端点、箭头、坐标轴、辅助线是否存在遮挡或归属歧义；
- 多子图、局部说明、全图总结是否各自归位，没有异常换行或跨区干扰；
- 暗色、亮色、Markdown 与需要时的 Handbook PDF 中，语义是否一致；
- 若图源同时服务 Markdown 与 Handbook，二者是否来自同一几何源且没有漂移。

具体 PGF 图层、版心预算、推荐留白、预览分辨率、编译与视觉自检方式全部由 `latex_layout_spec.md` 维护，本文件不复制厘米数或工具命令。

因此固定优先级是：

```text
插入位置与正文逻辑正确
> 语义与数学事实正确
> 术语清楚且可从当前手册复原
> 关系编码正确
> 无额外误导
> 实际阅读视图无碰撞、无歧义
> 风格排版美观
```

## 13. 跨场景调用方式

### 专题训练图

先由 `topic_practice_writing_spec.md` 判断是否值得画、何时集中图审、图归谁；准备新画时，必须回读目标训练文档与它调用的 Canonical 机制，按 §2.1--2.2 确定插入位置与图中内容，再进入本规范的语义设计，最后由 `latex_layout_spec.md` 落到 TikZ/SVG。

### Canonical Handbook 图

先读目标 Handbook 的完整相关小节，确定图放在何处以及前后文分别承担什么职责；再按 §2.2 写清图中必须出现/不得出现的内容。图的对象、关系、不变量、允许丢失与禁止误读服从本规范；版面和 TikZ 工程服从 `latex_layout_spec.md`。

### 真题 Source 图

先服从 `exam_source_conversion_spec.md` 的题面忠实性：不能改题意、不能画入答案、必须保留后续小问需要的信息。在这个前提下，关系符号、度量/示意区分与额外结构攻击继续服从本规范。

### 408 状态图、协议图与架构图

同样不默认“流程箭头万能”。先判断边是状态迁移、数据流、调用、依赖、包含还是静态关联，再进入端口和路由设计。

## 14. 一句话标准

> **先读具体手册，确定图插在哪里、前后文需要它解决什么，再写清图里究竟画什么；只有内容规划稳定后才进入样式设计。任何图都只能画出题设和模型真正拥有的结构，不能靠漂亮布局偷偷增加结论。**
