# 专题训练写作规范

> 本规范负责 Topic / Bridge / Integration 同目录训练 Markdown 的写作、拆分、图意图、集中图审、图形 Owner 与维护。
> 资产归属与 `.tex` / README / Subject Rules 的职责边界仍以 [`handbook_contract.md`](handbook_contract.md) 为准；跨学科图示语义统一服从 [`diagram_design_spec.md`](diagram_design_spec.md)；数学排版、TikZ 工程与暗亮 SVG 仍以 [`latex_layout_spec.md`](latex_layout_spec.md) 和全局 `infra/` 为准。

## 1. 目标：压缩题目空间，而不是制造第二本教材

专题训练 Markdown 解决三个问题：

1. **识别**：题目换皮以后，怎样认出它仍属于同一个问题族；
2. **执行**：看到什么信号，第一行动作是什么；
3. **校验**：怎样防止错误联想、错误分支和过度计算。

它不负责重新证明定义、定理和数学机制。知识真相仍由同目录 Canonical `.tex` 拥有。

因此长期结构是：

```text
机制正文 .tex
    ↓ 单向调用
训练 Markdown
    ↓ 代表题 / 错题 / 陌生题提供证据
真题与训练资产
```

不得反向让训练 Markdown 成为新的理论 Owner。

## 2. 硬性底线：只锁三件事

### 2.1 头部归属契约

每一份正式训练 Markdown 必须以以下最小头部开始：

```markdown
# 问题族名称

> 训练定位：这份文件负责什么场景、问题或检索意图。  
> 模型归属：链接到同目录真实 Canonical `.tex`；说明理论机制仍由该正文拥有。
```

要求：

- 一级标题必须直接对应学习者会搜索的问题，不用“母题汇总”“做题规则”之类资产类型命名；
- `训练定位` 要说明题目世界中的职责，不写空泛的“用于学习本章”；
- `模型归属` 必须指向真实 Canonical Owner；若机制跨 Topic，则指向对应 Bridge / Integration；
- 一个文件只能有一个主要检索意图。若头部需要用“以及、兼顾、顺便”串起多个相互独立的问题，优先审计是否应该拆分。

### 2.2 局部规则三元组

凡正文出现“规则”“第一动作”“稳定做法”“考场起手”这类可执行控制，必须能压成统一三元组：

```markdown
### 局部规则：语义标题

**触发信号**：题面出现什么可观察特征。

**第一动作**：动笔第一行写什么、比较什么、构造什么。

**检查与退出**：怎样验证路径仍合法；什么信号出现时停止当前路线并切换方法。
```

三元组是**语义契约**，不是要求每一节都必须有规则。纯反例、公式表、母例或分类表不需要硬凑三元组。

局部规则默认**不分配 `H-Rxx` 等稳定编号**。只有一条规则跨越多个训练文件、经过证据验证并晋升到 Subject Rules 时，才分配学科级稳定编号。这样避免文件拆分导致编号迁移、重排和双写。

### 2.3 单向依赖

训练 Markdown 可以：

- 引用 Canonical `.tex` 的机制；
- 使用一句必要解释连接题目与模型；
- 保存母题、变式轴、局部技巧、规则、反例、经典例子和代表题索引。

训练 Markdown 不可以：

- 重新完整证明同一条定理；
- 复制一套与 `.tex` 平行的定义体系；
- 因为“复习方便”重新维护第二份长机制正文；
- 把尚未验证的单题巧法伪装成稳定规则。

如果训练时发现“必须重新讲一大段理论才能解释这题”，先检查是否暴露了 Canonical `.tex` 的机制缺口；若是，就回修唯一知识 Owner。

## 3. 正文采用语义槽位，不采用固定章节模板

下面是可选语义槽位，不是强制目录：

- **问题表示 / 母题**：这类题真正研究什么对象、关系与目标；
- **变式轴**：题面通常怎样改变参数、表示、定义域或附加条件；
- **关键决策点**：哪一个信息真正决定路径；
- **局部规则**：触发信号—第一动作—检查与退出；
- **局部技巧**：只在当前问题族高价值的换元、构造、速算；
- **经典例子**：一个能跑完整决策链的代表对象；
- **反例 / 易错边界**：专门阻断错误逆推、缺资格或过度泛化；
- **代表题与证据**：真题、错题、陌生题索引及验证结果；
- **压缩**：必要时用一条短链总结考场调用。

正文形式服从数学对象本身：

| 内容性质 | 优先形式 |
|---|---|
| 分类辨析 | Markdown 表格、短列表 |
| 算法 / 操作流程 | 有序步骤、短流程图 |
| 结构关系 / 变换 | 公式链、语义图 |
| 易错边界 | 标准引用块，如 `> **易错边界：** ...` |
| 参数/分支对照 | 表格 + 最小反例 |
| 几何、函数图像、区间变换 | 精确矢量图 |

不强制“母题/变式/技巧/规则/例题/反例”七件套。缺什么写什么；没有信息增益的标题直接不建。

## 4. 文件什么时候新增、什么时候拆分

### 4.1 新增 Markdown 的真正条件

新增文件不是因为教材出现一个新小节，而是因为出现了新的**检索意图**。

满足下面两条时，通常值得单独建文件：

1. 学习者复习时会自然单独搜索它，例如“反函数”“周期性”“单调性”；
2. 它拥有相对独立的题目信号、第一动作或变式轴。

若两个概念总是共享同一批母题、同一条控制链，优先共置，不为目录整齐机械拆开。

### 4.2 行数只是报警器，不是判决器

禁止使用“超过 120 行必须拆分”一类硬阈值。数学公式、表格和母例会让行数严重失真。

可以把以下情况视为**重构报警信号**：

- 文件明显超过约 400 行；
- 同级母题数量已经很多，扫描目录时难以快速定位；
- 一个文件的标题开始出现两个以上可以独立搜索的主题；
- 不同部分拥有完全不同的触发信号和第一动作；
- 为了避免内容重复，文件内部不断写“另见本文件前面某节”。

报警以后仍不自动拆。只有当“独立检索意图 + 独立控制链”同时成立时才物理裂变。

例如 `反函数.md` 即使很长，也不能仅凭行数拆；若以后“反函数存在与一般反解”和“反三角主值折叠”已经形成两个独立复习入口，并各有自己的第一动作与代表题，再拆成两份才有收益。

### 4.3 合并信号

两个文件如果长期满足以下情况，应该考虑合并：

- README 中总是相邻出现；
- 代表题高度重叠；
- 第一动作几乎相同；
- 大量内容只是互相链接而各自没有独立训练责任。

文件存在本身不是价值；减少导航分叉比保持“一个知识点一个文件”更重要。

## 5. 日常维护工作流

刷题、复盘或导入旧笔记时，按下面顺序路由：

```text
遇到新信息
  │
  ├─ 已有问题族的新换皮？
  │      └─ 写入对应训练 Markdown 的变式轴 / 边界 / 代表题，通常只增加几行
  │
  ├─ 同一检索意图下的新母题？
  │      └─ 在现有 Markdown 新增一个问题表示与必要局部规则
  │
  ├─ 已形成独立检索意图与独立第一动作？
  │      └─ 新建同目录 Markdown，并把入口加入 README
  │
  ├─ 暴露理论机制、定义或边界缺口？
  │      └─ 回修 Canonical .tex，再在训练文档保留调用接口
  │
  └─ 规则跨越多个训练专题反复出现？
         └─ 进入 Evidence Promotion，成熟后晋升 Subject Rules
```

单题巧法默认只留在对应母题附近。没有重复迁移证据，不晋升学科规则。

### 5.1 图意图早记录，图资产晚生成

写训练正文时**不要求同步完成配图**。一旦判断某处确实需要视觉化，先在目标位置写一行“图意图占位”，继续完成正文语义，不让绘图打断问题族建模。

必要图统一写成：

```markdown
> **待补图｜反函数_单射与水平线判别**：用一条水平线对比单射与多对一，只表达“一个输出对应多少个合法输入”。
```

可能有帮助、但尚未确认值得维护的图写成：

```markdown
> **候选配图｜周期性_平移复制**：若文字仍不够直观，再用一个基本波段展示平移复制。
```

占位至少锁三件事：

1. **位置**：占位必须直接写在未来图片准备插入的真实位置，不能统一堆到文末“以后再处理”；
2. **名称**：`｜` 后面的名称从一开始就按未来最终图源 stem 命名，避免绘图时再次发明文件名；
3. **责任**：冒号后至少写清**这张图负责压缩什么推理**。复杂图可以继续补“必须表达 / 不应表达”的说明，但不要求在日常写作阶段填写完整规划表。

因此，占位本身已经是第一次“插入位置判断”。如果后来集中图审发现这个位置不对，应先移动占位和调整正文衔接，再开始画图。

**占位阶段严禁提前写不存在的 Markdown 图片链接**，例如把图片语法直接指向 `assets/待补.svg`。不存在的链接会污染 `E-LINK`，也把“尚未绘制”错误表达成“仓库断链”。

图意图后续只有四种合法结局：

```text
删除占位：复核后发现公式/表格更清楚
复用已有图：直接改成真实图引用
链接既有 Canonical 图：例如真题原图，不复制资产
新建语义图：建立 assets/src/<图名>.tex 并生成 SVG
```

因此“先占位”不是把技术债无限后移，而是把**是否需要图**和**怎样生产图**拆成两个不同决策。

## 6. 配图原则：训练层只决定“是否画、何时画、归谁维护”

训练 Markdown 不追求“每篇都有图”。图不是装饰，而是需要长期维护的视觉推理接口。训练层只做三件事：

```text
判断是否存在不可替代视觉责任
→ 检查是否已有同解释责任图可复用
→ 只有仍有缺口时才进入新图生产
```

“不可替代视觉责任”的判定、六问视觉解释契约、视觉语法、关系符号、一般性攻击与语义验收，统一由 [`diagram_design_spec.md`](diagram_design_spec.md) 拥有，本文件不再复制第二套定义。

若表格、公式或短流程已经更清楚，就删除图意图；删除无认知收益的图，同样属于图审完成。

### 6.1 集中图审的第一步：重新读具体手册，逐张确定插入位置与图中内容

集中图审不是看到“待补图”三个字就直接开 TikZ。对每一个准备保留的图意图，必须重新阅读：

- 当前训练 Markdown 的完整相关小节；
- 占位前后的正文、公式、例子与局部规则；
- 该训练文档所调用的 Canonical `.tex` 对应机制段落；
- 若图准备跨多个训练文件复用，再继续检查这些调用位置是否真的共享同一解释责任。

然后逐张形成一份**图前规划**。最少写清：

```text
目标文件：<具体 Markdown / Handbook>
目标小节：<具体标题>
插入位置：放在“什么内容”之后、“什么内容”之前
前文已经完成：<读者此时已经知道什么>
后文马上需要：<图要为下一步理解/判断/计算提供什么>
图中必须出现：<对象、关系、标签、数值、子图>
图中明确不画：<由正文承担或容易造成误读的内容>
复用判断：<删除 / 复用哪张图 / 新画，原因>
```

这一步的目标不是写抽象的“视觉责任”，而是让执行者能直接回答：

> **这张图为什么插在这里？读者看到它之前知道什么？看完它以后马上能做什么？图里到底要画哪些东西？**

如果这四个问题说不清，不进入绘图阶段。详细的图中语义、关系编码与禁止误读继续服从 [`diagram_design_spec.md`](diagram_design_spec.md) §2--§12。

图前规划属于工作过程，不要求长期原样保留在最终训练正文。图完成后，最终正文只保留真正需要的图片、简短图注和必要说明。

如果一次任务准备为**同一 Topic / Bridge / Integration 批量补 3 张以上图**，必须先把该批次所有候选图的图前规划审完，再开始第一张图源。原因很直接：只有先看完整批次，才能判断哪些其实是一张母图的不同调用、哪些位置应移动、哪些候选图可以删除。批量规划时优先用“目标文件 / 插入位置 / 前文已知 / 后文用途 / 必须出现 / 明确不画 / 复用结论”七列清单；定位使用“标题 + 相邻正文/公式锚点”，不要依赖容易漂移的绝对行号。

### 6.2 最佳工作流：语义先行，集中图审，批量生成

一个专题最稳的图形工作流是：

```text
正文/母题/规则先写清
→ 需要视觉压缩处立即在真实插入位置留下“待补图 / 候选配图”占位
→ 完成本轮语义审阅与 Source Diff
→ 汇总整个专题的图意图，去重并决定删除 / 复用 / 新画
→ 对每张保留图重新读目标小节与 Canonical 机制，写清“插在哪里、前后文是什么、图里画什么”
→ 按 diagram_design_spec.md 完成对象、关系、不变量、禁止误读与图型规划
→ 再按 latex_layout_spec.md 结合当前版心和项目样式偏好设计布局
→ 为真正需要的新图建立 assets/src/*.tex
→ 批量生成暗色/亮色 SVG
→ 检查孤立图 + 插回原文后的真实阅读效果
→ 用真实 Markdown 图片引用替换“待补图”
→ 用陌生题/复盘再次验证图是否真的帮助识别、预测或检查
→ 无收益的图删除或简化
→ 再进入成熟状态验收
```

这里的“最后补图”准确含义是：**晚于正文语义成形，早于专题成熟闭环**。不要在一句话还没想清楚时先花时间调坐标轴；也不要把必要图拖到专题已经宣布 `已采用` 以后。

集中图审的默认批次是**一个 Topic / Bridge / Integration 目录**，而不是等整门学科全部写完再统一补。这样既能获得批处理和统一风格的收益，又不会把视觉债务积成几十张图。

集中图审还有三个收益：

- 可以一次看到同专题多个文件的图意图，合并重复母图；
- 可以优先复用真题 Canonical 图或已有专题母图，减少资产数量；
- 可以统一检查视觉语言，而不是每写一段就临时发明一种画法。

### 6.3 图形工具分流

| 图的性质 | 推荐载体 | 原因 |
|---|---|---|
| 公式、短推导、分类表 | 原生 Markdown + LaTeX | 零派生资产，维护成本最低 |
| 简单非度量流程 / 依赖关系 | Mermaid 或文本流程 | 源码直接留在 Markdown，改动快 |
| 函数图像、几何、坐标系、对称/反射、区间映射、带数学标签的结构图 | TikZ/PGF 源 → SVG | 几何精确、公式统一、可版本控制、可重生成 |
| 真题原图的正式重建 | 复用 Exam Source 的 Semantic SVG 管线 | 保持题面资产与训练资产同一渲染底座 |
| 截图、教材页、手写图 | Evidence / Source | 只作证据；若长期承担解释责任，应重画为语义图 |

不要把所有图片都强行通过 LaTeX。需要精确数学/系统语义的图才走 TikZ→SVG；简单流程优先保留 Markdown 原生源。进入任何正式图形设计前，统一调用 [`diagram_design_spec.md`](diagram_design_spec.md) 选择视觉语法与关系编码。

## 7. TikZ → SVG：训练 Markdown 与真题共用同一底层管线

专题目录中的可重生成数学图统一采用：

```text
<专题目录>/
├── assets/
│   ├── src/
│   │   └── <图名>.tex       # 图形语义 Source
│   ├── <图名>.svg           # 暗色派生视图
│   └── light/
│       └── <图名>.svg       # 亮色派生视图
├── <训练主题>.md
└── ...
```

这里的 `.tex` 只拥有**图形几何与标签语义**，不拥有训练 Markdown 中不存在的新数学结论。

从资源仓库根目录显式编译：

```bash
python3 infra/scripts/compile_tikz_to_svg.py \
  "kaoyan/<专题目录>/assets/src/<图名>.tex"
```

共享编译器会生成暗色与亮色两份纯路径 SVG：

```text
assets/<图名>.svg
assets/light/<图名>.svg
```

它使用 `dvisvgm --no-fonts`，因此文字与公式转换为路径，不依赖阅读设备安装相同字体。

### 7.1 Markdown / Obsidian 嵌入规范

只有真实图资产已经存在后，才把“待补图”占位替换成图片引用。统一使用 Obsidian / 标准 Markdown 相对路径图片语法：

- 标准语法：`!` + `[图示说明]` + `(./assets/图名.svg)`；
- Obsidian 双链嵌入：`!` + `[[assets/图名.svg]]`。

**契约要求**：
- **严禁使用 HTML `<picture>` 或 `<img>` 标签**：冗长的 HTML 标签会破坏 Markdown 的纯文本可读性与 Obsidian 编辑器体验；
- 统一使用相对路径指向同目录 `assets/<图名>.svg`；
- Markdown 只维护这一条默认阅读引用；`assets/light/<图名>.svg` 是同源的亮色/打印派生视图，用于主题层、导出层与视觉验收，不在每份 Markdown 里维护第二套链接；
- 若未来确实需要自动随主题切图，在阅读器/主题层统一实现，不把 `<picture>` / `<img>` HTML 重新塞回每份训练笔记。

### 7.2 图形 Owner 与复用

图能否复用，判断标准不是“长得像不像”，而是**解释责任是否相同**：

- 若图只解释一个训练问题族：图源归该专题 `assets/src/`；
- 若同一张母图被同 Topic 多份训练文件调用，而且对象、关系、不变量与禁止误读都一致：保留一个图源，由其他文件直接引用；
- 若跨 Topic / Bridge 反复复用同一视觉机制，优先把图放在其**知识/接口 Owner 所在目录**，使用方链接调用，不在每个目录复制；只有现有 Owner 的图语义明显不适合新的解释责任时才建立新的图源；
- 若图本来就是某道真题题面：直接链接真题 Canonical SVG，不复制一份改名副本；
- 若真题图经过抽象后成为跨题母图：应在训练专题重新建立独立语义图源，因为它的解释责任已经从“忠实题面”变成“解释机制”；
- 若两张图几何骨架相同、但一张表达“真实映射”，另一张只表达“推理顺序/类比”，**不得为了省资产强行共用**；解释责任不同就应拆开；
- SVG 是 Derived View，不手工修改生成后的 path；要改图就改 `assets/src/*.tex` 再重编；
- 用户截图和教材截图不成为长期图形 Owner。

因此图形复用优先级固定为：

```text
同解释责任直接复用
→ 同 Owner 下抽象成母图后复用
→ 链接外部 Canonical 图
→ 最后才新建独立语义图
```

### 7.3 训练图的语义与工程验收入口

训练图不再在本文件维护一份重复的绘图硬清单：

1. **先做语义验收**：按 [`diagram_design_spec.md`](diagram_design_spec.md) 检查解释责任、对象/关系、不变量、允许丢失、禁止误读、一般性、对照单变量原则与关系符号；
2. **再做工程验收**：按 [`latex_layout_spec.md`](latex_layout_spec.md) 检查 `\linewidth`、真实几何、节点包络、端口、路由、遮挡、字号、主题、SVG 与实际阅读视图；
3. **最后做资产追溯**：专题自有图保持 `assets/src/<stem>.tex`、`assets/<stem>.svg`、`assets/light/<stem>.svg` 同 stem；外部 Canonical 图按 §7.2 链接复用，不复制伪 Owner。

顺序固定为：**语义正确 → 无额外误导 → 布局清楚 → 主题与资产闭环 → 最后才讨论漂亮。**

## 8. 经典例子与反例怎么放

训练文档中的例子只保留有明确教学责任的对象：

### 经典例子

用于完整跑通一条决策链，例如：

```text
题目信号 → 第一动作 → 关键转折 → 检查
```

### 反例

优先攻击最容易产生的错误逆推，例如：

```text
连续 ⇒ 有界？        反例：1/x 在 (0,1)
严格单调 ⇒ f'(x)>0？ 反例：x^3 在 0 处导数为 0
周期 ⇒ 有界？        反例：一个周期内存在无界奇点的周期函数
```

反例的价值不是“多记一个怪函数”，而是给每条规则建立**失效边界**。

同一个反例如果能攻击多个错误直觉，可以在一个 Owner 中完整解释，其他训练文件只链接调用，避免复制三遍。

### 8.1 代表题兼作小回归题组

代表题不只证明“这条规则见过”。当一个 Topic 的 Canonical 模型或重要局部规则发生修改时，Practice 应优先保留少量能迅速发现回归的题：

- 一道能正常跑通主机制的基线题；
- 一道专门检查适用边界的题；
- 一道只改变一个关键条件的扰动题；
- 若该问题族经常跨 Owner，再保留一题接口题。

这不是固定四题模板。只保留真正有区分力的题，也不要求另建数据库。修改模型后先重跑这些代表题；出现异常时再扩大检查范围。具体的“题目是否自洽、问题打穿哪一层、怎样做双向回测”由 [`problem_model_validation.md`](problem_model_validation.md) 统一规定。

## 9. 质量检查

一份训练 Markdown 成熟前至少自问：

1. 一级标题是不是一个真实检索意图？
2. 头部是否明确训练定位和唯一模型归属？
3. 是否在重复 `.tex` 的长理论，而不是调用它？
4. 每条可执行规则能否还原为“触发信号—第一动作—检查与退出”？
5. 有没有把单题巧法过早升级为稳定规则？
6. 母题是否能生成多个表面不同的题，而不是只解释一道答案？
7. 是否有必要的反例阻断错误逆推？
8. 图是否真正压缩推理；若删掉图，理解是否明显变差？
9. 每张保留图是否已经回到具体手册确定准确插入点，并写清“前文已知—图中内容—后文用途”？
10. 所有 `待补图` 是否都已经得到“删除 / 复用 / 链接 Canonical 图 / 新建图源”之一的明确结局？若父专题准备标记 `已采用`，必要图占位必须清零；
11. 可重生成 SVG 是否有 `assets/src/` 图源，而不是只剩手工产物？
12. README 是否只导航正式训练入口，没有重复文件和历史兼容壳？

### 9.1 门禁采用渐进收紧，而不是一次性扫旧库

本规范对**新建或本轮实质修改的正式训练 Markdown**立即生效。旧仓中尚未完成身份核销的 Source、历史工作稿和兼容文件，不为了“一次性全仓过格式检查”机械补头部或改造成训练资产。

自动门禁应随 Source Diff 与目录清理逐步扩大覆盖范围：先验证已经明确进入 README 正式训练导航的文件，再扩展到完成身份核销的专题目录。这样保证“契约是硬的”，同时不让 legacy 假阳性反过来驱动无价值格式劳动。

图意图采用分级闭环：

- `待人工确认` 等工作态允许存在 `待补图`，但 `audit` 必须把它列成维护债务，避免被遗忘；
- 父专题进入 `已采用` 前，正式训练导航中的 `待补图` 必须清零，否则属于硬错误；
- `候选配图` 不阻塞采用，它只是未来视觉增强线索；若长期没有收益，直接删除即可。

最终目标不是让所有文件长得一样，而是让学习者在陌生题中稳定完成：

```text
看见信号 → 认出问题族 → 选择第一动作 → 调用深层模型 → 检查边界
```
