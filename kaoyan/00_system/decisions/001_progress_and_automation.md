# ADR-001：生成式进度视图与最小自动化

## Status

Accepted

## Context

这是个人长期认知系统。需要快速看到当前焦点、专题进度和断链，但不能为了自动化引入数据库、复杂 schema，或让脚本替人判断规则是否成立。

## Options Considered

| 方案 | 优点 | 缺点 |
|---|---|---|
| 手工维护一张总进度表 | 简单直观 | 与各专题状态形成两份真相，容易漂移 |
| YAML/数据库保存全部状态 | 可查询、可统计 | 日常维护成本高，违背低摩擦目标 |
| 专题状态为源，脚本生成总览 | 状态贴近 Owner，总览可重复生成 | 需要状态行保持简短一致 |

## Decision

采用“局部状态为源 + `CURRENT.md` 人工焦点 + `PROGRESS.md` 生成视图”。只提供标准库脚本完成进度生成、链接检查和交互提示输出。

## Trade-offs

- 放弃复杂筛选、图表和自动证据统计；
- 状态行仍需人在真正变化时更新；
- 脚本只能检查结构一致性，不能检查认知是否正确。

## Consequences

- `PROGRESS.md` 不手工编辑；
- 新增稳定资产时，在入口前几行声明状态；
- 人工只需维护 `CURRENT.md` 的当前焦点；
- 当状态数量真实造成检索困难时，才考虑最少 front matter，不提前引入。

## Revisit Trigger

- 资产数量大到状态行无法可靠扫描；
- 同一资产需要多个独立负责人或并行发布分支；
- 真实使用证明需要按证据、日期或成熟度进行稳定查询。
