# 文章层

> **职责**：保存真实文章，并记录只属于某一篇文章的训练现场。文章层不长期定义表达，也不维护跨文章能力结论。

---

## 1. 单篇文章目录

```text
YYYY-MM-DD_short_title/
├── article.md
├── reading_view.tex
├── reading_view.pdf
└── assets/
```

### `article.md`：原文阅读页

面向第一次阅读和以后回看。

只保存：

- 标题；
- 作者；
- 杂志 / 网站 / 栏目；
- 原始发布日期；
- 必要来源定位；
- 原文。

不要在正文中插入学习答案、表达编号、发音标记或 AI 解释。

### `reading_view.tex`：单篇精读训练手札

面向训练。

可以保存：

- Cornell 双栏精读；
- 理解断点；
- 本篇结构；
- 声音与韵律训练；
- 复述和观点输出；
- AI 对谈中的关键反馈；
- 候选表达及其 `EXP-xxx` 引用；
- 能力层可以引用的证据。

其中任何具有长期复用价值的表达，都应在 `02_expressions/` 中建立完整节点；TeX 只保留当前语境所需的简要说明和链接。

### `reading_view.pdf`：阅读与批注产物

由 TeX 编译，不直接维护内容。

### `assets/`：辅助材料

只有实际需要时才创建，用于原页截图、文章音频、图片等。

---

## 2. 文章层内部的数据边界

```text
article.md
   │ 提供原文
   ↓
reading_view.tex
   │ 产生候选表达 / 训练证据
   ├────────→ 02_expressions/
   └────────→ 03_capabilities/
```

TeX 中再次呈现原文是排版需要，不代表 TeX 拥有另一份独立原文。原文转写若有纠错，以 `article.md` 为准，再同步训练版。

---

## 3. 不新增 `study.md`

当前阶段不再增加一个与 TeX 平行的 `study.md`。

原因是：

- `article.md` 已承担干净原文；
- `reading_view.tex` 已承担单篇训练手札；
- 表达和能力又分别有自己的长期所有者。

再加一份结构化学习笔记会让同一训练内容出现第三份维护位置。只有未来确实需要网页 / 数据库自动渲染，并且已有明确生成链路时，再评估是否引入中间数据层。
