# 单篇文章训练规范

> **定位**：本文规定文章层内部的两个对象如何分工，以及一篇文章怎样从首读走到训练闭环。具体的人机交互顺序、标记握手、参考复述与停止条件由 [`session_protocol.md`](session_protocol.md) 唯一拥有；Obsidian 标记细节见 [`obsidian_interaction.md`](obsidian_interaction.md)。

---

## 1. 单篇目录包含两个核心对象

```text
article.md
原文阅读与首读标记
        ↓
reading_view.tex
本篇精读、声音和输出训练
```

两者不能合并成一份“大而全笔记”。

### 1.1 `article.md`

面向学习者直接阅读。保存：

- 文章标题与必要来源信息；
- 原文正文；
- Obsidian 稳定块标识；
- 学习者自己的首读高亮和轻量标记。

不保存 AI 预先生成的：

- 文章总结和结构答案；
- 全文翻译；
- 长难句讲解；
- 表达节点；
- 发音与语调标注；
- 复述成品；
- 能力评价。

### 1.2 `reading_view.tex`

面向训练和打印。保存当前文章独有的训练信息，例如：

- 原文与局部定点解释；
- 首读真实断点；
- 文章结构与主旨复原；
- 值得练的语音训练句；
- 学习者真实复述、观点和对谈；
- 候选表达及 `EXP-xxx` 引用；
- 主动表达缺口；
- 可供能力层引用的训练证据。

它是“本篇训练现场”的所有者，不是表达节点和长期能力状态的所有者。

## 2. `article.md` 怎样设计

推荐结构：

```markdown
---
type: english-article
source: ...
section: ...
author: ...
published: ...
source_url: ...
source_page: ...
topics: [...]
---

# Article Title

Paragraph one. ^p01

Paragraph two. ^p02
```

### 2.1 来源信息放在 Properties

来源信息主要用于识别和追溯，不应占据正文顶部的大块阅读空间。未知字段可以省略，不为模板完整强行填空。

`topics` 只用于检索，不承担文章摘要职责。

### 2.2 正文保留稳定块标识

每个自然段末尾使用 `^p01`、`^p02` 等 Obsidian 原生块标识。表达层或能力层需要回链时，直接引用具体段落。

### 2.3 与正文存在语义依赖的 Box / Sidebar 属于文章源内容

如果正文明确要求读者“先看某个 box / sidebar / table / figure”，或者缺少它会让后续段落、题目或论证无法正常理解，那么这个组件不是可选附件，而是 `article.md` 的一部分。

处理原则：

- 保留原始措辞和标题，不把 AI 解释混进去；
- 在线性化阅读副本中，优先放到正文第一次明确调用它的位置附近，让阅读链不断裂；
- 如果只是装饰性图片、广告、页眉页脚或与正文没有解释依赖的边栏，不为“完整”而机械搬入；
- 若原刊布局与线性阅读顺序不同，可以调整组件位置，但不要改写其内容，也不要制造第二份重复文本。

### 2.4 首读痕迹属于学习者

学习者可以在原文中留下 `[?]`、`[!]`、`[★]`、`[~]` 等轻量标记。AI 不得擅自替学习者制造这些痕迹。

详细交互见 [`obsidian_interaction.md`](obsidian_interaction.md)。

## 3. `reading_view.tex` 怎样组织

Cornell 6:4 的价值不是“左边放原文，右边塞满解释”，而是让**原文和当前真正需要处理的信息保持邻近**。

### 3.1 题头

只放识别文章和训练所需的信息：

- 标题；
- 可选副标题；
- 来源；
- 主题；
- 可选训练标签；
- 日期。

不要在题头提前给出文章答案式总结。

### 3.2 双栏精读

左栏负责原文，右栏只处理当前段落真正值得停下来的内容。

右栏可以写：

- 这里为什么难懂；
- 结构怎样挂接；
- 当前语境下某个词或搭配是什么意思；
- 一条真正有帮助的口语重构；
- 候选表达或对应 `EXP-xxx`。

右栏不复制表达层的完整节点，也不为每个段落强行生成笔记。没有真实断点时，右栏可以很短甚至为空。

长文章不必为了排版完整而把全文全部复制进 TeX。只呈现需要精读的段落，并通过 `Pxx` 与 `article.md` 对应即可。

### 3.3 文章结构与主旨

这部分在训练后完成，用于检验学习者是否真正理解文章如何推进。

结构应服从文章文体，例如：

- 新闻：发现 → 证据 → 解释 → 不同观点 → 后续影响；
- 评论：问题 → 立场 → 理由 → 让步或反方 → 结论；
- 科普：现象 → 原理 → 例子 → 限制 → 启示；
- 叙事专栏：场景 → 经历 → 转折 → 观察 → 判断。

不要为了统一格式而把所有文章硬套成同一结构。

### 3.4 语音与韵律

只选真正值得反复模仿的句子。每条训练记录可以包含：

- 声音参考；
- 原句；
- 必要的 IPA；
- 意群与信息重音；
- 弱读、衔接和语调；
- 学习者真实练习后仍需要提醒的问题。

文字标注不能替代真实声音。完整方法见 [`prosody_guide.md`](prosody_guide.md)。

### 3.5 脱稿输出、参考复述与观点

输出任务根据文章长度和内容决定，可以包括：

- 快速概括；
- 结构化复述；
- 更完整的长复述；
- 个人观点；
- AI 多轮对谈。

常见的“30 秒”“1 分钟”只是训练尺度，不是每篇文章都必须机械完成的指标。

最重要的是先保留**学习者真实输出**。第一次完整复述前，AI 不给范文。真实输出和关键诊断完成后，AI 应给一版事实准确、结构清楚、难度约为学习者当前输出 `+1` 的**参考复述**，并与学习者版本做简短对照。参考版必须明确标成 AI 输出，不能写成学习者已经会说的内容或生命周期证据。

如果学习者已经多轮复述、继续练只会变成模仿参考版，或学习者明确表示够了，当次停止整篇重复，把下一次检索留给间隔复习。

### 3.6 本篇沉淀

训练结束后，只记录本篇最后向外输送了什么：

- 进入表达层的 `EXP-xxx`；
- 仍只属于本篇的主题词或局部解释；
- 值得能力层引用的代表性证据；
- 后续需要再次主动检索的问题。

详细表达定义去 `02_expressions/`，长期能力判断去 `03_capabilities/`。

## 4. 哪些内容通常只留在本篇

通常不需要上升为长期资产的内容包括：

- 某一句的句法挂接；
- 某段的指代关系；
- 当前文章才需要的背景解释；
- 本篇结构梳理；
- 本次复述原始版本；
- 本次 AI 对话中的局部纠错；
- 只在当前主题中有用的专业词。

这些信息的价值主要来自当前语境，没有必要全部搬进长期网络。

---

## 5. 哪些内容应该离开本篇

### 5.1 进入表达层

当某个表达具有明确沟通功能、较高迁移价值，并且未来真实可能使用时，在 TeX 中保留 `EXP-xxx` 引用，由表达层维护完整节点。

### 5.2 进入能力层

单次失误默认不进入能力层。只有某个现象在不同训练中反复出现，或者某次表现具有明显代表性时，能力层才建立结论并链接回来。

## 6. 训练密度怎样决定

不为单篇文章设置统一硬上限。训练深度综合考虑：

- 篇幅；
- 信息密度；
- 原文语言质量；
- 当前学习目标；
- 已有表达网络；
- 当天可用时间。

原则是：

> **文章本身决定训练密度，学习价值决定保留密度。**

一篇高质量长文可以跨多个训练时段。一篇主题重要但语言迁移价值一般的文章，可以理解得很深，却只沉淀少量表达。

## 7. 一篇文章什么时候算训练闭环

不按固定条数打勾，而看以下功能是否已经完成：

- **标记闭环**：学习者的首读标记已经全部回显并得到反馈，数量冲突没有被静默跳过；
- **理解闭环**：关键阅读断点已经真正解决；
- **结构闭环**：能脱离原文说清文章怎样展开；
- **语音闭环**：最值得练的发音、节奏或语调问题已经经过真实听、模仿和对比；
- **表达闭环**：值得长期保存的表达已经正确归档；
- **输出闭环**：已经保留至少一份学习者真实输出；
- **对照闭环**：学习者真实输出之后已有一版 AI 参考复述，并明确了最重要的内容、结构与表达差异；
- **反馈闭环**：本次训练暴露出的重要问题已经明确去向，留在本篇、进入表达层，或成为能力层证据；
- **复习闭环**：已写清下一次先不看参考答案要冷检索什么。

文章长短不同，完成这些闭环所需的训练量自然不同。

## 8. 推荐目录

```text
01_articles/
└── YYYY/
    └── YYYY-MM-DD_short_title/
        ├── article.md          # 原文阅读副本、来源、首读标记
        ├── reading_view.tex    # 单篇训练现场
        ├── reading_view.pdf    # 编译产物
        └── assets/             # 原页、音频、附图等按需保存
```

当前不增加与 TeX 平行的 `study.md`。只有未来确实出现网页或数据库渲染需求，并且已有明确生成链路时，再评估是否引入新的结构化中间层。
