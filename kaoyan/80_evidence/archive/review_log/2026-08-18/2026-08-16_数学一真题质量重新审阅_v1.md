## 一、本轮结论

本轮不能把“40 年机器检查全绿”直接解释为“数学真题质量已经完全达标”。初始机器门主要覆盖题量、文件存在、SVG 配对、主题面唯一性与答案泄露等结构事实，但没有验证 **Profile 与年度实际结构是否一致、逐题学科路由是否一致、数学一三类题型是否被共享题解合同正确表达**。

重新审阅后得到三类结论：

1. **Canonical Source 结构层总体稳定，但仍存在历史 LaTeX Fidelity 债务**；2026 年主题面已完成一轮人工公式/符号清洁。
2. **Exam Profile 存在两处系统性事实错误，已修正并加入机器门**：2007 年被错误并入 2008～2020 的 23 题结构；2021～2026 的 Q7 被错误路由为概率统计。
3. **旧 `qNN_*.md` 不能继续视为现行高质量题解 Owner**：它们普遍重复题面、采用旧“题面 + 答案与深度解析”两段式结构；当前数学一尚未建立新的 `solutions/qNN.md` 心智模型题解层。

## 七、2021～2025 倒序人工深审

### 7.1 2025：发现两个 Derived 推理缺陷

2025 Q1～Q22 已逐题独立复算，选择、填空与最终数值答案本身未发现错键；但旧解析暴露两处实质性质量问题：

1. **Q19 充分性证明缺少严格性闭合**：旧证明最终只得到 $f'(x_1)\le f'(x_5)$，不能据此宣称导函数严格递增。现改为任取 $u<c<v$，构造
   $$
   f'(u)\le \frac{f(c)-f(u)}{c-u}
   <\frac{f(v)-f(c)}{v-c}\le f'(v),
   $$
   从中真正得到 $f'(u)<f'(v)$。
2. **Q21 解集被错误收窄**：旧答案额外要求 $a_1a_2a_3\ne0$，会漏掉合法的含零分量解。由 $(A-E)^2=0$ 可知任意 $\alpha$ 都满足第二个结构条件，题目只需 $\beta=(A-E)\alpha\ne0$，因此唯一限制应为
   $$
   a_1+a_2\ne2a_3.
   $$

Canonical Source 同时完成一轮显式微分、条件集合、正体常数、分段环境与方向导数记号清洁。

### 7.2 2024：答案闭合，修正 Q5 图形语义污染

2024 Q1～Q22 已逐题复算，未发现旧答案结论错误。Q5 三平面位置关系的 Semantic SVG/TikZ 则存在一条无题意来源的折线虚线：`O -> (0.8,1.2) -> P`。它既不是三平面的共交线，也不对应任何遮挡后的真实直线，会制造额外几何关系。

本轮已从：

- `assets/src/q05_three_planes_pencil.tex`；
- 暗色 `assets/q05_three_planes_pencil.svg`；
- 亮色 `assets/light/q05_three_planes_pencil.svg`

同步删除该折线，并把源码语义明确为“三张平面共过同一直线 OP”，对应 $m=n=2$。

继续追查资产生成链时还发现两处工具级 Ownership 错误：`generate_math1_svgs.py` 曾把 2024 Q5 作为 `q01_three_planes.svg` 生成，`build_math1_archive.py` 的年度资产映射也把该图错误路由到 Q1；而当前 `exam.json` 与 Canonical TikZ Source 均明确其真实身份是 Q5。现已：

- 将 builder 映射修为 `q05 -> assets/q05_three_planes_pencil.svg`；
- 从 legacy direct-SVG 生成器移除 2024 Q5 的第二份几何实现，防止覆盖 TikZ-backed Canonical Asset；
- 明确图形 Ownership：有 `assets/src/*.tex` 的图由 TikZ Source 拥有几何语义，direct-SVG 生成器只维护尚未迁移的 legacy 图；
- 修正生成器执行语义：直接调用必须显式 `--all`，`--help` 与无写入确认不再触发重生成；builder 仅在用户显式 `--regenerate-svg` 时传入该授权。

审阅过程中曾在修复前调用一次 `generate_math1_svgs.py --help`；旧脚本忽略参数并执行了全量生成，因此工作树新增了 24 组、暗/亮共 48 个**未跟踪** direct-SVG 文件。它们没有进入 Canonical Source 或 Git tracked 资产，当前 Gate 也不引用它们。DevSpace 当前暴露的文件写接口没有删除动作，而 shell 合同明确禁止用 `rm/git clean` 绕过，因此本轮不越权删除；这些文件作为一次性运行态残留单独记为 cleanup debt。生成器本身已加回显式授权门，后续 `--help` 不会再产生同类副作用。

这次问题说明“派生图可以重生成”不能等价为“任意生成器都可以覆盖同名图”；生成机制也必须服从唯一 Owner。

## 八、仍未闭合的质量债务

### 8.1 历史 Canonical Source 的数学排版债务

全库扫描仍发现大量历史写法与当前 LaTeX Type System 不一致，例如：

- 裸 `dx / dy / dz`；
- `dxdydz`；
- 键盘 `|...|` 表绝对值或条件；
- 集合条件使用裸 `|`；
- 个别旧式 Unicode 数学符号。

这些不应仅凭正则表达式全库替换，因为同一个 `|` 可能分别承担绝对值、条件概率、集合条件或原题文本角色。正确做法仍是按年度/题目进入 Fidelity Pass，并在能确认语义时修正。

### 8.2 旧解析层尚未迁移

现有 896 份 `qNN_*.md` 继续保留为 legacy derived reference，不应原地改造成第二套 Canonical Source，也不应继续把它们当作“已经达到心智模型题解标准”。

下一阶段应在年度 `solutions/` 下重新建立 Derived Solution Layer，并只链接 Canonical Exam Source，不再复制完整题面。

### 8.3 场景路由工具存在协议实现差异

`agent_context_protocol.md` 已定义 `exam-solution` 场景，但当前 `cognitive_system.py start` 的 CLI 枚举没有该场景，本轮只能用 `review` 启动。该问题不影响本次真题内容修正，但属于维护工具债务，后续应单独闭合。
