# 408 真题题解跨年质量审阅 v1

日期：2026-08-16  
范围：`archives/408/2015年真题` ～ `archives/408/2026年真题`  
对象：Derived Solution Layer，共 12 年 × 47 题 = 564 份 `solutions/qNN.md`

## 1. 本轮目的

本轮不是继续扩年份，而是先回答三个维护问题：

1. 已写题解是否具有真正一致的结构，而不是“每年看起来差不多”；
2. 题解是否支持学生从真题中恢复心智模型，而不只是查看答案；
3. 以后如何让格式漂移、路由漂移、答案索引分叉和模型反馈遗漏变成可被系统及时发现的问题。

稳定 QA Owner 已建立：`00_system/exam_solution_quality_assurance.md`。

## 2. 全量文件事实审阅

全量扫描结果：

```text
solution files        = 564
completed years       = 2015..2026
files per year        = 47
objective answers     = 400
annual README         = 10/10
annual solution_review= 10/10
source/legacy refs    = resolved
```

400 道选择题的 `answer` 同时与年度全景索引及现存 legacy answer 字段交叉比较：

```text
solution vs annual index mismatch = 0

```

这只能证明**答案资产之间没有分叉**，不能代替独立知识正确性证明；知识正确性仍由每题的 model-grounded derivation + Verification 和年度内容审阅负责。

## 3. 实际发现的格式漂移

在新的严格 Gate 建立前，全量结构扫描确实发现了历史漂移，并非“已经完全一致”：

- 2025 校准年仍有大量选择题缺 `解题链` 或 `选项判断` H2；
- 2025 综合题若干缺 `Problem Representation / Decision Points`；
- 2025 使用过 `逐项判断`、`其他选项为什么不对` 等平行 H2；
- 2024/2026 个别算法题把 `Why Correct / Complexity` 提升成平行 H2；
- 2026 Q47 把 Source 条件说明写成平行 `Source Note` H2；
- 2026 个别题把 Source 状态编码进 `status: model-grounded-v1-with-*`，使 Derived Solution 状态词发生漂移；
- 2025 `solutions/README.md` 在迁移后缺失。

把新的机器 Gate 接入 `cognitive_system.py` 后，一次性暴露出 54 个结构/支持文件/状态硬错误。全部修复后：

```text
E-EXAM-SOLUTION-* = 0
repository check  = PASS
```

这说明以前只用“47 文件都存在 + 标题大致存在”的检查不足以保护长期一致性。

## 4. 格式修复中的二次风险

本轮在统一 2025 H2 时，人工抽查发现一个重要维护风险：**格式迁移本身也可能引入语义错误。**

例如某题补 `选项判断` 时，如果只依据题号/记忆写一个泛化总结，就可能与该题已有 `解题链` 不一致。发现后已经回到对应题解主推理逐题校正。

因此新增维护原则：

```text
Format Migration
-> preserve original derivation
-> rebuild summary from current Solution Chain
-> answer consistency check
-> semantic spot-check
```

禁止为了“填齐标题”生成与正文无关的占位总结。

## 5. 学生学习视角的统一结论

跨年审阅后，题解不应追求统一字数，而应统一**认知功能位置**：

```text
Model Anchor       = 为什么想到这个模型
Representation     = 题面变成什么对象/状态
Decision           = 为什么走这条路
Solution Chain     = 模型怎样生成答案
Verification       = 怎样尽早发现错了
Compression        = 下次如何重新调用
易错边界           = 哪两个相邻概念不能混
```

选择题省去独立 `Problem Representation / Decision Points` H2，但这两个动作必须实际发生在 `Model Anchor / 解题链` 中；综合题则显式保留。

学生推荐使用节奏：

```text
独立作答
-> 只揭示 Model Anchor / Representation 再尝试
-> 对照 Decision / Solution Chain 找 First Divergence
-> 遮住正文，用 Compression + Verification 复原
```

题解目标不是“解释得越来越长”，而是让学生逐渐不需要看完整题解。

## 6. Model Feedback 审阅

2015～2026 的年度 `solution_review.md` 已经积累大量 Candidate Evidence，例如：

- DS：Representation / Candidate Set / Invariant / 可复用状态；
- CO：Math / Type / Machine 分层、地址位预算、Cache/VM 分层、CF/OF 边界；
- OS：Event 权限、Blocked→Ready≠Running、冲突图与最小锁粒度；
- NET：Scope / State Owner、序号空间、方向化账本、分片守恒。

本轮对照四科现有 Rules 后，没有发现一个“现有 Canonical Handbook 已被真题证明为事实/机制错误却仍未修”的明确硬冲突。多数重复模式已经以待验证 Rule 或同义控制动作存在于当前 Rules 中；因此本轮不为了显得有产出而重复写第二份规则。

但系统规则已经改为：

```text
Candidate action / exam trick
-> Evidence Promotion

Proven Handbook fact/mechanism/boundary error
-> confirm Source
-> locate unique Owner
-> Stable Write immediately
-> revalidate affected solutions
```

也就是说，“单题不能随便晋升 Rule”不再被误用成“已证实模型错误也一直只记 Challenge”。

## 7. 新的机器硬 Gate

`cognitive_system.py check` 现在对已建立的 408 `solutions/` 自动检查：

```text
Q01..Q47 Coverage
annual README + solution_review
Frontmatter required fields
stable QID / status
Exam Profile subject routing + overrides
Q1..Q40 answer vs annual index
source_exam / legacy_reference existence
exact H2 set + order
Model Anchor: 题目信号 + 第一动作
stable H1
```

机器明确不判断知识正确性、Owner 语义正确性、Verification 是否真正独立、Rule 是否值得晋升。这些继续由人工/Agent 内容审阅承担。

## 8. 当前结论

2015～2026 题解目前可以收口为：

```text
564/564 Coverage
+ Answer Assets Consistent
+ Fixed H2 Structure
+ Stable Frontmatter / Routing
+ Annual Review Present
+ Machine QA Enforced
```

知识层质量仍遵循“每年独立求解 + Verification + 跨年抽样 + Model Feedback Closure”，而不是用机器格式 PASS 冒充“564 道全部重新证明一次”。

2016 的历史 routing override 已通过 Exam Profile 与机器测试固定；2015 也已完成年度 Gate。下一年度进入 2014；以后任何完成年度如果破坏固定题解结构，仓库 `check` 会直接失败。
