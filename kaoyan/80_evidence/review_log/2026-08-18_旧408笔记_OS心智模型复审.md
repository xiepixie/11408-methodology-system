## 3. 本轮最重要的认知升级：PV 从“模板题”变成“许可生成题”

Source 最值得保留的是一套生成式动作：先写进程实际动作，再问每一步的前置条件，把前置事实编码成 P，随后寻找谁在何处制造该事实并执行 V。

当前 OS-03 已经拥有更强的理论语言：Semaphore = Permit Counter + Atomic Wait/Wake；但过去复习入口仍可能让学生从“这是生产者—消费者吗”开始识别。新训练文档将考场入口固定为：

```text
坏状态
-> 继续条件
-> 容量 / 前驱完成 / 互斥许可
-> 初值
-> P 消费 / V 制造
-> 底层结构冲突
-> wait dependency
-> Safety / Deadlock / Starvation / 并发度检查
```

这比“先认经典题型再套模板”更能覆盖 2015、2020、2024、2025 等不同题面。

## 4. Source 中需要主动阻断的过度推广

### 4.1 “有 P 必有 V”不是逐行配对定律

它作为循环资源账本检查很实用，但严格说应检查的是许可生命周期：许可从哪里来、何时消费、是否需要归还。一次性初始许可可以只被消费；一次性事件也可能只产生一次。若把它背成“每个 P 代码附近一定有一个 V”，反而会制造伪约束。

### 4.2 “先同步 P，再互斥 P”不是统一排序规则

标准有界缓冲区里，这个顺序来自具体依赖：若抱着 `mutex` 阻塞等待 `empty/full`，制造该许可的另一方又需要同一 `mutex`，会形成闭环。真正规则是检查“阻塞时仍持有什么，制造等待许可的路径是否需要它”。

### 4.3 “全局锁 + 多资源 P”不是一次性申请的定义

“打破 Hold-and-Wait”是目标；拿着全局 mutex 连续执行多个可能阻塞的 P，并不能自动保证这一点，反而可能让执行流抱锁睡眠。应根据题意选择准入限制、全序、受保护状态的一次性资格判定，或 Banker / safety test。

### 4.4 无死锁不等于无饥饿

Source 多处把“彻底避免死锁”进一步压成像是整体进展已经保证。当前 Canonical 保留 Safety / Deadlock / Starvation 三层检查，公平性还依赖等待队列、准入和调度语义。

### 4.5 Page Fault 不是“磁盘页缺失”的同义词

经典请求分页题中可以按题设把 fault 理解为页面不驻留；系统心智模型必须保留更宽接口：COW、lazy allocation、permission fault 都可能进入 page-fault handler，且纯内存修复不要求阻塞等待 I/O。

### 4.6 I/O 控制方式不能用“固定数据粒度 + 固定 CPU 次数”定义

中断解决的是完成/就绪事件怎样进入 CPU，DMA 解决的是搬运循环由谁执行。设备可以批量中断、合并中断或轮询完成队列；scatter-gather DMA 也不要求单一物理连续块。稳定比较轴应是：等待主体、搬运主体、完成发现方式、CPU/硬件成本。

## 5. X-B03：先纠错，再按写作规范重构

第一次回写只修正了 X-B03 中的事实绝对化，但随后按 `00_system/handbook_writing_spec.md` 复核，发现这种“局部修正 + 对比表”仍然不合格：Bridge 不应继续拥有四种 I/O 控制方式的教材式展开，概念边界也不能只写误区列表，状态迁移不能使用无事件裸箭头。

因此第二轮不再补丁式修改，而是按 Bridge 的 Interface Contract 重构为：

- 母问题：硬件异步完成怎样变成内核可确认的软件完成；
- 对象：request、设备可见映射/描述符、数据缓冲区、完成证据、等待者/完成目标；
- 母接口：提交状态 → 硬件推进 → 完成证据 → 中断/轮询发现 → 驱动核验 → 软件完成；所有接口箭头均显式标注交接语义；
- 机制生成：Problem / Naive Solution / Failure / Mechanism；
- 生命周期：阻塞式设备读取只追踪软硬件交接段，状态迁移显式写事件；
- 不变量：请求身份、映射有效性、缓冲区所有权、完成资格、调度边界；
- 代价与权衡：轮询、中断、DMA、批量完成只保留本接口所需的成本摘要，完整机制回 Owner；
- 概念边界：改用规范五列表，阻断 DMA 完成/中断、Interrupt-driven/Async I/O、DMA/Zero-copy、I/O 完成/Running、DMA 地址/用户 VA；
- 母例与微扰：IRQ 到达但 request 报错，以及“无 IRQ、轮询成功”反例；
- 一页压缩：一句话 + 五个复原问题。

这才是本轮真正的 Canonical Bridge 修正。
