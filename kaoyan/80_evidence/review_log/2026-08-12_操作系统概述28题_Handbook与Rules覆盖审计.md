## 1. 本轮调用的模型

- OS-00：接口、批处理与多道、程序装入、OS 结构、引导、虚拟化；
- OS-01/02：用户态/内核态、系统调用/异常/中断、调度与上下文切换；
- X-B01：硬件可信入口、最小现场、权限转换与 OS 软件处理的责任交接；
- OS Rules：当前规则能否给这些概念辨析题提供足够短的考场入口。

本组题可压缩为四问：

```text
谁的代码正在执行？
-> 事件由当前指令主动/同步触发，还是由外部异步到达？
-> 硬件保存最小返回状态，还是 OS 保存软件现场并执行策略？
-> 结果只是 mode switch，还是进一步发生 schedule/context switch？
```

这条链是本轮从 28 题中反复出现的 Candidate Rule，不因一次结构审计直接进入“已采用”。

## 3. 三个需要保留的题面边界

### Q13：并发与并行不是同义属性

按 408 教材语境，I“具有并发和并行的特点”通常被判真：多任务 OS 支持并发，在多处理器平台上也可并行。它不意味着多任务 OS 必须运行在多 CPU 上，因此 III 假。

更严格的可迁移表达是：

```text
多任务 OS 必须支持并发；是否物理并行取决于可用处理器资源。
```

### Q25：按“动作方向”而不是完整生命周期选 B

“执行系统调用”作为入口动作是 `user -> kernel`，不能因为系统调用最终可能返回用户态就选择 D。CPU 调度/分派选择下一个运行实体，并在恢复现场后把控制交回其用户路径，因此教材答案取 B。

这题若改写成“系统调用服务完成并执行返回指令”，则也会发生 `kernel -> user`；原题没有这样写。

### Q27：区分 Guest 可见特权与真实控制层

Guest OS 可以认为自己运行在最高 Guest 特权级，但敏感操作仍受 VMM 截获、模拟或硬件虚拟化控制。题目中的“VMM 与操作系统特权级相同”若把操作系统指 Guest OS，则错误；不宜把具体 ring 编号泛化成所有虚拟化实现的共同规律。

## 4. 覆盖结论

### Canonical Handbook

- 28 题均可由现有 OS-00、OS-01/02 与 X-B01 的组合生成正确判断；没有发现事实错误或必须立即补写的新机制。
- Q20、Q24 的答案可以由模型推出，但当前 Canonical 对“初始化责任”和“编号到入口的直接索引表示”没有像其他题那样给出短入口，记为较弱覆盖。
- Q13、Q19、Q27 已有机制基础，但教材表述与工程边界之间仍需要使用者在实际作答中证明能稳定区分。

**结论：No Canonical Update。** 一组题面结构审计不足以触发 Handbook 修改。

### Candidate Rule

现有 OS Rules 的首次定位链适合综合题，但对序章概念辨析题偏长。本轮形成一个待验证的短规则候选：

```text
看到“用户态/内核态、中断、系统调用、调度”时：
1. 标执行主体：用户代码 / 内核代码 / 硬件入口；
2. 标触发来源：主动 syscall / 当前指令异常 / 外部中断；
3. 标责任层：硬件最小返回状态 / OS 完整软件现场与策略；
4. 标转换结果：仅 mode switch / 进一步 schedule / 真正 context switch。
```

检查方式：若一项同时混写两个阶段，先拆成“发生时、响应后、处理完成后”三个时刻再判断。

**结论：Candidate Rule，暂不修改 Rules。** 下一轮需要使用者无提示作答，并观察这四步是否降低 Q3/Q8/Q16/Q22/Q25/Q26 的混淆。
