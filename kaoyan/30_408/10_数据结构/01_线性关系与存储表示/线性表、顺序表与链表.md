# 线性表、顺序表与链表

> 训练定位：解决“逻辑结构与存储结构怎么分”“线性表为什么不是数组”“顺序表与链表的复杂度结论有什么前提”“链表指针题怎样避免丢链”等基础辨析与操作推演。  
> 模型归属：[DS01 线性关系与存储表示](DS01_线性关系与存储表示_方法论手册.tex)。线性表、顺序表示、链式表示及其不变量由 Canonical 正文拥有；本文件只负责识别、第一动作、复杂度前提和指针操作训练。

## 先建立三层词典

不要把“线性表、数组、顺序表、链表”放在同一层比较。

| 层次 | 这一层回答什么 | 典型对象 |
|---|---|---|
| 逻辑关系与操作契约 | 元素之间是什么关系？允许怎样访问、插入、删除？ | 线性表、有序表、栈、队列 |
| 存储方法 | 元素以及关系靠什么机制编码？ | 顺序存储、链式存储、索引、散列 |
| 具体表示 | 真实要维护哪些字段与不变量？ | 顺序表、单链表、双链表、循环链表 |

“数组”在不同语境下可能指语言提供的连续下标容器，也可能作为一种具体数据结构讨论。408 做线性表题时，最稳的说法不是“数组就是物理结构”，而是：**顺序表用一段连续、可按下标寻址的存储区域实现线性表，数组通常是这种表示的直接语言载体。**

“链表”也不是一个孤立的逻辑关系名称，而是**用链接域显式保存后继/前驱关系的一类具体表示**。

### 局部规则：先问定义换实现后还成立吗

**触发信号**：题目让你判断某个名词属于逻辑结构还是存储结构。

**第一动作**：假设把底层实现从连续存储换成链式存储，问“这个定义是否仍成立”。

**检查与退出**：若定义仍成立，它多半在逻辑/操作层；若名称本身已经指定连续地址、指针、索引或散列机制，就已经进入表示层。

## 问题一：逻辑结构和存储结构有什么区别

逻辑结构只描述**元素之间应该满足什么关系**，不关心机器地址；存储结构描述**怎样把元素本身以及这些关系编码进存储器**。

例如逻辑线性表

$$
L=(a_1,a_2,\ldots,a_n)
$$

只要求 $a_i$ 与 $a_{i+1}$ 具有相邻次序。它可以用连续位置表示，也可以让每个节点保存后继指针。

因此不要说“存数据只要保存元素值”。若物理相邻本身不能唯一恢复逻辑关系，就必须额外保存关系信息；单链表的 `next`、树节点的孩子指针、图的邻接信息都属于这种表示成本。反过来，顺序表不需要为每一对相邻元素保存显式指针，是因为**地址规则本身已经编码了位序关系**。

## 问题二：线性表为什么不是数组

因为二者回答的问题不同。

线性表回答的是：

> 有一个有序序列，插入、删除后应该得到什么新的逻辑次序？

顺序数组式表示回答的是：

> 用怎样的连续地址规则保存这个序列？

同一个线性表可以被实现为顺序表或链表。换掉表示以后，元素的逻辑次序和基本操作语义仍可以保持不变，所以“线性表”不能等同于“数组”。

一个很有用的反例是：若 $[a,b,c]$ 用单链表保存，地址可以完全不连续，但它仍然是线性表；因此“线性”说的是**关系是一条链式次序**，不是说物理地址排成一条连续线。

> **易错边界：**“线性表不是数组”不等于“数组与线性表毫无关系”。顺序表恰恰通常利用数组或等价的连续存储区域实现。

## 问题三：为什么顺序表随机访问是 $O(1)$

这里的“随机访问”是 **按给定下标直接访问**，不是“随机选择一个元素”。

若首地址为 $B$，每个元素宽度为 $w$，第 $i$ 个零基元素地址为

$$
\operatorname{addr}(A[i])=B+i\,w.
$$

在通常的随机存取机模型中，固定次数的整数运算和一次内存寻址视为常数时间。因此从 $i$ 到地址不需要经过 $A[0],A[1],\ldots,A[i-1]$，按位访问是 $\Theta(1)$。

### 局部规则：看到“顺序表查找”先分两种查找

**触发信号**：题目说“顺序表查找/访问”。

**第一动作**：先判断输入给的是“位序/下标”还是“关键字/值”。

**检查与退出**：按下标定位是 $\Theta(1)$；若只给值且没有额外索引，仍需逐项比较，最坏是 $\Theta(n)$。不要把“随机访问 $O(1)$”偷换成“任何查找都 $O(1)$”。

## 问题四：为什么链表按位查找是 $O(n)$

单链表没有“第 $i$ 个节点地址 = 首地址 + 固定偏移”这样的可计算关系。要找到第 $i$ 个节点，只能从入口沿 `next` 一次次走：

```text
head 指向第 1 个节点；再沿 next 依次到第 2 个、……、第 i 个节点
```

每次跳转本身可以视为 $O(1)$，但需要 $i-1$ 次跳转，所以访问第 $i$ 个节点是 $\Theta(i)$；当 $i$ 可以接近 $n$ 时，最坏复杂度为 $\Theta(n)$。

> **易错边界：**如果题目已经直接给了目标节点指针，那么读取该节点字段当然是 $O(1)$。$O(n)$ 说的是“只有表入口和位序时，从入口定位到第 $i$ 个节点”的成本。

## 问题五：头指针、头结点、首元结点有什么区别

把它们画成不同对象最稳：

```text
head  ──指向──> [头结点] ──next──> [首元结点] ──next──> ...
指针变量          哨兵节点              第一个有效数据节点
```

- **头指针**：保存链表入口的指针变量/引用。采用头结点时，它通常指向头结点；不采用头结点时，它通常直接指向首元结点。
- **头结点**：可选的哨兵节点，位于首元结点之前，通常不计入线性表长度，其数据域通常不承担有效元素语义。
- **首元结点**：真正保存第一个有效数据元素的节点。

采用头结点的核心收益是**把首部操作也改写成“已知前驱后的普通局部改边”**。空表时仍可以保留头结点，只需让其 `next` 表示“没有首元结点”。

### 局部规则：先声明“带不带头结点”

**触发信号**：链表题出现 `head/L`、空表、首部插删或循环链表。

**第一动作**：在草稿第一行写清楚：`带头结点 / 不带头结点`，并画出 `head` 实际指向谁。

**检查与退出**：所有判空、遍历终止和首部插删代码都必须服从这个约定；不能把两套表示的代码混用。

## 问题六：单链表逆置时最容易丢掉什么指针

最容易丢掉的是：**当前节点原来的后继，也就是“尚未处理后缀的唯一入口”**。

设

```text
prev：已经逆置完成的前缀入口
curr：当前节点
next：尚未处理后缀入口
```

一轮必须按这个依赖执行：

```text
next = curr->next;   // 先保存旧后继
curr->next = prev;   // 再反转当前边
prev = curr;
curr = next;
```

如果先执行 `curr->next = prev`，再去读 `curr->next`，原后继已经被覆盖，剩余整段链表就可能失去入口。

逆置时最值得记的不是四行代码，而是不变量：

> **`prev` 所指前缀已经完全反向；`curr` 所指后缀仍保持原方向；二者之间唯一需要本轮重接的边就是 `curr->next`。**

循环结束时 `curr == null`，此时 `prev` 是新的首元结点；若维护 `tail`，旧首元结点应成为新尾结点并满足 `tail->next == null`。

### 局部规则：覆盖指针前先问“我以后还怎么找到那一段”

**触发信号**：任何链表逆置、删除、重排或换边代码准备覆盖一个 `next`/`prev` 字段。

**第一动作**：先保存覆盖以后仍要继续访问的旧边。

**检查与退出**：每次修改后确认“已处理部分可达、未处理部分仍有入口”。一旦某段只剩即将被覆盖的唯一引用，先保存再写边。

## 问题七：“链表插入是 $O(1)$”有什么前提

这句话只描述**已经定位到局部改边位置以后**的更新成本。

对单链表，已知前驱节点 $p$，在其后插入 $x$：

```text
x->next = p->next;
p->next = x;
```

固定几次指针读写，所以局部更新是 $\Theta(1)$。但下面这些场景不能直接套：

| 题目实际给你的信息 | 总成本为什么可能不是 $O(1)$ |
|---|---|
| 只给第 $k$ 个位置 | 先沿链定位前驱，最坏 $\Theta(n)$ |
| 只给关键字 | 先按值搜索，最坏 $\Theta(n)$ |
| 要插入到有序位置 | 先找到满足顺序约束的位置，通常 $\Theta(n)$ |
| 要尾插但没有尾指针 | 先走到尾部，$\Theta(n)$ |
| 单链表只给“当前节点”，却要求在它前面插入 | 通常仍需找前驱，除非题目允许改变节点身份/数据语义的特殊技巧 |

因此复杂度必须写完整对象：

$$
T_{\text{insert}}
=
T_{\text{locate}}
+
T_{\text{update}}.
$$

链表真正稳定的优势是：**一旦局部位置已经被表示为节点/前驱引用，插删不需要像顺序表那样移动后续全部元素。**

## 问题八：为什么“单链表 / 循环链表 / 双链表”还不足以直接判复杂度

因为复杂度不仅由链的方向决定，还由题目到底保存了哪些**入口字段**决定。做端点操作题时，把表示先压成：

```text
(单向/双向, 普通/循环, 有无头结点, 长期保存哪些入口, 本次已经给出什么位置)
```

其中“入口”至少包括头指针、尾指针；“本次已经给出什么位置”包括目标节点、前驱、后继或位序。

| 表示 | 头插 | 头删 | 尾插 | 尾删 | 真正瓶颈 |
|---|---:|---:|---:|---:|---|
| 单链，仅头入口 | $O(1)$ | $O(1)$ | $O(n)$ | $O(n)$ | 找尾 / 找尾前驱 |
| 单链，头 + 尾指针 | $O(1)$ | $O(1)$ | $O(1)$ | $O(n)$ | 尾删仍找不到前驱 |
| 双链，头 + 尾指针 | $O(1)$ | $O(1)$ | $O(1)$ | $O(1)$ | 两方向邻接都可直接取得 |
| 循环单链，仅尾指针 | $O(1)$ | $O(1)$ | $O(1)$ | $O(n)$ | `tail->next` 可得首部，但尾前驱仍需遍历 |

> **易错边界：**循环性只把尾部重新接回入口，它没有创造 `prev`，也没有自动替你保存尾指针。双向性、循环性、入口字段是三件不同的事。

### 局部规则：复杂度题先做“字段盘点”

**触发信号**：题目问某种链表的首尾插删复杂度、最适合做队列的链式表示，或比较几种表示优劣。

**第一动作**：先写 `head / tail / prev / next / circular / header` 中题面明确存在的字段，再拆成

$$
T_{\text{op}}=T_{\text{locate}}+T_{\text{update}}+T_{\text{repair}}.
$$

**检查与退出**：如果某个选项的真假依赖“有没有尾指针 / 有没有头结点 / 是否已给前驱”，而题面没有说明这些条件，停止强行选唯一项，先检查题面是否欠定。

## 问题九：链表指针题为什么不能死背唯一赋值顺序

设在双链表中已知节点 `p`，其旧后继为 `q=p->next`，要把新节点 `x` 插入两者之间。最终必须满足：

```text
p->next = x
x->prev = p
x->next = q
q->prev = x       // q 非空时
```

真正的约束不是“这四句必须按某个固定顺序写”，而是**旧值被覆盖以前，所有仍依赖这个旧值的读取必须已经完成，或者旧值已经保存到临时变量。**

因此下面两种思路都可能合法：

```text
q = p->next;       // 先显式保存旧后继
...                // 再按任一满足依赖的顺序接四条边
```

或

```text
x->next = p->next; // 先让 x 保存旧后继
...                // 再覆盖 p->next
```

它们形成的是一个**读写依赖偏序**，不是唯一全序。判断选择题中的两段代码时，应逐段检查旧边是否被提前覆盖，而不是因为其中一段与教材示例行序不同就判错。

### 局部规则：先画“旧值依赖”，再看代码顺序

**触发信号**：选项给出多种 `next/prev` 赋值次序，问哪段能完成插入、删除、逆置或重排。

**第一动作**：圈出每一个即将被覆盖、但后面还需要读取的旧字段；若没有临时变量，就要求它先被某个新字段接住。

**检查与退出**：执行完后重新检查局部后置条件——前向可达、反向可达、首尾入口正确、没有把未处理后缀丢失。只要后置条件和依赖都满足，就不要额外要求“代码顺序必须和标准答案一模一样”。

## 问题十：单选题本身也需要做“题面充分性检查”

扫描题、旧题集和二手题库可能漏掉一个前提，而数据结构题恰好经常依赖表示细节。典型危险信号包括：

- 没说顺序表是否有剩余容量，却要求唯一判断插入复杂度；
- 没说链表是否维护尾指针，却比较尾插；
- 没说带不带头结点，却给判空表达式；
- 没说 `front/rear/top` 指向元素还是下一空位，却直接比较公式；
- 单选题中两个选项在同一明确模型下实际上等价或都成立。

### 局部规则：先独立判每个选项，不用“单选”反推理论

**触发信号**：你发现两个选项都像对的，或者必须偷偷补一个题面没有写出的字段才能让答案唯一。

**第一动作**：固定一套最小表示模型，把每个选项分别判真伪，并写出它依赖的前提。

**检查与退出**：若出现多真、多假或“换一个未声明约定答案就变”，把问题标为题面欠定/重复选项；不要为了迎合“单选”标签去修改已经验证过的结构不变量。

## 旧笔记里四个需要改掉的绝对化说法

### “数组、链表就是物理结构”

过于粗糙。408 更稳的层级是“顺序存储/链式存储”属于存储方法；顺序表、单链表等是具体表示；数组是常见连续存储载体，本身也可以作为独立数据结构讨论。

### “逻辑相邻的链表节点在物理内存中几乎总是分散”

不严谨。链式表示**不要求连续**，节点可以分散，也可能偶然连续；正确结论只是“逻辑相邻不能推出物理相邻”。

### “频繁插入线性表就应该选链表”

缺少输入契约。如果每次只给位序或关键字，链表仍要先 $O(n)$ 定位。真正有优势的是“已知节点/前驱后频繁局部插删”或“端点操作且维护相应指针”等 workload。

### “数据运算不属于数据结构本身”

在 408 教材口径下容易误导。更稳的说法是：**逻辑结构、存储表示和定义在其上的基本运算共同构成课程研究对象；ADT 把抽象状态与操作语义作为公开契约，具体算法再在某种存储表示上实现这些运算。**

## 一个反例修正“频繁插入就选链表”

假设长度为 $n$，每次操作给一个整数位序 $k$，要求在第 $k$ 个位置插入。

- 顺序表：定位 $O(1)$，移动后缀 $O(n)$；
- 单链表：定位前驱 $O(n)$，局部改边 $O(1)$。

两者总复杂度都可能是 $O(n)$。此时必须继续比较常数、缓存局部性、空间开销、是否已有迭代器/节点引用等，而不能只背“链表插入 $O(1)$”。

若场景改成“当前播放节点已经拿在手里，频繁在当前歌曲前后插入并需要上一首/下一首”，双链表就更自然：定位已经由当前节点给出，双向邻接和局部插删都是常数级更新。

## 十问压缩

```text
1. 逻辑结构：关系是什么？
2. 存储结构：关系靠地址规则还是显式链接保存？
3. 线性表 != 数组：一个是抽象次序/操作契约，一个是具体表示载体。
4. 顺序表按位 O(1)：下标可以直接算出地址。
5. 链表按位 O(n)：只能从入口逐边走到目标。
6. 链表换边前：先保存仍需访问的旧后继/前驱。
7. “链表插入 O(1)”只从“局部位置已经定位”之后开始计时。
8. 端点复杂度先盘点：单/双、普通/循环、头结点、头尾入口、已知位置。
9. 多段指针代码按读写依赖判，不按“是否和教材行序一致”判。
10. 单选标签不是数学前提：若表示约定缺失或选项等价，先判题面是否欠定。
```
