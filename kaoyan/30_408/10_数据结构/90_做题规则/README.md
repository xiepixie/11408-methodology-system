## 待验证

### 数据结构首次定位链

```text
Goal
-> Relation
-> Operations / Workload
-> Representation
-> Invariant
-> State / Progress
-> Cost / Boundary
```

先确定目标操作和关系，再比较表示；模拟过程中写出当前已确定区域、frontier 或剩余规模，最后统一计算比较、移动、空间与 I/O 成本。若题目已经明确给出结构与操作，直接从 `Representation / Invariant` 开始，不机械补写前置步骤。

### 先写表示，再模拟操作

题目要求执行插入、删除、遍历或查找时，先明确数组、链式节点、矩阵、邻接表或树节点中究竟保存了什么，再画状态变化。

### 修改结构时说出不变量

每次指针修改、旋转、交换、relax 或合并前，先说出操作后必须继续成立的结构条件。

### 边界进入算法骨架

写伪代码前主动检查空结构、单元素、首尾、重复 key 和越界，而不是把它们留到最后补丁式处理。

### 复杂度绑定基本操作

给出复杂度时同时说明计数对象和输入规模，避免只写一个没有成本模型的 `O(...)`。

### 线性表题先拆 Locate 与 Update

看到插入、删除或按值操作时，先分开“是否还要定位元素/前驱”和“定位后怎样修改表示”。只有题目已经给出节点或前驱时，链式局部修改才可记为 `O(1)`；按关键字查找的成本必须另计。

### 长度与容量分开检查

看到顺序表或动态数组时，草稿同时写 `length` 与 `capacity`，先判有效元素区和扩容条件，再计算移动成本；不能把空槽当成有效元素，也不能把一次扩容复制改写成单次 `O(1)`。

### 指针题先写不变量再改边

修改链表前先写 `head / tail / length / next`（双链表再加 `prev`）必须满足的关系，按“接入新边、断开旧边、修复边界、验证可达性”执行；遇到空表、单元素、首尾和重复值时停下来分支。

### 408 代码题先读函数合同

把 补充笔记中的 `c-exam` 细节作为本层控制适配：先圈定输入表示（数组、带头结点链表、树根、邻接矩阵/表）、输出契约（返回、打印或原地修改）、下标区间、空结点标记、方向和“无解”约定，再开始写状态转移。函数签名是答题合同，只写题目要求的函数体，不补 `main`、输入壳或自造测试接口；C 与 C++ 的分配/释放语义不能混用。

数组题逐个核对闭区间/开区间、每个下标所属数组、反向扫描的最小合法下标和值作下标前的值域过滤；二维矩阵题先固定行列语义，行通常统计出边、列统计入边。辅助数组必须显式初始化，标记数组长度要覆盖最大合法下标。

指针题在每次解引用前判空，带头结点从 `head->next` 判断数据起点；需要比较结点身份时比较地址，需要比较内容时比较数据域。删除或逆置前先保存后继，修改头指针时确认是“改局部指针”还是“改调用者的头指针”。递归题固定“出口、当前工作、子问题结果”三问，向下传状态、向上返回答案，并把递归栈 $O(h)$ 计入空间。

### 算法大题从暴力基线升级

先写一个能证明正确的暴力基线，再根据成本向量寻找可复用状态：一次扫描维护极值/计数，双指针对齐链表或多个有序序列，值域标记替代重复比较，原地区间逆置替代辅助数组，树递归返回子树信息，邻接矩阵双循环统计度数，BST 沿单一路径下降。每次优化都必须写出被复用的单调量、减少的重复工作和新的边界前提；不能只以“代码更短”作为最优证据。

正式卷面按“设计思想 → 题目指定函数 → 复杂度与边界”组织。30 秒终检至少覆盖：变量先初始化、端点不越界、`NULL` 不先解引用、循环确实推进、返回/输出/原地修改没有混淆、复杂度与实际循环和辅助空间一致。

### 真题训练的证据路由

历年题与扩展题只作为验证样本，不在本规则页复制题解。遇到数组/矩阵、指针链表、递归树、图矩阵或拓扑唯一性题，分别回指 DS01/DS07、DS04、DS02/DS04、DS08 的 Canonical 机制；记录题号、采用的状态不变量、失败边界和复杂度，作为后续“Rule 是否晋升”的证据。单个题目的技巧只写入题后证据，不直接升级为长期规则。
