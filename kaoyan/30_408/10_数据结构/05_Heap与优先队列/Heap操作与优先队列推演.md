# Heap 操作与优先队列推演

> 训练定位：解决“给一个堆/数组，要求插入、删除堆顶、建堆、判断堆、求比较/交换轨迹”的题目族。  
> 模型归属：[DS05｜Heap 与优先队列](DS05_Heap与优先队列_方法论手册.tex)。完全二叉树布局、上滤/下滤、建堆与优先队列机制由 Canonical 正文拥有；本文件只训练纸面状态推进和边界检查。

## 母题表示：Heap 题始终维护两条不变量

以最小堆为例：

1. **形状不变量**：数组对应完全二叉树，节点紧凑无空洞；
2. **序关系不变量**：

$$
A[parent(i)]\le A[i].
$$

最大堆只把不等号反向。

> **停止条件：**“根最小”只是堆序的结果，不足以证明整个数组是堆；必须检查每条父子边。

## 问题一：先锁定 0 基还是 1 基

### 0 基

$$
parent(i)=\left\lfloor\frac{i-1}{2}\right\rfloor,
\quad left=2i+1,
\quad right=2i+2.
$$

### 1 基

$$
parent(i)=\left\lfloor\frac i2\right\rfloor,
\quad left=2i,
\quad right=2i+1.
$$

### 局部规则：堆数组先锁下标体系

**触发信号**：题目给数组下标、最后非叶节点、建堆起点。

**第一动作**：先写下标体系，之后所有孩子/父亲公式只用这一套。

**检查与退出**：用根和最后一个非叶节点各代一次父子公式；若出现越界或把叶节点当成建堆起点，说明 0/1 起始下标已经混用。

## 问题二：插入不是“放到合适位置”，而是“末尾落位 + 上滤”

为了保持完全树形，新元素只能先进入数组末尾。

最小堆插入：

```text
append x at end
while parent > x:
    swap with parent
stop at root or parent <= x
```

### 检查

上滤只沿一条祖先链移动，因此最多走树高：

$$O(\log n).$$

如果纸面上新元素横向跨到同层另一个位置，已经破坏完全树的结构语义。

## 问题三：删除堆顶固定是“末元素补根 + 下滤”

最小堆：

```text
save root
move last element to root
shrink heap size
compare with children
if violation exists: swap with smaller child
repeat
```

### 局部规则：有两个孩子时先选更小孩子

**触发信号**：下滤位置左右孩子都存在。

**第一动作**：先比较两个孩子，选更小者，再和当前元素比较。

**检查与退出**：只和左孩子比较可能让右孩子仍小于父亲，局部修复不完整。

## 问题四：修改任意位置，方向由“破坏哪条边”决定

最小堆中：

- key 变小：可能比父亲还小 → 上滤；
- key 变大：可能大于孩子 → 下滤。

若只知道把末元素搬到删除位置 $i$，先和父亲比较；若已经小于父亲就上滤，否则检查孩子并下滤。

> Heap 修复不是“每次都先上滤再下滤”，而是根据唯一可能破坏的方向选择一条路径。

## 问题五：判断数组是不是堆，不需要真的建堆

只需从所有非叶节点检查现有孩子：

最小堆：

$$
A[i]\le A[left(i)],\quad A[i]\le A[right(i)]
$$

（孩子存在时）。

最多检查 $n-1$ 条父子边，时间：

$$O(n).$$

### 直接推论

最小堆中：

- 最小值一定是根；
- 第二小值一定在根的两个孩子中；
- 第三小及之后不能只凭数组局部关系直接确定。

## 问题六：建堆必须区分“两种过程”

### 逐个插入

```text
empty heap
-> insert each item
-> repeated sift-up
```

最坏：

$$O(n\log n).$$

### 自底向上建堆

从最后一个非叶节点向根依次下滤。

总代价：

$$O(n).
$$

原因不是“每个节点都是 O(1)”，而是：底层节点数量多但几乎不动，能走很多层的高节点很少。

### 局部规则

**触发信号**：题目问“建堆复杂度”“给数组一次性建立堆”。

**第一动作**：判断题目指 bottom-up heapify 还是 repeated insertion。

**检查与退出**：不要用“单次插入 O(log n)”直接推出所有建堆都必须 O(n log n)。

## 问题七：Heap Sort 必须画“有效堆区间”

升序堆排序常用最大堆：

```text
build max heap
for end = n-1 ... 1:
    swap root with A[end]
    heap_size--
    sift-down root
```

每一轮提交的事实：

> 当前最大元素已经进入最终位置，右侧已排序后缀不再属于堆。

### 检查

若下滤仍把已经提交到数组末端的元素当孩子，就忘记缩小 `heap_size`。

## 问题八：优先队列不是“整个堆已经排序”

Heap 支持的是：

- `top`: 当前极值 $O(1)$；
- `push`: 加一个候选 $O(\log n)$；
- `pop`: 删除当前极值 $O(\log n)$。

任意非祖先节点之间没有排序承诺。

这也是为什么 Huffman、Prim、Dijkstra 只需要优先队列接口，而不需要每轮把全部候选完整排序。

## 代表母题：最小堆插入

初始：

```text
[2, 5, 3, 9, 7, 8]
```

插入 1：

```text
append -> [2,5,3,9,7,8,1]
1 < parent(3) -> swap
[2,5,1,9,7,8,3]
1 < parent(2) -> swap
[1,5,2,9,7,8,3]
```

停止，因为到根。

最终只保证每条父子边合法，不要求 `[1,2,3,5,7,8,9]` 这样的完整有序数组。

## 代表母题：删除最小值

初始：

```text
[1,5,2,9,7,8,3]
```

删根，把末元素 3 补根：

```text
[3,5,2,9,7,8]
```

孩子 5 和 2 中选更小的 2：

```text
3 > 2 -> swap
[2,5,3,9,7,8]
```

当前位置 3 的孩子只有 8，满足 $3\le8$，结束。

## 陌生 Heap 题固定落笔协议

```text
1. 写 min-heap / max-heap 和 0/1 基下标。
2. 先检查完全树形，再检查父子序关系。
3. insert = 末尾 + sift-up。
4. delete-root = 末元素补根 + sift-down。
5. 两孩子下滤先选更优孩子。
6. 修改键值根据破坏方向选择上滤或下滤。
7. build heap 区分 repeated insertion 与 bottom-up heapify。
8. heap sort 每轮缩小有效堆区间。
9. 最后检查：是否错误推出了任意两个节点之间有序？
```

## 最短压缩

> **Heap 只维护完全树 + 父子偏序：插入末尾上滤，删根末元素补位下滤；建堆 O(n) 来自按高度分摊，不是每项 O(log n) 相加。**
