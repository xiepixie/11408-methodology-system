# 帧、透明传输与介质访问

> 训练定位：解决“给出比特流、帧格式、共享介质、交换机或无线场景时，怎样确定边界、检错、发送权与本跳转发”的题目族。  
> 模型归属：[NET-02 单跳交付](NET-02_单跳交付_方法论手册.tex)。Framing、CRC/海明码、CSMA/CD、CSMA/CA、Ethernet/WLAN、交换机、VLAN、PPP 的机制归 Canonical；本文件只训练调用顺序和状态推演。

## 母题表示：一跳题固定拆成四件事

看到链路层题，先不要混着做。草稿先画四格：

1. **边界**：这串 bit 怎样被划成 frame；
2. **正确性**：坏帧怎样被检测，是否有纠错/重传；
3. **发送权**：共享介质时谁何时能发；
4. **转发动作**：收到正确 frame 后交给谁。

这四件事的 Owner 不同，缺一格就容易把 CRC 当可靠传输、把交换机学习方向写反，或把共享 Ethernet 规则套到全双工交换链路。

## 问题一：透明传输先问“边界会不会被数据伪造”

### 局部规则：Flag 题先做可逆性检查

**触发信号**：题目给特殊 flag、ESC、连续 1、PPP/HDLC、字符填充或零比特填充。

**第一动作**：先写发送端的转义规则，再写接收端是否能唯一还原原 payload。

对于经典零比特填充：

- 数据中每遇到连续 5 个 `1`，发送端插入 `0`；
- 接收端识别“连续 5 个 `1` 后的填充 0”并删除；
- 目的首先是让 payload 不生成合法 flag `01111110`。

**检查与退出**：如果原数据中出现 5 个连续 `1`，即使第 6 位本来就是 `0`，按“连续 5 个 1 后插 0”的规则仍要执行 stuffing。不要采用“后面已经是 0 所以不填”的速记说法。

> 上传速记稿在这里存在内部冲突，不能直接迁入：它既写“连续5个1后插0”，又举出“5个1后本来就是0则无需填充”的例子。训练以 Canonical 的可逆 framing 规则为准。

## 问题二：NRZI 不凭口诀，先看“哪个比特触发翻转”

不同教材可能采用相反极性约定，所以 NRZI 题必须以题设约定为第一真值。

### 局部规则：NRZI 先抄事件语义

**触发信号**：题目出现 NRZI、长串 0/1、时钟恢复或 4B/5B。

**第一动作**：在草稿写出题设的明确约定：

```text
某个 bit -> transition
另一个 bit -> no transition
```

然后再判断哪种长串缺乏跳变。

**检查与退出**：若你同时写出“1 触发翻转”和“长串 1 没有跳变”，两句话互相矛盾，必须停下重读题设。

## 问题三：CRC、海明码、ARQ 三者职责要分开

| 机制 | 解决什么 | 不自动得到什么 |
|---|---|---|
| CRC/FCS | 检测某些传输错误 | 不自动纠错、不自动重传 |
| 海明码 | 用冗余定位/纠正一定范围错误 | 不代表存在 ACK/Timer |
| ARQ | ACK/Timer/Seq 形成恢复闭环 | 仍需要底层检错输入 |

### 海明码题固定两步

1. 先由目标能力判断最小码距：
   $$d_{min}\ge s+1\quad(检s位),\qquad d_{min}\ge2t+1\quad(纠t位).$$
2. 若是经典单错纠正海明码，再由：
   $$2^r\ge m+r+1$$
   求校验位数。

**检查与退出**：普通 $d_{min}=3$ 海明码可纠一位错，但不要无条件说“纠1检2”。若题目要求可靠检测双错，先确认是否加入额外总奇偶位形成 SEC-DED。

## 问题四：CSMA/CD 的第一动作永远是画最远冲突时间线

经典共享、半双工 Ethernet 才进入此模型。

最坏情况下，远端冲突信息返回发送站需要约：

$$2\tau.$$

发送端必须还在发送，才能检测到冲突：

$$
\frac{L_{min}}{R}\ge2\tau
\quad\Rightarrow\quad
L_{min}\ge2\tau R.
$$

### 局部规则：先判断是否存在 collision domain

**触发信号**：题目出现 Ethernet、冲突、最小帧长、二进制指数退避。

**第一动作**：先问链路是否“共享 + 半双工”。若是全双工交换式 Ethernet，停止使用 CSMA/CD。

**检查与退出**：如果题目已经是交换机端口到端口的独立全双工链路，却还在算碰撞窗口，说明场景前提错了。

## 问题五：CSMA/CA 用事件账本，不用“无线版 CSMA/CD”类比

经典 802.11 DCF 题按：

```text
信道空闲 DIFS
-> 随机 backoff（忙时冻结）
-> DATA
-> SIFS
-> ACK
```

若启用 RTS/CTS，再在 DATA 前加入：

```text
RTS -> SIFS -> CTS -> SIFS -> DATA -> SIFS -> ACK
```

### 三个计时状态分清

- **Backoff counter**：只有信道空闲时递减，忙时冻结；
- **ACK timeout**：发送后等待本跳成功证据；
- **NAV**：根据其他站帧中的持续时间信息进行虚拟载波侦听。

**检查与退出**：不要写“无线冲突后边发边检测”。发送端通常依赖 ACK 缺失等结果判断失败，而非可靠碰撞检测。

## 问题六：交换机题固定“先学源，再查目的”

收到一个正确 Ethernet frame：

```text
1. Learn(source MAC -> ingress port, age)
2. Lookup(destination MAC)
3. 决定过滤 / 定向转发 / 未知单播泛洪 / 广播泛洪
```

### 局部规则：未知单播不是“把帧改成广播帧”

未知单播时，交换机的动作是向多个端口复制原 frame；目的 MAC 本身仍是单播地址。

### VLAN 题再加一维 Scope

先确定 ingress VLAN，再在对应 VLAN 的 MAC 状态和广播域中做学习/转发。不同 VLAN 间不能靠普通二层转发直接互通。

## 问题七：802.11 地址题先写四个角色

不要死背 Address 1/2/3/4 的固定含义。先写：

- RA：无线当前接收者；
- TA：无线当前发送者；
- SA：原始 source；
- DA：最终 destination。

再依据 To DS / From DS 映射到实际字段。这样可以避免把 AP 当成“既是原始源又是最终目的”的万能角色。

## 问题八：PPP 先分“帧透明性”和“链路状态机”

### 帧题

经典骨架：

```text
Flag | Address | Control | Protocol | Information | FCS | Flag
```

先判断异步字节填充还是同步零比特填充，再处理 FCS。

### 状态题

按：

```text
physical up
-> LCP establish/configure
-> authentication?（可选）
-> NCP configure
-> network-layer data open
```

**检查与退出**：LCP 成功不等于 IP 已可用；还要看认证分支和对应 NCP 是否完成。

## 代表母题 A：最小帧长

某共享 Ethernet 速率为 $100\text{ Mb/s}$，最远单向传播时延为 $2.5\mu s$。

第一动作：

$$
L_{min}=2\tau R
=2\times2.5\times10^{-6}\times100\times10^6
=500\text{ bit}.
$$

随后再根据协议规定的合法最小帧长、字节对齐等题设判断最终答案。这里公式只给“碰撞可检测性下限”。

## 代表母题 B：交换机学习

初始 MAC 表为空，端口 1 收到：

```text
src=A, dst=B
```

状态推进：

1. 学习 `A -> 1`；
2. 查 B 未命中；
3. 向除端口 1 外的同 VLAN 相关端口泛洪。

随后若端口 3 收到 `src=B, dst=A`：

1. 学习 `B -> 3`；
2. A 命中端口 1；
3. 只向端口 1 定向转发。

## 题库验证：代表题与变式轴

当前正式题库已经对本 Topic 的主要控制链形成了多角度证据：

| 证据题 | 表面题型 | 实际验证的母模型 |
|---|---|---|
| 757、758 | 字符/零比特填充 | framing 必须可逆，边界符不能被 payload 伪造 |
| 759、760、765、766 | 码距、海明码、CRC | 检错、纠错与 ARQ 恢复职责分离 |
| 775–785 | 争用期、最短帧、退避 | 先判共享半双工，再由最远冲突时间生成 CSMA/CD 约束 |
| 786–788 | 无线 ACK、退避、IFS | CSMA/CA 是“侦听—退避—发送—ACK”的事件状态机，不是无线版碰撞检测 |
| 794、825、826 | 交换机自学习与泛洪 | `Learn(source) -> Lookup(destination) -> action` 必须逐帧维护 |
| 789、790、810、819–821 | VLAN / 冲突域 / 广播域 | 先定二层 Scope，再讨论转发与隔离 |
| 791、792、816–818 | PPP | 链路控制状态与向上数据服务语义是两条不同轴 |
| 811、812 | 802.11 地址字段 | 地址字段角色受 To DS / From DS 与当前无线角色约束 |

### 变式轴

1. **边界机制**：字符转义 / bit stuffing / 固定长度；
2. **错误处理**：只检测、可纠错、还是需要 ACK/Timer 恢复；
3. **介质模型**：共享半双工 / 独立全双工 / 无线竞争；
4. **交换状态**：MAC 表为空、部分已学、同端口过滤、跨交换机 VLAN；
5. **控制生命周期**：PPP LCP / authentication / NCP 是否完成。

> **仍需补的证据：**题库对完整 CSMA/CA backoff counter 冻结/恢复时间线、802.11 四地址逐字段映射、PPP 多阶段失败分支覆盖偏弱。它们应优先补成训练母题，而不是继续扩充 Canonical 定义。

## 题目攻击：交换机/VLAN 题必须区分“看见”与“接受”

### 攻击 826：最终 MAC 表不能倒推前面每一帧

826 的关键不是记住答案 C，而是逐事件维护：`A→B` 先让交换机学习 A，再对未知 B 泛洪；后续 `H→A`、`E→X`、`X→E` 使用的是**当时已经形成的表**。如果直接拿最终表判断第一帧，整个过程会被时间倒置。

更深一层还要区分四个事件：

```text
物理信号到接口
-> switch 是否把 frame 复制到该端口
-> NIC 是否接受目的 MAC
-> 是否递交上层
```

因此“某主机物理上能收到”不等于“该主机的网络层收到”。

### 攻击 789：802.1Q 保存 VLAN 身份，不制造跨 VLAN 可达性

A/F 能通信的理由是它们**同属 VLAN1 且跨交换机**，所以 trunk 必须在共享链路上保留 VLAN1 身份。把 F 改成 VLAN3 后，即使 trunk 能携带 VLAN1/VLAN3 两种 tagged frame，A/F 仍不能靠二层交换直接互通。

**First Divergence**：把“trunk 能承载多个 VLAN”误写成“trunk 能连接不同 VLAN”。

### 攻击 818：PPP 的控制生命周期和向上服务语义是两条轴

LCP/NCP 的存在说明链路有协商状态；PPP 数据帧没有因为这些状态就获得序号、ACK、可靠重传。题目一旦问“向网络层提供什么服务”，先查数据交付机制，而不是看到 `Establish/Open` 就自动选“面向连接可靠”。

## 单跳题独立检查

1. framing 是否可逆；
2. 检错与恢复是否混成同一机制；
3. 介质是否真的共享、半双工；
4. 交换机是否先从 source 学习；
5. MAC 是否只在当前一跳/二层广播域有效；
6. PPP 的 Protocol/LCP/NCP 是否被混成一个阶段。

## 最短压缩

> **一跳题按“定界 → 检错 → 取得发送权 → 本跳转发”推进；先学源再查目的，先判共享场景再用 CSMA/CD。**
