# 地址翻译软硬件交接

> 训练定位：面对同时出现 OS 页表状态、MMU/TLB、PTE 权限、fault 与 retry 的跨科题时，训练明确“谁预先配置、谁逐次消费、失败时谁接管”，避免把 OS 策略和硬件快路径写成一条无主语箭头链。  
> 模型归属：[X-B02 地址翻译硬件与 OS 虚拟内存桥梁手册](X-B02_HardwareAddressTranslation与OSVirtualMemory_桥梁手册.tex)。软硬件接口、不变量与责任边界由 Canonical Bridge 拥有；本文件只负责跨科题的落笔顺序与检查。

## 母题表示：一次访问至少有三个不同 Owner

| 阶段 | Owner | 当前责任 |
|---|---|---|
| 映射准备 | OS | 建立地址空间、PTE、权限、驻留与页表根状态 |
| 每次访问 | MMU / TLB / page-walk hardware | 消费当前映射状态，产生合法 PA 或精确 fault |
| 失败修复 | OS fault handler | 分类 fault，修复/拒绝，必要时处理旧翻译一致性 |

成功路径进入 Cache/Memory；可修复 fault 处理后才有 retry；不可修复 fault 进入拒绝/终止分支。

## 局部规则：先写访问请求，不只写 VA

**触发信号**：题目同时给虚拟地址、读写/取指、用户态/内核态或权限位。

**第一动作**：把请求写成 `(VA, access type, privilege)`，再检查当前 mapping 是否允许这次具体访问。

**检查与退出**：如果你只得到一个 PFN，却没有检查本次 R/W/X 与 privilege，翻译链还没有完成。

## 局部规则：OS 配置与硬件消费分两栏

**触发信号**：题目问“谁完成地址翻译”“缺页时谁处理”“TLB 谁使用”等软硬件分工。

**第一动作**：把 OS 预先写入的 mapping state 放左栏，把硬件逐次读取/缓存/检查的动作放右栏；只有 fault/异常交接时才把控制权重新画回 OS。

**检查与退出**：不要写成“OS 把每个 VA 翻译成 PA”；OS 提供和维护映射状态，硬件在访问快路径消费它。

## 局部规则：三种 miss 分开记账

**触发信号**：TLB miss、page fault、cache miss 在同一道题出现。

**第一动作**：分别问缺的是翻译缓存副本、合法/可用映射，还是数据缓存副本。

**检查与退出**：只有翻译成功得到合法 PA 后，才进入后续 Cache/Memory；如果在 PTE/权限处 fault，不应继续假装已有 PA 去算 Cache。

## 跨科综合题落笔顺序

1. 写访问请求 `(VA, R/W/X, privilege)`；
2. 标出 OS 预先建立的页表根、PTE 映射和权限状态；
3. 追踪 TLB hit 或 page walk；
4. 成功时得到 PA，再交给 Cache/Memory；
5. 失败时写明 fault 原因与保存现场；
6. OS 选择修复、拒绝或终止；
7. 若修复改变映射，检查旧 TLB 翻译是否需要失效、隔离或由 ASID 等机制区分；
8. 明确 retry 的是哪一次访问，不把“返回内核/用户态”写成“必然重新调度”。

## 局部规则：修改页表以后别忘旧翻译

**触发信号**：OS 修改 PTE、切换页表根、回收/重映射页面，题目同时涉及 TLB。

**第一动作**：问旧 TLB entry 是否仍可能被当前地址空间消费；根据具体 ISA/题设选择失效、隔离或地址空间标签机制。

**检查与退出**：如果映射已经改变，但旧翻译仍可能无条件命中，就破坏了“硬件消费的状态与 OS 当前承诺一致”这一 Bridge 不变量。

## 易错边界

> **TLB miss ≠ Page Fault。** 一个是翻译缓存副本缺失，一个是当前访问无法按映射/权限继续。

> **Page Fault ≠ Cache miss。** 前者发生在合法物理身份尚不能生成的翻译/权限阶段；后者发生在已有合法访问目标后的数据缓存层。

> **Hardware Cache ≠ OS Page Cache。** 两者都保存副本，但对象、Owner、填充/失效事件和题目层次不同。

## 最短压缩

跨科地址翻译只保留三个主语：**OS 写状态，硬件读状态；读不下去时 fault 把控制权交回 OS。** 每一条箭头若说不清是谁做什么，就改回带主语的自然语言或带标签的状态/接口关系。
