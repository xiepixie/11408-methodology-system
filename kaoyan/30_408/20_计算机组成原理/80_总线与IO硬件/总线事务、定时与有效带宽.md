# 总线事务、定时与有效带宽

> 训练定位：面对总线宽度、时钟/传输率、地址数据复用、同步/半同步/异步定时、突发与非突发传送、主存准备时间及有效带宽题时，训练先还原一次完整 transaction，再统计有效 payload，而不是直接做“宽度 × 频率”。  
> 模型归属：[CO-08｜总线与 I/O 硬件](CO-08_总线与IO硬件_方法论手册.tex)拥有总线协议、事务、定时与带宽机制；本文件只训练事务时间线、单位口径和代表真题攻击。主存内部 service time 由 CO-05 提供。

## 母题表示：带宽只是完整事务的一个投影

统一写成：

```text
Request / Grant（若需要）
→ Address / Command
→ Target Prepare / Wait
→ Data Beat(s)
→ Response / Release
```

然后再问：

```text
一次 transaction 有多少有效数据？
完整时间窗口多长？
哪些阶段只付一次，哪些每个 beat 都重复？
```

最终：

$$
\boxed{BW_{effective}=\frac{\text{有效 payload bytes}}{\text{完整统计时间}}}
$$

### 局部规则：看到“带宽”先拒绝心算

**触发信号**：总线宽度、MHz/GHz、MT/s、burst、wait、地址/数据复用同时出现。

**第一动作**：先画一笔 transaction：`A | wait | D1 | D2 | ... | response`，给每段标周期数，再数真正的数据字节。

**检查与退出**：只有题目明确给的是“每周期持续有 $k$ 次 data transfer 的峰值”时，才可直接用 `bytes/transfer × transfers/s`；若存在地址、等待或非突发重复开销，必须回事务时间线。

## 一、时钟频率、总线周期与有效传输率不是一个量

2009 Q20：总线时钟 10MHz，所以时钟周期为 $0.1\,\mu s$；但题目明确一个**总线周期**占 2 个时钟周期，每个总线周期才传 4B：

$$
BW=\frac{4B}{0.2\,\mu s}=20\text{ MB/s}.
$$

不能写成 $4B\times10MHz=40MB/s$，因为漏掉了“2 clocks / bus cycle”。

2025 Q20 反过来攻击另一种重复乘法：题面给 1333MT/s 这类**有效传输率**时，里面已经包含了每基础时钟多次传输的效果，不能再额外乘 quad-pumped 的 4。

### 局部规则：先判断题目给的是 Hz 还是 transfers/s

**触发信号**：`clock frequency / working frequency / MT/s / DDR / quad-pumped`。

**第一动作**：把量写出单位：

```text
Hz = cycles / s
MT/s = transfers / s
```

只有从 cycles/s 推 transfers/s 时才乘“每周期传几次”；若已经是 transfers/s，就直接乘每次 payload。

**检查与退出**：量纲必须最后变成 B/s。若式子里同时出现 MT/s 又乘一次“双沿/四倍”，优先检查是否重复计数。

## 二、总线宽度只决定一个 data beat 的上限

64 位总线意味着一个**数据 beat**最多承载 8B；它不说明：

- 地址阶段是否也占一拍；
- 目标是否要等待；
- 一次 transaction 有几个 beat；
- 是否每拍都能传数据。

2014 Q19 明确给“32 根地址/数据线、每周期上下沿各传一次数据”，此时峰值数据率可写：

$$
4B\times 2\times66MHz=528MB/s.
$$

因为题目问的是**最大数据传输率**，且已经明确每个时钟周期有两个数据传送时刻。地址/数据复用只说明同一组线在不同阶段承担不同角色，不会凭空把一个数据 beat 变成两个。

## 三、突发传输的价值是“摊薄地址/命令开销”

2012 Q19：100MHz、32 位、地址/数据线复用，一次 burst 写 128bit。

- 地址：1 个周期 = 10ns；
- 128bit 数据 = 4 个 32bit beat = 40ns；
- 总计 50ns。

地址只付一次，是 burst 的关键。

若改成不支持 burst，连续多个数据往往要为每次独立传送重新支付地址/命令，甚至目标准备时间。2023 Q20 就明确给出非突发模型：32B 块、64 位总线，需要 4 次独立 8B 传送；每次都付 `address 1ns + memory prepare 6ns + data 1ns`，于是总时间为：

$$
4\times(1+6+1)\text{ ns}=32\text{ ns}.
$$

### 局部规则：先判“控制开销按事务付还是按 beat 付”

**触发信号**：burst / non-burst / 连续地址 / block transfer。

**第一动作**：圈出地址、命令、prepare、response 等开销，给每项标 `once per transaction` 或 `once per beat`。

**检查与退出**：若 burst 和 non-burst 算出来完全一样，检查是否错误地让每个 burst beat 都重新发地址；若 non-burst 只付一次地址，也要检查题设是否允许。

## 四、主存准备时间与总线传送时间可以属于不同资源

总线题若同时给主存准备时间，先不要把它机械当“总线周期”。

一次读可以包含：

```text
总线发送地址
→ 主存内部准备 / 等待
→ 总线返回数据
```

这三段分别占用/等待的资源不同。题面若明确请求之间不能重叠，就串行相加；若给 bank/interleaving/pipeline/多个 outstanding request，则要重新画资源时间线，可能发生重叠。

因此 CO-05 输出 `memory service / ready`，CO-08 决定它如何嵌入 bus transaction；不能把 DRAM latency 直接叫成总线 bandwidth。

## 五、同步、半同步、异步是“何时采样”的协议，不是串/并行的同义词

2015 Q19 的四个选项很好地建立边界：

- 同步：所有参与方按统一时钟规则采样；
- 半同步：仍有公共时钟，慢设备通过 WAIT 等信号拉长；
- 异步：不依赖统一公共时钟，用 request/acknowledge 等握手建立完成关系。

在经典异步握手中：

- 非互锁：撤销更多依赖约定时间，快但鲁棒性弱；
- 半互锁：一方等待对方确认后再撤销；
- 全互锁：请求/回答的撤销都彼此确认，最可靠但握手最长。

### 局部规则：定时题先画“谁等谁”

**触发信号**：同步/半同步/异步、互锁/半互锁/不互锁、WAIT/ACK。

**第一动作**：为 request、ack、request↓、ack↓ 画因果箭头；公共时钟存在时再标采样边沿。

**检查与退出**：不要用“异步一定慢/并行一定快”作答；协议可靠性、传播距离、等待和位宽是不同轴。

## 六、峰值带宽与有效带宽必须分开

理论峰值在题设已经保证每个数据时隙都有效时可写：

$$
BW_{peak}=\text{bytes/transfer}\times\text{transfers/s}.
$$

有效带宽则还会被以下因素降低：

- 仲裁/授权；
- 地址与命令；
- wait state / memory prepare；
- response；
- 方向切换；
- 空闲槽；
- 协议编码；
- 不满载 burst。

所以“总线更宽/频率更高”只提高局部上限，不自动给出程序实际吞吐。

## 七、本轮真题攻击结论

| 真题 | 攻击的错误模型 | 稳定修正 |
|---|---|---|
| 2009 Q20 | 时钟周期 = 总线周期 | 先换成真正 bus transaction 周期 |
| 2012 Q19 | burst 每个 beat 都重新发地址 | 控制开销通常按 burst transaction 摊薄 |
| 2014 Q19 | 地址/数据复用会把数据率再折半 | 峰值只按实际 data transfer slots 计 |
| 2015 Q19 | 同步时钟可由各设备各自提供 | 同步协议需要共同采样时间基准 |
| 2023 Q20 | 块传输天然只付一次准备开销 | 非 burst 时每个独立传送都可能重复开销 |
| 2025 Q20 | MT/s 还要再乘 DDR/quad 倍数 | transfers/s 已是有效传送率就不重复乘 |

## 陌生总线性能题固定落笔协议

```text
1. 标 bytes/beat。
2. 标输入是 cycles/s 还是 transfers/s。
3. 画一个完整 transaction：grant / address / wait / data / response。
4. 标哪些开销 once-per-transaction，哪些 once-per-beat。
5. 数 payload bytes 与总时间。
6. 若有 burst / bank / pipeline，画资源重叠而不是机械相加。
7. 算 effective bandwidth；需要时再比较 peak bandwidth。
8. 用量纲 B/s 和极端情况做检查。
```

## 最短压缩

> **总线带宽题先画事务再算：宽度只给每 beat 数据量，频率要先分 cycles/s 与 transfers/s，burst 的价值是摊薄控制开销，有效带宽永远是 payload/完整时间。**
