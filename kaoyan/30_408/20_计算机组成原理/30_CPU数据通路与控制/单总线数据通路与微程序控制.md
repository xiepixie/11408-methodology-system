# 单总线数据通路与微程序控制

> 训练定位：面对 CPU 数据通路图、单总线微操作、控制信号补全、单周期/多周期比较、控制存储器与微指令编码题时，训练从“本拍哪个值从哪里到哪里”反推通路与控制，而不是背固定部件图或固定节拍。  
> 模型归属：[CO-03｜CPU 数据通路与控制](CO-03_CPU数据通路与控制_方法论手册.tex)拥有状态差、数据通路、资源调度、控制字与微程序机制；本文件只训练图题读取、逐拍账本和代表真题攻击。ISA 字段与指令语义仍回 CO-02。

## 母题表示：图上的线只有在承载“值”时才有意义

数据通路题统一压成：

```text
ISA 要求的状态差
→ 本条指令必须产生哪些值
→ 每个值的 producer / consumer
→ 当前已有路径与共享资源
→ 微操作分拍
→ Enable / Select / Command
→ 时钟边界提交
```

因此读一张陌生图，不先问“这是什么经典模型”，而先问：

```text
谁保存状态？
谁只做组合变换？
谁当前能驱动总线？
谁能在本拍锁存？
ALU 两个输入分别来自哪里？
```

## 一、先把元件分成“状态元件”和“操作元件”

2023 Q18 给出的最小攻击非常重要：

- ALU、MUX：当前输出由当前输入决定，是组合逻辑/操作元件；
- PC、通用寄存器：跨时钟保存状态，是状态元件。

这个区分直接改变做题行为：

- 经过 ALU/MUX 只说明“组合结果已经存在”；
- 写进 PC/GPR/MAR/MDR/临时寄存器后，才形成下一拍可继续依赖的状态；
- 若写入的是架构寄存器，还要进一步检查是否已经发生架构提交。

### 局部规则：图题第一遍只圈“谁会记住东西”

**触发信号**：题面给 CPU 方框图，要求判断部件性质、补通路或推微操作。

**第一动作**：把所有寄存器/锁存器圈成 State，把 ALU、扩展器、MUX、移位器等标成 Combinational；随后才追数据流。

**检查与退出**：如果推理出现“MUX 选出结果，所以寄存器值已经改变”，立即撤回；还缺目标写使能与时钟边界。

## 二、单总线不是“所有部件只有一根线”，而是共享一次驱动机会

在经典 CPU 内部单总线模型中，一个时刻通常只允许一个源驱动内部总线，但可以让多个目标同时锁存同一个总线值。

所以：

```text
一个源 → Bus → 多个合法目标
```

是允许的；

```text
两个不同源 → 同一 Bus
```

通常会冲突。

2015 Q43 中暂存器 T 的存在正是资源约束的结果：若 ALU 的两个输入都只能从同一条总线即时取得，就无法同时得到两个独立操作数。先把一个源值锁入 T，下一拍再让第二个源驱动总线，才能形成两个不同 ALU 输入。

### 局部规则：每一拍固定写四列

**触发信号**：要求写 `Xin/Xout`、控制信号或判断两个动作能否同拍。

**第一动作**：写：

| 本拍问题 | 要填的内容 |
|---|---|
| Bus Source | 谁唯一驱动总线 |
| Latch Targets | 哪些寄存器在边界锁存 |
| ALU / MUX | 本拍组合逻辑做什么、选什么 |
| External Resource | 主存读写/ready 是否另占接口 |

**检查与退出**：两个动作若使用不同资源且互不依赖，可以并行；不能因为它们写在两行微操作里就机械拆拍，也不能因为“同一拍看起来方便”就忽略双源争用。

## 三、微操作最少拍数是“依赖 + 资源”问题，不是指令名字问题

2009 Q44 的 `ADD (R1),R0` 要完成：

$$
M[R1]\leftarrow R0+M[R1].
$$

稳定依赖是：

```text
R1 → MAR
memory read → MDR
R0 与 MDR → ALU
ALU result → MDR
MDR → memory write
```

至于需要 5 拍还是 6 拍，要看题图是否允许“主存接口返回 MDR”与“CPU 内总线把 R0 锁入暂存器”并行。该真题明确存在一种合法 5 拍方案，说明：

> **最少拍数只能从当前数据通路和并行资源推出，不能从某条旧答案的固定微操作表背出来。**

2015 Q44 同样用 `sub R1,R3,(R2)` 与 `inc R1` 对比：间接操作数必须额外形成地址并完成访存，因此最少拍数不同；真正增加的不是“sub 这个名字复杂”，而是多了一段 `address → memory → value` 依赖链。

### 局部规则：先画值依赖，再压缩可并行动作

**触发信号**：问“至少几个时钟周期”“哪些微操作可以合并”。

**第一动作**：先按数据依赖画完整串，再尝试把互不依赖且不抢资源的相邻动作合并到同一拍。

**检查与退出**：每合并一次都过四道 Gate：输入已 ready、资源不冲突、组合路径不过长、不会打开错误写口。

## 四、单周期和“经典单总线微操作机”为什么冲突

2016 Q20 常被简化成“单周期处理器不能采用单总线”。更准确的考试模型是：

- 单周期要求一条指令的所有必要状态变化在一个时钟边界前完成；
- 经典寄存器传送式单总线若同一条指令需要多次由不同源依次驱动总线，就产生**时间上不可压缩的资源复用**；
- 要保持单周期，就必须增加并行组合路径、端口、独立加法器/存储接口等，使所有必需值在同一长周期中都能到达。

因此不能把“单周期”与“系统总线只有一条”混成一件事，也不能从真题结论推出“任何叫单总线的物理实现都绝对不可能单周期”。题目说的是经典 CPU 内部共享数据通路模型。

### 局部规则：单/多周期题先找“同一资源被一条指令重复使用几次”

**触发信号**：单周期、多周期、复用 ALU/存储器/内部总线。

**第一动作**：沿一条最复杂指令标每个资源的使用时刻；若同一不可并用资源需要前后两次使用，则单周期实现必须复制/增端口/改路径，否则只能拆拍。

**检查与退出**：性能判断最后必须回 $IC\times CPI\times T_{clk}$。`CPI=1` 不是“必然更快”的充分条件。

## 五、控制信号不是另一套知识：它只是数据动作的编码

2026 Q44 的稳定读法不是背 `MARSrc/ALUASrc/ALUBSrc/RegWr` 数值，而是先把每个控制信号翻译成一个问题：

```text
MARSrc  → MAR 的地址从谁来？
ALUASrc → ALU A 端从谁来？
ALUBSrc → ALU B 端从谁来？
RegWsrc → 寄存器写回数据从谁来？
RegDst  → 写哪个寄存器编号？
RegWr   → 本拍是否允许架构寄存器改变？
```

取指周期需要 `memory[PC]` 和 `PC+instruction_length`，却不应改 GPR，因此 `RegWr=0` 不是要背的位，而是由 Write Set 直接推出。

### 局部规则：求控制位先写自然语言动作

**触发信号**：题图给多个 `Src/op/Write/Enable`，要求填 0/1/编码。

**第一动作**：先写“本拍要产生什么值、最终写哪里”，逐个 MUX 找所需输入编号，最后才翻译成控制位。

**检查与退出**：把所有 Write Enable 与指令的 Write Set 对照；若一个 LOAD 打开 MemWrite，或取指周期打开 GPR RegWrite，说明控制解释出错。

## 六、微程序控制：字段编码本质是“互斥类共享一个选择字段”

微指令的操作控制字段若采用字段直接编码，把**不能同时出现的微命令**放入同一字段；不同字段则可并行发出相容微命令。

若某互斥类含 $m$ 个微命令，还必须保留“本字段本拍不发命令”的编码，因此该字段至少需要：

$$
\boxed{\left\lceil\log_2(m+1)\right\rceil\text{ bit}}
$$

2012 Q18 的 5 类大小为 $7,3,12,5,6$，位数分别为：

$$
3+2+4+3+3=15.
$$

### 局部规则：字段直接编码先给每组多留一个“空操作”状态

**触发信号**：微命令分若干互斥类，问操作控制字段最短长度。

**第一动作**：每类先算 `命令数 + 1`，再取 $\lceil\log_2\rceil$，最后各字段相加。

**检查与退出**：若题设明确某字段每拍必选一个命令、无需空状态，才可以去掉 `+1`；不能无条件套。

## 七、控制存储器按微地址访问，不是按内容访问

2017 Q18 专门攻击一个很容易与相联存储器混淆的说法：

- 主存按地址访问；
- 控制存储器同样由微地址/微程序计数器选择微指令；
- TLB/CAM 式“按内容匹配”是另一种结构。

`control store` 的“控制”描述其**保存的内容是微指令**，不是它采用内容寻址。

## 八、机器指令、微指令、汇编指令、伪指令分层

2024 Q13 把四个层次放在一起：

```text
汇编/伪指令 —— assembler 处理
机器指令     —— ISA 层 CPU 执行
微指令       —— 微程序控制器内部执行/解释控制字
```

“CPU 能理解微指令”只在采用微程序控制的实现内部成立；这不意味着应用程序能把微指令当 ISA 指令直接发射。微指令是微架构控制对象，机器指令是软件可见 ISA 对象。

2025 Q16 再次验证边界：定长/变长指令格式属于 ISA；阵列乘法器、微程序控制器、单总线数据通路属于实现选择。

## 九、编码宽度问题统一成“有多少个候选动作”

2015 Q43 中：

- ALU 有 7 种操作 → 至少 3 bit；
- 移位器有 3 种操作 → 至少 2 bit。

这和微指令字段编码共享一个最小信息量问题：一个字段若需要区分 $N$ 个候选状态，至少需要 $\lceil\log_2N\rceil$ 位。区别只在于是否还要编码“不动作”以及哪些动作允许并行。

## 十、本轮真题攻击结论

| 真题 | 攻击的错误模型 | 应保留的稳定模型 |
|---|---|---|
| 2009 Q44 | 微操作只能照固定表排 | 先依赖图，再按资源合并合法并行动作 |
| 2012 Q18 | 每类 $m$ 个命令只需编码 $m$ 状态 | 字段通常还需 no-op，算 $m+1$ |
| 2015 Q43/44 | 看图认部件，不追值流 | 单总线按 Source/Target/ALU/Write 四列推进 |
| 2016 Q20 | “单周期不能有任何单总线”绝对化 | 经典共享单总线的重复资源使用与单周期冲突 |
| 2017 Q18 | 控存“按内容”访问 | 控存由微地址访问；CAM 是另一结构 |
| 2023 Q18 | 组合结果与状态混为一谈 | Operation Element ≠ State Element |
| 2024 Q13 | 机器指令/微指令/伪指令同层 | ISA 对象、汇编器对象、微架构对象分层 |
| 2025 Q16 | ISA 决定具体控制实现 | ISA 契约 ≠ 微架构实现 |
| 2026 Q20/44 | CPI/控制位靠背 | 从调度/Write Set/数据来源重新生成 |

## 陌生数据通路题固定落笔协议

```text
1. 写指令 State Delta：Read / Derived / Write / Next PC。
2. 圈 State Element 与 Combinational Element。
3. 每个值写 producer → consumer。
4. 单总线每拍写唯一 Bus Source 和所有 Latch Targets。
5. 需要两操作数时检查是否必须暂存或复制路径。
6. 再映射 ALUop / Src / Write Enable / Mem command。
7. 若问最少拍数，尝试合并互不依赖且不争资源的动作。
8. 若问微指令字段，先分互斥类并检查 no-op 编码。
9. 最后用 Write Set 与关键路径做独立反查。
```

## 最短压缩

> **数据通路题不是认图：先写“值从哪来、去哪、何时锁存”，再让总线/ALU/MUX/控制位承载这条值流。微程序只是把这些控制动作编码进控制存储器。**
