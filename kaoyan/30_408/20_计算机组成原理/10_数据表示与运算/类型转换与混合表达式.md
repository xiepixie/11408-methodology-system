# 类型转换与混合表达式

> 训练定位：面对 `signed/unsigned`、不同整数位宽、`int/float/double` 显式转换、往返转换与混合表达式真假判断时，训练先锁定“当前这一步在哪种类型/位宽中计算”，再判断转换是否保值、是否舍入以及后续怎样重新解释。  
> 模型归属：[CO-01｜数据表示与运算](CO-01_数据表示与运算_方法论手册.tex)拥有位串、扩展/截断与整数/浮点转换机制；表达式求值顺序与源语言语义由 [CO-02｜ISA 与机器级程序](../20_ISA与机器级程序/CO-02_ISA与机器级程序_方法论手册.tex) / 题设提供。本文件只训练转换链与真假判断，不建立第二套 C 语言规范。

## 母题表示：类型转换不是“换标签”，而是一条有顺序的信息变换

做题时把每一步写成：

```text
当前类型 / 位宽
→ 当前值或位模式
→ 当前运算在哪个类型域中执行
→ 显式/隐式转换
→ 目标类型重新解释
→ 是否丢失信息
```

最危险的错误是让“最后的目标类型”反向污染前面的运算。例如：

```c
(double)(x + y)
```

并不等于

```c
(double)x + (double)y
```

前者先在 `x+y` 的源类型中完成加法，再转换；后者先把操作数转成 `double`，再做浮点加法。**转换发生在什么位置，本身就是状态链的一部分。**

### 局部规则：每遇到一个 cast，就在它左边画一道“类型边界”

**触发信号**：表达式中出现 `(int)`、`(float)`、`(double)`、`(unsigned)` 等显式转换，或题面问转换前后是否相等。

**第一动作**：从最内层表达式开始，在每个运算符旁标当前操作数类型与结果类型；只有该子表达式已经得到结果后，才越过 cast 做下一次转换。

**检查与退出**：若推理中出现“因为最后转成 double，所以前面的 int 加法不会溢出”之类说法，立即撤回。源语言中某一步若存在未定义/实现相关语义，必须按题设处理，不能用后续机器类型把它补成确定结果。

## 整数内部转换：先保源值，再改变宽度，最后按目标解释

在 408 常见二进制补码机器模型中，稳定控制链是：

$$
\boxed{\text{Source Value}\to\text{Width Conversion}\to\text{Destination Interpretation}}
$$

### 同宽 `signed ↔ unsigned`

位模式保持，解释函数改变。以 16 位为例：

```text
A1B6H 作为 signed：负数
A1B6H 作为 unsigned：同一位模式对应一个大正数
```

这一步没有“重新编码成另一个看起来不同的 16 位串”。

### 短到长

扩展方式由**源类型**决定：

- source unsigned：零扩展；
- source signed 补码：符号扩展。

不能看到 destination 是 unsigned 就提前补 0。

### 长到短

先保留目标宽度低位，再按目标类型解释。是否无损用“截后再扩”检查：如果按目标语义扩回原宽度不能恢复原值，说明信息已经丢失。

## 整数与浮点：范围够不够、精度够不够是两条独立轴

在常见 `int32 + binary32 + binary64` 模型下：

| 转换 | 范围 | 精度 | 稳定结论 |
|---|---|---|---|
| `int32 → float32` | 范围足够 | 只有 24 位有效二进制精度 | 可能舍入 |
| `int32 → double64` | 范围足够 | 53 位有效精度 | 所有 int32 都可精确表示 |
| `float32 → double64` | 范围/精度都扩大 | 不丢原 binary32 有效信息 | 有限 float32 可精确表示 |
| `double64 → float32` | 范围、精度都缩小 | 可能舍入 | 还可能发生范围溢出 |
| 浮点 → 整数 | 目标没有小数部分 | 题设常规定向 0 截断 | 小数信息通常丢失 |

因此：

$$
\boxed{\text{“目标范围足够”}\not\Rightarrow\text{“转换精确”}}
$$

例如大多数 int32 都落在 float32 的指数范围内，但超过 24 位有效二进制精度后，仍可能无法精确表示。

### 局部规则：整数转浮点先数“需要多少有效位”

**触发信号**：题目问某整数转 `float/double` 后是否仍精确、能否往返恢复。

**第一动作**：把整数写成二进制数量级，估计最高 1 到最低有效 1 之间需要多少有效位；再与目标浮点有效精度比较。

**检查与退出**：不要把“指数范围没溢出”当成“精确”。若目标是 IEEE 特殊值、非有限值或题设舍入模式改变，转回 IEEE 完整状态链。

## 往返转换：真正要问的是“第一步有没有丢信息”

一条往返链

$$
A\to B\to A
$$

能否恢复原值，关键不是“第二个 A 和第一个 A 名字相同”，而是第一步映射在当前输入集合上是否可恢复。

### 常见安全子域

- `int32 → double → int32`：int32 可被 binary64 精确表示，且回转结果在 int32 范围内，因此可恢复。
- 有限 `float32 → double → float32`：binary64 可以精确承载原 binary32 值，因此可恢复原数值。
- `int32 → float32 → int32`：只对能被 float32 精确表示、且回转仍在 int32 范围的输入稳定成立；不能对全部 int32 宣称安全。
- `float → int → float`：若原值含非零小数部分，向 0 截断后通常无法恢复。

### 局部规则：往返题先检查第一条箭头

**触发信号**：`x == (T1)(T2)x`、先扩后缩、先浮点后整数再转回等关系式。

**第一动作**：只看第一次转换：它是否在当前输入集合上丢了位、舍入或截断？若第一步已经多对一，后续再转回通常无法凭空恢复丢失信息。

**检查与退出**：还要单列 NaN、无穷、越界与语言未定义行为；这些边界可能让“数值可恢复”与“比较表达式为真”分离。

## 混合表达式真假判断：中间结果比最终类型更重要

本批 Q274 是一个很好的攻击例子。设 `x,y,z` 为 int32，并令：

```c
double dx = (double)x;
double dy = (double)y;
double dz = (double)z;
```

binary64 有 53 位有效精度，任意 int32 以及三个 int32 的数学和都远小于这个整数精度边界。因此：

$$
(dx+dy)+dz=dx+(dy+dz)
$$

在这个受限输入集合中可以对所有输入成立。这里不能机械套“浮点加法不满足结合律”，因为该题的所有中间整数和都恰好落在 binary64 可精确表示的格点上。

反过来：

```c
(double)(x + y)
```

中的 `x+y` 先在整数类型中求值，不能因为后面有 `(double)` 就把它当作 double 加法。

### 特殊值会破坏看似显然的代数恒等式

`dx/dx == dy/dy` 并不永远为真。若某个源整数为 0，则会出现 `0.0/0.0 = NaN`；NaN 与任何值（包括自身）进行普通相等比较都为假。

因此看到“平方必非负”“自己除自己必为 1”“浮点一定不结合”时，都先检查题设输入是否把运算限制在一个更小的精确子域，或是否允许 0 / NaN / infinity。

## 复合题：类型转换、移位、字节序必须分层

本批 Q279 的稳定顺序是：

```text
16 位补码位模式
→ 同宽转 unsigned：位模式不变，只改解释
→ unsigned 右移：逻辑右移
→ 得到最终 16 位结果
→ 最后才按大端/小端映射到两个地址字节
```

字节序永远不能反向改变寄存器中的转换和移位结果。完整内存排布动作见 [字节序、对齐与有效地址](../20_ISA与机器级程序/字节序对齐与有效地址.md)。
