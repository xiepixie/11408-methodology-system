# 计组做题规则与性能工具箱

状态：工作稿，待验证规则已建立，尚无已采用规则。

## 已采用

暂无。以下规则仍需用真实题目校准。

## 待验证

### 先定位数据，再画通路

看到指令、微操作或 Cache/Memory 综合题时，先标出数据当前所在位置与目标位置，再决定经过哪些 MUX、总线、功能部件和寄存器。

### 区分可用时刻与提交时刻

流水线题同时标记 value ready 和 architectural commit，不能因为数据已被 forwarding 就认为指令已经完成。

### 指令全过程题画三条线

分别画 value dependency、ready/need timing 和 exception/commit；取指访问与数据访问分开，每个 slow path 标检测者、处理者和重试点。阶段名只能做索引，不能替代这三条证据链。

### 流水线题先声明时序假设

先写 stage 定义、寄存器堆读写顺序、memory latency、分支决策级和 forwarding 端点；题设未给出的停顿数不能从“经典五级”直接推出。

### 依赖题比较 need 与 ready

对每条 RAW 依赖标 producer、consumer、value produced、path ready 和 consumer need。ready 晚于 need 才需要 stall；已有路径能在 need 前到达才可 forward。

### Stall 与 Flush 分别追踪保留和作废

写清哪些 PC/流水寄存器保持、哪个控制包被清零为 bubble；分支误判或异常则标出被作废的年轻指令。只写“插入气泡”不足以证明状态正确。

### 分支惩罚从决策级和冲刷范围数

先确定预测规则、决策阶段和已进入前端的错误路径指令，再计算额外周期；不要把“分支固定停两拍”当作跨模型结论。

### 每个 miss/fault 写处理者

TLB miss、Cache miss 和 Page Fault 必须分别写清检测者、处理者、是否需要 OS，以及完成后从哪里重试。

### 定长数题先声明“位串解释”和“目标位宽”

同一串比特可按 unsigned、补码、原码或浮点格式解释。计算前先写操作数解释、内部结果位宽和最终保留位宽；溢出是“数学结果不能被目标格式表示”，不能只看某一位。

### 扩展与截断题用“截后再扩”验证

zero extension 保留 unsigned 值，sign extension 保留补码值；窄化后按原解释扩回，能恢复原值才是无损。不能因高位看起来重复就跳过目标解释。

### Carry 与 Overflow 分开判

先在位串层得到低位结果，再分别按 unsigned 和补码解释。carry/borrow 描述无符号出位关系，overflow 描述有符号数学结果越界；二者不能互相代替。

### 乘除迭代题先固定寄存器布局和循环不变量

先画部分积/余数、乘数/商和附加位的位置，再按题设算法逐拍更新。每拍记录“判断依据、加减对象、移位方向、上商/编码位”；最后用乘积重算或 $X=YQ+R$ 校验，不能把不同教材算法的位序口诀混用。

### 乘法溢出从足宽乘积压回目标格式

先保留足宽积。unsigned 窄结果要求被丢高位全零；补码窄结果要求高位是保留结果符号位的扩展。只看低半部符号或某个 carry 不能证明乘法是否溢出。

### 浮点运算先分类，再保留 GRS 舍入证据

先处理 zero、subnormal、normal、infinity、NaN，再走对阶、有效数运算、规格化、舍入与编码。被移出的低位要压成 guard/round/sticky；主体尾数为零不代表小量对最终舍入无影响。

### 扩展操作码题画“剩余编码树”

从地址数最多的格式开始，先算当前操作码空间和已用数；剩余前缀乘以下一级被释放字段的编码数，得到下一层容量。每层都检查前缀无歧义和总编码预算。

### 指令题先写架构状态差

看到机器码、汇编或指令执行题，先写 Read Set、Write Set、Next PC 和可能的异常，再解码字段。若某个部件或节拍不能改变这组架构状态，就不能把它当作 ISA 必需事实。

### 寻址题先分 value、address、address-of-address

先写 $EA=f(fields,R,PC,M)$，再判断该地址是否还要取内存内容。立即/寄存器寻址没有数据访存；间接寻址的额外访存来自“先取地址，再用地址找对象”，不能按名称猜次数。

### 寻址题先写 EA 生成式，再数访存

把 value、address 和 address-of-address 分开。先写 $EA=f(PC,R,imm,M)$，完成符号扩展、比例和字节编址换算，再计算取指之外的数据访存次数。

### 编码题逐层扣除扩展前缀

每层先记录总编码数、已用数和剩余前缀；只有剩余前缀才能进入下一层。题目改变地址字段位数、指令字长或已用数量时，重新计算预算，不套固定“几位操作码”的答案。

### 字节序题画地址—字节表

给出多字节值时先标低地址和高地址，再按题设 endian 放置字节；寄存器中的数学值不因存储顺序改变。若同时给访问宽度或未对齐地址，另列读取字节数与 ISA 对未对齐访问的规定。

### 函数调用题分 ISA、ABI 与编译器选择

把跳转、寄存器、访存等 ISA 原语，与 caller/callee 保存、参数位置、栈帧布局等 ABI 约定分开；出现具体寄存器名时先确认架构，不能把某套 MIPS 或 x86 约定升级为普遍规律。

### 地址宽度与指令长度分开预算

题目同时出现指令字长、PC、指针、物理地址或数据宽度时，分别列出各自位数和用途；除非题设给出关系，不能由 32 位指令推出 32 位地址或固定访存范围。

### 数据通路题从 State Delta 开始

先写 Read Set、Derived Values、Write Set 和 Next PC；再标每个值的生产者与消费者，最后才连 MUX、总线和功能部件。新增硬件前先证明现有通路无法通过重新调度实现语义。

### 微操作并行性过四道 Gate

两项动作同拍执行必须同时满足：数据依赖允许、共享资源不冲突、最长组合路径满足时钟、写使能不产生多余架构副作用。箭头能同时画出不等于硬件能同时执行。

### 单周期/多周期比较使用完整 CPU time

统一程序和成本口径后计算 $IC\times CPI\times T_{clk}$。单周期的 $CPI=1$、多周期的短时钟或某一部件更快，都不能单独推出整体性能。

### 流水线依赖写四个时刻

对每条相关指令标出 producer、consumer、value ready 和 consumer need；另行标 architectural commit。旁路只解决已经产生且路径可达的值，不能转发未来值，也不等于提前提交。

### 主存芯片题拆“字数”和“字长”

先分别计算位扩展与字扩展所需芯片数，再确定片内地址位和片选位。地址线数量、芯片容量和 CPU 数据宽度是不同预算，不能混成一个除法。

### 存储题先列四种粒度

先分别写编址单位、存储字、总线事务和 Cache/page 批量粒度；只有题设明确相等时才合并计算。地址线由可寻址单元数决定，不由总字节数或机器字长单独决定。

### 存储性能题分 latency、cycle、bandwidth

先标数据何时有效、下一次独立访问何时可启动、一次事务搬多少有效数据，再计算带宽；不能用“宽度 × 频率”替代完整工作模式。

### 交叉编址题区分一次延迟与稳态吞吐

写出模块号与模块内地址，检查连续请求是否落在不同模块。低位交叉可能提升连续带宽，但不保证单次随机访问 latency 下降。

### 磁盘题保持 LBA 与物理位置分层

LBA 是主机接口编号，CHS 是教学几何或兼容视图；只有题目明确给出映射时才换算物理位置，不能由 LBA 连续推出真实介质连续。

### Cache 题先做地址三分，再跑状态机

先由块大小得到 offset，由组数得到 index，剩余才是 tag；随后检查 valid/tag，按 hit/miss、替换和写策略推进。容量题必须区分数据容量与 tag/valid/dirty/LRU 等总物理位数。

### Cache 题先统一“块、组、字节”单位

先确认按字节还是按字编址，再计算 block、set、offset/index/tag。地址三分完成前不代入访问序列，避免把块大小、存储字和数据总线宽度混成一个单位。

### 地址翻译题先拆 VA，再分三种缺失

先按 page size 拆 VPN 与 offset；TLB miss 进入 page walk，PTE 无效或权限失败才是 fault，PA 形成后再判断 Cache miss。每条分支都写检测者、处理者、重试点和最终提交点。

### TLB/Cache 组合题先检查索引是否落在页内偏移

VIPT 只有使用 page-offset 位索引时才能并行查找而不依赖未知 PFN；若 `sets x block size` 超过 page size，必须说明 synonym 或额外约束，不能直接套固定容量结论。

### Cache miss 写完整生命周期

遇到 miss，依次写 victim、dirty/write-back、下一级取块、tag/valid 更新、retry；若是写 miss，再单独判断 write-allocate 或 no-write-allocate。不能由 write-back 自动推出写分配。

### AMAT 题先声明“额外时间”和重叠

写清 hit time、miss rate、miss penalty 是否为额外值，以及写回、下一级 AMAT 和流水线 stall 是否已重叠；命中率更高不自动意味着总时间更短。

### 总线和 DMA 题同时追踪三种占用

分别记录 CPU 指令时间、总线/主存周期和设备传输时间；明确哪些阶段可重叠。DMA 请求总线、数据传输完成和最终中断是不同事件，DREQ 不能直接当作 CPU 中断。

### 总线/I-O 题先拆请求、事务与完成

先区分 CPU 或设备提出的 request、仲裁后发生的 bus transaction、控制器状态更新和 completion signal；再判断轮询、中断或 DMA 哪个主体推进状态，不能把一次中断当成全部传输过程。

### DMA 题先写控制器描述符与所有权转移

列出源/目的、长度、方向、突发或窃取周期、剩余计数和完成条件；CPU 配置与设备传输可重叠，但缓存一致性、地址映射和完成回调分别属于硬件接口、平台规则与 OS。

### 性能公式先声明串行项、并行项和单位

带宽、延迟、时钟周期、总线周期和吞吐量不能只凭名称相乘。先写一次事务含多少有效数据、多少周期、能否突发或重叠，再统一 bit/byte、Hz/s 和 ns 等单位。

## 性能工具箱

性能计算先声明成本模型，再选择公式：

- CPU time：$IC\times CPI\times clock\ period$；
- Pipeline：$ideal\ CPI+stall$；
- Cache：$hit\ time+miss\ rate\times miss\ penalty$；
- Memory/Bus：latency、throughput、bandwidth 和 bottleneck；
- 加速比较：明确基准、受影响比例和不能加速的部分。

不能用频率、CPI、IPC、MIPS 或命中率中的单一数字直接宣告系统更快。

### 性能题先走完整 Cost 坐标

把 `State -> Location -> Path -> Resource -> Timing -> Commit` 走完，再问成本：同一程序的 `IC` 是否改变、每条指令的 `CPI` 如何生成、时钟周期是多少、哪些 stall/miss 可重叠、最终提交何时发生。不能把局部 latency 直接当程序总时间。

### CPI 低不等于程序必然快

比较两台机器或两种实现时统一写
$$
CPU\ time=IC\times CPI\times clock\ period.
$$
若指令数、CPI、频率或时钟周期同时变化，必须代入完整口径；只比较 CPI、IPC、MIPS 或 GHz 都不足以判定总时间。

### 流水线题分 throughput 与 latency

吞吐量描述稳定填满后单位时间完成多少指令，latency 描述单条指令从进入到结果/提交的时间。加深流水、增加并行度或提高频率可能改善其中一项，却同时增加寄存器、分支、依赖或排空成本。

### 带宽题写瓶颈与协议效率

先列一次事务的有效数据量、地址/控制/等待周期、可否突发和可否与 CPU/设备重叠，再取最小瓶颈：互连、主存、Cache fill、设备或计算部件。峰值带宽不等于有效带宽，任何“乘宽度乘频率”的答案都要补协议效率和利用率。

## 已否定

### “同位宽整数除法永不溢出”

补码最小负数除以 $-1$ 就可能超出同位宽有符号范围；是否溢出取决于操作数格式、被除数宽度、商宽度和 ISA 语义。

### “除零一定由硬件中断，所有架构处理相同”

除零检测可以由组合逻辑完成，但架构结果可能是同步异常、规定结果或其他语义；必须读取题设 ISA，不能从电路直接推出 OS 行为。

### “RISC 必然硬布线，CISC 必然微程序”

ISA 设计取向与控制器实现是两条轴。二者有历史相关性，不存在稳定的一一对应。

### “单周期处理器必然使用哈佛结构”

单周期教学模型必须解决同拍取指和数据访问的资源冲突，但解决方案可以是独立存储、双端口、复制接口或题设的理想存储抽象。

### “DMA 传输让 CPU 开销恒为 O(1)”

CPU 不逐字搬运不等于所有请求成本为常数；描述符建立、分段、同步、一致性和完成处理都依赖传输组织与系统实现。

### “PC、PSW、Cache、MMU 对所有软件都完全不可见”

可见性和可配置性由 ISA、特权级和平台接口决定；普通用户态不可直接访问，不能推出 OS、固件或特权软件也不可管理。

### “寄存器可访问性有跨架构固定四级清单”

稳定判据是当前 ISA 是否提供读取、写入、配置或间接影响该状态的合法操作。PC、PSW、页表基址、Cache 和 PCB 的可见性分别依赖 ISA、特权接口、OS 软件与实现，不能用固定表格互推。

### “流水线越深一定越快”

深流水可能降低组合段延迟，却增加流水寄存器开销、分支 penalty、依赖距离和填充/排空成本；必须用 $IC\times CPI\times T_{clk}$ 比较完整时间。
