## 1. 为什么保留“六类题型”，但不给它们知识 Owner 身份

上传强化课材料把存储大题分成：

1. 地址映射与字段划分；
2. Cache 命中率；
3. Cache 完整访问过程；
4. 虚拟存储 + TLB + 页表 + Cache 联动；
5. 页数、缺页次数/缺页率；
6. Cache 性能分析与 AMAT。

这六类非常适合作为**找题和训练入口**，但它们混合了地址表示、一次访问状态机、访问序列和性能成本四种不同解释层，因此不作为六个平行知识章节。

训练层保留它们的价值：学生仍可从题面快速识别“我现在在练哪一类控制能力”；真正的机制解释则回到 Canonical Owner。

## 2. 存储真题统一控制协议

本 Practice System 统一使用：

```text
Question
→ Request / Object
→ Granularity
→ Address / Access Stream
→ Owner Route
→ State Trace
→ Event Count
→ Cost Model
→ Independent Verify
```

箭头含义是**求解依赖/检查顺序**：后一项依赖前一项提供的明确输入，不声称所有硬件事件按这条线串行发生。

### Request / Object

先问本题真正统计什么：指令访问、数据访问、某数组、某页、某 Cache line、某总线事务，还是 CPU 总时间。

### Granularity

同时出现的 byte / word / block / page / burst / bank 必须分别命名，只有题设明确相等时才能合并。

### Address / Access Stream

单次字段题生成一个地址；数组/循环题必须先从程序生成 memory-reference stream，再生成 address/block/page/set stream。

### Owner Route

当前状态属于 Cache、TLB、PTE、OS residency、主存 Bank、Bus 还是 DMA；每个 miss/fault 都先写处理者。

### State Trace

逐次维护真正改变的状态，例如 valid/tag/dirty/LRU、TLB entry、PTE present/permission、resident set、Bank busy window。

### Event Count

先数 reference、miss、fault、burst、writeback、DMA request，再进入性能。

### Cost Model

明确 hit time、miss penalty、miss total time、memory cycle、bus cycle 与可重叠项；不重复定价。

### Independent Verify

用地址范围、位数和、访问总数、block/page footprint、命中率范围、带宽瓶颈、fault 可行性等独立信息检查。

### 统一用词契约

| 推荐正式用语 | 本体系中的含义 | 避免的混写 |
|---|---|---|
| memory reference / 访存请求 | CPU/指令层发出的某一次数据或取指访问事件 | “访问一个数组元素”直接等同“一次 Cache 访问” |
| Cache hit / miss | 数据/指令 block 副本在某 Cache 层命中或缺失 | 用 hit/miss 描述页面驻留 |
| TLB hit / miss | translation entry 命中或缺失 | TLB miss 直接写成缺页 |
| page resident / present；缺页 | 页面当前驻留/映射可用；408 经典“缺页”指页面当前不驻留 | `Page hit / Page miss` |
| Page Fault（页故障异常） | 页式访问无法沿普通快路径完成的同步异常入口；具体原因可为 non-present、permission、COW 等 | “缺页中断”；把所有 Page Fault 都写成读磁盘 |
| 主存（main memory） | 系统存储层次名称，408 中通常由 DRAM 实现 | 把 DRAM 介质名当成任何场景下的层次名 |
| 后备存储（backing store） | file/swap-backed 页面需要恢复内容时的后备来源 | 把 demand-zero / COW 叫 backing store |
| latency / access time / cycle time | 单请求延迟 / 规定访问完成时间 / 下一独立操作合法启动间隔 | 三者都叫“访问时间” |
| throughput / bandwidth | requests(or transactions)/s / effective bytes/s | 把 transactions/s 直接当 B/s |
| AMAT / EAT | Cache/存储层次接口平均时间 / 翻译与 VM 路径常用的有效访问时间记号 | 把二者无条件当同一分母、同一路径 |

完整定义以 [存储层次与 AMAT](../60_Cache与存储层次/存储层次与AMAT.md) 和各 Canonical Owner 为准；本表只约束跨文档用词。

## 5. 原六类题型现在怎样使用

### 5.1 地址映射与字段划分

不要先问“这是什么公式”，先问当前粒度：

```text
编址单位
→ Block / Page / TLB Set / Cache Set 大小
→ 可寻址单元数
→ log2 位预算
→ 剩余高位身份字段
```

主存芯片字段转 CO-05；Cache 转 CO-06；VPN/TLB 转 CO-07；VA/PA 与 Cache 位交接转 CO-B02。

### 5.2 Cache 命中率

统一走：

```text
Program
→ Reference Stream
→ Address Stream
→ Block/Set Stream
→ Cache State
→ Hit/Miss Count
```

不再以“行遍历/列遍历/数组题”作为母模型。

### 5.3 Cache 完整访问过程

统一走 CO-06：

```text
Index
→ Tag + Valid
→ hit OR victim
→ dirty writeback if needed
→ fetch/fill
→ retry
```

### 5.4 TLB + 页表 + Cache 联动

统一走：

```text
CO-07 translation
→ CO-B02 handoff
→ CO-06 cache
```

fault 时停止 Cache，转 X-B02 / OS-04。

### 5.5 页数 / 缺页次数

先区分两类：

- **静态 footprint**：连续地址范围跨多少 page；
- **动态 fault trace**：访问序列 + resident set + replacement 决定多少 fault。

前者可用边界穿越公式，后者必须进入 OS-04 状态模拟。

### 5.6 Cache 性能 / AMAT

先调用 [存储层次与 AMAT](../60_Cache与存储层次/存储层次与AMAT.md)，确认当前平均的对象是 Cache reference、translation request、page access 还是整个程序成本。统一走：

```text
定义原始请求与分母
→ 列 hit / miss / fault 互斥路径
→ 先数事件
→ 定义 hit time / miss total / extra penalty
→ 再给事件定价
→ 检查 local/global miss rate
→ 再检查串行/并行/包含关系
→ 用 E[T] 重建公式
```

命中率只是事件比例，不是最终性能；AMAT 是每次原始访存请求的平均路径成本，也不等于完整 CPU time。

## 6. 贯穿训练的三个生成工具

### 工具 A：Lookup

```text
Key
→ Candidate Location
→ Identity
→ State
→ Payload
```

适用于 Cache/TLB 的组织类比；一旦进入 miss handler，回各自 Owner。

### 工具 B：Footprint

连续对象长 $L$ B，起始偏移 $d$，粒度 $U$：

$$
N_U=\left\lceil\frac{d+L}{U}\right\rceil.
$$

只负责“跨几个固定粒度单元”，不负责这些单元是否会被替换或命中。

### 工具 C：Event Count → Event Cost

$$
TotalCost=BaseCost+\sum_i N_i\cdot Penalty_i
$$

使用前必须声明 penalty 是额外成本还是总路径成本，并检查重叠与重复包含。

## 8. 证据与冲突账本

### 已确认：2013 强化课数值需要纠正

真题归档 `2013年真题/q43_计算机组成原理.md` 给 CPU 800MHz，因此：

$$
T_{clk}=1.25ns.
$$

100 条指令、CPI=4 的 base CPU time 为：

$$
100\times4\times1.25ns=500ns.
$$

120 次访存、5% miss → 6 次 miss；每次 burst 85ns → 510ns；总计：

$$
1010ns.
$$

上传强化课材料中的 1.5ns / 600ns / 1110ns 不应继续进入训练正文。

### 保留冲突：2025 Q43 AMAT 口径

题面写“命中时间 2 个周期，缺失损失 200 个周期”。若“缺失损失”是额外 penalty：

$$
2+0.0315\times200\approx8.30.
$$

当前归档解析计算约 8.24，相当于把 200 当 miss total time。两者语义不同。在取得更高优先级官方评分依据前：

- Canonical 保留“先声明成本定义”的原则；
- Practice 明示冲突；
- 不把 8.24 与 8.30 写成可互换答案。

### 已确认：LRU metadata 不设统一固定公式

真题可能给特定相联度并采用教学化位数；稳定理论只说“replacement state 属于组内 victim selection”。精确编码按题设/实现，不晋升成“每行固定 $\log_2E$ 位”。

## 10. 八项验收

- **Compression**：可压成 `Request → Granularity → Stream → Owner → State → Count → Cost → Verify`；
- **Generation**：字段、block/page 数、hit/miss、fault、AMAT 都可由前置对象重新生成，而非记六类答案；
- **Mapping**：新题可先按 Owner Route 挂到 CO-05/06/07/CO-B02/OS-04/X-B02；
- **Boundary**：TLB miss / Page Fault / Cache miss，地址字段 / 行内容，hit rate / total time 等有稳定判据；
- **Lifecycle**：Cache miss、translation、fault/retry 均有完整状态轨迹；
- **Cost**：先 event count 后 event cost，并显式检查重叠和定义；
- **Exam**：每个 Adapter 都给出题目信号与第一动作；
- **Growth**：新真题只需增加 Evidence / Rule 状态，不要求新增平行知识册。

当前决策：**sufficiently trustworthy**。没有需要重建 Canonical 母模型的关键缺口；优化重点是继续用新真题攻击 Practice Adapter 与 Rules。
