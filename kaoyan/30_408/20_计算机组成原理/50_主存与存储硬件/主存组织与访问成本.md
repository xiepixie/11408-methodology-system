# 主存组织与访问成本

> 训练定位：面对主存芯片扩展、DRAM 行列地址、交叉编址、连续对象跨存储体、突发传送、主存带宽、磁盘访问时间与 RAID 边界题时，训练把“地址、组织、事务、时间”拆开。  
> 模型归属：[CO-05 主存与存储硬件方法论手册](CO-05_主存与存储硬件_方法论手册.tex)。介质、芯片、Bank、Row/Column、Latency/Access Time/Cycle Time/Throughput/Bandwidth 的稳定机制由 Canonical 正文拥有；本文件只负责真题中的操作顺序、状态计算与检查。

## 母题表示：一个地址请求怎样被有限硬件真正服务

训练时统一写成：

```text
Request
→ 编址单位与数据粒度
→ 芯片 / 模块 / Bank / Row-Column 定位
→ 一次或多次存储事务
→ 数据可用
→ Latency / Cycle / Throughput / Bandwidth 记账
```

这里的箭头是**做题检查顺序**。真实硬件内部可能流水、并行或重叠；题设没有说明时，不把“检查顺序”误写成固定物理时序。

> [!idea] 第一动作
> 先写四个量：**一个地址代表什么、一次要读写多少数据、一个芯片一次提供多少位、一次存储/总线事务能搬多少。** 这四个量没统一前，不做容量、地址线或带宽计算。

## 一、容量与芯片扩展：先拆“字数”和“字长”

设单片规格为 $D\times W$，目标存储器规格为 $D_t\times W_t$。训练时先分别计算：

$$
n_{depth}=\frac{D_t}{D},\qquad n_{width}=\frac{W_t}{W},\qquad n=n_{depth}n_{width}.
$$

- `depth` 回答需要多少组不同地址空间；
- `width` 回答同一个地址要并联多少芯片才能凑够数据宽度；
- 字扩展影响片选；位扩展影响同一地址同时工作的芯片数。

这里还要把“芯片字数”和“CPU 全局地址单位”接起来。若若干 $D\times W$ 芯片先做位扩展形成一个 $D\times W_t$ 芯片组，而系统按字节编址，则这一组覆盖的全局地址跨度不是简单的 $D$ B，而是

$$
D\times\frac{W_t}{8}\text{ B}.
$$

例如两片 $8K\times8$ 并联成 $8K\times16$ 后，一个芯片组仍有 8K 个“存储字位置”，但每个位置占 2B，所以在全局字节地址空间中覆盖 16KB。先完成位扩展，再算片组选址区间，可以避免把“8K words”误当成“8KB”。

### 局部规则：片组选址先把芯片深度换成全局编址单位

**触发信号**：单片以 `K×bit` 给出、目标存储字长与单片数据宽度不同，又要求某地址落在哪个芯片组/该组首地址。

**第一动作**：先完成位扩展得到每个地址位置的目标字长，再按系统编址单位计算一个芯片组覆盖多少全局地址单元，最后按这个跨度切分地址区间。

**检查与退出**：若系统按字编址而不是字节编址，覆盖跨度应直接用“多少个可寻址字”计，不再乘字节数；先统一编址单位再做十六进制区间。

### 局部规则：地址空间、实际装机容量与 MAR 位数分开

**触发信号**：题目同时给“主存地址空间大小”“实际装了多少 MB”“MAR 位数”或“RAM/ROM 区间”。

**第一动作**：先判断题目问的是**可寻址范围**还是**当前实际实现容量**。

例如按字节编址、地址空间为 $2^m$ B 时，MAR 至少需要 $m$ 位；即使当前只安装其中一部分容量，也不能直接把当前容量位数当成地址空间位数。

**检查与退出**：若你用“已安装 32MB”推出“MAR 25 位”，但题目明确地址空间是 64MB，应立即停止并回到地址空间定义。

### 局部规则：RAM / ROM 地址区间先做空间分割

**触发信号**：题目给出混合地址空间（如高位 ROM、低位 RAM）或给出总寻址范围与若干芯片模块。

**第一动作**：先得到总可寻址单元数，再按题设比例或边界分配连续区间；最后才换成十六进制首尾地址。不要先凭最高十六进制位猜区域。

**检查与退出**：检查各区间长度之和等于总容量，首尾地址无重叠、无空隙。

## 二、DRAM：行列复用与刷新是两个不同成本

DRAM 题至少分两层：

1. **地址引脚**：行地址和列地址分时复用，同一组引脚先后送两部分地址；
2. **刷新**：通常按行维护电荷，行数越多，给定刷新周期下需要调度的刷新事件越多。

### 局部规则：求最少地址引脚

**触发信号**：DRAM 采用行/列地址复用，题目给阵列行列规模或要求在固定容量下求最少复用地址引脚。

**第一动作**：若阵列为 $r\times c$，先分别计算行、列地址位数，再取较大者：

$$
A=\max(\lceil\log_2 r\rceil,\lceil\log_2 c\rceil).
$$

在容量固定且允许选择行列组织时，行列位数越接近，通常越有利于减少地址引脚；若题目进一步要求减少刷新开销，再在满足最少引脚的候选中优先减少行数。

**检查与退出**：若题目只给总容量，却没有给行列组织、也没有允许自行选择阵列形状，就不能把总地址位数机械平分后声称得到唯一引脚数；先判断题面是否足以确定 geometry。

> [!trap] “地址位数的一半”不是无条件口诀
> 只有当行列规模恰好对称时，才可直接把总地址位数平分。非对称阵列应回到 $\max(\log_2 r,\log_2 c)$。

### 局部规则：刷新题先锁“需要刷多少行”

**触发信号**：DRAM 容量、刷新间隔、异步/集中刷新、刷新信号频率。

**第一动作**：先从题设得到真实 row count，再写

$$
\Delta t_{refresh,max}=\frac{T_{retention}}{N_{row}}.
$$

**检查与退出**：`64K×1` 只给总存储单元数，不能单独推出一定有 256 行；只有题目再给 `256×256` 阵列、行地址位数或等价组织时，才能确定刷新行数。若题面没有 row geometry 而答案依赖 256/128 等具体行数，应先判题目条件不足，而不是在解析中默认方阵。

另外，刷新期限是**最大允许间隔**：一个更短的调度间隔仍然合法。若题目问“哪种安排可以工作”，判断的是不等式可行性；只有问“最多允许连续多少次普通访问”时才逼近上限。

## 三、交叉编址：先锁定“哪几位选存储体”

低位交叉的稳定训练对象是：

```text
地址
→ 交叉粒度
→ 存储体号
→ 体内地址
→ 是否与前一请求争用同一体
```

若按字节做 $N$ 体低位交叉，且一个最低粒度单位恰好对应一个编址单元，则常见模型为：

$$
bank(a)=a\bmod N,\qquad local(a)=\left\lfloor\frac{a}{N}\right\rfloor.
$$

若题目按字、块或更大粒度交叉，应先把地址换成对应粒度编号，再取模；不能把所有低位交叉都机械理解成“地址最低 $\log_2N$ 位”。

### 连续对象跨存储体：不要只看起始地址

若一次最多传输 $T$ B，而对象长度为 $L$ B、起始地址相对事务边界偏移为 $d$，所需事务数至少为：

$$
N_{tx}=\left\lceil\frac{d+L}{T}\right\rceil.
$$

这个式子用于训练“边界穿越”直觉；具体是否能同周期并行、是否必须重新启动 Bank，仍服从题设的总线和存储周期模型。

### 冲突判断

**触发信号**：给一串地址，问哪些可能发生 Bank conflict。

**第一动作**：先把每个地址映射成 `bank id`；再结合题目给出的启动间隔和单体忙时间，判断同一 Bank 是否在尚未完成前收到新请求。

**检查与退出**：只因为两个地址属于同一 Bank，不自动推出一定冲突；还要看它们到达时间是否重叠。

### 精确“冲突次数”还必须给请求到达模型

若题目要求一个唯一的 Bank-conflict 次数，至少还要锁定：

```text
bank mapping
+ request arrival interval
+ one-bank busy window
+ conflict 后是否阻塞后续请求 / 还是进入队列
```

同一地址序列在“CPU 遇冲突立即停发”和“请求仍按原节拍进入控制器队列”两种模型下，后续到达时刻会不同，冲突次数也可能不同。**冲突的状态判据是 `arrival time < bank available time`，不是只看地址序列里两个同余项相隔几个位置。**

重复连续访问题还要写清每一轮是否从同一首地址重新开始、单体周期 $T$ 与可启动间隔 $\tau$ 的关系，以及统计 steady-state 还是包含首尾 latency。若这些条件会改变选项，必须进入题面。

## 四、Latency、Cycle、Throughput、Bandwidth：四个量分别记账

这一节只定义 CO-05 输出给上层的介质/事务成本；若题目要把这些成本继续组合成 Cache AMAT、TLB/VM EAT 或 CPU time，转 [存储层次与 AMAT](../60_Cache与存储层次/存储层次与AMAT.md)。

- **Latency**：从一次请求开始到所需结果可用的等待；
- **Access Time**：某存储器件/接口完成题设规定访问的时间，教材中常与 latency 近似使用，但要声明起止点；
- **Cycle Time**：同一资源下一次独立操作最早何时可以合法启动；
- **Throughput**：稳定状态下单位时间完成多少请求/事务；
- **Bandwidth**：稳定状态下单位时间真正搬运多少有效数据。

只有在“每个完成事务的数据量固定、统计窗口一致”等条件下，才能由 throughput 乘每事务数据量得到 bandwidth；不能把 transactions/s 和 B/s 当成同一个量。

> [!idea] 性能题第一动作
> 先画一次完整事务：`地址/命令 → 等待/准备 → 数据传送`，再标哪些阶段能与下一个请求或下一个 Bank 重叠。

### 多体交叉的性能

多体交叉可能提高**稳态吞吐**，却不必降低**首个请求的访问延迟**。计算最大带宽时，先确定：

- 每个体一次提供的数据量；
- 单体周期；
- 相邻体的启动间隔；
- 总线能否持续接收；
- 总线是否反而成为瓶颈。

最终带宽不能超过任一关键资源的服务上限。

## 五、突发总线与主存：先数事务，再算事务时间

典型真题会同时给：

- Cache block 大小；
- burst 一次传输量；
- 总线宽度与总线时钟；
- 主存多体交叉周期。

固定动作：

1. `一个 Cache block 需要几个 burst`；
2. 每个 burst 有多少地址/命令周期；
3. 第一个数据何时 ready；
4. 后续数据以什么节拍连续返回；
5. 哪些等待与传送可以重叠；
6. 最后得到一次 miss 的服务时间。

这一步只生成“下一级服务成本”。它可以成为 Cache miss path 的组成部分，但是否直接进入 AMAT、miss penalty 或 CPU stall，必须由 [存储层次与 AMAT](../60_Cache与存储层次/存储层次与AMAT.md) 的时间口径和 CO-04 的重叠条件决定。

## 六、磁盘与 RAID：介质时间和可靠性机制分开

### 磁盘访问时间

经典机械磁盘模型：

$$
T_{access}=T_{seek}+T_{rotation}+T_{transfer}+T_{controller}.
$$

若只给转速而无具体角位置，平均旋转等待通常按半圈计算。若一磁道有 $n$ 个等大扇区，读一个扇区的传输时间可由一圈时间除以 $n$ 推出。

经典几何题把定位拆成“柱面/磁道 + 磁头（盘面）+ 扇区”。磁头号与盘面选择是同一维度，不应再把“磁头号”和“盘面号”当两个独立坐标，同时漏掉磁道/柱面。真实设备常向主机暴露 LBA，是否还能直接推真实几何位置必须看题设。

若题目给出扇区间隙、同步区等“旋转时经过但不承载有效 payload”的时间，并问接口所需**峰值有效数据率**，分母应只使用真正有数据经过接口的时间窗口；若问整圈平均传输率，则可用整圈时间。先确认统计窗口，不能看到“每圈容量”就无条件除以一圈总时间。

> [!trap] 磁盘不是按字节独立完成物理读写
> 题目里的主机地址可以按字节表达，但磁盘介质的最小物理传输单位通常是扇区/块。不要把“按字节编址”扩展成“磁盘每次只读一个字节”。

### RAID

条带化主要购买并行吞吐；镜像和奇偶校验提供冗余信息、提高故障恢复能力。`性能并行` 与 `可靠性冗余` 是两条不同轴，不能因为都属于 RAID 就混为同一个目的。

## 七、概念边界

| 概念边界 | 为什么容易混淆 | 真正判据 | 题目信号 | 混淆后的错误 |
|---|---|---|---|---|
| 地址空间 ≠ 已装容量 | 都用 KB/MB/GB 表示 | 前者是可命名范围，后者是当前物理实现 | MAR、地址线、扩展空间 | 用当前容量错误决定 MAR |
| 字扩展 ≠ 位扩展 | 都会增加芯片数量 | 地址深度 vs 同一地址的数据宽度 | `K×W` 芯片组成目标规格 | 片选/数据线连接关系错误 |
| Access Time ≠ Cycle Time | 都用 ns 表示 | 数据 ready 时刻 vs 下一请求合法启动时刻 | DRAM 恢复、流水访存 | 带宽或请求间隔算错 |
| Latency ≠ Bandwidth | 都描述“快慢” | 单请求等待 vs 稳态数据率 | 多体交叉、burst | 把吞吐提升写成单次延迟下降 |
| Bank 同号 ≠ 一定冲突 | 同 Bank 确实共享资源 | 还需时间上发生重叠 | 地址序列 + 启动间隔 | 只按模值判冲突 |
| 条带化 ≠ 冗余 | RAID 中常同时出现 | 并行布局 vs 可恢复信息 | 性能/可靠性问法 | 把 RAID0 当作可靠性提升 |

## 八、本批题库怎样攻击主存模型

这批 284–306 题最有价值的不是多记几个答案，而是连续攻击了几个容易被“教材默认”掩盖的条件：

- **284 / 298**：芯片规格中的“字数”必须先换成 CPU 的全局编址单位。尤其位扩展成更宽存储字以后，`8K words` 在字节地址空间里可以覆盖 16KB，而不是机械等同 8KB。
- **286 / 287 / 302 / 303**：Flash/SSD 的介质不对称已经形成独立检索意图，详细训练转 [Flash 与 SSD 介质特性](Flash与SSD介质特性.md)；本文件只保留它与主存/外存角色、介质成本的接口。
- **289**：仅有 `64K×1` 容量不能生成唯一刷新行数；必须先知道 row geometry。正式题面补成 `256×256` 后，$2\text{ ms}/256$ 才有合法来源。
- **290**：$T/N_{row}$ 是刷新 deadline 上界，不是要求调度精确撞线；64 次普通读写后提前刷新仍然可行。
- **291**：只有题面明确“新增一根复用地址引脚同时让行、列各增加 1 位”时，容量才稳定扩大 4 倍；不能从“多一根地址线”无条件推出同一倍率。
- **294**：重复有限 burst 会暴露轮间 Bank 相位和 busy window；单轮 `T+(q-1)\tau` 不能直接替代稳态轮间 initiation interval。
- **297**：唯一冲突次数必须有 `arrival interval + bank busy window + conflict queue model`；只有地址模 4 的 bank stream 还不够。
- **301/304/305**：磁盘性能题再次证明单位口径属于模型输入；KB/MB 的十进制/二进制解释、旋转一周时间与 gap 时间必须在计算前锁定。

这些攻击没有要求重建 CO-05，而是把原来容易隐含的 `Geometry / Deadline / Arrival / Busy Window / Unit` 条件提升成显式输入。

## 十、最短压缩

```text
地址先回答“选谁”
→ 粒度回答“一次搬多少”
→ 事务回答“需要几次”
→ 时序回答“多久、何时能再来”
→ 带宽回答“长期能搬多快”
```

若题目已经进入 Cache tag/valid、TLB/page walk、OS page replacement 或 I/O 调度，停止本训练文件，分别转入 CO-06、CO-07 / CO-B02、OS-04 或 OS-05。
