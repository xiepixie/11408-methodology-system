# Flash 与 SSD 介质特性

> 训练定位：面对 Flash/SSD 的非易失性、读/编程/擦除粒度、写入寿命、磨损均衡、垃圾回收以及“SSD 是否属于主存”一类辨析题时，训练把**介质操作**与**设备接口/系统角色**分开。  
> 模型归属：[CO-05 主存与存储硬件](CO-05_主存与存储硬件_方法论手册.tex)拥有 Flash/SSD 的物理粒度、介质成本和系统位置；本文件只训练题面识别、边界判断与代表题，不复制 FTL 完整机制。

## 母题表示：先问题目说的是哪一层

Flash/SSD 题最容易把三个对象混成一个：

```text
Flash cell / NAND array
→ page / erase block 介质操作
→ SSD controller / FTL
→ host-visible block device
```

- **Flash 介质**回答电荷/阈值怎样保存信息、最小读/编程/擦除粒度是什么；
- **SSD 控制器**把主机逻辑块请求映射到底层 Flash 页面，并承担垃圾回收、磨损均衡、坏块管理等职责；
- **SSD 的系统角色**通常是非易失外存/二级存储，不因为速度比机械磁盘快就变成 DRAM 主存。

### 局部规则：看到“Flash/SSD”先圈出介质动作还是设备角色

**触发信号**：题面同时出现“页、块、擦除、磨损、主存、SSD、Flash”等词。

**第一动作**：在每个陈述旁标 `medium / controller / system role`。先判断它说的是 NAND 阵列内部动作，还是主机看到的 SSD 行为。

**检查与退出**：若一个结论把“主机写 4KB”直接等价成“介质立即原地擦除 4KB”，或把“非易失”直接等价成“ROM 不可更新”，说明层次已经混淆。

## 非易失不等于只读

Flash 断电后可保持信息，因此属于非易失存储；但它可以经过**编程（program）和擦除（erase）**重新写入。

所以：

$$
\boxed{\text{non-volatile}\neq\text{read-only}}
$$

“ROM”在教材分类里有时被用作较宽泛的非易失半导体存储类别，但不能据此推出 Flash 单元无法更新。

## NAND Flash 的关键不对称：页级读/编程，块级擦除

典型 NAND Flash 介质中：

- 读出以 **page** 为基本介质粒度；
- 编程通常也以 **page** 为基本粒度；
- 擦除必须以比 page 大得多的 **erase block** 为粒度。

因此写入不像 DRAM 那样可以对任意小单元无限次原地覆盖。已有页面需要更新时，SSD 控制器常把新版本写到其他可编程页面，旧版本失效，之后由垃圾回收把仍有效的数据搬走并擦除整个 erase block。

### 局部规则：问“哪一个粒度”时先区分 read/program/erase

**触发信号**：选项把“读、写/编程、擦除”全部说成同一 page 或同一 block 粒度。

**第一动作**：画三行：`read / program / erase`，分别填题设或经典 NAND 介质粒度；不要用一个“SSD 块大小”覆盖三类动作。

**检查与退出**：若题目讨论的是主机逻辑扇区、NVMe 命令或文件系统块，而不是 NAND 介质内部操作，停止使用“page/program + erase block”直接回答，先回到接口层。

## 为什么写通常比读更昂贵

读操作主要是感测已有单元状态；写入可能涉及可编程页选择、旧页失效、后续垃圾回收和块擦除。于是典型系统中：

$$
T_{read}<T_{program}\quad\text{且擦除/GC 会进一步放大写成本。}
$$

这是一种机制性的成本不对称，不等于“每次主机写请求都同步先擦一个块”。控制器可以延迟、合并或后台执行部分维护动作，所以实际写延迟会有波动。

## 写入寿命与磨损均衡

Flash 擦写次数有限。若总把高频更新集中在少数 erase block，这些块会先达到寿命上限。

**wear leveling（磨损均衡）**的目标是让擦写压力在物理块之间更均匀，从而延长整个设备的可用寿命。它购买的是寿命与可靠性，不是“让 Flash 变成无限次可写”。

垃圾回收和磨损均衡也可能引入：

- 额外数据搬移；
- 写放大；
- 后台 I/O；
- 尾延迟波动。

## SSD 为什么通常不叫主存

“速度快”不是存储层次身份的唯一判据。408 语境中的主存通常指 CPU 正常加载/存储路径上由 DRAM 构成的随机访问物理内存；SSD 通过存储设备接口暴露逻辑块，通常承担外存/二级存储角色。

因此：

> SSD 比 HDD 快很多，仍不推出“SSD 常用作主存”。

系统当然可以用 SSD 做 swap、持久内存的后备、缓存层等，但这些用途不改变经典 408 对主存/外存的基本分层。

## 易错边界

> **Flash ≠ DRAM。** 两者都能随机读某个地址区域，不代表保持机制、刷新/擦除或写入成本相同。

> **Flash page ≠ SSD host block。** 前者是介质内部组织，后者是设备接口逻辑地址粒度；控制器负责映射二者。

> **erase block ≠ Cache block。** 名字都叫 block，但属于不同 Owner、不同层次和不同状态机。

> **磨损均衡 ≠ 垃圾回收。** 两者可能协同，但前者主要平衡寿命，后者主要回收失效页面占据的可擦除空间。

## 最短压缩

> **Flash/SSD 题先分层：介质层记“页读/编程、块擦除、有限寿命”，控制器层记 FTL/GC/磨损均衡，系统层再判断它是外存还是其他角色。非易失绝不等于不可写。**
