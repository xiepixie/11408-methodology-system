# 路径与文件对象

> 训练定位：面对 pathname、directory entry、inode、fd、OFD、offset、link/unlink、fork/dup 等题面时，训练先判断当前操作的是“名字、对象、打开实例还是句柄”，再追踪引用和状态变化。  
> 模型归属：[OS-06/07 文件系统与持久化方法论手册](OS-06_OS-07_文件系统与持久化_方法论手册.tex)。namespace、inode、VFS、fd/OFD、offset 与对象生命周期机制由 Canonical 正文拥有；本文件只负责问题表示、状态跟踪与检查。

## 母题表示：四层对象不能压成“文件”两个字

```text
Pathname / Directory Entry
        ↓ 命名解析
Persistent File Object (inode/FCB)
        ↓ open 建立运行时访问状态
Open File Description (offset / flags / object reference)
        ↓ 进程句柄表引用
fd
```

训练时每一个动作都问：**它到底改了哪一层？**

## 局部规则：输入是 pathname 还是 fd，决定起手

**触发信号**：题目出现 `open/stat/link/unlink` 或 `read/write/lseek/dup`。

**第一动作**：先圈输入。pathname 从 namespace 开始解析；fd 已经跳过名字解析，先定位当前进程 fd table 指向的 OFD。

**检查与退出**：如果题目已经给 fd，你仍从根目录重新走路径；或者题目给 pathname，你直接跳到 offset，都说明层级起点错了。

## `open()`：建立的是运行时关系，不是“把文件读进内存”

### 局部规则：每次独立 open 先假设新 OFD

**触发信号**：同一个文件被多次 `open()`，题目问 offset 是否共享。

**第一动作**：分别画每个 fd 指向哪个 OFD；独立 `open()` 通常产生独立 OFD，因此 offset 独立。只有 `dup()`、`fork()` 继承等明确共享引用时，再画多个 fd 指向同一 OFD。

**检查与退出**：不要因为两个 fd 最终指向同一个 inode，就推出它们共享 offset。

## `dup()` / `fork()`：共享的是引用关系

### 局部规则：看到共享 offset 就追到 OFD

**触发信号**：两个 fd 的读写会互相影响文件位置，或者题目问 fork 后父子读同一打开文件。

**第一动作**：检查它们是否共同指向同一个 OFD；offset 属于打开实例，不属于 fd 整数，也不直接属于 inode。

**检查与退出**：若是两个独立 open，即使 pathname/inode 相同，也不要合并 OFD。

## `unlink()`：删名字不等于立刻删对象

### 局部规则：分别数命名引用和打开引用

**触发信号**：删除文件后仍有进程持有 fd，题目问是否还能读、何时回收数据块。

**第一动作**：分别追踪目录中的命名边/link count 与运行时 open reference。`unlink()` 先移除命名关系并减少 link count；已打开的 OFD 仍可保持对象引用。

**检查与退出**：`nlink = 0` 不能单独推出“对象已立即释放”；还要确认是否仍有打开引用以及文件系统的回收语义。

## hard link / symbolic link：先问“新名字指向什么”

| 情况 | 新命名对象 | 关键后果 |
|---|---|---|
| hard link | 另一个目录项指向同一持久对象 | 目标 inode 的 link count 增加 |
| symbolic link | 新建一个 symlink 对象，其内容保存目标 pathname | 目标删除后可能 dangling；解析时会继续解释路径 |

### 局部规则：遇到 link 题先分 Name 与 Object

**触发信号**：题目问 hard/symbolic link、删除目标、跨文件系统或 link count。

**第一动作**：画出“这个新名字最终共享原对象，还是先指向一个新的 symlink 对象”。

**检查与退出**：不要把 symlink 内容当成目标 inode 的第二条硬引用。

## 文件操作状态表

| 操作 | 首先改变什么 |
|---|---|
| `create` | 新对象 + 父目录命名关系 |
| `open` | 新 OFD + fd 引用 |
| `dup` | 新 fd 指向已有 OFD |
| `fork` | 子进程继承资源引用；是否共享 OFD 按语义判断 |
| `read/write` | 通过 OFD 访问对象，并按接口推进/使用 offset |
| `lseek` | 改 OFD offset，不搬数据 |
| `truncate` | 改文件 size，并可能释放/调整数据映射 |
| `unlink` | 删除 namespace 中一条命名边 |
| `close` | 删除一个 fd/OFD 引用，必要时触发最终回收 |

## 综合题落笔顺序

1. 输入是 pathname 还是 fd？
2. 当前操作的是 Name、Object、OFD 还是 fd？
3. pathname 从 root、cwd 还是 dirfd 开始？
4. 最终解析到哪个持久对象？
5. 当前 fd 指向哪个 OFD，是否和别的 fd 共享？
6. offset 存在哪里，当前操作怎样改变它？
7. 如果继续进入文件数据，转到“文件索引与 I/O 计算”；
8. 如果需要设备等待与完成，转到 OS-05 / OS-I01；
9. 如果问题变成多结构持久更新与 crash，转到“崩溃一致性”。

## 易错边界

> **filename ≠ inode。** 名字属于 namespace；inode/FCB 表示持久对象元数据。

> **fd ≠ OFD ≠ inode。** fd 是进程句柄；OFD 是打开实例状态；inode 是持久对象。

> **link count ≠ open reference。** 一个统计命名边，一个统计运行时引用关系。

> **file offset ≠ PBN。** offset 先变成 file page/LBN，再经映射结构得到存储位置。

## 最短压缩

遇到文件系统状态题，先写四个词：**Name / Object / Open State / Handle**。题目中的每个操作都必须落在其中一个层，再去看它是否连带修改其他层。
