# 文件索引与 I/O 计算

> 训练定位：面对 inode 混合索引、最大文件大小、字节偏移定位、路径访问与磁盘 I/O 次数题时，训练先锁定逻辑编号和缓存假设，再调用 Canonical 的 block mapping 机制完成计算。  
> 模型归属：[OS-06/07 文件系统与持久化方法论手册](OS-06_OS-07_文件系统与持久化_方法论手册.tex)。direct/single/double/triple、LBN→PBN、页缓存与块映射的定义和公式由 Canonical 正文拥有；本文件只负责落笔流程、变式与检查。

## 局部规则：先把字节位置变成 LBN

**触发信号**：题目给文件内字节偏移、block size，并要求判断落在哪一级索引或访问哪个数据块。

**第一动作**：先写

$$
LBN=\left\lfloor\frac{x}{B}\right\rfloor,
$$

再把 LBN 与 direct / single / double / triple 各自覆盖的逻辑块区间比较。

**检查与退出**：不要直接拿字节偏移和“第几个指针”比较；索引结构映射的是逻辑块编号，不是字节编号。

## 最大文件大小：公式由 Canonical 生成，训练只负责套入边界

设每个索引块可容纳 $K=B/a$ 个块地址，inode 中 direct/single/double/triple 指针数量分别为 $d,s,q,t$。计算题的执行顺序是：

1. 求 $K$；
2. 分别写出各层覆盖的数据块数；
3. 相加得到最大可寻址数据块数；
4. 乘 block size；
5. 最后检查题设是否还有文件长度字段、块号位宽或其他更小上限。

### 局部规则：先数“数据块”，最后再乘块大小

**触发信号**：多级索引公式中同时出现块大小、地址项大小和多重幂次。

**第一动作**：先只在“块的数量”这一单位下计算 direct、$K$、$K^2$、$K^3$ 的覆盖量。

**检查与退出**：如果中间步骤的单位已经变成字节，又继续与块数相加，立即回退；所有覆盖项先统一为 data blocks。

## I/O 次数题：先写假设表

同一个逻辑访问，在不同缓存状态下答案可以不同。正式计数前至少写清：

| 对象 | 当前是否已在内存 / 缓存 |
|---|---|
| 目录块 / dentry | 题设是否需要逐级读盘 |
| inode | 是否已在内存 |
| 单/双/三级间接索引块 | 哪些已经缓存 |
| 数据页 / 页缓存 | hit 还是 miss |
| FAT | 是否假设常驻内存 |
| 写回元数据 | 本题是否计入 |

### 局部规则：先画访问序列，再删缓存命中

**触发信号**：题目问“访问某字节需要几次磁盘 I/O”，并给出若干“已在内存/未缓存”的条件。

**第一动作**：先按机制画出完整对象访问序列，例如 `目录 → inode → 一级索引 → 二级索引 → 数据块`；然后把题设明确已缓存的节点划掉。

**检查与退出**：不要从“二级间接所以三次 I/O”这类记忆直接报数。那只在特定前提下成立。

## 路径查找 I/O：路径层级不是 I/O 次数

`/a/b/c` 有三个 component，不代表固定 3 次或 6 次磁盘访问。每一级解析可能涉及目录对象、目录数据块、目标 inode，还受 dcache/inode cache 影响。

### 局部规则：component 与磁盘对象分开计数

**触发信号**：绝对/相对路径 + “磁盘 I/O 次数”。

**第一动作**：逐 component 写“当前目录对象 → 查目录记录 → 得到下一个对象”，再标记哪些对象已在内存。

**检查与退出**：如果答案只由斜杠数量决定，基本说明没有建模实际访问对象。

## 页缓存与 block mapping：不要把顺序写反

普通 buffered file read 更自然的观察顺序是先按 `(file, page index)` 查页缓存；miss 后才需要文件系统继续建立到存储块的位置关系。

### 局部规则：题目出现页缓存时先判 hit/miss

**触发信号**：同一道题既出现 file offset/LBN/PBN，又明确给 page cache 状态。

**第一动作**：先判断所需文件页是否已经在页缓存；hit 时不应机械继续计底层 block mapping 的磁盘读取。

**检查与退出**：只有 miss 且确实需要后端存储内容时，才继续追到索引块和设备 I/O。

## 物理分配题：先区分连续、链接、索引三种“次序保存在哪里”

| 分配方式 | 文件块次序主要保存在哪里 | 随机访问 | 文件增长时的典型代价 |
|---|---|---|---|
| 连续分配 | `start + length` 隐含连续次序 | 好 | 后方无空间时可能整体搬迁 |
| 隐式链接 | 每个数据块中的 next 指针 | 差，需要顺链 | 改链需要读写相关数据块 |
| 索引分配 | 独立索引块/索引结构中的块号数组 | 好 | 可能新增/修改索引块 |

### 局部规则：I/O 次数取决于“指针在哪”，不是只看数据是否要移动

**触发信号**：题目问插入/删除/把最后一块移到文件头等逻辑重排需要几次磁盘 I/O。

**第一动作**：先写“逻辑次序由哪个持久对象表达”。若索引信息已经在内存，逻辑重排有时只改内存索引；隐式链接的 next 在数据块内，就必须读写相应块。

**检查与退出**：题设说“索引块已在内存”时，不要仍机械把改索引算成一次读盘；反之也不能把最终持久化写回永久忽略，除非题目明确只统计立即 I/O。

## 位示图：先统一三个编号起点

位示图题至少有三个编号系统：

```text
resource/block number
bitmap word/byte number
bit number inside the word
```

设每个字有 $w$ 位，资源块号从 0 开始，位示图的字号、位号从 1 开始，则块号 $b$ 对应：

$$
word=\left\lfloor\frac{b}{w}\right\rfloor+1,
\qquad
bit=(b\bmod w)+1.
$$

### 局部规则：先写“0-based 还是 1-based”再除法取模

**触发信号**：题目给块号、字长，问第几个字第几位，或者问整张 bitmap 占多少块。

**第一动作**：把资源编号起点、位示图字编号起点、位编号起点分别写在草稿上，再做除法/取模。

**检查与退出**：同一道题只要其中一个起点改为 1-based，答案就可能整体偏一；不能靠记忆“100号块在第4字第5位”。

### 位示图总空间

若有 $N$ 个资源块，每块只需 1 bit 表示 free/used，则：

$$
S_{bitmap}=N\text{ bits}=\left\lceil\frac{N}{8}\right\rceil\text{ bytes}.
$$

若位示图按大小为 $B$ bytes 的磁盘块连续存储，占用块数为：

$$
N_{mapblk}=\left\lceil\frac{N}{8B}\right\rceil.
$$

若从 0 号盘块开始存放，最后一个位示图盘块号为 $N_{mapblk}-1$。

## 顺序目录/索引顺序文件：先写“搜索对象”和平均位置假设

**触发信号**：题目给目录项数量、每块能放多少项，问平均磁盘访问次数；或给顺序文件记录数，要求估算建立一级索引后的平均查找量。

**第一动作**：先确认是顺序扫描目录块、组内顺序查找，还是索引多级查找；再确认目标位置是否按等可能处理、相关索引/目录块是否已缓存。

**检查与退出**：`N/2` 只来自“线性顺序查找 + 目标位置等可能”这类前提；一旦存在 cache、hash/B+tree 或分层索引，就不能机械除以 2。

## 常见变式

- 多个 direct / single 指针：先算每一类指针的总覆盖区间，不要默认各只有一个；
- 块地址项大小不整除 block size：按题设使用整数地址项数；
- 访问范围跨块：同时求起止 LBN，不只算起点；
- 写文件增长：除数据块外可能需要新索引块与 free-space metadata；
- ext4 extent 等工程结构：只用于理解边界，408 经典题按题设 mixed indexing 模型计算。

## 题库母题：文件计算题先统一“到底在数什么”

### [Q641 / Q643｜“两级索引到底能管多少文件数据？”](../../../archives/408/题库/操作系统/06_文件系统_选择题.md#641)

第一步只在“块的数量”这一单位里算。若一个索引块能放 $K$ 个地址，那么一级覆盖 $K$ 个数据块、二级覆盖 $K^2$ 个数据块。需要算最大文件大小时，最后才乘 block size；需要算文件总占用时，再按题意决定索引块本身是否也计入。

这样可以避免最常见的错误：把“索引块数、数据块数、字节数”放在同一个式子里直接相加。

### [Q645–649｜“文件中间插一块，为什么不同分配方式 I/O 差这么多？”](../../../archives/408/题库/操作系统/06_文件系统_选择题.md#645)

不要背“连续分配快、链接分配慢”。先问**逻辑顺序存在哪里**：

- 连续分配：顺序由物理连续位置隐含，扩展失败时可能搬整个文件；
- 隐式链接：顺序在数据块里的 next 指针中，要沿链找到修改点；
- 索引分配：顺序在索引表中，若索引已在内存，某些重排只需改索引项。

因此每道题都画“为了完成这次修改，哪些数据块必须读、哪些指针/索引必须改、哪些块必须写”。

### [Q650｜“10 个直接指针 + 1 个一级间接指针，为什么答案不是把索引块也算进去？”](../../../archives/408/题库/操作系统/06_文件系统_选择题.md#650)

题目问的是“最多能存多少**数据块**”。4KB 索引块、4B 块号，所以一级间接能指向 1024 个数据块，再加 10 个直接块，就是 1034 个数据块。索引块本身是元数据，不属于题目要求的数据块数。

### [Q651｜“一级目录平均查找要多少次磁盘 I/O？”](../../../archives/408/题库/操作系统/06_文件系统_选择题.md#651)

先锁三个前提：目录块有没有缓存、每块放多少 FCB、目标在目录中的位置怎样分布。1KB/64B=16 个 FCB/块，3200 项就是 200 个目录块；顺序查找且目标等可能时，平均检查一半约 100 块。**没有缓存前提就不能直接报 I/O 次数。**

### [Q658–659｜“位示图为什么公式会算对、位置却总错一位？”](../../../archives/408/题库/操作系统/06_文件系统_选择题.md#658)

因为块号、字号、位号可能分别采用 0-based 或 1-based。做题第一行就写清编号契约，再做商和余数。例如块号从 0 开始、每字 32 位：`block//32` 决定第几个 0-based word，`block%32` 决定第几个 0-based bit；如果题目要求字号/位号从 1 开始，最后统一 +1。

**文件计算题的稳定顺序是：先统一对象单位和编号/缓存前提 → 画真实访问或修改路径 → 最后再数 block、I/O 或 byte。**

## 最短压缩

```text
byte offset
→ LBN / file page index
→ 当前层级覆盖区间
→ 完整对象访问序列
→ 根据缓存条件删除无需 I/O 的节点
→ 最后计数并检查单位/边界
```

真正容易错的通常不是 $K^2$，而是**没先锁定题目正在数哪一种对象、哪些对象已经在内存**。
