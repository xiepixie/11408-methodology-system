OS-I02 · Course Capstone

fork() + COW + Resource Reference：
不要再问“整个进程复制了什么”

fork 最容易被一句“复制进程”害死。正确模型是：创建新的 process identity，然后对每类对象分别建立 Copy / Share / Reference / Rebuild 关系；以后只有拥有该关系的事件才让它分化。内存写会触发 COW，但不会复制 open file；close 会删一条 fd binding，但不会影响另一进程的 private page。

1 · Mother Question

父子为什么既是两个进程，又能暂时共享物理页和同一个文件 offset？

因为“身份”“逻辑语义”“物理表示”“引用关系”不是一个维度。新的 PID 不要求每个底层对象立即物理复制；共享底层对象也不意味着父子整个进程状态合并。

Current main

    Parent fd3
    →
    Open File Aoffset=0 ref=1
    fork
    P fd3 + C fd3two bindings
    →
    same Open File Aoffset shared · ref=2

    若 parent 先普通 read 100 bytes，open object 的 offset 变 100；child 后续使用继承 fd 普通 read 时从 100 继续。父子“fd 表各自拥有”与“underlying open state 共享”同时成立。

    7 · 两个共享轴彼此正交

    Child COW split

    只改变 child 的 private VM mapping / frame ownership；不会自动复制 OFD、inode 或 cwd。

    Child close(fd3)

    只删除 child 的 descriptor binding、减少 open-object ref；不会让 parent 的 private page 或 parent fd 失效。

    这是本课程最后一个统一动作：对每个事件只修改它真正 Own 的 relation。别让“某处发生分化”连带污染其他对象。

    8 · exec 再次说明 Process Identity ≠ Program Image

    Child process CPID=C
    exec
    same process Cnew program image

    exec 替换用户程序映像/地址空间内容，不以创建新 PID 为定义。未被 close-on-exec 关闭的 fd 还可以继续存在，所以 shell 的“fork → 重定向 fd → exec”才能组合起来。

    9 · close、unlink、exit：三种“不要了”作用在不同边

    事件主要删除/改变
    close(fd)当前进程的一条 fd binding / open-file reference
    unlink(path)namespace 中 name→inode 的持久链接
    exit()进程生命周期结束；关闭其 refs、释放/交接 VM 与文件资源，最后由 parent wait 回收 process shell

    这三者都可能最终导致对象 free，但它们触发的是不同引用边。生命周期题永远先画 relation，再做引用计数。

    10 · Capstone Example

    P: x=1 in private page P: fd3 → OFD-A(offset=0) → inode F fork() → child C C writes x=2 // COW: VM relation diverges only P reads 100 bytes // OFD-A offset = 100 C reads fd3 // starts from shared offset 100 C close(fd3) // child binding removed; parent fd remains C exec(newprog) // same child identity, new program image C exit(); P wait() // child process lifecycle reclaimed

    如果你能逐行说出“哪一个对象、哪一条 relation 在改变”，整个 OS 前 15 页已经真正连成系统。

    11 · Quick Attack

    Q1 · fork 后父子“共享地址空间”这句话对吗？
    对 private memory 来说不准确。逻辑地址空间语义是彼此独立；COW 只是暂时共享底层 physical representation。显式 MAP_SHARED/共享内存才是另一类共享语义。
    Q2 · child close(fd3) 会不会让 parent fd3 无效？
    不会。父子有各自 descriptor binding；close 只删除 child 那条引用。underlying open object 仍被 parent 引用。
    Q3 · 父子 fd 数字一样，所以共享 offset？
    数字不是判据。fork 语义下它们共享 offset，是因为两条 binding 指向同一 open file object/OFD。两次独立 open 即使都得到 fd=3，也可以 offset 独立。
    Q4 · COW split 后 child 的 file offset 会不会也复制？
    不会。COW 事件只改变 VM mapping / physical frame relation；open file relation 是独立轴。
