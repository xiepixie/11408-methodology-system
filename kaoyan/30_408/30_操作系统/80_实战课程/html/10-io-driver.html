Interrupt / Driver / DMA：
I/O 到底是谁等待、谁搬数据、谁宣布完成？

I/O 最容易乱，是因为四个维度常被一句“DMA 中断”揉在一起：调用线程是否等待、设备完成怎样被发现、数据主要由谁搬、完成后软件状态怎样交付。这一页用 xv6 UART、virtio disk 和 Fall 2026 E1000 lab 把这四条线拆开，再重新合成一次完整的阻塞 I/O。

1 · Mother Question

当一个进程说“帮我读数据”之后，CPU、driver、device、DMA、interrupt、scheduler 分别负责哪一步？

先记责任，不记设备名：“搬运者”和“完成发现者”是两条独立轴。DMA 回答谁搬数据；Interrupt 回答 CPU 怎样知道有事件。二者可以组合，也不互相推出。

2 · 四维坐标：Blocking / Async / Interrupt / DMA 必须拆开

Caller Behavior

Blocking / nonblocking：这次请求不能立刻完成时，调用线程现在怎么办？

Completion API

同步返回还是异步 callback/CQ/event？这是软件完成语义。

Discovery

Polling 还是 interrupt：CPU 怎样发现设备有进展/完成？

Movement

PIO 还是 DMA：数据主要通过 CPU 指令搬，还是设备/DMA 引擎直接与内存交换？

Anti-Bridge：Interrupt-driven ≠ Async API；DMA ≠ nonblocking；普通阻塞磁盘读完全可以是 Blocking + DMA + Interrupt。

3 · UART：中断驱动不等于 DMA

当前 xv6 16550 UART 是很好的“低速字符设备”模型。uartwrite() 在发送器忙时 sleep()；硬件发送完一个字符后触发 UART interrupt，uartintr() 把 tx_busy=0 并 wake sender。

CPU WriteReg(THR)CPU 发一个字符
→
UART worksdevice serializes byte
→
TX IRQready for next
→
uartintrtx_busy=0 + wakeup

这里中断解决的是等待发现：CPU 不必一直读 LSR。但这条简单发送路径也没有“整块数据由 DMA 引擎搬完”的语义，别看到 interrupt 就自动想到 DMA。

4 · Virtio Disk：Blocking + DMA-style descriptor + Interrupt 的完整样本

当前 xv6 virtio_disk_rw() 用 descriptors 把命令、buffer 和状态提交给设备。设备直接访问 descriptor 指向的内存；调用线程随后睡在 buf 上。设备完成后写 used ring 并触发 interrupt，driver 清 b->disk、wakeup waiter。

request thread: build descriptor chain publish to avail ring notify device while (b->disk == 1) sleep(b, &disk_lock) device: read/write memory through virtio DMA-style queue append used-ring completion raise interrupt ISR: consume used ring b->disk = 0 wakeup(b)

5 · Interactive I/O Triple Trace：数据线、完成线、任务状态线同时看

    6 · Completion Evidence ≠ Interrupt Signal

    Interrupt

    “有设备事件需要 CPU/driver 处理。”它是通知路径的一部分。

    Completion Evidence

    descriptor DD/status、used-ring entry、设备 status 等真正说明哪一个 request 完成以及结果如何。

    当前 virtio ISR 会消费 used ring，并检查每个 descriptor chain 对应的 status；E1000 lab 也要求看 TX/RX descriptor 的 DD bit，而不是“收到中断就假定所有 packet 都完成”。

    进一步：高性能系统也可以 polling completion queue，而不为每个完成都中断。于是 DMA completion ≠ interrupt 也必须成立。

    7 · DMA Address：经典 408 与现代工程边界要分层

    层正确说法
    408 经典模型CPU/driver 给 DMA 控制器主存起始地址、方向、长度；DMA 在设备与主存之间搬运，CPU 不逐字参与。
    xv6/QEMU 教学实现kernel memory 采用方便的映射，driver 可把 DMA buffer/descriptor 地址直接交给 emulated device；这简化了平台问题。
    现代平台driver 通常建立 DMA-visible mapping；device address 可能经 IOMMU/总线翻译，不应永久等同于 user VA 或 CPU physical address。

    这页已反向修正 Canonical X-B03：稳定接口应该是 prepare/map → submit → transfer → completion → sync/unmap，而不是把所有 DMA 写死成“裸 PA + 一次中断 + CPU 完全不介入”。

    9 · PLIC：中断控制器解决的是“谁的请求先递送到哪个 CPU”

    当前 xv6 用 RISC-V PLIC 接收 UART、virtio 等外部 interrupt。devintr() 先 plic_claim() 得到 IRQ，分派到设备 handler，最后 plic_complete()。

    408 边界：中断控制器只负责 pending/mask/priority/routing 等硬件交接；“哪个 process 被 wake、是否调度”回 OS，不能把中断优先级和调度优先级混成一张表。

    12 · Blocking read 的等待链与 DMA 是两个不同问题

    Request A

    user thread 调用同步 read()，cache miss 后必须等 disk：A 进入 Blocked。

    Request B

    异步 API 提交相同 DMA request 后立刻返回；完成后通过 completion queue/event 告知。

    共同硬件可能完全相同。谁 wait 是 API/OS policy；谁搬数据是 DMA；怎样发现完成是 interrupt/polling。这就是“四轴不能互推”的意义。

    14 · HDD 物理模型：为什么“磁盘调度”首先是在减少机械移动

    Track / 磁道

    一个盘面上同心圆状的记录轨迹。经典题常把“磁头位置”抽象成 track/cylinder number。

    Cylinder / 柱面

    多个盘面上相同半径磁道的集合。移动磁臂改变的主要就是当前 cylinder。

    Sector / 扇区

    磁道沿旋转方向切成的最小地址区域之一。到达正确 cylinder 后还可能等待目标 sector 转到磁头下。

    T_access = T_seek + T_rotation + T_transfer 随机扇区平均旋转等待： T_rotation(avg) ≈ 0.5 × one revolution time = 0.5 × 60 / RPM

    磁盘调度为什么按 cylinder 排？FCFS/SSTF/SCAN 主要试图降低 T_seek，即磁臂的往返距离。旋转优化、扇区布局和现代控制器内部调度是另一层问题；408 经典算法先按一维磁道数轴建模。

    SSD 边界：SSD 没有机械 seek/rotation，因此“最短磁头移动”不再是核心成本。408 仍考这些算法，是为了训练“调度策略必须服从设备成本模型”，不要把它们升级成所有存储设备的通用最优策略。

    15 · Interactive Disk Scheduling Lab：六种算法统一在一条数轴上

    约定：请求视为同一时刻已在队列；SSTF 同距离时优先较小柱面号；SCAN/C-SCAN 只有在还需去另一侧服务请求时才把物理端点/回卷计入完成轨迹。真题若明确另一约定，以题设为准。

    算法第一动作最容易错在哪里
    FCFS保留到达顺序别擅自排序
    SSTF每一步从“当前位置”重算最近请求局部最短不保证公平；新近请求可让远端饥饿
    SCAN先画初始方向，再沿方向服务需要反向时走到物理端点
    C-SCAN只沿一个方向服务到端点后回卷到另一端；回卷距离是否计入按题设
    LOOK像 SCAN，但“看见最后请求就回头”不要多走到无请求物理端点
    C-LOOK像 C-SCAN，但只在请求范围回卷最高请求 → 最低请求的 jump 仍是磁头移动

    五步法：数轴标请求 → 标当前方向 → 写完整服务顺序 → 累加相邻距离 → 最后检查 endpoint 与 last request 是否混淆。

    16 · Quick Attack

    Q1 · 设备使用 DMA，调用进程是否一定 Blocked？
    不一定。DMA 只说明搬运由设备/DMA 引擎与内存直接完成。调用者可以是同步阻塞，也可以异步提交后先返回。
    Q2 · 收到设备中断，能否立即说“本次 I/O 成功完成”？
    不能。中断只是设备事件通知；driver 仍需读取状态或消费 completion descriptor，才能知道具体哪个 request 完成及是否成功。
    Q3 · DMA 地址是否必然等于用户虚拟地址或 CPU 物理地址？
    用户 VA 不能直接当通用 device address；现代平台可能经 IOMMU。稳定说法是 driver 建立 DMA-visible mapping。408 经典题若明确简化成物理地址，就按题设推演。
    Q4 · Interrupt-driven I/O 是否等价于异步 I/O？
    不等价。设备内部可由 interrupt 完成，但用户线程仍可能一直阻塞到系统调用返回；异步 I/O 讨论的是软件 API 的完成交付语义。
    Q5 · LOOK 和 SCAN 的根本区别是什么？
    两者都沿一个方向有序服务再反向；SCAN 的经典模型会走到物理端点再回头，LOOK 只走到该方向最后一个实际请求就反向，因此避免无请求区间的机械移动。
    Q6 · SSTF 平均寻道通常较小，为什么仍可能不是好选择？
    它只优化当前一步的局部距离。若磁头附近持续有新请求，远端既有请求可能不断被插队，形成 starvation；平均距离好不等于进度公平。

    18 · Retrieval Check

    1. 面对任意 I/O 题先回答四轴：caller behavior、completion API、discovery、movement。
    2. 复原 virtio disk 的 submit → sleep → device transfer → used ring/IRQ → wake → resume。
    3. 解释为什么 DMA completion、interrupt、task wakeup、task running 是四个不同事件。
    4. 解释 DMA-visible mapping 的生命周期与为什么 user VA 不能直接交给设备。
    5. 用 E1000 RX ring 解释 buffer ownership 为什么必须从 NIC 移交给 network stack 后再补 fresh buffer。
    6. 说明 PLIC priority 与 process scheduler priority 为什么不能互推。
    7. 从 T_seek + T_rotation + T_transfer 解释为什么 HDD 调度主要优化柱面移动。
    8. 对同一请求串手算 FCFS/SSTF/SCAN/C-SCAN/LOOK/C-LOOK，先写服务顺序再累计距离，并明确初始方向与端点约定。
