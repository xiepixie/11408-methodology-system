# 操作系统题库回归矩阵

> 证据集：`archives/408/题库/操作系统` 475–695，共 221 题。  
> 目的：这是给维护者/Agent 使用的**导航索引**，记录“哪些题暴露了哪类错误、应该去哪个训练手册修”。它不是学习正文，也不要求学习者直接理解表格里的压缩术语。  
> 真正学习题目时，请进入对应 Training 文件的“题库母题”部分；那里必须写清题目在问什么、第一步怎么想、为什么这个方法成立。  
> 状态：练习题回归已支持；尚不能替代真题 + 陌生题验证，因此这里的规则不自动升级为 Adopted。

## 回归原则

每道新题只问三件事：

1. **它是否暴露 Canonical 机制错误？** 是 → 修 Canonical；
2. **机制正确，但第一动作不稳定？** 是 → 修 Training；
3. **只是题干缺模型前提/编号/成本约定？** 是 → 修 Question Contract，不把实现口径升级成通用定义。

优先记录能跨题复用的失败模式，不记录“某题答案是 A”这种一次性事实。

## 当前最稳定的跨题母模型

### 1. Contract before Calculation

```text
先锁模型契约
→ 再做计算
```

凡答案依赖“单处理器 / M:1 / 负值 semaphore / BIOS-MBR / CHS / 是否忽略缓存/缺页/写回”等条件时，这些条件必须先进入题面或草稿。

### 2. Owner before State Change

```text
谁拥有状态？
谁有权修改？
什么事件触发？
```

可统一解释 syscall privilege、mutex ownership、scheduler、page table、OFD、driver/controller 等大量题。

### 3. Orthogonal Axes Stay Orthogonal

```text
Blocked ≠ Unlock
Wakeup ≠ Running
Mapping ≠ Residency
Interrupt ≠ DMA
fd ≠ OFD ≠ file object
Available enough ≠ Safe
```

选项一旦把不同轴直接画等号，优先构造反例。

### 4. State Machine before Formula

调度、动态分区、PV、Banker、页面置换、buffer、disk scheduling 都应先维护状态，再用公式汇总。公式只压缩已经理解的状态迁移，不能代替状态表示。

### 5. Fast Path before Slow Path

syscall、虚存、文件、I/O 综合题先问“当前状态能否直接满足请求”。只有不能满足时，才展开 block、page fault、device I/O、writeback、recovery。不要因为题目出现某个慢路径名词就默认它必发生。

## 下一轮验证要求

每条候选规则至少继续通过两类攻击：

1. **真题攻击**：优先用 408 历年题检查考试口径是否与规则兼容；
2. **陌生变式攻击**：主动改变一个模型维度，例如 M:1→1:1、FIFO→CLOCK、single-resource→multi-resource、HDD→SSD、path→fd，看规则是否仍能给出正确第一动作。

若规则只能在原题换数字时成立，应降级为“题型模板”；只有改变表面故事、数据和实现细节后仍能稳定定位问题，才有资格继续向 Adopted 推进。
