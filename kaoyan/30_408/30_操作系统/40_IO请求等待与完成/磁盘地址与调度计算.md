# 磁盘地址、服务时间与调度计算

> 训练定位：面对 CHS/LBA 编号、连续块定位、寻道/旋转/传输时间、FCFS/SSTF/SCAN/C-SCAN/LOOK/C-LOOK、磁带记录密度以及 HDD/SSD 边界题时，训练先确定设备成本模型和编号约定，再做线性化与服务序列模拟。  
> 模型归属：[OS-05 I/O 系统方法论手册](OS-05_IO系统_方法论手册.tex)。HDD/SSD 机制、磁盘调度策略和磨损均衡定义由 Canonical 正文拥有；本文件只负责计算、事件顺序和检查。

## 第一问永远不是“用哪个公式”，而是“这是什么设备成本模型”

```text
HDD -> 机械寻道 + 旋转等待 + 传输
SSD -> 无机械寻道/旋转，但有 FTL、GC、写放大、磨损均衡、队列成本
Tape -> 顺序介质，记录密度 + gap + 定位/移动成本
```

### 局部规则：不要把 HDD 调度结论外推到 SSD

**触发信号**：题目同时出现 SCAN/SSTF 与 SSD/NVMe/flash。

**第一动作**：先问物理成本是否仍由磁头位置决定。只有机械 HDD 才把“减少磁头移动”作为核心调度目标。

**检查与退出**：SSD 仍需要 I/O 调度，但不再用柱面距离解释主要成本；连续 LBA 也不保证连续闪存物理页。

## CHS/LBA 线性编号：先写每层容量

若每柱面有 $H$ 个盘面/磁头，每磁道有 $S$ 个扇区，编号均从 0 开始，则：

$$
LBA=(Cylinder\times H+Head)\times S+Sector.
$$

反向转换时：

```text
Cylinder = LBA // (H*S)
rem      = LBA %  (H*S)
Head     = rem // S
Sector   = rem %  S
```

### 局部规则：文件第 0 个逻辑块从哪里开始，决定是否还要加基址

**触发信号**：题目说“文件从某个 CHS 地址连续存放”，问另一地址对应第几个逻辑块。

**第一动作**：把起点和目标都转成同一种线性编号，做：

$$
LBN=LBA_{target}-LBA_{start}.
$$

**检查与退出**：题目从 0 号逻辑记录编号时不再额外加 1；从“第 1 条记录”编号时才按题设转换。

## “连续存放”的下一块：先确认题设给出的几何遍历顺序

经典固定几何题常约定：

```text
sector 先递增
-> 当前磁道扇区用完后换同柱面下一盘面/磁头
-> 当前柱面所有盘面用完后柱面 +1
```

### 局部规则

**触发信号**：当前块正好处于最后一个 sector，问下一块 CHS。

**第一动作**：先让 sector 回 0，再按题设层次推进 head/cylinder。

**检查与退出**：现代磁盘的真实内部重映射不服从简单 CHS；只有题目明确固定几何模型时才这样算。

## HDD 服务时间：把三个时间分开

经典模型：

$$
T_{access}=T_{seek}+T_{rotation}+T_{transfer}.
$$

若转一周时间为 $R$，随机扇区平均旋转等待通常近似：

$$
E[T_{rotation}]=\frac{R}{2}.
$$

若一个完整磁道传输恰需一周，则传 $b$ 字节、每磁道 $N$ 字节时，纯连续传输时间近似：

$$
T_{transfer}=\frac{b}{N}R.
$$

### 局部规则：题目说“忽略旋转延迟”不代表传输时间也为 0

**触发信号**：题目同时给转速/每转时间和“忽略旋转延迟”。

**第一动作**：把“等待目标起始扇区到达”的 rotation latency 与“数据在盘片转动中经过磁头”的 transfer time 分开。

**检查与退出**：转一周时间既可能被用来算平均半圈等待，也可能被用来算整磁道传输；先看题设正在用哪一种。

## 磁盘调度：先生成服务顺序，再算距离

任何调度题统一两步：

1. 写出请求真正被服务的顺序；
2. 相邻服务位置做绝对差并求和。

不要在脑中一边选一边累计，容易漏端点或回绕。

### SSTF

每次从当前磁头位置选择最近请求：

```text
current -> argmin |request-current|
```

**检查**：持续到来的近端请求可能让远端旧请求长期等待，因此 SSTF 可能 starvation。

### SCAN

沿当前方向服务所有请求；经典 SCAN **到物理端点后再反向**。

### LOOK

沿当前方向服务到该方向最后一个请求后立即反向，不必走到物理端点。

### C-SCAN / C-LOOK

只在一个方向提供服务；到边界后回绕。C-SCAN 的边界是物理端点，C-LOOK 的边界是请求端点。

### 局部规则：看到 SCAN 先写 endpoint convention

**触发信号**：题目只说“电梯/SCAN”，答案涉及总移动距离。

**第一动作**：在草稿顶部写：

```text
SCAN: 是否必须走到 0 / max track？
LOOK: 是否只走到最远请求？
回绕距离是否计入？
```

**检查与退出**：如果题目没有给约定而不同约定会改变答案，应先补充模型；不能把 LOOK 的算法偷偷当成 SCAN。

## 旋转延迟与调度：先分“柱面顺序”和“扇区相位”

经典 FCFS/SSTF/SCAN 多数只决定下一次访问哪个柱面/磁道，直接优化的是 seek distance。若题目没有扇区相位、转速位置或 rotational-position-aware scheduling，就不要假装能精确优化旋转延迟。

文件物理布局和空闲空间分配会影响未来目标扇区在哪里，因此会**间接影响**旋转/寻道成本；但这与“某个经典柱面调度算法直接根据扇区相位做决策”不是一回事。

## 磁带记录题：数据长度与 gap 分开计

记录密度 $D$ 字符/英寸，每条记录 $L$ 字符，则纯数据长度：

$$
\ell_{data}=\frac{L}{D}.
$$

若每条记录按题设近似再附加 gap $g$，则 $N$ 条记录总长度：

$$
\ell_{total}\approx N\left(\frac{L}{D}+g\right).
$$

利用率：

$$
\eta=\frac{N(L/D)}{\ell_{total}}.
$$

### 局部规则

**触发信号**：选项使用整数近似长度，而严格来说首尾 gap 数可能是 $N-1$。

**第一动作**：检查题设是否明确“每条记录连同一个 gap 计长”或允许教材近似。

**检查与退出**：不要在近似题里因为一个端点 gap 与选项不匹配就擅自换模型；先写清使用的 convention。

## SSD：只保留真正稳定的机制边界

```text
没有机械 seek/rotation
!= 写入没有额外成本
```

Flash 写入需要 erase-before-rewrite，FTL 维护逻辑到物理映射，GC 会搬迁有效页并造成 write amplification。

- 动态磨损均衡：主要在可用/活跃块之间分散新写入；
- 静态磨损均衡：还会搬迁长期不变的冷数据，使全盘擦写次数更均匀。

### 检查

不要把“静态磨损均衡”理解成“每次写入直接覆盖最冷块”；它是一种长期数据搬迁与寿命均衡策略。

## 题库母题：先确认你面对的到底是哪一种存储设备

### [Q688｜“旋转延迟到底由什么决定？”](../../../archives/408/题库/操作系统/07_IO与设备管理_选择题.md#688)

先把 HDD 一次访问拆成三段：寻道、等待目标扇区转到磁头下、真正传输数据。经典 SSTF/SCAN 主要根据柱面距离改变寻道顺序；如果题目没有给扇区相位，它并不能精确优化旋转位置。文件布局会影响未来目标扇区在哪里，但这和“调度算法直接根据旋转相位做决策”不是一回事。

### [Q689–690｜“CHS 的下一块 / 某地址对应第几个逻辑记录怎样算？”](../../../archives/408/题库/操作系统/07_IO与设备管理_选择题.md#689)

第一行先写题目约定的递增顺序和编号起点。经典固定几何常用：sector 先加，扇区用完后 head 加，当前柱面所有盘面用完后 cylinder 加。需要把 CHS 线性化时使用

$$
LBA=(Cylinder\times H+Head)\times S+Sector.
$$

然后再做“下一块”或 `LBA_target-LBA_start`。**编号契约没锁定之前不要计算。**

### [Q691｜“题目说忽略旋转延迟，为什么公式里还有一整转时间 r？”](../../../archives/408/题库/操作系统/07_IO与设备管理_选择题.md#691)

因为旋转延迟和传输时间不是一回事。“忽略旋转延迟”只是不要算等待起始扇区转过来的平均半圈；数据真正从磁道经过磁头仍需要盘片旋转，整磁道传输时间仍可能等于一整转 $r$。所以必须先看 $r$ 在题目中代表等待成本还是传输成本。

### [Q692｜“SCAN 和 LOOK 为什么总差一个端点距离？”](../../../archives/408/题库/操作系统/07_IO与设备管理_选择题.md#692)

因为真正区别就在端点。SCAN 沿当前方向服务并继续走到物理端点，再反向；LOOK 只走到该方向最后一个待服务请求就反向。做题先在草稿顶部写：**当前方向是什么？是否必须走到 0/max track？回绕是否计距离？** 再列服务顺序，最后累计相邻位置差。

### [Q693｜“磁带利用率为什么不是只算数据长度？”](../../../archives/408/题库/操作系统/07_IO与设备管理_选择题.md#693)

顺序介质除了有效记录本身，还要为记录间隙付介质长度。先算每条记录的纯数据长度 $L/D$，再加题设 gap；总带长是数据+间隙，利用率才是“有效数据长度 / 总介质长度”。

### [Q695｜“SSD 题为什么不能继续套磁盘寻道模型？”](../../../archives/408/题库/操作系统/07_IO与设备管理_选择题.md#695)

SSD 没有机械磁头、柱面和旋转延迟。它的主要问题转成 FTL 映射、erase-before-write、GC、写放大和磨损均衡。静态磨损均衡会把长期不变的冷数据也纳入搬迁，让全盘擦写更均匀；它不是“每次写入就去覆盖最冷的数据块”。

**外存题的第一步永远是先锁设备模型：HDD / SSD / Tape？然后再锁编号和成本约定，最后才选公式或调度算法。**

## 最短压缩

```text
1. HDD / SSD / Tape？
2. 编号从 0 还是 1？CHS/LBA/LBN 当前是哪一层？
3. seek / rotation / transfer 哪些计、哪些忽略？
4. 调度算法 endpoint / direction / wrap 约定是什么？
5. 先写服务顺序，再累计距离。
6. SSD 题停止使用磁头距离模型，转向 FTL/GC/wear leveling。
```
