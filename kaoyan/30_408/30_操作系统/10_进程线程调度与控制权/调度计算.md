# 调度计算

> 训练定位：面对 FCFS、SJF/SRTF、HRRN、Priority、RR、MLQ/MLFQ 等 CPU 调度计算题时，训练围绕“决策事件点—当前就绪集合—策略选择—时间线—指标反推”完成状态模拟，不把算法名字当成结果。  
> 模型归属：[OS-01/02 进程线程调度与控制权方法论手册](OS-01_OS-02_进程线程调度与控制权_方法论手册.tex)。高级/中级/低级调度、抢占、调度目标、策略机制与 context switch 由 Canonical 正文拥有；本文件只负责计算执行与检查。

## 固定输入表

做任何调度计算前先整理：

| 字段 | 作用 |
|---|---|
| arrival time | 什么时候进入当前可调度集合 |
| service / burst time | 需要多少 CPU 时间 |
| priority | 谁优先；先确认数值大小的方向 |
| quantum | RR / MLFQ 的时间片 |
| preemptive? | 新事件是否可能打断当前任务 |
| tie-break | 同值时题设按什么规则 |

## 局部规则：只在决策事件点重新选

**触发信号**：抢占式算法、任务陆续到达、时间片耗尽或完成事件。

**第一动作**：先列出会触发调度决策的事件点：到达、完成、阻塞、时间片耗尽、优先级/队列规则要求重新评估等。

**检查与退出**：不要在任意连续时间点反复“重算最优任务”；算法只在定义好的调度机会作决策。

## 九步落笔流程

1. 判断题目讨论高级/中级/低级调度中的哪一层；经典 CPU 算法计算通常属于低级调度；
2. 圈出目标：throughput/turnaround、response/fairness，还是 deadline/predictability；
3. 整理 arrival、service、priority、quantum；
4. 判断抢占/非抢占；
5. 每到一个决策事件点，重新建立当前 ready set；
6. 若是 HRRN，只在真正需要重新选择时计算响应比；
7. 按策略选择，处理 tie-break；
8. 画完整 Gantt 时间线，逐段检查到达、完成、抢占；
9. 从时间线反推 turnaround、waiting、response 等指标，并检查定义与单位。

## 局部规则：等待时间不要靠印象累计

**触发信号**：有多次抢占/重新进入 CPU，直接心算 waiting time 容易漏段。

**第一动作**：优先由 `turnaround - service` 得到 waiting time（在经典单 CPU、无额外阻塞模型下），或明确累计每段 Ready 等待区间。

**检查与退出**：response time 只看首次获得 CPU；turnaround 看完成减到达；三者不要混算。

## HRRN：只在重新决策时更新

$$
R=\frac{W+S}{S}=1+\frac{W}{S}.
$$

### 局部规则：运行中的任务不因响应比变化而自动被抢占

**触发信号**：HRRN 题中等待时间持续增加。

**第一动作**：确认经典 HRRN 通常按非抢占策略；只在当前任务结束/阻塞后，对当时 ready set 计算响应比。

**检查与退出**：不要因为某个等待任务的 $R$ 变大就在中途打断正在运行的任务。

## RR：时间片结束不保证一定切换到别人

### 局部规则：先更新到达/队列，再看队列里还有谁

**触发信号**：时间片耗尽，题目问下一执行实体或 context switch 次数。

**第一动作**：按题设的同刻事件顺序处理新到达、当前任务重新入队和 ready queue；再取队首。

**检查与退出**：若队列只有当前任务，时间片边界不一定意味着换到不同进程；“调度事件”和“不同实体 context switch”不能混计。

## MLFQ：规则必须拆成三层

- 新任务初始进入哪一级；
- 同一级内部用什么策略；
- 什么事件导致升/降级或 priority boost。

### 局部规则：队列成员关系可变才是反馈

**触发信号**：多级队列与多级反馈队列辨析。

**第一动作**：先问任务是否会因运行/等待行为在队列之间移动。

**检查与退出**：固定 membership 的 MLQ 不要误套 MLFQ 的升降级规则。

## 最短压缩

调度计算不是“背算法排序”，而是反复执行：**事件发生 → 更新 ready set → 按 policy 决策 → 画时间线 → 从时间线算指标。**
