# 408-2014-Q22

> 原题：[[../2014 年全国硕士研究生招生考试#22|Q22]]

## 模型锚点

- 主题：CO08｜中断方式下的 CPU 时间占用。
- 题目信号：给出中断请求周期、每次响应与处理所需时间，以及允许的最长响应延迟。
- 第一动作：先把“每次真正占用 CPU 的服务时间”和“允许等待多久才开始响应”分开，再用每次服务时间除以请求周期求最低 CPU 占用比例。

## 解题链

设备每隔

$$
400\text{ ns}
$$

产生一次中断请求。

CPU 对每次请求实际用于响应和处理的时间为

$$
100\text{ ns}.
$$

因此在设备持续工作、且每个请求都必须得到处理的稳态条件下，每个 400 ns 周期中，CPU 至少要拿出 100 ns 用于该设备的 I/O 中断处理。

所以 CPU 时间占比至少为

$$
\frac{100}{400}=0.25=25\%.
$$

题目给出的最长响应延迟 50 ns 只约束“请求到达后最迟多久必须开始响应”，它不会改变每次中断实际需要消耗的 100 ns CPU 服务时间。

## 选项判断

故选 $\boxed{B}$。

A 相当于只计算了 50 ns 响应时限；C、D 则把响应延迟错误地当成了额外 CPU 服务时间或重复计入了服务开销。

## 校验

从资源守恒看：每 400 ns 到来 1 次任务，每次必需 100 ns CPU 时间，因此长期平均 CPU 至少有四分之一时间被该设备占用。允许延迟只改变这 100 ns 在 400 ns 窗口中的位置，不改变总面积。

## 压缩

```text
中断到达周期 + 每次 CPU 服务时间 + 响应时限
-> 先分清“等待多久”和“真正执行多久”
-> CPU 最低占比 = 每次服务时间 / 请求周期
-> 再检查服务时间是否能在允许时限和到达速率下被及时消费
```

## 易错边界

- 中断响应延迟不等于中断响应与处理时间；前者是等待上限，后者才占用 CPU。
- 如果请求到达间隔短于一次中断完整服务所需时间，系统才会出现无法及时消费请求的问题；本题 $400\text{ ns}>100\text{ ns}$，不存在这一矛盾。
