# 408-2014-Q26

> 原题：[[../2014 年全国硕士研究生招生考试#26|Q26]]

## 模型锚点

- 主题：OS01/02 + OS05｜I/O 完成后的进程状态转换。
- 题目信号：一个进程此前执行磁盘读操作，现在“读磁盘操作完成”，问操作系统对该进程必做什么。
- 第一动作：先问这个完成事件消除了什么等待条件；设备完成只让等待 I/O 的进程恢复可运行资格，不等于立刻获得 CPU。

## 解题链

进程发起需要等待的磁盘读操作后，会因为数据尚未就绪而进入阻塞态，并挂在对应 I/O 等待关系或等待队列中。

当磁盘读操作完成时，原来的等待条件已经成立：该进程不再因为磁盘 I/O 无法继续推进。

因此操作系统必须解除这项等待关系，把进程从阻塞态转为就绪态，使其重新进入可调度集合：

$$
\text{Blocked}\rightarrow\text{Ready}.
$$

但这并不意味着进程立即运行。后续是否得到 CPU，还要经过调度器选择：

$$
\text{Ready}\xrightarrow{\text{schedule}}\text{Running}.
$$

降低优先级、重新分配用户内存或增加时间片都不是完成一次磁盘读操作后必然发生的动作。

## 选项判断

故选 $\boxed{A}$。

## 校验

从状态定义反查：磁盘读已经完成后，进程已不再缺少其等待的外部事件，所以不能继续保持阻塞态；但此时它仍可能缺 CPU，因此最精确的新状态就是就绪态。

## 压缩

```text
I/O 完成
-> 等待条件消失
-> Blocked → Ready
-> 是否 Ready → Running 由调度器决定
```

## 易错边界

- I/O 完成不等于进程立即运行；完成事件负责“解除等待”，调度器负责“分配 CPU”。
- “必做”只保留由事件语义强制产生的状态变化，优先级、时间片和内存策略都不能凭空附加。
