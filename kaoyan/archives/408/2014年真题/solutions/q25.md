# 408-2014-Q25

> 原题：[[../2014 年全国硕士研究生招生考试#25|Q25]]

## 模型锚点

- 主题：OS01/02｜用户态与内核态的权限边界。
- 题目信号：题目要求判断哪条指令不能在用户态执行。
- 第一动作：不要按“这条指令是不是和操作系统有关”判断，而要看它是否会直接修改全局机器控制状态、破坏隔离或影响其他执行流。

## 解题链

用户态可以执行普通计算、跳转、栈操作，也可以通过受控的陷入指令主动请求内核服务。

`trap` 指令本身就是从用户态进入内核受控入口的一种机制，因此它必须能够由用户程序触发；否则用户程序无法通过这种方式发起系统调用。

跳转和压栈属于普通程序控制与数据操作，也可以在用户态执行。

关中断则会直接改变 CPU 是否接受可屏蔽中断的控制状态。如果普通用户程序可以随意关中断，就可能阻止时钟中断和设备中断，使操作系统失去抢占、计时和设备响应能力，因此这类指令属于特权指令，只能在内核态执行。

## 选项判断

故选 $\boxed{D}$。

## 校验

用保护边界反查：如果用户程序能执行“关中断”，它就能阻止时钟中断，进而长期霸占 CPU。这与操作系统必须控制处理机的基本保护目标冲突，因此 D 必须是特权操作。

## 压缩

```text
判断用户态能否执行
-> 看指令是否直接改变全局控制/保护状态
-> 普通计算与受控陷入可以
-> 关中断会破坏 OS 控制权，因此必须特权
```

## 易错边界

- “会进入内核”不等于“用户态不能执行”。`trap/syscall` 的设计目的就是让用户态通过受控入口请求内核服务。
- 特权指令的判据是其副作用是否需要被保护，而不是名字是否“像系统指令”。
