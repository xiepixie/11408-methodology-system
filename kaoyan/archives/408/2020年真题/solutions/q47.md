# 408-2020-Q47

## Model Anchor

- Topic：重叠私网地址下的 NAT / 端口映射与逐跳 IP 头状态变化。
- 题目信号：两个 LAN 都使用 `192.168.1.x`；Web 服务器与 H2 甚至都使用 `192.168.1.2`，但分别位于两个 NAT 域。
- 第一动作：不要只盯 IP 字面值；先给每个地址加上 **Scope/Owner**，再沿路径逐个检查在哪个 NAT 边界改 source、在哪个边界改 destination。

## Problem Representation

题图中的关键对象可以压缩为：

```text
left private LAN                         right private LAN
Web = 192.168.1.2                       H2 = 192.168.1.2
GW  = R2 192.168.1.1                   GW = R3 192.168.1.1
        |                                       |
R2 outside = 203.10.2.2/30             R3 outside = 203.10.2.6/30
        \                                       /
                         R1 / Internet-side routing
```

虽然 Web 和 H2 的私网地址都写成 `192.168.1.2`，但它们位于**不同私有地址域**，不能靠普通路由器用该地址直接区分。跨域通信必须借助 NAT 后的公网身份。

Web 使用默认 HTTP 端口：

$$\boxed{80}.$$

## Decision Points

### 1. 谁需要稳定的公网入口？

H2/H3 是主动发起连接的客户端，R3 可为其动态做源 NAT。

Web 服务器是被外部主动访问的一端，因此 R2 必须提供一个稳定的公网 `<IP,port>` 到私网 `<IP,port>` 映射，即静态 NAT / 端口转发。

### 2. NAT 不会在每台路由器都改同一字段

- 从 H2 私网出站经过 R3：改变的是**源地址**（SNAT）。
- 到达 Web 所在 R2 的公网入口：改变的是**目的地址**（DNAT/port forwarding）。
- 中间普通路由器 R1 只依据目的 IP 转发，不做这两端私网之间的地址解释。

## Solution Chain

### （1）需要进行什么配置？

在 R2 上为 Web 服务器配置静态 NAT / 端口映射：

```text
外网：203.10.2.2 : 80
          |
          v
内网：192.168.1.2 : 80
```

即

$$
\boxed{
203.10.2.2:80
\longleftrightarrow
192.168.1.2:80
}.
$$

这样 H2/H3 不需要知道 Web 的重叠私网地址，而是访问 R2 暴露的公网服务端点 `203.10.2.2:80`。

R3 对 H2/H3 的主动外出连接进行源 NAT，使右侧私网地址可在公网侧被唯一识别。

### （2）数据报 P 的源/目的 IP 如何变化？

#### H2 刚发送 P

H2 要访问的是 R2 对外暴露的 Web 服务，因此：

```text
src = 192.168.1.2    // H2 in right LAN
dst = 203.10.2.2     // R2 public Web endpoint
```

即

$$\boxed{192.168.1.2\to203.10.2.2}.$$

注意：H2 绝不能把目的地址直接写成 `192.168.1.2`。在 H2 自己的 LAN 语义中，这个地址就是它自己；重叠私网地址只有跨 NAT 域后才能被重新解释。

#### 经过 R3 转发后

R3 是右侧 LAN 的 NAT 边界。出站时执行 SNAT，把 H2 的私网源地址替换为 R3 的公网地址：

```text
src = 203.10.2.6
dst = 203.10.2.2
```

所以

$$\boxed{203.10.2.6\to203.10.2.2}.$$

目的地址尚未改变，因为数据报仍需要在公网侧被路由到 R2。

#### 经过 R2 转发后

R2 收到目的为 `203.10.2.2:80` 的流量，命中静态 NAT 表：

```text
203.10.2.2:80 -> 192.168.1.2:80
```

因此它执行 DNAT，将数据报送入左侧 LAN：

```text
src = 203.10.2.6
dst = 192.168.1.2    // Web server in left LAN
```

即

$$\boxed{203.10.2.6\to192.168.1.2}.$$

整个正向路径的 IP 地址状态链为：

```text
H2 before R3:
192.168.1.2  -> 203.10.2.2

R3 after SNAT:
203.10.2.6   -> 203.10.2.2

R2 after DNAT:
203.10.2.6   -> 192.168.1.2
```

## Verification

### Scope 验证

起点和终点都出现 `192.168.1.2` 并不矛盾：

```text
right-LAN 192.168.1.2 = H2
left-LAN  192.168.1.2 = Web
```

它们只有在各自私网 scope 内才唯一。公网中间路径使用 `203.10.2.6` 和 `203.10.2.2`，从而消除歧义。

### 反向流验证

Web 返回响应时，R2 会把 Web 的私网源端点反向翻译成 `203.10.2.2:80`；数据到达 R3 后，R3 再依据此前建立的 NAT 状态把目的端点反向还原成 H2。正反两条翻译链能够闭合，说明上述配置具有双向一致性。

## Compression

```text
same RFC1918 addresses in two LANs
-> identity must include NAT scope

publish server:
R2 static DNAT/PAT
203.10.2.2:80 -> 192.168.1.2:80

packet H2 -> Web:
192.168.1.2 -> 203.10.2.2
--R3 SNAT-->
203.10.2.6  -> 203.10.2.2
--R2 DNAT-->
203.10.2.6  -> 192.168.1.2
```

## 易错边界

- NAT 题最危险的是只看地址字符串，不看地址属于哪个网络域；本题两个 `192.168.1.2` 就是专门设计的陷阱。
- 客户端主动出站通常需要源 NAT；服务器被外部主动访问需要稳定的目的 NAT/端口映射。
- 普通路由转发不会任意改变 IP 源/目的地址；地址改变发生在明确的 NAT Owner 上。
- 本题只问 IP 地址；真实 PAT 还要维护传输层端口及连接状态，不能把“IP 映射”误认为完整 NAT 状态。
