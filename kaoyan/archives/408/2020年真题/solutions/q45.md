# 408-2020-Q45

## Model Anchor

- Topic：由偏序约束合成信号量同步。
- 题目信号：`C` 等待 `A,B` 两个前驱；`E` 等待 `C,D` 两个前驱；没有共享临界资源描述。
- 第一动作：先画 DAG，只编码**同步边**；不要看到多个操作就条件反射地加 mutex。

## Problem Representation

题目要求的 happens-before 关系只有：

```text
A ─┐
   ├─> C ─┐
B ─┘      ├─> E
D ────────┘
```

这是两个“AND-join”：

- C 必须收齐 A、B 两个完成事件；
- E 必须收齐 C、D 两个完成事件。

信号量最自然的解释是**完成事件令牌计数器**。

## Decision Points

Legacy 解法为每条边分别设 4 个二值/计数信号量，逻辑正确；但本题没有要求每条边必须独立命名，因此可以把同一个 join 的多个前驱完成事件汇总到一个计数信号量中，只用 2 个信号量。

## Solution Chain

定义：

```c
semaphore sAB = 0;  // 已完成的 A/B 前驱事件数
semaphore sCD = 0;  // 已完成的 C/D 前驱事件数
```

各操作可写为：

```c
A() {
    /* A */
    signal(sAB);
}

B() {
    /* B */
    signal(sAB);
}

C() {
    wait(sAB);
    wait(sAB);      // 收齐 A、B 两个完成令牌
    /* C */
    signal(sCD);
}

D() {
    /* D */
    signal(sCD);
}

E() {
    wait(sCD);
    wait(sCD);      // 收齐 C、D 两个完成令牌
    /* E */
}
```

所有信号量初值均为 0，因为开始时尚无任何前驱操作完成。

也可以使用 4 个信号量分别表达 `A->C`、`B->C`、`C->E`、`D->E`；该方案更直观但状态变量更多。上面的 2 信号量方案把同一汇合点的完成事件聚合，语义仍然完整。

## Verification

### Safety / 顺序验证

C 要连续成功执行两次 `wait(sAB)`。在 A、B 各执行一次 `signal(sAB)` 前，令牌数不可能达到 2，因此 C 不可能提前执行。

同理，E 必须获得来自 C、D 的两个令牌，因此不可能早于任一前驱。

### Progress 验证

A、B 本身没有前置等待；二者一旦都完成，C 的两个等待都可通过。C 与 D 都完成后，E 的两个等待都可通过，不存在循环等待，因此不会人为制造死锁。

## Compression

```text
partial order first
A,B -> C ; C,D -> E

join = count completion tokens
sAB=0: A/B signal, C waits twice
sCD=0: C/D signal, E waits twice
```

## 易错边界

- 本题是**同步**，不是互斥；没有任何理由增加 `mutex=1`。
- 一个计数信号量可以表示“已经完成多少个同类前驱事件”，不必机械地“一条边一个信号量”。
- 若某前驱可能执行多次，而题目要求按轮次一一配对，就不能直接沿用这个一次性事件聚合模型，必须重新定义令牌生命周期。
