# 408-2020-Q42

## Model Anchor

- Topic：前缀码的结构化表示、译码与合法性检查。
- 题目信号：编码由 0/1 组成，且任一完整编码不能是另一编码的前缀。
- 第一动作：把“前缀关系”从字符串比较改写为树上的“祖先—后代关系”。

## Problem Representation

最自然的数据结构是**二叉 Trie（编码树）**：

```text
root
├─0-> ...
└─1-> ...
```

每条根到终止结点的路径对应一个字符编码。若编码集合具有前缀特性，那么表示字符的终止结点不能是另一个字符终止结点的祖先；在标准编码树中，字符只出现在叶结点。

## Decision Points

1. 译码的状态只有“当前 Trie 结点 + 输入串当前位置”。
2. 每到达一个字符终止结点，就完成一个码字，输出字符并回到根。
3. 检查前缀特性时要同时防两类冲突：
   - **旧码字是新码字前缀**：新编码尚未读完，就遇到已有终止结点；
   - **新码字是旧码字前缀**：新编码读完时，当前位置下面已经存在子树。

## Solution Chain

### （1）适宜的数据结构

使用二叉树 / 二叉 Trie。左分支可代表 0，右分支代表 1；叶结点（或带 `terminal` 标记的结点）保存对应字符。

### （2）译码过程

从根开始逐位读取待译码的 0/1 串：

```text
read 0 -> left child
read 1 -> right child
```

每当到达某个字符的终止结点：

1. 输出该字符；
2. 将当前结点重新置为根；
3. 继续读取后续比特。

由于编码具有前缀特性，到达终止结点时这个码字已经唯一确定，不需要向后试探或回溯。

### （3）判定是否具有前缀特性

可在逐个插入编码、构建 Trie 的同时检查。

设待插入编码为 `C`：

```text
node = root
for each bit in C:
    if node is already terminal:
        reject   // 某个旧编码是 C 的前缀
    follow/create child(bit)

// C 已全部读完
if node is terminal:
    reject       // 重复编码
if node has any child:
    reject       // C 是某个旧编码的前缀
mark node terminal
```

全部编码均能插入而未触发冲突，则编码集具有前缀特性。

## Verification

以 `0` 和 `01` 为例：插入 `01` 时，读完第一位 `0` 就到达已有终止结点，立即发现 `0` 是 `01` 的前缀。

反过来先插 `01` 再插 `0`：`0` 读完时对应结点已有孩子 `1`，说明新码字 `0` 是旧码字 `01` 的前缀。

两种插入顺序都能检测到同一逻辑冲突，说明判据对称且完整。

## Compression

```text
prefix relation
-> ancestor relation in binary Trie

decode:
root --bits--> terminal -> output -> root

validate insert:
terminal before end -> old prefix of new
children at end     -> new prefix of old
```

## 易错边界

- 只检查“插入过程中是否遇到叶结点”不够，还必须检查新编码结束时是否已有后代。
- 前缀码保证**即时可译码**，不是说所有码字长度相同。
- 若使用 `terminal` 标记而非“叶结点=字符”，判定逻辑更一般，也能显式处理重复编码。
