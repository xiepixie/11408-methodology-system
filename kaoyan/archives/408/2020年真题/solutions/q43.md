# 408-2020-Q43

## Model Anchor

- Topic：乘法的 ISA/微体系结构实现层次，以及低 n 位乘积的溢出语义。
- 题目信号：同一个 `x*y` 被放在“无乘法指令 / 迭代乘法器 / 阵列乘法器”三个实现层级中比较。
- 第一动作：先区分 **语言语义、ISA 指令、硬件执行机制** 三层；最后的溢出题再分 signed / unsigned 两套解释。

## Problem Representation

乘法的核心恒等式是“部分积相加”。二进制乘数的每一位决定是否加入一个移位后的被乘数：

```text
if multiplier bit == 1:
    partial_sum += multiplicand << bit_position
```

因此即使 ALU 没有原生乘法功能，只要 ISA 能提供加/减、移位、测试/分支，就可以在软件或微操作层实现乘法。

## Decision Points

1. **没有 MUL 指令**：编译器必须展开为多条普通指令，重复取指/译码/执行。
2. **有迭代 MUL**：对程序员只是一条指令，但硬件内部仍需多轮“检查位—加部分积—移位”。
3. **阵列乘法器**：用更多组合逻辑并行产生/压缩部分积，以硬件面积换更短延迟。
4. **溢出判断**：先算完整 $2n$ 位数学乘积，再问低 n 位能否完整表达该类型结果。

## Solution Chain

### （1）没有乘法指令为什么仍能实现乘法？

因为乘法可分解为移位和加法。例如无符号整数可按乘数各位循环：

```text
result = 0
while y != 0:
    if y & 1: result += x
    x <<= 1
    y >>= 1
```

带符号乘法可在符号处理后使用同类算法，或采用补码乘法算法。因此“ALU 没有乘法功能”并不意味着高级语言不能执行乘法，只意味着需要由软件指令序列实现。

### （2）迭代乘法指令中的控制逻辑做什么？

控制逻辑负责驱动乘法数据通路的**状态机**，典型职责包括：

- 初始化被乘数、乘数、部分积寄存器；
- 检查乘数当前位；
- 决定本轮是否执行加法；
- 控制被乘数/乘数或部分积的移位；
- 维护循环计数；
- 判断乘法完成并提交最终结果。

所以它不是“执行算术”的主体，而是安排 ALU、移位器和寄存器在正确时刻完成正确状态迁移。

### （3）三种实现的执行时间

执行时间最长的是 **① 无乘法指令**。

原因：一个高级语言乘法被展开成很多机器指令，每条指令又经历自己的取指、译码和执行开销。

执行时间最短的是 **③ 阵列乘法器**。

原因：大量部分积运算在专用组合逻辑中并行完成。② 虽然程序只执行一条 MUL，但硬件内部通常仍需多轮迭代，因此位于两者之间。

因此：

$$\boxed{T_1>T_2>T_3\ \text{（典型教材模型）}}.$$

### （4）32 位乘法、返回值与溢出

给定

$$x=2^{31}-1=0x7FFFFFFF,\qquad y=2.$$

二者都为非负数，因此无论按带符号还是无符号解释，完整 64 位数学乘积都是

$$
(2^{31}-1)\times2=2^{32}-2
=\boxed{00000000FFFFFFFE_H}.
$$

#### `umul()`

32 位 `unsigned` 的范围为

$$0\sim2^{32}-1.$$

结果 $2^{32}-2$ 可以表示，所以

$$\boxed{umul()\text{ 不溢出}}.$$

返回低 32 位：

```text
FFFFFFFEH
```

其无符号值就是 $4294967294$。

#### `imul()`

32 位 `int` 范围为

$$-2^{31}\sim2^{31}-1.$$

真实结果 $2^{32}-2$ 远大于 `INT_MAX`，所以

$$\boxed{imul()\text{ 溢出}}.$$

若只保留低 32 位，同一比特串 `FFFFFFFEH` 按补码解释为 $-2$；这不是数学乘积，正是截断溢出的表现。

#### 无符号乘法如何用 2n 位乘积判溢出？

对于 n 位无符号操作数，结果要求落在 $[0,2^n-1]$。因此完整 2n 位乘积的高 n 位必须全 0：

```text
high_n_bits == 0 -> no overflow
high_n_bits != 0 -> overflow
```

本题高 32 位为 `00000000H`，所以无符号不溢出。

## Verification

完整 64 位乘积的高 32 位为 0，因此它确实适合 32 位**无符号**范围；但低 32 位最高位为 1，若按 signed 解码为负数，与两个正数相乘应得到正数的数学语义冲突，因此 signed 必然发生溢出。

这同时说明：**signed/unsigned 乘法得到的低位比特可以相同，但溢出判据不同。**

## Compression

```text
language x*y
-> ISA may expand into shift/add loop
-> iterative MUL = hardware state machine over ALU+shift
-> array multiplier = parallel hardware

full product first:
7FFFFFFF × 2 = 00000000_FFFFFFFE
unsigned: high32=0 -> OK
signed: true value > INT_MAX -> overflow
```

## 易错边界

- “没有乘法指令”不等于“不能做乘法”；ISA 能力与高级语言能力不是一层。
- 阵列乘法器“最快”是在本题的典型硬件模型下讨论，不等于现实所有 CPU 中 MUL 必然单周期。
- 无符号溢出可直接检查高 n 位；带符号乘法不能套同一规则，通常要求高 n 位等于低 n 位符号位的正确符号扩展。
