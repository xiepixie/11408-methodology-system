# 408-2020-Q44

## Model Anchor

- Topic：8 路组相联 Cache 的地址字段、LRU 元数据和 compulsory miss。
- 题目信号：32 位地址、64 B 块、32 KB 数据区、8-way、Write Through、初始 Cache 为空。
- 第一动作：先恢复 Cache Geometry，再处理具体访问；不要先对十六进制地址做零散位运算。

## Problem Representation

数据区大小：

$$32\text{ KB}=32768\text{ B}.$$

块大小 64 B，因此 Cache 行数

$$\frac{32768}{64}=512.$$

8 路组相联，所以组数

$$\frac{512}{8}=64=2^6.$$

于是 32 位主存地址划分为

```text
Tag        Set       Block Offset
20 bits    6 bits    6 bits
```

## Decision Points

1. `Write Through` 决定是否需要 dirty/修改位。
2. 8-way 的 LRU 状态要能区分 8 种相对位置，教材模型按每行 3 bit 记录。
3. 数组扫描题先看起始地址是否块对齐，再按“每块第一次访问 miss”计 compulsory miss。
4. 具体地址访问按 `Tag / Set / Offset` 三字段完成，不把字节偏移混入组号。

## Solution Chain

### （1）Tag、LRU 和修改位

64 B 块需要 6 位块内偏移；64 组需要 6 位组号，因此 Tag 为

$$32-6-6=\boxed{20\text{ bit}}.$$

8 路需要区分 8 个 LRU 次序状态位置，按题目采用的常见实现口径，每行 LRU 字段为

$$\lceil\log_2 8\rceil=\boxed{3\text{ bit}}.$$

采用 Write Through：每次 Cache 写同时更新下一层主存，因此 Cache 不需要依靠 dirty bit 记录“主存是否落后”，故

$$\boxed{\text{无修改位}}.$$

### （2）访问数组 s 的 Cache miss 次数

`s` 起始地址为 `008000C0H`。

低 6 位为 0，因为

$$0xC0=192=3\times64,$$

所以数组恰好从一个 64 B 主存块边界开始。

数组大小：

$$1024\times4\text{ B}=4096\text{ B}.$$

因此共覆盖

$$\frac{4096}{64}=64$$

个主存块。

每个块含

$$64/4=16$$

个 `int` 元素。程序按地址递增顺序访问：

```c
read s[k]
write s[k]
```

Cache 初始为空，所以每个主存块第一次读发生一次 compulsory miss，并把整块装入；随后该块内剩余元素的读写均命中。数组总共只有 64 个块，因此

$$\boxed{64\text{ 次缺失}}.$$

Write Through 只影响命中写时是否同时写主存，不会额外制造这里的读 miss。

### （3）首次读取 `00010003H` 中指令

先按地址字段分解。

块内偏移：

$$00010003_H\bmod64=3,$$

即 Offset=`000011₂`。

组号：地址的第 6～11 位。本地址所在块号为

$$\left\lfloor\frac{0x00010003}{64}\right\rfloor=0x400,$$

因此

$$Set=0x400\bmod64=\boxed{0}.$$

Tag 为高 20 位：

$$\boxed{00010_H}.$$

访问状态机：

```text
CPU gives address 00010003H
-> index set 0
-> compare valid Tag in all 8 ways
-> initial cache empty => all invalid => miss
-> fetch memory block 00010000H ~ 0001003FH
-> place it into any invalid way of set 0
-> write Tag=00010H, Valid=1
-> update LRU state
-> use offset 03H to select requested instruction byte/content
-> return to CPU
```

因为组内还有空行，不需要真正执行 LRU victim replacement；只需初始化该行的 LRU 状态。

## Verification

数组 s 恰占 4096 B，也就是 64 个 64 B 块。顺序访问若答案不是 64，就意味着要么把写操作错误算成新的块缺失，要么漏掉了“首次访问每个块必 miss”的初始空 Cache 条件。

对于 `00010003H`，块基址必须通过清零低 6 位得到：

$$00010000_H,$$

与上面的 Offset=3 完全闭合。

## Compression

```text
32KB / 64B / 8-way
-> 512 lines -> 64 sets
-> offset 6, set 6, tag 20
-> WT => no dirty

s: aligned 4096B / 64B = 64 blocks
-> 64 compulsory misses

00010003H
-> block 00010000H
-> set 0, tag 00010H, offset 3
-> empty-cache miss -> fill -> retry/return
```

## 易错边界

- Cache “数据区 32 KB”不包括 Tag/LRU 等元数据，计算组数时只用数据区容量。
- Write Through 与 Write Allocate 是两个不同维度；本题缺失计数由读访问已经确定，不需要凭空假设写缺失策略。
- LRU 只有在组满且发生新块冲突时才决定 victim；初始有 invalid line 时无需淘汰有效块。
