# 408-2020-Q31

## Model Anchor

- Topic：目录项、inode 编号与文件身份容量。
- 题目信号：目录项 64 B，其中只有 4 B 保存索引结点号。
- 第一动作：先问“全系统可区分多少个文件对象”的身份 Owner 是谁，而不是被 60 B 文件名字段带偏。

## 解题链

目录项中的文件名只是从名字到文件对象的映射键；真正指向文件控制信息的是 4 B 的索引结点号。

4 B = 32 bit，因此最多可表示

$$2^{32}$$

个不同索引结点编号。文件名虽然最长可达 60 个字符，但它限制的是单个名字的表示空间，并不直接决定文件对象总数上限。

## 选项判断

故选 $\boxed{B}$。

## Verification

不同目录中可以出现相同文件名，所以“可构造多少种文件名”显然不能作为整个文件系统文件数量上限。

## Compression

```text
file identity owner = inode number
4 B inode id -> 32 bits -> 2^32
```

## 易错边界

目录项是 `name -> inode` 映射；文件名空间与 inode 身份空间是不同维度。
