# 408-2019-Q40

## Model Anchor

- Topic：C/S 与 P2P 的通信角色模型。
- 题目信号：问错误项，关键是“客户与客户之间是否按 C/S 角色直接通信”。
- 第一动作：先锁定模型中的 endpoint role，而不是泛化成“网络上的任意两个主机都能通信”。

## 解题链

- P2P 中各结点地位对等，可同时承担资源提供者与请求者，A 正确。
- C/S 模型中，客户通过服务器获得服务；模型本身并不定义“客户与客户直接通信”作为服务路径，因此 B 错误。
- C/S 中通常由客户主动发起请求，服务器被动监听并响应，C 正确。
- 文件分发时 P2P 可以利用多个已获得数据的 peer 并行上传，系统总上传能力随 peer 增加，通常比单服务器瓶颈下的 C/S 更具扩展性，D 正确。

## 选项判断

$$\boxed{B}.$$

## Verification

这里判断的是**应用模型中的角色关系**，不是 IP 层是否允许两个客户主机互发分组。底层可达不等于上层模型把它定义成直接客户通信。

## Compression

```text
C/S service path = client <-> server
not client <-> client
```

## 易错边界

“现实中两个客户端程序也能建立连接”不能用来反驳 C/S 模型定义；一旦其中一方为另一方提供服务，它在那条交互里就承担服务器角色。
