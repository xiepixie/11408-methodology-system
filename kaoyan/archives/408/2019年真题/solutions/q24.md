# 408-2019-Q24

## Model Anchor

- Topic：阻塞进程的唤醒条件。
- 题目信号：问“可能将进程唤醒”的事件，本质是 `Blocked -> Ready` 的触发条件。
- 第一动作：对每个事件问：它是否可能让进程等待的条件变为满足？

## 解题链

I. **I/O 结束**：若进程因等待该 I/O 阻塞，设备完成后中断处理会把它从等待队列移入就绪队列，因此可唤醒。

II. **某进程退出临界区**：若退出时执行 `signal()`/释放互斥资源，可能使等待该资源的阻塞进程条件满足，因此可唤醒。

III. **当前进程时间片用完**：这是 Running → Ready 的抢占事件，不是在解除某个阻塞进程的等待条件，因此本身不是“唤醒”。

## 选项判断

I、II 正确：

$$\boxed{C}.$$

## Verification

统一成状态机即可：

```text
I/O completion / resource release -> wait condition resolved -> Blocked -> Ready
time slice expires              -> Running -> Ready
```

## Compression

```text
wake up = remove waiting condition
I/O done ✓
resource released ✓
time slice expired ✗
```

## 易错边界

`Ready` 不等于 `Running`。唤醒只是恢复调度资格，之后还需调度器 dispatch 才能真正运行。
