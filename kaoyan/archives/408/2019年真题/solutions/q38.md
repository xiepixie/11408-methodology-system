# 408-2019-Q38

## Model Anchor

- Topic：TCP 快速重传的重复 ACK 触发条件。
- 题目信号：`seq=100` 丢失，后续失序段让服务器持续回 `ack_seq=100`。
- 第一动作：建立 ACK 计数账本：第一次 ACK100 是正常累计确认，之后连续 3 个相同 ACK 才构成 three duplicate ACKs。

## 解题链

$t_0$ 时客户端第一次收到 `ack_seq=100`，随后发送 `seq=100` 的数据段，但该段丢失。

服务器之后收到更高序号的失序数据时，仍只能确认“下一个期望字节是 100”，因此反复发送 `ack_seq=100`。

按图中时间顺序：

```text
t1: duplicate ACK #1
t2: duplicate ACK #2
t3: duplicate ACK #3
```

TCP 快速重传在收到第 3 个重复 ACK 时立即重传缺失段，不必等到 $t_4$ 的超时。

## 选项判断

$$\boxed{C}.$$

## Verification

图中特意标出 $t_4$ 为 `seq=100` 超时时刻；若选择 $t_4$ 就等于完全没有利用快速重传机制。

## Compression

```text
lost seq=100
-> 3 duplicate ACK100
-> retransmit at t3
```

## 易错边界

“3 个重复 ACK”不包含最初那个正常 ACK；应从后续重复确认开始计数。
