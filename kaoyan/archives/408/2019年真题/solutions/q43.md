# 408-2019-Q43

## Model Anchor

- Topic：哲学家就餐、资源计数与死锁预防。
- 题目信号：每人必须同时获得“1 个碗 + 左右两根筷子”，要求**尽可能多并发**且**保证不死锁**。
- 第一动作：不要先写 P/V。先画资源依赖：死锁风险来自 n 位哲学家同时各持有一根筷子并等待下一根形成完整环；碗可以被用作 admission gate，限制进入“抢筷子阶段”的哲学家数量。

## Problem Representation

资源分两类：

```text
碗：m 个同类可替代资源
筷子：n 根位置固定的互斥资源 chopstick[i]
```

传统哲学家死锁状态是：

```text
P0 holds C0, waits C1
P1 holds C1, waits C2
...
P(n-1) holds C(n-1), waits C0
```

即所有 n 位哲学家同时进入抢筷子阶段，形成完整环形等待。

因此只要保证**最多 n-1 位哲学家可以同时进入抢筷子阶段**，完整环就不可能形成。

## Decision Points

### 1. 碗信号量初值为什么不是简单的 m？

若 $m<n$，只有 m 人能拿到碗，而 $m\le n-1$，天然破坏全体 n 人同时抢筷子的条件。

若 $m\ge n$，若仍令 `bowl=m`，可能让 n 人全部进入抢筷子阶段，恢复传统死锁风险。因此 admission 数必须封顶为 $n-1$。

所以：

$$\boxed{bowl=\min(m,n-1)}.$$

### 2. 这样是否牺牲“尽可能多同时就餐”？

不会产生额外的实际并发损失。

相邻哲学家不能同时就餐，因此仅由筷子约束，最多同时就餐人数也不超过

$$\left\lfloor\frac n2\right\rfloor.$$

而对 $n\ge3$，有

$$\left\lfloor\frac n2\right\rfloor\le n-1.$$

所以把 admission 上限设为 $n-1$ 只消除死锁状态，并不会把真正可能同时吃饭的人数压到更低。

## Solution Chain

定义：

```c
semaphore bowl = min(m, n - 1);      // 允许进入抢筷子阶段的人数
semaphore chopstick[n];

for (int i = 0; i < n; ++i)
    chopstick[i] = 1;                 // 每根筷子仅 1 个实例
```

哲学家 i：

```c
void philosopher(int i)
{
    while (true) {
        think();

        P(bowl);                      // 先取得进入资源竞争区的资格/一个碗
        P(chopstick[i]);              // 左筷子
        P(chopstick[(i + 1) % n]);    // 右筷子

        eat();

        V(chopstick[(i + 1) % n]);
        V(chopstick[i]);
        V(bowl);
    }
}
```

## Verification

### Safety：为什么不死锁？

假设发生筷子环形死锁，则必须有 n 位哲学家分别占有一根筷子并等待下一根，即所有 n 人都已通过 `P(bowl)`。

但：

$$bowl_{initial}=\min(m,n-1)\le n-1,$$

因此任意时刻最多只有 n-1 位哲学家能进入抢筷子阶段，与“n 人全部形成完整环”矛盾。

所以不存在这种环形等待死锁。

### Progress：是否仍有人能吃到？

因为至少有一位哲学家不在竞争环内，筷子等待图无法闭合成整环；至少存在一处断口，使某个已获准哲学家最终可以取得第二根筷子、进餐并释放资源，系统能够继续推进。

## Compression

```text
philosopher deadlock = all n enter fork-acquisition cycle
-> use bowls as admission gate
-> bowl = min(m, n-1)
-> at most n-1 contenders
-> circular wait cannot close
```

## 易错边界

- legacy 文字曾出现“让碗资源量等于 -1”的明显笔误，正确值是 $n-1$；代码中的 `min(m,n-1)` 才是逻辑 Owner。
- 仅把每根筷子设为互斥信号量不能防死锁；那只能保证 Safety 中的“单根筷子不被两人同时占用”，不能打破 circular wait。
- 本题要求防死锁，不等同于严格证明无饥饿；公平性还取决于信号量/调度实现。
