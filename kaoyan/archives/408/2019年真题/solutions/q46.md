# 408-2019-Q46

## Model Anchor

- Topic：分页地址不变量与指令 Cache 地址投影。
- 题目信号：上一题给的是**虚拟指令地址**，本题又问物理主存 Cache 组号。
- 第一动作：先区分 `VA page` 与 `PA cache fields`；唯一可以直接跨虚实地址复用的是**页内偏移低 12 位**。

## Problem Representation

已知：

```text
VA(push) = 00401000H
VA(call) = 00401025H
VA(ret)  = 0040104AH
page size = 4 KB = 2^12 B
I-Cache: 64 lines, 4-way
block size = 64 B = 2^6 B
```

Cache 共有：

$$\frac{64}{4}=16=2^4$$

组，因此物理地址字段为：

```text
Tag 22 bit | Set 4 bit | Block Offset 6 bit
 31..10       9..6          5..0
```

## Decision Points

1. 判断两条指令是否同页，只比较虚拟地址高 20 位。
2. Cache 的 tag/set 来自**物理地址**；不能把整个虚拟地址直接拿来当物理地址。
3. 但页大小 4 KB，因此 VA→PA 翻译保持低 12 位不变。
4. Cache 的 `set+offset` 一共只占低 $4+6=10$ 位，完全包含在 12 位页内偏移中，所以即使不知道页框号，也能唯一知道组号。

## Solution Chain

### 1. `push` 与 `ret` 是否在同一页？

4 KB 页大小意味着低 12 位为页内偏移，高 20 位为虚页号。

```text
00401000H -> VPN = 00401H, offset = 000H
0040104AH -> VPN = 00401H, offset = 04AH
```

两者虚页号相同，因此：

$$\boxed{\text{在同一虚拟页中}}.$$

而且地址差只有：

$$0040104A_H-00401000_H=4A_H<1000_H,$$

且没有跨越 4 KB 边界。

### 2. Cache 地址字段

块大小 64 B：

$$\log_2 64=6$$

位块内地址。

64 行、4 路：

$$64/4=16$$

组，需要 4 位组号。

因此 32 位主存物理地址：

$$\boxed{A[5:0]\text{：块内地址}}$$

$$\boxed{A[9:6]\text{：Cache 组号}}$$

$$\boxed{A[31:10]\text{：Tag，共22位}}.$$

### 3. 第 16 行 `call` 只可能在哪组命中？

`call` 的虚拟地址是：

$$\mathtt{00401025_H}.$$

页内偏移为低 12 位：

$$\mathtt{025_H}=0000\ 0010\ 0101_2.$$

分页翻译不会改变这 12 位，所以对应物理地址的低 12 位也完全相同。

Cache 组号取物理地址位 $A[9:6]$。对 `025H`：

```text
0000 0010 0101
^^^^          A[11:8]
     ^^^^     A[9:6] = 0000
         ^^^^^^ A[5:0]
```

因此组号：

$$\boxed{0}.$$

所以读取第 16 行 `call` 时，只可能在指令 Cache 的第 0 组中命中。

## Verification

### 页边界验证

4 KB 页的地址范围以 `...000H` 到 `...FFFH` 为一页：

```text
00401000H ~ 00401FFFH
```

`push` 与 `ret` 均落在该范围。

### Set Index 独立于页框号验证

本题 Cache 索引只需要低 10 位，而页内偏移有 12 位：

$$10<12.$$

所以页框号只影响更高的 tag，不可能改变 set=0。这就是“不知道物理页框仍能确定组号”的根本原因。

## Compression

```text
4KB page -> low12 unchanged across VA->PA
00401000h and 0040104Ah -> same VPN 00401h

64 lines / 4-way = 16 sets -> 4 set bits
64B block -> 6 offset bits
PA = tag[31:10] | set[9:6] | off[5:0]

call VA low12 = 025h
-> PA low12 = 025h
-> bits9:6 = 0000
-> set 0
```

## 易错边界

- Cache 本质上按主存**物理地址**查找；本题能从 VA 直接算 set，是因为 set 位完全落在页内偏移中，而不是因为 VA=PA。
- 若 Cache 更大、组号需要使用超过页内偏移的高位，则仅凭虚拟地址低位不能这样直接确定物理 set。
