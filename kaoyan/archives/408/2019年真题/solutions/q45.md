# 408-2019-Q45

## Model Anchor

- Topic：递归调用、机器指令边界、PC 相对寻址、字节序和有符号溢出。
- 题目信号：同一题从 C 递归语义一路下钻到 `call/jle/jmp/ret/imul` 机器级行为。
- 第一动作：建立三层账本：**源程序调用栈 → 指令地址/控制流 → 位级结果与 OF**。每一问只在自己的语义层计算，再通过接口连接。

## Problem Representation

核心代码：

```text
0040101C  7E 17          jle  00401035
00401025  E8 D6 FF FF FF call 00401000
00401030  0F AF C1       imul eax,ecx
00401033  EB 05          jmp  0040103A
0040104A  C3             ret
```

`call` 的 PC 相对位移以**下一条指令地址**为基准；`imul` 只把低 32 位写回 eax，但硬件内部可依据完整乘积判断有符号溢出。

## Decision Points

1. “调用 f1 多少次”包括最初的 `f1(10)`，而递归 `call` 指令只发生 9 次。
2. 条件转移与必然改变 PC 的控制流指令分开判断。
3. 相对寻址固定使用 `target - next_PC`，不能用当前指令首地址。
4. 大小端由机器码多字节立即数/位移字段的内存顺序判断。
5. C 的返回类型决定可表示范围；低 32 位回绕不等于数学结果正确。
6. signed multiply 的 OF 判断看“完整乘积是否能由低 32 位符号扩展恢复”。

## Solution Chain

### (1) f(10) 的调用次数与递归指令

调用链为：

```text
f1(10)
-> f1(9)
-> f1(8)
...
-> f1(2)
-> f1(1)
```

因此一共进入 `f1`：

$$\boxed{10\text{ 次}}.$$

其中最初一次由外部调用者发起；函数内部真正执行递归调用的是第 16 行：

```asm
call f1 (00401000)
```

它在 `n=10,9,...,2` 时共执行 9 次。

### (2) 条件转移与必然跳转指令

条件转移：

```asm
12: jle 00401035
```

是否跳转取决于前一条 `cmp` 设置的标志。

一定改变正常顺序执行 PC 的指令包括：

```text
16: call   -> 转到被调函数，同时保存返回地址
20: jmp    -> 无条件跳转
30: ret    -> 从栈中恢复返回地址并跳转
```

故答案为：

$$\boxed{jle\text{ 是条件转移；}call,jmp,ret\text{ 一定发生控制转移}}.$$

### (3) 第 17 行地址、call 位移与字节序

第 16 行 `call` 从 `00401025H` 开始，机器码：

```text
E8 D6 FF FF FF
```

共 5 B，因此下一条指令地址：

$$\boxed{0040102A_H}.$$

PC 相对寻址使用：

$$target=nextPC+disp.$$

所以

$$disp=00401000_H-0040102A_H=-2A_H.$$

32 位补码为：

$$\boxed{FFFFFFD6_H}.$$

机器中 4 个字节却按：

```text
D6 FF FF FF
```

存放，最低有效字节 `D6` 位于低地址，因此 M 采用：

$$\boxed{\text{小端方式}}.$$

### (4) 为什么 f1(13) 错？如何修复？

数学值：

$$13!=6227020800.$$

32 位 signed int 最大值只有：

$$2^{31}-1=2147483647.$$

所以数学结果超出 `int` 可表示范围，低 32 位留下：

$$6227020800\bmod2^{32}=1932053504,$$

正是题给返回值。

要得到正确结果，应让**递归返回值和乘法表达式都进入足够宽的整数类型**，例如：

```c
long long f1(int n)
{
    if (n > 1)
        return (long long)n * f1(n - 1);
    return 1LL;
}
```

此时 64 位 `long long` 足以表示 13!。

### (5) `imul` 的 OF 条件与溢出异常

设完整 64 位有符号乘积为：

```text
HIGH32 | LOW32
```

若只保留低 32 位，**无溢出**当且仅当完整 64 位结果恰好等于 `LOW32` 的符号扩展：

```text
LOW32[31] = 0 -> HIGH32 必须全 0
LOW32[31] = 1 -> HIGH32 必须全 1
```

否则：

$$\boxed{OF=1}.$$

等价地：高 32 位不是低 32 位符号位的 32 次复制时发生有符号溢出。

若希望 OF=1 时进入溢出异常处理，编译器可在 `imul` 后加入检查 OF 的溢出自陷指令，例如 x86 的：

```asm
into
```

其语义是 OF=1 时触发 overflow exception。

## Verification

### call 位移回代

$$0040102A_H+FFFFFFD6_H=00401000_H,$$

目标地址闭合。

### 13! 回绕校验

$$1932053504+2^{32}=6227020800.$$

说明返回值正是完整结果被截到低 32 位后的数值，不是递归逻辑错误。

### OF 语义校验

若低 32 位为负数位模式而高 32 位全 0，则完整 64 位结果显然不可能由低 32 位有符号值符号扩展得到，因此一定溢出；反向同理。

## Compression

```text
f1(10): 10 invocations, recursive call=line16
conditional jump: jle
always control-transfer: call/jmp/ret
nextPC = 40102Ah
disp = 401000h - 40102Ah = FFFFFFD6h
D6 FF FF FF -> little endian
13! > INT_MAX -> 32-bit overflow
signed mul OF -> high half != sign extension of low half
OF trap -> INTO
```

## 易错边界

- PC-relative displacement 以**下一条指令**为基准，这是机器码题最常见错点。
- 只把函数返回类型写成更宽类型还不够时，应确保参与计算的表达式也按宽类型执行；这里递归返回 `long long` 后，`n*f1(...)` 会自动提升，显式强转更清晰。
- OF 是有符号可表示性，不等于 CF，也不等于“高 32 位只要非 0 就溢出”；负数合法结果的高 32 位应全 1。
