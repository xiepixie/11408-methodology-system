# 408-2019-Q39

## Model Anchor

- Topic：TCP 三次握手的 SEQ/ACK 账本。
- 题目信号：给双方初始序列号 ISN，问第三次握手的确认号。
- 第一动作：牢记 SYN 虽不携带应用数据，但**消耗一个序号**。

## 解题链

甲主动连接：

```text
1) 甲 -> 乙: SYN, seq=2018
2) 乙 -> 甲: SYN+ACK, seq=2046, ack=2019
3) 甲 -> 乙: ACK, ack=?
```

乙的 SYN 占用序号 2046，因此甲下一步期望乙发送的序号为

$$2046+1=2047.$$

所以第三次握手 ACK 段中的确认序列号为 2047。

## 选项判断

$$\boxed{D}.$$

## Verification

ACK 的语义始终是“我下一步期望收到的序号”，不是“我刚刚收到的序号”。因此必须对乙的 SYN 序号加 1。

## Compression

```text
server ISN = 2046
SYN consumes 1 sequence number
-> ACK = 2047
```

## 易错边界

SYN 和 FIN 都各占 1 个序号；纯 ACK 不消耗新的数据序号。
