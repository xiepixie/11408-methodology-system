# 408-2019-Q17

## Model Anchor

- Topic：一条指令的数据依赖路径与硬件 Owner。
- 题目信号：`R[r2] ← R[r1] + M[R[r0]]`，并限定“取数及执行过程中”。
- 第一动作：把表达式拆成两个源操作数和一个运算，再为每个状态找实际硬件 Owner。

## 解题链

执行该指令至少要完成：

```text
R[r1]        <- 从 GPRs 读取
R[r0]        <- 从 GPRs 读取
M[R[r0]]     <- 访问 Memory
两操作数相加 <- ALU
结果写 R[r2] <- GPRs
```

因此 GPRs、ALU、Memory 都属于实际数据路径。

指令译码器 ID 用于识别当前指令及产生/协助产生控制信息，但题目限定的是**取数及执行过程**，不是整个取指译码生命周期，所以不计入该阶段需要的部件集合。

## 选项判断

I、II、III 正确，故

$$\boxed{B}.$$

## Verification

直接从右侧表达式做 data-flow tracing：两个 `R[...]` 一定触发寄存器读取，`M[...]` 一定触发主存读取，`+` 一定需要 ALU。

## Compression

```text
R[r1] + M[R[r0]]
-> GPR + Memory + ALU
```

## 易错边界

题目问“某阶段用到什么”，不要把 CPU 整条指令生命周期中所有部件都塞进答案。
