# 408-2019-Q25

## Model Anchor

- Topic：系统调用的边界与内核服务契约。
- 题目信号：四个陈述分别涉及执行模式、设备隔离、跨 OS 一致性和接口定义。
- 第一动作：先把“应用层 API”与“操作系统系统调用接口”分开。

## 解题链

I. 系统调用服务程序属于内核代码，执行时 CPU 在内核态，正确。

II. 用户程序不能任意直接执行特权 I/O 操作，而是通过系统调用请求内核代为访问设备，正确。

III. 不同操作系统的系统调用集合、编号和 ABI 并不统一；即使 POSIX 等规范能统一部分上层 API，也不等于底层系统调用接口完全相同，错误。

IV. 系统调用正是内核向用户程序暴露受控服务的基本接口，正确。

## 选项判断

I、II、IV 正确：

$$\boxed{C}.$$

## Verification

Linux 与 Windows 的系统调用 ABI 就不同，足以否定“不同操作系统提供统一系统调用接口”的绝对表述。

## Compression

```text
syscall
-> user/kernel boundary
-> controlled kernel service
-> OS-specific ABI
```

## 易错边界

库函数/API 可能为了可移植性长得相似，但它们下面调用的系统调用并不因此统一。
