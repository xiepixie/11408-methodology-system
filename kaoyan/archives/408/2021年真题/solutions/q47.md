# 408-2021-Q47

## Model Anchor

- Topic：DNS、ARP、交换机自学习与 Web 访问前置事件链。
- 题目信号：`t0` 时 H1 ARP 表和交换表都为空，直到 `t1` 交换机第一次收到封装 HTTP 请求的以太网帧。
- 第一动作：先按时间线恢复“HTTP 之前必须发生哪些事件”，并且每收到一帧都问一次：**S 从源 MAC 学到了什么？H2 是否会因为广播/未知单播而看到它？**

## Problem Representation

从图中可得本地 LAN 上的关键实体：

```text
H1:  192.168.1.2/25    MAC ...-cc    -> S port 4
DNS: 192.168.1.126/25  MAC ...-bb    -> S port 1
R:   192.168.1.1/25    MAC ...-aa    -> S port 2
H2:  192.168.1.3/25    MAC ...-dd    -> S port 3
```

H1 用域名访问 Internet 上的 Web 服务器，因此 HTTP 请求真正发出前至少经历：

```text
ARP for DNS
-> DNS query / reply
-> ARP for default gateway
-> TCP 3-way handshake
-> HTTP request
```

## Decision Points

1. DNS 服务器与 H1 同一子网，所以 DNS 查询前要先解析 DNS 服务器的 MAC。
2. Web 服务器在 Internet，H1 不需要 ARP Web 服务器，而是 ARP 默认网关 R。
3. 交换机只从**收到帧的源 MAC**学习端口；不会因为“知道 H2 存在”就自动拥有 H2 表项。
4. H2 最少只会收到被交换机泛洪的广播帧；已知目的 MAC 的单播不会发到 H2 端口。

## Solution Chain

### (1) 除 HTTP 外还运行什么应用层协议？如何封装？

H1 只有域名 `www.abc.com`，在发送 HTTP 请求前必须先得到 Web 服务器 IP 地址，因此还需要运行

$$\boxed{DNS}.$$

本题常规 DNS 查询使用 UDP，其逐层封装为

```text
DNS message
-> UDP datagram
-> IP datagram
-> Ethernet frame
```

即

$$\boxed{DNS\to UDP\to IP\to Ethernet}.$$

### (2) $t_1$ 时刻 S 的交换表

#### 第一次 ARP：解析 DNS 服务器 MAC

H1 发 ARP Request，源 MAC 为 `...-cc`，S 从端口 4 收到后学习：

```text
...-cc -> 4
```

DNS 服务器回 ARP Reply，源 MAC 为 `...-bb`，S 从端口 1 收到后学习：

```text
...-bb -> 1
```

随后 DNS 查询和 DNS 响应都是已知目的的单播，不引入新的源主机。

#### 第二次 ARP：解析默认网关 MAC

解析出 Web 服务器位于外网后，H1 需要把 IP 数据报交给默认网关，因此广播 ARP Request 查询 R 的 MAC。R 回 ARP Reply，S 从端口 2 学到：

```text
...-aa -> 2
```

H2 在整个过程中只接收广播，没有发送相关帧，因此 S 不会学到 `...-dd -> 3`。

所以 $t_1$ 时交换表至少为：

| MAC 地址 | 端口 |
|---|---:|
| `00-11-22-33-44-cc` | 4 |
| `00-11-22-33-44-bb` | 1 |
| `00-11-22-33-44-aa` | 2 |

### (3) H2 至少收到几个相关帧？

H2 与 H1 同处交换式以太网广播域。至少会看到两次 ARP Request：

1. H1 查询本地域名服务器 MAC；
2. H1 查询默认网关 R 的 MAC。

ARP Request 以以太网广播发送，所以这两个帧的目的 MAC 均为

$$\boxed{FF-FF-FF-FF-FF-FF}.$$

因此 H2 至少接收到

$$\boxed{2\text{ 个帧}}.$$

二者均为封装 ARP 请求报文的以太网广播帧。

## Verification

按帧事件审计交换机学习状态：

```text
H1 ARP req       -> learn cc@4, flood -> H2 sees #1
DNS ARP reply    -> learn bb@1, unicast to H1
DNS query/reply  -> known unicast
H1 ARP req for R -> cc@4 refreshed, flood -> H2 sees #2
R ARP reply      -> learn aa@2, unicast to H1
TCP handshake    -> known unicast via R
HTTP request     -> t1
```

在 `t1` 前没有任何来自 H2 的帧，因此交换表中没有 H2 的 MAC；同时也没有第三个必然广播事件。

## Compression

```text
name -> DNS first
DNS same LAN -> ARP DNS
remote Web -> ARP gateway
switch learns source MAC only

S table at t1:
cc->4, bb->1, aa->2

H2 sees only 2 mandatory broadcasts:
ARP(DNS) + ARP(gateway)
dst MAC = FF:FF:FF:FF:FF:FF
```

## 易错边界

- Legacy 把数据链路层封装写成“CSMA/CD 帧”不够准确：CSMA/CD 是共享以太网的介质访问控制机制，本题封装对象应称为**以太网帧**。
- DNS 查询并不广播给所有主机；完成 ARP 后，H1 到本地域名服务器的 DNS 报文是单播。
- 访问外网服务器时，ARP 的目标是**下一跳默认网关**，不是远端 Web 服务器。
