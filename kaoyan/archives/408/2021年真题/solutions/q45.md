# 408-2021-Q45

## Model Anchor

- Topic：信号量原子性、关中断临界区与忙等边界。
- 题目信号：用开/关中断保护 `wait/signal`，且 `wait` 内可能等待 `S>0`。
- 第一动作：先写不变量：对 S 的“检查 + 修改”必须不可交错；然后检查保护手段会不会反过来阻止使条件成立的事件发生。

## Problem Representation

`wait` 的关键复合动作是：

```text
observe S>0
-> claim one permit
-> S = S-1
```

如果两个执行流都能在检查后、减 1 前被交错，就可能同时取得同一个许可。

但若 `S<=0`，等待方又必须允许其他执行流运行 `signal(S)`，否则条件永远不会改变。

因此存在两个同时需要满足的约束：

```text
Safety: check/decrement must be atomic
Progress: waiting must not permanently block signal
```

## Decision Points

1. 方法 1 是否把中断关闭跨过整个等待循环？若是，会破坏 Progress。
2. 方法 2 在重新检查 S 前是否再次关中断？若是，`check -> decrement` 仍保持互斥。
3. 用户态是否有权限直接执行开/关中断指令？

## Solution Chain

### (1) 为什么访问 S 必须互斥

S 是多个进程/线程共享的同步状态。以 `wait` 为例，如果两个执行流同时读到 `S=1`，随后都执行 `S=S-1`，就可能让两个执行流都认为自己获得了唯一许可，破坏信号量语义。

因此对 S 的检查和更新必须构成原子临界区；`signal` 的更新同样不能与之任意交错。

### (2) 方法 1 与方法 2

#### 方法 1：错误

```c
关中断;
while (S <= 0);
...
```

若进入循环时 `S<=0`，当前 CPU 一直保持关中断并忙等。需要运行 `signal(S)` 的其他执行流可能因此无法获得执行机会，S 无法增加，形成无限等待。

所以方法 1 破坏了进展性。

#### 方法 2：在题设单处理机模型下正确

当发现 `S<=0` 时：

```c
开中断;
关中断;
```

短暂开放中断，使其他进程/中断处理能够推进并可能执行 `signal`。当前执行流再次进入检查前重新关中断，因此一旦观察到 `S>0`，直到执行 `S=S-1` 之间不会被本机中断打断，仍保持互斥。

故方法 2 在本题模型下正确。

### (3) 用户程序能否这样实现互斥

不能。

开中断/关中断会直接改变 CPU 的中断控制状态，属于特权操作，只允许内核态执行。用户程序不能靠执行这些指令自行屏蔽系统中断，否则会破坏操作系统对 CPU 和设备事件的控制。

## Verification

用 `S=0` 检查 liveness：

- 方法 1：关中断后永久自旋，`signal` 无机会推进；
- 方法 2：等待循环会暂时开中断，系统仍存在让 S 变化的执行机会。

再用 `S=1` 检查 safety：方法 2 从检查到 `S--` 期间保持关中断，单处理机上不会被另一执行流插入该临界段。

## Compression

```text
semaphore invariant:
check + update must be atomic
but wait(S<=0) must allow signal to run

method1: disable across spin -> no progress -> wrong
method2: temporarily enable while waiting, disable before recheck -> correct in uniprocessor model
user code: cli/sti are privileged -> cannot use
```

## 易错边界

- “互斥正确”还不够，还要检查进展性；把等待循环整个包在关中断区里会把唤醒自己的路径也封死。
- 关本 CPU 中断只适合题设的单处理机模型；在多处理器上，它不能阻止其他 CPU 并发访问同一 S，需要真正的跨核原子同步原语。
