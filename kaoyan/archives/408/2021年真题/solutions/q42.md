# 408-2021-Q42

## Model Anchor

- Topic：比较计数排序、排名构造与稳定性。
- 题目信号：每一对元素都比较一次，`count[i]` 最终直接作为输出下标。
- 第一动作：先解释 `count` 的语义：它是在给每个元素构造一个**唯一排名**，再判断相等元素的 tie-breaking 是否保持原顺序。

## Problem Representation

对任意一对 `i<j`：

```c
if (a[i] < a[j]) count[j]++;
else             count[i]++;
```

较大的元素排名值加 1，因此 `count[k]` 最终等价于元素 `a[k]` 在升序结果中的位置；相等元素则由 `else` 分支把**前面的元素排到后面**，这正是稳定性风险。

## Decision Points

1. 第 (1) 问只要按代码语义求最终 `b`，重复值虽然次序交换，但数值结果看不出来。
2. 比较次数由双循环边界决定，与输入是否有序无关。
3. 稳定性必须专门用两个相等元素检查，不能只看排序后的值序列。

## Solution Chain

### (1) 数组 b

输入

```text
25, -10, 25, 10, 11, 19
```

升序结果为

```text
-10, 10, 11, 19, 25, 25
```

因此

```c
b[6] = {-10, 10, 11, 19, 25, 25};
```

### (2) 比较次数

每一对下标 `i<j` 恰比较一次：

$$
(n-1)+(n-2)+\cdots+1
=\boxed{\frac{n(n-1)}2}.
$$

### (3) 稳定性与修改

原算法**不稳定**。

若 `a[i]==a[j]` 且 `i<j`，原条件 `a[i] < a[j]` 为假，于是执行 `count[i]++`，导致前面的相等元素获得更大的输出下标，排到后面的相等元素之后。

要保持稳定性，应让后出现的相等元素排名更大：

```c
if (a[i] <= a[j]) count[j]++;
else               count[i]++;
```

这样当 `a[i]==a[j]` 时，`j` 的位置在 `i` 之后，保留原相对次序。

## Verification

用两个带身份的相等元素 `25a,25b`（`a` 在前）检查：

- 原代码：相等时给 `25a` 的 count 加 1，可能得到 `25b,25a`；
- 修改后：给 `25b` 的 count 加 1，得到 `25a,25b`。

稳定性条件因此闭合。

## Compression

```text
pairwise compare -> count = rank
all pairs -> n(n-1)/2
original tie: earlier equal gets larger rank -> unstable
fix < to <= -> later equal gets larger rank -> stable
```

## 易错边界

排序结果中的两个 `25` 数值相同，所以仅观察 `b` 无法判断稳定性；必须给相等元素附加原始身份再检查相对次序。
