# 408-2021-Q44

## Model Anchor

- Topic：虚拟地址分解、组相联 TLB 与 LRU。
- 题目信号：30 位 VA、4 KB page、2-way TLB、8 sets、给 VPN 访问序列。
- 第一动作：固定 `VA -> VPN + offset -> TLB tag + set` 三层字段，再模拟每个 set 的局部 LRU；TLB replacement 不跨组发生。

## Problem Representation

页大小

$$4KB=2^{12}B,$$

所以 30 位虚拟地址结构为

```text
A29 ........ A12 | A11 ........ A0
      VPN(18)     | offset(12)
```

TLB 共 8 组：

$$8=2^3,$$

因此 VPN 低 3 位选组，其余 15 位为 TLB tag。

## Decision Points

1. 组号从 VPN 中取，不从页内偏移中取。
2. 2-way 只表示每组能同时保留两个表项；LRU 也只在发生冲突的该组内部维护。
3. 访问命中会刷新 LRU 次序，不能只记录首次装入顺序。
4. VA 位数增加而物理地址/页大小/组数不变时，增加的是 VPN 高位，也就是 TLB tag。

## Solution Chain

### (1) VPN 与页内地址

$$\boxed{VPN=A_{29}\sim A_{12}},$$

共 18 位；

$$\boxed{offset=A_{11}\sim A_0},$$

共 12 位。

### (2) TLB tag 与组号

8 组需要 3 位组号，因此

$$\boxed{set=A_{14}\sim A_{12}},$$

即 VPN 的低 3 位。

剩余 VPN 高 15 位为 tag：

$$\boxed{tag=A_{29}\sim A_{15}}.$$

### (3) LRU 替换

把 VPN 对 8 取模得到组号：

| VPN | set |
|---:|---:|
| 10 | 2 |
| 12 | 4 |
| 16 | 0 |
| 7 | 7 |
| 26 | 2 |
| 4 | 4 |
| 12 | 4 |
| 20 | 4 |

只有 set 4 出现超过 2 个不同 VPN。其局部访问序列为

```text
12 -> 4 -> 12 -> 20
```

装入 `12,4` 后，再访问 12 是命中，并把 12 更新为最近使用；此时 LRU 是 4。随后访问 20，需要替换：

$$\boxed{VPN=4}.$$

### (4) VA 增加到 32 位

VA 增加 2 位，页大小不变，所以 VPN 增加 2 位；组号仍为 3 位，因此新增两位全部进入 TLB tag。

物理地址仍为 24 位，页框号字段不变。因此每个 TLB 表项增加

$$\boxed{2\text{ bit}}.$$

## Verification

set 4 的状态可以写成：

```text
12: [12]
 4: [12,4]
12: [4,12]   // hit refreshes recency
20: replace 4 -> [12,20]
```

所以被替换的一定是 4，而不是更早装入但刚刚命中的 12。

## Compression

```text
4KB -> offset 12, VPN 18
8 sets -> set 3 bits = A14..A12
tag = A29..A15
VPN mod8 sequence -> set4: 12,4,12,20
LRU refresh on hit -> evict 4
VA +2 bits -> TLB tag +2 bits
```

## 易错边界

TLB 可以像 Cache 一样用组相联思路模拟，但它缓存的是地址翻译；不要把“TLB 组号”和“Cache 组号”混成同一个物理字段。
