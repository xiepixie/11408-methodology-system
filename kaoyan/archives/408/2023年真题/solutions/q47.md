# 408-2023-Q47

> 原题：[[../2023 年全国硕士研究生招生考试#47（9 分）|Q47]]

## Model Anchor

- Topic：FTP 双连接语义 + TCP 序号空间 + 慢开始/拥塞避免 + RTT 时间线。
- 题目信号：FTP 登录/上传、ISN=100、MSS=1000 B、ssthresh=4 MSS、文件 18000 B、无丢包乱序同时出现。
- 第一动作：建立三本账：`connection role`、`SEQ/ACK`、`cwnd + RTT rounds`；不要把 FTP 控制连接和数据连接混成同一 TCP 状态机。

## Problem Representation

```text
file size  = 18000 B = 18 MSS
MSS        = 1000 B
client ISN = 100
ssthresh   = 4 MSS
RTT        = 10 ms
loss       = none
```

按 408 经典慢开始口径：

```text
initial cwnd = 1 MSS
SYN consumes one sequence number
pure ACK consumes no sequence number
FIN consumes one sequence number
```

## Decision Points

- FTP 登录阶段建立的是控制连接；每次实际文件传输使用单独数据连接。
- ACK 号始终表示“下一个期望字节”，所以必须先把 SYN 占用的一个序号算进去。
- `ssthresh=4 MSS`：cwnd 从 1→2→4 后进入拥塞避免；之后按考试模型每 RTT 约增加 1 MSS。
- 总时间从“请求建立数据连接”开始，因此建连本身先占 1 RTT；第三次握手可以与首批应用数据衔接，不额外再加一个完整 RTT。

## Solution Chain

### (1) FTP 控制/数据连接

FTP 的控制连接需要贯穿登录和后续命令交互，因此是：

$$\boxed{\text{持久连接}}.$$

数据连接针对具体目录列表或文件传输建立，传输结束后关闭，因此是：

$$\boxed{\text{非持久连接}}.$$

H 登录 FTP 服务器时首先建立的是：

$$\boxed{\text{控制连接}}.$$

### (2) 第一个数据字节序号与第二次挥手 ACK

H 建立数据 TCP 连接时选择初始序号 100。SYN 占用一个序号，所以 F 的第一个数据字节序号为：

$$\boxed{101}.$$

18000 B 数据占用字节序号：

$$101\sim18100.$$

因此发送完整文件后，下一个序号为：

$$18101.$$

H 主动关闭数据连接时 FIN 使用 18101，并再消耗一个序号。服务器第二次挥手确认该 FIN 时：

$$ACK=18101+1=\boxed{18102}.$$

### (3) 两个 ACK 时刻的 cwnd

初始：

$$cwnd=1\text{ MSS}.$$

第 1 个段 `seq=101` 被确认后，ACK=1101：

$$cwnd:1\to2.$$

随后发送两个段。收到 ACK=2101 时，只新确认了其中一个 MSS，在慢开始中 cwnd 每收到一个新的 ACK 增加 1 MSS，因此：

$$\boxed{cwnd=3\text{ MSS}}.$$

继续收到 ACK=3101 后：

$$cwnd=4\text{ MSS}=ssthresh.$$

此后进入拥塞避免。下一轮发送 4 MSS；收到覆盖到 7100 的全部确认，即 ACK=7101 时，一整个 RTT 的 4 个确认使 cwnd 约增加 1 MSS：

$$\boxed{cwnd=5\text{ MSS}}.$$

### (4) 最短总时间与应用层平均发送速率

从请求建立数据连接开始计时。

#### RTT 0→1：建立连接

1 RTT 后 H 收到 SYN+ACK，并可在第三次握手 ACK 后立即发送首批数据。

#### 数据发送轮次

| 到达 ACK 前的 cwnd | 本轮最多发送 | 累计已发送 |
|---:|---:|---:|
| 1 MSS | 1 MSS | 1 MSS |
| 2 MSS | 2 MSS | 3 MSS |
| 4 MSS | 4 MSS | 7 MSS |
| 5 MSS | 5 MSS | 12 MSS |
| 6 MSS | 剩余 6 MSS | 18 MSS |

因此应用数据需要 5 个 RTT 批次得到最终确认。

总时间：

$$T=(1+5)RTT=6\times10\text{ ms}=\boxed{60\text{ ms}}.$$

应用层平均发送速率按题目从请求建连到文件全部确认的完整区间计算：

$$R=\frac{18000\text{ B}}{0.06\text{ s}}
=300000\text{ B/s}
=0.3\text{ MB/s}.$$

换算为 bit/s：

$$R=300000\times8=2.4\times10^6\text{ bit/s}
=\boxed{2.4\text{ Mb/s}}.$$

## Verification

### SEQ/ACK 守恒

```text
SYN : seq 100
DATA: seq 101 ... 18100   共 18000 个字节
FIN : seq 18101
ACK : next expected = 18102
```

完全闭合。

### 数据量守恒

$$1+2+4+5+6=18\text{ MSS}=18000\text{ B}.$$

### 时间守恒

```text
1 RTT 建连
5 RTT 数据确认轮次
= 6 RTT = 60 ms
```

平均速率反算：

$$2.4\text{ Mb/s}\times0.06\text{ s}=0.144\text{ Mbit}=18000\text{ B}.$$

## Compression

```text
FTP -> control persistent / data per-transfer
TCP seq -> SYN占1，首数据=ISN+1，FIN再占1
cwnd -> 1 -> 2 -> 4(ssthresh) -> 5 -> 6 ...
时间 -> 1 RTT handshake + 5 RTT data rounds = 60 ms
```

## 易错边界

- ACK=2101 不是“已经收到 2101 B”，而是“下一个期望字节序号为 2101”。
- 到达 ssthresh 后从 slow start 切到 congestion avoidance；不能继续按每 ACK +1 MSS 指数增长。
- FTP 控制连接和数据连接是两个不同 TCP 连接，不能共享同一序号空间。
- 本题平均速率的分母明确从请求建立数据连接开始，因此要把连接建立 RTT 算进去。
