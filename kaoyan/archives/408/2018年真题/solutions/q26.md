# 408-2018-Q26

## Model Anchor

- Topic：银行家安全性检测的 `Available / Allocation / Need` 状态推进。
- 题目信号：单类资源、给出总量/最大需求/已分配。
- 第一动作：先算当前 Available，再只让 `Need <= Available` 的进程假想完成并归还 Allocation。

## 解题链

总资源 4 个，当前已分配

$$2+1+0=3,$$

因此

$$Available=1.$$

剩余需求：

```text
P1: 4-2=2
P2: 3-1=2
P3: 1-0=1
```

只有 P3 能在 Available=1 时完成；但 P3 当前 Allocation=0，完成后归还 0 个资源，所以 Available 仍为 1。

此时 P1、P2 都还需要 2 个资源，没有任何进程能继续完成，安全性推进停滞。

## 选项判断

不存在安全序列，系统处于不安全状态，故选 $\boxed{A}$。

## Verification

关键资源守恒：P3 虽能结束，却没有占有资源可释放；因此它不能为后续状态创造额外 Available。

## Compression

```text
total-allocation -> Available
-> find Need<=Available
-> finish and release Allocation
-> no progress => unsafe
```

## 易错边界

“某进程可以完成”不等于“它完成后一定释放很多资源”；必须看它**当前已分配量**。
