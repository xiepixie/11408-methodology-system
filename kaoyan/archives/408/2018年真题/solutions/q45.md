# 408-2018-Q45

## Model Anchor

- Topic：二级页表地址字段构造、地址空间 Owner 与 CLOCK 状态位。
- 题目信号：题 44 已给 `10 bit 页目录号 + 10 bit 页号 + 12 bit 页内偏移`，再询问 PDBR 与线程/进程切换。
- 第一动作：把三个对象分清：`VA bit fields` 属于地址格式；`PDBR` 属于当前地址空间翻译根；`A/D bits` 属于页面使用状态。

## Problem Representation

虚拟地址固定为 32 位：

```text
[ directory 10 | page-table index 10 | offset 12 ]
```

PDBR 是硬件进行页表遍历的起点，因此必须指向 CPU 能直接访问的页目录物理位置。

进程是地址空间的 Owner；同一进程的多个线程共享这一地址空间。

## Decision Points

1. 第 (1) 问不要把十进制字段“6”直接拼成十六进制字符；要先按字段位宽放到正确 bit 位置。
2. PDBR 是否变化取决于**地址空间是否变化**，而不是“上下文切换是否发生”。
3. 改进型 CLOCK 的决策状态是最近访问与是否修改；因此寻找对应页表状态位，而不是把存在位/权限位全部列入。

## Solution Chain

### (1) 构造虚拟地址

页目录号 $d=6$，页号 $p=6$，页内偏移 $w=8$。

32 位虚拟地址为

$$VA=(d<<22)+(p<<12)+w.$$

代入：

$$6\times 2^{22}+6\times2^{12}+8$$

$$=\mathtt{01800000_H}+\mathtt{00006000_H}+\mathtt{00000008_H}$$

$$=\boxed{\mathtt{01806008_H}}.$$

### (2) PDBR 的地址性质与切换

PDBR 保存当前进程页目录的起始地址。页表遍历硬件需要在尚未完成本次 VA→PA 翻译之前就访问页目录，所以这个基址必须是

$$\boxed{\text{物理地址}}.$$

#### 进程切换

不同进程通常拥有不同虚拟地址空间及页目录，因此切换到另一进程时，需要装入该进程自己的页目录基址：

$$\boxed{PDBR\text{ 通常变化}}.$$

#### 同一进程的线程切换

线程拥有各自执行上下文，但共享所属进程的虚拟地址空间和页表。只在线程之间切换时，页目录 Owner 没有变化，所以

$$\boxed{PDBR\text{ 不变化}}.$$

这条判断可以压成：

```text
context switch happened?
不是关键
address-space owner changed?
才决定 PDBR 是否切换
```

### (3) 改进型 CLOCK 需要哪些页表字段

改进型 CLOCK 按 `(访问位 A, 修改位 D)` 对页面分类：

```text
(0,0) 最优先置换
(0,1)
(1,0)
(1,1) 最不优先
```

因此需要页表项记录：

$$\boxed{\text{访问位 / Reference bit}}$$

和

$$\boxed{\text{修改位 / Dirty bit}}.$$

访问位反映近期是否被访问；修改位决定换出时是否需要写回外存。

## Verification

`01806008H >> 22 = 6`；再取中间 10 位得到 6；低 12 位为 `008H`。三个字段反解与题设完全一致。

PDBR 的 Owner 校验也很直接：若同一进程线程切换就修改 PDBR，相当于无缘无故更换共享地址空间，与线程共享进程内存这一模型冲突。

## Compression

```text
10|10|12 VA
-> VA = dir<<22 | page<<12 | offset
-> PDBR is physical translation-root
-> process switch changes address-space owner => reload
-> same-process thread switch => keep
-> improved CLOCK => A + D bits
```

## 易错边界

- “进程切换”与“线程切换”都属于上下文切换，但只有前者通常切换地址空间。
- `PDBR` 不能保存一个还需要当前页表才能翻译的普通虚拟地址，否则页表遍历会形成循环依赖。
- CLOCK 的 A/D 位与有效位、保护位作用不同；不要把所有 PTE 字段都当作置换算法状态。
