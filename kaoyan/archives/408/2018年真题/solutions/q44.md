# 408-2018-Q44

## Model Anchor

- Topic：`VA -> TLB/Page Table -> PA -> Cache` 的两级地址解释链。
- 题目信号：一张图同时出现 VPN、页内偏移、实页号、TLB、Cache Tag/组号/块内地址。
- 第一动作：严格分两层：**TLB/page table 负责 VA→PA；Cache 只消费 PA**。先完成地址翻译，再做 Cache 投影，不能拿虚页号直接查 Cache。

## Problem Representation

题图给出的地址结构可压缩为：

```text
VA: [ VPN 20 bit | page offset 12 bit ]
                  |
             TLB/Page Table
                  v
PA: [ physical page number 16 bit | page offset 12 bit ]

PA for Cache:
[ Tag 20 bit | set 3 bit | block offset 5 bit ]
```

因此物理地址总宽度天然由“实页号 + 页内偏移”决定；Cache 的 `20+3+5` 又给出一条独立校验路径。

## Decision Points

1. TLB 的映射方式从“VPN 与所有 TLB 项并行比较”的结构判断，不从 Cache 的组相联方式类推。
2. Cache 容量题要先区分**数据容量**与题目所问的“总容量（包含标记和控制位）”。
3. 对第二个虚拟地址，只问 Cache 组号。若组号位完全落在页内偏移中，就无需知道物理页框；这是 VA/PA 低位不变的重要 Bridge。

## Solution Chain

### (1) 主存物理地址位数

题图中实页号占 16 位，页内偏移占 12 位，所以

$$16+12=\boxed{28\text{ bit}}.$$

也可从 Cache 地址字段反推：

$$20+3+5=28\text{ bit}.$$

两条路线一致。

### (2) TLB 映射方式与实现介质

题图中 VPN 与 TLB 中各 Tag 并行比较，没有组号字段限制某个 VPN 只能进入固定集合，因此为

$$\boxed{\text{全相联映射}}.$$

TLB 要求小容量、极低访问延迟，通常采用

$$\boxed{\text{SRAM}}$$

实现，而不是需要刷新的 DRAM。

### (3) Cache 映射、附加位与总容量

Cache 地址中组号为 3 位，所以有

$$2^3=8\text{ 组}.$$

图中每组有 2 行，因此是

$$\boxed{\text{2 路组相联}}.$$

块内偏移 5 位，所以每块数据大小

$$2^5=32\text{ B}=256\text{ bit}.$$

采用 Write Back，需要记录该行是否被 CPU 修改，故需要

$$\boxed{\text{修改位 / Dirty bit}}.$$

采用 2 路 LRU，需要记录两路最近使用关系；按本题每行附加字段的计数口径，记 1 位 LRU 信息。再加题图已有有效位，每行总位数：

$$256+20+1_{valid}+1_{dirty}+1_{LRU}=279\text{ bit}.$$

共 $8\times2=16$ 行，因此总容量

$$279\times16=4464\text{ bit}=\boxed{558\text{ B}}.$$

有效位的作用是：

> 指示该 Cache 行当前保存的 Tag/Data 是否属于一个已经装入且可被命中的有效主存块。

即使 Tag 比较相等，只要有效位为 0，也必须判 miss。

### (4) 两个虚拟地址

#### VA = `0008C040H`

页大小为 4 KB，页内偏移为低 12 位：

```text
VPN    = 0008CH
offset = 040H
```

图中 TLB 对 `0008CH` 命中，有效位为 1，对应实页号 `0040H`。故物理地址为

$$\boxed{0040040_H}.$$

再投影到 Cache：

```text
Tag    = 00400H
set    = 2
block offset = 0
```

检查第 2 组两路：图中虽然存在 Tag=`00400H` 的项，但其有效位为 0；另一行 Tag 又不匹配。因此

$$\boxed{\text{Cache miss}}.$$

这正体现 `Tag match` 与 `Valid=1` 必须同时成立。

#### VA = `0007C260H`

只要求其主存块映射到哪个 Cache 组。地址翻译不改变低 12 位页内偏移，而 Cache 的组号位和块内地址合计只有

$$3+5=8<12$$

位，因此组号完全可以直接从 VA 的页内偏移 `260H` 取出。

$$set=(0x260>>5)\ \&\ 0x7=3.$$

故映射到

$$\boxed{3\text{ 号组}}.$$

## Verification

- 物理地址宽度：`16+12=28` 与 `20+3+5=28` 双路闭合。
- `0040040H` 的低 8 位是 `01000000₂`：低 5 位为块内偏移 `00000`，其上 3 位为 `010₂=2`，与组号计算一致。
- `260H` 的低 8 位是 `01100000₂`：组位正是 `011₂=3`。

## Compression

```text
VA -> split VPN/offset
-> TLB hit gives physical page
-> PA = PPN || offset
-> Cache: Tag/set/block-offset
-> hit requires Tag match AND valid=1
-> if set bits lie inside page offset, VA low bits alone can determine set
```

## 易错边界

- TLB 与 Cache 都“像高速表”，但 Owner 不同：TLB 缓存地址翻译，Cache 缓存主存数据块。
- Cache 用物理地址查找；只有因为页内偏移在翻译前后保持不变，才可在特定题目中从 VA 低位直接得到 set。
- 回写策略需要 Dirty；直写策略通常不需要。
