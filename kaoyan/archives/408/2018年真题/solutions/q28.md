# 408-2018-Q28

## Model Anchor

- Topic：管程条件变量的等待语义。
- 题目信号：`x` 明确是 condition variable，问 `x.wait()` 的动作。
- 第一动作：区分 monitor mutual exclusion 与 condition synchronization；条件变量不保存普通“数值条件”，它维护等待该条件的线程队列。

## 解题链

执行 `x.wait()` 的线程说明当前条件尚不满足。其核心动作是：

1. 当前线程阻塞；
2. 加入条件变量 x 对应的等待队列；
3. 同时释放管程的互斥占有，使其他线程有机会进入管程改变状态。

A 错：管程互斥由管程进入机制负责，不由条件变量本身实现。

B 描述的是 `signal()`。

C 错：条件是否成立由程序在调用 `wait()` 前判断，不是 `wait()` 根据 x 的“值”判断。

## 选项判断

故选 $\boxed{D}$。

## Verification

若 `wait()` 不阻塞并释放管程，其他线程就无法进入并改变使条件成立的共享状态，系统可能永久停滞。

## Compression

```text
condition false -> x.wait() -> release monitor + Blocked on x queue
x.signal() -> wake waiter
```

## 易错边界

条件变量不是信号量，没有一个供 `wait()` 自己判断的整数资源计数。
