# 408-2018-Q32

## Model Anchor

- Topic：忙等互斥与阻塞等待的机制边界。
- 题目信号：问哪个同步机制能实现“让权等待”。
- 第一动作：判断等待失败后进程是继续占 CPU 自旋，还是进入阻塞队列把 CPU 让给别人。

## 解题链

Peterson、`swap`、TestAndSet 都属于典型忙等互斥：条件不满足时进程不断检查共享状态，仍占用 CPU。

信号量若由操作系统实现为阻塞式 `wait/P`，当资源不可用时可以把进程置为 Blocked，并加入相应等待队列；随后由 `signal/V` 唤醒。这正是“让权等待”。

## 选项判断

故选 $\boxed{C}$。

## Verification

让权等待的定义就是“不能进入临界区时不继续消耗处理机”。四个机制中只有阻塞信号量天然具备等待队列与调度交互。

## Compression

```text
failed entry
-> spin on CPU = busy waiting
-> Block + queue = yielding wait
-> semaphore
```

## 易错边界

信号量既可在不同系统中实现成不同底层机制；408 此处讨论的是经典阻塞型信号量语义。
