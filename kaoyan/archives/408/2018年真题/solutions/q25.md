# 408-2018-Q25

## Model Anchor

- Topic：共享变量读-改-写的交错与 lost update。
- 题目信号：两个线程各执行 `read -> inc local -> write`，问哪些交错能得到 x=2。
- 第一动作：把一条“x++”拆成三个事件；x=2 的必要条件是后写线程读取时已经看到另一线程写出的 1。

## 解题链

每个线程内部顺序固定：

```text
Ri(x) -> inci -> Wi(x)
```

若最终得到 2，那么最后写回的线程必须先读到 `x=1`。这要求另一线程已经完整执行到写回之后，最后线程才能开始它的读。

因此只有两种指令级序列：

```text
thread1 三条全部完成 -> thread2 三条全部完成
thread2 三条全部完成 -> thread1 三条全部完成
```

其余交错中，只要两个线程都在任何写回前读到 0，最终最多写回 1，发生 lost update。

## 选项判断

可得到 x=2 的序列共 2 个，故选 $\boxed{B}$。

## Verification

x 初值只有 0；局部 `inc` 只在寄存器上。想写出 2，某个 `mov R,x` 必须读到内存中的 1，所以必然要求另一线程先写回。

## Compression

```text
x++ is read-modify-write
-> x=2 requires second reader sees first write
-> only two serialized orders
```

## 易错边界

源代码的一条 `x++` 不是原子操作；并发题必须落到题目给出的机器级事件粒度。
