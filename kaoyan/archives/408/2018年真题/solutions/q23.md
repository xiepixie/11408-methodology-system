# 408-2018-Q23

## Model Anchor

- Topic：多任务 OS 的并发抽象与共享资源保护。
- 题目信号：判断多任务系统的必要特征，而不是判断多核硬件特征。
- 第一动作：先区分 concurrency 与 hardware parallelism，再检查共享状态是否需要同步机制。

## 解题链

I 正确：多任务系统允许多个任务在时间上交错推进，具有并发性；在多核平台上还可能并行。

II 正确：多个任务共享 CPU、内存、文件、设备等资源，需要互斥、同步或权限机制保护共享状态。

III 错误：单 CPU 通过调度与上下文切换同样可以实现多任务，不要求多 CPU。

## 选项判断

故选 $\boxed{C}$。

## Verification

经典单核分时系统就是反例：没有多 CPU，却显然属于多任务操作系统。

## Compression

```text
multitasking -> concurrent execution + shared-resource control
!= must have multiple CPUs
```

## 易错边界

并发是逻辑上的“多个任务在一段时间内共同推进”，并行才要求同一时刻有多个执行资源。
