# 408-2024-Q46

> 原题：[[../2024 年全国硕士研究生招生考试#46（8 分）|Q46]]

## Model Anchor

- Topic：单缓冲区上的 **Safety（互斥）** 与 **Ordering（同步）**。
- 题目信号：C1/C2/C3 的访问条件不同：`C1 requires empty`，`C2/C3 require non-empty`，且 C1、C3 都会修改共享 B。
- 第一动作：每小问先写必须保持的谓词，再问需要的是“谁必须先发生”还是“谁不能同时发生”；不要见到共享缓冲区就机械套 `empty/full/mutex` 三信号量模板。

## Problem Representation

缓冲区只有两个抽象状态：

```text
EMPTY
FULL(packet)
```

操作合同：

```text
C1: pre B=EMPTY -> write packet -> post B=FULL
C2: pre B=FULL  -> read packet
C3: pre B=FULL  -> modify packet -> post B=FULL
```

## Decision Points

- (1) 两个 C1 同时执行会竞争同一个共享写入状态，核心问题是互斥。
- (2) 只有 P1 写一次、P2 读一次，且 B 初始为空；只要保证 `C1 happens-before C2`，就已经自动排除了二者并发访问，**一个同步信号量足够**。
- (3) B 初始非空，两个 C3 都可执行，但二者都会修改同一数据分组，因此只需要一个 mutex。

## Solution Chain

### (1) 两个进程都执行 C1，C1 是否是临界区

**是。**

C1 会修改共享缓冲区 B，并且其合法前提是 `B=EMPTY`。若 P1、P2 同时观察到空并同时写入，两个写操作可能互相覆盖，使“单缓冲区只保存一个完整数据分组”的不变量被破坏。

因此对多个可能执行 C1 的进程，C1 对 B 的状态检查与写入需要互斥保护，是临界区。

### (2) B 初始为空；P1 执行 C1 一次，P2 执行 C2 一次

最少只需要 **1 个同步信号量**：

```c
semaphore full = 0;   // 表示“P1 已经完成 C1，B 中已有可读数据”

P1() {
    C1;               // 写入 B
    signal(full);     // 发布：B 已非空
}

P2() {
    wait(full);       // B 为空时在这里等待
    C2;               // 读取 B
}
```

初值：

$$\boxed{full=0}.$$

其作用是建立

$$C1\ \text{完成}\quad\longrightarrow\quad C2\ \text{开始}$$

的同步关系。

为什么不再需要 `mutex`？因为本小问中只有 P1 执行一次 C1、P2 执行一次 C2；`wait(full)` 已保证 P2 不可能和 C1 并发访问 B。额外互斥量不会增加正确性，只会违反“尽可能少”。

### (3) B 初始非空；P1、P2 各执行 C3 一次

C3 会修改同一个数据分组，两个进程不能同时修改，因此用 **1 个互斥信号量**：

```c
semaphore mutex = 1;

P1() {
    wait(mutex);
    C3;
    signal(mutex);
}

P2() {
    wait(mutex);
    C3;
    signal(mutex);
}
```

初值：

$$\boxed{mutex=1}.$$

因为 C3 不会把 B 变为空，题设又已保证初始非空，所以无需额外 `full` 信号量。

## Verification

### 对 (2) 做最坏交错

如果 P2 先运行，它立即阻塞在 `wait(full)`；只有 P1 完成 C1 并 `signal(full)` 后 P2 才能进入 C2。因此不可能读空缓冲区，也不可能与 C1 同时访问。

### 对 (3) 做互斥检查

`mutex=1` 时第一个进入 C3 的进程把它减为 0；另一个只能等待，直到前者完成修改并 V 操作。任意时刻最多一个 C3 修改 B，Safety 成立。

## Compression

```text
PV 大题
-> 先写共享状态/前置谓词
-> “必须先后”用同步 semaphore
-> “不能同时”用 mutex
-> 再问能否用同一个约束自动消除另一个风险
-> 最后最小化信号量数量
```

## 易错边界

- legacy 解析在 (2) 使用 `mutex + full` 两个信号量，不满足题目的“尽可能少”；这里只有一次 C1 和一次 C2，一个 `full=0` 已足够。
- “共享资源”不自动意味着每个场景都必须显式再加 mutex；若同步关系已经强制两段代码不重叠，就不要重复上锁。
- (3) 只需互斥，不需同步先后：P1 先或 P2 先都合法。
