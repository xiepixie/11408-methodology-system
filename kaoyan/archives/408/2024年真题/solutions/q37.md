# 408-2024-Q37

> 原题：[[../2024 年全国硕士研究生招生考试#37|Q37]]

## Model Anchor

- Topic：SR 的独立确认、窗口滑动与单帧超时重传。
- 题目信号：3 bit 序号、发送/接收窗口相等且取最大值、ACK 独立、F1 超时。
- 第一动作：先由序号空间求 SR 最大窗口，再维护 `base / 已发送 / 已确认 / timer`；不要把 SR 误做成 GBN 累计确认。

## 解题链

3 bit 序号空间大小为

$$N=2^3=8.$$

SR 为避免新旧序号混淆，发送/接收窗口最大为

$$W=N/2=4.$$

图中甲先发送 F0～F3。收到 `ACK0` 后，窗口基序号可从 0 向前移动到 1，腾出一个新发送位置，因此 $t_1$ 可以发送下一帧

$$\boxed{F4}.$$

F1 丢失，而 F2、F3 即使被乙正确接收并独立 ACK，也不能让发送窗口基序号越过尚未确认的 F1。到 $t_2$，F1 的定时器超时；SR 只重传该超时帧，而不是回退整个窗口，因此发送

$$\boxed{F1}.$$

所以选 **D（F4、F1）**。

## 选项判断

A、B 错在 $t_1$ 没有利用 `ACK0` 腾出的新窗口位置；C 把 F3 当成新帧或混淆已发送状态；D 符合 SR 的窗口与独立 timer 状态。

## Verification

`t1` 后窗口可覆盖序号 `1,2,3,4`；F1 未确认时 base=1 不动。F1 超时只触发 F1 重传，正是 SR 相对于 GBN 的核心差异。

## Compression

SR 图题 → **序号位数先定最大窗口 $2^{k-1}$ -> ACK 只标记单帧 -> base 只跨连续已确认前缀 -> 哪帧超时只重传哪帧**。

## 易错边界

SR 可以缓存/确认失序帧，但发送窗口基序号不能跨过最早未确认帧；“ACK2、ACK3 到了”不等于 F1 已被累计确认。
