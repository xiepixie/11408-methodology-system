# 408-2024-Q44

> 原题：[[../2024 年全国硕士研究生招生考试#44（10 分）|Q44]]

## Model Anchor

- Topic：`C array access -> machine instructions -> byte address -> endian decode -> page boundary -> instruction encode`。
- 题目信号：`sum+=a[i]` 被拆成 `slli/add/lw/add`，同时给小端字节表与 4 KB 页。
- 第一动作：先为四条指令建立**值的流向**，确定每个寄存器角色；再把数组访问统一转成字节地址 `base + i*element_size`。

## Problem Representation

指令链：

```asm
slli r4, r2, 2  // r4 = i * 4
add  r4, r3, r4 // r4 = base(a) + i*4
lw   r5, 0(r4)  // r5 = a[i]
add  r1, r1, r5 // sum += a[i]
```

因此数据依赖立即锁定：

```text
r2 = i
r3 = base(a)
r4 = &a[i]
r5 = a[i]
r1 = sum
```

## Decision Points

- 地址计算必须按**字节编址**，`int=4 B`，所以乘 4。
- 小端只改变“内存字节如何组成 32 位机器数”，不改变地址。
- 页号来自地址除以 4 KB；判断数组跨几页必须看数组实际访问区间/已知元素地址跨页，而不能只看一个元素。
- `slli` 编码直接按 Q43 给出的字段布局填位，不凭经验写十六进制。

## Solution Chain

### (1) `a` 首地址、`i`、`sum` 分别在哪个寄存器

由第一条：

```text
r4 <- r2 << 2 = i*4
```

所以

$$\boxed{i\text{ 在 }r2\ (02H)}.$$

第二条：

```text
r4 <- r3 + r4 = base(a)+i*4
```

所以

$$\boxed{a\text{ 的首地址在 }r3\ (03H)}.$$

最后一条：

```text
r1 <- r1 + r5 = sum + a[i]
```

所以

$$\boxed{sum\text{ 在 }r1\ (01H)}.$$

### (2) `a[i]` 地址、机器数、sum、页号与数组跨页数

已知：

```text
i        = 5
base(a)  = 0013 DFF0H
sum      = 0000 1332H
sizeof(int) = 4 B
```

#### ① `a[5]` 地址

$$
&a[5]=\texttt{0013DFF0H}+5\times4
=\texttt{0013DFF0H}+\texttt{14H}
=\boxed{\texttt{0013E004H}}.
$$

#### ② `a[5]` 的 32 位机器数

题 44 字节表中从 `0013E004H` 开始的 4 个字节为：

```text
地址: E004 E005 E006 E007
字节:   DC   EC   FF   FF
```

机器采用小端，低地址放低有效字节，因此寄存器读出的 32 位值为：

$$\boxed{\texttt{FFFFECDCH}}.$$

#### ③ 执行后 `sum` 的机器数

$$
\texttt{00001332H}+\texttt{FFFFECDCH}
=\texttt{1 0000000EH}.
$$

32 位寄存器保留低 32 位：

$$\boxed{sum=\texttt{0000000EH}}.$$

#### ④ `a[5]` 所在页号

页大小

$$4\text{ KB}=2^{12}\text{ B},$$

所以低 12 位是页内偏移，页号为地址右移 12 位：

$$
\texttt{0013E004H} >> 12
=\boxed{\texttt{0013EH}}.
$$

#### ⑤ 此次执行可知数组 `a` 至少占几页

数组首地址为 `0013DFF0H`，位于页 `0013DH`；`a[5]` 地址 `0013E004H` 已位于下一页 `0013EH`。

因此从题面已知的数组位置即可确定：

$$\boxed{a\text{ 至少跨 }2\text{ 页}}.$$

### (3) `slli r4,r2,2` 机器码与 short 情况

根据 Q43 的 `slli` 格式：

```text
31..25   24..20  19..15  14..12  11..7  6..0
0000000  shamt    rs1     010      rd     0010011
```

代入：

```text
shamt = 2     = 00010
rs1   = r2    = 00010
rd    = r4    = 00100
```

得到：

```text
0000000 00010 00010 010 00100 0010011
= 0021 2213H
```

所以

$$\boxed{\texttt{0021 2213H}}.$$

若数组元素改为 `short`，每个元素为 2 B，地址偏移应变成

$$i\times2=i\ll1,$$

故改为：

```asm
slli r4, r2, 1
```

## Verification

### 地址与页边界检查

`0013DFF0H` 到下一页 `0013E000H` 只有 16 B，而 `a[5]` 偏移为 20 B，所以它必然跨到 `0013E` 页；地址 `E004` 与这个边界关系吻合。

### 小端检查

若值为 `FFFFECDCH`，按小端拆成低到高字节正是：

```text
DC EC FF FF
```

与内存表完全一致。

### 加法检查

`FFFFECDC` 按补码为 -4900，`0x1332=4914`，两者和为 14，即 `0000000EH`，与机器位串加法独立一致。

## Compression

```text
数组机器题
-> 从指令依赖认出 base/index/sum
-> address = base + i*element_size
-> 按 endian 组字
-> page = address >> offset_bits
-> 最后按字段表编码指令
```

## 易错边界

- 数组 `a` 的首地址是 `0013DFF0H`，不能因为 `a[5]` 落在 `E004H` 就把 `E000H` 误当首地址。
- 小端只影响多字节值的字节顺序，不影响数组地址计算。
- `int -> short` 后索引比例从 4 B 变为 2 B，所以是 `<<1`，不是修改 `lw` 的立即数来补偿。
