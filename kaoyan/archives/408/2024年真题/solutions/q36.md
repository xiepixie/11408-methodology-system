# 408-2024-Q36

> 原题：[[../2024 年全国硕士研究生招生考试#36|Q36]]

## Model Anchor

- Topic：802.11 RTS/CTS 中 NAV 的剩余介质占用时间。
- 题目信号：隐藏站 B 是**收到 CTS 后**才设置 NAV；因此 DIFS、RTS、CTS 自身已经过去，不能再算进剩余时间。
- 第一动作：以“CTS 接收完毕”为 $t=0$ 画后续时间线，只累计直到 ACK 完成的剩余事件。

## 解题链

数据帧传输时间：

$$
T_{data}=\frac{1998\times8}{54\times10^6}
=296\ \mu s.
$$

B 收到 CTS 后，介质仍需保留：

```text
SIFS 28 μs
+ DATA 296 μs
+ SIFS 28 μs
+ ACK 2 μs
```

所以

$$NAV=28+296+28+2=\boxed{354\ \mu s}.$$

故选 **B**。

## 选项判断

A 少算必要间隔/确认阶段；C、D 把已经发生的 RTS/CTS/DIFS 等阶段重新计入，起算点错误。

## Verification

NAV 是接收 CTS 后“从现在起还要沉默多久”，所以任何发生在 CTS 之前的时间都不可能出现在该值中。这一时间语义可直接排除把 DIFS 或 RTS 加进去的路线。

## Compression

NAV 题 → **先钉死收到哪一帧的时刻 -> 只数此刻之后剩余的 SIFS / DATA / ACK 时间**。

## 易错边界

RTS 中的 Duration 与 CTS 中的 Duration 起算点不同；后发帧中的剩余时间应逐步扣除已经经过的阶段。
