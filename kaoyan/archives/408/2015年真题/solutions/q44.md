# 408-2015-Q44

> 原题：[[../2015 年全国硕士研究生招生考试#44|Q44]]

## Model Anchor

- Topic：CO02/CO03｜Instruction Format -> Operand Role -> Micro-operation -> Control Signal。
- 题目信号：承接 Q43 的单总线数据通路，给出指令格式和部分控制序列，连续问 opcode 容量、机器码、控制信号和最少执行周期。
- 第一动作：先锁 16 位指令各字段边界，再对每条汇编指令按“操作码 + 寻址方式 + 寄存器号”填位；执行周期则按**一次总线传送/锁存需要一个微操作阶段**逐拍展开。

## Problem Representation

这道题同时存在三层对象，必须分开：

```text
ISA syntax
    inc / shl / sub + operand roles
        ↓
Instruction Encoding
    opcode / addressing-mode / register fields
        ↓
Microarchitecture
    Rout / Rin / Tin / ALUop / SRop / SRout / MEMop ...
```

机器码问题只由前两层决定；控制信号和周期数必须进入第三层。

单总线约束继续成立：同一拍不能让多个源同时驱动总线，二元 ALU 运算通常需要 `T` 保存一个先到操作数。

## Decision Points

1. **操作码容量只看 opcode 字段宽度**，不能拿整个 16 位指令字做 $2^{16}$。
2. **寄存器间接寻址改变的是 operand source path**：先由寄存器给地址，再读主存；不是把寄存器号本身当操作数数据。
3. **机器码先填字段再转十六进制**，避免直接凭结果记忆。
4. **周期数看数据依赖路径，不看汇编有几个操作数就机械等于几拍。** `inc` 有 ALU 自增捷径，而间接操作数必须多出访存路径。

## Solution Chain

### (1) 最多可定义多少条指令

题图中 opcode 字段为 7 bit，因此最多区分：

$$
2^7=\boxed{128}
$$

条操作码。

### (2) 三条指令的机器代码

按题图的固定字段，把题设 opcode 与寻址方式、寄存器号填入 16 位指令字。

#### `inc R1`

题设 `inc` opcode = `01H`，R1 编号为 1，按格式编码得到：

```text
0000 0010 0100 0000
```

即：

$$\boxed{0240H}.$$

#### `shl R2, R1`

`shl` opcode = `02H`，目的寄存器 R2，源寄存器 R1，均为寄存器直接寻址：

```text
0000 0100 1000 1000
```

即：

$$\boxed{0488H}.$$

#### `sub R3, (R1), R2`

`sub` opcode = `03H`；目的寄存器 R3；第一源操作数采用 R1 寄存器间接；第二源为 R2 寄存器直接。填字段得到：

```text
0000 0110 1110 1010
```

即：

$$\boxed{06EAH}.$$

这里 `(R1)` 的关键不是括号长什么样，而是其寻址方式位必须取“寄存器间接=1”。

### (3) 图 a 中 ①～⑧

结合 Q43 数据通路和图 a 已给出的控制阶段，标号处应为：

| 标号 | 控制信号 / 取值 | 作用 |
|---|---|---|
| ① | `0` | 对应图中该控制字段的直接寻址/选择值 |
| ② | `mov` | SR 直送 |
| ③ | `mova` | ALU 直送 A |
| ④ | `left` | SR 左移一位 |
| ⑤ | `read` | 主存读 |
| ⑥ | `sub` | ALU 做减法 |
| ⑦ | `mov` | SR 直送 |
| ⑧ | `SRout` | 允许 SR 结果驱动内部总线 |

因此：

$$
\boxed{①=0,\ ②=mov,\ ③=mova,\ ④=left,\ ⑤=read,\ ⑥=sub,\ ⑦=mov,\ ⑧=SRout}.
$$

### (4) 两条指令执行阶段最少周期

#### `sub R1, R3, (R2)`

第二源操作数位于主存，地址来自 R2。最短数据生命周期可以概括为：

```text
R2 -> MAR / memory read
R3 -> T
MDR -> ALU with T -> SR
SR -> R1
```

受单总线和存储器访问阶段约束，至少需要：

$$\boxed{4\text{ 个时钟周期}}.$$

#### `inc R1`

自增只需把 R1 送入 ALU，产生 `R1+1`，再把结果经 SR 写回：

```text
R1 -> ALU/SR
SR -> R1
```

至少：

$$\boxed{2\text{ 个时钟周期}}.$$

## Verification

三类独立检查：

1. **编码长度**：`0240H / 0488H / 06EAH` 都恰好是 16 bit，没有越出定长指令格式。
2. **寻址语义**：只有 `(R1)` 那个源操作数要求 memory read；寄存器直接操作数不应凭空增加访存。
3. **周期下界**：`sub R1,R3,(R2)` 比 `inc R1` 多出的成本来自“间接地址 -> 主存取数 + 二元操作数暂存”，与数据路径机制一致。

## Compression

```text
machine-code problem
-> cut instruction fields first
-> fill opcode / mode / register ID
-> then hex

microcycle problem
-> write operand source path
-> respect one-bus-source-per-cycle
-> add memory stage for register indirect
-> count state transitions
```

复原检查：如果把 `(R2)` 改成 `R2`，哪一步消失？——主存读路径消失，执行阶段所需周期应重新缩短。

## 易错边界

- ISA 编码与微操作控制是两个层次；机器码不能从控制信号反猜。
- `(R1)` 是“R1 中存地址”，不是“R1 自身数据”。
- “3 操作数指令”不等于固定 3 周期；周期取决于数据来源、单总线冲突和中间锁存。
