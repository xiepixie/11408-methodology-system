# 408-2015-Q38

> 原题：[[../2015 年全国硕士研究生招生考试#38|Q38]]

## 模型锚点

- Topic：NET04｜CIDR 最长前缀匹配。
- 题目信号：同一前缀族 `/23 /25 /27` 加默认路由，目的地址为 `169.96.40.5`。
- 第一动作：先判断每条路由是否匹配，再在所有匹配项中选 prefix length 最大者；不要按表顺序或下一跳猜。

## 解题链

目的地址 `169.96.40.5` 落在：

- `169.96.40.0/23`；
- `169.96.40.0/25`；
- `169.96.40.0/27`。

其中 `/27` 的地址范围是：

```text
169.96.40.0 ~ 169.96.40.31
```

显然包含 `.5`，且 27 位前缀比 25、23 更长，因此优先选择 `/27` 项，对应接口 S3。

默认路由 `/0` 只在没有更具体匹配时兜底。

## 选项判断

故选 $\boxed{C}$。

## 校验

`/27` 每块 32 个地址，`.5` 与 `.0` 属同一个 0～31 地址块；这是对匹配关系的独立范围检查。

## 压缩

```text
routing lookup
-> collect all matching prefixes
-> choose longest prefix
-> default only if no specific route wins
```

## 易错边界

最长前缀匹配比较的是**匹配前缀长度**，不是路由表中谁排在前面，也不是哪条下一跳“看起来更近”。
