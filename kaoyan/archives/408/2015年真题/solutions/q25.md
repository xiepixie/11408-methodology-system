# 408-2015-Q25

> 原题：[[../2015 年全国硕士研究生招生考试#25|Q25]]

## 模型锚点

- Topic：OS01｜进程状态迁移的等待条件模型。
- 题目信号：问“执行态 -> 就绪态”的事件。
- 第一动作：先问离开 Running 后还缺不缺外部条件：只缺 CPU 是 Ready；还缺资源/I/O 是 Blocked。

## 解题链

A 执行 P(wait) 若资源不可用，会等待同步条件，进入阻塞态。

B 申请内存失败若需等待资源可用，本质也是等待资源条件，不是单纯失去 CPU。

C 启动 I/O 后进程通常等待设备完成，进入阻塞态。

D 被高优先级进程抢占时，原进程本身仍然具备继续执行所需的一切条件，只是 CPU 被夺走，因此从 Running 转入 Ready。

## 选项判断

故选 $\boxed{D}$。

## 校验

用资格检查：把 CPU 立刻重新给被抢占进程，它可以继续运行；而对正在等 I/O/P 操作的进程，即使立刻给 CPU，也无法完成原等待条件。

## 压缩

```text
Running leaves CPU
-> still runnable? Ready
-> waiting external/resource event? Blocked
-> preemption => Ready
```

## 易错边界

“没有在 CPU 上运行”不能区分 Ready 和 Blocked；真正边界是**除了 CPU 之外是否还缺条件**。
