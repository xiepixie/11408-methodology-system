# 408-2015-Q47

> 原题：[[../2015 年全国硕士研究生招生考试#47|Q47]]

## 模型锚点

- Topic：NET04｜DHCP bootstrap + ARP next-hop + subnet/gateway Scope。
- 题目信号：同一 LAN 内给出静态 IP/MAC、DHCP 动态地址池，并让主机分别访问 Internet 与本地 WWW。
- 第一动作：每一问重新锁定 Scope：`/24 可用主机地址`、`未配置主机的 DHCP bootstrap`、`当前二层 next hop`、`destination local or remote`。

## 问题表征

题图所在 LAN 为：

$$111.123.15.0/24.$$

静态占用：

```text
Router inside interface : 111.123.15.1/24
Host 1                  : 111.123.15.2/24
WWW server              : 111.123.15.3/24
DHCP server             : 111.123.15.4/24
```

路由器内网接口 MAC：

```text
00-a1-a1-a1-a1-a1
```

另一个已标注 MAC `00-b1-...` 属于其他图中对象，不是主机访问 Internet 时的第一跳网关 MAC。

/24 中：

```text
network   = 111.123.15.0
broadcast = 111.123.15.255
usable    = .1 ~ .254
```

因此 DHCP 最大动态池还要排除已静态占用的 `.1~.4`。

## 关键决策

1. **DHCP Discover 的 IP endpoint 不能用“即将获得的地址”**：发送时主机仍未配置 IP。
2. **访问 Internet 的以太网目的 MAC 不是远端 Internet 主机 MAC**：二层帧只需要送到当前 LAN 的下一跳网关。
3. **ARP 表为空时，第一帧不是数据帧，而是 ARP Request 广播。**
4. **访问本地 WWW 是否依赖默认网关？** 不依赖。若目的 IP 与主机在同一子网，主机直接 ARP 目的主机并二层交付。

## 求解链

### (1) DHCP 地址范围与 Discover IP 地址

/24 的可用主机地址为 `.1~.254`。

已有静态地址：

```text
.1 router
.2 host1
.3 WWW
.4 DHCP
```

因此主机 2～N 可动态分配的最大连续范围：

$$
\boxed{111.123.15.5\sim111.123.15.254}.
$$

主机 2 尚未获得地址时发送 DHCP Discover：

- 源 IP：

$$\boxed{0.0.0.0}$$

- 目的 IP：

$$\boxed{255.255.255.255}$$

这就是 DHCP bootstrap 的“我还不知道自己是谁，也不知道 DHCP server 在哪里”的初始 Scope。

### (2) ARP 表为空时访问 Internet

主机 2 判断 Internet 目的地址不在本地 `/24`，因此下一跳是默认网关 `111.123.15.1`。

但 ARP 表为空，尚不知道网关 IP 对应的 MAC，所以**第一个以太网帧**是 ARP Request，目的 MAC 必须广播：

$$
\boxed{FF-FF-FF-FF-FF-FF}.
$$

收到网关 ARP Reply 后，真正封装“主机 2 -> Internet”的 IP 分组时，当前二层帧目的 MAC 是路由器内网接口：

$$
\boxed{00-a1-a1-a1-a1-a1}.
$$

注意 IP 目的地址仍然是最终 Internet 主机；只是在每一跳重写二层头。

### (3) Host 1 配置错误网关后的可达性

Host 1：

```text
IP   = 111.123.15.2
mask = 255.255.255.0
configured gateway = 111.123.15.2   // 错
correct router      = 111.123.15.1
```

#### 能否访问 WWW 服务器？

WWW = `111.123.15.3/24`。

Host 1 用 `/24` 判断：

```text
111.123.15.2 & /24 = 111.123.15.0
111.123.15.3 & /24 = 111.123.15.0
```

目的属于同一子网，所以 Host 1 直接 ARP WWW 的 MAC 并发送，不需要默认网关。

因此：

$$\boxed{\text{能访问 WWW 服务器}}.$$

#### 能否访问 Internet？

Internet 目的地址不在本地 `/24`，必须交给默认网关。

但 Host 1 把 gateway 错配成 `111.123.15.2`，即自己的地址，而真正路由器是 `.1`。于是不存在一个正确的 L3 next hop 把分组转发到外网。

因此：

$$\boxed{\text{不能访问 Internet}}.$$

## 校验

用“本地/远端”双分支检查：

```text
WWW .3
-> same /24
-> direct delivery
-> gateway irrelevant

Internet
-> outside /24
-> must use router
-> gateway misconfigured
-> fail
```

再检查 DHCP 地址池容量：`.5~.254` 共 250 个地址，`.0/.255` 保留，`.1~.4` 静态占用，地址空间没有重叠。

## 压缩

```text
DHCP bootstrap:
no IP yet -> 0.0.0.0 -> 255.255.255.255

remote IP delivery:
destination outside subnet
-> next hop = default gateway
-> ARP empty: first frame broadcast ARP
-> data frame dst MAC = gateway MAC

local IP delivery:
same subnet -> ARP destination directly -> gateway not used
```

复原检查：若 WWW 改到另一个子网，即使 WWW 地址本身配置正确，Host 1 也会因为默认网关错误而同样无法访问它。

## 易错边界

- IP 目的地址表示端到端终点；Ethernet 目的 MAC 表示**当前链路下一跳**。
- DHCP Discover 的源 IP 不是主机最终租到的地址。
- 默认网关只参与远端网络交付；同网段主机间通信不经过网关。
