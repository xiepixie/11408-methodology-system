# 408-2015-Q41

> 原题：[[../2015 年全国硕士研究生招生考试#41|Q41]]

## Model Anchor

- Topic：DS01/DS10｜单链表删除 + 有界值域直接定位。
- 题目信号：链表有 $m$ 个整数，且给出非常强的边界 $|data|\le n$；要求“绝对值相同只保留第一次”，并追求尽可能高效。
- 第一动作：先问是否真的需要两两比较。既然去重键 $|data|$ 落在有限域 $[0,n]$，就用 `seen[abs(data)]` 把“以前出现过吗”变成 $O(1)$ 状态查询。

## Problem Representation

题目不是普通“链表去重”，真正的 Workload 是：

```text
输入顺序：必须保留
等价关系：x ~ y iff |x| = |y|
保留策略：每个等价类只保留第一次出现的结点
值域：key = |data| ∈ [0,n]
```

因此需要维护的最小状态只有：

```text
seen[k] = 0/1
```

表示绝对值 $k$ 是否已经出现。

链表修改还需维护：

```text
pre = 当前结点的前驱
p   = 当前待检查结点
```

不变量：扫描到 `p` 之前的链表中，每种绝对值最多保留一个结点，而且保留下来的必然是第一次出现者。

## Decision Points

1. **为什么不用双重扫描？** 朴素做法对每个结点向后找同绝对值结点，最坏 $O(m^2)$；题目给出的 $|data|\le n$ 正是在提示可以直接寻址。
2. **为什么索引用 `abs(data)`？** 题目定义的重复关系是绝对值相等；`3` 与 `-3` 必须映射到同一状态槽。
3. **删除后为什么不能推进 `pre`？** 当前结点被删后，`pre->next` 已经变成下一个待检查结点；若 `pre` 同时前移，会丢失正确前驱。
4. **空间为什么是 $O(n)$ 而不是 $O(m)$？** 辅助数组由键值域大小决定。

## Solution Chain

### (1) 基本设计思想

申请长度为 $n+1$ 的布尔/整型数组 `seen`，初值全 0。

从链表首个数据结点开始顺序扫描：

- 若 `seen[abs(p->data)] == 0`：这是该绝对值第一次出现，保留结点，并把对应槽置 1；
- 否则：该绝对值此前出现过，删除当前结点。

因此只需一趟链表扫描。

### (2) 结点定义

```c
typedef struct LNode {
    int data;
    struct LNode *next;
} LNode, *LinkList;
```

假设 `head` 为带头结点的单链表头指针。

### (3) 算法

```c
void removeSameAbs(LinkList head, int n) {
    bool *seen = (bool *)calloc(n + 1, sizeof(bool));

    LNode *pre = head;
    LNode *p = head->next;

    while (p != NULL) {
        int key = abs(p->data);       // 0 <= key <= n

        if (!seen[key]) {
            // 第一次出现：保留
            seen[key] = true;
            pre = p;
            p = p->next;
        } else {
            // 已出现：删除当前结点，但 pre 不前移
            pre->next = p->next;
            free(p);
            p = pre->next;
        }
    }

    free(seen);
}
```

### (4) 正确性

维护扫描不变量：

> 在每轮开始时，`pre` 之前（含 `pre`）已经处理完成；每个已出现的绝对值恰好保留其第一次出现的结点，`seen` 与已处理前缀中的绝对值集合一致。

若当前 key 未出现，则保留并登记，不变量继续成立；若已经出现，则当前一定不是第一次，删除它也不改变“每类保留第一次”的结论。

扫描结束时整个链表都满足要求。

### (5) 复杂度

链表每个结点只访问一次：

$$T(m,n)=O(m).$$

辅助状态数组大小为 $n+1$：

$$S(m,n)=O(n).$$

这比不利用值域约束的 $O(m^2)$ 双重扫描更高效。

## Verification

用最小样例：

```text
1 -> -2 -> 2 -> -1 -> 3
```

状态演化：

```text
1   : seen[1]=0 -> keep
-2  : seen[2]=0 -> keep
2   : seen[2]=1 -> delete
-1  : seen[1]=1 -> delete
3   : seen[3]=0 -> keep
```

结果：

```text
1 -> -2 -> 3
```

既保留了每个绝对值第一次出现者，也保持了原相对顺序。

## Compression

```text
|data| <= n + keep first by |data|
-> key = abs(data)
-> direct-address seen[0..n]
-> one-pass linked-list scan
-> duplicate: unlink, pre stays
-> O(m) time / O(n) space
```

复原检查：若题目删掉 $|data|\le n$ 这一有限值域条件，`seen` 直接寻址就不再是自然选择，应重新比较哈希集合与排序等表示。

## 易错边界

- `seen[data]` 错：负值无法直接索引，而且 `3/-3` 必须视为同一类；应使用 `seen[abs(data)]`。
- 删除当前结点后不能同时推进 `pre`。
- Legacy 代码把 `link/next` 字段写法混用，并在文字中一度出现 `q[data]`；正式题解统一为一个结点合同并按绝对值索引。
