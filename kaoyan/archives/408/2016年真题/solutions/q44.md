# 408-2016-Q44

> 原题：[[../2016 年全国硕士研究生招生考试#44|Q44]]

## 模型锚点

- Topic：CO-08｜异步串行帧、设备服务率与中断 I/O 时间线。
- 题目信号：`50 MHz + CPI=4 + device latency=0.5 ms + interrupt response 10 cycles + ISR 20 instructions + 第15条重新启动设备`。
- 第一动作：画两条时间线：**设备何时能产生下一个字符**与**CPU 每字符实际占用多少周期**；墙钟完成时间和 CPU 占用时间不能混算。

## 问题表征

```text
clock = 50 MHz -> 1 cycle = 20 ns
ASCII data = 7 bit
async framing = 1 start + 7 data + 1 parity + 1 stop
D start -> char in I/O port = 0.5 ms = 25,000 cycles
interrupt response = 10 cycles
ISR = 20 instructions, CPI=4 -> 80 CPU cycles
15th ISR instruction starts D again -> restart point after 60 ISR cycles
```

两个不同成本：

```text
wall-clock production interval:
device 25,000 + response 10 + first 15 ISR instructions 60

CPU work per character:
response 10 + all 20 ISR instructions 80
```

## 关键决策

- 第 (1) 问的串行线上帧长度必须包含 start bit；“7 位 ASCII + parity + stop”还不是完整异步字符帧。
- 第 (2) 问“完成 1000 字符所需时间”由设备和 CPU 重叠后的**关键路径**决定；CPU 占用时间则只累加 CPU 真正执行响应/ISR 的周期。
- 第 15 条指令启动下一次设备工作，所以最后 5 条 ISR 可以与设备的下一个 0.5 ms 工作阶段重叠，不能把整段 ISR 都串进字符间隔。

## 求解链

### (1) 每字符位数与设备最大字符率

异步字符帧：

$$1+7+1+1=\boxed{10\text{ bit}}.$$

设备从收到启动命令到把一个字符送入端口需 0.5 ms，因此持续工作时：

$$\frac1{0.5\text{ ms}}=\boxed{2000\text{ character/s}}.$$

### (2) 1000 个字符的完成时间

CPU 时钟周期：

$$T_{clk}=\frac1{50\text{ MHz}}=20\text{ ns}.$$

设备工作 0.5 ms 对应：

$$\frac{0.5\text{ ms}}{20\text{ ns}}=25\,000\text{ cycles}.$$

从一个字符开始设备工作，到 ISR 第 15 条指令再次启动下一字符，关键间隔约为：

$$25\,000+10+15\times4=25\,070\text{ cycles}.$$

因此 1000 字符任务的总墙钟时间约：

$$\boxed{25\,070\,000\text{ cycles}}.$$

如果把最后一个字符 ISR 剩余 5 条指令也精确计到“任务完全处理完”的终点，则会再多约 20 cycles；题目问“大约”，二者不影响核心时间模型。

### CPU 实际用于该任务的周期

每字符 CPU 工作：

$$10+20\times4=90\text{ cycles}.$$

1000 字符：

$$\boxed{90\,000\text{ cycles}}.$$

其余绝大多数时间 CPU 可以执行别的程序或等待设备事件，不属于本 I/O 任务的 CPU 占用。

### 中断响应阶段

按 408 的硬件入口抽象，主要包括：

1. 按体系结构要求屏蔽/关闭可屏蔽中断；
2. 保存异常/中断断点及程序状态（典型为 PC、PSW）；
3. 识别/取得中断源或中断向量，转入相应 ISR。

完整通用寄存器现场的进一步保存通常属于进入 ISR 后的软件工作，不与硬件响应阶段混写。

## 校验

### 量级检查

设备最多 2000 字符/s，1000 字符本身就需要约 0.5 s。CPU 50 MHz 下：

$$0.5\text{ s}\times50\text{ MHz}=25\text{ M cycles},$$

因此总时间约 25.07 M cycles 的数量级正确。

### CPU 利用检查

CPU 只花 90,000 cycles：

$$90\,000/50\text{ MHz}=1.8\text{ ms},$$

远小于设备约 0.5 s 的墙钟时间，符合“低速设备 + 中断 I/O”的设计目的。

## 压缩

```text
中断 I/O 综合题
-> frame bits
-> device service interval
-> interrupt response
-> ISR restart point
-> wall-clock critical path 与 CPU occupancy 分账
```

## 易错边界

- “任务经历了多少周期”不等于“CPU 被该任务占用了多少周期”。
- ISR 的第 15 条指令已经重新启动设备，后 5 条指令与设备工作可以重叠。
