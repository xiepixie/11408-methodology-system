# 408-2016-Q41

> 原题：[[../2016 年全国硕士研究生招生考试#41|Q41]]

## 模型锚点

- Topic：NET-06 / NET-07｜TCP 字节序号、接收窗口、拥塞窗口与连接关闭时间线。
- 题目信号：`20 KB receive buffer + MSS=1 KB + RTT=200 ms + initial seq=100 + ssthresh=32 KB` 同时出现。
- 第一动作：建立三张账：`SEQ/ACK 字节坐标`、`rwnd/cwnd/send-window`、`RTT event timeline`；每一问只从对应状态 Owner 取值。

## 问题表征

```text
MSS = 1 KB
S receive buffer = 20 KB, only fills and never drains
RTT = 200 ms, one-way delay = 100 ms
H3 ISN = 100
ssthresh = 32 KB
classic slow start: cwnd0 = 1 MSS = 1 KB
S ACKs every received segment
```

关键合同：

```text
SYN consumes 1 sequence number
first data byte seq = 101
rwnd = remaining receive-buffer capacity
send window upper bound = min(cwnd, rwnd)
slow start: each ACK of new data adds 1 MSS to cwnd
```

## 关键决策

- 窗口和序号都以**字节**计；MSS 只是在本题中把 1 KB 数据组织成一个段，不能把 ACK 序号当“第几个段”。
- 第 (3) 问发送窗口最终归零不是因为拥塞，而是 S 的 20 KB 接收缓存被填满；因此停止条件由 `rwnd=0` 拥有。
- 平均速率必须保持单位合同：`20 KB / 1 s = 20 KB/s`，换成 bit/s 时还要乘 8；不能把 KB/s 与 kb/s 直接改前缀。

## 求解链

### (1) 第二次握手

H3 首先发送：

```text
SYN=1, seq=100
```

SYN 占用一个序号，所以 S 的第二次握手必须确认下一期待序号：

$$ack=101.$$

第二次握手本身同时用于建立 S→H3 方向的同步，因此：

$$\boxed{SYN=1,\ ACK=1,\ ack=101}.$$

### (2) 第 8 个 ACK 后的三个窗口

S 每收到 1 KB 数据，接收缓存减少 1 KB。收到 8 KB 后：

$$rwnd=20-8=\boxed{12\text{ KB}}.$$

慢开始初始 `cwnd=1 KB`，每个新数据 ACK 增加 1 MSS。收到第 8 个 ACK 后：

$$cwnd=1+8=\boxed{9\text{ KB}}.$$

发送窗口受两者共同限制：

$$W_{send}=\min(cwnd,rwnd)=\min(9,12)=\boxed{9\text{ KB}}.$$

### (3) 零窗口时的下一序号与平均速率

20 KB 接收缓存最终全部装满。首个数据字节序号为 101，因此 20 KB 数据共占用：

$$20\times1024=20480$$

个字节序号。下一待发送字节序号：

$$101+20480=\boxed{20581}.$$

按 RTT 观察慢开始发送批次：

```text
Round 1: 1 KB
Round 2: 2 KB
Round 3: 4 KB
Round 4: 8 KB
Round 5: 5 KB   <- receiver buffer remaining capacity
Total  : 20 KB
```

从第 1 批发出到最后 5 KB 被确认、H3 得知 `rwnd=0`，共 5 个 RTT：

$$5\times200\text{ ms}=1\text{ s}.$$

平均数据速率：

$$\boxed{20\text{ KB/s}}.$$

若换成十进制 `kb/s`：

$$20\times1024\times8=\boxed{163.84\text{ kb/s}}.$$

### (4) S 最早何时释放连接

H3 在 t 时刻主动发 FIN。忽略报文发送时间，单向传播为 `RTT/2=100 ms`。

最短关闭事件链：

```text
t+100 ms : S 收到 H3 FIN，立即 ACK，并可立即发送自己的 FIN
t+200 ms : H3 收到 S FIN，立即发送最终 ACK
t+300 ms : S 收到最终 ACK，释放连接
```

所以：

$$\boxed{300\text{ ms}=1.5\,RTT}.$$

## 校验

### 字节序号守恒

H3 SYN 使用 100，数据从 101 开始；20 KB=20480 B，所以最后数据字节序号为：

$$101+20480-1=20580,$$

下一字节正好 20581。

### 缓存与窗口守恒

五轮发送量：

$$1+2+4+8+5=20\text{ KB},$$

恰好填满 S 的接收缓存，因此最后 `rwnd=0`，停止原因与题设一致。

### 单位检查

`20 KB/s` 必须是约 `160 kb/s` 量级；若得到 `20.48 kb/s`，说明把 byte/s 换成 bit/s 时漏乘了 8。

## 压缩

```text
TCP 综合题
-> SEQ/ACK 字节账
-> rwnd/cwnd/FlightSize 窗口账
-> RTT 时间线
-> 关闭时再切 FIN/ACK 状态机
```

## 易错边界

- `rwnd` 保护接收端缓存，`cwnd` 保护网络拥塞，两者 Owner 不同；发送上限取较小者。
- MSS 是段的最大数据量，不把 TCP 字节序号变成“段编号”。
- `KB/s` 与 `kb/s` 差一个 `×8` 的 bit/byte 转换。
