# 408-2016-Q25

> 原题：[[../2016 年全国硕士研究生招生考试#25|Q25]]

## Model Anchor

- Topic：OS-03｜资源等待图与死锁环。
- 题目信号：每个资源只有 1 个实例，问“若发生死锁，最少几个进程在环中”。
- 第一动作：不要从进程总数猜；先问能否构造 2 进程等待环，再找最短可行资源环。

## 解题链

两进程死锁要求：两个进程各持有对方还需要的资源，形成长度 2 的 circular wait。

检查需求集合：

```text
P1: {R1,R2}
P2: {R2,R3}
P3: {R1,R3}
P4: {R2}
```

任意两个需要两个资源的进程都只共享 1 个资源，没有一对能各持一种、再互等另一种形成 2 环；P4 只需要 R2，更不可能成为“持一个再等一个”的环成员。

但 3 环可以构造：

```text
P1 持 R1，等 R2
P2 持 R2，等 R3
P3 持 R3，等 R1
```

因此最少 3 个进程。

## 选项判断

故选 $\boxed{C}$。

## Verification

上述 3 环中每个进程都等待另一个环成员持有的唯一资源，没有任何一个能先完成并释放资源；死锁条件闭合。

## Compression

```text
最少死锁进程数
-> 先找最短 wait-for cycle
-> 2-cycle 不可构造？
-> 再尝试 3-cycle
```

## 易错边界

“系统里有 4 个进程”不意味着死锁必须包含 4 个；真正决定数量的是等待图中最短可形成的有向环。
