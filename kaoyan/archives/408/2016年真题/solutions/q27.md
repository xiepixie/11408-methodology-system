# 408-2016-Q27

> 原题：[[../2016 年全国硕士研究生招生考试#27|Q27]]

## Model Anchor

- Topic：OS-03｜TSL 自旋锁与等待语义。
- 题目信号：`while (TSL(&lock));` 是原子测试并置位循环，失败时线程仍持续执行循环。
- 第一动作：先判断等待者进入的是 **Blocked** 还是仍占 CPU 的 **busy waiting**。

## 解题链

当 `lock=TRUE` 时，等待进程不断执行 `TSL(&lock)`：

```text
check -> failed -> check again -> ...
```

它没有调用阻塞/睡眠原语，因此不会主动放弃 CPU，这正是自旋等待。

- A 错：退出临界区只是把 `lock=FALSE`，没有显式唤醒某个阻塞进程，因为等待者本来就不是以这种机制阻塞；
- B 对：等待者忙等，不主动让出 CPU；
- C 错：忙等不满足“让权等待”；
- D 错：TSL 指令自身提供原子读改写，不需要靠整个自旋期间关中断来保证互斥。

## 选项判断

故选 $\boxed{B}$。

## Verification

若等待者会 Blocked，则代码里必须存在“进入等待队列/睡眠”的机制；当前伪代码只有原子 TSL 循环，没有任何这样的状态迁移入口。

## Compression

```text
TSL spinlock
-> failed acquire 不睡眠
-> busy wait / 不让权
-> 原子性由 TSL 提供
```

## 易错边界

“互斥正确”与“等待方式友好”是两件事。TSL 可以实现互斥，但会消耗 CPU，自旋时间长时成本很高。
