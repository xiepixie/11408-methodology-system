# 408-2016-Q30

> 原题：[[../2016 年全国硕士研究生招生考试#30|Q30]]

## Model Anchor

- Topic：OS-03｜共享对象与 R/W conflict graph。
- 题目信号：四个选项把局部变量、同进程共享全局变量、跨进程同名变量混在一起。
- 第一动作：先确认两个操作是否访问**同一个对象**，再判断访问类型是否形成 R-W / W-W 冲突。

## 解题链

- A：Thread1 与 Thread2 的 `a` 都是各自线程栈上的局部变量，不是同一对象；
- B：`a=x` 与 `b=x` 都只读取 P2 的共享 `x`，R-R 可并发；
- C：P1 的两个线程都对同一个 `x` 执行 `x += ...`，它是 read-modify-write，若交错会发生 lost update，必须互斥；
- D：P1 与 P2 属于不同进程，各自定义的全局 `x` 位于不同地址空间，默认不是同一对象。

## 选项判断

需要互斥的是 `x+=1` 与 `x+=2`，故选 $\boxed{C}$。

## Verification

设 P1 的 `x=0`。若两个 `x+=` 都先读到 0，再分别写回 1 和 2，最终可能得到 1 或 2，而不是串行语义下的 3，直接构成竞态反例。

## Compression

```text
并发互斥题
-> same object?
-> access type?
-> R-R 可并发
-> R-W / W-W 才画冲突边
```

## 易错边界

变量名字相同不等于对象相同；线程共享进程地址空间，而不同进程默认有彼此独立的虚拟地址空间。
