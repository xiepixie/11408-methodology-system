# 408-2016-Q47

> 原题：[[../2016 年全国硕士研究生招生考试#47|Q47]]

## 模型锚点

- Topic：OS-06/07｜目录命名、FAT 链接分配与文件内偏移定位。
- 题目信号：`directory entry = name + first cluster`，其余簇号由 FAT 串起来；又问按名访问第 5000 字节。
- 第一动作：先分三层对象：`pathname -> directory entry -> first cluster -> FAT chain`；再把文件内字节偏移映射到第几个簇。

## 问题表征

由题图可恢复：

```text
dir   first cluster = 1
  └── dir1 first cluster = 48
        ├── file1 first cluster = 100, chain 100 -> 106 -> 108
        └── file2 first cluster = 200, chain 200 -> 201 -> 202

cluster size = 4 KB = 4096 B
FAT entry = 2 B = 16 bit cluster number
```

目录只拥有“名字 → 第一个簇号”；后继簇号属于 FAT。

## 关键决策

- 第 (2) 问先由 FAT 表项宽度得到**可编号簇数**，再乘每簇 4 KB；不要拿 FAT 自身长度直接当文件最大长度。
- 第 (3) 问 `106`、`108` 是**next-cluster value**，要找“哪个 FAT index 保存它”，因此答案分别是前驱簇的表项。
- 第 (4) 问 FAT 已在内存，所以无需读取前面的数据簇来“顺着链找下一簇”；只需访问尚未在内存的目录簇和真正包含目标字节的数据簇。

## 求解链

### (1) 所有目录文件的内容

`dir` 目录文件保存其直接孩子 `dir1` 的名字与首簇号：

| 文件名 | 第一个簇号 |
|---|---:|
| dir1 | 48 |

`dir1` 目录文件保存两个直接用户文件：

| 文件名 | 第一个簇号 |
|---|---:|
| file1 | 100 |
| file2 | 200 |

目录项不需要把文件后续所有簇号重复写入；这些链接由 FAT 拥有。

### (2) FAT 最大长度与最大文件长度

每个 FAT 表项占 2 B，能够保存 16 位簇号，因此按题设抽象最多有：

$$2^{16}$$

个可编号簇。

FAT 最大长度：

$$2^{16}\times2\text{ B}=2^{17}\text{ B}=\boxed{128\text{ KB}}.$$

若一个文件能够链接使用全部 $2^{16}$ 个簇，每簇 4 KB，则最大文件长度：

$$2^{16}\times4\text{ KB}=2^{28}\text{ B}=\boxed{256\text{ MB}}.$$

### (3) 106、108 分别保存在哪个 FAT 表项

file1 的簇链：

```text
100 -> 106 -> 108 -> EOF
```

FAT 的规则是：

```text
FAT[current_cluster] = next_cluster
```

因此：

$$\boxed{FAT[100]=106},$$

$$\boxed{FAT[106]=108}.$$

也就是说，簇号 106 存在 FAT 的第 100 项，簇号 108 存在第 106 项。

### (4) 读取 `dir/dir1/file1` 的第 5000 个字节需访问哪些簇

题设已说明 FAT 和 `dir` 目录文件在内存。

第一步解析 `dir1`：`dir` 已在内存，从中得到 `dir1` 的首簇号 48；但 `dir1` 目录内容尚不在内存，因此需要访问：

$$\boxed{48}.$$

从簇 48 的目录项得到：

```text
file1 -> first cluster 100
```

文件簇大小 4096 B：

```text
第 1～4096 字节   -> cluster 100
第 4097～8192 字节 -> cluster 106
```

第 5000 个字节属于第二个文件簇。由于 FAT 已在内存，可直接由 `FAT[100]=106` 知道下一簇是 106，不必为了找链而读取簇 100。

因此还需访问：

$$\boxed{106}.$$

总磁盘簇访问：

$$\boxed{48,\ 106}.$$

## 校验

### 容量守恒

`2 B/entry × 2^16 entries = 128 KB`；每个编号对应一个 4 KB 簇，所以可寻址数据容量为：

$$2^{16}\times2^{12}=2^{28}\text{ B}=256\text{ MB}.$$

### 文件偏移检查

第 5000 个字节在第二簇内的 1-based 位置：

$$5000-4096=904,$$

确实落在簇 106 中，不需要读取第三簇 108。

## 压缩

```text
FAT 按名访问
-> pathname 逐级读 directory
-> directory entry 只给 first cluster
-> FAT[current] 给 next cluster
-> file offset / cluster size 定位第几簇
```

## 易错边界

- 目录项中的“第一个簇号”和 FAT 中的“后继簇号”由不同对象拥有。
- FAT 已在内存时，沿链查后继不等于必须把每个前序数据簇从磁盘读出来。
