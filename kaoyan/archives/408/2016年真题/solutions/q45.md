# 408-2016-Q45

> 原题：[[../2016 年全国硕士研究生招生考试#45|Q45]]

## 模型锚点

- Topic：CO-07 × CO-06｜地址翻译、TLB 与 Cache 字段预算。
- 题目信号：`VA 32 bit / PA 24 bit / page 8 KB / TLB fully associative / Cache 64 KB 2-way / block 64 B` 同时出现。
- 第一动作：严格按层分账：**先页大小切 VA/PA，再由 Cache block 与 set 数切 PA**；每一字段只从自己的地址 Owner 取位。

## 问题表征

```text
page size = 8 KB = 2^13 B
VA = 32 bit -> VPN 19 bit + page offset 13 bit
PA = 24 bit -> PFN 11 bit + page offset 13 bit

Cache data = 64 KB
block = 64 B = 2^6 B
2-way
sets = 64 KB / (64 B * 2) = 512 = 2^9
PA Cache split = tag 9 | set 9 | block offset 6
```

图中字段按这一层级映射：

```text
A = VPN width
B = TLB tag width
C = PFN width
D = page offset width
E = Cache tag width
F = Cache set index width
G = block offset width
```

## 关键决策

- TLB 全相联意味着查找时**没有 TLB set index**，所以整个 VPN 都作为匹配标记 B。
- Cache 是物理地址投影：先得到 PA，再把主存块号拆成 `Cache tag + set index`；不能把 VPN 直接拿来做 Cache tag。
- 第 (4) 问不是“Cache 永远应直写”，而是比较两层 backing store 的写入代价：主存尚可承受逐次同步写，磁盘绝不能跟着每次内存写同步更新页面。

## 求解链

### (1) A～G 位数与 TLB 字段 B

页大小：

$$8\text{ KB}=2^{13}\text{ B},$$

所以页内偏移：

$$D=13.$$

虚页号：

$$A=32-13=19.$$

TLB 全相联，不需要组索引，标记 B 保存整个虚页号：

$$B=19.$$

物理页框号：

$$C=24-13=11.$$

Cache：

$$G=\log_2 64=6,$$

$$F=\log_2\frac{64\text{ KB}}{64\text{ B}\times2}=\log_2 512=9,$$

$$E=24-F-G=24-9-6=9.$$

因此：

$$\boxed{A=19,\ B=19,\ C=11,\ D=13,\ E=9,\ F=9,\ G=6}.$$

B 中保存的是：

$$\boxed{虚页号\ VPN}.$$

### (2) 主存块 4099 映射到哪个 Cache 组，H 是什么

2 路组相联共有 512 组。主存块号 `4099` 写成：

$$4099=8\times512+3.$$

所以：

$$set=4099\bmod512=\boxed{3}.$$

Cache tag 为块号除以组数的商：

$$tag=\left\lfloor4099/512\right\rfloor=8.$$

E/H 为 9 位时：

$$\boxed{H=000001000_2}.$$

### (3) Cache miss 与 page fault 哪个代价更大

Page fault 代价远大于 Cache miss。

- Cache miss：通常向下一层主存取一个 block；
- page fault：页面不在主存，需要 OS 参与并访问外存/磁盘，把整页调入主存，可能还伴随 victim 回写。

因此：

$$\boxed{Page\ Fault\ Cost\gg Cache\ Miss\ Cost}.$$

### (4) 为什么 Cache 可直写，而页面修改采用回写

Cache→主存层中，若采用 write-through，每次 Cache 写都同步更新主存。虽然有额外流量，但主存延迟仍远低于磁盘，且可以配合 write buffer。

主存→磁盘层若对页面采用“每次内存写都同步写磁盘”，单次普通 store 都可能触发极慢 I/O，系统无法接受。因此虚拟内存只把页标脏，等页面需要换出时再整页回写。

所以页面采用：

$$\boxed{Write\ Back}.$$

## 校验

### 位宽守恒

$$19+13=32,$$

$$11+13=24,$$

$$9+9+6=24.$$

三个地址切分都精确回到原地址宽度。

### Cache 映射守恒

`4099 = tag×512 + set = 8×512+3`，所以 tag=8、set=3 一一对应。

## 压缩

```text
TLB + Cache 综合题
-> page size 切 VPN/offset
-> PA 形成后切 Cache tag/set/offset
-> fully associative TLB: whole VPN as tag
-> miss/fault 比成本 Owner
```

## 易错边界

- TLB miss、Cache miss、page fault 是三个不同层级的“缺失”；不能看到 miss 就默认访问磁盘。
- Cache 的写策略和 VM dirty-page 回写策略处在不同层次，不能用同一延迟假设互推。
