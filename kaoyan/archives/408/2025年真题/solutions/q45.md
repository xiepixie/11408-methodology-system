# 408-2025-Q45

> 原题：[[../2025 年全国硕士研究生招生考试#45（本题 7 分）|Q45]]

## Model Anchor

- Topic：[[../../../../30_408/30_操作系统/20_并发同步与死锁/README|OS-03 并发、信号量与 PV]]。
- 题目信号：`挖坑 -> 放苗/填土 -> 浇水` 的流水前驱 + 未填树坑容量 3 + 甲乙共享铁锹。
- 第一动作：先列**坏状态**，再映射最少许可：
  1. 乙在没有坑时操作；
  2. 丙在尚未填土时浇水；
  3. 未填坑超过 3；
  4. 甲、乙同时使用唯一铁锹。

水桶虽然只有 1 个，但只有丙使用，不存在竞争，因此不需要专门的互斥信号量。

## Problem Representation

把甲看成“生产空树坑”的 producer，乙消费空坑并产出“已栽好待浇水的树”，丙再消费后者。

最少需要四类许可：

| 信号量 | 初值 | 含义 |
|---|---:|---|
| `pitSlot` | 3 | 还能新增多少个未填树坑 |
| `dugPit` | 0 | 当前已有多少个可供乙使用的树坑 |
| `waterReady` | 0 | 当前已有多少棵填土完成、等待浇水的树 |
| `shovel` | 1 | 唯一铁锹的互斥使用许可 |

核心容量不变量：

$$0\le dugPit\le3.$$

在动作完成边界上，`pitSlot` 与尚未处理的坑共同表达容量 3。

## Decision Points

- 先区分三类 semaphore 语义：`pitSlot` 是**容量许可**，`dugPit/waterReady` 是**前驱完成事实**，`shovel` 才是**互斥许可**；不能把所有信号量都理解成锁。
- 水桶虽然只有一个，但只有丙会访问，不存在执行流竞争，因此不需要额外 mutex。
- 为最大化并发，铁锹临界区只覆盖真正使用铁锹的“挖坑/填土”；`放树苗()` 不应因为和填土在同一线程就被粗粒度锁住。

## Solution Chain

```c
semaphore pitSlot    = 3;  // 最多允许 3 个尚未填好的树坑
semaphore dugPit     = 0;  // 已挖好、可放苗的树坑数
semaphore waterReady = 0;  // 已填土、等待浇水的树数
semaphore shovel     = 1;  // 甲和乙互斥使用铁锹

void 甲(void) {
    while (1) {
        wait(pitSlot);      // 先取得一个“可新增树坑”许可
        wait(shovel);
        挖树坑();
        signal(shovel);
        signal(dugPit);     // 制造“已有一个树坑”的事实
    }
}

void 乙(void) {
    while (1) {
        wait(dugPit);       // 必须先有树坑

        放树苗();           // 此动作本身不需要铁锹

        wait(shovel);
        填土();
        signal(shovel);

        signal(pitSlot);    // 该未填树坑已被消耗，可再挖一个
        signal(waterReady); // 制造“可以浇水”的事实
    }
}

void 丙(void) {
    while (1) {
        wait(waterReady);   // 必须填土完成后才能浇水
        浇水();             // 只有丙使用水桶，无需额外 mutex
    }
}
```

### Why Correct

- `wait(pitSlot)` 保证甲不能制造第 4 个未填坑；乙完成填土后才归还容量；
- `dugPit` 把“挖坑完成”编码为乙可消费的前驱事实；
- `waterReady` 把“填土完成”编码为丙可消费的前驱事实；
- `shovel=1` 把甲挖坑与乙填土的共享物理资源串行化；
- `放树苗()` 放在取得铁锹之前，避免把不使用铁锹的工作无谓纳入临界区，提高并发度。

## Verification

检查最坏交错：当已经有 3 个未填坑时，`pitSlot=0`，甲会阻塞；乙不需要 `pitSlot` 就能继续消费 `dugPit`、取得铁锹填土并 `signal(pitSlot)`，所以不会形成“甲拿着乙需要的许可睡眠”的死锁环。

## Compression

PV 大题 → **列坏状态 -> 每个“容量/前驱/互斥”各找 Owner -> 初值来自系统一开始已有多少许可 -> P 消费事实，V 制造事实**。

## 易错边界

- `pitSlot` 是容量许可，不是铁锹 mutex；
- `dugPit` 是同步计数，不是共享坑数组的互斥锁；
- “资源只有一个”并不自动需要 semaphore，只有多个执行流会竞争它时才需要互斥。本题水桶只有丙使用。
