# 408-2025-Q29

> 原题：[[../2025 年全国硕士研究生招生考试#29|Q29]]

## Model Anchor

- Topic：[[../../../../30_408/30_操作系统/50_文件系统/README|OS-06/07 文件系统与持久化]]。
- 题目信号：目录 + inode 模型下“新建文件”会更新哪些持久对象。
- 第一动作：先把对象身份和名字拆开：**inode/FCB 保存对象元数据；目录项保存 `filename -> inode number` 的命名关系。**

## 解题链

创建文件 F 时至少要：

1. 分配并初始化 F 的 inode；
2. 在父目录中新建 F 的目录项；
3. 目录项中保存 F 的名字及 inode 号。

因此：

- A 会做：初始化 inode；
- B 会做：目录项需要记录 inode 号；
- **C 不会做：访问权限属于文件对象元数据，应写入 inode/FCB，而不是写进目录文件的命名记录；**
- D 会做：父目录增加一条 F 对应的目录项。

**答案：C。**

## 选项判断

创建文件时目录项只负责“名字 → inode 号”，访问权限属于 inode/FCB 元数据，不写进目录命名记录，因此不会执行 C，选 $\boxed{C}$。

## Verification

设同一个 inode 有两个硬链接。两个目录项名字不同，但权限必须描述同一个文件对象；若权限分别存在每个目录项中，就会出现同一对象拥有两套互相冲突权限。由此可反证权限应属于 inode/对象元数据层。

## Compression

inode 文件系统的 create → **先造对象身份/metadata，再在父目录建立 `name -> inode` 边** → 名字在目录项，权限等对象属性在 inode。

## 易错边界

“目录项”不是“文件所有元数据的汇总”。经典 inode 模型中它主要承担命名映射；文件权限、大小、时间等属于 inode/FCB。
