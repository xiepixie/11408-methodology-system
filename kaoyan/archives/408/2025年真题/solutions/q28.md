# 408-2025-Q28

> 原题：[[../2025 年全国硕士研究生招生考试#28|Q28]]

## Model Anchor

- Topic：[[../../../../30_408/30_操作系统/50_文件系统/README|OS-06/07 文件系统与持久化]]。
- 题目信号：VFS 功能判断。
- 第一动作：先问 VFS 解决的根本矛盾：**底层文件系统实现很多，但应用希望继续调用同一套 `open/read/write/stat` 接口。**

## 解题链

- A 错：VFS 中的“virtual”指统一抽象层，不是“建立在虚拟内存中的文件系统”。
- B 错：统一接口是主要职责；是否更快取决于缓存和具体实现，VFS 本身不能保证提高访问速度。
- **C 对：VFS 对上提供统一文件操作接口，再把请求分派给具体文件系统实现。**
- D 错：VFS 抽象也可以承载网络文件系统，不能限定为只访问本地文件。

**答案：C。**

## 选项判断

VFS 的核心责任是向上提供统一文件操作接口并向下分派到具体文件系统；它不是虚拟内存文件系统，也不保证提速或只支持本地文件，因此选 $\boxed{C}$。

## Verification

如果没有 VFS，每种文件系统都要求应用换一套 API；而现实接口希望 `open/read/write` 不因 ext4、FAT 或网络文件系统而完全改写。这个“统一对象与操作合同”正是 VFS 的存在理由。

## Compression

VFS → **不是虚拟内存，也不是加速器；它是“统一文件 API -> 具体文件系统实现”的抽象/分派层。**

## 易错边界

VFS 与具体文件系统不是同一对象；VFS 负责抽象接口与运行时对象关系，真正的磁盘布局、分配策略由具体文件系统实现。
