# 408-2025-Q30

> 原题：[[../2025 年全国硕士研究生招生考试#30|Q30]]

## Model Anchor

- Topic：[[../../../../30_408/30_操作系统/30_虚拟内存与页生命周期/README|OS-04 mmap]]，文件对象接口调用 OS-06/07。
- 题目信号：memory-mapped file 的作用判断。
- 第一动作：先写映射关系：**file-backed `mmap` 建立的是“进程虚拟地址范围 ↔ 文件内容/后备对象”的关系**，不是把整个文件固定映射进某段物理内存。

## 解题链

**I 正确。** 两个进程若共享映射同一个文件区域，可以通过共同可见的映射页交换数据，因此可作为 IPC 的一种实现基础。

**II 不作为该机制的定义。** “页到磁盘块的映射”属于文件系统/块映射如何定位文件后备数据的内部机制；memory mapping 的核心合同不是建立普通虚拟页号与某磁盘块号的一一映射。

**III 正确。** 文件映射把文件的一段内容接入进程的虚拟地址空间，之后访问这些虚拟地址可按需触发 file-backed page fault 并建立驻留页。

**IV 错误。** 映射关系首先属于进程虚拟地址空间；物理页何时分配/驻留可以按需变化，并不存在“把文件映射到系统物理地址空间”的固定合同。

所以正确的是 **I、III**。

**答案：A。**

## 选项判断

逐项区分 `mmap` 的虚拟地址映射语义后，只有 I、III 成立，故选 $\boxed{A}$。

## Verification

如果 `mmap` 一执行就必须把文件整体映射进固定物理地址，那么大文件映射会立刻要求等量 RAM；实际的 file-backed mmap 可以只先建立 VMA/映射关系，访问时再按页调入。这个反例直接排除 IV，并说明“映射 ≠ 驻留”。

## Compression

memory-mapped file → **先区分映射关系与物理驻留** → `file ↔ process VA` 是核心；共享映射可 IPC；page-in / block mapping 是下层实现路径。

## 易错边界

`mmap` 不等于“把文件读入物理内存”，也不等于普通页表的 VA→PA 映射本身；它是在虚拟地址空间层把一个区域的 backing 绑定为文件内容。
