# 408-2025-Q36

> 原题：[[../2025 年全国硕士研究生招生考试#36|Q36]]

## Model Anchor

- Topic：[[../../../../30_408/40_计算机网络/04_IP地址_子网与分组转发/README|NET-04 DHCP]]。
- 题目信号：新主机尚未完成地址配置，正在发送 DHCPREQUEST。
- 第一动作：先判断客户端此刻**是否已经可以把租约地址当成本机源 IP 使用**，以及 REQUEST 为什么仍需要让同一广播域中的 DHCP server 都看到。

## 解题链

DHCP 配置完成前，客户端还不能把服务器 offer 的 `192.168.5.9` 当成已经生效的本地 IP。因此源 IP 仍使用 bootstrap 特殊地址：

$$0.0.0.0.$$

DHCPREQUEST 在经典 DORA 流程中继续广播：一方面选定某个 offer，另一方面让其他 server 也知道自己的 offer 未被采用。因此目的 IP 为受限广播地址：

$$255.255.255.255.$$

所以目的/源 IP 分别为：

$$255.255.255.255,\quad0.0.0.0.$$

## 选项判断

未完成地址配置的客户端仍以 `0.0.0.0` 为源、有限广播为目的发送 DHCPREQUEST，故选 $\boxed{C}$。

## Verification

若源地址直接写 `192.168.5.9`，就等于假设租约已在 DHCPACK 之前生效；这把“server 提议的 yiaddr”与“client 已正式配置的地址”混成了一个状态。

## Compression

DHCP bootstrap → **先看 client 是否已完成配置** → 未配置时 source=`0.0.0.0`；DISCOVER/选择 offer 的 REQUEST 常用 `255.255.255.255` 广播。

## 易错边界

DHCP 报文中的 `yiaddr` 是 server 提供/分配流程中的字段，不自动等于当前 IP 数据报的 source address。
