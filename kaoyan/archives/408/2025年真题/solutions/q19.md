# 408-2025-Q19

> 原题：[[../2025 年全国硕士研究生招生考试#19|Q19]]

## Model Anchor

- Topic：[[../../../../30_408/20_计算机组成原理/30_CPU数据通路与控制/README|CO-03 CPU 数据通路与控制]]。
- 题目信号：区分通用寄存器组、控制器与不同 CPU 组织方式。
- 第一动作：先分 **architectural role** 与 **implementation component**；尤其不要因为 PC 也是寄存器，就把它自动塞进“通用寄存器组”。

## 解题链

- **A 错。** PC 是程序计数器，承担下一条指令地址的专用架构状态；它通常不是通用寄存器组中的普通通用寄存器。
- B 对：控制器必须根据当前指令的操作码/控制字段识别应执行的操作，因此需要相应译码逻辑。
- C 对：教学模型中单周期控制通常主要是当前指令字段到控制信号的组合映射；多周期还要维护阶段状态并产生下一状态，控制 FSM 更复杂。
- D 对：流水线让多条指令重叠，必须处理结构、数据和控制冒险。

**答案：A。**

## 选项判断

PC 是专用架构状态而非普通 GPR；其余三项分别符合译码、控制 FSM 与流水线冒险机制，因此错误项为 $\boxed{A}$。

## Verification

把 PC 当成普通 GPR 会导致一个反例：若任意普通算术指令都可像读写 GPR 一样无条件改 PC，就会破坏取指控制语义。PC 即使在某些 ISA 中可被特定指令间接读写，也不因此自动属于“通用寄存器组”。

## Compression

CPU 部件判断 → **先问状态用途和接口是否通用** → “都是寄存器”不代表“都属于 GPR file”。

## 易错边界

“寄存器”是物理/状态类别；“通用寄存器”是软件使用合同。PC、IR、MAR、MDR、流水寄存器不能只因名字里有“寄存器”就混成一类。
