# 408-2025-Q46

> 原题：[[../2025 年全国硕士研究生招生考试#46（本题 8 分）|Q46]]

## Model Anchor

- Topic / Owner：OS-01/02 的 PCB 与进程/线程执行状态；OS-05 的应用 I/O 请求到驱动程序责任链；程序运行环境中的代码、全局数据、栈、堆对象归属。
- 题目信号：同一段 C 程序同时问“**谁管理它、变量存哪里、I/O 等待时进程处于什么状态**”。
- 第一动作：不要按变量名猜。逐个对象问：**它是谁的状态？生命周期多久？由编译器静态布局、函数调用栈还是运行时动态分配产生？**

## Problem Representation

把题中对象按“谁拥有、生命周期多久、怎样产生”分类：

| 对象 | Owner / 生命周期 | 典型区域或状态 |
|---|---|---|
| PCB | OS 内核、进程生命周期 | 内核管理区 |
| `main()` 指令 | 可执行映像 | 只读代码段 |
| 全局变量 `ptr` | 静态存储期 | 可读写数据/BSS |
| 自动局部 `length` | 当前函数调用 | 用户栈（若未进寄存器） |
| `malloc` 产生的对象 | 运行时动态分配 | 用户堆 |
| 等待键盘输入的进程 | 调度状态机 | Blocked/Waiting |

## Decision Points

- **指针变量与指针指向对象必须拆开。** `ptr` 自己是全局变量，而 `ptr` 保存的地址指向 `malloc` 创建的堆对象。
- **库函数不等于设备驱动。** `scanf/printf` 最终触发设备 I/O；`strlen` 是普通内存计算，`malloc/free` 属于运行时/内存管理而不是设备驱动路径。
- **Ready 与 Blocked 的判据是“还缺什么”。** 键盘数据未到达时即使给 CPU 也无法继续，所以缺的是外部事件而不是 CPU，必须判 Blocked。

## Solution Chain

### (1) PCB 所在区域与 `scanf()` 等待状态

PCB 是操作系统用于管理进程身份、资源引用、调度/等待状态等信息的内核控制记录，普通用户程序不能任意改写，因此位于：

$$\boxed{内核区}.$$

执行 `scanf()` 后若键盘输入尚未到达，进程当前不能继续推进，并等待 I/O 事件完成，故进入：

$$\boxed{阻塞态（Blocked/Waiting）}.$$

这里它不是 Ready：Ready 表示“只缺 CPU 就能继续”，而此时即使立即给 CPU，也没有所需输入数据。

### (2) `main()` 与哪些直接调用需要驱动程序

`main()` 的机器指令属于程序代码，放在题图的：

$$\boxed{只读代码段}.$$

直接调用函数中：

- `scanf()`：需要从键盘/输入设备取得数据，最终需要经过设备驱动与 I/O 子系统；
- `printf()`：输出到终端/显示相关设备，同样需要通过 I/O 子系统/驱动完成设备操作；
- `strlen()`：纯内存计算，不需要驱动程序；
- `malloc()` / `free()`：管理进程虚拟内存/运行时堆，可能与内核内存管理交互，但不是“通过设备驱动程序实现”的设备 I/O 功能。

因此应答：

$$\boxed{scanf()、printf()}.$$

### (3) `ptr`、`length` 与字符串所在区域

`ptr` 在所有函数外定义，是全局变量，其存储单元属于题图中的：

$$\boxed{可读写数据段}.$$

`length` 是 `main()` 的自动局部变量；若没有被编译器分配到寄存器中，则位于当前函数栈帧：

$$\boxed{用户栈}.$$

`malloc(100)` 动态分配 100 B，`ptr` 保存的是这块动态存储的地址，所以 `ptr` 指向的输入字符串位于：

$$\boxed{运行时堆}.$$

## Verification

把“指针变量”和“指针指向对象”分开即可独立检查：

```text
ptr 这个变量本身 -> 全局生命周期 -> 数据段
ptr 保存的地址    -> malloc 产生对象 -> 堆
```

若把两者都答“堆”，就混淆了 pointer object 与 pointee。

## Compression

进程地址空间题 → **按对象生命周期/Owner 分类**：代码→text；全局→data/BSS；自动局部→stack；malloc 对象→heap；PCB→kernel management state；等待设备事件→Blocked。

## 易错边界

“库函数”不等于“都需要系统调用/驱动”。`strlen` 可以完全在用户态读内存；`malloc/free` 的运行时实现也不能因为可能向内核申请页，就被误归成设备驱动。
