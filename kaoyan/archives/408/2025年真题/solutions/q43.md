# 408-2025-Q43

> 原题：[[../2025 年全国硕士研究生招生考试#43（本题 12 分）|Q43]]

## Model Anchor

- Topic：CO-06 Cache、CO-07 地址翻译；接口为 CO-B02 `Translation Result -> Cache Access`。
- 题目信号：**Cache set/index + 页大小 + 虚拟地址 + 顺序数组访问 + miss penalty**。
- 第一动作：先做位预算，再做访问序列：

```text
VA -> page offset / VPN
PA -> tag | set index | block offset
```

分页只替换页号，页内 offset 不变；所以只有完全落在 page offset 内的 Cache 低位字段，才可以直接从 VA 取得。

## Problem Representation

把题面先压成四组状态，而不是直接代公式：

```text
Cache geometry : 32 KB / 8-way / 64 B block
                 -> 512 lines -> 64 sets -> offset 6 bit + index 6 bit
VM geometry    : page = 4 KB -> page offset 12 bit
Array interval : 2048 int = 8192 B, start VA offset = 0x20
Access events  : each element 1 load + 1 store -> 4096 Cache accesses
Cost contract  : hit time = 2 cycles, miss penalty = 200 cycles
```

因此本题真正要追踪的是：地址字段是否能跨 VA→PA 保持、数组覆盖多少 Cache block / page、以及每个访问事件何时首次触及新块。

## Decision Points

- **先位预算，再访问序列。** 只有确认 `offset 6 + index 6 = 12` 完全位于 4 KB page offset 中，才能安全地用 VA 的低位直接得到 Cache set。
- **先把数组看成连续字节区间，再数块/页。** 起点位于块内偏移 32 B，不能用“8192/64=128”直接当覆盖块数。
- **成本对象先命名。** 题面给的是额外 `miss penalty`，因此使用 $HitTime+MissRate\times MissPenalty$；不能把 200 cycle 当成 miss 的总访问时间再次覆盖正常 lookup。

## Solution Chain

### (1) Cache 地址字段与可直接使用的 VA 位

Cache 数据区 32 KB，块 64 B：

$$
\text{line count}=\frac{32\text{ KB}}{64\text{ B}}=512.
$$

8 路组相联：

$$
\text{set count}=\frac{512}{8}=64=2^6.
$$

因此：

- block offset：$\log_2 64=6$ 位；
- set index：$\log_2 64=6$ 位。

即物理地址低位布局为：

```text
... | set index (6 bit) | block offset (6 bit)
          PA11..PA6          PA5..PA0
```

页大小 4 KB=$2^{12}$ B，分页映射保持低 12 位不变：

$$VA_{11..0}=PA_{11..0}.$$

故可直接用作 Cache set index 的虚拟地址位是：

$$\boxed{VA_{11}\sim VA_6}.$$

### (2) `d[100]` 的 VA 与 Cache 组号

一个 `int` 为 4 B：

$$100\times4=400=0x190.$$

所以：

$$
VA(d[100])=0x01800020+0x190
=\boxed{0x018001B0}.
$$

取低 12 位 `0x1B0 = 0001 1011 0000₂`，其中 $VA_{11..6}$ 为：

```text
000110₂ = 6
```

因此 Cache 组号为：

$$\boxed{6}.$$

### (3) 块内偏移、缺失率与平均访问时间

`d[0]` 地址低 6 位来自 `0x20`，所以块内偏移：

$$\boxed{0x20}.$$

数组大小：

$$2048\times4=8192\text{ B}.$$

它从一个 64 B 块的偏移 32 B 处开始，因此覆盖的 Cache 块数不是正好 128，而是：

$$
\left\lceil\frac{32+8192}{64}\right\rceil
=129.
$$

循环对每个 `d[i]` 有一次读和一次写，共：

$$2048\times2=4096$$

次数据 Cache 访问。顺序扫描中每个新块第一次读发生一次 compulsory miss，随后同块读/写命中，因此缺失次数为 129：

$$
MissRate=\frac{129}{4096}\times100\%
\approx\boxed{3.15\%}.
$$

题面给的是命中时间 2 cycle、**缺失损失（miss penalty）** 200 cycle，因此 AMAT 应按

$$
AMAT=HitTime+MissRate\times MissPenalty
$$

计算：

$$
AMAT=2+\frac{129}{4096}\times200
\approx\boxed{8.30\text{ cycles}}.
$$

### (4) 数组跨页数与缺页次数

页大小 4096 B，`d` 从页内偏移 `0x20=32` B 开始，数组长度 8192 B：

$$
\text{pages}=\left\lceil\frac{32+8192}{4096}\right\rceil=3.
$$

若这 3 个数组页一开始都不在主存，顺序扫描第一次触及每页时各产生一次缺页，之后都在该页内继续访问，因此：

$$\boxed{3\text{ 页，3 次缺页}}.
$$

## Verification

三个独立检查：

1. **位预算**：`block offset 6 + set index 6 = 12`，恰好完全落入 4 KB 页的 12 位 page offset，所以 `VA11..VA6` 可安全索引；
2. **边界块**：8192 B 本来是 128 个完整块，但起点偏移 32 B，使首尾各占半块，总覆盖 129 块；
3. **AMAT 口径**：`miss penalty` 是额外损失，不能把 miss 的总成本直接写成 200 而漏掉正常 2-cycle hit lookup。

## Compression

Cache + VM 综合题 → **先做 page-offset / block-offset / set-index 位预算 -> 再把数组变成连续字节区间 -> 数跨块/跨页边界 -> 最后按访问事件算 miss rate 和 AMAT**。

## 易错边界

- TLB miss、Page Fault、Cache miss 是三个不同状态机；
- `miss penalty` 通常是命中时间之外的额外代价；
- 数组长度刚好是若干块/页的整数倍，不代表数组一定只占这些块/页，起始偏移会多跨一个边界。
