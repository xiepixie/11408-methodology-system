# 408-2026-Q47

> 原题：[[../2026 年全国硕士研究生招生考试#47（本题 9 分）|Q47]]

## Model Anchor

- Topic：TCP 连接生命周期 + 字节序号空间 + 流量/拥塞双窗口 + RTT 时间线。
- 题目信号：**ISN、MSS、rwnd、ssthresh、逐段 ACK、RTT 同时出现**，不能只套一个窗口公式。
- 第一动作：建立三张同步账本：`SEQ/ACK`、`cwnd/rwnd/FlightSize`、`event timeline`。

## Problem Representation

```text
file size = 2000 B = 4 MSS
MSS       = 500 B
ssthresh  = 8 MSS
rwnd      = 1000 B = 2 MSS
RTT       = 5 ms
C ISN     = 1000
S ISN     = 2000
```

TCP 序号规则：

```text
SYN  消耗 1 个序号
FIN  消耗 1 个序号
纯 ACK 不消耗序号
ACK = 下一期待收到的字节序号
```

## Decision Points

- 当前 Canonical 未显式给初始 `cwnd`；本题按年度 `solution_review.md` 已登记的经典 408 慢开始口径 $cwnd_0=1\text{ MSS}$ 推导。若以后获得更高优先级原卷条件，应先修 Source 再重算本题。
- 有效发送窗口上限取 `min(cwnd,rwnd)`；如果题目问“还能新发多少”，还要再扣除 `FlightSize`。
- 第 (4) 问从“请求建立连接”开始计时，但第三次握手 ACK 可以和首批数据发送衔接，不需要额外再等一个 RTT。
- 计算 FIN/ACK 时必须先把 SYN 占用的序号纳入字节坐标，不能只拿文件长度直接加到 ISN 上。

## Solution Chain

### (1) 建立连接

TCP 正常建立连接需要三次握手：

```text
C -> S : SYN,     seq=1000
S -> C : SYN+ACK, seq=2000, ack_seq=1001
C -> S : ACK,     seq=1001, ack_seq=2001
```

所以：

$$\boxed{3\text{ 次握手}},$$

$$\boxed{ack\_seq=1001}.$$

### (2) 收到 `ack_seq=2001` 后的拥塞窗口与发送窗口

连接建立后，C 的首个数据字节序号是 1001。

初始：

$$cwnd=1\text{ MSS}.$$

第一个 500 B 数据段被确认后：

$$cwnd:1\to2\text{ MSS}.$$

随后 C 可发送两个 MSS。题目给出的 `ack_seq=2001` 确认了新的数据，因此在慢开始阶段再增加 1 MSS：

$$\boxed{cwnd=3\text{ MSS}=1500\text{ B}}.$$

但接收端通告

$$rwnd=1000\text{ B},$$

所以发送窗口上限为

$$W_{send}=\min(cwnd,rwnd)=\min(1500,1000)=\boxed{1000\text{ B}}.$$

### (3) 释放连接及 C 收到的最后一个 TCP 报文段

正常关闭采用四次挥手：

$$\boxed{4\text{ 次}}.$$

C 的 SYN 使用序号 1000，所以 2000 B 数据使用的字节序号为：

$$1001\sim3000.$$

因此 C 的 FIN 序号为

$$3001,$$

FIN 再占 1 个序号，S 对它的确认号为

$$\boxed{ack\_seq=3002}.$$

S 的 SYN 使用序号 2000；题设说明确认段不封装数据，纯 ACK 不占序号，所以 S 发送 FIN 时仍使用

$$\boxed{seq=2001}.$$

因此 C 收到的最后一个来自 S 的关闭报文可写为：

$$\boxed{seq=2001,\quad ack\_seq=3002,\quad FIN=1}.$$

### (4) C 确认 S 已收到整个文件的时刻

按 RTT 建时间线：

|    时刻 | 事件                              |    可发送数据 |
| -------: | ------------------------------------- | ----------------: |
|  0 ms | C 发送 SYN                        |        — |
|  5 ms | C 收到 SYN+ACK，连接可进入数据发送          |    1 MSS |
| 10 ms | 第 1 个 MSS 的 ACK 到达，`cwnd=2 MSS` |    2 MSS |
| 15 ms | 第 2、3 个 MSS 的 ACK 到达            | 最后 1 MSS |
| 20 ms | 第 4 个 MSS 的 ACK 到达              | 文件已被累计确认 |

因此：

$$\boxed{20\text{ ms}}.$$

## Verification

### 序号守恒

C：

```text
SYN  : 1000
DATA : 1001 ... 3000   共 2000 个字节序号
FIN  : 3001
next : 3002
```

所以 S 最终确认到 3002 自洽。

S：

```text
SYN      : 2000
pure ACK : 不占序号
FIN      : 2001
```

所以 C 收到的 S 端 FIN 的 `seq=2001` 自洽。

### 数据量与 RTT 守恒

发送批次：

$$1\text{ MSS}+2\text{ MSS}+1\text{ MSS}=4\text{ MSS}=2000\text{ B}.$$

从建连请求到最后数据 ACK 共 4 个 RTT：

$$4\times5\text{ ms}=20\text{ ms}.$$

## Compression

```text
TCP 综合题
-> 先建 SEQ/ACK 字节坐标
-> 再建 min(cwnd,rwnd) 窗口账
-> 最后把可发送批次放进 RTT 时间轴
```

## 易错边界

- ACK 值表示“下一期待字节”，不是“刚收到的最后一个字节序号”。
- `min(rwnd,cwnd)` 是总在途上限；若问新增可发送量，还要减 `FlightSize`。
- SYN、FIN 各占 1 个序号，纯 ACK 不占序号。
- 当前 Source 未显式给初始 `cwnd`，这是本题唯一需要保留的条件缺口。
