# 408-2026-Q46

> 原题：[[../2026 年全国硕士研究生招生考试#46（本题 8 分）|Q46]]

## Model Anchor

- Topic：`pathname -> inode -> logical block -> index path -> physical block` 与删除生命周期。
- 题目信号：同时给 **inode table 几何、直接/间接索引、目录项、两类位示图**。
- 第一动作：每一问先确认正在数的是 inode、数据块、索引块还是目录项，避免跨层混算。

文件系统综合题固定分层：

```text
pathname / directory entry
-> inode identity
-> byte offset -> logical block
-> inode index path
-> physical block
-> bitmap / inode bitmap lifecycle
```

这样可以把“查文件”“读数据”“删除对象”三类状态变化分开。

## Problem Representation

```text
block size       = 4 KB
inode size       = 128 B
inode table      = block 100 起，共 4096 blocks
inodes per block = 4096 / 128 = 32
inode(file)      = 1000
file size        = 30 KB
index structure  = 5 direct + single/double/triple indirect
```

目录关系按题图为：`dir -> dir1 -> file`。第 (2) 问因此不仅涉及删除父目录中的一个名字，还涉及其子文件与目录自身的资源生命周期。

## Decision Points

- inode 1000 定位：先算 `inodes per block`，再做商/余数。
- 偏移 21460：先转成逻辑块号，再判断落在直接还是间接索引区；题目已说明 inode 在内存，不能重复算 inode I/O。
- 删除 `dir1`：对象仍包含子文件，必须按“目录项 -> 子对象块/inode -> 目录自身 -> 父目录项”的依赖顺序处理。

## Solution Chain

### (1) inode 所在盘块、访问偏移的 I/O、最多文件数

#### ① `file` 的 inode 所在盘块

图中 `file` 的 inode 号为 **1000**。盘块 4 KB，inode 大小 128 B，因此每个 inode-table block 可放

$$\frac{4096}{128}=32$$

个 inode。

inode 1000 位于 inode table 的第

$$\left\lfloor\frac{1000}{32}\right\rfloor=31$$

个块（从 0 开始）。inode table 从物理块 100 开始，所以物理盘块号为

$$\boxed{100+31=131}.$$

块内是第 $1000\bmod32=8$ 个 inode，这也可作为定位复核。

#### ② 访问文件偏移 21460 的一个字节，最多读多少盘块

文件块大小 4096 B，逻辑块号为

$$LBN=\left\lfloor\frac{21460}{4096}\right\rfloor=5,$$

块内偏移

$$21460-5\times4096=980.$$

inode 有 5 个直接地址项，它们覆盖逻辑块 0～4；逻辑块 5 是第一个需要一级间接索引的块。

题设已经说明 inode 在内存，因此最坏需要：

```text
读一级间接索引块 1 次
+ 读目标数据块     1 次
```

共

$$\boxed{2\text{ 个盘块}}.$$

#### ③ 最多可以存放多少个文件

inode table 共 4096 个盘块，每块 32 个 inode：

$$4096\times32=131072.$$

在“磁盘空间足够”的前提下，文件数量由 inode 数量限制，因此最多

$$\boxed{131072\text{ 个文件对象}}.$$

### (2) 删除目录 `dir1` 时的元数据变化

图中关系为：

```text
dir
└── dir1   inode 201
    └── file   inode 1000
```

这里必须先澄清生命周期：**普通删除目录操作通常要求目录为空**。因此如果题目所说“删除 dir1”是指把图中的 `dir1` 及其内容一起删除，就必须先删除 `file`，再删除空的 `dir1`；若只执行普通 `rmdir(dir1)` 而不先处理 `file`，应因目录非空而失败。

按“删除整个 `dir1` 子树”的题意，元数据操作可按对象依赖顺序写：

#### A. 删除 `file`

1. 在 `dir1` 的目录数据中删除 `file -> inode 1000` 这条目录项；
2. 根据 inode 1000 找到并释放 `file` 占用的数据块；`file` 为 30 KB，实际使用若涉及间接索引块，相应索引块也必须一并释放；
3. 在**磁盘块位图**中把这些已释放的数据块/索引块标为未使用；
4. 释放 inode 1000，并在**inode 位图**中清除对应占用位；
5. 相应更新目录/文件的大小、时间戳、链接计数等题设模型要求的元数据。

#### B. 删除已经为空的 `dir1`

1. 释放 `dir1` 自身目录文件所占的数据块，并更新磁盘块位图；
2. 释放 inode 201，并更新 inode 位图；
3. 在父目录 `dir` 中删除 `dir1 -> inode 201` 的目录项；
4. 更新父目录相关元数据。

若教材模型显式维护 `.`、`..` 和目录链接计数，还需按其规则同步调整；本题核心得分点仍是：

```text
删除目录项
+ 释放数据/索引块
+ 更新块位图
+ 释放 inode
+ 更新 inode 位图
```

## Verification

### 地址验证

inode 1000：

$$31\times32=992,\qquad 1000-992=8,$$

所以它确实落在从 100 开始的第 31 个 inode-table block，即 131。

### 偏移验证

$$5\times4096=20480<21460<24576=6\times4096,$$

所以偏移 21460 必在逻辑块 5，而 5 个直接块刚好只覆盖 0～4，因此必须进入一级间接索引。

## Compression

```text
inode号 -> 每块inode数 -> inode-table物理块
byte offset -> LBN -> direct/indirect层级 -> I/O次数
删除 -> name edge -> data/index blocks -> block bitmap -> inode -> inode bitmap
```

## 易错边界

- inode 已经在内存，所以不能把“再读 inode 块”计入第 (1) 问的访问次数。
- 逻辑块编号从 0 开始；5 个直接地址项覆盖的是 0～4。
- 删除一个非空目录不能把“父目录项一删就结束”当完整操作；子对象仍然占用 inode 与数据块。
- 若题意只是普通 `rmdir`，非空 `dir1` 应先失败；递归删除是本解为完成题目目标采用的明确语义解释。
