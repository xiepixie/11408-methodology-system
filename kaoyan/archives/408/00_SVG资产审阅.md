# 408 历年真题 SVG 资产审阅

## 结论

2009～2024、2026 的网页抓取包已经包含大量可编辑 SVG。它们整体属于**结构化矢量图 + 少量设备/示意图 raster icon**，并非把整张题图截图塞进 `<image>` 的假 SVG，因此可以继续作为正式版题图的基础资产。

2025 年另有一套按本项目规范重建的高质量 Semantic SVG，作为后续逐年升级的参考标准。

## 当前正式版的 SVG 使用策略

1. **先保证题意结构正确**：节点、连线、方向、标签、权值、地址、表格字段必须完整。
2. **原 SVG 已清楚可读时直接复用**：不为了“统一风格”机械重画全部图。
3. **含小型 raster 设备图标可以接受**：前提是图标只是视觉对象，关键文字、网络地址、边权和连接关系仍是可编辑矢量/文本。
4. **禁止整张题图 raster 化**：若 raster 图像本身承担绝大部分题意，应进入重画队列。
5. **复杂题图逐年升级为 Semantic SVG**：需要频繁编辑、暗色阅读困难、对象关系复杂或图中文字太小的图优先升级。

## Semantic SVG 升级目标

升级后的主要对象使用稳定 id，例如：

```xml
<g id="router-r1">...</g>
<g id="host-h1">...</g>
<g id="link-r1-r2">...</g>
<g id="activity-b">...</g>
```

要求：

- 文字保持 `<text>` 或可编辑文本，不转轮廓；
- 连线、箭头、节点分别可编辑；
- 不增加原题没有的解释和答案提示；
- geometry 与 theme 分离；
- 新重建图使用项目统一 token，默认暗色背景 `#30362d`，需要时派生 light 版本。

## 主题策略

### 新建/重建 SVG

严格使用 `exam_source_conversion_spec.md` 的 dark/light token 体系：

- 默认 dark：适配 Obsidian `#30362d`；
- light：用于亮色主题、打印和导出；
- 同一图只维护一份语义/几何逻辑，不允许 dark/light 人工演化成两幅不同结构。

### 历史抓取 SVG

旧 SVG 若自身带完整白色画布、黑色文字，在暗色 Obsidian 中仍作为“白色题图卡片”清晰呈现，可以先保留；若背景透明而使用深色文字、或暗色环境下标签不可辨认，则必须重构或主题化后才能视为完成。

## 自动检查

整批验收至少检查：

```text
SVG XML 可解析
正式版引用的 SVG 文件存在
没有整页 raster 覆盖式 SVG
关键图中文字不是不可编辑路径
图中没有明显缺失的连线 / 箭头 / 标签
```

机器检查只负责文件事实。图中数字、方向、网络拓扑、边权等题意信息仍需要按题逐图视觉核对。

## 优先升级队列

优先级从高到低：

1. 网络拓扑、时序图、数据通路、流水线、页表/Cache 图；
2. AOE/AOV、最短路、B/B+ 树等结构关系直接参与计算的图；
3. 复杂表格型题图；
4. 仅作辅助示意、原 SVG 已清晰稳定的简单图。

2025 年已达到高质量 Semantic SVG 标杆；其他年份在后续拿到更高清原卷时按此顺序增量升级，不需要为了形式统一一次性重画全部历史资产。
