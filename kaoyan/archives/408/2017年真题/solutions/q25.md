# 408-2017-Q25

## Model Anchor

- Topic：动态分区回收、地址邻接合并与 Best-Fit 空闲链排序。
- 题目信号：回收后既要问“空闲分区数量”，又强调每次回收后重新排序。
- 第一动作：先按**地址空间**判断相邻分区并合并，再按**大小**执行最佳适应链的排序；这两个坐标系不能混在一起。

## 解题链

原空闲分区：

```text
20K,   size 40K   -> [20K,60K)
200K,  size 200K  -> [200K,400K)
500K,  size 80K
1000K, size 100K
```

回收 `[60K,200K)`、大小 140K。它左邻 `[20K,60K)`，右邻 `[200K,400K)`，三者连续，因此合并成：

```text
[20K,400K) -> start 20K, size 380K
```

于是只剩 3 个空闲分区，大小分别为 `380K、80K、100K`。Best-Fit 空闲链按大小升序重排，链首应为 `500K, 80K`。

## 选项判断

故选 $\boxed{B}$：3 个，500K，80 KB。

## Verification

总空闲容量守恒：原空闲 $40+80+100+200=420$ KB，加回收 140 KB，共 560 KB；合并后 $380+80+100=560$ KB，吻合。

## Compression

```text
free block -> address-neighbor coalesce -> recompute partitions -> policy-specific reorder
```

## 易错边界

最佳适应的“按大小排序”只决定搜索顺序；能否合并永远由物理地址连续性决定。
