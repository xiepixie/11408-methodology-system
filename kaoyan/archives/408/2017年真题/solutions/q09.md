# 408-2017-Q09

## 模型锚点

- Topic：B+ 树的外存索引场景。
- 题目信号：问应用场景，不是让比较树形细节。
- 第一动作：先匹配 workload：是否需要高扇出、降低磁盘 I/O、支持有序范围扫描。

## 解题链

B+ 树把大量关键字组织成高扇出的平衡多路树，内部结点主要承担索引功能，叶结点按关键字有序并可顺序连接。这正适合关系数据库的磁盘索引：树高低、随机 I/O 少，同时范围查询方便。

词法分析更典型使用自动机/散列；路由表强调最长前缀匹配，常用 Trie 等结构；磁盘空闲块管理通常使用位图、空闲链表等。

## 选项判断

故选 $\boxed{B}$。

## 校验

如果索引含数百万记录，二叉树扇出只有 2，而 B+ 树一个磁盘页可容纳大量索引项，树高显著更低，这正是外存索引的核心收益。

## 压缩

```text
external-memory index + range scan -> high fanout + ordered leaves -> B+ tree
```

## 易错边界

不要因为 B+ 树“能查找”就把所有查找场景都映射过去；选择结构要由访问介质和查询模式决定。
