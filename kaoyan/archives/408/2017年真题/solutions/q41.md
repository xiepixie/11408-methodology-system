# 408-2017-Q41

## Model Anchor

- Topic：表达式树、递归遍历与结构化输出。
- 题目信号：给的是**树结构语义**，目标是输出等价中缀表达式，并要求括号显式保存计算次序。
- 第一动作：先把输出合同写清楚：叶结点直接输出；运算符结点按中序输出左右子表达式；除根外的非叶子表达式用括号封装。

## Problem Representation

表达式树已经把运算优先关系编码进祖先/子树关系：

```text
node
├── left  = 左操作数/左子表达式
└── right = 右操作数/右子表达式
```

因此问题不是重新计算运算符优先级，而是把树中的结构信息无损序列化成文本。

对于二元运算符结点，天然对应：

```text
(left-expression) operator (right-expression)
```

若存在一元运算符，某一孩子为空时，中序递归仍可自然输出 `-d` 一类形式。为了不依赖 `*`、`+`、`-` 等具体优先级规则，我们用括号直接保存树的计算边界。

## Decision Points

### 1. 为什么是中序，不是先序/后序？

中缀表达式要求运算符位于两个操作数之间，所以遍历骨架必须是：

```text
left -> root(operator) -> right
```

即中序。

### 2. 为什么不能简单“每个结点都加括号”？

叶结点只是原子操作数，加括号没有必要；根结点是整个表达式最外层，外侧括号也不影响计算次序。题目要求的是通过括号反映次序，而不是制造冗余符号。

因此稳定规则是：

```text
非根 AND 非叶结点 -> 输出子表达式前后加括号
```

### 3. 为什么用递归最自然？

每个子树本身仍是一个完整表达式，问题具有严格自相似结构。递归函数只需维护一个额外状态：当前是否根结点（可用 `depth` 或显式参数）。

## Solution Chain

算法合同：

```text
PrintExpr(node, depth)
1. node == NULL -> return
2. 非根且非叶 -> print "("
3. PrintExpr(left)
4. print node->data
5. PrintExpr(right)
6. 非根且非叶 -> print ")"
```

C/C++ 实现：

```c
void PrintExpr(BTree *t, int depth) {
    if (t == NULL) return;

    int isLeaf = (t->left == NULL && t->right == NULL);
    int needParen = (depth > 0 && !isLeaf);   // 根 depth=0

    if (needParen) printf("(");

    PrintExpr(t->left, depth + 1);
    printf("%s", t->data);
    PrintExpr(t->right, depth + 1);

    if (needParen) printf(")");
}

void Solve(BTree *root) {
    PrintExpr(root, 0);
}
```

若树为空，直接无输出；若只有一个叶结点，则直接输出该操作数。

### Why Correct

对树高做结构归纳。

**基础情形：**叶结点没有子表达式，函数只输出自身数据，显然正确。

**归纳步骤：**假设左右子树都能被正确转换成保持原计算次序的中缀表达式。当前运算符结点按照 `左表达式 -> 运算符 -> 右表达式` 输出；若它不是整棵树根，则外加括号把该子树标成一个不可歧义的计算单元。因此当前子树也被正确表示。

归纳成立，所以根调用输出与原表达式树等价的中缀表达式。

### Complexity

每个结点恰好访问一次：

$$
T(n)=O(n).
$$

除输出本身外，递归栈深度为树高 $h$：

$$
S(h)=O(h).
$$

最坏退化树为 $O(n)$，平衡树约为 $O(\log n)$。

## Verification

用“运算符结点数”做独立结构检查：每个非根非叶运算符结点恰好产生一对括号，叶结点绝不产生括号；因此不会把操作数错误包成子表达式，也不会丢掉内部运算层级。

对题给示例树重新执行中序递归，可得到题目给出的 `(a+b)*(c*(-d))`、`(a*b)+(-(c-d))` 对应结构，验证括号边界与树形一致。

## Compression

```text
expression tree
-> inorder is infix skeleton
-> leaf = atom
-> non-root internal subtree = parenthesized unit
-> recurse once per node
```

## 易错边界

1. 旧解析函数名写成 `preorder`，但实际逻辑是中序遍历；命名不能反过来污染机制理解。
2. 不能只按运算符“通常优先级”决定括号，否则遇到一元运算或非结合运算容易丢失树本身指定的计算次序。
3. 空结点不输出，叶结点不加括号，根结点不需要最外层括号。
