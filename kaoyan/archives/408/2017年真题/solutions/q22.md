# 408-2017-Q22

## 模型锚点

- Topic：多重中断的响应窗口与中断嵌套。
- 题目信号：出现“多重中断”，关键就是高优先级中断能否在低优先级 ISR 期间再次进入。
- 第一动作：把中断过程拆成 `request -> sample -> boundary response -> ISR -> possible re-enable/nesting`，检查绝对命题覆盖了哪一阶段。

## 解题链

A 正确：外部中断通常在当前指令执行结束的边界检查并响应，保证精确的指令级状态。

C 正确：外设中断请求是外部异步事件，其产生不要求与当前指令同步。

D 正确：CPU 通过采样中断请求信号获知是否有请求。

B 错：多重中断要支持中断嵌套，进入 ISR 的初始阶段可以暂时关中断以保护现场，但在允许更高优先级中断嵌套时会重新开放相应中断，不能说整个“中断处理期间”CPU 都处于关中断状态。

## 选项判断

故选 $\boxed{B}$。

## 校验

若 B 为真，则 ISR 全程屏蔽所有中断，高优先级请求只能等当前 ISR 完成，系统实际上无法实现题干强调的多重中断嵌套。

## 压缩

```text
multiple interrupt -> ISR is not one indivisible closed-interrupt interval -> protect then selectively re-enable
```

## 易错边界

“中断响应入口会关中断”与“整个中断服务过程都关中断”不是同一命题。
