# 408-2017-Q27

## Model Anchor

- Topic：时间片轮转中的进程状态转换。
- 题目信号：四个命题中只有一个把“CPU 被剥夺”解释成“等待外部事件”。
- 第一动作：先问状态改变的事件 Owner：时间片耗尽是调度事件，不是 I/O/资源等待事件。

## 解题链

A 正确：时间片越短，抢占与上下文切换越频繁，调度开销上升。

B 错：当前进程时间片用完，若尚未结束，它仍具备运行条件，只是失去 CPU，应由运行态进入**就绪态**，不是阻塞态。

C 正确：时钟中断是维护时间片剩余量、CPU 时间等时间状态的触发事件。

D 正确：时间片选择需要在响应速度、切换开销、进程数量等因素间权衡。

## 选项判断

故选 $\boxed{B}$。

## Verification

阻塞态的必要语义是“即使现在给 CPU 也无法继续，需要等待事件”。时间片刚耗尽的进程没有这种等待条件，所以不能进入阻塞态。

## Compression

```text
time slice expires -> CPU ownership lost, runnable remains -> Running -> Ready
```

## 易错边界

`Ready` 与 `Blocked` 都是不占 CPU，但前者“等 CPU”，后者“等事件/资源”；判断状态必须看等待对象。
