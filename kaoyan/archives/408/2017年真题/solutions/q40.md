# 408-2017-Q40

## Model Anchor

- Topic：FTP 的控制连接与数据连接分离。
- 题目信号：四个命题围绕连接生命周期和端口角色。
- 第一动作：先建立两个独立状态机：`control connection` 长驻会话，`data connection` 按一次数据传输建立/关闭；再给端口找 Owner。

## 解题链

A 正确：FTP 的数据连接通常针对一次文件/目录数据传输建立，完成后关闭。

B 正确：控制连接承载命令/响应，在整个 FTP 会话期间保持。

D 正确：客户端连接服务器 TCP 21 端口建立控制连接。

C 错：经典主动模式中，**服务器端**的数据连接使用 TCP 20 端口，而客户端使用临时端口；不能说客户端的 TCP 20 端口与服务器建立数据连接。更一般地，FTP 被动模式的数据端口也不是固定 20，因此该绝对表述更不成立。

## 选项判断

故选 $\boxed{C}$。

## Verification

只要把端口归属写完整：`server control=21`、`server active-data=20`、`client=ephemeral`，C 中的端口 Owner 错位立即暴露。

## Compression

```text
FTP = long-lived control(21) + per-transfer data; active data server side uses 20
```

## 易错边界

“FTP 数据连接使用 20 端口”是经典主动模式下服务器端的说法，不能丢掉角色与模式限定。
