# 408-2017-Q31

## Model Anchor

- Topic：硬链接、inode 与打开文件状态分层。
- 题目信号：同一 inode 被两个路径名打开，但由两个进程分别获得 fd。
- 第一动作：先拆三层对象：`pathname -> inode`、`process fd -> open-file entry`、`open-file entry -> inode`，再判断哪些状态共享。

## 解题链

硬链接 `f1` 与 `f2` 是两个目录项，但指向同一个 inode，因此 II 正确：它们共享同一个内存索引结点/文件元数据对象。

两个进程分别执行打开操作，会各自得到文件描述符 `fd1/fd2`；文件描述符属于进程局部表，分别指向相应的打开文件表项，所以 III 正确。

文件读写位置属于“打开实例”的动态状态，而不是 inode 本体。两个独立 open 得到的打开实例可以维护各自的文件偏移，因此 I“读写指针保持相同”错误。

## 选项判断

正确的是 II、III，故选 $\boxed{B}$。

## Verification

若进程 1 对 fd1 读取 100 B，不应因此强迫另一个独立打开 fd2 的进程自动跳过 100 B；这直接说明 offset 不是硬链接共享 inode 的必然共享状态。

## Compression

```text
hard link shares inode
independent open owns offset
fd is process-local handle
```

## 易错边界

“同一文件对象”不等于“同一打开实例”。inode 共享元数据/数据身份，open-file entry 承担本次打开的动态状态。
