# 408-2017-Q24

## Model Anchor

- Topic：系统调用的控制流与特权级迁移。
- 题目信号：四个动作要求排序，核心是“用户先准备参数，trap 才把控制权交给内核”。
- 第一动作：按 `prepare -> enter kernel -> service -> return` 的生命周期排序，而不是按名词熟悉程度猜。

## 解题链

应用程序首先要把系统调用号/参数放到约定寄存器、栈或内存位置，即③传递参数；随后执行② trap 指令，触发受控的用户态→内核态切换；内核根据参数执行④相应服务程序；服务完成后再执行①返回用户态。

因此顺序是：

```text
③ 参数
-> ② trap
-> ④ kernel service
-> ① return user mode
```

## 选项判断

故选 $\boxed{C}$。

## Verification

若先 trap 再准备参数，内核进入后就拿不到本次调用的完整输入；若先返回用户态再执行服务程序，又破坏了系统调用由内核提供特权服务的基本边界。

## Compression

```text
args ready -> trap -> kernel service -> return
```

## 易错边界

“传递参数”属于调用协议的准备阶段；trap 是跨特权边界的事件，两者不能颠倒。
