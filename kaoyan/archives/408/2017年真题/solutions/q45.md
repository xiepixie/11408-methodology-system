# 408-2017-Q45

## Model Anchor

- Topic：虚拟地址分层、页表遍历与阻塞 I/O 生命周期。
- 题目信号：同一题把上一题代码地址映射到“页目录号/页表索引/页内偏移”，再切到 `scanf()` 的进程状态变化。
- 第一动作：地址题先做 bit projection；I/O 题先做 event timeline。不要把“进程状态”和“CPU 特权态”当成同一维状态。

## Problem Representation

二级分页地址结构：

```text
VA[31:22] -> Page Directory Index (10 bit)
VA[21:12] -> Page Table Index     (10 bit)
VA[11:0]  -> page offset          (12 bit)
```

页大小 $2^{12}=4$ KB，所以“代码占几页”只取决于所有指令地址落在哪些 4 KB 虚页中。

`scanf()` 则是另一条状态链：

```text
user Running
-> system call / kernel execution
-> input unavailable? Blocked
-> device completion interrupt
-> Ready
-> scheduler
-> Running
-> return to user mode
```

## Decision Points

### 1. 为什么只看高 20 位就能判断代码是否同页？

页内偏移是低 12 位，所以高 20 位相同就表示 VPN 相同。上一题机器代码从 `00401020H` 到 `0040107FH`，显然都落在 `00401000H~00401FFFH` 这一页。

### 2. 页目录和页表分别访问哪个表项？

不能把完整 VPN `00401H` 当成一个表索引。二级页表要求继续把 20 位 VPN 拆成两个 10 位索引。

### 3. `scanf()` 阻塞时 CPU 是否“处于内核态”？

要分清两个对象：进程 P 可以处于 Blocked，CPU 此时完全可能去运行别的进程；但在执行系统调用服务代码、处理中断时，CPU 会进入内核态。题目问“执行 scanf 过程中 CPU 是否会进入内核态”，答案是会。

## Solution Chain

### (1) f1 机器指令代码占多少页？

上一题得到代码地址区间：

$$
[00401020_H,0040107F_H].
$$

4 KB 页的边界为：

```text
00401000H ~ 00401FFFH
```

整个代码区间都在这个虚页中，因此：

$$
\boxed{1\text{ 页}}.
$$

### (2) 取 `push ebp` 时访问第几个页目录项和页表项？

第 1 条指令虚拟地址：

$$
VA=00401020_H.
$$

页目录索引：

$$
PDI=VA>>22=1.
$$

页表索引：

$$
PTI=(VA>>12)\ \&\ 3FF_H=1.
$$

因此若 TLB 未提供映射、确实需要访问内存页目录和页表，则：

$$
\boxed{\text{页目录第 1 项，随后相应页表第 1 项}}.
$$

编号均从 0 开始。

### (3) `scanf()` 期间 P 如何变化？CPU 是否进入内核态？

当进程 P 在用户态调用 `scanf()`，需要通过系统调用获得输入：

```text
P: Running(user)
-> trap/system call
-> Running(kernel)
```

若输入尚未到达，内核不能让 P 继续执行，于是：

```text
Running -> Blocked
```

随后 CPU 可以调度其他就绪进程。输入设备完成数据到达后发中断，驱动/中断处理程序满足 P 的等待条件：

```text
P: Blocked -> Ready
```

P 之后只有再次被调度，才发生：

```text
Ready -> Running
```

完成系统调用返回路径后恢复到用户态继续执行。

所以 CPU 在 `scanf()` 的系统调用处理以及设备中断处理阶段都**会进入内核态**。

## Verification

1. **页边界检查**：代码总长只有 96 B，而且起始偏移 `020H`，离本页末尾还有远大于 96 B 的空间，因此不可能跨页。
2. **地址重组检查**：`PDI=1, PTI=1` 对应 VPN $1\times2^{10}+1=0x401$；再拼低 12 位 `020H`，得到 `00401020H`，与原地址一致。
3. **状态机检查**：设备输入完成只能把 P 变为 Ready，不能直接保证 P 立刻 Running；这与调度器仍拥有 CPU 分配权的 Owner 边界一致。

## Compression

```text
VA -> [PDI|PTI|offset]
code range within same 4KB page -> 1 page

scanf:
Running(user) -> kernel -> Blocked -> device interrupt -> Ready -> schedule -> Running -> user
```

## 易错边界

1. 页目录索引和页表索引是两个不同的 10 位字段，不能把 20 位虚页号直接当作某一级表项编号。
2. `Wakeup = Blocked -> Ready`，不是 `Blocked -> Running`。
3. “进程在内核态运行”和“CPU 处于内核态”相关但不是持久绑定；P 阻塞期间 CPU 可去执行别的上下文。
