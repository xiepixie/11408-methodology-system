# 408-2017-Q11

## Model Anchor

- Topic：排序算法与底层存储表示的接口。
- 题目信号：把顺序存储改为链式存储，问哪些算法时间效率下降。
- 第一动作：不要只背排序复杂度；逐个检查算法是否依赖 $O(1)$ 随机下标访问、父子下标定位或大步长访问。

## 解题链

插入排序、选择排序、起泡排序都可以顺着链表结点进行比较；链式表示甚至能减少某些元素移动成本，因此并非必然降低时间效率。

希尔排序要求按增量访问相隔若干位置的元素；链表不能通过下标 $O(1)$ 跳到目标位置。堆排序更强依赖完全二叉树的数组映射：结点 $i$ 的孩子可由 `2i/2i+1` 直接定位；换成普通链式顺序表后这种随机定位优势消失。

因此明显受损的是 IV、V。

## 选项判断

故选 $\boxed{D}$。

## Verification

把“访问第 $i+k$ 个元素”作为最小操作：数组 $O(1)$，普通单链表通常要 $O(k)$ 或重新遍历；希尔与堆的核心访问模式正大量依赖此操作。

## Compression

```text
change representation -> inspect primitive operations -> random index required? -> if yes, linked storage raises cost
```

## 易错边界

算法复杂度不是脱离 Representation 的标签；同一算法在不同底层操作成本下，实际时间模型可以改变。
