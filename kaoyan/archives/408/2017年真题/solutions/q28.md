# 408-2017-Q28

## 模型锚点

- Topic：多道程序设计的资源重叠机制。
- 题目信号：比较多道与单道系统的系统级收益。
- 第一动作：从“一个作业等待 I/O 时能否让另一个作业占 CPU”这一机制出发，分别推 CPU、I/O、吞吐量和管理开销。

## 解题链

多道程序把多个作业同时放在系统中。当一个作业因 I/O 阻塞时，CPU 可运行另一个作业，于是 CPU 与 I/O 活动能够重叠：

- I 正确：CPU 空闲时间减少，利用率提高；
- III 正确：单位时间完成的作业数通常提高，即吞吐量增大；
- IV 正确：不同作业可让多个 I/O 设备更充分工作；
- II 错：为了调度、内存管理、保护与切换，多道系统的管理开销通常更大，不是更小。

## 选项判断

因此 I、III、IV 正确，选 $\boxed{D}$。

## 校验

单道系统在当前作业等待 I/O 时 CPU 可能闲置；多道系统能把这个“等待空洞”交给其他作业使用，这一条机制同时解释 I、III、IV。

## 压缩

```text
multiple resident jobs -> overlap CPU wait with other work -> utilization/throughput ↑; management overhead not ↓
```

## 易错边界

多道程序提高的是资源利用与吞吐，不保证单个作业响应更快，也不意味着系统管理成本更低。
