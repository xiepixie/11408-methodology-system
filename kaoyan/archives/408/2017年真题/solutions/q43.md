# 408-2017-Q43

## Model Anchor

- Topic：C 整数语义、补码环绕、IEEE 754 单精度精度/范围边界。
- 题目信号：同一个数学函数 $f(n)=2^{n+1}-1$，分别用 `unsigned/int` 与 `float` 迭代实现，并连续追问死循环、舍入、整数溢出、浮点无穷。
- 第一动作：建立三层账本，任何一步都不要混层：`Mathematical value -> language/type operation -> machine representation`。

## Problem Representation

数学对象始终是：

$$
f(n)=1+2+\cdots+2^n=2^{n+1}-1.
$$

但 `f1` 与 `f2` 的状态空间不同：

```text
f1:
unsigned i,n -> modulo 2^32 counter semantics
int sum,power -> 32-bit signed result interpretation (按本题机器模型)

f2:
float sum,power -> IEEE754 single
precision = 24 significant binary bits
finite exponent range is bounded
```

所以题目的核心不是“算等比数列”，而是判断数学值何时越过各表示层的 invariant。

## Decision Points

### 1. `n-1` 的 Owner 是谁？

若 `n` 为 unsigned，则 `0-1` 不是数学上的 `-1`，而是模 $2^{32}$ 的最大无符号数；这直接改变循环边界。

### 2. float 的两个边界必须分开

```text
precision boundary：还能不能精确表示每一位？
range boundary：指数还能不能表示有限数？
```

`f2(24)` 是 precision/rounding 问题；`f2(127)` 是 range/overflow 问题，不能用同一个“float 不够大”解释。

### 3. C 抽象语义与 408 机器模型

严格 C 标准下有符号整数溢出并不是定义为模 $2^{32}$ 环绕；本题显式要求机器数并给出 `f1(31)=-1`，因此应按题设的 32 位补码机器行为分析，不能把语言标准争议覆盖题面合同。

## Solution Chain

### (1) 为什么 `f1(0)` 死循环？改成 int 后呢？

原程序中 `n` 与 `i` 都是 `unsigned`。当 $n=0$：

$$
n-1=0-1\equiv2^{32}-1\pmod{2^{32}}.
$$

循环条件变成：

```c
i <= UINT_MAX
```

`i` 从 0 一直加到 `UINT_MAX` 后再 `i++` 会按无符号规则回绕到 0，于是条件重新成立，循环永不结束。

若把 `i,n` 都改为 `int`，当 $n=0$ 时：

$$
n-1=-1,
$$

初始 `i=0`，立即有 $0\le-1$ 为假，因此一次循环也不执行，不会死循环。

### (2) `f1(23)` 与 `f2(23)`

$$
f(23)=2^{24}-1=16777215.
$$

这是 24 个二进制 `1`。32 位 `int` 能表示；IEEE 754 单精度有 24 位有效精度（隐藏位 + 23 位 fraction），也能**精确**表示。

因此两者数值相等。

`f1(23)` 的 32 位机器数：

$$
\boxed{00FF\ FFFF_H}.
$$

对于 float：

$$
2^{24}-1=1.111\cdots111_2\times2^{23},
$$

阶码 $23+127=150=10010110_2$，fraction 为 23 个 1，因此：

$$
\boxed{4B7F\ FFFF_H}.
$$

### (3) 为什么 `f1(24)=33554431`，`f2(24)=33554432.0`？

数学值：

$$
f(24)=2^{25}-1=33554431.
$$

它需要 25 位有效二进制位，而单精度只有 24 位有效精度，所以不能精确表示。

在 $[2^{24},2^{25})$ 这个数量级，单精度相邻可表示数间距为 2。$2^{25}-1$ 位于两个可表示数之间，按 IEEE 754 默认的 round-to-nearest-even，会舍入为：

$$
\boxed{2^{25}=33554432.0}.
$$

整数 `f1` 此时仍未超过 `INT_MAX`，所以返回精确的 33554431。

### (4) 为什么 `f1(31)=-1`？最大精确 n？

$$
f(31)=2^{32}-1.
$$

其低 32 位恰为：

```text
11111111 11111111 11111111 11111111
```

按 32 位补码 `int` 解释即 `-1`，所以题设机器模型中 `f1(31)` 返回 -1。

要使数学值仍落在 signed 32-bit 正数范围：

$$
2^{n+1}-1\le2^{31}-1
\Rightarrow n+1\le31
\Rightarrow \boxed{n_{max}=30}.
$$

### (5) `f2(127)`、float 最大不溢出 n、最大精确 n

`7F80 0000H` 的字段为：

```text
sign = 0
exponent = 11111111
fraction = 0
```

对应 IEEE 754 的：

$$
\boxed{+\infty}.
$$

当 $n=126$：

$$
f(126)=2^{127}-1,
$$

舍入后可成为有限的 $2^{127}$，仍未越过单精度有限范围；再到 $n=127$，迭代结果向 $2^{128}$ 量级推进并溢出为 $+\infty$。因此不溢出的最大值为：

$$
\boxed{126}.
$$

要完全无舍入，$2^{n+1}-1$ 的连续 `1` 必须全部装入 24 位有效精度：

$$
n+1\le24
\Rightarrow \boxed{n_{max}=23}.
$$

## Verification

用三条独立边界交叉检查：

1. `f1(30)=2^{31}-1=INT_MAX`，刚好是 signed int 最大正数；再加一阶立即越界。
2. `f2(23)` 恰好需要 24 位有效位；`f2(24)` 需要 25 位，精度边界正好跨在这里。
3. `f2(127)` 给出的机器码 `7F800000H` 是 IEEE 754 标准的 +∞ 编码，和“最大有限 n=126”相互吻合。

## Compression

```text
math f(n)=2^(n+1)-1
-> check unsigned loop bound
-> check signed integer representable range
-> check float precision (24 bits)
-> check float exponent/range
-> only then interpret machine bits
```

## 易错边界

1. unsigned 的 `0-1` 是模运算回绕，不是 -1。
2. “float 能表示这么大的数量级”不等于“能精确表示这个整数”；范围与精度必须分开。
3. 本题 `f1(31)=-1` 是题设补码机器模型下的结果；不要把它推广成可移植 C 程序应依赖的有符号溢出行为。
4. `7F800000H` 是 +∞，不是最大有限单精度数；最大有限数的阶码为 254 且 fraction 全 1。
