# 408-2022-Q43

## Model Anchor

- Topic：单总线数据通路、ALU 标志与控制序列。
- 题目信号：给出 `Y/Z/MAR/MDR/IR/GPRs/FR` 和若干控制线，要求从状态变化反推硬件作用。
- 第一动作：每一小问都从对象契约开始：`bit semantics -> bus ownership -> register addressing -> micro-operations -> controller inputs`，不靠部件名称死背答案。

## Problem Representation

图中内部总线同一时刻只能由一个源驱动。ALU 需要两个输入，而运算结果还要在之后写回总线，因此形成经典暂存链：

```text
bus -> Y ----┐
             ├-> ALU -> Z -> bus
bus ---------┘
```

取指令时最小状态变化为：

```text
MAR <- PC
MDR <- M[MAR]
IR  <- MDR
```

## Decision Points

1. `SF/OF` 要从补码符号语义推，不把 carry 和 overflow 混用。
2. `Y/Z` 的存在原因是单总线资源冲突，而不是“ALU 算得慢”。
3. `rs/rd` 是寄存器编号：读端需要选择一路输出，写端需要把一个写使能译码到某个寄存器。
4. 控制序列按微操作的数据依赖排，不允许同一总线在同拍被 PC 和 MDR 同时驱动。

## Solution Chain

### (1) SF 与 OF

结果的最高位就是补码结果符号位，因此

$$\boxed{SF=F_{15}}.$$

#### 加法 $F=A+B$

有符号加法仅在**两个操作数同号而结果异号**时溢出：

$$
\boxed{
OF_{add}=\overline{A_{15}}\,\overline{B_{15}}\,F_{15}
+A_{15}B_{15}\overline{F_{15}}
}.
$$

#### 减法 $F=A-B$

减法仅在 A、B 异号且结果符号与 A 不同时溢出：

$$
\boxed{
OF_{sub}=\overline{A_{15}}B_{15}F_{15}
+A_{15}\overline{B_{15}}\,\overline{F_{15}}
}.
$$

### (2) 为什么设置 Y 和 Z

单内部总线一次只能传一个值，而 ALU 同一运算需要两个输入。

- Y 暂存先到达的一个操作数；
- 第二个操作数直接由总线送 ALU；
- ALU 结果不能在同一时刻再去争用当前总线，因此先锁存在 Z；
- 下一拍由 `Zout` 把结果送总线，再写目标寄存器。

所以 Y/Z 是为了解决**单总线时分复用下的数据保持与资源冲突**。

### (3) GPR 数量、rs/rd 来源及 rd 接口

图中 `rs`、`rd` 均为 4 bit，所以最多可编码

$$2^4=\boxed{16}$$

个通用寄存器。

寄存器编号来自当前指令字段，因此

$$\boxed{rs,rd\text{ 来自 IR}}.$$

写寄存器时 `rd` 需要把“编号”转换成某一个寄存器的独占写使能，故应连接

$$\boxed{\text{地址译码器}}.$$

相对地，读端 `rs` 通常控制多路选择器，从多个寄存器内容中选一路送出。

### (4) 取指控制序列与最少周期

忽略 PC 增量，按数据依赖分三段：

```text
T1: PCout, MARin
T2~T6: Read              // 从发出读命令到数据进入 MDR 共 5 周期
T7: MDRout, IRin
```

因此至少需要

$$\boxed{7\text{ 个时钟周期}}.$$

更抽象地说：

$$PC\to MAR\to Memory\to MDR\to IR.$$

### (5) 控制信号由谁产生，哪些寄存器反馈给它

图中的微操作控制信号由

$$\boxed{\text{控制部件 CU}}$$

产生。

CU 要根据当前指令决定下一组控制信号，因此需要 IR 的指令字段；条件转移等控制还依赖 ALU 状态标志，因此 FR 的输出也要反馈给 CU：

$$\boxed{IR,\ FR}.$$

## Verification

### OF 真值语义验证

加法：`positive + positive -> negative` 或 `negative + negative -> positive` 才置 OF；公式恰好覆盖这两个互斥分支。

减法：`positive - negative -> negative`、`negative - positive -> positive` 才溢出；公式同样对应这两个分支。

### 取指路径验证

每个状态都有唯一来源：PC 先给 MAR；内存读出的指令必须先进入 MDR；随后 MDR 才能经单总线进入 IR。不存在跨越依赖的并行捷径。

## Compression

```text
flags -> sign semantics
single bus -> Y holds operand, Z holds result
4-bit register index -> 16 GPRs
write index rd -> decoder
fetch -> PC→MAR→Mem→MDR→IR = 1+5+1
control -> CU reads IR + FR
```

## 易错边界

- OF 是**有符号**溢出，不是最高位进位 CF。
- `rd` 是“写哪个寄存器”的编号，应译码成 one-hot 写使能；不能因为 GPR 内有 MUX 就把 rd 接到读 MUX。
- “主存读需 5 周期”题面已定义为从发出读命令到数据传到 MDR 的完整区间，不应再额外重复加一个 MDR 写入周期。
