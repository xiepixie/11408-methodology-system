# 408-2022-Q46

## Model Anchor

- Topic：把操作偏序图编译成最小跨线程同步。
- 题目信号：T1 固定执行 `A,E,F`，T2 固定执行 `B,C,D`，图给额外 happens-before 约束。
- 第一动作：先利用**线程内部程序顺序自动满足的边**，只为跨线程且无法由程序顺序推出的依赖建立信号量。

## Problem Representation

必须满足：

```text
A -> C
B -> C
C -> D
C -> E
E -> F
```

线程内部已有：

```text
T1: A -> E -> F
T2: B -> C -> D
```

因此：

- `B -> C`、`C -> D` 已由 T2 程序顺序保证；
- `A -> E`、`E -> F` 已由 T1 程序顺序保证；
- 真正需要跨线程同步的只有 `A -> C` 和 `C -> E`。

## Decision Points

两个依赖方向相反：

```text
T1 --A完成--> T2
T2 --C完成--> T1
```

所以用两个初值为 0 的事件信号量最清晰，分别保存 `A_done` 与 `C_done`。

## Solution Chain

定义：

```c
semaphore S_AC = 0;   // A 是否已经完成，供 C 等待
semaphore S_CE = 0;   // C 是否已经完成，供 E 等待
```

T1：

```c
T1() {
    A;
    signal(S_AC);     // 发布 A 已完成

    wait(S_CE);       // E 必须等待 C
    E;
    F;                // 线程内 E -> F 自然成立
}
```

T2：

```c
T2() {
    B;                // 线程内 B -> C 自然成立

    wait(S_AC);       // C 还必须等待 A
    C;
    signal(S_CE);     // 发布 C 已完成

    D;                // 线程内 C -> D 自然成立
}
```

两信号量初值均为

$$\boxed{0}$$

因为在对应前驱操作真正完成前，后继不能越过同步点。

## Verification

逐边验证：

| 必须约束 | 保证机制 |
|---|---|
| A → C | `signal(S_AC)` / `wait(S_AC)` |
| B → C | T2 程序顺序 |
| C → D | T2 程序顺序 |
| C → E | `signal(S_CE)` / `wait(S_CE)` |
| E → F | T1 程序顺序 |

所有边均被覆盖，且没有增加额外的 D/E 先后关系，因此不会过度串行化。

## Compression

```text
画 happens-before graph
-> 删掉线程内 program-order 已覆盖的边
-> 剩 A→C、C→E
-> 两个 event semaphore，初值 0
```

## 易错边界

- 不需要为图中的每条边都建一个信号量；先利用线程内天然顺序。
- 也不要把 D 和 E 强行排成先后关系；题目只要求二者都在 C 后执行，它们可以并发。
- 信号量表达的是“前驱完成事件”，初值必须为 0；设为 1 会让后继提前通过。
